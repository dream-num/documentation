Collaboration UI integration for Web SDK clients.

```typescript
// [!code word:UniverCollaborationClientUIPlugin]
import { UniverCollaborationClientUIPlugin } from '@univerjs-pro/collaboration-client-ui'

univer.registerPlugin(UniverCollaborationClientUIPlugin, {})
```

## Entry Points

- Facade: `@univerjs-pro/collaboration-client-ui/facade`
- Locale: `@univerjs-pro/collaboration-client-ui/locale/*`

## IUniverCollaborationClientUIConfig

```ts
import type { DependencyOverride } from '@univerjs/core'

export interface IUniverCollaborationClientUIConfig {
  /**
   * Override internal modules with custom implementations.
   */
  override?: DependencyOverride

  /**
   * Enable UI integrations that depend on Docs, such as document selections and image paste.
   * Disable for hosts that only need the browser collaboration services. Defaults to true.
   */
  enableDocumentCollaborationUI?: boolean

  /**
   * Whether to enable frontend log.
   * @default false
   */
  enableFrontendLog?: boolean

  /** Show the built-in conflict notification. Defaults to true. */
  enableDefaultConflictUI?: boolean
}
```

## Conflict recovery

The UI reports the conflict reason and offers reload after the unit's offline cache is cleared. If cleanup fails, it offers retry and does not reload; a successful retry reloads the page. Cache cleanup does not confirm that local edits reached the server.

Set `enableDefaultConflictUI: false` to hide these notifications and handle `CollaborationConflict` in your application. Preserve or export its `localChanges` before refreshing, check `cacheCleared`, and resolve permission failures separately. See [the recovery flow and plugin/preset examples](/server/collaboration/browser-integration#conflict-recovery).

## Pending-save and license notices

The default UI shows a persistent notice when the server reports exhausted editing connections. A resend at least 20 seconds after the first send also raises a save-timeout notice. Each is removed when the unit leaves the awaiting states or is disposed. Domain rejection has a separate notification. `enableDefaultConflictUI` controls conflict recovery notices only, not these pending-save or domain notices. See [server reasons and license notices](/server/collaboration/browser-integration#server-rejections).
