Univer Rust 公式引擎為 Univer Office SDK 提供伺服器端試算表運算能力，支援批次處理、報表產生與 Agent 自動化。試算表承載著預算、預測和業務規則；當公式規模增長到幾十萬、上百萬，運算能力也成為應用程式的重要基礎。

我們選取 10 份工作簿，覆蓋重複公式、條件統計、跨表預算和預測模型。其中三個結果，展示了這套引擎可以處理的業務規模：

- **近 200 萬公式節點：12.29 秒**完成原生載入與全量計算。
- **54 張工作表的專案預算：1.27 秒。**
- **銷售 COUNTIFS 條件統計：3.54 秒。**

## 10 份工作簿的實測表現 [#結果速覽]

Rust 計入原生快照載入與全量計算，不含 XLSX 轉換；Excel、LibreOffice 計入原 XLSX 開啟與全量重算。

![Univer Rust 公式引擎、Excel 與 LibreOffice：10 份活頁簿的載入與運算耗時比較](/assets/blog/rust-formula-performance/calculation-times.svg)

單位秒，越低越快；橫軸為對數刻度。

## 不同業務模型，不同計算特點 [#如何理解這些差異]

在這組負載中，Univer Rust 公式引擎在條件計數、彙總和工作日計算上表現突出。結果也說明，公式數量並非決定耗時的唯一因素，引用範圍、函式組合和依賴結構同樣重要。

在預測模型中，Excel 和 LibreOffice 完成得更快，這也是後續最佳化的方向。完整呈現這些結果，方便開發者根據自己的業務負載作出判斷。

## 把計算能力帶進你的 Office 應用 [#從計算結果到應用體驗]

Univer Rust 公式引擎是 Office SDK 服務端計算流程的一部分。應用可以針對確定的內容版本計算，將結果隨 Snapshot 儲存；前端開啟時複用有效結果，並由前端公式引擎繼續響應使用者編輯。

基於同一內容執行時，開發者可以構建後臺報表、批次處理和 Agent 任務，讓計算結果自然進入後續業務流程。

瞭解[無頭與服務端計算](/overview/features/shared/server-calculation)，或從 [Office SDK 快速開始](/overview/get-started)構建你的應用。

<summary className="cursor-pointer font-medium">測試方法與樣張詳情</summary>

本次按各自輸入格式測量處理耗時：Rust 載入預轉換的原生引擎 JSON，Excel、LibreOffice 開啟 XLSX，包含樣式等文件處理。應用啟動、離線轉換和計時後的校驗不計入，不扣減開啟時間基線。

Rust 每份樣張預熱 1 次、正式測量 5 次，每輪使用獨立程序和新文件。Rust 結果取中位數。

**Excel、LibreOffice 對照記錄的環境：** Windows 11、Intel Core i7-13700H、約 32 GB 記憶體。Excel 為 16.0 build 20527.0，20 個計算執行緒；LibreOffice 為 26.8.1.1，啟用 CPU 多執行緒計算，未啟用 OpenCL 加速。本輪 Rust 使用 20 執行緒。

| 引擎 | 計時範圍 | 統計方式 |
| --- | --- | --- |
| Univer Rust 公式引擎 | 同一連續秒錶：讀取原生快照檔案 → JSON 反序列化 → `load_snapshot` 載入 → 首次建依賴 → 強制全量公式計算 → 應用結果；不計離線 XLSX 轉換。 | 每份預熱 1 次、正式測量 5 次，取中位數；每輪使用獨立程序和新文件，20 執行緒。 |
| Excel COM | 從新開啟原檔案 `Workbooks.Open` 到 `CalculateFullRebuild()` 返回，包含顯式重建依賴與全量重算。 | 每份預熱 1 次、正式測量 5 次，取中位數。 |
| LibreOffice 無頭模式 / UNO | 從新開啟原 XLSX 到 `calculateAll()` 返回，包含開啟階段執行的工作。 | 5 次測量的中位數；銷售條件計數為單次成功的診斷記錄。 |
