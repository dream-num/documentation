## What has changed since Luckysheet?

Luckysheet is an open-source browser spreadsheet used in many embedded editing projects. Its [repository](https://github.com/dream-num/Luckysheet) was archived on October 30, 2025 and recommends Univer for continued development. This update adds that status to the article originally published in August 2025.

Univer is developed by the team behind Luckysheet. It provides a new Office SDK with Sheets, Docs and additional commercial editors. It is a migration target, not a drop-in version upgrade.

## Compare the integration work

| Area | Luckysheet | Univer |
| --- | --- | --- |
| Project status | Archived repository; existing deployments remain your responsibility | Ongoing development in the Univer repositories |
| Open-source license | MIT | Apache-2.0 for the open-source core; commercial capabilities are licensed separately |
| Editor integration | Luckysheet configuration and APIs | Presets, plugins and Facade APIs |
| Stored content | Luckysheet workbook data | Univer snapshots; conversion and validation are needed when migrating |
| Collaboration | Existing Luckysheet integrations and backend implementations | Commercial collaboration services, with application-managed identity and permissions |
| Office files and advanced features | Check the libraries and plugins used by your deployment | Office import/export, charts and pivot tables are among the commercial capabilities |

The open-source Univer distribution contains frontend Sheets and Docs editor capabilities. It does not include server services or the full commercial suite. Do not infer feature availability from the repository license alone.

## Plan a migration around your files

Start with a representative workbook rather than changing every integration at once. Check formulas, number formats, merged cells, conditional formatting, images and any business-specific extensions. Compare both the visible result and the values produced by recalculation.

Then review the application boundary: save/load, events, custom menus, permissions, file conversion and collaboration. Map the old behavior to the current APIs. Existing Luckysheet JSON and custom plugins should not be assumed to work unchanged in Univer.

Keep a copy of the original data and test a rollback before moving production traffic. For self-hosted collaboration or file conversion, include the commercial server components and your own authentication, database and storage integration in the deployment review.

For a maintained Luckysheet application, migration is a product decision with testing and integration costs. For a new project, evaluate the supported SDK and the capabilities you need rather than beginning with an archived dependency.
