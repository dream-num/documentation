Univer Rust 数式エンジンは Univer Office SDK にサーバー側のスプレッドシート計算機能を提供し、バッチ処理、レポート生成、Agent の自動化を支えます。予算、予測、業務ルールを扱う数式が数十万、数百万規模になると、計算能力もアプリの重要な基盤です。

反復数式、条件付き集計、シート間予算、予測モデルを含む 10 冊で測定しました。次の 3 つの結果が、扱える業務規模を示しています。

- **約 200 万の数式ノード：12.29 秒**でネイティブ読み込みと全計算。
- **54 シートのプロジェクト予算：1.27 秒。**
- **売上 COUNTIFS の条件付き集計：3.54 秒。**

## 10 冊での実測結果 [#結果の概要]

Rust はネイティブスナップショットの読み込みと全計算を計測し、XLSX 変換は除外します。Excel・LibreOffice は元の XLSX のオープンと全再計算を計測します。

![Univer Rust 数式エンジン、Excel、LibreOffice：10 冊の読み込みと計算時間の比較](/assets/blog/rust-formula-performance/calculation-times.svg)

単位は秒で、小さいほど高速。横軸は対数目盛です。

## 業務モデルごとに異なる計算の特徴 [#結果の読み方]

今回の負荷では、Univer Rust 数式エンジンは条件付きカウント、集計、稼働日計算で良好な結果を示しました。数式数だけで時間は決まらず、参照範囲、関数の組み合わせ、依存関係も影響します。

予測モデルでは Excel と LibreOffice が早く完了しており、今後の最適化の方向も明確です。全結果を掲載することで、開発者が自身の業務負荷に照らして判断できます。

## Office アプリに計算能力を組み込む [#計算結果からアプリの応答性へ]

Univer Rust 数式エンジンは Office SDK のサーバー側計算を担います。特定の内容リビジョンを計算し、結果を Snapshot と保存できます。フロントエンドは有効な結果を再利用しながら、自身の数式エンジンでユーザーの編集に応答します。

同じコンテンツランタイムを基盤に、バックグラウンドのレポート、バッチ処理、Agent のタスクを構築し、計算結果を次の業務工程につなげられます。

[ヘッドレスとサーバー側計算](/overview/features/shared/server-calculation)を確認するか、[Office SDK のクイックスタート](/overview/get-started)からアプリを構築してください。

<details id="測定した処理" className="my-8 rounded-lg border border-(--separator) p-4">
<summary className="cursor-pointer font-medium">測定方法とサンプルの詳細</summary>

Rust は事前変換したネイティブエンジン JSON を読み込み、Excel・LibreOffice はスタイルなどの文書処理を含む XLSX を開きます。各入力形式での処理時間を測定しています。アプリ起動、オフライン変換、計測後の検証は除外し、オープン時間の基準値は差し引いていません。

Rust は各サンプルでウォームアップ 1 回、本測定 5 回を実施し、毎回独立したプロセスと新規文書を使います。Rust の値は中央値です。

**Excel・LibreOffice の対照記録の環境：** Windows 11、Intel Core i7-13700H、メモリ約 32 GB。Excel は 16.0 build 20527.0、計算スレッド 20。LibreOffice は 26.8.1.1、CPU のマルチスレッド計算を有効にし、OpenCL アクセラレーションは未使用。今回の Rust 測定は 20 スレッドです。

| エンジン | 計測範囲 | 統計方法 |
| --- | --- | --- |
| Univer Rust 数式エンジン | 連続タイマー：ネイティブファイル読み取り → JSON デシリアライズ → `load_snapshot` → 初回依存関係構築 → 全数式の強制計算 → 結果適用。オフライン XLSX 変換を除外。 | 各サンプルでウォームアップ 1 回、本測定 5 回の中央値。毎回独立したプロセスと新規文書、20 スレッド。 |
| Excel COM | 新規の `Workbooks.Open` から `CalculateFullRebuild()` の復帰まで。依存関係の明示的な再構築と全再計算を含む。 | 各サンプルでウォームアップ 1 回、本測定 5 回の中央値。 |
| ヘッドレス LibreOffice / UNO | 元の XLSX を新規に開いてから `calculateAll()` の復帰まで。オープン中の処理を含む。 | 5 回の中央値。ただし売上 COUNTIFS は成功した診断測定 1 回。 |
