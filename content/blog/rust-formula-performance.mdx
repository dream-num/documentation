The Univer Rust formula engine provides server-side spreadsheet calculation for Univer Office SDK, powering batch processing, report generation and agent automation. As budgets, forecasts and business rules grow to hundreds of thousands or millions of formulas, calculation becomes an essential part of the application.

We tested 10 workbooks covering repeated formulas, conditional statistics, cross-sheet budgets and forecast models. Three results illustrate the scale of work the engine can handle:

- **Nearly 2 million formula nodes: 12.29 seconds** for native loading and full calculation.
- **A project budget across 54 sheets: 1.27 seconds.**
- **A sales COUNTIFS workload: 3.54 seconds.**

## Different models, different strengths [#how-to-read-the-differences]

In this set of workloads, the Univer Rust formula engine performs well on conditional counts, aggregation and workday calculations. The results also show that formula count alone does not determine processing time: range sizes, function combinations and dependencies matter.

Excel and LibreOffice finish the forecast models sooner, leaving a clear direction for further optimization. Keeping every result visible helps developers judge the workloads that matter to their applications.

## Bring calculation into your Office application [#from-calculated-results-to-application-responsiveness]

The Univer Rust formula engine is part of the server-side calculation path in Office SDK. Applications can calculate a captured content revision, save the results in its snapshot, and let the frontend reuse valid values when opening the content. The frontend formula engine continues to respond to user edits.

This gives developers a way to build background reports, batch processing and agent tasks around the same content runtime, with calculated results available for the next step of the workflow.

Explore [Headless and server-side calculation](/overview/features/shared/server-calculation), or build your first application with the [Office SDK getting started guide](/overview/get-started).

<summary className="cursor-pointer font-medium">Test methods and workbook details</summary>

The timed paths use different input formats: Rust loads preconverted native engine JSON; Excel and LibreOffice open XLSX, including document processing such as styles. The figures compare those specified processing paths. Application startup, offline conversion and validation after timing are excluded. No opening-time baseline is subtracted.

Rust uses one warmup and five measured runs per workbook, each in a separate process with a new document. Rust results are medians.

**Reference environment for Excel and LibreOffice:** Windows 11, Intel Core i7-13700H, about 32 GB RAM. Excel: 16.0 build 20527.0, 20 calculation threads; LibreOffice: 26.8.1.1, CPU multi-threaded calculation enabled, without OpenCL acceleration. The Rust rerun uses 20 threads.

| Engine | Timed operation | Reported statistic |
| --- | --- | --- |
| Univer Rust formula engine | One continuous timer: read native snapshot file → deserialize JSON → `load_snapshot` → build dependencies → force all formulas → apply results. Offline XLSX conversion excluded. | 1 warmup + 5 measured runs per sample; median. Each run uses an independent process and a new document; 20 threads. |
| Excel COM | Fresh `Workbooks.Open` through `CalculateFullRebuild()` return, including explicit dependency rebuilding and full recalculation. | 1 warmup + 5 measured runs per workbook; median. |
| LibreOffice headless / UNO | Fresh XLSX open through `calculateAll()` return, including work performed during document opening. | 5-run median, except sales COUNTIFS, which is one successful diagnostic run. |

<p id="what-is-inside-each-workbook"><strong>What is inside each workbook?</strong></p>

Formula counts are **executable formula nodes**, not necessarily physical formula cells. Data cells are non-formula cells containing values, including headers. The suite contains nine primary workbooks and one supplementary scale variant, rather than ten independent formula families.

| Workbook | Formula nodes | Data cells / sheets | Formula characteristics |
| --- | --- | --- | --- |

| Mixed formula workload | 367,954 | 432,055 / 7 | `SUMIF`, `AVERAGEIFS`; conditional statistics mixed with dates and text. |
| Forecast model · large | 1,463,721 | 1,549,982 / 4 | 6 nesting levels; `INDEX`, `LARGE`, `OFFSET`, `MATCH` and arrays. |
