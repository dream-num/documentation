距离 Univer 0.25.0 发布，已经过去近四个月。今天，我们很高兴地宣布：**Univer 1.0 正式发布。**

这几个月，我们重构了演示文稿编辑器，加入了白板、多维表格和 PDF，为电子表格带来跨工作簿计算与透视图，为文档补齐目录、脚注和内容控件。我们也把更多工作放在编辑器之间：让内容能够相互嵌入，让评论、历史记录和权限覆盖更多产品，让程序和 AI Agent 能够直接操作这些内容。

现在，Univer 提供**电子表格、文档、演示文稿、白板、多维表格和 PDF 六种编辑器**。开发者可以沿用一套插件体系，把需要的编辑能力放进自己的产品，并通过 Web SDK、Server SDK 和 AI SDK 连接交互、协作与自动化。

你可以从一个表格开始，也可以构建包含多种内容的工作空间。[浏览示例](/showcase)，或直接从 [Sheets 安装指南](/guides/sheets/getting-started/installation)开始使用。

## 一套 SDK，连接六种办公内容

Univer 的目标一直很明确：让开发者在自己的应用里构建办公体验。

一个项目的预算在电子表格里，方案写在文档里，任务放在多维表格里，讨论需要一块白板。这些内容服务于同一个项目，也需要共同的编辑、协作和程序化处理能力。随着应用扩展，开发者还要处理不同编辑器之间的切换、数据引用和内容复用。

1.0 围绕这些需求扩展了产品。六种编辑器沿用 Univer 的插件和命令体系，各自提供面向内容的 Facade API；应用可以按需组合它们，继续使用自己的导航、用户体系和业务数据。对我们来说，这是 1.0 的一个重要里程碑：同一套架构可以承载更完整的办公工作流。

### Sheets：从数据计算到分析结果

电子表格依然是 Univer 的核心。1.0 继续扩展它的计算和分析能力。

现在，公式可以引用其他工作簿的数据。在同一计算环境中加载来源工作簿后，就可以在汇总表中计算 `Sales.xlsx` 的销售额：

```text
=SUM('[Sales.xlsx]Data'!B2:B100)
```

这让分散在不同工作簿里的数据能够参与同一份报表的计算。应用还可以为来源配置稳定的文档 ID 绑定，具体方式见[跨工作簿引用](/guides/sheets/features/core/formula#跨工作簿引用)。

透视表增加了日期分组、更多布局，以及百分比、差异和累计等值显示方式。新增的[透视图](/guides/sheets/features/pivot-chart)则把分析和展示连接起来：关联透视表后，图表共用字段、筛选和排序配置，随着报表的分析维度一起更新。

例如，一份销售报表可以先按月份和地区汇总，再显示各地区占总额的比例，最后用透视图呈现结果。数据整理、分析和展示因此可以放在同一个编辑流程中。

我们还扩展了<span className="whitespace-nowrap"><UniverIcon name="HistogramChartIcon" aria-hidden="true" className="mr-1 inline size-4 align-[-0.125em]" />直方图</span>、<span className="whitespace-nowrap"><UniverIcon name="TreemapChartIcon" aria-hidden="true" className="mr-1 inline size-4 align-[-0.125em]" />矩形树图</span>、<span className="whitespace-nowrap"><UniverIcon name="SunburstChartIcon" aria-hidden="true" className="mr-1 inline size-4 align-[-0.125em]" />旭日图</span>、<span className="whitespace-nowrap"><UniverIcon name="GaugeChartIcon" aria-hidden="true" className="mr-1 inline size-4 align-[-0.125em]" />仪表盘图</span>等普通图表类型，增加了多级分类轴、隐藏数据控制和 SVG 导出。这些能力由共享图表引擎提供，再接入不同的编辑器。了解更多：[图表指南](/guides/sheets/features/charts)。

### Docs：从连续写作到分页排版

一份团队知识库需要持续更新，一份正式报告则需要明确的页面结构。Docs 提供**现代模式**与**传统模式**，让应用可以围绕不同的写作和交付需求组织文档。1.0 继续完善这两种体验。

**现代模式**适合知识库、项目说明和在线协作。内容在连续页面中向下延展，无需按纸张分页；文字、图片和表格可以与[分栏](/guides/docs/features/columns)、提示块组合，用来组织产品对比、工作指南和团队手册。

### PDFs：让交付后的文件仍可处理

PDFs 让应用可以查看和编辑 PDF、管理页面、添加文本、图片、表格与批注，再按需要导出或打印。导入的源文档与后续编辑分别保存，共同呈现为用户正在处理的文件。

合同审阅、资料补充和文件交付因此有了可以直接集成的编辑入口。了解更多：[PDF 编辑指南](/guides/pdfs/features/core/editing)。

## 把相关内容放在一起编辑

有了不同的编辑器，下一步是让相关内容真正放在一起使用。

你可以在 Docs 正文中放入一份 Sheets 工作簿，让读者查看说明时直接使用表格；也可以在 Boards 上放置 Slides，围绕演示内容展开讨论。工作簿的标签页和 Bases 的数据表列表，也可以成为打开其他类型文档的入口。

通过新增的[跨文档嵌入](/guides/fundamentals/features/embed)，被引用的内容保留自己的数据模型和编辑能力。进入表格时可以使用表格工具，进入文档时可以继续编辑正文。内容可以独立保存，也可以在其他文档中被引用和使用。

这项能力目前覆盖 Sheets、Docs、Slides、Boards 和 Bases 之间受支持的异类嵌入。可用的组合、位置和保存方式见[跨文档嵌入指南](/guides/fundamentals/features/embed)。

## 为每天都要使用的编辑器打磨细节

这几个月，我们也持续改进打开文件、输入、滚动和审阅修改时的体验：

- **更适合不同屏幕的操作界面。** 调整 Ribbon 布局，扩展深色主题和 RTL 支持；完善 Sheets 的移动端编辑，并为 Docs、Slides、Boards 和 Bases 增加移动端工作台。应用可按产品指南选择对应的 UI 插件。
- **围绕实际编辑路径优化性能。** Sheets 增加大工作簿加载预览，优化滚动、外部数据粘贴和增量公式计算；Docs 增加可配置的布局 Worker，并缩小局部编辑触发的排版范围；Boards 与 Slides 优化复杂画布和缩略图渲染。
- **扩展协作中的审阅能力。** 将评论、权限控制和版本历史能力扩展到更多编辑器，并提供快照比较 API，帮助应用展示内容发生了哪些变化。

## 连接 Web、Server 与 AI

围绕这些编辑器，Univer 提供了三个可以按需组合的 SDK：

| SDK | 在应用中的职责 |
| --- | --- |
| [Web SDK](/guides/sheets) | 提供嵌入式编辑器、内容模型、渲染和 Facade API，也支持无头内容处理。 |
| [Server SDK](/server) | 提供协同与文件转换的集成模块，由应用接入自己的身份、权限、存储和部署环境。 |
| [AI SDK](/ai) | 为 Agent 和自动化程序提供 TypeScript 与 CLI 能力，用于读取、修改和检查内容。 |

这三个入口围绕同一份可编辑内容工作。用户在浏览器中修改文档，业务程序通过 API 批量处理数据，Agent 则可以先理解结构，再执行内容操作。

1.0 对程序化编辑的补充包括段落和文本范围定位、章节操作，以及图表、形状和白板对象的语义化 API。开发者可以直接表达要修改的内容，减少对界面坐标和点击顺序的依赖。

生成之后，还需要检查。AI SDK 提供视觉检查和布局诊断；接入相应的协同与 [Worktree](/ai/worktree) 能力后，Agent 可以先在草稿中编辑，再由用户在 Web 中审阅、决定是否合并。内容生成、检查和人类审阅可以成为应用中的一个连续流程。

这些能力可以逐步接入：先用 Web SDK 做本地编辑，再通过 Server SDK 连接存储、权限和文件转换，最后按需要增加 Agent 入口。

## 从 0.25.2 升级

1.0 包含 API 清理和包结构调整。已有项目升级时，建议先检查以下几处：

1. **运行环境和构建方式。** Web SDK 的编译目标从 Chrome 70 提高到 Chrome 88，支持基线为 Chrome / Edge 88、Firefox 90、Safari 14.1 和 Electron 12。Preset 移除了原有的 UMD 构建入口，使用脚本标签加载 Preset 的项目需要调整为模块构建方式。
2. **旧 Facade 调用。** 已弃用的入口被移除，例如 `createUniverSheet()`、`getActiveUniverSheet()` 和 `getUniverSheet()`，分别使用 `createWorkbook()`、`getActiveWorkbook()` 和 `getWorkbook()`。旧事件 Hook 需要迁移到 `addEvent()`。
3. **导入导出。** Exchange API 按产品拆分。例如，表格导入使用 `@univerjs-pro/sheets-exchange-client/facade` 中的 `importSheetToSnapshotAsync()`，替代旧的 `importXLSXToSnapshotAsync()`。同时检查插件注册和服务配置，见[导入导出指南](/guides/sheets/features/import-export)。
4. **高级功能与自定义扩展。** Docs、图表和形状的 Facade 有调整；历史记录改为共享模块与各产品插件组合；部分公式服务和类型移至 `engine-formula`。手动注册插件或使用底层服务的项目，应对照当前[功能指南](/guides/sheets/features/core)和 [API 参考](/reference)检查导入、参数和返回值。
5. **自定义代码的执行方式。** Uniscript 已移除。通过 RPC 传递函数源码并在远端反序列化的自定义公式注册路径已关闭；Worker 中需要的可信函数应随 Worker 代码部署，并在执行端注册。

升级时保持相互依赖的 Univer 功能包版本一致，再用现有的典型文档检查编辑、保存、撤销、导入导出和协同流程。只使用某一类编辑器的项目，可以继续按需安装相应功能。

## 开始构建

你可以从一个具体需求开始使用 Univer 1.0：

- 为应用加入电子表格或文档编辑：阅读 [Sheets](/guides/sheets/getting-started/installation) 与 [Docs](/guides/docs/getting-started/installation) 安装指南。
- 构建演示、白板、结构化数据或 PDF 工作区：了解 [Slides](/guides/slides)、[Boards](/guides/boards)、[Bases](/guides/bases) 和 [PDFs](/guides/pdfs)。
- 让多人和 Agent 参与同一份内容：从[协同快速开始](/server/collaboration/quick-start)和 [AI 内容操作](/ai/content-operations)继续。

感谢每一位提交代码、报告问题、完善文档和分享使用反馈的开发者。你们帮助我们把实际工作中的需求带进了这个版本。

欢迎在 [GitHub](https://github.com/dream-num/univer) 继续参与 Univer。我们期待看到你用 1.0 构建的应用。
