Univer Office SDK состоит из трёх частей. [Web SDK](/guides/sheets) запускает редакторы в браузере и может обрабатывать содержимое без интерфейса. [Server SDK](/server) обеспечивает совместное редактирование и обмен файлами. Этот раздел посвящён [AI SDK](/ai), SDK на TypeScript для создания CLI для Office. Он предоставляет агентам и средствам автоматизации точку входа в Node.js для загрузки, изучения, изменения и проверки Units[^document-unit] Univer.

Из возможностей AI SDK можно собрать собственную CLI. Приложение определяет имена и аргументы команд, объекты, с которыми они работают, правила идентификации и авторизации, формат вывода и среду выполнения.

## Рекомендуемая структура приложения

В примерах этого раздела используется схема `CLI + Web + Server`:

<Mermaid chart={"flowchart LR\n    Agent([\"AI Agent / пользователь CLI\"]) --> CLI[\"<b>AI SDK</b><br/>Бизнес-CLI\"]\n    Human([\"Пользователь\"]) --> Web[\"<b>Web SDK</b><br/>Web\"]\n    CLI --> Server[\"<b>Server SDK</b><br/>Совместная работа · Преобразование файлов\"]\n    Web --> Server\n    Server --> Storage[\"Хранилище\"]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Agent,Human actor"} />

- Агент или пользователь отправляет команды Univer через CLI.
- Web отображает страницу, чтобы пользователи могли редактировать её напрямую и проверять результат работы агента.
- Server хранит Units, ревизии и состояние совместного редактирования, общие для CLI и Web.

Три части можно развернуть отдельно или запустить на одной машине. Для знакомства с SDK сначала подключите Web и Server через Collaboration SDK, затем добавьте CLI. При развёртывании порядок может быть другим.

<Callout title="Приложение с одной CLI">
  AI SDK может работать с локальными Units без сервера. Для проверки результатов можно использовать структурированный вывод, попросить агента посмотреть снимок экрана или экспортировать файл Office. Для доступных в реальном времени страниц Web, общих ревизий, History и Worktree нужны функции Web и совместного редактирования.
</Callout>

## Организация CLI через Commander

Базовые пакеты предоставляют API на TypeScript. Пакеты предустановок представляют распространённые возможности как объекты `Command` библиотеки Commander, которые можно добавить в программу приложения:

```ts
import { Command } from "commander";

const program = new Command("my-cli");

program.addCommand(presetCommand);
program.addCommand(applicationCommand);

await program.parseAsync();
```

- **Предустановка команды** задаёт аргументы и справку, а также выводит текст или JSON.
- **Команда приложения** объединяет Runtime[^live-runtime], бизнес-объекты, данные об исполнителе и правила фиксации изменений или работы с файлами.
- И те и другие являются объектами `Command` библиотеки Commander и могут использоваться в одной программе.

На каждой странице сначала описана базовая возможность, а затем её интеграция с Commander.

## Постепенное добавление возможностей

Начните с чтения и записи содержимого Unit. Затем добавьте обработку файлов, визуальную проверку, совместное редактирование и управление процессами:

```text
загрузка и редактирование Unit
→ импорт и экспорт файлов Office
→ визуальная проверка
→ изолированное редактирование и проверка Worktree
→ повторное использование Runtime и Daemon
```

### 1. Загрузка и редактирование Unit

Загрузите Unit через Collaboration Runtime, изучите его структуру и запустите код Facade. По мере необходимости обращайтесь к справочнику API Facade.

### 2. Подключение границы файлов Office

Exchange преобразует файлы Office в UnitData и обратно. После импорта Unit хранится на Collaboration Server. При экспорте Collaboration Runtime получает актуальные UnitData перед записью файла.

### 3. Визуальная проверка

Структурированный вывод лишь частично описывает внешний вид страницы. Screenshot даёт агенту изображение страницы, а Layout Lint сообщает о проблемах вёрстки, которые агент может исправить.

### 4. Изоляция изменений через Worktree

Агент может несколько раз отредактировать и проверить черновик Worktree, не изменяя текущий документ. Затем пользователь проверяет черновик в Web и решает, объединить изменения или вернуть их на доработку.

### 5. Повторное использование дорогих сред

Начните с отдельного runtime для каждой команды и закрывайте его после завершения. Добавляйте пул, worker-процессы или демон, когда этого потребуют время запуска, параллельное выполнение или совместное использование ресурсов между процессами CLI.
