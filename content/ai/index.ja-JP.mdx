Univer Office SDK は 3 つの SDK で構成されています。[Web SDK](/guides/sheets) はブラウザーでエディターを実行し、UI を使わずにコンテンツを処理できます。[Server SDK](/server) は共同編集とファイル変換を提供します。このセクションで扱う [AI SDK](/ai) は Office CLI を構築するための TypeScript SDK です。エージェントや自動化処理が Univer Unit[^document-unit] を読み込み、内容を把握し、変更と確認を行うための Node.js エントリーポイントを提供します。

AI SDK の機能を組み合わせて独自の CLI を構築できます。コマンドの名前、引数、操作対象、認証と認可、出力形式、実行環境はアプリケーションが決めます。

## 推奨するアプリケーション構成

このセクションの例は `CLI + Web + Server` 構成を前提としています。

<Mermaid chart={"flowchart LR\n    Agent([\"AI Agent / CLI ユーザー\"]) --> CLI[\"<b>AI SDK</b><br/>業務 CLI\"]\n    Human([\"人間のユーザー\"]) --> Web[\"<b>Web SDK</b><br/>Web\"]\n    CLI --> Server[\"<b>Server SDK</b><br/>共同編集 · ファイル変換\"]\n    Web --> Server\n    Server --> Storage[\"ストレージ\"]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Agent,Human actor"} />

- エージェントや利用者は CLI を通じて Univer に操作を指示します。
- Web は利用者が直接編集し、エージェントの作業結果を確認できるページを表示します。
- Server は CLI と Web が共有する Unit、リビジョン、共同編集の状態を保存します。

3 つの部分は個別にデプロイすることも、1 台のマシンで動かすこともできます。学習時には Collaboration SDK で Web と Server を接続してから CLI を追加する手順が目安になります。デプロイ時の必須条件ではありません。

<Callout title="CLI だけで構成するアプリケーション">
  AI SDK はサーバーなしでローカルの Unit を処理できます。構造化出力を読む、エージェントにスクリーンショットを確認させる、Office ファイルをエクスポートするといった方法で結果を確認できます。ライブの Web ページ、共有リビジョン、History、Worktree には Web と共同編集の機能が必要です。
</Callout>

## Commander で CLI を構成する

基本パッケージは TypeScript API を提供します。プリセットパッケージは、よく使う機能を Commander の `Command` オブジェクトとして提供します。このオブジェクトをアプリケーション自身のプログラムに追加できます。

```ts
import { Command } from "commander";

const program = new Command("my-cli");

program.addCommand(presetCommand);
program.addCommand(applicationCommand);

await program.parseAsync();
```

- **コマンドプリセット**は引数とヘルプテキストを定義し、テキストまたは JSON を出力します。
- **アプリケーションコマンド**は Runtime[^live-runtime]、アプリケーションの操作対象、実行者の情報、コミットやファイルのポリシーを組み合わせます。
- どちらも Commander の `Command` オブジェクトなので、同じプログラムで併用できます。

各ページでは基本機能を説明したあとで、Commander との統合方法を示します。

## 機能を段階的に構築する

まず Unit のコンテンツの読み書きから始めます。その後でファイル処理、表示の確認、共同編集、プロセス管理を追加します。

```text
Unit の読み込みと編集
→ Office ファイルの入出力
→ 視覚的検査
→ 分離した Worktree の編集とレビュー
→ Runtime の再利用と Daemon
```

### 1. Unit の読み込みと編集

最小構成では、Collaboration Runtime で Unit を読み込み、構造を確認し、Facade コードを実行します。必要な Facade API は適宜調べます。

### 2. Office ファイルの境界を接続する

Exchange は Office ファイルと UnitData を相互に変換します。インポート後の Unit は Collaboration Server に保存されます。エクスポート時は Collaboration Runtime が最新の UnitData を取得してからファイルに書き出します。

### 3. 視覚的検査を追加する

構造化出力だけでは、レンダリング後のページの見た目を完全には把握できません。Screenshot はページを画像としてエージェントに渡し、Layout Lint は修正可能なレイアウト上の問題を報告します。

### 4. Worktree で変更を分離する

エージェントはライブのドキュメントを変更せずに Worktree の下書きを繰り返し編集し、確認できます。作業後に利用者が Web で下書きを確認し、マージするか差し戻すかを決めます。

### 5. 高コストなランタイムを再利用する

最初はコマンドごとに runtime を起動し、完了後に閉じます。起動コスト、同時実行、CLI プロセス間の共有が課題になった段階で、プール、ワーカー、デーモンを導入します。
