Worktree[^document-worktree] предоставляет агенту изолированное пространство для редактирования. Внутри черновика агент может вытащить, проверить, выполнить и совершить столько раундов, сколько ему нужно, затем пометить Worktree Ready, как только пройдут структурированные и визуальные проверки. Затем человек просматривает визуализированную страницу через Web и выбирает Merge или Reopen.

```text
создать Worktree
→ AI Agent редактирует черновик
→ структурная и визуальная проверка
→ Ready
→ человек проверяет в Web
→ Merge / Reopen
→ trunk
```

## Зачем Worktree

- Промежуточные правки агента никогда не достигают багажника.
- Каждый черновик имеет свои собственные снимки, изменения, изменения, присутствие и комнаты в реальном времени.
- Агент может синхронизировать, редактировать и проверять в течение нескольких раундов, прежде чем представить результат.
- Готов заморозить проект при его текущем пересмотре и установить явную границу обзора.
- Человек может просматривать, продолжать редактирование, сливаться или открываться через Интернет.
- Merge по-прежнему проходит через авторизацию и устанавливает границы самой службы совместной работы.

## Полный процесс

```text
создать / выбрать Worktree
→ выбрать Unit Worktree
→ загрузить через Collaboration Runtime
→ pull
→ inspect
→ api find / show
→ execute(write)
→ runtime.commit()
→ inspect + screenshot + layout lint
→ markReady
→ проверка в Web
→ merge / reopen
```

После того, как [Операции загрузки документов и контента](/ai/content-operations), [Офисные файлы импорт и экспорт](/server/import-export/node) и [Визуальный осмотр](/ai/visual-inspection) работают, наведите те же возможности на цель Worktree. Это создает рекомендуемый поток редактирования агента.

## Цель Worktree

Collaboration Runtime работает на Snapshot, наборах изменений и пересмотре одного блока, и у него нет концепции Worktree. Адаптер приложения отображает `worktreeID + unitID` на URL-адреса Snaps Photo, Submit, WebSocket и Session Ticket конечной точки Worktree, а затем передает эти URL-адресы на бэкэнд времени выполнения.

```text
worktreeID + unitID
→ адаптер цели приложения
→ URL протокола Worktree
→ Collaboration Runtime
```

Таким образом, одна и та же модель исполнения во время выполнения подключается либо к багажнику, либо к изолированному черновику Worktree.

## Действия AI Agent в черновике

Для Worktree Unit используется тот же цикл, что и для обычной Unit:

```text
load → pull → inspect → execute(write) → commit
```

Для готового входа Inspection пакет `@univer-cli/content-inspection-command` предоставляет две фабрики:

- `createContentInspectionCommand()` применяется к обычной цели.
- `createWorktreeContentInspectionCommand()` применяется, когда абонент должен явно выбрать `--trunk` или `--worktree <id>`.

Приложение применяет тот же тип выбора цели к выполнению, скриншоту и другим командам, а также владеет приобретением и выпуском выбранного Runtime.

## Выбор Worktree в Commander

Предустановка Inspection имеет вариант Worktree, который требует от абонента выбрать либо `--trunk` или `--worktree <id>`:

```ts
import type { WorktreeContentInspectionCommandDependencies } from "@univer-cli/content-inspection-command";
import { createWorktreeContentInspectionCommand } from "@univer-cli/content-inspection-command";
import { Command } from "commander";

function addWorktreeCommands(
  program: Command,
  dependencies: {
    acquireRuntime: WorktreeContentInspectionCommandDependencies["acquireRuntime"];
    markReady(worktreeID: string): Promise<void>;
  },
): void {
  program.addCommand(
    createWorktreeContentInspectionCommand({
      acquireRuntime: dependencies.acquireRuntime,
    }),
  );

  const worktreeCommand = new Command("worktree");
  worktreeCommand
    .command("ready")
    .argument("<worktree-id>")
    .action(async (worktreeID) => {
      await dependencies.markReady(worktreeID);
    });

  program.addCommand(worktreeCommand);
}
```

`acquireRuntime` и `markReady` являются зависимостями приложений, объявленными здесь явно, а не помощниками, скрытыми внутри AI SDK. Первый реализует отображение от цели Worktree до Runtime, описанного в предыдущем разделе; последний называет Collaboration SDK Worktree клиентом.

Команды выполнения, скриншота и вставки должны использовать одну и ту же целевую модель; в противном случае один идентификатор блока может решать различные задачи. Web может подвергать повторному открытию, отбраковке, слиянию и реальному обзору страницы на одном и том же клиенте Worktree. Продукт может обернуть некоторые из этих операций в дополнительные подкоманды Commander, когда это необходимо.

## Проверки AI Agent

До Ready можно совместить два типа проверки:

```text
структурная проверка: pull → inspect
визуальная проверка: Unit → Render Runtime → screenshot / layout lint
```

- Инспекция проверяет структурированное содержание Рабочей тетради, Рабочего листа, Диапазона, Документа, Параграфа, Представления или Слайда.
- Скриншот предоставляет визуализированную страницу для проверки агентом.
- Layout Lint диагностирует проблемы с компоновкой на слайде.
- Обнаружив проблему, AI Agent может повторить выполнение, фиксацию и проверку.

## Различие Commit, Ready и Merge

| Операция | Значение |
| --- | --- |
| `runtime.commit()` | Отправьте изменения, вызванные текущими мутациями, в проект Worktree |
| `markReady()` | Зафиксировать текущую ревизию черновика каждой Unit и перейти в `ready` |
| `reopenWorktree()` | Возвращение из `ready` в `draft` для продолжения редактирования |
| `mergeWorktree()` | Поочерёдно слить Units Worktree в trunk |

`runtime.commit()` продвигает только черновик. Он не сливается в багажник. Готов переносит работу агента в обзор, но результат все равно требует слияния Worktree, прежде чем он достигнет багажника.

## Проверка человеком в Web

Веб загружает тот же проект с клиентом Worktree и конфигурацией совместной работы Worktree. Поверхность обзора может представлять:

- Текущий статус Worktree.
- Страница единицы в проекте.
- Переключение trunk и черновика.
- Слияние предварительного просмотра для каждого блока.
- Операции Ready, Reopen, Discard и Merge.

Проект в Ready только для чтения. Перед тем, как человек или агент снова отредактирует, откройте его для Draft. После одобрения, Merge, затем переключитесь обратно на багажник, чтобы проверить интегрированный результат.

## Граница Collaboration SDK

Worktree Service, Endpoint, Client и Database Adapter принадлежат Collaboration SDK. AI SDK поставляет композитные возможности Unit Runtime, Inspection, API Reference, Execution и Screenshot. Приложению принадлежат команды жизненного цикла Worktree, отображение целей, идентификация и авторизация.

Композиция сервера, жизненный цикл и ограничения слияния описаны в [Расширениях совместного редактирования](/server/collaboration/extensions).

[^document-worktree]: Этот Worktree — изолированный совместный черновик документа, а не Git worktree или копия исходного кода. Изменения попадают в основную ветвь после проверки и слияния.
