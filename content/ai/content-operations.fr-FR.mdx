## Parcours minimal de contenu pour un AI Agent

Pour chaque commande de contenu, l'entreprise CLI charge l'unité cible[^document-unit] et la synchronise avec le dernier contenu. Du point de vue de l'agent, une opération de contenu typique se déroule comme suit:

<Mermaid chart={"flowchart LR\n    Task([Recevoir la tâche]) --> Inspect[\"inspect<br/>Comprendre structure et contenu\"]\n    Inspect --> API[\"api find / api show<br/>Si nécessaire : API inconnue\"]\n    API --> Read[\"execute · read<br/>Si nécessaire : hors Inspection\"]\n    Read --> Write[\"execute · write<br/>Modifier et valider\"]\n    Write --> Review[\"inspect / execute · read<br/>Vérifier avec la même frontière\"]\n    Review --> Done([Terminé])"} />

Le nœud `api find` / `api show`, le mode de lecture et l'examen final sont les seules étapes conditionnelles. L'agent sélectionne les capacités selon la limite suivante:

| Objectif de l’AI Agent | Fonction à privilégier |
| --- | --- |
| Comprendre la structure et la répartition du contenu principal | Vue d’ensemble `inspect` |
| Lire du contenu standard : Range, Paragraph ou Slide | Sélecteur `inspect` |
| Lire une mise en forme conditionnelle, une configuration Chart ou un élément non couvert | `execute --mode read` |
| Trouver ou confirmer une API Facade inconnue | `api find` / `api show` |
| Modifier et valider le document | `execute --mode write` |
| Vérifier le résultat | `inspect` / `execute --mode read` |

### Exemple : mettre à jour une plage Sheet

Envisagez une tâche qui met à jour `Data!A2:B2` dans `book-1` à `[["East", 128000]]`. Si l'entreprise CLI a été assemblée comme décrit plus loin sur cette page, l'agent procède comme suit.

1. Utilisez Inspection pour comprendre le cahier de travail et la plage cible :

```bash
UNIT_ID="book-1"
my-cli inspect workbook --unit "$UNIT_ID" --json
my-cli inspect range A1:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

2. Pour démontrer la référence de l'API, supposons que l'agent ne connaît pas `setValues` et doit confirmer sa signature :

```bash
my-cli api find setValues --unit sheet
my-cli api show FWorkbook.getSheetByName FWorksheet.getRange FRange.setValues
```

3. Exécutez le code Facade en mode écriture. La commande `execute` de l'application gère le commit :

```bash
my-cli execute --unit "$UNIT_ID" --mode write \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
sheet.getRange("A2:B2").setValues([["East", 128000]]);'
```

4. L'inspection porte sur les valeurs de la plage, alors lisez à nouveau la plage:

```bash
my-cli inspect range A2:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

Cette tâche ne nécessite pas de mode de lecture, parce que Inspection peut lire la plage avant et après l'écriture. Le mode de lecture est réservé au contenu que Inspection ne couvre pas, comme le formatage conditionnel et les exemples de configuration de graphique ci-dessous.

## Assembler ces fonctions dans une CLI métier

Cette section commence à partir de `@univer-cli/univer-collaboration-runtime` et ajoute Inspection, API Reference et Content Execution. Les extraits présentent l'interface centrale de chaque fonction. La configuration du serveur, l'identité, la présentation des erreurs et les arguments de commande restent la responsabilité de l'application.

Chaque étape est enregistrée sur le même programme racine Commander :

```ts
import { Command } from "commander";

const program = new Command("my-cli");

// Register the inspect, execute, and api commands introduced below here.
// Parse CLI arguments only after every command has been registered.
await program.parseAsync();
```

### 1. Charger une Unit collaborative

Collaboration Runtime[^live-runtime] sert deux finalités pour un agent en cours d'exécution dans Node.js : il exécute l'unité et agit comme client de collaboration. Un Runtime reste lié à une unité unique pour tout son cycle de vie.

```ts
import {
  createCollaborationServerAdapter,
  createUniverCollaborationRuntimeFactory,
} from "@univer-cli/univer-collaboration-runtime";
import { UniverInstanceType } from "@univerjs/core";

const factory = createUniverCollaborationRuntimeFactory({
  backend: createCollaborationServerAdapter({
    snapshotServerUrl,
    collabSubmitChangesetUrl,
    collabWebSocketUrl,
    wsSessionTicketUrl,
  }),
  createUniver: headlessUniverFactory,
});

const unitId = "book-1";
const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
```

L'application injecte `headlessUniverFactory`, qui est soit l'implémentation standard de `@univer-cli/headless-univer` ou une composition personnalisée; cette page omet les détails d'initialisation. L'application maquille également sa configuration du serveur, son identité et sa cible d'unité sur les adresses de protocole requises par l'adaptateur. L'exécution charge le Snapshot, maintient les révisions et les modifications à jour et fournit l'environnement d'exécution Facade.

Les API de base Runtime sont:

| API | Rôle |
| --- | --- |
| `pull()` | Récupère les modifications distantes, les réconcilie par OT et met à jour l’Unit |
| `execute({ mode, code })` | Exécute Facade ; `read` lit, `write` produit des mutations |
| `commit()` | Soumet manuellement les mutations en attente |
| `exportUnitData()` | Exporte l’UnitData complet actuellement détenu |
| `getState()` | Lit révision, connexion, attente et conflits |
| `close()` | Libère le handle backend et headless Univer |

### 2. Comprendre le contenu avec Inspection

Les tâches courantes de lecture n'exigent pas que l'agent écrive le code Facade. `@univer-cli/content-inspection` retourne des résultats structurés en lecture seule :

| Unit | Vue Inspection | Ce que l'agent apprend rapidement |
| --- | --- | --- |
| Sheet | Classeur | Identités des feuilles, plages utilisées, résumés Table, Rule et Drawing |
| Doc | Document | Mode, index des paragraphes, aperçus de texte et décomptes de fonctions |
| Slide | Présentation | Index des diapositives, aperçus de texte, nombre d’éléments, taille et nombre de Layouts |

Collaboration Runtime satisfait déjà à l'interface d'exécution en lecture seule que l'inspection s'attend à :

```ts
import { inspectContent } from "@univer-cli/content-inspection";

const workbook = await inspectContent(
  {
    unitId: runtime.unitId,
    unitType: "sheet",
    execute: async (input) => {
      const result = await runtime.execute(input);
      return { value: result.value };
    },
  },
  { kind: "workbook" },
);
```

`inspectContent()` compile `unitId` dans un programme Facade en lecture seule et localise le manuel cible via `univerAPI.getWorkbook(unitId)`. `unitType` vérifie que la requête correspond au type Unit.

Commencez par une requête d'aperçu pour établir la structure et le contenu principal de l'unité, puis utilisez la feuille de travail, la plage, le paragraphe et les sélecteurs de diapositives pour le contenu standard que couvre Inspection. Lorsque la configuration ou le détail requis est absent des résultats de l'inspection, comme une règle de formatage conditionnel complète ou une configuration graphique, lancez une petite requête ciblée via `execute({ mode: "read" })`.

Pour l'expérience Commander par défaut, ajoutez le préréglage `inspect`. L'application doit uniquement fournir un bail Runtime:

```ts
import type { ContentInspectionLease } from "@univer-cli/content-inspection-command";
import { createContentInspectionCommand } from "@univer-cli/content-inspection-command";

program.addCommand(
  createContentInspectionCommand({
    async acquireRuntime({ unitId }) {
      const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
      await runtime.pull();

      const lease: ContentInspectionLease = {
        unitId,
        unitType: "sheet",
        execute: async (input) => {
          const result = await runtime.execute(input);
          return { value: result.value };
        },
        invalidate: () => runtime.close(),
        release: () => runtime.close(),
      };

      return lease;
    },
  }),
);
```

`acquireRuntime` est le champ de dépendance publique du preset, et sa valeur de retour doit être conforme à `ContentInspectionLease`. Cet exemple n'a pas de piscine, donc `invalidate()` et `release()` fermer immédiatement le Runtime exclusif. Le préréglage gère l'analyse sélecteur, la sortie texte ou JSON, et la version de location. La cartographie des cibles, l'initialisation de l'exécution, l'authentification et le chargement à distance restent avec l'application. `inspectContent()` directement.

### 3. Trouver et comprendre les API Facade

Lorsque l'agent connaît la tâche, mais pas la Facade API correspondante, utilisez `@univer-cli/api-reference`. Il est livré avec le SDK actuel, ne charge pas d'unité, et ne contacte pas un service de documentation en ligne.

```ts
import { createStandardApiReference } from "@univer-cli/api-reference";

const reference = createStandardApiReference();

const matches = reference.find({
  terms: ["setValues", "conditional formatting"],
  unit: "sheet",
  limit: 20,
});

const details = reference.show(["FRange", "FRange.setValues", "ICellData.v"]);
```

- `find()` transforme les termes axés sur les tâches en symboles candidats.
- `show()` renvoie les détails précis d’une classe, d’un membre, d’un type ou d’une enum.
- `@univer-cli/api-reference-command` ajoute les préréglages optionnels `api find` et `api show`.

Pour enregistrer la même référence avec Commander :

```ts
import { createApiCommand } from "@univer-cli/api-reference-command";

program.addCommand(createApiCommand({ reference }));
```

API Reference vient avant l'exécution: l'agent inspecte le contenu actuel, trouve ou affiche l'API requise, puis écrit et exécute le code Facade.

### 4. Exécuter lectures et écritures Facade

Pour les lectures et les modifications arbitraires, utilisez Collaboration Runtime `execute()`. `@univer-cli/content-execution` lie Facade JavaScript à une unité spécifique et injecte des liaisons stables pour ce type d'unité:

```ts
import { prepareContentExecutionProgram } from "@univer-cli/content-execution";

const executionProgram = prepareContentExecutionProgram({
  unitId,
  unitType: "sheet",
  code: 'workbook.getActiveSheet().getRange("A1").setValue("done");',
});

const execution = await runtime.execute({
  mode: "write",
  code: executionProgram,
});
```

- `mode: "read"` permet des requêtes arbitraires en lecture seule et bloque les mutations.
- `mode: "write"` capture les mutations Facade et les ajoute à l'état local en attente de Runtime.
- Une exécution réussie signifie que le code a été exécuté. Cela ne signifie pas qu'un jeu de modifications a atteint le serveur.

`content-execution` produit seulement un programme d'exécution. Il n'acquiert jamais de Runtime, soumet des modifications, ou expédie un paquet public de commande `execute` preset. Le CLI d'affaires l'enroule donc dans une application Commander commande:

```ts
const executeCommand = new Command("execute")
  .requiredOption("--unit <id>")
  .requiredOption("--code <javascript>")
  .option("--mode <read|write>", "execute without or with mutations", "write")
  .action(async ({ unit, code, mode }) => {
    if (mode !== "read" && mode !== "write") {
      throw new Error("--mode must be read or write");
    }

    const runtime = await factory.load(unit, UniverInstanceType.UNIVER_SHEET);
    try {
      await runtime.pull();
      const executionProgram = prepareContentExecutionProgram({
        unitId: unit,
        unitType: "sheet",
        code,
      });
      const execution = await runtime.execute({ mode, code: executionProgram });

      if (mode === "read") {
        process.stdout.write(`${JSON.stringify(execution.value, null, 2)}\n`);
        return;
      }

      let committed = await runtime.commit();
      if (committed.status === "pull-required") {
        await runtime.pull();
        committed = await runtime.commit();
      }
      if (committed.status !== "confirmed") {
        throw new Error(`Commit failed: ${committed.status}`);
      }

      process.stdout.write(
        `${JSON.stringify(
          {
            commit: committed.status,
            mutations: execution.mutations.length,
            revision: committed.state.baseRevision,
            value: execution.value,
          },
          null,
          2,
        )}\n`,
      );
    } finally {
      await runtime.close();
    }
  });

program.addCommand(executeCommand);
```

Cette commande par défaut permet d'écrire en mode. Le mode de lecture imprime la valeur de retour du code Facade et rien d'autre : aucune mutation et aucun `commit()`. Le mode d'écriture n'imprime la valeur de mutation, de révision et de retour qu'après confirmation du commit, de sorte que l'agent peut déterminer le résultat exact de la soumission. Commander possède les arguments et le cycle de vie de la commande. L'application possède l'acquisition de Runtime, commit les récupérations, la présentation d'erreurs et la politique d'autorisation. Ce fragment minimal est fixé à Sheet; lorsque l'application supporte Doc, Slide, Base ou Board, ajoutez un mapping explicite des types CLI Unit à `UniverInstanceType` .

#### Réserver le mode lecture aux contenus non couverts

L'inspection indique combien de règles de formatage conditionnel une feuille de travail contient, mais pas la configuration complète de chaque règle. Lorsque l'agent a besoin de ce détail, il confirme l'API et exécute un extrait minimal de Facade en mode lecture:

```bash
my-cli api find getConditionalFormattingRules --unit sheet
my-cli api show FWorksheet.getConditionalFormattingRules

my-cli execute --unit "$UNIT_ID" --mode read \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
return sheet.getConditionalFormattingRules();'
```

L'inspection indique également le nombre de diagrammes qu'une feuille de travail contient. Lorsque la tâche nécessite une configuration graphique complète, une requête ciblée peut renvoyer `sheet.getCharts().map((chart) => chart.getInfo())`. Le mode de lecture ne produit jamais de mutations; son rôle est de combler les lacunes que l'inspection laisse, et non de remplacer l'inspection.

## Bilan

Un seul programme Commander combine désormais Collaboration Runtime, Inspection, API Reference et Content Execution. L'exécution charge et synchronise l'unité, exécute le code Facade et s'engage sur demande. L'inspection fournit des lectures structurées. L'API Reference aide l'agent à localiser le bon Facade API . Commander expose tout cela via un point d'entrée CLI.

Une opération typique commence avec `inspect` pour établir la structure, le contenu principal et les détails standard que l'inspection couvre déjà. Lorsqu'une API n'est pas claire, utilisez `api find` / `api show`. Utilisez le mode lecture uniquement pour la configuration ou le détail que l'Inspection ne couvre pas, puis modifiez et commit en mode écrit.
