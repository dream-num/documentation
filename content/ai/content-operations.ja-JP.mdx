## AI Agent の最小内容操作フロー

あらゆるコンテンツコマンドで、CLI は、対象の Unit[^document-unit] をロードし、最新のコンテンツと同期します。エージェントの視点から、典型的なコンテンツ操作は次のようになります。

<Mermaid chart={"flowchart LR\n    Task([編集タスクを受信]) --> Inspect[\"inspect<br/>構造と主要内容を理解\"]\n    Inspect --> API[\"api find / api show<br/>必要時：API が不明\"]\n    API --> Read[\"execute · read<br/>必要時：Inspection の対象外\"]\n    Read --> Write[\"execute · write<br/>編集してコミット\"]\n    Write --> Review[\"inspect / execute · read<br/>同じ境界に従い確認\"]\n    Review --> Done([完了])"} />

`api find` / `api show`ノード、読み取りモード、最終レビューは条件付きステップのみです。 エージェントは、次の境界に従って機能を選択します。

| AI Agent の目的 | 優先する機能 |
| --- | --- |
| 構造と主要内容の分布を理解 | `inspect` の概要 |
| Range、Paragraph、Slide など標準内容を読む | `inspect` セレクター |
| 条件付き書式、グラフ設定など未対応部分を読む | `execute --mode read` |
| 不慣れな Facade API を検索・確認 | `api find` / `api show` |
| ドキュメントを変更・コミット | `execute --mode write` |
| 結果を確認 | `inspect` / `execute --mode read` |

### 例：Sheet の範囲を更新

`book-1`の`Data!A2:B2`を`[["East", 128000]]`に更新するタスクを検討してください。 このページの後に説明した通り、CLIが組み込まれていると仮定すると、エージェントは次のように進行します。

1. 検査を使用して、ワークブックと対象範囲を理解します。

```bash
UNIT_ID="book-1"
my-cli inspect workbook --unit "$UNIT_ID" --json
my-cli inspect range A1:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

2. API リファレンスを実証するには、エージェントが `setValues` を知らず、そのシグネチャを確認する必要があります。

```bash
my-cli api find setValues --unit sheet
my-cli api show FWorkbook.getSheetByName FWorksheet.getRange FRange.setValues
```

3. 書き込みモードでファサードコードを実行します。アプリケーションの`execute`コマンドはコミットを処理します。

```bash
my-cli execute --unit "$UNIT_ID" --mode write \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
sheet.getRange("A2:B2").setValues([["East", 128000]]);'
```

4. タスクのリスクに基づいてレビューするかどうかを決定します。 検査は範囲値をカバーしていますので、もう一度範囲を読みます。

```bash
my-cli inspect range A2:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

このタスクは、検査が書込み前後のレンジを読み取りできるため、読み取りモードを必要としません。 読み取りモードは、以下の条件式設定やチャート設定例など、検査がカバーしないコンテンツのために予約されます。

## 業務 CLI に機能を組み込む

このセクションは、`@univer-cli/univer-collaboration-runtime` から始まり、検査、API リファレンス、および Content Execution. のスニペットは、各機能のコアインターフェイスを表示します。 サーバー構成、アイデンティティ、エラープレゼンテーション、およびコマンド引数は、アプリケーションの責任を保ちます。

各ステップは同じCommanderのルート プログラムで登録されます:

```ts
import { Command } from "commander";

const program = new Command("my-cli");

// Register the inspect, execute, and api commands introduced below here.
// Parse CLI arguments only after every command has been registered.
await program.parseAsync();
```

### 1. 共同編集 Unit の読み込み

Collaboration Runtime[^live-runtime]は、Node.jsで稼働するエージェントの2つの目的を果たしています。それはユニットを実行し、コラボレーションクライアントとして機能します。ランタイムは、そのライフサイクル全体にわたって単一のユニットにバインドされています。

```ts
import {
  createCollaborationServerAdapter,
  createUniverCollaborationRuntimeFactory,
} from "@univer-cli/univer-collaboration-runtime";
import { UniverInstanceType } from "@univerjs/core";

const factory = createUniverCollaborationRuntimeFactory({
  backend: createCollaborationServerAdapter({
    snapshotServerUrl,
    collabSubmitChangesetUrl,
    collabWebSocketUrl,
    wsSessionTicketUrl,
  }),
  createUniver: headlessUniverFactory,
});

const unitId = "book-1";
const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
```

アプリケーションは、`@univer-cli/headless-univer` またはカスタム構成から標準実装である `headlessUniverFactory`、を注入します。このページは初期化の詳細を省略します。アプリケーションは、サーバー構成、アイデンティティ、ユニットターゲットをアダプターが必要とするプロトコルアドレスにマップします。ランタイムはスナップショットをロードし、リビジョンとチェンジセットを最新の状態に保ちます。ファサード実行環境を提供します。

コアランタイム API は:

| API | 目的 |
| --- | --- |
| `pull()` | リモート変更を取得し OT で調整して Unit を更新 |
| `execute({ mode, code })` | Facade コード実行。`read` は読み取り、`write` は mutation を生成 |
| `commit()` | 現在の保留 mutation を手動送信 |
| `exportUnitData()` | Runtime が保持する完全な UnitData を出力 |
| `getState()` | リビジョン、接続、保留、競合状態を取得 |
| `close()` | バックエンドハンドルと headless Univer を解放 |

### 2. Inspection で内容を理解

一般的な読み取りタスクは、エージェントがファサードコードを書く必要はありません。 `@univer-cli/content-inspection`は、構造化された読み取り専用結果を返します。

| Unit | Inspection の概要 | エージェントがすぐに学習するもの |
| --- | --- | --- |
| Sheet | ブック概要 | シート識別情報、使用範囲、Table・Rule・Drawing の要約 |
| Doc | ドキュメント概要 | モード、段落索引、テキストプレビュー、機能数 |
| Slide | プレゼンテーション概要 | スライド索引、テキストプレビュー、要素数、サイズ、Layout 数 |

Collaboration Runtimeは既に点検が期待する読まれた実行インターフェイスを満たします:

```ts
import { inspectContent } from "@univer-cli/content-inspection";

const workbook = await inspectContent(
  {
    unitId: runtime.unitId,
    unitType: "sheet",
    execute: async (input) => {
      const result = await runtime.execute(input);
      return { value: result.value };
    },
  },
  { kind: "workbook" },
);
```

`inspectContent()`は、`unitId`を読み取り専用ファサードプログラムにコンパイルし、`univerAPI.getWorkbook(unitId)`を介して対象ワークブックを見つけます。 `unitType` は、クエリがユニットタイプに一致することを確認します。

ユニットの構造と主要なコンテンツを確立するために、概要クエリから始めて、ワークシート、範囲、段落、スライドセレクターを使用して、検査カバーの標準的なコンテンツ。 必要な構成または詳細が検査結果から欠落しているとき、完全な条件式フォーマット規則やチャート構成など、`execute({ mode: "read" })`を介して1つの小さな対象クエリを発行します。

デフォルトのCommander体験では、`inspect`プリセットを追加します。このアプリケーションは、ランタイムリースのみを提供する必要があります。

```ts
import type { ContentInspectionLease } from "@univer-cli/content-inspection-command";
import { createContentInspectionCommand } from "@univer-cli/content-inspection-command";

program.addCommand(
  createContentInspectionCommand({
    async acquireRuntime({ unitId }) {
      const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
      await runtime.pull();

      const lease: ContentInspectionLease = {
        unitId,
        unitType: "sheet",
        execute: async (input) => {
          const result = await runtime.execute(input);
          return { value: result.value };
        },
        invalidate: () => runtime.close(),
        release: () => runtime.close(),
      };

      return lease;
    },
  }),
);
```

`acquireRuntime`は、プリセットのパブリック依存関係フィールドであり、その戻り値は`ContentInspectionLease`に準拠しなければなりません。 この例にはプールはありません。`invalidate()`と`release()`は、排他的なランタイムをすぐに閉じます。 プリセットは、セレクターの解析、テキストまたはJSON出力、およびリースリリースを処理します。 ターゲットマッピング、ランタイムの初期化、認証、リモートローディングは、アプリケーションに残ります。 カスタムエージェントプロトコルの場合は、`inspectContent()`を直接呼び出します。

### 3. Facade API を探して理解

エージェントがタスクを知っているが、対応するFacade APIがわからない場合は、`@univer-cli/api-reference`を使用します。現在のSDKで出荷し、ユニットをロードし、オンラインのドキュメントサービスには連絡しません。

```ts
import { createStandardApiReference } from "@univer-cli/api-reference";

const reference = createStandardApiReference();

const matches = reference.find({
  terms: ["setValues", "conditional formatting"],
  unit: "sheet",
  limit: 20,
});

const details = reference.show(["FRange", "FRange.setValues", "ICellData.v"]);
```

- `find()`は、タスク指向の用語を候補のシンボルに変えます。
- `show()` はクラス、メンバー、型、列挙の正確な詳細を返します。
- `@univer-cli/api-reference-command`は、オプションの`api find`と`api show`プリセットを追加します。

Commanderと同じ参照を登録するには:

```ts
import { createApiCommand } from "@univer-cli/api-reference-command";

program.addCommand(createApiCommand({ reference }));
```

API リファレンスは実行前に行われます。エージェントは現在のコンテンツを検査し、必要な API を見つけ、記述して、ファサードコードを実行します。

### 4. Facade の読み書きを実行

任意の読み込みと修正のために、Collaboration Runtimeの`execute()`を使用します。 `@univer-cli/content-execution`は、ファサードJavaScriptを特定のユニットにバインドし、そのユニットタイプのための安定した結合を注入します。

```ts
import { prepareContentExecutionProgram } from "@univer-cli/content-execution";

const executionProgram = prepareContentExecutionProgram({
  unitId,
  unitType: "sheet",
  code: 'workbook.getActiveSheet().getRange("A1").setValue("done");',
});

const execution = await runtime.execute({
  mode: "write",
  code: executionProgram,
});
```

- `mode: "read"`は任意読まれた照会およびブロックの変異を可能にします。
- `mode: "write"`はファサードのミューテーションを捕獲し、ランタイムのローカルの保留状態にそれらを加えます。
- 成功する実行は、コードが実行されることを意味します。 変更セットがサーバーに到達したという意味ではありません。

`content-execution` は実行プログラムのみを生成します。ランタイムを取得したり、チェンジセットを提出したり、パブリック `execute`コマンドプリセットパッケージを出荷したりすることはありません。そのため、ビジネス CLI はアプリケーション Commander ファイルでラップします。

```ts
const executeCommand = new Command("execute")
  .requiredOption("--unit <id>")
  .requiredOption("--code <javascript>")
  .option("--mode <read|write>", "execute without or with mutations", "write")
  .action(async ({ unit, code, mode }) => {
    if (mode !== "read" && mode !== "write") {
      throw new Error("--mode must be read or write");
    }

    const runtime = await factory.load(unit, UniverInstanceType.UNIVER_SHEET);
    try {
      await runtime.pull();
      const executionProgram = prepareContentExecutionProgram({
        unitId: unit,
        unitType: "sheet",
        code,
      });
      const execution = await runtime.execute({ mode, code: executionProgram });

      if (mode === "read") {
        process.stdout.write(`${JSON.stringify(execution.value, null, 2)}\n`);
        return;
      }

      let committed = await runtime.commit();
      if (committed.status === "pull-required") {
        await runtime.pull();
        committed = await runtime.commit();
      }
      if (committed.status !== "confirmed") {
        throw new Error(`Commit failed: ${committed.status}`);
      }

      process.stdout.write(
        `${JSON.stringify(
          {
            commit: committed.status,
            mutations: execution.mutations.length,
            revision: committed.state.baseRevision,
            value: execution.value,
          },
          null,
          2,
        )}\n`,
      );
    } finally {
      await runtime.close();
    }
  });

program.addCommand(executeCommand);
```

このコマンドは、モードを記述するためのデフォルトです。 モードを読み、ファサードコードの戻り値を印刷します。 ミューテーションなし `commit()`. 書き込みモードは、コミットが確認された後にのみ、ミューテーションカウント、リビジョン、および戻り値を印刷します。そのため、エージェントは投稿の正確な結果を決定することができます。 Commander 引数とコマンドのライフサイクルを所有します。このアプリケーションは、ランタイム取得、コミットレトリー、エラープレゼンテーション、および認可ポリシーを所有しています。この最小限のフラグメントはシートに固定されます。アプリケーションがDoc、スライド、ベース、またはボードをサポートしている場合、CLIユニットタイプから明示的なマッピングを追加します。 `UniverInstanceType`.

#### Inspection が扱わない内容にだけ読み取りモードを使う

検査では、ワークシートに含まれる条件式ルールの数が、各規則の完全構成ではないかを報告します。エージェントがその詳細を必要とする場合、API を確認し、読み取りモードでのファサードスニペットを最小限に実行します。

```bash
my-cli api find getConditionalFormattingRules --unit sheet
my-cli api show FWorksheet.getConditionalFormattingRules

my-cli execute --unit "$UNIT_ID" --mode read \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
return sheet.getConditionalFormattingRules();'
```

検査は、ワークシートが含まれているチャートの数を同様に報告します。タスクがフルチャートの設定を必要とするとき、集中されたクエリは、`sheet.getCharts().map((chart) => chart.getInfo())`を返すことができます。モードを読んで、突然変異を生成しません。その役割は、検査葉が、検査を交換しないギャップを埋めることです。

## まとめ

CommanderプログラムがCollaboration Runtime、検査、APIリファレンス、Content Executionを組み合わせました。ランタイムの読み込みとユニットを同期させ、ファサードコードを実行し、要求の検査にコミットします。構造化された読み取りを提供します。 APIリファレンスは、エージェントが正しいFacade APIを見つけるのに役立ちます。 Commanderは、そのすべてが1つのCLIエントリーポイントを介してすべてのものを露出します。

典型的な操作は、構造、メインコンテンツ、およびすでにカバーする標準の詳細を確立するために`inspect`から始まります。 APIが不明な場合は、`api find` / `api show`を使用します。 読み取りモードを使用して、検査がカバーしない設定または詳細のためにのみ使用し、編集し、書き込みモードでコミットします。 レビューは同じ境界線検査に従う。
