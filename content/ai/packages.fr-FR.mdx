AI SDK publie actuellement 25 paquets indépendants. Installez les paquets de base dont l'application a besoin, puis ajoutez une commande prédéfinie à partir de la même ligne lorsque l'interaction terminal par défaut correspond au produit.

## Deux rôles de paquets

| Rôle                   | Fournit                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| Paquet de base | APIs TypeScript structurées, sans dépendance avec Commander et sans opinion sur les noms de commande, la sortie ou le comportement de sortie |
| Paquet de préréglage de commande | Un `Command` Commander natif reposant sur un paquet de base, avec arguments, aide et interaction terminal par défaut  |

Les préréglages de commande se terminent généralement dans `-command`. Chaque paquet de base n'a pas besoin d'un préréglage.

## Runtimes de contenu et de collaboration

[Limites des colis sans tête](/overview/features/shared/server-calculation#headless-packages) explique la division entre les paquets de contenu, les paquets UI et `engine-render` . ## Comment choisir

1. Commencez par le paquet de base correspondant à la tâche métier.
2. Ajoutez son préréglage uniquement si l’interaction Commander par défaut convient au produit.
3. Lorsque le CLI, le Web et le serveur partagent une unité, utilisez un runtime de collaboration au lieu de lire la base de données de collaboration directement.
4. Ajoutez pool, daemon ou Render Runtime seulement pour la réutilisation, l’accès interprocessus ou le rendu navigateur.
5. Lire le paquet cible README pour ses API publiques et pour plus de détails sur la propriété et l'aliénation.

Pour les concepts et l'utilisation de base, voir [Opérations de chargement et de contenu des documents](/ai/content-operations), [Contrôle visuel](/ai/visual-inspection) et [Réutilisation des temps d'exécution et Daemon](/ai/runtime-architecture).
