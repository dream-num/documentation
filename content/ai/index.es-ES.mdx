Univer Office SDK consta de tres partes. [Web SDK](/guides/sheets) ejecuta los editores en el navegador y puede procesar contenido sin interfaz gráfica. [Server SDK](/server) incorpora la colaboración y el intercambio de archivos. Esta sección se centra en [AI SDK](/ai), un SDK de TypeScript para crear CLI de Office. Ofrece a los agentes y a los procesos automatizados un punto de entrada en Node.js para cargar, comprender, modificar y comprobar las Units[^document-unit] de Univer.

AI SDK proporciona capacidades que la aplicación puede combinar para construir su propia CLI. La aplicación define los nombres y argumentos de los comandos, sus destinos, la identidad, la autorización, el formato de salida y el entorno de ejecución.

## Estructura recomendada

Los ejemplos de esta sección usan una arquitectura `CLI + Web + Server`:

<Mermaid chart={"flowchart LR\n    Agent([\"AI Agent / usuario CLI\"]) --> CLI[\"<b>AI SDK</b><br/>CLI de negocio\"]\n    Human([\"Usuario humano\"]) --> Web[\"<b>Web SDK</b><br/>Web\"]\n    CLI --> Server[\"<b>Server SDK</b><br/>Colaboración · Conversión de archivos\"]\n    Web --> Server\n    Server --> Storage[\"Almacenamiento\"]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Agent,Human actor"} />

- Los agentes y las personas usan la CLI para enviar instrucciones a Univer.
- Web muestra la página para que las personas puedan editarla directamente y revisar el resultado del agente.
- Server almacena las Units, las revisiones y el estado de colaboración que comparten la CLI y Web.

Puedes desplegar las tres partes por separado o ejecutarlas en una sola máquina. Para empezar, conecta Web y Server con Collaboration SDK y añade la CLI después. El orden de integración es flexible.

<Callout title="Aplicación solo con CLI">
  AI SDK puede trabajar con Units locales sin servidor. Puedes comprobar el resultado mediante la salida estructurada, pedir al agente que revise una captura de pantalla o exportar un archivo de Office. Las páginas Web en vivo, las revisiones compartidas, History y Worktree requieren las capacidades Web y de colaboración.
</Callout>

## Organizar la CLI con Commander

Los paquetes base proporcionan API de TypeScript. Los paquetes de presets ofrecen las capacidades comunes como objetos `Command` de Commander que puedes añadir al programa de tu aplicación:

```ts
import { Command } from "commander";

const program = new Command("my-cli");

program.addCommand(presetCommand);
program.addCommand(applicationCommand);

await program.parseAsync();
```

- Un **preset de comando** define sus argumentos y texto de ayuda, y devuelve texto o JSON.
- Un **comando de aplicación** combina Runtime[^live-runtime], los destinos de la aplicación, la identidad y las políticas de confirmación o de archivos.
- Ambos son objetos `Command` de Commander y pueden coexistir en el mismo programa.

Cada página presenta primero la capacidad básica y después muestra cómo integrarla con Commander.

## Construir capacidades progresivamente

Empieza por leer y escribir el contenido de una Unit. Después puedes añadir el procesamiento de archivos, la inspección visual, la colaboración y la gestión de procesos:

```text
cargar y editar una Unit
→ importar y exportar archivos Office
→ inspección visual
→ edición y revisión aisladas con Worktree
→ reutilización del Runtime y Daemon
```

### 1. Cargar y editar una Unit

Carga una Unit mediante Collaboration Runtime, inspecciona su estructura, ejecuta código con Facade y consulta las API de Facade que necesites.

### 2. Conectar el límite de archivos Office

Exchange convierte archivos de Office en UnitData y viceversa. Tras importar, la Unit se guarda en Collaboration Server. Al exportar, Collaboration Runtime obtiene la versión más reciente de UnitData antes de escribir el archivo.

### 3. Añadir inspección visual

Una salida estructurada solo describe parte de la página renderizada. Screenshot proporciona al agente una imagen de la página y Layout Lint identifica problemas de diseño que el agente puede corregir.

### 4. Aislar cambios con Worktree

Un agente puede hacer varias rondas de edición y comprobación en un borrador de Worktree sin modificar el documento activo. Una persona revisa después el borrador en Web y decide si fusionarlo o devolverlo para que se revise.

### 5. Reutilizar runtimes costosos

Inicia un runtime por comando y ciérralo cuando termine. Añade un pool, workers o un daemon cuando el coste de inicio, la concurrencia o la reutilización entre procesos de la CLI lo justifiquen.
