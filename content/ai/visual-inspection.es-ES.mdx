La inspección puede verificar valores, párrafos y estructura de página. No puede describir completamente el texto que desborda, elementos que se solapan, la posición de un gráfico o el diseño final de la página. Después de las operaciones de contenido estructurado están en marcha, agregue la reproducción del navegador para que el agente pueda inspeccionar el resultado visual real.

```text
últimas UnitData
→ Render Runtime
├── Screenshot → PNG → comprobación visual del AI Agent
└── Layout Lint → hallazgo estructurado → corrección del AI Agent
```

## Paso 1: preparar un estado explícito

Captura de pantalla y Layout Lint operan en UnitData materializado. No cargan objetivos remotos, y no interpretan cambios. Para una unidad colaborativa, sincronizarlo y exportar el estado actual completo primero:

```ts
await runtime.pull();
const unitData = await runtime.exportUnitData();
```

En un Worktree, exporta UnitData del proyecto de objetivo. Una aplicación local puede utilizar UnitData que ya ha cargado o importado. En ambos casos, la inspección visual se ejecuta contra un solo estado de contenido explícito.

## Paso 2: construir Render Page

`@univer-cli/univer-render-page` monta la página Render del lado del navegador. La aplicación elige los plugins Univer para incluir y construir la página estática:

```ts
import { createPresetRenderUniver, mountUniverRenderPage } from "@univer-cli/univer-render-page";

const container = document.querySelector<HTMLElement>("#app");
if (container === null) throw new Error("#app is required");

await mountUniverRenderPage({
  container,
  createUniver: createPresetRenderUniver,
});
```

La página Render es un punto de entrada del navegador, no una página para la revisión humana. Acepta UnitData de Node.js y devuelve PNGs o hechos de diseño.

## Paso 3: crear Render Runtime

`@univer-cli/univer-render-runtime` aloja la página en Node.js, inicia el navegador y gestiona el protocolo:

```ts
import { createUniverRenderRuntime } from "@univer-cli/univer-render-runtime";

const renderRuntime = await createUniverRenderRuntime({
  renderPageRoot,
});
```

Un solo Render Runtime puede ejecutar varias operaciones en secuencia. Reutilizarlo en un límite de ciclo de vida exterior en lugar de iniciar un navegador para cada imagen.

## Paso 4: capturar una imagen

`@univer-cli/unit-screenshot` es el punto de entrada de alto nivel para las capturas de pantalla de Sheet, Doc, Slide, Board y Base. Maneja la selección de objetivos, paginación, escala, nombre y límites de recursos:

```ts
import { createUnitScreenshot } from "@univer-cli/unit-screenshot";

const screenshot = createUnitScreenshot({ runtime: renderRuntime });
const result = await screenshot.capture({
  unitType: "sheet",
  unitData,
  target: {
    kind: "sheet-range",
    sheetName: "Data",
    range: "B2:H40",
    scale: 2,
  },
});
```

Un resultado puede contener varias imágenes. Cada imagen lleva los bytes PNG, sus dimensiones, la página o el objetivo a que pertenece, y un nombre de archivo sugerido. El paquete no escribe archivos. La aplicación determina dónde se almacenan las imágenes y cómo el agente las recibe.

Sin un objetivo, Captura de Pantalla selecciona el contenido predeterminado del tipo Unit, como el rango utilizado de la hoja de trabajo activa, cada página Doc o cada página de diapositivas.

## Paso 5: diagnosticar el diseño de Slide

`@univer-cli/unit-layout-lint` trabaja de los hechos de diseño que un navegador real produce, y devuelve los hallazgos estructurados con evidencia:

```ts
import { createUnitLayoutLint } from "@univer-cli/unit-layout-lint";

const lint = createUnitLayoutLint({ runtime: renderRuntime });
const report = await lint.lint({
  unitType: "slide",
  unitData,
  pages: [1, "closing-slide"],
});
```

Las reglas actuales son:

- `text-off-page`: la tinta de texto real se extiende más allá de la página.
- `text-escapes-container`: el texto escapa visiblemente de un contenedor opaco más pequeño.
- `text-overlaps-text`: dos áreas de texto dibujado se solapan significativamente.

Un hallazgo es una sugerencia de revisión apoyada por evidencia, y no siempre requiere un cambio. El agente puede combinar hallazgos con Capturas de Pantalla, hacer otra edición de Facade, y ejecutar la inspección visual de nuevo.

## Paso 6: añadir comandos Commander

Captura de Pantalla y Layout Lint ambos proporcionan presets nativos Commander. Pase las capacidades construidas arriba y los cargadores UnitData de la aplicación, a continuación, agregue los comandos al mismo `program` creado en [Carga de documentos y operaciones de contenido](/ai/content-operations):

```ts
import type { UnitScreenshotCommandDependencies } from "@univer-cli/unit-screenshot-command";
import { createUnitScreenshotCommand } from "@univer-cli/unit-screenshot-command";
import type { UnitLayoutLintCommandDependencies } from "@univer-cli/unit-layout-lint-command";
import { createUnitLayoutLintCommand } from "@univer-cli/unit-layout-lint-command";
import type { Command } from "commander";

function addVisualCommands(
  program: Command,
  dependencies: {
    loadUnit: UnitScreenshotCommandDependencies["loadUnit"];
    writeImages: UnitScreenshotCommandDependencies["writeImages"];
    loadSlide: UnitLayoutLintCommandDependencies["loadUnit"];
  },
): void {
  program.addCommand(
    createUnitScreenshotCommand({
      screenshot,
      loadUnit: dependencies.loadUnit,
      writeImages: dependencies.writeImages,
    }),
  );

  program.addCommand(
    createUnitLayoutLintCommand({
      lint,
      loadUnit: dependencies.loadSlide,
    }),
  );
}
```

Los presets poseen los selectores de capturas de pantalla, los selectores para página de diapositivas, `--json`, la salida de texto predeterminada y salidas de error Commander. Los parámetros de función inyectan la asignación de ID de unidad al estado de contenido y el escritor PNG. La aplicación también posee el ciclo de vida Render Runtime.

El preset de Captura de Pantalla también puede incluir un subcommand para la instalación del navegador y el probing. Un navegador no se descarga implícitamente para cada captura.

## Paso 7: liberar recursos del navegador

El creador cierra el Render Runtime en el límite de ciclo de vida Commander más externo:

```ts
try {
  await program.parseAsync();
} finally {
  await renderRuntime.close();
}
```

Para entrada y salida de agente personalizado, pasa por los presets y llama directamente a los paquetes de base. No renderice UnitData sin confiar directamente en un host compartido de alta propiedad. Utilice un usuario restringido, un contenedor, u otro límite de aislamiento de proceso.

Después de que haya controles visuales disponibles, agregue el mismo contenido y las capacidades de inspección al flujo [Worktree: edición de agentes y revisión humana](/ai/worktree).
