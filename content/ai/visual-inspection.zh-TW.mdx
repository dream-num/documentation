Inspection 可以校驗值、段落和頁面結構，但無法完整描述文字溢位、元素重疊、圖形位置和最終版式。完成結構化內容讀寫之後，再加入瀏覽器渲染，Agent 即可檢查真實的視覺效果。

```text
最新 UnitData
→ Render Runtime
├── Screenshot → PNG → AI Agent 視覺檢查
└── Layout Lint → 結構化發現 → AI Agent 修正
```

## 步驟 1：準備明確的內容狀態

Screenshot 和 Layout Lint 處理已經 materialize 的 UnitData，不載入遠端 target，也不解釋 changeset。如果 Unit 處於協同環境，需要先同步並匯出當前完整狀態：

```ts
await runtime.pull();
const unitData = await runtime.exportUnitData();
```

在 Worktree 場景下，從 draft target 匯出 UnitData。本地應用可以直接使用已經載入或匯入的 UnitData。無論來源是什麼，視覺檢查始終針對一個明確的內容狀態。

## 步驟 2：建置 Render Page

`@univer-cli/univer-render-page` 負責組裝瀏覽器端的 Render Page。應用決定啟用哪些 Univer 外掛，並建置靜態頁面：

```ts
import { createPresetRenderUniver, mountUniverRenderPage } from "@univer-cli/univer-render-page";

const container = document.querySelector<HTMLElement>("#app");
if (container === null) throw new Error("#app is required");

await mountUniverRenderPage({
  container,
  createUniver: createPresetRenderUniver,
});
```

Render Page 是瀏覽器端的渲染入口，不是供人審閱的頁面。它接收 Node.js 傳入的 UnitData，返回 PNG 或版面配置資料。

## 步驟 3：建立 Render Runtime

`@univer-cli/univer-render-runtime` 在 Node.js 中託管 Render Page、啟動瀏覽器，並管理頁面協議：

```ts
import { createUniverRenderRuntime } from "@univer-cli/univer-render-runtime";

const renderRuntime = await createUniverRenderRuntime({
  renderPageRoot,
});
```

一個 Render Runtime 可以按順序執行多次操作。應在更外層的生命週期邊界複用它，不要為每張圖片重新啟動瀏覽器。

## 步驟 4：擷取截圖

`@univer-cli/unit-screenshot` 是 Sheet、Doc、Slide、Board 和 Base 截圖的高層入口，負責 target 選擇、分頁、縮放、命名和資源限制：

```ts
import { createUnitScreenshot } from "@univer-cli/unit-screenshot";

const screenshot = createUnitScreenshot({ runtime: renderRuntime });
const result = await screenshot.capture({
  unitType: "sheet",
  unitData,
  target: {
    kind: "sheet-range",
    sheetName: "Data",
    range: "B2:H40",
    scale: 2,
  },
});
```

返回結果可能包含多張圖片。每張圖片都帶有 PNG bytes、寬高、所屬頁面或 target 的標識，以及建議的檔名。該包不寫入檔案；圖片的儲存位置和交付給 Agent 的方式由業務應用決定。

不傳 target 時，Screenshot 按 Unit 型別選擇預設內容，例如 Sheet 的 active worksheet used range、Doc 的所有頁面或 Slide 的所有頁面。

## 步驟 5：診斷 Slide 版面

`@univer-cli/unit-layout-lint` 基於真實瀏覽器生成的版面配置資料，返回帶證據的結構化 finding：

```ts
import { createUnitLayoutLint } from "@univer-cli/unit-layout-lint";

const lint = createUnitLayoutLint({ runtime: renderRuntime });
const report = await lint.lint({
  unitType: "slide",
  unitData,
  pages: [1, "closing-slide"],
});
```

目前規則包含：

- `text-off-page`：文字實際繪製區域超出頁面。
- `text-escapes-container`：文字明顯超出較小的不透明容器。
- `text-overlaps-text`：兩個實際文字 ink 區域明顯重疊。

finding 是帶證據的審閱建議，不一定都需要修改。Agent 可以結合 Screenshot 判斷，繼續修改 Facade 程式碼，然後重新執行視覺檢查。

## 步驟 6：加入 Commander 命令

Screenshot 和 Layout Lint 都提供原生 Commander 預設。將前面建立的 capability 和業務側的 UnitData loader 注入預設，再把它們新增到[文件內容載入與讀寫](/ai/content-operations)中建立的同一個 `program` 上：

```ts
import type { UnitScreenshotCommandDependencies } from "@univer-cli/unit-screenshot-command";
import { createUnitScreenshotCommand } from "@univer-cli/unit-screenshot-command";
import type { UnitLayoutLintCommandDependencies } from "@univer-cli/unit-layout-lint-command";
import { createUnitLayoutLintCommand } from "@univer-cli/unit-layout-lint-command";
import type { Command } from "commander";

function addVisualCommands(
  program: Command,
  dependencies: {
    loadUnit: UnitScreenshotCommandDependencies["loadUnit"];
    writeImages: UnitScreenshotCommandDependencies["writeImages"];
    loadSlide: UnitLayoutLintCommandDependencies["loadUnit"];
  },
): void {
  program.addCommand(
    createUnitScreenshotCommand({
      screenshot,
      loadUnit: dependencies.loadUnit,
      writeImages: dependencies.writeImages,
    }),
  );

  program.addCommand(
    createUnitLayoutLintCommand({
      lint,
      loadUnit: dependencies.loadSlide,
    }),
  );
}
```

預設命令負責截圖 selector、Slide page selector、`--json`、預設文字輸出和 Commander 的錯誤退出。Unit ID 到內容狀態的對映與 PNG writer 透過函式參數顯式注入。Render Runtime 的生命週期仍由應用管理。

Screenshot 預設還可以包含瀏覽器安裝與探測子命令。瀏覽器不會在每次截圖時被隱式下載。

## 步驟 7：釋放瀏覽器資源

建立者在最外層的 Commander 生命週期邊界關閉 Render Runtime：

```ts
try {
  await program.parseAsync();
} finally {
  await renderRuntime.close();
}
```

如需自定義 Agent 的輸入與輸出，可以繞過預設，直接呼叫基礎包。不要在共享的高權限主機上直接渲染不可信的 UnitData，應在中間加入受限使用者、容器或其他程序隔離邊界。

具備視覺檢查能力之後，即可將同一組內容操作與檢查能力接入 [Worktree：Agent 編輯與人類審閱](/ai/worktree) 流程。
