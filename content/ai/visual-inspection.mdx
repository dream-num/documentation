Inspection can verify values, paragraphs, and page structure. It cannot fully describe text that overflows, elements that overlap, the position of a graphic, or the final page layout. After the structured content operations are in place, add browser rendering so that the agent can inspect the actual visual result.

```text
latest UnitData
→ Render Runtime
├── Screenshot ──> PNG ──> agent visual check
└── Layout Lint ─> structured finding ──> agent correction
```

## Step 1: Prepare an explicit content state

Screenshot and Layout Lint operate on materialized UnitData. They do not load remote targets, and they do not interpret changesets. For a collaborative Unit, synchronize it and export the complete current state first:

```ts
await runtime.pull();
const unitData = await runtime.exportUnitData();
```

In a Worktree, export UnitData from the draft target. A local application can use UnitData that it has already loaded or imported. In both cases, visual inspection runs against a single explicit content state.

## Step 2: Build the Render Page

`@univer-cli/univer-render-page` assembles the browser-side Render Page. The application chooses which Univer plugins to include and builds the static page:

```ts
import { createPresetRenderUniver, mountUniverRenderPage } from "@univer-cli/univer-render-page";

const container = document.querySelector<HTMLElement>("#app");
if (container === null) throw new Error("#app is required");

await mountUniverRenderPage({
  container,
  createUniver: createPresetRenderUniver,
});
```

The Render Page is a browser rendering entry point, not a page for human review. It accepts UnitData from Node.js and returns PNGs or layout facts.

## Step 3: Create Render Runtime

`@univer-cli/univer-render-runtime` hosts the Render Page in Node.js, starts the browser, and manages the page protocol:

```ts
import { createUniverRenderRuntime } from "@univer-cli/univer-render-runtime";

const renderRuntime = await createUniverRenderRuntime({
  renderPageRoot,
});
```

A single Render Runtime can run several operations in sequence. Reuse it at an outer lifecycle boundary rather than starting a browser for each image.

## Step 4: Capture a Screenshot

`@univer-cli/unit-screenshot` is the high-level entry point for Sheet, Doc, Slide, Board, and Base screenshots. It handles target selection, pagination, scale, naming, and resource limits:

```ts
import { createUnitScreenshot } from "@univer-cli/unit-screenshot";

const screenshot = createUnitScreenshot({ runtime: renderRuntime });
const result = await screenshot.capture({
  unitType: "sheet",
  unitData,
  target: {
    kind: "sheet-range",
    sheetName: "Data",
    range: "B2:H40",
    scale: 2,
  },
});
```

A result may contain several images. Each image carries the PNG bytes, its dimensions, the page or target to which it belongs, and a suggested filename. The package does not write files. The application determines where images are stored and how the agent receives them.

Without a target, Screenshot selects default content for the Unit type, such as the used range of the active worksheet, every Doc page, or every Slide page.

## Step 5: Diagnose Slide layout

`@univer-cli/unit-layout-lint` works from layout facts that a real browser produces, and it returns structured findings with evidence:

```ts
import { createUnitLayoutLint } from "@univer-cli/unit-layout-lint";

const lint = createUnitLayoutLint({ runtime: renderRuntime });
const report = await lint.lint({
  unitType: "slide",
  unitData,
  pages: [1, "closing-slide"],
});
```

The current rules are:

- `text-off-page`: the actual text ink extends beyond the page.
- `text-escapes-container`: text visibly escapes a smaller opaque container.
- `text-overlaps-text`: two regions of actual text ink overlap significantly.

A finding is a review suggestion supported by evidence, and it does not always require a change. The agent can combine findings with Screenshots, make another Facade edit, and run visual inspection again.

## Step 6: Add Commander commands

Screenshot and Layout Lint both provide native Commander presets. Pass the capabilities built above and the application's UnitData loaders, then add the commands to the same `program` created in [Document loading and content operations](/ai/content-operations):

```ts
import type { UnitScreenshotCommandDependencies } from "@univer-cli/unit-screenshot-command";
import { createUnitScreenshotCommand } from "@univer-cli/unit-screenshot-command";
import type { UnitLayoutLintCommandDependencies } from "@univer-cli/unit-layout-lint-command";
import { createUnitLayoutLintCommand } from "@univer-cli/unit-layout-lint-command";
import type { Command } from "commander";

function addVisualCommands(
  program: Command,
  dependencies: {
    loadUnit: UnitScreenshotCommandDependencies["loadUnit"];
    writeImages: UnitScreenshotCommandDependencies["writeImages"];
    loadSlide: UnitLayoutLintCommandDependencies["loadUnit"];
  },
): void {
  program.addCommand(
    createUnitScreenshotCommand({
      screenshot,
      loadUnit: dependencies.loadUnit,
      writeImages: dependencies.writeImages,
    }),
  );

  program.addCommand(
    createUnitLayoutLintCommand({
      lint,
      loadUnit: dependencies.loadSlide,
    }),
  );
}
```

The presets own the screenshot selectors, the Slide page selectors, `--json`, the default text output, and Commander error exits. The function parameters inject the mapping from Unit ID to content state and the PNG writer. The application also owns the Render Runtime lifecycle.

The Screenshot preset can also include a subcommand for browser installation and probing. A browser is not downloaded implicitly for each capture.

## Step 7: Release browser resources

The creator closes the Render Runtime at the outermost Commander lifecycle boundary:

```ts
try {
  await program.parseAsync();
} finally {
  await renderRuntime.close();
}
```

For custom agent input and output, bypass the presets and call the base packages directly. Do not render untrusted UnitData directly on a shared high-privilege host. Use a restricted user, a container, or another process isolation boundary.

After visual checks are available, add the same content and inspection capabilities to the [Worktree: agent editing and human review](/ai/worktree) flow.
