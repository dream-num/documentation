**AI SDK** est un SDK TypeScript pour créer des CLI Office. Il fournit aux AI Agents et à l’automatisation un accès Node.js pour charger, comprendre, modifier et vérifier les Units Univer.

AI SDK est un ensemble de capacités composables, pas une CLI de produit figée. L’application métier possède les noms de commandes, arguments, cibles, identité et autorisations, sorties et déploiement.

## Structure d’application recommandée

Ce guide utilise une application `CLI + Web + Server` :

<Mermaid chart={"flowchart LR\n    Agent([\"AI Agent / utilisateur CLI\"]) --> CLI[\"<b>AI SDK</b><br/>CLI métier\"]\n    Human([\"Utilisateur humain\"]) --> Web[\"<b>Web SDK</b><br/>Web\"]\n    CLI --> Server[\"<b>Server SDK</b><br/>Collaboration · Conversion de fichiers\"]\n    Web --> Server\n    Server --> Storage[\"Stockage\"]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Agent,Human actor"} />

- CLI est le point d’entrée d’un AI Agent ou d’un utilisateur pour manipuler une Unit.
- Web présente la vraie page pour l’édition interactive et la revue humaine.
- Server conserve les Units, révisions et états collaboratifs partagés par CLI et Web.

Ces trois composants peuvent être déployés séparément ou fonctionner entièrement en local. Construire Web + Server avec Collaboration SDK avant la CLI est un parcours pédagogique recommandé, pas une contrainte de déploiement.

<Callout title="Les applications uniquement CLI sont aussi prises en charge">
  AI SDK peut traiter directement des Units locales. Les résultats se vérifient par sortie structurée, inspection visuelle par AI Agent ou fichiers Office exportés. Les pages Web en direct, révisions partagées, History et Worktree nécessitent les capacités Web et collaboratives correspondantes.
</Callout>

## Organiser la CLI avec Commander

Les paquets de base exposent des API TypeScript structurées. Les préréglages transforment les capacités courantes en objets Commander `Command` natifs. L’application métier possède toujours le programme racine :

```ts
import { Command } from "commander";

const program = new Command("my-cli");

program.addCommand(presetCommand);
program.addCommand(applicationCommand);

await program.parseAsync();
```

- Un **préréglage de commande** fournit arguments, aide et sortie texte ou JSON par défaut.
- Une **commande applicative** compose Runtime, cibles métier, identité, politique de commit ou de fichiers.
- Les deux sont des objets Commander `Command` ordinaires et peuvent cohabiter dans un même programme racine.

Chaque thème commence par la capacité de base, puis explique sa connexion à Commander.

## Construire progressivement les capacités

Le guide part des opérations essentielles sur les Units, puis ajoute fichiers, inspection visuelle, collaboration et processus :

```text
charger et modifier une Unit
→ importer et exporter des fichiers Office
→ inspection visuelle
→ édition et revue isolées avec Worktree
→ réutilisation du Runtime et Daemon
```

### 1. Charger et modifier une Unit

Établissez la boucle minimale d’un AI Agent : charger avec Collaboration Runtime, comprendre le contenu avec Inspection, exécuter du code Univer Facade et découvrir les API Facade au besoin.

### 2. Connecter la frontière des fichiers Office

Utilisez Exchange pour convertir fichiers Office et UnitData. Les Units importées restent sur Collaboration Server ; l’export récupère d’abord les dernières UnitData via Collaboration Runtime.

### 3. Ajouter l’inspection visuelle

Une sortie structurée ne décrit pas toute la mise en page. Screenshot fournit les images rendues à l’AI Agent, tandis que Layout Lint fournit des diagnostics structurés de disposition.

### 4. Isoler les changements avec Worktree

Un AI Agent peut modifier et vérifier un brouillon Worktree pendant plusieurs cycles. Une fois prêt, une personne le révise dans Web et choisit Merge ou Reopen.

### 5. Réutiliser les runtimes coûteux

Commencez par des runtimes éphémères. Ajoutez pool, workers ou daemon seulement lorsque le coût de démarrage, la concurrence ou la réutilisation entre processus CLI devient important.
