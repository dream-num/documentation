Univer Office SDK comprend trois parties. [Web SDK](/guides/sheets) exécute les éditeurs dans le navigateur et peut traiter du contenu sans interface. [Server SDK](/server) fournit la collaboration et l’échange de fichiers. Cette section présente [AI SDK](/ai), un SDK TypeScript pour créer des CLI Office. Il fournit aux agents et aux automatisations un point d’entrée Node.js pour charger, analyser, modifier et vérifier des Units[^document-unit] Univer.

AI SDK fournit des capacités que vous pouvez combiner pour créer votre propre CLI. L’application définit les noms et les arguments des commandes, leurs cibles, la gestion de l’identité et des autorisations, le format de sortie et l’environnement d’exécution.

## Structure d’application recommandée

Les exemples de cette section suivent une architecture `CLI + Web + Server` :

<Mermaid chart={"flowchart LR\n    Agent([\"AI Agent / utilisateur CLI\"]) --> CLI[\"<b>AI SDK</b><br/>CLI métier\"]\n    Human([\"Utilisateur humain\"]) --> Web[\"<b>Web SDK</b><br/>Web\"]\n    CLI --> Server[\"<b>Server SDK</b><br/>Collaboration · Conversion de fichiers\"]\n    Web --> Server\n    Server --> Storage[\"Stockage\"]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Agent,Human actor"} />

- Un agent ou une personne utilise la CLI pour donner des instructions à Univer.
- Web affiche la page pour permettre aux utilisateurs de la modifier directement et de vérifier le résultat produit par l’agent.
- Server stocke les Units, les révisions et l’état de collaboration partagés par la CLI et Web.

Les trois parties peuvent être déployées séparément ou exécutées sur une seule machine. Pour débuter, raccordez Web et Server à Collaboration SDK, puis ajoutez la CLI. Cet ordre est facultatif.

<Callout title="Application avec CLI seule">
  AI SDK peut traiter des Units locales sans serveur. Vous pouvez examiner le résultat sous forme de données structurées, demander à l’agent de vérifier une capture d’écran ou exporter un fichier Office. Les pages Web en direct, les révisions partagées, History et Worktree nécessitent les capacités Web et de collaboration.
</Callout>

## Organiser la CLI avec Commander

Les paquets de base fournissent des API TypeScript. Les paquets de préréglages exposent les fonctionnalités courantes sous forme d’objets `Command` de Commander que vous pouvez ajouter au programme de votre application :

```ts
import { Command } from "commander";

const program = new Command("my-cli");

program.addCommand(presetCommand);
program.addCommand(applicationCommand);

await program.parseAsync();
```

- Un **préréglage de commande** définit ses arguments et son texte d’aide et produit une sortie texte ou JSON.
- Une **commande applicative** combine Runtime[^live-runtime], les cibles métier de l’application, l’identité et les règles de validation ou de gestion des fichiers.
- Les deux sont des objets `Command` de Commander et peuvent être utilisés dans le même programme.

Chaque page présente d’abord la fonctionnalité de base, puis son intégration avec Commander.

## Construire progressivement les capacités

Commencez par lire et écrire le contenu d’une Unit. Ajoutez ensuite le traitement des fichiers, l’inspection visuelle, la collaboration et la gestion des processus :

```text
charger et modifier une Unit
→ importer et exporter des fichiers Office
→ inspection visuelle
→ édition et revue isolées avec Worktree
→ réutilisation du Runtime et Daemon
```

### 1. Charger et modifier une Unit

Chargez une Unit avec Collaboration Runtime, examinez sa structure, exécutez du code Facade sur son contenu et recherchez les API Facade dont vous avez besoin.

### 2. Connecter la frontière des fichiers Office

Exchange convertit les fichiers Office en UnitData et inversement. Après l’import, l’Unit est stockée sur Collaboration Server. Lors de l’export, Collaboration Runtime récupère les dernières UnitData avant d’écrire le fichier.

### 3. Ajouter l’inspection visuelle

Les données structurées ne décrivent qu’une partie de la page rendue. Screenshot fournit à l’agent une image de la page et Layout Lint signale les problèmes de mise en page qu’il peut corriger.

### 4. Isoler les changements avec Worktree

Un agent peut modifier et vérifier un brouillon Worktree à plusieurs reprises sans toucher au document en cours. Une personne examine ensuite le brouillon dans Web et décide de le fusionner ou de le renvoyer pour révision.

### 5. Réutiliser les runtimes coûteux

Démarrez un runtime par commande et fermez-le à la fin. Ajoutez un pool, des workers ou un daemon quand le coût du démarrage, la concurrence ou le partage entre processus CLI le justifie.
