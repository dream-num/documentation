検査は、値、段落、ページ構造を検証できます。 オーバーフロー、オーバーラップする要素、グラフィックの位置、または最終ページレイアウトのテキストを完全に記述することはできません。 構造化されたコンテンツ操作が配置されていると、エージェントが実際のビジュアル結果を調べることができるように、ブラウザのレンダリングを追加します。

```text
最新 UnitData
→ Render Runtime
├── Screenshot → PNG → AI Agent の視覚的検査
└── Layout Lint → 構造化された指摘 → AI Agent の修正
```

## ステップ 1：明確なコンテンツ状態を用意する

ScreenshotとLayout Lintは、材料化UnitDataで動作します。それらはリモートターゲットをロードせず、それらはチェンジセットを解釈しません。共同ユニットの場合、それを同期させ、完全な現在の状態を最初にエクスポートします。

```ts
await runtime.pull();
const unitData = await runtime.exportUnitData();
```

Worktreeでは、ドラフトターゲットからUnitDataをエクスポートします。 ローカルアプリケーションは、既にロードまたはインポートしたUnitDataを使うことができます。 どちらの場合も、視覚検査は単一の明示的なコンテンツ状態から実行されます。

## ステップ 2：Render Page をビルドする

`@univer-cli/univer-render-page`はブラウザ側レンダリングページを組み立てます。このアプリケーションは、Univerプラグインが静的なページを含めると構築するかどうかを選択します。

```ts
import { createPresetRenderUniver, mountUniverRenderPage } from "@univer-cli/univer-render-page";

const container = document.querySelector<HTMLElement>("#app");
if (container === null) throw new Error("#app is required");

await mountUniverRenderPage({
  container,
  createUniver: createPresetRenderUniver,
});
```

Render Pageは、人間のレビューのためのページではなく、エントリーポイントをレンダリングするブラウザです。 Node.jsからUnitDataを受け入れ、PNGやレイアウトの事実を返します。

## ステップ 3：Render Runtime を作成する

`@univer-cli/univer-render-runtime` が Node.js でページを提供し、ブラウザーを起動してページのプロトコルを管理します。

```ts
import { createUniverRenderRuntime } from "@univer-cli/univer-render-runtime";

const renderRuntime = await createUniverRenderRuntime({
  renderPageRoot,
});
```

単一のレンダーランタイムは、シーケンスで複数の操作を実行できます。各イメージのブラウザを起動するのではなく、外部のライフサイクル境界で再利用します。

## ステップ 4：スクリーンショットを取得する

`@univer-cli/unit-screenshot`は、シート、Doc、スライド、ボード、およびベーススクリーンショットの高レベルのエントリーポイントです。 ターゲット選択、パジネーション、スケール、ネーミング、リソース制限を処理します。

```ts
import { createUnitScreenshot } from "@univer-cli/unit-screenshot";

const screenshot = createUnitScreenshot({ runtime: renderRuntime });
const result = await screenshot.capture({
  unitType: "sheet",
  unitData,
  target: {
    kind: "sheet-range",
    sheetName: "Data",
    range: "B2:H40",
    scale: 2,
  },
});
```

その結果には、いくつかの画像が含まれる場合があります。各画像は、PNGバイト、その寸法、そのページ、またはその対象が所属するファイルの名前を、提案したファイル名に運ぶことができます。パッケージはファイルを書きません。アプリケーションは、画像が保存され、エージェントがそれらを受け取る場所を決定します。

ターゲットがなければ、スクリーンショットは、アクティブなワークシート、すべてのドキュメントページ、またはすべてのスライドページの使用範囲など、ユニットタイプのデフォルトコンテンツを選択します。

## ステップ 5：Slide レイアウトの診断

`@univer-cli/unit-layout-lint`は、実際のブラウザが生成するレイアウトの事実から機能し、それは証拠と構造化された検索を返します。

```ts
import { createUnitLayoutLint } from "@univer-cli/unit-layout-lint";

const lint = createUnitLayoutLint({ runtime: renderRuntime });
const report = await lint.lint({
  unitType: "slide",
  unitData,
  pages: [1, "closing-slide"],
});
```

現在のルールは次のとおりです。

- `text-off-page`: 実際のテキストインクはページを超えて拡張します。
- `text-escapes-container`：文字が小さい不透明コンテナーから見た目にもはみ出している。
- `text-overlaps-text`：2 つの文字描画領域が大きく重なる。

発見は証拠によって支えられるレビュー提案であり、それは常に変化を必要としません。エージェントは、スクリーンショットとの検索を組み合わせ、別のファサード編集を行い、再びビジュアル検査を実行することができます。

## ステップ 6：Commander コマンドの追加

スクリーンショットとLayout Lintの両方がネイティブCommanderプリセットを提供します。 上記の機能とアプリケーションのUnitDataローダーを渡すと、[文書の読み込みとコンテンツの操作](/ai/content-operations)で作成した同じ`program`にコマンドを追加します。

```ts
import type { UnitScreenshotCommandDependencies } from "@univer-cli/unit-screenshot-command";
import { createUnitScreenshotCommand } from "@univer-cli/unit-screenshot-command";
import type { UnitLayoutLintCommandDependencies } from "@univer-cli/unit-layout-lint-command";
import { createUnitLayoutLintCommand } from "@univer-cli/unit-layout-lint-command";
import type { Command } from "commander";

function addVisualCommands(
  program: Command,
  dependencies: {
    loadUnit: UnitScreenshotCommandDependencies["loadUnit"];
    writeImages: UnitScreenshotCommandDependencies["writeImages"];
    loadSlide: UnitLayoutLintCommandDependencies["loadUnit"];
  },
): void {
  program.addCommand(
    createUnitScreenshotCommand({
      screenshot,
      loadUnit: dependencies.loadUnit,
      writeImages: dependencies.writeImages,
    }),
  );

  program.addCommand(
    createUnitLayoutLintCommand({
      lint,
      loadUnit: dependencies.loadSlide,
    }),
  );
}
```

プリセットは、スクリーンショットセレクター、スライドページセレクター(`--json`)、デフォルトのテキスト出力、Commanderエラー出口を所有しています。 機能パラメータは、ユニットIDからコンテンツの状態、PNGライターへのマッピングを注入します。 アプリケーションは、レンダリングランタイムのライフサイクルを所有しています。

Screenshot プリセットには、ブラウザのインストールとプロービングのサブコマンドも含まれます。ブラウザは、各キャプチャーに対して無意にダウンロードされていません。

## ステップ 7：ブラウザー資源の解放

クリエーターは、Commander のライフサイクル境界の一番外側にレンダリングランタイムを閉じます。

```ts
try {
  await program.parseAsync();
} finally {
  await renderRuntime.close();
}
```

カスタムエージェントの入力と出力のために、プリセットをバイパスし、ベースパッケージを直接呼び出します。 共有された高優先ホストで、UnitDataを直接不信にレンダリングしないでください。 制限されたユーザー、コンテナ、または別のプロセス分離境界を使用してください。

ビジュアルチェックが使用可能になったら、同じコンテンツと[Worktree: エージェントの編集とヒューマンレビュー](/ai/worktree)フローに検査機能を追加してください。
