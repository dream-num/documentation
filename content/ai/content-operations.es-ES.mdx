## Flujo mínimo de contenido de un AI Agent

Para cada comando de contenido, el negocio CLI carga el objetivo Unit[^document-unit] y lo sincroniza con el último contenido. Desde la perspectiva del agente, una operación de contenido típica procede de la siguiente manera:

<Mermaid chart={"flowchart LR\n    Task([Recibir tarea]) --> Inspect[\"inspect<br/>Entender estructura y contenido\"]\n    Inspect --> API[\"api find / api show<br/>Si hace falta: API desconocida\"]\n    API --> Read[\"execute · read<br/>Si hace falta: fuera de Inspection\"]\n    Read --> Write[\"execute · write<br/>Editar y confirmar\"]\n    Write --> Review[\"inspect / execute · read<br/>Revisar con el mismo límite\"]\n    Review --> Done([Terminado])"} />

El nodo `api find` / `api show`, modo de lectura y la revisión final son los únicos pasos condicionales. El agente selecciona las capacidades según el siguiente límite:

| Objetivo del AI Agent | Función preferida |
| --- | --- |
| Entender estructura y distribución del contenido principal | Resumen `inspect` |
| Leer contenido estándar como Range, Paragraph o Slide | Selector `inspect` |
| Leer formato condicional, configuración Chart u otros huecos | `execute --mode read` |
| Buscar o confirmar una API Facade desconocida | `api find` / `api show` |
| Modificar y confirmar el documento | `execute --mode write` |
| Revisar el resultado | `inspect` / `execute --mode read` |

### Ejemplo: actualizar un rango Sheet

Considere una tarea que actualiza `Data!A2:B2` en `book-1` a `[["East", 128000]]`. Asumiendo que el negocio CLI ha sido montado como se describe más adelante en esta página, el agente procede como sigue.

1. Use la Inspección para entender el Cuaderno de Trabajo y el rango de destino:

```bash
UNIT_ID="book-1"
my-cli inspect workbook --unit "$UNIT_ID" --json
my-cli inspect range A1:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

2. Para demostrar la Referencia de API, asuma que el agente no conoce `setValues` y necesita confirmar su firma:

```bash
my-cli api find setValues --unit sheet
my-cli api show FWorkbook.getSheetByName FWorksheet.getRange FRange.setValues
```

3. Ejecute el código Facade en modo de escritura. El comando `execute` de la aplicación maneja el commit:

```bash
my-cli execute --unit "$UNIT_ID" --mode write \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
sheet.getRange("A2:B2").setValues([["East", 128000]]);'
```

4. Decidir si revisar basado en el riesgo de la tarea. La inspección cubre los valores de rango, por lo que lea el rango de nuevo:

```bash
my-cli inspect range A2:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

Esta tarea no requiere el modo de lectura, porque la Inspección puede leer el rango antes y después de la escritura. El modo de lectura está reservado para el contenido que la Inspección no cubre, como los ejemplos de configuración de formato condicional y Chart a continuación.

## Montar estas funciones en una CLI de negocio

Esta sección comienza desde `@univer-cli/univer-collaboration-runtime` y añade Inspección, Referencia API y Content Execution. Los fragmentos presentan la interfaz central de cada capacidad. Configuración del servidor, identidad, presentación de errores y argumentos de comando siguen siendo la responsabilidad de la aplicación.

Cada paso está registrado en el mismo programa raíz Commander:

```ts
import { Command } from "commander";

const program = new Command("my-cli");

// Register the inspect, execute, and api commands introduced below here.
// Parse CLI arguments only after every command has been registered.
await program.parseAsync();
```

### 1. Cargar una Unit colaborativa

Collaboration RuntimeX[^live-runtime] sirve dos propósitos para un agente que funciona en Node.js: ejecuta la Unidad, y actúa como cliente de colaboración. Un Runtime se mantiene vinculado a una unidad única para todo su ciclo de vida.

```ts
import {
  createCollaborationServerAdapter,
  createUniverCollaborationRuntimeFactory,
} from "@univer-cli/univer-collaboration-runtime";
import { UniverInstanceType } from "@univerjs/core";

const factory = createUniverCollaborationRuntimeFactory({
  backend: createCollaborationServerAdapter({
    snapshotServerUrl,
    collabSubmitChangesetUrl,
    collabWebSocketUrl,
    wsSessionTicketUrl,
  }),
  createUniver: headlessUniverFactory,
});

const unitId = "book-1";
const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
```

La aplicación inyecta `headlessUniverFactory`, que es la implementación estándar desde `@univer-cli/headless-univer` o una composición personalizada; esta página omite los detalles de la inicialización. La aplicación también mapea su configuración de servidor, identidad y objetivo de unidad en las direcciones de protocolo requeridas por el adaptador. Runtime carga el Snapshot, mantiene revisiones y cambios actualizados, y proporciona el entorno de ejecución Facade.

Las API principales de Runtime son:

| API | Propósito |
| --- | --- |
| `pull()` | Obtiene cambios remotos, los concilia por OT y actualiza la Unit |
| `execute({ mode, code })` | Ejecuta Facade; `read` lee y `write` produce mutaciones |
| `commit()` | Envía manualmente las mutaciones pendientes |
| `exportUnitData()` | Exporta todo el UnitData que mantiene Runtime |
| `getState()` | Lee revisión, conexión, pendientes y conflictos |
| `close()` | Libera el handle del backend y headless Univer |

### 2. Comprender contenido con Inspection

Las tareas comunes de lectura no requieren que el agente escriba código Facade. `@univer-cli/content-inspection` devuelve los resultados estructurados y solo leídos:

| Unit | Resumen Inspection | Lo que el agente aprende rápidamente |
| --- | --- | --- |
| Sheet | Libro | Identidad de hojas, rangos usados y resúmenes Table, Rule y Drawing |
| Doc | Documento | Modo, índice de párrafos, vistas previas de texto y recuentos de funciones |
| Slide | Presentación | Índice de diapositivas, vistas previas, cantidad de elementos, tamaño y número de Layouts |

Collaboration Runtime ya satisface la interfaz de ejecución de sólo lectura que la Inspección espera:

```ts
import { inspectContent } from "@univer-cli/content-inspection";

const workbook = await inspectContent(
  {
    unitId: runtime.unitId,
    unitType: "sheet",
    execute: async (input) => {
      const result = await runtime.execute(input);
      return { value: result.value };
    },
  },
  { kind: "workbook" },
);
```

`inspectContent()` compila `unitId` en un programa de sólo lectura Facade y localiza el libro de trabajo objetivo a través de `univerAPI.getWorkbook(unitId)`. `unitType` verifica que la consulta coincide con el tipo de unidad.

Comience con una consulta general para establecer la estructura de la Dependencia y el contenido principal, luego utilice la hoja de trabajo, el rango, el párrafo y los selectores de diapositivas para el contenido estándar que cubre la Inspección. Cuando la configuración o el detalle requerido falta de los resultados de la Inspección, como una regla de formato condicional completa o una configuración de la Carga, emita una pequeña consulta dirigida a través de `execute({ mode: "read" })`.

Para la experiencia Commander predeterminada, agregue el preset `inspect`. La aplicación sólo tiene que proporcionar un contrato de arrendamiento Runtime:

```ts
import type { ContentInspectionLease } from "@univer-cli/content-inspection-command";
import { createContentInspectionCommand } from "@univer-cli/content-inspection-command";

program.addCommand(
  createContentInspectionCommand({
    async acquireRuntime({ unitId }) {
      const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
      await runtime.pull();

      const lease: ContentInspectionLease = {
        unitId,
        unitType: "sheet",
        execute: async (input) => {
          const result = await runtime.execute(input);
          return { value: result.value };
        },
        invalidate: () => runtime.close(),
        release: () => runtime.close(),
      };

      return lease;
    },
  }),
);
```

`acquireRuntime` es el campo de dependencia pública del preset, y su valor de retorno debe ajustarse a `ContentInspectionLease`. Este ejemplo no tiene piscina, así que `invalidate()` y `release()` ambos cierran el tiempo de ejecución exclusivo inmediatamente. El preset maneja el persing selector, texto o salida JSON, y la liberación de arrendamiento. mapeo de objetivos, inicialización de Runtime, autenticación y carga remota permanecen con la aplicación. Para un protocolo de agente personalizado, llame `inspectContent()` directamente.

### 3. Buscar y entender API Facade

Cuando el agente conoce la tarea, pero no el Facade API correspondiente, use `@univer-cli/api-reference`. Nave con el SDK actual, no carga unidad, y no se pone en contacto con un servicio de documentación en línea.

```ts
import { createStandardApiReference } from "@univer-cli/api-reference";

const reference = createStandardApiReference();

const matches = reference.find({
  terms: ["setValues", "conditional formatting"],
  unit: "sheet",
  limit: 20,
});

const details = reference.show(["FRange", "FRange.setValues", "ICellData.v"]);
```

- `find()` convierte los términos orientados a tareas en símbolos candidatos.
- `show()` devuelve detalles precisos de clases, miembros, tipos o enums.
- `@univer-cli/api-reference-command` añade los presets opcionales `api find` y `api show`.

Para registrar la misma referencia con Commander:

```ts
import { createApiCommand } from "@univer-cli/api-reference-command";

program.addCommand(createApiCommand({ reference }));
```

API Referencia viene antes de la ejecución: el agente inspecciona el contenido actual, encuentra o muestra la API requerida, luego escribe y ejecuta el código Facade.

### 4. Ejecutar lecturas y escrituras Facade

Para lecturas y modificaciones arbitrarias, utilice Collaboration Runtime de `execute()`. `@univer-cli/content-execution` une Facade JavaScript a una unidad específica e inyecta enlaces estables para ese tipo de unidad:

```ts
import { prepareContentExecutionProgram } from "@univer-cli/content-execution";

const executionProgram = prepareContentExecutionProgram({
  unitId,
  unitType: "sheet",
  code: 'workbook.getActiveSheet().getRange("A1").setValue("done");',
});

const execution = await runtime.execute({
  mode: "write",
  code: executionProgram,
});
```

- `mode: "read"` permite consultas arbitrarias y bloquea mutaciones.
- `mode: "write"` captura mutaciones Facade y las añade al estado pendiente local de Runtime.
- Una ejecución exitosa significa que el código corrió. No significa que un cambio llegó al servidor.

`content-execution` sólo produce un programa de ejecución. Nunca adquiere un Runtime, presenta cambios, o envía un paquete de preestablecimiento de comandos `execute` público. El negocio CLI por lo tanto lo envuelve en una aplicación comando Commander:

```ts
const executeCommand = new Command("execute")
  .requiredOption("--unit <id>")
  .requiredOption("--code <javascript>")
  .option("--mode <read|write>", "execute without or with mutations", "write")
  .action(async ({ unit, code, mode }) => {
    if (mode !== "read" && mode !== "write") {
      throw new Error("--mode must be read or write");
    }

    const runtime = await factory.load(unit, UniverInstanceType.UNIVER_SHEET);
    try {
      await runtime.pull();
      const executionProgram = prepareContentExecutionProgram({
        unitId: unit,
        unitType: "sheet",
        code,
      });
      const execution = await runtime.execute({ mode, code: executionProgram });

      if (mode === "read") {
        process.stdout.write(`${JSON.stringify(execution.value, null, 2)}\n`);
        return;
      }

      let committed = await runtime.commit();
      if (committed.status === "pull-required") {
        await runtime.pull();
        committed = await runtime.commit();
      }
      if (committed.status !== "confirmed") {
        throw new Error(`Commit failed: ${committed.status}`);
      }

      process.stdout.write(
        `${JSON.stringify(
          {
            commit: committed.status,
            mutations: execution.mutations.length,
            revision: committed.state.baseRevision,
            value: execution.value,
          },
          null,
          2,
        )}\n`,
      );
    } finally {
      await runtime.close();
    }
  });

program.addCommand(executeCommand);
```

Este comando predetermina el modo de escribir. El modo de lectura imprime el valor de retorno del código Facade y nada más: no mutaciones y no `commit()`. El modo de escritura imprime el recuento de mutación, revisión y valor de retorno sólo después de que se confirme el compromiso, por lo que el agente puede determinar el resultado exacto de la presentación. Commander posee los argumentos y el ciclo de vida de comandos. La aplicación es dueña de la adquisición de Runtime, compromete retries, presentación de errores y política de autorización. Este fragmento mínimo se fija a Sheet; cuando la aplicación soporta Doc, Slide, Base o Board, agrega un mapeo explícito de los tipos de Unidad CLI a `UniverInstanceType`.

#### Usar lectura solo para contenido no cubierto

La inspección reporta cuántas reglas de formato condicional contiene un Workheet, pero no la configuración completa de cada regla. Cuando el agente necesita ese detalle, confirma la API y ejecuta un mínimo Facade snippet en modo de lectura:

```bash
my-cli api find getConditionalFormattingRules --unit sheet
my-cli api show FWorksheet.getConditionalFormattingRules

my-cli execute --unit "$UNIT_ID" --mode read \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
return sheet.getConditionalFormattingRules();'
```

La inspección también reporta cuántos Gráficos contiene una Hoja de Trabajo. Cuando la tarea requiere una configuración completa de Chart, una consulta enfocada puede devolver `sheet.getCharts().map((chart) => chart.getInfo())`. El modo de lectura nunca produce mutaciones; su papel es llenar las lagunas que deja la Inspección, no sustituir la Inspección.

## Resumen

Un solo programa Commander combina ahora Collaboration Runtime, Inspección, Referencia API y Content Execution. El tiempo de ejecución carga y sincroniza la Unidad, ejecuta código Facade y se compromete a petición. La inspección proporciona lecturas estructuradas. API Referencia ayuda al agente a localizar el Facade API adecuado. Commander expone todo a través de un punto de entrada CLI.

Una operación típica comienza con `inspect` para establecer la estructura, el contenido principal, y los detalles estándar que la Inspección ya cubre. Cuando una API no está clara, use `api find` / `api show`. Utilice el modo de lectura sólo para la configuración o detalle que la Inspección no cubre, luego editar y comprometerse en modo de escritura.
