검사는 값, 단락 및 페이지 구조를 확인할 수 있습니다. 과잉, 과잉, 그래픽의 위치, 또는 최종 페이지 레이아웃이 완전히 텍스트를 설명 할 수 없습니다. 구조화 된 콘텐츠 작업이 장소에 있기 때문에 에이전트가 실제 시각 결과를 검사 할 수 있도록 브라우저 렌더링을 추가하십시오.

```text
최신 UnitData
→ Render Runtime
├── Screenshot → PNG → AI Agent 시각 검사
└── Layout Lint → 구조화된 발견 → AI Agent 수정
```

## 1단계: 명확한 콘텐츠 상태 준비

스크린 샷 및 Layout Lint는 재료화 된 UnitData에서 작동한다. 그들은 원격 대상을로드하지 않으며 변경 설정을 해석하지 않습니다. 공동 단위의 경우, 동기화하고 완전 전류 상태를 먼저 내보내기 :

```ts
await runtime.pull();
const unitData = await runtime.exportUnitData();
```

Worktree에서, 초안 표적에서 UnitData를 수출하십시오. 국부적으로 신청은 이미 적재되거나 수입한 UnitData을 사용할 수 있습니다. 두 경우에, 시각 검사는 단 하나 명시한 내용 국가에 대하여 뛰습니다.

## 2단계: Render Page 빌드

`@univer-cli/univer-render-page`는 브라우저 측 렌더링 페이지를 조립합니다. 이 응용 프로그램은 Univer 플러그인을 선택하고 정적 페이지를 구축합니다.

```ts
import { createPresetRenderUniver, mountUniverRenderPage } from "@univer-cli/univer-render-page";

const container = document.querySelector<HTMLElement>("#app");
if (container === null) throw new Error("#app is required");

await mountUniverRenderPage({
  container,
  createUniver: createPresetRenderUniver,
});
```

렌더링 페이지는 브라우저 렌더링 항목 포인트입니다, 인간의 검토 페이지. 그것은 Node.js에서 UnitData를 받아 PNG 또는 레이아웃 사실을 반환합니다.

## 3단계: Render Runtime 생성

`@univer-cli/univer-render-runtime`은 Node.js에서 Render Page를 호스팅하고 브라우저를 시작하며 페이지 프로토콜을 관리합니다.

```ts
import { createUniverRenderRuntime } from "@univer-cli/univer-render-runtime";

const renderRuntime = await createUniverRenderRuntime({
  renderPageRoot,
});
```

단일 렌더링 런타임은 여러 작업을 순서대로 실행할 수 있습니다. 각 이미지에 대한 브라우저를 시작하는 것보다 외부 수명주기 경계에서 재사용하십시오.

## 4단계: 스크린샷 캡처

`@univer-cli/unit-screenshot`는 시트, Doc, 슬라이드, 보드 및 기본 스크린 샷을위한 고급 항목 포인트입니다. 그것은 대상 선택, 질, 규모,naming 및 리소스 제한을 처리합니다.

```ts
import { createUnitScreenshot } from "@univer-cli/unit-screenshot";

const screenshot = createUnitScreenshot({ runtime: renderRuntime });
const result = await screenshot.capture({
  unitType: "sheet",
  unitData,
  target: {
    kind: "sheet-range",
    sheetName: "Data",
    range: "B2:H40",
    scale: 2,
  },
});
```

결과에는 여러 이미지를 포함 할 수 있습니다. 각 이미지는 PNG 바이트, 그 크기, 페이지 또는 대상이 속한, 제안 된 파일 이름을 운반합니다. 패키지는 파일을 작성하지 않습니다. 응용 프로그램은 이미지가 저장되고 에이전트가 그(것)들을 수신하는 방법을 결정합니다.

대상없이 스크린 샷은 활성 워크 시트의 사용 범위와 같은 단위 유형의 기본 콘텐츠를 선택, 모든 Doc 페이지, 또는 모든 슬라이드 페이지.

## 5단계: Slide 레이아웃 진단

`@univer-cli/unit-layout-lint`는 실제 브라우저가 생성되는 레이아웃에서 작동하며, 증거로 구조화 된 결과를 반환합니다.

```ts
import { createUnitLayoutLint } from "@univer-cli/unit-layout-lint";

const lint = createUnitLayoutLint({ runtime: renderRuntime });
const report = await lint.lint({
  unitType: "slide",
  unitData,
  pages: [1, "closing-slide"],
});
```

현재 규칙은:

- `text-off-page` : 실제 텍스트 잉크는 페이지를 넘어 확장합니다.
- `text-escapes-container`: 작은 불투명 컨테이너 밖으로 텍스트가 눈에 띄게 벗어남.
- `text-overlaps-text`: 두 실제 텍스트 영역이 상당히 겹침.

발견은 증거에 의해 지원된 검토 제안이고, 항상 변화가 요구되지 않습니다. 대리인은 스크린샷을 가진 발견을 결합하고, 다른 정면 편집을 만들고, 시각 검사를 다시 실행할 수 있습니다.

## 6단계: Commander 명령 추가

스크린 샷과 Layout Lint 모두는 네이티브 Commander 프리셋을 제공합니다. 위의 기능을 통과하고 응용 프로그램의 UnitData 로더는 [문서 로딩 및 콘텐츠 작업](/ai/content-operations)에서 생성 된 동일한 `program`에 명령을 추가합니다.

```ts
import type { UnitScreenshotCommandDependencies } from "@univer-cli/unit-screenshot-command";
import { createUnitScreenshotCommand } from "@univer-cli/unit-screenshot-command";
import type { UnitLayoutLintCommandDependencies } from "@univer-cli/unit-layout-lint-command";
import { createUnitLayoutLintCommand } from "@univer-cli/unit-layout-lint-command";
import type { Command } from "commander";

function addVisualCommands(
  program: Command,
  dependencies: {
    loadUnit: UnitScreenshotCommandDependencies["loadUnit"];
    writeImages: UnitScreenshotCommandDependencies["writeImages"];
    loadSlide: UnitLayoutLintCommandDependencies["loadUnit"];
  },
): void {
  program.addCommand(
    createUnitScreenshotCommand({
      screenshot,
      loadUnit: dependencies.loadUnit,
      writeImages: dependencies.writeImages,
    }),
  );

  program.addCommand(
    createUnitLayoutLintCommand({
      lint,
      loadUnit: dependencies.loadSlide,
    }),
  );
}
```

미리 설정은 스크린 샷 선택기, 슬라이드 페이지 선택기, `--json`, 기본 텍스트 출력 및 Commander 오류 출구를 소유합니다. 기능 매개 변수는 단위 ID에서 콘텐츠 상태 및 PNG 작가에 매핑을 주사합니다. 응용 프로그램은 또한 Render Runtime Lifecycle을 소유합니다.

스크린 샷 미리 설정은 브라우저 설치 및 프로빙에 대한 하위 기능을 포함 할 수 있습니다. 브라우저는 각 캡처를 위해 부적절하게 다운로드되지 않습니다.

## 7단계: 브라우저 리소스 해제

제작자는 가장 바깥쪽 Commander 수명주기 경계에서 렌더링 실행 시간을 닫습니다.

```ts
try {
  await program.parseAsync();
} finally {
  await renderRuntime.close();
}
```

사용자 정의 에이전트 입력 및 출력, presets를 우회하고 기본 패키지를 직접 호출합니다. 공유 높은-privilege 호스트에 직접 UnitData를 신뢰할 수 없습니다. 제한된 사용자, 컨테이너 또는 다른 프로세스 고립 경계를 사용하십시오.

시각 검사가 유효하다 후에, [Worktree: 에이전트 편집 및 인간 검토](/ai/worktree) 교류에 동일한 내용 및 검사 기능을 추가하십시오.
