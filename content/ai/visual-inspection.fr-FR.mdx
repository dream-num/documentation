L'inspection peut vérifier les valeurs, les paragraphes et la structure de la page. Elle ne peut pas décrire entièrement le texte qui déborde, les éléments qui se chevauchent, la position d'un graphique ou la mise en page finale de la page . Après les opérations de contenu structuré sont en place, ajouter le rendu du navigateur afin que l'agent puisse inspecter le résultat visuel réel.

```text
dernières UnitData
→ Render Runtime
├── Screenshot → PNG → contrôle visuel de l’AI Agent
└── Layout Lint → constat structuré → correction par l’AI Agent
```

## Étape 1 : préparer un état explicite

Capture d'écran et Layout Lint fonctionnent sur UnitData matérialisé. Ils ne chargent pas les cibles distantes, et ils n'interprètent pas les changements. Pour une unité collaborative, synchronisez-le et exportez d'abord l'état courant complet :

```ts
await runtime.pull();
const unitData = await runtime.exportUnitData();
```

Dans un Worktree, exportez UnitData à partir de la cible d'ébauche. Une application locale peut utiliser UnitData qu'elle a déjà chargé ou importé. Dans les deux cas, l'inspection visuelle se déroule contre un seul état de contenu explicite.

## Étape 2 : construire la Render Page

`@univer-cli/univer-render-page` assemble la page Render côté navigateur. L'application choisit les plugins Univer pour inclure et construire la page statique:

```ts
import { createPresetRenderUniver, mountUniverRenderPage } from "@univer-cli/univer-render-page";

const container = document.querySelector<HTMLElement>("#app");
if (container === null) throw new Error("#app is required");

await mountUniverRenderPage({
  container,
  createUniver: createPresetRenderUniver,
});
```

La page Render est un point d'entrée de rendu de navigateur, pas une page pour l'examen humain. Elle accepte UnitData de Node.js et renvoie des PNGs ou des faits de mise en page.

## Étape 3 : créer le Render Runtime

`@univer-cli/univer-render-runtime` héberge la page dans Node.js, démarre le navigateur et gère le protocole :

```ts
import { createUniverRenderRuntime } from "@univer-cli/univer-render-runtime";

const renderRuntime = await createUniverRenderRuntime({
  renderPageRoot,
});
```

Un seul Render Runtime peut exécuter plusieurs opérations en séquence. Réutiliser à une limite externe du cycle de vie plutôt que de démarrer un navigateur pour chaque image.

## Étape 4 : capturer une image

`@univer-cli/unit-screenshot` est le point d'entrée de haut niveau pour les captures d'écran Feuille, Doc, Diapositive, Planche et Base. Il gère la sélection des cibles, la pagination, l'échelle, le nommage et les limites de ressources :

```ts
import { createUnitScreenshot } from "@univer-cli/unit-screenshot";

const screenshot = createUnitScreenshot({ runtime: renderRuntime });
const result = await screenshot.capture({
  unitType: "sheet",
  unitData,
  target: {
    kind: "sheet-range",
    sheetName: "Data",
    range: "B2:H40",
    scale: 2,
  },
});
```

Un résultat peut contenir plusieurs images. Chaque image porte les octets PNG, ses dimensions, la page ou la cible à laquelle elle appartient, et un nom de fichier suggéré. Le paquet n'écrit pas les fichiers. L'application détermine où les images sont stockées et comment l'agent les reçoit.

Sans cible, Screenshot sélectionne le contenu par défaut pour le type Unit, comme la plage utilisée de la feuille de travail active, chaque page Doc ou chaque page Diapositive.

## Étape 5 : diagnostiquer la disposition des Slides

`@univer-cli/unit-layout-lint` fonctionne à partir des faits de mise en page qu'un vrai navigateur produit, et il renvoie des constatations structurées avec des preuves:

```ts
import { createUnitLayoutLint } from "@univer-cli/unit-layout-lint";

const lint = createUnitLayoutLint({ runtime: renderRuntime });
const report = await lint.lint({
  unitType: "slide",
  unitData,
  pages: [1, "closing-slide"],
});
```

Les règles actuelles sont les suivantes:

- `text-off-page` : l'encre de texte s'étend au-delà de la page.
- `text-escapes-container` : le texte sort visiblement d’un conteneur opaque plus petit.
- `text-overlaps-text` : deux zones réelles de texte se chevauchent nettement.

Une conclusion est une suggestion d'examen appuyée par des preuves, et il ne nécessite pas toujours de changement. L'agent peut combiner les constatations avec des captures d'écran, faire une autre modification Facade, et effectuer une inspection visuelle à nouveau.

## Étape 6 : ajouter les commandes Commander

Capture d'écran et Layout Lint fournissent tous deux des presets natifs Commander. Passez les capacités construites ci-dessus et les chargeurs UnitData de l'application, puis ajoutez les commandes à la même `program` créée en [Opérations de chargement et de contenu des documents](/ai/content-operations):

```ts
import type { UnitScreenshotCommandDependencies } from "@univer-cli/unit-screenshot-command";
import { createUnitScreenshotCommand } from "@univer-cli/unit-screenshot-command";
import type { UnitLayoutLintCommandDependencies } from "@univer-cli/unit-layout-lint-command";
import { createUnitLayoutLintCommand } from "@univer-cli/unit-layout-lint-command";
import type { Command } from "commander";

function addVisualCommands(
  program: Command,
  dependencies: {
    loadUnit: UnitScreenshotCommandDependencies["loadUnit"];
    writeImages: UnitScreenshotCommandDependencies["writeImages"];
    loadSlide: UnitLayoutLintCommandDependencies["loadUnit"];
  },
): void {
  program.addCommand(
    createUnitScreenshotCommand({
      screenshot,
      loadUnit: dependencies.loadUnit,
      writeImages: dependencies.writeImages,
    }),
  );

  program.addCommand(
    createUnitLayoutLintCommand({
      lint,
      loadUnit: dependencies.loadSlide,
    }),
  );
}
```

Les préréglages possèdent les sélecteurs de capture d'écran, les sélecteur de page de diapositives, `--json`, la sortie texte par défaut et les sorties d'erreur Commander. Les paramètres de fonction injectent le mappage de l'ID d'unité à l'état de contenu et l'auteur PNG. L'application possède également le cycle de vie Render Runtime.

Le preset Screenshot peut également inclure une sous-commande pour l'installation et l'étude du navigateur. Un navigateur n'est pas téléchargé implicitement pour chaque capture.

## Étape 7 : libérer les ressources navigateur

Le créateur ferme le Render Runtime à la limite du cycle de vie Commander:

```ts
try {
  await program.parseAsync();
} finally {
  await renderRuntime.close();
}
```

Pour l'entrée et la sortie personnalisées de l'agent, contournez les préréglages et appelez les paquets de base directement. Ne rendez pas non-confiance UnitData directement sur un hôte partagé à haut privilège. Utilisez un utilisateur restreint, un conteneur ou une autre limite d'isolement de processus.

Une fois les contrôles visuels disponibles, ajoutez le même contenu et les mêmes capacités d'inspection au flux [Worktree : édition d'agents et révision humaine](/ai/worktree).
