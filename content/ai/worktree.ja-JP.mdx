Worktree[^document-worktree]は、分離された編集スペースを持つエージェントを提供します。 ドラフトの中に、エージェントは、必要に応じて多くのラウンドをプル、検査、実行し、コミットすることができ、そして構造と視覚的なチェックパスを一度Worktree準備をマークします。 人は、Webを介してレンダリングされたページをレビューし、マージまたはリオープンを選択します。

```text
Worktree 作成
→ AI Agent が下書きを編集
→ 構造化・視覚的検査
→ Ready
→ Web で人がレビュー
→ Merge / Reopen
→ trunk
```

## Worktree を使う理由

- エージェントによる中級編集はトランクに達しません。
- 各ドラフトには、独自のスナップショット、チェンジセット、リビジョン、プレゼンス、およびリアルタイムルームがあります。
- エージェントは、結果を提示する前に複数のラウンドを同期、編集、検証することができます。
- Ready は現在のリビジョンでドラフトを凍結し、明示的なレビュー境界を確立します。
- ユーザーは、Webを通じて編集、マージ、または再開を見直し、継続することができます。
- マージは引き続き、トランクコラボレーションサービス自体の認可とコミット境界を通過します。

## 全体の流れ

```text
Worktree を作成／選択
→ Worktree Unit を選択
→ Collaboration Runtime で読み込み
→ pull
→ inspect
→ api find / show
→ execute(write)
→ runtime.commit()
→ inspect + screenshot + layout lint
→ markReady
→ Web レビュー
→ merge / reopen
```

[文書の読み込みとコンテンツの操作](/ai/content-operations)、[オフィスファイルのインポートとエクスポート](/server/import-export/node)、[外観検査](/ai/visual-inspection) が動作し、Worktree ターゲットで同じ機能を指す。これは推奨するエージェントの編集フローを生成します。

## Worktree の対象

Collaboration Runtimeは、単一のユニットのスナップショット、チェンジセット、およびリビジョンで動作し、Worktreeの概念はありません。アプリケーションアダプタは、Worktreeエンドポイントのスナップショットや送信、WebSocket、セッションチケットURLに`worktreeID + unitID`をマップし、それらのURLをランタイムバックエンドに渡します。

```text
worktreeID + unitID
→ アプリケーションの対象アダプター
→ Worktree プロトコル URL
→ Collaboration Runtime
```

同じランタイムの実行モデルは、トランクまたは分離されたWorktreeのドラフトに接続します。

## 下書きでの AI Agent 操作

Worktree Unit でも通常の Unit と同じ基本ループを使います。

```text
load → pull → inspect → execute(write) → commit
```

既成の Inspection 入口には、`@univer-cli/content-inspection-command` の 2 つのファクトリーがあります。

- `createContentInspectionCommand()`は普通単位のターゲットに合わせます。
- `createWorktreeContentInspectionCommand()` は、発信者が明示的に `--trunk`、`--worktree <id>`. を選択しなければならない場合に適用される。

アプリケーションは、実行、スクリーンショット、その他のコマンドに同じ種類のターゲット選択を適用し、選択したランタイムの買収およびリリースを所有しています。

## Commander で Worktree を選ぶ

検査プリセットには、`--trunk`または`--worktree <id>`のいずれかを選択するための呼び出し器を必要とするWorktreeの変形があります。

```ts
import type { WorktreeContentInspectionCommandDependencies } from "@univer-cli/content-inspection-command";
import { createWorktreeContentInspectionCommand } from "@univer-cli/content-inspection-command";
import { Command } from "commander";

function addWorktreeCommands(
  program: Command,
  dependencies: {
    acquireRuntime: WorktreeContentInspectionCommandDependencies["acquireRuntime"];
    markReady(worktreeID: string): Promise<void>;
  },
): void {
  program.addCommand(
    createWorktreeContentInspectionCommand({
      acquireRuntime: dependencies.acquireRuntime,
    }),
  );

  const worktreeCommand = new Command("worktree");
  worktreeCommand
    .command("ready")
    .argument("<worktree-id>")
    .action(async (worktreeID) => {
      await dependencies.markReady(worktreeID);
    });

  program.addCommand(worktreeCommand);
}
```

`acquireRuntime`と`markReady`は、AI SDK内部に隠れるヘルパーではなく、明示的に宣言されたアプリケーション依存関係です。 以前のセクションで説明された実行時間にWorktreeターゲットからマッピングを実施します。 後者はCollaboration SDK Worktreeクライアントを呼び出します。

実行、スクリーンショット、およびレイアウトのlintコマンドは、同じターゲットモデルを使用する必要があります。 それ以外の場合は、1つのユニットIDは、異なるトランクまたはターゲットをドラフトに解決できます。 Webは、同じWorktreeクライアントでReopen、Discover、Merge、および実際のページレビューを公開することができます。 製品は、必要なときに追加のCommanderサブコマンドでそれらの操作の一部をラップすることができます。

## AI Agent の検査

Ready 前には 2 種類の検査を組み合わせられます。

```text
構造化検査：pull → inspect
視覚的検査：Unit → Render Runtime → screenshot / layout lint
```

- 検査は、ワークブック、ワークシート、レンジ、ドキュメント、パラグラフ、プレゼンテーション、スライドの構造化されたコンテンツを検証します。
- Screenshotは、エージェントがレビューするレンダリングされたページを提供します。
- Layout Lintは、スライド上のレイアウトの問題を診断します。
- 問題が見つかれば再び実行、コミット、検査できます。

## Commit、Ready、Merge の違い

| 操作 | 意味 |
| --- | --- |
| `runtime.commit()` | Worktreeのドラフトに現在の変異によって生成されたチェンジセットを提出する |
| `markReady()` | 各 Unit の現在の下書きリビジョンを固定して `ready` にする |
| `reopenWorktree()` | `ready`から`draft`に戻り、編集を続けます |
| `mergeWorktree()` | Worktree の Units を順に trunk へマージ |

`runtime.commit()`は、ドラフトだけを進めます。トランクにマージしません。Readyは、エージェントの作業をレビューに移しますが、結果はトランクに達する前にWorktreeマージを必要とします。

## Web での人によるレビュー

ウェブは、WorktreeクライアントとWorktreeコラボレーションの設定と同じドラフトをロードします。レビュー表面は、次のことができます。

- Worktreeの現在の状態。
- ユニットのレンダリングされたページをドラフトに表示します。
- trunk と下書きの切り替え。
- 各ユニットのプレビューをマージします。
- Ready、Reopen、Discard、Merge 操作。

Ready のドラフトは読み取り専用です。 人やエージェントが再び編集する前に、Draft に再オープンします。 承認後、Merge はトランクに戻り、統合された結果をチェックします。

## Collaboration SDK の境界

Worktreeサービス、エンドポイント、クライアント、およびデータベースアダプタはCollaboration SDKに属しています。 AI SDKは、互換性のあるユニットランタイム、検査、API参照、実行、およびスクリーンショット機能を提供します。 このアプリケーションは、Worktreeのライフサイクルコマンド、ターゲットマッピング、アイデンティティ、および認可を所有しています。

サーバー構成、ライフサイクル、マージ制約は[共同編集の拡張](/server/collaboration/extensions)を参照してください。

[^document-worktree]: この Worktree は文書内容の独立した共同編集ドラフトです。Git worktree やソースコードのチェックアウトではありません。変更はレビューとマージを経て主系統に反映されます。
