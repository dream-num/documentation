Worktree[^document-worktree]는 격리한 편집 공간을 가진 대리인을 제공합니다. 초안 안쪽에, 대리인은, 검사하고, 실행할 수 있고, 그것을 필요로 한 많은 둥근을 위해 투입하고, 그 후에 Worktree를 한 번 구조화하고 시각적인 체크 통행을 표시하십시오. 그 사람은 웹을 통해 연출한 페이지를 검토하고 Merge 또는 Reopen을 선택합니다.

```text
Worktree 생성
→ AI Agent 초안 편집
→ 구조화 및 시각 검사
→ Ready
→ 사람이 Web에서 검토
→ Merge / Reopen
→ trunk
```

## Worktree를 사용하는 이유

- Intermediate는 에이전트가 트렁크에 도달하지 않는 편집합니다.
- 각 초안에는 자체 스냅샷, 변경세트, 개정, 사전, 실시간 객실이 있습니다.
- 에이전트는 동기화 할 수, 편집, 그리고 결과를 제시하기 전에 여러 라운드를 확인합니다.
- 현재 개정판에서 초안을 동결하고 명시된 검토 경계를 수립합니다.
- 웹을 통해 한 사람이 검토, 계속 편집, Merge, 또는 Reopen 할 수 있습니다.
- Merge는 여전히 권한 부여를 통과하고 트렁크 협업 서비스의 경계를 커밋합니다.

## 전체 흐름

```text
Worktree 생성 / 선택
→ Worktree Unit 선택
→ Collaboration Runtime 로드
→ pull
→ inspect
→ api find / show
→ execute(write)
→ runtime.commit()
→ inspect + screenshot + layout lint
→ markReady
→ Web 검토
→ merge / reopen
```

[문서 로딩 및 콘텐츠 작업](/ai/content-operations), [Office 파일 가져 오기 및 내보내기](/server/import-export/node) 및 [비주얼 검사](/ai/visual-inspection)가 작동되면 Worktree 대상에서 동일한 기능을 점합니다. 추천된 에이전트 편집 흐름을 생성합니다.

## Worktree 대상

Collaboration Runtime는 스냅 샷, 변경 세트 및 단일 단위의 개정에 작동하며 Worktree의 개념이 없습니다. 응용 어댑터 맵 `worktreeID + unitID`를 Snapshot, 제출, WebSocket 및 Worktree 엔드 포인트의 세션 티켓 URL에 복사 한 다음 런타임 백엔드에 URL을 전달합니다.

```text
worktreeID + unitID
→ 애플리케이션 대상 어댑터
→ Worktree 프로토콜 URL
→ Collaboration Runtime
```

동일한 실행 실행 모델은 따라서 트렁크 또는 격리 된 Worktree 초안으로 연결됩니다.

## 초안에서 AI Agent 작업

Worktree Unit도 일반 Unit과 같은 핵심 루프를 사용합니다.

```text
load → pull → inspect → execute(write) → commit
```

준비된 Inspection 진입점으로 `@univer-cli/content-inspection-command`가 두 팩터리를 제공합니다.

- `createContentInspectionCommand()`는 정규적인 단위 표적에 적용합니다.
- `createWorktreeContentInspectionCommand()`는 콜러가 `--trunk` 또는 `--worktree <id>`를 명시적으로 선택할 때 적용됩니다.

이 응용 프로그램은 실행, 스크린 샷 및 기타 명령에 대한 대상 선택의 동일한 종류를 적용하고 선택한 실행 시간의 취득 및 릴리스를 소유합니다.

## Commander에서 Worktree 선택

검사 preset에는 `--trunk` 또는 `--worktree <id>` 중 하나를 선택하는 콜러가 필요한 Worktree 변형이 있습니다.

```ts
import type { WorktreeContentInspectionCommandDependencies } from "@univer-cli/content-inspection-command";
import { createWorktreeContentInspectionCommand } from "@univer-cli/content-inspection-command";
import { Command } from "commander";

function addWorktreeCommands(
  program: Command,
  dependencies: {
    acquireRuntime: WorktreeContentInspectionCommandDependencies["acquireRuntime"];
    markReady(worktreeID: string): Promise<void>;
  },
): void {
  program.addCommand(
    createWorktreeContentInspectionCommand({
      acquireRuntime: dependencies.acquireRuntime,
    }),
  );

  const worktreeCommand = new Command("worktree");
  worktreeCommand
    .command("ready")
    .argument("<worktree-id>")
    .action(async (worktreeID) => {
      await dependencies.markReady(worktreeID);
    });

  program.addCommand(worktreeCommand);
}
```

`acquireRuntime` 및 `markReady`는 AI SDK 내부에 숨겨지지지지 않는 신청 의존성입니다. 이전은 Worktree 타겟에서 맵핑을 구현하여 이전 섹션에 설명되어 있습니다. 후자는 Collaboration SDK Worktree 클라이언트를 호출합니다.

실행, 스크린 샷 및 레이아웃 lint 명령은 동일한 대상 모델을 사용해야합니다. 그렇지 않으면 하나의 단위 ID는 다른 트렁크 또는 초안 대상에 해결할 수 있습니다. 웹은 Reopen, Discard, Merge 및 같은 Worktree 클라이언트의 실제 페이지 검토를 노출 할 수 있습니다. 제품에는 필요에 따라 추가 Commander 하위 commands에서 이러한 작업의 일부를 포장 할 수 있습니다.

## AI Agent 검사

Ready 전에 두 종류의 검사를 조합할 수 있습니다.

```text
구조화 검사: pull → inspect
시각 검사: Unit → Render Runtime → screenshot / layout lint
```

- 검사는 Workbook, Worksheet, Range, Document, Paragraph, Presentation 또는 Slide의 구조화 된 내용을 확인합니다.
- 스크린 샷은 에이전트에 대한 렌더링 된 페이지를 제공합니다.
- Layout Lint는 슬라이드에 레이아웃 문제를 진단합니다.
- 문제가 발견되면 AI Agent가 실행, 커밋, 검사를 반복할 수 있습니다.

## Commit, Ready, Merge 구분

| 작업 | 의미 |
| --- | --- |
| `runtime.commit()` | Worktree 초안의 현재 mutations에 의해 생성 된 변경 사항 제출 |
| `markReady()` | 각 Unit의 현재 초안 리비전을 고정하고 `ready` 진입 |
| `reopenWorktree()` | `ready`에서 `draft`로 변환 |
| `mergeWorktree()` | Worktree Unit을 하나씩 trunk에 병합 |

`runtime.commit()`는 단지 초안을 전진합니다. 그것은 간선으로 합병하지 않습니다. 준비는 대리인의 일을 검토로 움직입니다, 그러나 결과는 아직도 간선에 도달하기 전에 Worktree Merge를 요구합니다.

## Web에서 사람의 검토

웹은 Worktree 클라이언트와 Worktree 협업 구성과 동일한 초안을로드합니다. 리뷰 표면은 다음과 같습니다.

- Worktree의 현재 상태.
- 초안의 단위의 렌더링 된 페이지.
- trunk와 초안 전환.
- 각 단위의 병합 미리보기.
- Ready, Reopen, Discard, Merge 작업.

Ready의 초안은 읽기 전용입니다. 한 사람이나 에이전트가 다시 편집하기 전에, Draft로 다시 열었습니다. 승인 후, Merge는 통합 결과를 검사하기 위해 트렁크로 전환합니다.

## Collaboration SDK 경계

Worktree 서비스, 엔드포인트, 클라이언트 및 데이터베이스 어댑터는 Collaboration SDK에 속합니다. AI SDK는 작곡 가능한 단위 런타임, 검사, API 참조, 실행 및 스크린 샷 기능을 제공합니다. 이 응용 프로그램은 Worktree 라이프 사이클 명령, 타겟 매핑, 정체성 및 권한 부여를 소유합니다.

서버 구성, 수명 주기, 병합 제약은 [공동 편집 확장](/server/collaboration/extensions)을 참고하세요.

[^document-worktree]: 여기서 Worktree는 문서 내용의 독립된 협업 초안입니다. Git worktree나 소스 코드 체크아웃이 아닙니다. 변경 사항은 검토와 병합을 거쳐야 본선에 반영됩니다.
