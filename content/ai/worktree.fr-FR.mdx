Worktree[^document-worktree] fournit à un agent un espace d'édition isolé. À l'intérieur d'un brouillon, l'agent peut tirer, inspecter, exécuter et commit pour autant de tours qu'il en a besoin, puis marquer le Worktree Prêt une fois la vérification structurée et visuelle passée.

```text
créer un Worktree
→ édition du brouillon par AI Agent
→ contrôles structurés et visuels
→ Ready
→ revue humaine dans Web
→ Merge / Reopen
→ trunk
```

## Pourquoi Worktree

- Les modifications intermédiaires de l'agent n'atteignent jamais le coffre.
- Chaque brouillon a ses propres Snapshots, changeets, révisions, Présence et chambres en temps réel.
- L'agent peut synchroniser, modifier et vérifier plusieurs tours avant de présenter un résultat.
- Prêt à geler le projet lors de sa révision actuelle et à établir une limite d'examen explicite.
- Une personne peut réviser, continuer à éditer, fusionner ou réouvrir sur le Web.
- Merge passe toujours par l'autorisation et s'engage dans les limites du service de collaboration du tronc lui-même.

## Parcours complet

```text
créer / sélectionner un Worktree
→ sélectionner une Unit Worktree
→ chargement par Collaboration Runtime
→ pull
→ inspect
→ api find / show
→ execute(write)
→ runtime.commit()
→ inspect + screenshot + layout lint
→ markReady
→ revue Web
→ merge / reopen
```

Une fois que [Opérations de chargement et de contenu des documents](/ai/content-operations), [Importation et exportation de fichiers bureautiques](/server/import-export/node) et [Contrôle visuel](/ai/visual-inspection) fonctionnent, pointez les mêmes capacités à une cible Worktree. Cela produit le flux d'édition d'agents recommandé.

## Cible Worktree

Collaboration Runtime fonctionne sur le Snapshot, les modifications et la révision d'une unité unique, et il n'a pas de concept d'un Worktree. L'adaptateur d'application map `worktreeID + unitID` à la Snapstop, Submit, WebSocket et les URL de ticket de session du point d'extrémité Worktree, puis passe ces URL à l'arrière-plan d'exécution.

```text
worktreeID + unitID
→ adaptateur de cible applicatif
→ URL du protocole Worktree
→ Collaboration Runtime
```

Le même modèle d'exécution d'exécution se connecte donc soit au tronc, soit à un projet isolé de Worktree.

## Opérations d’un AI Agent dans un brouillon

Le même cycle s’applique aux Units ordinaires et Worktree :

```text
load → pull → inspect → execute(write) → commit
```

Pour une entrée Inspection prête à l’emploi, `@univer-cli/content-inspection-command` fournit deux fabriques :

- `createContentInspectionCommand()` s'applique à une cible ordinaire de l'unité.
- `createWorktreeContentInspectionCommand()` s'applique lorsque l'appelant doit choisir explicitement `--trunk` ou `--worktree <id>`.

L'application applique le même type de sélection de cible aux commandes exécuter, screenshot et autres, et elle possède l'acquisition et la sortie de l'exécution sélectionnée.

## Choisir un Worktree dans Commander

Le préréglage d'inspection comporte une variante Worktree qui oblige l'appelant à choisir `--trunk` ou `--worktree <id>` :

```ts
import type { WorktreeContentInspectionCommandDependencies } from "@univer-cli/content-inspection-command";
import { createWorktreeContentInspectionCommand } from "@univer-cli/content-inspection-command";
import { Command } from "commander";

function addWorktreeCommands(
  program: Command,
  dependencies: {
    acquireRuntime: WorktreeContentInspectionCommandDependencies["acquireRuntime"];
    markReady(worktreeID: string): Promise<void>;
  },
): void {
  program.addCommand(
    createWorktreeContentInspectionCommand({
      acquireRuntime: dependencies.acquireRuntime,
    }),
  );

  const worktreeCommand = new Command("worktree");
  worktreeCommand
    .command("ready")
    .argument("<worktree-id>")
    .action(async (worktreeID) => {
      await dependencies.markReady(worktreeID);
    });

  program.addCommand(worktreeCommand);
}
```

`acquireRuntime` et `markReady` sont des dépendances d'applications déclarées explicitement ici, et non des helpers cachés à l'intérieur de AI SDK. L'ancien implémente la cartographie de la cible Worktree à l'exécution décrite dans la section précédente; ce dernier appelle le client Collaboration SDK Worktree .

Les commandes d'exécution, de capture d'écran et de mise en page doivent utiliser le même modèle cible; autrement, un ID d'unité peut résoudre à différentes cibles de tronc ou d'ébauche. Web peut exposer la réouverture, le rejet, la fusion et la révision de page réelle sur le même client Worktree. Un produit peut envelopper certaines de ces opérations dans des sous-commandes Commander supplémentaires quand il en a besoin.

## Contrôles de l’AI Agent

Avant Ready, combinez deux types de contrôles :

```text
contrôle structuré : pull → inspect
contrôle visuel : Unit → Render Runtime → screenshot / layout lint
```

- L'inspection vérifie le contenu structuré d'un cahier de travail, d'une feuille de travail, de la gamme, du document, du paragraphe, de la présentation ou de la diapositive.
- Capture d'écran fournit la page rendue pour l'agent à examiner.
- Layout Lint diagnostique les problèmes de mise en page sur une diapositive.
- En cas de problème, l’AI Agent peut exécuter, committer et vérifier à nouveau.

## Distinguer Commit, Ready et Merge

| Opération | Signification |
| --- | --- |
| `runtime.commit()` | Soumettre le jeu de modifications produit par les mutations actuelles à l'ébauche Worktree |
| `markReady()` | Figer la révision du brouillon de chaque Unit et passer à `ready` |
| `reopenWorktree()` | Retour de `ready` vers `draft` pour continuer à éditer |
| `mergeWorktree()` | Fusionner les Units Worktree une par une dans le trunk |

`runtime.commit()` avance seulement le brouillon. Il ne fusionne pas dans le tronc. Ready déplace le travail de l'agent dans l'examen, mais le résultat nécessite toujours une fusion Worktree avant qu'il atteigne le tronc.

## Revue humaine dans Web

Web charge le même brouillon avec le client Worktree et la configuration de collaboration Worktree. Une surface d'examen peut présenter:

- L'état actuel du Worktree.
- La page rendue d'une unité dans le projet.
- Le passage entre trunk et brouillon.
- Un aperçu de fusion pour chaque unité.
- Les opérations Ready, Reopen, Discard et Merge.

Avant qu'une personne ou un agent ne réédite, réouvrez-la à nouveau. Après approbation, fusionnez, puis retournez dans le coffre pour inspecter le résultat intégré.

## Frontière avec Collaboration SDK

Worktree Service, Endpoint, Client et Database Adapter appartiennent à Collaboration SDK. AI SDK fournit les capacités d'exécution, d'inspection, de référence API, d'exécution et de capture d'écran. L'application possède les commandes de cycle de vie Worktree, la cartographie des cibles, l'identité et l'autorisation.

Consultez les [extensions collaboratives](/server/collaboration/extensions) pour la composition serveur, le cycle de vie et les contraintes de fusion.

[^document-worktree]: Ce Worktree est un brouillon collaboratif isolé du contenu d’un document, pas un worktree Git ni une copie de sources. Les modifications rejoignent le tronc après révision et fusion.
