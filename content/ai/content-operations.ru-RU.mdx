## Минимальный путь работы AI Agent с содержимым

Для каждой команды контента бизнес CLI загружает целевой Unit[^document-unit] и синхронизирует его с последним контентом.С точки зрения агента типичная операция с контентом протекает следующим образом:

<Mermaid chart={"flowchart LR\n    Task([Получить задачу]) --> Inspect[\"inspect<br/>Понять структуру и содержимое\"]\n    Inspect --> API[\"api find / api show<br/>По необходимости: API неизвестен\"]\n    API --> Read[\"execute · read<br/>По необходимости: вне Inspection\"]\n    Read --> Write[\"execute · write<br/>Изменить и зафиксировать\"]\n    Write --> Review[\"inspect / execute · read<br/>Проверить по той же границе\"]\n    Review --> Done([Готово])"} />

Узел `api find`/`api show`, режим чтения и окончательный обзор являются единственными условными шагами. Агент выбирает возможности в соответствии со следующей границей:

| Цель AI Agent | Предпочтительная возможность |
| --- | --- |
| Понять структуру и распределение основного содержимого | Обзор `inspect` |
| Прочитать стандартные Range, Paragraph или Slide | Селектор `inspect` |
| Прочитать условное форматирование, конфигурацию Chart и другие пробелы | `execute --mode read` |
| Найти или подтвердить незнакомый Facade API | `api find` / `api show` |
| Изменить и зафиксировать документ | `execute --mode write` |
| Проверить результат | `inspect` / `execute --mode read` |

### Пример: обновление диапазона Sheet

Рассмотрим задачу, которая обновляет `Data!A2:B2` в `book-1` до `[["East", 128000]]`. Предполагая, что бизнес-клиент был собран, как описано ниже на этой странице, агент действует следующим образом.

1. Используйте Инспекции, чтобы понять Рабочую тетрадь и целевой диапазон:

```bash
UNIT_ID="book-1"
my-cli inspect workbook --unit "$UNIT_ID" --json
my-cli inspect range A1:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

2. Чтобы продемонстрировать API Reference, предположим, что агент не знает `setValues` и должен подтвердить свою подпись:

```bash
my-cli api find setValues --unit sheet
my-cli api show FWorkbook.getSheetByName FWorksheet.getRange FRange.setValues
```

3. Запустите код Facade в режиме записи. Команда `execute` приложения обрабатывает фиксацию:

```bash
my-cli execute --unit "$UNIT_ID" --mode write \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
sheet.getRange("A2:B2").setValues([["East", 128000]]);'
```

4. Решите, стоит ли пересматривать исходя из риска задачи. Инспекция охватывает значения Диапазона, поэтому прочитайте Диапарат еще раз:

```bash
my-cli inspect range A2:B2 --worksheet name:Data --unit "$UNIT_ID" --json
```

Эта задача не требует режима чтения, потому что Инспекция может читать Диапазон как до, так и после записи. Режим чтения зарезервирован для контента, который Инспекция не охватывает, например, примеры условного форматирования и конфигурации диаграммы ниже.

## Сборка возможностей в бизнес-CLI

Этот раздел начинается с `@univer-cli/univer-collaboration-runtime` и добавляет Инспекции, API Reference и Content Execution. Сниппеты представляют основной интерфейс каждой возможности. Конфигурация сервера, идентификация, представление ошибок и аргументы команд остаются ответственностью приложения.

Каждый шаг регистрируется в одной корневой программе Commander:

```ts
import { Command } from "commander";

const program = new Command("my-cli");

// Register the inspect, execute, and api commands introduced below here.
// Parse CLI arguments only after every command has been registered.
await program.parseAsync();
```

### 1. Загрузка совместной Unit

Collaboration Runtime[^live-runtime] служит двум целям для агента, работающего в Node.js: он выполняет Блок, и он действует как клиент совместной работы.

```ts
import {
  createCollaborationServerAdapter,
  createUniverCollaborationRuntimeFactory,
} from "@univer-cli/univer-collaboration-runtime";
import { UniverInstanceType } from "@univerjs/core";

const factory = createUniverCollaborationRuntimeFactory({
  backend: createCollaborationServerAdapter({
    snapshotServerUrl,
    collabSubmitChangesetUrl,
    collabWebSocketUrl,
    wsSessionTicketUrl,
  }),
  createUniver: headlessUniverFactory,
});

const unitId = "book-1";
const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
```

Приложение впрыскивает `headlessUniverFactory`, который является либо стандартной реализацией от `@univer-cli/headless-univer` или пользовательской композицией; на этой странице опущены детали инициализации. Приложение также отображает конфигурацию сервера, идентичность и цель блока на адреса протокола, требуемые адаптером. Время выполнения загружает Snapshot, обновляет изменения и изменения и обеспечивает среду выполнения Facade.

Основными API Runtime являются:

| API | Назначение |
| --- | --- |
| `pull()` | Получить удалённые изменения, согласовать через OT и обновить Unit |
| `execute({ mode, code })` | Выполнить Facade: `read` читает, `write` создаёт мутации |
| `commit()` | Вручную отправить текущие ожидающие мутации |
| `exportUnitData()` | Выгрузить полный текущий UnitData Runtime |
| `getState()` | Прочитать ревизию, соединение, ожидание и конфликты |
| `close()` | Освободить дескриптор backend и headless Univer |

### 2. Изучение содержимого через Inspection

Общие задачи чтения не требуют от агента написания кода Facade. `@univer-cli/content-inspection` возвращает структурированные результаты только для чтения:

| Unit | Обзор Inspection | Чему быстро учится агент |
| --- | --- | --- |
| Sheet | Книга | Идентификаторы листов, используемые диапазоны, сводки Table, Rule и Drawing |
| Doc | Документ | Режим, индекс абзацев, текстовые превью и количество возможностей |
| Slide | Презентация | Индекс слайдов, превью текста, число элементов, размер и число Layouts |

Collaboration Runtime уже удовлетворяет интерфейсу выполнения только для чтения, который, как ожидает Инспекция:

```ts
import { inspectContent } from "@univer-cli/content-inspection";

const workbook = await inspectContent(
  {
    unitId: runtime.unitId,
    unitType: "sheet",
    execute: async (input) => {
      const result = await runtime.execute(input);
      return { value: result.value };
    },
  },
  { kind: "workbook" },
);
```

`inspectContent()` компилирует `unitId` в программу Фасада только для чтения и находит целевую Рабочую книгу через `univerAPI.getWorkbook(unitId)`. `unitType` проверяет, что запрос соответствует типу Unit.

Начните с обзорного запроса, чтобы установить структуру блока и основной контент, затем используйте рабочий лист, диапазон, абзац и селекторы слайдов для стандартного контента, который охватывает проверка. Когда требуемая конфигурация или деталь отсутствуют в результатах проверки, таких как полное правило условного форматирования или конфигурация диаграммы, выдайте один небольшой целевой запрос через `execute({ mode: "read" })`.

Для опыта Commander по умолчанию добавьте предустановку `inspect`. Приложение должно только обеспечить аренду Runtime:

```ts
import type { ContentInspectionLease } from "@univer-cli/content-inspection-command";
import { createContentInspectionCommand } from "@univer-cli/content-inspection-command";

program.addCommand(
  createContentInspectionCommand({
    async acquireRuntime({ unitId }) {
      const runtime = await factory.load(unitId, UniverInstanceType.UNIVER_SHEET);
      await runtime.pull();

      const lease: ContentInspectionLease = {
        unitId,
        unitType: "sheet",
        execute: async (input) => {
          const result = await runtime.execute(input);
          return { value: result.value };
        },
        invalidate: () => runtime.close(),
        release: () => runtime.close(),
      };

      return lease;
    },
  }),
);
```

`acquireRuntime` — это поле общедоступной зависимости пресета, и его значение возврата должно соответствовать `ContentInspectionLease`. В этом примере нет пула, поэтому `invalidate()` и `release()` сразу замыкают эксклюзивное Runtime. Предустановленный обрабатывает селекторный анализ, вывод текста или JSON и лизинг. Картирование цели, инициализация Runtime, аутентификация и удаленная загрузка остаются с приложением. Для протокола пользовательского агента звоните `inspectContent()` напрямую.

### 3. Поиск и изучение Facade API

Когда агент знает задачу, но не соответствующий Facade API, используйте `@univer-cli/api-reference`. Он поставляется с текущим SDK, не загружает блок и не связывается с онлайн-службой документации.

```ts
import { createStandardApiReference } from "@univer-cli/api-reference";

const reference = createStandardApiReference();

const matches = reference.find({
  terms: ["setValues", "conditional formatting"],
  unit: "sheet",
  limit: 20,
});

const details = reference.show(["FRange", "FRange.setValues", "ICellData.v"]);
```

- `find()` превращает термины, ориентированные на задачи, в символы кандидатов.
- `show()` возвращает точные сведения о классе, члене, типе или enum.
- `@univer-cli/api-reference-command` добавляет дополнительные предустановки `api find` и `api show`.

Для регистрации той же ссылки с Commander:

```ts
import { createApiCommand } from "@univer-cli/api-reference-command";

program.addCommand(createApiCommand({ reference }));
```

Ссылка на API появляется перед выполнением: агент проверяет текущий контент, находит или показывает требуемый API, затем пишет и запускает код Facade.

### 4. Выполнение чтения и записи Facade

Для произвольных считываний и модификаций используйте Collaboration Runtime `execute()`. `@univer-cli/content-execution` связывает Facade JavaScript с конкретным блоком и впрыскивает стабильные связывания для этого типа блока:

```ts
import { prepareContentExecutionProgram } from "@univer-cli/content-execution";

const executionProgram = prepareContentExecutionProgram({
  unitId,
  unitType: "sheet",
  code: 'workbook.getActiveSheet().getRange("A1").setValue("done");',
});

const execution = await runtime.execute({
  mode: "write",
  code: executionProgram,
});
```

- `mode: "read"` позволяет выполнять произвольные запросы только для чтения и блокирует мутации.
- `mode: "write"` захватывает мутации Фасада и добавляет их в локальное состояние Runtime.
- Успешный запуск означает, что код запущен. Это не означает, что набор изменений достиг сервера.

`content-execution` производит только программу исполнения. Он никогда не приобретает Runtime, не отправляет пакеты изменений или не отправляет общедоступный пакет предварительного набора команд `execute`. Поэтому бизнес-клиент заворачивает его в команду Commander приложения:

```ts
const executeCommand = new Command("execute")
  .requiredOption("--unit <id>")
  .requiredOption("--code <javascript>")
  .option("--mode <read|write>", "execute without or with mutations", "write")
  .action(async ({ unit, code, mode }) => {
    if (mode !== "read" && mode !== "write") {
      throw new Error("--mode must be read or write");
    }

    const runtime = await factory.load(unit, UniverInstanceType.UNIVER_SHEET);
    try {
      await runtime.pull();
      const executionProgram = prepareContentExecutionProgram({
        unitId: unit,
        unitType: "sheet",
        code,
      });
      const execution = await runtime.execute({ mode, code: executionProgram });

      if (mode === "read") {
        process.stdout.write(`${JSON.stringify(execution.value, null, 2)}\n`);
        return;
      }

      let committed = await runtime.commit();
      if (committed.status === "pull-required") {
        await runtime.pull();
        committed = await runtime.commit();
      }
      if (committed.status !== "confirmed") {
        throw new Error(`Commit failed: ${committed.status}`);
      }

      process.stdout.write(
        `${JSON.stringify(
          {
            commit: committed.status,
            mutations: execution.mutations.length,
            revision: committed.state.baseRevision,
            value: execution.value,
          },
          null,
          2,
        )}\n`,
      );
    } finally {
      await runtime.close();
    }
  });

program.addCommand(executeCommand);
```

Эта команда по умолчанию пишет режим. Режим чтения печатает возвращаемое значение кода Facade и ничего больше: никаких мутаций и никакого `commit()`. Режим записи печатает количество мутационных изменений, пересмотр и возвращаемое значение только после подтверждения факта передачи, поэтому агент может определить точный результат представления. Commander владеет аргументами и жизненным циклом команды. Приложению принадлежат приобретение Runtime, совершение повторов, представление ошибок и политика авторизации. Этот минимальный фрагмент фиксируется на листе; когда приложение поддерживает Doc, Slide, Base или Board, добавьте явное отображение из типов CLI Unit в `UniverInstanceType` .

#### Чтение только для содержимого вне Inspection

Инспекция сообщает, сколько условно-форматирующих правил содержит Рабочий лист, но не полная конфигурация каждого правила.Когда агенту нужна эта деталь, он подтверждает API и запускает минимальный фрагмент Фасада в режиме чтения:

```bash
my-cli api find getConditionalFormattingRules --unit sheet
my-cli api show FWorksheet.getConditionalFormattingRules

my-cli execute --unit "$UNIT_ID" --mode read \
  --code 'const sheet = workbook.getSheetByName("Data");
if (!sheet) throw new Error("Worksheet Data not found");
return sheet.getConditionalFormattingRules();'
```

Инспекция также сообщает, сколько диаграмм содержит рабочий лист. Когда задача требует полной конфигурации диаграммы, сфокусированный запрос может вернуть `sheet.getCharts().map((chart) => chart.getInfo())`. Режим чтения никогда не производит мутаций; его роль заключается в заполнении пробелов, которые оставляет инспекция, а не в замене инспекции.

## Итог

Одна программа Commander теперь объединяет Collaboration Runtime, Inspection, API Reference и Content Execution. Время выполнения загружает и синхронизирует блок, выполняет код Facade и совершает по запросу. Inspection обеспечивает структурированные чтения. API Reference помогает агенту найти правильный Facade API . Commander раскрывает все это через одну точку входа CLI.

Типичная операция начинается с `inspect` для установления структуры, основного контента и стандартных деталей, которые уже охватывает Инспекция. Когда API неясен, используйте `api find` / `api show`. Используйте режим чтения только для конфигурации или детали, которые Инспекция не охватывает, затем редактируйте и фиксируйте в режиме записи. Обзор следует той же границе Инспекции.
