Univer Office SDK는 세 부분으로 구성됩니다. [Web SDK](/guides/sheets)는 브라우저에서 편집기를 실행하고 UI 없이 콘텐츠를 처리할 수 있습니다. [Server SDK](/server)는 협업 기능과 파일 변환 기능을 제공합니다. 이 섹션에서 다루는 [AI SDK](/ai)는 Office CLI를 만드는 TypeScript SDK입니다. 에이전트와 자동화 도구가 Univer Unit[^document-unit]을 불러오고, 내용을 파악하고, 변경하고, 검증할 수 있도록 Node.js 진입점을 제공합니다.

AI SDK의 기능을 조합해 필요한 CLI를 만들 수 있습니다. 명령 이름과 인수, 작업 대상, 인증과 권한, 출력 형식, 실행 환경은 애플리케이션에서 결정합니다.

## 권장 애플리케이션 구성

이 섹션의 예제는 `CLI + Web + Server` 구성을 기준으로 합니다.

<Mermaid chart={"flowchart LR\n    Agent([\"AI Agent / CLI 사용자\"]) --> CLI[\"<b>AI SDK</b><br/>업무 CLI\"]\n    Human([\"사람 사용자\"]) --> Web[\"<b>Web SDK</b><br/>Web\"]\n    CLI --> Server[\"<b>Server SDK</b><br/>협업 · 파일 변환\"]\n    Web --> Server\n    Server --> Storage[\"스토리지\"]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Agent,Human actor"} />

- 에이전트나 사용자는 CLI로 Univer에 작업을 지시합니다.
- Web은 사용자가 직접 편집하고 에이전트의 작업 결과를 검토할 수 있도록 페이지를 표시합니다.
- Server는 CLI와 Web에서 공유하는 Unit, 리비전, 협업 상태를 저장합니다.

세 부분은 따로 배포하거나 한 컴퓨터에서 실행할 수 있습니다. 처음에는 Collaboration SDK로 Web과 Server를 연결한 뒤 CLI를 추가해 보세요. 배포 시에 이 순서를 따를 필요는 없습니다.

<Callout title="CLI 전용 애플리케이션">
  AI SDK는 서버 없이 로컬 Unit을 처리할 수 있습니다. 구조화된 출력을 읽거나, 에이전트에게 스크린샷 검토를 맡기거나, Office 파일로 내보내 결과를 확인할 수 있습니다. 실시간 Web 페이지, 공유 리비전, History, Worktree를 사용하려면 Web과 협업 기능이 필요합니다.
</Callout>

## Commander로 CLI 구성

기본 패키지는 TypeScript API를 제공합니다. 프리셋 패키지는 자주 사용하는 기능을 Commander의 `Command` 객체로 제공하므로 애플리케이션의 프로그램에 바로 추가할 수 있습니다.

```ts
import { Command } from "commander";

const program = new Command("my-cli");

program.addCommand(presetCommand);
program.addCommand(applicationCommand);

await program.parseAsync();
```

- **명령 프리셋**은 인수와 도움말을 정의하고 텍스트나 JSON을 출력합니다.
- **애플리케이션 명령**은 Runtime[^live-runtime], 애플리케이션의 작업 대상, 사용자 정보, 커밋 또는 파일 정책을 조합합니다.
- 둘 다 Commander의 `Command` 객체이므로 한 프로그램에서 함께 사용할 수 있습니다.

각 페이지에서는 기본 기능을 소개한 뒤 Commander와 연동하는 방법을 설명합니다.

## 기능을 단계적으로 구축

먼저 Unit의 콘텐츠를 읽고 쓰는 기능을 구성합니다. 이후 파일 처리, 시각적 검사, 협업, 프로세스 관리 기능을 추가합니다.

```text
Unit 로드 및 편집
→ Office 파일 가져오기 및 내보내기
→ 시각적 검사
→ 격리된 Worktree 편집 및 검토
→ Runtime 재사용 및 Daemon
```

### 1. Unit 로드 및 편집

Collaboration Runtime으로 Unit을 불러오고 구조를 조사한 다음 Facade 코드를 실행합니다. 필요한 Facade API는 그때 찾아보면 됩니다.

### 2. Office 파일 경계 연결

Exchange는 Office 파일과 UnitData를 서로 변환합니다. 가져온 Unit은 Collaboration Server에 저장됩니다. 내보낼 때는 Collaboration Runtime이 최신 UnitData를 불러온 뒤 파일에 기록합니다.

### 3. 시각적 검사 추가

구조화된 출력만으로는 렌더링된 페이지의 모습을 모두 파악하기 어렵습니다. Screenshot은 에이전트에 페이지 이미지를 제공하며, Layout Lint는 에이전트가 수정할 수 있는 레이아웃 문제를 알려 줍니다.

### 4. Worktree로 변경 격리

에이전트는 실제 문서를 변경하지 않고 Worktree 초안을 반복해서 수정하고 확인할 수 있습니다. 작업이 끝나면 사용자가 Web에서 초안을 검토해 병합하거나 돌려보냅니다.

### 5. 비용이 큰 런타임 재사용

처음에는 명령마다 하나의 런타임을 시작하고 실행이 끝나면 종료합니다. 시작 비용, 동시 실행, CLI 프로세스 간 공유가 문제가 될 때 풀, 워커, 데몬을 추가합니다.
