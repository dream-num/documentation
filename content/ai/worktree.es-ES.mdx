Worktree[^document-worktree] proporciona un agente con un espacio de edición aislado. Dentro de un borrador, el agente puede tirar, inspeccionar, ejecutar y comprometer por tantas rondas como sea necesario, luego marca el Worktree List una vez que pasen los cheques estructurados y visuales. Una persona entonces revisa la página renderizada a través de Web y elige Merge o Reopen.

```text
crear Worktree
→ AI Agent edita el borrador
→ comprobaciones estructuradas y visuales
→ Ready
→ revisión humana en Web
→ Merge / Reopen
→ trunk
```

## Por qué usar Worktree

- Las ediciones intermedias del agente nunca llegan al maletero.
- Cada borrador tiene sus propias instantáneas, cambios, revisiones, Presencia y habitaciones en tiempo real.
- El agente puede sincronizar, editar y verificar en varias rondas antes de presentar un resultado.
- Listo congela el borrador en su revisión actual y establece un límite de revisión explícito.
- Una persona puede revisar, continuar editando, Merge o Reabrir a través de Web.
- La fusión aún pasa por la autorización y compromete los límites del Servicio de Colaboración del tronco en sí.

## Flujo completo

```text
crear / seleccionar Worktree
→ seleccionar Unit de Worktree
→ cargar con Collaboration Runtime
→ pull
→ inspect
→ api find / show
→ execute(write)
→ runtime.commit()
→ inspect + screenshot + layout lint
→ markReady
→ revisión Web
→ merge / reopen
```

Una vez que [Carga de documentos y operaciones de contenido](/ai/content-operations), [Importación y exportación de archivos de oficinas](/server/import-export/node) y [Inspección visual](/ai/visual-inspection) están trabajando, señala las mismas capacidades en un objetivo Worktree. Esto produce el flujo de edición de agente recomendado.

## Destino Worktree

Collaboration Runtime funciona en el Snapshot, cambia y la revisión de una unidad única, y no tiene concepto de Worktree. El adaptador de aplicaciones mapas `worktreeID + unitID` a la instantánea, enviar, WebSocket, y URLs del ticket de sesión del Worktree Endpoint, luego pasa esas URL al backend de tiempo de ejecución.

```text
worktreeID + unitID
→ adaptador de destino de la aplicación
→ URL del protocolo Worktree
→ Collaboration Runtime
```

Por lo tanto, el mismo modelo de ejecución de tiempo de ejecución conecta ya sea al tronco o a un borrador Worktree aislado.

## Operaciones del AI Agent en el borrador

Se usa el mismo ciclo básico que para una Unit normal:

```text
load → pull → inspect → execute(write) → commit
```

`@univer-cli/content-inspection-command` proporciona dos fábricas para disponer de una entrada Inspection:

- `createContentInspectionCommand()` se aplica a un objetivo común de la unidad.
- `createWorktreeContentInspectionCommand()` se aplica cuando el callador debe elegir explícitamente `--trunk` o `--worktree <id>`.

La aplicación aplica el mismo tipo de selección de objetivos a la ejecución, captura de pantalla y otros comandos, y posee la adquisición y liberación del Runtime seleccionado.

## Seleccionar Worktree en Commander

El preset de inspección tiene una variante Worktree que requiere que el callador elija `--trunk` o `--worktree <id>`:

```ts
import type { WorktreeContentInspectionCommandDependencies } from "@univer-cli/content-inspection-command";
import { createWorktreeContentInspectionCommand } from "@univer-cli/content-inspection-command";
import { Command } from "commander";

function addWorktreeCommands(
  program: Command,
  dependencies: {
    acquireRuntime: WorktreeContentInspectionCommandDependencies["acquireRuntime"];
    markReady(worktreeID: string): Promise<void>;
  },
): void {
  program.addCommand(
    createWorktreeContentInspectionCommand({
      acquireRuntime: dependencies.acquireRuntime,
    }),
  );

  const worktreeCommand = new Command("worktree");
  worktreeCommand
    .command("ready")
    .argument("<worktree-id>")
    .action(async (worktreeID) => {
      await dependencies.markReady(worktreeID);
    });

  program.addCommand(worktreeCommand);
}
```

`acquireRuntime` y `markReady` son dependencias de aplicaciones declaradas explícitamente aquí, no ayudantes ocultos dentro de AI SDK. El primero implementa el mapeo desde Worktree target a Runtime descrito en la sección anterior; este último llama al cliente Collaboration SDK Worktree .

Los comandos ejecutar, screenshot y layout lint deben utilizar el mismo modelo de destino; de lo contrario, un ID de unidad puede resolver a diferentes objetivos de tronco o borrador. Web puede exponer Reopen, Discard, Merge y revisión de página real en el mismo cliente Worktree. Un producto puede envolver algunas de esas operaciones en subcomandos adicionales Commander cuando es necesario.

## Comprobaciones del AI Agent

Antes de Ready, pueden combinarse dos tipos de comprobación:

```text
comprobación estructurada: pull → inspect
comprobación visual: Unit → Render Runtime → screenshot / layout lint
```

- La inspección verifica el contenido estructurado de un libro de trabajo, hoja de trabajo, rango, documento, párrafo, presentación o diapositiva.
- Captura de Pantalla proporciona la página renderizada para el agente a revisar.
- Layout Lint diagnostica problemas de diseño en una diapositiva.
- Si hay un problema, el AI Agent puede ejecutar, confirmar y comprobar de nuevo.

## Distinguir Commit, Ready y Merge

| Operación | Significado |
| --- | --- |
| `runtime.commit()` | Presentar los cambios producidos por las mutaciones actuales al proyecto Worktree |
| `markReady()` | Fijar la revisión actual del borrador de cada Unit y entrar en `ready` |
| `reopenWorktree()` | Volver de `ready` a `draft` para seguir editando |
| `mergeWorktree()` | Fusionar las Units del Worktree en trunk una a una |

`runtime.commit()` avanza sólo el borrador. No se fusiona en el tronco. Listo mueve el trabajo del agente en revisión, pero el resultado todavía requiere un Worktree Merge antes de que llegue al tronco.

## Revisión humana en Web

Web carga el mismo borrador con el cliente Worktree y la configuración de colaboración Worktree. Una superficie de revisión puede presentar:

- El estado actual de la Worktree.
- La página entregada de una Unidad en el proyecto.
- Alternancia entre trunk y borrador.
- Un avance de fusión para cada Unidad.
- Operaciones Ready, Reopen, Discard y Merge.

Un borrador en List es sólo lectura. Antes de que una persona o un agente se edite de nuevo, Reapéralo a Borrador. Después de la aprobación, Combinar, luego cambiar de nuevo al maletero para inspeccionar el resultado integrado.

## Límite de Collaboration SDK

Worktree Service, Endpoint, Client y Database Adapter pertenecen a Collaboration SDK. AI SDK suministra las capacidades de unidad composable Runtime, Inspection, API Reference, Execution y Captura de Pantalla. La aplicación posee los comandos de ciclo de vida Worktree, mapeo de objetivos, identidad y autorización.

Consulta las [extensiones de colaboración](/server/collaboration/extensions) para composición del servidor, ciclo de vida y restricciones de fusión.

[^document-worktree]: Este Worktree es un borrador colaborativo aislado del contenido del documento, no un worktree de Git ni una copia del código fuente. Los cambios pasan al tronco tras la revisión y fusión.
