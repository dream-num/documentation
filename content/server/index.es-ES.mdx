El backend guarda documentos, comprueba permisos y proporciona interfaces de colaboración o conversión de archivos. Las versiones actuales usan [Server SDK](/server) para integrar estas capacidades en tu propio entorno de aplicación.

Esta página trata la configuración del backend, el almacenamiento y los permisos. La [integración de colaboración](/server/collaboration/browser-integration) conecta el editor con documentos compartidos. La [integración de intercambio de archivos](/server/import-export) cubre subida, conversión y descarga. Sigue la guía de la función que necesites. Si requiere licencia, empieza por [configurar la licencia](/server/license). La edición solo en el navegador no necesita un servicio de colaboración.

## Elegir los servicios necesarios

| Necesidad | Preparación del backend | Guía |
| --- | --- | --- |
| Edición de documentos compartidos | Collaboration SDK, almacenamiento y permisos | [Inicio rápido de colaboración](/server/collaboration/quick-start) |
| Importar y exportar archivos Office | Conversión, subidas, consultas de tareas y descargas | [Conversión de archivos](/server/import-export/node) y [ejemplo Exchange](/server/collaboration/examples#exchange) |
| Historial o comentarios compartidos | Sus respectivos servicios, almacenamiento y permisos | [Módulos de extensión](/server/collaboration/extensions) |

Elige solo las capacidades necesarias. Convertir archivos no requiere edición colaborativa. Prepara el [entorno de los SDK](/server/requirements) y mantén compatibles las versiones de los paquetes Univer.

## Conectar la aplicación y el almacenamiento

Ejecuta el ejemplo del servicio elegido y conéctalo al backend. Para documentos colaborativos, tu aplicación crea el documento, registra su propietario y devuelve el ID al navegador. Consulta las API de creación en [Límites de los módulos](/server/collaboration/modules). Tu aplicación sigue gestionando usuarios, proyectos y carpetas.

El ejemplo de colaboración usa almacenamiento en memoria y pierde el contenido al reiniciar. Sigue [Adaptadores de base de datos](/server/collaboration/database-adapters) para conectar una base de datos y verifica que los documentos guardados sobrevivan al reinicio.

La conversión también necesita almacenar y limpiar subidas, tareas y descargas. Sigue el [ejemplo Exchange](/server/collaboration/examples#exchange).

## Conectar el inicio de sesión y los permisos

Sigue [Identidad y autorización](/server/collaboration/identity-and-authorization) para validar las credenciales existentes y comprobar si un usuario puede leer o modificar un documento. Sustituye los usuarios fijos y las reglas que permiten todo del ejemplo.

Protege las lecturas, conexiones de colaboración, envíos de cambios y cualquier historial, comentario o descarga habilitados. Un editor de solo lectura en el navegador no sustituye las comprobaciones del servidor.

## Desplegar y conectar el frontend

Despliega las interfaces en el dominio de tu aplicación. Para colaborar, los proxies deben reenviar HTTP y WebSocket; las páginas HTTPS deben usar WSS. Limita las subidas y gestiona los fallos y tiempos de espera de conversión.

Cuando el backend esté listo, completa la integración correspondiente:

- [Integración de colaboración](/server/collaboration/browser-integration): conecta el editor, crea y abre documentos compartidos y verifica la sincronización.
- [Integración de intercambio de archivos](/server/import-export): conecta subida, conversión y descarga y comprueba archivos reales.
