The **Univer** is a toolkit for building Office applications in which humans and AI Agents
operate the same content. A Univer application can provide a human-facing Web interface, an
Agent-facing CLI, and a Server shared by both, or use only the components it needs.

## SDK family

<Mermaid chart={"flowchart LR\n    Human([Human user]) --> Web[\"Web<br/>Web SDK\"]\n    Agent([Agent]) --> CLI[\"CLI<br/>AI SDK\"]\n    Web --> Server[\"Server<br/>Univer Collaboration SDK<br/>+ application code\"]\n    CLI --> Server"} />

| Component | Runtime | Primary SDK              | SDK provides                        | Application owns                                 |
| --------- | ------- | ------------------------ | ----------------------------------- | ------------------------------------------------ |
| Web       | Browser | Web SDK       | Interactive Office display and edit | UI, product interactions, browser integration    |
| CLI       | Node.js | AI SDK           | Agent-facing inspection and editing | Agent workflows, tool calls, and task bounds     |
| Server    | Node.js | Univer Collaboration SDK | Self-hosted sync for Web and CLI    | Product APIs, identity, policy, data, deployment |

Documentation is organized into [Web SDK](/guides/sheets), [Server SDK](/server), and [AI SDK](/ai), covering editors, collaboration and file exchange services, and agent content operations.

The AI SDK reuses headless content capabilities from the Web SDK. These components identify
the primary developer entry point and runtime placement, not three independent technology stacks
or complete products that can be deployed without application code.

## Deployment shapes

| Shape        | Web                      | CLI                     | Server          | Intended scope                      |
| ------------ | ------------------------ | ----------------------- | --------------- | ----------------------------------- |
| Local app    | Local browser/desktop UI | Local process           | Local process   | Desktop Office with a local Agent   |
| SaaS app     | Browser                  | User device/cloud Agent | Remote service  | Multiple users and central ops      |
| Web + Server | Browser                  | —                       | Local or remote | No Agent-facing surface yet         |
| Web-only     | Browser/desktop UI       | —                       | —               | Local, single-user, non-collab edit |

Components can run on one machine or span client devices and cloud infrastructure. Placement does
not change their responsibilities. Whenever a Server exists, Web and CLI use it to access shared
content and product capabilities.
