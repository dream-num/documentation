title: Server SDK
description: 애플리케이션의 문서 서비스, 저장소, 접근 권한을 준비합니다.
---

백엔드는 문서를 저장하고 사용자 권한을 검사하며 공동 편집이나 파일 변환 인터페이스를 제공합니다. 현재 릴리스에서는 [Server SDK](/server)를 사용해 자체 애플리케이션 환경에 이러한 기능을 통합합니다.

이 페이지는 백엔드 설정, 저장소, 권한을 다룹니다. [공동 편집 통합](/server/collaboration/browser-integration)은 편집기를 공유 문서에 연결하며, [파일 교환 통합](/server/import-export)은 업로드, 변환, 다운로드를 설명합니다. 필요한 기능의 가이드를 따르세요. 라이선스가 필요한 기능은 [라이선스 설정](/server/license)부터 시작하세요. 브라우저에서만 편집할 때는 공동 편집 서비스가 필요하지 않습니다.

## 필요한 서비스 선택

| 요구 사항 | 백엔드 준비 | 구현 가이드 |
| --- | --- | --- |
| 공유 문서 편집 | Collaboration SDK, 문서 저장소, 권한 | [공동 편집 빠른 시작](/server/collaboration/quick-start) |
| Office 파일 가져오기·내보내기 | 변환, 업로드, 작업 조회, 다운로드 | [파일 변환](/server/import-export/node) 및 [Exchange 예제](/server/collaboration/examples#exchange) |
| 기록 또는 공유 댓글 | 각각의 서비스, 저장소, 권한 | [확장 모듈](/server/collaboration/extensions) |

필요한 기능만 선택하세요. 파일 변환만 사용할 때는 공동 편집이 필요하지 않습니다. [SDK 환경](/server/requirements)을 준비하고 Univer 패키지 버전의 호환성을 유지하세요.

## 애플리케이션 및 저장소 연결

선택한 서비스의 예제를 실행한 뒤 백엔드에 연결하세요. 공동 편집 문서는 애플리케이션이 생성하고 소유권을 기록한 뒤 ID를 브라우저에 반환합니다. 생성 API는 [모듈 경계](/server/collaboration/modules)를 참고하세요. 사용자, 프로젝트, 폴더는 계속 애플리케이션에서 관리합니다.

공동 편집 예제는 메모리 저장소를 사용하므로 재시작하면 내용이 사라집니다. [데이터베이스 어댑터](/server/collaboration/database-adapters)에 따라 데이터베이스를 연결하고 재시작 후에도 저장된 문서가 유지되는지 검증하세요.

파일 변환에도 업로드, 작업, 다운로드의 저장과 정리가 필요합니다. [Exchange 예제](/server/collaboration/examples#exchange)를 따르세요.

## 로그인 및 권한 연결

[신원 및 권한 부여](/server/collaboration/identity-and-authorization)에 따라 기존 로그인 자격 증명을 검증하고 사용자가 문서를 읽거나 수정할 수 있는지 검사하세요. 예제의 고정 사용자와 모두 허용 규칙을 교체하세요.

문서 읽기, 공동 편집 연결, 변경 제출, 활성화한 기록·댓글·다운로드를 보호하세요. 브라우저 편집기를 읽기 전용으로 설정하는 것은 서버 권한 검사를 대신하지 않습니다.

## 배포 및 프런트엔드 연결

애플리케이션 도메인에 인터페이스를 배포하세요. 공동 편집 프록시는 HTTP와 WebSocket 트래픽을 모두 전달해야 하며 HTTPS 페이지에서는 WSS를 사용해야 합니다. 업로드를 제한하고 변환 실패와 시간 초과를 처리하세요.

백엔드가 준비되면 해당 기능의 통합을 완료하세요.

- [공동 편집 통합](/server/collaboration/browser-integration): 편집기를 연결하고 공유 문서를 생성·로드하며 동기화를 확인합니다.
- [파일 교환 통합](/server/import-export): 업로드, 변환, 다운로드를 연결하고 실제 파일로 검증합니다.
