L'éditeur ne peut pas ouvrir un fichier Excel directement. Le serveur convertit d'abord le fichier en données de document Univer, et lors de l'exportation il convertit les données éditées en fichier Excel. Les deux directions utilisent le module côté serveur `@univerjs-pro/exchange-node`. Le navigateur télécharge le fichier, ouvre le document et télécharge le résultat.

## Sans édition collaborative

Dans le scénario typique, un utilisateur télécharge un fichier Excel, l'édite sur la page, et télécharge le résultat sous forme de fichier Excel.

1. Le navigateur télécharge le fichier. Le serveur convertit le fichier en Univer et retourne les données.
2. Le navigateur ouvre un tableur à partir de ces données, prêt à être édité.
3. Lors de l'exportation, le navigateur envoie les données éditées au serveur, et le serveur génère un fichier Excel à télécharger.

Ce chemin n'implique pas de service de collaboration. Un *snapshot* dans les API du navigateur est les données de document utilisées ici. L'importation ou l'exportation d'un snapshot nécessite toujours une conversion côté serveur ; pour laisser les utilisateurs enregistrer leur travail et y revenir plus tard, l'application doit stocker ces données elle-même.

L'installation et l'utilisation du module de conversion sont couvertes par [Importation et exportation de fichiers bureautiques](/server/import-export/node). Cette page est également le point de départ si une application n'a besoin que du traitement de fichiers dans Node.js .

## Avec édition collaborative

Dans ce scénario, l'utilisateur importe un fichier Excel, partage le document avec ses collègues, le modifie avec eux et l'exporte plus tard.

1. Le serveur convertit le fichier téléversé et enregistre le résultat comme document collaboratif.
2. Le serveur retourne un ID de document. Le navigateur ouvre le document par cet ID, et d'autres utilisateurs rejoignent le document avec le même ID.
3. Lors de l'exportation, le serveur lit le dernier contenu du document et génère un fichier Excel à télécharger.

Cet ID document est le `unitId` dans les API du navigateur. Configurez [Intégration de la collaboration](/server/collaboration/browser-integration) d'abord, puis exécutez le [Exemple d'échange](/server/collaboration/examples#exchange). L'exemple présente le navigateur, le serveur et le code de conversion côte à côte.

Les modifications en cours doivent se synchroniser avant une exportation, sinon le fichier exporté peut manquer les dernières modifications. Pour lire et convertir les documents collaboratifs, consultez la section Bureau Exchange côté serveur dans [modules d'extension](/server/collaboration/extensions).

## Connecter les boutons d’import-export

Une fois que la conversion côté serveur fonctionne, l'étape suivante est de la connecter à la page.

- Les applications qui utilisent les menus de Univer ou les API Facade enregistrent le point de fin de fichier et le point d'échange de la même manière que le [Exemple d'échange](/server/collaboration/examples#exchange), puis configurent les plugins du navigateur.
- Les applications qui fournissent leurs propres boutons appellent les API de l'application : elles ouvrent les données du document ou l'ID du document retourné par une importation, et téléchargent le fichier généré après une exportation.

La configuration du navigateur pour chaque produit est en [Feuilles](/guides/sheets/features/import-export), [Docteurs](/guides/docs/features/import-export), [Diapositives](/guides/slides/features/import-export), [Conseils d ' administration](/guides/boards/features/import-export), [Bases](/guides/bases/features/import-export) et [PDF](/guides/pdfs/features/import-export). L'exemple de collaboration montre les feuilles. Pour les autres produits, voir [Importation et exportation de fichiers bureautiques](/server/import-export/node) et vérifier quels formats la version installée prend en charge.

## Vérifier l’intégration

Ouvrez le résultat dans une application Office et vérifiez les modifications, les formules, les images et la mise en page. Avec la collaboration, confirmez également que d'autres utilisateurs peuvent ouvrir le même document et que le contenu survit à un redémarrage du serveur.

Avant le déploiement, limiter les tailles de téléchargement et gérer les pannes de conversion et les délais. Les téléchargements, les requêtes de tâches et les téléchargements nécessitent des vérifications d'accès. Voir [identité et autorisation](/server/collaboration/identity-and-authorization).

## Configuration des plugins [#exchange-client-configuration]

`UniverExchangeClientPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | URL de base pour les téléchargements de fichiers. |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | Point d'arrivée qui reçoit les fichiers téléchargés. |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | Point d'extrémité qui démarre une importation. Gardez le porte-place `{type}`. |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | Point d'extrémité qui démarre une exportation. Gardez le détenteur de place `{type}`. |
| `getTaskServerUrl` | `string` | `'/universer-api/exchange/task/{taskID}'` | Point d'extrémité pour l'état des tâches. Conservez le détenteur de place `{taskID}`. |
| `signUrlServerUrl` | `string` | `'/universer-api/file/{fileID}/sign-url'` | Endpoint qui signe les URLs de fichier. Gardez le porte-place `{fileID}`. |
| `maxTimeoutTime` | `number` | `120000` | Durée maximale de suivi d’une conversion en millisecondes. |

## Configurer les pièces jointes OLE [#ole-configuration]

`UniverDrawingPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | Paramètres pour les pièces jointes OLE. |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | Construit le lien de l'application pour une pièce jointe en ligne. |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | Lis et écrit la pièce jointe originale dans le stockage de l'application. |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | Stocke la pièce jointe dans l’application et l’associe à cette unité. |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | Lit les octets de la pièce jointe dans le stockage de l’application. |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | Surpasse le flux d'aperçu de l'Office. |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | Construit un aperçu Office avec un rappel d'application. |

Ajouter `ole` à l'enregistrement `UniverDrawingPlugin` existant avant l'enregistrement d'Echange. La route ci-dessous appartient à l'application et doit pointer vers l'interface utilisateur du document de l'application; le second argument optionnel `getLink` porte le type de document lorsque nécessaire. Exchange effectue la conversion Office et détecte l'état de collaboration. Les pièces jointes saisies par un UUID nécessitent également `ole.attachmentIo`, avec les callbacks autorisés `upload(file, targetUnitId)` et `read(attachment, signal)`. Les prévisualisations Office nécessitent le rendu correspondant ou un callback `previewOffice` / `createOfficePreview` fourni par application.

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## Échecs d’export et limites de licence [#export-errors]

Une exportation peut échouer au moment de la soumission ou plus tard, pendant que la tâche est sonnée. Une réponse HTTP réussie ne signifie pas que le fichier est prêt. Vérifiez le `error.code` dans le protocole et l'état des tâches. Le client d'échange conserve les erreurs d'exportation du serveur dans `IExchangeService.requestState$`, de sorte qu'une interface utilisateur d'exportation personnalisée peut s'abonner avant de commencer l'opération.

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | Action |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | Réduire le document ou utiliser une licence avec une limite d’export supérieure. |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | Vérifier le quota restant et sa politique de réinitialisation. |
| `LICENSE_CONCURRENCY_TIMEOUT` | Réessayez plus tard, lorsque la capacité de conversion est disponible. |
| `LICENSE_VERSION_NOT_ALLOWED` | Utiliser une version couverte par la licence serveur. |
| `LICENSE_UNIT_TYPE_REJECTED` | Vérifier que la licence serveur couvre le type de document. |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | Inspectez la configuration de la licence du serveur, l'état d'utilisation et le stockage. |

Correspondez aux valeurs `ErrorCode` nommées de `@univerjs/protocol`; n'analysez pas le texte du message traduit. Gardez le message du serveur pour les diagnostics. Les défaillances réseau, les réponses malformées aux tâches et les délais de vote peuvent faire surface comme une défaillance générique, et aucun d'entre eux ne prouve qu'une licence a rejeté l'exportation. Appelez `subscription.unsubscribe()` lorsque l'éditeur est supprimé.

Si l'application déploie son propre moteur ou proxy en avant, ce moteur ou prex doit passer la réponse d'erreur structurée à travers et marquer la tâche échouée au lieu de la laisser en attente. Raising `maxTimeoutTime` donne seulement plus de temps aux sondages. Il n'ajoute pas de quota d'exportation ou de modifier ce que la licence couvre.

## Pièces jointes OLE [#ole-attachments]

Les utilisateurs peuvent télécharger un fichier original lorsqu'il est disponible, renommer une occurrence et supprimer une pièce jointe s'ils en ont la permission. Les pièces jointes image et PDF peuvent être prévisualisées. Les prévisualisations Office passent par la conversion Exchange JSON dans un éditeur temporaire en lecture seule, et l'ouverture d'un prévisualiser ne crée pas un document enfant persistant. Les applications et macros Native Office ne fonctionnent jamais.

La conversion d'une pièce jointe Office en document en ligne nécessite un hôte collaboratif, une autorisation de modification, une prise en charge de la conversion et `getLink`. La conversion crée un document indépendant et stocke son identité sur la pièce jointe, ce qui permet d'ouvrir plus tard la réutilisation de ce document. La modification du document n'écrase pas les octets de la pièce jointe originale.

Les exportations utilisent `oleAttachmentSource: 'original'` par défaut. Définissez-le à `'online'` pour intégrer la version actuelle confirmée de chaque document en ligne converti dans cette seule exportation; les originaux stockés ne sont pas réécrits. Les éditions doivent se synchroniser avant une exportation, et le moteur doit autoriser l'accès aux documents référencés. Passez l'option comme deuxième argument aux API d'exportation de Docs et Diapositives, ou comme quatrième argument aux API de l'exportation de Sheets. Les variantes Snapshot l'acceptent dans la même position. Voir la [exporter API](/reference/facade/univer#exportsheetbyunitidasync).

Pour les pièces jointes persistantes, Exchange soumet `fileID` et les `sourceUnitID` avant de convertir par référence, le moteur d'importation doit valider comment les deux se rapportent et vérifier l'accès de l'appelant. Le sondage d'une tâche peut retourner `progress.stage` comme `reading`, `converting`, `creating`ou `done`. Pour une UI de conversion personnalisée, voir la [Importation de pièces jointes et API de progression](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress).
