Exchange lit la licence dans le processus serveur qui exécute `@univerjs-pro/exchange-node`. Pour la conversion elle-même, voir [Importation et exportation de fichiers bureautiques](/server/import-export/node) .

## Configurer l’autorisation [#configure]

L'approche standard consiste à définir `UNIVER_LICENSE` et `UNIVER_LICENSE_KEY` dans l'environnement. Appeler `configureExchange` est alors facultatif : le SDK lit l'environnement une fois, sur la première requête export ou quota, et conserve cette configuration pour le reste du processus. Lorsqu'aucune variable n'est définie, Free s'applique. Lorsque les variables sont définies mais les identifiants sont invalides, les appels retournent une erreur, et ces identifiants ne peuvent pas être utilisés pour l'exportation.

Pour une configuration explicite, appelez `configureExchange({ license, licenseKey })`. La fonction retourne `Promise<void>` et ignore complètement l'environnement, alors attendez-le avant de commencer les exportations qui devraient utiliser les nouvelles identifiants.

```ts
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

Passez le contenu complet de `license` et `licenseKey` fourni par le fournisseur de licence, et non les chemins vers les fichiers. Définissez les deux valeurs ensemble et lisez-les à partir du système de gestion secrète de l'application.

| Entrée | Comportement |
| --- | --- |
| Ne pas appeler `configureExchange` | Les deux variables d'environnement sont lues lors de la première utilisation. Free s'applique lorsque aucune variable n'est définie. |
| `configureExchange({ license, licenseKey })` | Seules les références explicites sont utilisées. L'environnement est ignoré. |
| `configureExchange({})` | Free est sélectionné explicitement. L'environnement est ignoré. |
| Un seul titre dans la source sélectionnée | L'appel renvoie `INVALID_ARGUMENT`. L'autre champ n'est jamais rempli à partir d'une source différente. |

Une fois qu'une configuration d'environnement complète a été lue, elle reste fixe même si une opération ultérieure échoue. Pour remplacer les identifiants par défaut à l'exécution, appelez `configureExchange` et attendez-la. Un appel échoué quitte la configuration précédente en place, donc gérez l'erreur avant de commencer de nouvelles exportations.

ESM et CommonJS partagent une configuration unique dans le même contexte JavaScript. Chaque worker `worker_threads` doit se configurer ou initialiser à partir de son propre environnement. Une exportation utilise la configuration qui était en place lorsque la méthode d'exportation publique a été appelée; modifier les identifiants plus tard n'affecte pas les exportations qui ont déjà commencé.

### Autoriser une seule opération

Pour autoriser un seul appel sans modifier la configuration par défaut, passez une paire complète de `license` et `licenseKey` dans les options d'une API export ou de `getExportQuota`. L'exemple suivant interroge le quota et exporte avec les mêmes identifiants :

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeFormat, exportToBuffer, getExportQuota } from '@univerjs-pro/exchange-node'

const credentials = { license: '<license content>', licenseKey: '<licenseKey content>' }
const quota = await getExportQuota(credentials)
const output = await exportToBuffer(workbook, {
  type: UniverInstanceType.UNIVER_SHEET,
  format: ExchangeFormat.XLSX,
  ...credentials,
})
```

Lorsque les deux champs sont omis, la configuration par défaut s'applique; lorsqu'un seul champ est fourni, l'appel retourne `INVALID_ARGUMENT`. Une paire explicite n'est jamais remplie depuis la configuration par intérim ou depuis l'environnement, et une chaîne vide ne compte pas comme un champ omis. Les identifiants non valides retournent `LICENSE_INVALID`, et le SDK ne revient pas à la licence commerciale par défaut.

### Prise en charge facultative du PDF

Installez le paquet d’extension PDF et importez son point d’entrée avant de configurer l’autorisation :

```sh
pnpm add @univerjs-pro/exchange-node @univerjs-pro/exchange-pdf-node-binding
```

```ts
import '@univerjs-pro/exchange-node/pdf'
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

PDF utilise les mêmes API `importBuffer`, `importFile`, `exportToBuffer`, `exportToFile`, et les API Snapshot correspondantes, avec `UniverInstanceType.UNIVER_PDF` et `ExchangeFormat.PDF`. Une application qui ne gère que PDF n'a pas besoin du composant natif Office. La configuration basée sur l'environnement s'applique aussi au PDF.

## Consulter le quota restant [#quota]

`getExportQuota({ license, licenseKey })` retourne `Promise<ExportQuota>` pour le quota Office et PDF que partage l'autorisation. Lorsque les identifiants sont omis, l'appel interroge la configuration par défaut. L'appel n'accepte aucun type Unit et ne vérifie pas si un type d'exportation particulier est autorisé; cette vérification se produit pendant l'exportation.

Une requête ne consomme ni ne réserve de quotas, et elle ne vérifie pas la version SDK, le temps d'activation ou le type d'exportation. Un solde zéro retourne toujours un instantané réussi. D'autres demandes peuvent consommer des quotas immédiatement après, donc gérer les erreurs retournées par l'exportation réelle ainsi.

Avant l'entrée en vigueur de l'autorisation, une requête contre un quota limité renvoie l'instantané pour le premier mois d'autorisation, dont `periodStart` se trouve dans l'avenir. Une requête réussie, ou un statut `valid`, ne signifie pas que l'exportation est permise.

| Champ | Type | Signification |
| --- | --- | --- |
| `licenseStatus` | `'not_configured' \| 'expired' \| 'valid'` | L'abonnement à l'exportation n'est pas configuré, expiré ou n'a pas encore expiré. `valid` ne signifie pas que les contrôles d'admission à l'export ont été effectués. |
| `expiresAt` | `string \| null` | Expiration de l'abonnement à l'exportation en tant qu'horodatage UTC ISO. `null` lorsque rien n'est configuré ou qu'aucune expiration ne s'applique. |
| `observedAt` | `string` | Horodatage ISO UTC de cet instantané. |
| `limit` | `number \| null` | Limite mensuelle d'exportation actuelle. `null` lorsque le contingent est illimité. |
| `used` | `number \| null` | Exportations réussies au cours du mois en cours. `null` lorsque le contingent est illimité. |
| `reserved` | `number \| null` | Exportations en vol qui détiennent un quota au cours du mois en cours. `null` lorsque le quota est illimité. |
| `remaining` | `number \| null` | Exportations encore disponibles, calculées comme `max(0, limit - used - reserved)`. `null` lorsque le contingent est illimité. |
| `periodStart` | `string \| null` | Entrée en vigueur de l'ISO UTC inclusive de la fenêtre des quotas mensuels demandé. La première période commence à l'avenir, avant l'activation. `null` lorsque le quota est illimité. |
| `periodEnd` | `string \| null` | Exclusivité UTC ISO fin de la fenêtre de quota mensuel demandé. `null` lorsque le quota est illimité. |

`periodEnd` est le début de la prochaine fenêtre de contingent mensuel, et `expiresAt` la fin de l'abonnement à l'exportation. Bien que l'abonnement soit valide, les exportations utilisent toujours un quota commercial. L'épuisement ne sélectionne jamais Free, et la prochaine fenêtre commerciale commence le mois suivant.

Exemple d’instantané à quota limité :

```json
{
  "licenseStatus": "valid",
  "expiresAt": "2027-10-19T23:59:59Z",
  "observedAt": "2026-10-21T09:00:00Z",
  "limit": 500,
  "used": 20,
  "reserved": 1,
  "remaining": 479,
  "periodStart": "2026-10-19T00:00:00Z",
  "periodEnd": "2026-11-19T00:00:00Z"
}
```

## Utiliser le quota d’export [#accounting]

Licences gratuites 10 exportations réussies par mois d'autorisation. Le quota d'exportation commerciale, la concordance et les droits de version dépendent de la licence achetée. Ni Free ni une licence commerciale ne limite la taille du fichier ou le nombre de cellules. La réponse à la requête indique la période en cours et le quota restant.

Les importations ne nécessitent aucune autorisation d'exportation et ne consomment aucun contingent d'exportation.Dans le cadre d'un déploiement, les exportations de bureau et de PDF qui utilisent le même contingent de parts de licence commerciale. Les formats de conversion Exchange sont énumérés en [Importation et exportation de fichiers bureautiques](/server/import-export/node).

Chaque conversion réussie consomme une exportation, et le retour d'un tampon compte comme succès. Un échec ultérieur à écrire, télécharger ou télécharger le fichier ne rembourse pas cette exportation, et une autre conversion réussie en consomme une autre. Lorsque la période actuelle n'a plus de quota, de nouvelles exportations sont rejetées. Attendez la prochaine période d'autorisation ou de fournir une licence valide avec un quota plus élevé. Une licence commerciale épuisée mais valide ne revient pas au quota libre.

## Gérer les erreurs [#errors]

Identifier les erreurs par le `code` structuré plutôt que par l'analyse du texte `message`. L'interface utilisateur peut cartographier les codes d'erreur vers des messages localisés.

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeError, ExchangeFormat, exportToBuffer } from '@univerjs-pro/exchange-node'

try {
  const output = await exportToBuffer(workbook, {
    type: UniverInstanceType.UNIVER_SHEET,
    format: ExchangeFormat.XLSX,
  })
} catch (error) {
  if (error instanceof ExchangeError) {
    // Affichez le message correspondant à error.code, par ex. LICENSE_EXPORT_QUOTA_EXCEEDED quand le quota est épuisé
    console.error(error.code)
  } else {
    throw error
  }
}
```

Le tableau ci-dessous indique si une erreur provient d'une requête de quota (`getExportQuota`) ou d'une exportation réelle. Les deux API retournent Promises, donc les échecs nécessitent `await` et `try/catch`.

| Code | Opération | Signification et réponse |
| --- | --- | --- |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | Export uniquement | La période en cours n'a pas suffisamment de quotas d'exportation. Interrogez le quota ou contactez les ventes pour ajuster la licence. |
| `LICENSE_CONCURRENCY_TIMEOUT` | Export uniquement | En attendant un créneau de concurrence d'exportation chronométré. Réduire les exportations simultanées avant de soumettre à nouveau. |
| `LICENSE_UNIT_TYPE_REJECTED` | Export uniquement | Le type d'exportation n'est pas couvert par la licence, ou son droit de type a expiré. Fournir une licence valide qui couvre le type. |
| `LICENSE_INVALID` | Consultation, export | La licence est invalide. Vérifiez les identifiants complets, ou demandez une mise à jour du fournisseur de licence. |
| `LICENSE_POLICY_INVALID` | Consultation, export | La configuration d'autorisation ne répond pas aux exigences SDK. Demandez une mise à jour du fournisseur de licence. |
| `LICENSE_NOT_YET_EFFECTIVE` | Export uniquement | L'autorisation n'est pas encore entrée en vigueur et l'utiliser après sa date d'entrée en vigueur. |
| `LICENSE_VERSION_NOT_ALLOWED` | Export uniquement | La version actuelle du SDK est hors de la plage couverte. Utilisez une version correspondante ou mettez à jour la licence. |
| `UNSUPPORTED_FORMAT` | Export uniquement | Le format n'est pas pris en charge ou ne correspond pas au type Unit. Vérifiez les options d'exportation. |
| `INVALID_FILE` | Export uniquement | L'entrée de conversion est invalide. Vérifiez le contenu de l'entrée. |
| `INCOMPLETE_SNAPSHOT` | Export uniquement | Les données d'exportation sont incomplètes. Fournissez des données complètes ou un instantané complet. |
| `CONVERSION_FAILED` | Export uniquement | La conversion a échoué. Conserver l'erreur et vérifier le contenu de l'entrée. |
| `IO_ERROR` | Export uniquement | L'entrée ou la sortie du fichier a échoué. Si la conversion a réussi et que l'écriture de la sortie a échoué, cette exportation a déjà été consommée. |
| `INVALID_ARGUMENT` | Consultation, export | Les arguments ou les références sont incomplets. Vérifiez la configuration. |
| `NATIVE_LOAD_FAILED` | Consultation, export | Un composant SDK natif n'a pas réussi à se charger. Vérifiez que les paquets installés correspondent à l'environnement d'exécution. |
| `LICENSE_USAGE_STATE_INVALID` | Consultation, export | L'état d'utilisation de la licence ne peut pas être vérifié. Conserver l'erreur et contacter le support technique. |
| `LICENSE_USAGE_STORAGE_ERROR` | Consultation, export | Le traitement de l'utilisation de la licence a échoué. Conserver l'erreur, contacter le support technique, et ne pas soumettre de nouveau automatiquement. |

L'application peut construire des rappels d'expiration à partir de `licenseStatus` et `expiresAt`. Le SDK ne renvoie pas une liste séparée d'avis.

Après une erreur de traitement d'utilisation de licence, ne pas déduire de l'erreur seule si l'exportation a été comptée. Conserver l'erreur complète et contacter le support technique.
