編輯器不能直接開啟 Excel 檔案。檔案先由伺服器端轉換為 Univer 文件資料，匯出時再把編輯後的資料轉換回 Excel 檔案。兩個方向都由伺服器端的 `@univerjs-pro/exchange-node` 模組完成。瀏覽器負責上傳檔案、開啟文件和下載結果。

## 不使用協同編輯

最常見的場景是使用者上傳一份 Excel 檔案，在頁面上完成編輯，再下載為 Excel 檔案。

1. 瀏覽器上傳檔案，伺服器端將檔案轉換為 Univer 文件資料並返回。
2. 瀏覽器用這份資料開啟表格，即可開始編輯。
3. 匯出時，瀏覽器把編輯後的資料傳送給伺服器端，由伺服器端生成 Excel 檔案供下載。

這個過程不需要協同服務。瀏覽器 API 中的快照就是此處使用的文件資料。匯入和匯出快照同樣需要經過伺服器端轉換；如果使用者需要儲存資料並在之後繼續編輯，應用必須自行儲存這份資料。

轉換模組的安裝和使用方法見 [Office 檔案匯入匯出](/server/import-export/node)。如果只需要在 Node.js 中處理檔案，也可以從該頁開始閱讀。

## 使用協同編輯

在這種場景下，使用者匯入一份 Excel 檔案，把文件分享給同事，與同事共同編輯，之後再匯出。

1. 伺服器端轉換上傳的檔案，並把結果儲存為一份協同文件。
2. 伺服器端返回文件 ID。瀏覽器用這個 ID 開啟文件，其他使用者也透過同一個 ID 加入該文件。
3. 匯出時，伺服器端讀取文件的最新內容，生成 Excel 檔案供下載。

這個文件 ID 就是瀏覽器 API 中的 `unitId`。請先完成[協同整合](/server/collaboration/browser-integration)，再執行 [Exchange 範例](/server/collaboration/examples#exchange)。範例包含瀏覽器、伺服器端和轉換程式碼，可以對照閱讀。

匯出前必須等待當前編輯完成同步，否則匯出的檔案可能缺少剛修改的內容。協同文件的讀取和轉換方式見[擴充套件模組](/server/collaboration/extensions)中伺服器端 Office Exchange 一節。

## 接入匯入匯出按鈕

伺服器端轉換正常工作後，下一步是把頁面接入。

- 使用 Univer 自帶選單或 Facade API 時，按 [Exchange 範例](/server/collaboration/examples#exchange)的方式註冊 File Endpoint 和 Exchange Endpoint，再配置瀏覽器外掛。
- 自行實現按鈕時，呼叫業務介面：匯入完成後開啟介面返回的文件資料或文件 ID，匯出完成後下載生成的檔案。

各產品的瀏覽器配置分別見 [Sheets](/guides/sheets/features/import-export)、[Docs](/guides/docs/features/import-export)、[Slides](/guides/slides/features/import-export)、[Boards](/guides/boards/features/import-export)、[Bases](/guides/bases/features/import-export)、[PDFs](/guides/pdfs/features/import-export)。協同範例演示的是 Sheets。其他產品請先參閱 [Office 檔案匯入匯出](/server/import-export/node)，再核對所用版本支援的格式。

## 驗證整合

用一份真實的業務檔案完整執行匯入、修改和匯出流程，再用 Office 軟體開啟結果，檢查修改、公式、圖片和版面配置。涉及協同的場景還需確認其他使用者能開啟同一份文件，以及服務重啟後內容仍然存在。

上線前應限制上傳大小，並處理轉換失敗和超時。上傳、任務查詢和下載都需要權限檢查，具體見[身分與權限](/server/collaboration/identity-and-authorization)。

## 外掛設定 [#exchange-client-configuration]

`UniverExchangeClientPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | 下載檔案的基礎位址。 |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | 接收上傳檔案的介面。 |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | 啟動匯入工作的端點。保留 `{type}` 預留位置。 |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | 啟動匯出工作的端點。保留 `{type}` 預留位置。 |
| `getTaskServerUrl` | `string` | `'/universer-api/exchange/task/{taskID}'` | 查詢工作狀態的端點。保留 `{taskID}` 預留位置。 |
| `signUrlServerUrl` | `string` | `'/universer-api/file/{fileID}/sign-url'` | 為檔案 URL 簽名的介面。保留 `{fileID}` 佔位符。 |
| `maxTimeoutTime` | `number` | `120000` | 輪詢轉換工作的最長時間，單位為毫秒。 |

## 設定 OLE 附件 [#ole-configuration]

`UniverDrawingPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | OLE 附件的配置項。 |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | 產生開啟線上附件的應用程式連結。 |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | 在應用自己的儲存裡讀寫附件原檔案。 |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | 把附件寫入應用儲存，並關聯到當前單元。 |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | 從應用程式儲存空間讀取附件位元組。 |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | 接管 Office 附件的預覽流程。 |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | 用應用程式提供的回呼建立 Office 預覽。 |

註冊 Exchange 之前，先將 `ole` 加入已有的 `UniverDrawingPlugin` 註冊項。下面的路由由應用提供，需要指向應用自己的文件介面；需要文件型別時，透過 `getLink` 的第二個參數傳入。Exchange 負責 Office 轉換，也會檢測協同狀態。以 UUID 引用的附件還需要配置 `ole.attachmentIo`，提供帶鑑權的 `upload(file, targetUnitId)` 和 `read(attachment, signal)` 回撥。Office 預覽需要對應的渲染器，或由應用實現 `previewOffice` / `createOfficePreview` 回撥。

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## 匯出失敗與授權限制 [#export-errors]

匯出可能在提交時失敗，也可能在輪詢任務時失敗。HTTP 請求成功並不表示檔案已經生成，還需要檢查協議中的 `error.code` 和任務狀態。Exchange 客戶端會把伺服器端的匯出錯誤儲存在 `IExchangeService.requestState$` 中，自定義匯出介面可以在發起操作前訂閱。

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | 處理方式 |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | 縮小文件，或換用匯出上限更大的許可證。 |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 檢查剩餘匯出額度及重置規則。 |
| `LICENSE_CONCURRENCY_TIMEOUT` | 待轉換容量可用後重試。 |
| `LICENSE_VERSION_NOT_ALLOWED` | 改用伺服器端許可證覆蓋的版本。 |
| `LICENSE_UNIT_TYPE_REJECTED` | 確認伺服器授權涵蓋此文件類型。 |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | 檢查伺服器端許可證配置、用量狀態和儲存。 |

判斷錯誤時應依據 `@univerjs/protocol` 中具名的 `ErrorCode`，不要解析翻譯後的提示文字。伺服器端返回的訊息應保留，以便排查問題。網路故障、格式錯誤的任務響應和輪詢超時可能只返回一個通用錯誤，這些情況都不能證明是許可證拒絕了本次匯出。移除編輯器時呼叫 `subscription.unsubscribe()` 釋放訂閱。

如果應用在中間部署了自己的後端或代理，該後端或代理應將結構化錯誤響應原樣透傳，並將任務標記為失敗，而不是讓它一直停留在 pending 狀態。調大 `maxTimeoutTime` 只會為輪詢提供更多時間，不會增加匯出額度，也不會改變許可證覆蓋的範圍。

## OLE 附件 [#ole-attachments]

Sheets、Docs 和 Slides 會將匯入的 OLE 原檔案與預覽圖分開儲存。原檔案可用時，使用者可以下載，也可以重新命名某個附件例項；擁有權限時還可以刪除附件。圖片和 PDF 附件可以預覽。Office 預覽透過 Exchange 的 JSON 轉換，在臨時的只讀編輯器中開啟，不會生成持久化的子文件。原生 Office 應用和宏不會被執行。

將 Office 附件轉換為線上文件，需要宿主支援協同、具備編輯權限、支援轉換，並且已配置 `getLink`。轉換會新建一份獨立文件，將其標識記錄在附件上，之後開啟時複用這份文件。編輯該線上文件不會覆蓋附件的原始位元組。缺失、外部引用或不支援的附件會保留原狀態，不會變成可編輯的 Office 物件。

匯出預設使用 `oleAttachmentSource: 'original'`。設為 `'online'` 時，只在這一個匯出檔案中嵌入各線上文件當前已確認的版本，儲存的原件不會被改寫。匯出前必須等待同步完成，後端應校驗被引用文件的訪問權限。Docs 和 Slides 的匯出 API 將該選項作為第二個參數，Sheets 作為第四個參數；snapshot 變體的參數位置相同。參見[匯出 API](/reference/facade/univer#exportsheetbyunitidasync)。

對於已持久化的附件，Exchange 會提交 `fileID` 和擁有該附件的 `sourceUnitID`。匯入後端在按引用轉換之前，必須先校驗兩者的歸屬關係以及呼叫者的權限。輪詢任務時可能返回 `progress.stage`，其值為 `reading`、`converting`、`creating` 或 `done`。自定義轉換介面見[附件匯入與進度 API](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress)。
