---
title: Импорт и экспорт файлов Office
description: Использование Exchange для обмена содержимым между файлами Office и совместными Units.
---

Конвертация файлов Office обрабатывается `@univerjs-pro/exchange-node`, а не AI SDK. На границе файла приложение CLI вызывает `importFile()` и `exportToFile()` , а затем использует AI SDK или Collaboration SDK для работы на блоке.

## Соблюдение границ SDK

```ts
import { exportToFile, importFile } from "@univerjs-pro/exchange-node";
```

| Возможность | Ответственный |
| --- | --- |
| Преобразование файлов Office в UnitData и из него | Exchange |
| Среда без интерфейса, проверка содержимого и выполнение Facade | AI SDK |
| Снимки, наборы изменений, ревизии и сохранение | Collaboration SDK |
| Пути, политика форматов, бизнес-API и сопоставление ошибок | Бизнес-приложение |

## Импорт совместной Unit

Бизнес-приложение считывает файл Office через Exchange и передает полученный UnitData на сервер Collaboration Server, который создает блок:

```text
файл Office
→ importFile()
→ UnitData
→ API бизнес-сервера
→ совместная Unit
```

Приложение определяет первоначальную правку, бизнес-метаданные и результат, который возвращается.Как только Единица существует, как CLI, так и Web управляют ею через Сервер.

## Экспорт актуальной ревизии

Для экспорта CLI загружает последнюю подтвержденную версию через Collaboration Runtime, а затем передает полный UnitData для обмена:

```text
совместная Unit
→ актуальные UnitData
→ exportToFile()
→ файл Office
```

Расширение выходного файла определяет формат.

## Предоставление файловых операций через Commander

AI SDK не предоставляет предустановленный пакет команд для импорта и экспорта файлов Office.В бизнес-приложении Commander используется для объединения Exchange, Collaboration Runtime и собственного Server API:

```ts
import { Command } from "commander";

interface IFileExchangeDependencies {
  importFile(path: string): Promise<unknown>;
  createUnit(unitData: unknown): Promise<unknown>;
  loadLatestUnitData(unitId: string): Promise<unknown>;
  exportFile(unitData: unknown, path: string): Promise<void>;
  writeResult(result: unknown): void;
}

function addFileExchangeCommands(program: Command, dependencies: IFileExchangeDependencies): void {
  program.addCommand(
    new Command("import").argument("<office-file>").action(async (sourcePath) => {
      const unitData = await dependencies.importFile(sourcePath);
      const created = await dependencies.createUnit(unitData);
      dependencies.writeResult(created);
    }),
  );

  program.addCommand(
    new Command("export")
      .argument("<office-file>")
      .requiredOption("--unit <id>")
      .action(async (outputPath, { unit }) => {
        const unitData = await dependencies.loadLatestUnitData(unit);
        await dependencies.exportFile(unitData, outputPath);
      }),
  );
}
```

Все возможности за пределами Commander объявлены явно в `IFileExchangeDependencies`, поэтому команды не полагаются на скрытых помощников.Приложение выполняет преобразование файлов, вызывая `importFile()` и `exportToFile()` Exchange, реализует `loadLatestUnitData()` на Collaboration Runtime , и впрыскивает свой собственный API сервера и вывод результатов.

## Поддерживаемые форматы

| Unit | Импорт | Экспорт |
| --- | --- | --- |
| Sheet | `.xls`, `.xlsx`, `.xlsm`, `.csv`, `.tsv` | `.xlsx`, `.csv`, `.tsv` |
| Doc | `.doc`, `.docx` | `.docx` |
| Slide | `.ppt`, `.pptx`, `.pptm`, `.ppsx`, `.ppsm`, `.potx` | `.pptx` |

Приложение должно отклонить расширение, которое не соответствует типу Unit, прежде чем оно сгенерирует файл.

## Только локальная CLI

Приложение может обходить сервер совместной работы, передавая импортированный контент непосредственно в локальную среду выполнения без головы и экспортируя файл Office. Этот подход подходит для разовой обработки, но он не предоставляет общие изменения, предварительный просмотр в реальном времени, историю или Worktree.

Имена команд, аргументы пути и представление результатов остаются ответственностью бизнес-приложения. Для пути совместного блока см. [Операции загрузки документов и контента](/ai/content-operations). После того, как граница файла установлена, продолжайте с [Визуальный осмотр](/ai/visual-inspection), что позволяет агенту проверить визуализированный UnitData .
