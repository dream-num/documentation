El editor no puede abrir un archivo Excel directamente. El servidor primero convierte el archivo en datos de documentos Univer, y en la exportación convierte los datos editados de nuevo en un archivo Excel. Ambas direcciones utilizan el módulo `@univerjs-pro/exchange-node` lado servidor. El navegador carga el archivo, abre el documento y descarga el resultado.

<Mermaid chart={'flowchart LR; A["Archivo Excel"] -->|Importación del servidor| B["Documento Univer<br/>Edición en navegador"]; B -->|Exportación del servidor| C["Archivo Excel"];'} />

## Sin edición colaborativa

En el escenario típico, un usuario carga un archivo Excel, lo edita en la página y descarga el resultado como un archivo Excel.

1. El navegador carga el archivo. El servidor convierte el archivo en datos de documentos Univer y devuelve los datos.
2. El navegador abre una hoja de cálculo de esos datos, listo para la edición.
3. En exportación, el navegador envía los datos editados al servidor, y el servidor genera un archivo Excel para su descarga.

Este camino no implica un servicio de colaboración. Un *snapshot* en el navegador APIs es los datos de documentos utilizados aquí. Importar o exportar una instantánea todavía requiere conversión del lado del servidor; dejar que los usuarios guarden su trabajo y vuelvan a él más tarde, la aplicación debe almacenar esos datos.

La instalación y el uso del módulo de conversión está cubierto en [Importación y exportación de archivos de oficinas](/server/import-export/node). Esa página es también el punto de partida si una aplicación sólo necesita procesamiento de archivos en Node.js .

## Con edición colaborativa

En este escenario, el usuario importa un archivo Excel, comparte el documento con sus colegas, lo edita con ellos y lo exporta más tarde.

1. El servidor convierte el archivo subido y guarda el resultado como documento colaborativo.
2. El servidor devuelve un documento ID. El navegador abre el documento por ese ID, y otros usuarios se unen al documento con el mismo ID.
3. En exportación, el servidor lee el último contenido del documento y genera un archivo Excel para su descarga.

Ese documento ID es el `unitId` en las APIs del navegador. Configurar [Integración de la colaboración](/server/collaboration/browser-integration) primero, luego ejecutar el [Ejemplo de cambio](/server/collaboration/examples#exchange). El ejemplo presenta el navegador, el servidor y el código de conversión lado a lado.

Las ediciones pendientes deben sincronizarse antes de una exportación; de lo contrario, el archivo exportado puede perder los últimos cambios. Para leer y convertir documentos de colaboración, consulte la sección de Intercambio de Office del lado del servidor en [módulos de extensión](/server/collaboration/extensions).

## Conectar los botones de importación y exportación

Una vez que la conversión del lado del servidor funciona, el siguiente paso es conectarlo a la página.

- Las aplicaciones que utilizan los menús de Univer o las API de Facade registran el File Endpoint y Exchange Endpoint de la misma manera que el [Ejemplo de cambio](/server/collaboration/examples#exchange), luego configuran los plugins del navegador.
- Las aplicaciones que proporcionan sus propios botones llaman a las APIs de aplicación: abren los datos de documentos o ID de documento devueltos por una importación, y descargan el archivo generado después de una exportación.

La configuración del navegador para cada producto está en [Hojas](/guides/sheets/features/import-export), [Docs](/guides/docs/features/import-export), [Diapositivas](/guides/slides/features/import-export), [Juntas](/guides/boards/features/import-export), [Bases](/guides/bases/features/import-export), y [PDF](/guides/pdfs/features/import-export). El ejemplo de colaboración muestra las hojas. Para los demás productos, vea [Importación y exportación de archivos de oficinas](/server/import-export/node) y compruebe qué formatos soporta la versión instalada.

## Comprobar la integración

Tome un archivo real de la aplicación a través de importación, edición y exportación. Abra el resultado en una aplicación de Office y compruebe las ediciones, fórmulas, imágenes y diseño. Con la colaboración, también confirme que otros usuarios pueden abrir el mismo documento y que el contenido sobrevive a un servidor reiniciar.

Antes del despliegue, limitar los tamaños de carga y manejar los fallos de conversión y los plazos. Subidas, consultas de tareas y descargas todos requieren cheques de acceso. [identidad y autorización](/server/collaboration/identity-and-authorization).

`UniverExchangeClientPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | Base URL para descargas de archivos. |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | Endpoint que recibe archivos cargados. |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | Endpoint que comienza una importación. Mantenga el marcador de posición `{type}`. |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | Endpoint que inicia una exportación. Mantenga el marcador de posición `{type}`. |

`UniverDrawingPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | Ajustes para apegos OLE. |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | Construye el enlace de aplicación para un accesorio en línea. |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | Lee y escribe el apego original en el almacenamiento de aplicaciones. |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | Guarda el adjunto en la aplicación y lo asocia con esta unidad. |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | Lee los bytes del adjunto del almacenamiento de la aplicación. |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | Supera el flujo de vista de Office. |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | Construye una vista previa de Office con un callback de aplicación. |

Añadir `ole` a las existentes `UniverDrawingPlugin` La ruta siguiente pertenece a la aplicación y debe apuntar al documento UI de la aplicación; el segundo opcional `getLink` el argumento lleva el tipo de documento cuando es necesario. El intercambio realiza la conversión de Office y detecta el estado de colaboración. `ole.attachmentIo`, con autorización `upload(file, targetUnitId)` y `read(attachment, signal)` callbacks. Las previsiones de la oficina requieren el renderizador de coincidencia o una aplicación proporcionada `previewOffice` / `createOfficePreview` Callback.

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## Errores de exportación y límites de licencia [#export-errors]

Una exportación puede fallar en el tiempo de envío o más tarde, mientras que la tarea es encuestada. Una respuesta HTTP exitosa por sí sola no significa que el archivo está listo. Chequee el `error.code` en el protocolo y el estado de tarea. El cliente de intercambio mantiene errores de exportación del servidor en `IExchangeService.requestState$`, por lo que una UI de exportación personalizada puede suscribirse antes de que comience la operación.

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | Acción |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | Reduzca el documento o use una licencia con un límite de exportación mayor. |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | Compruebe la cuota restante y su política de reinicio. |
| `LICENSE_CONCURRENCY_TIMEOUT` | Regresa más tarde, cuando la capacidad de conversión está disponible. |
| `LICENSE_VERSION_NOT_ALLOWED` | Use una versión cubierta por la licencia del servidor. |
| `LICENSE_UNIT_TYPE_REJECTED` | Compruebe que la licencia cubra el tipo de documento. |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | Inspeccione la configuración de licencia del servidor, estado de uso y almacenamiento. |

Coincide con los valores `ErrorCode` llamados de `@univerjs/protocol`; no parse texto traducido del mensaje. Mantenga el mensaje del servidor para el diagnóstico. Fallos de la red, respuestas de tareas malformadas, y tiempo de votación pueden aparecer como un fallo genérico en su lugar, y ninguno de ellos prueba que una licencia rechazó la exportación. Llame `subscription.unsubscribe()` cuando el editor es eliminado.

Si la aplicación despliega su propio backend o proxy en frente, ese backend o el proxy debe pasar la respuesta de error estructurada a través y marcar la tarea falló en lugar de dejarla pendiente. Raising `maxTimeoutTime` sólo da más tiempo de votación. No añade cuota de exportación o cambia lo que cubre la licencia.

## Adjuntos OLE [#ole-attachments]

Los usuarios pueden descargar un archivo original cuando está disponible, renombrar un evento, y eliminar un accesorio si tienen permiso. Los archivos de imágenes y archivos PDF pueden ser previsualizados. Las previsiones de Office pasan a través de la conversión de Exchange JSON en un editor de sólo lectura temporal, y abrir una vista previa no crea un documento infantil perdurado.

Convertir un archivo adjunto de Office en un documento en línea requiere un host colaborativo, permiso de edición, soporte de conversión, y `getLink`. La conversión crea un documento independiente y almacena su identidad en el archivo adjunto, así que más tarde abre la reutilización de ese documento. Editar el documento no sobreescribir los bytes originales de adjuntos.

Uso de las exportaciones `oleAttachmentSource: 'original'` por defecto. `'online'` para incrustar la versión confirmada actual de cada documento convertido en línea en esa exportación; los originales almacenados no son reescritos. Edits deben sincronizarse antes de una exportación, y el backend debe autorizar el acceso a los documentos referenciados. Pase la opción como el segundo argumento a Docs y Slides export APIs, o como el cuarto argumento a Sheets export APIs. [API de exportación](/reference/facade/univer#exportsheetbyunitidasync).

Para los apegos persistentes, Exchange presenta `fileID` y `sourceUnitID` que lo posee. Antes de convertirlo por referencia, el backend de importación debe validar cómo se relacionan los dos y comprobar el acceso del callador. Votar una tarea puede devolver `progress.stage` como `reading`, `converting`, `creating`, o `done`. Para una conversión personalizada UI, vea el [API de importación y progreso de archivos adjuntos](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress).
