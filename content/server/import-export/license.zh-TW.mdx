Exchange 在執行 `@univerjs-pro/exchange-node` 的伺服器端程序內讀取許可證。轉換本身的使用方法參見 [Office 檔案匯入匯出](/server/import-export/node)。

## 設定授權 [#configure]

常規做法是在環境變數中設定 `UNIVER_LICENSE` 和 `UNIVER_LICENSE_KEY`，此時呼叫 `configureExchange` 是可選的：SDK 會在第一次匯出或查詢額度時讀取一次環境變數，並在程序餘下的生命週期內沿用該配置。兩個變數都未設定時使用 Free。變數已設定但憑據無效時，呼叫會返回錯誤，這些憑據不能用於匯出。

如需顯式配置，呼叫 `configureExchange({ license, licenseKey })`。該函式返回 `Promise<void>`，並完全忽略環境變數，因此應在開始使用新憑據的匯出之前 await 該呼叫。

```ts
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

`license` 和 `licenseKey` 必須填寫授權提供方給出的完整內容，而不是檔案路徑。兩項應同時配置，並從應用的金鑰管理系統中讀取。

| 輸入 | 行為 |
| --- | --- |
| 不呼叫 `configureExchange` | 首次使用時讀取兩個環境變數。兩個變數都未設定時使用 Free。 |
| `configureExchange({ license, licenseKey })` | 只使用顯式傳入的憑據。環境變數被忽略。 |
| `configureExchange({})` | 顯式選擇 Free。環境變數被忽略。 |
| 所選來源只提供一個憑據 | 呼叫返回 `INVALID_ARGUMENT`。另一個欄位不會從其他來源補齊。 |

完整的環境配置一經讀取即保持固定，即使後續操作失敗也不會改變。若要在執行時替換預設憑據，應自行呼叫 `configureExchange` 並 await 該呼叫。呼叫失敗時保留原有配置，因此應先處理錯誤，再開始新的匯出。

ESM 和 CommonJS 在同一個 JavaScript 上下文中共用一份配置。每個 `worker_threads` Worker 都必須自行配置，或從自身的環境變數初始化。匯出使用的是呼叫公開匯出方法時已生效的配置；此後更改憑據不影響已經開始的匯出。

### 為單次操作指定授權

若要為單次呼叫授權而不改動預設配置，可在匯出 API 或 `getExportQuota` 的選項中傳入一對完整的 `license` 和 `licenseKey`。下面的範例用同一份憑據查詢額度並執行匯出：

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeFormat, exportToBuffer, getExportQuota } from '@univerjs-pro/exchange-node'

const credentials = { license: '<license content>', licenseKey: '<licenseKey content>' }
const quota = await getExportQuota(credentials)
const output = await exportToBuffer(workbook, {
  type: UniverInstanceType.UNIVER_SHEET,
  format: ExchangeFormat.XLSX,
  ...credentials,
})
```

檔案匯出、Snapshot 匯出和可選的 PDF 匯出都支援同樣的方式。兩個欄位都不傳時使用預設配置；只傳一個時返回 `INVALID_ARGUMENT`。顯式傳入的一對憑據不會從預設配置或環境變數中補齊，空字串也不視為未傳。憑據無效時返回 `LICENSE_INVALID`，SDK 不會回退到預設的商業授權。

### 選用 PDF 支援

安裝 PDF 擴充套件包，並在配置授權之前匯入其入口：

```sh
pnpm add @univerjs-pro/exchange-node @univerjs-pro/exchange-pdf-node-binding
```

```ts
import '@univerjs-pro/exchange-node/pdf'
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

匯入該入口即註冊了 PDF 支援，原生元件在首次使用時載入。PDF 使用同一套 `importBuffer`、`importFile`、`exportToBuffer`、`exportToFile` 以及對應的 Snapshot API，並指定 `UniverInstanceType.UNIVER_PDF` 和 `ExchangeFormat.PDF`。僅處理 PDF 的應用不需要載入 Office 原生元件。透過環境變數的配置同樣適用於 PDF。

## 查詢剩餘額度 [#quota]

`getExportQuota({ license, licenseKey })` 返回 `Promise<ExportQuota>`，查詢的是該授權在 Office 與 PDF 之間共享的額度。不傳憑據時查詢預設配置。該呼叫不接受 Unit 型別，也不判斷某個型別是否允許匯出；型別檢查在匯出時進行。

查詢既不消耗也不預留額度，也不檢查 SDK 版本、授權生效時間和匯出型別權限。餘額為零時仍會成功返回一份快照。其他請求可能在此後立即消耗額度，因此實際匯出返回的錯誤同樣需要處理。

授權尚未生效時，有限額度的查詢返回第一個授權月的快照，其 `periodStart` 位於未來。查詢成功或 `licenseStatus` 為 `valid`，並不表示允許匯出。版本、生效時間、型別權限、可用額度和並行名額都在匯出時檢查。

| 欄位 | 類型 | 含義 |
| --- | --- | --- |
| `licenseStatus` | `'not_configured' \| 'expired' \| 'valid'` | 匯出訂閱處於未配置、已過期或未過期狀態。`valid` 並不意味著已透過匯出的准入檢查。憑據無效時返回錯誤。 |
| `expiresAt` | `string \| null` | 匯出訂閱的到期時間，UTC ISO 時間戳。未配置或沒有到期時間時為 `null`。 |
| `observedAt` | `string` | 本快照的 UTC ISO 時間戳。 |
| `limit` | `number \| null` | 當前每月的匯出上限。額度不限時為 `null`。 |
| `used` | `number \| null` | 當前月已成功匯出的次數。額度不限時為 `null`。 |
| `reserved` | `number \| null` | 當前月正在處理並佔用額度的匯出次數。額度不限時為 `null`。 |
| `remaining` | `number \| null` | 仍可用的匯出次數，按 `max(0, limit - used - reserved)` 計算。額度不限時為 `null`。 |
| `periodStart` | `string \| null` | 所查詢的月額度視窗的起點，UTC ISO 時間戳，包含該時刻。第一個週期在授權生效之前，起點位於未來。額度不限時為 `null`。 |
| `periodEnd` | `string \| null` | 所查詢的月額度視窗的終點，UTC ISO 時間戳，不包含該時刻。額度不限時為 `null`。 |

`periodEnd` 是下一個月額度視窗的起點，`expiresAt` 是匯出訂閱的終點。訂閱有效期間，匯出一律使用商業額度。額度用盡不會切換到 Free，下一個商業額度視窗在次月開啟。只有訂閱到期才會切換到剩餘的 Free 額度，該額度既不重置，也不會重新發放。

有限額度快照範例：

```json
{
  "licenseStatus": "valid",
  "expiresAt": "2027-10-19T23:59:59Z",
  "observedAt": "2026-10-21T09:00:00Z",
  "limit": 500,
  "used": 20,
  "reserved": 1,
  "remaining": 479,
  "periodStart": "2026-10-19T00:00:00Z",
  "periodEnd": "2026-11-19T00:00:00Z"
}
```

## 使用額度 [#accounting]

Free 每個授權月允許 10 次成功匯出。商業授權的匯出次數、並行數和版本權限取決於所購買的授權。Free 和商業授權都不限制檔案大小或單元格數量。當前週期和剩餘額度以查詢結果為準。當月未用完的額度不結轉。

匯入不需要匯出授權，也不消耗匯出額度。在同一個部署內，使用同一份商業授權的 Office 與 PDF 匯出共享額度。Exchange 支援的轉換格式參見 [Office 檔案匯入匯出](/server/import-export/node)。

每次成功轉換消耗一次匯出，返回 Buffer 即視為成功。此後寫入、上傳或下載檔案失敗不會退回該次匯出，再次成功轉換會再消耗一次。當前週期沒有剩餘額度時，新的匯出會被拒絕。應等待下一個授權週期，或提供一份額度更高的有效授權。已用盡但仍在有效期內的商業授權不會回退到 Free 額度。

## 處理錯誤 [#errors]

判斷錯誤時應依據結構化的 `code`，而不是解析 `message` 文字。UI 可以將錯誤碼對映為本地化訊息。診斷資訊應保留給技術支援。

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeError, ExchangeFormat, exportToBuffer } from '@univerjs-pro/exchange-node'

try {
  const output = await exportToBuffer(workbook, {
    type: UniverInstanceType.UNIVER_SHEET,
    format: ExchangeFormat.XLSX,
  })
} catch (error) {
  if (error instanceof ExchangeError) {
    // 依 error.code 顯示對應提示，例如額度不足時為 LICENSE_EXPORT_QUOTA_EXCEEDED
    console.error(error.code)
  } else {
    throw error
  }
}
```

下表說明錯誤來自額度查詢（`getExportQuota`）還是來自實際匯出。兩類 API 都返回 Promise，因此需要用 `await` 和 `try/catch` 處理失敗。

| 錯誤碼 | 來源 | 含義與處理 |
| --- | --- | --- |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 僅匯出 | 當前週期的匯出額度不足。查詢額度，或聯絡商務調整授權。 |
| `LICENSE_CONCURRENCY_TIMEOUT` | 僅匯出 | 等待匯出並行名額超時。應先降低並行數，再重新提交。 |
| `LICENSE_UNIT_TYPE_REJECTED` | 僅匯出 | 該匯出型別不在授權範圍內，或該型別的授權已過期。應提供覆蓋該型別的有效授權。 |
| `LICENSE_INVALID` | 查詢、匯出 | 授權無效。檢查完整憑據，或聯絡授權提供方取得更新。 |
| `LICENSE_POLICY_INVALID` | 查詢、匯出 | 授權配置不符合 SDK 要求。聯絡授權提供方取得更新。 |
| `LICENSE_NOT_YET_EFFECTIVE` | 僅匯出 | 授權尚未生效。應在生效日期之後使用。 |
| `LICENSE_VERSION_NOT_ALLOWED` | 僅匯出 | 當前 SDK 版本超出授權範圍。改用匹配的版本，或更新授權。 |
| `UNSUPPORTED_FORMAT` | 僅匯出 | 格式不受支援，或與 Unit 型別不匹配。檢查匯出選項。 |
| `INVALID_FILE` | 僅匯出 | 轉換輸入無效。檢查輸入內容。 |
| `INCOMPLETE_SNAPSHOT` | 僅匯出 | 匯出資料不完整。應提供完整的資料或完整的 Snapshot。 |
| `CONVERSION_FAILED` | 僅匯出 | 轉換失敗。保留錯誤資訊並檢查輸入內容。 |
| `IO_ERROR` | 僅匯出 | 檔案輸入或輸出失敗。如果轉換成功但寫入輸出失敗，該次匯出已被消耗。 |
| `INVALID_ARGUMENT` | 查詢、匯出 | 參數或憑據不完整。檢查配置。 |
| `NATIVE_LOAD_FAILED` | 查詢、匯出 | SDK 原生元件載入失敗。檢查安裝的包與執行環境是否匹配。 |
| `LICENSE_USAGE_STATE_INVALID` | 查詢、匯出 | 無法驗證授權用量狀態。保留錯誤資訊並聯系技術支援。 |
| `LICENSE_USAGE_STORAGE_ERROR` | 查詢、匯出 | 授權用量處理失敗。保留錯誤資訊，聯絡技術支援，不要自動重複提交。 |

應用可以根據 `licenseStatus` 和 `expiresAt` 生成到期提醒。SDK 不單獨返回提示列表。

出現授權用量處理錯誤後，不要僅憑錯誤本身推斷該次匯出是否已計入。應保留完整的錯誤資訊並聯系技術支援。
