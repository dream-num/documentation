Exchange 在运行 `@univerjs-pro/exchange-node` 的服务端进程内读取许可证。转换本身的使用方法参见 [Office 文件导入导出](/server/import-export/node)。

## 配置授权 [#configure]

常规做法是在环境变量中设置 `UNIVER_LICENSE` 和 `UNIVER_LICENSE_KEY`，此时调用 `configureExchange` 是可选的：SDK 会在第一次导出或查询额度时读取一次环境变量，并在进程余下的生命周期内沿用该配置。两个变量都未设置时使用 Free。变量已设置但凭据无效时，调用会返回错误，这些凭据不能用于导出。

如需显式配置，调用 `configureExchange({ license, licenseKey })`。该函数返回 `Promise<void>`，并完全忽略环境变量，因此应在开始使用新凭据的导出之前 await 该调用。

```ts
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

`license` 和 `licenseKey` 必须填写授权提供方给出的完整内容，而不是文件路径。两项应同时配置，并从应用的密钥管理系统中读取。

| 输入 | 行为 |
| --- | --- |
| 不调用 `configureExchange` | 首次使用时读取两个环境变量。两个变量都未设置时使用 Free。 |
| `configureExchange({ license, licenseKey })` | 只使用显式传入的凭据。环境变量被忽略。 |
| `configureExchange({})` | 显式选择 Free。环境变量被忽略。 |
| 所选来源只提供一个凭据 | 调用返回 `INVALID_ARGUMENT`。另一个字段不会从其他来源补齐。 |

完整的环境配置一经读取即保持固定，即使后续操作失败也不会改变。若要在运行时替换默认凭据，应自行调用 `configureExchange` 并 await 该调用。调用失败时保留原有配置，因此应先处理错误，再开始新的导出。

ESM 和 CommonJS 在同一个 JavaScript 上下文中共用一份配置。每个 `worker_threads` Worker 都必须自行配置，或从自身的环境变量初始化。导出使用的是调用公开导出方法时已生效的配置；此后更改凭据不影响已经开始的导出。

### 为单次操作指定授权

若要为单次调用授权而不改动默认配置，可在导出 API 或 `getExportQuota` 的选项中传入一对完整的 `license` 和 `licenseKey`。下面的示例用同一份凭据查询额度并执行导出：

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeFormat, exportToBuffer, getExportQuota } from '@univerjs-pro/exchange-node'

const credentials = { license: '<license content>', licenseKey: '<licenseKey content>' }
const quota = await getExportQuota(credentials)
const output = await exportToBuffer(workbook, {
  type: UniverInstanceType.UNIVER_SHEET,
  format: ExchangeFormat.XLSX,
  ...credentials,
})
```

文件导出、Snapshot 导出和可选的 PDF 导出都支持同样的方式。两个字段都不传时使用默认配置；只传一个时返回 `INVALID_ARGUMENT`。显式传入的一对凭据不会从默认配置或环境变量中补齐，空字符串也不视为未传。凭据无效时返回 `LICENSE_INVALID`，SDK 不会回退到默认的商业授权。

### 可选 PDF 支持

安装 PDF 扩展包，并在配置授权之前导入其入口：

```sh
pnpm add @univerjs-pro/exchange-node @univerjs-pro/exchange-pdf-node-binding
```

```ts
import '@univerjs-pro/exchange-node/pdf'
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

导入该入口即注册了 PDF 支持，原生组件在首次使用时加载。PDF 使用同一套 `importBuffer`、`importFile`、`exportToBuffer`、`exportToFile` 以及对应的 Snapshot API，并指定 `UniverInstanceType.UNIVER_PDF` 和 `ExchangeFormat.PDF`。仅处理 PDF 的应用不需要加载 Office 原生组件。通过环境变量的配置同样适用于 PDF。

## 查询剩余额度 [#quota]

`getExportQuota({ license, licenseKey })` 返回 `Promise<ExportQuota>`，查询的是该授权在 Office 与 PDF 之间共享的额度。不传凭据时查询默认配置。该调用不接受 Unit 类型，也不判断某个类型是否允许导出；类型检查在导出时进行。

查询既不消耗也不预留额度，也不检查 SDK 版本、授权生效时间和导出类型权限。余额为零时仍会成功返回一份快照。其他请求可能在此后立即消耗额度，因此实际导出返回的错误同样需要处理。

授权尚未生效时，有限额度的查询返回第一个授权月的快照，其 `periodStart` 位于未来。查询成功或 `licenseStatus` 为 `valid`，并不表示允许导出。版本、生效时间、类型权限、可用额度和并发名额都在导出时检查。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `licenseStatus` | `'not_configured' \| 'expired' \| 'valid'` | 导出订阅处于未配置、已过期或未过期状态。`valid` 并不意味着已通过导出的准入检查。凭据无效时返回错误。 |
| `expiresAt` | `string \| null` | 导出订阅的到期时间，UTC ISO 时间戳。未配置或没有到期时间时为 `null`。 |
| `observedAt` | `string` | 本快照的 UTC ISO 时间戳。 |
| `limit` | `number \| null` | 当前每月的导出上限。额度不限时为 `null`。 |
| `used` | `number \| null` | 当前月已成功导出的次数。额度不限时为 `null`。 |
| `reserved` | `number \| null` | 当前月正在处理并占用额度的导出次数。额度不限时为 `null`。 |
| `remaining` | `number \| null` | 仍可用的导出次数，按 `max(0, limit - used - reserved)` 计算。额度不限时为 `null`。 |
| `periodStart` | `string \| null` | 所查询的月额度窗口的起点，UTC ISO 时间戳，包含该时刻。第一个周期在授权生效之前，起点位于未来。额度不限时为 `null`。 |
| `periodEnd` | `string \| null` | 所查询的月额度窗口的终点，UTC ISO 时间戳，不包含该时刻。额度不限时为 `null`。 |

Free（Freemium）的额度指每月免水印导出额度，并非总导出次数上限。`remaining` 为零时仍可导出带水印的完整文件，不应仅因该余额为零就拒绝 Free 导出。商业订阅到期后适用 Free 规则，不会额外重置其月额度，也不代表商业生产授权已续期。

`periodEnd` 是下一个月额度窗口的起点，`expiresAt` 是导出订阅的终点。订阅有效期间，导出一律使用商业额度。额度用尽不会切换到 Free，下一个商业额度窗口在次月开启。只有订阅到期才会切换到剩余的 Free 额度，该额度既不重置，也不会重新发放。

有限额度快照示例：

```json
{
  "licenseStatus": "valid",
  "expiresAt": "2027-10-19T23:59:59Z",
  "observedAt": "2026-10-21T09:00:00Z",
  "limit": 500,
  "used": 20,
  "reserved": 1,
  "remaining": 479,
  "periodStart": "2026-10-19T00:00:00Z",
  "periodEnd": "2026-11-19T00:00:00Z"
}
```

## 使用额度 [#accounting]

Free（Freemium）每个授权月包含 10 次免水印导出。从当月第 11 次成功导出起，仍可导出带水印的完整文件。免水印额度按月重置，不结转。商业授权的导出次数、并发数和版本权限仍以所购授权为准。Free 和商业授权都不限制文件大小或单元格数量。当前周期和剩余额度以查询结果为准。

导入不需要导出授权，也不消耗导出额度。在同一个部署内，使用同一份商业授权的 Office 与 PDF 导出共享额度。Exchange 支持的转换格式参见 [Office 文件导入导出](/server/import-export/node)。

每次成功转换计一次，返回 Buffer 即视为成功。此后写入、上传或下载文件失败不退次数，再次成功转换会再次计次。Free 免水印额度耗尽后，后续仍可导出完整文件，但文件带水印。有效商业授权的导出额度耗尽时，新的导出会被拒绝，需等待下一个授权周期或升级为额度更高的有效授权；不会回退到 Free 额度。

## 处理错误 [#errors]

判断错误时应依据结构化的 `code`，而不是解析 `message` 文本。UI 可以将错误码映射为本地化消息。诊断信息应保留给技术支持。

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeError, ExchangeFormat, exportToBuffer } from '@univerjs-pro/exchange-node'

try {
  const output = await exportToBuffer(workbook, {
    type: UniverInstanceType.UNIVER_SHEET,
    format: ExchangeFormat.XLSX,
  })
} catch (error) {
  if (error instanceof ExchangeError) {
    // 根据 error.code 展示对应提示，例如额度不足时为 LICENSE_EXPORT_QUOTA_EXCEEDED
    console.error(error.code)
  } else {
    throw error
  }
}
```

下表说明错误来自额度查询（`getExportQuota`）还是来自实际导出。两类 API 都返回 Promise，因此需要用 `await` 和 `try/catch` 处理失败。

| 错误码 | 来源 | 含义与处理 |
| --- | --- | --- |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 仅导出 | 当前周期的商业导出额度不足。查询额度，或联系商务调整授权。仅耗尽 Free 免水印额度不会触发此错误。 |
| `LICENSE_CONCURRENCY_TIMEOUT` | 仅导出 | 等待导出并发名额超时。应先降低并发数，再重新提交。 |
| `LICENSE_UNIT_TYPE_REJECTED` | 仅导出 | 该导出类型不在授权范围内，或该类型的授权已过期。应提供覆盖该类型的有效授权。 |
| `LICENSE_INVALID` | 查询、导出 | 授权无效。检查完整凭据，或联系授权提供方获取更新。 |
| `LICENSE_POLICY_INVALID` | 查询、导出 | 授权配置不符合 SDK 要求。联系授权提供方获取更新。 |
| `LICENSE_NOT_YET_EFFECTIVE` | 仅导出 | 授权尚未生效。应在生效日期之后使用。 |
| `LICENSE_VERSION_NOT_ALLOWED` | 仅导出 | 当前 SDK 版本超出授权范围。改用匹配的版本，或更新授权。 |
| `UNSUPPORTED_FORMAT` | 仅导出 | 格式不受支持，或与 Unit 类型不匹配。检查导出选项。 |
| `INVALID_FILE` | 仅导出 | 转换输入无效。检查输入内容。 |
| `INCOMPLETE_SNAPSHOT` | 仅导出 | 导出数据不完整。应提供完整的数据或完整的 Snapshot。 |
| `CONVERSION_FAILED` | 仅导出 | 转换失败。保留错误信息并检查输入内容。 |
| `IO_ERROR` | 仅导出 | 文件输入或输出失败。如果转换成功但写入输出失败，该次导出已被消耗。 |
| `INVALID_ARGUMENT` | 查询、导出 | 参数或凭据不完整。检查配置。 |
| `NATIVE_LOAD_FAILED` | 查询、导出 | SDK 原生组件加载失败。检查安装的包与运行环境是否匹配。 |
| `LICENSE_USAGE_STATE_INVALID` | 查询、导出 | 无法验证授权用量状态。保留错误信息并联系技术支持。 |
| `LICENSE_USAGE_STORAGE_ERROR` | 查询、导出 | 授权用量处理失败。保留错误信息，联系技术支持，不要自动重复提交。 |

应用可以根据 `licenseStatus` 和 `expiresAt` 生成到期提醒。SDK 不单独返回提示列表。

出现授权用量处理错误后，不要仅凭错误本身推断该次导出是否已计入。应保留完整的错误信息并联系技术支持。
