Exchange считывает лицензию внутри серверного процесса, который запускает `@univerjs-pro/exchange-node`. Для самого преобразования см. [Офисные файлы импорт и экспорт](/server/import-export/node) .

## Настройка авторизации [#configure]

Стандартный подход заключается в том, чтобы установить `UNIVER_LICENSE` и `UNIVER_LICENSE_KEY` в среде. Звонок `configureExchange` тогда необязателен: SDK считывает среду один раз, по первому экспортному или квотному запросу, и сохраняет эту конфигурацию для остальной части процесса. Когда ни одна из переменных не установлена, применяется Free. Когда переменные установлены, но учетные данные недействительны, звонки возвращают ошибку, и эти учетные данные нельзя использовать для экспорта.

Для явной конфигурации позвоните `configureExchange({ license, licenseKey })`. Функция возвращает `Promise<void>` и полностью игнорирует окружающую среду, поэтому ожидайте ее перед началом экспорта, который должен использовать новые учетные данные.

```ts
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

Передайте полное содержимое `license` и `licenseKey`, поставляемое поставщиком лицензии, а не пути к файлам. Установите оба значения вместе и прочитайте их из секретной системы управления приложением.

| Входные данные | Поведение |
| --- | --- |
| `configureExchange` не вызывается | Обе переменные среды считываются при первом использовании. Бесплатно применяется, когда ни одна из переменных не установлена. |
| `configureExchange({ license, licenseKey })` | Используются только явные данные. Окружающая среда игнорируется. |
| `configureExchange({})` | Свободная выбрана явным образом. Окружающая среда игнорируется. |
| Только один сертификат в выбранном источнике | Звонок возвращает `INVALID_ARGUMENT`. Другое поле никогда не заполняется из другого источника. |

После прочтения полной конфигурации окружения она остается фиксированной, даже если более поздняя операция не удалась. Чтобы заменить учетные данные по умолчанию во время выполнения, позвоните `configureExchange` и ждите его. Неудачный вызов оставляет предыдущую конфигурацию на месте, поэтому обработайте ошибку, прежде чем начинать новый экспорт.

ESM и CommonJS имеют единую конфигурацию в одном и том же контексте JavaScript. Каждый работник `worker_threads` должен настраивать себя или инициализировать из своей собственной среды. Экспорт использует конфигурацию, которая была на месте, когда был назван метод государственного экспорта; изменение учетных данных позже не влияет на экспорт, который уже начался.

### Авторизация одной операции

Чтобы разрешить один звонок без изменения конфигурации по умолчанию, передайте полную пару `license` и `licenseKey` в опциях экспортного API или `getExportQuota`. Следующий пример запрашивает квоту и экспорт с теми же учетными данными:

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeFormat, exportToBuffer, getExportQuota } from '@univerjs-pro/exchange-node'

const credentials = { license: '<license content>', licenseKey: '<licenseKey content>' }
const quota = await getExportQuota(credentials)
const output = await exportToBuffer(workbook, {
  type: UniverInstanceType.UNIVER_SHEET,
  format: ExchangeFormat.XLSX,
  ...credentials,
})
```

Экспорт файлов, экспорт Snapshot и дополнительный экспорт PDF принимают одну и ту же пару. Когда оба поля опущены, применяется конфигурация по умолчанию; когда поставляется только одно поле, вызов возвращает `INVALID_ARGUMENT`. Явная пара никогда не завершается из конфигурации по умолчанию или из окружающей среды, а пустая строка не считается опущенным полем. Недействительные учетные данные возвращают `LICENSE_INVALID`, а SDK не возвращается к коммерческой лицензии по умолчанию.

### Необязательная поддержка PDF

Установите пакет расширения PDF и импортируйте его точку входа до настройки авторизации:

```sh
pnpm add @univerjs-pro/exchange-node @univerjs-pro/exchange-pdf-node-binding
```

```ts
import '@univerjs-pro/exchange-node/pdf'
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

Импорт регистрирует поддержку PDF, и нативные компоненты загружаются, когда они впервые используются. PDF использует те же `importBuffer`, `importFile`, `exportToBuffer`, `exportToFile` и соответствующие API Snapshot, с `UniverInstanceType.UNIVER_PDF` и `ExchangeFormat.PDF`. Приложению, которое обрабатывает только PDF, не нужен нативный компонент Office. Конфигурация на основе среды также применяется к PDF.

## Запрос оставшейся квоты [#quota]

`getExportQuota({ license, licenseKey })` возвращает `Promise<ExportQuota>` для квоты Office и PDF, которую разделяет авторизация. Когда учетные данные опущены, вызов запрашивает конфигурацию по умолчанию. Звонок не принимает тип Unit и не проверяет, разрешен ли конкретный тип экспорта; эта проверка происходит во время экспорта.

Запрос не потребляет и не резервирует квоту, и он не проверяет версию SDK, время активации или право на экспорт. Нулевой баланс по-прежнему возвращает успешный снимок. Другие запросы могут потреблять квоту сразу после этого, поэтому обрабатывайте ошибки, возвращаемые фактическим экспортом.

Перед вступлением в силу запроса против ограниченной квоты возвращает снимок за первый месяц авторизации, чей `periodStart` лежит в будущем. Успешный запрос или статус `valid` не означает, что экспорт разрешен. SDK проверяет версию, активацию, право типа, доступную квоту и параллель во время экспорта.

| Поле | Тип | Значение |
| --- | --- | --- |
| `licenseStatus` | `'not_configured' \| 'expired' \| 'valid'` | Подписка на экспорт неконфигурирована, истекла или еще не истекла. `valid` не означает, что проверки на допуск к экспорту прошли. Недействительные учетные данные возвращают ошибку. |
| `expiresAt` | `string \| null` | Срок действия экспортной подписки в виде временной метки UTC ISO. `null`, когда ничего не настроено или не истекает. |
| `observedAt` | `string` | Метка времени ISO в UTC для этого снимка. |
| `limit` | `number \| null` | Текущий ежемесячный лимит экспорта. `null`, когда квота неограниченна. |
| `used` | `number \| null` | Успешный экспорт в текущем месяце. `null`, когда квота не ограничена. |
| `reserved` | `number \| null` | Экспорт в полете, который держит квоту в текущем месяце. `null`, когда квота не ограничена. |
| `remaining` | `number \| null` | Экспорт по-прежнему доступен, рассчитывается как `max(0, limit - used - reserved)`. `null`, когда квота не ограничена. |
| `periodStart` | `string \| null` | Инклюзивный UTC ISO старт запрашиваемого месячного окна квот. Первый период начинается в будущем, до активации. `null`, когда квота не ограничена. |
| `periodEnd` | `string \| null` | Эксклюзивный UTC ISO конец запрашиваемого месячного окна квот `null`, когда квота не ограничена. |

В Free (Freemium) квота означает месячное количество экспортов без водяных знаков, а не предел общего числа экспортов. При нулевом `remaining` по-прежнему можно экспортировать полные файлы с водяными знаками. Не отклоняйте экспорт Free только из-за этого остатка. После истечения коммерческой подписки действуют правила Free без дополнительного сброса месячной квоты и без продления разрешения на коммерческое использование в рабочей среде.

`periodEnd` — это начало следующего месячного окна квот, а `expiresAt` является окончанием экспортной подписки. Пока подписка действительна, экспорт всегда использует коммерческую квоту. Исчерпание никогда не выбирает Free, а следующее коммерческое окно начинается в следующем месяце. Только истечение срока подписки переключается на оставшуюся бесплатную квоту, которая не сбрасывается и не предоставляется снова.

Пример снимка с ограниченной квотой:

```json
{
  "licenseStatus": "valid",
  "expiresAt": "2027-10-19T23:59:59Z",
  "observedAt": "2026-10-21T09:00:00Z",
  "limit": 500,
  "used": 20,
  "reserved": 1,
  "remaining": 479,
  "periodStart": "2026-10-19T00:00:00Z",
  "periodEnd": "2026-11-19T00:00:00Z"
}
```

## Расход квоты экспорта [#accounting]

Free (Freemium) включает 10 экспортов без водяных знаков за каждый лицензионный месяц. Начиная с 11-го успешного экспорта за месяц можно продолжать экспортировать полные файлы с водяными знаками. Квота без водяных знаков обновляется ежемесячно и не переносится. Коммерческая квота, параллелизм и права на версии по-прежнему определяются приобретённой лицензией. Ни Free, ни коммерческая лицензия не ограничивает размер файла или число ячеек. Текущий период и остаток указаны в ответе на запрос.

Импорт не требует разрешения на экспорт и не потребляет экспортную квоту. В рамках одного развертывания экспорт Office и PDF использует одну и ту же коммерческую лицензию. Форматы конвертации биржи перечислены в [Офисные файлы импорт и экспорт](/server/import-export/node).

Каждая успешная конвертация учитывается один раз; возврат Buffer означает успех. Последующий сбой записи, отправки или скачивания не отменяет учёт. Повторная успешная конвертация учитывается снова. После исчерпания квоты Free без водяных знаков можно продолжать экспорт полных файлов с водяными знаками. При исчерпании квоты действующей коммерческой лицензии новые экспорты отклоняются до следующего периода или перехода на действующую лицензию с большей квотой. Перехода на квоту Free не происходит.

## Обработка ошибок [#errors]

Выявить ошибки по структурированному `code`, а не по разбору текста `message`. Пользовательский интерфейс может сопоставить коды ошибок с локализованными сообщениями. Сохранить диагностические данные для технической поддержки.

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeError, ExchangeFormat, exportToBuffer } from '@univerjs-pro/exchange-node'

try {
  const output = await exportToBuffer(workbook, {
    type: UniverInstanceType.UNIVER_SHEET,
    format: ExchangeFormat.XLSX,
  })
} catch (error) {
  if (error instanceof ExchangeError) {
    // Покажите сообщение для error.code, например LICENSE_EXPORT_QUOTA_EXCEEDED, когда квота исчерпана
    console.error(error.code)
  } else {
    throw error
  }
}
```

В таблице ниже указывается, происходит ли ошибка из квотного запроса (`getExportQuota`) или из фактического экспорта.Оба API возвращают Обещания, поэтому для сбоев требуются `await` и `try/catch`.

| Код | Операция | Значение и действия |
| --- | --- | --- |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | Только экспорт | Недостаточно коммерческой квоты экспорта в текущем периоде. Запросите остаток или обратитесь в отдел продаж для изменения лицензии. Одно лишь исчерпание квоты Free без водяных знаков не вызывает эту ошибку. |
| `LICENSE_CONCURRENCY_TIMEOUT` | Только экспорт | В ожидании слота для экспортной параллели. Сократите параллельный экспорт, прежде чем отправлять снова. |
| `LICENSE_UNIT_TYPE_REJECTED` | Только экспорт | Тип экспорта не покрывается лицензией, или его право на тип истекло.Предоставьте действительную лицензию, которая охватывает тип. |
| `LICENSE_INVALID` | Запрос, экспорт | Лицензия недействительна. Проверьте полные учетные данные или запросите обновление у поставщика лицензии. |
| `LICENSE_POLICY_INVALID` | Запрос, экспорт | Конфигурация авторизации не соответствует требованиям SDK. Запросите обновление у поставщика лицензии. |
| `LICENSE_NOT_YET_EFFECTIVE` | Только экспорт | Разрешение еще не вступило в силу. Используйте его после даты вступления в силу. |
| `LICENSE_VERSION_NOT_ALLOWED` | Только экспорт | Текущая версия SDK вне лицензированного диапазона. Используйте подходящую версию или обновите лицензию. |
| `UNSUPPORTED_FORMAT` | Только экспорт | Формат не поддерживается или не соответствует типу Unit. Проверьте варианты экспорта. |
| `INVALID_FILE` | Только экспорт | Ввод конверсии недействителен. Проверьте содержимое ввода. |
| `INCOMPLETE_SNAPSHOT` | Только экспорт | Экспортные данные являются неполными. Предоставьте полные данные или полный Снимок. |
| `CONVERSION_FAILED` | Только экспорт | Конверсия не удалась. Сохранить ошибку и проверить содержимое ввода. |
| `IO_ERROR` | Только экспорт | Ввод или вывод файлов не удался. Если преобразование увенчалось успехом, а запись вывода не удалась, этот экспорт уже был потреблен. |
| `INVALID_ARGUMENT` | Запрос, экспорт | Аргументы или учетные данные неполны. Проверьте конфигурацию. |
| `NATIVE_LOAD_FAILED` | Запрос, экспорт | Нативный компонент SDK не загружался. Проверь, чтобы установленные пакеты соответствовали среде выполнения. |
| `LICENSE_USAGE_STATE_INVALID` | Запрос, экспорт | Состояние использования лицензии не может быть проверено. Сохранить ошибку и связаться с технической поддержкой. |
| `LICENSE_USAGE_STORAGE_ERROR` | Запрос, экспорт | Обработка использования лицензии не удалась. Сохранить ошибку, связаться с технической поддержкой и не отправлять автоматически. |

Приложение может создавать напоминания об истечении срока действия от `licenseStatus` и `expiresAt`. SDK не возвращает отдельный список уведомлений.

После ошибки обработки использования лицензии не делайте вывод только из ошибки, был ли подсчитан экспорт. Сохраняйте полную ошибку и свяжитесь с технической поддержкой.
