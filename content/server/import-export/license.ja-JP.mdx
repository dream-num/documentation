交換は、`@univerjs-pro/exchange-node`を実行しているサーバープロセス内のライセンスを読みます。変換自体については、[オフィスファイルのインポートとエクスポート](/server/import-export/node)を参照してください。

## 認可の設定 [#configure]

標準のアプローチは、環境で`UNIVER_LICENSE`と`UNIVER_LICENSE_KEY`を設定することです。`configureExchange`を呼び出すと、オプションがあります。SDKは、最初のエクスポートまたはクォータクエリで、環境を一度読み、プロセスの残りの部分の構成を保持します。変数が設定されていない場合、無料が適用されます。変数が設定されているが、資格情報が無効な場合は、エラーを呼び出し、それらの資格情報はエクスポートに使用できません。

明示的な設定については、`configureExchange({ license, licenseKey })` を呼び出します。この関数は `Promise<void>`を返し、完全に環境を無視します。そのため、新しい認証情報を使用するべきエクスポートを開始する前に待ってください。

```ts
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

ライセンスプロバイダが供給する`license`と`licenseKey`のコンテンツは、ファイルへのパスではなく、完全なファイルを渡します。 両方の値を設定し、アプリケーションの秘密管理システムからそれらを読みます。

| 入力 | 動作 |
| --- | --- |
| `configureExchange` を呼び出さない | 環境変数の両方が最初の使用時に読み込まれます。変数がセットされていない場合、無料が適用されます。 |
| `configureExchange({ license, licenseKey })` | 明示的な資格情報のみが使用されます。環境は無視されます。 |
| `configureExchange({})` | 自由は明示的に選択されます。環境は無視されます。 |
| 選択したソースの1つのクレデンシャルだけ | コールは `INVALID_ARGUMENT` を返します。他のフィールドは異なるソースから埋め込まれることはありません。 |

完全な環境設定が読み込まれると、後で動作が失敗しても固定されます。 デフォルト認証をランタイムに置き換えるには、`configureExchange` を呼び出して待ちます。 失敗した呼び出しは、以前の設定を所定の位置に残します。 これにより、新しいエクスポートを開始する前にエラーが処理します。

ESM と CommonJS は、同じ JavaScript コンテキスト内で単一の構成を共有します。各 `worker_threads` Worker は、独自の環境から構成または初期化する必要があります。エクスポートは、パブリックエクスポートメソッドが呼び出されたときに配置された構成を使用します。後で、認証を変更することは、既に開始したエクスポートには影響しません。

### 1 回の操作に認可を指定する

デフォルト設定を変更せずに単一の呼び出しを承認するには、エクスポートAPIまたは`getExportQuota`のオプションで完全な`license`と`licenseKey`ペアを渡します。 次の例では、クォータと同じ資格情報でエクスポートします。

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeFormat, exportToBuffer, getExportQuota } from '@univerjs-pro/exchange-node'

const credentials = { license: '<license content>', licenseKey: '<licenseKey content>' }
const quota = await getExportQuota(credentials)
const output = await exportToBuffer(workbook, {
  type: UniverInstanceType.UNIVER_SHEET,
  format: ExchangeFormat.XLSX,
  ...credentials,
})
```

ファイルエクスポート、スナップショットエクスポート、およびオプションのPDFエクスポートは同じペアを受け入れます。両方のフィールドが省略されている場合、デフォルト設定が適用されます。 1つのフィールドのみが供給されると、コールは`INVALID_ARGUMENT`を返します。 明示的なペアは、デフォルトの設定からまたは環境から完了し、空の文字列は省略されたフィールドとしてカウントされません。 無効な認証情報は`LICENSE_INVALID`に戻り、SDKはデフォルトのライセンスに戻っていません。

### オプションの PDF サポート

PDF 拡張パッケージをインストールし、認可を設定する前にそのエントリーをインポートします。

```sh
pnpm add @univerjs-pro/exchange-node @univerjs-pro/exchange-pdf-node-binding
```

```ts
import '@univerjs-pro/exchange-node/pdf'
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

インポートは PDF サポートとネイティブコンポーネントの読み込みを最初に使用したときに登録します。 PDF は同じ `importBuffer`、`importFile`、`exportToBuffer`, `exportToFile` ファイルと対応するスナップショット API を使用します。 `UniverInstanceType.UNIVER_PDF` そして `ExchangeFormat.PDF`。 PDF のみを扱うアプリケーションは、Office のネイティブコンポーネントを必要としません。 環境ベースの設定は、PDF にも適用されます。

## 残りの割り当ての照会 [#quota]

`getExportQuota({ license, licenseKey })` は、認可が共有する Office と PDF の quota の `Promise<ExportQuota>`を返します。 認証情報が省略されると、呼び出しはデフォルトの設定を問い合わせます。 呼び出しはユニットタイプを受け付けず、特定のエクスポートタイプが許可されているかどうかはチェックしません。 エクスポート中にチェックが行われます。

クエリは、クォータを消費したり、予約したりすることができません。また、SDKバージョン、アクティベーション時間、またはエクスポートタイプのエンタイトルメントはチェックしません。ゼロバランスは、成功するスナップショットを返します。他のリクエストは、直後にクォータを摂取する可能性があるため、実際のエクスポートで返されたエラーも処理します。

認可が有効になる前に、限られたクォータに対するクエリは、`periodStart`が将来にある最初の承認月のスナップショットを返します。 成功したクエリ、または`valid`ステータス、エクスポートが許可されていないという意味ではありません。 SDKは、バージョン、アクティベーション、タイプエンタイトル、利用可能なクォータ、およびエクスポート中にconcurrencyをチェックします。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `licenseStatus` | `'not_configured' \| 'expired' \| 'valid'` | エクスポートサブスクリプションは、未設定、期限切れ、または期限切れです。 `valid`は、エクスポートの入学確認が渡されたという意味ではありません。 無効な認証情報はエラーを返します。 |
| `expiresAt` | `string \| null` | UTC ISOのタイムスタンプとしてエクスポートサブスクリプションの有効期限。何も設定されていないか、有効期限が適用されないときに`null`。 |
| `observedAt` | `string` | このスナップショットの UTC ISO タイムスタンプ。 |
| `limit` | `number \| null` | 現在の月間輸出限度額。 クォータが無制限の場合、`null`。 |
| `used` | `number \| null` | 今月の成功を収めたエクスポート。 クォータが無制限であるときの`null`。 |
| `reserved` | `number \| null` | 現在の月のクォータを握る機内輸出。 クォータが無制限であるとき`null`。 |
| `remaining` | `number \| null` | `max(0, limit - used - reserved)`として計算された、まだエクスポート。 クォータが無制限であるとき`null`。 |
| `periodStart` | `string \| null` | UTC ISO は、月単位のクォータウィンドウの起動を促します。最初の期間は、アクティベーションの前に、将来から始まります。クォータが無制限の場合、`null`。 |
| `periodEnd` | `string \| null` | クォータが無制限に`null`の月間限定版のクォータウィンドウのUTC ISO終了。 |

Free（Freemium）の枠は毎月の透かしなしエクスポート枠であり、総エクスポート数の上限ではありません。`remaining` がゼロでも透かし付きの完全なファイルをエクスポートできます。この残数だけを理由に Free のエクスポートを拒否しないでください。商用サブスクリプションの期限後は Free の規則が適用されますが、その月間枠は追加でリセットされず、商用本番利用の許諾も更新されません。

`periodEnd`は、次の月のクォータウィンドウの始まりであり、`expiresAt` はエクスポートサブスクリプションの終了です。サブスクリプションが有効である間、輸出は常に商業用クォータを使用します。 排気は無料を選択しず、次の商用ウィンドウは翌月に始まります。 残りのFree quotaへのサブスクリプションのみの有効期限スイッチはリセットされ、再び付与されません。

上限のある割り当てのスナップショットの例：

```json
{
  "licenseStatus": "valid",
  "expiresAt": "2027-10-19T23:59:59Z",
  "observedAt": "2026-10-21T09:00:00Z",
  "limit": 500,
  "used": 20,
  "reserved": 1,
  "remaining": 479,
  "periodStart": "2026-10-19T00:00:00Z",
  "periodEnd": "2026-11-19T00:00:00Z"
}
```

## 割り当ての消費 [#accounting]

Free（Freemium）には、ライセンス月ごとに 10 回の透かしなしエクスポートが含まれます。その月の 11 回目の成功したエクスポートからも、透かし付きの完全なファイルを出力できます。透かしなし枠は毎月リセットされ、繰り越されません。商用のエクスポート枠、同時実行数、バージョン権限は購入したライセンスに従います。Free と商用ライセンスには、ファイルサイズやセル数の上限はありません。現在の期間と残数はクエリ結果で確認してください。

インポートはエクスポートの承認を必要としず、エクスポートのクォータを消費しません。同じ商用ライセンス共有クォータを使用する1つの展開、オフィスおよびPDFのエクスポート内で。交換変換フォーマットは[オフィスファイルのインポートとエクスポート](/server/import-export/node)にリストされています。

変換が成功するたびに 1 回と数え、Buffer の返却を成功と見なします。その後の書き込み、アップロード、ダウンロードの失敗で回数は戻りません。再変換が成功すると再度数えます。Free の透かしなし枠を使い切っても、以後は透かし付きの完全なファイルを出力できます。有効な商用ライセンスの枠を使い切ると、次のライセンス期間または上限の高い有効なライセンスへのアップグレードまで新規エクスポートは拒否されます。Free 枠には切り替わりません。

## エラー処理 [#errors]

`message`テキストを解析するのではなく、構造化された`code`によるエラーを特定します。 UIは、エラーコードをローカライズされたメッセージにマップすることができます。テクニカルサポートの診断の詳細を保持します。

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeError, ExchangeFormat, exportToBuffer } from '@univerjs-pro/exchange-node'

try {
  const output = await exportToBuffer(workbook, {
    type: UniverInstanceType.UNIVER_SHEET,
    format: ExchangeFormat.XLSX,
  })
} catch (error) {
  if (error instanceof ExchangeError) {
    // error.code に応じたメッセージを表示する。割り当て不足のときは LICENSE_EXPORT_QUOTA_EXCEEDED
    console.error(error.code)
  } else {
    throw error
  }
}
```

下の表は、エラーがクォータクエリ(`getExportQuota`)から発生するか、実際のエクスポートから発生するか否かを示します。 API はどちらも Promise を返すため、`await` と `try/catch`. が必要です。

| コード | 発生する操作 | 意味と対処 |
| --- | --- | --- |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | エクスポートのみ | 現在の期間の商用エクスポート枠が不足しています。残数を照会するか、営業にライセンスの調整を依頼してください。Free の透かしなし枠の消尽だけでは、このエラーは発生しません。 |
| `LICENSE_CONCURRENCY_TIMEOUT` | エクスポートのみ | エクスポートの通貨スロットをタイムアウト待ちます。再度送信する前に、同時エクスポートを削減します。 |
| `LICENSE_UNIT_TYPE_REJECTED` | エクスポートのみ | エクスポートタイプはライセンスで覆われていないか、そのタイプは期限切れです。タイプをカバーする有効なライセンスを提供します。 |
| `LICENSE_INVALID` | 照会、エクスポート | ライセンスは無効です。完全な認証情報をチェックするか、ライセンスプロバイダから更新をリクエストしてください。 |
| `LICENSE_POLICY_INVALID` | 照会、エクスポート | 認可設定はSDKの要件を満たしません。ライセンスプロバイダから更新をリクエストしてください。 |
| `LICENSE_NOT_YET_EFFECTIVE` | エクスポートのみ | 許可はまだ効果を取らない。その有効な日付の後でそれを使用して下さい。 |
| `LICENSE_VERSION_NOT_ALLOWED` | エクスポートのみ | 現在の SDK バージョンがライセンスの範囲外。対応するバージョンを使うか、ライセンスを更新する。 |
| `UNSUPPORTED_FORMAT` | エクスポートのみ | フォーマットはサポートされていないか、ユニットタイプに一致しません。 エクスポートオプションを確認してください。 |
| `INVALID_FILE` | エクスポートのみ | 変換入力は無効です。入力内容をご確認ください。 |
| `INCOMPLETE_SNAPSHOT` | エクスポートのみ | エクスポートデータが不完全です。完全なデータまたは完全なスナップショットを提供します。 |
| `CONVERSION_FAILED` | エクスポートのみ | 変換が失敗しました。 エラーを保持し、入力内容を確認します。 |
| `IO_ERROR` | エクスポートのみ | ファイルの入力や出力が失敗しました。変換が成功し、出力が失敗した場合、エクスポートは既に消費されています。 |
| `INVALID_ARGUMENT` | 照会、エクスポート | 引数や資格情報は不完全です。設定を確認してください。 |
| `NATIVE_LOAD_FAILED` | 照会、エクスポート | ネイティブ SDK コンポーネントがロードできません。インストールされたパッケージがランタイム環境にマッチしていることを確認してください。 |
| `LICENSE_USAGE_STATE_INVALID` | 照会、エクスポート | ライセンス使用状況は検証できません。 エラーを保持し、テクニカルサポートにお問い合わせください。 |
| `LICENSE_USAGE_STORAGE_ERROR` | 照会、エクスポート | ライセンス使用の処理に失敗しました。 エラーを保持し、技術的なサポートに連絡し、自動的に再送信しないでください。 |

アプリケーションは、`licenseStatus`と`expiresAt`から遠赤外線リマインダーを構築することができます。SDKは、通知の別のリストを返すことはありません。

ライセンス使用処理エラー後、エクスポートがカウントされたかどうかだけ、エラーから差し込みません。 完全なエラーを保持し、技術的なサポートにお問い合わせください。
