Excel を Univer で開くには、エディターが読めるデータへ変換します。出力時は編集後のデータを Excel に戻します。サーバーの `@univerjs-pro/exchange-node` が変換し、ブラウザーはアップロード、表示、結果のダウンロードを行います。

## 共同編集を使わない場合

例えば Excel をアップロードし、ページ上で編集して Excel としてダウンロードします。

1. ブラウザーがファイルを送り、サーバーが Univer データに変換して返します。
2. ブラウザーがそのデータでスプレッドシートを開き、編集可能にします。
3. 出力時は編集後のデータをサーバーに送り、ダウンロード用 Excel を生成します。

この処理に共同編集サービスは不要です。ブラウザー API の「スナップショット」がここで扱うデータです。スナップショットの入出力にもサーバー変換は必要です。作業を保存して後で再開するには、アプリケーション側でそのデータも保存してください。

変換モジュールの導入と利用は [Office ファイルの入出力](/server/import-export/node)を参照してください。Node.js でファイルを処理するだけの場合も同じページから始めます。

## 共同編集を使う場合

例えば Excel を取り込み、同僚と共有して共同編集し、後で出力します。

1. サーバーがファイルを変換し、結果を共同編集ドキュメントとして保存します。
2. サーバーが ID を返し、ブラウザーが読み込みます。他のユーザーも同じ ID で参加します。
3. 出力時は最新の内容を読み、ダウンロード用 Excel を生成します。

ブラウザー API の `unitId` がこの ID です。[共同編集の統合](/server/collaboration/browser-integration)を終えてから [Exchange の例](/server/collaboration/examples#exchange)を実行し、ブラウザー、サーバー、変換コードを合わせて確認してください。

出力前に現在の編集の同期を待たないと、最新の変更が欠落する場合があります。共同編集ドキュメントの取得と変換は[拡張モジュール](/server/collaboration/extensions)のサーバー側 Office Exchange を参照してください。

## 入出力ボタンの接続

サーバー変換が動作したらページへ接続します。

- **Univer メニューまたは Facade API：** [Exchange の例](/server/collaboration/examples#exchange)に従いアップロード、変換、タスク照会、ダウンロードの API を実装し、ブラウザープラグインを設定します。アドレスとレスポンス形式を一致させてください。
- **独自ボタン：** アプリケーション API を呼びます。取り込み後は返されたデータまたは ID を開き、出力後は生成ファイルをダウンロードします。

ブラウザー設定は [Sheets](/guides/sheets/features/import-export)、[Docs](/guides/docs/features/import-export)、[Slides](/guides/slides/features/import-export)、[Boards](/guides/boards/features/import-export)、[Bases](/guides/bases/features/import-export)、[PDFs](/guides/pdfs/features/import-export) を参照してください。共同編集例は Sheets を扱います。他製品は [Office ファイルの入出力](/server/import-export/node)と対象リリースの対応形式を確認してください。

## 統合の検証

実際の業務ファイルを取り込み、編集して出力します。Office アプリケーションで開き、変更、数式、画像、レイアウトを確認してください。共同編集では他のユーザーも同じドキュメントを開けることと、サーバー再起動後の保持も検証します。

配置前にサンプルの一時ファイルとメモリ上のタスクをアプリケーションのストレージに置き換え、容量制限、変換失敗、タイムアウトを処理してください。アップロード、タスク照会、ダウンロードにはアクセス検証が必要です。[ID と認可](/server/collaboration/identity-and-authorization)を参照してください。

## エクスポート失敗とライセンス制限 [#export-errors]

エクスポートは要求送信時にもタスクのポーリング中にも失敗します。HTTP 成功だけでは完了を判断できません。プロトコルの `error.code` とタスク状態を確認してください。Exchange クライアントは `IExchangeService.requestState$` でサーバーのエクスポートエラーを伝えるため、独自 UI は操作前に購読できます。

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | 対処 |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | 文書を小さくするか、エクスポート上限の大きいライセンスを使います。 |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 残りのエクスポート枠とリセット規則を確認します。 |
| `LICENSE_CONCURRENCY_TIMEOUT` | 変換処理に空きができてから再試行します。 |
| `LICENSE_VERSION_NOT_ALLOWED` | サーバーライセンスが対象とするバージョンを使います。 |
| `LICENSE_UNIT_TYPE_REJECTED` | サーバーライセンスが文書形式を許可しているか確認します。 |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | サーバーのライセンス設定、使用量情報、ストレージを確認します。 |

翻訳済みメッセージを解析せず、`@univerjs/protocol` の `ErrorCode` 名で判定し、診断用にサーバーメッセージを保持してください。通信失敗、不正なタスク応答、ポーリングのタイムアウトは汎用エラーになる場合があり、ライセンス拒否とは限りません。エディターを削除するときは `subscription.unsubscribe()` で購読を解除します。

独自のバックエンドやプロキシでは構造化エラーを保持し、失敗したタスクを pending のままにしないでください。`maxTimeoutTime` を増やしてもポーリング時間が延びるだけで、エクスポート枠や許可範囲は変わりません。
