エディタは、直接Excelファイルを開くことができません。 サーバは、最初にファイルをUniverドキュメントデータに変換し、エクスポート上で、編集されたデータをExcelファイルに変換します。 どちらの指示も、サーバー側`@univerjs-pro/exchange-node`モジュールを使用します。 ブラウザはファイルをアップロードし、ドキュメントを開き、結果をダウンロードします。

## 共同編集を使わない場合

典型的なシナリオでは、ユーザーはExcelファイルをアップロードし、ページ上で編集し、結果をExcelファイルとしてダウンロードします。

1. ブラウザはファイルをアップロードします。サーバーはファイルをUniverドキュメントデータに変換し、データを返します。
2. ブラウザは、そのデータからスプレッドシートを開き、編集の準備が整いました。
3. エクスポートでは、ブラウザは編集したデータをサーバーに送信し、サーバーはダウンロード用にExcelファイルを生成します。

このパスにはコラボレーションサービスはありません。ブラウザ API の *snapshot* は、ここで使用されているドキュメントデータです。スナップショットのインポートやエクスポートは、サーバー側の変換が必要です。ユーザーが自分の仕事を保存し、後で返すようにするには、アプリケーションは、そのデータを格納する必要があります。

[オフィスファイルのインポートとエクスポート](/server/import-export/node)にコンバージョンモジュールをインストールして使用しています。このページは、アプリケーションがNode.jsでファイル処理のみを必要とする場合の開始点です。

## 共同編集を使う場合

このシナリオでは、ユーザーはExcelファイルをインポートし、文書を同僚と共有し、それらを編集し、後でそれをエクスポートします。

1. サーバーがファイルを変換し、結果を共同編集ドキュメントとして保存します。
2. サーバはドキュメント ID を返します。ブラウザは、その ID によってドキュメントを開き、他のユーザーは同じ ID でドキュメントに参加します。
3. エクスポートでは、サーバーはドキュメントの最新のコンテンツを読み込み、ダウンロード用のExcelファイルを生成します。

そのドキュメント ID は、ブラウザ API の `unitId` です。[コラボレーション統合](/server/collaboration/browser-integration)を最初に設定し、[交換例](/server/collaboration/examples#exchange). を実行します。例は、ブラウザ、サーバー、およびコンバージョンコードをサイドで表示します。

Pending 編集はエクスポート前に同期しなければなりません。 それ以外の場合は、エクスポートされたファイルは最新の変更を見逃すことができます。 共同文書を読んで変換するには、[拡張モジュール](/server/collaboration/extensions) のサーバー側 Office Exchange セクションを参照してください。

## 入出力ボタンの接続

サーバ側のコンバージョンが機能したら、次のステップはページに接続することです。

- UniverのメニューやファサードAPIを使用するアプリケーションは、[交換例](/server/collaboration/examples#exchange)と同じ方法でFile EndpointとExchange Endpointを登録し、ブラウザプラグインを設定します。
- 独自のボタンを提供するアプリケーションは、アプリケーション API を呼び出します。ドキュメントデータやドキュメント ID をインポートで返し、エクスポート後に生成されたファイルをダウンロードします。

各製品のブラウザ構成は[シート](/guides/sheets/features/import-export)、[ドキュメント](/guides/docs/features/import-export)の[スライド](/guides/slides/features/import-export)は、[ボード](/guides/boards/features/import-export)と[ベース](/guides/bases/features/import-export)および[PDFファイル](/guides/pdfs/features/import-export)にあります。 コラボレーション例はシートを示しています。 他の製品については、[オフィスファイルのインポートとエクスポート](/server/import-export/node)を参照してください。 インストールされたリリースがどのフォーマットをサポートしていますかを確認してください。

## 統合の検証

インポート、編集、およびエクスポートを通じて、アプリケーションから実際のファイルを取ります。 結果をOfficeアプリケーションで開き、編集、式、画像、レイアウトを確認します。 コラボレーションにより、他のユーザーは同じ文書を開くことができ、コンテンツがサーバーの再起動を生き延ばすことができることを確認します。

展開前に、アップロードサイズを制限し、変換の失敗とタイムアウトを処理します。 アップロード、タスクのクエリ、ダウンロードはすべてアクセスチェックを必要とします。 [アイデンティティと権限](/server/collaboration/identity-and-authorization)を参照してください。

## プラグイン設定 [#exchange-client-configuration]

`UniverExchangeClientPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | ファイルのダウンロードのためのベースURL。 |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | アップロードされたファイルを受け取るエンドポイント。 |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | インポートを開始するエンドポイント。`{type}`プレースホルダーをキープします。 |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | エクスポートを開始するエンドポイント。 `{type}`プレースホルダーをキープします。 |
| `getTaskServerUrl` | `string` | `'/universer-api/exchange/task/{taskID}'` | タスクステータスのエンドポイント。`{taskID}`プレースホルダーをキープします。 |
| `signUrlServerUrl` | `string` | `'/universer-api/file/{fileID}/sign-url'` | ファイルURLを標識するエンドポイント。`{fileID}`プレースホルダーをキープします。 |
| `maxTimeoutTime` | `number` | `120000` | 変換タスクをポーリングする最長時間。単位はミリ秒です。 |

## OLE 添付ファイルの設定 [#ole-configuration]

`UniverDrawingPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | OLE添付ファイルの設定 |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | オンライン添付ファイル用のアプリケーションリンクをビルドします。 |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | アプリケーションストレージに元の添付ファイルを読み書きします。 |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | 添付ファイルをアプリのストレージに保存し、このユニットに関連付けます。 |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | アプリのストレージから添付ファイルのバイト列を読み込みます。 |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | オフィスプレビューフローをオーバーライドします。 |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | アプリケーションのコールバックでOfficeのプレビューを作成します。 |

追加する `ole` 既存のものへ `UniverDrawingPlugin` Exchange が登録される前に登録します。 下のルートはアプリケーションに属し、アプリケーションのドキュメント UI を指す必要があります。 オプションの 2 番目の `getLink` 引数は、必要に応じてドキュメントタイプを運びます。 Exchange は、Office の変換を実行し、コラボレーション状態を検知します。 UUID によってキー化された添付ファイルも必要です。 `ole.attachmentIo`、承認されると `upload(file, targetUnitId)` そして、 `read(attachment, signal)` コールバック。 Office プレビューは、マッチング レンダラーまたはアプリケーション provided が必要です。 `previewOffice` / `createOfficePreview` コールバック。

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## エクスポート失敗とライセンス制限 [#export-errors]

タスクがポーリングされる間、エクスポートは、送信時に失敗することができます。 成功したHTTPレスポンスだけでは、ファイルが準備が整っているわけではありません。 プロトコルとタスク状態の`error.code`を確認してください。 交換クライアントは、`IExchangeService.requestState$`のサーバーのエクスポートエラーを保持しているため、動作を開始する前にカスタムエクスポートUIを購読できます。

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | 対処 |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | 文書を小さくするか、エクスポート上限の大きいライセンスを使います。 |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 残りのエクスポート枠とリセット規則を確認します。 |
| `LICENSE_CONCURRENCY_TIMEOUT` | 変換容量が利用可能になったら、後で再試行してください。 |
| `LICENSE_VERSION_NOT_ALLOWED` | サーバーライセンスが対象とするバージョンを使います。 |
| `LICENSE_UNIT_TYPE_REJECTED` | サーバーライセンスが文書形式を許可しているか確認します。 |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | サーバのライセンス構成、使用状況、ストレージを調べます。 |

`@univerjs/protocol` から名前付けされた `ErrorCode`値にマッチします。翻訳されたメッセージのテキストを解析しないでください。サーバーのメッセージは、診断のために保持します。ネットワークの失敗、マルフォームされたタスクの応答、およびポーリングのタイムアウトは、一般的な失敗として表面することができます。それらのどれも、ライセンスがエクスポートを拒否したことが証明されていません。エディタが削除されたときに `subscription.unsubscribe()`を呼び出します。

アプリケーションが前面に独自のバックエンドまたはプロキシを展開する場合、そのバックエンドまたはプロキシは構造化されたエラー応答を経由して渡し、タスクが終わるのではなく失敗をマークしなければなりません。 `maxTimeoutTime` を上げることは、より多くの時間をポーリングするだけです。 エクスポートクォータを追加したり、ライセンスカバーを変更したりすることはありません。

## OLE 添付ファイル [#ole-attachments]

シート、ドキュメント、およびスライドは、プレビュー画像から別々にOLEファイルをインポートしました。 ユーザーは、利用可能なときに元のファイルをダウンロードし、イベントの名前を変更し、許可を持っている場合は添付ファイルを削除します。 画像とPDF添付ファイルをプレビューすることができます。 オフィスプレビューは、Exchange JSON変換を一時読み取り専用エディタに移動し、プレビューを開くと、永続的な子文書を作成しません。 ネイティブオフィスアプリケーションとマクロは実行しません。

オンラインで文書にOfficeの添付ファイルを作成するには、共同ホスト、編集権限、変換サポート、および`getLink`が必要です。変換は、独立した文書を作成して、そのアイデンティティを添付ファイルに保存するので、その後、その文書を再使用します。文書を編集することは元の添付ファイルバイトを上書きしません。 ミス、外部、または未サポートの添付ファイルは、編集可能なOfficeオブジェクトに切り替える代わりに、ステータスを保持します。

エクスポートはデフォルトで`oleAttachmentSource: 'original'`を使用します。`'online'`に設定して、変換されたオンライン文書の現在の確認バージョンを1つのエクスポートに埋め込むようにします。保存されたオリジナルは書き換えられません。 編集はエクスポート前に同期し、バックエンドは参照された文書へのアクセスを承認しなければなりません。 DocsとSlidesのエクスポートAPIへの2番目の引数としてオプションを渡すか、シートのエクスポートAPIの4番目の引数として。 スナップショットのバリアントは同じポジションでそれを受け入れます。 [エクスポート API](/reference/facade/univer#exportsheetbyunitidasync)を参照してください。

永続的な添付ファイルの場合、Exchangeは`fileID`と`sourceUnitID`を提出します。 参照によって変換する前に、インポートのバックエンドは、2つのリレーションと呼び出し者のアクセスを確認する方法を検証する必要があります。 タスクをポーリングすると、`reading`、`converting`、`creating`、または`done`として`progress.stage`を返すことができます。 カスタム変換UIについては、[添付ファイルインポートと進捗API](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress)を参照してください。
