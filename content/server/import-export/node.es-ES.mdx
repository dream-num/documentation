---
title: Importación y exportación de archivos Office
description: Usa Exchange para importar y exportar contenido entre archivos Office y Units colaborativas.
---

La conversión de archivos de oficina es manejada por `@univerjs-pro/exchange-node`, no por AI SDK. En el límite de archivo, una aplicación CLI llama `importFile()` y `exportToFile()`, luego utiliza AI SDK y Collaboration SDK para operar en la Unidad.

## Mantener los límites de los SDK

```ts
import { exportToFile, importFile } from "@univerjs-pro/exchange-node";
```

| Capacidad | Responsable |
| --- | --- |
| Convertir archivos de Office en UnitData | Exchange |
| Runtime sin interfaz, inspección y ejecución Facade | AI SDK |
| Instantáneas, conjuntos de cambios, revisiones y persistencia | Collaboration SDK |
| Rutas, políticas de formato, API de negocio y mapeo de errores | Aplicación de negocio |

## Importar una Unit colaborativa

La aplicación de negocio lee un archivo de Office a través de Exchange y pasa el UnitData resultante al Servidor de Colaboración, que crea la Unidad:

```text
archivo Office
→ importFile()
→ UnitData
→ API del servidor de negocio
→ Unit colaborativa
```

La aplicación determina la revisión inicial, los metadatos de negocio y el resultado que se devuelve. Una vez que la Unidad existe, tanto el CLI como la Web lo operan a través del Servidor.

## Exportar la última revisión

Para la exportación, el CLI carga la última revisión confirmada a través de Collaboration Runtime, luego pasa el UnitData completo a Exchange:

```text
Unit colaborativa
→ últimas UnitData
→ exportToFile()
→ archivo Office
```

La extensión del archivo de salida determina el formato.

## Exponer las operaciones de archivo con Commander

AI SDK no proporciona un paquete de comando preset para la importación y exportación de archivos de Office. La aplicación empresarial utiliza Commander para combinar Exchange, Collaboration Runtime y su propia API de servidor:

```ts
import { Command } from "commander";

interface IFileExchangeDependencies {
  importFile(path: string): Promise<unknown>;
  createUnit(unitData: unknown): Promise<unknown>;
  loadLatestUnitData(unitId: string): Promise<unknown>;
  exportFile(unitData: unknown, path: string): Promise<void>;
  writeResult(result: unknown): void;
}

function addFileExchangeCommands(program: Command, dependencies: IFileExchangeDependencies): void {
  program.addCommand(
    new Command("import").argument("<office-file>").action(async (sourcePath) => {
      const unitData = await dependencies.importFile(sourcePath);
      const created = await dependencies.createUnit(unitData);
      dependencies.writeResult(created);
    }),
  );

  program.addCommand(
    new Command("export")
      .argument("<office-file>")
      .requiredOption("--unit <id>")
      .action(async (outputPath, { unit }) => {
        const unitData = await dependencies.loadLatestUnitData(unit);
        await dependencies.exportFile(unitData, outputPath);
      }),
  );
}
```

Cada capacidad fuera de Commander se declara explícitamente en `IFileExchangeDependencies`, por lo que los comandos no confían en ningún ayudante oculto. La aplicación realiza la conversión de archivos llamando `importFile()` y `exportToFile()`, implementa `loadLatestUnitData()` en Collaboration Runtime, y inyecta su propia API de servidor y la salida de resultados.

## Formatos compatibles

| Unit | Importación | Exportación |
| --- | --- | --- |
| Sheet | `.xls`, `.xlsx`, `.xlsm`, `.csv`, `.tsv` | `.xlsx`, `.csv`, `.tsv` |
| Doc | `.doc`, `.docx` | `.docx` |
| Slide | `.ppt`, `.pptx`, `.pptm`, `.ppsx`, `.ppsm`, `.potx` | `.pptx` |

La aplicación debe rechazar una extensión que no coincida con el tipo de Unidad antes de generar un archivo.

## Usar solo una CLI local

Una aplicación puede pasar al Servidor de Colaboración pasando el contenido importado directamente a un tiempo de ejecución local sin cabeza y exportando un archivo de Office. Este enfoque se adapta a un procesamiento de una sola vez, pero no proporciona revisiones compartidas, vista previa web en vivo, historia o Worktree.

Los nombres de comandos, los argumentos de ruta y la presentación de resultados siguen siendo la responsabilidad de la aplicación de negocio. Para el camino de unidad colaborativa, vea [Carga de documentos y operaciones de contenido](/ai/content-operations). Una vez que el límite de archivo está en su lugar, continúe con [Inspección visual](/ai/visual-inspection), que permite a un agente verificar el UnitData renderizado.
