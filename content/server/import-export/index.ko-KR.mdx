Univer에서 Excel을 열려면 먼저 편집기가 읽을 수 있는 데이터로 변환하고, 내보낼 때는 편집한 데이터를 Excel로 변환합니다. 서버의 `@univerjs-pro/exchange-node`가 변환을 담당하고 브라우저는 업로드, 문서 열기, 결과 다운로드를 담당합니다.

## 공동 편집 없이 사용

예를 들어 사용자가 Excel을 업로드하고 페이지에서 편집한 뒤 결과를 Excel로 다운로드합니다.

1. 브라우저가 파일을 업로드하면 서버가 Univer 문서 데이터로 변환해 반환합니다.
2. 브라우저가 해당 데이터로 스프레드시트를 열어 편집하게 합니다.
3. 내보내기 시 편집한 데이터를 서버에 보내 다운로드할 Excel을 생성합니다.

이 흐름에는 공동 편집 서비스가 필요하지 않습니다. 브라우저 API의 스냅샷이 여기서 사용하는 문서 데이터입니다. 스냅샷 가져오기·내보내기에도 서버 변환이 필요합니다. 사용자가 저장 후 나중에 돌아오게 하려면 애플리케이션이 해당 데이터를 저장해야 합니다.

변환 모듈의 설치와 사용은 [Office 파일 가져오기 및 내보내기](/server/import-export/node)를 참고하세요. Node.js에서 파일만 처리하는 경우도 여기서 시작하세요.

## 공동 편집 사용

예를 들어 Excel을 가져와 동료와 공유하고 함께 편집한 후 내보냅니다.

1. 서버가 업로드한 파일을 변환해 공동 편집 문서로 저장합니다.
2. 서버가 ID를 반환하면 브라우저가 해당 ID를 열고 다른 사용자도 같은 ID로 참여합니다.
3. 내보내기 시 서버가 최신 내용을 읽어 다운로드할 Excel을 생성합니다.

브라우저 API의 `unitId`가 이 문서 ID입니다. 먼저 [공동 편집 통합](/server/collaboration/browser-integration)을 완료하고 [Exchange 예제](/server/collaboration/examples#exchange)를 실행하세요. 브라우저, 서버, 변환 코드를 함께 참고할 수 있습니다.

현재 편집이 동기화된 뒤 내보내세요. 그렇지 않으면 최신 변경이 빠질 수 있습니다. 공동 편집 문서를 읽고 변환하는 방법은 [확장 모듈](/server/collaboration/extensions)의 서버 측 Office Exchange를 참고하세요.

## 가져오기·내보내기 버튼 연결

서버 변환이 동작하면 페이지에 연결하세요.

- **Univer 메뉴 또는 Facade API 사용:** [Exchange 예제](/server/collaboration/examples#exchange)에 따라 업로드, 변환, 작업 조회, 다운로드 인터페이스를 구현하고 브라우저 플러그인을 설정하세요. 요청 주소와 응답 형식이 일치해야 합니다.
- **자체 버튼 사용:** 애플리케이션 API를 호출하세요. 가져오기 후 반환된 문서 데이터나 ID를 열고, 내보내기 후 생성된 파일을 다운로드하세요.

브라우저 설정은 [Sheets](/guides/sheets/features/import-export), [Docs](/guides/docs/features/import-export), [Slides](/guides/slides/features/import-export), [Boards](/guides/boards/features/import-export), [Bases](/guides/bases/features/import-export), [PDFs](/guides/pdfs/features/import-export)를 참고하세요. 공동 편집 예제는 Sheets를 사용합니다. 다른 제품은 [Office 파일 가져오기 및 내보내기](/server/import-export/node)와 해당 릴리스의 지원 형식을 확인하세요.

## 통합 확인

실제 업무 파일을 가져와 편집하고 내보내세요. Office 애플리케이션에서 결과를 열어 변경 사항, 수식, 이미지, 레이아웃을 확인하세요. 공동 편집에서는 다른 사용자도 같은 문서를 열 수 있고 서버 재시작 후 내용이 유지되는지 확인하세요.

배포 전에 예제의 임시 파일과 메모리 작업을 애플리케이션 저장소로 교체하고 업로드 크기를 제한하며 변환 실패와 시간 초과를 처리하세요. 업로드, 작업 조회, 다운로드에는 접근 검사가 필요합니다. [신원 및 권한 부여](/server/collaboration/identity-and-authorization)를 참고하세요.

## 내보내기 실패와 라이선스 제한 [#export-errors]

내보내기는 요청 제출이나 작업 폴링 중 실패할 수 있습니다. HTTP 성공만으로 파일 생성 완료를 판단하지 말고 프로토콜 `error.code`와 작업 상태를 확인하세요. Exchange 클라이언트는 `IExchangeService.requestState$`로 서버의 내보내기 오류를 전달하므로 사용자 UI에서 작업 전에 구독할 수 있습니다.

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | 처리 방법 |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | 문서를 줄이거나 더 큰 내보내기 제한을 허용하는 라이선스를 사용하세요. |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 남은 내보내기 할당량과 초기화 규칙을 확인하세요. |
| `LICENSE_CONCURRENCY_TIMEOUT` | 변환 용량이 확보된 뒤 다시 시도하세요. |
| `LICENSE_VERSION_NOT_ALLOWED` | 서버 라이선스가 지원하는 버전을 사용하세요. |
| `LICENSE_UNIT_TYPE_REJECTED` | 서버 라이선스가 문서 유형을 지원하는지 확인하세요. |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | 서버 라이선스 설정, 사용량 상태, 저장소를 점검하세요. |

번역된 메시지를 파싱하지 말고 `@univerjs/protocol`의 명명된 `ErrorCode`를 비교하세요. 서버 메시지는 진단용으로 보관하세요. 네트워크 오류, 잘못된 응답, 폴링 시간 초과는 일반 오류일 수 있으므로 라이선스 거부로 단정하지 마세요. 편집기를 제거할 때 `subscription.unsubscribe()`로 구독을 해제하세요.

사용자 정의 백엔드나 프록시는 구조화된 오류 응답을 보존하고 실패 작업을 계속 pending으로 두지 않아야 합니다. `maxTimeoutTime`을 늘려도 폴링 시간만 늘어날 뿐 할당량이나 라이선스 범위는 바뀌지 않습니다.
