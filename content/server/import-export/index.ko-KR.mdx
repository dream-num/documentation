편집기는 Excel 파일을 직접 열 수 없습니다. 서버는 먼저 Univer 문서 데이터로 파일을 변환하고 내보내기에서 Excel 파일로 편집 된 데이터를 변환합니다. 두 방향은 서버 측 `@univerjs-pro/exchange-node` 모듈을 사용합니다. 브라우저는 파일을 업로드하고 문서를 열고 결과를 다운로드합니다.

## 공동 편집 없이 사용

전형적인 시나리오에서 사용자는 Excel 파일을 업로드하고 페이지를 편집하고 Excel 파일로 결과를 다운로드합니다.

1. 브라우저는 파일을 업로드합니다. 서버는 Univer 문서 데이터로 파일을 변환하고 데이터를 반환합니다.
2. 브라우저는 그 데이터에서 스프레드 시트를 열고 편집 할 준비가되어 있습니다.
3. 내보내기에서 브라우저는 편집 된 데이터를 서버에 보냅니다. 서버는 다운로드 Excel 파일을 생성합니다.

이 경로는 협업 서비스를 포함하지 않습니다. 브라우저 API의 *snapshot*는 여기에 사용되는 문서 데이터입니다. 스냅 샷을 가져 오기 또는 내보내는 것은 서버 측 변환을 필요로합니다. 사용자가 작업을 저장하고 나중에 다시 돌아갈 수 있도록 응용 프로그램은 데이터 자체를 저장해야합니다.

변환 모듈을 사용하여 [Office 파일 가져 오기 및 내보내기](/server/import-export/node)에 덮여있다. 그 페이지는 Node.js에서 처리하는 응용 프로그램 만 필요로하는 경우 시작 지점이기도합니다.

## 공동 편집 사용

이 시나리오에서 사용자는 Excel 파일을 가져 와서 동료와 문서를 공유하고 나중에 파일을 내보내고 나중에 내보내십시오.

1. 서버가 업로드한 파일을 변환해 공동 편집 문서로 저장합니다.
2. 서버는 문서 ID를 반환합니다. 브라우저는 ID로 문서를 열고 다른 사용자는 동일한 ID로 문서에 가입합니다.
3. 수출에, 서버는 문서의 최신 내용을 읽고 다운로드에 대한 Excel 파일을 생성합니다.

그 문서 ID는 브라우저 API에서 `unitId`입니다. [협업 통합](/server/collaboration/browser-integration)를 먼저 설정한 다음 [Exchange 예제](/server/collaboration/examples#exchange)을 실행합니다. 예는 브라우저, 서버 및 변환 코드 측을 나타냅니다.

Pending edits는 수출의 앞에 동기화해야 합니다; 그렇지 않으면 수출한 파일은 최신 변화를 놓을 수 있습니다. collaborative 문서를 읽고 개조하기 위하여는, [확장 모듈](/server/collaboration/extensions)에 있는 서버 측 사무실 교환 단면도를 보십시오.

## 가져오기·내보내기 버튼 연결

서버 측 변환이 작동되면 다음 단계는 페이지로 연결됩니다.

- Univer의 메뉴 또는 Facade API를 사용하는 응용 프로그램은 [Exchange 예제](/server/collaboration/examples#exchange)와 같은 방식으로 파일 엔드포인트 및 Exchange 엔드포인트를 등록하고 브라우저 플러그인을 구성합니다.
- 자신의 버튼 호출 응용 프로그램을 제공하는 응용 프로그램 API: 그들은 문서 데이터를 열고 또는 문서 ID는 수입에 의해 반환, 그리고 수출 후 생성 된 파일을 다운로드.

각 제품에 대한 브라우저 구성은 [제품정보](/guides/sheets/features/import-export), [팟캐스트](/guides/docs/features/import-export)의 [제품정보](/guides/slides/features/import-export)에서 [회사연혁](/guides/boards/features/import-export)와 [기본 정보](/guides/bases/features/import-export) 및 [PDF 파일](/guides/pdfs/features/import-export)입니다. 공동 예제는 시트를 보여줍니다. 다른 제품에 대해서는 [Office 파일 가져 오기 및 내보내기](/server/import-export/node)를 참조하고 설치 된 릴리스 지원 형식을 확인합니다.

## 통합 확인

수입, 편집 및 수출을 통해 응용 프로그램에서 실제 파일을 가져 가라. Office 응용 프로그램에 결과를 열고 편집, 공식, 이미지 및 레이아웃을 확인하십시오. 협업으로 다른 사용자가 동일한 문서를 열 수 있으며 컨텐츠가 서버 재시작을 유지할 수 있음을 확인합니다.

배포, 제한 업로드 크기 및 처리 변환 실패 및 타임 아웃. 업로드, 작업 쿼리, 모든 액세스 체크를 다운로드. 참조 [ID 및 인증](/server/collaboration/identity-and-authorization).

## 플러그인 설정 [#exchange-client-configuration]

`UniverExchangeClientPlugin`

| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | 파일 다운로드에 대한 기본 URL. |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | 업로드된 파일을 수신하는 엔드포인트. |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | 수입을 시작하는 엔드포인트. `{type}` 플레이스홀더 유지. |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | 수출을 시작하는 엔드포인트. `{type}` 플레이스홀더 유지. |
| `getTaskServerUrl` | `string` | `'/universer-api/exchange/task/{taskID}'` | 작업 상태에 대한 엔드포인트. `{taskID}` 플레이스홀더를 유지하십시오. |
| `signUrlServerUrl` | `string` | `'/universer-api/file/{fileID}/sign-url'` | 파일 URL을 표시하는 엔드포인트. `{fileID}` 플레이스홀더를 유지하십시오. |
| `maxTimeoutTime` | `number` | `120000` | 변환 작업을 폴링하는 최대 시간입니다. 단위는 밀리초입니다. |

## OLE 첨부 파일 설정 [#ole-configuration]

`UniverDrawingPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | OLE 첨부 파일에 대한 설정. |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | 온라인 첨부 파일에 대한 응용 링크 구축. |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | Application Storage에서 원래 첨부 파일을 읽고 작성합니다. |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | 첨부 파일을 앱 저장소에 쓰고 현재 단위에 연결합니다. |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | 앱 저장소에서 첨부 파일 바이트를 읽습니다. |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | Office 미리보기 흐름을 무시합니다. |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | Application 콜백으로 Office 미리보기를 빌드합니다. |

Exchange가 등록되기 전에 기존 `UniverDrawingPlugin` 등록에 `ole`을 추가합니다. 아래의 경로는 응용 프로그램에 속하고 응용 프로그램의 문서 UI에 포인트를해야합니다. 옵션 두 번째 `getLink` 인수는 필요한 경우 문서 유형을 수행합니다. Exchange는 Office 변환을 수행하고 공동 상태를 감지합니다. UUID에 의해 keyed 첨부 파일은 `ole.attachmentIo`, 공인 `upload(file, targetUnitId)` 및 `read(attachment, signal)` 콜백이 필요합니다. Office 미리보기는 일치 렌더링 또는 응용 프로그램 보호 `previewOffice` / `createOfficePreview` 통화를 요구합니다.

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## 내보내기 실패와 라이선스 제한 [#export-errors]

수출은 제출 시간 또는 나중에 실패 할 수 있지만 작업이 오염되어 있습니다. 성공적인 HTTP 응답은 혼자 파일은 준비가되어 있지 않습니다. 프로토콜 및 작업 상태의 `error.code`를 확인하십시오. 교환 클라이언트는 `IExchangeService.requestState$`에서 서버 수출 오류를 유지하므로 사용자 정의 수출 UI가 작동하기 전에 구독 할 수 있습니다.

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | 처리 방법 |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | 문서를 줄이거나 더 큰 내보내기 제한을 허용하는 라이선스를 사용하세요. |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 남은 내보내기 할당량과 초기화 규칙을 확인하세요. |
| `LICENSE_CONCURRENCY_TIMEOUT` | 나중에 다시, 변환 용량을 사용할 수 있습니다. |
| `LICENSE_VERSION_NOT_ALLOWED` | 서버 라이선스가 지원하는 버전을 사용하세요. |
| `LICENSE_UNIT_TYPE_REJECTED` | 서버 라이선스가 문서 유형을 지원하는지 확인하세요. |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | 서버 라이센스 구성, 사용 상태 및 저장을 검사합니다. |

`@univerjs/protocol`의 `ErrorCode` 값에 일치; 번역된 메시지 텍스트를 파싱하지 마십시오. 진단을위한 서버의 메시지를 유지하십시오. 네트워크 실패, 변형 작업 응답 및 오염 타임 아웃은 대신 일반적인 실패로 표면 할 수 있으며 수출을 거부 한 라이센스가 없다는 것을 증명합니다. 편집기가 제거되면 `subscription.unsubscribe()`를 호출하십시오.

애플리케이션이 앞의 자체 백엔드 또는 프록시를 배포하면 백엔드나 프록시가 구조 오류 응답을 통과하고 작업이 종료되지 않고 실패한 것을 표시해야합니다. `maxTimeoutTime`를 상승하면 더 많은 시간을 오염시킵니다. 그것은 수출 할당량을 추가하거나 라이센스 표지를 변경하지 않습니다.

## OLE 첨부 파일 [#ole-attachments]

파일 형식은 파일 형식의 파일 형식을 변경할 수 있습니다. 파일 형식의 이미지는 파일 형식의 파일을 변환하는 것입니다. 파일 형식은 이미지 형식의 이미지 형식을 변경하고, 파일 형식을 수정할 수 있으며, 파일 형식의 형식을 변경하거나, 파일 형식은 파일을 변환 할 수 있습니다. 이미지와 PDF 파일 형식은 파일의 형식을 변경하는 데 사용할 수 있습니다.

Office 첨부 파일을 온라인 문서로 변환하는 것은 협업 호스트, 편집 권한, 변환 지원 및 `getLink`가 필요합니다. 변환은 독립적 인 문서를 작성하고 첨부 파일에 대한 정체성을 저장하므로 나중에 문서가 다시 사용할 수 있습니다. 문서 편집은 원본 첨부 파일 바이트를 덮지 않습니다. 미스링, 외부 또는 지원되지 않은 첨부 파일은 편집 가능한 Office 개체로 전환하는 대신 해당 상태를 유지합니다.

기본으로 `oleAttachmentSource: 'original'`를 사용합니다. `'online'`로 설정하면 현재 1개의 수출에 있는 각 변환 온라인 문서의 버전을 확인했습니다. 저장된 원본은 rewritten이 아닙니다. 편집은 수출 전에 동기화해야 하며, 백엔드는 참조된 문서에 접근을 허가해야 합니다. 두 번째 인수로 Docs 및 슬라이드 수출 API에 대한 옵션을 통과하거나, 내보내기 APIs. Snapshot 변형은 [수출 API](/reference/facade/univer#exportsheetbyunitidasync)2QXQXZ에 동일하게 허용됩니다.

persisted 부착물의 경우 Exchange는 `fileID` 및 `sourceUnitID`을 제출합니다. 참고로 변환하기 전에, 수입 백엔드는 두 개의 리레이트를 확인하고 콜러의 액세스를 확인하는 방법을 검증해야합니다. 작업을 오염하면 `progress.stage`을 `reading`, `converting`, `creating` 또는 `done`으로 반환 할 수 있습니다. 사용자 정의 변환 UI의 경우 [첨부 파일 및 진행 APIs](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress)을 참조하십시오.
