El intercambio lee la licencia dentro del proceso del servidor que ejecuta `@univerjs-pro/exchange-node`. Para la conversión en sí, vea [Importación y exportación de archivos de oficinas](/server/import-export/node) .

## Configurar la autorización [#configure]

El enfoque estándar es establecer `UNIVER_LICENSE` y `UNIVER_LICENSE_KEY` en el ambiente. Llamar `configureExchange` es entonces opcional: el SDK lee el medio ambiente una vez, en la primera consulta de exportación o cuota, y mantiene esa configuración para el resto del proceso. Cuando no se establece ninguna variable, se aplica gratis. Cuando las variables se establecen pero las credenciales son inválidas, las llamadas devuelven un error, y esas credenciales no se pueden utilizar para exportar.

Para una configuración explícita, llame a `configureExchange({ license, licenseKey })`. La función devuelve `Promise<void>` e ignora completamente el medio ambiente, así que espere antes de comenzar las exportaciones que deben utilizar las nuevas credenciales.

```ts
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

Pase el contenido completo `license` y `licenseKey` suministrado por el proveedor de licencias, no caminos a los archivos. Establecer ambos valores juntos y leerlos desde el sistema de gestión secreta de la aplicación.

| Entrada | Comportamiento |
| --- | --- |
| No llamar a `configureExchange` | Ambas variables de entorno se leen en primer uso. Se aplica gratis cuando no se establece ninguna variable. |
| `configureExchange({ license, licenseKey })` | Sólo se utilizan las credenciales explícitas. El ambiente es ignorado. |
| `configureExchange({})` | Libre es seleccionado explícitamente. El ambiente es ignorado. |
| Sólo una credencial en la fuente seleccionada | La llamada devuelve `INVALID_ARGUMENT`. El otro campo nunca se llena de una fuente diferente. |

Una vez que se ha leído una configuración completa del entorno, se mantiene fijo incluso si una operación posterior falla. Para reemplazar las credenciales predeterminadas en el tiempo de ejecución, llame a `configureExchange` y lo espere. Una llamada fallida deja la configuración anterior en su lugar, así que maneje el error antes de iniciar nuevas exportaciones.

ESM y CommonJS comparten una única configuración dentro del mismo contexto JavaScript. Cada trabajador `worker_threads` debe configurarse o inicializar desde su propio entorno. Una exportación utiliza la configuración que estaba en marcha cuando se llamó el método de exportación pública; cambiar las credenciales más tarde no afecta a las exportaciones que ya han comenzado.

### Autorizar una sola operación

Para autorizar una sola llamada sin cambiar la configuración predeterminada, pasar un par `license` completo y `licenseKey` en las opciones de una API de exportación o de `getExportQuota`. El siguiente ejemplo consulta la cuota y las exportaciones con las mismas credenciales:

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeFormat, exportToBuffer, getExportQuota } from '@univerjs-pro/exchange-node'

const credentials = { license: '<license content>', licenseKey: '<licenseKey content>' }
const quota = await getExportQuota(credentials)
const output = await exportToBuffer(workbook, {
  type: UniverInstanceType.UNIVER_SHEET,
  format: ExchangeFormat.XLSX,
  ...credentials,
})
```

Las exportaciones de archivos, las exportaciones de Snapshot y las exportaciones de PDF opcionales aceptan el mismo par. Cuando ambos campos se omiten, se aplica la configuración predeterminada; cuando sólo se suministra un campo, la llamada regresa `INVALID_ARGUMENT`. Un par explícito nunca se completa desde la configuración predeterminada o desde el entorno, y una cadena vacía no cuenta como un campo omitido. `LICENSE_INVALID`, y el SDK no cae de nuevo a la licencia comercial predeterminada.

### Compatibilidad opcional con PDF

Instala el paquete de extensión PDF e importa su punto de entrada antes de configurar la autorización:

```sh
pnpm add @univerjs-pro/exchange-node @univerjs-pro/exchange-pdf-node-binding
```

```ts
import '@univerjs-pro/exchange-node/pdf'
import { configureExchange, getExportQuota } from '@univerjs-pro/exchange-node'

await configureExchange({
  license: '<license content>',
  licenseKey: '<licenseKey content>',
})

const quota = await getExportQuota()
```

La importación registra soporte PDF y los componentes nativos se cargan cuando se utilizan por primera vez. PDF utiliza el mismo `importBuffer`, `importFile`, `exportToBuffer`, `exportToFile`, y APIs de instantáneas correspondientes, con `UniverInstanceType.UNIVER_PDF` y `ExchangeFormat.PDF`. Una aplicación que maneja sólo PDF no necesita el componente nativo de Office.

## Consultar la cuota restante [#quota]

`getExportQuota({ license, licenseKey })` devuelve `Promise<ExportQuota>` para la Oficina y cuota PDF que la autorización comparte. Cuando se omiten las credenciales, la llamada consulta la configuración predeterminada. La llamada acepta ningún tipo de unidad y no verifica si se permite un tipo de exportación particular; ese cheque ocurre durante la exportación.

Una consulta no consume ni cuota de reservas, y no comprueba la versión SDK, el tiempo de activación o el derecho de tipo de exportación. Un saldo cero todavía devuelve una instantánea exitosa. Otras solicitudes pueden consumir cuota inmediatamente después, así que maneje los errores devueltos por la exportación real también.

Antes de que la autorización surta efecto, una consulta contra una cuota limitada devuelve la instantánea para el primer mes de autorización, cuyo `periodStart` se encuentra en el futuro. Una consulta exitosa, o un estado `valid`, no significa que se permita la exportación. La versión de cheques SDK, activación, tipo de derecho, cuota disponible y concurrencia durante la exportación.

| Campo | Tipo | Significado |
| --- | --- | --- |
| `licenseStatus` | `'not_configured' \| 'expired' \| 'valid'` | La suscripción a la exportación no está configurada, caducada o aún no caducada. `valid` no significa que las comprobaciones de admisión a la exportación hayan pasado. |
| `expiresAt` | `string \| null` | Expiración de la suscripción a la exportación como un UTC ISO timestamp. `null` cuando no se configura nada o no se aplica caducidad. |
| `observedAt` | `string` | Marca de tiempo ISO en UTC de esta instantánea. |
| `limit` | `number \| null` | Límite de exportación mensual actual. `null` cuando la cuota es ilimitada. |
| `used` | `number \| null` | Exportaciones exitosas en el mes actual. `null` cuando la cuota es ilimitada. |
| `reserved` | `number \| null` | Exportaciones en vuelo que tienen cuota en el mes actual. `null` cuando la cuota es ilimitada. |
| `remaining` | `number \| null` | Exportaciones todavía disponibles, calculadas como `max(0, limit - used - reserved)`. `null` cuando la cuota es ilimitada. |
| `periodStart` | `string \| null` | Inclusive UTC ISO start of the queried monthly quota window. El primer período comienza en el futuro, antes de la activación. `null` cuando la cuota es ilimitada. |
| `periodEnd` | `string \| null` | Exclusiva UTC ISO final de la ventana de cuota mensual queried. `null` cuando la cuota es ilimitada. |

En Free (Freemium), la cuota corresponde a las exportaciones mensuales sin marca de agua, no al total de exportaciones. Un saldo `remaining` de cero permite seguir exportando archivos completos con marca de agua; no rechace una exportación Free solo por ese saldo. Al caducar una suscripción comercial se aplican las reglas Free, sin reinicio adicional de su cuota mensual ni renovación de la autorización comercial en producción.

`periodEnd` es el comienzo de la siguiente ventana de cuota mensual, y `expiresAt` está al final de la suscripción a la exportación. Mientras que la suscripción es válida, las exportaciones siempre utilizan cuota comercial. El agotamiento nunca selecciona Libre, y la siguiente ventana comercial comienza en el mes siguiente. Sólo la expiración de la suscripción cambia a la cuota libre restante, que no es reajuste ni concedido de nuevo.

Ejemplo de instantánea con cuota limitada:

```json
{
  "licenseStatus": "valid",
  "expiresAt": "2027-10-19T23:59:59Z",
  "observedAt": "2026-10-21T09:00:00Z",
  "limit": 500,
  "used": 20,
  "reserved": 1,
  "remaining": 479,
  "periodStart": "2026-10-19T00:00:00Z",
  "periodEnd": "2026-11-19T00:00:00Z"
}
```

## Uso de la cuota de exportación [#accounting]

Free (Freemium) incluye 10 exportaciones sin marca de agua por mes de licencia. Desde la 11.ª exportación correcta del mes se pueden seguir exportando archivos completos con marca de agua. La cuota sin marca de agua se reinicia cada mes y no se acumula. La cuota comercial, la concurrencia y los derechos de versión siguen dependiendo de la licencia adquirida. Ni Free ni una licencia comercial limita el tamaño de archivo o el número de celdas. Consulte la respuesta de la consulta para conocer el período y el saldo actuales.

Las importaciones no requieren autorización de exportación y no consumen cuota de exportación. Dentro de un despliegue, las exportaciones de Office y PDF que utilizan la misma cuota de cuota de licencia comercial. Los formatos de conversión de Exchange se enumeran en [Importación y exportación de archivos de oficinas](/server/import-export/node).

Cada conversión correcta cuenta una vez; devolver un Buffer se considera un éxito. Un fallo posterior al escribir, subir o descargar el archivo no devuelve ese uso. Otra conversión correcta vuelve a contar. Agotar la cuota Free sin marca de agua permite seguir exportando archivos completos con marca de agua. Si una licencia comercial válida agota su cuota, se rechazan nuevas exportaciones hasta el siguiente período o hasta actualizar a una licencia válida con una cuota mayor. No se recurre a la cuota Free.

## Gestionar errores [#errors]

Identificar errores por el `code` estructurado en lugar de analizar el texto `message`. La UI puede mapear códigos de error a los mensajes localizados. Retener los detalles de diagnóstico para el soporte técnico.

```ts
import { UniverInstanceType } from '@univerjs/core'
import { ExchangeError, ExchangeFormat, exportToBuffer } from '@univerjs-pro/exchange-node'

try {
  const output = await exportToBuffer(workbook, {
    type: UniverInstanceType.UNIVER_SHEET,
    format: ExchangeFormat.XLSX,
  })
} catch (error) {
  if (error instanceof ExchangeError) {
    // Muestra el mensaje de error.code, p. ej. LICENSE_EXPORT_QUOTA_EXCEEDED cuando se agota la cuota
    console.error(error.code)
  } else {
    throw error
  }
}
```

En la tabla siguiente se indica si un error se origina de una consulta de cuota (`getExportQuota`) o de una exportación real. Ambas APIs devuelven Promesas, por lo que los fallos requieren `await` y `try/catch`.

| Código | Operación | Significado y respuesta |
| --- | --- | --- |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | Solo exportación | La cuota comercial de exportación del período es insuficiente. Consulte la cuota o contacte con ventas para ajustar la licencia. Agotar únicamente la cuota Free sin marca de agua no provoca este error. |
| `LICENSE_CONCURRENCY_TIMEOUT` | Solo exportación | Esperando un cronograma de concurrencia de exportación. Reducir las exportaciones concurrentes antes de presentar nuevamente. |
| `LICENSE_UNIT_TYPE_REJECTED` | Solo exportación | El tipo de exportación no está cubierto por la licencia, o su derecho de tipo ha caducado. Proporciona una licencia válida que cubre el tipo. |
| `LICENSE_INVALID` | Consulta, exportación | La licencia es inválida. Revise las credenciales completas, o solicite una actualización del proveedor de licencias. |
| `LICENSE_POLICY_INVALID` | Consulta, exportación | La configuración de autorización no cumple con los requisitos de SDK. Solicite una actualización del proveedor de licencias. |
| `LICENSE_NOT_YET_EFFECTIVE` | Solo exportación | La autorización aún no ha tenido efecto. Úsalo después de su fecha efectiva. |
| `LICENSE_VERSION_NOT_ALLOWED` | Solo exportación | La versión actual del SDK está fuera del rango licenciado. Usa una versión compatible o actualiza la licencia. |
| `UNSUPPORTED_FORMAT` | Solo exportación | El formato no está soportado o no coincide con el tipo de Unidad. Compruebe las opciones de exportación. |
| `INVALID_FILE` | Solo exportación | La entrada de conversión es inválida. Compruebe el contenido de la entrada. |
| `INCOMPLETE_SNAPSHOT` | Solo exportación | Los datos de exportación son incompletos. Proporcionar datos completos o una instantánea completa. |
| `CONVERSION_FAILED` | Solo exportación | La conversión falló. Retenga el error y compruebe el contenido de entrada. |
| `IO_ERROR` | Solo exportación | La entrada o salida del archivo falló. Si la conversión tuvo éxito y la escritura de la salida falló, esa exportación ya se ha consumido. |
| `INVALID_ARGUMENT` | Consulta, exportación | Los argumentos o credenciales son incompletos. Compruebe la configuración. |
| `NATIVE_LOAD_FAILED` | Consulta, exportación | Un componente SDK nativo no se pudo cargar. Compruebe que los paquetes instalados coinciden con el entorno de tiempo de ejecución. |
| `LICENSE_USAGE_STATE_INVALID` | Consulta, exportación | El estado de uso de la licencia no puede ser verificado. Retenga el error y el soporte técnico de contacto. |
| `LICENSE_USAGE_STORAGE_ERROR` | Consulta, exportación | El procesamiento del uso de la licencia falló. Retenga el error, contacte soporte técnico, y no vuelva a presentar automáticamente. |

La aplicación puede construir recordatorios de expiración de `licenseStatus` y `expiresAt`. El SDK no devuelve una lista separada de avisos.

Después de un error de procesamiento del uso de licencias, no se infiere del error solo si se contó la exportación. Retenga el error completo y el soporte técnico de contacto.
