사무실 파일 변환은 AI SDK에 의해 `@univerjs-pro/exchange-node`로 처리됩니다. 파일 경계에서 CLI 응용 프로그램은 `importFile()`와 `exportToFile()`를 호출하고 AI SDK 및 Collaboration SDK을 사용하여 단위로 작동합니다.

## SDK 역할 경계 유지

```ts
import { exportToFile, importFile } from "@univerjs-pro/exchange-node";
```

| 기능 | 담당 |
| --- | --- |
| 사무실 파일을 UnitData로 변환 | Exchange |
| 헤드리스 런타임, 콘텐츠 검사, Facade 실행 | AI SDK |
| 스냅샷, 변경 집합, 리비전, 영구 저장 | Collaboration SDK |
| 경로, 형식 정책, 업무 API, 오류 매핑 | 업무 애플리케이션 |

## 공동 편집 Unit 가져오기

비즈니스 응용 프로그램은 Exchange를 통해 Office 파일을 읽고 UnitData를 협업 서버로 전달합니다. 이는 Unit을 만듭니다.

```text
Office 파일
→ importFile()
→ UnitData
→ 업무 Server API
→ 공동 편집 Unit
```

이 응용 프로그램은 초기 개정, 비즈니스 메타 데이터 및 반환 된 결과 결정합니다. 단위가 존재하면 CLI와 웹이 서버를 통해 작동됩니다.

## 최신 리비전 내보내기

수출을 위해, CLI는 Collaboration Runtime를 통해 최신 확인된 개정을 적재하고, 그 후에 완전한 UnitData에 교환합니다:

```text
공동 편집 Unit
→ 최신 UnitData
→ exportToFile()
→ Office 파일
```

출력 파일의 확장은 형식을 결정합니다.

## Commander로 파일 작업 노출

AI SDK는 사무실 파일 수입품과 수출을 위한 미리 설치 명령 포장을 제공하지 않습니다. 사업 신청은 교환, Collaboration Runtime 및 그것의 자신의 서버 API를 결합하는 Commander를 이용합니다:

```ts
import { Command } from "commander";

interface IFileExchangeDependencies {
  importFile(path: string): Promise<unknown>;
  createUnit(unitData: unknown): Promise<unknown>;
  loadLatestUnitData(unitId: string): Promise<unknown>;
  exportFile(unitData: unknown, path: string): Promise<void>;
  writeResult(result: unknown): void;
}

function addFileExchangeCommands(program: Command, dependencies: IFileExchangeDependencies): void {
  program.addCommand(
    new Command("import").argument("<office-file>").action(async (sourcePath) => {
      const unitData = await dependencies.importFile(sourcePath);
      const created = await dependencies.createUnit(unitData);
      dependencies.writeResult(created);
    }),
  );

  program.addCommand(
    new Command("export")
      .argument("<office-file>")
      .requiredOption("--unit <id>")
      .action(async (outputPath, { unit }) => {
        const unitData = await dependencies.loadLatestUnitData(unit);
        await dependencies.exportFile(unitData, outputPath);
      }),
  );
}
```

Commander 이외의 모든 기능은 `IFileExchangeDependencies`에서 명시적으로 선언되어 있으므로, 숨겨지은 헬퍼에 의존합니다. 이 응용 프로그램은 Exchange의 `importFile()` 및 `exportToFile()`를 호출하여 파일 변환을 수행하며 Collaboration Runtime에 `loadLatestUnitData()`을 구현하고 자체 서버 API 및 결과 출력을 주입합니다.

## 지원 형식

| Unit | 가져오기 | 내보내기 |
| --- | --- | --- |
| Sheet | `.xls`, `.xlsx`, `.xlsm`, `.csv`, `.tsv` | `.xlsx`, `.csv`, `.tsv` |
| Doc | `.doc`, `.docx` | `.docx` |
| Slide | `.ppt`, `.pptx`, `.pptm`, `.ppsx`, `.ppsm`, `.potx` | `.pptx` |

이 응용 프로그램은 파일을 생성하기 전에 단위 유형과 일치하지 않는 확장을 거부해야합니다.

## 로컬 CLI만 사용

애플리케이션은 로컬 헤드리스 런타임에 직접 수입된 콘텐츠를 전달하여 협업 서버를 우회할 수 있으며, Office 파일을 내보내기 할 수 있습니다. 이 접근법은 하나의 오프 처리에 적합하지만, 공유된 개정, 라이브 웹 미리보기, 역사 또는 Worktree를 제공하지 않습니다.

명령 이름, 경로 인수 및 결과 발표는 비즈니스 응용 프로그램의 책임에 남아. 협업 단위 경로에 대 한, [문서 로딩 및 콘텐츠 작업](/ai/content-operations)를 참조하십시오. 일단 파일 경계가 장소에 있을 때, [비주얼 검사](/ai/visual-inspection)와 함께 계속, 에이전트가 렌더링 된 UnitData을 확인할 수 있습니다.
