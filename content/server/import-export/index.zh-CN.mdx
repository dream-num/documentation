编辑器不能直接打开 Excel 文件。文件先由服务端转换为 Univer 文档数据，导出时再把编辑后的数据转换回 Excel 文件。两个方向都由服务端的 `@univerjs-pro/exchange-node` 模块完成。浏览器负责上传文件、打开文档和下载结果。

<Mermaid chart={'flowchart LR; A["Excel 文件"] -->|服务端导入| B["Univer 文档<br/>在浏览器中编辑"]; B -->|服务端导出| C["Excel 文件"];'} />

## 不需要多人编辑

最常见的场景是用户上传一份 Excel 文件，在页面上完成编辑，再下载为 Excel 文件。

1. 浏览器上传文件，服务端将文件转换为 Univer 文档数据并返回。
2. 浏览器用这份数据打开表格，即可开始编辑。
3. 导出时，浏览器把编辑后的数据发送给服务端，由服务端生成 Excel 文件供下载。

这个过程不需要协同服务。浏览器 API 中的快照就是此处使用的文档数据。导入和导出快照同样需要经过服务端转换；如果用户需要保存数据并在之后继续编辑，应用必须自行存储这份数据。

转换模块的安装和使用方法见 [Office 文件导入导出](/server/import-export/node)。如果只需要在 Node.js 中处理文件，也可以从该页开始阅读。

## 需要多人编辑同一份文档

在这种场景下，用户导入一份 Excel 文件，把文档分享给同事，与同事共同编辑，之后再导出。

1. 服务端转换上传的文件，并把结果保存为一份协同文档。
2. 服务端返回文档 ID。浏览器用这个 ID 打开文档，其他用户也通过同一个 ID 加入该文档。
3. 导出时，服务端读取文档的最新内容，生成 Excel 文件供下载。

这个文档 ID 就是浏览器 API 中的 `unitId`。请先完成[协同集成](/server/collaboration/browser-integration)，再运行 [Exchange 示例](/server/collaboration/examples#exchange)。示例包含浏览器、服务端和转换代码，可以对照阅读。

导出前必须等待当前编辑完成同步，否则导出的文件可能缺少刚修改的内容。协同文档的读取和转换方式见[扩展模块](/server/collaboration/extensions)中服务端 Office Exchange 一节。

## 接入页面上的导入、导出按钮

服务端转换正常工作后，下一步是把页面接入。

- 使用 Univer 自带菜单或 Facade API 时，按 [Exchange 示例](/server/collaboration/examples#exchange)的方式注册 File Endpoint 和 Exchange Endpoint，再配置浏览器插件。
- 自行实现按钮时，调用业务接口：导入完成后打开接口返回的文档数据或文档 ID，导出完成后下载生成的文件。

各产品的浏览器配置分别见 [Sheets](/guides/sheets/features/import-export)、[Docs](/guides/docs/features/import-export)、[Slides](/guides/slides/features/import-export)、[Boards](/guides/boards/features/import-export)、[Bases](/guides/bases/features/import-export)、[PDFs](/guides/pdfs/features/import-export)。协同示例演示的是 Sheets。其他产品请先参阅 [Office 文件导入导出](/server/import-export/node)，再核对所用版本支持的格式。

## 接入后检查

用一份真实的业务文件完整执行导入、修改和导出流程，再用 Office 软件打开结果，检查修改、公式、图片和布局。涉及协同的场景还需确认其他用户能打开同一份文档，以及服务重启后内容仍然存在。

上线前应限制上传大小，并处理转换失败和超时。上传、任务查询和下载都需要权限检查，具体见[身份与权限](/server/collaboration/identity-and-authorization)。

## 插件配置 [#exchange-client-configuration]

`UniverExchangeClientPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | 下载文件的基础地址。 |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | 接收上传文件的接口。 |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | 启动导入任务的接口。保留 `{type}` 占位符。 |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | 启动导出任务的接口。保留 `{type}` 占位符。 |
| `getTaskServerUrl` | `string` | `'/universer-api/exchange/task/{taskID}'` | 查询任务状态的接口。保留 `{taskID}` 占位符。 |
| `signUrlServerUrl` | `string` | `'/universer-api/file/{fileID}/sign-url'` | 为文件 URL 签名的接口。保留 `{fileID}` 占位符。 |
| `maxTimeoutTime` | `number` | `120000` | 轮询转换任务的最长时间，单位为毫秒。 |

## 配置 OLE 附件 [#ole-configuration]

`UniverDrawingPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | OLE 附件的配置项。 |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | 生成打开在线附件的应用链接。 |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | 在应用自己的存储里读写附件原文件。 |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | 把附件写入应用存储，并关联到当前单元。 |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | 从应用存储读取附件字节。 |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | 接管 Office 附件的预览流程。 |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | 用应用提供的回调创建 Office 预览。 |

注册 Exchange 之前，先将 `ole` 加入已有的 `UniverDrawingPlugin` 注册项。下面的路由由应用提供，需要指向应用自己的文档界面；需要文档类型时，通过 `getLink` 的第二个参数传入。Exchange 负责 Office 转换，也会检测协同状态。以 UUID 引用的附件还需要配置 `ole.attachmentIo`，提供带鉴权的 `upload(file, targetUnitId)` 和 `read(attachment, signal)` 回调。Office 预览需要对应的渲染器，或由应用实现 `previewOffice` / `createOfficePreview` 回调。

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## 导出失败与许可证限制 [#export-errors]

导出可能在提交时失败，也可能在轮询任务时失败。HTTP 请求成功并不表示文件已经生成，还需要检查协议中的 `error.code` 和任务状态。Exchange 客户端会把服务端的导出错误保存在 `IExchangeService.requestState$` 中，自定义导出界面可以在发起操作前订阅。

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | 处理方式 |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | 缩小文档，或换用导出上限更大的许可证。 |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | 检查剩余导出额度及重置规则。 |
| `LICENSE_CONCURRENCY_TIMEOUT` | 待转换容量可用后重试。 |
| `LICENSE_VERSION_NOT_ALLOWED` | 改用服务端许可证覆盖的版本。 |
| `LICENSE_UNIT_TYPE_REJECTED` | 检查服务端许可证是否覆盖该文档类型。 |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | 检查服务端许可证配置、用量状态和存储。 |

判断错误时应依据 `@univerjs/protocol` 中具名的 `ErrorCode`，不要解析翻译后的提示文字。服务端返回的消息应保留，以便排查问题。网络故障、格式错误的任务响应和轮询超时可能只返回一个通用错误，这些情况都不能证明是许可证拒绝了本次导出。移除编辑器时调用 `subscription.unsubscribe()` 释放订阅。

如果应用在中间部署了自己的后端或代理，该后端或代理应将结构化错误响应原样透传，并将任务标记为失败，而不是让它一直停留在 pending 状态。调大 `maxTimeoutTime` 只会为轮询提供更多时间，不会增加导出额度，也不会改变许可证覆盖的范围。

## OLE 附件 [#ole-attachments]

Sheets、Docs 和 Slides 会将导入的 OLE 原文件与预览图分开保存。原文件可用时，用户可以下载，也可以重命名某个附件实例；拥有权限时还可以删除附件。图片和 PDF 附件可以预览。Office 预览通过 Exchange 的 JSON 转换，在临时的只读编辑器中打开，不会生成持久化的子文档。原生 Office 应用和宏不会被执行。

将 Office 附件转换为在线文档，需要宿主支持协同、具备编辑权限、支持转换，并且已配置 `getLink`。转换会新建一份独立文档，将其标识记录在附件上，之后打开时复用这份文档。编辑该在线文档不会覆盖附件的原始字节。缺失、外部引用或不支持的附件会保留原状态，不会变成可编辑的 Office 对象。

导出默认使用 `oleAttachmentSource: 'original'`。设为 `'online'` 时，只在这一个导出文件中嵌入各在线文档当前已确认的版本，存储的原件不会被改写。导出前必须等待同步完成，后端应校验被引用文档的访问权限。Docs 和 Slides 的导出 API 将该选项作为第二个参数，Sheets 作为第四个参数；snapshot 变体的参数位置相同。参见[导出 API](/reference/facade/univer#exportsheetbyunitidasync)。

对于已持久化的附件，Exchange 会提交 `fileID` 和拥有该附件的 `sourceUnitID`。导入后端在按引用转换之前，必须先校验两者的归属关系以及调用者的权限。轮询任务时可能返回 `progress.stage`，其值为 `reading`、`converting`、`creating` 或 `done`。自定义转换界面见[附件导入与进度 API](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress)。
