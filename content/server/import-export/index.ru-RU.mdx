Чтобы открыть Excel в Univer, сначала преобразуйте файл в данные редактора. При экспорте преобразуйте изменённые данные обратно в Excel. Серверный `@univerjs-pro/exchange-node` выполняет преобразование, а браузер загружает файлы, открывает документы и скачивает результаты.

## Без совместного редактирования

Например, пользователь загружает Excel, редактирует его на странице и скачивает результат в Excel.

1. Браузер загружает файл, сервер преобразует его в данные Univer и возвращает их.
2. Браузер открывает таблицу с этими данными для редактирования.
3. При экспорте браузер отправляет изменённые данные серверу, который создаёт файл Excel.

Сервис совместного редактирования здесь не нужен. «Снимок» в браузерных API — это используемые здесь данные документа. Импорт и экспорт снимков всё равно требуют серверного преобразования. Для сохранения и дальнейшего продолжения работы приложение должно хранить эти данные.

Установка и применение модуля описаны в [Импорте и экспорте Office](/server/import-export/node). Оттуда же начните, если нужна только обработка файлов в Node.js.

## С совместным редактированием

Например, пользователь импортирует Excel, делится документом с коллегами, редактирует его вместе с ними и затем экспортирует.

1. Сервер преобразует загруженный файл и сохраняет совместный документ.
2. Возвращает ID, который открывает браузер; другие пользователи входят по тому же ID.
3. При экспорте сервер читает актуальное содержимое и создаёт Excel для скачивания.

`unitId` браузерных API — этот ID. Сначала завершите [интеграцию совместного редактирования](/server/collaboration/browser-integration), затем запустите [пример Exchange](/server/collaboration/examples#exchange). Изучайте его браузерный, серверный и преобразующий код вместе.

Перед экспортом дождитесь синхронизации, иначе файл может не содержать последних изменений. Чтение и преобразование совместных документов описано в серверном Office Exchange раздела [Модули расширений](/server/collaboration/extensions).

## Подключение кнопок импорта и экспорта

Когда преобразование на сервере работает, подключите его к странице:

- **Меню Univer или API Facade:** зарегистрируйте File Endpoint и Exchange Endpoint по [примеру Exchange](/server/collaboration/examples#exchange), затем настройте браузерные плагины.
- **Собственные кнопки:** вызывайте API приложения. После импорта откройте полученные данные или ID, после экспорта скачайте результат.

Настройки браузера см. в [Sheets](/guides/sheets/features/import-export), [Docs](/guides/docs/features/import-export), [Slides](/guides/slides/features/import-export), [Boards](/guides/boards/features/import-export), [Bases](/guides/bases/features/import-export) и [PDFs](/guides/pdfs/features/import-export). Совместный пример использует Sheets. Для остальных проверьте [Импорт и экспорт Office](/server/import-export/node) и форматы своего выпуска.

## Проверка интеграции

Импортируйте реальный файл, отредактируйте и экспортируйте. Откройте его в Office и проверьте изменения, формулы, изображения и макет. Для совместной работы также проверьте доступ других пользователей и сохранность после перезапуска сервера.

До развёртывания ограничьте размеры загрузок и обработайте ошибки и тайм-ауты. Загрузка, опрос задач и скачивание требуют проверки доступа; см. [Идентификация и авторизация](/server/collaboration/identity-and-authorization).

## Настройка плагинов [#exchange-client-configuration]

`UniverExchangeClientPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | Базовый URL скачивания файлов. |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | Конечная точка загрузки файлов на сервер. |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | Конечная точка запуска импорта. Сохраните подстановку `{type}`. |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | Конечная точка запуска экспорта. Сохраните подстановку `{type}`. |
| `getTaskServerUrl` | `string` | `'/universer-api/exchange/task/{taskID}'` | Конечная точка проверки статуса задачи. Сохраните подстановку `{taskID}`. |
| `signUrlServerUrl` | `string` | `'/universer-api/file/{fileID}/sign-url'` | Конечная точка подписи файловых URL. Сохраните подстановку `{fileID}`. |
| `maxTimeoutTime` | `number` | `120000` | Максимальное время опроса задачи конвертации в миллисекундах. |

## Настройка вложений OLE [#ole-configuration]

`UniverDrawingPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | Параметры этой функции. |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | Создаёт ссылку для открытия онлайн-вложения. |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | Читает и записывает исходное вложение в хранилище приложения. |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | Сохраняет вложение в хранилище приложения и связывает с текущей единицей. |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | Читает байты вложения из хранилища приложения. |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | Заменяет обработку предпросмотра Office. |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | Создаёт предпросмотр Office через функцию приложения. |

Добавьте `ole` в существующую регистрацию `UniverDrawingPlugin` перед Exchange. Маршрут ниже должен открывать интерфейс документов вашего приложения; при необходимости учитывайте второй аргумент `getLink` — тип документа. Exchange предоставляет конвертацию Office и определение совместного режима. Вложения по UUID также требуют `ole.attachmentIo` с авторизованными callbacks `upload(file, targetUnitId)` и `read(attachment, signal)`. Для Office-просмотра нужен соответствующий рендерер либо собственный `previewOffice` / `createOfficePreview`.

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## Ошибки экспорта и ограничения лицензии [#export-errors]

Экспорт может завершиться ошибкой при отправке запроса или опросе задачи. Успешный HTTP-ответ ещё не означает готовность файла: проверяйте `error.code` и состояние задачи. Клиент Exchange передаёт серверные ошибки экспорта через `IExchangeService.requestState$`; собственный интерфейс может подписаться до начала операции.

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | Действие |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | Уменьшите документ или используйте лицензию с большим лимитом экспорта. |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | Проверьте остаток квоты экспорта и правила её сброса. |
| `LICENSE_CONCURRENCY_TIMEOUT` | Повторите попытку, когда освободится мощность конвертации. |
| `LICENSE_VERSION_NOT_ALLOWED` | Используйте версию, разрешённую серверной лицензией. |
| `LICENSE_UNIT_TYPE_REJECTED` | Проверьте, разрешает ли серверная лицензия тип документа. |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | Проверьте настройки лицензии, состояние использования и серверное хранилище. |

Сравнивайте именованные значения `ErrorCode` из `@univerjs/protocol`, а не переведённые сообщения. Сохраняйте сообщение сервера для диагностики. Сетевые сбои, неверные ответы и тайм-ауты могут дать общую ошибку и не доказывают отказ лицензии. При удалении редактора вызовите `subscription.unsubscribe()`.

Собственный сервер или прокси должен сохранять структурированный ответ об ошибке и отмечать задачу как неудачную, а не оставлять pending. Увеличение `maxTimeoutTime` только продлевает опрос и не меняет квоту или разрешения лицензии.

## Вложения OLE [#ole-attachments]

Sheets, Docs и Slides хранят импортированные файлы OLE отдельно от изображений предпросмотра. Доступные оригиналы можно скачать, а при наличии прав — переименовать отдельное вхождение или удалить вложение. Для изображений и PDF есть предпросмотр. Office-просмотр использует JSON-конвертацию Exchange и временный редактор только для чтения, не создавая постоянный дочерний документ. Нативные приложения Office и макросы не выполняются.

Преобразование вложения Office в онлайн-документ требует совместного хоста, права редактирования, конвертации и `getLink`. Создаётся независимый документ, его идентификатор сохраняется во вложении для повторного открытия. Правки онлайн-документа не перезаписывают исходные байты. Отсутствующие, внешние и неподдерживаемые вложения сохраняют свой статус.

Экспорт по умолчанию использует `oleAttachmentSource: 'original'`. Значение `'online'` включает текущие подтверждённые версии преобразованных документов только в этот экспорт, не меняя сохранённые оригиналы. Дождитесь синхронизации и проверяйте доступ к связанным документам на сервере. Передавайте опцию вторым аргументом API Docs/Slides или четвёртым аргументом Sheets; варианты snapshot используют ту же позицию. См. [API экспорта](/reference/facade/univer#exportsheetbyunitidasync).

Для сохранённых вложений Exchange передаёт `fileID` и содержащую их Unit — `sourceUnitID`. До преобразования по ссылке сервер должен проверить эту связь и права пользователя. Опрос задачи может возвращать `progress.stage`: `reading`, `converting`, `creating` или `done`. Для собственного интерфейса см. [API импорта и хода выполнения](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress).
