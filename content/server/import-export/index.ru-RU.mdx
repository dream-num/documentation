Редактор не может открыть файл Excel напрямую. Сервер сначала преобразует файл в данные документа Univer, а на экспорте преобразует отредактированные данные обратно в файл Excel. В обоих направлениях используется серверный модуль `@univerjs-pro/exchange-node` . Браузер загружает файл, открывает документ и загружает результат.

## Без совместного редактирования

В типичном сценарии пользователь загружает файл Excel, редактирует его на странице и загружает результат в виде файла Excel.

1. Браузер загружает файл. Сервер преобразует файл в данные документа Univer и возвращает данные.
2. Браузер открывает электронную таблицу из этих данных, готовую к редактированию.
3. При экспорте браузер отправляет отредактированные данные на сервер, а сервер генерирует файл Excel для загрузки.

Этот путь не включает в себя службу совместной работы. *snapshot* в API-интерфейсах браузера - это данные документа, используемые здесь. Импорт или экспорт снимка по-прежнему требует преобразования на стороне сервера; чтобы позволить пользователям сохранить свою работу и вернуться к ней позже, приложение должно хранить сами эти данные.

Установка и использование модуля конверсии описаны в [Офисные файлы импорт и экспорт](/server/import-export/node). Эта страница также является отправной точкой, если приложение нуждается только в обработке файлов в Node.js.

## С совместным редактированием

В этом сценарии пользователь импортирует файл Excel, делится документом с коллегами, редактирует его с ними и экспортирует позже.

1. Сервер преобразует загруженный файл и сохраняет совместный документ.
2. Сервер возвращает идентификатор документа. Браузер открывает документ этим идентификатором, и другие пользователи присоединяются к документу с тем же идентификатором.
3. При экспорте сервер считывает последнее содержимое документа и генерирует файл Excel для загрузки.

Этот идентификатор документа - `unitId` в API браузера. Сначала настройте [Интеграция сотрудничества](/server/collaboration/browser-integration), затем запустите [Пример обмена](/server/collaboration/examples#exchange). В примере показаны браузер, сервер и код конверсии бок о бок.

В ожидании правок необходимо синхронизироваться перед экспортом; в противном случае экспортируемый файл может пропустить последние изменения. Для чтения и преобразования совместных документов см. раздел Office Exchange на стороне сервера в [Модули расширения](/server/collaboration/extensions).

## Подключение кнопок импорта и экспорта

Как только конверсия на стороне сервера работает, следующим шагом является подключение к странице.

- Приложения, использующие меню Univer или API-интерфейсы Facade, регистрируют конечную точку файла и конечную точку обмена таким же образом, как и [Пример обмена](/server/collaboration/examples#exchange), а затем настраивают плагины браузера.
- Приложения, которые предоставляют свои собственные кнопки, называют API приложения: они открывают данные документа или идентификатор документа, возвращенный импортом, и загружают сгенерированный файл после экспорта.

Конфигурация браузера для каждого продукта находится в [Листовки](/guides/sheets/features/import-export), [Док](/guides/docs/features/import-export), [Скольжения](/guides/slides/features/import-export), [Советы](/guides/boards/features/import-export), [Основания](/guides/bases/features/import-export) и [PDF](/guides/pdfs/features/import-export). Пример совместной работы демонстрирует листы. Для других продуктов см. [Офисные файлы импорт и экспорт](/server/import-export/node) и проверьте, какой формат поддерживает установленный выпуск.

## Проверка интеграции

Возьмите реальный файл из приложения через импорт, редактирование и экспорт. Откройте результат в приложении Office и проверьте правки, формулы, изображения и макет. С помощью совместной работы также подтвердите, что другие пользователи могут открыть тот же документ и что контент выживает при перезагрузке сервера.

Перед развертыванием ограничьте размеры загрузки и обработайте сбои конверсии и тайм-ауты. Загрузки, запросы задач и загрузки требуют проверки доступа. См. [удостоверение личности и разрешение](/server/collaboration/identity-and-authorization).

## Настройка плагинов [#exchange-client-configuration]

`UniverExchangeClientPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `downloadEndpointUrl` | `string` | `location.origin` | Базовый URL для загрузки файлов. |
| `uploadFileServerUrl` | `string` | `'/universer-api/stream/file/upload'` | Конечная точка, которая получает загруженные файлы. |
| `importServerUrl` | `string` | `'/universer-api/exchange/{type}/import'` | Конечная точка, с которой начинается импорт. Держите заполнитель `{type}`. |
| `exportServerUrl` | `string` | `'/universer-api/exchange/{type}/export'` | Конечная точка, с которой начинается экспорт. Держите заполнитель `{type}`. |
| `getTaskServerUrl` | `string` | `'/universer-api/exchange/task/{taskID}'` | Конечная точка для статуса задачи. Держите заполнитель `{taskID}`. |
| `signUrlServerUrl` | `string` | `'/universer-api/file/{fileID}/sign-url'` | Конечная точка, которая подписывает URL-адреса файлов. Держите заполнитель `{fileID}`. |
| `maxTimeoutTime` | `number` | `120000` | Максимальное время опроса задачи конвертации в миллисекундах. |

## Настройка вложений OLE [#ole-configuration]

`UniverDrawingPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>ole</ConfigKey> | `object` |  | Настройки для вложений OLE. |
| <ConfigKey depth={1}>getLink</ConfigKey> | `IOleConfig["getLink"]` |  | Создает ссылку приложения для онлайн-вложения. |
| <ConfigKey depth={1}>attachmentIo</ConfigKey> | `object` |  | Читает и пишет оригинальное вложение в хранилище приложений. |
| <ConfigKey depth={2}>upload</ConfigKey> | `(file: File, targetUnitId: string) => Promise<IBaseAttachment>` |  | Сохраняет вложение в хранилище приложения и связывает с текущей единицей. |
| <ConfigKey depth={2}>read</ConfigKey> | `(attachment: IBaseAttachment, signal?: AbortSignal) => Promise<Uint8Array>` |  | Читает байты вложения из хранилища приложения. |
| <ConfigKey depth={1}>previewOffice</ConfigKey> | `IOleConfig["previewOffice"]` |  | Перекрывает поток предварительного просмотра Office. |
| <ConfigKey depth={1}>createOfficePreview</ConfigKey> | `IOleConfig["createOfficePreview"]` |  | Создает предварительный просмотр Office с помощью обратного вызова приложения. |

Добавьте `ole` к существующей регистрации `UniverDrawingPlugin` до регистрации Exchange. Маршрут ниже относится к приложению и должен указывать на UI документа приложения; необязательный второй аргумент `getLink` несет тип документа при необходимости. Exchange выполняет преобразование Office и обнаруживает состояние совместной работы. Приложения, на которые настроен UUID, также требуют `ole.attachmentIo` с авторизованными обратными вызовами `upload(file, targetUnitId)` и `read(attachment, signal)`. Предварительные просмотры Office требуют соответствующего рендеринга или предоставленного приложением `previewOffice` / `createOfficePreview` обратного вызова.

```ts
import { UniverDrawingPlugin } from '@univerjs/drawing'

univer.registerPlugin(UniverDrawingPlugin, {
  ole: {
    getLink: (unitId) => `/documents/${encodeURIComponent(unitId)}`,
  },
})
```

## Ошибки экспорта и ограничения лицензии [#export-errors]

Экспорт может выйти из строя во время отправки или позже, пока задача опрошена. Успешный ответ HTTP сам по себе не означает, что файл готов. Проверьте `error.code` в протоколе и состоянии задачи. Клиент обмена сохраняет ошибки экспорта сервера в `IExchangeService.requestState$`, поэтому пользовательский пользовательский интерфейс экспорта может подписаться до того, как он начнет операцию.

```ts
import { IExchangeService } from '@univerjs-pro/exchange-client'
import { ErrorCode } from '@univerjs/protocol'

const exchange = univer.__getInjector().get(IExchangeService)
const subscription = exchange.requestState$.subscribe(({ error }) => {
  if (!error || error.code === ErrorCode.OK) return
  console.error(error.code, error.message)
})
```

| ErrorCode | Действие |
| --- | --- |
| `LICENSE_EXPORT_SIZE_EXCEEDED` | Уменьшите документ или используйте лицензию с большим лимитом экспорта. |
| `LICENSE_EXPORT_QUOTA_EXCEEDED` | Проверьте остаток квоты экспорта и правила её сброса. |
| `LICENSE_CONCURRENCY_TIMEOUT` | Повторяйте позже, когда доступна емкость преобразования. |
| `LICENSE_VERSION_NOT_ALLOWED` | Используйте версию, разрешённую серверной лицензией. |
| `LICENSE_UNIT_TYPE_REJECTED` | Проверьте, разрешает ли серверная лицензия тип документа. |
| `LICENSE_POLICY_INVALID`, `LICENSE_USAGE_STATE_INVALID`, `LICENSE_USAGE_STORAGE_ERROR` | Проверьте конфигурацию лицензии сервера, состояние использования и хранилище. |

Сопоставление по названным значениям `ErrorCode` от `@univerjs/protocol`; не анализируйте переведенный текст сообщения. Сохраните сообщение сервера для диагностики. Сбои в сети, неправильные ответы на задачи и тайм-ауты опроса могут всплыть как общий сбой, и ни один из них не доказывает, что лицензия отклонила экспорт. Позвоните `subscription.unsubscribe()`, когда редактор удален.

Если приложение развертывает свой собственный бэкэнд или прокси-сервер впереди, этот бэкенд или прокси должен пройти через структурированный ответ на ошибку и отметить задачу не удалось, а не оставить ее на рассмотрении. Повышение `maxTimeoutTime` только дает опросу больше времени. Он не добавляет экспортную квоту или не изменяет то, что охватывает лицензия.

## Вложения OLE [#ole-attachments]

Листы, документы и слайды хранят импортированные OLE-файлы отдельно от их изображений предварительного просмотра. Пользователи могут загружать оригинальный файл, когда он доступен, переименовывать событие и удалять вложения, если у них есть разрешение. Вложения изображения и PDF могут быть предварительно просмотрены. Office previews проходят через преобразование Exchange JSON во временный редактор только для чтения, а открытие предварительного просмотра не создает постоянный детский документ. Приложения Native Office и макросы никогда не запускаются.

Преобразование вложения Office в онлайн-документ требует совместного хоста, разрешения на редактирование, поддержки конверсии и `getLink`. Конверсия создает независимый документ и сохраняет его личность в вложении, поэтому позже открывает повторное использование этого документа. Редактирование документа не перезаписывает исходные байты вложений. Отсутствующие, внешние или неподдерживаемые вложения сохраняют свой статус вместо того, чтобы превращаться в редактируемые объекты Office.

Экспорт использует `oleAttachmentSource: 'original'` по умолчанию. Установите его на `'online'` для встраивания текущей подтвержденной версии каждого преобразованного онлайн-документа в этот один экспорт; сохраненные оригиналы не переписываются. Редакции должны синхронизироваться перед экспортом, а бэкэнд должен разрешить доступ к указанным документам. Передайте опцию в качестве второго аргумента в Docs and Slides Export APIs или в качестве четвертого аргумента в Sheets Export APIs. Варианты снимков принимают его в той же позиции. См. [Экспортный API](/reference/facade/univer#exportsheetbyunitidasync).

Для постоянных вложений Exchange отправляет `fileID` и `sourceUnitID`, которым он владеет. Перед конвертацией по ссылке, импортный бэкэнд должен проверить, как они связаны, и проверить доступ вызывающего абонента. Опрос задачи может вернуть `progress.stage` как `reading` , `converting` `creating` или `done`. Для пользовательского интерфейса преобразования см. [Импорт вложений и прогресс API](/reference/packages/plugins/univerjs-pro/exchange-client#attachment-imports-and-task-progress)
