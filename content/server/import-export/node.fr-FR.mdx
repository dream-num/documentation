---
title: Importation et exportation de fichiers Office
description: Utiliser Exchange pour transférer le contenu entre fichiers Office et Units collaboratives.
---

La conversion des fichiers de bureau est gérée par `@univerjs-pro/exchange-node`, pas par AI SDK. À la limite du fichier, une application CLI appelle `importFile()` et `exportToFile()`, puis utilise AI SDK et Collaboration SDK d'opérer sur l'unité.

## Respecter les responsabilités des SDK

```ts
import { exportToFile, importFile } from "@univerjs-pro/exchange-node";
```

| Capacité | Responsable |
| --- | --- |
| Conversion des fichiers Office vers et depuis UnitData | Exchange |
| Runtime sans interface, inspection et exécution Facade | AI SDK |
| Instantanés, jeux de modifications, révisions et persistance | Collaboration SDK |
| Chemins, règles de format, API métier et correspondance des erreurs | Application métier |

## Importer une Unit collaborative

L'application d'affaires lit un fichier Office via Exchange et transmet le UnitData résultant au serveur Collaboration, qui crée l'unité:

```text
fichier Office
→ importFile()
→ UnitData
→ API du serveur métier
→ Unit collaborative
```

L'application détermine la révision initiale, les métadonnées d'affaires et le résultat qui est retourné. Une fois l'unité existante, le CLI et le Web l'utilisent par l'intermédiaire du serveur.

## Exporter la dernière révision

Pour l'exportation, le CLI charge la dernière révision confirmée via Collaboration Runtime, puis passe le UnitData complet à Exchange:

```text
Unit collaborative
→ dernières UnitData
→ exportToFile()
→ fichier Office
```

L'extension du fichier de sortie détermine le format.

## Exposer les opérations de fichier avec Commander

AI SDK ne fournit pas de paquet de commande prédéfini pour l'importation et l'exportation de fichiers Office. L'application d'affaires utilise Commander pour combiner Exchange, Collaboration Runtime et sa propre API serveur:

```ts
import { Command } from "commander";

interface IFileExchangeDependencies {
  importFile(path: string): Promise<unknown>;
  createUnit(unitData: unknown): Promise<unknown>;
  loadLatestUnitData(unitId: string): Promise<unknown>;
  exportFile(unitData: unknown, path: string): Promise<void>;
  writeResult(result: unknown): void;
}

function addFileExchangeCommands(program: Command, dependencies: IFileExchangeDependencies): void {
  program.addCommand(
    new Command("import").argument("<office-file>").action(async (sourcePath) => {
      const unitData = await dependencies.importFile(sourcePath);
      const created = await dependencies.createUnit(unitData);
      dependencies.writeResult(created);
    }),
  );

  program.addCommand(
    new Command("export")
      .argument("<office-file>")
      .requiredOption("--unit <id>")
      .action(async (outputPath, { unit }) => {
        const unitData = await dependencies.loadLatestUnitData(unit);
        await dependencies.exportFile(unitData, outputPath);
      }),
  );
}
```

Toutes les capacités extérieures à Commander sont déclarées explicitement dans `IFileExchangeDependencies`, de sorte que les commandes ne comptent sur aucun helper caché. L'application effectue la conversion de fichiers en appelant `importFile()` et `exportToFile()` d'échange, implémente `loadLatestUnitData()` sur Collaboration Runtime.

## Formats pris en charge

| Unit | Import | Export |
| --- | --- | --- |
| Sheet | `.xls`, `.xlsx`, `.xlsm`, `.csv`, `.tsv` | `.xlsx`, `.csv`, `.tsv` |
| Doc | `.doc`, `.docx` | `.docx` |
| Slide | `.ppt`, `.pptx`, `.pptm`, `.ppsx`, `.ppsm`, `.potx` | `.pptx` |

L'application doit rejeter une extension qui ne correspond pas au type Unit avant de générer un fichier.

## Utiliser uniquement une CLI locale

Une application peut contourner le Serveur de Collaboration en passant directement le contenu importé à un runtime local sans tête et en exportant un fichier Office. Cette approche convient à un traitement unique, mais elle ne fournit pas de révisions partagées, aperçu Web en direct, Historique, ou Worktree.

Les noms de commande, les arguments de chemin et la présentation des résultats restent la responsabilité de l'application d'affaires. Pour le chemin de l'unité collaborative, voir [Opérations de chargement et de contenu des documents](/ai/content-operations). Une fois la limite de fichier en place, continuer avec [Contrôle visuel](/ai/visual-inspection), ce qui permet à un agent de vérifier le UnitData rendu.
