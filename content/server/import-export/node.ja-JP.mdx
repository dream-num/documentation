---
title: Office ファイルのインポートとエクスポート
description: Exchange で Office ファイルと共同編集 Unit の間の入出力を行います。
---

AI SDK ではなく、オフィスファイル変換は `@univerjs-pro/exchange-node`. で処理されます。 ファイルの境界では、CLI アプリケーションは `importFile()`、`exportToFile()`を呼び出し、その後、AI SDKとCollaboration SDKを使用して、ユニット上で動作します。

## SDK の責任範囲を保つ

```ts
import { exportToFile, importFile } from "@univerjs-pro/exchange-node";
```

| 機能 | 担当 |
| --- | --- |
| 事務所ファイルをUnitDataに変換 | Exchange |
| ヘッドレスランタイム、内容検査、Facade 実行 | AI SDK |
| スナップショット、変更セット、リビジョン、永続化 | Collaboration SDK |
| パス、形式の方針、業務 API、エラー対応付け | 業務アプリケーション |

## 共同編集 Unit のインポート

業務アプリケーションは、Exchange を通じて Office ファイルを読み込み、その結果の UnitData をコラボレーション サーバーに渡します。これにより、ユニットが作成されます。

```text
Office ファイル
→ importFile()
→ UnitData
→ 業務 Server API
→ 共同編集 Unit
```

アプリケーションは、初期リビジョン、ビジネスメタデータ、および返される結果を決定します。 ユニットが存在すると、CLI と Web の両方がサーバーを通じて動作します。

## 最新リビジョンのエクスポート

輸出のために、CLIはCollaboration Runtimeを通して最も最近の確認された修正を荷を積み、そして交換に完全なUnitDataを渡します:

```text
共同編集 Unit
→ 最新 UnitData
→ exportToFile()
→ Office ファイル
```

出力ファイルの拡張子はフォーマットを決定します。

## Commander でファイル操作を公開する

AI SDKは、Officeファイルのインポートとエクスポート用のプリセットコマンドパッケージを提供していません。ビジネスアプリケーションは、交換、Collaboration Runtime、および独自のサーバーAPIを組み合わせるためにCommanderを使用します。

```ts
import { Command } from "commander";

interface IFileExchangeDependencies {
  importFile(path: string): Promise<unknown>;
  createUnit(unitData: unknown): Promise<unknown>;
  loadLatestUnitData(unitId: string): Promise<unknown>;
  exportFile(unitData: unknown, path: string): Promise<void>;
  writeResult(result: unknown): void;
}

function addFileExchangeCommands(program: Command, dependencies: IFileExchangeDependencies): void {
  program.addCommand(
    new Command("import").argument("<office-file>").action(async (sourcePath) => {
      const unitData = await dependencies.importFile(sourcePath);
      const created = await dependencies.createUnit(unitData);
      dependencies.writeResult(created);
    }),
  );

  program.addCommand(
    new Command("export")
      .argument("<office-file>")
      .requiredOption("--unit <id>")
      .action(async (outputPath, { unit }) => {
        const unitData = await dependencies.loadLatestUnitData(unit);
        await dependencies.exportFile(unitData, outputPath);
      }),
  );
}
```

Commanderの外のすべての機能は、`IFileExchangeDependencies`で明示的に宣言されているので、コマンドは隠れたヘルパーに依存しません。アプリケーションは、Exchangeの`importFile()`と`exportToFile()`を呼び出してファイル変換を実行し、Collaboration Runtimeに`loadLatestUnitData()`を実行し、独自のサーバーAPIと結果の出力を注入します。

## 対応形式

| Unit | インポート | エクスポート |
| --- | --- | --- |
| Sheet | `.xls`, `.xlsx`, `.xlsm`, `.csv`, `.tsv` | `.xlsx`, `.csv`, `.tsv` |
| Doc | `.doc`, `.docx` | `.docx` |
| Slide | `.ppt`, `.pptx`, `.pptm`, `.ppsx`, `.ppsm`, `.potx` | `.pptx` |

アプリケーションは、ファイルを生成する前に、ユニットタイプに一致しない拡張子を拒否する必要があります。

## ローカル CLI のみを使う

アプリケーションは、インポートされたコンテンツをローカルのヘッドレスランタイムに直接渡し、Officeファイルをエクスポートすることにより、コラボレーションサーバーを迂回することができます。 このアプローチは、ワンオフ処理に適していますが、共有リビジョン、ライブWebプレビュー、履歴、またはWorktreeを提供していません。

コマンド名、パス引数、および結果プレゼンテーションは、ビジネスアプリケーションの責任を保ちます。 共同ユニットパスの場合、[文書の読み込みとコンテンツの操作](/ai/content-operations)を参照してください。 ファイル境界が配置されると、エージェントがレンダリングされたUnitDataをチェックすることができます[外観検査](/ai/visual-inspection)を続けてください。
