title: Office and PDF file import and export
description: Use the Node SDK to convert between Office or PDF files and Univer document data.
---

`@univerjs-pro/exchange-node` imports and exports Office and PDF files as Univer document data. In Node.js, use Buffers or file paths, or convert complete snapshots directly. PDF requires installing and registering the [optional PDF backend](#pdf) below.

## Keep the SDK boundary

```ts
import { exportToFile, importFile } from "@univerjs-pro/exchange-node";
```

| Capability                                                 | Owner                |
| ---------------------------------------------------------- | -------------------- |
| Office and PDF files to and from UnitData                  | Exchange  |
| Headless runtime, content inspection, and Facade execution | AI SDK       |
| Snapshots, changesets, revisions, and persistence          | Collaboration SDK    |
| Paths, format policy, business APIs, and error mapping     | Business application |

## Import a collaborative Unit

The business application reads an Office file through Exchange, then sends the resulting UnitData to Collaboration
Server to create a Unit:

```text
Office file
→ importFile()
→ UnitData
→ business Server API
→ collaborative Unit
```

The application decides the initial revision, business metadata, and result. After creation, CLI and Web both operate
the Unit through the Server.

## File name and format [#file-name-and-format]

`fileName` supplies the source file name, such as `report.xlsx`. When `format` is omitted, the SDK uses its extension to infer the format. Importers also use it for document naming; for example, XLSX import names the workbook `report`. A Buffer contains the file's bytes without its original name, so pass that name separately, even when you specify `format`.

- `importBuffer` and `importBufferToSnapshot` require a non-empty `fileName`, even when `format` is specified.
- `importFile` and `importFileToSnapshot` use the input path's basename by default; `fileName` can override it.
- When `format` is omitted, the SDK infers it from the file name's extension. For a missing or unsupported extension, specify `format` explicitly. An explicit `format` takes precedence over the extension.

## Specify a document ID [#document-id]

When importing a file, the SDK generates a document ID by default. If your system has already assigned an ID to the document, pass `unitId` to use that ID for the imported document. The following example imports XLSX:

```ts
import { UniverInstanceType } from '@univerjs/core';
import { importBufferToSnapshot } from '@univerjs-pro/exchange-node';

const imported = await importBufferToSnapshot(xlsxBuffer, {
    type: UniverInstanceType.UNIVER_SHEET,
    fileName: 'example.xlsx',
    unitId: 'your-document-id', // Optional; generated automatically when omitted.
});
```

In collaborative applications, this is the document ID used to [create and open the same document](/server/collaboration/browser-integration#create-and-open-the-same-document).

## Export the latest revision

For export, the CLI first loads the latest confirmed revision through Collaboration Runtime, then passes complete
UnitData to Exchange:

```text
collaborative Unit
→ latest UnitData
→ exportToFile()
→ Office file
```

Specify the target export format through `format` and use a matching output file extension.

## Expose the file boundary through Commander

The AI SDK does not provide a preset command package for Office file import and export. The business application uses
Commander to compose Exchange, Collaboration Runtime, and its own Server API:

```ts
import { Command } from "commander";

interface IFileExchangeDependencies {
  importFile(path: string): Promise<unknown>;
  createUnit(unitData: unknown): Promise<unknown>;
  loadLatestUnitData(unitId: string): Promise<unknown>;
  exportFile(unitData: unknown, path: string): Promise<void>;
  writeResult(result: unknown): void;
}

function addFileExchangeCommands(program: Command, dependencies: IFileExchangeDependencies): void {
  program.addCommand(
    new Command("import").argument("<office-file>").action(async (sourcePath) => {
      const unitData = await dependencies.importFile(sourcePath);
      const created = await dependencies.createUnit(unitData);
      dependencies.writeResult(created);
    }),
  );

  program.addCommand(
    new Command("export")
      .argument("<office-file>")
      .requiredOption("--unit <id>")
      .action(async (outputPath, { unit }) => {
        const unitData = await dependencies.loadLatestUnitData(unit);
        await dependencies.exportFile(unitData, outputPath);
      }),
  );
}
```

Every non-Commander capability is explicitly declared in `IFileExchangeDependencies`; none is an unseen helper. The
application implements file conversion with Exchange `importFile()` / `exportToFile()`, implements
`loadLatestUnitData()` with Collaboration Runtime, and injects its own Server API and result presentation.

## Supported formats

| Unit  | Import                                              | Export                  |
| ----- | --------------------------------------------------- | ----------------------- |
| Sheet | `.xls`, `.xlsx`, `.xlsm`, `.csv`, `.tsv`            | `.xlsx`, `.csv`, `.tsv` |
| Base  | `.xls`, `.xlsx`, `.csv`, `.tsv`                     | `.xlsx`, `.csv`, `.tsv` |
| Doc   | `.doc`, `.docx`                                     | `.docx`                 |
| Slide | `.ppt`, `.pptx`, `.pptm`, `.ppsx`, `.ppsm`, `.potx` | `.pptx`                 |
| PDF   | `.pdf`                                              | `.pdf`                  |

The application should reject an extension that does not match the Unit type before generating a file.

## PDF import and export [#pdf]

Install the Node SDK and optional PDF conversion backend:

```sh
pnpm add @univerjs-pro/exchange-node @univerjs-pro/exchange-pdf-node-binding
```

Execute the `@univerjs-pro/exchange-node/pdf` side-effect import before converting to register PDF support. If you configure authorization through `configureExchange()`, register PDF support first as well. This example converts between a file and a complete snapshot:

```ts
import { UniverInstanceType } from '@univerjs/core';
import {
    ExchangeFormat,
    importFileToSnapshot,
    exportSnapshotToFile,
} from '@univerjs-pro/exchange-node';

// Enable PDF support before configuring authorization or converting files.
import '@univerjs-pro/exchange-node/pdf';

const snapshot = await importFileToSnapshot('input.pdf', {
    type: UniverInstanceType.UNIVER_PDF,
    format: ExchangeFormat.PDF,
});

await exportSnapshotToFile(snapshot, 'output.pdf', {
    type: UniverInstanceType.UNIVER_PDF,
    format: ExchangeFormat.PDF,
});
```

PDF also supports `importFile`, `importBuffer`, `exportToFile`, `exportToBuffer`, and their snapshot APIs, using `UniverInstanceType.UNIVER_PDF` and `ExchangeFormat.PDF`. Buffer imports still require `fileName`. Converting PDF files in Node.js does not require an editor or collaboration service.

These APIs convert between PDF files and PDF document data; they do not export Office documents as PDF. See [Import/export licensing](/server/import-export/license) for PDF export authorization and quota, and [PDF import and export](/guides/pdfs/features/import-export) for browser integration.

## Use only a local CLI

An application can bypass the Collaboration Server, pass imported content directly to a local headless runtime, and
export an Office file. This is useful for one-off processing but does not provide shared revisions, live Web preview,
History, or Worktree.

Command names, path arguments, and result presentation belong to the business application. See
[Document loading and content operations](/ai/content-operations) for the collaborative Unit path. After adding the
file boundary, continue with [Visual inspection](/ai/visual-inspection) so an agent can check the rendered UnitData.
