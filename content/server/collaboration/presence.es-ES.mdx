---
title: Presencia en línea
description: Muestra quién está en un documento, los nombres y avatares de colaboradores y los cursores y selecciones remotos.
---

La presencia muestra quién más tiene el mismo documento abierto y donde cada persona está trabajando. Cuando Bob selecciona la celda B3, por ejemplo, Alice ve su selección etiquetada con el nombre “Bob”. Las aplicaciones también pueden mostrar los colaboradores actuales en una barra de avatar o una lista de miembros.

El SDK sincroniza la información de membresía y cursor y hace que los cursores remotos donde el editor los apoya. Los nombres de los colaboradores y los avatares son suministrados por la aplicación, y la API de suscripción de miembros está disponible para barras de avatar, paneles miembros y conteos de usuario en línea.

## Antes de empezar

Completa [Inicio rápido](/server/collaboration/quick-start) y [Identidad y autorización](/server/collaboration/identity-and-authorization) primero. En ese punto el editor debe sincronizar las ediciones, el servidor debe identificar al usuario registrado a través de `context.userID`, y las políticas de lectura, INGRESO y edición deben estar en su lugar.

Los ejemplos a continuación extienden la configuración `transport` existente, `endpoint` y `univer`. Retener las reglas de autenticación y autorización de la guía anterior.

## Sincronización de miembros y cursores

Alice y Bob abren la misma hoja de cálculo. La presencia produce dos tipos de actualizaciones:

| Acción | Lista de miembros | Qué ve Alice en la hoja |
| --- | --- | --- |
| Alice abre la hoja | Alice | Su propia selección |
| Bob abre la misma hoja | Alice, Bob | La selección de Bob cuando elige una celda |
| Bob pasa de B3 a C5 | Alice, Bob | Su selección se mueve a C5 |
| Bob cierra la hoja | Alice, tras recibir la salida | Desaparece la selección de Bob |

La lista de miembros cambia cuando una conexión se une o sale. Moving un cursor sólo cambia la selección dibujada en el editor; no añade o elimina un miembro. Si Bob también edita el valor en C5, el contenido de documento se sincroniza a través del flujo de edición de la colaboración.

La presencia se encuentra en un documento, una Unidad. Cubre a las personas actualmente conectadas a ese documento, mientras que la lista de acceso configurada en la guía anterior cubre a todos los que se les permite abrirlo. La presencia es temporal: el movimiento del cursor no crea un cambio, no avanza la revisión del documento, y no se guarda en la base de datos.

Con los plugins de colaboración de Quick start y el correspondiente editor UI habilitado, el SDK captura el cursor local y las actualizaciones de selección, los envía, y hace los correspondientes cursors, selecciones y nombres en los editores de otros miembros.

| Editor | Suscripción de miembros | UI de cursor y selección remotos |
| --- | --- | --- |
| Sheet | Compatible | Selecciones de celdas y rangos |
| Doc | Compatible | Cursores y selecciones de texto |
| Slide | Compatible | Posiciones del puntero y selecciones de objetos |
| Board | Compatible | Posiciones del puntero y selecciones de objetos |
| Base | Compatible | No disponible |

## 1. Establecer nombres y avatares

Establecer `context.member.name` y `context.member.avatar` en el `connect` Middleware de Endpoint. La aplicación decide cómo recuperar el perfil: consultarlo con el `context.session.userID` autenticado o reutilizar los datos guardados durante la autenticación en `customData`.

Este ejemplo utiliza `customData` para evitar una segunda búsqueda. Agregue estos campos al Transport Middleware existente y registre `connect` antes de iniciar el servidor:

```ts
type AppUser = {
  id: string;
  name: string;
  avatar?: string;
};

transport.use(async (context, next) => {
  // Your authentication function; rejects unauthenticated requests.
  const user: AppUser = await auth.requireUser(context.incomingMessage);
  context.userID = user.id;
  // An application-defined field to reuse the profile in connect.
  context.customData.user = user;
  await next();
});

endpoint.use("connect", async (context, next) => {
  // Read the profile saved when the session ticket was issued.
  const user = context.session.customData.user as AppUser;
  // Without this assignment, the member name defaults to userID.
  context.member.name = user.name;
  // Use an empty string when there is no avatar URL.
  context.member.avatar = user.avatar ?? "";
  await next();
});
```

El SDK pasa la `customData` de la solicitud de sesión-taket a `context.session.customData`. En un despliegue de varios nodos, un remitente conectado a otro nodo llega con sólo `userID` y `memberID`, por lo que los datos que deben viajar con cada mensaje pertenecen a la carga útil de Presencia. La clave `user` y el tipo `AppUser` son opciones de aplicación; el SDK no los interpreta. Otros colaboradores reciben el perfil asignado a `context.member`.

`connect` se ejecuta una vez por cada nueva conexión WebSocket, incluyendo reconexiones, y siempre antes de que el cliente se une a un documento. Cuando un perfil cambia en la aplicación, los perfiles de miembro ya compartidos con las conexiones existentes no se actualizan automáticamente.

## 2. Mostrar una lista de miembros (opcional)

Para construir una barra de avatar o un panel miembro, suscríbete a los miembros del documento abierto con `subscribeCollaborators(unitID, callback)`. La renderización de cursor no depende de esta suscripción.

```ts
import { FUniver } from "@univerjs/core/facade";
// Import once in the client entry point to enable collaboration Facade methods.
import "@univerjs-pro/collaboration-client/facade";

// Reuse an existing univerAPI if your editor setup already provides one.
const univerAPI = FUniver.newAPI(univer);
// unitID is the ID of the document open in the editor.
const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, (members) => {
  // Each callback is a new list snapshot that the application can use to update its UI.
  console.table(members);
});
```

El SDK espera que la sala de colaboración del documento esté disponible. Cada callback recibe una instantánea `IMember[]` de los miembros actualmente conocidos por el cliente, incluyendo el propio cliente una vez que se ha unido. Una lista vacía puede llegar durante la inicialización. El callback reporta la membresía, no posiciones de cursor.

Los datos de Alice y Bob incluyen estos campos (los ID son ilustrativos):

| `userID` | `memberID`                             | `name`  | `avatar` |
| -------- | -------------------------------------- | ------- | -------- |
| `alice`  | `83446a72-a1cc-4ed8-aedc-afd8907bbb18` | `Alice` | `""`     |
| `bob`    | `7ee5a94e-c784-4e1e-b1a3-b9d34be8ec4e` | `Bob`   | `""`     |

`userID` identifica a una persona en la aplicación. `memberID` identifica una conexión y es asignada por el SDK. Si Bob abre una segunda pestaña, la lista gana otra entrada con `userID: "bob"` y un `memberID`, por lo que ahora hay dos usuarios y tres conexiones. Las aplicaciones pueden agrupar por `userID` para una barra de avatar o un recuento de usuario en línea, o utilizar `memberID` para mostrar y contar conexiones.

Libere la suscripción cuando se elimina la vista que lo utiliza:

```ts
subscription.dispose();
```

Disponer una aplicación creada `univerAPI` y la instancia Univer cuando el editor es destruido. Cerrar sólo un panel miembro requiere deshacerse de la suscripción de ese panel.

### Ejemplo: lista de miembros React

Pase el `univerAPI` existente y el documento ID en este componente:

```tsx
import type { FUniver } from "@univerjs/core/facade";
import type { IMember } from "@univerjs/protocol";
import "@univerjs-pro/collaboration-client/facade";
import { useEffect, useState } from "react";

export function OnlineMembers({ univerAPI, unitID }: { univerAPI: FUniver; unitID: string }) {
  const [members, setMembers] = useState<IMember[]>([]);

  useEffect(() => {
    // Clear the previous document list while waiting for the new subscription.
    setMembers([]);
    const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, setMembers);
    // Unsubscribe when the document changes or the component unmounts.
    return () => subscription.dispose();
  }, [univerAPI, unitID]);

  // Show each user once, even when they have multiple connections.
  const users = [...new Map(members.map((member) => [member.userID, member])).values()];

  return (
    <ul>
      {users.map((user) => (
        <li key={user.userID}>
          {user.avatar && <img src={user.avatar} alt="" width={24} height={24} />}
          <span>{user.name}</span>
        </li>
      ))}
    </ul>
  );
}
```

La suscripción refleja la última membresía de la habitación recibida por el cliente. Una conexión perdida lleva tiempo para detectar, por lo que un miembro que sale puede permanecer en la lista brevemente. El estado de colaboración incorporado de SDK UI proporciona el estado de sincronización del cliente actual, una indicación offline, y una acción de reconexión.

## Prueba con dos usuarios

1. Inicia sesión como Alice y Bob en perfiles de navegador distintos y abre el mismo documento.
2. Comprueba que aparecen ambos nombres.
3. En una hoja, seleccione B3 como Bob, luego C5. Alice debe ver la selección de Bob llamada movimiento mientras que la lista de miembros permanece sin cambios.
4. Abrir otra ficha como Bob. La suscripción debe incluir otra `memberID`, y la lista React todavía debe mostrar Bob una vez.
5. Cierra ambas pestañas de Bob. Tras recibir las salidas, la lista de Alice solo debe contener Alice.
