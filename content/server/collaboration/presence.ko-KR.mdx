다른 사람들이 같은 문서가 열리며 각 사람이 작업하는 것을 보여줍니다. Bob이 셀 B3을 선택하면 Alice는 "Bob"이라는 이름으로 라벨을 보여줍니다. 응용 프로그램은 또한 아바타 바 또는 회원 목록에서 현재 공동 작업을 표시 할 수 있습니다.

SDK는 회원 및 커서 정보를 동기화하고 편집기가 지원되는 원격 커서를 렌더링합니다. Collaborator 이름과 아바타는 응용 프로그램에 의해 공급되며 회원 가입 API는 아바타 바, 회원 패널 및 온라인 사용자 카운트에 사용할 수 있습니다.

## 시작 전

[빠른 시작](/server/collaboration/quick-start) 및 [Identity 및 인증](/server/collaboration/identity-and-authorization)를 먼저 완료하십시오. 편집기가 편집을 동기화해야 할 점에서 서버는 `context.userID`을 통해 서명 된 사용자를 식별하고, 읽고, 가입하고, 정책을 편집해야합니다.

아래 예제는 기존 `transport`, `endpoint` 및 `univer` 설정을 확장합니다. 이전 가이드에서 인증 및 인증 규칙을 유지하십시오.

## 멤버와 커서 동기화

Alice와 Bob은 동일한 스프레드 시트를 엽니다. Presence는 두 종류의 업데이트를 생성합니다.

| 동작 | 멤버 목록 | Alice가 시트에서 보는 내용 |
| --- | --- | --- |
| Alice가 시트를 엶 | Alice | 자신의 선택 영역 |
| Bob이 같은 시트를 엶 | Alice, Bob | Bob이 셀을 선택하면 그의 선택 영역 |
| Bob이 B3에서 C5로 이동 | Alice, Bob | Bob의 선택 영역이 C5로 이동 |
| Bob이 시트를 닫음 | 나가기 업데이트 수신 후 Alice만 | Bob의 선택 영역 사라짐 |

회원 목록은 연결이 참여하거나 나날 때 변경됩니다. 커서를 이동하면 편집기에서 선택한을 변경합니다. 회원을 추가하거나 제거하지 않습니다. Bob은 또한 C5의 값을 편집하면 문서 콘텐츠는 협업 편집 흐름을 통해 동기화됩니다.

Presence는 하나의 문서에 따라 단위입니다. 이 문서에 현재 연결된 사람들을 다룹니다. 이전 가이드에서 구성 된 액세스 목록은 모두 열 수 있습니다. Presence is Temporary: cursor Movement does not create changeset, 문서 개정을 미리하지 않으며 데이터베이스에 저장되지 않습니다.

Quick start 및 대응 편집기 UI에서 협업 플러그인으로, SDK는 로컬 커서 및 선택 업데이트를 캡처하고, 해당 커서, 선택 및 다른 회원 편집기의 이름을 렌더링합니다.

| 편집기 | 온라인 멤버 구독 | 원격 커서·선택 UI |
| --- | --- | --- |
| Sheet | 지원 | 셀·범위 선택 |
| Doc | 지원 | 텍스트 커서·선택 |
| Slide | 지원 | 포인터 위치·객체 선택 |
| Board | 지원 | 포인터 위치·객체 선택 |
| Base | 지원 | 제공하지 않음 |

## 1. 협업자 이름과 아바타 설정

Endpoint의 `connect` Middleware에서 `context.member.name` 및 `context.member.avatar`를 설정하십시오. 응용 프로그램은 프로파일을 검색하는 방법을 결정합니다. 인증 된 `context.session.userID`로 쿼리하거나 `customData` 인증을 통해 저장된 데이터를 재사용하십시오.

이 예제는 `customData`를 사용하여 두 번째 조회를 피합니다. 기존의 Transport Middleware에 이러한 필드를 추가하고 서버 시작 전에 `connect`을 등록하십시오.

```ts
type AppUser = {
  id: string;
  name: string;
  avatar?: string;
};

transport.use(async (context, next) => {
  // Your authentication function; rejects unauthenticated requests.
  const user: AppUser = await auth.requireUser(context.incomingMessage);
  context.userID = user.id;
  // An application-defined field to reuse the profile in connect.
  context.customData.user = user;
  await next();
});

endpoint.use("connect", async (context, next) => {
  // Read the profile saved when the session ticket was issued.
  const user = context.session.customData.user as AppUser;
  // Without this assignment, the member name defaults to userID.
  context.member.name = user.name;
  // Use an empty string when there is no avatar URL.
  context.member.avatar = user.avatar ?? "";
  await next();
});
```

SDK는 세션 티켓 요청에서 `customData`을 `context.session.customData`로 전달합니다. 다중 노드 배포에서, 다른 노드에 연결된 보낸자는 `userID` 및 `memberID` 만 도착하므로 각 메시지가 Presence 페이로드에 속해야 할 데이터가 있습니다. `user` 키와 `AppUser` 유형은 응용 프로그램 선택이 아닙니다. SDK는 그들을 해석하지 않습니다. 다른 협동자는 `context.member`에 할당 된 프로필을받습니다.

`connect`는 각 새로운 WebSocket 연결을 위해 한 번 실행하고, 클라이언트가 문서에 가입하기 전에 항상. 응용 프로그램에서 프로필 변경할 때, 기존의 연결과 함께 이미 공유 회원 프로필은 자동으로 업데이트되지 않습니다.

## 2. 멤버 목록 표시(선택)

avatar bar 또는 회원 패널을 구축하려면 `subscribeCollaborators(unitID, callback)`와 열린 문서의 구성원에 가입하십시오. Cursor 렌더링은이 구독에 따라 달라지지 않습니다.

```ts
import { FUniver } from "@univerjs/core/facade";
// Import once in the client entry point to enable collaboration Facade methods.
import "@univerjs-pro/collaboration-client/facade";

// Reuse an existing univerAPI if your editor setup already provides one.
const univerAPI = FUniver.newAPI(univer);
// unitID is the ID of the document open in the editor.
const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, (members) => {
  // Each callback is a new list snapshot that the application can use to update its UI.
  console.table(members);
});
```

SDK는 문서의 협업 룸에 대한 대기를 제공합니다. 각 콜백은 클라이언트 자체를 포함하여 클라이언트에게 알려진 회원의 `IMember[]` 스냅 샷을 수신합니다. 빈 목록은 초기화 중에 도착 할 수 있습니다. 콜백 보고서 회원은 커서 위치가 아닙니다.

Alice와 Bob의 데이터는 다음과 같습니다(ID는 예시입니다).

| `userID` | `memberID`                             | `name`  | `avatar` |
| -------- | -------------------------------------- | ------- | -------- |
| `alice`  | `83446a72-a1cc-4ed8-aedc-afd8907bbb18` | `Alice` | `""`     |
| `bob`    | `7ee5a94e-c784-4e1e-b1a3-b9d34be8ec4e` | `Bob`   | `""`     |

`userID`는 신청에서 사람을 식별합니다. `memberID`는 1개의 연결을 식별하고 SDK에 의해 할당됩니다. 밥이 두번째 탭을 열면, 목록은 `userID: "bob"`와 다른 `memberID`를 가진 또 다른 입장을 얻습니다, 그래서 지금 2명의 사용자 및 3개의 연결이 있습니다. 신청은 아바타 막대기 또는 온라인 사용자 조사를 위해 `userID`에 의하여 그룹 할 수 있습니다, 또는 `memberID`를 전시하고 조사 연결하기 위하여 이용하십시오. 편집자는 각 연결의 커서를 따로따로 만듭니다.

그것을 제거하는 전망이 있을 때 구독을 해제:

```ts
subscription.dispose();
```

Application-created `univerAPI` 및 Univer 인스턴스를 컴파일하면 편집기가 파괴됩니다. 회원 패널만 닫으면 패널의 구독만 거부해야 합니다.

### 예제: React 멤버 목록

기존 `univerAPI` 및 문서 ID를 이 구성 요소로 전달하십시오.

```tsx
import type { FUniver } from "@univerjs/core/facade";
import type { IMember } from "@univerjs/protocol";
import "@univerjs-pro/collaboration-client/facade";
import { useEffect, useState } from "react";

export function OnlineMembers({ univerAPI, unitID }: { univerAPI: FUniver; unitID: string }) {
  const [members, setMembers] = useState<IMember[]>([]);

  useEffect(() => {
    // Clear the previous document list while waiting for the new subscription.
    setMembers([]);
    const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, setMembers);
    // Unsubscribe when the document changes or the component unmounts.
    return () => subscription.dispose();
  }, [univerAPI, unitID]);

  // Show each user once, even when they have multiple connections.
  const users = [...new Map(members.map((member) => [member.userID, member])).values()];

  return (
    <ul>
      {users.map((user) => (
        <li key={user.userID}>
          {user.avatar && <img src={user.avatar} alt="" width={24} height={24} />}
          <span>{user.name}</span>
        </li>
      ))}
    </ul>
  );
}
```

구독은 클라이언트가 받은 최신 룸 멤버십을 반영합니다. 분실된 연결은 시간이 걸립니다. 출발 회원은 목록에서 간단히 유지될 수 있습니다. SDK의 내장 협업 상태 UI는 현재 클라이언트의 동기화 상태, 오프라인 표시 및 재연결 동작을 제공합니다.

## 두 사용자로 확인

1. 별도 브라우저 프로필에서 Alice와 Bob으로 로그인해 같은 문서를 엽니다.
2. 목록에 두 이름이 보이는지 확인합니다.
3. 시트에서 밥으로 B3를 선택하면 C5를 선택합니다. 앨리스는 Bob의 이름을 선택 이동을 보아야하며 회원 목록은 변경되지 않습니다.
4. 밥으로 다른 탭을 엽니 다. 구독은 다른 `memberID`를 포함해야하며 React 목록은 여전히 밥을 표시해야합니다.
5. Bob의 두 탭을 닫습니다. 나가기 업데이트 수신 후 Alice 목록에는 Alice만 남아야 합니다.
