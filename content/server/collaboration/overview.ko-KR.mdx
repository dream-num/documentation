**Univer Collaboration SDK**는 Univer 문서 모형을 위한 서버 측 SDK입니다. 그것은 가동 변환 (OT[^operational-transformation]), 개정[^collaboration-revision], 스냅샷, 순간 동기화 및 지속을 취급합니다, 이렇게 다수 Univer 클라이언트가 동일한 권위 단위를 편집할 수 있다 그래야.

애플리케이션은 Node.js 서비스에 SDK를 포함했습니다. 식별 및 인증은 Middleware를 통해 연결되며, Middleware 또는 Events에 로그인 및 기타 응용 프로그램으로 연결됩니다. 별도의 데이터베이스 어댑터는 애플리케이션의 데이터베이스에 협업 데이터를 연결합니다.

<Callout title="완전한 문서 제품이 아닙니다.">
  SDK는 협업 코어만 제공합니다. 사용자, 역할, 계층, 공유, 파일 공간 및 비즈니스 워크플로우는 범위 밖에 있으며, 애플리케이션은 여전히 그 제품 기능과 데이터 모델을 소유합니다.
</Callout>

## 해결하는 문제

Web SDK 디스플레이 및 편집 시트, Doc, 슬라이드, 보드,베이스 및 브라우저의 PDF 콘텐츠. 실시간 멀티 사용자 편집은 Web SDK의 상단에 서버 측 권한을 요구합니다. 그 권한은 컨텐츠를로드하고 동시 변경, 사전 개정을 확인하고, 단일 클라이언트가 일관된 상태로 복구 할 수 있도록합니다.

다음 애플리케이션에 적합합니다.

- 이미 Univer를 사용하여 편집기를 구축하고 실시간 멀티 사용자 편집을 원합니다.
- 호스트 협업 데이터 자체를 원하고 자신의 데이터베이스를 선택하십시오;
- 기존 신원 확인, 권한 부여, 테넌트 규칙을 협업 작업에 연결해야 하는 경우
- 핵심 협업에 History, Thread Comment, Worktree, 파일 스토리지 또는 Office 가져오기와 내보내기를 추가하려는 경우

## 전체 협업 서비스

| 모듈 | 주요 역할 |
| --- | --- |
| Collaboration Client | Loads Units, changesets를 제출하고 브라우저의 협업 상태를 유지하십시오. |
| Node Transport | HTTP/WebSocket 트래픽을 수신하고 애플리케이션의 입장 Middleware 실행 |
| `UniverCollabEndpoint` | 클라이언트 프로토콜, Session, Room, Presence, ACK, 브로드캐스트 구현 |
| `UniverCollabService` | Unit Lifecycle 관리, OT 수행, 지속적인 개정을 확인합니다 |
| Database Adapter | 상점 스냅샷, 변경 세트, 개정 및 제출 idempotency 국가 원자로 |

## SDK가 제공하는 기능

핵심 기능은 다음과 같습니다.

- 시트, Doc, 슬라이드, 보드,베이스 및 PDF에 대한 장치 생성, 로딩, 삭제 및 복구;
- 스냅샷, 변경 집합, 리비전, OT, 제출 멱등성
- WebSocket Sessions, Rooms, Presence, ACKs 및 방송과 함께 HTTP 콘텐츠 로딩;
- Transport, Endpoint, Service 경계의 Middleware
- Unit 생성, 변경 집합 커밋, 삭제, 복구에 대한 프로세스 내부 Events
- 내장 또는 사용자 정의 Database Adapter를 통한 협업 데이터 저장;
- 다중 노드 배포를 통해 수평 스케일링: 노드는 pub/sub 어댑터와 공유 세션 티켓 스토어를 통해 협력하고, SDK는 Redis 구현을 제공합니다.

핵심 경로가 장소에 있는 경우, 신청은 버전 역사, 스레드 댓글, Worktree 초안, 파일 저장 및 서버 측 사무실 수입품 및 수출을 추가할 수 있습니다. 그 기능의 각각에는 그것의 자신의 서비스, Middleware, 사건, 또는 데이타베이스 접합기가 있습니다.

## 애플리케이션이 담당하는 기능

| Collaboration SDK | 애플리케이션 |
| --- | --- |
| Unit 협업 상태 | 사용자, 테넌트, 계층, 공유 관계 |
| OT, 리비전, 스냅샷 | 로그인, Session, 신원 매핑 |
| 협업 Session, Room, Presence | 역할, ACL, 제품 정책 |
| 협업 및 파일 Database Adapter | 제품 데이터베이스와 스토리지 운영 |
| Middleware와 Event 확장 지점 | 로깅, 감사, 지표, 외부 통합 |
| 클라이언트 프로토콜 Endpoint | 업무 API 및 문서 생성 등의 흐름 |

## 세 가지 일반 확장 지점

| 확장 지점 | 해결하는 문제 |
| --- | --- |
| Middleware | Inspects 또는 enriches Context, 요청을 거부, 또는 작업 실행 동안 무슨 일이 있었는지 기록 |
| Event | 상태 변경을 확인하여 in-process 파생된 상태 업데이트 또는 비-critical follow-up 작업을 시작합니다. |
| Database Adapter | 데이터가 생길 수 있는 선택과 원자성, CAS 및 idempotency 계약 구현 |

식별 및 권한은 Middleware를 통해 연결됩니다. Middleware는 실행하기 전에 작동을 검증하고, 이벤트 기록 변경 또는 트리거 후속 작업을 한 번 상태가 확인됩니다. 로깅, 요청 추적, 메트릭스, 파생 상태 업데이트를 수행 할 수 있습니다. [Middleware 및 이벤트](/server/collaboration/middleware-and-events)는 각 실행이 있는지 설명합니다.

## 시작하기

1. [빠른 시작](/server/collaboration/quick-start)를 실행하고 두 브라우저에서 전체 경로 확인.
2. [모듈 경계와 관계](/server/collaboration/modules)를 읽고 각 패키지의 목적을 이해합니다.
3. 통합 작업을 위해 [Middleware 및 이벤트](/server/collaboration/middleware-and-events), [Identity 및 인증](/server/collaboration/identity-and-authorization) 또는 [데이터베이스 어댑터](/server/collaboration/database-adapters)를 선택하십시오.
4. [협업 확장 모듈](/server/collaboration/extensions)로 이동하여 역사, 댓글, Worktrees, 파일 저장 및 수입 및 수출.

[^operational-transformation]: OT는 서로 다른 문서 리비전을 기준으로 동시에 생성된 작업을 조정하여 일관되게 적용하도록 합니다. 마지막으로 도착한 스냅샷으로 문서 전체를 덮어쓰는 방식이 아닙니다.

[^collaboration-revision]: 리비전은 Unit의 확정된 편집 이력에서 위치를 나타냅니다. changeset은 한 제출에 포함된 작업 집합이며, 확정되면 이력이 진행됩니다. SDK 패키지 버전이나 타임스탬프가 아닙니다.
