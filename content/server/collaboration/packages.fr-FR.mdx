Cette page explique comment sélectionner les paquets du Collaboration SDK. Commencez par la collaboration de base, puis ajoutez les modules d'extension requis par le produit. L'installation de chaque paquet n'est pas nécessaire.

Les paquets serveur pour Adaptateurs de bases de données, Fichier et Office Exchange sont open source sous Apache-2.0, et leur code source est publié dans [univer-collaboration-sdk-community](https://github.com/dream-num/univer-collaboration-sdk-community). Ces paquets utilisent le même préfixe et la même version que tous les autres paquets, et ils sont installés de la même manière.

## Core Collaboration

Core Collaboration fournit le chemin principal: collaboration du navigateur, traitement du protocole du serveur, OT, révisions, et la persistance.

| Environnement   | Paquet                                                                                                                                 | Ce qu'il fait                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Navigateur      | [**@univerjs-pro/collaboration**](https://www.npmjs.com/package/@univerjs-pro/collaboration)                                           | Enregistre les capacités collaboratives de base du navigateur                                           |
| Navigateur      | [**@univerjs-pro/collaboration-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client)                             | Charge les Units, envoie les changements et maintient la synchronisation                                |
| Navigateur      | [**@univerjs-pro/collaboration-client-ui**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client-ui)                       | Fournit l’UI et les styles d’état collaboratif                                                          |
| Server          | [**@univerjs-pro/collaboration-transport-node**](https://www.npmjs.com/package/@univerjs-pro/collaboration-transport-node)             | Reçoit le trafic HTTP et WebSocket Node.js                                                              |
| Server          | [**@univerjs-pro/collaboration-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-endpoint)                         | Implémente protocole Client, Sessions, Rooms et Presence                                                |
| Server          | [**@univerjs-pro/collaboration-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-service)                           | Gère Units, OT, révisions et API du Service central                                                     |
| Base de données | [**@univerjs-pro/collaboration-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-memory)           | Stockage en processus pour tests, exemples et développement temporaire                                  |
| Base de données | [**@univerjs-pro/collaboration-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-sqlite)           | Persistance SQLite pour développement, tests, usage local et petite échelle                             |
| Base de données | [**@univerjs-pro/collaboration-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-postgres)       | Persistance PostgreSQL partagée entre plusieurs nœuds                                                   |
| Base de données | [**@univerjs-pro/collaboration-database-postgres-s3**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-postgres-s3) | Stocke les blocs de cellules dans S3 pour réduire la taille de la base PostgreSQL et de ses sauvegardes |
| Multi-node      | [**@univerjs-pro/collaboration-cluster-redis**](https://www.npmjs.com/package/@univerjs-pro/collaboration-cluster-redis)               | Adaptateur pub/sub et stockage des session tickets sur Redis pour le déploiement sur plusieurs nœuds    |

Un serveur Core utilise Transport, Endpoint, Service et un adaptateur de base de données. Memory, SQLite, PostgreSQL et PostgreSQL + S3 implémentent le même contrat. Une application choisit généralement un seul de ces adaptateurs. Pour un déploiement sur plusieurs nœuds, Endpoint définit aussi `IPubSubAdapter` et `ISessionTicketStore` pour la diffusion des messages et le partage des tickets de session. Le SDK en fournit une implémentation Redis.

## History

L'historique construit un index version-histoire à partir de la création de l'unité et des changementset commit Événements que Core émet.

| Environnement   | Paquet                                                                                                                                           | Ce qu'il fait                                  |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| Navigateur      | Réutilise Core Client/UI                                                                                                                         | Affiche et lit les entrées d’historique        |
| Server          | [**@univerjs-pro/collaboration-history-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-service)                     | Construit et interroge l’index d’historique    |
| Server          | [**@univerjs-pro/collaboration-history-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-endpoint)                   | Expose le protocole History au Client          |
| Base de données | [**@univerjs-pro/collaboration-history-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-memory)     | Stockage en mémoire de l’index History         |
| Base de données | [**@univerjs-pro/collaboration-history-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-sqlite)     | Stocke l’index History dérivé                  |
| Base de données | [**@univerjs-pro/collaboration-history-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-postgres) | Stocke l’index de l’historique dans PostgreSQL |

Les données d'historique sont un index dérivé et peuvent toujours être reconstruites.

## Thread Comment

Thread Comment gère le contenu des commentaires, les réponses et leur état de résolution.

| Environnement   | Paquet                                                                                                                                           | Ce qu'il fait                                                      |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Navigateur      | Réutilise les paquets Core Collaboration                                                                                                         | Utilise Comment Client et l’UI                                     |
| Server          | [**@univerjs-pro/collaboration-comment-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-service)                     | Gère les commentaires et l’événement `commentCommitted`            |
| Server          | [**@univerjs-pro/collaboration-comment-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-endpoint)                   | Fournit le protocole et publie les mises à jour via les Unit Rooms |
| Base de données | [**@univerjs-pro/collaboration-comment-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-memory)     | Stockage des commentaires en processus                             |
| Base de données | [**@univerjs-pro/collaboration-comment-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-sqlite)     | Persistance SQLite des commentaires                                |
| Base de données | [**@univerjs-pro/collaboration-comment-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-postgres) | Stocke les commentaires et les réponses dans PostgreSQL            |

Comment Adapter stocke les commentaires. Les ancres mobiles avec le contenu restent dans les instantanés et changements Core.

## Worktree

Worktree fournit brouillons isolés, transitions d’état et fusion par Unit.

| Environnement   | Paquet                                                                                                                                             | Ce qu'il fait                                    |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Navigateur      | [**@univerjs-pro/collaboration-worktree-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-client)                       | Connecte brouillons, états et fusion Worktree    |
| Server          | [**@univerjs-pro/collaboration-worktree-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-service)                     | Gère changements du brouillon, états et fusion   |
| Server          | [**@univerjs-pro/collaboration-worktree-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-endpoint)                   | Fournit le protocole au Worktree Client          |
| Base de données | [**@univerjs-pro/collaboration-worktree-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-memory)     | Stockage Worktree en processus                   |
| Base de données | [**@univerjs-pro/collaboration-worktree-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-sqlite)     | Persistance SQLite de Worktree                   |
| Base de données | [**@univerjs-pro/collaboration-worktree-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-postgres) | Conserve les brouillons Worktree dans PostgreSQL |

Le service Worktree fusionne en fin de compte dans le coffre par l'intermédiaire du service de base, de sorte que Middleware doit être configuré aux deux limites du service.

## File

Fichier stocke les fichiers binaires que les clients Univer téléchargent : images et pièces jointes insérées dans une unité, ainsi que les fichiers source et résultat d'une importation ou d'une exportation.

| Environnement | Paquet | Ce qu'il fait |
| --- | --- | --- |
| Navigateur | Réutilise le Core Collaboration Client | Envoie images et pièces jointes et résout les ID de fichier en URL |
| Server | [**@univerjs-pro/collaboration-file-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-service) | Applique les règles de propriété, les Middleware et le nettoyage des fichiers temporaires |
| Server | [**@univerjs-pro/collaboration-file-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-endpoint) | Fournit les routes d’envoi, de sign-url et de téléchargement |
| Base de données | [**@univerjs-pro/collaboration-file-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-memory) | Stockage en mémoire des métadonnées et du contenu |
| Base de données | [**@univerjs-pro/collaboration-file-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-sqlite) | Persistance SQLite des métadonnées de fichier |
| Base de données | [**@univerjs-pro/collaboration-file-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-postgres) | Persistance PostgreSQL des métadonnées de fichier |
| Stockage | [**@univerjs-pro/collaboration-file-blob-local**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-local) | Stocke le contenu dans un répertoire local |
| Stockage | [**@univerjs-pro/collaboration-file-blob-s3**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-s3) | Stocke le contenu dans un stockage objet compatible S3, avec liens directs signés |

Les métadonnées et le contenu sont deux contrats indépendants, de sorte que chacun peut utiliser le stockage que l'application fournit déjà. Les métadonnées peuvent résider dans la base de données alors que le contenu réside dans le stockage d'objets.

## Office Exchange

Office Exchange importe des fichiers Office en Units collaboratives et exporte des Units en fichiers. File stocke les fichiers source et résultat.

| Environnement | Paquet | Ce qu'il fait |
| --- | --- | --- |
| Navigateur | [**@univerjs-pro/exchange-client**](https://www.npmjs.com/package/@univerjs-pro/exchange-client) | Fournit l’échange de fichiers de base du navigateur |
| Navigateur | [**@univerjs-pro/sheets-exchange-client**](https://www.npmjs.com/package/@univerjs-pro/sheets-exchange-client) | Fournit l’import-export Sheet |
| Server | [**@univerjs-pro/collaboration-exchange-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-service) | Gère les task d’import et d’export, les Middleware et la création et lecture des Units |
| Server | [**@univerjs-pro/collaboration-exchange-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-endpoint) | Fournit les routes d’import, d’export et de task |
| Server | [**@univerjs-pro/exchange-node**](https://www.npmjs.com/package/@univerjs-pro/exchange-node) | Convertit Office et données Univer dans Node.js |

Service d'échange crée et lit les unités par le service de base et lit et écrit les fichiers par le service des fichiers, de sorte qu'il doit être assemblé avec le noyau et le fichier.

## Règles de sélection

1. Commencez par les paquets Core du [démarrage rapide](/server/collaboration/quick-start).
2. Choisissez un [adaptateur de base de données Core](/server/collaboration/database-adapters) en fonction des besoins de stockage de l’application.
3. Pour un déploiement sur plusieurs nœuds, ajoutez l’adaptateur pub/sub et le stockage de session tickets sur Redis.
4. Installez uniquement les paquets de modules d'extension que le produit utilise.
5. Si le produit nécessite des images, des pièces jointes, ou l'importation et l'exportation, assemblez Fichier d'abord et ajoutez Office Exchange seulement quand cela est nécessaire.
6. Créer un Adaptateur séparé pour chaque module même lorsque plusieurs modules partagent une base de données.

Voir [Modules d'extension de la collaboration](/server/collaboration/extensions) pour les relations entre les modules, et [exemple index](/server/collaboration/examples), pour les assemblages runnables.
