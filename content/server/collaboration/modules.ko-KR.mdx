Univer 협업은 브라우저 클라이언트와 서버 측 모듈의 집합으로 구성됩니다. 각 모듈은 책임의 한 종류를 소유합니다. 응용 프로그램은 공공 인터페이스를 통해 모듈을 구성하므로 코드는 OT[^operational-transformation] 구현의 내부에 의존하지 않습니다, 프로토콜 또는 지속 층.

## Collaboration Client

브라우저 협업 클라이언트는 Web SDK와 함께 실행되며 클라이언트의 협업을 처리합니다.

- 그것은 단위 스냅 샷을 요청하고 누락 된 모든 확인 된 변경 세트.
- WebSocket 연결을 열려면 한 번 세션 티켓을 사용합니다.
- Unit Rooms에 가입하고 다른 회원들과 교환합니다.
- 그것은 변경 설정으로 서버에 로컬 mutations를 제출합니다.
- 그것은 ACKs와 방송을 받고, 다시 연결 후 그것은 놓친 변경을 fetches.

클라이언트는 사용자가 신뢰할 수 있는지 결정하지 않으며, 권한 데이터 소스가 아닙니다. 그 결정은 해당 Middleware의 정체성과 허가를 시행하는 서버에 속합니다.

## Node Transport

`@univerjs-pro/collaboration-transport-node`는 HTTP와 WebSocket 트래픽의 Node.js 항목 포인트입니다. 호스트 HTTP 서버에서 요청 및 WebSocket 업그레이드를 받으며 애플리케이션에 등록한 Entry Middleware를 실행하고, 엔드포인트에 트래픽을 전달합니다.

수송은 OT, 단위 자료, 또는 ACL 모형을 이해하지 않습니다. 회의는 3개의 방법을 이용합니다:

```ts
transport.use(httpMiddleware);
transport.useUpgrade(upgradeMiddleware);
transport.register(endpoint);
```

- `use()`는 정규적인 HTTP 요구를 취급하고 `userID`, `customData`의 통나무, 또는 추적을 설치할 수 있습니다.
- `useUpgrade()`는 WebSocket Handhake를 취급하고 설치하기 전에 연결을 거부 할 수 있습니다.
- `register()`는 프로토콜 엔드포인트를 등록하여, 그 수명주기는 그 후 관리합니다.

## Collaboration Endpoint

`@univerjs-pro/collaboration-endpoint`는 Univer 협업 클라이언트에 의해 사용되는 프로토콜을 구현하고 다음 기능을 소유합니다.

| 기능 | Endpoint 역할 |
| --- | --- |
| 콘텐츠 로드 | 반환 단위 스냅 샷 및 블록, 어떤 확인된 변경과 함께 클라이언트가 부족 |
| 변경 제출 | 변경 집합 수신, ACK 반환, 확정 변경을 Room에 브로드캐스트 |
| Session 연결 | 한 번의 세션 티켓을 발행하고 WebSocket 세션을 수립하고 유지 |
| Room 협업 | JOIN, LEAVE, 멤버 상태, Presence 처리 |
| Unit 수명 주기 | 삭제·복구 요청을 해당 Service 호출에 매핑 |
| 다중 노드 | Relays Rooms, Presence, and Broadcasts throughout nodes through the Selection pub/sub adapter and a shared ticket store |

Endpoint는 OT을 수행하지 않으며 협업 데이터를 저장하지 않습니다. 그것은 클라이언트 프로토콜로 돌아가는 서비스 및지도에서 권위있는 결과를 얻습니다. 문서 생성과 같은 제품 운영은 서비스 호출 애플리케이션 API에 속합니다.

## Collaboration Service

`@univerjs-pro/collaboration-service`는 협력 핵심이고 네트워크에 의존하지 않습니다. 그것은 장, Doc, 활주, 널, 기초 및 PDF를 포함합니다:

- 그것은 단위 회복 자료 및 확인된 changesets를 읽습니다.
- Unit Data 또는 Snapshots에서 Unit을 생성합니다.
- 변경 사항을 제출하면 OT을 실행하고 연속 개정[^collaboration-revision]를 미리 시작합니다.
- `(unitID, sid, reqId)`를 통해 중복 제출을 식별합니다.
- 그것은 soft-deletes, 재기, 또는 영구적으로 단위를 삭제합니다.
- 서비스 Middleware를 실행하고 확인 후 이벤트를 방출합니다.

서비스에는 HTTP 또는 WebSocket 레이어가 없으며 사용자, 역할, ACL, hierarchy 또는 파일 관리에 대해 알지 못합니다. Endpoint는 서비스의 상단에 브라우저 프로토콜을 구축합니다. 애플리케이션은 비즈니스 API 또는 배경 작업에서 직접 서비스의 공개 API를 호출 할 수 있습니다.

### 핵심 API

| 기능 | Service API |
| --- | --- |
| Unit 로드 | `getUnitLoadData()`, `getUnitLoadDataWithBlocks()` |
| 증분 데이터 읽기 | `getChangesets()`, `getSheetBlock()` |
| Unit 생성 | `createUnitFromData()`, `createUnitFromSnapshot()` |
| 변경 제출 | `submitChangeset()` |
| 삭제·복구 | `deleteUnits()`, `recoverUnits()` |

## Database Adapter

Database Adapter는 Service와 저장소 사이의 계약이며 다음을 보장해야 합니다.

- 초기 스냅샷과 의존 데이터의 원자적 생성
- 리비전 비교 후 교환(CAS)
- idempotent 변경 사항 제출;
- 그것의 의존성 전부 후에 스냅 샷 시정은 존재합니다;
- Unit 수명 주기 배치의 전부 성공 또는 전부 미적용

애플리케이션은 `IDatabaseAdapter`를 통해 저장소를 연결합니다. 내장 어댑터 선택과 사용자 정의 어댑터 구현은 [Database Adapter](/server/collaboration/database-adapters)를 참조하세요.

## 네 가지 핵심 개념

| 개념 | 의미 |
| --- | --- |
| Unit | 독립적으로 로드 및 협업 Univer 콘텐츠, 독특한 `unitID` 및 유형 |
| Snapshot | 개정에 따른 단위 내용, 살아있는 mutable 객체가 아닌 |
| Changeset | idempotency를 위한 기본 개정 및 정체성으로 함께 제출된 mutations의 배치 |
| Revision | `1`에서 시작하는 확인된 단위 국가의 지속적인 버전 수 |

콘텐츠를 실행하는 모든 변경은 Facade APIs 또는 Commands를 통해 이동합니다. 스냅 샷 개체를 Mutating하면 클라이언트 또는 서비스에 라이브 유닛을 업데이트하지 않습니다.

## Unit 로드

<Mermaid chart={"sequenceDiagram\n    participant Client\n    participant Transport\n    participant Endpoint\n    participant Service\n    participant Adapter\n\n    Client->>Transport: HTTP로 Unit 로드\n    Transport->>Endpoint: 인증된 요청 Context\n    Endpoint->>Service: getUnitLoadData()\n    Service->>Adapter: 스냅샷 + 변경 집합\n    Adapter-->>Service: 기준 데이터\n    Service-->>Endpoint: Unit 로드 데이터\n    Endpoint-->>Client: 프로토콜 응답"} />

`userID/customData`는 현재 HTTP 요청을 서비스 미들웨어로 수송 Middleware에 의해 설립. 응용 프로그램은 읽기 허용 여부를 결정한다. 클라이언트는 일반 HTTP를 읽기 전에 방에 가입 할 필요가 없습니다.

## 편집 제출

```text
Facade / Command
  → Mutation
  → Client 변경 집합
  → Endpoint 제출
  → Service Middleware
  → OT + 리비전 CAS
  → Adapter 원자적 커밋
  → 확정 변경 집합
  → ACK / Room 브로드캐스트
```

데이터베이스 어댑터의 확인된 개정은 저자 상태입니다. ACK 및 방송은 낮은 대기 시간으로 동기화 된 온라인 클라이언트를 유지합니다. 메시지를 놓는 클라이언트는 이미 개정을 사용하여 확인 된 변경 세트를 fetch 할 수 있습니다.

## 최소 서버 구성

```ts
import { createServer } from "node:http";

import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

const server = createServer();
transport.attach(server);
server.listen(3010);
```

하드 코딩된 사용자와 메모리 어댑터는 모듈 어셈블리만 보여줍니다. 실제 애플리케이션은 중간웨어를 통해 컨텍스트를 설정하고 데이터 요구 사항을 일치시키는 어댑터를 선택하십시오.

### 애플리케이션 API로 Unit 생성

응용 프로그램은 자신의 HTTP 또는 RPC 엔드포인트를 정의하고 인증, 입력 유효성 및 비즈니스 체크 패스를 입력 한 후 생성 된 `service`를 호출 할 수 있습니다 :

```text
업무 클라이언트
  → POST /api/units
  → 애플리케이션 인증·검증
  → service.createUnitFromData()
  → Database Adapter
```

아래의 Express 예제는 인증 Middleware가 `response.locals.user`를 설정하고 `request.body.data`는 이미 Workbook Data로 검증되었습니다.

```ts
import { randomUUID } from "node:crypto";

import { json } from "express";
import { UniverType } from "@univerjs/protocol";

app.post("/api/units", json({ limit: "1mb" }), async (request, response, next) => {
  try {
    const user = response.locals.user as { readonly userID: string };
    const unitID = randomUUID();

    const result = await service.createUnitFromData(
      {
        type: UniverType.UNIVER_SHEET,
        data: {
          ...request.body.data,
          id: unitID,
          rev: 1,
        },
      },
      {
        userID: user.userID,
        customData: { traceID: randomUUID() },
      },
    );

    response.status(result.status === "created" ? 201 : 200).json(result);
  } catch (error) {
    next(error);
  }
});
```

`POST /api/units`는 애플리케이션 경로이며 협업 클라이언트 프로토콜의 일부가 아닙니다. `createUnitFromData()`를 호출하는 것은 여전히 서비스 `createUnit` Middleware를 실행합니다. 제품 레코드, 소유자 ACL, 오류 응답 매핑 및 실패 보상은 응용 프로그램의 책임에 남아 있습니다.

## 리소스 정리

`transport.dispose()`는 `register()`에 등록 된 엔드 포인트를 분배합니다. 응용 프로그램이 거부되어야하는 서비스 및 데이터베이스 어댑터는 어셈블리 주문의 역방향으로 별도로 처분해야합니다.

```ts
await transport.dispose();
await service.dispose();
await database.dispose();
```

애플리케이션이 pub/sub 어댑터를 공급한 경우, 해당 어댑터와 그 연결이 전송 후 처리해야 합니다. Endpoint는 그(것)들을 분해하지 않습니다.

이 모듈 경계에서 동작을 확장하려면 [Middleware 및 이벤트](/server/collaboration/middleware-and-events)로 계속됩니다.

[^operational-transformation]: OT는 서로 다른 문서 리비전을 기준으로 동시에 생성된 작업을 조정하여 일관되게 적용하도록 합니다. 마지막으로 도착한 스냅샷으로 문서 전체를 덮어쓰는 방식이 아닙니다.

[^collaboration-revision]: 리비전은 Unit의 확정된 편집 이력에서 위치를 나타냅니다. changeset은 한 제출에 포함된 작업 집합이며, 확정되면 이력이 진행됩니다. SDK 패키지 버전이나 타임스탬프가 아닙니다.
