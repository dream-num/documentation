---
title: Licence
description: Collaboration SDK s’appuie sur la licence pour décider des connexions d’édition collaborative, des domaines autorisés, des nœuds de collaboration et des types de documents.
---

`UniverCollabService` charge la licence pendant la construction, et Endpoints et Worktrees partagent cette instance. Configurez la licence comme décrit dans [Licence](/server/license#collaboration-sdk); sans une, le SDK fonctionne sur le niveau libre. Si la vérification échoue, le constructeur lance un `CollabError` (`LICENSE_INVALID` ou `LICENSE_POLICY_INVALID`), et le service ne démarre pas.

## Ce que décide la licence [#limits]

| Élément | Vérifié par | Au-delà de la limite |
| --- | --- | --- |
| Connexions d’édition collaborative | Point final, sur réception des soumissions | Les éditions des nouvelles connexions restent dans le navigateur et sont réétudiées |
| Domaines autorisés | Point d'arrivée, lors de la connexion et sur les soumissions | La session de collaboration du navigateur passe hors ligne |
| Nœuds de collaboration | Endpoint | Les nœuds au-delà de la limite passent hors ligne après un délai de grâce |
| Types de documents | Service sur la création et l ' édition d ' unités | La création et les soumissions sont refusées ; les documents existants restent consultables |

### Connexions d’édition collaborative [#editing-connections]

Une connexion de collaboration occupe une fente après sa première soumission réussie et la libère lorsque la connexion se ferme, ou 120 secondes après sa dernière soumission réussie. Les connexions qui ouvrent un document seulement pour la visualisation peuvent se joindre à tout moment. Les modifications à l'intérieur d'un Worktree comptent contre le même pool de fente que les modifications sur le tronc.

Lorsque chaque fente est occupée, les modifications d'une nouvelle connexion restent dans le navigateur, et Web SDK les renver avec backoff jusqu'à ce qu'une fente devienne disponible. Les connexions qui détiennent déjà une fente continuent à éditer. Le `CollaborationChangesetResend` du navigateur rapporte ces renverres avec `reason: 'license_editing_connections_exceeded'`.

### Domaines autorisés [#domains]

Lorsque Web SDK ouvre une connexion de collaboration ou soumet des modifications, l'Endpoint compare le domaine de la page avec les domaines autorisés dans la Licence. Un domaine extérieur à cette liste reçoit `403` ; la session de collaboration du navigateur va ensuite hors ligne et affiche la raison. La session rétresse lorsque l'utilisateur se reconnecte ou ouvre un autre document.

### Nœuds de collaboration [#nodes]

Un **Licence unique de nœud**, y compris le niveau libre, exécute un nœud de collaboration. Le passage de `pubSub` à l'Endpoint rend le constructeur lancer `LICENSE_POLICY_INVALID`.

Une **licence multi-noeud** définit une limite de nœud. Lorsque le nombre de nœuds en cours d'exécution dépasse cette limite, les nœuds les plus récents entrent dans une période de grâce avec des avertissements croissants et vont ensuite hors ligne. Les nouvelles connexions reçoivent `503`, et les connexions existantes se ferment. Les nœuds dans la limite continuent à servir le trafic. Si le nombre de noeuds tombe dans la limite pendant la période de grâce, les nœudS supplémentaires reviennent à la normale. Un noeud qui est passé hors ligne est compté comme un nouveau noeud après le redémarrage de son processus. Pour les déploiements multinoeuds, voir [Déploiement](/server/deployment#plusieurs-nœuds-de-collaboration).

### Types de documents [#unit-types]

La licence énumère les types de documents disponibles pour la collaboration. La création d'une unité de tout autre type lance `LICENSE_UNIT_TYPE_REJECTED`, et les modifications soumises sont rejetées. `CollaborationConflict` dans le navigateur rapporte `reason` sous `license_unit_type_rejected`. Les documents existants restent visibles.

## Observer l’état [#observe]

```ts
// Service
collabService.license.status // état de la licence : 'not_configured' | 'expired' | 'valid'
collabService.license.editingConnectionsLimit // limite de connexions d’édition : number | null ; null signifie illimité
collabService.license.nodesLimit // limite de nœuds : number | null ; null signifie illimité
collabService.license.domains // domaines autorisés : string[]
collabService.license.expiresAt // date d’expiration : chaîne ISO | null ; null sans licence configurée
collabService.license.update({ license, licenseKey }) // remplace la licence ; lève une erreur et conserve l’actuelle si la vérification échoue

// Endpoint
endpoint.license.editingConnections.limit // limite de places : number | null ; null signifie illimité
endpoint.license.editingConnections.used // places occupées : number | null ; null quand limit est illimité
endpoint.license.editingConnections.remaining // places restantes : number | null ; null signifie illimité
endpoint.license.editingConnections.has(memberID) // ce membre occupe-t-il une place : boolean ; false quand limit est illimité
endpoint.license.nodes.limit // limite de nœuds : number | null ; null signifie illimité
endpoint.license.nodes.status // état de ce nœud : 'normal' | 'exceeded' | 'exceeded-warning' | 'exceeded-offlineSoon' | 'exceeded-offline'

// Événements
endpoint.license.on('editingConnectionsChanged', ({ change, memberIDs, used, limit }) => {}) // des places ont été prises ou rendues : change vaut 'acquired' | 'released', used est la valeur après le changement ; non émis quand limit est illimité
endpoint.license.on('editingConnectionsExceeded', ({ memberID, userID, unitID, used, limit }) => {}) // toutes les places sont prises et la soumission d’une nouvelle connexion n’a pas été enregistrée
endpoint.license.on('nodesStatusChanged', ({ status, previousStatus, limit, reason }) => {}) // l’état de ce nœud a changé ; reason n’a de valeur qu’au passage hors ligne
```

`nodesStatusChanged` allume une fois pour chaque changement d'état de ce noeud. Lorsque `status` devient `exceeded-offline`, le noeud a cessé d'accepter les connexions; le retirer de l'équilibreur de charge ou soulever une alerte.
