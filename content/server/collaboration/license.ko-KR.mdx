`UniverCollabService`는 건설 기간 동안 라이센스를로드하고 엔드포인트와 워크 트리는 그 인스턴스를 공유합니다. [이름 *](/server/license#collaboration-sdk)에 설명 된 라이센스를 구성하십시오. 하나없이 SDK는 무료 계층에서 실행됩니다. 검증이 실패하면 생성자는 `CollabError` (`LICENSE_INVALID` 또는 `LICENSE_POLICY_INVALID`)를 던져 서비스가 시작되지 않습니다.

## 라이선스가 결정하는 네 가지 [#limits]

| 항목 | 확인 위치 | 한도를 넘으면 |
| --- | --- | --- |
| 협업 편집 연결 | 제출을 받기에 Endpoint, | 새 연결에서 편집은 브라우저에 남아 있으며, retried |
| 승인된 도메인 | Endpoint, 연결 및 제출시 | 브라우저의 협업 세션이 오프라인으로 전환됨 |
| 협업 노드 | Endpoint | 한도를 넘은 노드는 유예 기간 후 오프라인됨 |
| 문서 유형 | 서비스, 단위 생성 및 편집 제출 | 생성과 제출이 거부되며, 기존 문서는 계속 볼 수 있음 |

### 협업 편집 연결 [#editing-connections]

허용량은 적극적으로 편집되는 연결만 계산합니다. 협업 연결은 첫 성공적인 제출 후 슬롯을 점유하고 연결이 닫을 때 120 초, 또는 마지막 성공적인 제출 후 120 초를 방출합니다. 보기만 문서를 열 수있는 연결은 언제든지 참여할 수 있습니다. 같은 슬롯 풀에 대한 Worktree 내부 편집은 트렁크에서 편집합니다.

모든 슬롯이 점유될 때, 새로운 연결에서 편집은 브라우저에 남아 있으며 Web SDK는 슬롯이 사용할 때까지 백오프로 다시 보냅니다. 슬롯을 계속 편집 할 수있는 연결. 브라우저의 `CollaborationChangesetResend` 이벤트는 `reason: 'license_editing_connections_exceeded'`와 함께 이러한 재전송을 보고합니다.

### 승인된 도메인 [#domains]

Web SDK가 협업 연결을 열 때 또는 편집을 제출하면 엔드포인트는 라이센스의 허가 된 도메인과 페이지의 도메인을 비교합니다. 목록 외부 도메인은 `403`를받습니다. 브라우저의 협업 세션은 오프라인으로 진행되며 이유를 표시합니다. 사용자의 재연결 또는 다른 문서를 열 때 세션 저장소.

### 협업 노드 [#nodes]

무료 계층을 포함한 **단일 노드 라이센스**는 하나의 협업 노드를 실행합니다. `pubSub`를 Endpoint에 전달하면 생성기가 `LICENSE_POLICY_INVALID`을 던집니다.

₢ 킹 **멀티 노드 라이센스** 노드 제한을 정의합니다. 실행 노드의 수는 제한을 초과할 때, 최신 노드는 에스컬레이션 경고와 함께 우아한 기간을 입력하고 오프라인으로 이동합니다. 새로운 연결은 수신 `503`, 그리고 기존의 연결 닫기. 제한 내에서 노드는 계속 트래픽을 제공. 노드가 은혜 기간 동안 제한 내에서 다시 떨어지면, 여분 노드가 정상으로 돌아갑니다. 오프라인으로 사라진 노드는 프로세스 재시작 후 다시 새로운 노드로 계산됩니다. 멀티 노드 배포를 위해, 참조 [관련 상품](/server/deployment#여러-협업-노드).

### 문서 유형 [#unit-types]

라이센스는 협업을 위해 사용할 수있는 문서 유형 목록을 나열합니다. 다른 유형의 단위를 만드는 것은 `LICENSE_UNIT_TYPE_REJECTED`를 던지고 제출 된 편집은 거부됩니다. 브라우저의 `CollaborationConflict`는 `reason`가 `license_unit_type_rejected`로보고합니다. 기존 문서는 볼 수 있습니다.

## 상태 확인 [#observe]

```ts
// Service
collabService.license.status // 라이선스 상태: 'not_configured' | 'expired' | 'valid'
collabService.license.editingConnectionsLimit // 협업 편집 연결 한도: number | null, null은 무제한
collabService.license.nodesLimit // 협업 노드 한도: number | null, null은 무제한
collabService.license.domains // 승인된 도메인: string[]
collabService.license.expiresAt // 만료 시각: ISO 문자열 | null, 설정하지 않으면 null
collabService.license.update({ license, licenseKey }) // 라이선스 교체: 검증에 실패하면 예외를 던지고 현재 라이선스를 유지

// Endpoint
endpoint.license.editingConnections.limit // 자리 한도: number | null, null은 무제한
endpoint.license.editingConnections.used // 사용 중인 자리: number | null, limit이 무제한이면 null
endpoint.license.editingConnections.remaining // 남은 자리: number | null, null은 무제한
endpoint.license.editingConnections.has(memberID) // 이 멤버가 자리를 가졌는지: boolean, limit이 무제한이면 false
endpoint.license.nodes.limit // 노드 한도: number | null, null은 무제한
endpoint.license.nodes.status // 이 노드의 상태: 'normal' | 'exceeded' | 'exceeded-warning' | 'exceeded-offlineSoon' | 'exceeded-offline'

// 이벤트
endpoint.license.on('editingConnectionsChanged', ({ change, memberIDs, used, limit }) => {}) // 자리를 차지하거나 반환할 때 발생: change는 'acquired' | 'released', used는 변화 후의 값, limit이 무제한이면 발생하지 않음
endpoint.license.on('editingConnectionsExceeded', ({ memberID, userID, unitID, used, limit }) => {}) // 자리가 가득 차서 새 연결의 제출이 저장되지 않았을 때 발생
endpoint.license.on('nodesStatusChanged', ({ status, previousStatus, limit, reason }) => {}) // 이 노드의 상태가 바뀔 때 발생, reason은 오프라인될 때만 값이 있음
```

`nodesStatusChanged`는 이 노드의 각 상태 변경을 위해 한 번 불을 붙입니다. `status`가 `exceeded-offline`이 되면 노드는 연결 허용을 중단했습니다. 로드밸런서에서 제거하거나 경고를 올리십시오.
