**Univer Collaboration SDK** 是 Univer 文档模型的服务端协同 SDK。它处理 OT[^operational-transformation]、revision[^collaboration-revision]、snapshot、实时同步与持久化，使多个 Univer 客户端能够同时编辑同一个权威 Unit。

应用将 SDK 嵌入自己的 Node.js 服务，通过 Middleware 接入身份与权限，并将日志与其他业务逻辑挂接到 Middleware 或 Event。协同数据由独立的 Database Adapter 连接到应用的数据库。

<Callout title="它不是完整的文档产品">
  SDK 只提供协同核心，不包含用户、角色、目录、分享、文件空间或业务工作流。这些产品能力及其数据模型仍由应用负责。
</Callout>

## 它解决什么问题

Web SDK 负责在浏览器中显示和编辑 Sheet、Doc、Slide、Board、Base 与 PDF 内容。多人实时编辑还需要一个服务端权威：它加载内容、确认并发修改、推进 revision，并使断线的客户端恢复到一致状态。

它适用于以下应用：

- 已经使用 Univer 构建编辑器，并希望支持多人实时编辑；
- 希望自行托管协同数据，并自行选择数据库；
- 需要将现有的身份、权限或租户规则接入协同操作；
- 需要在核心协同之上增加 History、Thread Comment、Worktree、文件存储或 Office 导入导出。

| 模块                   | 主要职责                                               |
| ---------------------- | ----------------------------------------------------- |
| Collaboration Client   | 加载 Unit、提交 changeset，并维护浏览器端的协同状态    |
| Node Transport         | 接收 HTTP/WebSocket 流量，运行应用注册的入口 Middleware |
| `UniverCollabEndpoint` | 实现客户端协议、Session、Room、Presence、ACK 与广播    |
| `UniverCollabService`  | 管理 Unit 生命周期，执行 OT，确认连续 revision         |
| Database Adapter       | 原子保存 snapshot、changeset、revision 与提交幂等状态  |

## SDK 提供什么

核心能力包括：

- 为 Sheet、Doc、Slide、Board、Base 与 PDF 创建、加载、删除和恢复 Unit；
- snapshot、changeset、revision、OT 与提交幂等；
- HTTP 内容加载，以及 WebSocket 的 Session、Room、Presence、ACK 与广播；
- Transport、Endpoint 与 Service 三个边界上的 Middleware；
- Unit 创建、changeset 提交、删除与恢复等进程内 Event；
- Memory、SQLite 与 PostgreSQL 实现，以及自定义 Database Adapter 的合同；
- 通过多节点部署实现水平扩展：节点之间通过 pub/sub 适配器与共享的 Session Ticket 存储协作，SDK 提供 Redis 实现。

核心链路可用后，应用还可以增加版本历史、Thread Comment、Worktree 草稿、文件存储与服务端 Office 导入导出。这些能力各自拥有 Service、Middleware、Event 或 Database Adapter。

## 应用负责什么

| Collaboration SDK              | 业务应用                    |
| ------------------------------ | --------------------------- |
| Unit 协同状态                  | 用户、租户、目录和分享关系  |
| OT、revision 与 snapshot       | 登录、Session 与身份映射    |
| 协同 Session、Room 与 Presence | 角色、ACL 与产品策略        |
| 协同与文件的 Database Adapter  | 产品数据库与存储的运维      |
| Middleware 与 Event 扩展点     | 日志、审计、指标和外部集成  |
| 客户端协议 Endpoint            | 创建文档等业务 API 与工作流 |

## 三类通用扩展点

| 扩展点           | 适合解决的问题                                                   |
| ---------------- | ---------------------------------------------------------------- |
| Middleware       | 操作执行期间检查或补充 Context、拒绝请求，或者记录处理过程       |
| Event            | 观察已经确认的状态变化，更新进程内派生状态或安排非关键的后续处理 |
| Database Adapter | 决定协同数据的存储位置，并实现原子性、CAS 和幂等合同             |

身份与权限通过 Middleware 接入。Middleware 在操作执行前校验并限制操作，Event 在状态确认后记录变更或触发后续处理。日志、请求追踪、指标与派生数据更新可以由两者承担。各自的执行边界见 [Middleware 与 Event](/server/collaboration/middleware-and-events)。

## 从哪里开始

1. 完成[快速开始](/server/collaboration/quick-start)，并用两个浏览器验证完整链路。
2. 阅读[模块边界与协作关系](/server/collaboration/modules)，了解每个 package 的存在原因。
3. 根据接入任务选择 [Middleware 与 Event](/server/collaboration/middleware-and-events)、[身份与权限](/server/collaboration/identity-and-authorization)或 [Database Adapter](/server/collaboration/database-adapters)。
4. 如需 History、Comment、Worktree、文件存储或导入导出，请阅读[协同扩展模块](/server/collaboration/extensions)。

[^operational-transformation]: *操作转换（OT）* 会调整基于不同文档修订号并发产生的操作，使它们能够一致地应用。它处理的是编辑操作，而不是用最后到达的快照覆盖整份文档。

[^collaboration-revision]: 修订号（revision）标识 Unit 已确认编辑历史中的位置。变更集（changeset）包含一次提交中的操作，确认后会推进历史。修订号不是 SDK 包版本，也不是时间戳。
