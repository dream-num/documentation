Presence 讓使用者看到還有誰開啟了同一份文件，以及其他成員正在操作的位置。例如，Bob 選中 B3 單元格時，Alice 能看到標有“Bob”的選區。應用也可以用頭像欄或成員列表展示當前的協作者。

SDK 負責同步成員和游標資訊，並渲染編輯器支援的遠端游標。協作者的名稱和頭像由應用提供，成員訂閱 API 可用於建置頭像欄、成員面板或線上人數統計。

## 開始之前

請先完成[快速開始](/server/collaboration/quick-start)和[身分與權限](/server/collaboration/identity-and-authorization)。此時編輯器應已能同步內容修改，伺服器端應能透過 `context.userID` 識別登入使用者，讀取、JOIN 和編輯的權限規則也已配置。

以下範例在已有的 `transport`、`endpoint` 和 `univer` 配置上繼續擴充套件，並沿用上一篇的認證和權限規則。

## 成員與游標同步

Alice 和 Bob 開啟同一張表格。Presence 會產生兩類更新：

| 操作 | 成員清單 | Alice 在表格中看到的內容 |
| --- | --- | --- |
| Alice 開啟表格 | Alice | 自己的選取範圍 |
| Bob 開啟相同表格 | Alice、Bob | Bob 選取儲存格時的選取範圍 |
| Bob 從 B3 移至 C5 | Alice、Bob | Bob 的選取範圍移至 C5 |
| Bob 關閉表格 | 收到離開更新後只剩 Alice | Bob 的選取範圍消失 |

連線加入或離開時，成員列表會隨之更新。移動游標只改變編輯器中繪製選區的位置，不會增加或減少成員。如果 Bob 隨後修改 C5 的值，文件內容會透過協同編輯流程同步。

Presence 的作用範圍是一份文件，也就是一個 Unit。它表示當前連線到這份文件的成員，上一篇配置的訪問列表則表示誰有權開啟這份文件。Presence 是臨時狀態：移動游標不會生成 changeset，不會推進文件 revision，也不會寫入資料庫。

啟用快速開始中的協同外掛和對應的編輯器 UI 後，SDK 會採集本地的游標和選區更新併傳送，再在其他成員的編輯器中渲染對應的游標、選區和名稱。

| 編輯器 | 線上成員訂閱 | 遠端游標與選取範圍 UI |
| --- | --- | --- |
| Sheet | 支援 | 儲存格與範圍選取 |
| Doc | 支援 | 文字游標與選取範圍 |
| Slide | 支援 | 指標位置與物件選取 |
| Board | 支援 | 指標位置與物件選取 |
| Base | 支援 | 不提供 |

## 1. 設定協作者名稱與頭像

在 Endpoint 的 `connect` Middleware 中設定 `context.member.name` 和 `context.member.avatar`。資料的取得方式由應用決定：可以根據已認證的 `context.session.userID` 查詢，也可以複用認證時存入 `customData` 的資料。

下面的範例透過 `customData` 避免第二次查詢。請將這些欄位加入已有的 Transport Middleware，並在啟動服務前註冊 `connect`：

```ts
type AppUser = {
  id: string;
  name: string;
  avatar?: string;
};

transport.use(async (context, next) => {
  // Your authentication function; rejects unauthenticated requests.
  const user: AppUser = await auth.requireUser(context.incomingMessage);
  context.userID = user.id;
  // An application-defined field to reuse the profile in connect.
  context.customData.user = user;
  await next();
});

endpoint.use("connect", async (context, next) => {
  // Read the profile saved when the session ticket was issued.
  const user = context.session.customData.user as AppUser;
  // Without this assignment, the member name defaults to userID.
  context.member.name = user.name;
  // Use an empty string when there is no avatar URL.
  context.member.avatar = user.avatar ?? "";
  await next();
});
```

SDK 會將簽發 Session Ticket 的請求中的 `customData` 傳遞到 `context.session.customData`。多節點部署時，連線在其他節點上的傳送者只攜帶 `userID` 和 `memberID`，因此需要隨每條訊息傳遞的資料應放入 Presence payload。`user` 欄位名和 `AppUser` 型別由應用自行約定，SDK 不解析它們。其他協作者收到的是設定在 `context.member` 上的資料。

每條新的 WebSocket 連線都會執行一次 `connect`，重連也不例外，執行時機在客戶端加入文件之前。應用中修改使用者資料後，已共享給現有連線的成員資料不會自動更新。

## 2. 顯示成員清單（選用）

如需頭像欄或成員面板，可用 `subscribeCollaborators(unitID, callback)` 訂閱已開啟文件的成員。游標渲染不依賴這個訂閱。

```ts
import { FUniver } from "@univerjs/core/facade";
// Import once in the client entry point to enable collaboration Facade methods.
import "@univerjs-pro/collaboration-client/facade";

// Reuse an existing univerAPI if your editor setup already provides one.
const univerAPI = FUniver.newAPI(univer);
// unitID is the ID of the document open in the editor.
const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, (members) => {
  // Each callback is a new list snapshot that the application can use to update its UI.
  console.table(members);
});
```

SDK 會等待文件的協同房間就緒。每次回撥提供客戶端當前已知成員的 `IMember[]` 快照，加入後也包含自己；初始化期間可能先收到空列表。回撥只報告成員，不包含游標位置。

Alice 和 Bob 的成員資料欄位如下（ID 僅供示範）：

| `userID` | `memberID`                             | `name`  | `avatar` |
| -------- | -------------------------------------- | ------- | -------- |
| `alice`  | `83446a72-a1cc-4ed8-aedc-afd8907bbb18` | `Alice` | `""`     |
| `bob`    | `7ee5a94e-c784-4e1e-b1a3-b9d34be8ec4e` | `Bob`   | `""`     |

`userID` 標識應用中的一個使用者，`memberID` 由 SDK 分配，標識一條連線。如果 Bob 再開啟一個標籤頁，列表會增加一項，`userID` 仍為 `"bob"`，`memberID` 不同，此時共有兩個使用者、三條連線。應用可以按 `userID` 歸併成員，用於頭像欄或線上人數統計；也可以按 `memberID` 展示和統計連線。編輯器為每條連線單獨渲染游標。

使用該訂閱的檢視關閉時，請釋放訂閱：

```ts
subscription.dispose();
```

銷燬編輯器時，還需釋放應用建立的 `univerAPI` 和 Univer 例項。如果只關閉成員面板，釋放該面板的訂閱即可。

### 範例：React 成員清單

將已有的 `univerAPI` 和文件 ID 傳入該元件：

```tsx
import type { FUniver } from "@univerjs/core/facade";
import type { IMember } from "@univerjs/protocol";
import "@univerjs-pro/collaboration-client/facade";
import { useEffect, useState } from "react";

export function OnlineMembers({ univerAPI, unitID }: { univerAPI: FUniver; unitID: string }) {
  const [members, setMembers] = useState<IMember[]>([]);

  useEffect(() => {
    // Clear the previous document list while waiting for the new subscription.
    setMembers([]);
    const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, setMembers);
    // Unsubscribe when the document changes or the component unmounts.
    return () => subscription.dispose();
  }, [univerAPI, unitID]);

  // Show each user once, even when they have multiple connections.
  const users = [...new Map(members.map((member) => [member.userID, member])).values()];

  return (
    <ul>
      {users.map((user) => (
        <li key={user.userID}>
          {user.avatar && <img src={user.avatar} alt="" width={24} height={24} />}
          <span>{user.name}</span>
        </li>
      ))}
    </ul>
  );
}
```

成員訂閱反映客戶端最近一次收到的房間成員狀態。連線中斷需要一定時間才能檢測到，因此已離開的成員可能短暫保留在列表中。SDK 內建的協同狀態 UI 會顯示當前客戶端的同步狀態、離線提示和重連入口。

## 使用兩位使用者驗證

1. 在不同瀏覽器設定檔中分別以 Alice 和 Bob 登入，開啟同一文件。
2. 確認成員清單中出現兩個名稱。
3. 在 Sheet 中讓 Bob 先選中 B3，再選中 C5。Alice 應看到標有 Bob 名稱的選區移動，成員列表保持不變。
4. 以 Bob 開啟另一個分頁。訂閱應增加另一個 `memberID`，React 清單仍只顯示一次 Bob。
5. 關閉 Bob 的兩個標籤頁。收到離開通知後，Alice 的成員列表應只剩她自己。
