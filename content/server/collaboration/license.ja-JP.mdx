`UniverCollabService` は、構造中にライセンスをロードし、エンドポイントとワークツリーがそのインスタンスを共有します。[ライセンス](/server/license#collaboration-sdk)で記述されているライセンスを設定し、一つなしに、SDK はフリーティア上で動作します。検証が失敗すると、コンストラクタは `CollabError` (`LICENSE_INVALID`または `LICENSE_POLICY_INVALID`) をスローし、サービスは起動しません。

## ライセンスが決める 4 項目 [#limits]

| 項目 | 確認する場所 | 上限を超えた場合 |
| --- | --- | --- |
| 共同編集接続 | エンドポイント、投稿を受信する | 新しい接続からの編集はブラウザに残り、取得されます。 |
| 承認済みドメイン | エンドポイントは、投稿の接続と接続時に | ブラウザーの共同編集セッションがオフラインになる |
| 共同編集ノード | Endpoint | 上限を超えたノードは猶予期間の後にオフラインになる |
| ドキュメントの種類 | サービス、ユニット作成および編集の提出 | 作成と送信が拒否され、既存のドキュメントは引き続き閲覧できる |

### 共同編集接続 [#editing-connections]

allowance は、積極的に編集しているコネクションのみをカウントします。コラボレーションコネクションは、最初の成功した投稿の後、スロットを占有し、接続が閉じるとき、または最後の成功した投稿の後に 120 秒を解放します。 ドキュメントを開くコネクションがいつでも参加できます。 Worktree 内の編集は、トランク上の編集と同じスロットプールに対してカウントします。

すべてのスロットが占有されると、新しい接続から編集がブラウザに残り、Web SDKは、スロットが利用可能になるまで、バックオフでそれらを再送します。 既にスロットを保持している接続は、編集を続行します。 ブラウザの`CollaborationChangesetResend`では、これらは`reason: 'license_editing_connections_exceeded'`に留まっています。

### 承認済みドメイン [#domains]

Web SDKがコラボレーション接続を開くか、編集を提出すると、エンドポイントは、ライセンスの認可ドメインとページドメインを比較します。 そのリストの外側のドメインは、`403`を受け取ります。 ブラウザのコラボレーションセッションはオフラインで行われ、理由が表示されます。 ユーザーが別のドキュメントを再接続または開いたときにセッションは、再接続します。

### 共同編集ノード [#nodes]

**シングルノードライセンス**は、無料のティアを含む1つのコラボレーションノードを実行します。 エンドポイントに`pubSub`を渡すことで、コンストラクタが`LICENSE_POLICY_INVALID`を投げます。

**マルチノードライセンス** は、ノードの制限を定義します。 実行ノードの数がその制限を超えた場合、最新のノードは、エスカレート警告で猶予期間に入り、オフラインで行きます。 新しい接続は `503` を受信し、既存の接続が閉じます。 制限内のノードはトラフィックを引き続き提供します。 ノードが猶予期間中に制限内で低下した場合、追加のノードは正常に戻ります。 プロセスが再起動した後、オフラインに新しいノードが再びカウントされます。 マルチノードの展開については、[導入事例](/server/deployment#複数の共同編集ノード)を参照してください。

### ドキュメントの種類 [#unit-types]

ライセンスは、コラボレーションで利用可能なドキュメントタイプをリストします。他のタイプのユニットを作成すると`LICENSE_UNIT_TYPE_REJECTED`をスローし、提出された編集は拒否されます。 ブラウザの`CollaborationConflict`は`license_unit_type_rejected`として`reason`を報告します。 既存の文書は閲覧可能です。

## 状態の確認 [#observe]

```ts
// Service
collabService.license.status // ライセンスの状態：'not_configured' | 'expired' | 'valid'
collabService.license.editingConnectionsLimit // 共同編集接続の上限：number | null、null は無制限
collabService.license.nodesLimit // 共同編集ノードの上限：number | null、null は無制限
collabService.license.domains // 承認済みドメイン：string[]
collabService.license.expiresAt // 有効期限：ISO 文字列 | null、未設定のときは null
collabService.license.update({ license, licenseKey }) // ライセンスを置き換える：検証に失敗するとスローし、現在のライセンスを維持

// Endpoint
endpoint.license.editingConnections.limit // 枠の上限：number | null、null は無制限
endpoint.license.editingConnections.used // 使用中の枠：number | null、limit が無制限のときは null
endpoint.license.editingConnections.remaining // 残りの枠：number | null、null は無制限
endpoint.license.editingConnections.has(memberID) // このメンバーが枠を持っているか：boolean、limit が無制限のときは false
endpoint.license.nodes.limit // ノードの上限：number | null、null は無制限
endpoint.license.nodes.status // このノードの状態：'normal' | 'exceeded' | 'exceeded-warning' | 'exceeded-offlineSoon' | 'exceeded-offline'

// イベント
endpoint.license.on('editingConnectionsChanged', ({ change, memberIDs, used, limit }) => {}) // 枠が使用または解放されたときに発生：change は 'acquired' | 'released'、used は変化後の値、limit が無制限のときは発生しない
endpoint.license.on('editingConnectionsExceeded', ({ memberID, userID, unitID, used, limit }) => {}) // 枠が埋まっていて、新しい接続の送信が保存されなかったときに発生
endpoint.license.on('nodesStatusChanged', ({ status, previousStatus, limit, reason }) => {}) // このノードの状態が変わったときに発生、reason はオフライン時のみ値を持つ
```

`nodesStatusChanged`は、このノードの各ステータス変更のために一度に火災します。 `status`が`exceeded-offline`になると、ノードは接続を受け付けなくなりました。 ロードバランサから削除するか、アラートを上げます。
