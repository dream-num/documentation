이 페이지는 Collaboration SDK에서 패키지를 선택하는 방법을 설명합니다. 핵심 협업으로 시작하면 제품 요구 사항이 확장 모듈을 추가합니다. 모든 패키지를 설치하면 필요하지 않습니다.

데이터베이스 어댑터, 파일 및 Office Exchange의 서버 패키지는 Apache-2.0의 오픈 소스이며 소스 코드는 [univer-collaboration-sdk 커뮤니티](https://github.com/dream-num/univer-collaboration-sdk-community)에 게시됩니다. 이 패키지는 다른 패키지와 동일한 패키지 접두사 및 버전을 사용하며 동일한 방법으로 설치됩니다.

## Core Collaboration

핵심 협업은 주요 경로를 제공합니다: 브라우저 협업, 서버 프로토콜 처리, OT, 개정 및 지속.

| 실행 환경    | 패키지                                                                                                                                 | 그것은 무엇입니까?                                                      |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 브라우저     | [**@univerjs-pro/collaboration**](https://www.npmjs.com/package/@univerjs-pro/collaboration)                                           | 브라우저 기본 공동 편집 기능 등록                                       |
| 브라우저     | [**@univerjs-pro/collaboration-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client)                             | Unit 로드, 변경 제출, 실시간 동기화                                     |
| 브라우저     | [**@univerjs-pro/collaboration-client-ui**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client-ui)                       | 공동 편집 상태 UI 및 스타일 제공                                        |
| Server       | [**@univerjs-pro/collaboration-transport-node**](https://www.npmjs.com/package/@univerjs-pro/collaboration-transport-node)             | Node.js HTTP 및 WebSocket 트래픽 수신                                   |
| Server       | [**@univerjs-pro/collaboration-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-endpoint)                         | Client 프로토콜, Sessions, Rooms, Presence 구현                         |
| Server       | [**@univerjs-pro/collaboration-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-service)                           | Unit, OT, 리비전, 핵심 Service API 관리                                 |
| 데이터베이스 | [**@univerjs-pro/collaboration-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-memory)           | 테스트, 예제, 임시 개발용 프로세스 내 저장                              |
| 데이터베이스 | [**@univerjs-pro/collaboration-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-sqlite)           | 개발, 테스트, 로컬, 소규모용 SQLite 영구 저장                           |
| 데이터베이스 | [**@univerjs-pro/collaboration-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-postgres)       | 여러 노드가 공유하는 PostgreSQL 영속성                                  |
| 데이터베이스 | [**@univerjs-pro/collaboration-database-postgres-s3**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-postgres-s3) | 셀 데이터 블록을 S3에 저장해 PostgreSQL 데이터베이스와 백업 크기를 줄임 |
| Multi-node   | [**@univerjs-pro/collaboration-cluster-redis**](https://www.npmjs.com/package/@univerjs-pro/collaboration-cluster-redis)               | 다중 노드 배포를 위한 Redis 기반 pub/sub 어댑터와 Session Ticket 저장소 |

Core Server에는 Transport, Endpoint, Service와 Database Adapter 하나가 필요합니다. Memory, SQLite, PostgreSQL, PostgreSQL + S3는 같은 계약을 구현하며, 애플리케이션은 일반적으로 이 중 하나를 선택합니다. 여러 노드를 배포할 때는 pub/sub 어댑터와 공유 세션 티켓 저장소도 필요합니다. Endpoint는 두 계약(`IPubSubAdapter`, `ISessionTicketStore`)을 정의하고 SDK는 Redis 구현을 제공합니다.

## History

History는 Unit 작성 및 변경 사항의 버전-history 인덱스를 구축하여 핵심이 방출되는 이벤트를 진행합니다.

| 실행 환경    | 패키지                                                                                                                                           | 그것은 무엇입니까?                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- |
| 브라우저     | Core Client/UI 재사용                                                                                                                            | 기록 항목 표시 및 읽기             |
| Server       | [**@univerjs-pro/collaboration-history-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-service)                     | 기록 인덱스 생성 및 조회           |
| Server       | [**@univerjs-pro/collaboration-history-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-endpoint)                   | Client에 History 프로토콜 제공     |
| 데이터베이스 | [**@univerjs-pro/collaboration-history-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-memory)     | History 인덱스의 인프로세스 저장소 |
| 데이터베이스 | [**@univerjs-pro/collaboration-history-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-sqlite)     | 파생 History 인덱스 저장           |
| 데이터베이스 | [**@univerjs-pro/collaboration-history-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-postgres) | 기록 인덱스를 PostgreSQL에 저장    |

역사 자료는 파생된 색인이고 항상 재건될 수 있습니다. 핵심 변화 세트는 단위 내용을 위해 권위를 남아 있습니다.

## Thread Comment

Thread Comment는 댓글 본문, 답글, 해결 상태를 관리합니다.

| 실행 환경    | 패키지                                                                                                                                           | 그것은 무엇입니까?                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| 브라우저     | Core Collaboration 패키지 재사용                                                                                                                 | Comment Client 및 UI 사용                        |
| Server       | [**@univerjs-pro/collaboration-comment-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-service)                     | 댓글 작업 및 `commentCommitted` 이벤트 관리      |
| Server       | [**@univerjs-pro/collaboration-comment-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-endpoint)                   | 댓글 프로토콜 및 Unit Rooms를 통한 업데이트 전파 |
| 데이터베이스 | [**@univerjs-pro/collaboration-comment-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-memory)     | 프로세스 내 댓글 저장                            |
| 데이터베이스 | [**@univerjs-pro/collaboration-comment-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-sqlite)     | SQLite 댓글 영구 저장                            |
| 데이터베이스 | [**@univerjs-pro/collaboration-comment-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-postgres) | 댓글과 답글을 PostgreSQL에 저장                  |

Comment Adapter는 댓글 데이터를 저장합니다. 콘텐츠와 이동하는 앵커는 Core 스냅샷과 변경 집합에 남습니다.

## Worktree

Worktree는 격리 초안, 상태 전환, Unit별 병합을 제공합니다.

| 실행 환경    | 패키지                                                                                                                                             | 그것은 무엇입니까?                |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 브라우저     | [**@univerjs-pro/collaboration-worktree-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-client)                       | Worktree 초안, 상태, 병합 연결    |
| Server       | [**@univerjs-pro/collaboration-worktree-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-service)                     | 초안 변경, 상태, 병합 관리        |
| Server       | [**@univerjs-pro/collaboration-worktree-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-endpoint)                   | Worktree Client 프로토콜 제공     |
| 데이터베이스 | [**@univerjs-pro/collaboration-worktree-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-memory)     | 프로세스 내 Worktree 저장         |
| 데이터베이스 | [**@univerjs-pro/collaboration-worktree-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-sqlite)     | SQLite Worktree 영구 저장         |
| 데이터베이스 | [**@univerjs-pro/collaboration-worktree-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-postgres) | Worktree 초안을 PostgreSQL에 저장 |

Worktree 서비스는 궁극적으로 핵심 서비스를 통해 트렁크로 합병하므로 Middleware는 두 서비스 경계에서 구성해야 합니다.

## File

파일 저장 Univer 클라이언트 업로드: 이미지 및 첨부 파일 단위로 삽입, 수입 또는 수출의 소스 및 결과 파일과 함께. 단위 데이터 레코드 만 파일 ID.

| 실행 환경 | 패키지 | 그것은 무엇입니까? |
| --- | --- | --- |
| 브라우저 | Core Collaboration Client 재사용 | 이미지와 첨부 파일을 업로드하고 파일 ID를 URL로 변환 |
| Server | [**@univerjs-pro/collaboration-file-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-service) | 소유 규칙, Middleware, 임시 파일 정리 수행 |
| Server | [**@univerjs-pro/collaboration-file-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-endpoint) | 업로드, sign-url, 다운로드 라우트 제공 |
| 데이터베이스 | [**@univerjs-pro/collaboration-file-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-memory) | 메타데이터와 콘텐츠의 인프로세스 저장소 |
| 데이터베이스 | [**@univerjs-pro/collaboration-file-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-sqlite) | 파일 메타데이터의 SQLite 영속성 |
| 데이터베이스 | [**@univerjs-pro/collaboration-file-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-postgres) | 파일 메타데이터의 PostgreSQL 영속성 |
| 스토리지 | [**@univerjs-pro/collaboration-file-blob-local**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-local) | 콘텐츠를 로컬 디렉터리에 저장 |
| 스토리지 | [**@univerjs-pro/collaboration-file-blob-s3**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-s3) | 콘텐츠를 S3 호환 객체 스토리지에 저장하고 서명된 직접 링크 발급 |

Metadata 및 content는 두 개의 독립적 인 계약이므로 이미 응용 프로그램이 제공하는 스토리지를 사용할 수 있습니다. Metadata는 객체 저장소에 콘텐츠가 남아있는 동안 데이터베이스에 의존 할 수 있습니다.

## Office Exchange

Office Exchange는 Office 파일을 협업 Unit으로 가져오고 Unit을 파일로 내보냅니다. 원본 파일과 결과 파일은 File이 저장합니다.

| 실행 환경 | 패키지 | 그것은 무엇입니까? |
| --- | --- | --- |
| 브라우저 | [**@univerjs-pro/exchange-client**](https://www.npmjs.com/package/@univerjs-pro/exchange-client) | 브라우저 기본 파일 교환 제공 |
| 브라우저 | [**@univerjs-pro/sheets-exchange-client**](https://www.npmjs.com/package/@univerjs-pro/sheets-exchange-client) | Sheet 파일 가져오기 및 내보내기 |
| Server | [**@univerjs-pro/collaboration-exchange-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-service) | 가져오기와 내보내기 task, Middleware, Unit 생성과 읽기 관리 |
| Server | [**@univerjs-pro/collaboration-exchange-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-endpoint) | 가져오기, 내보내기, task 라우트 제공 |
| Server | [**@univerjs-pro/exchange-node**](https://www.npmjs.com/package/@univerjs-pro/exchange-node) | Node.js에서 Office 파일과 Univer 데이터 변환 |

Exchange Service는 Core Service를 통해 Units를 만들고 읽고 파일 서비스를 통해 파일을 작성하고, Core 및 File과 함께 조립해야 합니다.

## 선택 원칙

1. [빠른 시작](/server/collaboration/quick-start)의 Core 패키지부터 시작하세요.
2. 애플리케이션의 저장소 요구 사항에 맞는 [Core Database Adapter](/server/collaboration/database-adapters)를 선택합니다.
3. 다중 노드로 배포할 때는 Redis 기반 pub/sub 어댑터와 Session Ticket 저장소를 추가하세요.
4. 제품 용도에 대한 확장 모듈 패키지 만 설치하십시오.
5. 제품이 이미지, 부착물 또는 수입 및 수출을 필요로 하는 경우에, 파일을 첫째로 조립하고 필요로 하는 경우에만 사무실 교환을 추가하십시오.
6. 여러 모듈이 하나의 데이터베이스를 공유 할 때 각 모듈에 대한 별도의 어댑터를 만듭니다.

모듈 간의 관계를 위해 [협업 확장 모듈](/server/collaboration/extensions)를 참조하고, 실행 가능한 어셈블리를 위한 [예제 인덱스](/server/collaboration/examples).
