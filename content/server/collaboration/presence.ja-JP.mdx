---
title: オンライン状態
description: ドキュメント内のメンバー、共同編集者の名前とアバター、リモートカーソルと選択範囲を表示します。
---

プレゼンスは、他の文書が開いているか、各人が働いているかを示しています。ボブがセルB3を選択した場合、例えば「Bob」という名前でラベル付けされた彼の選択を見ることができます。アプリケーションは、アバターバーまたはメンバーリストに現在の共同作業者を表示することもできます。

SDK は、メンバーシップとカーソル情報を統合し、エディタがサポートするリモートカーソルをレンダリングします。コラブレータ名とアバターはアプリケーションによって供給され、アバターバー、メンバーパネル、オンラインユーザー数のサブスクリプション API が利用できます。

## 始める前に

[クイックスタート](/server/collaboration/quick-start)と[アイデンティティと認可](/server/collaboration/identity-and-authorization)を最初に完了します。 その時点で、エディタは編集を同期させるべきである、サーバーは、`context.userID`を介して署名されたユーザーを識別し、読み、JOIN、および編集ポリシーが配置されている必要があります。

以下の例では、既存の`transport`、`endpoint`および`univer`の設定を拡張します。 以前のガイドから認証および承認規則を保持します。

## メンバーとカーソルの同期

アリスとボブは同じスプレッドシートを開きます。 プレゼンスは2種類のアップデートを生成します。

| 操作 | メンバー一覧 | Alice の表に見えるもの |
| --- | --- | --- |
| Alice が開く | Alice | 自分の選択範囲 |
| Bob が同じ表を開く | Alice、Bob | Bob がセルを選ぶとその選択範囲 |
| Bob が B3 から C5 に移動 | Alice、Bob | Bob の選択範囲が C5 に移動 |
| Bob が表を閉じる | 退出更新の受信後は Alice のみ | Bob の選択範囲が消える |

メンバーリストは、コネクションが結合または葉したときに変更されます。 カーソルの移動は、エディタで描画された選択のみを変更します。メンバーを追加または削除しません。 ボブがC5で値を編集する場合、コラボレーション編集フローを通してドキュメントコンテンツが同期されます。

プレゼンスは1つの文書、ユニットにスコープ付けされます。この文書に現在接続されている人々をカバーしますが、以前のガイドで設定されたアクセスリストは、誰でも開くことができます。プレゼンスは一時的です。カーソルの動きは変更を作成せず、ドキュメントのリビジョンを進歩させず、データベースに保存されません。

クイックスタートと対応するエディタ UI のコラボレーションプラグインにより、SDK はローカルカーソルと選択の更新をキャプチャし、それらを送信し、他のメンバーのエディタで対応するカーソル、選択、および名前をレンダリングします。

| エディター | オンラインメンバー購読 | リモートカーソル・選択 UI |
| --- | --- | --- |
| Sheet | 対応 | セルと範囲の選択 |
| Doc | 対応 | テキストカーソルと選択 |
| Slide | 対応 | ポインター位置とオブジェクト選択 |
| Board | 対応 | ポインター位置とオブジェクト選択 |
| Base | 対応 | 非対応 |

## 1. 共同編集者の名前とアバターを設定

エンドポイントの`connect`ミドルウェアに`context.member.name`と`context.member.avatar`を設定します。このアプリケーションは、プロファイルを取得する方法を決定します。認証された`context.session.userID`でクエリするか、`customData`での認証時に保存されたデータを再利用します。

この例では、`customData` を使用して、2番目のルックアップを回避します。 これらのフィールドを既存のトランスポートミドルウェアに追加し、サーバーを起動する前に `connect`を登録します。

```ts
type AppUser = {
  id: string;
  name: string;
  avatar?: string;
};

transport.use(async (context, next) => {
  // Your authentication function; rejects unauthenticated requests.
  const user: AppUser = await auth.requireUser(context.incomingMessage);
  context.userID = user.id;
  // An application-defined field to reuse the profile in connect.
  context.customData.user = user;
  await next();
});

endpoint.use("connect", async (context, next) => {
  // Read the profile saved when the session ticket was issued.
  const user = context.session.customData.user as AppUser;
  // Without this assignment, the member name defaults to userID.
  context.member.name = user.name;
  // Use an empty string when there is no avatar URL.
  context.member.avatar = user.avatar ?? "";
  await next();
});
```

SDK は、セッションチケットリクエストから `context.session.customData` に `customData` を渡します。マルチノードのデプロイでは、別のノードに接続された送信者は `userID` と `memberID` だけに到着します。そのため、各メッセージで旅行しなければならないデータは Presence ペイロードにあります。`user` キーと `AppUser` 型はアプリケーションの選択です。SDK はそれらを解釈しません。他の共同作業者は `context.member` に割り当てられたプロファイルを受け取ります。

`connect`は、クライアントがドキュメントに参加する前に、再接続を含む、新しいWebSocket接続ごとに1回実行されます。 プロファイルがアプリケーションで変更されると、既存の接続と既に共有されたメンバープロファイルは自動的に更新されません。

## 2. メンバー一覧の表示（任意）

アバターバーまたはメンバーパネルを作成するには、`subscribeCollaborators(unitID, callback)`で開かれた文書のメンバーを購読します。 カーソルのレンダリングはこのサブスクリプションに依存しません。

```ts
import { FUniver } from "@univerjs/core/facade";
// Import once in the client entry point to enable collaboration Facade methods.
import "@univerjs-pro/collaboration-client/facade";

// Reuse an existing univerAPI if your editor setup already provides one.
const univerAPI = FUniver.newAPI(univer);
// unitID is the ID of the document open in the editor.
const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, (members) => {
  // Each callback is a new list snapshot that the application can use to update its UI.
  console.table(members);
});
```

SDK は、ドキュメントのコラボレーションルームが利用可能になるのを待ちます。各コールバックは、クライアントに現在知られているメンバーの `IMember[]` スナップショットを受け取ります。クライアント自身が参加したら。初期化中に空のリストが到着できます。コールバックレポートのメンバーシップは、カーソルの位置ではありません。

Alice と Bob のメンバーデータは次のようになります（ID は例です）。

| `userID` | `memberID`                             | `name`  | `avatar` |
| -------- | -------------------------------------- | ------- | -------- |
| `alice`  | `83446a72-a1cc-4ed8-aedc-afd8907bbb18` | `Alice` | `""`     |
| `bob`    | `7ee5a94e-c784-4e1e-b1a3-b9d34be8ec4e` | `Bob`   | `""`     |

`userID` は、アプリケーション内の人を特定します。`memberID` は 1 つの接続を識別し、SDK によって割り当てられます。ボブが 2 番目のタブを開くと、リストは `userID: "bob"` と異なる `memberID` で別のエントリを獲得し、現在は 2 つのユーザーと 3 つの接続があります。アプリケーションは、アバター バーまたはオンライン ユーザー数の `userID` によってグループ化したり、`memberID` を使用して接続を表示およびカウントしたりできます。エディタは、各接続のカーソルを別々にレンダリングします。

利用するビューが削除されたときにサブスクリプションを解放します。

```ts
subscription.dispose();
```

エディタが破壊されると、アプリケーション作成の`univerAPI`とUniverインスタンスを消去します。 会員パネルのみクローズすると、そのパネルのサブスクリプションだけを解除する必要があります。

### 例：React のメンバー一覧

既存の `univerAPI` とドキュメント ID をこのコンポーネントに渡します。

```tsx
import type { FUniver } from "@univerjs/core/facade";
import type { IMember } from "@univerjs/protocol";
import "@univerjs-pro/collaboration-client/facade";
import { useEffect, useState } from "react";

export function OnlineMembers({ univerAPI, unitID }: { univerAPI: FUniver; unitID: string }) {
  const [members, setMembers] = useState<IMember[]>([]);

  useEffect(() => {
    // Clear the previous document list while waiting for the new subscription.
    setMembers([]);
    const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, setMembers);
    // Unsubscribe when the document changes or the component unmounts.
    return () => subscription.dispose();
  }, [univerAPI, unitID]);

  // Show each user once, even when they have multiple connections.
  const users = [...new Map(members.map((member) => [member.userID, member])).values()];

  return (
    <ul>
      {users.map((user) => (
        <li key={user.userID}>
          {user.avatar && <img src={user.avatar} alt="" width={24} height={24} />}
          <span>{user.name}</span>
        </li>
      ))}
    </ul>
  );
}
```

サブスクリプションは、クライアントが受け取った最新のルームメンバーシップを反映しています。 紛失した接続は、検出する時間がかかります。そのため、出発メンバーはリストに簡単に残ります。 SDK の組み込みコラボレーションステータス UI は、現在のクライアントの同期状態、オフライン表示、再接続アクションを提供します。

## 2 人で確認する

1. 別々のブラウザープロフィールで Alice と Bob としてログインし、同じドキュメントを開きます。
2. 一覧に両方の名前が表示されることを確認します。
3. シートでは、B3をボブとして選択し、C5を選択します。 会員リストが変更されていないまま、アリスはボブの名前の「選択」を選択している必要があります。
4. 別のタブをボブとして開きます。サブスクリプションには、別の`memberID`が含まれている必要があります。 Reactリストは引き続きボブを表示する必要があります。
5. Bob の両タブを閉じます。退出更新の受信後、Alice の一覧は Alice のみになります。
