---
title: Présence en ligne
description: Affichez les personnes dans un document, leurs noms et avatars, ainsi que les curseurs et sélections distants.
---

La présence montre qui d'autre a le même document ouvert et où chaque personne travaille. Lorsque Bob sélectionne la cellule B3, par exemple, Alice voit sa sélection étiquetée avec le nom « Bob ». Les applications peuvent également afficher les collaborateurs actuels dans une barre d'avatar ou une liste de membres.

Le SDK synchronise les informations d'adhésion et de curseur et rend les curseurs distants où l'éditeur les supporte. Les noms de collaborateurs et les avatars sont fournis par l'application, et l'API d'abonnement des membres est disponible pour les barres d'avatar, les panneaux de membres et les comptes d'utilisateurs en ligne.

## Avant de commencer

Terminez d'abord [Démarrage rapide](/server/collaboration/quick-start) et [Identité et autorisation](/server/collaboration/identity-and-authorization). À ce moment-là, l'éditeur devrait synchroniser les modifications, le serveur devrait identifier l'utilisateur connecté via `context.userID`, et les politiques de lecture, JOIN et de modification devraient être en place.

Les exemples ci-dessous prolongent la configuration existante de `transport`, `endpoint` et `univer`. Conserver les règles d'authentification et d'autorisation du guide précédent.

## Synchronisation des membres et curseurs

Alice et Bob ouvrent le même tableur. La présence produit deux types de mises à jour:

| Action | Liste des membres | Ce qu’Alice voit dans la feuille |
| --- | --- | --- |
| Alice ouvre la feuille | Alice | Sa propre sélection |
| Bob ouvre la même feuille | Alice, Bob | La sélection de Bob lorsqu’il choisit une cellule |
| Bob passe de B3 à C5 | Alice, Bob | Sa sélection se déplace vers C5 |
| Bob ferme la feuille | Alice, après réception du départ | La sélection de Bob disparaît |

La liste des membres change quand une connexion se joint ou quitte. Déplacer un curseur ne change que la sélection dessinée dans l'éditeur; il n'ajoute pas ou ne supprime pas un membre. Si Bob modifie également la valeur en C5, le contenu du document est synchronisé par le flux d'édition de collaboration.

La présence est étendue à un document, une unité. Elle couvre les personnes actuellement connectées à ce document, tandis que la liste d'accès configurée dans le guide précédent couvre tout le monde autorisé à l'ouvrir. La présence est temporaire : le mouvement du curseur ne crée pas de changement, n'avance pas la révision du document et n'est pas sauvegardée dans la base de données.

Avec les plugins de collaboration Quick start et l'interface utilisateur de l'éditeur correspondant activé, le SDK capture les mises à jour locales du curseur et de la sélection, les envoie et rend les curseurs, les sélections et les noms correspondants dans les éditeurs d'autres membres.

| Éditeur | Abonnement aux membres | UI distante de curseur et sélection |
| --- | --- | --- |
| Sheet | Pris en charge | Sélections de cellules et plages |
| Doc | Pris en charge | Curseurs et sélections de texte |
| Slide | Pris en charge | Positions du pointeur et sélections d’objets |
| Board | Pris en charge | Positions du pointeur et sélections d’objets |
| Base | Pris en charge | Non disponible |

## 1. Définir noms et avatars

Définissez `context.member.name` et `context.member.avatar` dans le Middleware `connect` d'Endpoint. L'application décide comment récupérer le profil : interrogez-le avec le `context.session.userID` authentifié, ou réutilisez les données enregistrées lors de l'authentification dans `customData`.

Cet exemple utilise `customData` pour éviter une seconde recherche. Ajoutez ces champs au Middleware Transport existant et enregistrez `connect` avant de démarrer le serveur:

```ts
type AppUser = {
  id: string;
  name: string;
  avatar?: string;
};

transport.use(async (context, next) => {
  // Your authentication function; rejects unauthenticated requests.
  const user: AppUser = await auth.requireUser(context.incomingMessage);
  context.userID = user.id;
  // An application-defined field to reuse the profile in connect.
  context.customData.user = user;
  await next();
});

endpoint.use("connect", async (context, next) => {
  // Read the profile saved when the session ticket was issued.
  const user = context.session.customData.user as AppUser;
  // Without this assignment, the member name defaults to userID.
  context.member.name = user.name;
  // Use an empty string when there is no avatar URL.
  context.member.avatar = user.avatar ?? "";
  await next();
});
```

Le SDK passe la `customData` de la demande de billet de session `context.session.customData`. Dans un déploiement multi-nœuds, un expéditeur connecté à un autre noeud arrive avec seulement `userID` et `memberID`, donc les données qui doivent voyager avec chaque message appartient à la charge utile Présence. `user` clé et le `AppUser` type sont des choix d'application; le SDK ne les interprète pas. `context.member`.

`connect` fonctionne une fois pour chaque nouvelle connexion WebSocket, y compris les reconnections, et toujours avant que le client ne rejoigne un document. Lorsqu'un profil change dans l'application, les profils de membres déjà partagés avec les connexions existantes ne sont pas mis à jour automatiquement.

## 2. Afficher une liste de membres (facultatif)

Pour construire une barre d'avatar ou un panneau de membres, abonnez-vous aux membres du document ouvert avec `subscribeCollaborators(unitID, callback)`. Le rendu du curseur ne dépend pas de cet abonnement.

```ts
import { FUniver } from "@univerjs/core/facade";
// Import once in the client entry point to enable collaboration Facade methods.
import "@univerjs-pro/collaboration-client/facade";

// Reuse an existing univerAPI if your editor setup already provides one.
const univerAPI = FUniver.newAPI(univer);
// unitID is the ID of the document open in the editor.
const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, (members) => {
  // Each callback is a new list snapshot that the application can use to update its UI.
  console.table(members);
});
```

Le SDK attend que la salle de collaboration du document devienne disponible. Chaque callback reçoit un instantané `IMember[]` des membres actuellement connus du client, y compris le client lui-même une fois qu'il a rejoint. Une liste vide peut arriver lors de l'initialisation.

Les données d’Alice et Bob comportent ces champs (ID illustratifs) :

| `userID` | `memberID`                             | `name`  | `avatar` |
| -------- | -------------------------------------- | ------- | -------- |
| `alice`  | `83446a72-a1cc-4ed8-aedc-afd8907bbb18` | `Alice` | `""`     |
| `bob`    | `7ee5a94e-c784-4e1e-b1a3-b9d34be8ec4e` | `Bob`   | `""`     |

`userID` identifie une personne dans l'application. `memberID` désigne une connexion et est assignée par le SDK. Si Bob ouvre un deuxième onglet, la liste gagne une autre entrée avec `userID: "bob"` et un `memberID` différent, il y a donc maintenant deux utilisateurs et trois connexions. Les applications peuvent regrouper par `userID` pour une barre d'avatar ou un nombre d'utilisateurs en ligne, ou utiliser `memberID` afin d'afficher et de compter les connexions. L'éditeur rend séparément le curseur de chaque connexion.

Relâchez l'abonnement lorsque la vue qui l'utilise est supprimée :

```ts
subscription.dispose();
```

Disposer d'un `univerAPI` créé par application et de l'instance Univer lorsque l'éditeur est détruit.

### Exemple : liste de membres React

Passez le `univerAPI` existant et l'ID du document dans ce composant:

```tsx
import type { FUniver } from "@univerjs/core/facade";
import type { IMember } from "@univerjs/protocol";
import "@univerjs-pro/collaboration-client/facade";
import { useEffect, useState } from "react";

export function OnlineMembers({ univerAPI, unitID }: { univerAPI: FUniver; unitID: string }) {
  const [members, setMembers] = useState<IMember[]>([]);

  useEffect(() => {
    // Clear the previous document list while waiting for the new subscription.
    setMembers([]);
    const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, setMembers);
    // Unsubscribe when the document changes or the component unmounts.
    return () => subscription.dispose();
  }, [univerAPI, unitID]);

  // Show each user once, even when they have multiple connections.
  const users = [...new Map(members.map((member) => [member.userID, member])).values()];

  return (
    <ul>
      {users.map((user) => (
        <li key={user.userID}>
          {user.avatar && <img src={user.avatar} alt="" width={24} height={24} />}
          <span>{user.name}</span>
        </li>
      ))}
    </ul>
  );
}
```

L'abonnement reflète le dernier abonnement à la salle reçu par le client. Une connexion perdue prend du temps à détecter, de sorte qu'un membre sortant peut rester dans la liste brièvement. L'interface d'état de collaboration intégrée de SDK fournit l'état de synchronisation du client actuel, une indication hors ligne et une action de reconnect.

## Essai avec deux utilisateurs

1. Connectez Alice et Bob dans des profils de navigateur distincts et ouvrez le même document.
2. Vérifiez que les deux noms figurent dans la liste.
3. Dans une feuille, sélectionnez B3 comme Bob, puis C5. Alice devrait voir le mouvement de sélection nommé Bob pendant que la liste des membres reste inchangée.
4. Ouvrez un autre onglet en tant que Bob. L'abonnement devrait inclure un autre `memberID`, et la liste React devrait toujours afficher Bob une fois.
5. Fermez les deux onglets de Bob. Après les mises à jour de départ, la liste d’Alice ne doit contenir qu’Alice.
