На этой странице объясняется, как выбрать пакеты из Collaboration SDK. Начните с Core Collaboration, затем добавьте модули расширения, которые требуются продукту. Установка каждого пакета не требуется.

Пакеты серверов для адаптеров баз данных, файлов и Office Exchange имеют открытый исходный код под Apache-2.0, а их исходный код опубликован в [сообщество единомышленников-совместителей](https://github.com/dream-num/univer-collaboration-sdk-community). Эти пакеты используют тот же префикс пакета и версию, что и любой другой пакет, и они установлены таким же образом.

## Core Collaboration

Core Collaboration обеспечивает основной путь: совместная работа браузера, обработка протокола сервера, OT, пересмотры и настойчивость.

| Среда       | Пакет                                                                                                                                  | Что он делает                                                                              |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Браузер     | [**@univerjs-pro/collaboration**](https://www.npmjs.com/package/@univerjs-pro/collaboration)                                           | Регистрирует базовые браузерные возможности                                                |
| Браузер     | [**@univerjs-pro/collaboration-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client)                             | Загрузка Units, отправка изменений и синхронизация                                         |
| Браузер     | [**@univerjs-pro/collaboration-client-ui**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client-ui)                       | Предоставляет UI состояния и стили                                                         |
| Server      | [**@univerjs-pro/collaboration-transport-node**](https://www.npmjs.com/package/@univerjs-pro/collaboration-transport-node)             | Принимает HTTP и WebSocket Node.js                                                         |
| Server      | [**@univerjs-pro/collaboration-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-endpoint)                         | Реализует протокол Client, Sessions, Rooms и Presence                                      |
| Server      | [**@univerjs-pro/collaboration-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-service)                           | Управляет Units, OT, ревизиями и API ядра                                                  |
| База данных | [**@univerjs-pro/collaboration-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-memory)           | Хранение в процессе для тестов, примеров и временной разработки                            |
| База данных | [**@univerjs-pro/collaboration-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-sqlite)           | SQLite для разработки, тестов, локальных и небольших установок                             |
| База данных | [**@univerjs-pro/collaboration-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-postgres)       | Хранение в PostgreSQL, общее для нескольких узлов                                          |
| База данных | [**@univerjs-pro/collaboration-database-postgres-s3**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-postgres-s3) | Хранит блоки ячеек в S3, уменьшая размер базы PostgreSQL и её резервных копий              |
| Multi-node  | [**@univerjs-pro/collaboration-cluster-redis**](https://www.npmjs.com/package/@univerjs-pro/collaboration-cluster-redis)               | Pub/sub-адаптер и хранилище session tickets на Redis для развёртывания на нескольких узлах |

Для сервера Core нужны Transport, Endpoint, Service и один адаптер базы данных. Memory, SQLite, PostgreSQL и PostgreSQL + S3 реализуют один контракт, и приложение обычно выбирает один из них. Для работы нескольких узлов также нужны адаптер pub/sub и общее хранилище билетов сессий. Endpoint определяет оба контракта (`IPubSubAdapter` и `ISessionTicketStore`), а SDK предоставляет реализацию на Redis.

## History

История строит индекс истории версии от создания Единицы и изменяет фиксацию событий, которые излучает Ядро.

| Среда       | Пакет                                                                                                                                            | Что он делает                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| Браузер     | Повторно использует Core Client/UI                                                                                                               | Показывает и читает историю                |
| Server      | [**@univerjs-pro/collaboration-history-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-service)                     | Строит и запрашивает индекс истории        |
| Server      | [**@univerjs-pro/collaboration-history-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-endpoint)                   | Предоставляет Client протокол History      |
| База данных | [**@univerjs-pro/collaboration-history-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-memory)     | Хранение индекса History в памяти процесса |
| База данных | [**@univerjs-pro/collaboration-history-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-sqlite)     | Хранит производный индекс History          |
| База данных | [**@univerjs-pro/collaboration-history-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-postgres) | Хранит индекс истории в PostgreSQL         |

Исторические данные являются производным индексом и всегда могут быть восстановлены. Основные изменения остаются авторитетными для контента Unit.

## Thread Comment

Thread Comment управляет текстом комментариев, ответами и статусом обсуждения.

| Среда       | Пакет                                                                                                                                            | Что он делает                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| Браузер     | Использует пакеты Core Collaboration                                                                                                             | Использует Comment Client и UI                                 |
| Server      | [**@univerjs-pro/collaboration-comment-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-service)                     | Управляет комментариями и событием `commentCommitted`          |
| Server      | [**@univerjs-pro/collaboration-comment-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-endpoint)                   | Предоставляет протокол и публикует обновления через Unit Rooms |
| База данных | [**@univerjs-pro/collaboration-comment-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-memory)     | Хранение комментариев в процессе                               |
| База данных | [**@univerjs-pro/collaboration-comment-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-sqlite)     | Хранение комментариев в SQLite                                 |
| База данных | [**@univerjs-pro/collaboration-comment-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-postgres) | Хранит комментарии и ответы в PostgreSQL                       |

Comment Adapter хранит комментарии. Движущиеся с содержимым якоря остаются в снимках и изменениях Core.

## Worktree

Worktree предоставляет изолированные черновики, переходы статуса и слияние по Unit.

| Среда       | Пакет                                                                                                                                              | Что он делает                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Браузер     | [**@univerjs-pro/collaboration-worktree-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-client)                       | Подключает черновики, статус и слияние Worktree       |
| Server      | [**@univerjs-pro/collaboration-worktree-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-service)                     | Управляет изменениями черновиков, статусом и слиянием |
| Server      | [**@univerjs-pro/collaboration-worktree-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-endpoint)                   | Предоставляет протокол Worktree Client                |
| База данных | [**@univerjs-pro/collaboration-worktree-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-memory)     | Хранение Worktree в процессе                          |
| База данных | [**@univerjs-pro/collaboration-worktree-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-sqlite)     | Хранение Worktree в SQLite                            |
| База данных | [**@univerjs-pro/collaboration-worktree-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-postgres) | Сохраняет черновики Worktree в PostgreSQL             |

Сервис Worktree в конечном итоге сливается в багажник через Core Service, поэтому промежуточное ПО должно быть настроено на обоих границах Сервиса.

## File

Файл хранит двоичные файлы, которые загружают клиенты Univer: изображения и вложения, вставленные в блок, вместе с файлами источника и результата импорта или экспорта.

| Среда | Пакет | Что он делает |
| --- | --- | --- |
| Браузер | Повторно использует Core Collaboration Client | Загружает изображения и вложения и преобразует ID файлов в URL |
| Server | [**@univerjs-pro/collaboration-file-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-service) | Применяет правила владения, Middleware и очистку временных файлов |
| Server | [**@univerjs-pro/collaboration-file-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-endpoint) | Предоставляет маршруты загрузки, sign-url и скачивания |
| База данных | [**@univerjs-pro/collaboration-file-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-memory) | Хранение метаданных и содержимого в памяти процесса |
| База данных | [**@univerjs-pro/collaboration-file-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-sqlite) | Хранение метаданных файлов в SQLite |
| База данных | [**@univerjs-pro/collaboration-file-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-postgres) | Хранение метаданных файлов в PostgreSQL |
| Хранилище | [**@univerjs-pro/collaboration-file-blob-local**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-local) | Хранит содержимое в локальном каталоге |
| Хранилище | [**@univerjs-pro/collaboration-file-blob-s3**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-s3) | Хранит содержимое в S3-совместимом объектном хранилище с подписанными прямыми ссылками |

Метаданные и контент - это два независимых контракта, поэтому каждый может использовать хранилище, которое уже предоставляет приложение. Метаданные могут находиться в базе данных, а контент находится в объектном хранилище.

## Office Exchange

Office Exchange импортирует файлы Office как совместные Units и экспортирует Units в файлы. Исходные и результирующие файлы хранит File.

| Среда | Пакет | Что он делает |
| --- | --- | --- |
| Браузер | [**@univerjs-pro/exchange-client**](https://www.npmjs.com/package/@univerjs-pro/exchange-client) | Базовые браузерные возможности обмена файлами |
| Браузер | [**@univerjs-pro/sheets-exchange-client**](https://www.npmjs.com/package/@univerjs-pro/sheets-exchange-client) | Импорт и экспорт Sheet |
| Server | [**@univerjs-pro/collaboration-exchange-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-service) | Управляет task импорта и экспорта, Middleware, созданием и чтением Units |
| Server | [**@univerjs-pro/collaboration-exchange-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-endpoint) | Предоставляет маршруты импорта, экспорта и task |
| Server | [**@univerjs-pro/exchange-node**](https://www.npmjs.com/package/@univerjs-pro/exchange-node) | Преобразование Office и данных Univer в Node.js |

Exchange Service создает и считывает Единицы через Core Service, а также считывает и записывает файлы через File Service, поэтому он должен быть собран вместе с Core и File.

## Правила выбора

1. Начните с пакетов Core из [Быстрого старта](/server/collaboration/quick-start).
2. Выберите [адаптер базы данных Core](/server/collaboration/database-adapters) с учётом требований приложения к хранению данных.
3. Для развёртывания на нескольких узлах добавьте pub/sub-адаптер и хранилище session tickets на Redis.
4. Установите только пакеты модулей расширения, которые использует продукт.
5. Если продукт требует изображений, вложений или импорта и экспорта, сначала соберите файл и добавьте Office Exchange только тогда, когда это необходимо.
6. Создайте отдельный адаптер для каждого модуля, даже если несколько модулей имеют общую базу данных.

См. [Модули расширения совместной работы](/server/collaboration/extensions) для взаимосвязей между модулями и [Примеры индексов](/server/collaboration/examples) - для управляемых сборок.
