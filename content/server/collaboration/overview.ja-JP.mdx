**Univer Collaboration SDK**はUniver文書モデルのサーバー側SDKです。それは操作上の変換(OT[^operational-transformation])、リビジョン[^collaboration-revision]、スナップショット、実時間同期、および永続性を扱います、従って多数のUniver顧客は同じauthoritative単位を編集できます。

アプリケーションは、Node.js サービスの SDK を埋め込んでいます。 アイデンティティと認可は、ミドルウェアを介して接続し、ログやその他のアプリケーションロジックをミドルウェアやイベントに添付します。 別のデータベースアダプタは、コラボレーションデータをアプリケーションデータベースに接続します。

<Callout title="完全な文書製品ではありません">
  SDKはコラボレーションコアのみを提供します。ユーザー、ロール、階層、共有、ファイルスペース、ビジネスワークフローはスコープ外にあり、アプリケーションはこれらの製品の機能とデータモデルを保有しています。
</Callout>

## 解決する課題

Web SDKは、ブラウザのシート、Doc、スライド、ボード、ベース、およびPDFコンテンツを表示および編集します。 リアルタイムのマルチユーザー編集は、Web SDKの上部にあるサーバー側の権限を必要とします。 その権限は、コンテンツを読み、同時変更を確認し、リビジョンを進め、接続されていないクライアントが一貫した状態に回復させます。

次のようなアプリケーションに適しています。

- 既にUniverを使用してエディタを構築し、リアルタイムのマルチユーザー編集を望む;
- コラボレーションデータを自身でホストし、独自のデータベースを選択したい。
- 既存の本人確認、認可、テナントルールを共同編集操作に接続したい；
- 基本的な共同編集に History、Thread Comment、Worktree、ファイルストレージ、Office のインポートとエクスポートを追加したい。

## SDK が提供する機能

中核機能は次のとおりです。

- シート、ドキュメント、スライド、ボード、ベース、PDF用のユニットの作成、読み込み、削除、および復元。
- スナップショット、変更セット、リビジョン、OT、送信の冪等性；
- HTTP コンテンツの読み込み、WebSocket セッション、ルーム、プレゼンス、ACKs、および放送とともに。
- Transport、Endpoint、Service 境界の Middleware；
- Unit 作成、変更セットのコミット、削除、復元に対応するプロセス内 Events；
- 組み込みまたは独自の Database Adapter による共同編集データの保存。
- マルチノード展開による水平スケーリング: ノードはパブ/サブアダプターと共有セッションチケットストアを通じて連携し、SDKはRedis実装を提供します。

コアパスが配置されると、アプリケーションはバージョン履歴、スレッドコメント、Worktreeドラフト、ファイルストレージ、サーバー側のOfficeインポートとエクスポートを追加することができます。 これらの各機能は、独自のサービス、ミドルウェア、イベント、またはデータベースアダプタを持っています。

## アプリケーションが担う機能

| Collaboration SDK | アプリケーション |
| --- | --- |
| Unit の共同編集状態 | ユーザー、テナント、階層、共有関係 |
| OT、リビジョン、スナップショット | ログイン、Session、ID の対応付け |
| 共同編集の Session、Room、Presence | ロール、ACL、製品ポリシー |
| 共同編集とファイルの Database Adapter | 製品データベースとストレージの運用 |
| Middleware と Event の拡張ポイント | ログ、監査、メトリクス、外部連携 |
| クライアントプロトコルの Endpoint | 業務 API とドキュメント作成などのフロー |

## 3 つの汎用拡張ポイント

| 拡張ポイント | 解決する課題 |
| --- | --- |
| Middleware | コンテキストを調べたり、コンテクストを豊かにしたり、リクエストを拒絶したり、操作中に何が起きたかを記録したりします。 |
| Event | 処理された状態を更新するか、または非重大なフォローアップ作業を開始する状態の変更を確認した状態を観察します |
| Database Adapter | データが、大気、CAS、および潜在的契約を生き、実施する場所を選択 |

アイデンティティと認可は、ミドルウェアを介して接続します。ミドルウェアは、実行前に動作を検証し、イベントレコードの変更や、フォローアップ作業をトリガーします。ログ、リクエストのトレース、メトリック、および派生状態の更新を運ぶことができます。 [ミドルウェアとイベント](/server/collaboration/middleware-and-events)は、各々が実行する場所を説明しています。

## 次のステップ

1. [クイックスタート](/server/collaboration/quick-start)を実行し、2つのブラウザでフルパスを確認します。
2. [モジュールの境界と関係](/server/collaboration/modules)で各パッケージの役割を理解します。
3. [ミドルウェアとイベント](/server/collaboration/middleware-and-events)、[アイデンティティと認可](/server/collaboration/identity-and-authorization)または[データベースのアダプター](/server/collaboration/database-adapters)を選択して、統合タスクを手元で選択します。
4. 歴史、コメント、Worktrees、ファイルストレージ、インポート、エクスポートの[コラボレーション拡張モジュール](/server/collaboration/extensions)に移動します。

[^operational-transformation]: *操作変換（OT）*は、異なる文書リビジョンに対して同時に生成された操作を調整し、一貫して適用できるようにします。最後に届いたスナップショットで文書全体を置き換える方式ではありません。

[^collaboration-revision]: リビジョンは Unit の確定済み編集履歴における位置です。changeset は送信する操作の集合で、その確定により履歴が進みます。SDK パッケージのバージョンやタイムスタンプではありません。
