**Univer Collaboration SDK** 是 Univer 文件模型的伺服器端協同 SDK。它處理 OT[^operational-transformation]、revision[^collaboration-revision]、snapshot、即時同步與持久化，使多個 Univer 客戶端能夠同時編輯同一個權威 Unit。

應用將 SDK 嵌入自己的 Node.js 服務，透過 Middleware 接入身分與權限，並將日誌與其他業務邏輯掛接到 Middleware 或 Event。協同資料由獨立的 Database Adapter 連線到應用的資料庫。

<Callout title="它不是完整的文件產品">
  SDK 只提供協同核心，不包含使用者、角色、目錄、分享、檔案空間或業務工作流。這些產品能力及其資料模型仍由應用負責。
</Callout>

## 解決的問題

Web SDK 負責在瀏覽器中顯示和編輯 Sheet、Doc、Slide、Board、Base 與 PDF 內容。多人即時編輯還需要一個伺服器端權威：它載入內容、確認並行修改、推進 revision，並使斷線的客戶端恢復到一致狀態。

它適用於以下應用：

- 已經使用 Univer 建置編輯器，並希望支援多人即時編輯；
- 希望自行託管協同資料，並自行選擇資料庫；
- 需要將現有的身分、權限或租戶規則接入協同操作；
- 需要在核心協同之上增加 History、Thread Comment、Worktree、檔案儲存或 Office 匯入匯出能力。

| 模組 | 主要職責 |
| --- | --- |
| Collaboration Client | 載入 Unit、提交 changeset，並維護瀏覽器端的協同狀態 |
| Node Transport | 接收 HTTP/WebSocket 流量，執行應用註冊的入口 Middleware |
| `UniverCollabEndpoint` | 實作用戶端協定、Session、Room、Presence、ACK 與廣播 |
| `UniverCollabService` | 管理 Unit 生命週期，執行 OT，確認連續 revision |
| Database Adapter | 以原子方式儲存快照、變更集、修訂版本及提交冪等狀態 |

## SDK 提供的能力

核心能力包括：

- 為 Sheet、Doc、Slide、Board、Base 與 PDF 建立、載入、刪除和恢復 Unit；
- 快照、變更集、修訂版本、OT 與提交冪等性；
- HTTP 內容載入，以及 WebSocket 的 Session、Room、Presence、ACK 與廣播；
- Transport、Endpoint 與 Service 三個邊界上的 Middleware；
- Unit 建立、changeset 提交、刪除與恢復等程序內 Event；
- Memory、SQLite 與 PostgreSQL 實現，以及自定義 Database Adapter 的合同；
- 透過多節點部署實現水平擴充套件：節點之間透過 pub/sub 介面卡與共享的 Session Ticket 儲存協作，SDK 提供 Redis 實現。

核心鏈路可用後，應用還可以增加版本歷史、Thread Comment、Worktree 草稿、檔案儲存與伺服器端 Office 匯入匯出。這些能力各自擁有 Service、Middleware、Event 或 Database Adapter。

## 應用負責的能力

| Collaboration SDK | 應用 |
| --- | --- |
| Unit 協同狀態 | 使用者、租戶、層級與分享關係 |
| OT、修訂版本與快照 | 登入、Session 與身分對應 |
| 協同 Session、Room 與 Presence | 角色、ACL 與產品策略 |
| 協同與檔案的 Database Adapter | 產品資料庫與儲存的維運 |
| Middleware 與 Event 擴充點 | 日誌、稽核、指標與外部整合 |
| 用戶端協定 Endpoint | 業務 API 與建立文件等流程 |

## 三種通用擴充點

| 擴充點 | 解決的問題 |
| --- | --- |
| Middleware | 操作執行期間檢查或補充 Context、拒絕請求，或者記錄處理過程 |
| Event | 觀察已經確認的狀態變化，更新程序內派生狀態或安排非關鍵的後續處理 |
| Database Adapter | 決定協同資料的儲存位置，並實現原子性、CAS 和冪等合同 |

身分與權限透過 Middleware 接入。Middleware 在操作執行前校驗並限制操作，Event 在狀態確認後記錄變更或觸發後續處理。日誌、請求追蹤、指標與派生資料更新可以由兩者承擔。各自的執行邊界見 [Middleware 與 Event](/server/collaboration/middleware-and-events)。

## 從哪裡開始

1. 完成[快速開始](/server/collaboration/quick-start)，並用兩個瀏覽器驗證完整鏈路。
2. 閱讀[模組邊界與協作關係](/server/collaboration/modules)，瞭解每個 package 的存在原因。
3. 根據接入任務選擇 [Middleware 與 Event](/server/collaboration/middleware-and-events)、[身分與權限](/server/collaboration/identity-and-authorization)或 [Database Adapter](/server/collaboration/database-adapters)。
4. 如需 History、Comment、Worktree、檔案儲存或匯入匯出，請閱讀[協同擴充套件模組](/server/collaboration/extensions)。

[^operational-transformation]: *操作轉換（OT）* 會調整基於不同文件修訂號並行產生的操作，使它們能一致地套用。它處理的是編輯操作，而非用最後抵達的快照覆蓋整份文件。

[^collaboration-revision]: 修訂號（revision）標示 Unit 已確認編輯歷史中的位置。變更集（changeset）包含一次提交的操作，確認後會推進歷史。修訂號不是 SDK 套件版本，也不是時間戳記。
