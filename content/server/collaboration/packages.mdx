This page is a package selection map for the Collaboration SDK. Assemble Core Collaboration first,
then add extension modules required by the product. You do not need to install every package.

The server packages for Database Adapters, File, and Office Exchange are open source under Apache-2.0;
the source lives in [univer-collaboration-sdk-community](https://github.com/dream-num/univer-collaboration-sdk-community).
They share the package prefix and version of every other package and install the same way.

## Core Collaboration

Core Collaboration provides the main path for browser collaboration, server protocol handling, OT,
revisions, and persistence.

| Runtime    | Package                                                                                                                          | Primary responsibility                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Browser    | [**@univerjs-pro/collaboration**](https://www.npmjs.com/package/@univerjs-pro/collaboration)                                     | Registers foundational browser collaboration capabilities                |
| Browser    | [**@univerjs-pro/collaboration-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client)                       | Loads Units, submits changesets, and maintains realtime synchronization  |
| Browser    | [**@univerjs-pro/collaboration-client-ui**](https://www.npmjs.com/package/@univerjs-pro/collaboration-client-ui)                 | Provides collaboration status UI and styles                              |
| Server     | [**@univerjs-pro/collaboration-transport-node**](https://www.npmjs.com/package/@univerjs-pro/collaboration-transport-node)       | Receives Node.js HTTP and WebSocket traffic                              |
| Server     | [**@univerjs-pro/collaboration-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-endpoint)                   | Implements the Client protocol, Sessions, Rooms, and Presence            |
| Server     | [**@univerjs-pro/collaboration-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-service)                     | Manages Units, OT, revisions, and core Service APIs                      |
| Database   | [**@univerjs-pro/collaboration-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-memory)     | In-process storage for tests, examples, and temporary development        |
| Database   | [**@univerjs-pro/collaboration-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-sqlite)     | SQLite persistence for development, testing, local, and small-scale use  |
| Database   | [**@univerjs-pro/collaboration-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-database-postgres) | PostgreSQL persistence shared by several nodes                           |
| Multi-node | [**@univerjs-pro/collaboration-cluster-redis**](https://www.npmjs.com/package/@univerjs-pro/collaboration-cluster-redis)         | Redis pub/sub adapter and session ticket store for multi-node deployment |

A Core Server needs Transport, Endpoint, Service, and one Database Adapter. Memory, SQLite, and
PostgreSQL implement the same Adapter contract; applications normally select one. A multi-node deployment also
needs a pub/sub adapter and a shared session ticket store. The Endpoint defines both contracts
(`IPubSubAdapter`, `ISessionTicketStore`); the SDK provides a Redis implementation.

## History

History builds a version-history index from Core Unit creation and changeset commit Events.

| Runtime  | Package                                                                                                                                      | Primary responsibility                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Browser  | Reuses Core Client/UI                                                                                                                        | Displays and reads history entries                   |
| Server   | [**@univerjs-pro/collaboration-history-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-service)                 | Builds and queries the history index                 |
| Server   | [**@univerjs-pro/collaboration-history-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-endpoint)               | Provides History protocol capabilities to the Client |
| Database | [**@univerjs-pro/collaboration-history-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-memory) | In-process storage for the History index             |
| Database | [**@univerjs-pro/collaboration-history-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-history-database-sqlite) | SQLite persistence for the History index             |

History data is a rebuildable derived index. Core changesets remain authoritative for Unit content.

## Thread Comment

Thread Comment manages comment bodies, replies, and solved state for Sheets and Docs.

| Runtime  | Package                                                                                                                                      | Primary responsibility                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Browser  | Reuses Core Collaboration packages                                                                                                           | Uses Comment Client and UI capabilities                                |
| Server   | [**@univerjs-pro/collaboration-comment-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-service)                 | Manages comment operations and the `commentCommitted` Event            |
| Server   | [**@univerjs-pro/collaboration-comment-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-endpoint)               | Provides the comment protocol and publishes updates through Unit Rooms |
| Database | [**@univerjs-pro/collaboration-comment-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-memory) | In-process comment storage                                             |
| Database | [**@univerjs-pro/collaboration-comment-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-comment-database-sqlite) | SQLite comment persistence                                             |

The Comment Adapter stores comment data. Anchors that move with content remain part of Core
snapshots and changesets.

## Worktree

Worktree provides isolated drafts, status transitions, and per-Unit merge.

| Runtime  | Package                                                                                                                                        | Primary responsibility                                  |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Browser  | [**@univerjs-pro/collaboration-worktree-client**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-client)                   | Connects Worktree draft, status, and merge capabilities |
| Server   | [**@univerjs-pro/collaboration-worktree-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-service)                 | Manages draft changesets, status, and merge             |
| Server   | [**@univerjs-pro/collaboration-worktree-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-endpoint)               | Provides protocol capabilities to Worktree Client       |
| Database | [**@univerjs-pro/collaboration-worktree-database-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-memory) | In-process Worktree storage                             |
| Database | [**@univerjs-pro/collaboration-worktree-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-worktree-database-sqlite) | SQLite Worktree persistence                             |

Worktree Service eventually merges into the trunk through Core Service, so Middleware must be
configured for both Service boundaries.

## File

File stores the binary files that Univer clients upload: images and attachments inserted into a Unit,
plus the source and result files of import and export. Unit data records only the file ID.

| Runtime  | Package                                                                                                                                    | Primary responsibility                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Browser  | Reuses the Core Collaboration Client                                                                                                       | Uploads images and attachments and resolves file IDs to URLs                  |
| Server   | [**@univerjs-pro/collaboration-file-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-service)                     | Applies ownership rules, Middleware, and temporary-file cleanup               |
| Server   | [**@univerjs-pro/collaboration-file-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-endpoint)                   | Provides the upload, sign-url, and download routes                            |
| Database | [**@univerjs-pro/collaboration-file-memory**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-memory)                       | In-process storage for metadata and content                                   |
| Database | [**@univerjs-pro/collaboration-file-database-sqlite**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-sqlite)     | SQLite persistence for file metadata                                          |
| Database | [**@univerjs-pro/collaboration-file-database-postgres**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-database-postgres) | PostgreSQL persistence for file metadata                                      |
| Storage  | [**@univerjs-pro/collaboration-file-blob-local**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-local)               | Stores file content in a local directory                                      |
| Storage  | [**@univerjs-pro/collaboration-file-blob-s3**](https://www.npmjs.com/package/@univerjs-pro/collaboration-file-blob-s3)                     | Stores file content in S3-compatible object storage, with signed direct links |

Metadata and content are two independent contracts, so each can follow the application's existing
storage, such as metadata in the database and content in object storage.

## Office Exchange

Office Exchange imports Office files into collaborative Units and exports Units as files. File stores
the source and result files.

| Runtime | Package                                                                                                                          | Primary responsibility                                                   |
| ------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Browser | [**@univerjs-pro/exchange-client**](https://www.npmjs.com/package/@univerjs-pro/exchange-client)                                 | Provides foundational browser file-exchange capabilities                 |
| Browser | [**@univerjs-pro/sheets-exchange-client**](https://www.npmjs.com/package/@univerjs-pro/sheets-exchange-client)                   | Provides Sheet file import and export                                    |
| Server  | [**@univerjs-pro/collaboration-exchange-service**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-service)   | Manages import and export tasks, Middleware, and Unit creation and reads |
| Server  | [**@univerjs-pro/collaboration-exchange-endpoint**](https://www.npmjs.com/package/@univerjs-pro/collaboration-exchange-endpoint) | Provides the import, export, and task routes                             |
| Server  | [**@univerjs-pro/exchange-node**](https://www.npmjs.com/package/@univerjs-pro/exchange-node)                                     | Converts Office files and Univer data in Node.js                         |

Exchange Service creates and reads Units through Core Service and reads and writes files through File
Service, so it is assembled together with Core and File.

## Selection rules

1. Start with the Core packages from [Quick Start](/server/collaboration/quick-start).
2. Select one Core Database Adapter from Memory, SQLite, PostgreSQL, or a custom implementation.
3. For a multi-node deployment, add the Redis pub/sub adapter and session ticket store.
4. Install only the extension-module packages used by the product.
5. For images, attachments, or import and export, assemble File first, then add Office Exchange as needed.
6. Create separate Adapters for each module even when they share one database.

See [Collaboration extension modules](/server/collaboration/extensions) for module relationships and the
[examples index](/server/collaboration/examples) for runnable assemblies.
