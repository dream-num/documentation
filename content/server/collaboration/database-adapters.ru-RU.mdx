Database Adapter сохраняет основные данные совместной работы, используемые Collaboration Service. Разработчик может реализовать `IDatabaseAdapter` для любой базы, способной выполнить полный контракт поведения. Service отвечает за семантику Unit, OT и ревизий. Adapter превращает её в атомарные операции хранения, безопасные при повторе.

Database Adapters открыты под лицензией Apache-2.0; исходный код находится в [univer-collaboration-sdk-community](https://github.com/dream-num/univer-collaboration-sdk-community), имена пакетов и версии те же, что у остальных пакетов.

## Проверка сохранения после перезапуска [#verify-persistence]

Остановите Quick Start и выполните `pnpm example:database-adapter` из корня. Откройте `http://127.0.0.1:3010/?unit=persistent-sheet`, измените ячейку и проверьте её в другом браузере. Остановите сервер, повторите команду и откройте тот же URL: значение должно сохраниться. Файл — `examples/database-adapter/.data/collaboration.sqlite`; не удаляйте его между запусками. Сервер читает существующий Unit и вызывает `createUnitFromData()` только при `UNIT_NOT_FOUND`. См. [server/main.ts](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/database-adapter/server/main.ts).

## Что хранит Adapter

Для каждого совместно редактируемого документа (Unit) Adapter хранит три вида данных.

- **Запись Unit** содержит идентификатор документа, тип, автора, время создания и текущую ревизию (`headRevision`). При сохранении changeset адаптер обновляет ревизию в рамках той же операции. В `UnitRecord.metadata` приложение может хранить и обновлять собственные поля, например название документа (`name`), идентификатор последнего редактора (`lastEditorID`) и время последней правки (`lastModifiedAt`).
- **Снимок** содержит данные документа на определённой ревизии. Для чтения заданной ревизии Service может загрузить последний снимок с номером не выше запрошенного и применить последующие изменения вплоть до нужной ревизии. Для электронных таблиц Adapter также хранит блоки данных, на которые ссылается снимок.
- **Набор изменений (changeset)** объединяет операции одной отправки. Adapter сохраняет наборы изменений в порядке ревизий вместе с идентификаторами отправки `sid` и `reqId`. По ним Service распознаёт повторную отправку клиента и не применяет одну правку дважды.[^submission-idempotency] В `ChangesetRecord.metadata` приложение может записать источник правки (`source`) или идентификатор связанной бизнес-операции (`operationId`).

О том, как задать метаданные при создании документа и отправке изменений, см. раздел [Сохранение метаданных](/server/collaboration/middleware-and-events#persistent-metadata).

При мягком удалении данные сохраняются. После восстановления редактирование можно продолжить. При окончательном удалении данные документа становятся недоступны, а его идентификатор нельзя использовать повторно.

Пользователями, ролями и правами доступа управляет приложение. У History, Thread Comment и Worktree отдельные интерфейсы адаптеров.

## Требования к чтению и записи

При реализации `IDatabaseAdapter` соблюдайте следующие требования.

| Операция | Требование |
| --- | --- |
| Создание Unit | Атомарно сохраните запись Unit с метаданными, начальный снимок и блоки Sheet, на которые он ссылается. Все эти данные должны стать доступны для чтения одновременно. |
| Фиксация changeset | Запись допустима только при совпадении текущей и ожидаемой ревизий (CAS)[^revision-cas]. За одну атомарную операцию сохраните changeset с его метаданными, полностью замените метаданные Unit и увеличьте номер ревизии на единицу. При несовпадении верните текущую ревизию без записи данных. |
| Чтение наборов изменений | Верните наборы из запрошенного диапазона в порядке возрастания ревизий, без пропусков. Сохраняйте исходные `sid` и `reqId`, чтобы Service мог распознать повторную отправку для той же Unit. |
| Сохранение снимка | К моменту, когда снимок станет доступен для чтения, должны читаться и все блоки Sheet, на которые он ссылается. |
| Удаление и восстановление | Применяйте операцию ко всем Unit в пакете. Если хотя бы для одной она завершилась ошибкой, весь пакет должен остаться в исходном состоянии. |

## Memory Adapter

[`@univerjs-pro/collaboration-database-memory`](https://github.com/dream-num/univer-collaboration-sdk-community/tree/main/packages/collaboration-database-memory) — реализация в памяти процесса для:

- модульных и интеграционных тестов;
- временных сред разработки;
- быстрой проверки собственных Middleware или сборки клиента.

```ts
import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
```

Memory Adapter соблюдает те же контракты ревизий, CAS и идемпотентности, что и постоянные реализации, но все данные находятся в текущем процессе Node.js и теряются при его завершении.

## SQLite Adapter

[`@univerjs-pro/collaboration-database-sqlite`](https://github.com/dream-num/univer-collaboration-sdk-community/tree/main/packages/collaboration-database-sqlite) — постоянное хранилище SQLite для разработки, тестов, локальных приложений и небольших нагрузок.

```ts
import { mkdir } from "node:fs/promises";

import { SQLiteDatabaseAdapter } from "@univerjs-pro/collaboration-database-sqlite";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";

await mkdir("./data", { recursive: true });

const database = new SQLiteDatabaseAdapter({
  filename: "./data/collaboration.sqlite",
  busyTimeoutMs: 5_000,
});
const service = new UniverCollabService({ dbAdapter: database });
```

В пустой базе он инициализирует схему, а существующую только проверяет. Расположение файла, резервные копии и другие настройки SQLite определяет приложение.

## PostgreSQL Adapter

[`@univerjs-pro/collaboration-database-postgres`](https://github.com/dream-num/univer-collaboration-sdk-community/tree/main/packages/collaboration-database-postgres) — постоянная реализация на основе node-postgres, которую могут разделять несколько узлов совместной работы.

```ts
import { PostgresDatabaseAdapter } from "@univerjs-pro/collaboration-database-postgres";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { Pool } from "pg";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
const database = await PostgresDatabaseAdapter.create({ pool });
const service = new UniverCollabService({ dbAdapter: database });
```

Пул соединений принадлежит приложению и закрывается после освобождения Service. `create()` инициализирует схему `collaboration` в пустой базе, а существующую только проверяет.

## Собственные Database Adapters

Собственный Adapter обычно подходит, когда:

- приложение уже использует MySQL или другую бизнес-базу;
- отправки совместной работы должны интегрироваться со специфическими механизмами базы приложения;
- эксплуатационные или нормативные требования выходят за рамки встроенных Adapters.

Реализуйте `IDatabaseAdapter` и внедрите его в Service так же, как встроенный Adapter:

```ts
const database = new ApplicationCollaborationDatabase({ pool });
const service = new UniverCollabService({ dbAdapter: database });
```

Service не зависит от конкретной базы, но и не может добавить транзакции, CAS или дедупликацию в вашу реализацию. Adapter должен выполнить полный контракт средствами своей базы. Встроенные реализации в [репозитории сообщества](https://github.com/dream-num/univer-collaboration-sdk-community) показывают один контракт на разных базах и служат образцом.

## Как хранить бизнес-данные

**Для данных, связанных с документом или отдельным набором изменений, используйте `metadata`.** Приложение может задать поля при создании документа или отправке changeset. Встроенный Adapter сохранит их вместе с данными совместного редактирования. См. [Сохранение метаданных](/server/collaboration/middleware-and-events#persistent-metadata).

**Для записи в отдельные таблицы используйте Middleware или Events.** Чтобы сохранить в журнале аудита саму попытку выполнить операцию, сделайте запись в Middleware. Чтобы обновить таблицу после успешного коммита, подпишитесь на `changesetCommitted`. По умолчанию такие записи выполняются вне транзакции совместного редактирования. При конфликте ревизий Middleware на этапе коммита может выполниться повторно, поэтому предусмотрите защиту от дублирования записей. События доставляются в пределах процесса без гарантии доставки и подходят для данных, которые приложение может позднее дополнить или восстановить.

**Если приложению нужны собственная база и схема либо общая транзакция для бизнес-данных и данных совместного редактирования, используйте собственный Adapter.** При вызове Service приложение может передать через `customData`, например, идентификатор бизнес-операции. Метод адаптера может прочитать нужные поля из `ctx.customData` и выбрать таблицы для обновления. Так, `commitChangeset()` может по идентификатору обновить запись бизнес-операции в той же транзакции, в которой сохраняется changeset.

Область действия `customData` ограничена текущим вызовом. Встроенные адаптеры не сохраняют эти поля автоматически и не записывают их в бизнес-таблицы.

## Хранение расширений

History, Thread Comment, Worktree и File определяют независимые интерфейсы Database Adapter. Их Adapters могут использовать одну базу или разные хранилища. Одна собственная реализация также может предоставлять несколько интерфейсов Adapter и внедряться в соответствующие Services.

Из-за независимости интерфейсов SDK по умолчанию не предоставляет межмодульных транзакций. Даже при общей базе стратегию межмодульной согласованности определяет приложение.

## Выбор Adapter

| Adapter | Подходящие задачи | Основное ограничение |
| --- | --- | --- |
| Memory | Тесты, примеры, временная разработка | Данные исчезают при завершении процесса |
| SQLite | Разработка, тесты, локальные приложения, небольшой масштаб | Однофайловая база с настройками под контролем приложения |
| PostgreSQL | Развёртывание на нескольких узлах и существующие базы PostgreSQL | Пул и эксплуатация базы под контролем приложения |
| Собственный | Существующие базы или особая интеграция бизнес-данных | Приложение реализует и проверяет полный контракт |

Приложение владеет всеми внедрёнными Adapters. Освободите Service раньше Adapter:

```ts
await service.dispose();
await database.dispose();
```

Сравнить работающие реализации можно в [примере Database Adapter](/server/collaboration/examples#database-adapter).

[^submission-idempotency]: Идемпотентность позволяет повторить отправку без повторного применения изменений. Сохраняйте идентификатор отправки: те же данные с новым идентификатором считаются новой отправкой.

[^revision-cas]: CAS обновляет значение, только если оно совпадает с ожидаемым. Проверка текущей ревизии и запись следующего состояния должны быть атомарными, чтобы два параллельных запроса не подтвердили одну ревизию.
