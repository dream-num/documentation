**Univer Collaboration SDK** - это серверный SDK для модели документа Univer. Он обрабатывает операционную трансформацию (OT[^operational-transformation]), модификации [^collaboration-revision], снимки, синхронизацию в реальном времени и постоянство, так что несколько клиентов Univer могут редактировать один и тот же авторитетный блок.

Приложения встраивают SDK в свои сервисы Node.js. Идентификацию и авторизацию подключают через Middleware, а журналирование и другую логику приложения прикрепляют к Middleware или Events. Отдельный адаптер базы данных соединяет данные совместной работы с базой данных приложения.

<Callout title="Это не полный документный продукт.">
  SDK обеспечивает только ядро совместной работы. Пользователи, роли, иерархия, совместное использование, файловые пространства и бизнес-процессы находятся за пределами его сферы действия, и приложение по-прежнему владеет этими возможностями продукта и их моделями данных.
</Callout>

## Какие задачи он решает

Web SDK отображает и редактирует Sheet, Doc, Slide, Board, Base и PDF-контент в браузере. Редактирование в режиме реального времени требует авторитета на стороне сервера поверх Web SDK. Этот авторитет загружает контент, подтверждает одновременные изменения, продвигает изменения и позволяет отключенному клиенту восстановиться в согласованном состоянии.

SDK подходит приложениям, которые:

- Univer уже используется для создания редактора и редактирования в режиме реального времени;
- • хотят сами размещать данные о совместной работе и выбирать свою базу данных;
- должны применять существующие правила идентификации, авторизации или арендаторов к совместным операциям;
- нуждаются в History, Thread Comment, Worktree, хранении файлов или импорте и экспорте Office поверх базового совместного редактирования.

## Полный сервис совместной работы

| Модуль | Основная ответственность |
| --- | --- |
| Collaboration Client | Загружает блоки, отправляет изменения и сохраняет состояние совместной работы браузера текущим |
| Node Transport | Получает трафик HTTP/WebSocket и запускает приложение Middleware |
| `UniverCollabEndpoint` | Реализует клиентский протокол, Sessions, Rooms, Presence, ACK и рассылку |
| `UniverCollabService` | Управляет жизненным циклом блока, выполняет OT и подтверждает непрерывные изменения. |
| Database Adapter | Хранит снимки, изменения, пересмотры и состояние идемпотентности представления атомарно |

## Что предоставляет SDK

Основные возможности:

- создание, загрузка, удаление и восстановление блоков для листа, дока, слайда, доски, базы и PDF;
- снимки, наборы изменений, ревизии, OT и идемпотентность отправок;
- Загрузка HTTP-контента, а также сеансы WebSocket, комнаты, присутствие, ACK и трансляции;
- Middleware на границах Transport, Endpoint и Service;
- локальные для процесса Events создания Unit, фиксации изменений, удаления и восстановления;
- хранение данных совместного редактирования с помощью встроенного или собственного адаптера базы данных;
- Горизонтальное масштабирование через развертывание нескольких узлов: узлы взаимодействуют через адаптер паба / субмарины и общий магазин билетов сеанса, а SDK обеспечивает реализацию Redis.

После того, как основной путь установлен, приложения могут добавлять историю версий, Thread Comments, черновики Worktree, файловое хранилище и серверный Office импорт и экспорт. Каждая из этих возможностей имеет свои собственные службы, промежуточное ПО, события или адаптеры базы данных.

## За что отвечает приложение

| Collaboration SDK | Приложение |
| --- | --- |
| Состояние совместной работы Unit | Пользователи, арендаторы, иерархия и связи общего доступа |
| OT, ревизии и снимки | Вход, Sessions и сопоставление идентификаторов |
| Sessions, Rooms и Presence совместной работы | Роли, ACL и политики продукта |
| Database Adapters совместной работы и файлов | Базы данных продукта и эксплуатация хранилища |
| Точки расширения Middleware и Event | Журналирование, аудит, метрики и внешние интеграции |
| Endpoints клиентского протокола | Бизнес-API и процессы, например создание документов |

## Три общие точки расширения

| Точка расширения | Какие задачи решает |
| --- | --- |
| Middleware | Проверяет или обогащает Контекст, отклоняет запрос или записывает, что произошло во время операции. |
| Event | Наблюдает подтвержденные изменения состояния для обновления состояния, полученного в процессе, или начала некритической последующей работы. |
| Database Adapter | Выберите, где данные живут и реализуют контракты на атомарность, CAS и идемпотентность. |

Идентификация и авторизация подключаются через Middleware. Middleware проверяет и ограничивает операцию перед ее запуском, а Events записывает изменения или запускает последующую работу после подтверждения состояния. Либо может нести журналирование, отслеживание запросов, метрики и обновления производного состояния. [Промежуточное ПО и события](/server/collaboration/middleware-and-events) объясняет, где каждый запускается.

## С чего начать

1. Запустите [Быстрый старт](/server/collaboration/quick-start) и проверьте полный путь в двух браузерах.
2. Прочитайте [Границы и связи модулей](/server/collaboration/modules), чтобы понять назначение пакетов.
3. Выберите [Промежуточное ПО и события](/server/collaboration/middleware-and-events), [Идентификация и авторизация](/server/collaboration/identity-and-authorization) или [Адаптер баз данных](/server/collaboration/database-adapters) для задач интеграции.
4. Перейдите в [Модули расширения совместной работы](/server/collaboration/extensions) для истории, комментариев, рабочих деревьев, хранения файлов и импорта и экспорта.

[^operational-transformation]: Операционная трансформация (OT) согласует одновременные операции, созданные на разных ревизиях документа. Она обрабатывает изменения, а не заменяет весь документ последним полученным снимком.

[^collaboration-revision]: Ревизия обозначает позицию в подтверждённой истории Unit. Changeset содержит операции одной отправки; их подтверждение продвигает историю. Ревизия не является версией SDK или меткой времени.
