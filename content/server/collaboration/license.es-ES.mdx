---
title: Licencia
description: Collaboration SDK usa la licencia para decidir las conexiones de edición colaborativa, los dominios autorizados, los nodos de colaboración y los tipos de documento.
---

`UniverCollabService` carga la Licencia durante la construcción, y Endpoints y Worktrees comparten esa instancia. Configure la Licencia como se describe en [Licencia](/server/license#collaboration-sdk); sin uno, el SDK se ejecuta en el nivel libre. Si la verificación falla, el constructor lanza un `CollabError` (`LICENSE_INVALID` o `LICENSE_POLICY_INVALID`), y el servicio no comienza.

## Qué decide la licencia [#limits]

| Elemento | Dónde se comprueba | Al superar el límite |
| --- | --- | --- |
| Conexiones de edición colaborativa | Endpoint, on receiving submissions | Las versiones de las nuevas conexiones permanecen en el navegador y se retiran |
| Dominios autorizados | Endpoint, al conectarse y a las presentaciones | La sesión de colaboración del navegador pasa a sin conexión |
| Nodos de colaboración | Endpoint | Los nodos que superan el límite se desconectan tras un periodo de gracia |
| Tipos de documento | Servicio, creación de una unidad y presentación de edición | Se rechazan la creación y los envíos; los documentos existentes siguen visibles |

### Conexiones de edición colaborativa [#editing-connections]

La asignación sólo cuenta con conexiones que están editando activamente. Una conexión de colaboración ocupa una ranura después de su primera presentación exitosa y la libera cuando la conexión cierra, o 120 segundos después de su última presentación exitosa. Conexiones que abren un documento sólo para la visualización se pueden unir en cualquier momento. Edita dentro de un Worktree contamos con la misma ranura que edita en el maletero.

Cuando cada ranura está ocupada, las ediciones de una nueva conexión permanecen en el navegador, y Web SDK las reenvia con backoff hasta que una ranura se pone disponible. Conexiones que ya tienen una ranura continuar editando. El `CollaborationChangesetResend` del navegador informa estos reenviamientos con `reason: 'license_editing_connections_exceeded'`.

### Dominios autorizados [#domains]

Cuando Web SDK abre una conexión de colaboración o envía ediciones, el Endpoint compara el dominio de la página con los dominios autorizados en la Licencia. Un dominio fuera de esa lista recibe `403`; la sesión de colaboración del navegador entonces se desconecta y muestra la razón. La sesión se vuelve cuando el usuario vuelve a conectar o abre otro documento.

### Nodos de colaboración [#nodes]

Un **Licencia de un solo nodo**, incluyendo el nivel libre, ejecuta un nodo de colaboración. Pasando `pubSub` al Endpoint hace que el constructor tire `LICENSE_POLICY_INVALID`.

A **Licencia multinodo** define un límite de nodo. Cuando el número de nodos que se ejecutan excede ese límite, los nodos más recientes entran en un período de gracia con advertencias crecientes y luego salen fuera de línea. `503`, y las conexiones existentes cierran. Nodos dentro del límite continúan sirviendo el tráfico. Si el recuento del nodo cae dentro del límite durante el período de gracia, los nodos extra vuelven a la normalidad. Un nodo que ha ido fuera de línea se cuenta como un nuevo nodo después de que su proceso se reinicia. [Despliegue](/server/deployment#varios-nodos-de-colaboración).

### Tipos de documento [#unit-types]

La Licencia enumera los tipos de documentos disponibles para la colaboración. Crear una Unidad de cualquier otro tipo lanza `LICENSE_UNIT_TYPE_REJECTED`, y las ediciones presentadas son rechazadas. `CollaborationConflict` en el navegador informa `reason` como `license_unit_type_rejected`. Los documentos existentes siguen siendo visibles.

## Observar el estado [#observe]

```ts
// Service
collabService.license.status // estado de la licencia: 'not_configured' | 'expired' | 'valid'
collabService.license.editingConnectionsLimit // límite de conexiones de edición: number | null; null significa ilimitado
collabService.license.nodesLimit // límite de nodos: number | null; null significa ilimitado
collabService.license.domains // dominios autorizados: string[]
collabService.license.expiresAt // fecha de caducidad: cadena ISO | null; null sin licencia configurada
collabService.license.update({ license, licenseKey }) // sustituye la licencia; si la verificación falla, lanza un error y conserva la actual

// Endpoint
endpoint.license.editingConnections.limit // límite de plazas: number | null; null significa ilimitado
endpoint.license.editingConnections.used // plazas ocupadas: number | null; null cuando limit es ilimitado
endpoint.license.editingConnections.remaining // plazas libres: number | null; null significa ilimitado
endpoint.license.editingConnections.has(memberID) // si este miembro tiene plaza: boolean; false cuando limit es ilimitado
endpoint.license.nodes.limit // límite de nodos: number | null; null significa ilimitado
endpoint.license.nodes.status // estado de este nodo: 'normal' | 'exceeded' | 'exceeded-warning' | 'exceeded-offlineSoon' | 'exceeded-offline'

// Eventos
endpoint.license.on('editingConnectionsChanged', ({ change, memberIDs, used, limit }) => {}) // se ocuparon o liberaron plazas: change es 'acquired' | 'released', used es el valor tras el cambio; no se emite cuando limit es ilimitado
endpoint.license.on('editingConnectionsExceeded', ({ memberID, userID, unitID, used, limit }) => {}) // las plazas están llenas y el envío de una conexión nueva no se guardó
endpoint.license.on('nodesStatusChanged', ({ status, previousStatus, limit, reason }) => {}) // cambió el estado de este nodo; reason solo tiene valor al desconectarse
```

`nodesStatusChanged` dispara una vez por cada cambio de estado de este nodo. Cuando `status` se convierte en `exceeded-offline`, el nodo ha dejado de aceptar conexiones; eliminarlo del balanceador de carga o levantar una alerta.
