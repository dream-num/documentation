Univerコラボレーションは、ブラウザクライアントとサーバーサイドモジュールのセットで構成されています。各モジュールは、責任の1つのクラスを所有しています。アプリケーションは、パブリックインターフェイスを介してモジュールを構成しているため、そのコードはOT[^operational-transformation]実装、プロトコル、または永続レイヤーの内部に依存しません。

## Collaboration Client

ブラウザコラボレーションクライアントは、Web SDKと並行して実行し、クライアントのコラボレーションの側面を処理します。

- ユニットのスナップショットと、それが欠落している確認されたチェンジセットを要求します。
- WebSocket接続を開くには、ワンタイムセッションチケットを使用します。
- ユニットルームと交流のプレゼンスを他のメンバーと結合します。
- ローカルのミューテーションをサーバーに変更として送信します。
- ACKsや放送を受信し、再接続後、見逃した変更が発生した。

クライアントは、ユーザが信頼されるかどうかを判断しません。権限のあるデータソースではありません。その決定は、対応するミドルウェアのアイデンティティと認可を強化するサーバーに属します。

## Node Transport

`@univerjs-pro/collaboration-transport-node`は、HTTPおよびWebSocketトラフィックのNode.jsエントリーポイントです。 リクエストとWebSocktがホストHTTPサーバーからアップグレードされ、アプリケーションによって登録されたエントリーミドルウェアを実行し、エンドポイントへのトラフィックをルート化します。

トランスポートは、OT、ユニットデータ、またはACLモデルを理解していません。アセンブリは3つの方法を使用します。

```ts
transport.use(httpMiddleware);
transport.useUpgrade(upgradeMiddleware);
transport.register(endpoint);
```

- `use()` は通常の HTTP リクエストを扱い、`userID`、`customData`, ログ、またはトレースを設定できます。
- `useUpgrade()`はWebSocketハンドシェイクを扱い、その前に接続を拒否することができます。
- `register()`は、輸送をライフサイクルし、管理するプロトコルエンドポイントを登録します。

## Collaboration Endpoint

`@univerjs-pro/collaboration-endpoint`は、Univerコラボレーションクライアントが使用するプロトコルを実装し、次の機能を所有しています。

| 機能 | Endpoint の役割 |
| --- | --- |
| 内容の読み込み | クライアントが欠けている確認された変更とともに、ユニットのスナップショットとブロックを返します。 |
| 変更送信 | 変更セットを受け取り、ACK を返し、確定変更を Room に配信 |
| Session 接続 | ワンタイムセッションチケットを発行し、WebSocketセッションの確立と維持 |
| Room の共同編集 | JOIN、LEAVE、メンバー状態、Presence を処理 |
| Unit のライフサイクル | 削除・復元リクエストを Service 呼び出しに対応付け |
| 複数ノード | リレールーム、プレゼンス、およびオプションのパブ/サブアダプタと共有チケットストアを通じてノードを横断する放送 |

Endpoint は OT を実行せず、コラボレーションデータ自体を格納しません。これにより、クライアントプロトコルに戻ったサービスやマップから権限のある結果が得られます。ドキュメントを作成するなどの製品操作は、サービスを呼び出すアプリケーション API に帰属します。

## Collaboration Service

`@univerjs-pro/collaboration-service`はコラボレーションコアであり、ネットワークに依存しません。シート、ドキュメント、スライド、ボード、ベース、PDFをカバーしています。

- ユニットの回復データを読み、チェンジセットを確認しました。
- ユニットデータやスナップショットからユニットを作成します。
- 変更セットを提出すると、OTを実行し、継続的なリビジョン[^collaboration-revision]を進歩させます。
- `(unitID, sid, reqId)`で重複した投稿を識別します。
- ソフト削除、回復、または永久にユニットを削除します。
- サービスミドルウェアを実行し、確認後にイベントを発します。

本サービスには、HTTPまたはWebSocketレイヤーがなく、ユーザー、ロール、ACL、階層、ファイル管理については知りません。エンドポイントは、サービスの上にブラウザプロトコルを構築します。アプリケーションは、ビジネスAPIやバックグラウンドタスクから直接サービスパブリックAPIを呼び出すこともできます。

### 基本 API

| 機能 | Service API |
| --- | --- |
| Unit を読み込み | `getUnitLoadData()`、`getUnitLoadDataWithBlocks()` |
| 増分データを読み取り | `getChangesets()`、`getSheetBlock()` |
| Unit を作成 | `createUnitFromData()`、`createUnitFromSnapshot()` |
| 変更を送信 | `submitChangeset()` |
| 削除と復元 | `deleteUnits()`、`recoverUnits()` |

## Database Adapter

Database Adapter は Service とストレージ間の契約で、次を保証します。

- 初期スナップショットと依存データのアトミックな作成；
- リビジョンの比較交換（CAS）；
- 意図的なチェンジセットの提出;
- すべての依存関係が存在する後だけ可視性をスナップショットします。
- Unit ライフサイクルの一括操作を全件成功か全件未実行にする。

アプリケーションは `IDatabaseAdapter` を介してストレージに接続します。組み込みのアダプターを選ぶ方法と独自のアダプターを実装する方法は、[Database Adapter](/server/collaboration/database-adapters) を参照してください。

## 4 つの基本概念

| 概念 | 意味 |
| --- | --- |
| Unit | 独自の`unitID`とタイプで、Univerコンテンツを独立してロード可能でコラボレーション |
| Snapshot | 単位のコンテンツは、ライブミュータブルオブジェクトではなく、リビジョンで主張しました |
| Changeset | 一緒に提出された突然変異のバッチ, ベースリビジョンと出欠のためのアイデンティティ |
| Revision | `1`で始まる確認された単位の状態の連続的な版数 |

コンテンツを実行するすべての変更は、ファサード API または Commands で行われます。スナップショットオブジェクトのミュートは、クライアントまたはサービス内のライブユニットを更新しません。

## Unit の読み込み

<Mermaid chart={"sequenceDiagram\n    participant Client\n    participant Transport\n    participant Endpoint\n    participant Service\n    participant Adapter\n\n    Client->>Transport: HTTP で Unit を読み込み\n    Transport->>Endpoint: 認証済みリクエスト Context\n    Endpoint->>Service: getUnitLoadData()\n    Service->>Adapter: スナップショット + 変更セット\n    Adapter-->>Service: 正本データ\n    Service-->>Endpoint: Unit 読み込みデータ\n    Endpoint-->>Client: プロトコルレスポンス"} />

`userID/customData` は、Transport Middleware が、現在の HTTP リクエストを Service Middleware に転送することで確立しました。このアプリケーションは、読み取りが許可されているかどうかを決定します。クライアントは、プレーン HTTP を読んだ前に、Room に参加する必要はありません。

## 編集の送信

```text
Facade / Command
  → Mutation
  → Client の変更セット
  → Endpoint への送信
  → Service Middleware
  → OT + リビジョン CAS
  → Adapter のアトミックなコミット
  → 確定変更セット
  → ACK / Room への配信
```

データベースアダプタで確認されたリビジョンは、権威ある状態です。 ACKsと放送は、オンラインクライアントが低レイテンシで同期を維持します。 メッセージが見逃すクライアントは、すでに知っているリビジョンを使用して欠けている確認されたリチェンジを手に入れることができます。

## 最小のサーバー構成

```ts
import { createServer } from "node:http";

import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

const server = createServer();
transport.attach(server);
server.listen(3010);
```

ハードドライブのユーザーとメモリアダプタは、モジュールアセンブリのみを実証します。 実際のアプリケーションは、ミドルウェアを介してコンテキストを確立し、データ要件に合ったアダプタを選択します。

### アプリケーション API で Unit を作成

アプリケーションは、独自のHTTPまたはRPCエンドポイントを定義し、認証、入力検証、およびビジネスチェックパスの後に作成した`service`を呼び出します。

```text
業務クライアント
  → POST /api/units
  → アプリケーションの認証と検証
  → service.createUnitFromData()
  → Database Adapter
```

以下は、認証ミドルウェアが`response.locals.user`を設定し、`request.body.data`が既にWorkbook Dataとして検証されていることを想定しています。

```ts
import { randomUUID } from "node:crypto";

import { json } from "express";
import { UniverType } from "@univerjs/protocol";

app.post("/api/units", json({ limit: "1mb" }), async (request, response, next) => {
  try {
    const user = response.locals.user as { readonly userID: string };
    const unitID = randomUUID();

    const result = await service.createUnitFromData(
      {
        type: UniverType.UNIVER_SHEET,
        data: {
          ...request.body.data,
          id: unitID,
          rev: 1,
        },
      },
      {
        userID: user.userID,
        customData: { traceID: randomUUID() },
      },
    );

    response.status(result.status === "created" ? 201 : 200).json(result);
  } catch (error) {
    next(error);
  }
});
```

`POST /api/units`はアプリケーションルートであり、コラボレーションクライアントプロトコルの一部ではありません。 `createUnitFromData()`を呼び出すと、サービスの`createUnit`ミドルウェアが実行されます。 製品レコード、所有者ACL、エラー応答マッピング、および障害補償は、アプリケーションに対する責任を保ちます。

## リソースの解放

`transport.dispose()`は、`register()`に登録されているエンドポイントを処分します。アプリケーションが注入したサービスおよびデータベースアダプタは、アセンブリの順番の逆に、別々に処分しなければなりません。

```ts
await transport.dispose();
await service.dispose();
await database.dispose();
```

アプリケーションがパブ/サブアダプタを受け取った場合、トランスポート後にそのアダプタとその接続を処分する必要があります。エンドポイントはそれらを処分しません。

これらのモジュールの境界線で動作を拡張するには、[ミドルウェアとイベント](/server/collaboration/middleware-and-events) を続けてください。

[^operational-transformation]: *操作変換（OT）*は、異なる文書リビジョンに対して同時に生成された操作を調整し、一貫して適用できるようにします。最後に届いたスナップショットで文書全体を置き換える方式ではありません。

[^collaboration-revision]: リビジョンは Unit の確定済み編集履歴における位置です。changeset は送信する操作の集合で、その確定により履歴が進みます。SDK パッケージのバージョンやタイムスタンプではありません。
