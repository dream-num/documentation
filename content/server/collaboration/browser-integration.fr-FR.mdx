La collaboration connecte les éditeurs du navigateur à un service de documents partagés. Par exemple, deux utilisateurs ouvrent le même classeur et une modification dans un navigateur apparaît dans l’autre.

Préparez le backend avec l’[intégration serveur](/server), puis configurez l’éditeur et le chargement ci-dessous. Suivez ensemble les codes Server et Web du [démarrage rapide Office](/server/collaboration/quick-start).

## Connecter votre éditeur existant

Conservez votre éditeur Web SDK. Suivez la [configuration navigateur du démarrage rapide](/server/collaboration/quick-start) pour ajouter les plugins collaboratifs et configurer le chargement, l’envoi de modifications et les adresses WebSocket. Gardez les versions des paquets navigateur et serveur compatibles.

Les utilisateurs fixes et les autorisations par défaut des exemples servent à la démonstration. Dans votre application, joignez les identifiants de connexion aux requêtes pour que le backend vérifie l’identité et l’accès au document. Consultez la [configuration de la licence](/server/license) pour la licence.

## Créer et ouvrir le même document

La création et l’ouverture sont deux actions distinctes :

1. Lorsqu’un utilisateur crée un document, votre backend l’enregistre et renvoie son ID.
2. Le navigateur charge cet ID. Réutilisez-le pour rouvrir le document ou le partager.

Le `unitId` de l’API est cet ID de document. Ne créez pas un nouveau document local vierge à chaque visite.

Par exemple, après avoir enregistré les plugins Sheets et collaboratifs, chargez un classeur du serveur :

```ts
import '@univerjs-pro/collaboration-client/facade'

const workbook = await univerAPI.getCollaboration().loadSheetAsync('your-document-id')
if (!workbook) throw new Error('Document could not be loaded')
```

Consultez les guides [Sheets](/guides/sheets/features/collaboration), [Docs](/guides/docs/features/collaboration), [Slides](/guides/slides/features/collaboration), [Boards](/guides/boards/features/collaboration), [Bases](/guides/bases/features/collaboration) et [PDFs](/guides/pdfs/features/collaboration) pour le chargement propre à chaque produit. Vérifiez la prise en charge par le produit et la version backend ciblée.

## Vérifier synchronisation, enregistrement et autorisations

Ouvrez le même document dans deux sessions indépendantes, par exemple une fenêtre normale et une privée. Modifiez dans l’une et vérifiez l’autre. Vérifiez ensuite le contenu après actualisation, reconnexion et redémarrage serveur.

Testez avec un éditeur, un lecteur et un utilisateur non autorisé. Les réglages UI de lecture seule contrôlent les interactions ; le serveur doit toujours refuser les lectures et changements non autorisés.

Si les documents se chargent mais que les modifications ne se synchronisent pas, vérifiez WebSocket. Si le contenu disparaît au redémarrage, vérifiez le stockage backend. Ces réglages sont décrits dans l’[intégration serveur](/server).

## Ajouter échange de fichiers, commentaires ou historique

Pour modifier ensemble un fichier importé, créez un document collaboratif à partir des données converties ; consultez l’[intégration de l’échange de fichiers](/server/import-export). Commentaires et historique nécessitent leurs propres plugins, services et autorisations. Suivez les [modules d’extension Office](/server/collaboration/extensions).

Pour les panneaux d’historique, consultez [Sheets](/guides/sheets/features/edit-history), [Docs](/guides/docs/features/edit-history), [Slides](/guides/slides/features/edit-history), [Boards](/guides/boards/features/edit-history) et [Bases](/guides/bases/features/edit-history). La portée actuelle pour PDFs est décrite dans [Historique PDFs](/guides/pdfs/features/edit-history).
