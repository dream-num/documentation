このページでは2つのパスについて説明します。最初の例は公式で実行され、2つのブラウザでの完全なコラボレーションパスを検証します。2番目のものは、独自のUniverアプリケーションにコピーできる最小限のサーバーとWebアセンブリを示します。

開始前に[環境とバージョンの要件](/server/requirements)を満たしてください。すべての `@univerjs/*` と `@univerjs-pro/*` を、対応する同一リリース群に固定する必要があります。

## 手順 1：公式サンプルを実行する

### 実行前の準備

このリポジトリは**Node.js 24+**を要求し、**午後10時～午後3時**を宣言します。`node --version`と`pnpm --version`をチェックし、リポジトリのロックファイルを使用して、リポジトリのルートから`pnpm example:*`のすべてのコマンドを実行します。各コマンドは、ブラウザとサーバーをビルドし、サンプルをタイプチェックし、起動します。これらのコマンドは、ホットリロード開発サーバーを提供しません。そのため、ソースファイルを編集した後、プロセスを停止し、コマンドを再び実行する必要があります。

ライセンスを持っている場合、コマンドを実行する前に、シェルに`UNIVER_LICENSE`と`UNIVER_LICENSE_KEY`を設定してください。ビルドは`vite.config.ts`を経由してブラウザバンドルに`UNIVER_LICENSE`を埋め込み、サーバーが起動したときにCollaboration SDKは両方の変数を読みます。ライセンスを変更した後にコマンドを再実行します。 [ライセンス](/server/license#collaboration-sdk)を参照してください。

```bash
git clone https://github.com/dream-num/univer-collaboration-examples.git
cd univer-collaboration-examples
pnpm install --frozen-lockfile
pnpm example:quick-start
```

次のURLを開きます。

```text
http://127.0.0.1:3010/?unit=quick-start-sheet
```

### リアルタイム共同編集の確認

1. 1つのブラウザウィンドウで完全なURLを開きます。
2. 同じ URL を別のウィンドウまたはタブで開きます。
3. いずれかのシートで1セルを変更します。
4. 同じ編集がもう一方にも現れることを確認します。

各ウィンドウはそれぞれ WebSocket セッションを開きます。後で[権限のサンプル](/server/collaboration/examples#permissions)を 2 つのアカウントで試すときは、別々のブラウザープロファイルを使ってログイン Cookie を分けます。

### 成功によって確認できること

```text
Univer Collaboration Client
  → Node Transport
  → UniverCollabEndpoint
  → UniverCollabService
  → MemoryDatabaseAdapter
```

2つのブラウザが同期状態のままの場合、完全なパスが動作します。各ブラウザは、ユニットをHTTP経由でロードし、WebSocketセッションを1回セッションチケットで開いて、同じ部屋に加わりました。本サービスは、OTを実行し、新しいリビジョンを確認し、アダプタを介して保存し、エンドポイントは他のメンバーにリビジョンを放送しました。

## 手順 2：アプリケーションに組み込む

以下のコードは、サーバーとWebアセンブリの最小限です。 公式クイックスタートには、完全なアプリケーション構造が含まれています。

- [server/main.ts](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/server/main.ts)
- [web/main.ts](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/web/main.ts)
- [package.json](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/package.json)

Univer Webアプリケーションを既にインストールしている場合は、ランタイム、プリセット、UI を保ち、以下に説明したコラボレーションクライアントの構成とサーバーだけを追加します。空のプロジェクトでは、`index.html`、`vite.config.ts` をコピーし、クイックスタートディレクトリからスタイルをコピーしてアプリケーションシェルとして使用してください。

### 実行可能なファイルから移行する

コピー `examples/quick-start` 初期のスケルトンとして、保持 `package.json`, `index.html`, `vite.config.ts`, `web/styles.css`, `web/main.ts`, と `server/main.ts`. Express が機能するので、ビルドを実行し、そのディレクトリからスクリプトを起動します。 `dist/web` 作業ディレクトリに相対的。 Vite ライセンスの定義を保ち、Vite のライセンスの定義を与えて下さい `#app` 非ゼロ高さ。下にあるコードは、これらの部品がどのように組み立てられるかを説明します。完全な実行可能なプロジェクトでは、リポジトリファイルを使用します。

この例は、同じ起源からページと`/universer-api`を扱います。 他の場所にフロントエンドを移動する場合は、HTTPとWebSocketの両方のアップグレードをバックエンドにプロキシするか、または5つのクライアントURLを一緒に変更します。 `unit`は、バックエンドが作成したIDと一致しなければなりません。 URLパラメータは文書を作成しません。 例は`unit`を読み、`loadSheetAsync()`で明示的に文書をロードします。 アプリケーションでは、[コラボレーション統合](/server/collaboration/browser-integration)で説明したように、ロードする前に現在のユーザーを設定します。

### 1. 対応する同一バージョンのパッケージ群をインストールする

Server は、トランスポート、エンドポイント、サービス、および 1 つのデータベース アダプターを必要とします。 ブラウザは、コラボレーション クライアントが必要です。 パッケージをインストールし、Univer のすべてのパッケージを同じバージョンにピン留めします。

```bash
pnpm add \
  @univerjs-pro/collaboration \
  @univerjs-pro/collaboration-client \
  @univerjs-pro/collaboration-client-ui \
  @univerjs-pro/collaboration-database-memory \
  @univerjs-pro/collaboration-endpoint \
  @univerjs-pro/collaboration-service \
  @univerjs-pro/collaboration-transport-node \
  @univerjs-pro/license \
  @univerjs/core \
  @univerjs/preset-sheets-core \
  @univerjs/presets \
  @univerjs/protocol \
  express react react-dom rxjs
```

正式な例は、現在のパッケージ構成と正確なバージョンの実行可能で権威のある参照です。

### 2. Service、Endpoint、初期 Unit を作る

`UniverCollabService` は権威あるコラボレーションコアです。エンドポイントは、ブラウザプロトコルをサービスにマップし、メモリアダプタはスナップショット、チェンジセット、リビジョンを一時的に保存します。

```ts
import type { IWorkbookData } from "@univerjs/core";
import { createServer } from "node:http";
import express from "express";
import { LocaleType } from "@univerjs/core";
import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";
import { ErrorCode, UniverType } from "@univerjs/protocol";

const UNIT_ID = "quick-start-sheet";
const unitData: IWorkbookData = {
  id: UNIT_ID,
  rev: 1,
  name: "Quick Start Sheet",
  appVersion: "",
  locale: LocaleType.EN_US,
  sheetOrder: ["sheet-1"],
  sheets: {
    "sheet-1": {
      id: "sheet-1",
      name: "Sheet 1",
      rowCount: 100,
      columnCount: 26,
      cellData: {},
    },
  },
  styles: {},
  resources: [],
};

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

await service.createUnitFromData(
  { type: UniverType.UNIVER_SHEET, data: unitData },
  { userID: "demo-user" },
);
```

`demo-user`は、信頼できるアイデンティティがトランスポートからエンドポイントとサービスへの流れをどのように流れるかを示しています。 生産アプリケーションは、`transport.use()`内の独自のクッキー、ベアトークン、またはセッションを検証し、安定したビジネス`userID`を設定します。

### 3. 認可、HTTP、WebSocket の入口を配置する

現在のコラボレーションクライアントは、認可プロトコルを問い合わせます。クイックスタートは、すべてのリクエストのルートで `allowed: true` を返し、アプリケーションの HTTP サーバにトランスポートを添付します。

```ts
const app = express();

app.post("/universer-api/authz/-/object/-/batch_allowed", express.json(), (request, response) => {
  const body = request.body as {
    requests: Array<{ unitID: string; objectID: string; actions: unknown[] }>;
  };
  response.json({
    error: { code: ErrorCode.OK, message: "" },
    objectActions: body.requests.map((item) => ({
      unitID: item.unitID,
      objectID: item.objectID,
      actions: item.actions.map((action) => ({ action, allowed: true })),
    })),
  });
});

app.use(express.static("dist/web"));

const server = createServer(app);
transport.attach(server);
server.listen(3010, "127.0.0.1");
```

すべてのリクエストを付与することは、セキュリティ境界ではなく、教育のショートカットです。 生産アプリケーションは、HTTP読み取り、リアルタイムJOIN、チェンジセットの送信、およびユニットのライフサイクル操作を保護する必要があります。 完全なカバレッジモデルについては、[アイデンティティと認可](/server/collaboration/identity-and-authorization)を参照してください。

### 4. ブラウザー Runtime に Collaboration Client を登録する

標準の Web SDK とプリセットを保持し、コラボレーションプラグインとプロトコル URL を追加します。

#### プラグイン設定 [#plugin-configuration]

`UniverLicensePlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `license` | `string` |  | クライアント用ライセンスファイルの内容。 |

`UniverCollaborationClientPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `socketService` | `Ctor<ICollaborationSocketService>` |  | 現在のランタイムの使用をソケットで実装します。 |
| `sendChangesetTimeout` | `number` | `2000` | どのくらいの編集がバッチ処理されます。, ミリ秒単位で, 送信される前に. |
| `authzUrl` | `string` | `'/universer-api/authz'` | 権限を確認するエンドポイント。 |
| `snapshotServerUrl` | `string` | `'/universer-api/snapshot'` | 文書のスナップショットを読み込むエンドポイント。 |
| `collabSubmitChangesetUrl` | `string` | `'/universer-api/comb'` | 変更セットを送信するエンドポイント。 |
| `collabWebSocketUrl` | `string` | `'ws://127.0.0.1:8000/universer-api/comb/connect'` | 変更をリアルタイム同期する WebSocket の URL。 |
| `wsSessionTicketUrl` | `string` | `'/universer-api/user/session-ticket'` | WebSocket セッションチケット取得用のエンドポイント。 |

#### プリセット設定 [#preset-configuration]

`UniverSheetsCorePreset`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` | `'app'` | エディターのマウント先となる DOM 要素、またはその ID。 |

```ts
import { LocaleType, LogLevel } from "@univerjs/core";
import { UniverCollaborationPlugin } from "@univerjs-pro/collaboration";
import { UniverCollaborationClientPlugin } from "@univerjs-pro/collaboration-client";
import CollaborationClientEnUS from "@univerjs-pro/collaboration-client/locale/en-US";
import {
  BrowserCollaborationSocketService,
  UniverCollaborationClientUIPlugin,
} from "@univerjs-pro/collaboration-client-ui";
import CollaborationClientUIEnUS from "@univerjs-pro/collaboration-client-ui/locale/en-US";
import { UniverLicensePlugin } from "@univerjs-pro/license";
import { UniverSheetsCorePreset } from "@univerjs/preset-sheets-core";
import UniverPresetSheetsCoreEnUS from "@univerjs/preset-sheets-core/locales/en-US";
import { createUniver, defaultTheme, mergeLocales } from "@univerjs/presets";
import "@univerjs-pro/collaboration-client/facade";
import "@univerjs/preset-sheets-core/lib/index.css";
import "@univerjs-pro/collaboration-client-ui/lib/index.css";

const httpProtocol = location.protocol === "https:" ? "https" : "http";
const wsProtocol = location.protocol === "https:" ? "wss" : "ws";
const baseURL = `${httpProtocol}://${location.host}/universer-api`;

const unitId = new URLSearchParams(location.search).get("unit");
if (!unitId) throw new Error("Open the URL printed by the server; it names the Sheet with ?unit=.");
const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
      CollaborationClientEnUS,
      CollaborationClientUIEnUS,
    ),
  },
  theme: defaultTheme,
  logLevel: LogLevel.WARN,
  collaboration: true,
  presets: [UniverSheetsCorePreset({ container: "app" })],
  plugins: [
    [UniverLicensePlugin, { license: import.meta.env.UNIVER_LICENSE || undefined }],
    UniverCollaborationPlugin,
    [
      UniverCollaborationClientPlugin,
      {
        socketService: BrowserCollaborationSocketService,
        sendChangesetTimeout: 200,
        authzUrl: `${baseURL}/authz`,
        snapshotServerUrl: `${baseURL}/snapshot`,
        collabSubmitChangesetUrl: `${baseURL}/comb`,
        collabWebSocketUrl: `${wsProtocol}://${location.host}/universer-api/comb/connect`,
        wsSessionTicketUrl: `${baseURL}/user/session-ticket`,
      },
    ],
    UniverCollaborationClientUIPlugin,
  ],
});

const workbook = await univerAPI.getCollaboration().loadSheetAsync(unitId);
if (!workbook) throw new Error("Document could not be loaded");
```

このページでは、`id="app"` の要素を要求し、クエリパラメータを使用してユニットを選択する必要があります。

```text
/?unit=quick-start-sheet
```

### 5. 学習用の設定をアプリケーションの機能に置き換える

| 学習用設定 | 置き換えるもの |
| --- | --- |
| 固定`demo-user` | アプリケーション認証 Middleware と安定したユーザー ID |
| 常に許可する権限チェック | 読み取り、JOIN、送信、ライフサイクルを覆うサーバー ACL |
| 固定ユニット | `createUnitFromData()` を呼ぶ作成 API と製品レコード |
| 記憶アダプター | SQLite または契約テスト済みの独自永続化 Adapter |

[データベースのアダプター](/server/collaboration/database-adapters)と[アイデンティティと認可](/server/collaboration/identity-and-authorization)を続けて、必要に応じて[歴史、スレッドコメント、Worktree、または交換](/server/collaboration/extensions)を追加します。 [サンプルインデックス](/server/collaboration/examples)は、すべての実行可能な構成をカバーしています。

## 初回実行のトラブルシューティング

| 症状 | 確認点 |
| --- | --- |
| インストール・ビルド失敗 | Node.js 24+、指定 pnpm、Univer のバージョン統一 |
| 3010 が使用中 | 前のサンプルを停止、または `PORT=3011` を設定して両ブラウザーの URL を変更 |
| 白画面・静的ファイル不足 | ビルド完了; スタートは、例のディレクトリから実行します。 `#app` は高さを持っています |
| 編集が同期しない | 両方のウィンドウで同じ完全なURL; 成功したスナップショットとセッションチケットリクエスト; `/universer-api/comb/connect`でのWebSocket接続 |
| 再起動で消える | Quick Start はメモリ保存。SQLite サンプルへ進む |
