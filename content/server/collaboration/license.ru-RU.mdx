`UniverCollabService` загружает Лицензию во время строительства, и Endpoints и Worktrees разделяют этот экземпляр. Настройка Лицензии, как описано в [Лицензия](/server/license#collaboration-sdk); без него SDK работает на свободном уровне. Если проверка не удается, конструктор бросает `CollabError` (`LICENSE_INVALID` или `LICENSE_POLICY_INVALID`), и служба не запускается.

## Что определяет лицензия [#limits]

| Параметр | Где проверяется | При превышении |
| --- | --- | --- |
| Подключения совместного редактирования | Конечный пункт, при получении представлений | Редакции от новых подключений остаются в браузере и перепроверяются |
| Разрешённые домены | Конечная точка, при подключении и на представлениях | Сеанс совместного редактирования в браузере переходит в офлайн |
| Узлы совместного редактирования | Endpoint | Узлы сверх лимита после льготного периода отключаются |
| Типы документов | Обслуживание, создание и редактирование подразделения | Создание и отправки отклоняются; существующие документы остаются доступны для просмотра |

### Подключения совместного редактирования [#editing-connections]

Разрешение учитывает только соединения, которые активно редактируют. Соединение для совместной работы занимает слот после его первого успешного представления и выпускает его, когда соединение закрывается, или через 120 секунд после его последнего успешного представления. Соединения, которые открывают документ только для просмотра, могут присоединиться в любое время. Редактирование внутри Worktree счет против того же пула слотов, что и редактирование на багажнике.

Когда каждый слот занят, в браузере остаются правки из нового соединения, и Web SDK пересылает их с обратной связью, пока слот не станет доступен. Соединения, которые уже содержат слот, продолжают редактирование. `CollaborationChangesetResend` браузера сообщает об этих пересылках с `reason: 'license_editing_connections_exceeded'`.

### Разрешённые домены [#domains]

Когда Web SDK открывает соединение для совместной работы или отправляет правки, конечная точка сравнивает домен страницы с авторизованными доменами в Лицензии. Домен вне этого списка получает `403`; сессия совместной работы браузера затем отключается и отображает причину. Сеанс повторяется, когда пользователь повторно подключается или открывает другой документ.

### Узлы совместного редактирования [#nodes]

**одноузловая лицензия**, включая бесплатный уровень, запускает один узел совместной работы.Переход `pubSub` в конечную точку заставляет конструктора бросать `LICENSE_POLICY_INVALID`.

**многоузловая лицензия** определяет предел узла. Когда число запущенных узлов превышает этот предел, новейшие узлы входят в льготный период с нарастающими предупреждениями, а затем отключаются. Новые соединения получают `503`, а существующие соединения закрываются. Узлы в пределах лимита продолжают обслуживать трафик. Если в течение льготного периода количество узлов падает обратно в пределах лимитов, дополнительные узлы возвращаются в нормальное состояние. Узел, который вышел в оффлайн, снова считается новым узлом после перезапуска его процесса. Для развертывания многоузлов см. [Развертывание](/server/deployment#несколько-узлов-совместного-редактирования).

### Типы документов [#unit-types]

В Лицензии перечислены типы документов, доступные для совместной работы. Создание Единицы любого другого типа бросает `LICENSE_UNIT_TYPE_REJECTED`, а представленные правки отвергаются. `CollaborationConflict` в браузере сообщает `reason` как `license_unit_type_rejected`. Существующие документы остаются видимыми.

## Наблюдение за состоянием [#observe]

```ts
// Service
collabService.license.status // состояние лицензии: 'not_configured' | 'expired' | 'valid'
collabService.license.editingConnectionsLimit // лимит подключений редактирования: number | null; null — без ограничений
collabService.license.nodesLimit // лимит узлов: number | null; null — без ограничений
collabService.license.domains // разрешённые домены: string[]
collabService.license.expiresAt // срок действия: строка ISO | null; null, если лицензия не настроена
collabService.license.update({ license, licenseKey }) // заменяет лицензию; при неудачной проверке выбрасывает ошибку и сохраняет текущую

// Endpoint
endpoint.license.editingConnections.limit // лимит мест: number | null; null — без ограничений
endpoint.license.editingConnections.used // занятые места: number | null; null, если limit без ограничений
endpoint.license.editingConnections.remaining // свободные места: number | null; null — без ограничений
endpoint.license.editingConnections.has(memberID) // занимает ли участник место: boolean; false, если limit без ограничений
endpoint.license.nodes.limit // лимит узлов: number | null; null — без ограничений
endpoint.license.nodes.status // состояние этого узла: 'normal' | 'exceeded' | 'exceeded-warning' | 'exceeded-offlineSoon' | 'exceeded-offline'

// События
endpoint.license.on('editingConnectionsChanged', ({ change, memberIDs, used, limit }) => {}) // места заняты или освобождены: change — 'acquired' | 'released', used — значение после изменения; не вызывается, если limit без ограничений
endpoint.license.on('editingConnectionsExceeded', ({ memberID, userID, unitID, used, limit }) => {}) // все места заняты, отправка нового подключения не сохранена
endpoint.license.on('nodesStatusChanged', ({ status, previousStatus, limit, reason }) => {}) // изменилось состояние этого узла; reason заполняется только при отключении
```

`nodesStatusChanged` запускает один раз для каждого изменения состояния этого узла.Когда `status` становится `exceeded-offline`, узел прекращает прием соединений; удалите его из балансировщика нагрузки или поднимите оповещение.
