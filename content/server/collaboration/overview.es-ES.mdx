**Univer Collaboration SDK** es un SDK de colaboración del lado del servidor para el modelo de documentos de Univer. Proporciona transformación operacional (OT), revisiones, instantáneas, sincronización en tiempo real y persistencia para que varios clientes Univer editen la misma Unit autoritativa.

Los desarrolladores lo integran en su aplicación Node.js, conectan la identidad y la autorización mediante Middleware y amplían el registro y otras funciones mediante Middleware o Events. Un Database Adapter conecta por separado los datos colaborativos con la base de datos de la aplicación.

<Callout title="No es un producto documental completo">
Collaboration SDK proporciona el núcleo colaborativo. No proporciona usuarios, roles, jerarquías, uso compartido, espacios de archivos ni flujos de negocio. Tu aplicación sigue siendo responsable de esas funciones y modelos de datos.
</Callout>

## Qué resuelve

Web SDK muestra y edita contenido Sheet, Doc, Slide, Board y Base en el navegador. La edición multiusuario también requiere un servidor autoritativo que cargue el contenido, confirme cambios concurrentes, avance las revisiones y permita que los clientes desconectados recuperen un estado coherente.

Es adecuado para aplicaciones que:

- ya usan Univer para crear un editor y necesitan edición multiusuario en tiempo real;
- quieren alojar los datos colaborativos y elegir su base de datos;
- necesitan conectar sus reglas de identidad, autorización o inquilinos con las operaciones colaborativas;
- necesitan History, Thread Comment o Worktree además de la colaboración básica.

## Qué proporciona el SDK

Las funciones principales incluyen:

- creación, carga, eliminación y recuperación de Units Sheet, Doc, Slide, Board y Base;
- instantáneas, conjuntos de cambios, revisiones, OT e idempotencia de los envíos;
- carga de contenido por HTTP y Sessions, Rooms, Presence, ACK y difusiones por WebSocket;
- Middleware en los límites de Transport, Endpoint y Service;
- Events locales al proceso para creación de Units, confirmación de cambios, eliminación y recuperación;
- contratos de Database Adapter Memory, SQLite y personalizados.

Una vez que funciona el circuito básico, la aplicación puede añadir historial de versiones, comentarios en hilos, borradores Worktree y conversión de archivos Office en el servidor. Estas funciones tienen sus propios Services, Middleware, Events o Database Adapters.

## Qué corresponde a la aplicación

| Collaboration SDK | Aplicación |
| --- | --- |
| Estado colaborativo de las Units | Usuarios, inquilinos, jerarquía y relaciones de uso compartido |
| OT, revisiones e instantáneas | Inicio de sesión, Sessions y correspondencia de identidades |
| Sessions, Rooms y Presence de colaboración | Roles, ACL y políticas del producto |
| Database Adapters de colaboración | Archivos, almacenamiento de objetos y bases de datos del producto |
| Puntos de extensión Middleware y Event | Registro, auditoría, métricas e integraciones externas |
| Endpoints del protocolo cliente | API de negocio y flujos como la creación de documentos |

## Tres puntos de extensión generales

| Punto de extensión | Problemas que resuelve |
| --- | --- |
| Middleware | Inspecciona o amplía el Context, rechaza solicitudes o registra el procesamiento durante una operación |
| Event | Observa cambios confirmados para actualizar estado derivado dentro del proceso o realizar tareas posteriores no críticas |
| Database Adapter | Selecciona el almacenamiento e implementa los contratos de atomicidad, CAS e idempotencia |

La identidad y la autorización se integran mediante Middleware. Usa Middleware para validar y restringir antes de ejecutar una operación, y Events para registrar cambios o iniciar tareas posteriores una vez confirmado el estado. Ambos pueden servir para registros, trazabilidad de solicitudes, métricas y actualización de estado derivado. Consulta [Middleware y Events](/server/collaboration/middleware-and-events) para conocer sus límites de ejecución.
