title: Descripción general del Collaboration SDK
description: Conoce qué resuelve Univer Collaboration SDK, cómo se componen sus módulos, sus puntos de extensión y las funciones de producto que conserva tu aplicación.
---

El **Univer Collaboration SDK** es un SDK de lado servidor para el modelo de documento Univer. Maneja la transformación operativa (OT[^operational-transformation]), revisiones[^collaboration-revision], instantáneas, sincronización en tiempo real y persistencia, para que varios clientes de Univer puedan editar la misma unidad autorizada.

Las aplicaciones incrustan el SDK en sus servicios Node.js. La identidad y la autorización se conectan a través de Middleware, y la logging y otra lógica de aplicación se adjuntan a Middleware o Eventos. Un adaptador de base de datos separado conecta datos de colaboración a la base de datos de la aplicación.

<Callout title="No es un producto de documento completo">
  El SDK proporciona sólo el núcleo de colaboración. Los usuarios, roles, jerarquía, compartir, espacios de archivo y flujos de trabajo de negocios están fuera de su alcance, y la aplicación todavía posee esas capacidades de producto y sus modelos de datos.
</Callout>

## Qué resuelve

El Web SDK muestra y edita Sheet, Doc, Slide, Board, Base y contenido PDF en el navegador. La edición multiusuario en tiempo real requiere una autoridad del lado del servidor en la parte superior del Web SDK. Esa autoridad carga el contenido, confirma los cambios concurrentes, avanza revisiones, y permite a un cliente desconectado recuperarse a un estado consistente.

Es adecuado para aplicaciones que:

- ya use Univer para construir un editor y desear la edición multiusuario en tiempo real;
- desea recibir datos de colaboración y elegir su propia base de datos;
- necesitan conectar sus reglas de identidad, autorización o inquilinos con las operaciones colaborativas;
- necesitan History, Thread Comment, Worktree, almacenamiento de archivos o importación y exportación de Office además de la colaboración básica.

## Qué proporciona el SDK

Las funciones principales incluyen:

- crear, cargar, eliminar y recuperar Unidades para Hoja, Doc, Diapositiva, Board, Base y PDF;
- instantáneas, conjuntos de cambios, revisiones, OT e idempotencia de los envíos;
- Carga de contenidos HTTP, junto con WebSocket Sessions, Rooms, Presence, ACKs y broadcasts;
- Middleware en los límites de Transport, Endpoint y Service;
- Events locales al proceso para creación de Units, confirmación de cambios, eliminación y recuperación;
- Aplicación de memoria, SQLite y PostgreSQL, y el contrato para un adaptador de base de datos personalizado;
- Escalada horizontal a través del despliegue de varios nodos: los nodos cooperan a través de un adaptador de pub/sub y una tienda de entradas de sesión compartida, y el SDK proporciona una implementación de Redis.

Una vez que la ruta principal está en su lugar, las aplicaciones pueden agregar historia de la versión, Comentarios de los hilos, borradores Worktree, almacenamiento de archivos y importación y exportación de la oficina del lado del servidor. Cada una de esas capacidades tiene sus propios Servicios, Middleware, Eventos o Adaptadores de bases de datos.

## Qué corresponde a la aplicación

| Collaboration SDK | Aplicación |
| --- | --- |
| Estado colaborativo de las Units | Usuarios, inquilinos, jerarquía y relaciones de uso compartido |
| OT, revisiones e instantáneas | Inicio de sesión, Sessions y correspondencia de identidades |
| Sessions, Rooms y Presence de colaboración | Roles, ACL y políticas del producto |
| Database Adapters de colaboración y archivos | Bases de datos del producto y operación del almacenamiento |
| Puntos de extensión Middleware y Event | Registro, auditoría, métricas e integraciones externas |
| Endpoints del protocolo cliente | API de negocio y flujos como la creación de documentos |

## Tres puntos de extensión generales

| Punto de extensión | Problemas que resuelve |
| --- | --- |
| Middleware | Inspecciones o enriquece Context, rechaza una solicitud, o registra lo que pasó mientras una operación se ejecuta |
| Event | Observa los cambios confirmados del estado para actualizar el estado derivado del proceso o iniciar un trabajo de seguimiento no crítico |
| Database Adapter | Selecciona dónde viven los datos e implementa los contratos de atomicidad, CAS e idempotencia |

La identidad y la autorización se conectan a través de Middleware. Middleware valida y restringe una operación antes de que se ejecute, y Eventos registra cambios o activa el trabajo de seguimiento una vez que se confirme el estado. O puede llevar registro, solicitud de localización, métricas y actualizaciones de estado derivado. [Medios y Eventos](/server/collaboration/middleware-and-events) explica dónde se ejecuta cada uno.

## Por dónde empezar

1. Ejecute el [Inicio rápido](/server/collaboration/quick-start) y compruebe la ruta completa en dos navegadores.
2. Lee [Límites y relaciones entre módulos](/server/collaboration/modules) para comprender el propósito de cada paquete.
3. Elija [Medios y Eventos](/server/collaboration/middleware-and-events), [Identidad y autorización](/server/collaboration/identity-and-authorization) o [Adaptadores de bases de datos](/server/collaboration/database-adapters) para la tarea de integración a mano.
4. Vaya a [Módulos de extensión de colaboración](/server/collaboration/extensions) para historia, comentarios, Worktrees, almacenamiento de archivos, e importación y exportación.

[^operational-transformation]: La transformación operacional (OT) ajusta operaciones concurrentes creadas sobre distintas revisiones para aplicarlas de forma coherente. Trabaja con las ediciones, sin sustituir todo el documento por la última instantánea recibida.

[^collaboration-revision]: Una revisión identifica una posición en el historial confirmado de una Unit. Un changeset contiene las operaciones de un envío; su confirmación hace avanzar el historial. No es una versión del SDK ni una marca de tiempo.
