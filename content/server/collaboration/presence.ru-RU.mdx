Присутствие показывает, у кого еще открыт тот же документ и где работает каждый человек. Когда Боб выбирает ячейку B3, например, Алиса видит его выбор с пометкой «Боб». Приложения также могут отображать текущих сотрудников в аватаре или списке членов.

SDK синхронизирует информацию о членстве и курсоре и отображает удаленные курсоры, где редактор поддерживает их. Имена коллаборационистов и аватары предоставляются приложением, а API подписки участника доступен для баров аватара, панелей участников и онлайн-счетов пользователей.

## Перед началом

Сначала заполните [Быстрый старт](/server/collaboration/quick-start) и [Идентификация и авторизация](/server/collaboration/identity-and-authorization). В этот момент редактор должен синхронизировать правки, сервер должен идентифицировать подписанного пользователя через `context.userID`, и должны быть введены политики чтения, JOIN и редактирования.

Приведенные ниже примеры расширяют существующую настройку `transport`, `endpoint` и `univer`. Сохраняют правила аутентификации и авторизации из предыдущего руководства.

## Синхронизация участников и курсоров

Алиса и Боб открывают одну и ту же электронную таблицу. Присутствие производит два вида обновлений:

| Действие | Список участников | Что видит Alice в таблице |
| --- | --- | --- |
| Alice открывает таблицу | Alice | Своё выделение |
| Bob открывает ту же таблицу | Alice, Bob | Выделение Bob при выборе ячейки |
| Bob переходит из B3 в C5 | Alice, Bob | Выделение Bob перемещается в C5 |
| Bob закрывает таблицу | Alice после получения выхода | Выделение Bob исчезает |

Список участников изменяется, когда соединение присоединяется или уходит. Перемещение курсора изменяет только выбор, нарисованный в редакторе; он не добавляет или не удаляет участник. Если Боб также редактирует значение в C5, содержание документа синхронизируется через поток редактирования совместной работы.

Присутствие охватывает людей, которые в настоящее время подключены к этому документу, в то время как список доступа, настроенный в предыдущем руководстве, охватывает всех, кому разрешено его открыть. Присутствие является временным: движение курсора не создает изменения, не продвигает пересмотр документа и не сохраняется в базе данных.

С помощью плагинов для совместной работы от Quick Start и включенного пользовательского интерфейса соответствующего редактора SDK захватывает локальные обновления курсора и выбора, отправляет их и отображает соответствующие курсоры, выборы и имена в редакторах других членов.

| Редактор | Подписка на участников | UI удалённых курсоров и выделений |
| --- | --- | --- |
| Sheet | Поддерживается | Выделение ячеек и диапазонов |
| Doc | Поддерживается | Текстовые курсоры и выделения |
| Slide | Поддерживается | Положение указателя и выбор объектов |
| Board | Поддерживается | Положение указателя и выбор объектов |
| Base | Поддерживается | Недоступен |

## 1. Настройка имён и аватаров

Установите `context.member.name` и `context.member.avatar` в промежуточном ПО `connect` от Endpoint. Приложение решает, как извлечь профиль: запросить его с помощью аутентифицированного `context.session.userID` или повторно использовать данные, сохраненные во время аутентинации в `customData`.

В этом примере используется `customData`, чтобы избежать повторного поиска. Добавьте эти поля в существующее транспортное промежуточное ПО и зарегистрируйте `connect` перед запуском сервера:

```ts
type AppUser = {
  id: string;
  name: string;
  avatar?: string;
};

transport.use(async (context, next) => {
  // Your authentication function; rejects unauthenticated requests.
  const user: AppUser = await auth.requireUser(context.incomingMessage);
  context.userID = user.id;
  // An application-defined field to reuse the profile in connect.
  context.customData.user = user;
  await next();
});

endpoint.use("connect", async (context, next) => {
  // Read the profile saved when the session ticket was issued.
  const user = context.session.customData.user as AppUser;
  // Without this assignment, the member name defaults to userID.
  context.member.name = user.name;
  // Use an empty string when there is no avatar URL.
  context.member.avatar = user.avatar ?? "";
  await next();
});
```

SDK передает `customData` из запроса сеансового билета в `context.session.customData`. В многоузловом развертывании отправитель, подключенный к другому узлу, поступает только с `userID` и `memberID`, поэтому данные, которые должны путешествовать с каждым сообщением, принадлежат полезной нагрузке Presence. Ключ `user` а также тип `AppUser` являются вариантами приложений; SDK их не интерпретирует. Другие сотрудники получают профиль, назначенный `context.member` .

`connect` запускается один раз для каждого нового соединения WebSocket, включая переподключение, и всегда до того, как клиент присоединяется к документу.При изменении профиля в приложении профили участников, уже совместно используемые с существующими соединениями, не обновляются автоматически.

## 2. Список участников (необязательно)

Чтобы построить аватар-бар или панель участника, подпишитесь на участников открытого документа с помощью `subscribeCollaborators(unitID, callback)`. От этой подписки не зависит рендеринг курсора.

```ts
import { FUniver } from "@univerjs/core/facade";
// Import once in the client entry point to enable collaboration Facade methods.
import "@univerjs-pro/collaboration-client/facade";

// Reuse an existing univerAPI if your editor setup already provides one.
const univerAPI = FUniver.newAPI(univer);
// unitID is the ID of the document open in the editor.
const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, (members) => {
  // Each callback is a new list snapshot that the application can use to update its UI.
  console.table(members);
});
```

SDK ожидает появления комнаты для совместной работы документа. Каждый обратный звонок получает снимок `IMember[]` участников, известных клиенту в настоящее время, включая самого клиента, как только он присоединился. Пустой список может прибыть во время инициализации. Обратный вызов сообщает о членстве, а не о позициях курсора.

Данные Alice и Bob содержат такие поля (ID приведены для примера):

| `userID` | `memberID`                             | `name`  | `avatar` |
| -------- | -------------------------------------- | ------- | -------- |
| `alice`  | `83446a72-a1cc-4ed8-aedc-afd8907bbb18` | `Alice` | `""`     |
| `bob`    | `7ee5a94e-c784-4e1e-b1a3-b9d34be8ec4e` | `Bob`   | `""`     |

`userID` идентифицирует человека в приложении. `memberID` определяет одно соединение и назначается SDK. Если Боб открывает вторую вкладку, список получает другую запись с `userID: "bob"`, а также другой `memberID`. Теперь есть два пользователя и три соединения. Приложения могут группироваться `userID` для аватаров или онлайн-счета пользователей, или использовать `memberID` чтобы отображать и считать соединения. Редактор отображает курсор каждого соединения отдельно.

Отпустите подписку, когда вид, который ее использует, будет удален:

```ts
subscription.dispose();
```

Удалите созданный приложением экземпляр `univerAPI` и Univer, когда редактор будет уничтожен. Закрытие только панели участника требует удаления только подписки этой панели.

### Пример списка участников на React

Передайте существующий `univerAPI` и ID документа в этот компонент:

```tsx
import type { FUniver } from "@univerjs/core/facade";
import type { IMember } from "@univerjs/protocol";
import "@univerjs-pro/collaboration-client/facade";
import { useEffect, useState } from "react";

export function OnlineMembers({ univerAPI, unitID }: { univerAPI: FUniver; unitID: string }) {
  const [members, setMembers] = useState<IMember[]>([]);

  useEffect(() => {
    // Clear the previous document list while waiting for the new subscription.
    setMembers([]);
    const subscription = univerAPI.getCollaboration().subscribeCollaborators(unitID, setMembers);
    // Unsubscribe when the document changes or the component unmounts.
    return () => subscription.dispose();
  }, [univerAPI, unitID]);

  // Show each user once, even when they have multiple connections.
  const users = [...new Map(members.map((member) => [member.userID, member])).values()];

  return (
    <ul>
      {users.map((user) => (
        <li key={user.userID}>
          {user.avatar && <img src={user.avatar} alt="" width={24} height={24} />}
          <span>{user.name}</span>
        </li>
      ))}
    </ul>
  );
}
```

Подписка отражает последнее членство в комнате, полученное клиентом. Потерянное соединение требует времени для обнаружения, поэтому уходящий член может оставаться в списке кратко. Встроенный пользовательский интерфейс статуса совместной работы SDK обеспечивает состояние синхронизации текущего клиента, офлайн-индикацию и действие повторного подключения.

## Проверка с двумя пользователями

1. Войдите как Alice и Bob в разных профилях браузера и откройте один документ.
2. Убедитесь, что в списке оба имени.
3. В листе выберите B3 в качестве Боба, а затем C5. Алиса должна увидеть названный ход выбора Боба, в то время как список участников остается неизменным.
4. Откройте еще одну вкладку в качестве Боба. Подписка должна включать еще один `memberID`, а список React должен по-прежнему отображать Боба один раз.
5. Закройте обе вкладки Bob. После обновлений выхода у Alice должна остаться только Alice.
