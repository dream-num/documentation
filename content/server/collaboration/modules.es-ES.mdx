Univer La colaboración consiste en un cliente del navegador y un conjunto de módulos del lado del servidor. Cada módulo posee una clase de responsabilidad. Las aplicaciones componen los módulos a través de interfaces públicas, por lo que su código no depende de los internos de la implementación OT[^operational-transformation], el protocolo o la capa de persistencia.

## Collaboration Client

El navegador Collaboration Client corre junto al Web SDK y maneja el lado cliente de la colaboración:

- Pide instantáneas de la unidad y cualquier cambio confirmado que no está.
- Utiliza un boleto de sesión de una sola vez para abrir una conexión WebSocket.
- Se une a Unit Rooms e intercambia Presence con otros miembros.
- Presenta mutaciones locales al servidor como cambiaformas.
- Recibe ACKs y transmisiones, y después de una reconexión, sembra los cambios que perdió.

El Cliente no determina si un usuario es confiable, y no es la fuente de datos autorizada. Esa decisión pertenece al servidor, que impone la identidad y la autorización en el correspondiente Middleware.

## Node Transport

`@univerjs-pro/collaboration-transport-node` es el punto de entrada Node.js para el tráfico HTTP y WebSocket. Recibe solicitudes y actualizaciones WebSockets desde el servidor HTTP host, ejecuta la entrada Middleware registrado por la aplicación, y rutas de tráfico a Endpoints.

El transporte no comprende los modelos OT, Unit data o ACL. Assembly utiliza tres métodos:

```ts
transport.use(httpMiddleware);
transport.useUpgrade(upgradeMiddleware);
transport.register(endpoint);
```

- `use()` maneja solicitudes HTTP ordinarias y puede establecer `userID`, `customData` , registros , o trazas .
- `useUpgrade()` maneja el apretón de manos WebSocket y puede rechazar la conexión antes de que se establezca.
- `register()` registra un protocolo Endpoint, cuyo ciclo de vida el Transporte entonces maneja.

## Collaboration Endpoint

`@univerjs-pro/collaboration-endpoint` implementa el protocolo utilizado por el Cliente de Colaboración Univer y posee las siguientes capacidades:

| Función | Responsabilidad de Endpoint |
| --- | --- |
| Carga de contenido | Devuelve instantáneas y bloques de la unidad, junto con cualquier cambio confirmado que el cliente carece |
| Envío de cambios | Recibe cambios, devuelve ACK y difunde cambios confirmados a la Room |
| Conexión Session | Temas de sesión de una sola vez Tickets, luego establece y mantiene WebSocket Sessions |
| Colaboración Room | Gestiona JOIN, LEAVE, estado de miembros y Presence |
| Ciclo de vida Unit | Asocia solicitudes de eliminación y recuperación con llamadas Service |
| Varios nodos | Relays Rooms, Presence y transmisiones a través de nodos a través de un adaptador opcional de pub/sub y una tienda de entradas compartida |

El Endpoint no realiza OT y no almacena datos de colaboración en sí mismo. Obtiene el resultado autorizado del Servicio y los mapas que dan lugar al protocolo del Cliente. Operaciones de productos como la creación de un documento pertenecen a una API de aplicación que llama al Servicio.

## Collaboration Service

`@univerjs-pro/collaboration-service` es el núcleo de colaboración y no depende de la red. Cubre la hoja, Doc, Slide, Board, Base y PDF:

- Lee datos de recuperación de la unidad y cambios confirmados.
- Crea Unidades de Datos de Unidad o instantáneas.
- Presentar un cambio de funcionamiento OT y adelanta la revisión continua[^collaboration-revision].
- Identifica las presentaciones duplicadas a través de `(unitID, sid, reqId)`.
- Suave-deletes, recupera o elimina permanentemente Unidades.
- Funciona Service Middleware y emite Eventos después de la confirmación.

El Servicio no tiene capa HTTP o WebSocket, y no sabe sobre usuarios, roles, ACLs, jerarquía o gestión de archivos. El Endpoint construye el protocolo del navegador en la parte superior del Servicio. Las aplicaciones también pueden llamar la API pública del Servicio directamente desde APIs de negocios o tareas de fondo.

### API principales

| Función | API de Service |
| --- | --- |
| Cargar Unit | `getUnitLoadData()`, `getUnitLoadDataWithBlocks()` |
| Leer datos incrementales | `getChangesets()`, `getSheetBlock()` |
| Crear Unit | `createUnitFromData()`, `createUnitFromSnapshot()` |
| Enviar cambios | `submitChangeset()` |
| Eliminar y recuperar | `deleteUnits()`, `recoverUnits()` |

## Database Adapter

Es el contrato entre Service y almacenamiento. Debe garantizar:

- creación atómica de instantánea inicial y dependencias;
- comparación e intercambio de revisión;
- idempotent changeset submission;
- la visibilidad instantánea sólo después de que todas sus dependencias existan;
- lotes del ciclo de vida Unit de todo o nada.

La aplicación conecta el almacenamiento mediante `IDatabaseAdapter`. Para elegir un adaptador integrado o implementar uno propio, consulta la guía de [adaptadores de base de datos](/server/collaboration/database-adapters).

## Cuatro conceptos principales

| Concepto | Significado |
| --- | --- |
| Unit | Contenido Univer de carga independiente y colaborativo, con un `unitID` único y un tipo |
| Snapshot | El contenido de la unidad persiste en una revisión, no en el objeto mutable en vivo |
| Changeset | Un lote de mutaciones presentadas conjuntamente, con una revisión de base y una identidad para la idempotencia |
| Revision | El número de versión continua del estado de unidad confirmado, comenzando en `1` |

Todos los cambios en el contenido de ejecución pasan por Facade APIs o Comandos. Mutar un objeto de instantáneas no actualiza la Unidad en vivo en el Cliente o el Servicio.

El `userID/customData` establecido por Transport Middleware viaja con la actual solicitud HTTP en Service Middleware. La aplicación decide si se permite una lectura. Un cliente no necesita unirse a una habitación antes de leer sobre HTTP simple.

## Enviar una edición

```text
Facade / Command
  → Mutation
  → Changeset del Client
  → envío a Endpoint
  → Middleware de Service
  → OT + CAS de revisión
  → commit atómico de Adapter
  → Changeset confirmado
  → ACK / difusión a Room
```

La revisión confirmada en el Adaptador de Bases de Datos es el estado autoritativo. ACKs y transmisiones mantienen a los clientes en línea sincronizados con baja latencia. Un cliente que pierde un mensaje puede buscar los cambios confirmados que falta utilizando la revisión que ya sabe.

## Montaje mínimo del servidor

```ts
import { createServer } from "node:http";

import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

const server = createServer();
transport.attach(server);
server.listen(3010);
```

El usuario codificado y el adaptador de memoria sólo muestran montaje de módulos. Aplicaciones reales establecen Contexto a través de Middleware y selecciona un adaptador que se ajuste a sus requisitos de datos.

### Crear una Unit con una API de aplicación

Las aplicaciones pueden definir sus propios puntos finales HTTP o RPC y llamar al `service` creado anteriormente después de la autenticación, validación de entrada y cheques de negocio pasan:

```text
Cliente de negocio
  → POST /api/units
  → autenticación y validación de la aplicación
  → service.createUnitFromData()
  → Database Adapter
```

El ejemplo Express a continuación supone que la autenticación Middleware ha establecido `response.locals.user` y que `request.body.data` ya ha sido validada como Datos del Cuaderno de Trabajo:

```ts
import { randomUUID } from "node:crypto";

import { json } from "express";
import { UniverType } from "@univerjs/protocol";

app.post("/api/units", json({ limit: "1mb" }), async (request, response, next) => {
  try {
    const user = response.locals.user as { readonly userID: string };
    const unitID = randomUUID();

    const result = await service.createUnitFromData(
      {
        type: UniverType.UNIVER_SHEET,
        data: {
          ...request.body.data,
          id: unitID,
          rev: 1,
        },
      },
      {
        userID: user.userID,
        customData: { traceID: randomUUID() },
      },
    );

    response.status(result.status === "created" ? 201 : 200).json(result);
  } catch (error) {
    next(error);
  }
});
```

`POST /api/units` es una ruta de aplicación y no forma parte del protocolo del cliente de colaboración. Llamando a `createUnitFromData()` sigue ejecutando el `createUnit` Middleware del Servicio. Registros de productos, ACLs propietario, asignación de responsabilidad de errores y compensación de fallos siguen siendo la responsabilidad de la aplicación.

## Liberar recursos

`transport.dispose()` dispone los puntos finales registrados con `register()`. El Servicio y el Adaptador de bases de datos que la aplicación inyectada debe ser eliminado por separado, en el reverso de la orden de montaje:

```ts
await transport.dispose();
await service.dispose();
await database.dispose();
```

Si la aplicación suministra un adaptador de pub/sub, también debe disponer de ese adaptador y sus conexiones después del Transporte. El Endpoint no los dispone.

Para ampliar el comportamiento en estos límites de módulos, continúe con [Medios y Eventos](/server/collaboration/middleware-and-events).

[^operational-transformation]: La transformación operacional (OT) ajusta operaciones concurrentes creadas sobre distintas revisiones para aplicarlas de forma coherente. Trabaja con las ediciones, sin sustituir todo el documento por la última instantánea recibida.

[^collaboration-revision]: Una revisión identifica una posición en el historial confirmado de una Unit. Un changeset contiene las operaciones de un envío; su confirmación hace avanzar el historial. No es una versión del SDK ni una marca de tiempo.
