Сотрудничество соединяет редакторы браузера с одним общим сервисом документов. Когда два пользователя открывают одну и ту же электронную таблицу, в одном браузере появляется редактирование в другом.

Настройка бэкэнда сначала через [Серверная интеграция](/server). Конфигурация редактора и загрузка документов, описанные ниже, следуют за ней. Парный сервер и веб-код находятся в [Сотрудничество Quick Start](/server/collaboration/quick-start) .

## Подключение существующего редактора

Не требуется другой редактор. Сохраните существующий редактор Web SDK и следуйте за [Конфигурация браузера в Quick Start](/server/collaboration/quick-start), чтобы добавить плагины для совместной работы, а затем настройте загрузку документов, отправку редактирования и адрес WebSocket. Версии браузера и пакета сервера должны оставаться совместимыми.

Фиксированные примеры пользователей и разрешения по умолчанию предназначены для демонстрации. В приложении отправляйте учетные данные входа с каждым запросом, чтобы бэкэнд мог проверить личность и доступ к документу. Лицензирование покрывается [Конфигурация лицензии](/server/license).

## Настройка плагинов [#client-configuration]

### Пакетная отправка и интервалы повторов [#client-retry-timeouts]

`UniverCollaborationClientPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `socketService` | `Ctor<ICollaborationSocketService>` |  | Выбирает реализацию сокета, используемую текущим временем выполнения. |
| `sendChangesetTimeout` | `number` | `2000 ms` | Устанавливает, как долго локальные правки буферизируются перед отправкой. |
| `changesetAckTimeout` | `number` | `20000 ms` | Устанавливает, как долго ждать подтверждения перед повторным использованием. |
| `maxChangesetAckTimeout` | `number` | `120000 ms` | Устанавливает верхнюю границу на интервале между пересылками. |

Задержка пакетирования и тайм-аут подтверждения являются отдельными таймерами. По умолчанию плагин клиента `sendChangesetTimeout: 2000`, `changesetAckTimeout: 20000` и `maxChangesetAckTimeout: 120000` используют тайм-оут также. Изменения, которые никогда не признаются, возмущены экспоненциальным обратным выключением, ограниченным по максимуму. Установка тайм-Аут подтверждения и максимальный тайм-авт к тому же значению создает постоянный интервал.

```ts
import { UniverCollaborationClientPlugin } from '@univerjs-pro/collaboration-client'
import { BrowserCollaborationSocketService } from '@univerjs-pro/collaboration-client-ui'

univer.registerPlugin(UniverCollaborationClientPlugin, {
  socketService: BrowserCollaborationSocketService,
  sendChangesetTimeout: 200,
  changesetAckTimeout: 20_000,
  maxChangesetAckTimeout: 120_000,
})
```

Добавьте эти опции к существующей регистрации клиента и сохраните конфигурацию разъема и конечной точки. Предустановки совместной работы Sheets и Docs используют задержку пакетирования 200 мс и не выставляют опции тайм-аута подтверждения, поэтому настройка этих тайм-уаутов требует режима плагина.

## Настройка пресетов [#client-preset-configuration]

`UniverSheetsCollaborationPreset / UniverDocsCollaborationPreset`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `enableDefaultConflictUI` | `boolean` | `true` | Показывает встроенные уведомления о восстановлении конфликта. |

```ts
import { UniverSheetsCollaborationPreset } from '@univerjs/preset-sheets-collaboration'

const collaborationPreset = UniverSheetsCollaborationPreset({ enableDefaultConflictUI: false })
```

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'

const collaborationPreset = UniverDocsCollaborationPreset({ enableDefaultConflictUI: false })
```

По умолчанию пользовательский интерфейс показывает уведомление о конфликте, которое называет причину. Уведомление предлагает перезагрузку после успешной очистки кэша и повторную попытку, если очистка не удалась. Чтобы запустить поток восстановления в приложении, установите `enableDefaultConflictUI: false` в существующей инициализации и обработайте событие напрямую.

Добавьте предустановки совместной работы к существующему вызову `createUniver({ presets: [...] })`, рядом с предустанавливаемым редактором, и сохраните настройки конечной точки и истории. См. [полезные грузы событий](#conflict-recovery) и [клиентская конфигурация](/reference/packages/plugins/univerjs-pro/collaboration-client).

## Создание и открытие одного документа

Создание документа и открытие его – это отдельные действия:

1. Когда пользователь создает документ, бэкэнд сохраняет его и возвращает его идентификатор.
2. Браузер загружает этот ID. Повторно используйте тот же идентификатор, когда документ снова открывается или передается другому пользователю.

API называет документ ID `unitId`. Не создавайте новый локальный пустой документ при каждом посещении.

Задайте текущего пользователя до загрузки документа. Он определяет личность участника и владельца локального офлайн-кэша; см. [Идентификация и авторизация](/server/collaboration/identity-and-authorization).

Например, после регистрации Специфических листов и плагинов для совместной работы, загрузите электронную таблицу с сервера:

```ts
import { UserManagerService } from '@univerjs/core'
import '@univerjs-pro/collaboration-client/facade'

univer.__getInjector().get(UserManagerService).setCurrentUser({ userID, name, avatar })

const workbook = await univerAPI.getCollaboration().loadSheetAsync('your-document-id')
if (!workbook) throw new Error('Document could not be loaded')
```

Специфическая загрузка продукта описана в руководствах [Листовки](/guides/sheets/features/collaboration), [Док](/guides/docs/features/collaboration), [Скольжения](/guides/slides/features/collaboration), [Советы](/guides/boards/features/collaboration), [Основания](/guides/bases/features/collaboration) и [PDF](/guides/pdfs/features/collaboration). Подтвердите, что продукт и бэкэнд-релиз поддерживают эту функцию.

## Проверка синхронизации, сохранения и прав

Откройте один и тот же документ в двух независимых сеансах браузера, таких как обычное окно и приватное. Редактируйте в одном сеансе и проверяйте, что показывает другой. Затем перезагрузите страницу, переподключите, перезапустите сервер и подтвердите, что контент все еще присутствует.

Тестирование как редактора, зрителя и пользователя без доступа.Настройки пользовательского интерфейса только для чтения контролируют только то, что позволяет страница; сервер должен по-прежнему отклонять несанкционированные чтения и изменения.

Если документы загружаются, но редактирование не синхронизируется, проверьте соединение WebSocket. Если контент исчезает после перезагрузки, проверяйте бэкэнд-хранилище. Эти настройки принадлежат [Серверная интеграция](/server).

## Состояние синхронизации и повторные отправки [#sync-status]

Импортировать коллаборацию Facade перед регистрацией слушателей. `CollaborationStatusChanged` сообщает о текущем состоянии каждого уже сотрудничающего подразделения при регистрации слушателя, затем сообщает об изменениях без повторения последовательных идентичных статусов. `hasWritePending(unitId)` охватывает очерченные правки, правки, ожидающие подтверждения, и автономные правки. Если идентификатор опущен, он проверяет сфокусированный блок. Подключенный сокет не означает, что правки сохранены.

```ts
import '@univerjs-pro/collaboration-client/facade'

const collaboration = univerAPI.getCollaboration()
const statusSubscription = univerAPI.addEvent(univerAPI.Event.CollaborationStatusChanged, (event) => {
  console.info(event.unitId, event.status, collaboration.hasWritePending(event.unitId))
})
const resendSubscription = univerAPI.addEvent(univerAPI.Event.CollaborationChangesetResend, (event) => {
  console.info(event.unitId, event.reason, event.attempt, event.unsyncedMutationCount, event.nextDelayMs)
})
```

`CollaborationChangesetResend` пожары на пересылках, а не на первом представлении.Причины `ack_timeout`, `request_failed`, `license_editing_connections_exceeded`, `should_retry` и `reconnect`; `attempt`, `elapsedMs`, `unsyncedMutationCount` и `nextDelayMs` предоставляют данные, необходимые для индикатора сохранения или повторного использования. Удалите подписки на события, когда редактор удален.

`request_failed` означает отказ в повторном запросе, такой как сетевая ошибка или ответ HTTP 408, 429 или 5xx. `license_editing_connections_exceeded` - все лицензированные соединения редактирования используются, и сервер запрашивает повторную отправку.

## Обработка конфликтов приложением [#conflict-recovery]

`CollaborationConflict` стреляет один раз, когда устройство вступает в конфликт, после попытки очистки офлайн-кэша. Зарегистрируйте слушателя перед загрузкой любых документов. Его `reason` - `transform_failed`, `apply_failed`, `changeset_rejected`, `license_unit_type_rejected`, `permission_rejected` или `remote_revert`; `message` и `revert` предоставляют дополнительную информацию, когда это доступно.

`license_unit_type_rejected` означает, что лицензия сервера не поддерживает совместное редактирование документов этого типа.

```ts
import type { IEventParamConfig } from '@univerjs/core/facade'
import '@univerjs-pro/collaboration-client/facade'

const conflicts = new Map<string, IEventParamConfig['CollaborationConflict']>()
const conflictSubscription = univerAPI.addEvent(univerAPI.Event.CollaborationConflict, (event) => {
  conflicts.set(event.unitId, event)
})
```

Пример сохраняет событие для экрана восстановления хоста. Карта живет только в памяти, поэтому приложение должно сохранить или экспортировать любой `localChanges` перед обновлением. Это событие является единственной возможностью сохранить их; данные кэша, которые уже были очищены, не могут быть восстановлены более поздним чтением. `awaitingChangeset`, возможно, уже был применен на сервере, поэтому его не следует воспроизводить вслепую.

`cacheCleared: false` означает, что обновление будет воспроизводить старые кэшированные правки, поэтому очистка кеша должна быть решена до обновления. Очистка кэша не означает, что несинхронизированные правки были сохранены. Конфликт `permission_rejected` также требует разрешения доступа; перезагрузка не дает разрешения.

## Причины сервера и уведомления о лицензии [#server-rejections]

Когда сервер отклоняет изменение, `CollaborationConflict.message` несет причину, которую сервер дал, если он дал. Не анализируйте локализованный текст сообщения, чтобы решить действие восстановления; вместо этого ветвь на `reason`. `license_unit_type_rejected` требует лицензии сервера, которая охватывает тип документа, в то время как `license_editing_connections_exceeded` является сигналом повторной отправки: изменения остаются непризнанными и продолжают повторную проверку. Держите редактор открытым, пока `hasWritePending(unitId)` не станет ложным или приложение не сохранило изменения.

Пользовательский интерфейс по умолчанию отображает уведомление о емкости редактирования и, при повторной отправке, по крайней мере, через 20 секунд после первой отправки, уведомление о сэкономлении времени. Они удаляются, когда устройство покидает ожидающие состояния или удаляется. Отказ домена также имеет специальное уведомление. `enableDefaultConflictUI: false` отключает только уведомления о восстановлении конфликта; он не отключает эти уведомления о ожидании или домене.
