Univer Collaboration 由瀏覽器端的 Client 和一組伺服器端模組組成。每個模組負責一類職責。應用透過公開介面完成組裝，因此業務程式碼不需要了解 OT[^operational-transformation] 實現、協議細節或持久化層的內部結構。

## Collaboration Client

瀏覽器端的 Collaboration Client 與 Web SDK 一同執行，負責協同中屬於客戶端的工作：

- 向伺服器端請求 Unit snapshot，以及自身缺失的 confirmed changeset。
- 使用一次性 Session Ticket 建立 WebSocket 連線。
- 加入 Unit Room，並與其他成員交換 Presence。
- 將本地 mutation 以 changeset 的形式提交到伺服器端。
- 接收 ACK 與廣播，並在重連後補齊漏掉的內容。

Client 不判斷使用者是否可信，也不是權威資料來源。該判斷由伺服器端負責，伺服器端在相應的 Middleware 中執行身分與權限策略。

## Node Transport

`@univerjs-pro/collaboration-transport-node` 是 Node.js 側的 HTTP 與 WebSocket 入口。它從宿主 HTTP Server 接收請求和 WebSocket upgrade，執行應用註冊的入口 Middleware，再將流量路由到 Endpoint。

Transport 不涉及 OT、Unit 資料或 ACL 模型。組裝時使用以下三個方法：

```ts
transport.use(httpMiddleware);
transport.useUpgrade(upgradeMiddleware);
transport.register(endpoint);
```

- `use()` 處理普通 HTTP 請求，`userID`、`customData`、日誌與 trace 均在此建立。
- `useUpgrade()` 處理 WebSocket handshake，可在連線建立之前拒絕該連線。
- `register()` 註冊協議 Endpoint，此後其生命週期由 Transport 管理。

## Collaboration Endpoint

`@univerjs-pro/collaboration-endpoint` 實現了 Univer Collaboration Client 使用的協議，負責以下能力：

| 能力 | Endpoint 職責 |
| --- | --- |
| 內容載入 | 返回 Unit snapshot 與 block，以及 Client 缺失的 confirmed changeset |
| 變更提交 | 接收 changeset，返回 ACK，並將 confirmed changeset 廣播到 Room |
| Session 連線 | 簽發一次性 Session Ticket，建立並維護 WebSocket Session |
| Room 協同 | 處理 JOIN、LEAVE、成員狀態與 Presence |
| Unit 生命週期 | 將刪除與恢復請求對映為對應的 Service 呼叫 |
| 多節點 | 透過可選的 pub/sub 介面卡與共享的 Session Ticket 儲存，將 Room、Presence 與廣播轉發到其他節點 |

Endpoint 本身不執行 OT，也不直接儲存協同資料。它向 Service 取得權威結果，再將結果對映回 Client 協議。建立文件這類產品操作應由應用 API 呼叫 Service 完成。

## Collaboration Service

`@univerjs-pro/collaboration-service` 是協同核心，不依賴網路，覆蓋 Sheet、Doc、Slide、Board、Base 與 PDF：

- 讀取 Unit 的恢復資料與 confirmed changeset。
- 從 Unit Data 或快照建立 Unit；
- 提交 changeset 時執行 OT，並推進連續 revision[^collaboration-revision]。
- 透過 `(unitID, sid, reqId)` 識別重複提交；
- 軟刪除、還原或永久刪除 Unit；
- 執行 Service Middleware，並在確認後發出 Event。

Service 不包含 HTTP 與 WebSocket 層，也不涉及使用者、角色、ACL、目錄或檔案管理。Endpoint 在 Service 之上實現瀏覽器協議；應用也可以直接在業務 API 或後臺任務中呼叫其公開 API。

### 核心 API

| 能力 | Service API |
| --- | --- |
| 載入 Unit | `getUnitLoadData()`、`getUnitLoadDataWithBlocks()` |
| 讀取增量資料 | `getChangesets()`、`getSheetBlock()` |
| 建立 Unit | `createUnitFromData()`、`createUnitFromSnapshot()` |
| 提交變更 | `submitChangeset()` |
| 刪除與還原 | `deleteUnits()`、`recoverUnits()` |

## Database Adapter

Database Adapter 是 Service 與儲存之間的合同，必須保證以下事項：

- 初始 snapshot 及其依賴資料的原子建立；
- 修訂版本比較並交換（CAS）；
- changeset 提交的冪等性；
- 依賴全部就位後，snapshot 才對讀取可見；
- Unit 生命週期批次的全有或全無。

應用程式透過 `IDatabaseAdapter` 接入儲存服務。如何選擇內建配接器或實作自訂配接器，請參閱 [Database Adapter](/server/collaboration/database-adapters)。

## 四個核心概念

| 概念 | 意義 |
| --- | --- |
| Unit | 一份 Univer 內容，有唯一的 `unitID` 和型別，可以獨立載入、獨立協同 |
| Snapshot | Unit 在某個 revision 上持久化下來的內容，不是執行中的可變物件 |
| Changeset | 一次提交中包含的 mutation 集合，帶 base revision 和用於冪等的身分標識 |
| Revision | Unit 已確認狀態的連續版本號，初始值為 `1` |

執行中的內容只能透過 Facade 或 Command 修改。修改 snapshot 物件不會更新 Client 或 Service 中的 live Unit。

## 載入 Unit

<Mermaid chart={"sequenceDiagram\n    participant Client\n    participant Transport\n    participant Endpoint\n    participant Service\n    participant Adapter\n\n    Client->>Transport: 透過 HTTP 載入 Unit\n    Transport->>Endpoint: 已驗證的請求 Context\n    Endpoint->>Service: getUnitLoadData()\n    Service->>Adapter: 快照 + 變更集\n    Adapter-->>Service: 權威資料\n    Service-->>Endpoint: Unit 載入資料\n    Endpoint-->>Client: 協定回應"} />

Transport Middleware 建立的 `userID/customData` 會隨當前 HTTP 請求傳入 Service Middleware。是否允許本次讀取由應用策略決定。透過 HTTP 直接讀取之前，客戶端不需要先加入 Room。

## 提交編輯

```text
Facade / Command
  → Mutation
  → Client 變更集
  → Endpoint 提交
  → Service Middleware
  → OT + 修訂版本 CAS
  → Adapter 原子提交
  → 已確認變更集
  → ACK / Room 廣播
```

Database Adapter 中的 confirmed revision 是權威狀態。ACK 與廣播使線上客戶端以較低的延遲保持同步。客戶端如果漏掉訊息，可以使用已知的 revision 拉取缺失的 confirmed changeset。

## 最小服務端組裝

```ts
import { createServer } from "node:http";

import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

const server = createServer();
transport.attach(server);
server.listen(3010);
```

此處寫死的使用者與 Memory Adapter 僅用於演示模組的組裝方式。真實應用透過 Middleware 建立 Context，並根據自身資料需求選擇 Adapter。

### 透過應用 API 建立 Unit

應用可以自行定義 HTTP 或 RPC 介面，在認證、參數校驗與業務檢查透過後，呼叫上文建立的 `service`：

```text
業務用戶端
  → POST /api/units
  → 應用驗證身分與輸入
  → service.createUnitFromData()
  → Database Adapter
```

下面的 Express 範例假設認證 Middleware 已設定 `response.locals.user`，且 `request.body.data` 已按 Workbook Data 完成校驗：

```ts
import { randomUUID } from "node:crypto";

import { json } from "express";
import { UniverType } from "@univerjs/protocol";

app.post("/api/units", json({ limit: "1mb" }), async (request, response, next) => {
  try {
    const user = response.locals.user as { readonly userID: string };
    const unitID = randomUUID();

    const result = await service.createUnitFromData(
      {
        type: UniverType.UNIVER_SHEET,
        data: {
          ...request.body.data,
          id: unitID,
          rev: 1,
        },
      },
      {
        userID: user.userID,
        customData: { traceID: randomUUID() },
      },
    );

    response.status(result.status === "created" ? 201 : 200).json(result);
  } catch (error) {
    next(error);
  }
});
```

`POST /api/units` 是應用自己的路由，不屬於 Collaboration Client 協議。呼叫 `createUnitFromData()` 時，Service 的 `createUnit` Middleware 仍會執行。產品記錄、owner ACL、錯誤響應對映與失敗補償仍由應用負責。

## 資源清理

`transport.dispose()` 釋放透過 `register()` 註冊的 Endpoint。應用注入的 Service 與 Database Adapter 需要分別釋放，順序與組裝時相反：

```ts
await transport.dispose();
await service.dispose();
await database.dispose();
```

如果應用提供了 pub/sub 介面卡，還應在釋放 Transport 之後釋放該介面卡及其連線。Endpoint 不會代為釋放。

如需在上述模組邊界上擴充套件行為，請繼續閱讀 [Middleware 與 Event](/server/collaboration/middleware-and-events)。

[^operational-transformation]: *操作轉換（OT）* 會調整基於不同文件修訂號並行產生的操作，使它們能一致地套用。它處理的是編輯操作，而非用最後抵達的快照覆蓋整份文件。

[^collaboration-revision]: 修訂號（revision）標示 Unit 已確認編輯歷史中的位置。變更集（changeset）包含一次提交的操作，確認後會推進歷史。修訂號不是 SDK 套件版本，也不是時間戳記。
