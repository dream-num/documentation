Esta página describe dos caminos. La primera ejecuta el ejemplo oficial y verifica la ruta completa de colaboración en dos navegadores. La segunda presenta el servidor mínimo y la asamblea web, que puede copiar en su propia aplicación Univer.

Antes de empezar, cumple los [requisitos de entorno y versión](/server/requirements). Todos los paquetes `@univerjs/*` y `@univerjs-pro/*` deben fijarse al mismo conjunto de versiones compatibles.

## Camino uno: ejecutar el ejemplo oficial

### Preparar el primer inicio

Este repositorio requiere **Node.js 24+** y declara **pnpm 10.32.1**. Chequee `node --version` e `pnpm --version`, utilice el archivo de repositorio y ejecute todos los comandos `pnpm example:*` de la raíz del repositorio. Cada comando construye el navegador y el servidor, escribe el ejemplo fuente y luego lo inicia. Estos comandos no proporcionan un servidor de descarga caliente

Si tienes una Licencia, establece `UNIVER_LICENSE` y `UNIVER_LICENSE_KEY` en tu shell antes de ejecutar el comando. La construcción incrusta `UNIVER_LICENSE` en el paquete del navegador a través de `vite.config.ts`, y el Collaboration SDK lee ambas variables cuando el servidor comienza. Reaccione el comando después de cambiar la Licencia. Ver [Licencia](/server/license#collaboration-sdk).

```bash
git clone https://github.com/dream-num/univer-collaboration-examples.git
cd univer-collaboration-examples
pnpm install --frozen-lockfile
pnpm example:quick-start
```

Abra la siguiente URL:

```text
http://127.0.0.1:3010/?unit=quick-start-sheet
```

### Verificar la colaboración en tiempo real

1. Abra la URL completa en una ventana del navegador.
2. Abre la misma URL en otra ventana o pestaña.
3. Cambia una celda en cualquiera de las Hojas.
4. Confirma que el cambio aparece en el otro navegador.

Cada ventana abre su propia sesión WebSocket. Cuando pruebes dos cuentas en el [ejemplo de permisos](/server/collaboration/examples#permissions), usa perfiles de navegador distintos para separar sus cookies de sesión.

### Qué demuestra el resultado

```text
Univer Collaboration Client
  → Node Transport
  → UniverCollabEndpoint
  → UniverCollabService
  → MemoryDatabaseAdapter
```

Si los dos navegadores permanecen sincronizados, la ruta completa funciona. Cada navegador carga una Unidad sobre HTTP, abrió una sesión WebSocket con un boleto de sesión único, y se unió a la misma Sala. El Servicio realizó OT, confirmó una nueva revisión, lo salvó a través del Adaptador, y el Endpoint transmitió esa revisión a los otros miembros.

## Camino dos: integrarlo en tu aplicación

El código a continuación es el servidor mínimo y el montaje Web. El inicio rápido oficial contiene la estructura de aplicación completa:

- [server/main.ts](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/server/main.ts)
- [web/main.ts](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/web/main.ts)
- [package.json](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/package.json)

Si ya tiene una aplicación Univer Web, mantenga su Runtime, presets y UI, y agregue sólo la configuración del Cliente de Colaboración y el Servidor descritos a continuación. Para un proyecto vacío, copie `index.html`, `vite.config.ts` y los estilos del directorio Quick Start y utilícelos como el shell de aplicación.

### Migrar desde los archivos ejecutables

Copiar `examples/quick-start` como el esqueleto inicial y retener `package.json`, `index.html`, `vite.config.ts`, `web/styles.css`, `web/main.ts`, y `server/main.ts`. Ejecutar sus scripts de construcción y inicio de ese directorio, porque Express sirve `dist/web` en relación con el directorio de trabajo. Mantenga la definición de licencia Vite, y dar `#app` una altura no cero. El código de abajo sólo explica cómo se montan estas piezas; para un proyecto ejecutable completo, utilizar los archivos de repositorio.

El ejemplo sirve a la página y `/universer-api` desde el mismo origen. Si usted mueve el frontend en otro lugar, proxy tanto HTTP como la actualización WebSocket al backend, o cambiar las cinco URLs del cliente juntos. `unit` debe coincidir con el ID que creó el backend; un parámetro URL por sí solo no crea un documento. `unit` y carga el documento explícitamente con `loadSheetAsync()`. En su aplicación, establezca el usuario actual antes de cargar, como se describe en [Integración de la colaboración](/server/collaboration/browser-integration).

### 1. Instalar un conjunto de versiones compatibles

El servidor necesita Transporte, Endpoint, Service y un adaptador de base de datos. El navegador necesita el cliente de colaboración. Instalar los paquetes, luego pinar cada paquete Univer a la misma versión exacta:

```bash
pnpm add \
  @univerjs-pro/collaboration \
  @univerjs-pro/collaboration-client \
  @univerjs-pro/collaboration-client-ui \
  @univerjs-pro/collaboration-database-memory \
  @univerjs-pro/collaboration-endpoint \
  @univerjs-pro/collaboration-service \
  @univerjs-pro/collaboration-transport-node \
  @univerjs-pro/license \
  @univerjs/core \
  @univerjs/preset-sheets-core \
  @univerjs/presets \
  @univerjs/protocol \
  express react react-dom rxjs
```

El ejemplo oficial manifiesto es la referencia corregible y autorizada para la composición actual del paquete y versiones exactas.

### 2. Crear Service, Endpoint y Unit inicial

`UniverCollabService` es el núcleo de colaboración autorizado. El Endpoint mapea el protocolo del navegador en el Servicio, y el Adaptador de memoria almacena temporalmente instantáneas, cambios y revisiones:

```ts
import type { IWorkbookData } from "@univerjs/core";
import { createServer } from "node:http";
import express from "express";
import { LocaleType } from "@univerjs/core";
import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";
import { ErrorCode, UniverType } from "@univerjs/protocol";

const UNIT_ID = "quick-start-sheet";
const unitData: IWorkbookData = {
  id: UNIT_ID,
  rev: 1,
  name: "Quick Start Sheet",
  appVersion: "",
  locale: LocaleType.EN_US,
  sheetOrder: ["sheet-1"],
  sheets: {
    "sheet-1": {
      id: "sheet-1",
      name: "Sheet 1",
      rowCount: 100,
      columnCount: 26,
      cellData: {},
    },
  },
  styles: {},
  resources: [],
};

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

await service.createUnitFromData(
  { type: UniverType.UNIVER_SHEET, data: unitData },
  { userID: "demo-user" },
);
```

El `demo-user` fijo ilustra cómo una identidad de confianza fluye desde el Transporte hacia el Endpoint y el Servicio. Una aplicación de producción valida su propia cookie, token de portadores, o sesión dentro de `transport.use()`, y luego establece un negocio estable `userID`.

### 3. Montar autorización y puntos de entrada HTTP y WebSocket

El Cliente de Colaboración actual solicita un protocolo de autorización. Quick Start devuelve `allowed: true` para esa ruta en cada solicitud y adjunta el Transporte al servidor HTTP de la aplicación:

```ts
const app = express();

app.post("/universer-api/authz/-/object/-/batch_allowed", express.json(), (request, response) => {
  const body = request.body as {
    requests: Array<{ unitID: string; objectID: string; actions: unknown[] }>;
  };
  response.json({
    error: { code: ErrorCode.OK, message: "" },
    objectActions: body.requests.map((item) => ({
      unitID: item.unitID,
      objectID: item.objectID,
      actions: item.actions.map((action) => ({ action, allowed: true })),
    })),
  });
});

app.use(express.static("dist/web"));

const server = createServer(app);
transport.attach(server);
server.listen(3010, "127.0.0.1");
```

El ejemplo permite todas las solicitudes para simplificar la configuración. En producción, protege las lecturas HTTP, la incorporación a sesiones en tiempo real, los envíos de cambios y las operaciones del ciclo de vida de una Unit. Consulta [Identidad y autorización](/server/collaboration/identity-and-authorization) para ver dónde aplicar esos controles.

### 4. Registrar el cliente Collaboration en Runtime del navegador

Retener los presets y Web SDK estándar, a continuación, añadir los plugins de colaboración y las URLs del protocolo:

#### Configuración de plugins [#plugin-configuration]

`UniverLicensePlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `license` | `string` |  | Contenido del archivo de licencia del cliente. |

`UniverCollaborationClientPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `socketService` | `Ctor<ICollaborationSocketService>` |  | Implementación de calcetines los usos actuales de tiempo de ejecución. |
| `sendChangesetTimeout` | `number` | `2000` | ¿Cuánto tiempo las ediciones están batidas, en milisegundos, antes de que sean enviadas. |
| `authzUrl` | `string` | `'/universer-api/authz'` | Punto de conexión para comprobar permisos. |
| `snapshotServerUrl` | `string` | `'/universer-api/snapshot'` | Punto de conexión para cargar instantáneas del documento. |
| `collabSubmitChangesetUrl` | `string` | `'/universer-api/comb'` | Punto de conexión para enviar conjuntos de cambios. |
| `collabWebSocketUrl` | `string` | `'ws://127.0.0.1:8000/universer-api/comb/connect'` | URL WebSocket para sincronizar cambios en tiempo real. |
| `wsSessionTicketUrl` | `string` | `'/universer-api/user/session-ticket'` | Punto de conexión para obtener un ticket de sesión WebSocket. |

#### Configuración de preajustes [#preset-configuration]

`UniverSheetsCorePreset`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` | `'app'` | Elemento DOM donde se monta el editor o su ID. |

```ts
import { LocaleType, LogLevel } from "@univerjs/core";
import { UniverCollaborationPlugin } from "@univerjs-pro/collaboration";
import { UniverCollaborationClientPlugin } from "@univerjs-pro/collaboration-client";
import CollaborationClientEnUS from "@univerjs-pro/collaboration-client/locale/en-US";
import {
  BrowserCollaborationSocketService,
  UniverCollaborationClientUIPlugin,
} from "@univerjs-pro/collaboration-client-ui";
import CollaborationClientUIEnUS from "@univerjs-pro/collaboration-client-ui/locale/en-US";
import { UniverLicensePlugin } from "@univerjs-pro/license";
import { UniverSheetsCorePreset } from "@univerjs/preset-sheets-core";
import UniverPresetSheetsCoreEnUS from "@univerjs/preset-sheets-core/locales/en-US";
import { createUniver, defaultTheme, mergeLocales } from "@univerjs/presets";
import "@univerjs-pro/collaboration-client/facade";
import "@univerjs/preset-sheets-core/lib/index.css";
import "@univerjs-pro/collaboration-client-ui/lib/index.css";

const httpProtocol = location.protocol === "https:" ? "https" : "http";
const wsProtocol = location.protocol === "https:" ? "wss" : "ws";
const baseURL = `${httpProtocol}://${location.host}/universer-api`;

const unitId = new URLSearchParams(location.search).get("unit");
if (!unitId) throw new Error("Open the URL printed by the server; it names the Sheet with ?unit=.");
const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
      CollaborationClientEnUS,
      CollaborationClientUIEnUS,
    ),
  },
  theme: defaultTheme,
  logLevel: LogLevel.WARN,
  collaboration: true,
  presets: [UniverSheetsCorePreset({ container: "app" })],
  plugins: [
    [UniverLicensePlugin, { license: import.meta.env.UNIVER_LICENSE || undefined }],
    UniverCollaborationPlugin,
    [
      UniverCollaborationClientPlugin,
      {
        socketService: BrowserCollaborationSocketService,
        sendChangesetTimeout: 200,
        authzUrl: `${baseURL}/authz`,
        snapshotServerUrl: `${baseURL}/snapshot`,
        collabSubmitChangesetUrl: `${baseURL}/comb`,
        collabWebSocketUrl: `${wsProtocol}://${location.host}/universer-api/comb/connect`,
        wsSessionTicketUrl: `${baseURL}/user/session-ticket`,
      },
    ],
    UniverCollaborationClientUIPlugin,
  ],
});

const workbook = await univerAPI.getCollaboration().loadSheetAsync(unitId);
if (!workbook) throw new Error("Document could not be loaded");
```

La página requiere un elemento con `id="app"` y selecciona la Unidad a través de parámetros de consulta:

```text
/?unit=quick-start-sheet
```

### 5. Sustituir la configuración didáctica

| Configuración didáctica | Sustitución |
| --- | --- |
| Un `demo-user` fijo | Middleware de autenticación e ID de usuario estable |
| Controles de permisos que siempre permiten | ACL del servidor para lectura, JOIN, envío y ciclo de vida |
| Una unidad fija | API de creación y registro de producto que llamen a `createUnitFromData()` |
| El adaptador de memoria | SQLite o Adapter persistente propio con pruebas de contrato |

Continúa con [Adaptadores de bases de datos](/server/collaboration/database-adapters) e [Identidad y autorización](/server/collaboration/identity-and-authorization). Añade [History, Thread Comment, Worktree o Exchange](/server/collaboration/extensions) según lo necesites. En el [índice de ejemplos](/server/collaboration/examples) encontrarás todas las configuraciones que puedes ejecutar.

## Resolver problemas del primer inicio

| Síntoma | Comprobación |
| --- | --- |
| Fallo de instalación o compilación | Node.js 24+, pnpm declarado, versiones Univer iguales |
| Puerto 3010 ocupado | Detener el ejemplo anterior o usar `PORT=3011` y actualizar ambas URL |
| Página vacía o recursos ausentes | Construir completado; iniciar se ejecuta desde el directorio de ejemplo; `#app` tiene altura |
| Los cambios no se sincronizan | La misma URL completa en ambas ventanas; las solicitudes de instantáneas y de sesión-ticket exitosos; una conexión WebSocket en `/universer-api/comb/connect` |
| Datos perdidos al reiniciar | Quick Start usa memoria; continuar con SQLite |
