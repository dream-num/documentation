Univer Collaboration 由浏览器端的 Client 和一组服务端模块组成。每个模块负责一类职责。应用通过公开接口完成组装，因此业务代码不需要了解 OT[^operational-transformation] 实现、协议细节或持久化层的内部结构。

## Collaboration Client

浏览器端的 Collaboration Client 与 Web SDK 一同运行，负责协同中属于客户端的工作：

- 向服务端请求 Unit snapshot，以及自身缺失的 confirmed changeset。
- 使用一次性 Session Ticket 建立 WebSocket 连接。
- 加入 Unit Room，并与其他成员交换 Presence。
- 将本地 mutation 以 changeset 的形式提交到服务端。
- 接收 ACK 与广播，并在重连后补齐漏掉的内容。

Client 不判断用户是否可信，也不是权威数据源。该判断由服务端负责，服务端在相应的 Middleware 中执行身份与权限策略。

## Node Transport

`@univerjs-pro/collaboration-transport-node` 是 Node.js 侧的 HTTP 与 WebSocket 入口。它从宿主 HTTP Server 接收请求和 WebSocket upgrade，执行应用注册的入口 Middleware，再将流量路由到 Endpoint。

Transport 不涉及 OT、Unit 数据或 ACL 模型。组装时使用以下三个方法：

```ts
transport.use(httpMiddleware);
transport.useUpgrade(upgradeMiddleware);
transport.register(endpoint);
```

- `use()` 处理普通 HTTP 请求，`userID`、`customData`、日志与 trace 均在此建立。
- `useUpgrade()` 处理 WebSocket handshake，可在连接建立之前拒绝该连接。
- `register()` 注册协议 Endpoint，此后其生命周期由 Transport 管理。

## Collaboration Endpoint

`@univerjs-pro/collaboration-endpoint` 实现了 Univer Collaboration Client 使用的协议，负责以下能力：

| 能力分类      | Endpoint 负责的内容                                                                            |
| ------------- | ---------------------------------------------------------------------------------------------- |
| 内容加载      | 返回 Unit snapshot 与 block，以及 Client 缺失的 confirmed changeset                               |
| 修改提交      | 接收 changeset，返回 ACK，并将 confirmed changeset 广播到 Room                                   |
| Session 连接  | 签发一次性 Session Ticket，建立并维护 WebSocket Session                                          |
| Room 协同     | 处理 JOIN、LEAVE、成员状态与 Presence                                                            |
| Unit 生命周期 | 将删除与恢复请求映射为对应的 Service 调用                                                        |
| 多节点        | 通过可选的 pub/sub 适配器与共享的 Session Ticket 存储，将 Room、Presence 与广播转发到其他节点     |

Endpoint 本身不执行 OT，也不直接保存协同数据。它向 Service 获取权威结果，再将结果映射回 Client 协议。创建文档这类产品操作应由应用 API 调用 Service 完成。

## Collaboration Service

`@univerjs-pro/collaboration-service` 是协同核心，不依赖网络，覆盖 Sheet、Doc、Slide、Board、Base 与 PDF：

- 读取 Unit 的恢复数据与 confirmed changeset。
- 从 Unit Data 或 Snapshot 创建 Unit。
- 提交 changeset 时执行 OT，并推进连续 revision[^collaboration-revision]。
- 通过 `(unitID, sid, reqId)` 识别重复提交。
- 软删除、恢复或永久删除 Unit。
- 运行 Service Middleware，并在确认后发出 Event。

Service 不包含 HTTP 与 WebSocket 层，也不涉及用户、角色、ACL、目录或文件管理。Endpoint 在 Service 之上实现浏览器协议；应用也可以直接在业务 API 或后台任务中调用其公开 API。

### 核心 API

| 能力         | Service API                                        |
| ------------ | -------------------------------------------------- |
| 加载 Unit    | `getUnitLoadData()`、`getUnitLoadDataWithBlocks()` |
| 读取增量数据 | `getChangesets()`、`getSheetBlock()`               |
| 创建 Unit    | `createUnitFromData()`、`createUnitFromSnapshot()` |
| 提交修改     | `submitChangeset()`                                |
| 删除与恢复   | `deleteUnits()`、`recoverUnits()`                  |

## Database Adapter

Database Adapter 是 Service 与存储之间的合同，必须保证以下事项：

- 初始 snapshot 及其依赖数据的原子创建；
- revision compare-and-swap；
- changeset 提交的幂等性；
- 依赖全部就位后，snapshot 才对读取可见；
- Unit 生命周期批次的全有或全无。

应用通过 `IDatabaseAdapter` 接入存储。如何选择内置适配器或实现自定义适配器，见 [Database Adapter](/server/collaboration/database-adapters)。

## 四个核心概念

| 概念      | 含义                                                                       |
| --------- | -------------------------------------------------------------------------- |
| Unit      | 一份 Univer 内容，有唯一的 `unitID` 和类型，可以独立加载、独立协同          |
| Snapshot  | Unit 在某个 revision 上持久化下来的内容，不是运行中的可变对象               |
| Changeset | 一次提交中包含的 mutation 集合，带 base revision 和用于幂等的身份标识        |
| Revision  | Unit 已确认状态的连续版本号，初始值为 `1`                                   |

运行中的内容只能通过 Facade 或 Command 修改。修改 snapshot 对象不会更新 Client 或 Service 中的 live Unit。

## 加载一个 Unit

<Mermaid chart={"sequenceDiagram\n    participant Client\n    participant Transport\n    participant Endpoint\n    participant Service\n    participant Adapter\n\n    Client->>Transport: Load Unit over HTTP\n    Transport->>Endpoint: Authenticated request context\n    Endpoint->>Service: getUnitLoadData()\n    Service->>Adapter: Snapshot + changesets\n    Adapter-->>Service: Authoritative data\n    Service-->>Endpoint: Unit load data\n    Endpoint-->>Client: Protocol response"} />

Transport Middleware 建立的 `userID/customData` 会随当前 HTTP 请求传入 Service Middleware。是否允许本次读取由应用策略决定。通过 HTTP 直接读取之前，客户端不需要先加入 Room。

## 提交一次修改

```text
Facade / Command
  → Mutation
  → Client Changeset
  → Endpoint submit
  → Service Middleware
  → OT + Revision CAS
  → Adapter atomic commit
  → confirmed Changeset
  → ACK / Room broadcast
```

Database Adapter 中的 confirmed revision 是权威状态。ACK 与广播使在线客户端以较低的延迟保持同步。客户端如果漏掉消息，可以使用已知的 revision 拉取缺失的 confirmed changeset。

## 最小服务端组装

```ts
import { createServer } from "node:http";

import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

const server = createServer();
transport.attach(server);
server.listen(3010);
```

此处写死的用户与 Memory Adapter 仅用于演示模块的组装方式。真实应用通过 Middleware 建立 Context，并根据自身数据需求选择 Adapter。

### 通过应用 API 创建 Unit

应用可以自行定义 HTTP 或 RPC 接口，在认证、参数校验与业务检查通过后，调用上文创建的 `service`：

```text
业务客户端
  → POST /api/units
  → 应用认证与参数校验
  → service.createUnitFromData()
  → Database Adapter
```

下面的 Express 示例假设认证 Middleware 已设置 `response.locals.user`，且 `request.body.data` 已按 Workbook Data 完成校验：

```ts
import { randomUUID } from "node:crypto";

import { json } from "express";
import { UniverType } from "@univerjs/protocol";

app.post("/api/units", json({ limit: "1mb" }), async (request, response, next) => {
  try {
    const user = response.locals.user as { readonly userID: string };
    const unitID = randomUUID();

    const result = await service.createUnitFromData(
      {
        type: UniverType.UNIVER_SHEET,
        data: {
          ...request.body.data,
          id: unitID,
          rev: 1,
        },
      },
      {
        userID: user.userID,
        customData: { traceID: randomUUID() },
      },
    );

    response.status(result.status === "created" ? 201 : 200).json(result);
  } catch (error) {
    next(error);
  }
});
```

`POST /api/units` 是应用自己的路由，不属于 Collaboration Client 协议。调用 `createUnitFromData()` 时，Service 的 `createUnit` Middleware 仍会执行。产品记录、owner ACL、错误响应映射与失败补偿仍由应用负责。

## 资源释放

`transport.dispose()` 释放通过 `register()` 注册的 Endpoint。应用注入的 Service 与 Database Adapter 需要分别释放，顺序与组装时相反：

```ts
await transport.dispose();
await service.dispose();
await database.dispose();
```

如果应用提供了 pub/sub 适配器，还应在释放 Transport 之后释放该适配器及其连接。Endpoint 不会代为释放。

如需在上述模块边界上扩展行为，请继续阅读 [Middleware 与 Event](/server/collaboration/middleware-and-events)。

[^operational-transformation]: *操作转换（OT）* 会调整基于不同文档修订号并发产生的操作，使它们能够一致地应用。它处理的是编辑操作，而不是用最后到达的快照覆盖整份文档。

[^collaboration-revision]: 修订号（revision）标识 Unit 已确认编辑历史中的位置。变更集（changeset）包含一次提交中的操作，确认后会推进历史。修订号不是 SDK 包版本，也不是时间戳。
