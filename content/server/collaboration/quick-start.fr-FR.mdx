Cette page décrit deux chemins. La première exécute l'exemple officiel et vérifie le chemin de collaboration complète dans deux navigateurs. La seconde présente le minimum de Serveur et d'assemblage Web, que vous pouvez copier dans votre propre application Univer.

Avant de commencer, respectez les [exigences d’environnement et de version](/server/requirements). Tous les paquets `@univerjs/*` et `@univerjs-pro/*` doivent être verrouillés sur le même ensemble de versions compatibles.

## Premier parcours : exécuter l’exemple officiel

### Préparer le premier lancement

Ce dépôt nécessite **Node.js 24+** et déclare **pnpm 10,32.1**. Vérifiez `node --version` and `pnpm --version`, utilisez le fichier de verrouillage du dépôt et exécutez toutes les commandes `pnpm example:*` depuis la racine du dépôt. Chaque commande construit le navigateur et le serveur, tape-vérifie l'exemple, puis démarre. Ces commandes ne fournissent pas de serveur de développement à recharger à chaud, donc après avoir édité les fichiers sources, vous devez arrêter le processus et exécuter la commande à nouveau.

Si vous avez une licence, définissez `UNIVER_LICENSE` et `UNIVER_LICENSE_KEY` dans votre shell avant d'exécuter la commande. La compilation intègre `UNIVER_LICENSE` au paquet de navigateurs via `vite.config.ts`, et la Collaboration SDK lit les deux variables lorsque le serveur démarre. Réinitialisez la commande après avoir changé la licence. Voir [Licence](/server/license#collaboration-sdk).

```bash
git clone https://github.com/dream-num/univer-collaboration-examples.git
cd univer-collaboration-examples
pnpm install --frozen-lockfile
pnpm example:quick-start
```

Ouvrez l'URL suivante :

```text
http://127.0.0.1:3010/?unit=quick-start-sheet
```

### Vérifier la collaboration en temps réel

1. Ouvrez l'URL complète dans une fenêtre de navigateur.
2. Ouvrez la même URL dans une deuxième fenêtre ou un deuxième onglet.
3. Changez une cellule dans chaque feuille.
4. Vérifiez que la modification apparaît dans l’autre navigateur.

Chaque fenêtre ouvre sa propre session WebSocket. Pour tester ensuite deux comptes dans l’[exemple de permissions](/server/collaboration/examples#permissions), utilisez des profils de navigateur distincts afin de séparer leurs cookies de connexion.

### Ce que prouve la réussite

```text
Univer Collaboration Client
  → Node Transport
  → UniverCollabEndpoint
  → UniverCollabService
  → MemoryDatabaseAdapter
```

Si les deux navigateurs restent synchronisés, le chemin complet fonctionne. Chaque navigateur chargeait une unité sur HTTP, ouvrait une session WebSocket avec un ticket de session unique, et rejoignait la même salle. Le Service effectuait une OT, confirmait une nouvelle révision, l'enregistrait par l'adaptateur, et le Point d'Endpoint retransmettait cette révision aux autres membres.

## Deuxième parcours : intégrer dans votre application

Le code ci-dessous est le serveur minimal et l'assemblage Web. Le démarrage rapide officiel contient la structure complète de l'application:

- [server/main.ts](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/server/main.ts)
- [web/main.ts](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/web/main.ts)
- [package.json](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/package.json)

Si vous avez déjà une application Web Univer, conservez son temps d'exécution, ses préréglages et l'interface utilisateur, et ajoutez seulement la configuration du Client Collaboration et le serveur décrit ci-dessous. Pour un projet vide, copiez `index.html` et `vite.config.ts` ainsi que les styles du répertoire Quick Start et utilisez-les comme shell d'application.

### Partir des fichiers exécutables

Copier `examples/quick-start` en tant que squelette initial et conserver `package.json`, `index.html`, `vite.config.ts`, `web/styles.css`, `web/main.ts` et `server/main.ts`. Exécuter ses scripts de construction et de démarrage à partir de ce répertoire, parce qu'Express dessert `dist/web` par rapport au répertoire de travail. Conserver la définition de licence Vite, et donner `#app` une hauteur non nulle. Le code ci-dessous explique seulement comment ces pièces sont assemblées; pour un projet complet, utilisez les fichiers de dépôt.

L'exemple sert la page et `/universer-api` de la même origine. Si vous déplacez le frontend ailleurs, proxy à la fois HTTP et la mise à niveau WebSocket vers le backend, ou changez les cinq URLs clientes ensemble. `unit` doit correspondre à l'ID que le backend a créé; un paramètre URL seul ne crée pas de document. L'exemple lit `unit` et charge le document explicitement avec `loadSheetAsync()`. Dans votre application, définissez l'utilisateur courant avant le chargement, comme décrit dans [Intégration de la collaboration](/server/collaboration/browser-integration).

### 1. Installer un ensemble cohérent de paquets

Le serveur a besoin de Transport, Endpoint, Service et un Adaptateur de base de données. Le navigateur a besoin du Client Collaboration. Installez les paquets, puis épinglez chaque paquet Univer à la même version exacte:

```bash
pnpm add \
  @univerjs-pro/collaboration \
  @univerjs-pro/collaboration-client \
  @univerjs-pro/collaboration-client-ui \
  @univerjs-pro/collaboration-database-memory \
  @univerjs-pro/collaboration-endpoint \
  @univerjs-pro/collaboration-service \
  @univerjs-pro/collaboration-transport-node \
  @univerjs-pro/license \
  @univerjs/core \
  @univerjs/preset-sheets-core \
  @univerjs/presets \
  @univerjs/protocol \
  express react react-dom rxjs
```

Le manifeste officiel de l'exemple est la référence exécutable, faisant autorité pour la composition actuelle du paquet et les versions exactes.

### 2. Créer Service, Endpoint et Unit initiale

`UniverCollabService` est le noyau de collaboration faisant autorité. Le point d'arrivée map le protocole du navigateur sur le Service, et l'adaptateur mémoire stocke temporairement des instantanés, des modifications et des révisions :

```ts
import type { IWorkbookData } from "@univerjs/core";
import { createServer } from "node:http";
import express from "express";
import { LocaleType } from "@univerjs/core";
import { MemoryDatabaseAdapter } from "@univerjs-pro/collaboration-database-memory";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";
import { UniverCollabService } from "@univerjs-pro/collaboration-service";
import { createNodeTransport } from "@univerjs-pro/collaboration-transport-node";
import { ErrorCode, UniverType } from "@univerjs/protocol";

const UNIT_ID = "quick-start-sheet";
const unitData: IWorkbookData = {
  id: UNIT_ID,
  rev: 1,
  name: "Quick Start Sheet",
  appVersion: "",
  locale: LocaleType.EN_US,
  sheetOrder: ["sheet-1"],
  sheets: {
    "sheet-1": {
      id: "sheet-1",
      name: "Sheet 1",
      rowCount: 100,
      columnCount: 26,
      cellData: {},
    },
  },
  styles: {},
  resources: [],
};

const database = new MemoryDatabaseAdapter();
const service = new UniverCollabService({ dbAdapter: database });
const endpoint = new UniverCollabEndpoint(service);
const transport = createNodeTransport();

transport.use(async (context, next) => {
  context.userID = "demo-user";
  await next();
});
transport.register(endpoint);

await service.createUnitFromData(
  { type: UniverType.UNIVER_SHEET, data: unitData },
  { userID: "demo-user" },
);
```

La `demo-user` fixe illustre comment une identité de confiance se déplace du Transport vers le Point d'Endpoint et le Service. Une application de production valide son propre cookie, jeton porteur, ou session à l'intérieur de `transport.use()`, et définit ensuite une entreprise stable `userID`.

### 3. Monter les points d’entrée d’autorisation, HTTP et WebSocket

Le Client Collaboration en cours interroge un protocole d'autorisation. Quick Start retourne `allowed: true` pour cette route sur chaque requête et joint le Transport au serveur HTTP de l'application:

```ts
const app = express();

app.post("/universer-api/authz/-/object/-/batch_allowed", express.json(), (request, response) => {
  const body = request.body as {
    requests: Array<{ unitID: string; objectID: string; actions: unknown[] }>;
  };
  response.json({
    error: { code: ErrorCode.OK, message: "" },
    objectActions: body.requests.map((item) => ({
      unitID: item.unitID,
      objectID: item.objectID,
      actions: item.actions.map((action) => ({ action, allowed: true })),
    })),
  });
});

app.use(express.static("dist/web"));

const server = createServer(app);
transport.attach(server);
server.listen(3010, "127.0.0.1");
```

Une application de production doit protéger les lectures HTTP, JOIN en temps réel, la soumission de changementset et les opérations de cycle de vie d'unité. Voir [Identité et autorisation](/server/collaboration/identity-and-authorization) pour le modèle de couverture complet.

### 4. Enregistrer le client Collaboration dans le Runtime navigateur

Conserver les préréglages et Web SDK standard, puis ajouter les plugins Collaboration et les URLs du protocole :

#### Configuration des plugins [#plugin-configuration]

`UniverLicensePlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `license` | `string` |  | Contenu du fichier de licence côté client. |

`UniverCollaborationClientPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `socketService` | `Ctor<ICollaborationSocketService>` |  | Implémentation de la prise en charge de l'exécution courante. |
| `sendChangesetTimeout` | `number` | `2000` | Combien de temps les modifications sont par lots, en millisecondes, avant qu'elles ne soient envoyées. |
| `authzUrl` | `string` | `'/universer-api/authz'` | Point de terminaison de vérification des permissions. |
| `snapshotServerUrl` | `string` | `'/universer-api/snapshot'` | Point de terminaison de lecture des instantanés. |
| `collabSubmitChangesetUrl` | `string` | `'/universer-api/comb'` | Point de terminaison d’envoi des lots de modifications. |
| `collabWebSocketUrl` | `string` | `'ws://127.0.0.1:8000/universer-api/comb/connect'` | URL WebSocket de synchronisation en temps réel. |
| `wsSessionTicketUrl` | `string` | `'/universer-api/user/session-ticket'` | Point de terminaison d’obtention du ticket de session WebSocket. |

#### Configuration des préréglages [#preset-configuration]

`UniverSheetsCorePreset`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` | `'app'` | Élément DOM de montage de l’éditeur ou son identifiant. |

```ts
import { LocaleType, LogLevel } from "@univerjs/core";
import { UniverCollaborationPlugin } from "@univerjs-pro/collaboration";
import { UniverCollaborationClientPlugin } from "@univerjs-pro/collaboration-client";
import CollaborationClientEnUS from "@univerjs-pro/collaboration-client/locale/en-US";
import {
  BrowserCollaborationSocketService,
  UniverCollaborationClientUIPlugin,
} from "@univerjs-pro/collaboration-client-ui";
import CollaborationClientUIEnUS from "@univerjs-pro/collaboration-client-ui/locale/en-US";
import { UniverLicensePlugin } from "@univerjs-pro/license";
import { UniverSheetsCorePreset } from "@univerjs/preset-sheets-core";
import UniverPresetSheetsCoreEnUS from "@univerjs/preset-sheets-core/locales/en-US";
import { createUniver, defaultTheme, mergeLocales } from "@univerjs/presets";
import "@univerjs-pro/collaboration-client/facade";
import "@univerjs/preset-sheets-core/lib/index.css";
import "@univerjs-pro/collaboration-client-ui/lib/index.css";

const httpProtocol = location.protocol === "https:" ? "https" : "http";
const wsProtocol = location.protocol === "https:" ? "wss" : "ws";
const baseURL = `${httpProtocol}://${location.host}/universer-api`;

const unitId = new URLSearchParams(location.search).get("unit");
if (!unitId) throw new Error("Open the URL printed by the server; it names the Sheet with ?unit=.");
const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
      CollaborationClientEnUS,
      CollaborationClientUIEnUS,
    ),
  },
  theme: defaultTheme,
  logLevel: LogLevel.WARN,
  collaboration: true,
  presets: [UniverSheetsCorePreset({ container: "app" })],
  plugins: [
    [UniverLicensePlugin, { license: import.meta.env.UNIVER_LICENSE || undefined }],
    UniverCollaborationPlugin,
    [
      UniverCollaborationClientPlugin,
      {
        socketService: BrowserCollaborationSocketService,
        sendChangesetTimeout: 200,
        authzUrl: `${baseURL}/authz`,
        snapshotServerUrl: `${baseURL}/snapshot`,
        collabSubmitChangesetUrl: `${baseURL}/comb`,
        collabWebSocketUrl: `${wsProtocol}://${location.host}/universer-api/comb/connect`,
        wsSessionTicketUrl: `${baseURL}/user/session-ticket`,
      },
    ],
    UniverCollaborationClientUIPlugin,
  ],
});

const workbook = await univerAPI.getCollaboration().loadSheetAsync(unitId);
if (!workbook) throw new Error("Document could not be loaded");
```

La page nécessite un élément avec `id="app"` et sélectionne l'unité par les paramètres de requête :

```text
/?unit=quick-start-sheet
```

### 5. Remplacer la configuration pédagogique

| Configuration pédagogique | Remplacement |
| --- | --- |
| Un `demo-user` fixe | Middleware d’authentification et ID utilisateur stable |
| Contrôles d'autorisation qui permettent toujours | ACL serveur couvrant lecture, JOIN, envoi et cycle de vie |
| Une unité fixe | API de création et enregistrement produit appelant `createUnitFromData()` |
| L'adaptateur mémoire | SQLite ou Adapter persistant personnalisé validé par tests de contrat |

Poursuivez avec les [adaptateurs de base de données](/server/collaboration/database-adapters) et la gestion de [l’identité et des autorisations](/server/collaboration/identity-and-authorization). Ajoutez ensuite [History, Thread Comment, Worktree ou Exchange](/server/collaboration/extensions) selon vos besoins. L’[index des exemples](/server/collaboration/examples) recense toutes les configurations exécutables.

## Dépanner le premier lancement

| Symptôme | Vérification |
| --- | --- |
| Échec d’installation ou de compilation | Node.js 24+, pnpm déclaré, versions Univer alignées |
| Port 3010 occupé | Arrêter l’exemple précédent ou utiliser `PORT=3011` dans les deux URL |
| Page vide ou ressources absentes | Build completed; start s'exécute à partir du répertoire exemple; `#app` a la hauteur |
| Modifications non synchronisées | La même URL complète dans les deux fenêtres; des requêtes d'instantanés et de tickets de session réussies; une connexion WebSocket à `/universer-api/comb/connect` |
| Données perdues au redémarrage | Quick Start utilise la mémoire ; passer à SQLite |
