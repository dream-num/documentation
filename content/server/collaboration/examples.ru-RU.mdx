## Быстрый старт [#quick-start]

Соберите клиент для совместной работы, транспорт, конечную точку, службу и адаптер памяти. Используйте два браузера для проверки загрузки HTTP, сеансы WebSocket, Комната, ACK и вещание для одного и того же листа.

```bash
pnpm example:quick-start
```

Откройте `http://127.0.0.1:3010/?unit=quick-start-sheet`.

- [Руководство примера](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/README.md)
- [Серверная точка входа](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/server/main.ts)
- [Точка входа Web](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/quick-start/web/main.ts)
- [Пошаговое руководство на сайте](/server/collaboration/quick-start)

## Права на объекты [#object-permissions]

Под учётной записью Alice защитите B2:B3. Bob по-прежнему может изменить A1, но изменение B2 будет отклонено. Добавьте Bob в число редакторов защищённого диапазона и проверьте, что теперь он может сохранить изменение B2.

```bash
pnpm example:object-permissions
```

Откройте `http://127.0.0.1:3010`.

## История [#history]

Добавьте History Service, отдельный адаптер, History Endpoint и запись истории браузера, все за пределами Core. Создание блока и изменение пакета Events создают историю как производный индекс, который можно реконструировать.

```bash
pnpm example:history
```

Откройте `http://127.0.0.1:3010/?unit=history-sheet`, измените Sheet и выберите `History` сверху.

## Развёртывание на нескольких узлах [#multi-node]

Запуск двух узлов совместной работы за Nginx. Redis ретранслирует обновления в реальном времени между узлами и разделяет билеты на сеанс, поэтому любой узел может обслуживать любой запрос. Пример также требует Docker Compose и [Лицензия](/server/collaboration/license#nodes), который охватывает два узла.

```bash
pnpm example:multi-node
```

Откройте `http://127.0.0.1:3010/` и выберите **Новый лист** для создания файла. Скопируйте полный URL в другую вкладку, чтобы проверить совместное редактирование того же документа. Затем создайте еще несколько файлов и наблюдайте, как они распределены по узлам.

- [Руководство примера](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/multi-node/README.md)
