Server SDKアプリケーションには3つの展開図があり、アプリケーションのスケールはどのアプリケーションが使用するかを決定します。 [Collaboration SDK](/server/collaboration/overview)、[輸入および輸出](/server/import-export)および[事例紹介](/server/collaboration/examples)から始めて、モジュールがどのように組み立てられているかを確認します。 デプロイメントは、同じアセンブリを実行する多くのノードだけを決定します。

| 形態 | 共同編集 | インポートとエクスポート | 推奨規模 |
| --- | --- | --- | --- |
| [単一マシン](#単一マシン) | 1 ノード | 同じノード | ローカルアプリケーション、開発とテスト、少数の社内ユーザー |
| [インポートとエクスポートの分離](#インポートとエクスポートの分離) | 1 ノード | 独立ノード | 複数ユーザー向けのオンラインサービス、1 ノードの容量内 |
| [複数ノード](#複数の共同編集ノード) | 複数ノード | 独立ノード | 1 ノードの容量を超える場合、またはノードのフェイルオーバーが必要な場合 |

単一ノードの容量を見積もるには、ドキュメントのサイズ、同時編集者数、編集頻度を [共同編集の性能テストレポート](/server/collaboration/performance) の測定条件と比較してください。

## 単一マシン

単一のNode.jsプロセスで実行されるすべてのコンポーネントおよびブラウザは、そのプロセスに直接接続します。

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"ブラウザー\"]) --> App[\"共同編集 + Exchange\"]\n    App --> DB[(\"データベース\")]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

- Database Adapter は `IDatabaseAdapter` の契約を実装します。[データベースアダプター](/server/collaboration/database-adapters)を参照してください。
- 輸出入は、Exchange ServiceとFile Serviceにより提供されます。[コラボレーション拡張モジュール](/server/collaboration/extensions)を参照してください。
- 変換はCPU-boundなので、大きめのファイルが連携を遅くします。

変換がコラボレーションレイテンシーに影響を及ぼすか、多くのユーザーに対してサービスが応答しなくなったときに、インポートとエクスポートを別のノードに移動します。

## インポートとエクスポートの分離

コラボレーションが単一のノードに残っている間、専用のノードでインポートとエクスポートを実行します。ゲートウェイは2種類のリクエストを別々にルーティングし、両側は同じデータベースを使用します。

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"ブラウザー\"]) --> Gateway[\"ゲートウェイ\"]\n    Gateway -->|\"共同編集リクエスト\"| Node[\"共同編集ノード\"]\n    Gateway -->|\"インポート/エクスポートリクエスト\"| Exchange[\"インポート/エクスポートノード\"]\n    Node --> DB[(\"データベース\")]\n    Exchange --> DB\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

インポートとエクスポートノードは、データベースアダプタ、`UniverCollabService`、File Service、Exchange Serviceを組み立て、データベースと直接連携します。インジェクションポイントは、単一のマシンと同じです。両方のノードは、同じファイルストレージでFile Serviceを指し、両方のノードは`UniverCollabService`上で同じ認可ミドルウェアをインストールします。

プロセスメモリは、1つのコラボレーションノードが機能できるドキュメントの数を制限します。その容量が上回っているとき、またはフェイルオーバーが必要な場合は、複数のノードに移動します。

## 複数の共同編集ノード

複数のコラボレーションノードは同じデータベースに対して同じコードを実行します。パブ/サブアダプタは、ノード間でルーム、プレゼンス、および放送を中継し、チケットストアはセッションチケットを共有します。 `@univerjs-pro/collaboration-cluster-redis`は、Redisの実装を提供します。すべてのノードは、実行ノードの数をカバーする同じライセンスを使用します。 [コラボレーションノード](/server/collaboration/license#nodes)を参照してください。参照実装については、[マルチノード](/server/collaboration/examples#multi-node)をご覧ください。

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"ブラウザー\"]) --> Gateway[\"ゲートウェイ\"]\n    subgraph Nodes[\"共同編集ノード\"]\n        direction TB\n        A[\"ノード A\"]\n        B[\"ノード B\"]\n    end\n    Gateway -->|\"共同編集リクエスト\"| A\n    Gateway --> B\n    subgraph Exchange[\"インポート/エクスポートノード\"]\n        direction TB\n        X1[\"ノード A\"]\n        X2[\"ノード B\"]\n    end\n    Gateway -->|\"インポート/エクスポートリクエスト\"| X1\n    Gateway --> X2\n    A --- PubSub[(\"pub/sub + ticket store\")]\n    B --- PubSub\n    A --> DB[(\"データベース\")]\n    B --> DB\n    X1 --> DB\n    X2 --> DB\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

各コラボレーションノードは、Redis pub/sub アダプターとチケットストアをエンドポイントに渡します。アセンブリの残りの部分は変更されません。

```ts
import { createClient } from "redis";
import { RedisPubSubAdapter, RedisSessionTicketStore } from "@univerjs-pro/collaboration-cluster-redis";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";

const client = createClient({ url: process.env.REDIS_URL });
const subClient = client.duplicate();
await Promise.all([client.connect(), subClient.connect()]);

const pubSub = new RedisPubSubAdapter({ pubClient: client, subClient });
const ticketStore = new RedisSessionTicketStore({ client });
const endpoint = new UniverCollabEndpoint(service, { pubSub, ticketStore });
```

## さらに先へ

1つの非常に大きな文書は、同じノード上の小さな文書のリクエストを遅くします。 ノードプールを文書サイズで分割し、ゲートウェイは大きな文書を専用のプールにルーティングします。 ルーティングキーはユニットIDであり、すべてのプールはデータベースとパブ/サブを共有します。
