Le Univer Office SDK se compose de trois parties : [Web SDK](/guides/sheets) exécute des éditeurs intégrés et traite du contenu en mode sans tête[^headless-mode]; [Server SDK](/server) gère la collaboration et l'échange de fichiers; et [AI SDK](/ai) couvre les workflows d'Agent.

**Univer** est une boîte à outils pour la construction d'applications Office dans lesquelles les personnes et les agents d'IA travaillent sur le même contenu. Une application peut fournir une interface Web pour les personnes, un CLI pour les agents, et un serveur que les deux partagent, ou elle peut prendre seulement les parties dont elle a besoin.

| Composant | Runtime | SDK principal | Fourni par le SDK | Responsabilité applicative |
| --- | --- | --- | --- | --- |
| Web | Navigateur | Web SDK | Un éditeur qui affiche et modifie le contenu Office dans le navigateur | UI, interactions de produits et intégration du navigateur |
| CLI | Node.js | AI SDK | Inspection et édition pour les agents d'IA | Parcours AI Agent, appels d’outils, limites des tâches |
| Server | Node.js | Server SDK (Collaboration, Exchange) | Collaboration auto-hébergée et échange de fichiers Office | API métier, identité, droits, stockage et déploiement |

Chaque partie a sa propre section: [Web SDK](/guides/sheets) couvre les éditeurs, [Server SDK](/server) englobe les services de collaboration et d'échange de fichiers, et [AI SDK](/ai) concerne les opérations de contenu pour les agents AI.

AI SDK réutilise les capacités de contenu sans tête de Web SDK. Ces composants identifient les points d'entrée principaux du développeur et le temps d'exécution de chaque pièce. Ce ne sont pas trois piles isolées, et aucun d'entre eux n'est un produit fini qui peut être déployé sans code d'application.

## Intégrer l’import-export

Le module Server SDK `@univerjs-pro/exchange-node` convertit entre les fichiers Office et les données du document Univer. L'application intègre le module de conversion et fournit les API de téléchargement, de conversion et de téléchargement elle-même. Web SDK gère le côté navigateur, et un CLI peut appeler le module de transformation dans Node.js . La configuration du navigateur pour chaque produit reste dans la documentation Web SDK de ce produit.

- **Sans montage collaboratif :** convertit un fichier en un instantané de document, puis ouvre et modifie cet instantané dans le navigateur. Pour exporter, passez le dernier instantané au module de conversion, qui produit le fichier. Ce flux nécessite une conversion côté serveur mais pas de service de collaboration.
- **Avec une édition collaborative :** stocke les données importées comme un document collaboratif. Web SDK et AI SDK fonctionnent ensuite sur le même contenu par l'intermédiaire de son ID de document. Avant d'exporter, synchronisez les modifications actuelles, puis lisez les données de document les plus récentes et convertissez-les.

Si seule la conversion est nécessaire, lancez Exchange dans un processus local Node.js ou un service distant; ni AI SDK ni l'édition collaborative n'est nécessaire. [Intégration de l'échange de fichiers](/server/import-export) décrit le flux d'application, et [Importation et exportation de fichiers bureautiques](/server/import-export/node) montre comment utiliser le module de conversion.

## Formes de déploiement

| Forme | Web | CLI | Server | Portée |
| --- | --- | --- | --- | --- |
| Application locale | Navigateur local/UI de bureau | Processus local | Processus local | Office de bureau et AI Agent local |
| SaaS | Navigateur | Appareil utilisateur/AI Agent cloud | Service distant | Plusieurs utilisateurs et exploitation centralisée |
| Web + Server | Navigateur | — | Local ou distant | Pas encore d’entrée AI Agent |
| Web seul | Navigateur/UI de bureau | — | — | Édition locale, individuelle, non collaborative |

Tous les composants peuvent fonctionner sur une seule machine, ou ils peuvent être distribués à travers les périphériques utilisateurs et l'infrastructure cloud. L'emplacement de déploiement ne change pas la responsabilité de chaque composant. Une fois qu'un serveur est présent, Web et CLI l'utilisent pour accéder à des capacités de contenu et de produit partagés.
