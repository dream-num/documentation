The backend saves documents, checks user permissions, and provides interfaces for collaboration or file conversion. Current releases use [Server SDK](/server) to add these capabilities in your own application environment.

This page covers backend setup, storage, and permissions. [Collaboration integration](/server/collaboration/browser-integration) connects the editor to shared documents. [File exchange integration](/server/import-export) covers file upload, conversion, and download. Follow the guide for the feature you need. For features that require a license, start with [license configuration](/guides/license). Browser-only editing does not require a collaboration service.


## Integration sequence

1. [Run Quick Start](/server/collaboration/quick-start): edit the same document in two independent browser contexts and verify both directions.
2. [Add persistence](/server/collaboration/database-adapters#verify-persistence): restart the SQLite example and confirm the value survives.
3. [Add identity and permissions](/server/collaboration/identity-and-authorization#verify-permissions): compare editor and viewer sessions.
4. [Connect your browser application](/server/collaboration/browser-integration): replace the demo identity, document creation and protocol addresses with your application’s implementations.
5. [Choose an extension](/server/collaboration/examples): add history, comments, worktree or exchange after the core path works. For file conversion alone, start with [Exchange](/server/import-export/node).

## Choose the services you need

| Requirement | Backend preparation | Implementation guide |
| --- | --- | --- |
| Shared document editing | Collaboration SDK, document storage, and permissions | [Collaboration Quick Start](/server/collaboration/quick-start) |
| Office file import/export | Conversion, uploads, task queries, and downloads | [File conversion](/server/import-export/node) and the [Exchange example](/server/collaboration/examples#exchange) |
| History or shared comments | Their respective services, storage, and permissions | [Extension modules](/server/collaboration/extensions) |

Choose only the capabilities you need. File conversion alone does not require collaborative editing. Prepare the [SDK environment](/server/requirements) and keep Univer package versions compatible.

## Connect your application and storage

Run the chosen service's example, then connect it to your backend. For collaborative documents, your application creates the document, records its ownership, and returns its ID to the browser. See [module boundaries](/server/collaboration/modules) for creation APIs. Your application continues to manage users, projects, and folders.

The collaboration example uses memory storage and loses content on restart. Follow [Database Adapters](/server/collaboration/database-adapters) to connect a database, then verify that saved documents survive a restart.

File conversion also needs storage and cleanup for uploads, tasks, and downloads. Follow the [Exchange example](/server/collaboration/examples#exchange).

## Connect login and permissions

Follow [identity and authorization](/server/collaboration/identity-and-authorization) to verify existing login credentials and check whether a user may read or modify a document. Replace fixed example users and allow-all rules.

Protect document reads, collaboration connections, edit submissions, and any enabled history, comments, and downloads. A read-only browser editor does not replace server permission checks.

## Deploy and connect the frontend

Deploy interfaces on your application's domain. For collaboration, forward both HTTP and WebSocket traffic through proxies; HTTPS pages should use WSS. Limit file uploads and handle conversion failures and timeouts.

Once the backend is ready, finish the relevant feature integration:

- [Collaboration integration](/server/collaboration/browser-integration): connect the editor, create and open shared documents, and verify synchronization.
- [File exchange integration](/server/import-export): connect uploads, conversion, and downloads, then check real files.
