Una aplicación Server SDK tiene tres formas de despliegue, y la escala de la aplicación determina cuál utilizar. Comience con [Collaboration SDK](/server/collaboration/overview), [importación y exportación](/server/import-export) y el [ejemplos](/server/collaboration/examples) para ver cómo se montan los módulos. El despliegue sólo determina cuántos nodos ejecutan esa misma asamblea.

| Forma | Colaboración | Importación y exportación | Escala recomendada |
| --- | --- | --- | --- |
| [Una sola máquina](#una-sola-máquina) | Un nodo | El mismo nodo | Aplicaciones locales, desarrollo y pruebas, pocos usuarios internos |
| [Separar la importación y exportación](#separar-la-importación-y-exportación) | Un nodo | Nodo independiente | Servicio en línea multiusuario dentro de la capacidad de un nodo |
| [Varios nodos](#varios-nodos-de-colaboración) | Varios nodos | Nodo independiente | Más allá de la capacidad de un nodo, o conmutación por error entre nodos |

## Una sola máquina

Todos los componentes funcionan en un solo proceso Node.js, y el navegador se conecta a ese proceso directamente.

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"Navegador\"]) --> App[\"Colaboración + Exchange\"]\n    App --> DB[(\"Base de datos\")]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

- El Database Adapter implementa el contrato `IDatabaseAdapter`; consulta [Adaptadores de base de datos](/server/collaboration/database-adapters).
- Importación y exportación son proporcionados por Servicio de Intercambio y Servicio de Archivo. Ver [Módulos de extensión de colaboración](/server/collaboration/extensions).
- Conversión es CPU-bound, por lo que un archivo grande retarda la colaboración.

Mueva la importación y la exportación a un nodo separado cuando las conversiones comienzan a afectar la latencia de la colaboración, o cuando el servicio debe seguir siendo sensible para muchos usuarios.

## Separar la importación y exportación

La importación y exportación se ejecutan en un nodo dedicado mientras la colaboración permanece en un solo nodo. La puerta de entrada recorre los dos tipos de solicitudes por separado, y ambas partes utilizan la misma base de datos.

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"Navegador\"]) --> Gateway[\"Gateway\"]\n    Gateway -->|\"Solicitudes de colaboración\"| Node[\"Nodo de colaboración\"]\n    Gateway -->|\"Solicitudes de importación y exportación\"| Exchange[\"Nodo de importación y exportación\"]\n    Node --> DB[(\"Base de datos\")]\n    Exchange --> DB\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

El nodo de importación y exportación monta el Adaptador de Bases de Datos, un `UniverCollabService`, Servicio de Archivo y Servicio de Intercambio, y luego trabaja directamente con la base de datos. Los puntos de inyección son los mismos que en una sola máquina. Ambos nodos apuntan Servicio de Archivo en el mismo almacenamiento de archivos, y ambos instalan la misma autorización Middleware en `UniverCollabService`.

La memoria del proceso limita el número de documentos que un nodo de colaboración puede servir. Muévete a múltiples nodos cuando esa capacidad se exceda, o cuando se requiera la falla.

## Varios nodos de colaboración

Varios nodos de colaboración ejecutan el mismo código contra la misma base de datos. Un adaptador pub/sub relés Habitaciones, Presencia y transmisiones entre los nodos, y una tienda de entradas comparte entradas Sesión Tickets. `@univerjs-pro/collaboration-cluster-redis` proporciona la implementación de Redis. Cada nodo utiliza la misma Licencia, que cubre el número de nodos que se ejecutan; véase [nodos de colaboración](/server/collaboration/license#nodes). Para una implementación de referencia, vea [Nodos múltiples](/server/collaboration/examples#multi-node).

Cada nodo de colaboración pasa por el adaptador Redis pub/sub y la tienda de entradas al Endpoint. El resto de la asamblea no se cambia:

```ts
import { createClient } from "redis";
import { RedisPubSubAdapter, RedisSessionTicketStore } from "@univerjs-pro/collaboration-cluster-redis";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";

const client = createClient({ url: process.env.REDIS_URL });
const subClient = client.duplicate();
await Promise.all([client.connect(), subClient.connect()]);

const pubSub = new RedisPubSubAdapter({ pubClient: client, subClient });
const ticketStore = new RedisSessionTicketStore({ client });
const endpoint = new UniverCollabEndpoint(service, { pubSub, ticketStore });
```

## Más allá

Un documento muy grande ralentiza las solicitudes de documentos pequeños en el mismo nodo. Dividir las piscinas de nodo por tamaño de documento y dejar que la ruta de entrada documentos grandes a una piscina dedicada. La clave de enrutamiento sigue siendo el ID de unidad, y cada piscina comparte la base de datos y pub/sub.
