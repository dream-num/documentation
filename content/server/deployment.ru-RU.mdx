Приложение Server SDK имеет три формы развертывания, и масштаб приложения определяет, какой из них использовать. Начните с [Collaboration SDK](/server/collaboration/overview), [импорт и экспорт](/server/import-export) и [примеры](/server/collaboration/examples) чтобы увидеть, как собираются модули. Развертывание определяет только то, сколько узлов запускают ту же самую сборку.

| Форма | Совместное редактирование | Импорт и экспорт | Рекомендуемый масштаб |
| --- | --- | --- | --- |
| [Одна машина](#одна-машина) | Один узел | Тот же узел | Локальные приложения, разработка и тестирование, несколько внутренних пользователей |
| [Отдельный импорт и экспорт](#отдельный-импорт-и-экспорт) | Один узел | Отдельный узел | Многопользовательский онлайн-сервис в пределах емкости одного узла |
| [Несколько узлов](#несколько-узлов-совместного-редактирования) | Несколько узлов | Отдельный узел | Сверх емкости одного узла или при необходимости переключения между узлами |

При выборе конфигурации одного узла сопоставьте размер документов, число одновременных редакторов и частоту отправок с данными отчёта [«Производительность совместного редактирования»](/server/collaboration/performance).

## Одна машина

Все компоненты выполняются в одном процессе Node.js, и браузер подключается к этому процессу напрямую.

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"Браузер\"]) --> App[\"Совместное редактирование + Exchange\"]\n    App --> DB[(\"База данных\")]\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

- Database Adapter реализует контракт `IDatabaseAdapter`; см. [Адаптеры баз данных](/server/collaboration/database-adapters).
- Импорт и экспорт предоставляются Exchange Service и File Service. См. [Модули расширения совместной работы](/server/collaboration/extensions).
- Конверсия связана с процессором, поэтому большой файл замедляет совместную работу.

Переместить импорт и экспорт в отдельный узел, когда конверсии начинают влиять на задержку совместной работы, или когда сервис должен оставаться отзывчивым для многих пользователей.

## Отдельный импорт и экспорт

Импорт и экспорт выполняются на выделенном узле, в то время как сотрудничество остается на одном узле. Шлюз направляет два вида запросов отдельно, и обе стороны используют одну и ту же базу данных.

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"Браузер\"]) --> Gateway[\"Шлюз\"]\n    Gateway -->|\"Запросы совместного редактирования\"| Node[\"Узел совместного редактирования\"]\n    Gateway -->|\"Запросы импорта и экспорта\"| Exchange[\"Узел импорта и экспорта\"]\n    Node --> DB[(\"База данных\")]\n    Exchange --> DB\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

Узел импорта и экспорта собирает Адаптер базы данных, `UniverCollabService`, Службу файлов и Службу обмена, а затем работает непосредственно с базой данных. Точки впрыска те же, что и на одной машине. Оба узла указывают Службу файлов на одно и то же хранилище файлов, и оба устанавливают на `UniverCollabService` одну и ту же авторизацию Middleware.

Память процессов ограничивает количество документов, которые может обслуживать один узел совместной работы. Переместить на несколько узлов, когда эта емкость превышена, или когда требуется отказоустойчивость.

## Несколько узлов совместного редактирования

Несколько узлов совместной работы запускают один и тот же код против одной и той же базы данных. Адаптер паба/суба ретранслирует комнаты, присутствие и трансляции между узлами, а магазин билетов делит сессионные билеты. `@univerjs-pro/collaboration-cluster-redis` Каждый узел использует одну и ту же Лицензию, которая охватывает количество запущенных узлов; см. [Ноды совместной работы](/server/collaboration/license#nodes)Для справочной реализации см. [многоузловый](/server/collaboration/examples#multi-node).

Каждый узел совместной работы передает адаптер паба/подложки Redis и магазин билетов в конечную точку. Остальная часть сборки неизменна:

```ts
import { createClient } from "redis";
import { RedisPubSubAdapter, RedisSessionTicketStore } from "@univerjs-pro/collaboration-cluster-redis";
import { UniverCollabEndpoint } from "@univerjs-pro/collaboration-endpoint";

const client = createClient({ url: process.env.REDIS_URL });
const subClient = client.duplicate();
await Promise.all([client.connect(), subClient.connect()]);

const pubSub = new RedisPubSubAdapter({ pubClient: client, subClient });
const ticketStore = new RedisSessionTicketStore({ client });
const endpoint = new UniverCollabEndpoint(service, { pubSub, ticketStore });
```

## Дальше

Один очень большой документ замедляет запросы на небольшие документы на одном и том же узле. Разделите пулы узлов по размеру документа и позвольте шлюзу направлять большие документы в выделенный пул. Ключ маршрутизации по-прежнему является идентификатором блока, и каждый пул делится базой данных и пабом/субъектом.
