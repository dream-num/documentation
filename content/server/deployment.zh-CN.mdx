本页按规模介绍 Server SDK 应用的三种部署形态。先阅读 [Collaboration SDK](/server/collaboration/overview)、
[导入导出](/server/import-export)和[示例](/server/collaboration/examples)，了解模块如何组装；部署是把同一套
组装放到一个或多个节点上。每种形态都可以作为终点。

| 形态                  | 协同     | 导入导出 | 推荐规模                         |
| --------------------- | -------- | -------- | -------------------------------- |
| [单机](#单机)         | 一个节点 | 同一节点 | 本地应用、开发测试、少量内部用户 |
| [服务拆分](#服务拆分) | 一个节点 | 独立节点 | 多人线上服务，单节点容量以内     |
| [多节点](#多协同节点) | 多个节点 | 独立节点 | 超出单节点容量，或需要故障切换   |

## 单机

一个 Node.js 进程承载协同和导入导出，浏览器直接连接。存储用 SQLite，或通过自定义 Database Adapter
接入你的数据库。参考示例：[Exchange](/server/collaboration/examples#exchange)，协同和导入导出在同一进程。

| 组件     | 部署方式            | 共享                       |
| -------- | ------------------- | -------------------------- |
| 协同     | 一个节点            | 与导入导出共享 CPU 和内存  |
| 导入导出 | 同一节点            | 与协同共享 CPU 和内存      |
| 存储     | SQLite 文件或数据库 | 本节点                     |

- SQLite 持久化并自动建表，写入串行；Memory Adapter 只用于本地验证。
- 一次转换是 CPU 密集型的，大文件会拖慢协同。
- 单副本运行，重启会断开所有 Session。

导入导出影响协同响应、提交排队，或要面向多人持续服务时，进入服务拆分。

## 服务拆分

网关转发 HTTP 和 WebSocket；协同一个节点；导入导出独立节点；两者连同一个数据库。两项拆分互相独立。

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"浏览器\"]) -->|\"HTTPS / WSS\"| Gateway[\"网关\"]\n    Gateway -->|\"协同\"| Node[\"协同节点<br/>Transport · Endpoint · Service\"]\n    Gateway -->|\"上传 · 任务 · 下载\"| Exchange[\"导入导出节点<br/>Service + Exchange\"]\n    Node --> DB[(\"数据库\")]\n    Exchange --> DB\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

| 组件     | 部署方式                       | 共享                     |
| -------- | ------------------------------ | ------------------------ |
| 网关     | 分别路由协同和导入导出路径     | 仅转发                   |
| 协同     | 一个节点                       | 数据库                   |
| 导入导出 | 独立节点，按 CPU 和内存扩缩容  | 数据库：Unit、任务、文件 |
| 存储     | 数据库                         | 所有节点                 |

- Database Adapter 实现 `IDatabaseAdapter` 契约，注入点相同，见 [Database Adapter](/server/collaboration/database-adapters)。
- 导入导出节点组装 Database Adapter、`UniverCollabService` 和转换模块，直接访问数据库。
- 任务和文件放在所有副本都能访问的存储里；任务设超时，下载链接过期。见[文件交换集成](/server/import-export)。

协同仍是一个节点，能服务的文档数受进程内存限制。超出容量或需要故障切换时进入多节点。

## 多协同节点

多个协同节点运行同一份代码，连同一个数据库。pub/sub adapter 在节点间中继 Room、Presence 和广播，
ticket store 共享 Session Ticket，`@univerjs-pro/collaboration-cluster-redis` 提供 Redis 实现。参考示例：[Multi-node](/server/collaboration/examples#multi-node)。

<Mermaid chart={"%%{init: {\"themeVariables\": {\"fontSize\": \"14px\"}, \"flowchart\": {\"nodeSpacing\": 24, \"rankSpacing\": 40, \"padding\": 12}}}%%\nflowchart LR\n    Browser([\"浏览器\"]) -->|\"HTTPS / WSS\"| Gateway[\"网关\"]\n    subgraph Nodes[\"协同节点\"]\n        direction TB\n        A[\"节点 A\"]\n        B[\"节点 B\"]\n    end\n    Gateway -->|\"WebSocket 与提交<br/>按 unit ID\"| A\n    Gateway -->|\"其余请求<br/>任意节点\"| B\n    Gateway -->|\"上传 · 任务 · 下载\"| Exchange[\"导入导出节点 ×N\"]\n    A --- PubSub[(\"pub/sub + ticket store\")]\n    B --- PubSub\n    A --> DB[(\"数据库\")]\n    B --> DB\n    Exchange --> DB\n    classDef default rx:8,ry:8,stroke-width:1px\n    classDef actor fill:transparent,stroke:none\n    class Browser actor"} />

| 组件     | 部署方式                        | 共享                          |
| -------- | ------------------------------- | ----------------------------- |
| 网关     | WebSocket 和提交按 unit ID 路由 | 仅转发                        |
| 协同     | N 个相同节点                    | 数据库、pub/sub、ticket store |
| 导入导出 | 独立节点                        | 数据库                        |
| 存储     | 数据库                          | 所有节点                      |

- 创建 pub/sub adapter 和 ticket store 传给 `UniverCollabEndpoint`，其余组装保持原样，见[包概览](/server/collaboration/packages)。
- 网关把同一文档的 WebSocket 和提交固定到一个节点，其余请求任意节点，见[网关配置](https://github.com/dream-num/univer-collaboration-examples/blob/main/examples/multi-node/README.zh-CN.md#配置网关)。
- Redis 以高可用方式运行；节点故障时客户端经网关重连到其他节点。

## 进一步

- 转换交给独立扩缩容的 worker：任务在数据库，文件在对象存储，由队列派发。
- 按租户或文档大小划分节点池，路由键仍是 unit ID，各池共享数据库和 pub/sub。
- History、Thread Comment 和 Worktree 遵循同样的形态，见[协同扩展模块](/server/collaboration/extensions)。
