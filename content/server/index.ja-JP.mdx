バックエンドはドキュメントを保存し、ユーザー権限を検証して、共同編集やファイル変換のインターフェースを提供します。現在のリリースでは [Server SDK](/server) を使い、自分のアプリケーション環境にこれらの機能を組み込みます。

このページではバックエンドの設定、ストレージ、権限を説明します。[共同編集の統合](/server/collaboration/browser-integration)ではエディターを共有ドキュメントに接続し、[ファイル交換の統合](/server/import-export)ではアップロード、変換、ダウンロードを扱います。必要な機能のガイドを選んでください。ライセンスが必要な機能は[ライセンス設定](/guides/license)から始めます。ブラウザー内だけでの編集に共同編集サービスは不要です。

## 統合の順序

1. [Quick Start](/server/collaboration/quick-start)：独立した 2 つのブラウザー環境で双方向編集を確認します。
2. [永続化](/server/collaboration/database-adapters#verify-persistence)：SQLite サンプルを再起動し値を確認します。
3. [認証と権限](/server/collaboration/identity-and-authorization#verify-permissions)：editor と viewer を確認します。
4. [業務フロントエンド](/server/collaboration/browser-integration)：デモの認証、文書作成、URL を置き換えます。
5. [拡張機能](/server/collaboration/examples)：履歴、コメント、Worktree、Exchange を追加します。ファイル変換だけなら [Exchange](/server/import-export/node) から開始できます。

## 必要なサービスを選ぶ

| 要件 | バックエンドの準備 | 実装ガイド |
| --- | --- | --- |
| 共有ドキュメントの編集 | Collaboration SDK、ドキュメント保存、権限 | [共同編集クイックスタート](/server/collaboration/quick-start) |
| Office ファイルの入出力 | 変換、アップロード、タスク照会、ダウンロード | [ファイル変換](/server/import-export/node)と [Exchange の例](/server/collaboration/examples#exchange) |
| 履歴や共有コメント | それぞれのサービス、ストレージ、権限 | [拡張モジュール](/server/collaboration/extensions) |

必要な機能だけを選びます。ファイル変換だけなら共同編集は不要です。[SDK 環境](/server/requirements)を準備し、Univer パッケージのバージョンに互換性を持たせてください。

## アプリケーションとストレージの接続

選んだサービスの例を実行してから、バックエンドに接続します。共同編集ドキュメントはアプリケーションが作成し、所有者を記録して ID をブラウザーに返します。作成 API は[モジュールの境界](/server/collaboration/modules)を参照してください。ユーザー、プロジェクト、フォルダーは引き続きアプリケーションが管理します。

共同編集の例はメモリストレージを使用するため、再起動で内容が失われます。[データベースアダプター](/server/collaboration/database-adapters)に従ってデータベースを接続し、保存したドキュメントが再起動後も残ることを確認してください。

ファイル変換でもアップロード、タスク、ダウンロードの保存とクリーンアップが必要です。[Exchange の例](/server/collaboration/examples#exchange)を参照してください。

## ログインと権限の接続

[ID と認可](/server/collaboration/identity-and-authorization)に従って既存のログイン資格情報を検証し、ユーザーがドキュメントを読み取り・変更できるか確認します。例の固定ユーザーと全許可のルールを置き換えてください。

ドキュメントの読み取り、共同編集接続、編集内容の送信、有効にした履歴・コメント・ダウンロードを保護します。ブラウザーの読み取り専用設定はサーバーの権限検証の代わりにはなりません。

## デプロイとフロントエンドの接続

アプリケーションのドメインにインターフェースを配置します。共同編集ではプロキシが HTTP と WebSocket の両方を転送する必要があり、HTTPS ページは WSS を使います。アップロードを制限し、変換失敗とタイムアウトを処理してください。

バックエンドの準備ができたら、対象機能の統合を完了します。

- [共同編集の統合](/server/collaboration/browser-integration)：エディターの接続、共有ドキュメントの作成と表示、同期の検証。
- [ファイル交換の統合](/server/import-export)：アップロード、変換、ダウンロードの接続と実際のファイルでの確認。
