El Univer Office SDK consta de tres partes: [Web SDK](/guides/sheets) ejecuta editores y procesos integrados contenidos en modo sin cabeza[^headless-mode]; [Server SDK](/server) maneja la colaboración y el intercambio de archivos; y [AI SDK](/ai) cubre los flujos de trabajo del agente.

**Univer** es un conjunto de herramientas para la construcción de aplicaciones de Office en las que las personas y Agentes AI trabajan en el mismo contenido. Una aplicación puede proporcionar una interfaz web para las personas, un CLI para Agentes, y un Servidor que ambos comparten, o puede tomar sólo las partes que necesita.

## Composición de los SDK

| Componente | Entorno | SDK principal | Proporciona | Responsabilidad de la aplicación |
| --- | --- | --- | --- | --- |
| Web | Navegador | Web SDK | Un editor que muestra y edita Contenido de Office en el navegador | UI, interacciones de productos e integración del navegador |
| CLI | Node.js | AI SDK | Inspección y edición de agentes de inteligencia artificial | Flujos AI Agent, llamadas a herramientas y límites de tareas |
| Server | Node.js | Server SDK (Collaboration, Exchange) | Colaboración autoalojada e intercambio Office | API de negocio, identidad, permisos, archivos y despliegue |

Cada parte tiene su propia sección: [Web SDK](/guides/sheets) cubre editores, [Server SDK](/server) abarca servicios de colaboración e intercambio de archivos, y [AI SDK](/ai) incluye operaciones de contenido para Agentes AI.

AI SDK reutiliza las capacidades de contenido sin cabeza de Web SDK. Estos componentes identifican los principales puntos de entrada del desarrollador y el tiempo de funcionamiento de cada parte. No son tres pilas aisladas, y ninguno de ellos es un producto terminado que se puede implementar sin código de aplicación.

## Integrar importación y exportación

El Server SDK módulo `@univerjs-pro/exchange-node` convertidos entre archivos de Office y Univer La aplicación incrusta el módulo de conversión y proporciona la carga, conversión y descarga API. Web SDK maneja el lado del navegador, y un CLI puede llamar al módulo de conversión en Node.js. Configuración del navegador para cada producto permanece en el producto Web SDK documentación.

- **Sin edición colaborativa:** convierte un archivo en una instantánea de documentos, luego abre y edita esa instantánea en el navegador. Para exportar, pasa la última instantánea al módulo de conversión, que produce el archivo. Este flujo requiere conversión del lado del servidor pero no servicio de colaboración.
- **Con la edición colaborativa:** almacenan los datos importados como documento colaborativo. Web SDK y AI SDK luego operan en el mismo contenido a través de su ID de documento. Antes de exportar, sincronizar las ediciones actuales, luego leer los últimos datos de documentos y convertirlo.

Si sólo se necesita la conversión, ejecute Exchange en un proceso Node.js local o un servicio remoto; ni AI SDK ni edición colaborativa es necesaria. [Integración del intercambio de archivos](/server/import-export) describe el flujo de aplicación, y [Importación y exportación de archivos de oficinas](/server/import-export/node) muestra cómo utilizar el módulo de conversión.

## Formas de despliegue

| Forma | Web | CLI | Server | Uso |
| --- | --- | --- | --- | --- |
| Aplicación local | Navegador local/UI de escritorio | Proceso local | Proceso local | Office de escritorio con AI Agent local |
| SaaS | Navegador | Dispositivo del usuario/AI Agent en nube | Servicio remoto | Varios usuarios y operación centralizada |
| Web + Server | Navegador | — | Local o remoto | Sin entrada AI Agent todavía |
| Solo Web | Navegador/UI de escritorio | — | — | Edición local, individual y no colaborativa |

Todos los componentes pueden funcionar en una máquina, o pueden ser distribuidos en dispositivos de usuario e infraestructura de nube. La ubicación de despliegue no cambia la responsabilidad de cada componente. Una vez que un servidor está presente, Web y CLI lo utilizan para acceder a contenidos compartidos y capacidades de producto.
