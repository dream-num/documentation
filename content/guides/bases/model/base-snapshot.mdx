## IBaseSnapshot

`IBaseSnapshot` is the format that Univer Bases writes to storage. A snapshot describes one Base unit: its tables and their order, the schema version, timestamps, and optional revision metadata.

### Properties

| Property | Type | Description |
| --- | --- | --- |
| id | `string` | Unique ID of the Base unit. |
| name | `string` | Name of the Base. |
| schemaVersion | `number` | Snapshot schema version. |
| tables | `Record\<string, ITableSnapshot\>` | Tables keyed by table ID. |
| tableOrder | `string[]` | Ordered list of table IDs. |
| createdAt | `number` | Creation timestamp. |
| updatedAt | `number` | Timestamp of the last update. |
| createdBy? | `string` | ID of the creator. |
| rev? | `number` | Optional revision value, used by the persistence or collaboration layers. |

## Minimal snapshot

```ts
const baseSnapshot = {
  id: 'base-1',
  name: 'Product tracker',
  schemaVersion: 1,
  tableOrder: ['tasks'],
  tables: {
    tasks: {
      id: 'tasks',
      name: 'Tasks',
      primaryFieldId: 'title',
      fieldOrder: ['title', 'status'],
      fields: {
        title: { id: 'title', name: 'Title', type: 'text', config: {} },
        status: { id: 'status', name: 'Status', type: 'singleSelect', config: {} },
      },
      recordOrder: ['rec-1'],
      records: {
        'rec-1': {
          id: 'rec-1',
          values: { title: 'Write docs', status: 'In progress' },
          orderKey: 'a0',
          createdAt: Date.now(),
          updatedAt: Date.now(),
        },
      },
      views: {},
      viewOrder: [],
    },
  },
  createdAt: Date.now(),
  updatedAt: Date.now(),
}
```

## Usage

`IBaseSnapshot` serves the following cases:

1. Create a `UniverInstanceType.UNIVER_BASE` unit.
2. Persist and restore structured data.
3. Prepare data for server-side processing.
4. Transfer data between collaboration and import/export services.

<Callout type="warning">
  A snapshot object is persistence data. Once a Base is running, use the Facade API instead of mutating the snapshot directly.
</Callout>

## Save and restore

Call `save()` on the Facade to include resources from registered plugins, such as dashboards and local comments. In the example, `saveToBackend` represents the persistence function of the application:

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')
await saveToBackend(base.save())
```

In a new editor instance, register the same plugins first, then restore with `univerAPI.createBase(savedSnapshot)`. Do not persist only `tables`, and do not mutate the snapshot of the running model in place.
