## IBaseSnapshot

`IBaseSnapshot` — формат, который Univer Bases записывает в хранилище.Снимок описывает один базовый блок: его таблицы и их порядок, версию схемы, временные метки и необязательные метаданные пересмотра.

### Свойства

| Свойство | Тип | Описание |
| --- | --- | --- |
| id | `string` | Уникальный идентификатор экземпляра Base. |
| name | `string` | Название базы. |
| schemaVersion | `number` | Версия схемы снимка. |
| tables | `Record\<string, ITableSnapshot\>` | Таблицы, где ключом служит идентификатор таблицы. |
| tableOrder | `string[]` | Упорядоченный список идентификаторов таблиц. |
| createdAt | `number` | Временная метка создания. |
| updatedAt | `number` | Таймстэмп последнего обновления. |
| createdBy? | `string` | Идентификатор создателя. |
| rev? | `number` | Факультативное значение пересмотра, используемое уровнями настойчивости или совместной работы. |

## Минимальный снимок

```ts
const baseSnapshot = {
  id: 'base-1',
  name: 'Product tracker',
  schemaVersion: 1,
  tableOrder: ['tasks'],
  tables: {
    tasks: {
      id: 'tasks',
      name: 'Tasks',
      primaryFieldId: 'title',
      fieldOrder: ['title', 'status'],
      fields: {
        title: { id: 'title', name: 'Title', type: 'text', config: {} },
        status: { id: 'status', name: 'Status', type: 'singleSelect', config: {} },
      },
      recordOrder: ['rec-1'],
      records: {
        'rec-1': {
          id: 'rec-1',
          values: { title: 'Write docs', status: 'In progress' },
          orderKey: 'a0',
          createdAt: Date.now(),
          updatedAt: Date.now(),
        },
      },
      views: {},
      viewOrder: [],
    },
  },
  createdAt: Date.now(),
  updatedAt: Date.now(),
}
```

## Использование

`IBaseSnapshot` обслуживает следующие случаи:

1. Создание экземпляра `UniverInstanceType.UNIVER_BASE`.
2. Сохранение и восстановление структурированных данных.
3. Подготовка данных для обработки на стороне сервера.
4. Передача данных между сервисами совместной работы и импорта/экспорта.

<Callout type="warning">
  Объектом снимка являются данные о стойкости. Как только База запущена, используйте Facade API вместо того, чтобы мутировать снимок напрямую.
</Callout>

## Сохранение и восстановление

Позвоните `save()` на Facade, чтобы включить ресурсы из зарегистрированных плагинов, таких как панели инструментов и локальные комментарии. В примере `saveToBackend` представляет функцию персистентности приложения:

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')
await saveToBackend(base.save())
```

В новом экземпляре редактора сначала зарегистрируйте те же плагины, а затем восстановите с помощью `univerAPI.createBase(savedSnapshot)`. Не сохраняйте только `tables` и не мутируйте снимок запущенной модели на месте.
