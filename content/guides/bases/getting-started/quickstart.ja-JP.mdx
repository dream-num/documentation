Bases API とそのドキュメントを介した4つのコンセプト。ベースがどのように組み込まれ、保存、変更、および制御されるかをカバーし、Univer Bases をインストールする前に理解すべきである。

## 基本概念 [#basic-concepts]

### プラグイン

Univerは、プラグインとして機能します。 `@univerjs-pro/bases`には、ベースモデル、そのコマンド、および`UniverBasesPlugin`が含まれています。 `@univerjs-pro/bases-ui` にはスタンドアローンのワークベンチと`UniverBasesUIPlugin`が含まれます。 モデルプラグインは、式エンジンを使用しており、式フィールドはベース計算パイプラインに参加します。

アプリケーションが必要とする製品プラグインのみを登録します。 [インストールガイド](/guides/bases/getting-started/installation)は、完全なブラウザのセットアップとそれの背後にある技術的な依存性を提供します。

### スナップショットとデータモデル

`IBaseSnapshot`は、単一のベースユニットの持続的なフォーマットです。テーブルと注文が含まれています。各テーブルには、フィールド、レコード、ビュー、各コレクションの注文が含まれています。ビューは同じレコード上の投影であるため、ビューを切り替えることは、データの別のコピーを作成しません。

スナップショットはベースを作成、保存、または復元します。 ユニットが実行されると、スナップショットオブジェクトを直接変更しないでください。 スキーマは、[ベーススナップショット](/guides/bases/model/base-snapshot)と[テーブル、フィールド、レコード](/guides/bases/model/tables-fields-records)で記述されています。

### コマンド

実行時に変更するコマンドを実行します。テーブルの作成、フィールドの更新、レコードの編集、またはコマンドレイヤーまたはファサードレイヤーによるビューの変更は、モデル、UI、undo/redo、およびコラボレーションパスを同期に保ちます。

アプリケーションコードはFacade APIを使用する必要があります。Facadeが露出しない低レベルの統合のためにコマンドIDを直接使用してください。

### Facade API

Facade API は、ベースコマンドとモデルレイヤーを上回るオブジェクトレイヤーを提供します。ベース、テーブル、フィールド、レコード、ビュー。モデルの操作で `@univerjs-pro/bases/facade` をインポートし、UI 状態の `@univerjs-pro/bases-ui/facade` は、プラグインを登録した後に `FUniver.newAPI(univer)` を呼び出します。

次に、[インストールと基本的な使い方](/guides/bases/getting-started/installation)を読んで、[ベース Facade APIガイド](/guides/bases/getting-started/facade)に従ってベースデータを作成および編集します。
