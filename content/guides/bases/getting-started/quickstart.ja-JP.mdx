Univer Bases をインストールする前に、API とドキュメント全体で使われる 4 つの基本概念を確認します。これらは Base の構成、保存、変更、操作方法を表します。

## 基本概念 [#basic-concepts]

### プラグイン

Univer の機能はプラグインとして提供されます。`@univerjs-pro/bases` は Base モデル、コマンド、`UniverBasesPlugin` を提供し、`@univerjs-pro/bases-ui` は独立したワークベンチと `UniverBasesUIPlugin` を提供します。数式フィールドを Bases の計算処理に統合するため、モデルプラグインは Pro 数式エンジンも利用します。

アプリケーションに必要な製品プラグインだけを登録してください。[インストールガイド](/guides/bases/getting-started/installation)では、ブラウザー向けの完全な構成と技術的な依存関係を説明します。

### スナップショットとデータモデル

`IBaseSnapshot` は 1 つの Base ユニットを永続化する形式です。テーブルとその順序を持ち、各テーブルはフィールド、レコード、ビュー、および各コレクションの順序を持ちます。ビューは同じレコードに対する投影であり、ビューを切り替えてもデータは複製されません。

スナップショットは Base の作成、保存、復元に使います。ユニットの実行後は、スナップショットオブジェクトを直接変更しないでください。スキーマについては [Base スナップショット](/guides/bases/model/base-snapshot)と[テーブル、フィールド、レコード](/guides/bases/model/tables-fields-records)を参照してください。

### コマンド

実行中の変更はコマンドを経由します。テーブルの作成、フィールドの更新、レコードの編集、ビューの変更をコマンドまたは Facade 経由で行うことで、モデル、UI、元に戻す／やり直す、共同編集の経路が一致します。

アプリケーションコードでは Facade API を優先してください。Facade にない低レベル統合が必要な場合に限り、コマンド ID を直接使用します。

### Facade API

Facade API は Bases のコマンド層とモデル層を、Base、テーブル、フィールド、レコード、ビューのオブジェクトとして扱えるようにします。モデル操作には `@univerjs-pro/bases/facade`、UI 状態には `@univerjs-pro/bases-ui/facade` を読み込み、プラグイン登録後に `FUniver.newAPI(univer)` で API を作成します。

次に[インストールと基本使用](/guides/bases/getting-started/installation)へ進み、[Bases Facade API ガイド](/guides/bases/getting-started/facade)でデータの作成と編集を確認してください。
