## 全局生命周期

- **Starting**：Univer 正在初始化，尚未创建任何业务实例。
- **Ready**：首个业务实例已创建完成。之后再创建实例不会重新触发这个阶段。
- **Rendered**：标准 UI 已完成第一次渲染切换。此时异步内容可能仍在加载。
- **Steady**：标准 UI 在 Rendered 之后延迟一段时间进入这个阶段，不会等待所有异步任务结束。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="事件监听的范围">

`LifeCycleChanged` 报告的是 Univer 的全局阶段。如果在全局阶段已经到达 `Ready` 之后再加载插件 B，B 仍会执行 `onReady()`，但不会再触发一次全局 `Ready` 事件。

添加监听器后，回调可能立即收到当前阶段，包括 `Starting`。如果只需要了解 Univer 当前所处的阶段，可直接调用 `univerAPI.getCurrentLifecycleStage()`。

</Callout>

要移除监听器，销毁返回的 `disposable` 对象：

```typescript
disposable.dispose()
```

## 插件生命周期钩子

插件加载时执行 `onStarting()`，然后追赶上 Univer 当前所处的全局阶段。在不同时机加载 B，可以对比它与 A 的钩子调用顺序。

<LifecycleDemo />

通用插件在注册时加载。业务类型插件通常在创建该类型的第一个实例之前加载。如果某个类型已经启动，新加入的插件会在一个延迟批次中加载。显式依赖可以使插件更早加载。

每一批次都同步调用钩子，按依赖顺序逐阶段执行，不等待钩子中的异步任务。访问所需的实例、DOM 元素或资源之前，应先确认其已经就绪。
