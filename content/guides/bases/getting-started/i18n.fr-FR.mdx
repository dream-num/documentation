## Langue de l’interface

`locale` sélectionne le paquet langue pour les menus, les tooltips, les dialogues, et le reste de l'interface traduite. Les fichiers `locales` sont enregistrés sans en sélectionner un. Le paramètre est partagé par les unités de l'instance Univer. Il prend des valeurs `LocaleType`, comme `LocaleType.EN_US` .

- **Tous les produits: UI**: `locale` modifie la langue des menus, tooltips, dialogues et étiquettes de plugins. Il ne traduit pas le contenu utilisateur ou ne renomme pas les unités existantes.
- **Feuilles: formats et formules de cellules**: Les nombres et les dates dans les cellules suivent une chaîne de repli: la redéfinition locale du format numéro, puis l'instantané du cahier de travail `locale`, puis l 'instance `locale`. `region` ne remplace aucun d'entre eux. Le comportement de la formule comme `DOLLAR` et le format de devise des résultats financiers suivent toujours `locale` comme la normalisation des entrées CJK.
- **Docs: statistiques**: `locale` détermine comment le texte est segmenté et compté.

### Changer la langue à l’exécution

Chargez les paquets de langue pour chaque plugin installé ou préréglage avant de changer de langue. `loadLocales()` fusionne les traductions sans commutation; `setLocale()` sélectionne à partir de ce qui est déjà chargé et ne télécharge rien. Une clé de traduction manquante s'affiche comme la clé elle-même. L'exemple ci-dessous charge le paquet d'interface utilisateur partagé; ajoutez les paquets de langage cible pour les autres plugins installés au même appel.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

`mergeLocales` combine les packs de langues de plusieurs plugins ou presets en un seul objet complet.

### Packs linguistiques personnalisés

Vous pouvez également écrire un paquet de langage personnalisé : assemblez l'objet dont vous avez besoin et passez-le à l'instance `Univer`. Les paquets de langage expédiés par les presets vivent habituellement dans `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Contribuer aux traductions

Univer fournit les paquets de langues intégrés suivants:

- `zh-CN` : chinois simplifié
- `en-US` : anglais
- `zh-TW` : chinois traditionnel
- `zh-HK` : chinois traditionnel (Hong Kong)
- `ru-RU` : russe
- `vi-VN` : vietnamien
- `fa-IR` : persan
- `fr-FR` : français
- `ja-JP` : japonais
- `ko-KR` : coréen
- `es-ES` : espagnol
- `ca-ES` : catalan
- `sk-SK` : slovaque
- `ar-SA` : arabe
- `de-DE` : allemand
- `id-ID` : indonésien
- `it-IT` : italien
- `pl-PL` : polonais
- `pt-BR` : portugais (Brésil)

Ce sont tous les packs de langage intégrés. Univer est un projet open source, et les développeurs du monde entier sont les bienvenus pour ajouter ou améliorer ces localités.

## Paramètres régionaux

`region` sélectionne les conventions régionales que les caractéristiques régionales suivent. Le réglage est partagé par les unités dans l'instance Univer.

Les deux paramètres prennent `LocaleType` valeurs. Par exemple, `LocaleType.EN_US` est `enUS`, pendant `en-US` est un nom de fichier langue-pack et une balise BCP 47. Ne pas passer les codes de pays tels que `US` ou `SG` comme `region`. Si l'interface utilisateur utilise une autre localité, la région n'exige pas que son paquet linguistique soit chargé.

Si `region` n'est jamais configuré, il suit `locale`, y compris les appels `setLocale()` ultérieurs. La configuration de `region` à l'initialisation ou l'appel `setRegion()` arrête cette suite automatique. Après cela, changer la langue conserve la région sélectionnée. Aucune API publique ne restaure l'automatique suivante; lorsque les deux doivent changer ensemble, définissez les deux explicitement.

Ajouter `region: LocaleType.DE_DE` à côté de `locale` dans `createUniver()` ou `new Univer()` pour conserver la langue UI pendant que les conventions régionales allemandes s'appliquent.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Ici, l'interface utilisateur passe à l'anglais alors que le formatage régional reste allemand. `getCurrentLocale()` et `getCurrentRegion()` retournent les identifiants réellement en vigueur. Pour changer les deux ensemble, appelez les deux setters avec la même valeur `LocaleType`.

- **Feuilles : contrôles des devises**: `region` détermine l'icône de monnaie dans la barre d'outils, les choix de monnaie et de comptabilité et leurs prévisualisations, et le format que la commande de monnaie s'applique.
- **Docs: statistiques** : `region` formate les nombres affichés dans la boîte de dialogue statistique et la barre d'état, y compris les séparateurs de regroupement. La modification de `region` ne modifie pas les règles de comptage.
- **Commentaires de filetage, lorsque activé**: `region` contrôle comment les dates et les heures sont affichées, à l'aide d'une horloge de 24 heures et de chiffres latins. `locale` contrôle le texte de l'interface utilisateur de commentaire. Ni les changements stockés horodatage, et `region` n'est pas un réglage de fuseau horaire.
- **Planches, diapositives, bases, PDFs**: `locale` contrôle l'interface utilisateur traduite. `region` est disponible pour les fonctionnalités partagées qui le lisent, comme les commentaires de thread après leur intégration. Il ne reformate pas automatiquement le tableau ou le texte de diapositive, les champs de base ou le contenu PDF.
