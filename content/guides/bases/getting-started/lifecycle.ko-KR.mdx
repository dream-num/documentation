## 전역 수명 주기

- **을 시작**: Univer는 초기화되고, 사업 단위는 아직 존재하지 않습니다.
- **지원하다**: 첫번째 사업 단위는 창조되었습니다. 나중에 단위는 이 단계를 다시 방아쇠하지 않습니다.
- **이름 ***: 표준 UI는 첫번째 렌더링 스위치를 완료했습니다. 비동기 내용은 아직도 적재될지도 모릅니다.
- **인기 카테고리**: 표준 UI는 렌더링 후 지연 후이 단계를 도달합니다. 모든 비동기 작업을 기다릴 수 없습니다.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="이벤트가 알리는 대상">

`LifeCycleChanged`는 Univer의 글로벌 단계를 보고합니다. 플러그인 B가 `Ready`에 도달한 후 로드되는 경우, B는 여전히 `onReady()`를 실행하지만, 두 번째 글로벌 `Ready` 이벤트가 방출되지 않습니다.

`Starting`를 포함한 현재 스테이지를 즉시 받을 수 있음을 청취하십시오. Univer가 직접 `univerAPI.getCurrentLifecycleStage()`로 호출하는 유일한 단계를 결정하려면.

</Callout>

청취자를 제거하려면 반환된 `disposable` 객체의 dispose:

```typescript
disposable.dispose()
```

## 플러그인 수명 주기 훅

플러그인은 `onStarting()`를 실행하면 현재 글로벌 단계로 이동할 수 있습니다. 다른 시간에 B를 로딩하면 후크가 A와 비교하는 방법을 보여줍니다.

<LifecycleDemo />

일반 플러그인은 등록에로드합니다. 비즈니스 유형 플러그인은 일반적으로 그 유형의 첫 번째 단위 이전에로드됩니다. 새로운 플러그인이 이미 시작된 유형에 추가되면, 그것은 방어 된 배치에로드됩니다. 명시적 의존도가 이전로드하는 플러그인을 일으킬 수 있습니다.

각 배치는 동시에 걸이, 1개의 단계 및 비동기 일을 기다리지 않고, 의존성 순서에서. 필요한 단위, DOM 성분, 또는 자원이 접근하기 전에 준비되어 있다는 것을 확인하십시오.
