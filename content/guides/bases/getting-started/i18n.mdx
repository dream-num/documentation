## Interface language

`locale` selects the language pack for menus, tooltips, dialogs, and the rest of the translated UI. `locales` registers packs without selecting one. The setting is shared by the units in the Univer instance. It takes `LocaleType` values, such as `LocaleType.EN_US`.

- **All products: UI**: `locale` changes the language of menus, tooltips, dialogs, and plugin labels. It does not translate user content or rename existing units.
- **Sheets: cell formats and formulas**: Numbers and dates in cells follow a fallback chain: the number-format locale override, then the workbook snapshot `locale`, then the instance `locale`. `region` does not replace any of them. Formula behavior such as `DOLLAR` and the currency format of financial results still follows `locale`, as does CJK input normalization.
- **Docs: statistics**: `locale` determines how text is segmented and counted.

### Changing language at runtime

Load the language packs for every installed plugin or preset before switching the language. `loadLocales()` merges translations without switching; `setLocale()` selects from what is already loaded and downloads nothing. A missing translation key is displayed as the key itself. The example below loads the shared UI pack; add the target-language packs for the other installed plugins to the same call.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Merging language packs [#mergeLocales]

`mergeLocales` combines the language packs of several plugins or presets into one complete language pack object.

### Custom language packs

You can also write a custom language pack: assemble the object that you need and pass it to the `Univer` instance. The language packs shipped by presets usually live in `<rootDir>/packages/<PLUGIN_NAME>/locale`.

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

- `de-DE`: German
- `id-ID`: Indonesian
- `it-IT`: Italian
- `pl-PL`: Polish

## Regional settings

`region` selects the regional conventions that regional features follow. The setting is shared by the units in the Univer instance.

Both settings take `LocaleType` values. For example, `LocaleType.EN_US` is `enUS`, while `en-US` is a language-pack file name and a BCP 47 tag. Do not pass country codes such as `US` or `SG` as `region`. If the UI uses a different locale, the region does not require its language pack to be loaded.

If `region` is never set, it follows `locale`, including later `setLocale()` calls. Setting `region` at initialization, or calling `setRegion()`, stops that automatic following. After that, changing the language keeps the selected region. No public API restores the automatic following; when the two should change together, set both explicitly.

Add `region: LocaleType.DE_DE` next to `locale` in either `createUniver()` or `new Univer()` to keep the UI language while German regional conventions apply.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Here the UI switches to English while regional formatting remains German. `getCurrentLocale()` and `getCurrentRegion()` return the identifiers actually in effect. To change both together, call both setters with the same `LocaleType` value.

- **Sheets: currency controls**: `region` determines the currency icon in the toolbar, the currency and accounting choices and their previews, and the format that the currency command applies. Changing it does not rewrite existing cell formats or convert monetary values.
- **Docs: statistics**: `region` formats the counts shown in the statistics dialog and the status bar, including grouping separators. Changing `region` does not change the counting rules.
- **Thread comments, when enabled**: `region` controls how dates and times are displayed, using a 24-hour clock and Latin digits. `locale` controls the comment UI text. Neither changes stored timestamps, and `region` is not a timezone setting.
- **Boards, Slides, Bases, PDFs**: `locale` controls the translated UI. `region` is available to shared features that read it, such as thread comments after they are integrated. It does not automatically reformat board or slide text, Base fields, or PDF content.
