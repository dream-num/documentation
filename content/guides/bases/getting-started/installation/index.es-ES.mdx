Esta página describe cómo instalar Univer Bases y cómo ejecutarlo después de la instalación. Bases se distribuye como un producto Univer Office SDK y actualmente utiliza el modo plugin.

Si los conceptos básicos de Univer no son familiares, lea [Quickstart](/guides/bases/getting-started/quickstart) primero.

Univer admite dos modos de integración: *Modo de inicio* y * Modo de plugin*. Precombina plugins y reduce el trabajo de configuración. Si necesita **profunda personalización o extensiones**, utilice Modo de plugin para que pueda seleccionar y configurar plugins individualmente.

## Configuración a través del modo complemento

Una aplicación Bases navegador normalmente registra el tiempo de ejecución compartido Univer, el motor de renderizado, la concha UI, el motor fórmula, y la licencia primero, luego el modelo Bases y los plugins UI.

### Uso del Administrador de paquetes

Utiliza una herramienta de compilación compatible con ES Modules y el campo `exports` de `package.json`.

#### Instalación

Univer construye su interfaz de usuario con React y utiliza RxJS para flujos de datos, y también se puede incrustar en Vue o Angular aplicaciones. Asegúrese de que las `react`, `react-dom`, y `rxjs` dependencias de pares[^peer-dependency] están instaladas.

Mantenga cada paquete `@univerjs/*` y `@univerjs-pro/*` en **la misma versión**.

#### Uso

Crear el contenedor con una altura explícita antes de inicializar Univer:

```html
<div id="app" style="height: 600px"></div>
```

Importar las entradas de fachada utilizadas a continuación antes de llamar `FUniver.newAPI(univer)`. Cargar el `@univerjs/design` CSS primero, luego el `@univerjs/ui`CSS, y el producto CSS último.

<Callout type="warning" title="Caution">
  - Registrar `UniverLicensePlugin` antes de los plugins Bases.
  - Importe el CSS de la interfaz de usuario compartido antes CSS de la interfaz de usuario del producto.
  - Utilice `UniverProFormulaEnginePlugin` de `@univerjs-pro/engine-formula` para Bases, incluyendo formas de panel. Si combina productos en una instancia `Univer`, sustitúyase cualquier importación y registro `UniverFormulaEnginePlugin` en lugar de registrar ambos motores de fórmula.
</Callout>

<Steps>
  <Step>
    Estilos de importación, paquetes locales, y los plugins que necesita:

    ```ts
    import { UniverBasesPlugin } from '@univerjs-pro/bases'
    import { UniverBasesUIPlugin } from '@univerjs-pro/bases-ui'
    import BasesUIEnUS from '@univerjs-pro/bases-ui/locale/en-US'
    import BasesEnUS from '@univerjs-pro/bases/locale/en-US'
    import { UniverProFormulaEnginePlugin } from '@univerjs-pro/engine-formula'
    import { UniverLicensePlugin } from '@univerjs-pro/license'
    import { LocaleType, mergeLocales, Univer, UniverInstanceType } from '@univerjs/core'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs-pro/bases-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Importar entradas de fachada si planea utilizar Facade API[^facade-entry]:

    ```ts
    import { FUniver } from '@univerjs/core/facade'
    import '@univerjs-pro/bases/facade'
    import '@univerjs-pro/bases-ui/facade'
    ```
  </Step>
  <Step>
    Cree una instancia Univer, registre los plugins y cree una unidad Base:

    ```ts
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          BasesEnUS,
          BasesUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverUIPlugin, { container: 'app' })

    univer.registerPlugin(UniverProFormulaEnginePlugin)
    univer.registerPlugin(UniverLicensePlugin, {
      license: process.env.CLIENT_LICENSE_TEXT,
    })
    univer.registerPlugin(UniverBasesPlugin)
    univer.registerPlugin(UniverBasesUIPlugin)

    univer.createUnit(UniverInstanceType.UNIVER_BASE, {})

    const univerAPI = FUniver.newAPI(univer)
    ```
  </Step>
</Steps>

#### Configuración de plugins [#plugin-configuration]

`UniverUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Elemento DOM donde se monta el editor o su ID. |

`UniverLicensePlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `license` | `string` |  | Contenido del archivo de licencia del cliente. |

#### Métodos `univer.registerPlugin` y `univer.registerPlugins` [#registerPlugin]

`univer.registerPlugin` registra un plugin en una instancia Univer. Llámalo después de crear la instancia.

La firma es `univer.registerPlugin(Plugin, options)`. `Plugin` es el plugin para registrarse, y `options` Es un objeto de configuración opcional. Cada plugin define sus propias opciones.

`univer.registerPlugins` toma un array y registra varios plugins en una llamada. Úsalo para mantener el registro de plugins en un solo lugar.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  [UniverUIPlugin, { container: 'app' }],

  UniverProFormulaEnginePlugin,
  [UniverLicensePlugin, {
    license: process.env.CLIENT_LICENSE_TEXT,
  }],
  UniverBasesPlugin,
  UniverBasesUIPlugin,
])
```

## Compatibilidad móvil [#mobile-support]

El paquete `@univerjs-pro/bases-ui` actual no exporta un plugin UI móvil dedicado. Ni una importación `MobileUIPlugin` ni una opción `mobile: true` existe, así que no escriba uno. Un contenedor estrecho no demuestra soporte táctil completo; prueba la interfaz de usuario existente en los dispositivos de destino.

## Otras versiones

Además de las versiones estables, Univer publica canales alfa y beta. Estos canales permiten probar nuevas características antes de su lanzamiento oficial. Nuevas características también conllevan riesgo: estas construcciones pueden contener fallos, funcionalidad incompleta o características inestables, así que evitelas en producción donde sea posible.

### Lanzamiento alfa/beta

Cuando el Univer el equipo completa una nueva característica o un cambio significativo, puede publicar un pre-release al canal de alfa o beta. Instalar una construcción alfa o de beta de un Univer paquete con estos comandos:

```package-install
npm install @univerjs-pro/bases@alpha # Alpha version
npm install @univerjs-pro/bases@beta # Beta version
```

Si encuentras un problema o tienes comentarios mientras usas una construcción alfa o beta, reporta al equipo Univer a través de [Cuestiones de GitHub](https://github.com/dream-num/univer/issues).
