## Глобальный жизненный цикл

- **Начинать**: Univer является инициализацией, и бизнес-единицы пока не существует.
- **Готовы**: Создано первое бизнес-подразделение. Позднее подразделения не запускают этот этап снова.
- **отданный**: Стандартный пользовательский интерфейс завершил свой первый переключатель рендеринга. Асинхронный контент все еще может загружаться.
- **стойкий**: Стандартный интерфейс достигает этой стадии после задержки после Rendered. Он не ждет всех асинхронных задач.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Что сообщает событие">

`LifeCycleChanged` сообщает о глобальной стадии Univer. Если плагин B загружается после того, как глобальная стадия достигла `Ready`, B по-прежнему работает под управлением `onReady()` , но второе глобальное событие `Ready` не испускается.

Слушатель, которого вы добавляете, может сразу же получить текущий этап, включая `Starting`. Чтобы определить, на какой стадии находится Univer, позвоните `univerAPI.getCurrentLifecycleStage()` напрямую.

</Callout>

Чтобы удалить слушателя, удалите возвращенный объект `disposable`:

```typescript
disposable.dispose()
```

## Хуки жизненного цикла плагинов

Плагин запускает `onStarting()`, когда он загружается, а затем догоняет текущую глобальную стадию. Загрузка B в разное время показывает, как его вызовы крючка сравниваются с вызовами A.

<LifecycleDemo />

Общие плагины загружаются при регистрации. Плагин бизнес-типа обычно загружается до создания первого блока этого типа. Если новый плагин добавляется к типу, который уже начался, он загружается в отложенной партии. Явная зависимость может вызвать загрузку плагина раньше.

Каждая партия вызывает крючки синхронно, по одному этапу за раз и в порядке зависимости, не дожидаясь асинхронной работы.Подтвердить, что необходимый блок, DOM-элемент или ресурс готов перед доступом к нему.
