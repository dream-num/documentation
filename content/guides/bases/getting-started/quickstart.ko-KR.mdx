Univer Bases를 설치하기 전에 API와 문서 전반에서 사용하는 네 가지 기본 개념을 확인하세요. 이 개념들은 Base를 구성하고 저장하고 변경하고 제어하는 방식을 설명합니다.

## 기본 개념 [#basic-concepts]

### 플러그인

Univer 기능은 플러그인으로 제공됩니다. `@univerjs-pro/bases`는 Base 모델, 명령, `UniverBasesPlugin`을 제공하고, `@univerjs-pro/bases-ui`는 독립형 워크벤치와 `UniverBasesUIPlugin`을 제공합니다. 수식 필드를 Bases 계산 흐름에 연결하기 위해 모델 플러그인은 Pro 수식 엔진도 사용합니다.

애플리케이션에 필요한 제품 플러그인만 등록하세요. [설치 가이드](/guides/bases/getting-started/installation)에서 브라우저용 전체 구성과 기술적 의존성을 확인할 수 있습니다.

### 스냅샷과 데이터 모델

`IBaseSnapshot`은 하나의 Base 단위를 영속화하는 형식입니다. 테이블과 테이블 순서를 포함하며, 각 테이블은 필드, 레코드, 뷰와 각 컬렉션의 순서를 포함합니다. 뷰는 같은 레코드를 다른 방식으로 투영하므로 뷰를 전환해도 데이터 사본이 새로 생기지 않습니다.

스냅샷은 Base를 생성하고 저장하고 복원할 때 사용합니다. 단위가 실행된 뒤에는 스냅샷 객체를 직접 수정하지 마세요. 스키마는 [Base 스냅샷](/guides/bases/model/base-snapshot)과 [테이블, 필드 및 레코드](/guides/bases/model/tables-fields-records)를 참고하세요.

### 명령

런타임 변경은 명령을 통해 수행됩니다. 명령 또는 Facade 계층으로 테이블 생성, 필드 업데이트, 레코드 편집, 뷰 변경을 수행하면 모델, UI, 실행 취소/다시 실행, 협업 흐름이 일관되게 유지됩니다.

애플리케이션 코드에서는 Facade API를 우선 사용하세요. Facade가 제공하지 않는 저수준 통합이 필요할 때만 명령 ID를 직접 사용합니다.

### Facade API

Facade API는 Bases 명령과 모델 계층을 Base, 테이블, 필드, 레코드, 뷰 객체로 감쌉니다. 모델 작업에는 `@univerjs-pro/bases/facade`, UI 상태에는 `@univerjs-pro/bases-ui/facade`를 불러온 뒤 플러그인 등록 후 `FUniver.newAPI(univer)`로 API를 만드세요.

이어서 [설치 및 기본 사용법](/guides/bases/getting-started/installation)을 진행하고 [Bases Facade API 가이드](/guides/bases/getting-started/facade)에서 Base 데이터를 생성하고 편집하는 방법을 확인하세요.
