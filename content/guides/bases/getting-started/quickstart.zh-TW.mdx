有四個概念貫穿 Bases API 與 Bases 文件，分別說明 Base 如何組裝、如何持久化、如何修改以及如何控制。安裝 Univer Bases 之前，應先理解這四個概念。

## 基本概念 [#basic-concepts]

### 外掛

Univer 的功能以外掛形式提供。`@univerjs-pro/bases` 包含 Base 模型、其命令以及 `UniverBasesPlugin`；`@univerjs-pro/bases-ui` 包含獨立工作臺和 `UniverBasesUIPlugin`。模型外掛還會使用公式引擎，因此公式欄位會參與 Bases 的計算流程。

只註冊應用實際需要的產品外掛。[安裝和基本使用](/guides/bases/getting-started/installation)提供了完整的瀏覽器配置及其依賴的技術元件。

### 快照與資料模型

`IBaseSnapshot` 是單個 Base 單元的持久化格式。它包含表及其順序，每張表包含欄位、記錄、檢視以及各個集合的順序。檢視是同一批記錄的不同投影，切換檢視不會建立資料副本。

快照用於建立、儲存或恢復 Base。單元開始執行後，不要直接修改快照物件。資料結構參見 [Base 快照](/guides/bases/model/base-snapshot)和[表、欄位與記錄](/guides/bases/model/tables-fields-records)。

### 命令

執行時的修改都透過命令完成。建立表、更新欄位、編輯記錄或切換檢視時，透過命令層或 Facade 層進行，可以使模型、UI、撤銷/重做和協同鏈路保持一致。

應用程式碼應優先使用 Facade API。只有在需要 Facade 未暴露的底層整合時，才直接使用命令 ID。

### Facade API

Facade API 在 Base 的命令層和模型層之上提供物件層：Base、表、欄位、記錄和檢視。模型操作匯入 `@univerjs-pro/bases/facade`，UI 狀態操作匯入 `@univerjs-pro/bases-ui/facade`，並在註冊外掛後呼叫 `FUniver.newAPI(univer)` 建立 API 物件。

接下來閱讀[安裝和基本使用](/guides/bases/getting-started/installation)，然後按照 [Bases Facade API 指南](/guides/bases/getting-started/facade)建立和編輯 Base 資料。
