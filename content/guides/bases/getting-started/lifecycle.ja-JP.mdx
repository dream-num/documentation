## グローバルライフサイクル

- **スタート**:Univerは初期化しており、まだビジネスユニットが存在しません。
- **レディー**:最初のビジネスユニットが作成されました。後者はこのステージを再びトリガーしません。
- **レンダリングされる**:標準UIは最初のレンダリングスイッチを完了しました。非同期のコンテンツはまだロードされるかもしれません。
- **ステアディ**: 標準 UI はレンダリングされた後遅れのこの段階に達します。それはすべての非同期タスクを待っていません。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="イベントが通知する対象">

`LifeCycleChanged`は、Univerのグローバルステージを報告しています。グローバルステージが`Ready`に達した後にプラグインBがロードされると、Bは`onReady()`を実行しますが、第2のグローバル`Ready`イベントは発生しません。

追加するリスナーは、`Starting`を含む、すぐに現在のステージを受け取ることができます。 Univerがどの段階にあるかを判断するには、`univerAPI.getCurrentLifecycleStage()`を直接呼び出します。

</Callout>

リスナーを削除するには、返された`disposable`オブジェクトのdispose:

```typescript
disposable.dispose()
```

## プラグインのライフサイクルフック

プラグインは、ロード時に `onStarting()` を実行し、現在のグローバルステージまでキャッチします。B を異なる時間にロードすると、そのホックコールが A のものとどのように比較するかを示しています。

<LifecycleDemo />

一般的なプラグインは、登録時にロードします。 ビジネスタイプのプラグインは通常、そのタイプの最初のユニットが作成される前にロードします。 既に開始したタイプに新しいプラグインが追加された場合、それは、不良なバッチにロードされます。 明示的な依存性は、プラグインが先に読み込まれる可能性があります。

各バッチは、同期作業を待つことなく、時間と依存の順番で同期的に1つのステージを呼び出します。 必要なユニット、DOM要素、またはリソースがアクセスする前に準備が整っていることを確認してください。
