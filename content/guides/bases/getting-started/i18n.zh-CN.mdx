## 界面语言

`locale` 决定菜单、提示、对话框以及其他界面文案使用哪套语言包；`locales` 只注册语言包，不负责选择。该配置由 Univer 实例中的各个单元共享。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有产品：界面**：`locale` 决定菜单、提示、对话框和插件标签的语言。它不会翻译用户内容，也不会重命名已有单元。
- **Sheets：单元格格式与公式**：单元格中的数字和日期按以下回退顺序取语言：数字格式的 locale 覆盖值，然后是工作簿快照的 `locale`，最后是实例的 `locale`。`region` 不会替代其中任何一项。`DOLLAR` 等公式行为以及财务函数结果的货币格式仍由 `locale` 决定，中日韩输入归一化也是如此。
- **Docs：文档统计**：`locale` 决定文本如何分词、如何计数。

### 运行时切换语言

切换语言之前，先加载所有已安装插件或预设的语言包。`loadLocales()` 只合并翻译，不切换语言；`setLocale()` 从已加载的内容中选择，不会下载任何内容。缺少翻译时，界面直接显示键名。以下示例加载共享 UI 语言包；其他已安装插件的目标语言包应加入同一次调用。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 自定义语言包

也可以编写自定义语言包：组装所需的对象，并传给 `Univer` 实例。预设自带的语言包通常位于 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目录。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 贡献语言包

Univer 目前内置以下语言包：

- `zh-CN`：简体中文
- `en-US`：英文
- `zh-TW`：繁体中文
- `zh-HK`：繁体中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韩文
- `es-ES`：西班牙文
- `ca-ES`：加泰罗尼亚文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：意大利文
- `pl-PL`：波兰文
- `pt-BR`：葡萄牙文（巴西）

以上即为全部内置语言包，其他语言尚未支持。Univer 是开源项目，欢迎各地开发者补充或改进这些语言包。

## 地区设置

`region` 决定相关功能采用哪个地区的惯例。该配置由 Univer 实例中的各个单元共享。

两项配置都使用 `LocaleType` 值。例如 `LocaleType.EN_US` 的值是 `enUS`，而 `en-US` 是语言包文件名，也是 BCP 47 标签。不要把 `US`、`SG` 等国家代码作为 `region` 传入。界面使用其他语言时，地区不需要额外加载对应语言包。

如果从未设置 `region`，它会跟随 `locale`，之后调用 `setLocale()` 时也会同步。在初始化时设置 `region`，或调用 `setRegion()`，都会停止这种自动跟随。此后切换语言时，会保留已选定的地区。目前没有公开 API 可以恢复自动跟随；当两者需要一起变化时，请分别设置。

在 `createUniver()` 或 `new Univer()` 中，将 `region: LocaleType.DE_DE` 放在 `locale` 旁边，即可保留界面语言，同时应用德国地区惯例。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此时界面切换为英文，地区格式仍为德国。`getCurrentLocale()` 和 `getCurrentRegion()` 返回实际生效的标识。要让两者一起变化，请使用同一个 `LocaleType` 值分别调用两个 setter。

- **Sheets：货币操作**：`region` 决定工具栏中的货币图标、货币和会计格式的选项及其预览，以及货币命令应用的格式。修改地区不会重写已有的单元格格式，也不会换算金额。
- **Docs：文档统计**：`region` 决定统计对话框和状态栏中数字的显示格式，包括分组分隔符。修改 `region` 不会改变统计规则。
- **启用评论时**：`region` 决定日期和时间的显示方式，使用 24 小时制和拉丁数字；`locale` 决定评论界面文案。两者都不会修改已存储的时间戳，`region` 也不是时区设置。
- **Boards、Slides、Bases、PDFs**：`locale` 控制界面翻译。`region` 供读取它的共享功能使用，例如接入后的评论。它不会自动重新格式化白板或幻灯片文本、Base 字段或 PDF 内容。
