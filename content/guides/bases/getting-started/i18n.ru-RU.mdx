## Язык интерфейса

`locale` выбирает языковой пакет для меню, подсказок, диалогов и остальной части переведенного пользовательского интерфейса. `locales` регистрирует пакеты без выбора одного. Настройка разделяется блоками в экземпляре Univer. Он принимает значения `LocaleType`, такие как `LocaleType.EN_US` .

- **Все продукты: UI**: `locale` меняет язык меню, подсказок, диалогов и ярлыков плагинов. Он не переводит пользовательский контент или не переименовывает существующие блоки.
- **Листы: форматы ячеек и формулы**: Числа и даты в ячейках следуют за цепочкой резервного копирования: переопределяется числовой формат, затем скриншот книги `locale`, затем экземпляр `locale`. `region` не заменяет ни одного из них. Поведение формулы, такое как `DOLLAR` и валютный формат финансовых результатов, по-прежнему следует `locale` , как и нормализация ввода CJK.
- **Док: статистика**: `locale` определяет, как текст сегментирован и подсчитан.

### Смена языка во время работы

Загрузите языковые пакеты для каждого установленного плагина или предустановленного перед переключением языка. `loadLocales()` объединяет переводы без переключения; `setLocale()` выбирает из того, что уже загружено, и ничего не загружает. Отсутствующий ключ перевода отображается как сам ключ. Пример ниже загружает общий пакет пользовательского интерфейса; добавьте пакеты целевого языка для других установленных плагинов к тому же вызову.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Объединение языковых пакетов [#mergeLocales]

`mergeLocales` объединяет языковые пакеты из нескольких плагинов или предустановок в один полный объект языкового пакета.

### Пользовательские языковые пакеты

Вы также можете написать пользовательский языковой пакет: собрать нужный вам объект и передать его в экземпляр `Univer`. Языковые пакеты, отправляемые пресетами, обычно живут в `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Участие в переводе

Univer предоставляет следующие встроенные языковые пакеты:

- `zh-CN`: упрощённый китайский
- `en-US`: английский
- `zh-TW`: традиционный китайский
- `zh-HK`: традиционный китайский (Гонконг)
- `ru-RU`: русский
- `vi-VN`: вьетнамский
- `fa-IR`: персидский
- `fr-FR`: французский
- `ja-JP`: японский
- `ko-KR`: корейский
- `es-ES`: испанский
- `ca-ES`: каталонский
- `sk-SK`: словацкий
- `ar-SA`: арабский
- `de-DE`: немецкий
- `id-ID`: индонезийский
- `it-IT`: итальянский
- `pl-PL`: польский
- `pt-BR`: португальский (Бразилия)

Univer - это проект с открытым исходным кодом, и разработчики со всего мира могут добавлять или улучшать эти локализации.

## Региональные настройки

`region` выбирает региональные конвенции, которые следуют за региональными функциями. Настройка разделяется подразделениями в экземпляре Univer.

Обе настройки принимают значения `LocaleType`. Например, `LocaleType.EN_US` — это `enUS`, а `en-US` является именем файла языкового пакета и тегом BCP 47. Не пропускайте коды стран, такие как `US` или `SG` как `region` Если пользовательский интерфейс использует другой локальный интерфейс, регион не требует загрузки своего языкового блока.

Если `region` никогда не устанавливается, он следует за `locale`, включая более поздние вызовы `setLocale()`. Настройка `region` при инициализации или вызов `setRegion()` останавливает это автоматическое следование. После этого изменение языка удерживает выбранный регион. Ни один публичный API не восстанавливает автоматическое следования; когда оба должны измениться вместе, установите оба явно.

Добавьте `region: LocaleType.DE_DE` рядом с `locale` в `createUniver()` или `new Univer()`, чтобы сохранить язык пользовательского интерфейса при применении региональных конвенций Германии.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Здесь пользовательский интерфейс переключается на английский, а региональное форматирование остается немецким. `getCurrentLocale()` и `getCurrentRegion()` возвращают идентификаторы, фактически действующие. Чтобы изменить оба вместе, вызовите оба сеттера с одинаковым значением `LocaleType`.

- **Листы: валютный контроль**: `region` определяет значок валюты на панели инструментов, выбор валюты и бухгалтерского учета и их предварительный просмотр, а также формат, к которому применяется команда валюты.Изменение не переписывает существующие форматы ячеек или не конвертирует денежные значения.
- **Док: статистика**: `region` форматирует счета, показанные в диалоге статистики и строке состояния, включая разделители групп.Изменение `region` не меняет правил подсчета.
- **Комментарии, когда включено**: `region` контролирует, как отображаются даты и время, используя 24-часовые часы и латинские цифры. `locale` управляет текстом пользовательского интерфейса комментария. Ни один из них не изменяет сохраненные метки времени, а `region` не является настроем часовой зоны.
- **Доски, слайды, базы, PDF**: `locale` управляет переведенным пользовательским интерфейсом. `region` доступен для общих функций, которые читают его, таких как комментарии к потокам после их интеграции. Он не автоматически переформатирует доску или слайд-текст, поля базы или PDF-контент.

</Callout>

  Не каждый плагин поставляется с языковым пакетом. В документации по каждой функции указывается, включен ли один.
</Callout>

```typescript
univerAPI.setDirection('rtl')
```
