## 介面語言

`locale` 決定選單、提示、對話方塊以及其他介面文案使用哪套語言套件；`locales` 只註冊語言套件，不負責選擇。該配置由 Univer 例項中的各個單元共享。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有產品：介面**：`locale` 決定選單、提示、對話方塊和外掛標籤的語言。它不會翻譯使用者內容，也不會重新命名已有單元。
- **Sheets：單元格格式與公式**：單元格中的數字和日期按以下回退順序取語言：數字格式的 locale 覆蓋值，然後是工作簿快照的 `locale`，最後是例項的 `locale`。`region` 不會替代其中任何一項。`DOLLAR` 等公式行為以及財務函式結果的貨幣格式仍由 `locale` 決定，中日韓輸入歸一化也是如此。
- **Docs：文件統計**：`locale` 決定文字如何分詞、如何計數。

### 執行時切換語言

切換語言之前，先載入所有已安裝外掛或預設的語言套件。`loadLocales()` 只合並翻譯，不切換語言；`setLocale()` 從已載入的內容中選擇，不會下載任何內容。缺少翻譯時，介面直接顯示鍵名。以下範例載入共享 UI 語言套件；其他已安裝外掛的目標語言套件應加入同一次呼叫。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

`mergeLocales` 將多個外掛或預設的語言套件合併為一個完整的語言套件物件。

### 自訂語系檔

也可以編寫自定義語言套件：組裝所需的物件，並傳給 `Univer` 例項。預設自帶的語言套件通常位於 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目錄。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 貢獻語系

Univer 目前內建以下語言套件：

- `zh-CN`：簡體中文
- `en-US`：英文
- `zh-TW`：繁體中文（臺灣）
- `zh-HK`：繁體中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韓文
- `es-ES`：西班牙文
- `ca-ES`：加泰羅尼亞文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：義大利文
- `pl-PL`：波蘭文
- `pt-BR`：葡萄牙文（巴西）

以上即為全部內建語言套件，其他語言尚未支援。Univer 是開源專案，歡迎各地開發者補充或改進這些語言套件。

## 地區設定

`region` 決定相關功能採用哪個地區的慣例。該配置由 Univer 例項中的各個單元共享。

兩項配置都使用 `LocaleType` 值。例如 `LocaleType.EN_US` 的值是 `enUS`，而 `en-US` 是語言套件檔名，也是 BCP 47 標籤。不要把 `US`、`SG` 等國家程式碼作為 `region` 傳入。介面使用其他語言時，地區不需要額外載入對應語言套件。

如果從未設定 `region`，它會跟隨 `locale`，之後呼叫 `setLocale()` 時也會同步。在初始化時設定 `region`，或呼叫 `setRegion()`，都會停止這種自動跟隨。此後切換語言時，會保留已選定的地區。目前沒有公開 API 可以恢復自動跟隨；當兩者需要一起變化時，請分別設定。

在 `createUniver()` 或 `new Univer()` 中，將 `region: LocaleType.DE_DE` 放在 `locale` 旁邊，即可保留介面語言，同時應用德國地區慣例。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此時介面切換為英文，地區格式仍為德國。`getCurrentLocale()` 和 `getCurrentRegion()` 返回實際生效的標識。要讓兩者一起變化，請使用同一個 `LocaleType` 值分別呼叫兩個 setter。

- **Sheets：貨幣操作**：`region` 決定工具欄中的貨幣圖示、貨幣和會計格式的選項及其預覽，以及貨幣命令應用的格式。修改地區不會重寫已有的單元格格式，也不會換算金額。
- **Docs：文件統計**：`region` 決定統計對話方塊和狀態列中數字的顯示格式，包括分組分隔符。修改 `region` 不會改變統計規則。
- **啟用評論時**：`region` 決定日期和時間的顯示方式，使用 24 小時制和拉丁數字；`locale` 決定評論介面文案。兩者都不會修改已儲存的時間戳，`region` 也不是時區設定。
- **Boards、Slides、Bases、PDFs**：`locale` 控制介面翻譯。`region` 供讀取它的共享功能使用，例如接入後的評論。它不會自動重新格式化白板或幻燈片文字、Base 欄位或 PDF 內容。
