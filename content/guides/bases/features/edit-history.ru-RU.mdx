После изменения полей, записей или просмотров откройте историю для просмотра более ранних версий, сравните изменения и восстановите версию, когда позволяют разрешения. История читает версии, сохраняемые сервером. Отмените и переделайте только текущую сессию редактирования и не требуйте службы истории.

## Подготовка сервисов совместного редактирования и истории

Заполните [Интеграция сотрудничества](/server/collaboration/browser-integration) и [Конфигурация лицензии](/server/license). Затем проверьте, что два сеанса могут редактировать один и тот же документ Bases и что изменения сохраняются после перезагрузки.

Подключите хранилище истории и разрешения через [Расширение сотрудничества с офисом](/server/collaboration/extensions) и [Пример истории](/server/collaboration/examples#history). Основное сотрудничество не позволяет историю само по себе, и бэкэнд должен поддерживать списки истории, содержание версии и восстановление.

## Добавление плагинов истории

Добавьте эту конфигурацию поверх существующей настройки продукта, лицензии и совместной работы. Если предустановленная или существующая конфигурация уже регистрирует эти плагины, обновите эту конфигурация вместо того, чтобы регистрировать плагины снова.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Настройка плагинов

`UniverEditHistoryPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |
| `univerContainerId` | `string` |  | DOM ID контейнера редактора. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Дополнительные плагины для просмотра истории. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Конструктор плагина. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Варианты перешли к конструктору этого плагина. |

Точка `/api/history` на конечной точке собственной истории приложения и подтвердить, что его API соответствует запросам, которые посылает клиент. Оба значения `historyServerUrl` должны быть идентичны. Установите `univerContainerId` в DOM ID контейнера редактора, и загрузите локализацию, которую использует редактор.

Если документ содержит пользовательский контент, используйте `viewerPlugins` для добавления плагинов, которые зритель уже не включает; не регистрируйте встроенные плагины для просмотра снова.

## Просмотр и восстановление версий

Откройте историю из меню редактора и выберите версию, чтобы просмотреть ее содержимое и изменения, которые она содержит. Восстановление версии переписывает текущий общий документ, поэтому только пользователи с разрешением на восстановление должны быть в состоянии выполнить эту операцию, и сервер должен обеспечить соблюдение этого разрешения.

Чтобы проверить интеграцию, отредактировать поля, записи или просмотры, подождите, пока сотрудничество подтвердит изменение, затем проверьте список истории и содержание версии. Откройте приложение и перезапустите сервис, чтобы проверить настойчивость. Восстановите более раннюю версию и подтвердите, что другая сессия браузера получает восстановленное состояние.

Если список пуст, сначала проверьте, была ли записана история для этого документа, затем проверьте идентификатор документа и URL-адрес службы. Если просмотр работает, но восстановление не удается, проверьте разрешения на восстановление и соединение для совместной работы. Чтение истории также требует авторизации, потому что более старые версии могут по-прежнему содержать данные, которые с тех пор были удалены.

## Сравнение снимков [#compare-snapshots]

Чтобы построить экран обзора или передать изменения агенту ИИ, позвоните в `compareUnitData()` или подготовьте сравнение один раз с `prepareUnitComparison()`. Зарегистрируйте плагин History для продукта и импортируйте запись Facade. Передайте два полностью материализованных снимка того же блока, что и `beforeSnapshot` и `afterSnapshot`: сравнение только для чтения: оно не требует службы истории и не восстанавливает или объединяет контент.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Прочтите `scopes`, чтобы увидеть, какие виды доступны, затем передайте область `query()` для фильтрации результата без повторного сравнения. Страница содержит 100 элементов по умолчанию и до 1000. Используйте `page.hasMore` с `offset` чтобы извлечь оставшиеся элементы. `summary` охватывает все сравнение, даже после того, как вы отфильтровали элементы. Перед тем, как рассматривать результат как полное сравнение, проверьте `diagnostics.readiness` и `diagnostics.codes`. Для использования Node.js или CLI без редактора, см. [безголовое сравнение API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison) .
