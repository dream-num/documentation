Permettez aux utilisateurs d’ouvrir la même Base et de modifier ensemble tables, champs, enregistrements et vues. Ils peuvent travailler dans des vues différentes tout en modifiant le même document.

## Étapes d’intégration

1. Suivez l’[intégration collaborative](/server/collaboration/browser-integration) pour exécuter l’exemple et connecter la connexion utilisateur, les autorisations et le stockage en base de données.
2. Ajoutez la configuration du client Collaboration à votre éditeur Bases existant. Suivez le [démarrage rapide Office](/server/collaboration/quick-start) pour le navigateur, mais créez et stockez des documents Bases au lieu de copier les données Sheets de l’exemple.
3. Créez la Base via le backend de votre application et renvoyez son ID au navigateur.

## Ouvrir une Base du serveur

```ts
import '@univerjs-pro/bases/facade'
import '@univerjs-pro/collaboration-client/facade'

const base = await univerAPI.getCollaboration().loadBaseAsync('your-base-id')
if (!base) throw new Error('Base could not be loaded')
```

Réutilisez cet ID pour rouvrir ou partager le document. Ne remplacez pas le chargement serveur par `createBase()` et un nouveau document local vierge.

## Vérifier la synchronisation et l’enregistrement

Ouvrez le même ID dans deux sessions de navigateur indépendantes. Ajoutez un enregistrement ou modifiez un champ dans l’une, puis vérifiez que l’autre reçoit le changement. Vérifiez que les modifications persistent après actualisation et redémarrage du serveur.

Contrôlez côté serveur l’accès des lecteurs et des utilisateurs non autorisés. Les [réglages locaux de lecture seule](/guides/bases/features/core/permissions) ne contrôlent que le comportement de l’éditeur. La conversion de fichiers, les commentaires et l’historique nécessitent leurs fonctionnalités backend respectives ; consultez [Import-export](/guides/bases/features/import-export), [Commentaires](/guides/bases/features/thread-comment) et [Historique](/guides/bases/features/edit-history).
