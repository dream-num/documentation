修改字段、记录或视图后，可以打开历史记录查看以前的版本、比较变化，并在有权限时恢复某个版本。历史记录读取的是服务端已保存的版本。撤销和重做仅作用于当前编辑会话，不需要历史服务。

## 先准备协同和历史服务

先按[协同集成](/server/collaboration/browser-integration)完成编辑器接入，再完成[许可证配置](/server/license)。然后确认两个会话能够编辑同一份 Bases 文档，并且刷新后改动仍然存在。

按 [Office 协同扩展模块](/server/collaboration/extensions)和 [History 示例](/server/collaboration/examples#history)接入历史存储和权限。核心协同不会自动启用历史记录，后端还必须支持历史列表、版本内容和恢复操作。

## 添加历史记录插件

把下面的代码加入现有的产品、许可证和协同配置。如果某个预设或已有配置已注册这些插件，应修改该配置，不要再注册一次。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/zh-CN'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/zh-CN'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.ZH_CN, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 插件配置

`UniverEditHistoryPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的地址。 |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的地址。 |
| `univerContainerId` | `string` |  | 编辑器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 为历史版本查看器额外注册的插件。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 插件的构造函数。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 传给该插件构造函数的配置。 |

将 `/api/history` 替换为应用自己的历史接口地址，并确认该接口与客户端发出的请求相匹配。两个 `historyServerUrl` 必须保持一致，`univerContainerId` 必须与编辑器容器的 DOM ID 一致，语言资源也必须与编辑器当前使用的语言一致。

历史查看器会另外启动一个只读编辑器。文档包含自定义内容时，通过 `viewerPlugins` 补充查看器未内置的插件；内置插件不要重复注册。

## 查看和恢复版本

从编辑器菜单打开历史记录，选择一个版本查看其内容和变化。恢复版本会改写当前共享文档，因此只应开放给具有恢复权限的用户，并且必须由服务端再次校验该权限。

验证时可以先修改字段、记录或视图，等协同确认改动后再查看历史列表和版本内容。重新打开应用并重启服务后再次读取，确认改动仍然存在。然后恢复一个旧版本，确认另一个浏览器会话也收到恢复后的状态。

列表为空时，先检查历史服务是否记录了这份文档，再检查文档 ID 和服务地址。如果能够查看版本但恢复失败，应检查恢复权限和协同连接。旧版本中可能仍保留后来被删除的数据，因此读取历史同样需要权限。

## 比较快照 [#compare-snapshots]

如需构建审阅界面，或将变更交给 AI Agent，可以调用 `compareUnitData()`，也可以先用 `prepareUnitComparison()` 计算一次，再反复查询。先注册本品类的 History 插件并导入 Facade 入口，再将同一文档的两份完整快照分别作为 `beforeSnapshot` 和 `afterSnapshot` 传入。该比较是只读的，不需要历史服务，也不会恢复或合并内容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

通过 `scopes` 可以查看有哪些视图，再将选中的 scope 传给 `query()`，这样只筛选结果，不会重新计算差异。每页默认包含 100 项，最多 1,000 项，其余条目用 `page.hasMore` 配合 `offset` 获取。`summary` 始终描述整个比较，不随条目筛选变化。在将结果视为完整比较之前，先检查 `diagnostics.readiness` 和 `diagnostics.codes`。不需要编辑器的 Node.js 或 CLI 用法见[无界面比较 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
