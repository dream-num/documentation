Après avoir modifié les champs, les enregistrements ou les vues, ouvrez l'historique pour afficher les versions antérieures, comparez les modifications et restaurez une version lorsque les permissions le permettent. L'historique lit les versions persistantes par le serveur.

## Préparer les services de collaboration et d’historique

Terminez [l'intégration de la collaboration](/server/collaboration/browser-integration) et [configuration de licence](/server/license). Vérifiez ensuite que deux sessions peuvent modifier le même document Bases et que les modifications persistent après un rechargement.

Connectez le stockage et les permissions d'historique à travers [Prolongation de la collaboration avec les bureaux](/server/collaboration/extensions) et le [Exemple historique](/server/collaboration/examples#history). La collaboration de base ne permet pas l'historique par elle-même, et le moteur doit supporter les listes d'historique, le contenu de la version et la restauration.

## Ajouter les plugins d’historique

Ajoutez cette configuration en plus de la configuration existante du produit, de la licence et de la collaboration. Si un préréglage ou une configuration existante enregistre déjà ces plugins, mettez à jour cette configuration au lieu de réenregistrer les plugins.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuration des plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |
| `univerContainerId` | `string` |  | ID DOM du conteneur de l’éditeur. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | plugins supplémentaires pour le visionneur d'histoire. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Constructeur du plugin. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Options transmises au constructeur de ce plugin. |

Pointez `/api/history` au point final de l'historique de l'application et confirmez que son API correspond aux requêtes envoyées par le client. Les deux valeurs `historyServerUrl` doivent être identiques. Définissez `univerContainerId` sur l'ID DOM du conteneur de l'éditeur et chargez la locale utilisée par l'éditeur.

Si le document contient du contenu personnalisé, utilisez `viewerPlugins` pour ajouter les plugins que le visionneur n'inclut pas déjà; ne reregistrez pas les plugins de visionneuse intégrés.

## Consulter et restaurer des versions

Ouvrez l'historique depuis le menu de l'éditeur et sélectionnez une version pour afficher son contenu et les modifications qu'il contient. Restaurer une version réécrit le document partagé courant, de sorte que seuls les utilisateurs avec la permission de restauration devraient être en mesure d'effectuer cette opération, et le serveur doit faire respecter cette autorisation.

Pour vérifier l'intégration, modifier les champs, les enregistrements ou les vues, attendre que la collaboration confirme le changement, puis inspecter la liste d'historique et le contenu de la version. Réouvrir l'application et redémarrer le service pour tester la persistance. Restaurer une version antérieure et confirmer qu'une autre session du navigateur reçoit l'état restauré.

Si la liste est vide, vérifiez d'abord si l'historique a été enregistré pour ce document, puis vérifiez l'ID du document et l'URL du service. Si la visualisation fonctionne mais que la restauration échoue, vérifiez les permissions de restauration et la connexion de collaboration.

## Comparer des snapshots [#compare-snapshots]

Pour créer un écran d'examen ou passer les modifications à un agent AI, appelez `compareUnitData()`, ou préparez la comparaison une fois avec `prepareUnitComparison()`. Enregistrez le plugin History pour le produit et importez l'entrée Facade. Passez deux instantanés entièrement matérialisés de la même unité que `beforeSnapshot` et `afterSnapshot` . La comparaison est en lecture seule : elle ne nécessite aucun service d'historique et ne restaure pas ou ne fusionne pas de contenu.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Lire `scopes` pour voir quelles vues sont disponibles, puis passer une portée à `query()` afin de filtrer le résultat sans refaire la comparaison. Une page contient 100 éléments par défaut et jusqu'à 1 000. Utilisez `page.hasMore` avec `offset` et récupérer les éléments restants. `summary` couvre toute la comparaison, même après avoir filtré des éléments. Avant de traiter le résultat comme une comparaison complète, vérifiez `diagnostics.readiness` ou `diagnostics.codes`. Pour Node.js or CLI use without an editor, consultez le [API de comparaison sans tête](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison) .
