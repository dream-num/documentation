After changing fields, records, or views, open history to view earlier versions, compare changes, and restore a version when permissions allow it. History reads versions persisted by the server. Undo and redo apply only to the current editing session and do not require a history service.

## Prepare collaboration and history services

Complete [collaboration integration](/server/collaboration/browser-integration) and [license configuration](/server/license). Then verify that two sessions can edit the same Bases document and that the changes persist after a reload.

Connect history storage and permissions through [Office collaboration extensions](/server/collaboration/extensions) and the [History example](/server/collaboration/examples#history). Core collaboration does not enable history by itself, and the backend must support history lists, version content, and restoration.

## Add the history plugins

Add this configuration on top of the existing product, license, and collaboration setup. If a preset or an existing configuration already registers these plugins, update that configuration instead of registering the plugins again.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Plugin configuration

`UniverEditHistoryPlugin`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Base URL of the history service. |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Base URL of the history service. |
| `univerContainerId` | `string` |  | DOM ID of the editor container. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Extra plugins for the history viewer. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Plugin constructor. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Options passed to that plugin’s constructor. |

Point `/api/history` at the application's own history endpoint and confirm that its API matches the requests the client sends. Both `historyServerUrl` values must be identical. Set `univerContainerId` to the DOM ID of the editor container, and load the locale that the editor uses.

The history viewer starts a separate read-only editor. If the document contains custom content, use `viewerPlugins` to add the plugins that the viewer does not already include; do not register the built-in viewer plugins again.

## View and restore versions

Open history from the editor menu and select a version to view its content and the changes it contains. Restoring a version rewrites the current shared document, so only users with restore permission should be able to perform this operation, and the server must enforce that permission.

To check the integration, edit fields, records, or views, wait until collaboration confirms the change, then inspect the history list and the version content. Reopen the application and restart the service to test persistence. Restore an earlier version and confirm that another browser session receives the restored state.

If the list is empty, first check whether history was recorded for this document, then check the document ID and the service URL. If viewing works but restoration fails, check the restore permissions and the collaboration connection. Reading history also requires authorization, because older versions may still contain data that has since been deleted.

## Compare snapshots [#compare-snapshots]

To build a review screen or pass the changes to an AI Agent, call `compareUnitData()`, or prepare the comparison once with `prepareUnitComparison()`. Register the History plugin for the product and import the Facade entry. Pass two fully materialized snapshots of the same unit as `beforeSnapshot` and `afterSnapshot`. The comparison is read-only: it requires no history service and does not restore or merge content.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Read `scopes` to see which views are available, then pass a scope to `query()` to filter the result without rerunning the comparison. A page contains 100 items by default and up to 1,000. Use `page.hasMore` with `offset` to retrieve the remaining items. `summary` covers the entire comparison, even after you filter items. Before treating the result as a complete comparison, check `diagnostics.readiness` and `diagnostics.codes`. For Node.js or CLI use without an editor, see the [headless comparison API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
