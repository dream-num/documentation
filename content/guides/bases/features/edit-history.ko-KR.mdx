변경 필드, 레코드, 또는 레이아웃, 이전 버전을 볼 수있는 개방 된 역사, 변경을 비교하고, 권한을 허용 할 때 버전을 복원합니다. 역사는 서버에 의해 지속되는 버전을 읽습니다. Undo 및 redo는 현재 편집 세션에만 적용하고 역사 서비스가 필요하지 않습니다.

## 공동 편집 및 기록 서비스 준비

[협업 통합](/server/collaboration/browser-integration) 및 [인증 구성](/server/license)를 완료하십시오. 그런 다음 두 세션이 동일한 기본 문서를 편집하고 다시로드 한 후 변경 지속될 수 있습니다.

[Office 협업 확장](/server/collaboration/extensions)와 [연혁 예](/server/collaboration/examples#history)를 통해 역사 저장 및 권한을 연결하십시오. 핵심 협력은 자체로 역사를 활성화하지 않으며, 백엔드는 역사 목록, 버전 내용 및 복원을 지원해야합니다.

## 기록 플러그인 추가

기존 제품, 라이센스 및 협업 설정의 상단에이 구성을 추가하십시오. 미리 설정 또는 기존 구성이 이미이 플러그인을 등록하면 플러그인을 다시 등록하는 대신 구성을 업데이트합니다.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 플러그인 설정

`UniverEditHistoryPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |
| `univerContainerId` | `string` |  | 편집기 컨테이너의 DOM ID입니다. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 역사 뷰어에 대한 추가 플러그인. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 플러그인 생성자입니다. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 플러그인의 생성자에 전달된 옵션. |

애플리케이션 자체 역사 엔드포인트에서 포인트 `/api/history`는 API가 클라이언트가 보낸 요청을 확인합니다. `historyServerUrl` 값 모두 동일해야합니다. 편집기 컨테이너의 DOM ID에 `univerContainerId`를 설정하고 편집기가 사용하는 로컬을로드하십시오.

역사 뷰어는 별도의 읽기 전용 편집기를 시작합니다. 문서가 사용자 정의 콘텐츠를 포함하면 `viewerPlugins`를 사용하여 이미 포함되지 않는 플러그인을 추가하십시오. 내장 뷰어 플러그인을 다시 등록하지 마십시오.

## 버전 보기 및 복원

편집 메뉴에서 역사를 열고, 내용을 볼 수있는 버전을 선택하고 변경이 포함되어 있습니다. 현재 공유 문서를 다시 작성하는 버전 복원, 그래서 복원 권한이 작업을 수행 할 수 있어야, 서버는 그 권한을 시행해야합니다.

통합, 편집 필드, 레코드 또는 레이아웃을 확인하려면, 협업이 변경을 확인 할 때까지 기다리는 다음 역사 목록과 버전 콘텐츠를 검사합니다. 응용 프로그램을 열고 persistence를 테스트하기 위해 서비스를 다시 시작합니다. 이전 버전을 복원하고 다른 브라우저 세션이 복원 된 상태로 수신 확인.

목록이 비어있는 경우, 역사가이 문서에 기록되었는지 확인한 후, 문서 ID 및 서비스 URL을 확인합니다. 보기 작품이지만 복원 실패하면 복원 권한 및 협업 연결을 확인하십시오. 이전 버전이 삭제 된 데이터가 포함되기 때문에 기록도 권한이 필요합니다.

## 스냅샷 비교 [#compare-snapshots]

검토 화면을 구축하거나 AI 에이전트에 변경 사항을 전달하려면 `compareUnitData()`를 호출하거나 `prepareUnitComparison()`와 함께 한 번 비교를 준비하십시오. 제품을위한 역사 플러그인을 등록하고 Facade 항목을 가져 오기. `beforeSnapshot` 및 `afterSnapshot`과 같은 두 개의 완전히 재료화 된 스냅 샷을 통과하십시오. 비교는 읽기 전용입니다 : 그것은 역사 서비스가 필요하지 않으며 복원하거나 결합 콘텐츠를하지 않습니다.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

읽음 `scopes` 해당 이용 후기에 달린 코멘트가 없습니다. `query()` 비교를 다시 실행하지 않고 결과를 필터링합니다. 페이지는 기본으로 100 항목과 최대 1,000 항목이 포함되어 있습니다. 사용 `page.hasMore` 이름 * `offset` 나머지 아이템을 검색합니다. `summary` 전체 비교를 커버, 심지어 필터 항목 후. 전체 비교로 결과를 치료하기 전에, 체크 `diagnostics.readiness` 그리고, `diagnostics.codes`.를 위해 Node.js 또는 편집기없이 CLI 사용, 참조 [headless 비교 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
