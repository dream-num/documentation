필드, 레코드 또는 뷰를 변경한 뒤 기록을 열면 이전 버전을 살펴보고 변경 사항을 비교하며, 권한이 있는 경우 버전을 복원할 수 있습니다. 기록은 서버에 영구 저장된 버전을 읽습니다. 실행 취소와 다시 실행은 현재 편집 세션에 적용되며 기록 서비스가 필요하지 않습니다.

## 공동 편집 및 기록 서비스 준비

[공동 편집 통합](/server/collaboration/browser-integration)과 [라이선스 설정](/server/license)을 완료하세요. 두 세션에서 같은 Bases 문서를 편집할 수 있고 다시 로드해도 변경 사항이 유지되는지 확인하세요.

[Office 공동 편집 확장](/server/collaboration/extensions)과 [기록 예제](/server/collaboration/examples#history)에 따라 기록 저장소와 권한을 연결하세요. 핵심 공동 편집 기능만으로 기록이 자동 활성화되지는 않습니다. 백엔드는 기록 목록, 버전 내용, 복원도 지원해야 합니다.

## 기록 플러그인 추가

기존 제품, 라이선스, 공동 편집 설정에 다음을 추가하세요. 프리셋이나 기존 설정이 이미 이 플러그인을 등록한다면 중복 등록하지 말고 해당 설정을 수정하세요.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

`/api/history`를 애플리케이션의 기록 엔드포인트로 바꾸고 API가 클라이언트 요청과 일치하는지 확인하세요. 두 `historyServerUrl` 값은 같아야 합니다. `univerContainerId`를 편집기 컨테이너의 DOM ID로 설정하고 편집기와 일치하는 언어 팩을 로드하세요.

기록 뷰어는 별도의 읽기 전용 편집기를 생성합니다. 사용자 지정 콘텐츠에는 `viewerPlugins`를 사용해 뷰어에 아직 포함되지 않은 플러그인을 추가하세요. 내장 뷰어 플러그인을 다시 등록하지 마세요.

## 버전 보기 및 복원

편집기 메뉴에서 기록을 열고 버전을 선택하여 내용과 변경 사항을 확인하세요. 복원은 현재 공유 문서를 변경합니다. 복원 권한이 있는 사용자만 실행할 수 있어야 하며 서버에서도 이 권한을 강제해야 합니다.

통합을 검증하려면 필드, 레코드 또는 뷰를 변경하고 공동 편집 확인 응답을 기다린 후 기록 목록과 버전 내용을 확인하세요. 애플리케이션을 다시 열고 서비스를 재시작하여 영구 저장 여부를 확인하세요. 이전 버전을 복원한 뒤 다른 브라우저 세션에도 복원된 상태가 전달되는지 확인하세요.

목록이 비어 있으면 먼저 해당 문서의 기록이 생성되었는지 확인하고 문서 ID와 서비스 URL을 확인하세요. 조회는 되지만 복원에 실패한다면 복원 권한과 공동 편집 연결을 확인하세요. 이전 버전에는 삭제된 데이터가 포함될 수 있으므로 기록 읽기에도 권한 검사가 필요합니다.
