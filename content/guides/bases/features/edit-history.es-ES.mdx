Después de cambiar campos, registros o vistas, la historia abierta para ver versiones anteriores, comparar cambios y restaurar una versión cuando los permisos lo permiten. La historia lee las versiones perduradas por el servidor. Deshacer y redo sólo se aplican a la sesión de edición actual y no requieren un servicio de historia.

## Preparar los servicios de colaboración e historial

Completa [integración de la colaboración](/server/collaboration/browser-integration) y [configuración de licencias](/server/license). A continuación, verifique que dos sesiones pueden editar el mismo documento Bases y que los cambios persisten después de una recarga.

Conecte el almacenamiento de historia y los permisos a través de [Ampliación de la colaboración de las oficinas](/server/collaboration/extensions) y [Ejemplo de historia](/server/collaboration/examples#history). La colaboración básica no permite la historia por sí misma, y el backend debe apoyar listas de historia, contenido de versiones y restauración.

## Añadir los plugins de historial

Añadir esta configuración encima de la configuración de producto, licencia y colaboración existente. Si un preset o una configuración existente ya registra estos plugins, actualice esa configuración en lugar de registrar los plugins de nuevo.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuración de plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |
| `univerContainerId` | `string` |  | ID DOM del contenedor del editor. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | plugins adicionales para el espectador de la historia. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Constructor del plugin. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Las opciones pasaron al constructor de ese plugin. |

Point `/api/history` en el propio endpoint de la aplicación y confirma que su API coincide con las solicitudes que envía el cliente. Ambos valores de `historyServerUrl` deben ser idénticos. Establecer `univerContainerId` al DOM ID del contenedor de editor, y cargar el local que el editor utiliza.

El visor de historia comienza un editor independiente de sólo lectura. Si el documento contiene contenido personalizado, utilice `viewerPlugins` para añadir los plugins que el visor no incluye ya; no registre los plugins de visualización incorporado de nuevo.

## Consultar y restaurar versiones

Abrir la historia del menú del editor y seleccionar una versión para ver su contenido y los cambios que contiene. Restaurar una versión reescribirá el documento compartido actual, por lo que sólo los usuarios con permiso de restauración deben ser capaces de realizar esta operación, y el servidor debe hacer cumplir ese permiso.

Para comprobar la integración, editar campos, registros o vistas, espere hasta que la colaboración confirme el cambio, luego inspeccione la lista de historia y el contenido de la versión. Reabrir la aplicación y reiniciar el servicio para probar la persistencia. Restaurar una versión anterior y confirmar que otra sesión del navegador recibe el estado restaurado.

Si la lista está vacía, primero compruebe si la historia fue registrada para este documento, luego comprueba el documento ID y la URL del servicio. Si la visualización de obras pero la restauración falla, compruebo los permisos de restauración y la conexión de colaboración. La historia de la lectura también requiere autorización, porque las versiones anteriores todavía pueden contener datos que han sido borrados.

## Comparar snapshots [#compare-snapshots]

Para construir una pantalla de revisión o pasar los cambios a un Agente AI, llame a `compareUnitData()`, o prepare la comparación una vez con `prepareUnitComparison()`. Registre el plugin de Historia para el producto e import la entrada Facade. Pase dos instantáneas totalmente materializadas de la misma unidad que `beforeSnapshot` y `afterSnapshot` . La comparación es sólo lectura: no requiere servicio de historia y no restable o restaura.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Leer `scopes` para ver qué puntos de vista están disponibles, a continuación, pasar un alcance `query()` para filtrar el resultado sin recortar la comparación. Una página contiene 100 artículos por defecto y hasta 1.000. `page.hasMore` con `offset` para recuperar los elementos restantes. `summary` cubre toda la comparación, incluso después de filtrar los elementos. Antes de tratar el resultado como una comparación completa, comprobar `diagnostics.readiness` y `diagnostics.codes`. Para Node.js o CLI uso sin un editor, ver el [API de comparación sin cabeza](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
