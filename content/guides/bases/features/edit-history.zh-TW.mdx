修改欄位、記錄或檢視後，可以開啟歷史記錄檢視以前的版本、比較變化，並在有權限時恢復某個版本。歷史記錄讀取的是伺服器端已儲存的版本。撤銷和重做僅作用於當前編輯會話，不需要歷史服務。

## 準備協同與歷史服務

先按[協同整合](/server/collaboration/browser-integration)完成編輯器接入，再完成[許可證配置](/server/license)。然後確認兩個會話能夠編輯同一份 Bases 文件，並且重新整理後改動仍然存在。

按 [Office 協同擴充套件模組](/server/collaboration/extensions)和 [History 範例](/server/collaboration/examples#history)接入歷史儲存和權限。核心協同不會自動啟用歷史記錄，後端還必須支援歷史列表、版本內容和恢復操作。

## 加入歷史外掛

把下面的程式碼加入現有的產品、許可證和協同配置。如果某個預設或已有配置已註冊這些外掛，應修改該配置，不要再註冊一次。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 外掛設定

`UniverEditHistoryPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的位址。 |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的位址。 |
| `univerContainerId` | `string` |  | 編輯器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 為歷史版本檢視器額外註冊的外掛。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 外掛的建構函式。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 傳給該外掛建構函式的配置。 |

將 `/api/history` 替換為應用自己的歷史介面地址，並確認該介面與客戶端發出的請求相匹配。兩個 `historyServerUrl` 必須保持一致，`univerContainerId` 必須與編輯器容器的 DOM ID 一致，語言資源也必須與編輯器當前使用的語言一致。

歷史檢視器會另外啟動一個只讀編輯器。文件包含自定義內容時，透過 `viewerPlugins` 補充檢視器未內建的外掛；內建外掛不要重複註冊。

## 檢視與還原版本

從編輯器選單開啟歷史記錄，選擇一個版本檢視其內容和變化。恢復版本會改寫當前共享文件，因此只應開放給具有恢復權限的使用者，並且必須由伺服器端再次校驗該權限。

驗證時可以先修改欄位、記錄或檢視，等協同確認改動後再檢視歷史列表和版本內容。重新開啟應用並重啟服務後再次讀取，確認改動仍然存在。然後恢復一箇舊版本，確認另一個瀏覽器會話也收到恢復後的狀態。

列表為空時，先檢查歷史服務是否記錄了這份文件，再檢查文件 ID 和服務地址。如果能夠檢視版本但恢復失敗，應檢查恢復權限和協同連線。舊版本中可能仍保留後來被刪除的資料，因此讀取歷史同樣需要權限。

## 比較快照 [#compare-snapshots]

如需建置審閱介面，或將變更交給 AI Agent，可以呼叫 `compareUnitData()`，也可以先用 `prepareUnitComparison()` 計算一次，再反覆查詢。先註冊本品類的 History 外掛並匯入 Facade 入口，再將同一文件的兩份完整快照分別作為 `beforeSnapshot` 和 `afterSnapshot` 傳入。該比較是隻讀的，不需要歷史服務，也不會恢復或合併內容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

透過 `scopes` 可以檢視有哪些檢視，再將選中的 scope 傳給 `query()`，這樣只篩選結果，不會重新計算差異。每頁預設套件含 100 項，最多 1,000 項，其餘條目用 `page.hasMore` 配合 `offset` 取得。`summary` 始終描述整個比較，不隨條目篩選變化。在將結果視為完整比較之前，先檢查 `diagnostics.readiness` 和 `diagnostics.codes`。不需要編輯器的 Node.js 或 CLI 用法見[無介面比較 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
