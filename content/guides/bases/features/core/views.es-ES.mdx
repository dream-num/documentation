Una tabla puede tener varias vistas. Las tareas pueden entrar en una cuadrícula y su estado rastreado en un kanban; cambiar entre los dos no copia ningún registro.

<ViewsDemo />

| Ver | Caso de uso | Configuración principal |
| --- | --- | --- |
| `Grid` | Editar, filtrar y clasificar filas | Campos congelados, altura de hilera, anchos de campo |
| `Kanban` | Grupo por estado o propietario | `groupFieldId` |
| `Calendar` | Registros de programación por fecha | `startDateFieldId`, fecha de final opcional |
| `Gantt` | Duración de la planificación y dependencias | Fechas de inicio y finalización, comparación con el plan, progreso, predecesores y calendario laboral |
| `Gallery` | Mostrando imágenes y tarjetas de contenido | Cubierta, título y campos de tarjeta |
| `Pivot` | Resúmenes y gráficos | Requiere el [plugin de dashboard](/guides/bases/features/dashboard) |

Los ejemplos suponen que un `table` ya existe. Reemplazar los IDs de campo con campos reales, y crear cualquier campo de fecha o agrupación antes de configurar la vista que los utiliza.

## Crear vistas

```ts
const grid = table.createView('All records', univerAPI.Enum.BaseViewType.Grid)

const kanban = table.createView(
  'By status',
  univerAPI.Enum.BaseViewType.Kanban,
  {
    view: {
      config: { groupFieldId: 'status' },
    },
  },
)
```

## Activar una vista en la interfaz de usuario

```ts
const baseUI = univerAPI.getBaseUI()
await baseUI.activateTable(table.getId())
await baseUI.activateView(kanban.getId())
```

## Configurar reglas de vista

```ts
kanban.setGroup([
  { fieldId: 'status', direction: univerAPI.Enum.BaseSortDirection.ASC },
])

kanban.setFilter({
  conjunction: univerAPI.Enum.BaseFilterConjunction.AND,
  conditions: [
    { fieldId: 'archived', operator: univerAPI.Enum.BaseFilterOperator.IS, operand: false },
  ],
})
```

Ajustes de campo en una visibilidad de control de vistas, anchos y pantalla de tarjeta. No cambian el esquema de mesa subyacente.

## Fechas del calendario

```ts
const calendar = table.createView('Schedule', univerAPI.Enum.BaseViewType.Calendar, {
  view: {
    config: { startDateFieldId: 'startDate', endDateFieldId: 'endDate', mode: 'month' },
  },
})
```

Un calendario requiere un campo de inicio. Gantt también requiere un campo actualizado, y admite días de trabajo, progreso y dependencias. En una galería, `card` configura el título y los campos que cada tarjeta muestra.

## Planificación de Gantt

`startDateFieldId` y `endDateFieldId` son obligatorios. `progressFieldId` vincula un campo `Progress`. Su valor establece el progreso de cada barra, y el progreso se puede arrastrar en el escritorio. `workingDaysOnly` sombrea los días no laborables en la línea de tiempo y cuenta cada barra en días laborables, y `workingDays` define el patrón semanal y las excepciones que se usan para esos recuentos y para la desviación.

| Propiedad | Tipo | Descripción |
| --- | --- | --- |
| `startDateFieldId` | `string` | Campo de fecha de inicio del cronograma actual. |
| `endDateFieldId` | `string` | Campo de fecha de finalización del cronograma actual. |
| `progressFieldId` | `string` | Campo `Progress` que aporta el progreso. |
| `showPlanComparison` | `boolean` | Muestra las barras planificadas debajo de las barras actuales. |
| `planStartDateFieldId` | `string` | Campo de fecha con el inicio planificado. |
| `planEndDateFieldId` | `string` | Campo de fecha con el fin planificado. |
| `planColor` | `string` | Color de relleno de las barras planificadas. |
| `remainingColor` | `string` | Color del trabajo incompleto cuando se establece `progressFieldId`. De forma predeterminada se usa un tono más claro del color de la barra. |
| `workingDaysOnly` | `boolean` | Marca los días no laborables y cuenta solo los días laborables. |
| `workingDays` | `object` | Calendario laboral con `weekdays` y `exceptions`. |

```ts
const gantt = table.createView('Delivery', univerAPI.Enum.BaseViewType.Gantt, {
  view: {
    config: {
      startDateFieldId: 'startDate',
      endDateFieldId: 'endDate',
      progressFieldId: 'progress',
      showPlanComparison: true,
      planStartDateFieldId: 'plannedStart',
      planEndDateFieldId: 'plannedEnd',
    },
  },
})
```

En la interfaz, abra Configuración de la vista de Gantt y active «Comparar con el plan», y luego seleccione los campos de inicio y fin planificados. Las barras planificadas se dibujan debajo de las barras actuales cuando ambos campos planificados están establecidos. Pase el cursor sobre una barra en el escritorio o tóquela en el móvil para comparar ambos cronogramas. El texto emergente indica la desviación de inicio y fin en días laborables.

## Predecesores de Gantt

Establezca `dependencyFieldId` en un campo `RecordLink` de varios valores que apunte a la misma tabla. El campo debe ser editable y no debe ser un campo del sistema.

El paquete `@univerjs-pro/bases` exporta `AddGanttPredecessorCommand` y `RemoveGanttPredecessorCommand`. Ambos aceptan `unitId`, `tableId`, `viewId`, `predecessorId` y `successorId`. El comando de adición devuelve `true` cuando el vínculo existe después de la llamada, `false` cuando la solicitud se rechaza, y `'cycle'` cuando el vínculo crearía una dependencia circular. El comando de eliminación devuelve `true` cuando el vínculo no existe después de la llamada.

```ts
import { AddGanttPredecessorCommand, RemoveGanttPredecessorCommand } from '@univerjs-pro/bases'

const base = univerAPI.getActiveBase()
if (!base) throw new Error('No active Base')

const params = {
  unitId: base.getId(),
  tableId: table.getId(),
  viewId: gantt.getId(),
  predecessorId: 'task-1',
  successorId: 'task-2',
}

const added = await univerAPI.executeCommand(AddGanttPredecessorCommand.id, params)
// true: linked, false: rejected, 'cycle': would create a cycle

await univerAPI.executeCommand(RemoveGanttPredecessorCommand.id, params)
```

En el escritorio, arrastre el conector de cualquiera de los dos extremos de una barra actual sobre otra barra para añadir un vínculo de fin a comienzo. Una sola acción de deshacer elimina el vínculo.

Para la edición colaborativa de Gantt, actualice la puerta de enlace a una versión que admita la transformación operacional de Base antes de desplegar los clientes 1.6.0.

## Orden y presentación de campos

```ts
grid.setSort([{ fieldId: 'priority', direction: univerAPI.Enum.BaseSortDirection.DESC }])
grid.setFieldVisible('internalNotes', false)
grid.setFieldWidth('title', 280)
```

Filtros, clasificación, agrupación y visualización de campo todos pertenecen a la vista actual. Ninguna de estas configuraciones elimina los registros o campos subyacentes.

## Colores condicionales

La siguiente regla destaca los registros cuyo puntaje es superior a 80:

```ts
const score = table.addField('Score', univerAPI.Enum.BaseFieldType.Number)
grid.setConditionalColorRules([{
  id: 'high-score',
  target: univerAPI.Enum.BaseConditionalColorTarget.ROW,
  fieldId: score.getId(),
  operator: univerAPI.Enum.BaseConditionalColorOperator.GREATER_THAN,
  operand: 80,
  color: '#dcfce7',
}])
```

Las reglas toman prioridad en orden de matriz. Pase `[]` para aclarar todas las reglas. El objetivo puede ser una célula, una fila o una columna; colorear una columna es incondicional.
