Una tabla puede tener varias vistas. Las tareas pueden entrar en una cuadrícula y su estado rastreado en un kanban; cambiar entre los dos no copia ningún registro.

<ViewsDemo />

| Ver | Caso de uso | Configuración principal |
| --- | --- | --- |
| `Grid` | Editar, filtrar y clasificar filas | Campos congelados, altura de hilera, anchos de campo |
| `Kanban` | Grupo por estado o propietario | `groupFieldId` |
| `Calendar` | Registros de programación por fecha | `startDateFieldId`, fecha de final opcional |
| `Gantt` | Duración de la planificación y dependencias | Fechas de inicio y finalización, progreso opcional y campos de dependencia |
| `Gallery` | Mostrando imágenes y tarjetas de contenido | Cubierta, título y campos de tarjeta |
| `Pivot` | Resúmenes y gráficos | Requiere el [plugin de dashboard](/guides/bases/features/dashboard) |

Los ejemplos suponen que un `table` ya existe. Reemplazar los IDs de campo con campos reales, y crear cualquier campo de fecha o agrupación antes de configurar la vista que los utiliza.

## Crear vistas

```ts
const grid = table.createView('All records', univerAPI.Enum.BaseViewType.Grid)

const kanban = table.createView(
  'By status',
  univerAPI.Enum.BaseViewType.Kanban,
  {
    view: {
      config: { groupFieldId: 'status' },
    },
  },
)
```

## Activar una vista en la interfaz de usuario

```ts
const baseUI = univerAPI.getBaseUI()
await baseUI.activateTable(table.getId())
await baseUI.activateView(kanban.getId())
```

## Configurar reglas de vista

```ts
kanban.setGroup([
  { fieldId: 'status', direction: univerAPI.Enum.BaseSortDirection.ASC },
])

kanban.setFilter({
  conjunction: univerAPI.Enum.BaseFilterConjunction.AND,
  conditions: [
    { fieldId: 'archived', operator: univerAPI.Enum.BaseFilterOperator.IS, operand: false },
  ],
})
```

Ajustes de campo en una visibilidad de control de vistas, anchos y pantalla de tarjeta. No cambian el esquema de mesa subyacente.

## Fechas del calendario

```ts
const calendar = table.createView('Schedule', univerAPI.Enum.BaseViewType.Calendar, {
  view: {
    config: { startDateFieldId: 'startDate', endDateFieldId: 'endDate', mode: 'month' },
  },
})
```

Un calendario requiere un campo de inicio. Gantt también requiere un campo actualizado, y admite días de trabajo, progreso y dependencias. En una galería, `card` configura el título y los campos que cada tarjeta muestra.

## Orden y presentación de campos

```ts
grid.setSort([{ fieldId: 'priority', direction: univerAPI.Enum.BaseSortDirection.DESC }])
grid.setFieldVisible('internalNotes', false)
grid.setFieldWidth('title', 280)
```

Filtros, clasificación, agrupación y visualización de campo todos pertenecen a la vista actual. Ninguna de estas configuraciones elimina los registros o campos subyacentes.

## Colores condicionales

La siguiente regla destaca los registros cuyo puntaje es superior a 80:

```ts
const score = table.addField('Score', univerAPI.Enum.BaseFieldType.Number)
grid.setConditionalColorRules([{
  id: 'high-score',
  target: univerAPI.Enum.BaseConditionalColorTarget.ROW,
  fieldId: score.getId(),
  operator: univerAPI.Enum.BaseConditionalColorOperator.GREATER_THAN,
  operand: 80,
  color: '#dcfce7',
}])
```

Las reglas toman prioridad en orden de matriz. Pase `[]` para aclarar todas las reglas. El objetivo puede ser una célula, una fila o una columna; colorear una columna es incondicional.
