---
title: Permisos
---

Una base entera se puede hacer solo lectura, como puede ser una tabla individual, campo, registro o vista. Esto cubre los informes de lectura y las versiones de aplicaciones en las que los usuarios pueden editar sólo parte de los datos.

Registrar el plugin Bases e importar `@univerjs-pro/bases/facade` antes de llamar a cualquiera de estas APIs.

## Configurar una Base como solo lectura

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')

await base.getPermission().setReadOnly()
console.log(base.getPermission().canEdit()) // false

await base.getPermission().setEditable()
```

## Restringir un objeto individual

El siguiente ejemplo restringe una sola tabla:

```ts
const table = base.getTables()[0]
if (!table) throw new Error('Create a table first')

await table.getPermission().setReadOnly()
await table.getPermission().setEditable()
```

Campos, registros y vistas también exponen `getPermission()`, al igual que los tableros de control y las vistas de pivote una vez que se registra su plugin. Hacer un objeto de niño editable no elimina una restricción en su padre: si la tabla es sólo lectura, hacer un registro dentro de él editable no tiene efecto.

`setReadOnly()` y `setEditable()` devuelven promesas, por lo que `await`. Para cambiar varios objetos en una sola llamada, utilice `base.getPermission().setObjectPermissions()`; [Bases Facade](/reference/facade/base) lista los parámetros.

## Copia, exportación y comentarios

Los permisos de nivel base también determinan si se permite copiar, exportar y comentar.

```ts
import { UnitAction } from '@univerjs/protocol'

await base.getPermission().setPoint(UnitAction.Copy, false)
```

Utilice `UnitAction.Export` y `UnitAction.Comment` para exportar y comentar respectivamente.

## Conectar los permisos de negocio

Los permisos locales rigen lo que el editor permite. Una aplicación colaborativa también debe autorizar lecturas de contenido, unirse a la colaboración y enviar cambios en el servidor; véase [integración del servidor](/server).

Durante las pruebas, utilice un editor, un espectador y un usuario sin acceso, y verifique tanto las acciones en la página como las solicitudes directas.
