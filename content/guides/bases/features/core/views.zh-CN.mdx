同一张表可以有多个视图。例如，在网格中录入任务，在看板中追踪任务状态。切换视图不会复制记录。

<ViewsDemo />

| 视图 | 适合的场景 | 主要配置 |
| --- | --- | --- |
| 网格 `Grid` | 按行编辑、筛选和排序 | 冻结字段、行高、字段宽度 |
| 看板 `Kanban` | 按状态或负责人分组 | `groupFieldId` |
| 日历 `Calendar` | 按日期安排记录 | `startDateFieldId`，可选结束日期 |
| 甘特图 `Gantt` | 规划工期与依赖 | 开始和结束日期、计划对照、完成率、前置任务和工作日历 |
| 画廊 `Gallery` | 展示图片和内容卡片 | 封面、标题和卡片字段 |
| 透视 `Pivot` | 汇总统计与图表 | 需要[仪表盘插件](/guides/bases/features/dashboard) |

以下示例假设已经取得 `table`。请将字段 ID 替换为真实字段 ID；日期或分组类字段需要先创建，再配置使用这些字段的视图。

## 创建视图

```ts
const grid = table.createView('All records', univerAPI.Enum.BaseViewType.Grid)

const kanban = table.createView(
  'By status',
  univerAPI.Enum.BaseViewType.Kanban,
  {
    view: {
      config: { groupFieldId: 'status' },
    },
  },
)
```

## 在 UI 中激活视图

```ts
const baseUI = univerAPI.getBaseUI()
await baseUI.activateTable(table.getId())
await baseUI.activateView(kanban.getId())
```

## 配置视图规则

```ts
kanban.setGroup([
  { fieldId: 'status', direction: univerAPI.Enum.BaseSortDirection.ASC },
])

kanban.setFilter({
  conjunction: univerAPI.Enum.BaseFilterConjunction.AND,
  conditions: [
    { fieldId: 'archived', operator: univerAPI.Enum.BaseFilterOperator.IS, operand: false },
  ],
})
```

视图上的字段设置控制可见性、宽度和卡片展示方式，不会改变底层的表结构。

## 日历与日期字段

```ts
const calendar = table.createView('Schedule', univerAPI.Enum.BaseViewType.Calendar, {
  view: {
    config: { startDateFieldId: 'startDate', endDateFieldId: 'endDate', mode: 'month' },
  },
})
```

日历需要开始日期字段。甘特图还需要结束日期字段，并支持工作日、进度和依赖关系。画廊使用 `card` 配置标题，以及每张卡片展示的字段。

## 甘特图排期

`startDateFieldId` 和 `endDateFieldId` 为必填项。`progressFieldId` 绑定完成率字段，其数值决定每个任务条的完成度，桌面端可以拖动完成度。`workingDaysOnly` 会在时间线中标出非工作日，并按工作日统计每个任务条。`workingDays` 定义每周工作日和例外日期，用于统计和偏差计算。

| 配置项 | 类型 | 说明 |
| --- | --- | --- |
| `startDateFieldId` | `string` | 当前排期的开始日期字段。 |
| `endDateFieldId` | `string` | 当前排期的结束日期字段。 |
| `progressFieldId` | `string` | 提供完成度的完成率字段。 |
| `showPlanComparison` | `boolean` | 在当前任务条下方显示计划任务条。 |
| `planStartDateFieldId` | `string` | 计划开始的日期字段。 |
| `planEndDateFieldId` | `string` | 计划结束的日期字段。 |
| `planColor` | `string` | 计划任务条的填充颜色。 |
| `remainingColor` | `string` | 设置 `progressFieldId` 后，未完成部分的颜色。默认使用任务条颜色的浅色。 |
| `workingDaysOnly` | `boolean` | 标出非工作日，并按工作日统计。 |
| `workingDays` | `object` | 工作日历，包含 `weekdays` 和 `exceptions`。 |

```ts
const gantt = table.createView('Delivery', univerAPI.Enum.BaseViewType.Gantt, {
  view: {
    config: {
      startDateFieldId: 'startDate',
      endDateFieldId: 'endDate',
      progressFieldId: 'progress',
      showPlanComparison: true,
      planStartDateFieldId: 'plannedStart',
      planEndDateFieldId: 'plannedEnd',
    },
  },
})
```

在 UI 中打开甘特视图设置，启用“计划对照”，然后选择计划开始和计划结束字段。两个计划字段都设置后，计划任务条会显示在当前任务条下方。桌面端将鼠标悬停在任务条上，或在移动端轻点任务条，即可对照两套排期。提示中会显示开工和完工偏差（工作日）。

## 甘特图前置任务

将 `dependencyFieldId` 设为指向同一张表的多值记录关联字段。该字段必须可编辑，且不能是系统字段。

`@univerjs-pro/bases` 包导出 `AddGanttPredecessorCommand` 和 `RemoveGanttPredecessorCommand`。两者的参数都是 `unitId`、`tableId`、`viewId`、`predecessorId` 和 `successorId`。添加命令在调用后关联已存在时返回 `true`，请求被拒绝时返回 `false`，会形成循环依赖时返回 `'cycle'`。删除命令在调用后关联不存在时返回 `true`。

```ts
import { AddGanttPredecessorCommand, RemoveGanttPredecessorCommand } from '@univerjs-pro/bases'

const base = univerAPI.getActiveBase()
if (!base) throw new Error('No active Base')

const params = {
  unitId: base.getId(),
  tableId: table.getId(),
  viewId: gantt.getId(),
  predecessorId: 'task-1',
  successorId: 'task-2',
}

const added = await univerAPI.executeCommand(AddGanttPredecessorCommand.id, params)
// true：已建立关联；false：被拒绝；'cycle'：会形成循环依赖

await univerAPI.executeCommand(RemoveGanttPredecessorCommand.id, params)
```

在桌面端，将当前任务条任一端的连接点拖到另一个任务条上，即可添加完成到开始（finish-to-start）关联。一次撤销即可移除该关联。

启用甘特图协同编辑前，先将网关升级到支持 Base 操作转换（OT）的版本，再部署 1.6.0 客户端。

## 排序和字段显示

```ts
grid.setSort([{ fieldId: 'priority', direction: univerAPI.Enum.BaseSortDirection.DESC }])
grid.setFieldVisible('internalNotes', false)
grid.setFieldWidth('title', 280)
```

筛选、排序、分组和字段显示都属于当前视图，均不会删除底层的记录或字段。

## 条件着色

以下规则将分数高于 80 的记录标记出来：

```ts
const score = table.addField('Score', univerAPI.Enum.BaseFieldType.Number)
grid.setConditionalColorRules([{
  id: 'high-score',
  target: univerAPI.Enum.BaseConditionalColorTarget.ROW,
  fieldId: score.getId(),
  operator: univerAPI.Enum.BaseConditionalColorOperator.GREATER_THAN,
  operand: 80,
  color: '#dcfce7',
}])
```

规则按数组顺序决定优先级，传入 `[]` 可清空规则。目标可以是单元格、整行或整列；整列着色不判断条件。
