---
title: Записи, связи и иерархия
---

Запись представляет собой один бизнес-объект, такой как задача, клиент или заказ. Facade API охватывает операции, которые применяются к записям: написание партии, чтение страницы, связывание другой таблицы и организация записей родителей и детей.

## Создание и чтение записей

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')

const table = base.insertTable('Tasks', { primaryFieldName: 'Title' })
const titleId = table.getPrimaryFieldId()
const records = table.addRecords([
  { values: { [titleId]: 'Write documentation' } },
  { values: { [titleId]: 'Review examples' } },
])
records[0].setValue(titleId, 'Publish documentation')

const page = table.queryRecords({ offset: 0, limit: 20 })
console.log(page.total, page.records)
```

Значения записи по умолчанию помечаются идентификатором поля. Если данные помечены именем поля, передайте `univerAPI.Enum.BaseFieldKeyEnum.Name`. `queryRecords()` запрашивает только данные, уже загруженные локально; он не извлекает страницы из бэкэнда. Используйте `viewId` для чтения записей в пределах области просмотра или `sort`, чтобы установить порядок.

Удалите партию с `table.deleteRecords(recordIds)` или дублируйте запись с `record.duplicate()`. Обе операции проходят через систему команд, поэтому отмена и переделка поддерживаются.

## Поиск записей

Ищите текст в полях, которые вы выбираете:

```ts
const matches = table.search({ query: 'documentation', fieldIds: [titleId], limit: 20 })
console.log(matches)
```

## Связь с другой таблицей

Следующий пример связывает каждую задачу с проектом:

```ts
const projects = base.insertTable('Projects', { primaryFieldName: 'Name' })
const project = projects.addRecord({ [projects.getPrimaryFieldId()]: 'Website' })
const projectField = table.addField('Project', univerAPI.Enum.BaseFieldType.RecordLink, {
  field: { config: { targetTableId: projects.getId(), multiple: false } },
})
records[0].setLinkedRecordIds(projectField.getId(), [project.getId()])
console.log(records[0].getLinkedRecordIds(projectField.getId()))
```

Связанные цели должны принадлежать к одной и той же Базе. Установите `multiple: true`, чтобы позволить более чем одной связанной записи, `displayFieldId` выбрать отображаемую этикетку, а `pickerFieldIds` предоставить дополнительный контекст в сборщике. Прочитайте и запишите идентификаторы через API-интерфейсы ссылок, а не напрямую создавая внутренние строки хранения.

## Родительские и дочерние записи

Следующий пример делает обзор API ребенком задачи документации:

```ts
const parent = records[0]
const parentFieldId = table.getHierarchyFieldId()
const child = parent.addChild(parentFieldId, { [titleId]: 'Check API examples' })
console.log(child.getParent(parentFieldId)?.getId())

child.setParent(parentFieldId, null)
```

Добавление первого ребенка создает необходимое поле родительских ссылок. Используйте `getChildren()`, `getAncestors()` и `getDescendants()` для чтения отношений. Иерархия может быть глубиной в пять уровней. Запись не может быть собственным родителем, а циклы отвергаются. Недействительные операции бросают, поэтому уловите ошибку и представьте полезное сообщение в пользовательском интерфейсе.

Иерархия является частью данных таблицы, поэтому переключение или фильтрация просмотров не меняет ее. [Фасад Базы](/reference/facade/base) документирует оставшиеся методы.
