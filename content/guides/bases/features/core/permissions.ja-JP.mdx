---
title: 権限
---

ベース全体が、個々のテーブル、フィールド、レコード、ビューを編集できるため、読み取り専用のレポートとアプリケーションバージョンをカバーします。

これらの API のいずれかを呼び出す前に、ベースプラグインを登録し、`@univerjs-pro/bases/facade` をインポートします。

## Base を読み取り専用にする

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')

await base.getPermission().setReadOnly()
console.log(base.getPermission().canEdit()) // false

await base.getPermission().setEditable()
```

## 個別のオブジェクトを制限する

次の例では、単一のテーブルを制限します。

```ts
const table = base.getTables()[0]
if (!table) throw new Error('Create a table first')

await table.getPermission().setReadOnly()
await table.getPermission().setEditable()
```

フィールド、レコード、およびビューは、プラグインが登録されると、ダッシュボードやピボットビューを行うため、`getPermission()`を露出します。 子オブジェクトの編集可能を作ることは、その親に対する制限を解除しません。テーブルが読み取り専用である場合は、編集可能な内部のレコードは効果がありません。

`setReadOnly()`と`setEditable()`は約束を返し、`await`を返します。 複数のオブジェクトを1つの呼び出しで変更するには、`base.getPermission().setObjectPermissions()`を使用します。 [ベースファサード](/reference/facade/base) パラメータをリストします。

## コピー、エクスポート、コメント

ベースレベルの権限もコピー、エクスポート、コメントが許可されているかどうかを判断します。コピーを無効にするには:

```ts
import { UnitAction } from '@univerjs/protocol'

await base.getPermission().setPoint(UnitAction.Copy, false)
```

`UnitAction.Export`と`UnitAction.Comment`を使用して、それぞれにエクスポートおよびコメントを行います。

## 業務上の権限との連携

ローカルパーミッションは、エディタが許可するかどうかを管理します。共同アプリケーションは、コンテンツの読み込みを承認し、コラボレーションに参加し、サーバー上の変更を提出する必要があります。 [サーバ統合](/server)を参照してください。

テスト中に、エディタ、ビューア、アクセスのないユーザを使用し、ページ上のアクションと直接リクエストの両方を検証します。
