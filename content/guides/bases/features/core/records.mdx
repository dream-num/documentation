---
title: Records, links, and hierarchy
---

A record represents one business object, such as a task, a customer, or an order. The Facade API covers the operations that apply to records: writing a batch, reading a page, linking another table, and organizing parent-child records.

## Create and read records

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')

const table = base.insertTable('Tasks', { primaryFieldName: 'Title' })
const titleId = table.getPrimaryFieldId()
const records = table.addRecords([
  { values: { [titleId]: 'Write documentation' } },
  { values: { [titleId]: 'Review examples' } },
])
records[0].setValue(titleId, 'Publish documentation')

const page = table.queryRecords({ offset: 0, limit: 20 })
console.log(page.total, page.records)
```

Record values are keyed by field ID by default. If the data is keyed by field name, pass `univerAPI.Enum.BaseFieldKeyEnum.Name`. `queryRecords()` queries only the data already loaded locally; it does not fetch pages from a backend. Use `viewId` to read records within the scope of a view, or `sort` to set the ordering.

Delete a batch with `table.deleteRecords(recordIds)`, or duplicate a record with `record.duplicate()`. Both operations go through the command system, so undo and redo are supported.

## Search records

Search for text within the fields that you select:

```ts
const matches = table.search({ query: 'documentation', fieldIds: [titleId], limit: 20 })
console.log(matches)
```

## Link another table

The following example links each task to a project:

```ts
const projects = base.insertTable('Projects', { primaryFieldName: 'Name' })
const project = projects.addRecord({ [projects.getPrimaryFieldId()]: 'Website' })
const projectField = table.addField('Project', univerAPI.Enum.BaseFieldType.RecordLink, {
  field: { config: { targetTableId: projects.getId(), multiple: false } },
})
records[0].setLinkedRecordIds(projectField.getId(), [project.getId()])
console.log(records[0].getLinkedRecordIds(projectField.getId()))
```

Linked targets must belong to the same Base. Set `multiple: true` to allow more than one linked record, `displayFieldId` to choose the displayed label, and `pickerFieldIds` to supply additional context in the picker. Read and write IDs through the link APIs rather than constructing internal storage strings directly.

## Parent-child records

The following example makes the API review a child of the documentation task:

```ts
const parent = records[0]
const parentFieldId = table.getHierarchyFieldId()
const child = parent.addChild(parentFieldId, { [titleId]: 'Check API examples' })
console.log(child.getParent(parentFieldId)?.getId())

child.setParent(parentFieldId, null)
```

Adding the first child creates the required parent-link field. Use `getChildren()`, `getAncestors()`, and `getDescendants()` to read the relationships back. A hierarchy can be five levels deep. A record cannot be its own parent, and cycles are rejected. Invalid operations throw, so catch the error and present a useful message in the UI.

Hierarchy is part of the table data, so switching or filtering views does not change it. [Bases Facade](/reference/facade/base) documents the remaining methods.
