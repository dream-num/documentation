---
title: Registros, enlaces y jerarquía
---

Un registro representa un objeto de negocio, como una tarea, un cliente o un pedido. El Facade API cubre las operaciones que se aplican a los registros: escribir un lote, leer una página, vincular otra tabla, y organizar registros entre padres e hijos.

## Crear y leer registros

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')

const table = base.insertTable('Tasks', { primaryFieldName: 'Title' })
const titleId = table.getPrimaryFieldId()
const records = table.addRecords([
  { values: { [titleId]: 'Write documentation' } },
  { values: { [titleId]: 'Review examples' } },
])
records[0].setValue(titleId, 'Publish documentation')

const page = table.queryRecords({ offset: 0, limit: 20 })
console.log(page.total, page.records)
```

Los valores de registro son claves por ID de campo por defecto. Si los datos se claven por nombre de campo, pasar `univerAPI.Enum.BaseFieldKeyEnum.Name`. `queryRecords()` sólo consulta los datos ya cargados localmente; no recoge páginas de un backend. Utilice `viewId` para leer los registros dentro del alcance de una vista, o `sort` a establecer el orden.

Eliminar un lote con `table.deleteRecords(recordIds)`, o duplicar un registro con `record.duplicate()`. Ambas operaciones pasan por el sistema de comandos, por lo que se admiten deshacer y rehacer.

## Buscar registros

Busque texto dentro de los campos que seleccione:

```ts
const matches = table.search({ query: 'documentation', fieldIds: [titleId], limit: 20 })
console.log(matches)
```

## Vincular otra tabla

El siguiente ejemplo vincula cada tarea a un proyecto:

```ts
const projects = base.insertTable('Projects', { primaryFieldName: 'Name' })
const project = projects.addRecord({ [projects.getPrimaryFieldId()]: 'Website' })
const projectField = table.addField('Project', univerAPI.Enum.BaseFieldType.RecordLink, {
  field: { config: { targetTableId: projects.getId(), multiple: false } },
})
records[0].setLinkedRecordIds(projectField.getId(), [project.getId()])
console.log(records[0].getLinkedRecordIds(projectField.getId()))
```

Los objetivos vinculados deben pertenecer a la misma Base. Establecer `multiple: true` para permitir más de un registro enlazado, `displayFieldId` elegir la etiqueta mostrada, y `pickerFieldIds` suministrar contexto adicional en el selector. Leer y escribir IDs a través de las APIs de enlace en lugar de construir cadenas de almacenamiento interno directamente.

## Registros padre e hijo

El siguiente ejemplo hace que la revisión de la API sea un niño de la tarea de documentación:

```ts
const parent = records[0]
const parentFieldId = table.getHierarchyFieldId()
const child = parent.addChild(parentFieldId, { [titleId]: 'Check API examples' })
console.log(child.getParent(parentFieldId)?.getId())

child.setParent(parentFieldId, null)
```

La adición del primer niño crea el campo paréntesis requerido. Use `getChildren()`, `getAncestors()` y `getDescendants()` para leer las relaciones de vuelta. Una jerarquía puede ser de cinco niveles de profundidad. Un registro no puede ser su propio padre, y los ciclos son rechazados. Las operaciones inválidas lanzan, así que captura el error y presentar un mensaje útil en la interfaz de usuario.

La Jerarquía es parte de los datos de la tabla, por lo que cambiar o filtrar puntos de vista no lo cambia. [Bases Facade](/reference/facade/base) documenta los métodos restantes.
