---
title: 權限
---

可以將整個 Base 設為只讀，也可以只將某張表、某個欄位、某條記錄或某個檢視設為只讀。這涵蓋只讀報表，以及只允許使用者修改部分資料的應用場景。

呼叫這些 API 前，需要先註冊 Bases 外掛並匯入 `@univerjs-pro/bases/facade`。

## 將 Base 設為唯讀

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')

await base.getPermission().setReadOnly()
console.log(base.getPermission().canEdit()) // false

await base.getPermission().setEditable()
```

## 限制個別物件

以下範例限制單張表的編輯權限：

```ts
const table = base.getTables()[0]
if (!table) throw new Error('Create a table first')

await table.getPermission().setReadOnly()
await table.getPermission().setEditable()
```

欄位、記錄和檢視同樣提供 `getPermission()`，儀表盤和透視檢視在註冊對應外掛後也可使用。將下層物件設為可編輯，並不會解除上層物件的限制：如果表是隻讀的，單獨將表中的記錄設為可編輯不會產生任何效果。

`setReadOnly()` 和 `setEditable()` 返回 Promise，需要 `await`。要一次修改多個物件，可使用 `base.getPermission().setObjectPermissions()`，參數見 [Bases Facade](/reference/facade/base)。

## 複製、匯出與留言

Base 級權限還決定複製、匯出和評論是否可用。例如，關閉複製：

```ts
import { UnitAction } from '@univerjs/protocol'

await base.getPermission().setPoint(UnitAction.Copy, false)
```

匯出和評論分別使用 `UnitAction.Export` 和 `UnitAction.Comment`。

## 接入業務權限

本地權限控制編輯器允許執行的操作。協同應用還必須在伺服器端校驗內容讀取、加入協同和提交修改，見[伺服器端整合](/server)。

測試時應分別使用編輯者、檢視者和無權限使用者進行驗證，頁面上的操作和直接發出的請求都需要覆蓋。
