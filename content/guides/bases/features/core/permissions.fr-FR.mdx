title: Autorisations
---

Une base entière peut être faite en lecture seule, tout comme une table individuelle, un champ, un enregistrement ou une vue. Ceci couvre les rapports en lecture seule et les versions d'application dans lesquelles les utilisateurs ne peuvent modifier qu'une partie des données.

Enregistrez le plugin Bases et importez `@univerjs-pro/bases/facade` avant d'appeler l'une de ces API.

## Rendre une Base accessible en lecture seule

```ts
const base = univerAPI.getActiveBase()
if (!base) throw new Error('Open a Base first')

await base.getPermission().setReadOnly()
console.log(base.getPermission().canEdit()) // false

await base.getPermission().setEditable()
```

## Restreindre un objet individuel

L'exemple suivant limite un seul tableau :

```ts
const table = base.getTables()[0]
if (!table) throw new Error('Create a table first')

await table.getPermission().setReadOnly()
await table.getPermission().setEditable()
```

Les champs, les enregistrements et les vues exposent également `getPermission()`, comme les tableaux de bord et les vues de pivot une fois leur plugin enregistré. Rendre un objet enfant modifiable ne supprime pas une restriction sur son parent : si la table est en lecture seule, faire un enregistrement à l'intérieur de lui modifiable n'a pas d'effet.

`setReadOnly()` et `setEditable()` promettent un retour, donc `await` les promet. Pour modifier plusieurs objets en un seul appel, utilisez `base.getPermission().setObjectPermissions()`; [Façade des bases](/reference/facade/base) liste les paramètres.

## Copie, export et commentaires

Les permissions de base déterminent également si la copie, l'exportation et le commentaire sont autorisés.

```ts
import { UnitAction } from '@univerjs/protocol'

await base.getPermission().setPoint(UnitAction.Copy, false)
```

Utilisez `UnitAction.Export` et `UnitAction.Comment` pour exporter et commenter respectivement.

## Connecter les autorisations métier

Les permissions locales régissent ce que l'éditeur permet. Une application collaborative doit également autoriser la lecture de contenu, l'intégration de la collaboration et la soumission de modifications sur le serveur ; voir [intégration du serveur](/server).

Lors des tests, utilisez un éditeur, un visionneur et un utilisateur sans accès, et vérifiez les actions sur la page et les requêtes directes.
