コメントを使用してタスク、注文、およびその他のレコードを議論します。コメントは、Grid、Kanban、Gallery、カレンダー、およびガントビューのレコードに添付され、ビューを切り替えることは、別の議論を作成しません。

## プラグインの登録

Bases コアと UI プラグインの後に次のプラグインを登録します。

```package-install
npm install @univerjs/thread-comment @univerjs/thread-comment-ui @univerjs-pro/bases-thread-comment @univerjs-pro/bases-thread-comment-ui
```

```ts
import { UniverBasesThreadCommentPlugin } from '@univerjs-pro/bases-thread-comment'
import { UniverBasesThreadCommentUIPlugin } from '@univerjs-pro/bases-thread-comment-ui'
import ProductLocale from '@univerjs-pro/bases-thread-comment-ui/locale/ja-JP'
import { LocaleType, mergeLocales } from '@univerjs/core'
import SharedLocale from '@univerjs/thread-comment-ui/locale/ja-JP'
import '@univerjs-pro/bases-thread-comment/facade'
import '@univerjs/thread-comment/facade'
import '@univerjs/thread-comment-ui/lib/index.css'
import '@univerjs-pro/bases-thread-comment-ui/lib/index.css'

univerAPI.loadLocales(LocaleType.JA_JP, mergeLocales(SharedLocale, ProductLocale))
univer.registerPlugin(UniverBasesThreadCommentPlugin)
univer.registerPlugin(UniverBasesThreadCommentUIPlugin)
```

コメントパッケージからローカルリソースをマージし、アプリケーション用の現在のユーザーを設定します。 UIプラグインは、コメントコントロールをレコードに追加し、データプラグインはレコードにコメントを関連付けます。

## コメントの追加と読み取り

```ts
const record = univerAPI.getActiveBase()?.getTables()[0]?.getRecords()[0]
if (!record) throw new Error('Create a record first')

await record.createCommentAsync('Please confirm the delivery date.')
const comments = record.getComments()
console.log(comments.map(({ root }) => root.id))
```

`getComments()`は、既にローカルに読み込まれているコメントを返します。リモートデータソースでは、`await record.listCommentsAsync()` は、既にそれらを返す前に知っているスレッドを同期させます。返信、更新、削除は [コメントファサード](/reference/facade/thread-comment)で記述されています。

## 保存と共有の議論

アプリケーションが `base.save()` を呼び出すと、ローカルで作成されたコメントは、ベースリソースの一部として保存されます。 スナップショットを復元する前にコメントプラグインを登録します。

共有された議論には、コメントサービス、データソース、および権限が必要です。 文書のコラボレーションはコメントを結びつけることはありません。 [オフィス拡張モジュール](/server/collaboration/extensions)を最初に構成し、作成、読み込み、パーミッションの確認、および2つのアカウントで再オープンします。

## 共通のコメント操作 [#shared-comment-api]

これらのメソッドを呼び出す前に、共有コメントファサードと製品ファサードの両方をインポートします。 製品のヘルパーは安定したアンカーを作成し、共有された API は、応答、更新、解像度、削除を処理します。 `getComments()` はローカルの状態を読み込み、 `listCommentsAsync()`は、設定されたデータソースを介して既に知っているスレッドを同期させます。 サーバーのすべてのスレッドは検出されません。

```ts
import '@univerjs/thread-comment/facade'

const [thread] = univerAPI.getComments({ resolved: false })
if (thread) {
  await univerAPI.replyCommentAsync({
    unitId: thread.unitId,
    subUnitId: thread.subUnitId,
    threadId: thread.threadId,
    content: 'Reviewed.',
  })
}
```

## 共有ディスカッション [#shared-discussions]

共有ディスカッションを有効にするには、コメントサービスとエンドポイントを[Server SDK](/server/collaboration/extensions)に統合し、`UniverThreadCommentDataSourcePlugin`から`@univerjs-pro/thread-comment-datasource`を連携してライセンスを設定しています。 バンドルされたデータソースは`/universer-api/comment/unit/{unitId}/...`と`/universer-api/user/list`を呼び出すので、アプリケーションはこれらのルートを明示しなければなりません。 サーバーの権限はコメントをコントロールし、文書の編集を独立して記述する必要があります。
