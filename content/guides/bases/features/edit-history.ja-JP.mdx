フィールド、レコード、またはビューの変更後、以前のバージョンを表示し、変更を比較し、権限が許可したときにバージョンを復元します。 履歴は、サーバーによって永続したバージョンを読みます。 undoとredoは、現在の編集セッションにのみ適用され、履歴サービスを必要としません。

## 共同編集と履歴サービスの準備

[コラボレーション統合](/server/collaboration/browser-integration)と[ライセンス構成](/server/license)を補完します。 その後、2つのセッションが同じベース文書を編集でき、再ロード後の変更が永続的であることを確認します。

[オフィスのコラボレーション拡張](/server/collaboration/extensions)と[歴史例](/server/collaboration/examples#history)による履歴記憶と権限を接続します。コアコラボレーションはそれ自体で履歴を有効にせず、バックエンドは履歴リスト、バージョンコンテンツ、および復元をサポートする必要があります。

## 履歴プラグインの追加

既存の製品、ライセンス、コラボレーション設定の上部にこの設定を追加します。プリセットまたは既存の設定がすでにこれらのプラグインを登録している場合は、プラグインを再度登録する代わりに、その設定を更新します。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/bases-history @univerjs-pro/bases-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBasesHistoryPlugin } from '@univerjs-pro/bases-history'
import { UniverBasesHistoryUIPlugin } from '@univerjs-pro/bases-history-ui'
import HistoryLocale from '@univerjs-pro/bases-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/bases-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBasesHistoryPlugin)
univer.registerPlugin(UniverBasesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### プラグイン設定

`UniverEditHistoryPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |

`UniverBasesHistoryUIPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |
| `univerContainerId` | `string` |  | エディターコンテナの DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 歴史ビューア用の余分なプラグイン。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | プラグインのコンストラクター。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | そのプラグインのコンストラクタに渡されたオプション。 |

アプリケーションの履歴エンドポイントで`/api/history`をポイントし、クライアントが送信するリクエストと一致するAPIが確認されます。`historyServerUrl`の値は同一でなければなりません。エディタコンテナのDOM IDに`univerContainerId`を設定し、エディタが使用するロケールをロードします。

履歴ビューアは別々の読み取り専用エディタを開始します。 ドキュメントにカスタムコンテンツが含まれている場合は、`viewerPlugins`を使用してビューアが既に含まなかったプラグインを追加してください。 組み込みビューアプラグインを再度登録しないでください。

## バージョンの表示と復元

エディタメニューから履歴を開き、そのコンテンツと含まれている変更を表示するためにバージョンを選択します。バージョンを復元すると、現在の共有文書が書き換えられます。そのため、復元権限を持つユーザーはこの操作を実行できるようにする必要があります。サーバーは、その許可を強制しなければなりません。

統合、編集フィールド、レコード、またはビューを確認するには、コラボレーションが変更を確認するまで待ちます。その後、履歴リストとバージョンのコンテンツを調べます。アプリケーションを再オープンし、サービスを再始動して、永続性をテストします。以前のバージョンを復元し、別のブラウザセッションが復元された状態を受け取ることを確認します。

リストが空の場合、まずこのドキュメントの履歴が記録されたかどうかを確認し、ドキュメント ID とサービス URL を確認します。 閲覧作品が失敗した場合、復元権限とコラボレーション接続を確認します。 読み上げ履歴には、古いバージョンが削除されたデータが含まれている可能性があるため、許可が必要です。

## スナップショットの比較 [#compare-snapshots]

レビュー画面を作成するか、AIエージェントへの変更を渡すには、`compareUnitData()` を呼び出すか、または `prepareUnitComparison()`. 製品の履歴プラグインを登録し、ファサードエントリーをインポートします。 `beforeSnapshot`と`afterSnapshot`と同じユニットの2つの完全に材料化されたスナップショットを渡します。 比較は読み取り専用です:それは履歴サービスを必要としませんし、コンテンツを復元するか、またはマージしません。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BASE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

フィードバック `scopes` どのビューが利用できるかを確認するために、スコープを渡します `query()` 比較を再実行せずに結果をフィルタリングします。 ページには、デフォルトで最大1,000個のアイテムが含まれています。 使用 `page.hasMore` と、 `offset` 残りの項目を取り出します。 `summary` アイテムをフィルタリングした後であっても、比較全体をカバーします。 結果を完全な比較として扱う前に、チェック `diagnostics.readiness` そして、 `diagnostics.codes`. のために Node.js エディタなしでまたはCLIの使用は、参照してください [ヘッドレス比較API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
