感謝你對貢獻 Univer 的興趣！本文檔將幫助你快速上手。

## 行為準則

我們致力於為所有貢獻者提供一個友好、安全和受歡迎的環境。請在所有互動中保持尊重和建設性。

## 如何貢獻

### 報告缺陷

在建立缺陷報告之前，請：

1. 搜尋 [現有 issue](https://github.com/dream-num/univer/issues) 以避免重複
2. 使用最新穩定版驗證該缺陷是否仍然存在
3. 收集相關資訊：瀏覽器版本、Node.js 版本、錯誤資訊

報告時請包含：

- 清晰、描述性的標題
- 復現步驟
- 預期行為與實際行為
- 最小可復現示例（CodeSandbox、StackBlitz 或 GitHub 倉庫）
- 如有必要，附上截圖或錄影

### 提議新功能

歡迎提交功能請求！建議先開啟一個 discussion，收集社群和維護者的回饋。

### 提交程式碼

#### 開發環境搭建

1. Fork 並克隆倉庫：
   ```bash
   git clone https://github.com/YOUR_USERNAME/univer.git
   cd univer
   ```

2. 安裝依賴：
   ```bash
   pnpm install
   ```

3. 構建專案：
   ```bash
   pnpm build
   ```

4. 執行測試：
   ```bash
   pnpm test
   ```

#### 專案結構

```
packages/
  core/           # 核心基礎設施（依賴注入、命令系統、生命週期）
  design/         # 設計系統和基礎樣式
  engine-render/  # Canvas 渲染引擎
  engine-formula/ # 公式計算引擎
  sheets/         # 電子表格資料模型和核心邏輯
  sheets-ui/      # 電子表格 UI 元件
  docs/           # 文件資料模型
  docs-ui/        # 文件 UI 元件
  slides/         # 簡報資料模型
  ui/             # 共享 UI 框架
examples/         # 整合示例（React、Vue、Angular 等）
```

#### 編寫外掛程式

Univer 基於外掛程式架構構建。要添加新功能：

1. 在 `packages/` 下建立新套件，或建立獨立倉庫
2. 實作繼承自 `Plugin` 的外掛程式類別
3. 在 `onStarting` 中註冊命令、服務和控制器
4. 如需暴露公共 API，添加 Facade 擴充
5. 編寫測試和文件

請參閱 [自訂外掛程式教學](/guides/recipes/tutorials/custom-plugin) 取得分步指南。

#### 提交規範

我們使用 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/v1.0.0/)：

```
<type>(<scope>): <subject>

<body>

<footer>
```

常用類型：

- `feat`：新功能
- `fix`：缺陷修復
- `docs`：文件變更
- `style`：程式碼格式調整
- `refactor`：程式碼重構
- `perf`：效能最佳化
- `test`：測試相關
- `chore`：建置流程或輔助工具變更

示例：
```
feat(sheets): 增加自訂數字格式支援

Closes #1234
```

#### Pull Request 流程

1. 從 `dev` 分支建立功能分支
2. 進行清晰、專注的提交
3. 根據需要添加或更新測試
4. 確保 `pnpm lint` 和 `pnpm test` 通過
5. 如果變更影響公共 API，更新文件
6. 向 `dev` 分支發起 Pull Request
7. 填寫 PR 模板，提供清晰的描述

### 貢獻文件

文件改進同樣受到高度重視。編輯文件的步驟：

1. 文件位於 [documentation 倉庫](https://github.com/dream-num/documentation)
2. 每頁對應一個 `.mdx` 檔案
3. 遵循現有的風格和格式
4. 如適用，請同時更新所有語言版本（en-US、zh-CN、zh-TW、ja-JP）
