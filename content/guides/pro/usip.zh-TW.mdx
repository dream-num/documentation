## 概述

Univer Pro 的後端服務沒有整合賬戶系統（也不應該整合），預設配置下，Univer Pro 的後端服務不會對訪問者進行身份認證，也即所有使用者都可訪問所有的資源。

如果你需要對使用者進行身份認證，認證透過才能使用，那麼你必須實現自己的賬戶系統。你可以配置 Univer Server 和你的系統進行互動，Univer Server 在需要認證使用者身份的時候即會呼叫你的系統完成認證。

為了實現這類互動，Univer Pro 設計了 *Univer Server 整合協議 USIP（Univer Server Integration Protocol）*。USIP本質上是一種 SPI（`Service Provider Interface`），也即由 **Univer Pro 來定義介面，然後由你的系統進行實現**。

Univer Pro 根據使用者的潛在需求，已經定義好了一些 USIP 介面，你可以選擇實現一些介面來改變 Univer Pro 處理某些使用者請求的流程，比如進行使用者認證和許可權校驗。如果當前已有 USIP 介面無法滿足你的需求，可以給我們提出建議。

## USIP 介面說明

目前 Univer Pro 定義了三類場景的 USIP 介面：

- 👥 賬戶類
  - 身份認證
  - 使用者資訊獲取：name、avatar 之類的基礎資訊
- 🔒 許可權類
  - 獲取使用者在某一文件上的許可權角色
  - 獲取某一文件的協作者列表
- 📄 檔案類
  - 通知文件最新修改時間

## 配置 USIP 接入

如何配置 Univer 後端服務啟用使用者身份認證和許可權校驗？

使用 docker compose 部署時，在自定義的配置檔案 `.env.custom` 中新增以下配置：

```properties title=".env.custom"
# usip about
USIP_ENABLED=true  # 設定為 true 以啟用 USIP
USIP_URI_CREDENTIAL=https://your-domain/usip/credential # 配置好身份認證 USIP 的實現 URL
USIP_URI_USERINFO=https://your-domain/usip/userinfo     # 配置好使用者資訊獲取 USIP 的實現 URL
USIP_URI_ROLE=https://your-domain/usip/role             # 配置好許可權角色獲取 USIP 的實現 URL
USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators # 配置好協作者列表 USIP 的實現 URL
USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time # 配置好接收文件修改時間 USIP 的實現 URL

# auth about
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false  # 見下面許可權設計說明
AUTH_PERMISSION_CUSTOMER_STRATEGIES=      # 見下面許可權設計說明
```

使用 K8s 部署時，編輯你的自定義 values.yaml，新增以下配置：

```yaml title="values.yaml"
universer:
  config:
    usip:
      enabled: true # 設定為 true 以啟用 USIP
      uri:
        userinfo: 'https://your-domain/usip/userinfo' # 配置好使用者資訊獲取 USIP 的實現 URL
        collaborators: 'https://your-domain/usip/collaborators' # 配置好協作者列表 USIP 的實現 URL
        role: 'https://your-domain/usip/role' # 配置好許可權角色獲取 USIP 的實現 URL
        credential: 'https://your-domain/usip/credential' # 配置好身份認證 USIP 的實現 URL
        unitEditTime: 'https://your-domain/usip/unit-edit-time' # 配置好接收文件修改時間 USIP 的實現 URL
    auth:
      permission:
        enableObjInherit: false # 見下面許可權設計說明
        customerStrategies: '' # 見下面許可權設計說明
```

**請注意**，一旦你配置了開啟 USIP，上述的所有 4 個 USIP API 的 url 都需要配置，並且需要你的服務正確實現。如何在部署的時候應用這些配置請參考[生產部署](/guides/pro/deploy)。

## Univer 許可權設計

Univer 的許可權控制採用的是 `RBAC` 模型，目前固定設定了 3 個角色：`owner`、`editor`、`reader`，並且 editor 角色具有 reader 角色的許可權、owner 角色又具有 editor 角色和 reader 角色的許可權。目前暫未開放自定義角色，但開放了使用者可配置各許可權點位所需的最低角色。Univer 內建有一份預設生效的配置，如果你沒有需要可以什麼都不做，如果有需要，你可以配置以覆蓋部分許可權點位的最低角色要求。

Univer 內建的預設生效的各許可權點位及其所需的最低角色如下：

| 許可權點位 | 許可權點位列舉值 | 點位含義 | 最低角色要求 | 角色列舉值 |
|:-------|:---------|:-------|:-------|:-------|
| ManageCollaborator | 2 | 邀請 / 刪除文件的協作者 | owner | 2 |
| Copy | 6 | 複製文件內容 | reader | 0 |
| Print | 3 | 列印 | editor | 1 |
| Duplicate | 4 | 複製文件 | editor | 1 |
| Share | 7 | 分享給他人 | reader | 0 |
| Export | 8 | 匯出 | editor | 1 |
| Comment | 5 | 評論 | reader | 0 |
| View | 0 | 閱讀 | reader | 0 |
| MoveSheet | 25 | 移動 workbook 內的 worksheet | editor | 1 |
| DeleteSheet | 26 | 刪除 worksheet | editor | 1 |
| HideSheet | 27 | 隱藏 worksheet | editor | 1 |
| CopySheet | 28 | 複製 worksheet | editor | 1 |
| RenameSheet | 29 | 重新命名 worksheet | editor | 1 |
| CreateSheet | 30 | 新增 worksheet | editor | 1 |
| SetCellStyle | 33 | 設定單元格樣式 | editor | 1 |
| SetCellValue | 34 | 設定單元格值 | editor | 1 |
| InsertHyperlink | 16 | 插入超連結 | editor | 1 |
| Sort | 17 | 排序 | editor | 1 |
| Filter | 18 | 過濾 | editor | 1 |
| PivotTable | 19 | 透視表 | editor | 1 |
| RecoverHistory | 43 | 恢復文件到歷史版本 | editor | 1 |
| ViewHistory | 44 | 檢視文件編輯歷史記錄 | reader | 0 |
| SelectProtectedCells | 31 | 選擇被保護區域的單元格 | editor | 1 |
| SelectUnProtectedCells | 32 | 選擇非保護區域的單元格 | editor | 1 |
| SetRowStyle | 35 | 設定行樣式 | editor | 1 |
| SetColumnStyle | 36 | 設定列樣式 | editor | 1 |
| InsertRow | 37 | 插入行 | editor | 1 |

| Delete | 42 | 刪除文件 | owner | 2 |
| CreatePermissionObject | 45 | 建立保護區 / 保護子表 | editor | 1 |

如果你想要修改其中一些許可權點位要求的最低角色，比如，想設定只有文件 owner（role=2） 才能複製內容（action=6）和列印（action=3），可如下配置：

使用 docker compose 部署時，在自定義的配置檔案 `.env.custom` 中新增以下配置：

```properties title=".env.custom"
AUTH_PERMISSION_CUSTOMER_STRATEGIES=[{"action": 3, "role": 2}, {"action": 6, "role": 2}]
```

使用 K8s 部署時，編輯你的自定義 values.yaml，新增以下配置：

```yaml title="values.yaml"
universer:
  config:
    auth:
      permission:
        customerStrategies: '[ {"action": 3, "role": 2}, {"action": 6, "role": 2} ]'
```

可以看到，配置的值是一個 json 物件陣列，物件的 action 即為上述列表中的許可權點位列舉值，role 則是該許可權點位要求的最低角色對應的列舉值。

Univer 許可權管理設計還有一個需要關注的點：

Univer 除了在整個文件級別控制許可權，還會在文件下的保護區域 / 子表上控制許可權，他們都擁有獨立的授權使用者管理。比如，使用者 A 是整個文件的 editor，但不是此文件中某個保護區域 / 子表的 editor 或 owner，那麼使用者 A 不能編輯此保護區域 / 子表。在 Univer 的預設配置下，即使使用者 A 是文件的 owner，也無法管理其他使用者在此文件上建立的保護區域 / 子表，除非其他使用者給他新增了保護區域 / 子表的許可權。如果你想要配置成文件的 owner 無條件擁有文件中所有物件的 owner 角色，可以如下修改配置：

使用 docker compose 部署時，在自定義的配置檔案 `.env.custom` 中新增以下配置：

```properties title=".env.custom"
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=true
```

使用 K8s 部署時，編輯你的自定義 values.yaml，新增以下配置：

```yaml title="values.yaml"
universer:
  config:
    auth:
      permission:
        enableObjInherit: true
```

## 前端配置自定義請求頭

在使用 USIP 時，你可能需要在前端請求中新增自定義的請求頭（比如 Authorization token）。你可以透過 Univer 的 HTTPService 攔截器來實現這一點。

在初始化 Univer 例項時，新增如下程式碼：

<Tabs items={['預設模式', '外掛模式']}>
  <Tab>
    ```typescript
    import { HTTPService } from '@univerjs/preset-sheets-core'

    // 透過 Univer 例項獲取 injector
    const injector = univer.__getInjector()
    // 新增自定義請求頭
    const httpService = injector.get(HTTPService)
    httpService.registerHTTPInterceptor({
      priority: 0,
      interceptor: (request, next) => {
        // 在這裡新增你需要的請求頭
        // 例如新增 Authorization token：
        // request.headers.set('Authorization', 'Bearer your-token-here')
        return next(request)
      },
    })
    ```
  </Tab>
  <Tab>
    ```typescript
    import { HTTPService } from '@univerjs/network'

    // 透過 Univer 例項獲取 injector

        // request.headers.set('Authorization', 'Bearer your-token-here')
        return next(request)
      },
    })
    ```
  </Tab>
</Tabs>

如果使用了[歷史記錄](/guides/sheets/features/edit-history)，你需要在[獲取 HistoryUniver 的例項](/guides/sheets/features/edit-history#get-edit-history-univer-instance)後為其新增相同的攔截器：

```typescript
historyLoaderService.historyUniver$.subscribe((historyUniver) => {
  if (!historyUniver) return

  const injector = historyUniver.__getInjector()
  const httpService = injector.get(HTTPService)
  httpService.registerHTTPInterceptor({
    priority: 0,
    interceptor: (request, next) => {
    // 在這裡新增你需要的請求頭
    // 例如新增 Authorization token：
    // request.headers.set('Authorization', 'Bearer your-token-here')
      return next(request)
    },
  })
})
```
