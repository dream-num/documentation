## Configuración de implementación

### Cómo modificar la configuración de implementación

La configuración de implementación predeterminada de Univer se encuentra en el archivo `.env` en el directorio de instalación. Si necesita modificar la configuración de instalación, no edite el archivo `.env` directamente. En su lugar, cree un archivo de configuración personalizado llamado `.env.custom` en el mismo directorio. Los elementos configurados en `.env.custom` anularán los valores predeterminados en el archivo `.env`.

### Detalles de configuración

#### Habilitar autenticación de identidad y administración de permisos

El significado de los elementos de configuración relevantes ya se explicó en [Integre con su sistema a través de USIP](/guides/pro/usip) y no se repetirá aquí. Para habilitarlo, puede consultar la siguiente configuración:

```properties title=".env.custom"
# usip about
USIP_ENABLED=true # Set to true to enable USIP
USIP_URI_CREDENTIAL=https://your-domain/usip/credential
USIP_URI_USERINFO=https://your-domain/usip/userinfo
USIP_URI_ROLE=https://your-domain/usip/role
USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

# apikey is optional
USIP_APIKEY=

# auth about
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
AUTH_PERMISSION_CUSTOMER_STRATEGIES=
```

#### Habilitar la publicación de eventos de Univer

El significado de los elementos de configuración relevantes ya se explicó en [Integre con su sistema a través de Univer Event Sync](/guides/pro/event-sync) y no se repetirá aquí. Para habilitarlo, puede consultar la siguiente configuración:

```properties title=".env.custom"
EVENT_SYNC=true # Set to true to enable
```

#### Usar componentes de infraestructura automantenidos

##### RDS

**Tenga en cuenta**, debido a que el componente Temporal utilizado por Univer no es compatible con GaussDB y DamengDB, si elige cualquiera de estas bases de datos, Univer instalará PostgreSQL por separado para Temporal. Temporal almacena los estados del flujo de trabajo de las tareas de importación/exportación en la base de datos y no involucra ningún dato del documento. Incluso si se pierde, solo provocará que fallen las tareas de importación/exportación incompletas y no tendrá ningún otro impacto.

###### Utilice RDS compatible con PostgreSQL

```properties title=".env.custom"
# RDS config
DISABLE_UNIVER_RDS=true # When using your own RDS, disable Univer's default PostgreSQL

DATABASE_DRIVER=postgresql # Set to postgresql for PostgreSQL-compatible databases
DATABASE_HOST=your-database-host
DATABASE_PORT=your-database-port
DATABASE_DBNAME=univer # Univer database init scripts use this name by default; keep it consistent if changed
DATABASE_USERNAME=user-name # Grant select, insert, update, delete permissions
DATABASE_PASSWORD=password
```

#### Configuración de programación de edición colaborativa por niveles

Introducida desde `v0.15.0`, deshabilitada de forma predeterminada y debe configurarse manualmente para habilitarla. El sistema decide en qué nivel del clúster de servicios de colaboración programar en función del recuento total de celdas del libro y el tiempo de importación real. Para los libros recién importados, la programación se basa en el tiempo de importación; para los libros creados de otras formas o después de generar una nueva instantánea, la programación se basa en el recuento total de celdas. Después de la creación de cada instantánea, los datos de métricas relevantes se conservarán en la base de datos y la política de programación se actualizará.

La esencia de la programación por niveles es implementar el servicio de colaboración como múltiples clústeres y especificar qué clúster maneja hojas de cálculo de diferentes escalas a través de reglas. La estructura de datos de la configuración de reglas es la siguiente:

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

Descripción:

- `tiers`: Describe información sobre cada clúster; teóricamente se puede configurar cualquier número de clústeres.
- `enable`: establece si se habilita este clúster; establezca en `false` y el clúster se ignorará.
- `upgradeCellsThreshold`: especifica el recuento total de celdas de hoja necesarias para programar en este clúster.
- `downgradeCellsThreshold`: si la hoja está actualmente programada para este clúster, solo se puede degradar a un clúster de nivel inferior cuando el recuento total de celdas cae por debajo de este valor. Esto evita el cambio frecuente de hojas cuya escala está cerca del límite del nivel.
- `upgradeImportTimeThreshold`: Para hojas recién importadas sin estadísticas de recuento total de celdas, esta configuración se utiliza para la programación. El mecanismo es el mismo que `upgradeCellsThreshold`, excepto que la métrica es el tiempo de importación real.

Debe asegurarse de que al menos un clúster tenga todos los requisitos de métrica establecidos en 0, para que se pueda programar cada hoja.

Ejemplos de programación según la configuración de ejemplo anterior:

- el libro de trabajo1 tiene un recuento de celdas inicial de 0 después de la creación y está programado para el clúster normal.
- Cuando se edita el libro de trabajo1 y el total el recuento de celdas alcanza 1000, se programa para el clúster grande.
- Cuando el recuento total de celdas del libro1 cae a 999, debido a que todavía está por encima del umbral de degradación de 900, permanece programado para el clúster grande.
- Cuando el recuento total de celdas del libro1 cae aún más a 899, se degrada nuevamente al clúster normal.
- el libro2 se importa con un tiempo real de 61 segundos, lo que excede el El umbral del clúster enorme es de 60 segundos, por lo que está programado para el clúster enorme.

El script de implementación Docker Compose de Univer proporciona opciones para implementar 1 o 2 niveles (separando hojas de cálculo normales y grandes). El parámetro `ENABLE_LARGE_TIER_COLLABORATION_SERVER` en la configuración del clúster controla si se utiliza el clúster de hoja de cálculo grande para la programación y si Docker Compose realmente implementa los servicios del clúster de hoja de cálculo grande. Si se necesita un control más preciso del nivel del clúster o una implementación de K8, ajuste la orquestación de gráficos/composición de la ventana acoplable para implementar realmente el nivel correspondiente de los clústeres de servicios `collaboration-server` y luego configure la tabla de enrutamiento de programación (matriz `tiers`) como se describe anteriormente.

De forma predeterminada, solo se configuran dos niveles: `normal` y `large`.

```properties title=".env.custom"
# Configure to enable/disable large cluster, true-enable, false-disable, default disabled
ENABLE_LARGE_TIER_COLLABORATION_SERVER=false

# If large cluster is enabled, sheets will be scheduled to the large cluster when total cell count reaches this scale, default 2M
LARGE_TIER_MIN_CELLS_COUNT=2000000

# If the sheet is currently scheduled to the large cluster, it will only be downgraded back to the normal cluster when total cell count falls below this value, default 1.95M
LARGE_TIER_DOWNGRADE_CELLS_COUNT=1950000

# If large cluster is enabled, workbooks will be scheduled to the large cluster when import time exceeds this value, default 10s
LARGE_TIER_MIN_IMPORT_SECONDS=10

# large cluster collaboration service instance count, default 2
LARGE_TIER_COLLABORATION_SERVER_REPLICATION_CNT=2

# large cluster collaboration service instance memory limit, recommended at least 8GB, default 8GB
LARGE_TIER_COLLABORATION_SERVER_MEMORY_LIMIT=8192
```

#### Configuración de red

Si los puertos expuestos predeterminados de Univer entran en conflicto con otros servicios, puede modificarlos según sea necesario:

```properties title=".env.custom"
# If it conflicts with existing network configuration, you can modify the CIDR used by docker
DOCKER_NETWORK_SUBNET=172.30.0.0/16

# Univer API service exposed port; if it conflicts with other host services, change to another port
HOST_NGINX_PORT=the-univer-server-api-port-you-wantted

# If you choose Univer's built-in MinIO as object storage and there is a port conflict, add this configuration item
# If you are using self-maintained object storage, setting this configuration item has no effect
HOST_MINIO_PORT=the-minio-port-you-wantted

# If you choose Univer's built-in observability components and there is a port conflict, add this configuration item
# If you are using self-maintained observability components, setting this configuration item has no effect
HOST_GRAFANA_PORT=the-grafana-port-you-wantted
```

#### Ejemplo de configuración

El siguiente ejemplo de configuración logra:

- Habilitar la integración USIP, autenticar la identidad del usuario, habilitar la validación de permisos
- Configurar que solo el propietario del documento puede copiar contenido y imprimir
- Habilitar la publicación de eventos de Univer
- Usar PostgreSQL automantenido
- Usar Object Storage automantenido
- Modificar el puerto expuesto del servicio Univer
- Establecer la configuración de capacidad del servidor de colaboración y Universer

Contenido del archivo `.env.custom`:

```properties title=".env.custom"
# 1. enable USIP integration
# usip about
USIP_ENABLED=true
USIP_URI_CREDENTIAL=https://usip-demo.univer.ai/usip/credential
USIP_URI_USERINFO=https://usip-demo.univer.ai/usip/userinfo
USIP_URI_ROLE=https://usip-demo.univer.ai/usip/role
USIP_URI_COLLABORATORS=https://usip-demo.univer.ai/usip/collaborators
USIP_URI_UNITEDITTIME=https://usip-demo.univer.ai/usip/unit-edit-time

# 2. only owner can copy content and print
AUTH_PERMISSION_CUSTOMER_STRATEGIES=[ {"action": 3, "role": 2}, {"action": 6, "role": 2} ]

# 3. enable univer event sync
EVENT_SYNC=true # Set to true to enable

# 4. use owner RDS
# postgresql config
DISABLE_UNIVER_RDS=true # When using your own RDS, disable Univer's default PostgreSQL

DATABASE_DRIVER=postgresql # Set to postgresql for PostgreSQL-compatible databases
DATABASE_HOST=univer-postgresql
DATABASE_PORT=5432
DATABASE_DBNAME=univer
DATABASE_USERNAME=universer-biz
DATABASE_PASSWORD=123456

# 5. use owner Object storage
# s3 config
DISABLE_UNIVER_S3=true # When using your own object storage, disable Univer's built-in MinIO

S3_USER=universer-biz
S3_PASSWORD=123456
S3_REGION=cn-sz
S3_PATH_STYLE=true
S3_ENDPOINT=univer-s3:9652
S3_ENDPOINT_PUBLIC=univer.ai:9653
S3_DEFAULT_BUCKET=univer

# 7. set the service scale
```

## SOP de implementación

Después de determinar la configuración requerida, puede implementar los servicios back-end de Univer de acuerdo siga los siguientes pasos.

### SOP de implementación de Docker Compose

1. Prepare el archivo de configuración `.env.custom` (omita este paso si no se necesitan modificaciones).
2. Prepare los archivos de licencia, incluidos `license.txt` y `licenseKey.txt`.
3. Si elige utilizar RDS automantenido, descargue el [script de inicialización de base de datos](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz) e inicialización completa de RDS, incluido el universal y el temporal. Si utiliza GaussDB o DamengDB, no se requiere inicialización temporal.
4. Obtenga los servicios back-end de Univer Pro:
   - Si el servidor de implementación puede acceder a Internet público:
     - Ejecute `bash -c "$(curl -fsSL https://get.univer.ai/product)" [-- version]` para descargar la versión especificada de los servicios de Univer. Si no se especifica ninguna versión, la última versión se descarga de forma predeterminada.
     - La CLI intentará abrir automáticamente su navegador para recuperar un token de autenticación de [//cli-auth](//cli-auth). Si el navegador no se abre automáticamente, visite esta URL manualmente para obtener su token y luego péguelo en la terminal cuando se le solicite.
   - Si el servidor de implementación no puede acceder a Internet público:
     - [Haga clic aquí para descargar](//releases/univer-server/download) el paquete de instalación fuera de línea todo en uno proporcionado por Univer.
     - Cargue el paquete de instalación fuera de línea en el servidor de implementación y extráigalo.
     - Ingrese al directorio extraído y ejecútelo. `bash load-images.sh` para cargar imágenes del servicio back-end de Univer en Docker local.
5. Copie el archivo `.env.custom` preparado en la carpeta del servicio Univer descargado, en el mismo directorio que el archivo `.env` predeterminado.
6. Copie los archivos de licencia `license.txt` y `licenseKey.txt` en el directorio `configs/` de la carpeta del servicio Univer descargado.
7. Ingrese al directorio raíz del servicio Univer y ejecute `bash run.sh start` para completar la implementación del servicio.
8. Completar las pruebas de regresión.
