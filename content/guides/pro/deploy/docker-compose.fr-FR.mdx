## Configuration du déploiement

### Modifier la configuration du déploiement

La configuration de déploiement par défaut d’Univer se trouve dans le fichier `.env` du répertoire d’installation. Si vous devez modifier la configuration de l’installation, ne modifiez pas directement le fichier `.env`. Créez plutôt un fichier de configuration personnalisé nommé `.env.custom` dans le même répertoire. Les éléments configurés dans `.env.custom` remplaceront les valeurs par défaut du fichier `.env`.

### Détails de la configuration

#### Activer l’authentification des identités et la gestion des autorisations

La signification des paramètres concernés est déjà expliquée dans [Intégrer Univer à votre système via USIP](/guides/pro/usip) et ne sera pas reprise ici. Pour activer cette fonctionnalité, utilisez la configuration suivante :

```properties title=".env.custom"
# usip about
USIP_ENABLED=true # Set to true to enable USIP
USIP_URI_CREDENTIAL=https://your-domain/usip/credential
USIP_URI_USERINFO=https://your-domain/usip/userinfo
USIP_URI_ROLE=https://your-domain/usip/role
USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

# apikey is optional
USIP_APIKEY=

# auth about
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
AUTH_PERMISSION_CUSTOMER_STRATEGIES=
```

#### Activer la publication des événements Univer

La signification des paramètres concernés est déjà expliquée dans [Intégrer Univer à votre système via Univer Event Sync](/guides/pro/event-sync) et ne sera pas reprise ici. Pour activer cette fonctionnalité, utilisez la configuration suivante :

```properties title=".env.custom"
EVENT_SYNC=true # Set to true to enable
```

#### Utiliser des composants d’infrastructure autogérés

##### RDS

**Remarque :** le composant Temporal utilisé par Univer ne prend pas en charge GaussDB ni DamengDB. Si vous choisissez l’une de ces bases de données, Univer installera donc séparément PostgreSQL pour Temporal. Temporal stocke dans la base de données l’état des workflows des tâches d’importation et d’exportation, sans traiter aucune donnée de document. Même en cas de perte de ces données, seules les tâches d’importation ou d’exportation inachevées échoueront, sans autre incidence.

###### Utiliser un RDS compatible avec PostgreSQL

```properties title=".env.custom"
# RDS config
DISABLE_UNIVER_RDS=true # When using your own RDS, disable Univer's default PostgreSQL

DATABASE_DRIVER=postgresql # Set to postgresql for PostgreSQL-compatible databases
DATABASE_HOST=your-database-host
DATABASE_PORT=your-database-port
DATABASE_DBNAME=univer # Univer database init scripts use this name by default; keep it consistent if changed
DATABASE_USERNAME=user-name # Grant select, insert, update, delete permissions
DATABASE_PASSWORD=password
```

##### MQ

```properties title=".env.custom"
DISABLE_UNIVER_MQ=true # When using your own MQ, disable Univer's built-in MQ

RABBITMQ_CLUSTER_ENABLED=true # Must be set to true
RABBITMQ_CLUSTER_USERNAME=user-name # Needs Declare Exchange, Produce, Consume permissions
RABBITMQ_CLUSTER_PASSWORD=password # password

# use comma to separate multiple addresses
# for example: RABBITMQ_CLUSTER_ADDR=192.168.1.2:5672,192.168.1.5:5672,192.168.1.7:5672
# Every addr must be readable and writable; Univer will poll the hosts until a connection succeeds
RABBITMQ_CLUSTER_ADDR=host:port[,host:port]

# RABBITMQ_CLUSTER_VHOST is the vhost of the rabbitmq cluster. If you don't set it, the default value is /
# for example: RABBITMQ_CLUSTER_VHOST=univer
RABBITMQ_CLUSTER_VHOST=/
RABBITMQ_CLUSTER_SCHEMA=amqp
```

##### Stockage d’objets

```properties title=".env.custom"
DISABLE_UNIVER_S3=true # When using your own object storage, disable Univer's built-in MinIO

# s3 config

S3_PASSWORD=password
S3_REGION=your-inner-s3like-region # If the S3-like service has no such concept, fill in any string

# S3_PATH_STYLE, can be set to true or false
# If set to true, use Path-Style to construct access URLs
# If set to false, use Virtual-Host Style to construct access URLs
S3_PATH_STYLE=true|false

# S3_ENDPOINT address provided for internal service access
S3_ENDPOINT=inner-visit-host:port

# S3_ENDPOINT_PUBLIC publicly accessible address, used when the client directly connects to object storage to download files
S3_ENDPOINT_PUBLIC=public-visit-host:port

# S3_DEFAULT_BUCKET configures which bucket to use
S3_DEFAULT_BUCKET=default-bucket-name
```

#### Configuration de la capacité

```properties title=".env.custom"
UNIVERSER_REPLICATION_CNT=2 # universer instance count
COLLABORATION_SERVER_REPLICATION_CNT=2 # collaboration service instance count
COLLABORATION_SERVER_MEMORY_LIMIT=2048 # collaboration service max memory limit, in MB
COLLABORATION_HELPER_REPLICATION_CNT=2 # helper service instance count, note: introduced since v0.13.0
COLLABORATION_HELPER_MEMORY_LIMIT=2048 # helper max memory limit, in MB, note: introduced since v0.13.0

# import/export exchange-worker capacity-related config
EXCHANGE_WORKER_REPLICATION_CNT=1 # working exchange worker count
EXCHANGE_WORKER_MEMORY_LIMIT=4096 # MB, the memory limit of each exchange-worker.
EXCHANGE_WORKER_IMPORT_CONCURRENT=1 # how many import tasks each worker can do at the same time.
EXCHANGE_WORKER_EXPORT_CONCURRENT=1 # how many export tasks each worker can do at the same time.
```

#### Configuration de la planification par niveau pour l’édition collaborative

Introduite dans la version `v0.15.0`, cette fonctionnalité est désactivée par défaut et doit être configurée manuellement. Le système choisit le niveau du cluster de services de collaboration auquel affecter un classeur en fonction du nombre total de cellules et de la durée réelle de l’importation. Les classeurs nouvellement importés sont affectés selon la durée de l’importation. Pour les classeurs créés autrement ou après la génération d’un nouvel instantané, l’affectation repose sur le nombre total de cellules. Après chaque création d’instantané, les métriques correspondantes sont enregistrées dans la base de données et la stratégie de planification est mise à jour.

La planification par niveau consiste à déployer le service de collaboration sous forme de plusieurs clusters et à définir, au moyen de règles, le cluster chargé des feuilles de calcul de chaque taille. La structure des données de configuration de ces règles est la suivante :

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

Description :

- `tiers` : décrit les informations de chaque cluster. En théorie, le nombre de clusters configurables n’est pas limité.
- `enable` : indique si ce cluster est activé. Si la valeur est `false`, le cluster est ignoré.
- `upgradeCellsThreshold` : indique le nombre total de cellules que la feuille doit atteindre pour être affectée à ce cluster.
- `downgradeCellsThreshold` : si la feuille est actuellement affectée à ce cluster, elle ne peut être rétrogradée vers un cluster de niveau inférieur que lorsque son nombre total de cellules passe sous cette valeur. Cela évite les changements fréquents pour les feuilles dont la taille est proche de la limite entre deux niveaux.
- `upgradeImportTimeThreshold` : pour les feuilles nouvellement importées dont le nombre total de cellules n’est pas encore connu, ce paramètre sert à la planification. Son fonctionnement est identique à celui de `upgradeCellsThreshold`, mais la métrique utilisée est la durée réelle de l’importation.

Vous devez vous assurer qu’au moins un cluster a toutes ses exigences de métriques définies sur 0, afin que chaque feuille puisse être affectée à un cluster.

Exemples de planification avec la configuration ci-dessus :

- Après sa création, workbook1 contient initialement 0 cellule et est affecté au cluster normal.
- Lorsque workbook1 est modifié et que son nombre total de cellules atteint 1 000, il est affecté au cluster large.
- Lorsque le nombre total de cellules de workbook1 redescend à 999, il reste affecté au cluster large, car ce nombre est toujours supérieur au seuil de rétrogradation de 900.
- Lorsque le nombre total de cellules de workbook1 redescend ensuite à 899, il est rétrogradé vers le cluster normal.
- L’importation de workbook2 dure 61 secondes, ce qui dépasse le seuil de 60 secondes du cluster huge. Il est donc affecté au cluster huge.

Le script de déploiement Docker Compose d’Univer permet de déployer un ou deux niveaux afin de séparer les feuilles de calcul normales des feuilles volumineuses. Le paramètre `ENABLE_LARGE_TIER_COLLABORATION_SERVER` de la configuration du cluster détermine si le cluster réservé aux feuilles volumineuses est utilisé pour la planification et si Docker Compose déploie réellement les services de ce cluster. Si vous avez besoin de niveaux plus précis ou d’un déploiement K8s, adaptez l’orchestration docker compose / charts pour déployer effectivement les clusters de services `collaboration-server` du niveau correspondant, puis configurez la table de routage de la planification, c’est-à-dire le tableau `tiers`, comme indiqué ci-dessus.

Par défaut, seuls deux niveaux sont configurés : `normal` et `large`.

```properties title=".env.custom"
# Configure to enable/disable large cluster, true-enable, false-disable, default disabled
ENABLE_LARGE_TIER_COLLABORATION_SERVER=false

# If large cluster is enabled, sheets will be scheduled to the large cluster when total cell count reaches this scale, default 2M
LARGE_TIER_MIN_CELLS_COUNT=2000000

# If the sheet is currently scheduled to the large cluster, it will only be downgraded back to the normal cluster when total cell count falls below this value, default 1.95M
LARGE_TIER_DOWNGRADE_CELLS_COUNT=1950000

# If large cluster is enabled, workbooks will be scheduled to the large cluster when import time exceeds this value, default 10s
LARGE_TIER_MIN_IMPORT_SECONDS=10

# large cluster collaboration service instance count, default 2
LARGE_TIER_COLLABORATION_SERVER_REPLICATION_CNT=2

# large cluster collaboration service instance memory limit, recommended at least 8GB, default 8GB
LARGE_TIER_COLLABORATION_SERVER_MEMORY_LIMIT=8192
```

#### Configuration réseau

Si les ports exposés par défaut par Univer entrent en conflit avec d’autres services, vous pouvez les modifier selon vos besoins :

```properties title=".env.custom"
# If it conflicts with existing network configuration, you can modify the CIDR used by docker
DOCKER_NETWORK_SUBNET=172.30.0.0/16

# Univer API service exposed port; if it conflicts with other host services, change to another port
HOST_NGINX_PORT=the-univer-server-api-port-you-wantted

# If you choose Univer's built-in MinIO as object storage and there is a port conflict, add this configuration item
# If you are using self-maintained object storage, setting this configuration item has no effect
HOST_MINIO_PORT=the-minio-port-you-wantted

# If you choose Univer's built-in observability components and there is a port conflict, add this configuration item
# If you are using self-maintained observability components, setting this configuration item has no effect
HOST_GRAFANA_PORT=the-grafana-port-you-wantted
```

#### Exemple de configuration

L’exemple de configuration suivant permet de :

- Activer l’intégration USIP, authentifier l’identité des utilisateurs et activer la validation des autorisations
- Autoriser uniquement le propriétaire du document à copier le contenu et à l’imprimer
- Activer la publication des événements Univer
- Utiliser une instance PostgreSQL autogérée
- Utiliser un stockage d’objets autogéré
- Modifier le port exposé du service Univer
- Configurer la capacité d’universer et de collaboration-server

Contenu du fichier `.env.custom` :

```properties title=".env.custom"
# 1. enable USIP integration
# usip about
USIP_ENABLED=true
USIP_URI_CREDENTIAL=https://usip-demo.univer.ai/usip/credential
USIP_URI_USERINFO=https://usip-demo.univer.ai/usip/userinfo
USIP_URI_ROLE=https://usip-demo.univer.ai/usip/role
USIP_URI_COLLABORATORS=https://usip-demo.univer.ai/usip/collaborators
USIP_URI_UNITEDITTIME=https://usip-demo.univer.ai/usip/unit-edit-time

# 2. only owner can copy content and print
AUTH_PERMISSION_CUSTOMER_STRATEGIES=[ {"action": 3, "role": 2}, {"action": 6, "role": 2} ]

# 3. enable univer event sync
EVENT_SYNC=true # Set to true to enable

# 4. use owner RDS
# postgresql config
DISABLE_UNIVER_RDS=true # When using your own RDS, disable Univer's default PostgreSQL

DATABASE_DRIVER=postgresql # Set to postgresql for PostgreSQL-compatible databases
DATABASE_HOST=univer-postgresql
DATABASE_PORT=5432
DATABASE_DBNAME=univer
DATABASE_USERNAME=universer-biz
DATABASE_PASSWORD=123456

# 5. use owner Object storage
# s3 config
DISABLE_UNIVER_S3=true # When using your own object storage, disable Univer's built-in MinIO

S3_USER=universer-biz
S3_PASSWORD=123456
S3_REGION=cn-sz
S3_PATH_STYLE=true
S3_ENDPOINT=univer-s3:9652
S3_ENDPOINT_PUBLIC=univer.ai:9653
S3_DEFAULT_BUCKET=univer

# 6. change univer service Port
HOST_NGINX_PORT=8010

# 7. set the service scale
UNIVERSER_REPLICATION_CNT=4 # universer instance count
COLLABORATION_SERVER_REPLICATION_CNT=5 # collaboration service instance count
MAX_MEMORY_LIMIT=2048 # collaboration service max memory limit, in MB
```

## Procédure de déploiement

Une fois la configuration nécessaire déterminée, déployez les services back-end d’Univer en suivant les étapes ci-dessous.

### Procédure de déploiement avec Docker Compose

1. Préparez le fichier de configuration `.env.custom` (ignorez cette étape si aucune modification n’est nécessaire).
2. Préparez les fichiers de licence, notamment `license.txt` et `licenseKey.txt`.
3. Si vous choisissez d’utiliser un RDS autogéré, téléchargez le [script d’initialisation de la base de données](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz) et procédez à l’initialisation du RDS, notamment pour universer et temporal. Si vous utilisez GaussDB ou DamengDB, l’initialisation de temporal n’est pas nécessaire.
4. Obtenez les services back-end d’Univer Pro :
   - Si le serveur de déploiement peut accéder à Internet :
     - Exécutez `bash -c "$(curl -fsSL https://get.univer.ai/product)" [-- version]` pour télécharger la version indiquée des services Univer. Si aucune version n’est spécifiée, la dernière version est téléchargée par défaut.
     - La CLI tentera d’ouvrir automatiquement votre navigateur afin de récupérer un jeton d’authentification depuis [//cli-auth](//cli-auth). Si le navigateur ne s’ouvre pas automatiquement, accédez manuellement à cette URL pour obtenir votre jeton, puis collez-le dans le terminal lorsque vous y êtes invité.
   - Si le serveur de déploiement ne peut pas accéder à Internet :
     - [Cliquez ici pour télécharger](//releases/univer-server/download) le package d’installation hors ligne tout-en-un fourni par Univer.
     - Téléversez le package d’installation hors ligne sur le serveur de déploiement et extrayez-le.
     - Accédez au répertoire extrait et exécutez `bash load-images.sh` pour charger les images des services back-end d’Univer dans l’instance Docker locale.
5. Copiez le fichier `.env.custom` préparé dans le dossier des services Univer téléchargés, dans le même répertoire que le fichier `.env` par défaut.
6. Copiez les fichiers de licence `license.txt` et `licenseKey.txt` dans le répertoire `configs/` du dossier des services Univer téléchargés.
7. Accédez au répertoire racine des services Univer et exécutez `bash run.sh start` pour terminer le déploiement des services.
8. Effectuez les tests de non-régression.
