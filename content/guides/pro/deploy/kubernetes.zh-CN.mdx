## 部署配置

### 如何修改部署配置

Univer 的默认部署配置位于 Helm chart 的 `values.yaml` 中，[点击查看](https://github.com/dream-num/helm-charts/blob/main/charts/univer-stack/values.yaml)。如需修改配置，无需编辑 charts 中的文件，只需新建一个 `values.yaml` 文件，将需要修改的配置项写入其中即可。通过 `helm install` 命令安装时指定该 `values.yaml` 文件，即可用自定义配置覆盖默认配置。未指定的配置项将使用默认值。具体的 Helm 命令说明见后文部署步骤。

### 配置详解

#### 启用身份认证和权限管理

相关配置项的意义已在[通过 USIP 与你的系统集成](/guides/pro/usip)中说明，此处不再赘述。如需启用，可参考如下配置：

```yaml title="values.yaml"
universer:
  config:
    usip:
      enabled: true # 设置为 true 以启用 USIP
      uri:
        userinfo: 'https://your-domain/usip/userinfo'
        collaborators: 'https://your-domain/usip/collaborators'
        role: 'https://your-domain/usip/role'
        credential: 'https://your-domain/usip/credential'
        unitEditTime: 'https://your-domain/usip/unit-edit-time'

      # apikey 是可选的
      apikey: ''
    auth:
      permission:
        enableObjInherit: false
        customerStrategies: ''
```

#### 开启 Univer 事件发布

相关配置项的意义已在[通过 Univer 事件同步机制与你的系统集成](/guides/pro/event-sync)中说明，此处不再赘述。如需启用，可参考如下配置：

```yaml title="values.yaml"
universer:

    rabbitmq:
      eventSync: true # 设置为 true 以开启
```

#### 使用自己维护的基础组件

##### RDS

**请注意**，由于 Univer 使用的组件 Temporal 不支持 GaussDB 和 DamengDB，若选择这两种数据库，Univer 将为 Temporal 单独安装 PostgreSQL。Temporal 在数据库中存储的是导入导出任务的流程状态，不涉及任何文档数据。即使丢失，也仅会导致未完成的导入导出任务失败，不会产生其他影响。

###### 使用兼容 PostgreSQL 的 RDS

```yaml title="values.yaml"
postgresql:
  enabled: false # 禁用 Univer 自带的数据库

universer:
  config:
    database:
      driver: postgresql # 设置为 postgresql 代表使用兼容 postgresql 的数据库
      host: your-database-host
      port: your-database-port
      dbname: univer # Univer 数据库初始化脚本默认使用该名称，若已更改，请保持此处一致
      username: postgres # 需授予该用户 select、insert、update、delete 权限
      password: postgres

temporal: # temporal 用到了数据库
  server:
    config:
      persistence:
        default:
          driver: sql # 固定设置为 sql
          sql:
            driver: postgres12 # postgres 需要 12 以上的版本
            host: your-database-host
            port: your-database-port
            database: temporal # Univer 数据库初始化脚本默认使用该名称，若已更改，请保持此处一致
            user: postgres # 需授予该用户 select、insert、update、delete 权限
            password: postgres

        visibility:
          driver: sql
          sql:
            driver: postgres12 # postgres 需要 12 以上的版本
            host: your-database-host
            port: your-database-port
            database: temporal_visibility # Univer 数据库初始化脚本默认使用该名称，若已更改，请保持此处一致
            user: postgres # 需授予该用户 select、insert、update、delete 权限
            password: postgres
```

```yaml title="values.yaml"
  config:
```

```yaml title="values.yaml"
      poolSize: 100
      # 如果是 redis 集群，可以用逗号分隔多个地址
      # 例如：192.168.1.100:6379,192.168.1.101:6379

      write_timeout: 1s
      db: 0
      username: user_name_here
      password: password_here

      # TLS 配置
      # 支持三种模式：不安全模式（insecure）、仅进行 CA 验证、以及客户端证书（mTLS）验证。

        enabled: false
        insecure: false

        cert: ''
        key: ''

# 跟 universer.config.redis 一样
worker:
  redis:
    poolSize: 10
    addr: 192.168.1.100:6379
    read_timeout: 1s
    write_timeout: 1s
    db: 0
    username: user_name_here
    password: password_here

      enabled: false

  enabled: false # 禁用 Univer 自带的 Redis
```

##### MQ

```yaml title="values.yaml"
universer:
  config:
    rabbitmq:
      cluster:
        enabled: true # 必须设置为 true

        # for example: RABBITMQ_CLUSTER_ADDR=192.168.1.2:5672,192.168.1.5:5672

        password: password-here
        vhost: /
        schema: amqp

  enabled: false # 禁用 Univer 自带的 RabbitMQ
```

#### 协同编辑分层调度配置

自 `v0.15.0` 起引入，默认未启用，需手动配置开启。系统根据 workbook 的单元格总数及导入实际耗时决定调度到哪个等级的协同服务集群。对于刚通过导入创建的 workbook，依据导入耗时进行调度；对于其他方式创建或触发新快照生成后的 workbook，则依据单元格总数进行调度。每次快照创建后，相关指标数据将持久化到数据库并更新调度策略。

分层调度的本质是将协同服务部署为多个集群，并通过规则指定不同规模的表格由哪个集群处理。规则配置的数据结构如下：

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

说明：

- `tiers`：描述各集群信息，理论上可配置任意多个集群。
- `enable`：设置是否启用该集群，设置为 `false` 则该集群将被忽略。
- `upgradeCellsThreshold`：指定 sheet 单元格总数达到此规模时才能调度到该集群。
- `downgradeCellsThreshold`：若 sheet 当前正被调度到该集群，仅当单元格总数低于此值时才能降级到更低等级的集群。此设置可避免在等级边界处规模的 sheet 被频繁切换调度。
- `upgradeImportTimeThreshold`：新导入的 sheet 尚无单元格总数统计，此时利用该配置决定调度，作用机制同 `upgradeCellsThreshold`，仅指标换为导入实际耗时。

必须保证至少有一个集群的指标要求全部为 0，才能确保每个 sheet 都能被调度到。

按上述示例配置参数下的调度示例：

- workbook1 创建后的初始单元格数量为 0，调度到 normal 集群。
- workbook1 编辑后总单元格数量达到 1000 时，调度到 large 集群。
- workbook1 总单元格数量降至 999 时，由于仍大于降级线 900，继续调度到 large 集群。
- workbook1 总单元格数量继续降至 899 时，降级调度回 normal 集群。
- workbook2 被导入，实际耗时 61 秒，已超过 huge 集群的条件 60 秒，将调度到 huge 集群处理。

若需更精细的集群等级控制，请调整 charts 的编排以实际部署对应等级的 `collaboration-server` 服务集群，然后按上述说明配置调度路由表（`tiers` 数组）。

K8s 下请自行在 Helm values 中配置 `unitRoutingConf`。

#### 使用 K8s 部署的特殊配置

Univer Pro 在 Helm chart 中默认配置了部署前端 demo 服务，并将 http 网关服务 universer 的 ingress 路由域名设置成了 demo 的域名。在生产部署时，需禁用 demo 服务，并将 universer 的 ingress 路由更改为实际域名。需在 `values.yaml` 中添加以下配置：

```yaml title="values.yaml"
collaboration-demo:
  enabled: false # 设置为 false 则禁止部署 demo 服务
universer:
  ingress:
    enabled: true
    hosts:
      - host: use-your-own-domain-here # 修改为你的实际域名
        paths:
          - path: /universer-api/
            pathType: Prefix
```

## 部署 SOP

确定所需配置后，可按照以下步骤实施 Univer 后端服务的部署。

### K8s 部署 SOP

使用 K8s 部署时请注意：若有自定义配置修改，需自行管理自定义配置文件 `values.yaml` 的版本，因为后续升级操作仍需要提供完整的自定义配置。建议使用 Git 等版本管理工具进行管理。

1. 准备好配置文件 `values.yaml`（如无修改需求，可跳过此步）。
2. 准备好 License 文件 `license.txt` 和 `licenseKey.txt`。
3. 若选择使用自己维护的 RDS，请下载[数据库初始化脚本](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz)并完成 RDS 的初始化，包括 universer 和 temporal 的初始化。若使用的是 GaussDB 或 DamengDB，则无需初始化 temporal。
4. 执行 Helm 安装命令，使用你的 `values.yaml` 文件和 License 文件：
   - 若部署服务器可访问公共互联网：
     ```shell
     helm install -n univer --create-namespace \
         -f your-own-values.yaml-path \
         --set global.istioNamespace="univer" \
         --set-file universer.license.licenseV2=your-license.txt-path \
         --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
         univer-stack \
         oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
         --version target-version

     # 执行成功后，运行以下两个命令重启服务以完成 sidecar 注入
     kubectl rollout restart -n univer deployment/collaboration-server
     kubectl rollout restart -n univer deployment/universer
     ```
     若需部署 Univer 配置的可观测组件，请执行以下命令安装：
     ```bash
     helm upgrade --install -n univer-observability --create-namespace \
         --set global.univerNamespace="univer" \
         univer-observability \
         oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-observability
     ```

     参数说明：
     - `--set global.univerNamespace="univer"`：配置所观测的 Univer 集群的 namespace 为 `"univer"`。
   - 若部署服务器无法访问公共互联网：
     - [点此下载](https://univer.ai/releases/univer-server/download) Univer 提供的 K8s all in one 离线安装包。
     - 将离线安装包上传至部署服务器并解压。
     - 进入解压后的目录执行：
       ```shell
       export REGISTER=XXXX # 你的私有镜像仓库
       export NAMESPACE=XXX # 要上传的镜像 namespace
       docker login $REGISTER
       bash load-image.sh --registry $REGISTER --namespace $NAMESPACE
       ```
     - 执行成功后会在当前目录生成 `values.yaml` 和 `values-observability.yaml` 文件，可按需修改配置：
       - `values.yaml`：Univer 服务的配置文件
       - `values-observability.yaml`：Univer 服务相关可观测性监控组件的配置文件
     - 接着执行以下命令进行安装：
       ```shell
       helm install -n univer --create-namespace \
           -f your-own-values.yaml-path \
           --set global.istioNamespace="univer" \
           --set-file universer.license.licenseV2=your-license.txt-path \
           --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
           univer-stack \
           univer-stack-xxxx.tgz # 需改为当前目录解压后对应的 chart 包

       # 执行成功后，运行以下两个命令重启服务以完成 sidecar 注入
       kubectl rollout restart -n univer deployment/collaboration-server
       kubectl rollout restart -n univer deployment/universer
       ```
     - 若需部署 Univer 配置的可观测组件，请执行以下命令安装：
       ```bash
       helm upgrade --install -n univer-observability --create-namespace \
           --set global.univerNamespace="univer" \
           -f your-own-values-observability.yaml-path \
           univer-observability \
           univer-observability-xxxx.tgz
       ```

       参数说明：
       - `--set global.univerNamespace="univer"`：配置所观测的 Univer 集群的 namespace 为 `"univer"`。

参数说明：

- `-n univer`：指定集群 namespace 为 `univer`，可根据需要更改，但需记住该值，后续升级时仍需使用。
- `univer-stack`：Helm release 的名称，可根据需要更改，但需记住该值，后续升级时仍需使用。
- `--version target-version`：指定部署版本，需修改为目标版本；也可去掉此项以自动选择最新版本。
- `-f your-own-values.yaml-path`：指定自定义配置文件 `values.yaml` 的路径，需确保路径正确。
- `--set-file universer.license.licenseV2=your-license.txt-path`：指定 License 解压后的 `license.txt` 文件路径。
- `--set-file universer.license.licenseKeyV2=your-licenseKey.txt-path`：指定 License 解压后的 `licenseKey.txt` 文件路径。

5. 完成回归测试。
