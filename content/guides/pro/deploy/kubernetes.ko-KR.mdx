## 배포 구성

### 배포 구성을 수정하는 방법

Univer의 기본 배포 구성은 Helm chart의 `values.yaml`에 있습니다. [여기에서 확인할 수 있습니다](https://github.com/dream-num/helm-charts/blob/main/charts/univer-stack/values.yaml). 구성을 변경해야 하더라도 chart 내부의 파일을 직접 수정할 필요는 없습니다. 새 `values.yaml` 파일을 만들고 변경할 구성 항목만 작성하면 됩니다. `helm install` 명령으로 설치할 때 이 `values.yaml` 파일을 지정하면 사용자 지정 구성이 기본 구성을 덮어씁니다. 지정하지 않은 구성 항목에는 기본값이 적용됩니다. Helm 명령의 자세한 사용 방법은 아래 배포 절차를 참고하세요.

### 구성 상세

#### ID 인증 및 권한 관리 활성화

관련 구성 항목의 의미는 [USIP를 통해 시스템과 통합하기](/guides/pro/usip)에서 이미 설명했으므로 여기서는 반복하지 않습니다. 활성화하려면 다음 구성을 참고하세요.

```yaml title="values.yaml"
universer:
  config:
    usip:
      enabled: true # Set to true to enable USIP
      uri:
        userinfo: 'https://your-domain/usip/userinfo'
        collaborators: 'https://your-domain/usip/collaborators'
        role: 'https://your-domain/usip/role'
        credential: 'https://your-domain/usip/credential'
        unitEditTime: 'https://your-domain/usip/unit-edit-time'

      # apikey is optional
      apikey: ''
    auth:
      permission:
        enableObjInherit: false
        customerStrategies: ''
```

#### Univer 이벤트 발행 활성화

관련 구성 항목의 의미는 [Univer Event Sync를 통해 시스템과 통합하기](/guides/pro/event-sync)에서 이미 설명했으므로 여기서는 반복하지 않습니다. 활성화하려면 다음 구성을 참고하세요.

```yaml title="values.yaml"
universer:
  config:
    rabbitmq:
      eventSync: true # Set to true to enable
```

#### 직접 관리하는 인프라 구성 요소 사용

##### RDS

**유의하세요.** Univer에서 사용하는 Temporal 구성 요소는 GaussDB와 DamengDB를 지원하지 않습니다. 따라서 두 데이터베이스 중 하나를 선택하면 Univer가 Temporal용 PostgreSQL을 별도로 설치합니다. Temporal은 데이터베이스에 가져오기 및 내보내기 작업의 워크플로 상태만 저장하며 문서 데이터는 저장하지 않습니다. 이 데이터가 손실되더라도 완료되지 않은 가져오기 및 내보내기 작업이 실패할 뿐, 다른 영향은 없습니다.

###### PostgreSQL 호환 RDS 사용

```yaml title="values.yaml"
postgresql:
  enabled: false # Disable Univer's built-in database

universer:
  config:
    database:
      driver: postgresql # Set to postgresql for PostgreSQL-compatible databases
      host: your-database-host
      port: your-database-port
      dbname: univer # Univer database init scripts use this name by default; keep it consistent if changed
      username: postgres # Grant select, insert, update, delete permissions
      password: postgres
      sslMode: disable # Supported values: disable, require, verify-ca, verify-full; set to require / verify-ca / verify-full to enable SSL

temporal: # temporal uses the database
  server:
    config:
      persistence:
        default:
          driver: sql # Fixed to sql
          sql:
            driver: postgres12 # postgres 12 or above required
            host: your-database-host
            port: your-database-port
            database: temporal # Univer database init scripts use this name by default; keep it consistent if changed
            user: postgres # Grant select, insert, update, delete permissions
            password: postgres

        visibility:
          driver: sql
          sql:
            driver: postgres12 # postgres 12 or above required
            host: your-database-host
            port: your-database-port
            database: temporal_visibility # Univer database init scripts use this name by default; keep it consistent if changed
            user: postgres # Grant select, insert, update, delete permissions
            password: postgres
```

###### MySQL 호환 RDS 사용

```yaml title="values.yaml"
postgresql:
  enabled: false # Disable Univer's built-in database

universer:
  config:
    database:
      driver: mysql # Set to mysql for MySQL-compatible databases
      host: your-database-host
      port: your-database-port
      dbname: univer # Univer database init scripts use this name by default; keep it consistent if changed
      username: mysql # Grant select, insert, update, delete permissions
      password: mysql
      sslMode: disable # Supported values: disable, require, verify-ca, verify-full; set to require / verify-ca / verify-full to enable SSL

temporal:
  server:
    config:
      persistence:
        default:
          driver: sql
          sql:
            driver: mysql8 # MySQL 8.x required
            host: your-database-host
            port: your-database-port
            database: temporal # Univer database init scripts use this name by default; keep it consistent if changed
            user: mysql # Grant select, insert, update, delete permissions
            password: mysql

        visibility:
          driver: sql
          sql:
            driver: mysql8
            host: your-database-host
            port: your-database-port
            database: temporal_visibility # Univer database init scripts use this name by default; keep it consistent if changed
            user: mysql
            password: mysql
```

참고: `sslMode`는 MySQL에도 적용됩니다. `require`, `verify-ca`, `verify-full`은 `tls=true`로 매핑되며, 그 밖의 값은 MySQL DSN에 `tls=<your-value>` 형식으로 그대로 전달됩니다.

##### Redis

```yaml title="values.yaml"
universer:
  config:
    redis:
      poolSize: 100
      # If using a redis cluster, separate multiple addresses with commas
      # e.g.: 192.168.1.100:6379,192.168.1.101:6379
      addr: 192.168.1.100:6379
      read_timeout: 1s
      write_timeout: 1s
      db: 0
      username: user_name_here
      password: password_here

      # TLS config
      # Supports three modes: insecure, CA verification only, and client certificate (mTLS) verification.
      # CA, certificate, and private key should be filled with file content when needed
      tlsConfig:
        enabled: false
        insecure: false
        ca: ''
        cert: ''
        key: ''

# Same as universer.config.redis
worker:
  redis:
    poolSize: 10
    addr: 192.168.1.100:6379
    read_timeout: 1s
    write_timeout: 1s
    db: 0
    username: user_name_here
    password: password_here
    tlsConfig:
      enabled: false
      insecure: false
      ca: ''
      cert: ''
      key: ''

redis:
  enabled: false # Disable Univer's built-in Redis
```

##### MQ

```yaml title="values.yaml"
universer:
  config:
    rabbitmq:
      cluster:
        enabled: true # Must be set to true
        # use comma to separate multiple addresses
        # for example: RABBITMQ_CLUSTER_ADDR=192.168.1.2:5672,192.168.1.5:5672
        # Every addr must be readable and writable; Univer will poll the hosts until a connection succeeds
        addr: '192.168.1.2:5672,192.168.1.5:5672'
        username: user-here
        password: password-here
        vhost: /
        schema: amqp

rabbitmq:
  enabled: false # Disable Univer's built-in RabbitMQ
```

K8s에서 기본 제공 관측성 구성 요소를 배포할 때는 별도 구성이 필요하지 않습니다. 활성화 방법은 아래의 K8s 배포 절차를 참고하세요.

#### 용량 관련 구성

```yaml title="values.yaml"
universer:
  replicaCount: 3 # universer instance count
collaboration-server:
  replicaCount: 3 # collaboration service instance count
  maxMemoryLimit: 2048 # MB, collaboration service max memory limit
collaboration-helper-server: # Note: introduced since v0.13.0
  replicaCount: 2 # helper service instance count
worker:
  replicaCount: 1 # working exchange worker count
  temporalWorker:
    importConcurrent: 1 # how many import tasks each worker can do at the same time.
    exportConcurrent: 1 # how many export tasks each worker can do at the same time.
```

#### 계층형 공동 편집 스케줄링 구성

`v0.15.0`부터 도입된 기능으로 기본적으로 비활성화되어 있으며, 사용하려면 직접 구성해야 합니다. 시스템은 통합 문서의 전체 셀 수와 실제 가져오기 소요 시간을 기준으로 공동 편집 서비스 클러스터의 어느 계층에 할당할지 결정합니다. 새로 가져온 통합 문서는 가져오기 시간을 기준으로 할당합니다. 다른 방식으로 만든 통합 문서나 새 스냅샷이 생성된 통합 문서는 전체 셀 수를 기준으로 할당합니다. 스냅샷이 생성될 때마다 관련 지표 데이터가 데이터베이스에 영구 저장되고 스케줄링 정책이 업데이트됩니다.

계층형 스케줄링의 핵심은 공동 편집 서비스를 여러 클러스터로 배포하고, 규모가 서로 다른 스프레드시트를 어느 클러스터에서 처리할지 규칙으로 지정하는 것입니다. 규칙 구성의 데이터 구조는 다음과 같습니다.

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

각 항목의 의미는 다음과 같습니다.

- `tiers`: 각 클러스터의 정보를 설명합니다. 이론적으로는 클러스터를 원하는 수만큼 구성할 수 있습니다.
- `enable`: 해당 클러스터의 활성화 여부를 설정합니다. `false`로 설정하면 해당 클러스터를 무시합니다.
- `upgradeCellsThreshold`: 이 클러스터에 할당되기 위해 필요한 시트의 전체 셀 수를 지정합니다.
- `downgradeCellsThreshold`: 시트가 현재 이 클러스터에 할당되어 있다면, 전체 셀 수가 이 값보다 작아져야만 하위 계층 클러스터로 내려갈 수 있습니다. 계층 경계에 가까운 규모의 시트가 클러스터 사이를 자주 오가는 것을 방지합니다.
- `upgradeImportTimeThreshold`: 새로 가져온 시트는 아직 전체 셀 수 통계가 없으므로 이 구성을 기준으로 할당합니다. 지표가 실제 가져오기 시간이라는 점을 제외하면 `upgradeCellsThreshold`와 같은 방식으로 작동합니다.

모든 시트를 할당할 수 있도록 지표 요구 사항이 모두 0인 클러스터가 하나 이상 있어야 합니다.

위 예제 구성을 적용했을 때의 스케줄링 사례는 다음과 같습니다.

- workbook1은 생성 직후 셀 수가 0이므로 normal 클러스터에 할당됩니다.
- workbook1을 편집해 전체 셀 수가 1000에 도달하면 large 클러스터에 할당됩니다.
- workbook1의 전체 셀 수가 999로 줄어도 하향 임계값인 900보다 크므로 large 클러스터에 계속 할당됩니다.
- workbook1의 전체 셀 수가 899까지 줄어들면 normal 클러스터로 다시 내려갑니다.
- workbook2를 가져오는 데 실제로 61초가 걸려 huge 클러스터의 임계값인 60초를 초과했으므로 huge 클러스터에 할당됩니다.

클러스터 계층을 더 세밀하게 제어하려면 chart 오케스트레이션을 조정해 해당 계층의 `collaboration-server` 서비스 클러스터를 실제로 배포한 다음, 위 설명에 따라 스케줄링 라우팅 테이블(`tiers` 배열)을 구성하세요.

K8s에서는 Helm values에 `unitRoutingConf`를 직접 구성하세요.

#### K8s 배포를 위한 특수 구성

Univer SDK Pro의 Helm chart는 기본적으로 프런트엔드 데모 서비스를 구성하고 HTTP 게이트웨이 서비스(universer)의 ingress 라우팅 도메인을 데모 도메인으로 설정합니다. 프로덕션 환경에 배포할 때는 데모 서비스를 비활성화하고 universer의 ingress 라우팅을 실제 도메인으로 변경해야 합니다. `values.yaml`에 다음 구성을 추가하세요.

```yaml title="values.yaml"
collaboration-demo:
  enabled: false # Set to false to disable deploying the demo service
universer:
  ingress:
    enabled: true
    hosts:
      - host: use-your-own-domain-here # Change to your actual domain
        paths:
          - path: /universer-api/
            pathType: Prefix
```

## 배포 표준 절차

필요한 구성을 결정한 뒤 다음 단계에 따라 Univer 백엔드 서비스를 배포할 수 있습니다.

### K8s 배포 표준 절차

K8s로 배포할 때 유의하세요. 사용자 지정 구성을 변경했다면 이후 업그레이드 작업에서도 전체 사용자 지정 구성이 필요하므로 `values.yaml` 파일의 버전을 직접 관리해야 합니다. Git과 같은 버전 관리 도구를 사용하는 것이 좋습니다.

1. 구성 파일 `values.yaml`을 준비합니다. 수정할 내용이 없다면 이 단계는 건너뜁니다.
2. License 파일 `license.txt`와 `licenseKey.txt`를 준비합니다.
3. 직접 관리하는 RDS를 사용한다면 [데이터베이스 초기화 스크립트](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz)를 다운로드하고 universer와 temporal을 포함해 RDS 초기화를 완료합니다. GaussDB 또는 DamengDB를 사용한다면 temporal을 초기화할 필요가 없습니다.
4. 준비한 `values.yaml` 파일과 License 파일을 사용해 Helm 설치 명령을 실행합니다.
   - 배포 서버에서 공용 인터넷에 접속할 수 있는 경우:
     ```shell
     helm install -n univer --create-namespace \
         -f your-own-values.yaml-path \
         --set global.istioNamespace="univer" \
         --set-file universer.license.licenseV2=your-license.txt-path \
         --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
         univer-stack \
         oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
         --version target-version

     # After success, run the following two commands to restart services to complete sidecar injection
     kubectl rollout restart -n univer deployment/collaboration-server
     kubectl rollout restart -n univer deployment/universer
     ```

     매개변수 설명:
     - `--set global.univerNamespace="univer"`: 관측할 Univer 클러스터의 namespace를 `"univer"`로 설정합니다.
   - 배포 서버에서 공용 인터넷에 접속할 수 없는 경우:
     - Univer에서 제공하는 K8s 올인원 오프라인 설치 패키지를 [여기에서 다운로드](//releases/univer-server/download)합니다.

       ```shell
       export REGISTER=XXXX # Your private image registry
       export NAMESPACE=XXX # The image namespace to upload to

       bash load-image.sh --registry $REGISTER --namespace $NAMESPACE
       ```
     - 명령이 성공하면 현재 디렉터리에 `values.yaml`과 `values-observability.yaml` 파일이 생성됩니다. 필요에 따라 구성을 수정하세요.
       - `values.yaml`: Univer 서비스 구성 파일
       - `values-observability.yaml`: Univer 서비스의 관측성 모니터링 구성 요소 설정 파일

       kubectl rollout restart -n univer deployment/universer

       - `--set global.univerNamespace="univer"`: 관측할 Univer 클러스터의 namespace를 `"univer"`로 설정합니다.

매개변수 설명:

- `-n univer`: 클러스터 namespace를 `univer`로 지정합니다. 필요에 따라 변경할 수 있지만 이후 업그레이드에도 필요하므로 이 값을 기억해 두세요.
- `univer-stack`: Helm release의 이름입니다. 필요에 따라 변경할 수 있지만 이후 업그레이드에도 필요하므로 이 값을 기억해 두세요.
- `--version target-version`: 배포 버전을 지정합니다. 원하는 버전으로 변경하세요. 이 항목을 생략하면 최신 버전이 자동으로 선택됩니다.
- `-f your-own-values.yaml-path`: 사용자 지정 구성 파일 `values.yaml`의 경로를 지정합니다. 경로가 올바른지 확인하세요.
- `--set-file universer.license.licenseV2=your-license.txt-path`: 압축을 푼 `license.txt` 파일의 경로를 지정합니다.
- `--set-file universer.license.licenseKeyV2=your-licenseKey.txt-path`: 압축을 푼 `licenseKey.txt` 파일의 경로를 지정합니다.
