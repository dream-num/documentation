## Deployment-Konfiguration

### So ändern Sie die Deployment-Konfiguration

Univers Standard-Deployment-Konfiguration befindet sich in der Datei `.env` im Installationsverzeichnis. Wenn Sie die Installationskonfiguration ändern müssen, bearbeiten Sie die Datei `.env` nicht direkt. Erstellen Sie stattdessen eine benutzerdefinierte Konfigurationsdatei mit dem Namen `.env.custom` im selben Verzeichnis. In `.env.custom` konfigurierte Elemente überschreiben die Standardwerte in der Datei `.env`.

### Konfigurationsdetails

#### Identitätsauthentifizierung und Berechtigungsverwaltung aktivieren

Die Bedeutung der relevanten Konfigurationselemente wurde bereits in [Integration mit Ihrem System über USIP](/guides/pro/usip) erläutert und wird hier nicht wiederholt. Um es zu aktivieren, können Sie auf die folgende Konfiguration zurückgreifen:

```properties title=".env.custom"
# usip about
USIP_ENABLED=true # Set to true to enable USIP
USIP_URI_CREDENTIAL=https://your-domain/usip/credential
USIP_URI_USERINFO=https://your-domain/usip/userinfo
USIP_URI_ROLE=https://your-domain/usip/role
USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

# apikey is optional
USIP_APIKEY=

# auth about
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
AUTH_PERMISSION_CUSTOMER_STRATEGIES=
```

#### Univer Event Publishing aktivieren

Die Bedeutung der relevanten Konfigurationselemente wurde bereits in [Integration mit Ihrem System über Univer Event Sync](/guides/pro/event-sync) erläutert und wird hier nicht wiederholt. Um es zu aktivieren, können Sie auf die folgende Konfiguration zurückgreifen:

```properties title=".env.custom"
EVENT_SYNC=true # Set to true to enable
```

#### Selbstverwaltete Infrastrukturkomponenten verwenden

##### RDS

**Bitte beachten Sie**: Da die von Univer verwendete Temporal-Komponente GaussDB und DamengDB nicht unterstützt, installiert Univer PostgreSQL separat für Temporal, wenn Sie sich für eine dieser Datenbanken entscheiden. Temporal speichert Workflow-Status von Import-/Exportaufgaben in der Datenbank und bezieht keine Dokumentdaten mit ein. Selbst wenn es verloren geht, schlägt es nur bei unvollständigen Import-/Exportaufgaben fehl und hat keine weiteren Auswirkungen.

###### Verwenden Sie PostgreSQL-kompatibles RDS

```properties title=".env.custom"
# RDS config
DISABLE_UNIVER_RDS=true # When using your own RDS, disable Univer's default PostgreSQL

DATABASE_DRIVER=postgresql # Set to postgresql for PostgreSQL-compatible databases
DATABASE_HOST=your-database-host
DATABASE_PORT=your-database-port
DATABASE_DBNAME=univer # Univer database init scripts use this name by default; keep it consistent if changed
DATABASE_USERNAME=user-name # Grant select, insert, update, delete permissions
DATABASE_PASSWORD=password
```

#### Tiered Collaborative Editing Scheduling Configuration

Eingeführt seit `v0.15.0`, standardmäßig deaktiviert und muss manuell vorgenommen werden zur Aktivierung konfiguriert. Das System entscheidet anhand der Gesamtzellenzahl der Arbeitsmappe und der tatsächlichen Importzeit, für welche Ebene des Collaboration-Service-Clusters die Planung geplant werden soll. Bei neu importierten Arbeitsmappen basiert die Planung auf der Importzeit; Bei Arbeitsmappen, die auf andere Weise oder nach der Generierung eines neuen Snapshots erstellt wurden, basiert die Planung auf der Gesamtzellenzahl. Nach jeder Snapshot-Erstellung werden die relevanten Metrikdaten in der Datenbank gespeichert und die Planungsrichtlinie aktualisiert.

Der Kern der mehrstufigen Planung besteht darin, den Kollaborationsdienst als mehrere Cluster bereitzustellen und anhand von Regeln anzugeben, welcher Cluster Tabellenkalkulationen unterschiedlicher Größenordnung verarbeitet. Die Datenstruktur der Regelkonfiguration lautet wie folgt:

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

Beschreibung:

- `tiers`: Beschreibt Informationen zu jedem Cluster; Theoretisch können beliebig viele Cluster konfiguriert werden.
- `enable`: Legt fest, ob dieser Cluster aktiviert werden soll; Wird auf `false` gesetzt und der Cluster wird ignoriert.
- `upgradeCellsThreshold`: Gibt die Gesamtzahl der Blattzellen an, die für die Planung für diesen Cluster erforderlich ist.
- `downgradeCellsThreshold`: Wenn das Blatt derzeit für diesen Cluster geplant ist, kann es nur dann auf einen Cluster niedrigerer Ebene herabgestuft werden, wenn die Gesamtzellenzahl unter diesen Wert fällt. Dadurch wird ein häufiger Wechsel bei Blättern vermieden, deren Maßstab nahe der Ebenengrenze liegt.
- `upgradeImportTimeThreshold`: Für neu importierte Blätter ohne Statistiken zur Gesamtzellenzahl wird diese Konfiguration für die Planung verwendet. Der Mechanismus ist derselbe wie bei `upgradeCellsThreshold`, außer dass es sich bei der Metrik um die tatsächliche Importzeit handelt.

Sie müssen sicherstellen, dass in mindestens einem Cluster alle Metrikanforderungen auf 0 gesetzt sind, damit jedes Blatt geplant werden kann.

Planungsbeispiele unter der Beispielkonfiguration oben:

- Arbeitsmappe1 hat nach der Erstellung eine anfängliche Zellenanzahl von 0 und wird für den normalen Cluster geplant.
- Wenn Arbeitsmappe1 bearbeitet wird und die Wenn die Gesamtzellenzahl 1000 erreicht, wird sie für den großen Cluster geplant.
- Wenn die Gesamtzellenzahl von Arbeitsmappe1 auf 999 sinkt, weil sie immer noch über dem Downgrade-Schwellenwert von 900 liegt, bleibt sie für den großen Cluster geplant.
- Wenn die Gesamtzellenzahl von Arbeitsmappe1 weiter auf 899 sinkt, wird sie wieder auf den normalen Cluster herabgestuft.
- Arbeitsmappe2 wird mit einer tatsächlichen Zeit von 61 Sekunden importiert, was den Schwellenwert für den großen Cluster von 60 Sekunden überschreitet, sodass sie für den großen Cluster geplant wird Cluster.

Das Docker Compose-Bereitstellungsskript von Univer bietet Optionen zum Bereitstellen von 1 oder 2 Ebenen (Trennung normaler und großer Tabellenkalkulationen). Der Parameter `ENABLE_LARGE_TIER_COLLABORATION_SERVER` in der Clusterkonfiguration steuert, ob der große Tabellenkalkulationscluster für die Planung verwendet werden soll und ob Docker Compose tatsächlich die großen Tabellenkalkulationsclusterdienste bereitstellt. Wenn eine feinere Clusterebenensteuerung oder K8s-Bereitstellung erforderlich ist, passen Sie die Docker-Compose/Charts-Orchestrierung an, um tatsächlich die entsprechende Ebene der `collaboration-server`-Dienstcluster bereitzustellen, und konfigurieren Sie dann die Planungs-Routing-Tabelle (`tiers`-Array) wie oben beschrieben.

Standardmäßig sind nur zwei Ebenen konfiguriert: `normal` und `large`.

```properties title=".env.custom"
# Configure to enable/disable large cluster, true-enable, false-disable, default disabled
ENABLE_LARGE_TIER_COLLABORATION_SERVER=false

# If large cluster is enabled, sheets will be scheduled to the large cluster when total cell count reaches this scale, default 2M
LARGE_TIER_MIN_CELLS_COUNT=2000000

# If the sheet is currently scheduled to the large cluster, it will only be downgraded back to the normal cluster when total cell count falls below this value, default 1.95M
LARGE_TIER_DOWNGRADE_CELLS_COUNT=1950000

# If large cluster is enabled, workbooks will be scheduled to the large cluster when import time exceeds this value, default 10s
LARGE_TIER_MIN_IMPORT_SECONDS=10

# large cluster collaboration service instance count, default 2
LARGE_TIER_COLLABORATION_SERVER_REPLICATION_CNT=2

# large cluster collaboration service instance memory limit, recommended at least 8GB, default 8GB
LARGE_TIER_COLLABORATION_SERVER_MEMORY_LIMIT=8192
```

#### Netzwerkkonfiguration

Wenn die standardmäßig offengelegten Ports von Univer mit anderen Diensten in Konflikt stehen, können Sie sie nach Bedarf ändern:

```properties title=".env.custom"
# If it conflicts with existing network configuration, you can modify the CIDR used by docker
DOCKER_NETWORK_SUBNET=172.30.0.0/16

# Univer API service exposed port; if it conflicts with other host services, change to another port
HOST_NGINX_PORT=the-univer-server-api-port-you-wantted

# If you choose Univer's built-in MinIO as object storage and there is a port conflict, add this configuration item
# If you are using self-maintained object storage, setting this configuration item has no effect
HOST_MINIO_PORT=the-minio-port-you-wantted

# If you choose Univer's built-in observability components and there is a port conflict, add this configuration item
# If you are using self-maintained observability components, setting this configuration item has no effect
HOST_GRAFANA_PORT=the-grafana-port-you-wantted
```

#### Konfigurationsbeispiel

Das folgende Konfigurationsbeispiel erreicht:

- Aktivieren Sie die USIP-Integration, authentifizieren Sie die Benutzeridentität, aktivieren Sie die Berechtigungsvalidierung
- Konfigurieren Sie, dass nur der Dokumentbesitzer Inhalte kopieren kann und Drucken
- Aktivieren Sie die Veröffentlichung von Univer-Veranstaltungen
- Verwenden Sie selbstverwaltetes PostgreSQL
- Verwenden Sie selbstverwalteten Objektspeicher
- Ändern Sie den bereitgestellten Port des Univer-Dienstes
- Legen Sie die Kapazitätskonfiguration für Universer und Kollaborationsserver fest

`.env.custom` Dateiinhalt:

```properties title=".env.custom"
# 1. enable USIP integration
# usip about
USIP_ENABLED=true
USIP_URI_CREDENTIAL=https://usip-demo.univer.ai/usip/credential
USIP_URI_USERINFO=https://usip-demo.univer.ai/usip/userinfo
USIP_URI_ROLE=https://usip-demo.univer.ai/usip/role
USIP_URI_COLLABORATORS=https://usip-demo.univer.ai/usip/collaborators
USIP_URI_UNITEDITTIME=https://usip-demo.univer.ai/usip/unit-edit-time

# 2. only owner can copy content and print
AUTH_PERMISSION_CUSTOMER_STRATEGIES=[ {"action": 3, "role": 2}, {"action": 6, "role": 2} ]

# 3. enable univer event sync
EVENT_SYNC=true # Set to true to enable

# 4. use owner RDS
# postgresql config
DISABLE_UNIVER_RDS=true # When using your own RDS, disable Univer's default PostgreSQL

DATABASE_DRIVER=postgresql # Set to postgresql for PostgreSQL-compatible databases
DATABASE_HOST=univer-postgresql
DATABASE_PORT=5432
DATABASE_DBNAME=univer
DATABASE_USERNAME=universer-biz

# 5. use owner Object storage
# s3 config
DISABLE_UNIVER_S3=true # When using your own object storage, disable Univer's built-in MinIO

S3_USER=universer-biz
S3_PASSWORD=123456

S3_PATH_STYLE=true
S3_ENDPOINT=univer-s3:9652
```

## Bereitstellungs-SOP

Nachdem Sie die erforderliche Konfiguration ermittelt haben, können Sie Univer-Back-End-Dienste wie folgt bereitstellen Schritte.

### Docker Compose Deployment SOP

1. Bereiten Sie die Konfigurationsdatei `.env.custom` vor (überspringen Sie diesen Schritt, wenn keine Änderungen erforderlich sind).
2. Bereiten Sie die Lizenzdateien vor, einschließlich `license.txt` und `licenseKey.txt`.
3. Wenn Sie sich für die Verwendung eines selbstverwalteten RDS entscheiden, laden Sie [Datenbankinitialisierungsskript](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz) herunter und führen Sie die RDS-Initialisierung durch, einschließlich Universer und Temporal. Bei Verwendung von GaussDB oder DamengDB ist keine zeitliche Initialisierung erforderlich.
4. Beziehen Sie die Back-End-Dienste von Univer Pro:
   - Wenn der Bereitstellungsserver auf das öffentliche Internet zugreifen kann:
     - Führen Sie `bash -c "$(curl -fsSL https://get.univer.ai/product)" [-- version]` aus, um die angegebene Version der Univer-Dienste herunterzuladen. Wenn keine Version angegeben ist, wird standardmäßig die neueste Version heruntergeladen.
     - Die CLI versucht, Ihren Browser automatisch zu öffnen, um ein Authentifizierungstoken von [//cli-auth](//cli-auth) abzurufen. Wenn der Browser nicht automatisch geöffnet wird, besuchen Sie bitte diese URL manuell, um Ihr Token zu erhalten, und fügen Sie es dann in das Terminal ein, wenn Sie dazu aufgefordert werden.
   - Wenn der Bereitstellungsserver nicht auf das öffentliche Internet zugreifen kann:
     - [Klicken Sie hier, um](//releases/univer-server/download) das von Univer bereitgestellte All-in-One-Offline-Installationspaket herunterzuladen.
     - Laden Sie das Offline-Installationspaket auf den Bereitstellungsserver hoch und extrahieren Sie es.
     - Geben Sie das extrahierte Verzeichnis ein und führen Sie `bash load-images.sh` aus, um Univer-Back-End-Service-Images in den lokalen Docker zu laden.
5. Kopieren Sie die vorbereiteten `.env.custom`-Datei in den heruntergeladenen Univer-Dienstordner, im selben Verzeichnis wie die Standarddatei `.env`.
6. Kopieren Sie die Lizenzdateien `license.txt` und `licenseKey.txt` in das Verzeichnis `configs/` des heruntergeladenen Univer-Dienstes Ordner.
7. Geben Sie das Stammverzeichnis des Univer-Dienstes ein und führen Sie `bash run.sh start` aus, um die Dienstbereitstellung abzuschließen.
8. Regressionstests abschließen.
