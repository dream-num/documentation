## 部署配置

### 如何修改部署配置

Univer 的默认部署配置位于安装目录下的 `.env` 文件中。如需修改安装配置，请勿直接编辑 `.env` 文件，而应在其同级目录下创建名为 `.env.custom` 的自定义配置文件。`.env.custom` 中配置的项将覆盖 `.env` 文件中的默认值。

### 配置详解

#### 启用身份认证和权限管理

相关配置项的意义已在[通过 USIP 与你的系统集成](/guides/pro/usip)中说明，此处不再赘述。如需启用，可参考如下配置：

```properties title=".env.custom"
# usip about
USIP_ENABLED=true # 设置为 true 以启用 USIP
USIP_URI_CREDENTIAL=https://your-domain/usip/credential
USIP_URI_USERINFO=https://your-domain/usip/userinfo
USIP_URI_ROLE=https://your-domain/usip/role
USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

# apikey 是可选的
USIP_APIKEY=

# auth about
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
AUTH_PERMISSION_CUSTOMER_STRATEGIES=
```

#### 开启 Univer 事件发布

相关配置项的意义已在[通过 Univer 事件同步机制与你的系统集成](/guides/pro/event-sync)中说明，此处不再赘述。如需启用，可参考如下配置：

```properties title=".env.custom"
EVENT_SYNC=true # 设置为 true 以开启
```

#### 使用自己维护的基础组件

##### RDS

**请注意**，由于 Univer 使用的组件 Temporal 不支持 GaussDB 和 DamengDB，若选择这两种数据库，Univer 将为 Temporal 单独安装 PostgreSQL。Temporal 在数据库中存储的是导入导出任务的流程状态，不涉及任何文档数据。即使丢失，也仅会导致未完成的导入导出任务失败，不会产生其他影响。

###### 使用兼容 PostgreSQL 的 RDS

```properties title=".env.custom"
# RDS config
DISABLE_UNIVER_RDS=true # 使用自己的 RDS 时，需禁用 Univer 默认部署的 PostgreSQL

DATABASE_DRIVER=postgresql # 设置为 postgresql 代表使用兼容 postgresql 的数据库
DATABASE_HOST=your-database-host
DATABASE_PORT=your-database-port
DATABASE_DBNAME=univer # Univer 数据库初始化脚本默认使用该名称，若已更改，请保持此处一致
DATABASE_USERNAME=user-name # 需授予该用户 select、insert、update、delete 权限
DATABASE_PASSWORD=password
```

##### Redis

```properties title=".env.custom"
# redis config
DISABLE_UNIVER_REDIS=true # 使用自己的 Redis 时，需禁用 Univer 内建的 Redis

# if you use redis cluster, use comma ',' to separate multiple addresses
# for example: REDIS_ADDR=192.168.1.5:6001,192.168.1.5:6002,192.168.1.5:6003
REDIS_ADDR=host:port[,host:port]
REDIS_USERNAME=user-name
REDIS_PASSWORD=password
REDIS_DB=0

# redis tls config
# 支持三种模式：不安全模式（insecure）、仅进行 CA 验证、以及客户端证书（mTLS）验证。
# CA、证书和私钥既可以以文件路径形式提供，也可以直接以文件内容形式提供；
# 如果使用文件路径，请务必使用 Docker volume 挂载后的容器内虚拟路径。
REDIS_TLS_ENABLED=false
REDIS_TLS_INSECURE=false
REDIS_TLS_CA=
REDIS_TLS_CERT=
REDIS_TLS_KEY=
```

##### MQ

```properties title=".env.custom"
DISABLE_UNIVER_MQ=true # 使用自己的 MQ 时，需禁用 Univer 内建的 MQ

RABBITMQ_CLUSTER_ENABLED=true # 必须设置为 true
RABBITMQ_CLUSTER_USERNAME=user-name # 需具备 Declare Exchange、Produce、Consume 权限
RABBITMQ_CLUSTER_PASSWORD=password # password

# use comma to separate multiple addresses
# for example: RABBITMQ_CLUSTER_ADDR=192.168.1.2:5672,192.168.1.5:5672,192.168.1.7:5672
# 每个 addr 都要能读写，Univer 在连接时会轮询其中的 host，直到连接成功
RABBITMQ_CLUSTER_ADDR=host:port[,host:port]

# RABBITMQ_CLUSTER_VHOST is the vhost of the rabbitmq cluster. If you don't set it, the default value is /
# for example: RABBITMQ_CLUSTER_VHOST=univer
RABBITMQ_CLUSTER_VHOST=/
RABBITMQ_CLUSTER_SCHEMA=amqp
```

##### Object Storage

```properties title=".env.custom"
DISABLE_UNIVER_S3=true # 使用自己的 object storage 时，需禁用 Univer 内建的 MinIO

# s3 config
S3_USER=user
S3_PASSWORD=password
S3_REGION=your-inner-s3like-region # 若 S3-like 服务无此概念，可随意填写一个字符串

# S3_PATH_STYLE，可设置 true 或 false
# 若设置为 true，使用路径样式（Path-Style）构建访问 URL
# 若设置为 false，使用虚拟主机样式（Virtual-Host Style）构建访问 URL
S3_PATH_STYLE=true|false

# S3_ENDPOINT 提供给内部服务访问的地址
S3_ENDPOINT=inner-visit-host:port

# S3_ENDPOINT_PUBLIC 公开访问的地址，在客户端直接连接对象存储下载文件时使用
S3_ENDPOINT_PUBLIC=public-visit-host:port

# S3_DEFAULT_BUCKET 配置使用哪个 bucket
S3_DEFAULT_BUCKET=default-bucket-name
```

#### 协同编辑分层调度配置

自 `v0.15.0` 起引入，默认未启用，需手动配置开启。系统根据 workbook 的单元格总数及导入实际耗时决定调度到哪个等级的协同服务集群。对于刚通过导入创建的 workbook，依据导入耗时进行调度；对于其他方式创建或触发新快照生成后的 workbook，则依据单元格总数进行调度。每次快照创建后，相关指标数据将持久化到数据库并更新调度策略。

分层调度的本质是将协同服务部署为多个集群，并通过规则指定不同规模的表格由哪个集群处理。规则配置的数据结构如下：

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

说明：

- `tiers`：描述各集群信息，理论上可配置任意多个集群。
- `enable`：设置是否启用该集群，设置为 `false` 则该集群将被忽略。
- `upgradeCellsThreshold`：指定 sheet 单元格总数达到此规模时才能调度到该集群。
- `downgradeCellsThreshold`：若 sheet 当前正被调度到该集群，仅当单元格总数低于此值时才能降级到更低等级的集群。此设置可避免在等级边界处规模的 sheet 被频繁切换调度。
- `upgradeImportTimeThreshold`：新导入的 sheet 尚无单元格总数统计，此时利用该配置决定调度，作用机制同 `upgradeCellsThreshold`，仅指标换为导入实际耗时。

必须保证至少有一个集群的指标要求全部为 0，才能确保每个 sheet 都能被调度到。

按上述示例配置参数下的调度示例：

- workbook1 创建后的初始单元格数量为 0，调度到 normal 集群。
- workbook1 编辑后总单元格数量达到 1000 时，调度到 large 集群。
- workbook1 总单元格数量降至 999 时，由于仍大于降级线 900，继续调度到 large 集群。
- workbook1 总单元格数量继续降至 899 时，降级调度回 normal 集群。
- workbook2 被导入，实际耗时 61 秒，已超过 huge 集群的条件 60 秒，将调度到 huge 集群处理。

Univer 的 Docker Compose 部署脚本提供了选项，可选部署 1 个或 2 个等级的集群（分离普通表格和大表格）。集群配置中的 `ENABLE_LARGE_TIER_COLLABORATION_SERVER` 参数控制调度时是否使用大表格集群，以及控制 Docker Compose 是否实际部署大表格集群服务。若需更精细的集群等级控制或使用 K8s 部署，请调整 docker compose / charts 的编排以实际部署对应等级的 `collaboration-server` 服务集群，然后按上述说明配置调度路由表（`tiers` 数组）。

默认部署仅配置了两个等级：`normal` 和 `large`。

```properties title=".env.custom"
# 配置开启/关闭 large 集群，true-开启，false-关闭，默认关闭
ENABLE_LARGE_TIER_COLLABORATION_SERVER=false

# 若开启 large 集群，当总单元格数达到此规模后将调度到 large 集群，默认 2M
LARGE_TIER_MIN_CELLS_COUNT=2000000

# 若 sheet 当前调度在 large 集群，则只有当总单元格数降至此值以下时才会降级回 normal 集群，默认 1.95M
LARGE_TIER_DOWNGRADE_CELLS_COUNT=1950000

# 若开启 large 集群，当 workbook 导入耗时超过配置后将调度到 large 集群，默认 10s
LARGE_TIER_MIN_IMPORT_SECONDS=10

# large 集群协同服务实例数，默认 2
LARGE_TIER_COLLABORATION_SERVER_REPLICATION_CNT=2

# large 集群协同服务实例内存限制，建议至少配置 8GB，默认 8GB
LARGE_TIER_COLLABORATION_SERVER_MEMORY_LIMIT=8192
```

#### 网络配置

若 Univer 暴露的默认端口与其他服务冲突，可按需修改：

```properties title=".env.custom"
# 若与现有网络配置冲突，可修改 docker 使用的网段。使用 CIDR 表示法
DOCKER_NETWORK_SUBNET=172.30.0.0/16

# Univer API 服务暴露的端口，若与宿主机其他服务端口冲突，请更换为其他端口
HOST_NGINX_PORT=the-univer-server-api-port-you-wantted

# 若选择 Univer 安装包内置的 MinIO 作为对象存储且存在端口冲突，请添加此配置项修改
# 若使用的是自己维护的对象存储，设置此配置项无意义
HOST_MINIO_PORT=the-minio-port-you-wantted

# 若选择 Univer 安装包内置的可观测组件且存在端口冲突，请添加此配置项修改
# 若使用的是自己维护的可观测组件，设置此配置项无意义
HOST_GRAFANA_PORT=the-grafana-port-you-wantted
```

#### 配置示例

以下配置示例实现了：

- 开启 USIP 集成、认证用户身份、开启权限校验
- 配置仅文档 owner 可复制内容和打印
- 开启 Univer 事件发布
- 使用自己的 PostgreSQL
- 使用自己的 Object Storage
- 修改 Univer 服务暴露的端口
- 设置 universer 和 collaboration-server 的容量配置

`.env.custom` 文件内容如下：

```properties title=".env.custom"
# 1. enable USIP integration
# usip about
USIP_ENABLED=true
USIP_URI_CREDENTIAL=https://usip-demo.univer.ai/usip/credential
USIP_URI_USERINFO=https://usip-demo.univer.ai/usip/userinfo
USIP_URI_ROLE=https://usip-demo.univer.ai/usip/role
USIP_URI_COLLABORATORS=https://usip-demo.univer.ai/usip/collaborators
USIP_URI_UNITEDITTIME=https://usip-demo.univer.ai/usip/unit-edit-time

# 2. only owner can copy content and print
AUTH_PERMISSION_CUSTOMER_STRATEGIES=[ {"action": 3, "role": 2}, {"action": 6, "role": 2} ]

# 3. enable univer event sync
EVENT_SYNC=true # 设置为 true 以开启

# 4. use owner RDS
# postgresql config
DISABLE_UNIVER_RDS=true # 使用自己的 RDS 时，需禁用 Univer 默认部署的 PostgreSQL

DATABASE_DRIVER=postgresql # 设置为 postgresql 代表使用兼容 postgresql 的数据库
DATABASE_HOST=univer-postgresql
DATABASE_PORT=5432
DATABASE_DBNAME=univer
DATABASE_USERNAME=universer-biz
DATABASE_PASSWORD=123456

# 5. use owner Object storage
# s3 config
DISABLE_UNIVER_S3=true # 使用自己的 object storage 时，需禁用 Univer 内建的 MinIO

S3_USER=universer-biz
S3_PASSWORD=123456
S3_REGION=cn-sz
S3_PATH_STYLE=true
S3_ENDPOINT=univer-s3:9652
S3_ENDPOINT_PUBLIC=univer.ai:9653
S3_DEFAULT_BUCKET=univer

# 6. change univer service Port
HOST_NGINX_PORT=8010

# 7. set the service scale
UNIVERSER_REPLICATION_CNT=4 # universer 实例数
COLLABORATION_SERVER_REPLICATION_CNT=5 # 协同服务实例数
MAX_MEMORY_LIMIT=2048 # 协同服务最大内存限制，单位为 MB
```

## 部署 SOP

确定所需配置后，可按照以下步骤实施 Univer 后端服务的部署。

### Docker Compose 部署 SOP

1. 准备好配置文件 `.env.custom`（如无修改需求，可跳过此步）。
2. 准备好 License 文件，包括 `license.txt` 和 `licenseKey.txt`。
3. 若选择使用自己维护的 RDS，请下载[数据库初始化脚本](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz)并完成 RDS 的初始化，包括 universer 和 temporal 的初始化。若使用的是 GaussDB 或 DamengDB，则无需初始化 temporal。
4. 获取 Univer Pro 后端服务：
   - 若部署服务器可访问公共互联网：
     - 执行 `bash -c "$(curl -fsSL https://get.univer.ai/product)" [-- version]`，下载指定版本的 Univer 服务。若未指定 version，默认下载最新版本。
   - 若部署服务器无法访问公共互联网：
     - [点此下载](https://univer.ai/releases/univer-server/download) Univer 提供的 All in one 离线安装包。
     - 将离线安装包上传至部署服务器并解压。
     - 进入解压后的目录，执行 `bash load-images.sh` 将 Univer 后端服务的镜像加载到本机 Docker。
5. 将准备好的 `.env.custom` 文件复制到下载的 Univer 服务文件夹下，与默认的 `.env` 文件放在同一目录。
6. 将 License 文件 `license.txt` 和 `licenseKey.txt` 复制到下载的 Univer 服务文件夹下的 `configs/` 目录。
7. 进入 Univer 服务根目录，执行 `bash run.sh start` 即可完成服务部署。
8. 完成回归测试。
