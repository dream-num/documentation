## 용량 계획

용량 요구 사항은 실제 비즈니스 규모를 기준으로 평가해야 합니다. 수요가 많다면 Docker Compose 배포가 적합하지 않을 수 있습니다. 특히 다음 사항에 유의하세요.

- **exchange worker**(가져오기/내보내기 서비스)는 계산 집약적인 서비스로, 특히 대용량 문서를 가져올 때 짧은 시간 동안 많은 CPU와 메모리를 사용할 수 있습니다. 가져오기/내보내기 수요를 평가하여 적절한 CPU 및 메모리 리소스를 할당하세요.
- **collaboration-server**(협업 엔진)는 상태를 유지하는 Node 서비스로, 많은 문서를 동시에 열어 편집하면 상당한 메모리를 사용합니다. 필요한 인스턴스 수와 인스턴스별 메모리 구성을 평가하세요. 매우 큰 스프레드시트(셀 500만 개 초과)를 편집해야 한다면 인스턴스당 최소 8 GB의 메모리를 할당하는 것이 좋습니다.

또한 `v0.15.0`부터 도입된 협업 편집 계층형 스케줄링을 사용하려면 사용 시나리오에 포함된 스프레드시트의 규모 분포를 파악해야 합니다(문서와 슬라이드는 계층형 스케줄링 대상이 아닙니다). 이를 바탕으로 계층형 스케줄링 구성 여부를 결정합니다. 필요한 경우 클러스터 계층 수와 각 계층에서 처리할 스프레드시트 규모(전체 셀 수, 가져오기 시간 등)도 평가해야 합니다. 구체적인 구성 방법은 해당 배포 플랫폼의 구성 문서를 참고하세요.

### 협업 편집 리소스 요구 사항

대부분이 소규모 문서라면 협업 서비스의 사양을 2c4g로 구성할 수 있으며, 그렇지 않다면 4c8g를 권장합니다. 단일 협업 서비스 인스턴스의 사양을 이보다 더 높이는 것은 CPU 낭비로 이어질 수 있어 권장하지 않습니다.

- 단일 협업 서비스 인스턴스(2c4g / 4c8g)는 약 1100개 / 1200개의 소규모 문서를 동시에 편집할 수 있으며, 이는 약 360 / 400의 편집-저장 QPS에 해당합니다.
- 단일 universer 서비스(2c4g / 4c8g)는 약 1200개 / 2200개의 소규모 문서를 동시에 편집할 수 있으며, 이는 약 400 / 730의 편집-저장 QPS에 해당합니다.

### 다중 사용자 협업 리소스 요구 사항

다중 사용자 협업에서는 편집-저장 작업이 사용하는 리소스 외에도 협업 메시지 브로드캐스트에 필요한 CPU 수요가 더 큽니다. 협업 메시지 브로드캐스트는 universer 서비스가 처리하므로 collaboration-server의 리소스 사용량에는 영향을 주지 않습니다.

2c4g × 2 구성은 초당 10개의 편집 작업을 1400명에게 푸시할 수 있습니다. 평균적으로 CPU 코어 1개는 초당 최대 3500회의 협업 브로드캐스트를 지원합니다.

협업 브로드캐스트 QPS 계산식은 다음과 같습니다.

```
Collaborative Broadcast QPS = Edit-Save QPS × (Active Users / Active Documents − 1)
```

1을 빼는 이유는 자신에게 보내는 푸시가 이미 편집-저장 QPS에 포함되어 있기 때문입니다.

### 용량 요구 사항 계산기

아래 계산기를 사용하면 실제 비즈니스 매개변수를 바탕으로 필요한 리소스 구성을 빠르게 추정할 수 있습니다. 활성 문서 수, 저장 빈도, 협업 비율 등의 매개변수를 입력하면 편집 QPS, 협업 브로드캐스트 QPS와 권장 Node 서비스, Universer 및 데이터베이스 구성이 자동으로 출력됩니다.
