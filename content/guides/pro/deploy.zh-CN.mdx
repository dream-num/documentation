## 部署架构及服务介绍

![部署架构及服务介绍](./deploy/deploy-arch.png)

### 演进历史

- 自 `v0.13.0` 起，新增 `collaboration-helper` 服务，用于处理异步执行的 CPU 密集型任务（如生成快照）。
- 自 `v0.15.0` 起，引入协同编辑分层调度，将不同规模 sheet 的操作调度至不同的协同服务集群，以降低大表格编辑对普通规模表格的影响。

### 服务介绍

- **collaboration-server**：后端的协同编辑引擎，实现了与前端一致的 OT 算法。
- **collaboration-helper**：负责处理协同中的 CPU 密集型任务（如快照生成），保障协同编辑的流畅运行。注：`v0.13.0` 起引入。
- **universer**：处理文档操作请求，维护文档数据，并负责协同消息的广播。
- **exchange worker**：负责执行文档的导入导出计算任务，属于计算密集型服务，对内存亦有较高需求。

<Callout>
  collaboration-server 是有状态服务，对同一文档的编辑请求均在同一 collaboration-server 实例中处理，可减少数据加载开销，从而提升整体性能。
  因此，universer 在调用 collaboration-server 处理编辑操作时，增加了一层一致性哈希路由。
</Callout>

### 组件介绍

- **RDS**：关系型数据库，用于存储文档的元数据、权限配置等。
- **Object Storage**：对象存储，用于存储文档的内容数据，包括图片、数据块等。
- **Redis**：文档在线协作者缓存及 API 限流。
- **RabbitMQ**：消息队列，用于 universer 服务间交换需要广播的协同消息。
- **Temporal**：开源的流程执行引擎，Univer 将其用于管理文档导入导出的异步流程。

## 部署前准备

在了解 Univer 后端服务的基本架构后，生产部署前应对以下事项进行评估：

### 部署方式选择

Univer 目前提供两种部署方式：

- **Docker Compose 部署**
  Docker Compose 仅支持单机部署，扩展方式以纵向扩展为主，**不支持横向扩展**。适用于无 Kubernetes 运维能力且使用规模较小的场景。

- **兼容标准 Kubernetes 部署**
  若已运维 Kubernetes 集群且兼容标准 K8s 模式，推荐采用此方式。Univer 支持水平扩容，K8s 部署可提供最佳的可扩展性。

### 用户身份认证与权限校验

Univer 的安装配置默认未启用身份认证与权限校验，需根据实际业务需求决定是否开启。详见[通过 USIP 与你的系统集成](/guides/pro/usip)。

### 容量评估

需根据实际业务规模评估容量需求。若需求较大，Docker Compose 部署方式可能不适用。特别说明：

- **exchange worker**（导入导出服务）为计算密集型服务，处理导入导出任务时可能在短时间内占用大量 CPU 与内存，尤其是导入大文档时。需评估导入导出需求，为其分配合适的 CPU 与内存资源。
- **collaboration-server**（协同引擎）为有状态的 Node 服务，在同时打开较多文档编辑时会占用较多内存。需评估所需实例数及每个实例的内存配置。若有编辑超大表格（大于 500 万单元格）的需求，建议每个实例至少配置 8 GB 内存。

此外，自 `v0.15.0` 起引入的协同编辑分层调度，需统计使用场景中表格的规模分布（文档与幻灯片不参与分层调度），以判断是否需配置分层调度。若需要，还需评估集群等级数量及各等级处理的表格规模（单元格总数、导入耗时等指标）。具体配置说明见后续章节。

#### 协同编辑资源需求计算

若绝大部分为小文档，协同服务可选择 2c4g 规格；否则建议选择 4c8g 规格。不建议继续增加单实例协同服务的规格，以免造成 CPU 资源浪费。

- 单实例协同服务（2c4g / 4c8g）可支持约 1100 / 1200 篇小规模文档的并发编辑，按编辑保存 QPS 计算约为 360 / 400。
- 单 universer 服务（2c4g / 4c8g）可支持约 1200 / 2200 篇小规模文档的并发编辑，按编辑保存 QPS 计算约为 400 / 730。

#### 多人协同资源需求计算

多人协同时，除编辑保存消耗资源外，协同消息广播对 CPU 资源的需求更为显著。协同消息广播由 universer 服务完成，不影响 collaboration-server 的资源占用。

2c4g × 2 的配置可支持向 1400 人每秒推送 10 次编辑操作。平均而言，1 核 CPU 最高可支持每秒 3500 次协同广播。

协同广播 QPS 计算公式为：

```
协同广播 QPS = 编辑保存 QPS × (活跃用户数 / 活跃文档数 − 1)
```

其中减去 1 是因为向自身的推送已计入编辑保存 QPS 中。

#### 容量需求计算器

可使用下方的计算器，根据实际业务参数快速估算所需的资源配置。输入活跃文档数、保存频率、协同比例等参数后，计算器将自动输出编辑 QPS、协同广播 QPS 以及推荐的 Node 服务、Universer 和数据库配置。

### 基础组件选择

如上述系统部署架构所示，Univer 依赖的基础组件包括 MQ、Redis、RDS、Object Storage。Univer 的安装包会包含对应组件的常用开源版本。

同时，Univer 支持改用自己维护的组件，并且**强烈建议**在生产环境中这样做，原因如下：

- 便于系统维护
- 保障数据存储安全
- 确保系统运行稳定

特别是文档数据的存储组件 RDS 与 Object Storage。若使用 Univer 内置版本，在物理机存储损坏的情况下可能造成数据的永久丢失。若缺乏自有的存储基础设施，建议选择公有云厂商提供的服务。若只能使用 Univer 内置的存储组件，则务必定期备份数据，建议每天备份一次。

若选择使用自己维护的组件，需确保完全兼容 Univer 对这些组件的要求。各组件要求如下：

#### MQ

需完全兼容 AMQP/AMQPS，目前建议选用 RabbitMQ。Univer 安装包使用的官方镜像为 `rabbitmq:3-management`。

#### Redis

需兼容所有 Redis 命令。Univer 安装包使用的官方镜像为 `bitnami/redis:7.0.15-debian-11-r3`。

目前 Univer 使用的 Redis 命令包括：`GET`、`MGET`、`SET`、`SETNX`、`DEL`、`EXISTS`、`EXPIRE`、`HSET`、`HGET`、`HDEL`、`HGETALL`、`HLEN`、`SCAN`、`Pipeline`、`EVAL`、`EVALSHA`。需确保 Redis 组件兼容上述命令。在满足兼容性的前提下，亦可使用分布式版本的 Redis。

#### RDS

目前已适配 PostgreSQL 16.1、MySQL 8.0、GaussDB、DamengDB，可选择上述数据库或兼容的数据库。Univer 安装包使用的官方镜像为 `postgres:16.1`。

请注意，Univer 目前暂未支持需要按表字段分片的分布式数据库。若分布式数据库无法完全兼容单机数据库的访问方式，则不能使用。另外，若使用 TiDB 等完全兼容的分布式数据库，也需谨慎——Univer 目前的 ID 生成器生成的 ID 为趋势递增，可能导致请求集中在同一节点处理，从而出现性能瓶颈。

#### Object Storage

需兼容 AWS S3 API。Univer 安装包使用的官方镜像为 `bitnami/minio:2024.8.3-debian-12-r1`。

#### 可观测组件

在后续运维 Univer 后端服务时，需确定使用 Univer 集成的可观测组件还是接入已有的可观测系统。Univer 目前提供 Prometheus 指标、Grafana 看板及服务日志。接入详情请参阅[运维手册](/guides/pro/sre-manual)。

若无可观测系统或难以接入，建议启用 Univer 内置的可观测组件。

## 部署配置

### 如何修改部署配置？

#### Docker Compose 部署

Univer 的默认部署配置位于安装目录下的 `.env` 文件中。如需修改安装配置，请勿直接编辑 `.env` 文件，而应在其同级目录下创建名为 `.env.custom` 的自定义配置文件。`.env.custom` 中配置的项将覆盖 `.env` 文件中的默认值。

#### Kubernetes 部署

Univer 的默认部署配置位于 Helm chart 的 `values.yaml` 中，[点击查看](https://github.com/dream-num/helm-charts/blob/main/charts/univer-stack/values.yaml)。如需修改配置，无需编辑 charts 中的文件，只需新建一个 `values.yaml` 文件，将需要修改的配置项写入其中即可。通过 `helm install` 命令安装时指定该 `values.yaml` 文件，即可用自定义配置覆盖默认配置。未指定的配置项将使用默认值。具体的 Helm 命令说明见后文部署步骤。

### 配置详解

#### 使用自己维护的基础组件

##### RDS

**请注意**，由于 Univer 使用的组件 Temporal 不支持 GaussDB 和 DamengDB，若选择这两种数据库，Univer 将为 Temporal 单独安装 PostgreSQL。Temporal 在数据库中存储的是导入导出任务的流程状态，不涉及任何文档数据。即使丢失，也仅会导致未完成的导入导出任务失败，不会产生其他影响。

    ```properties title=".env.custom"
    # redis config
    DISABLE_UNIVER_REDIS=true # 使用自己的 Redis 时，需禁用 Univer 内建的 Redis

    REDIS_TLS_ENABLED=false

    REDIS_TLS_CERT=
    ```

#### 协同编辑分层调度配置

自 `v0.15.0` 起引入，默认未启用，需手动配置开启。系统根据 workbook 的单元格总数及导入实际耗时决定调度到哪个等级的协同服务集群。对于刚通过导入创建的 workbook，依据导入耗时进行调度；对于其他方式创建或触发新快照生成后的 workbook，则依据单元格总数进行调度。每次快照创建后，相关指标数据将持久化到数据库并更新调度策略。

分层调度的本质是将协同服务部署为多个集群，并通过规则指定不同规模的表格由哪个集群处理。规则配置的数据结构如下：

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

说明：

- `tiers`：描述各集群信息，理论上可配置任意多个集群。
- `enable`：设置是否启用该集群，设置为 `false` 则该集群将被忽略。
- `upgradeCellsThreshold`：指定 sheet 单元格总数达到此规模时才能调度到该集群。
- `downgradeCellsThreshold`：若 sheet 当前正被调度到该集群，仅当单元格总数低于此值时才能降级到更低等级的集群。此设置可避免在等级边界处规模的 sheet 被频繁切换调度。
- `upgradeImportTimeThreshold`：新导入的 sheet 尚无单元格总数统计，此时利用该配置决定调度，作用机制同 `upgradeCellsThreshold`，仅指标换为导入实际耗时。

必须保证至少有一个集群的指标要求全部为 0，才能确保每个 sheet 都能被调度到。

按上述示例配置参数下的调度示例：

- workbook1 创建后的初始单元格数量为 0，调度到 normal 集群。
- workbook1 编辑后总单元格数量达到 1000 时，调度到 large 集群。
- workbook1 总单元格数量降至 999 时，由于仍大于降级线 900，继续调度到 large 集群。
- workbook1 总单元格数量继续降至 899 时，降级调度回 normal 集群。
- workbook2 被导入，实际耗时 61 秒，已超过 huge 集群的条件 60 秒，将调度到 huge 集群处理。

Univer 的 Docker Compose 部署脚本提供了选项，可选部署 1 个或 2 个等级的集群（分离普通表格和大表格）。
集群配置中的 `ENABLE_LARGE_TIER_COLLABORATION_SERVER` 参数控制调度时是否使用大表格集群，以及控制 Docker Compose 是否实际部署大表格集群服务。
若需更精细的集群等级控制或使用 K8s 部署，请调整 docker compose / charts 的编排以实际部署对应等级的 `collaboration-server` 服务集群，然后按上述说明配置调度路由表（`tiers` 数组）。

若直接使用 Univer 提供的 docker compose 编排，可调整如下参数来配置是否启用第二个等级集群，以及什么规模的表格算作大表格需要分离处理。

<Tabs items={['docker compose', 'K8s']}>

## 部署 SOP

确定所需配置后，可按照以下步骤实施 Univer 后端服务的部署。

### Docker Compose 部署 SOP [#deploy-to-docker-compose]

1. 准备好配置文件 `.env.custom`（如无修改需求，可跳过此步）。
2. 准备好 License 文件，包括 `license.txt` 和 `licenseKey.txt`。
3. 若选择使用自己维护的 RDS，请下载[数据库初始化脚本](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz)并完成 RDS 的初始化，包括 universer 和 temporal 的初始化。若使用的是 GaussDB 或 DamengDB，则无需初始化 temporal。
4. 获取 Univer Pro 后端服务：
   - 若部署服务器可访问公共互联网：
     - 执行 `bash -c "$(curl -fsSL https://get.univer.ai/product)" [-- version]`，下载指定版本的 Univer 服务。若未指定 version，默认下载最新版本。
   - 若部署服务器无法访问公共互联网：
     - [点此下载](https://univer.ai/releases/univer-server/download) Univer 提供的 All in one 离线安装包。
     - 将离线安装包上传至部署服务器并解压。
     - 进入解压后的目录，执行 `bash load-images.sh` 将 Univer 后端服务的镜像加载到本机 Docker。
5. 将准备好的 `.env.custom` 文件复制到下载的 Univer 服务文件夹下，与默认的 `.env` 文件放在同一目录。
6. 将 License 文件 `license.txt` 和 `licenseKey.txt` 复制到下载的 Univer 服务文件夹下的 `configs/` 目录。
7. 进入 Univer 服务根目录，执行 `bash run.sh start` 即可完成服务部署。
8. 完成回归测试。

### K8s 部署 SOP [#deploy-to-k8s]

使用 K8s 部署时请注意：若有自定义配置修改，需自行管理自定义配置文件 `values.yaml` 的版本，因为后续升级操作仍需要提供完整的自定义配置。建议使用 Git 等版本管理工具进行管理。

1. 准备好配置文件 `values.yaml`（如无修改需求，可跳过此步）。
2. 准备好 License 文件 `license.txt` 和 `licenseKey.txt`。
3. 若选择使用自己维护的 RDS，请下载[数据库初始化脚本](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz)并完成 RDS 的初始化，包括 universer 和 temporal 的初始化。若使用的是 GaussDB 或 DamengDB，则无需初始化 temporal。
4. 执行 Helm 安装命令，使用你的 `values.yaml` 文件和 License 文件：
   - 若部署服务器可访问公共互联网：
     ```shell
     helm install -n univer --create-namespace \
         -f your-own-values.yaml-path \
         --set global.istioNamespace="univer" \
         --set-file universer.license.licenseV2=your-license.txt-path \
         --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
         univer-stack \
         oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
         --version target-version

     # 执行成功后，运行以下两个命令重启服务以完成 sidecar 注入
     kubectl rollout restart -n univer deployment/collaboration-server
     kubectl rollout restart -n univer deployment/universer
     ```
     若需部署 Univer 配置的可观测组件，请执行以下命令安装：
     ```bash
     helm upgrade --install -n univer-observability --create-namespace \
         --set global.univerNamespace="univer" \
         univer-observability \
         oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-observability
     ```

     参数说明：
     - `--set global.univerNamespace="univer"`：配置所观测的 Univer 集群的 namespace 为 `"univer"`。
   - 若部署服务器无法访问公共互联网：
     - [点此下载](https://univer.ai/releases/univer-server/download) Univer 提供的 K8s all in one 离线安装包。
     - 将离线安装包上传至部署服务器并解压。
     - 进入解压后的目录执行：
       ```shell
       export REGISTER=XXXX # 你的私有镜像仓库
       export NAMESPACE=XXX # 要上传的镜像 namespace
       docker login $REGISTER
       bash load-image.sh --registry $REGISTER --namespace $NAMESPACE
       ```
     - 执行成功后会在当前目录生成 `values.yaml` 和 `values-observability.yaml` 文件，可按需修改配置：
       - `values.yaml`：Univer 服务的配置文件
       - `values-observability.yaml`：Univer 服务相关可观测性监控组件的配置文件
     - 接着执行以下命令进行安装：
       ```shell
       helm install -n univer --create-namespace \
           -f your-own-values.yaml-path \
           --set global.istioNamespace="univer" \
           --set-file universer.license.licenseV2=your-license.txt-path \
           --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
           univer-stack \
           univer-stack-xxxx.tgz # 需改为当前目录解压后对应的 chart 包

       # 执行成功后，运行以下两个命令重启服务以完成 sidecar 注入
       kubectl rollout restart -n univer deployment/collaboration-server
       kubectl rollout restart -n univer deployment/universer
       ```
     - 若需部署 Univer 配置的可观测组件，请执行以下命令安装：
       ```bash
       helm upgrade --install -n univer-observability --create-namespace \
           --set global.univerNamespace="univer" \
           -f your-own-values-observability.yaml-path \
           univer-observability \
           univer-observability-xxxx.tgz
       ```

       参数说明：
       - `--set global.univerNamespace="univer"`：配置所观测的 Univer 集群的 namespace 为 `"univer"`。

参数说明：

- `-n univer`：指定集群 namespace 为 `univer`，可根据需要更改，但需记住该值，后续升级时仍需使用。
- `univer-stack`：Helm release 的名称，可根据需要更改，但需记住该值，后续升级时仍需使用。
- `--version target-version`：指定部署版本，需修改为目标版本；也可去掉此项以自动选择最新版本。
- `-f your-own-values.yaml-path`：指定自定义配置文件 `values.yaml` 的路径，需确保路径正确。
- `--set-file universer.license.licenseV2=your-license.txt-path`：指定 License 解压后的 `license.txt` 文件路径。
- `--set-file universer.license.licenseKeyV2=your-licenseKey.txt-path`：指定 License 解压后的 `licenseKey.txt` 文件路径。
