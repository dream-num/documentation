## デプロイ構成とコンポーネント

![デプロイ構成](./deploy/deploy-arch.png)

<Callout title="バージョン情報">
  - v0.13.0 で `collaboration-helper` を導入（スナップショット生成などの CPU 集約処理）。
  - v0.15.0 で協調編集の分層スケジューリングを導入。

### サービス一覧

- **collaboration-server**：協調編集エンジン（OT）
- **collaboration-helper**：CPU 集約タスク（v0.13.0+）
- **universer**：ドキュメント操作と協調ルーティング
- **exchange worker**：インポート/エクスポート（計算/メモリ集約）

<Callout>
  collaboration-server はステートフルである。同一ドキュメントの編集は同一インスタンスにルーティングされる。
</Callout>

### 依存コンポーネント

- **RDS**：メタデータ・権限
- **Object Storage**：ドキュメントデータ、画像
- **Redis**：協作者キャッシュ、レート制限
- **RabbitMQ**：協調メッセージ配信
- **Temporal**：インポート/エクスポートのワークフロー

## デプロイ方式

| 方式 | 用途 | 特徴 |

| Docker Compose | 小規模、K8s なし | 単一ノード、垂直スケールのみ |
| K8s | 中〜大規模 | 水平スケールと拡張性 |

## 本番チェックリスト

- **ID/権限**：USIP が必要か
- **容量計画**：協調/交換の CPU/メモリ
- **基盤**：自前またはクラウド管理の利用
- **データ保護**：RDS/Object Storage のバックアップ
- **可観測性**：[運用手冊](/guides/pro/sre-manual)参照

## 容量計画

ほとんどのドキュメントが小規模であれば、協調サービスは 2c4g のスペックを選択する。そうでない場合は 4c8g を推奨する。協調サービスの単一インスタンスのスペックをさらに増やすことは推奨しない。CPU リソースの無駄が増えるためである。

- 単一 collaboration-server インスタンス（2c4g / 4c8g）は、小規模ドキュメントの同時編集をそれぞれ約 1100 / 1200 件まで処理でき、編集保存 QPS に換算すると約 360 / 400 である。
- 単一 universer サービス（2c4g / 4c8g）は、小規模ドキュメントの同時編集をそれぞれ約 1200 / 2200 件まで処理でき、編集保存 QPS に換算すると約 400 / 730 である。

### 多人協調のリソース見積もり

多人協調時には、編集保存以外に協調メッセージのブロードキャストが CPU リソースを大きく消費する。ブロードキャストは universer サービス内で完結し、Node サービスのリソースには影響しない。

2c4g × 2 の構成であれば、1400 人に対して毎秒 10 回の編集操作を配信できる。平均して 1 コアは毎秒最大 3500 回の協調ブロードキャストを処理できる。

ブロードキャスト QPS = 編集保存 QPS × (アクティブユーザー数 / アクティブドキュメント数 − 1)。マイナス 1 は、自分自身へのプッシュが既に編集保存 QPS に含まれているためである。

### 容量見積もりツール

以下の計算機を使用し、実際の業務パラメータから必要なリソース構成を迅速に見積もることができる。アクティブドキュメント数、保存間隔、協調比率などを入力すると、編集 QPS、ブロードキャスト QPS、および推奨の Node サービス、Universer、データベース構成が自動的に表示される。

## よく使う設定

### USIP を有効化

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    # usip
    USIP_ENABLED=true # true で有効化
    USIP_URI_CREDENTIAL=https://your-domain/usip/credential
    USIP_URI_USERINFO=https://your-domain/usip/userinfo
    USIP_URI_ROLE=https://your-domain/usip/role
    USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
    USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

    # Apikey config is optional.
    USIP_APIKEY=

    # auth
    AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
    AUTH_PERMISSION_CUSTOMER_STRATEGIES=
    ```
  </Tab>
  <Tab label="K8s">
    ```yaml title="values.yaml"
    universer:
      config:
        usip:
          enabled: true
          uri:
            userinfo: 'https://your-domain/usip/userinfo'
            collaborators: 'https://your-domain/usip/collaborators'
            role: 'https://your-domain/usip/role'
            credential: 'https://your-domain/usip/credential'
            unitEditTime: 'https://your-domain/usip/unit-edit-time'

          # apikey is optional.
          apikey: ''
        auth:
          permission:
            enableObjInherit: false
            customerStrategies: ''
    ```
  </Tab>
</Tabs>

補足：

- `USIP_ENABLED` / `usip.enabled` 有効化時は全エンドポイント必須
- `USIP_URI_*`：USIP API の URL
- `AUTH_PERMISSION_*`：権限ポイント/継承（[USIP](/guides/pro/usip)参照）

### 自前インフラ利用

<Callout>
  安定性とデータ保護のため、自前またはクラウド管理コンポーネントを推奨する。
</Callout>

#### 互換要件

- MQ：AMQP/AMQPS 互換。推奨 RabbitMQ。内蔵イメージ：`rabbitmq:3-management`。
- Redis：主要コマンド互換（GET/MGET/SET/SETNX/DEL/EXISTS/EXPIRE/HSET/HGET/HDEL/HGETALL/HLEN/SCAN/Pipeline/EVAL/EVALSHA）。
- RDS：PostgreSQL 16.1、MySQL 8.0、GaussDB、DamengDB。分散 DB は未対応の場合あり。TiDB などの完全互換製品を使用する場合は、単調増加 ID によるホットスポットリスクに注意すること。
- Object Storage：AWS S3 互換。内蔵イメージ：`bitnami/minio:2024.8.3-debian-12-r1`。

#### RDS

**注意**：Temporal は GaussDB/DamengDB 非対応。Temporal は別 PostgreSQL を使用する。

##### PostgreSQL 互換

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    DISABLE_UNIVER_RDS=true

    DATABASE_DRIVER=postgresql
    DATABASE_HOST=your-database-host
    DATABASE_PORT=your-database-port
    DATABASE_DBNAME=univer
    DATABASE_USERNAME=user-name
    DATABASE_PASSWORD=password
    ```
  </Tab>
  <Tab label="K8s">
    ```yaml title="values.yaml"
    postgresql:
      enabled: false

    universer:
      config:
        database:
          driver: postgresql
          host: your-database-host
          port: your-database-port
          dbname: univer
          username: postgres
          password: postgres

    temporal:
      server:
        config:
          persistence:
            default:
              driver: sql
              sql:
                driver: postgres12
                host: your-database-host
                port: your-database-port
                database: temporal
                user: postgres
                password: postgres

            visibility:
              driver: sql
              sql:
                driver: postgres12
                host: your-database-host
                port: your-database-port
                database: temporal_visibility
                user: postgres
                password: postgres
    ```
  </Tab>
</Tabs>

補足：

- `DISABLE_UNIVER_RDS`：内蔵 DB を無効化
- `DATABASE_DBNAME`：初期化スクリプトと一致させる
- `DATABASE_USERNAME`：select/insert/update/delete 権限推奨
- Temporal DB はワークフローのみで文書データは格納しない
- `driver: postgres12` は PostgreSQL 12+ が必要

### 分層スケジューリング（高度）

v0.15.0 から分層ルーティングを導入（デフォルトは無効）。

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

補足：

- `tiers`：階層一覧
- `enable`：有効/無効
- `upgradeCellsThreshold`：昇格の閾値
- `downgradeCellsThreshold`：降格の閾値
- `upgradeImportTimeThreshold`：インポート時間の閾値
- 少なくとも 1 階層はすべて 0 にする必要がある

例：

- 0 セル → normal
- 1000 セル → large
- 899 セル → normal
- 61s のインポート → huge

Docker Compose は 2 階層（normal/large）を提供：

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    ENABLE_LARGE_TIER_COLLABORATION_SERVER=false
    LARGE_TIER_MIN_CELLS_COUNT=2000000
    LARGE_TIER_DOWNGRADE_CELLS_COUNT=1950000
    LARGE_TIER_MIN_IMPORT_SECONDS=10
    LARGE_TIER_COLLABORATION_SERVER_REPLICATION_CNT=2
    LARGE_TIER_COLLABORATION_SERVER_MEMORY_LIMIT=8192
    ```
  </Tab>
  <Tab label="K8s">
    多階層の構成とルールを自前で設定すること。
  </Tab>
</Tabs>

## デプロイ手順

### Docker Compose

1. `.env.custom` を用意（任意）
2. `license.txt` と `licenseKey.txt` を用意
3. 自前 RDS の場合は[初期化スクリプト](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz)を実行
4. Univer Server を取得
   - オンライン：`bash -c "$(curl -fsSL https://get.univer.ai/product)" [-- version]`
   - オフライン：All-in-one パッケージを解凍し `bash load-images.sh`
5. `.env.custom` をルートに配置
6. ライセンスファイルを `configs/` に配置
7. ルートで `bash run.sh start`
8. 回帰テスト

### K8s

1. `values.yaml` を用意（任意、バージョン管理推奨）
2. `license.txt` と `licenseKey.txt` を用意
3. 自前 RDS の場合は初期化
4. Helm でインストール
   - オンライン：

   ```shell
   helm install -n univer --create-namespace \
     -f your-own-values.yaml-path \
     --set global.istioNamespace="univer" \
     --set-file universer.license.licenseV2=your-license.txt-path \
     --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
     univer-stack \
     oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
     --version target-version

   kubectl rollout restart -n univer deployment/collaboration-server
   kubectl rollout restart -n univer deployment/universer
   ```

   - オフライン：

   ```shell
   export REGISTER=XXXX
   export NAMESPACE=XXX
   docker login $REGISTER
   bash load-image.sh --registry $REGISTER --namespace $NAMESPACE

   helm install -n univer --create-namespace \
     -f your-own-values.yaml-path \
     --set global.istioNamespace="univer" \
     --set-file universer.license.licenseV2=your-license.txt-path \
     --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
     univer-stack-xxxx.tgz
   ```

パラメータ：

- `-n univer`：namespace
- `univer-stack`：Helm リリース名
- `--version target-version`：対象バージョン
- `-f your-own-values.yaml-path`：カスタム値ファイル
- `--set-file universer.license.licenseV2`：`license.txt` のパス
- `--set-file universer.license.licenseKeyV2`：`licenseKey.txt` のパス

helm upgrade --install -n univer-observability --create-namespace \
  --set global.univerNamespace="univer" \
  univer-observability \
  oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-observability
