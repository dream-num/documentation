## デプロイ構成とサービス概要

![Introduction to Deployment Architecture and Services](./deploy/deploy-arch.png)

### アーキテクチャの進化

- `v0.13.0` スナップショット生成など、非同期で実行すべき CPU 集約タスクを処理する `collaboration-helper` サービスを導入
- `v0.15.0` 協調編集に階層スケジューリングを導入。サイズの異なるシートを別クラスタに振り分け、大規模シート編集の影響を抑制

### サービス概要

- collaboration-server: バックエンドの共同編集エンジン（フロントエンドと同じ OT アルゴリズムを実装）
- collaboration-helper: 共同編集フロー内の CPU 集約タスク（例: スナップショット生成）を処理し、リアルタイム共同編集の応答性を維持。※ v0.13.0 で導入
- universer: unit の各種操作リクエスト処理、unit データ保持、共同編集メッセージのブロードキャスト
- exchange worker: unit のインポート/エクスポート計算タスクを実行。計算負荷/メモリ要求が高い

<Callout>
  collaboration-server はステートフルサービスで、同一ドキュメントの編集リクエストは同じ collaboration-server インスタンスで処理されます。これにより処理時のデータ読み込みが削減され、性能が向上します。
  そのため、universer から collaboration-server を呼び出す際に一貫性ハッシュによるルーティング層を追加しています。
</Callout>

### コンポーネント概要

- RDS: リレーショナルデータベース。ドキュメントのメタデータや権限設定を保存
- Object Storage: ドキュメント内容（画像/データブロック等）を保存
- Redis: ドキュメントのオンライン共同編集者キャッシュ、API レート制限
- RabbitMQ: メッセージキュー。universer 間で共同編集メッセージを交換
- Temporal: オープンソースのワークフロー実行エンジン。インポート/エクスポートの非同期処理を管理

## デプロイ前の準備

本番環境にデプロイする前に、以下を慎重に検討してください:

### デプロイ方式の選択

Univer は次の 2 つの方式を提供しています:

- Docker Compose でデプロイ:
    単一マシンのみで、**水平スケールは非対応**です。K8s を運用しておらず、利用規模が大きくない場合に適しています。
- 標準 K8s でデプロイ:
    K8s クラスターを運用している場合はこちらが最適です。Univer は水平スケールをサポートし、K8s デプロイはスケーラビリティに優れます。

### ユーザー認証と権限管理の要件

Univer のインストール設定では認証がデフォルトで無効です。利用要件に応じて有効化するか判断してください。詳細は [USIP 連携](/guides/pro/usip) を参照してください。

### 容量評価

容量要件を慎重に見積もる必要があります。需要が大きい場合は Docker Compose が適さない可能性があります。特に次の点に注意してください:

- インポート/エクスポートの exchange worker は計算負荷が高く、特に大きなドキュメントの処理で短時間に CPU/メモリを大きく消費します。需要を評価し、適切なリソースを割り当ててください。
- 共同編集エンジンの collaboration-server はステートフルな Node.js サービスで、同時に複数ドキュメントを開くとメモリ消費が増加します。必要なインスタンス数とメモリ構成を慎重に評価してください。非常に大きいスプレッドシート（500 万セル超）の編集が想定される場合、1 インスタンスあたり最低 8GB のメモリを推奨します。

注: `v0.15.0` 以降、共同編集の階層スケジューリングが導入されました。利用シナリオにおけるシートサイズ分布（Docs/Slides は対象外）を分析し、階層スケジューリングが必要か判断してください。必要なら、階層数や各階層が扱うシートサイズ（総セル数、インポート時間など）を決定します。詳細設定は後続セクションで説明します。

### 基盤コンポーネントの選定

上記のデプロイ構成図のとおり、Univer は MQ、Redis、RDS、Object Storage を使用します。インストールパッケージには一般的な OSS 版が含まれます。

もちろん、独自管理のコンポーネントを使用できます。以下の理由からそれを推奨します:

- システム保守が容易
- データ保管の安全性が高い
- システムの安定性向上

特に RDS と Object Storage は、Univer 組み込み版を使うと物理障害時に永続的なデータ損失が起こり得ます。自社のストレージ基盤がない場合は、公的クラウドベンダーのサービス利用を推奨します。組み込みストレージしか使えない場合は、少なくとも 1 日 1 回の定期バックアップを必ず行ってください。

独自コンポーネントを利用する場合は、Univer の要件に完全に準拠していることを確認してください。要件は以下のとおりです。

#### MQ

AMQP/AMQPS 互換が必要です。現時点では RabbitMQ を推奨します。インストールパッケージは `rabbitmq:3-management` を使用しています。

#### Redis

Redis コマンド互換が必要です。インストールパッケージでは bitnami/redis: 7.0.15-debian-11-r3 を使用しています。Univer が利用する Redis コマンドは GET/MGET/SET/SETNX/DEL/EXISTS/EXPIRE/HSET/HGET/HDEL/HGETALL/HLEN/SCAN/Pipeline/EVAL/EVALSHA です。互換性を確保してください。互換性があれば分散版 Redis も利用できます。

#### RDS

現在は PostgreSQL 16.1、MySQL 8.0、GaussDB、DamengDB に対応しています。これらまたは互換 DB を利用できます。インストールパッケージは postgres: 16.1 を使用しています。

ただし、現在 Univer は分散 DB をサポートしません。スタンドアロン DB と同等のアクセスができない場合は利用不可です。例えばシャーディング必須の DB は未対応です。TiDB のような互換分散 DB を使う場合も、Univer の ID が単調増加するため同一ノードに偏り、性能低下が起こり得ますので注意してください。

#### Object Storage

AWS S3 互換の API が必要です。インストールパッケージでは bitnami/minio: 2024.8.3-debian-12-r1 を使用しています。

#### 可観測性コンポーネント

運用時に Univer の組み込み可観測性コンポーネントを使うか、自社の監視基盤に接続するかを検討してください。Univer は Prometheus メトリクス、Grafana ダッシュボード、サービスログを提供します。詳細は [SRE マニュアル](/guides/pro/sre-manual) を参照してください。自社の監視基盤がない場合は、Univer の組み込み可観測性を有効化することを推奨します。

## デプロイ設定

### 設定の変更方法

#### Docker Compose でデプロイ

既定の設定はインストールディレクトリの `.env` にあります。この `.env` を直接編集せず、同じディレクトリに `.env.custom` を作成して設定値を記述してください。`.env.custom` に設定した値はインストール時に `.env` の値を上書きします。

#### K8s でデプロイ

既定の設定は Helm Chart の values.yaml にあります（[参照](https://github.com/dream-num/helm-charts/blob/main/charts/univer-stack/values.yaml)）。設定を変更する場合、チャート内のファイルは編集せず、新しい values.yaml を作成して変更したい項目だけを書き込みます。Helm がそれらを上書きし、未指定項目は既定値を使用します。具体的な Helm コマンドは最後のデプロイ手順で説明します。

### 設定詳細

#### 認証と権限管理の有効化

設定項目の意味は [USIP 連携](/guides/pro/usip) に記載されています。有効化する場合は次のように設定します:

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    # usip about
    USIP_ENABLED=true # Set true to enable USIP
    USIP_URI_CREDENTIAL=https://your-domain/usip/credential
    USIP_URI_USERINFO=https://your-domain/usip/userinfo
    USIP_URI_ROLE=https://your-domain/usip/role
    USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
    USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

    # auth about
    AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
    AUTH_PERMISSION_CUSTOMER_STRATEGIES=
    ```
  </Tab>
  <Tab label="K8s">
    ```yaml title="values.yaml"
    universer:
      config:
        usip:
          enabled: true # Set true to enable USIP
          uri:
            userinfo: 'https://your-domain/usip/userinfo'
            collaborators: 'https://your-domain/usip/collaborators'
            role: 'https://your-domain/usip/role'
            credential: 'https://your-domain/usip/credential'
            unitEditTime: 'https://your-domain/usip/unit-edit-time'
        auth:
          permission:
            enableObjInherit: false
            customerStrategies: ''
    ```
  </Tab>
</Tabs>

#### 独自コンポーネントの利用

##### RDS

Univer が使用する Temporal は gaussdb / damengDB をサポートしていません。これらを利用する場合、Temporal 用に専用 PostgreSQL をインストールします。Temporal DB に保存されるのはインポート/エクスポートのプロセス状態であり、ドキュメントデータには影響しません。失われても未完了タスクが失敗するだけで、それ以外の影響はありません。

###### PostgreSQL 互換 RDS を利用

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"

    DISABLE_UNIVER_RDS=true # When using your own RDS, prevent Univer deploying the default postgresql

    DATABASE_DRIVER=postgresql # Set to postgresql to use a postgresql-compatible database
    DATABASE_HOST=your-database-host
    DATABASE_PORT=your-database-port
    DATABASE_DBNAME=univer # The default name used by Univer's database initialization script, update here if you have changed it
    DATABASE_USERNAME=postgres # You should grant this user select, insert, update, delete permissions
    DATABASE_PASSWORD=password
    ```

  <Tab label="K8s">

    ```yaml title="values.yaml"
                password: postgres

            visibility:
              driver: sql
              sql:
                driver: postgres12 # PostgreSQL requires version 12 or higher.
                host: your-database-host
                port: your-database-port
    ```

##### Redis

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    # redis config
    DISABLE_UNIVER_REDIS=true # When using your own Redis, prevent Univer deploying the default redis

    # if you use redis cluster, use comma ',' to separate multiple addresses
    # for example: REDIS_ADDR=192.168.1.5:6001,192.168.1.5:6002,192.168.1.5:6003

    REDIS_USERNAME=user-name
    REDIS_PASSWORD=password

    # Support three modes: insecure, CA verification only, and client certificate (mTLS) verification.

    REDIS_TLS_INSECURE=false

    REDIS_TLS_CERT=
    REDIS_TLS_KEY=
    ```

  <Tab label="K8s">

    ```yaml title="values.yaml"
          write_timeout: 1s

          password: password_here

            cert: ''
            key: ''

        write_timeout: 1s

        password: password_here

          enabled: false
    ```

##### MQ

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    DISABLE_UNIVER_MQ=true # When using your own MQ, prevent Univer deploying the default MQ

    RABBITMQ_CLUSTER_ENABLED=true # Must be set to true
    RABBITMQ_CLUSTER_USERNAME=user-name # need grant Declear Exchange、Produce、Consume to the user
    RABBITMQ_CLUSTER_PASSWORD=password # password

    # use comma to separate multiple addresses
    # for example: RABBITMQ_CLUSTER_ADDR=192.168.1.2:5672,192.168.1.5:5672,192.168.1.7:5672
    # Each addr must be able to Consume and Produce. Univer will poll these host when connecting, until the connection is successful
    RABBITMQ_CLUSTER_ADDR=host:port[,host:port]

    # RABBITMQ_CLUSTER_VHOST is the vhost of the rabbitmq cluster. If you don't set it, the default value is /
    # for example: RABBITMQ_CLUSTER_VHOST=univer
    RABBITMQ_CLUSTER_VHOST=/
    RABBITMQ_CLUSTER_SCHEMA=amqp
    ```
  </Tab>
  <Tab label="K8s">
    ```yaml title="values.yaml"

            # Each addr must be able to Consume and Produce. Univer will poll these host when connecting, until the connection is successful
            addr: '192.168.1.2:5672,192.168.1.5:5672'
            username: user-here
            password: password-here
            vhost: /
            schema: amqp

      enabled: false # When using your own MQ, prevent Univer deploying the default MQ
    ```

#### 共同編集の階層スケジューリング設定

`v0.15.0` 以降、階層スケジューリングが導入されました。デフォルトでは無効のため、手動設定が必要です。現在はワークブックの総セル数とインポート実時間で、対象の協調サービスクラスタを決定します。インポートで作成されたワークブックは実際のインポート時間で判定し、それ以外の作成や新規スナップショット時には総セル数で判定します。スナップショット作成後、関連メトリクスが DB に永続化され、スケジュール対象が更新されます。

階層スケジューリングは、複数クラスタに協調サービスをデプロイし、どのサイズのワークブックをどのクラスタで処理するかのルールを定義する仕組みです。設定構造は以下のとおりです:

```yaml
unitRoutingConf:
  tiers:
    - tierName: normal
      enable: true
      upgradeCellsThreshold: 0
      downgradeCellsThreshold: 0
      upgradeImportTimeThreshold: 0
    - tierName: large
      enable: true
      upgradeCellsThreshold: 1000
      downgradeCellsThreshold: 900
      upgradeImportTimeThreshold: 10
    - tierName: huge
      enable: true
      upgradeCellsThreshold: 10000
      downgradeCellsThreshold: 9000
      upgradeImportTimeThreshold: 60
```

設定パラメータの説明:

- `tiers`: 各クラスタの定義。理論上は任意の数のクラスタを設定可能
- `enable`: クラスタの有効化フラグ。`false` の場合は無視される
- `upgradeCellsThreshold`: このクラスタにスケジュールするための最小セル数
- `downgradeCellsThreshold`: 既にこのクラスタに割り当て済みの場合、セル数がこの閾値を下回ったときのみ下位クラスタへ降格する（境界付近の頻繁な切替を防ぐ）
- `upgradeImportTimeThreshold`: インポート直後などセル数未確定の場合、実際のインポート時間で判断。`upgradeCellsThreshold` と同様の仕組み

少なくとも 1 つのクラスタは全閾値を 0 に設定し、すべてのシートが必ずどこかのクラスタに割り当てられるようにしてください。

上記設定例に基づくスケジュール例:

- workbook w1 がセル数 0 で作成 → normal クラスタに割り当て
- w1 のセル数が 1000 → large クラスタへ昇格
- w1 のセル数が 999 → downgrade 閾値 900 を上回るため large のまま
- w1 のセル数が 899 → normal に降格
- workbook w2 をインポートし、所要時間 61 秒 → huge 閾値 60 秒を超えるため huge に割り当て

Univer の Docker Compose デプロイでは、単一階層または 2 階層（通常サイズ/大サイズ）のクラスタをデプロイできます。`ENABLE_LARGE_TIER_COLLABORATION_SERVER` が大サイズ階層クラスタの利用有無を制御し、Docker Compose が実際に大サイズクラスタをデプロイするかどうかも決定します。

より細かい階層制御が必要、または K8s デプロイする場合は、Docker Compose ファイルまたは Helm チャートを調整して対応する collaboration-server クラスタをデプロイし、上記ルールに基づいてルーティングテーブル（`unitRoutingConf.tiers` 配列）を設定してください。

Univer 提供の Docker Compose 設定をそのまま使う場合は、以下のパラメータで調整できます:

- 第 2 階層（大サイズ階層）クラスタの有効/無効
- 大サイズシートの判定基準

## 本番デプロイ SOP

必要な設定を決めたら、以下の手順で Univer バックエンドサービスをデプロイします。

### Docker でデプロイする SOP [#deploy-to-docker-compose]

1. `.env.custom` を準備（変更がなければ省略可）
2. `license.txt` と `licenseKey.txt` を準備
3. 独自 RDS を使う場合は、[DB 初期化スクリプト](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz) をダウンロードして RDS（universer/temporal）を初期化。gaussdb / damengdb の場合は temporal の初期化は不要です。
4. Univer バックエンドサービスを取得
   - サーバーがインターネットにアクセス可能な場合
     - `bash -c "$(curl -fsSL https://get.univer.ai/product)" [-- version]` を実行し、指定バージョンをダウンロード（未指定なら最新）
   - インターネットにアクセスできない場合
     - [こちら](https://univer.ai/releases/univer-server/download) から All-in-one オフラインパッケージをダウンロード
     - サーバーへアップロードして解凍
     - 解凍ディレクトリで `bash load-images.sh` を実行し、Docker にイメージを読み込み
5. `.env.custom` をバックエンドサービスフォルダへコピーし、`.env` と同じディレクトリに配置
6. `license.txt` と `licenseKey.txt` を `configs/` 配下にコピー
7. バックエンドサービスのルートディレクトリで `bash run.sh start` を実行し、Univer サービスを起動
8. 動作確認を行う

### K8s でデプロイする SOP [#deploy-to-k8s]

K8s デプロイでは、カスタム設定変更がある場合に `values.yaml` のバージョン管理が必要です。後続のアップグレードでも完全なカスタム設定が求められるため、git などで管理することを推奨します。

1. `values.yaml` を準備（変更がなければ省略可）
2. `license.txt` と `licenseKey.txt` を準備
3. 独自 RDS を使う場合は、[DB 初期化スクリプト](https://release-univer.oss-cn-shenzhen.aliyuncs.com/releases/latest/univer-server-sql-latest.tar.gz) をダウンロードして RDS（universer/temporal）を初期化。gaussdb / dameng の場合は temporal 初期化は不要です。
4. `values.yaml` とライセンスファイルを使って Helm でインストール
   - デプロイサーバーがインターネットにアクセス可能な場合:
     - 次のコマンドでインストール:
        ```shell
        helm install -n univer --create-namespace \
            -f your-own-values.yaml-path \
            --set global.istioNamespace="univer" \
            --set-file universer.license.licenseV2=your-license.txt-path \
            --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
            univer-stack \
            oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
            --version target-version

        # After successful execution, execute the following two commands to restart the services and complete the sidecar injection
        kubectl rollout restart -n univer deployment/collaboration-server
        kubectl rollout restart -n univer deployment/universer
        ```
     - Univer が用意した可観測性コンポーネントをデプロイする場合は、以下を実行:
        ```bash
        helm upgrade --install -n univer-observability --create-namespace \
            --set global.univerNamespace="univer" \
            univer-observability \
            oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-observability
        ```

        パラメータ説明:

        - `--set global.univerNamespace="univer"`: 観測対象のクラスタを "univer" に設定
   - デプロイサーバーがインターネットにアクセスできない場合:
     - [こちら](https://univer.ai/releases/univer-server/download) から K8s All-in-one オフラインパッケージをダウンロード
     - サーバーへアップロードして解凍
     - 解凍ディレクトリでイメージを読み込み:
        ```shell
        export REGISTER=XXXX # Your private image register
        export NAMESPACE=XXX # The namespace where image save
        docker login $REGISTER
        bash load-image.sh --registry $REGISTER --namespace $NAMESPACE
        ```
     - 読み込み後、カレントディレクトリに `values.yaml` と `values-observability.yaml` が生成されるので、必要に応じて編集
       - values.yaml: Univer サービス設定
       - values-observability.yaml: 可観測性コンポーネント設定
     - 次のコマンドでインストール:
        ```shell
        helm install -n univer --create-namespace \
            -f your-own-values.yaml-path \
            --set global.istioNamespace="univer" \
            --set-file universer.license.licenseV2=your-license.txt-path \
            --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path \
            univer-stack \
            univer-stack-xxxx.tgz # should change to the right chart name

        # After successful execution, execute the following two commands to restart the services and complete the
        kubectl rollout restart -n univer deployment/collaboration-server
        kubectl rollout restart -n univer deployment/universer
        ```
     - Univer の可観測性コンポーネントをデプロイする場合は次のコマンドを実行:
        ```bash
        helm upgrade --install -n univer-observability --create-namespace \
            --set global.univerNamespace="univer" \
            -f your-own-values-observability.yaml-path \
            univer-observability \
            univer-observability-xxxx.tgz
        ```

        パラメータ説明:

        - `--set global.univerNamespace="univer"`: 観測対象のクラスタを "univer" に設定

パラメータ説明:

- `-n univer`：namespace を univer に指定。変更可能だが将来のアップグレード時に必要
- `univer-stack`：Helm release 名。変更可能だが将来のアップグレード時に必要
- `--version target-version`：デプロイするバージョン。ターゲットに合わせて変更し、最新を使う場合は省略
- `-f your-own-values.yaml-path`：カスタム `values.yaml` のパスを指定
- `--set-file universer.license.licenseV2=your-license.txt-path`：解凍後の `license.txt` パスを指定
- `--set-file universer.license.licenseKeyV2=your-licenseKey.txt-path`：解凍後の `licenseKey.txt` パスを指定

5. 動作確認を行う
