---
title: Intégration d’USIP
---

Par défaut, Univer Pro n’intègre pas de système de comptes. Si vous avez besoin de vérifier les identités, de contrôler les autorisations ou d’intégrer votre système, utilisez USIP (Univer Server Integration Protocol). USIP est une SPI : Univer définit les interfaces et votre système les implémente.

## Cas d’utilisation

- Exiger une connexion pour accéder au contenu
- Gérer les autorisations de modification selon le rôle
- Synchroniser les informations des collaborateurs, les commentaires et l’heure de modification

## Processus d’intégration

1. Implémentez les API USIP (voir ci-dessous)
2. Activez USIP dans la configuration du déploiement
3. Transmettez les en-têtes d’authentification depuis le client (par exemple, le token)

## API USIP

USIP couvre actuellement trois catégories :

- 👥 Comptes : vérification de l’identité et informations utilisateur
- 🔒 Autorisations : rôles et collaborateurs
- 📄 Documents : heure de la dernière modification

## Configurer USIP [#usip-configuration]

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    USIP_ENABLED=true
    USIP_URI_CREDENTIAL=https://your-domain/usip/credential
    USIP_URI_USERINFO=https://your-domain/usip/userinfo
    USIP_URI_ROLE=https://your-domain/usip/role
    USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
    USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

    USIP_APIKEY=

    AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
    AUTH_PERMISSION_CUSTOMER_STRATEGIES=
    ```
  </Tab>
  <Tab label="K8s">
    ```yaml title="values.yaml"
    universer:
      config:
        usip:
          enabled: true
          uri:
            userinfo: 'https://your-domain/usip/userinfo'
            collaborators: 'https://your-domain/usip/collaborators'
            role: 'https://your-domain/usip/role'
            credential: 'https://your-domain/usip/credential'
            unitEditTime: 'https://your-domain/usip/unit-edit-time'
          apikey: ''
        auth:
          permission:
            enableObjInherit: false
            customerStrategies: ''
    ```
  </Tab>
</Tabs>

**Remarque** : lorsque USIP est activé, les cinq points de terminaison doivent être configurés et implémentés.

Si votre service USIP est accessible sur le réseau public, vous pouvez adopter un mécanisme similaire à celui des requêtes d’API d’IA pour sécuriser les requêtes. Générez une clé d’API et configurez-la sur le serveur Univer. Lors des appels aux API USIP, la requête inclura l’en-tête x-api-key: API_KEY, que vous pourrez utiliser pour vérifier sa légitimité.

## Modèle d’autorisations

Univer utilise un contrôle d’accès par rôles (RBAC) avec des rôles fixes : `owner`, `editor`, `reader`. Vous pouvez remplacer le rôle minimal requis pour chaque point d’autorisation.

Pour réserver la copie et l’impression aux propriétaires :

```properties title=".env.custom"
AUTH_PERMISSION_CUSTOMER_STRATEGIES=[{"action": 3, "role": 2}, {"action": 6, "role": 2}]
```

Configuration K8s :

```yaml title="values.yaml"
universer:
  config:
    auth:
      permission:
        customerStrategies: '[ {"action": 3, "role": 2}, {"action": 6, "role": 2} ]'
```

### Héritage des autorisations des objets

Par défaut, le propriétaire d’un document ne dispose pas automatiquement des autorisations de propriétaire sur toutes les « zones protégées/sous-tables » de ce document. Pour accorder sans condition au propriétaire du document toutes les autorisations sur l’ensemble de ses sous-objets, vous pouvez activer l’héritage des autorisations avec les paramètres suivants :

```properties title=".env.custom"
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=true
```

Configuration K8s :

```yaml title="values.yaml"
universer:
  config:
    auth:
      permission:
        enableObjInherit: true
```

## En-têtes du client

Si vous devez ajouter des en-têtes personnalisés (par exemple, un token Authorization), utilisez les intercepteurs HTTPService :

<Tabs items={['Preset', 'Plugin']}>
  <Tab>
    ```typescript
    import { HTTPService } from '@univerjs/preset-sheets-core'

    const injector = univer.__getInjector()
    const httpService = injector.get(HTTPService)
    httpService.registerHTTPInterceptor({
      priority: 0,
      interceptor: (request, next) => {
        // request.headers.set('Authorization', 'Bearer your-token-here')
        return next(request)
      },
    })
    ```
  </Tab>
  <Tab>

  </Tab>
</Tabs>

Si vous utilisez l’[historique des modifications](/guides/sheets/features/edit-history), appliquez le même intercepteur à HistoryUniver :

```typescript
historyLoaderService.historyUniver$.subscribe((historyUniver) => {
  if (!historyUniver) return

  const injector = historyUniver.__getInjector()
  const httpService = injector.get(HTTPService)
  httpService.registerHTTPInterceptor({
    priority: 0,
    interceptor: (request, next) => {
      // request.headers.set('Authorization', 'Bearer your-token-here')
      return next(request)
    },
  })
})
```
