---
title: Downtime-Upgrade SOP
---

Diese Seite bietet eine Referenz-SOP für Ausfallzeit-Upgrades. Passen Sie es bei Bedarf an Ihre Produktionsstandards an.

## Docker Compose Upgrade

### Vorbereitung

- Wählen Sie die Zielversion und überprüfen Sie die Konfigurationsänderungen in [Produktionsbereitstellung](/guides/pro/deploy)
- Bereiten Sie ein neues `.env.custom` vor (behalten Sie das alte für Rollback bei)
- Bereiten Sie Lizenzdateien vor
- Benachrichtigen Sie Benutzer über das Wartungsfenster

### Upgrade-Schritte

<Steps>
  <Step>
    #### Schreibvorgänge blockieren und alte Version stoppen

Blockieren Sie neue Anfragen, um Dateninkonsistenzen zu vermeiden.

Bearbeiten Sie `universer-old/nginx/universer.conf` und fügen Sie hinzu:

    ```nginx
    location ~ ^/universer-api {return 403;}
    ```

Nginx neu laden:

    ```bash
    docker exec univer-lb nginx -s reload
    ```

Warten Sie mindestens 1 Minute und stoppen Sie dann die alten Dienste:

    ```bash
    cd universer-old && bash run.sh stop
    ```
  </Step>
  <Step>
    #### Datensicherung

Sichern Sie RDS-Metadaten (Objektspeicherung nur anhängen; Sicherung bei Bedarf).
  </Step>
  <Step>
    #### Neue Version bereitstellen

    - Laden Sie die Zielversion herunter (online oder offline)
    - Kopieren Sie die neue `.env.custom`
    - Platzieren Sie die Lizenzdateien unter `configs/`
    - Wenn Sie selbstverwaltetes RDS verwenden, führen Sie DB-Upgrade-Skripts aus

Um nur Testkonten zuzulassen, fügen Sie zu `nginx/universer.conf` hinzu:

    ```nginx title="/nginx/universer.conf"
    underscores_in_headers on;
    if ($http_x_request_env != "test") {
      return 403;
    }
    ```

Starten Sie die neue Version:

    ```bash
    bash run.sh start
    ```
  </Step>
</Steps>

### Nach dem Upgrade Validierung

- Schlüsselflüsse mit `x-request-env=test` überprüfen
- Protokolle und Metriken überwachen

### Umstellung

Header-Einschränkung entfernen und Nginx neu laden:

```bash
docker exec univer-lb nginx -s reload
```

### Rollback

- Neue Version stoppen
- Alte Nginx-Konfiguration wiederherstellen
- Alte Version starten

## K8s Upgrade

### Vorbereitung

- Bereiten Sie ein neues `values.yaml` vor (behalten Sie das alte)
- Bereiten Sie Lizenzdateien vor
- Benachrichtigen Sie Benutzer über das Wartungsfenster

### Upgrade-Schritte

<Steps>
  <Step>
    #### Blockieren Sie den Zugriff auf die alte Version

Deaktivieren Sie den Zugriff in der alten Konfiguration:

    ```yaml title="values.yaml"
    universer:
      ingress:
        enabled: false
    ```

Wenden Sie es mit der aktuellen Diagrammversion an:

    ```bash
    helm upgrade univer-stack \
      oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
      --version your-current-version \
      -n univer \
      -f values-1.0.0-forbid.yaml \
      --set-file universer.license.licenseV2=your-license.txt-path \
      --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path
    ```

Suchen Sie das aktuelle Diagramm Version über `helm list --all-namespaces --filter univer-stack`.
  </Step>
  <Step>
    #### Datensicherung

RDS-Metadaten sichern.
  </Step>
  <Step>
    #### Upgrade auf neue Version

Um nur Testbenutzer zuzulassen, fügen Sie die neue Konfiguration hinzu:

    ```yaml title="values.yaml"
    universer:
      ingress:
        enabled: true
        annotations:
          nginx.ingress.kubernetes.io/configuration-snippet: |
            if ($http_x_request_env != "test") {
              return 403;
            }
    ```

Upgrade:

    ```bash
    helm upgrade --install univer-stack \
      oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
      --version target-version \
      -n univer \
      -f your-values.yaml-path \
      --set-file universer.license.licenseV2=your-license.txt-path \
      --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path
    ```

Für Offline-Szenarien verwenden Sie das Offline-Paket und führen Sie `bash load-image.sh` aus.
  </Step>
</Steps>

### Post-Upgrade-Validierung & Umstellung

- Mit Testkonto validieren
- Eingangsbeschränkung entfernen und erneut anwenden

### Rollback

Verwenden Sie die alte Diagrammversion und -konfiguration:

```bash
helm upgrade --install univer-stack \
  oci://univer-acr-registry.cn-shenzhen.cr.aliyuncs.com/helm-charts/univer-stack \
  --version old-version \
  -n univer \
  -f old-values.yaml \
  --set-file universer.license.licenseV2=your-license.txt-path \
  --set-file universer.license.licenseKeyV2=your-licenseKey.txt-path
```
