title: USIP 통합
---

Univer Pro에는 기본적으로 계정 시스템이 포함되어 있지 않습니다. 신원 확인, 권한 제어 또는 시스템 통합이 필요한 경우 USIP(Univer Server Integration Protocol)를 사용하세요. USIP는 SPI로, Univer가 인터페이스를 정의하고 사용자의 시스템이 이를 구현합니다.

## 사용 사례

- 로그인 후 접근 허용
- 역할 기반 편집 권한
- 공동 작업자 정보, 댓글 및 편집 시간 동기화

## 통합 절차

1. USIP API 구현(아래 내용 참조)
2. 배포 구성에서 USIP 활성화
3. 클라이언트에서 인증 헤더 전달(예: 토큰)

## USIP API

현재 USIP는 다음 세 가지 범주를 지원합니다.

- 👥 계정: 신원 확인, 사용자 정보
- 🔒 권한: 역할 및 공동 작업자
- 📄 문서: 마지막 편집 시간

## USIP 구성 [#usip-configuration]

<Tabs items={['docker compose', 'K8s']}>
  <Tab label="docker compose">
    ```properties title=".env.custom"
    USIP_ENABLED=true
    USIP_URI_CREDENTIAL=https://your-domain/usip/credential
    USIP_URI_USERINFO=https://your-domain/usip/userinfo
    USIP_URI_ROLE=https://your-domain/usip/role
    USIP_URI_COLLABORATORS=https://your-domain/usip/collaborators
    USIP_URI_UNITEDITTIME=https://your-domain/usip/unit-edit-time

    USIP_APIKEY=

    AUTH_PERMISSION_ENABLE_OBJ_INHERIT=false
    AUTH_PERMISSION_CUSTOMER_STRATEGIES=
    ```
  </Tab>
  <Tab label="K8s">
    ```yaml title="values.yaml"
    universer:
      config:
        usip:
          enabled: true
          uri:
            userinfo: 'https://your-domain/usip/userinfo'
            collaborators: 'https://your-domain/usip/collaborators'
            role: 'https://your-domain/usip/role'
            credential: 'https://your-domain/usip/credential'
            unitEditTime: 'https://your-domain/usip/unit-edit-time'
          apikey: ''
        auth:
          permission:
            enableObjInherit: false
            customerStrategies: ''
    ```
  </Tab>
</Tabs>

**참고**: USIP를 활성화하면 엔드포인트 다섯 개를 모두 구성하고 구현해야 합니다.

USIP 서비스가 공용 네트워크에 노출된 경우 API 요청의 보안을 위해 AI API 요청과 유사한 메커니즘을 사용할 수 있습니다. API 키를 생성하여 Univer 서버에 구성하세요. USIP API를 호출하면 요청에 x-api-key: API_KEY 헤더가 포함되며, 이 헤더를 사용해 요청의 유효성을 확인할 수 있습니다.

## 권한 모델

복사와 인쇄를 소유자에게만 허용하려면 다음과 같이 설정합니다.

```properties title=".env.custom"
AUTH_PERMISSION_CUSTOMER_STRATEGIES=[{"action": 3, "role": 2}, {"action": 6, "role": 2}]
```

K8s 구성:

```yaml title="values.yaml"
universer:
  config:
    auth:
      permission:
        customerStrategies: '[ {"action": 3, "role": 2}, {"action": 6, "role": 2} ]'
```

### 객체 권한 상속

기본적으로 문서 소유자에게 해당 문서 내의 모든 "보호된 영역/하위 테이블"에 대한 소유자 권한이 자동으로 부여되지는 않습니다. 문서 소유자에게 문서 내 모든 하위 객체에 대한 전체 권한을 조건 없이 부여하려면 다음 설정을 구성하여 권한 상속을 활성화할 수 있습니다.

```properties title=".env.custom"
AUTH_PERMISSION_ENABLE_OBJ_INHERIT=true
```

K8s 구성:

```yaml title="values.yaml"
universer:
  config:
    auth:
      permission:
        enableObjInherit: true
```

## 클라이언트 헤더

사용자 지정 헤더(예: Authorization 토큰)를 추가해야 하는 경우 HTTPService 인터셉터를 사용하세요.

<Tabs items={['프리셋', '플러그인']}>
  <Tab>
    ```typescript
    import { HTTPService } from '@univerjs/preset-sheets-core'

    const injector = univer.__getInjector()
    const httpService = injector.get(HTTPService)
    httpService.registerHTTPInterceptor({
      priority: 0,
      interceptor: (request, next) => {
        // request.headers.set('Authorization', 'Bearer your-token-here')
        return next(request)
      },
    })
    ```
  </Tab>
  <Tab>

    import { HTTPService } from '@univerjs/network'

      priority: 0,

</Tabs>

[편집 기록](/guides/sheets/features/edit-history)을 사용하는 경우 HistoryUniver에도 같은 인터셉터를 적용하세요.

```typescript
historyLoaderService.historyUniver$.subscribe((historyUniver) => {
  if (!historyUniver) return

  const injector = historyUniver.__getInjector()
  const httpService = injector.get(HTTPService)
  httpService.registerHTTPInterceptor({
    priority: 0,
    interceptor: (request, next) => {
      // request.headers.set('Authorization', 'Bearer your-token-here')
      return next(request)
    },
  })
})
```

전체 예제는 [Univer Pro Sheet 스타터 키트](https://github.com/dream-num/univer-pro-sheet-start-kit/blob/main/src/setup-univer.ts)를 참조하세요.
