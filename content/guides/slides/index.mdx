## What is Univer Slides

Univer Slides is the presentation product in Univer Office SDK. It supports building slide deck editors, presentation viewers, and import and export flows, and it can process slides on the server through the Web SDK runtime.

Slides run on [Web SDK](/guides/sheets), which provides both the browser editor and headless processing on the server. [Server SDK](/server) adds collaboration and file exchange, and [AI SDK](/ai) covers agent workflows.

Slides is an independent Web SDK unit type. At runtime you create a unit of type `UniverInstanceType.UNIVER_SLIDE` and then register the model, UI, and optional feature plugins that match the capabilities you need.

<Callout type="info">
  Univer Slides is published under the `@univerjs-pro` package scope. Licensed features require a [client license](/server/license). Add [Univer Server SDK](/server) when your application needs collaboration or file conversion.
</Callout>

## Browser Compatibility

Web SDK compiles with a Chrome 88 target, but compilation alone does not guarantee support for every mainstream environment. Web SDK is intended to work in the browsers and Node.js versions listed below:

| Edge | Firefox | Chrome | Safari | Electron |
| ---- | ------- | ------ | ------ | -------- |
| >=88 | >=90    | >=88   | >=14.1 | >=12     |

<Callout type="warning">
  Web SDK relies on `Intl.Segmenter`. If the browser or runtime environment does not support it, add the matching polyfill first. `@formatjs/intl-segmenter` is recommended.
</Callout>

If a compatibility problem occurs, apply the matching polyfill first. If the problem persists, [open an issue](https://github.com/dream-num/univer/issues/new/choose).

## Node.js Compatibility

<Callout type="warning">
  This covers only running Web SDK directly in Node.js. It does not apply when a Node.js-based build tool bundles Web SDK for the browser.
</Callout>

Web SDK runs in Node.js v18.17.0 and later.

## Highlights

- The presentation model tracks presentation identity, page size, slide order, slides, master pages, layout pages, themes, transitions, and resources.
- Rendering and editing cover the slide canvas, thumbnails, selection, the clipboard, text and shape editing, alignment guides, and playback.
- Page and element changes go through commands and mutations, which keeps model updates, rendering, and undo and redo synchronized.
- The Facade API creates and finds presentations, saves snapshots, and exposes slide and element operations through application-facing objects.
- Optional features such as tables, charts, printing, and import/export stay outside the core stack.

## Pre-Requisite Knowledge

The documentation is written for newcomers, but it assumes a baseline so that the content can stay focused on Web SDK. Readers should know JavaScript and its ecosystem; basic Node.js knowledge is also useful when Web SDK will run on Node.js.

When several people need to edit the same slides, or an application needs shared history, comments, or file conversion, add the corresponding modules from [Univer Server SDK](/server) to the backend. Authentication, permissions, storage, and deployment remain the responsibility of the application. Editing in the browser alone requires none of these services.
