Permettez à plusieurs utilisateurs de modifier le même diaporama et de voir leurs changements respectifs. Suivez l’[intégration collaborative](/server/collaboration/browser-integration) pour connecter le backend, l’authentification, les autorisations et le stockage, puis configurez la [licence](/server/license).

## Configurer et charger un document

Ajoutez la configuration du client Collaboration à votre éditeur Slides existant en suivant le [démarrage rapide Office](/server/collaboration/quick-start). Cet exemple utilise Sheets ; votre backend doit créer et conserver un document Slides, puis renvoyer son ID au navigateur.

```ts
import '@univerjs-pro/slides/facade'
import '@univerjs-pro/collaboration-client/facade'

const document = await univerAPI.getCollaboration().loadSlideAsync('your-document-id')
if (!document) throw new Error('Document could not be loaded')
```

Réutilisez le même ID pour rouvrir ou partager le document. Ne créez pas un document local vierge à la place du chargement du document serveur.

## Vérifier la synchronisation et les autorisations

Ouvrez le même ID dans deux sessions de navigateur indépendantes. Modifiez du texte ou déplacez un élément dans une session et vérifiez l’autre. Assurez-vous que le contenu persiste après rechargement de la page, reconnexion et redémarrage du service. Utilisez un compte lecteur et un compte non autorisé pour vérifier que le serveur refuse les écritures et lectures interdites.

L’[historique des modifications](/guides/slides/features/edit-history) et l’[import-export](/guides/slides/features/import-export) nécessitent une configuration distincte ; la collaboration ne les active pas automatiquement.
