修改幻灯片文字、形状或页面顺序后，可以打开历史记录查看之前的版本、比较变化，并在有权限时恢复某个版本。历史记录读取服务端保存的版本。撤销和重做只作用于当前编辑会话，不需要历史服务，也无法替代历史记录。

## 先准备协同和历史服务

先按[协同集成](/server/collaboration/browser-integration)连接编辑器，完成[许可证配置](/server/license)，再确认两个会话可以编辑同一份 Slides 文档，并且刷新后内容仍然保留。

按 [Office 协同扩展模块](/server/collaboration/extensions)和 [History 示例](/server/collaboration/examples#history)接入历史存储和权限。核心协同不会自动启用历史记录，后端还需要支持历史列表、版本内容和恢复操作。

## 添加历史记录插件

将以下注册代码加入已有的产品、许可证和协同配置。如果预设或现有配置已经注册了这些插件，修改该配置，不要重复注册。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/slides-history @univerjs-pro/slides-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/zh-CN'
import { UniverSlidesHistoryPlugin } from '@univerjs-pro/slides-history'
import { UniverSlidesHistoryUIPlugin } from '@univerjs-pro/slides-history-ui'
import HistoryLocale from '@univerjs-pro/slides-history-ui/locale/zh-CN'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.ZH_CN, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSlidesHistoryPlugin)
univer.registerPlugin(UniverSlidesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 插件配置

`UniverEditHistoryPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的基础 URL。 |

`UniverSlidesHistoryUIPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的基础 URL。 |
| `univerContainerId` | `string` |  | 编辑器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 为历史版本查看器追加的插件。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 插件构造函数。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 该构造函数接受的配置项。 |

将 `/api/history` 替换为应用实际的历史接口，并确认该接口能够响应客户端发送的请求。两个 `historyServerUrl` 必须一致。`univerContainerId` 填写编辑器容器的 DOM ID，加载的语言包应与编辑器当前语言一致。

历史查看器会启动一个独立的只读编辑器。如果内容需要查看器未内置的插件，通过 `viewerPlugins` 添加，不要重复注册内置插件。

## 查看和恢复版本

从编辑器菜单打开历史记录，选择一个版本，查看其内容和变化。恢复版本会改写当前共享文档，因此只有拥有恢复权限的用户才能执行，并且服务端必须强制校验该权限。

验证接入时，修改幻灯片文字、形状或页面顺序，等待协同确认，然后查看历史列表和版本内容。重新打开应用并重启服务，确认版本仍然存在。恢复一个旧版本，再确认另一个浏览器会话收到恢复后的状态。

如果列表为空，先确认该文档是否记录了历史，再核对文档 ID 和服务地址。如果版本可以查看但恢复失败，检查恢复权限和协同连接。读取历史同样需要授权，因为旧版本可能包含后来已删除的数据。

## 比较快照 [#compare-snapshots]

如果需要构建审阅界面，或将变更交给 AI Agent，可以调用 `compareUnitData()`，也可以使用 `prepareUnitComparison()` 先准备一次比较。先注册该文档类型的 History 插件并导入 Facade 入口，然后将同一个 unit 的两份完整快照分别传给 `beforeSnapshot` 和 `afterSnapshot`。该比较是只读的，不需要历史服务，也不会恢复或合并内容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SLIDE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` 列出可用的视图。将其中一个传给 `query()`，可以在不重新执行比较的情况下筛选结果。每页默认返回 100 项，最多接受 1,000 项。结合 `page.hasMore` 和 `offset` 可以读取其余条目。即使筛选了条目，`summary` 仍然描述整个比较。将结果视为完整比较之前，先检查 `diagnostics.readiness` 和 `diagnostics.codes`。无需编辑器的 Node.js 或 CLI 用法，参见[无界面比较 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
