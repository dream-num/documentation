Registrar los plugins de comentarios después de que el editor de productos y la licencia se configuran. Carga los estilos compartidos y de producto UI y recursos locales. El plugin de producto posee sus recursos de comentario, por lo que una instantánea se puede restaurar sólo después de que se registra ese plugin.

```package-install
npm install @univerjs/thread-comment @univerjs/thread-comment-ui @univerjs-pro/slides-thread-comment @univerjs-pro/slides-thread-comment-ui
```

```ts
import { UniverSlidesThreadCommentPlugin } from '@univerjs-pro/slides-thread-comment'
import { UniverSlidesThreadCommentUIPlugin } from '@univerjs-pro/slides-thread-comment-ui'
import ProductLocale from '@univerjs-pro/slides-thread-comment-ui/locale/es-ES'
import { LocaleType, mergeLocales } from '@univerjs/core'
import SharedLocale from '@univerjs/thread-comment-ui/locale/es-ES'

import '@univerjs/thread-comment-ui/lib/index.css'
import '@univerjs-pro/slides-thread-comment-ui/lib/index.css'

univerAPI.loadLocales(LocaleType.ES_ES, mergeLocales(SharedLocale, ProductLocale))
univer.registerPlugin(UniverSlidesThreadCommentPlugin)
univer.registerPlugin(UniverSlidesThreadCommentUIPlugin)
```

## Compatibilidad móvil [#mobile-support]

Configure el [editor móvil](/guides/slides/getting-started/installation#mobile-support) primero. En la configuración de modo plugin descrito en esta página, sustitúyase los registros de escritorio a continuación con las exportaciones móviles de los mismos paquetes, y haga el reemplazo **antes de abrir un documento**. Mantenga los plugins modelo, estilos, locales y las importaciones Facade, y no registre ambas variantes.

| Paquete | Registro de escritorio | Registro móvil |
| --- | --- | --- |
| `@univerjs-pro/slides-thread-comment-ui` | `UniverSlidesThreadCommentUIPlugin` | `UniverSlidesThreadCommentMobileUIPlugin` |

## Facade de comentarios [#comment-facade]

Importar el comentario compartido Facade y el producto Facade antes de llamar estos métodos. Los ayudantes del producto crean anclas estables, y la API compartida maneja respuestas, actualizaciones, resolución y eliminación. `getComments()` lee el estado local. `listCommentsAsync()` sincroniza los hilos que ya conoce a través de la fuente de datos configurada, pero no descubre cada hilo en el servidor.

```ts
import '@univerjs/thread-comment/facade'
import '@univerjs-pro/slides-thread-comment/facade'

const element = univerAPI.getActivePresentation()?.getSlideByIndex(0)?.getElements()[0]
if (element) {
  await element.createCommentAsync('Please review this element.')
  console.log(await element.listCommentsAsync())
}
```

```ts
import '@univerjs/thread-comment/facade'

const [thread] = univerAPI.getComments({ resolved: false })
if (thread) {
  await univerAPI.replyCommentAsync({
    unitId: thread.unitId,
    subUnitId: thread.subUnitId,
    threadId: thread.threadId,
    content: 'Reviewed.',
  })
}
```

## Conversaciones compartidas [#shared-discussions]

Los debates compartidos requieren que el servicio de comentarios y el punto final estén conectados a través de [Server SDK](/server/collaboration/extensions). Después de la configuración de la colaboración y la licencia, regístrese `UniverThreadCommentDataSourcePlugin` de `@univerjs-pro/thread-comment-datasource`. La fuente de datos suministrada llama `/universer-api/comment/unit/{unitId}/...` y `/universer-api/user/list`, por lo que la aplicación debe exponer esas rutas.
