Después de editar texto de diapositivas, formas o orden de diapositivas , historia abierta para inspeccionar versiones anteriores , comparar cambios , y restaurar una versión cuando el permiso permite . Historia lee las versiones que el servidor almacena . Deshacer y redo se aplican sólo a la sesión de edición actual y no requieren un servicio de historia .

## Preparar los servicios de colaboración e historial

Comience con [integración de la colaboración](/server/collaboration/browser-integration) y [configuración de licencias](/server/license). Verifique que dos sesiones pueden editar el mismo documento de diapositivas y que los cambios sobreviven a una recarga.

Conectar el almacenamiento de historia y los permisos a través de [Ampliación de la colaboración de las oficinas](/server/collaboration/extensions) y [Ejemplo de historia](/server/collaboration/examples#history). La colaboración básica no permite la historia por sí misma. El backend también debe apoyar listas de historia, contenido de versiones y restauración.

## Añadir los plugins de historial

Agregue las siguientes inscripciones al producto existente, licencia y configuración de colaboración. Si un preset o una configuración existente ya registra estos plugins, modifique esa configuración en lugar de registrarlos por segunda vez.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/slides-history @univerjs-pro/slides-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSlidesHistoryPlugin } from '@univerjs-pro/slides-history'
import { UniverSlidesHistoryUIPlugin } from '@univerjs-pro/slides-history-ui'
import HistoryLocale from '@univerjs-pro/slides-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSlidesHistoryPlugin)
univer.registerPlugin(UniverSlidesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuración de plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |

`UniverSlidesHistoryUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |
| `univerContainerId` | `string` |  | ID DOM del contenedor del editor. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Plugins adicionales del visor de historial. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | El constructor de plugins. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Opciones aceptadas por el constructor. |

Reemplazar `/api/history` con el endpoint histórico de la aplicación, y asegurar que el endpoint responda a las solicitudes que envía el cliente. Ambos valores `historyServerUrl` deben ser idénticos. Establecer `univerContainerId` al DOM ID del contenedor de editor, y cargar el local que coincida con el editor.

El lector de historia ejecuta un editor solo lectura independiente. Si el contenido requiere plugins que el espectador no incluye, agréguelos a través de `viewerPlugins`, y no registre los plugins de visualización incorporados por segunda vez.

## Consultar y restaurar versiones

Abrir historia del menú del editor, seleccionar una versión, e inspeccionar su contenido y cambios. Restauración reescribe el documento compartido actual, por lo que sólo los usuarios que tienen el permiso de restauración deben realizarlo, y el servidor debe hacer cumplir ese permiso.

Para verificar la integración, editar texto de diapositivas, formas o orden de diapositivas , esperar la confirmación de la colaboración , luego inspeccionar la lista de historia y el contenido de la versión . Reabrir la aplicación y reiniciar el servicio para verificar la persistencia . Restaurar una versión anterior y confirmar que otra sesión del navegador recibe el estado restaurado .

Si la lista está vacía, compruebe si la historia fue grabada para este documento, a continuación, comprima el documento ID y la URL del servicio. Si las versiones son visibles pero la restauración falla, comprended los permisos de restauración y la conexión de colaboración.

## Comparar snapshots [#compare-snapshots]

Para construir una pantalla de revisión o para pasar cambios a un agente de inteligencia artificial, llame a `compareUnitData()` o prepare la comparación una vez con `prepareUnitComparison()`. Registre el plugin de Historia para el producto e importe la entrada de Facade. Tanto `beforeSnapshot` como `afterSnapshot` deben estar completamente materializados instantáneas de la misma unidad.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SLIDE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` lista las opiniones que ofrece la comparación. Pase un alcance para `query()` para filtrar el resultado sin ejecutar la comparación de nuevo. Una página devuelve 100 artículos por defecto y acepta hasta 1.000. `page.hasMore` junto con `offset` para recuperar los elementos restantes. `summary` todavía describe toda la comparación, incluso cuando los elementos son filtrados. `diagnostics.readiness` y `diagnostics.codes` antes de tratar un resultado como una comparación completa. Para Node.js o CLI uso sin un editor, ver el [API de comparación sin cabeza](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
