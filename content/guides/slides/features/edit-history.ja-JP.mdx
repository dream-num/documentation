スライドテキスト、図形、またはスライドオーダーを編集した後、以前のバージョンを検査し、変更を比較し、許可時にバージョンを復元します。 履歴は、サーバーが保存するバージョンを読み込みます。 undo と redo は、現在の編集セッションのみに適用され、履歴サービスを必要としません。

## 共同編集と履歴サービスの準備

[コラボレーション統合](/server/collaboration/browser-integration)と[ライセンス構成](/server/license)から始まります。 2つのセッションが同じスライドのドキュメントを編集でき、その変更が再ロードされる可能性があることを確認します。

[オフィスのコラボレーション拡張](/server/collaboration/extensions)と[歴史例](/server/collaboration/examples#history)による履歴記憶と権限を接続します。コアコラボレーションは、それ自体で履歴を有効にしません。バックエンドは、履歴リスト、バージョンコンテンツ、および復元をサポートする必要があります。

## 履歴プラグインの追加

既存の製品、ライセンス、コラボレーション設定に次の登録を追加します。プリセットまたは既存の設定がすでにこれらのプラグインを登録している場合は、その設定を2回目の登録ではなく変更します。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/slides-history @univerjs-pro/slides-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSlidesHistoryPlugin } from '@univerjs-pro/slides-history'
import { UniverSlidesHistoryUIPlugin } from '@univerjs-pro/slides-history-ui'
import HistoryLocale from '@univerjs-pro/slides-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSlidesHistoryPlugin)
univer.registerPlugin(UniverSlidesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### プラグイン設定

`UniverEditHistoryPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |

`UniverSlidesHistoryUIPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |
| `univerContainerId` | `string` |  | エディターコンテナの DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 履歴ビューアーに追加するプラグイン。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | プラグインコンストラクタ。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 施工者によるオプション |

`/api/history`をアプリケーションの歴史エンドポイントに置き換え、エンドポイントがクライアントが送信するリクエストに応答することを保証します。 `historyServerUrl`の値は同じでなければなりません。 `univerContainerId` をエディタコンテナの DOM ID に設定し、エディタと一致するロケールをロードします。

履歴ビューアは別々の読み取り専用エディタを実行します。ビューアが含まないプラグインが必要な場合は、`viewerPlugins`を介してそれらを追加し、ビルトインビューアプラグインを秒間登録しません。

## バージョンの表示と復元

エディタメニューから履歴を開き、バージョンを選択し、コンテンツと変更を調べます。復元は現在の共有文書を書き換えます。そのため、復元権限を保持しているユーザーは、それを実行する必要があります。サーバーは、その許可を強制しなければなりません。

統合を確認するために、スライドテキスト、図形、またはスライドオーダーを編集し、コラボレーション確認を待ち、履歴リストとバージョンコンテンツを確認します。アプリケーションを再オープンし、サービスを再始動して、永続性を確認します。以前のバージョンを復元し、別のブラウザセッションが復元された状態を受け取ることを確認します。

リストが空の場合、このドキュメントの履歴が記録されたかどうかを確認し、ドキュメント ID とサービス URL を確認します。バージョンが表示されていないが、復元が失敗した場合は、復元権限とコラボレーション接続を確認してください。古いバージョンが削除されたデータを含む可能性があるため、履歴の読み込みには承認が必要です。

## スナップショットの比較 [#compare-snapshots]

レビュー画面を作成するか、またはAIエージェントへの変更を渡すには、`compareUnitData()` を呼び出すか、または `prepareUnitComparison()`. 製品の履歴プラグインを登録し、ファサードエントリーをインポートします。 `beforeSnapshot`と`afterSnapshot`は、同じユニットの完全に材料化されたスナップショットでなければなりません。 比較は、読み取り専用であり、履歴サービスは不要で、コンテンツの復元やマージも不要です。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SLIDE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes`は、比較が提供するビューをリストします。 1つのスコープを`query()`に渡し、再び比較を実行せずに結果をフィルタリングします。 ページは、デフォルトで100項目を返し、最大1,000を受け入れます。 `offset`と一緒に`page.hasMore`を使用して残りのアイテムを取得してください。 `summary`は、アイテムがフィルタリングされた場合でも、全体的な比較を説明します。 結果の完全な比較として扱う前に`diagnostics.readiness`と`diagnostics.codes`をチェックしてください。 エディタなしでNode.jsまたはCLIの使用については、[ヘッドレス比較API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)を参照してください。
