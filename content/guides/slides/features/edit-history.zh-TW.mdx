修改幻燈片文字、形狀或頁面順序後，可以開啟歷史記錄檢視之前的版本、比較變化，並在有權限時恢復某個版本。歷史記錄讀取伺服器端儲存的版本。撤銷和重做只作用於當前編輯會話，不需要歷史服務，也無法替代歷史記錄。

## 準備協同與歷史服務

先按[協同整合](/server/collaboration/browser-integration)連線編輯器，完成[許可證配置](/server/license)，再確認兩個會話可以編輯同一份 Slides 文件，並且重新整理後內容仍然保留。

按 [Office 協同擴充套件模組](/server/collaboration/extensions)和 [History 範例](/server/collaboration/examples#history)接入歷史儲存和權限。核心協同不會自動啟用歷史記錄，後端還需要支援歷史列表、版本內容和恢復操作。

## 加入歷史外掛

將以下注冊程式碼加入已有的產品、許可證和協同配置。如果預設或現有配置已經註冊了這些外掛，修改該配置，不要重複註冊。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/slides-history @univerjs-pro/slides-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSlidesHistoryPlugin } from '@univerjs-pro/slides-history'
import { UniverSlidesHistoryUIPlugin } from '@univerjs-pro/slides-history-ui'
import HistoryLocale from '@univerjs-pro/slides-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSlidesHistoryPlugin)
univer.registerPlugin(UniverSlidesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 外掛設定

`UniverEditHistoryPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的基礎 URL。 |

`UniverSlidesHistoryUIPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的基礎 URL。 |
| `univerContainerId` | `string` |  | 編輯器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 為歷史版本檢視器追加的外掛。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 外掛建構函式。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 該建構函式接受的配置項。 |

將 `/api/history` 替換為應用實際的歷史介面，並確認該介面能夠響應客戶端傳送的請求。兩個 `historyServerUrl` 必須一致。`univerContainerId` 填寫編輯器容器的 DOM ID，載入的語言套件應與編輯器當前語言一致。

歷史檢視器會啟動一個獨立的只讀編輯器。如果內容需要檢視器未內建的外掛，透過 `viewerPlugins` 新增，不要重複註冊內建外掛。

## 檢視與還原版本

從編輯器選單開啟歷史記錄，選擇一個版本，檢視其內容和變化。恢復版本會改寫當前共享文件，因此只有擁有恢復權限的使用者才能執行，並且伺服器端必須強制校驗該權限。

驗證接入時，修改幻燈片文字、形狀或頁面順序，等待協同確認，然後檢視歷史列表和版本內容。重新開啟應用並重啟服務，確認版本仍然存在。恢復一箇舊版本，再確認另一個瀏覽器會話收到恢復後的狀態。

如果列表為空，先確認該文件是否記錄了歷史，再核對文件 ID 和服務地址。如果版本可以檢視但恢復失敗，檢查恢復權限和協同連線。讀取歷史同樣需要授權，因為舊版本可能包含後來已刪除的資料。

## 比較快照 [#compare-snapshots]

如果需要建置審閱介面，或將變更交給 AI Agent，可以呼叫 `compareUnitData()`，也可以使用 `prepareUnitComparison()` 先準備一次比較。先註冊該文件型別的 History 外掛並匯入 Facade 入口，然後將同一個 unit 的兩份完整快照分別傳給 `beforeSnapshot` 和 `afterSnapshot`。該比較是隻讀的，不需要歷史服務，也不會恢復或合併內容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SLIDE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` 列出可用的檢視。將其中一個傳給 `query()`，可以在不重新執行比較的情況下篩選結果。每頁預設返回 100 項，最多接受 1,000 項。結合 `page.hasMore` 和 `offset` 可以讀取其餘條目。即使篩選了條目，`summary` 仍然描述整個比較。將結果視為完整比較之前，先檢查 `diagnostics.readiness` 和 `diagnostics.codes`。無需編輯器的 Node.js 或 CLI 用法，參見[無介面比較 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
