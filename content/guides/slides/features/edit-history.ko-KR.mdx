슬라이드 텍스트, 모양, 또는 슬라이드 순서를 편집 한 후, 이전 버전을 검사하기 위해 역사를 열고, 변경 사항을 비교하고, 권한 허용 할 때 버전을 복원합니다. 역사는 서버 상점이 버전을 읽습니다. Undo 및 redo는 현재 편집 세션에만 적용하고 역사 서비스가 필요하지 않습니다.

## 공동 편집 및 기록 서비스 준비

[협업 통합](/server/collaboration/browser-integration) 및 [인증 구성](/server/license)와 함께 시작하십시오. 두 세션이 동일한 슬라이드 문서를 편집 할 수 있다는 것을 검증하고 그 변경은 다시로드를 생존합니다.

[Office 협업 확장](/server/collaboration/extensions)와 [연혁 예](/server/collaboration/examples#history)를 통해 역사 저장 및 권한을 연결하십시오. 핵심 협력은 자체로 역사를 활성화하지 않습니다. 백엔드는 역사 목록, 버전 내용 및 복원을 지원해야합니다.

## 기록 플러그인 추가

기존 제품, 라이센스 및 협업 설정에 대한 다음 등록을 추가하십시오. 미리 설정하거나 기존 구성이 이미이 플러그인을 등록하면 두 번째 시간을 등록하는 대신 구성을 수정합니다.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/slides-history @univerjs-pro/slides-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSlidesHistoryPlugin } from '@univerjs-pro/slides-history'
import { UniverSlidesHistoryUIPlugin } from '@univerjs-pro/slides-history-ui'
import HistoryLocale from '@univerjs-pro/slides-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSlidesHistoryPlugin)
univer.registerPlugin(UniverSlidesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 플러그인 설정

`UniverEditHistoryPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |

`UniverSlidesHistoryUIPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |
| `univerContainerId` | `string` |  | 편집기 컨테이너의 DOM ID입니다. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 기록 뷰어에 추가할 플러그인입니다. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 플러그인 생성자. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | constructor에 의해 허용되는 옵션. |

`/api/history`를 응용 프로그램의 역사 엔드 포인트로 교체하고 클라이언트가 보낸 요청을 종료 할 수 있도록합니다. `historyServerUrl` 값 모두 동일해야합니다. 편집기 컨테이너의 DOM ID에 `univerContainerId`을 설정하고 편집기와 일치하는 Locale를로드하십시오.

역사 뷰어는 별도의 읽기 전용 편집기를 실행합니다. 콘텐츠가 포함되지 않는 플러그인이 필요하면 `viewerPlugins`를 통해 추가하고 내장 뷰어 플러그인을 두 번째로 등록하지 마십시오.

## 버전 보기 및 복원

편집 메뉴에서 역사를 열고, 버전을 선택하고, 콘텐츠를 검사하고 변경합니다. 복원은 현재 공유 문서를 다시 작성, 그래서 복원 권한을 보유하는 유일한 사용자는 그것을 수행해야, 서버는 그 권한을 시행해야합니다.

통합을 확인하려면 슬라이드 텍스트, 모양, 또는 슬라이드 주문, 협력 확인을 기다립니다, 다음 역사 목록과 버전 콘텐츠를 검사. 응용 프로그램을 열고 지속을 확인하기 위해 서비스를 다시 시작합니다. 이전 버전을 복원하고 다른 브라우저 세션이 복원 된 상태를 수신 확인.

목록이 비어있을 경우, 이 문서에 기록된 기록이 기록된지 확인한 후, 문서 ID와 서비스 URL을 확인합니다. 버전이 눈에 띄는 경우, 복원 권한 및 협업 연결을 확인하십시오. 이전 버전이 삭제된 데이터가 포함될 수 있기 때문에, 읽기 기록은 저자화가 필요합니다.

## 스냅샷 비교 [#compare-snapshots]

검토 화면을 구축하거나 AI 에이전트로 변경을 통과하려면 `compareUnitData()`를 호출하거나 `prepareUnitComparison()`와 함께 비교를 준비하십시오. 제품을위한 역사 플러그인을 등록하고 Facade 항목을 가져 오기. `beforeSnapshot` 및 `afterSnapshot`는 동일한 단위의 완전히 Materialized 스냅 샷이어야합니다. 비교는 읽기 전용이며, 역사 서비스가 필요하지 않으며 복원 또는 합병 내용이 없습니다.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SLIDE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes`는 비교 제안이 있는 전망입니다. 비교를 다시 달리기 없이 결과를 거르기 위하여 `query()`에 1개의 범위를 통과하십시오. 페이지는 과태로 100개의 품목을 돌려보내고 1,000까지 받아들입니다. 남아있는 품목을 검색하기 위하여 `offset`와 함께 `page.hasMore`를 사용하십시오. `summary`는 아직도 전체적인 비교를 설명합니다, 품목이 거르는 때. 완전한 비교로 결과를 대우하기 전에 `diagnostics.readiness`와 `diagnostics.codes`를 검사하십시오. 편집기 없이 Node.js 또는 CLI 사용을 위해, [headless 비교 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)를 보십시오.
