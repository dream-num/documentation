После редактирования текста слайда, форм или порядка слайдов откройте историю, чтобы проверить более ранние версии, сравнить изменения и восстановить версию, когда позволяет разрешение. История читает версии, которые хранит сервер. Отменить и переделать применяются только к текущей сессии редактирования и не требуют службы истории.

## Подготовка сервисов совместного редактирования и истории

Начните с [Интеграция сотрудничества](/server/collaboration/browser-integration) и [Конфигурация лицензии](/server/license). Убедитесь, что два сеанса могут редактировать один и тот же документ Slides и что изменения выдерживают перезагрузку.

Подключите хранилище истории и разрешения через [Расширение сотрудничества с офисом](/server/collaboration/extensions) и [Пример истории](/server/collaboration/examples#history). Основное сотрудничество не позволяет историю само по себе. Бэкэнд также должен поддерживать списки истории, содержание версий и восстановление.

## Добавление плагинов истории

Добавьте следующие регистрации в существующую настройку продукта, лицензии и совместной работы.Если предустановленная или существующая конфигурация уже регистрирует эти плагины, измените эту конфигурацию вместо того, чтобы регистрировать их во второй раз.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/slides-history @univerjs-pro/slides-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSlidesHistoryPlugin } from '@univerjs-pro/slides-history'
import { UniverSlidesHistoryUIPlugin } from '@univerjs-pro/slides-history-ui'
import HistoryLocale from '@univerjs-pro/slides-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSlidesHistoryPlugin)
univer.registerPlugin(UniverSlidesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Настройка плагинов

`UniverEditHistoryPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |

`UniverSlidesHistoryUIPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |
| `univerContainerId` | `string` |  | DOM ID контейнера редактора. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Дополнительные плагины для просмотра истории. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Конструктор плагинов. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Варианты, принятые конструктором. |

Замените `/api/history` конечной точкой истории приложения и убедитесь, что конечная точка отвечает на запросы, которые отправляет клиент. Оба значения `historyServerUrl` должны быть идентичны. Установите `univerContainerId` на DOM-идентификатор контейнера редактора и загрузите локалку, соответствующую редактору.

Просмотрщик истории запускает отдельный редактор только для чтения.Если контент требует плагинов, которые не включает зритель, добавьте их через `viewerPlugins` и не регистрируйте встроенные плагины просмотра во второй раз.

## Просмотр и восстановление версий

Откройте историю из меню редактора, выберите версию и проверьте ее содержимое и изменения. Восстановление переписывает текущий общий документ, поэтому его должны выполнять только пользователи, которые имеют разрешение на восстановление, и сервер должен обеспечить это разрешение.

Чтобы проверить интеграцию, отредактировать текст слайда, формы или порядок слайдов, дождаться подтверждения совместной работы, затем проверить список истории и содержание версии. Откройте приложение и перезапустите сервис для проверки стойкости. Восстановите более раннюю версию и подтвердите, что другой сеанс браузера получает восстановленное состояние.

Если список пуст, проверьте, была ли записана история для этого документа, затем проверьте идентификатор документа и URL-адрес службы. Если версии видны, но восстановление не удается, проверяйте разрешения на восстановление и соединение для совместной работы. Для чтения истории также требуется авторизация, потому что более старые версии могут содержать данные, которые с тех пор были удалены.

## Сравнение снимков [#compare-snapshots]

Чтобы построить экран обзора или передать изменения агенту ИИ, позвоните в `compareUnitData()` или подготовьте сравнение один раз с `prepareUnitComparison()`. Зарегистрируйте плагин History для продукта и импортируйте запись Facade. И `beforeSnapshot`, и `afterSnapshot` должны быть полностью материализованными снимками одного и того же блока. Сравнение только для чтения, не требует обслуживания истории и не восстанавливает и не объединяет контент.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SLIDE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` перечисляет виды, которые предлагает сравнение. Передайте одну область в `query()` для фильтрации результата без повторного запуска сравнения. Страница возвращает 100 элементов по умолчанию и принимает до 1000. Используйте `page.hasMore` вместе с `offset`, чтобы извлечь оставшиеся элементы. `summary` по-прежнему описывает все сравнение, даже когда элементы фильтруются. Проверяйте `diagnostics.readiness` и `diagnostics.codes` перед тем, как рассматривать результат как полное сравнение. Для использования Node.js или CLI без редактора см. [безголовое сравнение API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
