Enregistrez les plugins de commentaires après l'éditeur de produit et la licence sont configurés. Chargez les styles d'interface utilisateur partagés et produits et les ressources locales. Le plugin produit possède ses ressources de commentaires, de sorte qu'un instantané ne peut être restauré qu'après que ce plugin est enregistré.

```package-install
npm install @univerjs/thread-comment @univerjs/thread-comment-ui @univerjs-pro/slides-thread-comment @univerjs-pro/slides-thread-comment-ui
```

```ts
import { UniverSlidesThreadCommentPlugin } from '@univerjs-pro/slides-thread-comment'
import { UniverSlidesThreadCommentUIPlugin } from '@univerjs-pro/slides-thread-comment-ui'
import ProductLocale from '@univerjs-pro/slides-thread-comment-ui/locale/fr-FR'
import { LocaleType, mergeLocales } from '@univerjs/core'
import SharedLocale from '@univerjs/thread-comment-ui/locale/fr-FR'

import '@univerjs/thread-comment-ui/lib/index.css'
import '@univerjs-pro/slides-thread-comment-ui/lib/index.css'

univerAPI.loadLocales(LocaleType.FR_FR, mergeLocales(SharedLocale, ProductLocale))
univer.registerPlugin(UniverSlidesThreadCommentPlugin)
univer.registerPlugin(UniverSlidesThreadCommentUIPlugin)
```

## Prise en charge mobile [#mobile-support]

Configurez d'abord le [éditeur mobile](/guides/slides/getting-started/installation#mobile-support). Dans la configuration en mode plugin décrite sur cette page, remplacez les enregistrements de bureau ci-dessous avec les exportations mobiles des mêmes paquets, et faites le remplacement **avant d'ouvrir un document** . Gardez les plugins modèles, styles, locaux et importations Facade, et ne enregistrez pas les deux variantes.

| Paquet | Inscription de bureau | Inscription mobile |
| --- | --- | --- |
| `@univerjs-pro/slides-thread-comment-ui` | `UniverSlidesThreadCommentUIPlugin` | `UniverSlidesThreadCommentMobileUIPlugin` |

## Facade des commentaires [#comment-facade]

Importez le commentaire partagé Facade et le produit Facade avant d'appeler ces méthodes. Les helpers de produit créent des ancres stables, et l'API partagée gère les réponses, les mises à jour, la résolution et la suppression. `getComments()` lit l'état local. `listCommentsAsync()` synchronise les threads qu'il connaît déjà à travers la source de données configurée, mais il ne découvre pas tous les thread sur le serveur.

```ts
import '@univerjs/thread-comment/facade'
import '@univerjs-pro/slides-thread-comment/facade'

const element = univerAPI.getActivePresentation()?.getSlideByIndex(0)?.getElements()[0]
if (element) {
  await element.createCommentAsync('Please review this element.')
  console.log(await element.listCommentsAsync())
}
```

```ts
import '@univerjs/thread-comment/facade'

const [thread] = univerAPI.getComments({ resolved: false })
if (thread) {
  await univerAPI.replyCommentAsync({
    unitId: thread.unitId,
    subUnitId: thread.subUnitId,
    threadId: thread.threadId,
    content: 'Reviewed.',
  })
}
```

## Discussions partagées [#shared-discussions]

Les discussions partagées exigent que le service de commentaires et le point d'arrivée soient reliés par [Server SDK](/server/collaboration/extensions). Après la collaboration et la configuration de licence, enregistrer `UniverThreadCommentDataSourcePlugin` de `@univerjs-pro/thread-comment-datasource`. Les appels de source de données fournis `/universer-api/comment/unit/{unitId}/...` et `/universer-api/user/list`, donc l'application doit exposer ces itinéraires . Commentaire lit et écrit nécessitent leurs propres permissions de serveur ; l'autorisation d'édition de document ne les couvre pas .
