Après avoir modifié le texte, les formes ou l'ordre des diapositives, ouvrez l'historique pour inspecter les versions antérieures, comparer les modifications et restaurer une version lorsque l'autorisation le permet. L'historique lit les versions que le serveur stocke.

## Préparer les services de collaboration et d’historique

Commencez par [l'intégration de la collaboration](/server/collaboration/browser-integration) et [configuration de licence](/server/license). Vérifiez que deux sessions peuvent modifier le même document de diapositives et que les modifications survivent à un rechargement.

Connectez le stockage d'historique et les permissions via [Prolongation de la collaboration avec les bureaux](/server/collaboration/extensions) et le [Exemple historique](/server/collaboration/examples#history). La collaboration de base ne permet pas l'historique par elle-même. Le moteur doit également prendre en charge les listes d'historique, le contenu de la version et la restauration.

## Ajouter les plugins d’historique

Ajouter les enregistrements suivants à la configuration existante du produit, de la licence et de la collaboration. Si un préréglage ou une configuration existante enregistre déjà ces plugins, modifiez cette configuration au lieu de les enregistrer une seconde fois.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/slides-history @univerjs-pro/slides-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSlidesHistoryPlugin } from '@univerjs-pro/slides-history'
import { UniverSlidesHistoryUIPlugin } from '@univerjs-pro/slides-history-ui'
import HistoryLocale from '@univerjs-pro/slides-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSlidesHistoryPlugin)
univer.registerPlugin(UniverSlidesHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuration des plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |

`UniverSlidesHistoryUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |
| `univerContainerId` | `string` |  | ID DOM du conteneur de l’éditeur. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Plugins supplémentaires du visualiseur d’historique. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Le constructeur du plugin. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Options acceptées par le constructeur. |

Remplacez `/api/history` par le paramètre historique de l'application, et assurez-vous que le paramètre répond aux demandes envoyées par le client. Les deux valeurs `historyServerUrl` doivent être identiques. Définissez `univerContainerId` à l'ID DOM du conteneur de l'éditeur et chargez la locale qui correspond à l'éditeur.

Si le contenu nécessite des plugins que le visionneur n'inclut pas, ajoutez-les par l'intermédiaire de `viewerPlugins`, et n'enregistrez pas les plugins de visionneuse intégrés une seconde fois.

## Consulter et restaurer des versions

Ouvrez l'historique depuis le menu de l'éditeur, sélectionnez une version, et inspectez son contenu et ses modifications. La restauration réécrit le document partagé courant, de sorte que seuls les utilisateurs qui détiennent la permission de restauration doivent l'exécuter, et le serveur doit faire respecter cette autorisation.

Pour vérifier l'intégration, modifier le texte, les formes ou l'ordre des diapositives, attendre la confirmation de la collaboration, puis inspecter la liste d'historique et le contenu de la version. Réouvrir l'application et redémarrer le service pour vérifier la persistance. Restaurer une version antérieure et confirmer qu'une autre session du navigateur reçoit l'état restauré.

Si la liste est vide, vérifiez si l'historique a été enregistré pour ce document, puis vérifiez l'ID du document et l'URL du service. Si les versions sont visibles mais que la restauration échoue, vérifiez les autorisations de restauration et la connexion de collaboration.

## Comparer des snapshots [#compare-snapshots]

Pour créer un écran d'examen ou pour passer des modifications à un agent AI, appelez `compareUnitData()`, ou préparez la comparaison une fois avec `prepareUnitComparison()`. Enregistrez le plugin History pour le produit et importez l'entrée Facade. `beforeSnapshot` et `afterSnapshot` doivent tous les deux être des instantanés entièrement matérialisés de la même unité. La comparaison est en lecture seule, ne nécessite aucun service d'historique, et ne restaure ni ne fusionne de contenu.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SLIDE,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` liste les vues que la comparaison offre. Passez une portée à `query()` pour filtrer le résultat sans faire la comparaison à nouveau. Une page retourne 100 éléments par défaut et accepte jusqu'à 1000. Utilisez `page.hasMore` avec `offset` afin de récupérer les éléments restants. `summary` décrit toujours l'ensemble de la comparaison, même lorsque les éléments sont filtrés. Vérifiez `diagnostics.readiness` et `diagnostics.codes` avant de traiter un résultat comme une comparaison complète. Pour Node.js ou CLI utiliser sans éditeur, consultez le [API de comparaison sans tête](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
