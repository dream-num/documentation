## Idioma de la interfaz

`locale` selecciona el paquete de idiomas para menús, puntas de herramientas, diálogos y otros UI traducidos. `locales` registra paquetes de idiomas sin seleccionar uno. Este ajuste pertenece a la instancia Univer y es compartido por todas las unidades en el caso. Use valores `LocaleType`, como `LocaleType.EN_US`.

- **Todos los productos: interfaz**: `locale` cambia las traducciones de menús, ayudas, diálogos y etiquetas de plugins. No traduce contenido del usuario ni renombra unidades existentes.
- **Hojas: formatos celulares y fórmulas**: Cuando una célula hace un número o una fecha, Univer comprueba primero la sobrevaloración de formato número, luego la instantánea del libro `locale`, y finalmente la instancia `locale`. `region` no reemplaza ninguno de estos. Fórmulas como `DOLLAR`, junto con el formato de moneda aplicado a los resultados financieros, sigue `locale`. La normalización de entrada CJK se comporta de la misma manera.
- **Docs: estadística**: `locale` determina la segmentación de palabras y el conteo.

### Cambiar el idioma durante la ejecución

Cargue todos los paquetes de idiomas para los plugins instalados o presets antes de cambiar. `loadLocales()` fusiona las traducciones sin cambiar el idioma actual; `setLocale()` selecciona un idioma sin descargar ningún dato. Una clave de traducción faltante se muestra como la clave misma. El ejemplo a continuación carga el paquete UI compartido. Si otros plugins se instalan, fusionar sus paquetes de idiomas de destino en la misma llamada.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Paquetes de idiomas personalizados

Univer también admite paquetes de idiomas personalizados. Agrupe un objeto de paquete de idiomas según sea necesario y pásela a la instancia `Univer`. Los paquetes de lenguaje presto se almacenan generalmente en el directorio `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Contribución de traducciones

Univer ofrece los siguientes paquetes de idiomas incorporados:

- `zh-CN`: chino simplificado
- `en-US`: inglés
- `zh-TW`: tradicional Chino
- `zh-HK`: Chino tradicional (Hong Kong)
- `ru-RU`: Ruso
- `vi-VN`: Vietnamita
- `fa-IR`: Persa
- `fr-FR`: Francés
- `ja-JP`: japonés
- `ko-KR`: coreano
- `es-ES`: español
- `ca-ES`: catalán
- `sk-SK`: eslovaco
- `ar-SA`: Árabe
- `de-DE`: alemán
- `id-ID`: indonesio
- `it-IT`: italiano
- `pl-PL`: polaco
- `pt-BR`: portugués (brasileño)

Univer es un proyecto de código abierto, y los desarrolladores de todas las regiones pueden agregar o mejorar paquetes de idiomas.

## Configuración regional

`region` selecciona las convenciones regionales utilizadas por las características regionales. Al igual que `locale`, pertenece a la instancia Univer y es compartida por todas las unidades en la instancia.

Ambos ajustes `LocaleType` valores, por ejemplo, el valor de `LocaleType.EN_US` es `enUS`, mientras `en-US` es el nombre del archivo idioma-paquete y la etiqueta BCP 47. No pasar códigos de país como `US` o `SG` como tal `region`. Cuando la UI utiliza un idioma diferente, la región no requiere su propio paquete de idiomas.

Cuando `region` no se establece explícitamente, sigue `locale`, incluyendo posteriores llamadas `setLocale()`. Si `region` se establece en la inicialización o `setRegion()` ha sido llamado, automáticamente después de las paradas, y los cambios de lenguaje posteriores conservan la región seleccionada. Ninguna API pública restaura automáticamente después; cuando ambos valores deben cambiar juntos, establecer ambos.

Para mantener el idioma UI utilizando convenciones regionales alemanas, agregue `region: LocaleType.DE_DE` junto a `locale` en `createUniver()` o `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Aquí la UI es el formato inglés y regional sigue siendo alemán. `getCurrentLocale()` y `getCurrentRegion()` devuelven los identificadores efectivos. Para cambiar ambos a la vez, llame a ambos setters con el mismo valor `LocaleType`.

- **Hojas: controles de divisas**: `region` selecciona el icono de la barra de herramientas de moneda, las opciones de moneda y contabilidad y las previsiones, y el formato aplicado por el comando de divisas. Cambiar la región no reescribir los formatos de celda existentes o convertir los valores monetarios.
- **Docs: estadística**: `region` formatea los números mostrados en el diálogo de estadísticas y la barra de estado, por ejemplo los separadores de agrupación. Cambiar `region` no cambia las reglas de contabilidad.
- **Thread comments, when enabled**: `region` determina cómo se muestran las fechas y los tiempos, utilizando el tiempo de 24 horas y dígitos latinos; `locale` determinará el texto UI del comentario. Ni cambios horarios almacenados, y `region` no es un ajuste de la zona horaria.
- **Boards, Slides, Bases, PDFs**: `locale` controla la interfaz de usuario traducida. `region` está disponible para funciones compartidas que la consumen, tales como comentarios de hilo cuando está integrada. No se reforma automáticamente tabla o texto de diapositivas, campos de base o contenido PDF.
