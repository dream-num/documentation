## 전역 수명 주기

- **을 시작**: 초기화는 진행 중이며, 사업 단위는 아직 존재하지 않습니다.
- **지원하다**: 첫번째 사업 단위는 창조되었습니다. 단위는 나중에 이 단계를 다시 방아쇠하지 않습니다.
- **이름 ***: 표준 UI는 첫번째 렌더링 스위치를 완료했습니다. 이것은 모든 비동기 내용이 준비되어 있다는 것을 의미하지 않습니다.
- **인기 카테고리** : 표준 UI는 렌더링 후이 단계를 몇 번 입력합니다. 모든 비동기 작업을 기다릴 수 없습니다.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="이벤트가 알리는 대상">

`LifeCycleChanged`는 Univer의 글로벌 스테이지를 보여줍니다. 예를 들어, 글로벌 스테이지가 `Ready`에 도달 한 후 플러그인 B가 `onReady()`를 실행하지만, 두 번째 글로벌 `Ready` 이벤트가 방출되지 않습니다.

청취자가 추가될 때, 콜백은 `Starting`를 포함한 현재 단계를 즉시 받게 될 수 있습니다. 현재 단계만 얻으려면 `univerAPI.getCurrentLifecycleStage()`로 직접 전화하십시오.

</Callout>

청취자를 제거하려면 반환된 `disposable` 개체를 사용하십시오.

```typescript
disposable.dispose()
```

## 플러그인 수명 주기 훅

플러그인은 `onStarting()`를 실행하면 현재 글로벌 단계로 잡을 수 있습니다. A의 후크 통화를 비교하기 위해 B로드가 가능한 단계를 제어합니다.

<LifecycleDemo />

일반 플러그인은 등록에로드합니다. 비즈니스 유형 플러그인은 일반적으로 그 유형의 첫 번째 단위 전에로드됩니다. 이미 deferred 배치에로드를 시작 한 유형을위한 새로운 플러그인. Explicit Dependencies는 이전 로딩을 유발할 수 있습니다.

동일한 배치의 후크는 비동기적으로, 단계 및 의존성 순서로, 그리고 Univer는 그 안에 비동기적인 일을 기다리지 않습니다. 특정한 단위, DOM 성분, 또는 자원이 접근하기 전에 준비되어 있다는 것을 확인하십시오.
