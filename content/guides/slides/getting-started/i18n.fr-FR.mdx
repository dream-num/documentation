## Langue de l’interface

`locale` sélectionne le paquet de langues pour les menus, les tooltips, les dialogues et les autres interfaces traduites. `locales` enregistre les paquets de langues sans en sélectionner un. Ce paramètre appartient à l'instance Univer et est partagé par toutes les unités de l'instance. Utilisez les valeurs `LocaleType`, telles que `LocaleType.EN_US`.

- **Tous les produits : interface**: `locale` change les traductions des menus, infobulles, dialogues et libellés des plugins. Le contenu utilisateur et les noms des unités existantes restent inchangés.
- **Feuilles: formats et formules de cellules**: Lorsqu'une cellule rend un numéro ou une date, Univer vérifie d'abord la préséance number-format locale, puis l'instantané du cahier de travail `locale`, et enfin l'instance `locale`. `region` ne remplace aucun de ces derniers. Les formules telles que `DOLLAR`, ainsi que le format de monnaie appliqué aux résultats financiers, suivent toujours `locale`.
- **Docs: statistiques**: `locale` détermine la segmentation et le comptage des mots.

### Changer la langue à l’exécution

Chargez tous les packs de langues pour les plugins ou préréglages installés avant de passer à l'action. `loadLocales()` fusionne les traductions sans changer la langue courante; `setLocale()` sélectionne une langue sans télécharger de données. Une clé de traduction manquante s'affiche comme la clé elle-même. L'exemple ci-dessous charge le pack d'interface utilisateur partagé.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Packs linguistiques personnalisés

Univer prend également en charge les paquets de langues personnalisés. Assemblez un objet de paquet de langues au besoin et passez-le à l'instance `Univer`. Les paquets de langues prédéfinis sont généralement stockés dans le répertoire `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Contribuer aux traductions

Univer fournit les paquets de langues intégrés suivants:

- `zh-CN` : chinois simplifié
- `en-US` : anglais
- `zh-TW` : chinois traditionnel
- `zh-HK` : chinois traditionnel (Hong Kong)
- `ru-RU` : russe
- `vi-VN` : vietnamien
- `fa-IR` : persan
- `fr-FR` : français
- `ja-JP` : japonais
- `ko-KR` : coréen
- `es-ES` : espagnol
- `ca-ES` : catalan
- `sk-SK` : slovaque
- `ar-SA` : arabe
- `de-DE` : allemand
- `id-ID` : indonésien
- `it-IT` : italien
- `pl-PL` : polonais
- `pt-BR` : portugais (Brésil)

D'autres langues ne sont pas encore prises en charge. Univer est un projet open source, et les développeurs de toutes les régions sont les bienvenus pour ajouter ou améliorer des paquets de langues.

## Paramètres régionaux

`region` sélectionne les conventions régionales utilisées par les fonctions régionales. Comme `locale`, il appartient à l'instance Univer et est partagé par toutes les unités de l'instance.

Les deux paramètres prennent des valeurs de `LocaleType`. Par exemple, la valeur de `LocaleType.EN_US` est de `enUS`, tandis que `en-US` est le nom du fichier de paquet de langue et l'étiquette BCP 47. Ne passez pas les codes de pays tels que `US` ou `SG` comme `region`. Lorsque l'interface utilisateur utilise une langue différente, la région n'a pas besoin de son propre paquet de langue.

Lorsque `region` n'est pas défini explicitement, il suit `locale`, y compris les appels `setLocale()` suivants. Si `region` est défini à l'initialisation ou `setRegion()` a été appelé, stops automatiques, et modifications de langue ultérieures conservent la région sélectionnée. Aucune API publique ne restaure automatiquement suivant; lorsque les deux valeurs doivent changer ensemble, définissez les deux.

Pour conserver la langue de l'interface utilisateur en utilisant des conventions régionales allemandes, ajoutez `region: LocaleType.DE_DE` à côté de `locale` dans `createUniver()` ou `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Ici, l'interface utilisateur est anglaise et le formatage régional reste allemand. `getCurrentLocale()` et `getCurrentRegion()` retournent les identifiants effectifs. Pour changer les deux à la fois, appelez les deux setters avec la même valeur `LocaleType`.

- **Feuilles : contrôles des devises**: `region` sélectionne l'icône de la barre d'outils de la monnaie, les options et les prévisualisations de la monnaie et du format appliqué par la commande de la monnaie.
- **Docs: statistiques**: `region` formate les nombres affichés dans la boîte de dialogue statistique et la barre d'état, par exemple les séparateurs de regroupement. La modification de `region` ne modifie pas les règles de comptage.
- **Commentaires de filetage, lorsque activé**: `region` détermine la façon dont les dates et les heures sont affichées, en utilisant des chiffres latins et 24 heures sur 24; `locale` détermine le texte de l'interface utilisateur de commentaire. `region` n'est pas un réglage de fuseau horaire.
- **Planches, diapositives, bases, PDFs**: `locale` contrôle l'interface utilisateur traduite. `region` est disponible pour les fonctions partagées qui la consomment, comme les commentaires de thread lors de l'intégration. Il ne reformate pas automatiquement le tableau ou le texte de diapositive, les champs de base ou le contenu PDF.
