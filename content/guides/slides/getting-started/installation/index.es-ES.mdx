title: Instalación y uso básico
---

Esta página describe cómo instalar Univer Slides y renderizar un editor en la página. Los ejemplos utilizan los paquetes de diapositivas Web SDK. Univer no proporciona un preset de diapositivas, por lo que la aplicación se monta en modo plugin.

Si no está familiarizado con los conceptos básicos de Univer, lea primero [Quickstart](/guides/slides/getting-started/quickstart).

Univer ofrece dos modos de integración: *Modo de inicio* y * Modo de plugin*. Modo de preconfigurado proporciona paquetes de plugin preconfigurados, que elimina la mayoría del trabajo de montaje. Aplicaciones que necesitan **profunda personalización o extensiones** Modo de uso Plugin, en el que cada plugin es seleccionado y configurado individualmente.

## Configuración a través del modo complemento

Univer distribuye Diapositivas como un conjunto de plugins. Un editor del navegador normalmente registra el tiempo de ejecución compartido Univer, el plugin de licencia, las dependencias de Docs y Drawing, y luego el modelo de diapositivas y los plugins UI.

### Uso del administrador de paquetes

La herramienta de construcción debe apoyar ES Modules y el campo `exports` en `package.json`.

#### Instalación

Univer utiliza React para su interfaz de usuario y RxJS para los flujos de datos, y también puede incrustarse en Vue o Angular aplicaciones. Las `react`, `react-dom`, y `rxjs` dependencias de pares[^peer-dependency] deben ser instaladas; el comando Yarn a continuación los incluye explícitamente.

Todos los paquetes `@univerjs/*` y `@univerjs-pro/*` deben permanecer en **la misma versión**.

#### Uso

Crear el contenedor y darle una altura explícita antes de inicializar Univer:

```html
<div id="app" style="height: 600px"></div>
```

Importar las entradas de fachada utilizadas en los siguientes pasos antes de llamar `FUniver.newAPI(univer)`. Importar el `@univerjs/design` CSS primero, luego el `@univerjs/ui`CSS, y el producto CSS último.

<Callout type="warning" title="Caution">
  - Regístrate `UniverLicensePlugin` antes de cualquier plugin de diapositivas.
  - Importar el CSS UI compartido antes del producto UI CSS.
  - Agregue paquetes opcionales como impresión, tablas, gráficos e importación/exportación sólo cuando el producto los requiera.
  - `UniverSlidesUIPlugin` carga `UniverProFormulaEnginePlugin` por su cuenta para formas. Si la misma instancia `Univer` también registra `UniverFormulaEnginePlugin`, instale `@univerjs-pro/engine-formula` y reemplace la importación y registro de ese motor con `UniverProFormulaEnginePlugin` en el código de inicialización. No registre ambos motores de fórmula.
</Callout>

<Steps>
  <Step>
    Importar las hojas de estilo, paquetes locales, y los plugins necesarios:

    ```typescript
    import { UniverLicensePlugin } from '@univerjs-pro/license'
    import { UniverSlidesPlugin } from '@univerjs-pro/slides'
    import { UniverSlidesUIPlugin } from '@univerjs-pro/slides-ui'
    import SlidesUIEnUS from '@univerjs-pro/slides-ui/locale/en-US'
    import SlidesEnUS from '@univerjs-pro/slides/locale/en-US'
    import { LocaleType, mergeLocales, Univer, UniverInstanceType } from '@univerjs/core'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverDrawingPlugin } from '@univerjs/drawing'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    import '@univerjs-pro/slides-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Para utilizar el Facade API[^facade-entry], importar las entradas de fachada también:

    ```typescript
    import { FUniver } from '@univerjs/core/facade'
    import '@univerjs-pro/slides/facade'
    ```
  </Step>
  <Step>
    Crear una instancia Univer, registrar los plugins, y crear una unidad de diapositivas:

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
          SlidesEnUS,
          SlidesUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)
    univer.registerPlugin(UniverDrawingPlugin)

    univer.registerPlugin(UniverLicensePlugin, {
      license: process.env.CLIENT_LICENSE_TEXT,
    })

    univer.registerPlugin(UniverSlidesPlugin)
    univer.registerPlugin(UniverSlidesUIPlugin)

    univer.createUnit(UniverInstanceType.UNIVER_SLIDE, {})

    const univerAPI = FUniver.newAPI(univer)
    ```
  </Step>
</Steps>

El objeto `univerAPI` que `FUniver.newAPI(univer)` devuelve es Univer's Facade API. La aplicación la utiliza para crear presentaciones y para llamar a las API de diapositivas.

#### Configuración de plugins [#plugin-configuration]

`UniverUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Elemento DOM donde se monta el editor, o su ID. |

`UniverLicensePlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `license` | `string` |  | Contenido del archivo de licencia del cliente. |

#### Métodos `univer.registerPlugin` y `univer.registerPlugins` [#registerPlugin]

Llame a `univer.registerPlugin` después de crear la instancia Univer para registrar un solo plugin.

La firma es `univer.registerPlugin(Plugin, options)`. `Plugin` es la clase plugin, y `options` mantiene la configuración de ese plugin.

`univer.registerPlugins` acepta un array y registra varios plugins en una llamada. Este formulario es conveniente cuando la lista de plugins debe mantenerse en un solo lugar.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverDrawingPlugin,
  [UniverLicensePlugin, {
    license: process.env.CLIENT_LICENSE_TEXT,
  }],
  UniverSlidesPlugin,
  UniverSlidesUIPlugin,
])
```

#### Paquetes de funciones opcionales

Instalar un paquete de características cuando el editor necesite la capacidad correspondiente:

```shell
pnpm add @univerjs-pro/slides-print
pnpm add @univerjs-pro/slides-table @univerjs-pro/slides-table-ui
pnpm add @univerjs-pro/chart-ui @univerjs-pro/slides-chart @univerjs-pro/slides-chart-ui
pnpm add @univerjs-pro/slides-exchange-client
```

Los ejemplos de registro se dan en [Impresión](/guides/slides/features/print), [Cuadro](/guides/slides/features/tables), [Gráficos](/guides/slides/features/charts), y [Importación y exportación](/guides/slides/features/import-export).

#### Complementos opcionales de carga diferida

El modo Plugin también permite que un plugin de función se cargue sólo cuando el producto lo necesita:

```typescript
univer.createUnit(UniverInstanceType.UNIVER_SLIDE, {})

import('@univerjs-pro/slides-chart').then(({ UniverSlidesChartPlugin }) => {
  univer.registerPlugin(UniverSlidesChartPlugin)
})
```

### Uso del lado del servidor

En Node.js, registre los plugins modelo y omita los plugins UI del navegador:

```typescript
univer.registerPlugin(UniverSlidesPlugin)
```

El plugin modelo realiza el procesamiento sin cabezas de instantánea. Exposing collaboration or file-conversion APIs requiere el [Módulos Server SDK](/server) correspondiente. Registrar este plugin por sí solo no crea esos servicios.

## Compatibilidad móvil [#mobile-support]

<Callout type="warning">
  Estos ejemplos requieren paquetes SDK que exportan los plugins móviles que se enumeran a continuación. Todas las dependencias `@univerjs/*` y `@univerjs-pro/*` deben permanecer en **la misma versión**.

  `1.0.0-rc.0` no exporta `UniverSlidesMobileUIPlugin`. Elija una construcción que incluya esta entrada móvil antes de seguir el ejemplo.
</Callout>

Controles táctiles en Univer Las diapositivas requieren **plugins UI móvil**.[^mobile-ui-mode] Decide el modo UI antes de crear el editor.

En el ejemplo del plugin anterior, **Sustituir la sustitución** la interfaz de usuario importa y registra los siguientes datos antes de `createUnit()`. No los anexes a un editor de escritorio que ya se ha inicializado. Mantenga los plugins modelo, motores, archivos locales, CSS, y las importaciones Facade. Las clases de escritorio y móviles se denominan exportaciones desde el **mismo paquete de entrada** .

`UniverMobileUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Elemento DOM donde se monta el editor, o su ID. |
| `disableAutoFocus` | `true` | `true` | Evita que el editor reciba el foco al iniciarse. |

```typescript
import { UniverSlidesMobileUIPlugin } from '@univerjs-pro/slides-ui'
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
univer.registerPlugin(UniverSlidesMobileUIPlugin)
```

### Correspondencia de plugins

Registrar sólo las características en uso, y mantener sus plugins modelo y dependencias requeridas. Una exportación UI móvil no significa que el escritorio y el móvil ofrecen los mismos controles. Las características Pro todavía requieren la licencia adecuada. Las características con un backend requieren la integración de la aplicación con el [Univer Server SDK](/server).

### Contenedor e interacción táctil

El contenedor necesita una altura explícita, y el mirador de la página debe configurarse. `100dvh` sigue la altura dinámica del puerto de visualización. Prueba de desplazamiento, pinche zoom, selección de texto, acceso a portapapeles y el teclado en pantalla en los navegadores móviles seleccionados. Reactivar un editor de escritorio no lo cambia a los plugins móviles.

`UniverMobileUIPlugin` predetermina a `disableAutoFocus: true`, por lo que el editor no se centra automáticamente durante la inicialización.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Otras versiones

Univer publica canales alpha / beta junto a sus versiones estables. Hacen nuevas características disponibles antes de su lanzamiento oficial, a un costo de mayor riesgo. Estas versiones pueden contener errores, funcionalidad incompleta o características inestables, por lo que deben evitarse en la producción cuando sea posible.

### Lanzamiento alfa/beta

Cuando el equipo Univer completa una nueva característica o un cambio significativo, puede pre-release el trabajo al canal de alfa o beta. Instala la versión alfa / beta de un paquete Univer de la siguiente manera:

```package-install
npm install @univerjs-pro/slides@alpha # Alpha version
npm install @univerjs-pro/slides@beta # Beta version
```

Informar problemas y comentarios sobre una versión alfa / beta al equipo Univer a través de [Cuestiones de GitHub](https://github.com/dream-num/univer/issues).

[^peer-dependency]: Las `peerDependencies` son dependencias que la aplicación anfitriona debe proporcionar con versiones compatibles. Permiten compartir bibliotecas como React con Univer.

[^facade-entry]: Facade es la API de aplicación de los plugins registrados. Importar una entrada de Facade añade métodos a la API, pero no registra el plugin de la función.

[^mobile-ui-mode]: Un plugin de UI móvil selecciona controles táctiles y servicios móviles durante la inicialización. No detecta automáticamente el dispositivo ni cambia una instancia existente al redimensionar la ventana. Para cambiar de modo, conserve el estado del documento, destruya la instancia anterior e inicialice los plugins elegidos.
