title: Installation et utilisation de base
---

Cette page décrit comment installer les diapositives Univer et rendre un éditeur sur la page. Les exemples utilisent les paquets de diapositives Web SDK. Univer ne fournit pas encore un préréglage de diapositives, de sorte que l'application est assemblée en mode plugin.

Si vous n'êtes pas familier avec les concepts de base de Univer, lisez d'abord [Démarrage rapide](/guides/slides/getting-started/quickstart).

Univer fournit deux modes d'intégration : *Preset Mode* et *Plugin Mode*. Preset Mode fournit des paquets de plugins préconfigurés, ce qui supprime la plupart des travaux d'assemblage. Applications qui nécessitent **personnalisation profonde ou extensions** utiliser le mode Plugin, dans lequel chaque plugin est sélectionné et configuré individuellement.

## Configuration en mode plugin

Univer distribue des diapositives comme un ensemble de plugins. Un éditeur de navigateur enregistre généralement le Univer runtime partagé, le plugin de licence, les dépendances Docs et dessin, puis le modèle de diapositives et les plugins UI.

### Utilisation d’un gestionnaire de packages

L'outil de construction doit prendre en charge les modules ES et le champ `exports` dans `package.json`.

#### Installation

Univer utilise React pour son interface utilisateur et RxJS pour les flux de données, et il peut également être intégré dans les applications Vue ou Angular. La `react`, `react-dom` et `rxjs` dépendances de pairs[^peer-dependency] doit être installée; la commande Yarn ci-dessous les inclut explicitement.

Tous les paquets `@univerjs/*` et `@univerjs-pro/*` doivent rester sur **la même version**.

#### Utilisation

Créez le conteneur et donnez-lui une hauteur explicite avant d'initialiser Univer:

```html
<div id="app" style="height: 600px"></div>
```

Importez les entrées de façade utilisées dans les étapes suivantes avant d'appeler `FUniver.newAPI(univer)`. Importez d'abord le `@univerjs/design` CSS, puis le `@univerjs/ui` CSS et le produit CSS.

<Callout type="warning" title="Attention">
  - Enregistrer `UniverLicensePlugin` avant tout plugin Slides.
  - Importez le CSS d'interface utilisateur partagé avant le produit CSS d'UI.
  - Ajouter des paquets optionnels tels que l'impression, les tableaux, les graphiques et l'importation/exportation seulement lorsque le produit en a besoin.
  - `UniverSlidesUIPlugin` charge `UniverProFormulaEnginePlugin` seul pour les formes. Si la même instance `Univer` enregistre également `UniverFormulaEnginePlugin`, installez `@univerjs-pro/engine-formula` et remplacez l'importation et l'immatriculation de ce moteur par `UniverProFormulaEnginePlugin` dans le code d'initialisation.
</Callout>

<Steps>
  <Step>
    Importez les feuilles de style, les paquets locaux et les plugins requis:

    ```typescript
    import { UniverLicensePlugin } from '@univerjs-pro/license'
    import { UniverSlidesPlugin } from '@univerjs-pro/slides'
    import { UniverSlidesUIPlugin } from '@univerjs-pro/slides-ui'
    import SlidesUIEnUS from '@univerjs-pro/slides-ui/locale/en-US'
    import SlidesEnUS from '@univerjs-pro/slides/locale/en-US'
    import { LocaleType, mergeLocales, Univer, UniverInstanceType } from '@univerjs/core'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverDrawingPlugin } from '@univerjs/drawing'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    import '@univerjs-pro/slides-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Pour utiliser le Facade API[^facade-entry], importez aussi les entrées de façade :

    ```typescript
    import { FUniver } from '@univerjs/core/facade'
    import '@univerjs-pro/slides/facade'
    ```
  </Step>
  <Step>
    Créez une instance Univer, enregistrez les plugins et créez une unité de diapositives :

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
          SlidesEnUS,
          SlidesUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)
    univer.registerPlugin(UniverDrawingPlugin)

    univer.registerPlugin(UniverLicensePlugin, {
      license: process.env.CLIENT_LICENSE_TEXT,
    })

    univer.registerPlugin(UniverSlidesPlugin)
    univer.registerPlugin(UniverSlidesUIPlugin)

    univer.createUnit(UniverInstanceType.UNIVER_SLIDE, {})

    const univerAPI = FUniver.newAPI(univer)
    ```
  </Step>
</Steps>

L'objet `univerAPI` retourné par `FUniver.newAPI(univer)` est Univer Facade API. L'application l'utilise pour créer des présentations et pour appeler les API Diapositives.

#### Configuration des plugins [#plugin-configuration]

`UniverUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Élément DOM où monter l’éditeur, ou son identifiant. |

`UniverLicensePlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `license` | `string` |  | Contenu du fichier de licence client. |

#### Méthodes `univer.registerPlugin` et `univer.registerPlugins` [#registerPlugin]

Appelez `univer.registerPlugin` après avoir créé l'instance Univer pour enregistrer un seul plugin.

La signature est `univer.registerPlugin(Plugin, options)`. `Plugin` est la classe de plugin, et `options` détient la configuration de ce plugin.

`univer.registerPlugins` accepte un tableau et enregistre plusieurs plugins en un seul appel. Ce formulaire est pratique lorsque la liste des plugins doit être maintenue en un seul endroit.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverDrawingPlugin,
  [UniverLicensePlugin, {
    license: process.env.CLIENT_LICENSE_TEXT,
  }],
  UniverSlidesPlugin,
  UniverSlidesUIPlugin,
])
```

#### Paquets de fonctionnalités facultatives

Installez un paquet de fonctionnalités lorsque l'éditeur a besoin de la capacité correspondante:

```shell
pnpm add @univerjs-pro/slides-print
pnpm add @univerjs-pro/slides-table @univerjs-pro/slides-table-ui
pnpm add @univerjs-pro/chart-ui @univerjs-pro/slides-chart @univerjs-pro/slides-chart-ui
pnpm add @univerjs-pro/slides-exchange-client
```

Des exemples d'enregistrement sont donnés en [Impression](/guides/slides/features/print), [Tableau](/guides/slides/features/tables), [Graphiques](/guides/slides/features/charts) et [Importation et exportation](/guides/slides/features/import-export).

#### Charger les plugins facultatifs à la demande

Le mode Plugin permet également de charger un plugin de fonction uniquement lorsque le produit en a besoin:

```typescript
univer.createUnit(UniverInstanceType.UNIVER_SLIDE, {})

import('@univerjs-pro/slides-chart').then(({ UniverSlidesChartPlugin }) => {
  univer.registerPlugin(UniverSlidesChartPlugin)
})
```

### Utilisation côté serveur

Dans Node.js, enregistrez les plugins du modèle et omettez les plugins de l'interface utilisateur du navigateur :

```typescript
univer.registerPlugin(UniverSlidesPlugin)
```

Le plugin modèle effectue un traitement instantané sans tête. L'exposition d'APIs de collaboration ou de conversion de fichiers nécessite la [Modules Server SDK](/server) correspondante. L'enregistrement de ce plugin seul ne crée pas ces services.

## Prise en charge mobile [#mobile-support]

<Callout type="warning">
  Ces exemples nécessitent des paquets SDK qui exportent les plugins mobiles énumérés ci-dessous. Toutes les dépendances `@univerjs/*` et `@univerjs-pro/*` doivent rester sur **la même version**.

  `1.0.0-rc.0` n'exporte pas `UniverSlidesMobileUIPlugin`. Choisissez une compilation qui inclut cette entrée mobile avant de suivre l'exemple.
</Callout>

Les commandes tactiles dans les diapositives Univer nécessitent **plugins d'interface utilisateur mobiles**.[^mobile-ui-mode] Décidez du mode UI avant de créer l'éditeur.

Dans l'exemple de mode plugin ci-dessus, **remplacer** l'interface utilisateur importe et enregistre avec ceux ci-dessous avant `createUnit()`. Ne les ajoutez pas à un éditeur de bureau qui a déjà été initialisé. Gardez les modèles plugins, moteurs, fichiers locaux, CSS et importations Facade. Les classes de bureau et mobiles sont nommées exportations de **même entrée du colis** .

`UniverMobileUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Élément DOM où monter l’éditeur, ou son identifiant. |
| `disableAutoFocus` | `true` | `true` | Empêche l’éditeur de prendre le focus au démarrage. |

```typescript
import { UniverSlidesMobileUIPlugin } from '@univerjs-pro/slides-ui'
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
univer.registerPlugin(UniverSlidesMobileUIPlugin)
```

### Correspondance des plugins

Une exportation d'interface utilisateur mobile ne signifie pas que le bureau et le mobile offrent les mêmes contrôles. Les fonctionnalités Pro nécessitent toujours la licence appropriée. Les fonctionnalités avec un moteur nécessitent une intégration côté application avec le [Univer Server SDK](/server).

### Conteneur et interactions tactiles

Le conteneur a besoin d'une hauteur explicite, et le port de vue de la page doit être configuré. `100dvh` suit la hauteur de port de vue dynamique. Tester la défilement, pincer le zoom, la sélection de texte, l'accès au presse-papiers et le clavier à l'écran dans les navigateurs mobiles ciblés.

`UniverMobileUIPlugin` par défaut sur `disableAutoFocus: true`, de sorte que l'éditeur ne se concentre pas automatiquement pendant l'initialisation.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Autres versions

Univer publie des canaux alpha/beta aux côtés de ses versions stables. Ils rendent de nouvelles fonctionnalités disponibles avant leur sortie officielle, au prix de risques plus élevés. Ces versions peuvent contenir des bogues, des fonctionnalités incomplètes ou des fonctionnalités instables, de sorte qu'elles doivent être évitées dans la production lorsque c'est possible.

### Version alpha / beta

Lorsque l'équipe Univer complète une nouvelle fonctionnalité ou un changement significatif, elle peut pré-libérer le travail sur le canal alpha ou bêta. Installez la version alpha / bêta d'un paquet Univer comme suit:

```package-install
npm install @univerjs-pro/slides@alpha # Alpha version
npm install @univerjs-pro/slides@beta # Beta version
```

Signaler les problèmes et les commentaires sur une version alpha/bêta à l'équipe Univer via [GitHub Problèmes](https://github.com/dream-num/univer/issues).

[^peer-dependency]: Les `peerDependencies` sont des dépendances que l’application hôte doit fournir dans une version compatible. Elles permettent de partager des bibliothèques comme React avec Univer.

[^facade-entry]: Facade est l’API applicative des plugins enregistrés. Importer une entrée Facade ajoute des méthodes API, mais n’enregistre pas le plugin fonctionnel lui-même.

[^mobile-ui-mode]: Un plugin UI mobile sélectionne les commandes tactiles et les services mobiles à l’initialisation. Il ne détecte pas automatiquement l’appareil et ne change pas le mode d’une instance lors du redimensionnement. Pour changer de mode, conservez l’état du document, détruisez l’ancienne instance et initialisez les plugins choisis.
