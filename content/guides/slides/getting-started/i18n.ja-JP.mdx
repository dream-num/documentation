## インターフェースの言語

`locale` は、メニュー、ツールチップ、ダイアログなどの翻訳された UI の言語パックを選択します。`locales` は、言語パックを 1 つ選択せずに登録します。この設定は Univer インスタンスに属し、インスタンス内のすべての単位で共有されます。`LocaleType.EN_US` などの`LocaleType` 値を使用します。

- **全製品：UI**：`locale` はメニュー、ツールチップ、ダイアログ、プラグインのラベルを翻訳します。ユーザーの内容や既存ユニット名は変更しません。
- **シート: 細胞のフォーマットおよび方式**: セルが番号または日付をレンダリングすると、Univerは、最初に、ワークブックスナップショット`locale`、および最終的にインスタンス`locale`をチェックします。 `region`がこれらのいずれかを交換しません。 `DOLLAR`などの式は、財務結果に適用される通貨フォーマットとともに、`locale`に引き続き適用されます。 通常のCQZは同じように振る舞います。
- **Docs: 統計**:`locale`は単語の区分およびカウントを決定します。

### 実行時の言語の切り替え

インストールされたプラグインやプリセットを切り替える前に、すべての言語パックをロードします。 `loadLocales()`は、現在の言語を変更することなく、翻訳をマージします。 `setLocale()` は、任意のデータをダウンロードせずに言語を選択します。 欠落した翻訳キーは、キー自体として表示されます。 以下の例は、共有されたUIパックを読み込みます。 他のプラグインがインストールされている場合、同じ呼び出しでターゲット言語パックをマージしてください。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

`mergeLocales`は複数のプラグインやプリセットから1つの完全な言語パックオブジェクトに言語パックを組み合わせたものです。

### カスタム言語パック

Univerは、カスタム言語パックもサポートしています。必要に応じて言語パックオブジェクトを組み立て、`Univer`インスタンスに渡します。プリセット言語パックは、一般的に`<rootDir>/packages/<PLUGIN_NAME>/locale`ディレクトリに保存されます。

````typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
````

### 翻訳への貢献

Univerは、以下の組み込み言語パックを提供します。

- `zh-CN`: 中国語（簡体字）
- `en-US`: 英語
- `zh-TW`: 中国語（繁体字）
- `zh-HK`: 中国語（繁体字・香港）
- `ru-RU`: ロシア語
- `vi-VN`: ベトナム語
- `fa-IR`: ペルシャ語
- `fr-FR`: フランス語
- `ja-JP`: 日本語
- `ko-KR`: 韓国語
- `es-ES`: スペイン語
- `ca-ES`: カタルーニャ語
- `sk-SK`: スロバキア語
- `ar-SA`: アラビア語
- `de-DE`: ドイツ語
- `id-ID`: インドネシア語
- `it-IT`: イタリア語
- `pl-PL`: ポーランド語
- `pt-BR`: ポルトガル語（ブラジル）

また、Univerはオープンソースプロジェクトであり、すべての地域の開発者が言語パックを追加または改善することを歓迎しています。

## 地域設定

`region` は、地域機能で使用される地域の慣行を選択します。`locale`と同様に、Univerインスタンスに属し、インスタンス内のすべてのユニットによって共有されます。

どちらの設定も取ります。 `LocaleType` 値。例えば、値の `LocaleType.EN_US` です。 `enUS`, しばらくの間 `en-US` 言語パックファイル名とBCP 47タグです。 などの国コードを渡さないでください。 `US` または `SG` として `region`. UI が異なる言語を使用している場合、その領域は独自の言語パックを必要としません。

`region`が明示的に設定されていない場合、その後の`setLocale()`呼び出しを含む`locale`に続いています。 `region`は初期化または`setRegion()`で設定されている場合は、自動的に次の停止を呼び出され、その後の言語変更は選択した領域を保持します。 パブリックAPIは、次の自動復帰しません。 両方の値が一緒に変更する必要がある場合は、それらの両方を設定してください。

ドイツの地方慣習を使ってUI言語を維持するために、`createUniver()`または`new Univer()`の`locale`の隣に`region: LocaleType.DE_DE`を加えて下さい。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

ここでは、UIは英語と地域の書式がドイツ語のままです。 `getCurrentLocale()`と`getCurrentRegion()`は、効果的な識別子を返します。 一度に両方の変更を行うには、同じ`LocaleType`値のセッターを呼び出します。

- **シート:通貨コントロール**: `region`は通貨ツールバーのアイコン、通貨と会計オプションとプレビュー、通貨コマンドで適用されるフォーマットを選択します。 地域を変更すると、既存のセルのフォーマットを刷新したり、通貨の値を変換したりしません。
- **Docs: 統計**:`region`は、統計ダイアログとステータスバーに表示された数字をフォーマットします。例えば、グループ分けの区切り文字。`region`を変更してもカウントルールは変更されません。
- **スレッドコメント, 有効にしたときに**: `region`は、24時間時間、ラテンの数字を使用して、日付と時刻がどのように表示されるかを決定します。 `locale`では、コメントUIテキストを決定します。 保存されたタイムスタンプを変更し、`region`がタイムゾーンの設定ではありません。
- **ボード、スライド、ベース、PDF**: `locale`は、翻訳されたUIを制御します。 `region` は、統合時にスレッドコメントなど、消費する機能を共有することができます。 ボードまたはスライドテキスト、ベースフィールド、またはPDFコンテンツを自動的に再フォーマットしません。

## 右から左へのレイアウト

<Callout type="warning" title="キューション">
  RTL は UI レイヤーのみをカバーしています。レンダリングレイヤーは RTL をサポートしていません。
</Callout>

<Callout type="warning" title="キューション">
  すべてのプラグインが言語パックを提供していません。各機能ページは、それが実行するかどうかを状態にします。
</Callout>

```typescript
univerAPI.setDirection('rtl')
```
