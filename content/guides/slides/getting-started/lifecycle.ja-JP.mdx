## グローバルライフサイクル

- **スタート**:初期化が進んでおり、まだビジネスユニットが存在しません。
- **レディー**:最初のビジネスユニットが作成されました。 ユニットは、このステージを再びトリガーしません。
- **レンダリングされる**: 標準UIは最初のレンダリングスイッチを完了しました。 これは、すべての非同期コンテンツが準備が整っているわけではありません。
- **ステアディ**: 標準UIはレンダリングされた後、この段階に時間を入れます。それはすべての非同期のタスクを待っていません。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="イベントが通知する対象">

`LifeCycleChanged`はUniverのグローバルステージを報告しています。例えば、プラグインBが`Ready`に達した後に読み込まれた場合、Bは`onReady()`を実行しますが、第2のグローバル`Ready`イベントは発生しません。

リスナーを追加すると、そのコールバックは、`Starting`を含む、すぐに現在のステージを受け取ることができます。 現在のステージのみを取得するには、`univerAPI.getCurrentLifecycleStage()`を直接呼び出します。

</Callout>

リスナーを削除するには、返された`disposable`オブジェクトを使用します。

```typescript
disposable.dispose()
```

## プラグインのライフサイクルフック

プラグインは、読み込まれたときに `onStarting()` を実行し、現在のグローバルステージまでキャッチします。 A の呼び出しを比較するために B がロードするステージを制御します。

<LifecycleDemo />

一般的なプラグインは、登録にロードします。 ビジネスタイプのプラグインは通常、そのタイプの最初のユニットが構築される前にロードします。 既に不良なバッチにロードを開始したタイプの新しいプラグイン。 明示的な依存関係は、以前のロードをトリガーすることができます。

同じバッチのホックは同期的に呼び出され、ステージと依存の順番でステージを合わせ、Univerは内部の非同期タスクを待ちません。特定のユニット、DOM要素、またはリソースがアクセスする前に準備が整っていることを確認してください。
