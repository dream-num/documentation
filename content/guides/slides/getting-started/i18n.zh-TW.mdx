## 介面語言

`locale` 決定選單、提示、對話方塊和其他介面文案使用哪個語言套件。`locales` 只註冊語言套件，不負責選擇語言。該配置屬於 Univer 例項，由例項中的所有文件單元共享。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有產品：介面**：`locale` 改變選單、提示、對話方塊和外掛標籤的翻譯，但不會翻譯使用者內容，也不會重新命名已有文件單元。
- **Sheets：單元格格式與公式**：單元格渲染數字或日期時，先檢查數字格式中的 locale 覆蓋值，再檢查工作簿快照的 `locale`，最後檢查例項的 `locale`。`region` 不替代其中任何一層。`DOLLAR` 等公式行為，以及財務結果應用的貨幣格式，仍然跟隨 `locale`。中日韓輸入歸一化的行為相同。
- **Docs：文件統計**：`locale` 決定分詞和字數統計。

### 執行時切換語言

切換語言之前，先載入已安裝外掛或預設的全部語言套件。`loadLocales()` 合併翻譯，但不改變當前語言；`setLocale()` 只選擇語言，不會下載任何內容。缺少翻譯的鍵會直接顯示為鍵名。下面的範例載入共享 UI 語言套件；如果安裝了其他外掛，請在同一次呼叫中合併它們的目標語言套件。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 合併語言套件 [#mergeLocales]

`mergeLocales` 將多個外掛或預設的語言套件合併為一個完整的語言套件物件：

### 自訂語系檔

Univer 也支援自定義語言套件。按需要組裝語言套件物件，並傳給 `Univer` 例項。預設語言套件一般存放在 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目錄中。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 貢獻語系

Univer 內建以下語言套件：

- `zh-CN`：簡體中文
- `en-US`：英文
- `zh-TW`：繁體中文（臺灣）
- `zh-HK`：繁體中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韓文
- `es-ES`：西班牙文
- `ca-ES`：加泰羅尼亞文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：義大利文
- `pl-PL`：波蘭文
- `pt-BR`：葡萄牙文（巴西）

其他語言暫未支援。Univer 是開源專案，歡迎各地開發者新增或改進語言套件。

## 地區設定

`region` 決定地區相關功能採用的地區習慣。它和 `locale` 一樣屬於 Univer 例項，由例項中的所有文件單元共享。

兩項配置都使用 `LocaleType` 取值。例如 `LocaleType.EN_US` 的值為 `enUS`，而 `en-US` 是語言套件檔名，也是 BCP 47 標籤。不要把 `US`、`SG` 等國家程式碼傳給 `region`。介面使用另一種語言時，地區不需要額外載入自己的語言套件。

未顯式設定 `region` 時，它跟隨 `locale`，之後呼叫 `setLocale()` 也會同步變化。如果在初始化時設定了 `region`，或呼叫過 `setRegion()`，自動跟隨就會停止，之後切換語言會保留已選地區。目前沒有恢復自動跟隨的公開 API；需要兩者一起變化時，請同時設定。

要在保留介面語言的同時使用德國地區習慣，請在 `createUniver()` 或 `new Univer()` 的 `locale` 旁新增 `region: LocaleType.DE_DE`。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此時介面為英文，地區格式仍為德國。`getCurrentLocale()` 和 `getCurrentRegion()` 返回當前生效的標識。要同時改變兩者，請用相同的 `LocaleType` 值分別呼叫兩個 setter。

- **Sheets：貨幣操作**：`region` 決定貨幣工具欄圖示、貨幣和會計格式的選項與預覽，以及貨幣命令應用的格式。切換地區不會重寫已有單元格格式，也不會換算金額。
- **Docs：文件統計**：`region` 決定統計對話方塊和狀態列中數字的顯示格式，例如分組分隔符。只改變 `region` 不會改變統計規則。
- **啟用評論時**：`region` 決定日期和時間的顯示格式，使用 24 小時制和拉丁數字；`locale` 決定評論介面文案。兩者都不會改變已儲存的時間戳，`region` 也不是時區設定。
- **Boards、Slides、Bases、PDFs**：`locale` 控制介面翻譯。`region` 供會用到它的共享功能使用，例如接入後的評論。它不會自動重新格式化白板或幻燈片文字、Base 欄位或 PDF 內容。
