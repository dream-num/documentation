## 界面语言

`locale` 决定菜单、提示、对话框和其他界面文案使用哪个语言包。`locales` 只注册语言包，不负责选择语言。该配置属于 Univer 实例，由实例中的所有文档单元共享。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有产品：界面**：`locale` 改变菜单、提示、对话框和插件标签的翻译，但不会翻译用户内容，也不会重命名已有文档单元。
- **Sheets：单元格格式与公式**：单元格渲染数字或日期时，先检查数字格式中的 locale 覆盖值，再检查工作簿快照的 `locale`，最后检查实例的 `locale`。`region` 不替代其中任何一层。`DOLLAR` 等公式行为，以及财务结果应用的货币格式，仍然跟随 `locale`。中日韩输入归一化的行为相同。
- **Docs：文档统计**：`locale` 决定分词和字数统计。

### 运行时切换语言

切换语言之前，先加载已安装插件或预设的全部语言包。`loadLocales()` 合并翻译，但不改变当前语言；`setLocale()` 只选择语言，不会下载任何内容。缺少翻译的键会直接显示为键名。下面的示例加载共享 UI 语言包；如果安装了其他插件，请在同一次调用中合并它们的目标语言包。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

`mergeLocales` 将多个插件或预设的语言包合并为一个完整的语言包对象：

### 自定义语言包

Univer 也支持自定义语言包。按需要组装语言包对象，并传给 `Univer` 实例。预设语言包一般存放在 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目录中。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 贡献语言包

Univer 内置以下语言包：

- `zh-CN`：简体中文
- `en-US`：英文
- `zh-TW`：繁体中文
- `zh-HK`：繁体中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韩文
- `es-ES`：西班牙文
- `ca-ES`：加泰罗尼亚文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：意大利文
- `pl-PL`：波兰文
- `pt-BR`：葡萄牙文（巴西）

其他语言暂未支持。Univer 是开源项目，欢迎各地开发者添加或改进语言包。

## 地区设置

`region` 决定地区相关功能采用的地区习惯。它和 `locale` 一样属于 Univer 实例，由实例中的所有文档单元共享。

两项配置都使用 `LocaleType` 取值。例如 `LocaleType.EN_US` 的值为 `enUS`，而 `en-US` 是语言包文件名，也是 BCP 47 标签。不要把 `US`、`SG` 等国家代码传给 `region`。界面使用另一种语言时，地区不需要额外加载自己的语言包。

未显式设置 `region` 时，它跟随 `locale`，之后调用 `setLocale()` 也会同步变化。如果在初始化时设置了 `region`，或调用过 `setRegion()`，自动跟随就会停止，之后切换语言会保留已选地区。目前没有恢复自动跟随的公开 API；需要两者一起变化时，请同时设置。

要在保留界面语言的同时使用德国地区习惯，请在 `createUniver()` 或 `new Univer()` 的 `locale` 旁添加 `region: LocaleType.DE_DE`。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此时界面为英文，地区格式仍为德国。`getCurrentLocale()` 和 `getCurrentRegion()` 返回当前生效的标识。要同时改变两者，请用相同的 `LocaleType` 值分别调用两个 setter。

- **Sheets：货币操作**：`region` 决定货币工具栏图标、货币和会计格式的选项与预览，以及货币命令应用的格式。切换地区不会重写已有单元格格式，也不会换算金额。
- **Docs：文档统计**：`region` 决定统计对话框和状态栏中数字的显示格式，例如分组分隔符。只改变 `region` 不会改变统计规则。
- **启用评论时**：`region` 决定日期和时间的显示格式，使用 24 小时制和拉丁数字；`locale` 决定评论界面文案。两者都不会改变已存储的时间戳，`region` 也不是时区设置。
- **Boards、Slides、Bases、PDFs**：`locale` 控制界面翻译。`region` 供会用到它的共享功能使用，例如接入后的评论。它不会自动重新格式化白板或幻灯片文本、Base 字段或 PDF 内容。
