## Cycle de vie global

- **Début** : L'initialisation est en cours, et aucune unité opérationnelle n'existe encore.
- **Prêt**: La première unité d'affaires a été créée. Les unités créées plus tard ne déclenchent plus cette étape.
- **Rendu**: L'interface utilisateur standard a complété son premier commutateur de rendu. Cela ne signifie pas que tout le contenu asynchrone est prêt.
- **Stabilité**: L'interface utilisateur standard entre dans cette étape un certain temps après le rendu. Elle n'attend pas toutes les tâches asynchrones.

### API Facade

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Ce que signale l’événement">

`LifeCycleChanged` rapporte la phase globale de Univer. Par exemple, lorsque le plugin B se charge après que la phase globale ait atteint `Ready`, B exécute son `onReady()` mais aucun second événement global `Ready` n'est émis.

Lorsqu'un auditeur est ajouté, son callback peut recevoir immédiatement l'étape courante, y compris `Starting`. Pour obtenir seulement l'étape actuelle, appelez directement `univerAPI.getCurrentLifecycleStage()` .

</Callout>

Pour supprimer un auditeur, utilisez l'objet `disposable` retourné :

```typescript
disposable.dispose()
```

## Hooks de cycle de vie des plugins

Un plugin exécute `onStarting()` lorsqu'il charge, puis rattrape jusqu'à la phase globale actuelle. Contrôlez le stade auquel B charge afin de comparer ses appels de crochet avec ceux de A.

<LifecycleDemo />

Les plugins de type Business chargent généralement avant que la première unité de ce type soit construite. De nouveaux plugins pour un type qui a déjà commencé la charge dans un lot différé. Les dépendances explicites peuvent déclencher une charge plus précoce.

Les crochets dans le même lot sont appelés synchrones, étape par étape et dans l'ordre de dépendance, et Univer n'attend pas les tâches asynchrones à l'intérieur d'eux. Confirmez que l'unité spécifique, l'élément DOM ou la ressource est prêt avant d'y accéder.
