## Язык интерфейса

`locale` выбирает языковой пакет для меню, подсказок, диалогов и другого переведенного пользовательского интерфейса. `locales` регистрирует языковые пакеты без выбора одного. Этот параметр принадлежит экземпляру Univer и разделяется всеми единицами в экземпляре. Используйте значения `LocaleType`, такие как `LocaleType.EN_US`.

- **Все продукты: интерфейс**: `locale` меняет переводы меню, подсказок, диалогов и подписей плагинов. Пользовательский текст и имена существующих документов не меняются.
- **Листы: форматы ячеек и формулы**: Когда ячейка отображает номер или дату, Univer сначала проверяет переопределение локального формата номера, затем снимок из книги `locale` и, наконец, экземпляр `locale`. `region` не заменяет ни один из них. Формулы, такие как `DOLLAR`, вместе с валютным форматом, применяемым к финансовым результатам, по-прежнему следуют `locale` . Нормализация ввода CJK ведет себя так же.
- **Док: статистика**: `locale` определяет сегментацию и подсчет слов.

### Смена языка во время работы

Загрузите все языковые пакеты для установленных плагинов или предустановок перед переключением. `loadLocales()` сливает переводы без изменения текущего языка; `setLocale()` выбирает язык без загрузки каких-либо данных. В качестве самого ключа отображается отсутствующий ключ перевода. Пример ниже загружает общий пакет пользовательского интерфейса. Если установлены другие плагины, объедините их пакеты целевого языка в том же вызове.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Пользовательские языковые пакеты

Univer также поддерживает пользовательские языковые пакеты. Соберите объект языкового пакета по мере необходимости и перенесите его в экземпляр `Univer`. Предустановленные языковые наборы обычно хранятся в каталоге `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Участие в переводе

Univer предоставляет следующие встроенные языковые пакеты:

- `zh-CN`: упрощённый китайский
- `en-US`: английский
- `zh-TW`: традиционный китайский
- `zh-HK`: традиционный китайский (Гонконг)
- `ru-RU`: русский
- `vi-VN`: вьетнамский
- `fa-IR`: персидский
- `fr-FR`: французский
- `ja-JP`: японский
- `ko-KR`: корейский
- `es-ES`: испанский
- `ca-ES`: каталонский
- `sk-SK`: словацкий
- `ar-SA`: арабский
- `de-DE`: немецкий
- `id-ID`: индонезийский
- `it-IT`: итальянский
- `pl-PL`: польский
- `pt-BR`: португальский (Бразилия)

Univer - это проект с открытым исходным кодом, и разработчики из всех регионов могут добавлять или улучшать языковые пакеты.

## Региональные настройки

`region` выбирает региональные конвенции, используемые региональными функциями.Как и `locale`, он принадлежит экземпляру Univer и разделяется всеми единицами в экземпляре.

Обе настройки принимают значения `LocaleType`. Например, значение `LocaleType.EN_US` — `enUS`, в то время как `en-US` является именем файла языкового пакета и тегом BCP 47. Не пропускайте коды стран, такие как `US` или `SG` как `region` Когда пользовательский интерфейс использует другой язык, регион не требует своего собственного языкового набора.

Когда `region` не установлен явно, он следует за `locale`, включая последующие вызовы `setLocale()`. Если `region` установлен при инициализации или `setRegion()` был вызван, автоматические следующие остановки и более поздние языковые изменения сохраняют выбранную область. Никакой публичный API не восстанавливает автоматическое следование; когда оба значения должны изменяться вместе, установите оба из них.

Чтобы сохранить язык пользовательского интерфейса при использовании немецких региональных конвенций, добавьте `region: LocaleType.DE_DE` рядом с `locale` в `createUniver()` или `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Здесь UI - английский, а региональное форматирование остается немецким. `getCurrentLocale()` и `getCurrentRegion()` возвращают эффективные идентификаторы. Чтобы изменить оба сразу, вызовите оба сеттера с одинаковым значением `LocaleType`.

- **Листы: валютный контроль**: `region` выбирает значок панели инструментов валюты, параметры валюты и бухгалтерского учета и предварительные просмотры, а также формат, применяемый командой валюты. Изменение региона не переписывает существующие форматы ячеек или конвертирует денежные значения.
- **Док: статистика**: `region` форматирует цифры, отображаемые в диалоге статистики и строке состояния, например разделители групп.Изменение `region` не меняет правил подсчета.
- **Комментарии, когда включено**: `region` определяет, как отображаются даты и время, используя 24-часовое время и латинские цифры; `locale` определяют текст пользовательского интерфейса комментария.Ни один из них не изменяет сохраненные временные метки, а `region` не является настроем часовой зоны.
- **Доски, слайды, базы, PDF**: `locale` управляет переведенным пользовательским интерфейсом. `region` доступен для общих функций, которые потребляют его, таких как комментарии потоков при интеграции. Он не автоматически переформатирует доску или слайд-текст, поля базы или PDF-контент.

</Callout>
