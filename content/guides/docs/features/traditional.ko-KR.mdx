적용 대상: 전통 문서.

실제 페이지가 있는 보고서와 계약서를 만듭니다. 전통 문서는 섹션으로 페이지 크기, 여백, 단, 머리글과 바닥글을 관리합니다. 텍스트와 콘텐츠 블록에는 공통 Docs API를 사용합니다.

먼저 [설치](/guides/docs/getting-started/installation)를 완료하고 [해당 유형의 문서를 생성](/guides/docs/getting-started/document-types#create-document)하세요. 아래 코드는 해당 문서에 순서대로 적용합니다.

레이아웃 API를 호출하기 전에 문서 유형을 확인하세요.

```typescript
const doc = univerAPI.getActiveDocument()
if (!doc?.isTraditional()) throw new Error('Create a Traditional document first')
```

## 페이지 설정 [#page-setup]

첫 번째 섹션을 설정합니다. 아래 치수는 96 DPI 레이아웃 픽셀입니다. 섹션 설정이 문서 기본값보다 우선하며 `getEffectivePageSetup()`은 실제 적용값을 반환합니다.

```typescript
const section = doc.getSection(0)
if (!section) throw new Error('Section not found')

const updated = section.setPageSetup({
  pageSize: { width: 794, height: 1123 },
  marginTop: 72,
  marginBottom: 72,
  marginLeft: 72,
  marginRight: 72,
})
if (!updated) throw new Error('Page setup failed')
console.log(section.getEffectivePageSetup())
```

## 페이지 단 나누기 [#page-columns]

전통 문서 섹션 안의 페이지 단입니다. 페이지를 배치할 때 텍스트가 단을 따라 흐릅니다. `setColumns(1)`로 한 단으로 복원합니다. 현대 문서의 [단 그룹](/guides/docs/features/columns)과는 다릅니다.

```typescript
if (!section.setColumns(2, { gap: 18, separator: true })) {
  throw new Error('Page columns could not be updated')
}
console.log(section.describe().columnCount) // 2
```

## 머리글, 바닥글과 필드 [#header-footer-fields]

섹션에 속한 머리글과 바닥글 세그먼트를 만든 뒤 공통 문단 API로 편집합니다. 반환된 segment ID는 각 텍스트 스트림을 식별합니다. 전용 Ribbon은 페이지 번호, 첫 페이지/홀짝 페이지, 날짜와 시간 필드를 제공합니다.

```typescript
const headerId = section.ensureHeader()
const footerId = section.ensureFooter()
doc.appendParagraph('Launch plan | Internal', headerId)
doc.appendParagraph('Product Operations', footerId)
```

전통 문서의 머리글이나 바닥글을 편집하면 삽입, 탐색, 첫 페이지 및 홀수/짝수 페이지 옵션과 위치 설정을 위한 컨텍스트 Ribbon이 표시됩니다. 현재 페이지 번호, 전체 페이지 수, 현지화된 날짜와 시간을 삽입할 수 있습니다. 페이지 필드는 각 페이지에 맞는 값을 표시합니다. 날짜/시간의 자동 업데이트를 켜면 필드로, 끄면 고정 텍스트로 삽입됩니다. 날짜/시간 필드는 문서를 열거나 필드 업데이트를 실행할 때 갱신되며 시계처럼 계속 바뀌지는 않습니다. 현대 문서는 페이지 머리글과 바닥글을 사용하지 않습니다.

## 페이지 나누기 규칙 [#pagination]

`keepNext`는 제목과 다음 문단을, `keepLines`는 문단의 줄들을 가능한 한 같은 페이지에 유지합니다. `pageBreakBefore`는 새 페이지에서 문단을 시작합니다. 한 페이지보다 긴 내용은 나뉠 수 있습니다. 현대 문서는 이 규칙으로 실제 페이지를 나누지 않습니다.

```typescript
const title = doc.findParagraphByText('Launch plan')
if (!title) throw new Error('Title not found')
title.setStyle({ keepNext: univerAPI.Enum.BooleanNumber.TRUE, keepLines: univerAPI.Enum.BooleanNumber.TRUE })

const checklist = doc.appendParagraph('Delivery checklist')
checklist.setStyle({ pageBreakBefore: univerAPI.Enum.BooleanNumber.TRUE })
```

## 섹션 [#sections]

최상위 문단 경계에 섹션 나누기를 삽입합니다. `nextSectionType`은 다음 섹션의 시작 방식을 지정합니다. 앞부분을 편집해도 섹션 ID는 유지됩니다. `getSection(index)`는 ID가 아니라 0부터 시작하는 인덱스를 받습니다.

```typescript
const chapter = doc.findParagraphByText('Delivery checklist')
if (!chapter) throw new Error('Chapter not found')

const previousSection = doc.insertSectionBreak(chapter.getInfo().startOffset, {
  nextSectionType: univerAPI.Enum.SectionType.NEXT_PAGE,
})
if (!previousSection) throw new Error('Section break could not be inserted')
console.log(doc.getSections().map(item => item.getId()))
```
