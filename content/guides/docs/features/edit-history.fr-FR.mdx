Après avoir modifié des paragraphes, des formats ou des tables, l'historique vous permet d'inspecter les versions antérieures, de comparer les modifications et de restaurer une version lorsque vous en avez la permission. Les versions sont stockées par le serveur. L'annulation et le redémarrage sont indépendants de l'historique : ils s'appliquent à la session d'édition actuelle et ne nécessitent pas de service d'historique.

## Préparer les services de collaboration et d’historique

Terminez d'abord [l'intégration de la collaboration](/server/collaboration/browser-integration) et [configuration de licence](/server/license). Vérifiez ensuite que deux sessions peuvent modifier le même document Docs et que les modifications survivent à un rechargement.

Connectez le stockage et les permissions d'historique comme décrit dans [Prolongation de la collaboration avec les bureaux](/server/collaboration/extensions) et le [Exemple historique](/server/collaboration/examples#history). La collaboration de base n'autorise pas l'historique par elle-même ; le moteur doit également servir les listes d'historique, le contenu de la version et la restauration.

Ajouter cette configuration à la configuration existante du produit, de la licence et de la collaboration. Si un préréglage ou une configuration existante enregistre déjà ces plugins, modifiez cette configuration au lieu de les enregistrer une seconde fois.

## Mode plugin [#plugin-mode]

### Installation

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/docs-history @univerjs-pro/docs-history-ui
```

### Utilisation

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverDocsHistoryPlugin } from '@univerjs-pro/docs-history'
import { UniverDocsHistoryUIPlugin } from '@univerjs-pro/docs-history-ui'
import HistoryLocale from '@univerjs-pro/docs-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverDocsHistoryPlugin)
univer.registerPlugin(UniverDocsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuration des plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |

`UniverDocsHistoryUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |
| `univerContainerId` | `string` |  | ID DOM du conteneur de l’éditeur. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Plugins supplémentaires du visualiseur d’historique. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Le constructeur du plugin. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Options acceptées par ce constructeur. |

Définissez `/api/history` sur le paramètre d'historique de l'application et assurez-vous que le paramètre répond aux demandes envoyées par le client. Les deux valeurs `historyServerUrl` doivent être identiques. Définissez la valeur `univerContainerId` dans l'ID DOM du conteneur de l'éditeur et chargez la localité qui correspond à la langue de l'édition.

Si les documents contiennent du contenu personnalisé, utilisez `viewerPlugins` pour ajouter les plugins que le visionneur n'inclut pas. N'enregistrez pas les plugins de visionneuse intégrés à nouveau.

## Mode prédéfini [#preset-mode]

### Installation

```package-install
npm install @univerjs/preset-docs-collaboration
```

### Utilisation

`UniverDocsCollaborationPreset` inclut déjà l'interface d'historique et les plugins dont elle dépend. Gardez l'éditeur existant et la configuration de la licence. Si le préréglage est déjà enregistré, mettez à jour cette inscription au lieu d'enregistrer le préréglé ou les plugins d'historique une seconde fois.

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'
import CollaborationLocale from '@univerjs/preset-docs-collaboration/locales/en-US'
import '@univerjs/preset-docs-collaboration/lib/index.css'

const collaborationPreset = UniverDocsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### Configuration des préréglages

`UniverDocsCollaborationPreset`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | URL de base du serveur de collaboration. |
| `univerContainerId` | `string` | `'app'` | ID DOM du conteneur de l’éditeur. |

Ajouter `collaborationPreset` au tableau `presets` de l'appel `createUniver()` existant, et fusionner `CollaborationLocale` dans l'entrée locale pour la langue correspondante. Définissez `universerEndpoint` à l'URL de base du serveur et `univerContainerId` vers l'ID du conteneur de l'éditeur. Le préréglage construit l'URL historique sous `{universerEndpoint}/universer-api/history`. Utilisez le mode Plugin si vous avez besoin d'une configuration personnalisée `historyServerUrl` ou `viewerPlugins` . L'un ou l'autre mode nécessite toujours les services de backend décrits ci-dessus.

## Consulter et restaurer des versions

Ouvrez l'historique dans le menu de l'éditeur et sélectionnez une version pour inspecter son contenu et les modifications qu'il contient. Restaurer une version modifie le document partagé actuel, de sorte qu'il devrait être limité aux utilisateurs avec la permission de restauration, et le serveur doit faire respecter cette autorisation.

Pour vérifier l'intégration, modifier les paragraphes, le formatage ou les tables, attendre que la collaboration confirme les modifications, puis inspecter la liste d'historique et le contenu de la version. Réouvrir l'application et redémarrer le service pour confirmer que les données persistent. Restaurer une version antérieure et confirmer qu'une session dans un autre navigateur reçoit l'état restauré.

Si la liste est vide, vérifiez d'abord si l'historique a été enregistré pour ce document, puis vérifiez l'ID du document et l'URL du service. Si les versions peuvent être consultées mais que la restauration échoue, vérifiez les permissions de restauration et la connexion de collaboration.

## Comparer des snapshots [#compare-snapshots]

Pour créer un écran d'examen, ou pour fournir une description de ce qui a changé à un agent AI, appelez `compareUnitData()`, ou préparez une comparaison une fois avec `prepareUnitComparison()` et demandez-la à plusieurs reprises. Enregistrez le plugin History pour le produit et importez l'entrée Facade. Passez deux instantanés entièrement matérialisés de la même unité que `beforeSnapshot` ou `afterSnapshot`. La comparaison est en lecture seule : elle ne nécessite aucun service d'historique, et elle ne restaure ni ne fusionne de contenu.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_DOC,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Lire `scopes` pour voir quelles vues sont disponibles, puis passer l'une d'entre elles à `query()` afin de restreindre le résultat sans revérifier la comparaison. Une page contient 100 éléments par défaut et accepte jusqu'à 1 000. Utilisez `page.hasMore` avec `offset` à récupérer les éléments restants. `summary` décrit l'ensemble de la comparaison même lorsque les éléments sont filtrés. Vérifiez `diagnostics.readiness` et `diagnostics.codes` avant de traiter le résultat comme une comparaison complète. Pour Node.js ou CLI sans éditeur, consultez le [API de comparaison sans tête](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
