단락, 서식, 또는 테이블을 편집 한 후, 역사는 이전 버전을 검사하고 변경 사항을 비교하고 권한이있을 때 버전을 복원 할 수 있습니다. 버전은 서버에 의해 저장됩니다. Undo 및 redo는 역사의 독립적입니다 : 그들은 현재 편집 세션에 적용하고 역사 서비스를 필요로하지 않습니다.

## 공동 편집 및 기록 서비스 준비

[협업 통합](/server/collaboration/browser-integration) 및 [인증 구성](/server/license)를 먼저 완료하십시오. 그런 다음 두 세션이 동일한 Docs 문서를 편집 할 수 있으며 변경은 다시로드를 살아남을 수 있습니다.

[Office 협업 확장](/server/collaboration/extensions) 및 [연혁 예](/server/collaboration/examples#history)에 설명된 기록 저장 및 권한을 연결하십시오. 핵심 협력은 자체로 역사를 활성화하지 않습니다; 백엔드는 또한 역사 명부, 버전 내용 및 복원을 봉사해야 합니다.

기존 제품, 라이센스 및 협업 설정에 이 구성을 추가하십시오. 미리 설정하거나 기존 구성이 이미이 플러그인을 등록하면 두 번째 시간을 등록하는 대신 구성을 수정합니다.

## 플러그인 모드 [#plugin-mode]

### 설치

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/docs-history @univerjs-pro/docs-history-ui
```

### 사용법

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverDocsHistoryPlugin } from '@univerjs-pro/docs-history'
import { UniverDocsHistoryUIPlugin } from '@univerjs-pro/docs-history-ui'
import HistoryLocale from '@univerjs-pro/docs-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverDocsHistoryPlugin)
univer.registerPlugin(UniverDocsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 플러그인 설정

`UniverEditHistoryPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |

`UniverDocsHistoryUIPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |
| `univerContainerId` | `string` |  | 편집기 컨테이너의 DOM ID입니다. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 기록 뷰어에 추가할 플러그인입니다. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 플러그인 생성자. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 그 생성자에 의해 허용되는 옵션. |

`/api/history`를 응용 프로그램의 자신의 역사 엔드포인트에 설정하고 클라이언트가 보낸 요청을 종료 할 수 있는지 확인합니다. `historyServerUrl` 값 모두 동일해야합니다. 편집기 컨테이너의 DOM ID에 `univerContainerId`을 설정하고 편집기 언어를 일치시키는 Locale를로드하십시오.

역사 뷰어는 별도의 읽기 전용 편집기를 엽니다. 문서가 사용자 정의 콘텐츠를 포함하면 뷰어가 포함되지 않는 플러그인을 추가하려면 `viewerPlugins`를 사용하십시오. 내장 뷰어 플러그인을 다시 등록하지 마십시오.

## 프리셋 모드 [#preset-mode]

### 설치

```package-install
npm install @univerjs/preset-docs-collaboration
```

### 사용법

`UniverDocsCollaborationPreset`는 이미 역사 UI와 플러그인을 포함합니다. 기존 편집기 및 라이센스 설정을 유지하십시오. 미리 설정이 이미 등록되면 사전 설정 또는 역사 플러그인을 등록하는 대신 등록을 업데이트하십시오.

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'
import CollaborationLocale from '@univerjs/preset-docs-collaboration/locales/en-US'
import '@univerjs/preset-docs-collaboration/lib/index.css'

const collaborationPreset = UniverDocsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### 프리셋 설정

`UniverDocsCollaborationPreset`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | 공동 편집 서버의 기본 URL입니다. |
| `univerContainerId` | `string` | `'app'` | 편집기 컨테이너의 DOM ID입니다. |

기존 `createUniver()` 통화의 `presets` 배열에 `collaborationPreset`를 추가하고, 일치한 언어를 위한 국부적으로 입장으로 `CollaborationLocale`를 합병합니다. `universerEndpoint`를 서버 기본적인 URL 및 `univerContainerId`에 편집기 콘테이너 ID에 놓으십시오. 미리 설치는 `{universerEndpoint}/universer-api/history`로 역사 URL을 건설합니다. 당신이 주문 `historyServerUrl` 또는 `viewerPlugins` 윤곽을 필요로 하는 경우에 플러그인 형태를 사용하십시오. 어떤 형태든지 아직도 위에 설명된 백엔드 서비스를 요구합니다.

## 버전 보기 및 복원

편집기 메뉴에서 역사를 열고 콘텐츠를 검사하는 버전을 선택하고 변경이 포함되어 있습니다. 버전이 현재 공유 된 문서를 수정하는 것을 복원 권한을 사용하여 사용자에게 제한해야합니다. 서버는 그 권한을 시행해야합니다.

통합, 편집 단락, 포맷, 또는 테이블을 확인하려면, 변경을 확인하기 위해 대기, 다음 역사 목록과 버전 콘텐츠를 검사합니다. 응용 프로그램을 다시 열고 데이터를 인식하는 서비스를 다시 시작합니다. 이전 버전을 복원하고 다른 브라우저에서 세션이 복원 된 상태를받습니다.

목록이 비어있는 경우, 역사가 기록 된지 확인한 후, 문서 ID 및 서비스 URL을 확인하십시오. 버전이 보이지만 복원이 실패하면 복원 권한 및 협업 연결을 확인하십시오. 이전 버전이 삭제 된 데이터를 포함 할 수 있기 때문입니다.

## 스냅샷 비교 [#compare-snapshots]

검토 화면을 구축하려면, 또는 변경 된 설명과 AI 에이전트를 제공, `compareUnitData()` 호출, 또는 `prepareUnitComparison()`와 한 번 비교를 준비하고 반복적으로 쿼리. 제품에 대한 역사 플러그인을 등록하고 Facade 항목을 가져. `beforeSnapshot` 및 `afterSnapshot`과 같은 동일한 단위의 2 개의 완전히 재료 스냅 샷을 통과. 비교는 읽기 전용입니다: 그것은 역사 서비스가 필요 없으며, 그것은 콘텐츠와 결합하지 않습니다.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_DOC,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

읽음 `scopes` 볼 수 있듯이, 그 중 하나를 통과 `query()` 비교를 다시 실행하지 않고 결과를 좁히기 위해. 페이지는 기본으로 100 항목을 보유하고 1,000까지 수용합니다. 사용 `page.hasMore` 이름 * `offset` 나머지 아이템을 묶기 위해. `summary` 항목이 필터링 될 때 전체 비교를 설명합니다. 체크 `diagnostics.readiness` 그리고, `diagnostics.codes` 완전한 비교로 결과를 대우하기 전에. Node.js 또는 편집자없이 CLI 사용, 참조 [headless 비교 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
