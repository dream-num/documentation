Univer Docs provides core features including a document editor, formula engine, rendering engine, design system, and UI component library. Together, they form a powerful document processing platform that supports various document formats and complex operations.

## Features

Univer Docs core features include:

- **Document Rendering**: Supports rendering of Univer Docs, including cursor and selection rendering.
- **Document Typesetting**: Supports full-text typesetting, including paragraph settings, spacing before and after paragraphs, paragraph alignment, indentation, and hanging indent. It also includes typesetting capabilities within paragraphs, such as punctuation compression, hanging punctuation, character spacing, and Western word breaking.
- **Formula Calculation**: Supports adding and calculating Univer formulas (in development).
- **Table Capabilities**: Supports inserting basic tables and editing tables, including adding and deleting rows, and editing cells.
- **Document Styles**: Univer Docs supports both _traditional document styles_ similar to Microsoft Word (including pagination, headers, and footers) and _modern document styles_ similar to Notion. In modern document styles, pagination is not required, content can expand infinitely, and it supports mixed typesetting of various official or third-party block-level elements (such as text, images, tables, etc.) (planned).
- **Headers and Footers**: Supports inserting headers and footers, editing header and footer content, and distinguishing between first pages and odd/even pages (only supported in traditional documents).
- **List Features**: Supports inserting and editing ordered, unordered, and task lists, as well as list indentation and outdenting.
- **Emoji and Symbols**: Insert emoji and symbols from the Docs ribbon.
- **Plugin System**: Supports a plugin system that allows for custom plugins, such as formula plugins, image plugins, chart plugins, etc. This is also one of the core architectural capabilities of Univer.

## Plugin Mode

### Installation

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/design @univerjs/ui @univerjs/docs @univerjs/docs-ui
```

### Usage

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import DesignEnUS from '@univerjs/design/locale/en-US'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
import DocsUIEnUS from '@univerjs/docs-ui/lib/locale/en-US'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverUIPlugin } from '@univerjs/ui'
import UIEnUS from '@univerjs/ui/locale/en-US'
import '@univerjs/docs/facade'
import '@univerjs/docs-ui/facade'
import '@univerjs/design/lib/index.css'
import '@univerjs/ui/lib/index.css'
import '@univerjs/docs-ui/lib/index.css'

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(DesignEnUS, UIEnUS, DocsUIEnUS),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverUIPlugin, {
  container: 'app',
})
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverDocsUIPlugin)

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})
```

## Viewing controls [#ribbon-controls]

The View ribbon contains page settings, zoom, and fullscreen controls. The zoom selector and bottom zoom bar reflect the same document view scale; changing it does not change text formatting.

## Menu order and grid layout [#menu-order-and-grid-layout]

Define the shared [`MenuConfig`](/reference/packages/plugins/univerjs/ui#menuconfig) with Docs menu IDs, then apply it using either integration mode:

```ts
import type { MenuConfig } from '@univerjs/ui'

const menu: MenuConfig = {
  'ribbon.start.format': { order: -1 },
  'doc.command.set-inline-format-bold': {
    order: 0,
    gridLayout: { row: 2, column: 2 },
  },
  'doc.command.set-inline-format-italic': {
    gridLayout: { row: 2, column: 1 },
  },
}
```

Choose your integration mode and merge these options into the existing initialization. Keep your other plugins, locale, theme, and container settings; do not register the same plugin twice.

## Document outline [#document-outline]

The left outline navigates between headings; it does not insert a table of contents into the document. With `toc` omitted, it is enabled for Modern documents and disabled for Traditional documents. Explicit `true` or `false` overrides either default. The panel collapses when space is insufficient or a table overlaps it, then reopens when space is available.

Merge this option into your existing initialization; do not register the same plugin twice.

## Update menus with the Facade API [#menu-facade]

After initialization, use [`updateMenuConfig()`](/reference/facade/univer#updatemenuconfig) to update the existing instance:

```ts
import '@univerjs/ui/facade'

univerAPI.updateMenuConfig(menu)
```

`order` sorts siblings from lowest to highest; `gridLayout` only applies to the grid Ribbon, using 1-based coordinates within a two-row group. Runtime updates preserve unspecified properties and refresh the UI immediately. In plugin mode, pass `menu` to `UniverUIPlugin` and import `@univerjs/ui/facade` before using the Facade. See the [menu layout guide](/guides/sheets/features/core#menu-order-and-grid-layout) for grid fields and custom buttons.

## Paste options [#paste-options]

Docs provides three paste modes: keep source formatting, match destination formatting, and keep text only. Destination formatting retains supported emphasis such as bold and italic while adopting the target text and paragraph styles. Text-only paste removes images and hyperlinks; table content becomes tab-separated text. Use the post-paste options to change the most recent paste. If the browser blocks clipboard reads, use its keyboard or system paste action.

On desktop, the Ribbon **Paste** dropdown appears beside undo and redo and is hidden while editing shape text. The **Paste special** submenu is in the formatting group of both desktop and mobile context menus.

## Header and footer fields [#header-footer-fields]

In traditional documents, editing a header or footer opens a contextual Ribbon for insertion, navigation, first-page and odd/even-page options, and positioning. It can insert current-page and total-page fields, or a localized date and time. Page fields display values for each rendered page. For date/time, enable automatic updating to store a field, or disable it to insert fixed text. Date/time fields refresh when the document opens or when you choose **Update fields**; they are not a continuously ticking clock. Modern documents do not use page headers or footers.

## Collapse heading sections [#heading-collapse]

Modern documents (`documentStyle.documentFlavor: DocumentFlavor.MODERN`) show a triangle beside Heading 1–5 when the heading has section content. Collapsing keeps the heading visible and hides everything up to the next heading of the same or higher level, including nested headings, tables, and images. Each table cell and Modern column has its own heading hierarchy.

This works independently of `toc`. Traditional documents and embedded text editors do not show collapse controls. Expanding a parent retains its nested headings’ collapse states.

<HeadingCollapseDemo />

`IParagraph.headingCollapsed` is saved in the Univer snapshot. Only `true` collapses a section. Content remains in the snapshot, and the state participates in undo/redo and collaboration; it is shared with other editors. A selection in hidden content moves to the visible heading. Office import/export preservation is not guaranteed.

For programmatic changes, use the document ID and a stable `paragraphId` from its snapshot with the registered command. Set `collapsed: false` to expand.

```ts
import { SetHeadingCollapsedCommand } from '@univerjs/docs'

const changed = await univerAPI.executeCommand(SetHeadingCollapsedCommand.id, {
  unitId: documentId,
  paragraphId: headingParagraphId,
  collapsed: true,
})
```

The command returns `false` for an unchanged state or invalid target, including a Traditional document, a heading hidden by an ancestor, an empty section when collapsing, or missing edit permission. See [the command contract](/reference/packages/plugins/univerjs/docs#heading-collapse).
