Univer Docs consists of a document editor, a formula engine, a rendering engine, a design system, and a UI component library. Together they form a document processing platform that supports multiple document formats and complex operations.

## Features

- **Document rendering.** Univer Docs renders the document content, the cursor, and the selection.
- **Document typesetting.** Full-text typesetting covers paragraph settings: spacing before and after a paragraph, alignment, indentation, and hanging indent. Within a paragraph, it also covers punctuation compression, hanging punctuation, character spacing, and Western word breaking.
- **Formula calculation.** Univer Docs supports adding and calculating Univer formulas. This capability is still in development.
- **Tables.** Univer Docs supports inserting basic tables and editing them, including adding or deleting rows and editing cells.
- **Document styles.** Univer Docs supports both _traditional document styles_ similar to Microsoft Word (pagination, headers, and footers) and _modern document styles_ similar to Notion. Modern documents do not paginate: content expands without limit, and official or third-party block-level elements, such as text, images, and tables, can be mixed in the same document (planned).
- **Headers and footers.** Univer Docs supports inserting a header or footer and editing its content. First pages and odd/even pages can differ (traditional documents only).
- **Lists.** Univer Docs supports inserting and editing ordered, unordered, and task lists, and indenting or outdenting them.
- **Emoji and symbols.** Emoji and symbols can be inserted from the Docs ribbon.
- **Plugin system.** Univer Docs supports custom plugins, such as formula, image, and chart plugins. The plugin system is also one of Univer's core architectural capabilities.

## Plugin mode

### Installation

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/design @univerjs/ui @univerjs/docs @univerjs/docs-ui
```

### Usage

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import DesignEnUS from '@univerjs/design/locale/en-US'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
import DocsUIEnUS from '@univerjs/docs-ui/lib/locale/en-US'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverUIPlugin } from '@univerjs/ui'
import UIEnUS from '@univerjs/ui/locale/en-US'
import '@univerjs/docs/facade'
import '@univerjs/docs-ui/facade'
import '@univerjs/design/lib/index.css'
import '@univerjs/ui/lib/index.css'
import '@univerjs/docs-ui/lib/index.css'

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(DesignEnUS, UIEnUS, DocsUIEnUS),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverUIPlugin, {
  container: 'app',
})
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverDocsUIPlugin)

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})
```

## Viewing controls [#ribbon-controls]

The View ribbon contains page settings, zoom, and fullscreen controls. The zoom selector and the zoom bar at the bottom show the same document view scale. Changing that scale does not change text formatting.

## Menu order and grid layout [#menu-order-and-grid-layout]

Define a shared [`MenuConfig`](/reference/packages/plugins/univerjs/ui#menuconfig) with Docs menu IDs, then apply it for the integration mode in use:

```ts
import type { MenuConfig } from '@univerjs/ui'

const menu: MenuConfig = {
  'ribbon.start.format': { order: -1 },
  'doc.command.set-inline-format-bold': {
    order: 0,
    gridLayout: { row: 2, column: 2 },
  },
  'doc.command.set-inline-format-italic': {
    gridLayout: { row: 2, column: 1 },
  },
}
```

Merge these options into the existing initialization for the integration mode in use. Retain the other plugin, locale, theme, and container settings, and do not register the same plugin twice.

## Document outline [#document-outline]

The outline on the left navigates between headings. It does not insert a table of contents into the document. When `toc` is omitted, Modern documents show the outline and Traditional documents hide it. An explicit `true` or `false` overrides either default. The panel collapses when space is insufficient or a table overlaps it, and reopens when space is available.

Merge this option into the existing initialization, and do not register the same plugin twice.

## Update menus with the Facade API [#menu-facade]

After initialization, call [`updateMenuConfig()`](/reference/facade/univer#updatemenuconfig) on the existing instance:

```ts
import '@univerjs/ui/facade'

univerAPI.updateMenuConfig(menu)
```

`order` sorts siblings from lowest to highest. `gridLayout` applies only to the grid Ribbon and uses 1-based coordinates within each two-row group. Runtime updates preserve properties that were not specified and refresh the UI immediately. In plugin mode, pass `menu` to `UniverUIPlugin`, and import `@univerjs/ui/facade` before calling the Facade. The [menu layout guide](/guides/sheets/features/core#menu-order-and-grid-layout) covers grid fields and custom buttons.

## Paste options [#paste-options]

Docs provides three paste modes: keep source formatting, match destination formatting, and keep text only. Match destination formatting adopts the target text and paragraph styles while keeping supported emphasis such as bold and italic. Text-only paste removes images and hyperlinks, and table content becomes tab-separated text. The post-paste options apply to the most recent paste. If the browser blocks clipboard reads, use the keyboard shortcut or the system paste command.

On desktop, the Ribbon **Paste** dropdown is located beside undo and redo, and it is hidden while editing shape text. The **Paste special** submenu is in the formatting group of the context menu on both desktop and mobile.

## Header and footer fields [#header-footer-fields]

In traditional documents, editing a header or footer opens a contextual Ribbon with insertion and navigation controls, first-page and odd/even-page options, and positioning settings. The Ribbon can insert current-page and total-page fields, or a localized date and time. Page fields show the value for each rendered page. For date and time, enable automatic updating to store a field, and disable it to insert fixed text. Date and time fields refresh when the document opens or when **Update fields** is selected, and they do not update continuously. Modern documents do not use page headers or footers.

## Collapse heading sections [#heading-collapse]

Modern documents (`documentStyle.documentFlavor: DocumentFlavor.MODERN`) show a triangle beside Heading 1–5 when the heading has section content. Collapsing keeps the heading visible and hides everything up to the next heading of the same or higher level, including nested headings, tables, and images. Each table cell and Modern column has its own heading hierarchy.

Collapse behavior is independent of `toc`. Traditional documents and embedded text editors do not show collapse controls. Expanding a parent heading preserves the collapse state of its nested headings.

<HeadingCollapseDemo />

`IParagraph.headingCollapsed` is stored in the Univer snapshot, and only `true` collapses a section. Content remains in the snapshot, and the state participates in undo/redo and collaboration, so other editors see it. A selection inside hidden content moves to the visible heading. Preservation through Office import and export is not guaranteed.

For programmatic changes, call the registered command with the document ID and a stable `paragraphId` from the snapshot. Setting `collapsed: false` expands the section.

```ts
import { SetHeadingCollapsedCommand } from '@univerjs/docs'

const changed = await univerAPI.executeCommand(SetHeadingCollapsedCommand.id, {
  unitId: documentId,
  paragraphId: headingParagraphId,
  collapsed: true,
})
```

The command returns `false` for an unchanged state or an invalid target, including a Traditional document, a heading hidden by an ancestor, an empty section when collapsing, or missing edit permission. See [the command contract](/reference/packages/plugins/univerjs/docs#heading-collapse).
