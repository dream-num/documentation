Univer Docs se compose d'un éditeur de documents, d'un moteur de formule, d'une machine de rendu, d' un système de conception et d'une bibliothèque de composants UI. Ensemble, ils forment une plateforme de traitement de documents qui prend en charge plusieurs formats de documents et des opérations complexes.

## Fonctionnalités

- **Le rendu des documents.** Univer Docs rend le contenu du document, le curseur et la sélection.
- **La composition des documents.** La composition en texte intégral couvre les paramètres des paragraphes : espacement avant et après un paragraphe, alignement, indentation et tiret suspendu.
- **Calcul de la formule.** Univer Docs prend en charge l'ajout et le calcul de formules Univer. Cette capacité est toujours en développement.
- **Tableaux.** Univer Docs prend en charge l'insertion de tables de base et leur édition, y compris l'ajout ou la suppression de lignes et de cellules d'édition.
- **Styles de documents.** Univer Docs prend en charge les styles de documents _traditionnels_ similaires à Microsoft Word (pagination, en-têtes et pied de page) et _modernes styles de documents_ similaires à Notion. Les documents modernes ne paginent pas : le contenu s'élargit sans limite, et les éléments de niveau de blocs officiels ou tiers, tels que le texte, les images et les tables, peuvent être mélangés dans le même document (prévu).
- **En-têtes et pied de pied.** Univer Docs prend en charge l'insertion d'un en-tête ou d'un pied de page et l'édition de son contenu.
- **Listes.** Univer Docs prend en charge l'insertion et l'édition des listes de tâches ordonnées, non ordonnées et indentées.
- **Emoji et les symboles.** Emoji et les symboles peuvent être insérés à partir du ruban Docs.
- **Système de greffon.** Univer Docs prend en charge les plugins personnalisés, tels que les plugins de formule, d'image et de graphique. Le système de plugin est également l'une des capacités architecturales de base de Univer.

## Mode plugin

### Installation

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/design @univerjs/ui @univerjs/docs @univerjs/docs-ui
```

### Utilisation

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import DesignEnUS from '@univerjs/design/locale/en-US'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
import DocsUIEnUS from '@univerjs/docs-ui/lib/locale/en-US'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverUIPlugin } from '@univerjs/ui'
import UIEnUS from '@univerjs/ui/locale/en-US'
import '@univerjs/docs/facade'
import '@univerjs/docs-ui/facade'
import '@univerjs/design/lib/index.css'
import '@univerjs/ui/lib/index.css'
import '@univerjs/docs-ui/lib/index.css'

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(DesignEnUS, UIEnUS, DocsUIEnUS),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverUIPlugin, {
  container: 'app',
})
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverDocsUIPlugin)

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})
```

### Configuration des plugins [#plugin-configuration]

#### @univerjs/core

La bibliothèque centrale fournit le constructeur Univer, ainsi que des thèmes et des langues.

```typescript
import type { IUniverConfig } from '@univerjs/core'
import { LocaleType, Univer } from '@univerjs/core'

const config: IUniverConfig = {
  locale: LocaleType.FR_FR,
  darkMode: false,
}
const univer = new Univer(config)
```

Référence : [`IUniverConfig`](/reference/packages/plugins/univerjs/core#iuniverconfig)

#### @univerjs/engine-render

Le moteur de rendu est responsable du rendu, des barres de défilement, du curseur et de la sélection. Il est enregistré comme `UniverRenderEnginePlugin`.

Référence : [@univerjs/engine-render](https://docs.univer.ai/reference/packages/plugins/univerjs/engine-render)

#### @univerjs/engine-formula

Référence : [@univerjs/engine-formula](https://docs.univer.ai/reference/packages/plugins/univerjs/engine-formula)

#### @univerjs/design

Le système de conception fournit les composants de base et les styles.

Voir : [chapitre consacré à l’interface utilisateur](/guides/docs/ui/overview)

## Contrôles d’affichage [#ribbon-controls]

Le ruban Affichage contient les paramètres de page, le zoom et les commandes en plein écran. Le sélecteur de zoom et la barre de zoom en bas montrent la même échelle de vision du document.

## Ordre des menus et disposition en grille [#menu-order-and-grid-layout]

Définissez un [`MenuConfig`](/reference/packages/plugins/univerjs/ui#menuconfig) partagé avec les ID de menu Docs, puis appliquez-le pour le mode d'intégration utilisé :

```ts
import type { MenuConfig } from '@univerjs/ui'

const menu: MenuConfig = {
  'ribbon.start.format': { order: -1 },
  'doc.command.set-inline-format-bold': {
    order: 0,
    gridLayout: { row: 2, column: 2 },
  },
  'doc.command.set-inline-format-italic': {
    gridLayout: { row: 2, column: 1 },
  },
}
```

Fusionner ces options dans l'initialisation existante pour le mode d'intégration en cours d'utilisation. Conserver l'autre plugin, locale, thème et paramètres de conteneur, et ne pas enregistrer le même plugin deux fois.

## Plan du document [#document-outline]

Le contour de gauche navigue entre les rubriques. Il n'insère pas de table des matières dans le document. Lorsque `toc` est omis, les documents modernes le montrent et les documents traditionnels le cachent. Un `true` explicite ou `false` remplace par défaut. Le panneau s'effondre lorsque l'espace est insuffisant ou qu'une table le chevauche, et rouvre lorsque l' espace est disponible.

Fusionner cette option dans l'initialisation existante, et ne pas enregistrer le même plugin deux fois.

## Mettre à jour les menus avec l’API Facade [#menu-facade]

Après initialisation, appelez [`updateMenuConfig()`](/reference/facade/univer#updatemenuconfig) sur l'instance existante :

```ts
import '@univerjs/ui/facade'

univerAPI.updateMenuConfig(menu)
```

`order` sorte de frères et sœurs du plus bas au plus haut. `gridLayout` s'applique uniquement à la grille Ribbon et utilise des coordonnées basées sur 1 au sein de chaque groupe de deux lignes. Les mises à jour d'exécution préservent les propriétés qui n'ont pas été spécifiées et rafraîchissent immédiatement l'interface utilisateur. `menu` à `UniverUIPlugin`, et importations `@univerjs/ui/facade` avant d'appeler la Façade. ## Options de collage [#paste-options]

Le formatage de destination correspond au texte cible et aux styles de paragraphes tout en conservant l'accent supporté comme bold et italique. La pâte de texte seulement supprime les images et les hyperliens, et le contenu de la table devient du texte séparé des onglets. Les options post-colle s'appliquent à la pâte la plus récente. Si le navigateur bloque la lecture du presse-papiers, utilisez le raccourci clavier ou la commande de collage système.

Sur le bureau, le menu déroulant Ribbon **Pâte** est situé à côté de la désactivation et du redécoupage, et il est caché lors de l'édition du texte de forme. Le sous-menu **Pâte spéciale** se trouve dans le groupe de formatage du menu contextuel sur le bureau et sur le mobile.

## Champs des en-têtes et pieds de page [#header-footer-fields]

Dans les documents traditionnels, l'édition d'un en-tête ou d'un pied de page ouvre un Ruban contextuel avec des commandes d'insertion et de navigation, des options de première page et de page impair/even-page et des paramètres de positionnement. Le Ruban peut insérer des champs de page courante et de page totale, ou une date et une heure localisées. Les champs de page montrent la valeur de chaque page rendue. **Champs de mise à jour** Les documents modernes n'utilisent pas d'en-têtes de page ou de pied de page.

## Replier les sections [#heading-collapse]

Les documents Modern (`documentStyle.documentFlavor: DocumentFlavor.MODERN`) affichent un triangle à côté des titres de niveau 1 à 5 dont la section contient du contenu. Le repli conserve le titre et masque le contenu jusqu’au prochain titre de niveau égal ou supérieur, y compris les sous-titres, tableaux et images. Chaque cellule de tableau et chaque colonne Modern possède sa propre hiérarchie.

Le comportement d'effondrement est indépendant de `toc`. Les documents traditionnels et les éditeurs de texte intégrés ne montrent pas les contrôles d'effondrement.

<HeadingCollapseDemo />

`IParagraph.headingCollapsed` est stocké dans l'instantané Univer, et seul `true` s'effondre une section. Le contenu reste dans l'aperçu, et l'état participe à undo/redo et à la collaboration, de sorte que d'autres éditeurs le voient. Une sélection à l'intérieur du contenu caché se déplace vers la rubrique visible. La préservation par l'importation et l'exportation Office n'est pas garantie.

Pour les modifications programmatiques, appelez la commande enregistrée avec l'ID du document et un `paragraphId` stable depuis l'instantané. La configuration `collapsed: false` élargit la section.

```ts
import { SetHeadingCollapsedCommand } from '@univerjs/docs'

const changed = await univerAPI.executeCommand(SetHeadingCollapsedCommand.id, {
  unitId: documentId,
  paragraphId: headingParagraphId,
  collapsed: true,
})
```

La commande renvoie `false` pour un état inchangé ou une cible invalide, y compris un document traditionnel, un titre caché par un ancêtre, une section vide lors de l'effondrement, ou une autorisation d'édition manquante. Voir [le contrat de commande](/reference/packages/plugins/univerjs/docs#heading-collapse).
