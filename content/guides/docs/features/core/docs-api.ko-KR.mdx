Univer Docs API로 앱에서 문서를 만들고 편집하고 저장할 수 있습니다. 특정 문단을 찾아 보고서를 갱신하고 글자 스타일을 바꾸거나 자동 수정 위치를 사용자에게 보여 줄 수 있습니다. 다음 예제는 출시 계획 문서를 만드는 과정부터 저장까지 설명합니다.

[문서 만들기](#create-document) · [문단 편집](#edit-paragraph) · [글자 스타일 변경](#text-style) · [결과 저장](#get-document-data)

예제는 **Univer 1.3.0**을 사용합니다. [Docs 설치](/guides/docs/getting-started/installation)를 완료하고 Univer 패키지 버전을 일치시키세요.

## ID, 세그먼트와 텍스트 오프셋 [#document-identifiers]

영구 ID로 내용을 식별하고 오프셋으로 텍스트 위치를 지정합니다. 앞에 텍스트를 삽입해 인덱스가 바뀌어도 기존 문단과 구역 ID는 유지됩니다.

| 식별자 | 의미 | 접근 방법 |
| --- | --- | --- |
| `unitId` | 전체 문서. Docs에는 `subUnitId`가 없습니다. | `doc.getId()` |
| `paragraphId` | 영구 문단 ID. | `paragraph.getId()`, `doc.getParagraph(id, segmentId?)` |
| `sectionId` | 전통 문서의 영구 구역 ID. | `section.getId()`. `doc.getSection(index)`는 ID가 아닌 **0** 기반 인덱스를 받습니다. |
| `segmentId` | 본문(`''`), 머리글 또는 바닥글 스트림. | `paragraph.getSegmentId()` |
| `startOffset`, `endOffset` | 세그먼트 안의 UTF-16 위치. 시작 포함, 끝 제외. | `paragraph.getRange()`, `range.getRange()` |

문단과 구역 핸들은 호출 시 영구 ID를 다시 찾습니다. `FDocumentTextRange`는 **고정 오프셋**이므로 앞에서 삽입·삭제하면 다시 가져와야 합니다. 삭제된 요소의 핸들은 무효입니다. [문단](/reference/facade/document-paragraph), [구역](/reference/facade/document-section), [범위](/reference/facade/document-text-range)를 참고하세요.

## Facade 가져오기

플러그인 모드에서는 내용 조작에 Docs Facade, 화면 선택에 Docs UI Facade도 필요합니다. 프리셋에는 해당 항목이 포함됩니다.

```typescript
import '@univerjs/docs/facade'
import '@univerjs/docs-ui/facade'
```

## 문서 만들기 [#create-document]

문단 두 개와 전통 구역 하나를 만듭니다. 이후 예제는 반환된 `doc`를 사용합니다. 같은 문단을 다시 찾도록 스냅샷에 ID를 지정합니다.

```typescript
const doc = univerAPI.createDocument({
  id: 'launch-plan',
  title: 'Launch plan',
  body: {
    dataStream: 'Launch plan\rStatus: Draft\r\n',
    paragraphs: [
      { startIndex: 11, paragraphId: 'p-title' },
      { startIndex: 25, paragraphId: 'p-status' },
    ],
    sectionBreaks: [{ startIndex: 26, sectionId: 's-main' }],
  },
  documentStyle: {
    documentFlavor: univerAPI.Enum.DocumentFlavor.TRADITIONAL,
    pageSize: { width: 595, height: 842 },
    marginTop: 40,
    marginBottom: 40,
    marginLeft: 40,
    marginRight: 40,
  },
})
```

편집기에 “Launch plan”과 “Status: Draft” 두 문단이 표시됩니다. 이후에도 `p-title`, `p-status`로 같은 문단을 찾을 수 있습니다.

`\r`는 문단, `\n`은 구역을 끝냅니다. `startIndex`는 해당 제어 문자를 가리킵니다. [본문 구조](/guides/docs/model/document-body)를 참고하세요. 실행 중에는 API가 인덱스를 관리하므로 실시간 스냅샷을 직접 수정하지 마세요.

## 문단 찾기와 편집 [#edit-paragraph]

실제 문단 ID를 사용하세요. `setText()`는 문단 텍스트를 바꾸고 `appendText()`는 문단 끝 문자 앞에 추가합니다. 앞에 내용을 삽입한 뒤에도 같은 상태 문단을 편집합니다.

```typescript
const paragraph = doc.getParagraph('p-status')
if (!paragraph) throw new Error('Status paragraph not found')

const paragraphId = paragraph.getId()
doc.insertText(0, '[Review] ')
paragraph.setText('Status: Ready')
paragraph.appendText(' for review')

console.log(doc.getParagraph(paragraphId)?.getText())
// Status: Ready for review
```

첫 문단은 “[Review] Launch plan”, 두 번째 문단은 “Status: Ready for review”가 됩니다. 상태 문단의 위치가 바뀌어도 ID는 유지됩니다.

## 선택을 바꾸지 않고 텍스트 스타일 설정 [#text-style]

텍스트를 찾아 직접 스타일을 적용합니다. 화면에 선택 영역이 없어도 되므로 Agent와 헤드리스 처리에도 적합합니다.

```typescript
const status = doc.getParagraph('p-status')
const ready = status?.findText('Ready')
if (!ready) throw new Error('Target text not found')

ready.setTextStyle({ cl: { rgb: '#2563eb' }, bl: 1 })
console.log(ready.getText())
```

“Ready”가 파란색 굵은 글씨로 표시되며 같은 문단의 나머지 글자는 바뀌지 않습니다.

`setTextStyle()`는 기존 문자를 수정하며 이후 입력할 텍스트의 전역 색상을 설정하지 않습니다. 문단 배치와 기본 텍스트 스타일에는 [paragraph.setStyle()](/reference/facade/document-paragraph#setstyle)을 사용하세요.

## 편집기에서 선택 표시 [#text-selection]

이 본문 예제에서는 먼저 본문 편집 상태로 들어간 뒤 현재 오프셋을 `setSelection()`에 전달하세요. Docs UI가 필요하고 반환값은 `void`이며 내용은 바뀌지 않습니다. **현재 편집 중인 세그먼트**를 사용하고 `segmentId` 인수는 없습니다. 머리글이나 바닥글에서 본문으로 자동 전환하지 않습니다.

```typescript
const target = doc.getParagraph('p-status')?.findText('Ready')
if (!target) throw new Error('Target text not found')

const { startOffset, endOffset } = target.getRange()
doc.setSelection(startOffset, endOffset)
```

## 전통 문서 구역 찾기 [#document-sections]

Section API는 **Traditional** 문서용입니다. Modern 문서는 ColumnGroup API를 사용합니다. `getSection(0)`은 첫 구역이며 ID는 현재 구역 목록에서 찾습니다. 문자열 ID를 `getSection()`에 전달하지 마세요.

```typescript
if (doc.isTraditional()) {
  const firstSection = doc.getSection(0)
  console.log(firstSection?.getId())

  const section = doc.getSections().find(item => item.getId() === 's-main')
  console.log(section?.getRange())
}
```

## 저장과 해제 [#get-document-data]

`save()`는 문단·구역 ID를 포함한 스냅샷을 반환하며 저장은 앱이 담당합니다. 단일 문서는 `disposeUnit()`, 호스트 해제 시 편집기는 `univer.dispose()`로 해제합니다.

```typescript
const snapshot = doc.save()
console.log(snapshot.body?.paragraphs, snapshot.body?.sectionBreaks)

// When this document is no longer needed:
// univerAPI.disposeUnit(doc.getId())
```

## 기타 텍스트 작업

위치를 알면 `doc.insertText(offset, text, segmentId?)`, `doc.deleteRange({ startOffset, endOffset, segmentId })`를 사용하세요. `insertText(0, text)`는 **맨 앞**에 삽입합니다. 페이지 나누기는 `doc.insertText(offset, '\f')`, [통계](/reference/facade/document#getdocumentdatamodel)는 `doc.getDocumentDataModel().getStatistics()`를 사용합니다.
