編輯段落、樣式或表格之後，可以透過歷史記錄檢視先前的版本、比較改動，並在有權限時恢復某個版本。版本由伺服器端儲存。撤銷和重做與歷史記錄無關：它們只作用於當前編輯會話，不需要歷史服務。

## 準備協同與歷史服務

先完成[協同整合](/server/collaboration/browser-integration)和[許可證配置](/server/license)。然後確認兩個會話可以編輯同一份 Docs 文件，並且重新整理後改動仍然存在。

歷史儲存和權限按 [Office 協同擴充套件模組](/server/collaboration/extensions)和 [History 範例](/server/collaboration/examples#history)接入。核心協同不會自行啟用歷史記錄，後端還必須提供歷史列表、版本內容和恢復操作。

把這部分配置加入現有的產品、許可證和協同配置。如果預設或現有配置已經註冊了這些外掛，請修改該配置，不要重複註冊。

## 外掛模式 [#plugin-mode]

### 安裝

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/docs-history @univerjs-pro/docs-history-ui
```

### 使用

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverDocsHistoryPlugin } from '@univerjs-pro/docs-history'
import { UniverDocsHistoryUIPlugin } from '@univerjs-pro/docs-history-ui'
import HistoryLocale from '@univerjs-pro/docs-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverDocsHistoryPlugin)
univer.registerPlugin(UniverDocsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 外掛設定

`UniverEditHistoryPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的基礎地址。 |

`UniverDocsHistoryUIPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的基礎地址。 |
| `univerContainerId` | `string` |  | 編輯器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 歷史版本檢視器使用的額外外掛。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 外掛的建構函式。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 該外掛建構函式接受的配置項。 |

把 `/api/history` 替換為應用自己的歷史介面地址，並確認該介面能回應客戶端發出的請求。兩個 `historyServerUrl` 必須一致。`univerContainerId` 設為編輯器容器的 DOM ID，語言資源要與編輯器語言一致。

歷史檢視器會開啟一個獨立的只讀編輯器。文件包含自定義內容時，用 `viewerPlugins` 新增檢視器未內建的外掛。不要重複註冊內建的檢視器外掛。

## 預設模式 [#preset-mode]

### 安裝

```package-install
npm install @univerjs/preset-docs-collaboration
```

### 使用

`UniverDocsCollaborationPreset` 已經包含歷史介面及其依賴的外掛。保留現有的編輯器和許可證配置。如果該預設已經註冊，請更新原有註冊，不要重複註冊預設或歷史外掛。

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'
import CollaborationLocale from '@univerjs/preset-docs-collaboration/locales/en-US'
import '@univerjs/preset-docs-collaboration/lib/index.css'

const collaborationPreset = UniverDocsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### 預設設定

`UniverDocsCollaborationPreset`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | 協作服務的基礎位址。 |
| `univerContainerId` | `string` | `'app'` | 編輯器容器的 DOM ID。 |

把 `collaborationPreset` 加入現有 `createUniver()` 呼叫的 `presets` 陣列，並把 `CollaborationLocale` 合併到對應語言的資源中。`universerEndpoint` 設為伺服器端的基礎 URL，`univerContainerId` 設為編輯器容器 ID。預設生成的歷史地址為 `{universerEndpoint}/universer-api/history`。如需自定義 `historyServerUrl` 或 `viewerPlugins`，請改用外掛模式。無論使用哪種模式，都需要上文所述的後端服務。

## 檢視與還原版本

從編輯器選單開啟歷史記錄，選擇一個版本，即可檢視其內容和改動。恢復版本會修改當前的共享文件，因此只應向具有恢復權限的使用者開放，並由伺服器端強制執行該權限。

驗證整合時，請修改段落、樣式或表格，等待協同確認改動，然後檢視歷史列表和版本內容。重新開啟應用並重啟服務，確認資料仍然存在。最後恢復一個較早的版本，確認另一個瀏覽器中的會話收到恢復後的狀態。

如果列表為空，先確認這份文件是否記錄了歷史，再檢查文件 ID 和服務地址。如果版本可以檢視但恢復失敗，請檢查恢復權限和協同連線。讀取歷史同樣需要授權，因為舊版本可能仍包含後來被刪除的資料。

## 比較快照 [#compare-snapshots]

要建置審閱介面，或向 AI Agent 提供改動說明，可以呼叫 `compareUnitData()`，也可以用 `prepareUnitComparison()` 只准備一次比較，然後反覆查詢。先註冊本品類的 History 外掛並匯入 Facade 入口。把同一 Unit 的兩份完整快照分別作為 `beforeSnapshot` 和 `afterSnapshot` 傳入。該比較是隻讀的，不需要歷史服務，也不會恢復或合併內容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_DOC,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

先讀取 `scopes` 檢視可用的檢視，然後把其中一個傳給 `query()`，即可縮小結果範圍，而不必重新執行比較。每頁預設套件含 100 項，最多接受 1,000 項。用 `page.hasMore` 配合 `offset` 取得剩餘條目。`summary` 描述整個比較，即使條目經過篩選也不變。在把結果視為完整比較之前，請檢查 `diagnostics.readiness` 和 `diagnostics.codes`。不使用編輯器、在 Node.js 或 CLI 中使用時，請參閱[無介面比較 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
