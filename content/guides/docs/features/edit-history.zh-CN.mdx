编辑段落、样式或表格之后，可以通过历史记录查看先前的版本、比较改动，并在有权限时恢复某个版本。版本由服务端保存。撤销和重做与历史记录无关：它们只作用于当前编辑会话，不需要历史服务。

## 先准备协同和历史服务

先完成[协同集成](/server/collaboration/browser-integration)和[许可证配置](/server/license)。然后确认两个会话可以编辑同一份 Docs 文档，并且刷新后改动仍然存在。

历史存储和权限按 [Office 协同扩展模块](/server/collaboration/extensions)和 [History 示例](/server/collaboration/examples#history)接入。核心协同不会自行启用历史记录，后端还必须提供历史列表、版本内容和恢复操作。

把这部分配置加入现有的产品、许可证和协同配置。如果预设或现有配置已经注册了这些插件，请修改该配置，不要重复注册。

## 插件模式 [#plugin-mode]

### 安装

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/docs-history @univerjs-pro/docs-history-ui
```

### 使用

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/zh-CN'
import { UniverDocsHistoryPlugin } from '@univerjs-pro/docs-history'
import { UniverDocsHistoryUIPlugin } from '@univerjs-pro/docs-history-ui'
import HistoryLocale from '@univerjs-pro/docs-history-ui/locale/zh-CN'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.ZH_CN, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverDocsHistoryPlugin)
univer.registerPlugin(UniverDocsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 插件配置

`UniverEditHistoryPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的基础地址。 |

`UniverDocsHistoryUIPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的基础地址。 |
| `univerContainerId` | `string` |  | 编辑器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 历史版本查看器使用的额外插件。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 插件的构造函数。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 该插件构造函数接受的配置项。 |

把 `/api/history` 替换为应用自己的历史接口地址，并确认该接口能回应客户端发出的请求。两个 `historyServerUrl` 必须一致。`univerContainerId` 设为编辑器容器的 DOM ID，语言资源要与编辑器语言一致。

历史查看器会打开一个独立的只读编辑器。文档包含自定义内容时，用 `viewerPlugins` 添加查看器未内置的插件。不要重复注册内置的查看器插件。

## 预设模式 [#preset-mode]

### 安装

```package-install
npm install @univerjs/preset-docs-collaboration
```

### 使用

`UniverDocsCollaborationPreset` 已经包含历史界面及其依赖的插件。保留现有的编辑器和许可证配置。如果该预设已经注册，请更新原有注册，不要重复注册预设或历史插件。

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'
import CollaborationLocale from '@univerjs/preset-docs-collaboration/locales/zh-CN'
import '@univerjs/preset-docs-collaboration/lib/index.css'

const collaborationPreset = UniverDocsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### 预设配置

`UniverDocsCollaborationPreset`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | 协同服务的基础地址。 |
| `univerContainerId` | `string` | `'app'` | 编辑器容器的 DOM ID。 |

把 `collaborationPreset` 加入现有 `createUniver()` 调用的 `presets` 数组，并把 `CollaborationLocale` 合并到对应语言的资源中。`universerEndpoint` 设为服务端的基础 URL，`univerContainerId` 设为编辑器容器 ID。预设生成的历史地址为 `{universerEndpoint}/universer-api/history`。如需自定义 `historyServerUrl` 或 `viewerPlugins`，请改用插件模式。无论使用哪种模式，都需要上文所述的后端服务。

## 查看和恢复版本

从编辑器菜单打开历史记录，选择一个版本，即可查看其内容和改动。恢复版本会修改当前的共享文档，因此只应向具有恢复权限的用户开放，并由服务端强制执行该权限。

验证集成时，请修改段落、样式或表格，等待协同确认改动，然后查看历史列表和版本内容。重新打开应用并重启服务，确认数据仍然存在。最后恢复一个较早的版本，确认另一个浏览器中的会话收到恢复后的状态。

如果列表为空，先确认这份文档是否记录了历史，再检查文档 ID 和服务地址。如果版本可以查看但恢复失败，请检查恢复权限和协同连接。读取历史同样需要授权，因为旧版本可能仍包含后来被删除的数据。

## 比较快照 [#compare-snapshots]

要构建审阅界面，或向 AI Agent 提供改动说明，可以调用 `compareUnitData()`，也可以用 `prepareUnitComparison()` 只准备一次比较，然后反复查询。先注册本品类的 History 插件并导入 Facade 入口。把同一 Unit 的两份完整快照分别作为 `beforeSnapshot` 和 `afterSnapshot` 传入。该比较是只读的，不需要历史服务，也不会恢复或合并内容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_DOC,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

先读取 `scopes` 查看可用的视图，然后把其中一个传给 `query()`，即可缩小结果范围，而不必重新执行比较。每页默认包含 100 项，最多接受 1,000 项。用 `page.hasMore` 配合 `offset` 获取剩余条目。`summary` 描述整个比较，即使条目经过筛选也不变。在把结果视为完整比较之前，请检查 `diagnostics.readiness` 和 `diagnostics.codes`。不使用编辑器、在 Node.js 或 CLI 中使用时，请参阅[无界面比较 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
