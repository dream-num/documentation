段落、書式、表を編集すると、以前のバージョンを調べたり、変更を比較したり、権限を持っているときにバージョンを復元したりできます。バージョンはサーバーによって保存されます。Undo と redo は歴史とは独立しています。それらは現在の編集セッションに適用され、履歴サービスを必要としません。

## 共同編集と履歴サービスの準備

[コラボレーション統合](/server/collaboration/browser-integration)と[ライセンス構成](/server/license)を最初に完了します。 その後、2つのセッションが同じドキュメントを編集でき、その変更が再ロードされる可能性があることを確認します。

[オフィスのコラボレーション拡張](/server/collaboration/extensions)と[歴史例](/server/collaboration/examples#history)で説明されているように歴史の保存と権限を接続します。コアコラボレーションは、それ自体で歴史を有効にしません。バックエンドは、歴史リスト、バージョンコンテンツ、および復元にも役立つ必要があります。

この設定を既存の製品、ライセンス、およびコラボレーション設定に追加します。プリセットまたは既存の設定がすでにこれらのプラグインを登録している場合は、その設定を2回目の登録ではなく変更します。

## プラグインモード [#plugin-mode]

### インストール

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/docs-history @univerjs-pro/docs-history-ui
```

### 使い方

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverDocsHistoryPlugin } from '@univerjs-pro/docs-history'
import { UniverDocsHistoryUIPlugin } from '@univerjs-pro/docs-history-ui'
import HistoryLocale from '@univerjs-pro/docs-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverDocsHistoryPlugin)
univer.registerPlugin(UniverDocsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### プラグイン設定

`UniverEditHistoryPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |

`UniverDocsHistoryUIPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |
| `univerContainerId` | `string` |  | エディターコンテナの DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 履歴ビューアーに追加するプラグイン。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | プラグインコンストラクタ。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | そのコンストラクタで受け入れられるオプション。 |

`/api/history`をアプリケーション独自の履歴エンドポイントに設定し、エンドポイントがクライアントが送信するリクエストに応答するようにします。 `historyServerUrl`の値は同じでなければなりません。 `univerContainerId` をエディタコンテナの DOM ID に設定し、エディタ言語に一致するロケールをロードします。

履歴ビューアは別々の読み取り専用エディタを開きます。 ドキュメントにカスタムコンテンツが含まれている場合は、ビューアが含まないプラグインを追加するには、`viewerPlugins`を使用します。 組み込みビューアプラグインを再度登録しないでください。

## プリセットモード [#preset-mode]

### インストール

```package-install
npm install @univerjs/preset-docs-collaboration
```

### 使い方

`UniverDocsCollaborationPreset`は、すでに履歴UIとそれに依存するプラグインが含まれています。 既存のエディタとライセンス設定をキープしてください。 プリセットが既に登録されている場合は、プリセットを登録する代わりに、その登録を更新するか、または歴史プラグインを2回更新します。

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'
import CollaborationLocale from '@univerjs/preset-docs-collaboration/locales/en-US'
import '@univerjs/preset-docs-collaboration/lib/index.css'

const collaborationPreset = UniverDocsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### プリセット設定

`UniverDocsCollaborationPreset`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | 共同編集サーバーのベース URL。 |
| `univerContainerId` | `string` | `'app'` | エディターコンテナの DOM ID。 |

追加する `collaborationPreset` にほんご `presets` 既存の配列 `createUniver()` 呼び出しと合併 `CollaborationLocale` マッチング言語のロケールエントリーへ。セット `universerEndpoint` サーバベース URL に、 `univerContainerId` エディタコンテナ ID へ。プリセットは、履歴 URL を以下のように構築します。 `{universerEndpoint}/universer-api/history`. カスタムが必要な場合は、プラグインモードを使用する `historyServerUrl` または `viewerPlugins` 設定。 どちらのモードでも、上記のバックエンドサービスが必要です。

## バージョンの表示と復元

エディタメニューから履歴を開き、そのコンテンツと含まれている変更を調べるためにバージョンを選択します。バージョンを復元すると、現在の共有文書が変更されるため、復元権限を持つユーザーに限定される必要があります。サーバーは、その許可を強制しなければなりません。

統合の確認、段落の編集、整形、テーブルの編集、変更の確認、履歴リストとバージョンのコンテンツの検査を待ちます。アプリケーションを再オープンし、データを永続的に確認するためにサービスを再起動します。以前のバージョンを復元し、別のブラウザのセッションが復元された状態を受け取ることを確認します。

リストが空の場合、まずこのドキュメントの履歴が記録されたかどうかを確認し、ドキュメント ID とサービス URL を確認します。バージョンが閲覧できるが、修復が失敗した場合は、復元権限とコラボレーション接続を確認してください。古いバージョンが削除されたデータを含む可能性があるため、履歴の読み込みも許可が必要です。

## スナップショットの比較 [#compare-snapshots]

レビュー画面を作成するか、または変更されたものの説明をAIエージェントに提供するために、`compareUnitData()`を呼び出し、または`prepareUnitComparison()`に一度比較を準備し、繰り返しクエリします。 製品の履歴プラグインを登録し、ファサードエントリーをインポートします。 同じユニットの2つの完全に材料化されたスナップショットを`beforeSnapshot`と`afterSnapshot`に渡します。 比較は読み取り専用です:それは履歴サービスを必要としず、それはコンテンツを復元するか、マージしません。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_DOC,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

どのビューが利用可能なかを確認するために`scopes`を読み、その後、`query()`に1つを渡すと、比較を再実行せずに結果が狭くなります。 ページには、デフォルトで100項目を保持し、最大1,000を受け入れます。 残りの項目をフェッチするために`page.hasMore`と`offset`を使用してください。 `summary`は、アイテムがフィルタリングされた場合でも、全体の比較について説明します。 結果の完全な比較として扱う前に`diagnostics.readiness`と`diagnostics.codes`をチェックしてください。 エディタなしでNode.jsまたはCLIの使用については、[ヘッドレス比較API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)を参照してください。
