Después de editar párrafos, formato o tablas, la historia le permite inspeccionar versiones anteriores, comparar cambios y restaurar una versión cuando tiene permiso. Las versiones son almacenadas por el servidor. Deshacer y rehacer son independientes de la historia: se aplican a la sesión de edición actual y no requieren un servicio de historia.

## Preparar los servicios de colaboración e historial

Completa [integración de la colaboración](/server/collaboration/browser-integration) y [configuración de licencias](/server/license) primero. A continuación, verifique que dos sesiones pueden editar el mismo documento Docs y que los cambios sobreviven a una recarga.

Conecte el almacenamiento de historia y los permisos descritos en [Ampliación de la colaboración de las oficinas](/server/collaboration/extensions) y [Ejemplo de historia](/server/collaboration/examples#history). La colaboración básica no permite la historia por sí misma; el backend también debe servir listas de historia, contenido de versión y restauración.

Agregue esta configuración al producto existente, licencia y configuración de colaboración. Si un preset o una configuración existente ya registra estos plugins, modifique esa configuración en lugar de registrarlos por segunda vez.

## Modo de complemento [#plugin-mode]

### Instalación

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/docs-history @univerjs-pro/docs-history-ui
```

### Uso

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverDocsHistoryPlugin } from '@univerjs-pro/docs-history'
import { UniverDocsHistoryUIPlugin } from '@univerjs-pro/docs-history-ui'
import HistoryLocale from '@univerjs-pro/docs-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverDocsHistoryPlugin)
univer.registerPlugin(UniverDocsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuración de plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |

`UniverDocsHistoryUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |
| `univerContainerId` | `string` |  | ID DOM del contenedor del editor. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Plugins adicionales del visor de historial. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | El constructor de plugins. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Opciones aceptadas por ese constructor. |

Establecer `/api/history` en el propio endpoint de la historia de la aplicación, y asegúrese de que endpoint responda a las solicitudes que envía el cliente. Ambos valores `historyServerUrl` deben ser idénticos. Establecer `univerContainerId` al DOM ID del contenedor de editor, y cargar el local que coincida con el lenguaje de editor.

El visor de historia abre un editor independiente de sólo lectura. Si los documentos contienen contenido personalizado, utilice `viewerPlugins` para agregar los plugins que el visor no incluye. No registre los plugins de visualización incorporado de nuevo.

## Modo preestablecido [#preset-mode]

### Instalación

```package-install
npm install @univerjs/preset-docs-collaboration
```

### Uso

`UniverDocsCollaborationPreset` ya incluye la historia UI y los plugins que depende. Mantenga el editor existente y la configuración de licencia. Si el preset ya está registrado, actualice ese registro en lugar de registrar el preset o los plugins de historia por segunda vez.

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'
import CollaborationLocale from '@univerjs/preset-docs-collaboration/locales/en-US'
import '@univerjs/preset-docs-collaboration/lib/index.css'

const collaborationPreset = UniverDocsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### Configuración de preajustes

`UniverDocsCollaborationPreset`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | URL base del servidor de colaboración. |
| `univerContainerId` | `string` | `'app'` | ID DOM del contenedor del editor. |

Añadir `collaborationPreset` a la matriz `presets` de la llamada `createUniver()` existente, y combinar `CollaborationLocale` en la entrada local para el idioma de coincidencia. Establecer `universerEndpoint` en la URL base del servidor y `univerContainerId` en el ID del contenedor del editor. El preset construye la URL de la historia como `{universerEndpoint}/universer-api/history`. Utilice el modo Plugin si necesita una configuración personalizada `historyServerUrl` o `viewerPlugins`. Cualquier modo todavía requiere los servicios de backend descritos anteriormente.

## Consultar y restaurar versiones

Abrir la historia del menú del editor y seleccionar una versión para inspeccionar su contenido y los cambios que contiene. Restaurar una versión modifica el documento compartido actual, por lo que debe limitarse a los usuarios con permiso de restauración, y el servidor debe hacer cumplir ese permiso.

Para verificar la integración, editar párrafos, formatear o tablas, esperar la colaboración para confirmar los cambios, luego inspeccionar la lista de historia y el contenido de la versión. Reabrir la aplicación y reiniciar el servicio para confirmar que los datos persisten. Restaurar una versión anterior y confirmar que una sesión en otro navegador recibe el estado restaurado.

Si la lista está vacía, primero compruebe si la historia fue registrada para este documento, luego comprueba el documento ID y la URL del servicio. Si las versiones pueden ser vistas pero la restauración falla, compruebo los permisos de restauración y la conexión de colaboración. La historia de la lectura también requiere autorización, porque las versiones anteriores pueden contener datos que se han borrado.

## Comparar snapshots [#compare-snapshots]

Para construir una pantalla de revisión, o para proporcionar un agente de inteligencia artificial con una descripción de lo que cambió, llame a `compareUnitData()`, o prepare una comparación una vez con `prepareUnitComparison()` y la consulta repetidamente. Registrar el plugin de historia para el producto e importar la entrada de Facade. Pase dos instantáneas totalmente materializadas de la misma unidad que `beforeSnapshot` o `afterSnapshot`.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_DOC,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Leer `scopes` para ver qué puntos de vista están disponibles, luego pasar uno de ellos a `query()` para reducir el resultado sin rehacer la comparación. Una página contiene 100 artículos por defecto y acepta hasta 1.000. Uso `page.hasMore` con `offset` para buscar los elementos restantes. `summary` describe toda la comparación incluso cuando los elementos son filtrados. `diagnostics.readiness` y `diagnostics.codes` antes de tratar el resultado como una comparación completa. Para Node.js o uso de CLI sin un editor, ver el [API de comparación sin cabeza](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
