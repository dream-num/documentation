После редактирования абзацев, форматирования или таблиц история позволяет проверять более ранние версии, сравнивать изменения и восстанавливать версию при наличии разрешения. Версии хранятся на сервере. Отмена и переделка независимы от истории: они применяются к текущей сессии редактирования и не требуют службы истории.

## Подготовка сервисов совместного редактирования и истории

Сначала заполните [Интеграция сотрудничества](/server/collaboration/browser-integration) и [Конфигурация лицензии](/server/license). Затем проверьте, что два сеанса могут редактировать один и тот же документ Docs и что изменения выдерживают перезагрузку.

Подключите хранилище истории и разрешения, как описано в [Расширение сотрудничества с офисом](/server/collaboration/extensions) и [Пример истории](/server/collaboration/examples#history). Основное сотрудничество не позволяет историю само по себе; бэкэнд также должен обслуживать списки истории, содержание версии и восстановление.

Добавьте эту конфигурацию к существующему продукту, лицензии и настройке совместной работы.Если предустановленная или существующая конфигурация уже регистрирует эти плагины, измените эту конфигурация вместо того, чтобы регистрировать их во второй раз.

## Режим плагина [#plugin-mode]

### Установка

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/docs-history @univerjs-pro/docs-history-ui
```

### Использование

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverDocsHistoryPlugin } from '@univerjs-pro/docs-history'
import { UniverDocsHistoryUIPlugin } from '@univerjs-pro/docs-history-ui'
import HistoryLocale from '@univerjs-pro/docs-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverDocsHistoryPlugin)
univer.registerPlugin(UniverDocsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Настройка плагинов

`UniverEditHistoryPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |

`UniverDocsHistoryUIPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |
| `univerContainerId` | `string` |  | DOM ID контейнера редактора. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Дополнительные плагины для просмотра истории. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Конструктор плагинов. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Варианты, принятые этим конструктором. |

Установите `/api/history` на конечную точку истории приложения и убедитесь, что конечная точка отвечает на запросы, которые отправляет клиент. Оба значения `historyServerUrl` должны быть идентичны. Установите значение `univerContainerId` в DOM-идентификатор контейнера редактора и загрузите локализацию, соответствующую языку редактора.

Зритель истории открывает отдельный редактор только для чтения. Если документы содержат пользовательский контент, используйте `viewerPlugins` для добавления плагинов, которые зритель не включает. Не регистрируйте встроенные плагины просмотра снова.

## Режим предустановки [#preset-mode]

### Установка

```package-install
npm install @univerjs/preset-docs-collaboration
```

### Использование

`UniverDocsCollaborationPreset` уже включает в себя пользовательский интерфейс истории и плагины, от которых он зависит. Сохраняйте существующий редактор и настройку лицензии. Если предустановка уже зарегистрирована, обновите эту регистрацию вместо регистрации предустанавливаемых или плагинов истории во второй раз.

```ts
import { UniverDocsCollaborationPreset } from '@univerjs/preset-docs-collaboration'
import CollaborationLocale from '@univerjs/preset-docs-collaboration/locales/en-US'
import '@univerjs/preset-docs-collaboration/lib/index.css'

const collaborationPreset = UniverDocsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### Настройка пресетов

`UniverDocsCollaborationPreset`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | Базовый URL сервера совместной работы. |
| `univerContainerId` | `string` | `'app'` | DOM ID контейнера редактора. |

Добавьте `collaborationPreset` в массив `presets` существующего вызова `createUniver()` и объедините `CollaborationLocale` во входную строку локализации для соответствующего языка. Установите `universerEndpoint` на URL серверной базы и `univerContainerId` для идентификатора контейнера редактора. Предустановленный URL-адрес истории строится как `{universerEndpoint}/universer-api/history`. Используйте режим плагина, если вам нужна настраиваемая конфигурация `historyServerUrl` или `viewerPlugins` . Любой режим по-прежнему требует бэкэнд-сервисов, описанных выше.

## Просмотр и восстановление версий

Откройте историю из меню редактора и выберите версию, чтобы проверить ее содержимое и изменения, которые она содержит. Восстановление версии изменяет текущий общий документ, поэтому он должен быть ограничен пользователями с разрешением на восстановление, и сервер должен обеспечить это разрешение.

Чтобы проверить интеграцию, отредактировать абзацы, форматирование или таблицы, дождаться совместной работы, чтобы подтвердить изменения, затем проверить список истории и содержание версии. Откройте приложение и перезапустите сервис, чтобы подтвердить, что данные сохраняются. Восстановите более раннюю версию и подтвердите, что сеанс в другом браузере получает восстановленное состояние.

Если список пуст, сначала проверьте, была ли записана история для этого документа, затем проверьте идентификатор документа и URL-адрес службы. Если версии можно просматривать, но восстановление не удается, проверьте разрешения на восстановление и соединение для совместной работы. Чтение истории также требует авторизации, потому что более старые версии все еще могут содержать данные, которые с тех пор были удалены.

## Сравнение снимков [#compare-snapshots]

Чтобы построить экран обзора, или предоставить Агенту ИИ описание того, что изменилось, позвоните `compareUnitData()`, или подготовьте сравнение один раз с `prepareUnitComparison()` и запрашивайте его повторно. Зарегистрируйте плагин History для продукта и импортируйте запись Facade. Передайте два полностью материализованных снимка того же устройства, что и `beforeSnapshot` или `afterSnapshot`. Сравнение только для чтения: оно не требует службы истории, и оно не восстанавливает и не объединяет контент.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_DOC,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Прочтите `scopes`, чтобы увидеть, какие виды доступны, затем переведите один из них в `query()` для сужения результата без повторного сравнения. Страница содержит 100 элементов по умолчанию и принимает до 1000. Используйте `page.hasMore` с `offset` чтобы получить оставшиеся элементы. `summary` описывает все сравнение даже при фильтрации элементов. Проверьте `diagnostics.readiness` и `diagnostics.codes` перед тем, как рассматривать результат как полное сравнение. Для использования Node.js или CLI без редактора см. [безголовое сравнение API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
