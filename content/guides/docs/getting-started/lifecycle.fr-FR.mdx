## Cycle de vie global

- **Début**: Univer initialise, et aucune unité commerciale n'existe encore.
- **Prêt**: La première unité d'affaires a été créée. Les unités créées plus tard ne déclenchent plus cette étape.
- **Rendu**: L'interface utilisateur standard a complété son premier commutateur de rendu. Le contenu asynchrone peut encore être chargé.
- **Stabilité**: L'interface utilisateur standard atteint cette étape après un délai qui suit Rendu. Elle n'attend pas que toutes les tâches asynchrones soient terminées.

### API Facade

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Ce que signale l’événement">

`LifeCycleChanged` rapporte la phase globale de Univer. Si le plugin B est chargé après le `Ready` global, par exemple, B exécute toujours `onReady()`, mais aucun second événement global `Ready` n'est émis.

Un auditeur ajouté à tout moment peut s'allumer immédiatement avec l'étape actuelle, y compris `Starting`. Pour déterminer l'étape courante seulement, appelez directement `univerAPI.getCurrentLifecycleStage()` .

</Callout>

Pour supprimer un auditeur, utilisez l'objet `disposable` retourné par l'appel :

```typescript
disposable.dispose()
```

## Hooks de cycle de vie des plugins

Un plugin exécute `onStarting()` lorsqu'il charge et passe ensuite à la phase globale dans laquelle se trouve Univer. La démo ci-dessous change quand B charge et montre comment ses appels de crochet se comparent avec A.

<LifecycleDemo />

Les plugins de type Business chargent généralement avant la création de la première unité de ce type. Un nouveau plugin pour un type qui a déjà commencé les chargements plus tard, dans un lot différé. Les dépendances explicites peuvent le charger plus tôt.

Les crochets fonctionnent synchronement dans un lot, étape par étape et dans un ordre de dépendance. Rien n'attend le travail asynchrone à l'intérieur d'un crochet. Confirmez que l'unité, l'élément DOM ou la ressource est réellement prêt avant d'y accéder.
