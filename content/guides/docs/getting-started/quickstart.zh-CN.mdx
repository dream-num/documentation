Univer Docs 由插件构成，文档内容保存在快照中，改动通过命令执行，日常调用则通过 Facade API 完成。本页说明这四个概念。如需运行一个编辑器，请继续阅读[安装和基本使用](/guides/docs/getting-started/installation)。

## 基本概念 [#basic-concepts]

后续内容会反复使用这四个术语：

- 插件 Plugin
- 快照 Snapshot
- 命令 Command
- Facade API

### 插件

Univer 的全部功能均由插件提供，插件也是 Univer 最小的构成单元。若干插件组合在一起，构成一个 Univer 应用。

插件承担以下两类职责：

1. 实现具体功能，例如 `@univerjs/docs-hyper-link` 为 Univer Docs 提供超链接模型和命令；
2. 提供基础能力，例如 `@univerjs/engine-render` 负责渲染。

按需选择插件即可组成合适的 Univer 应用，不会加载未使用的代码。现有插件无法满足需求时，可以编写插件来扩展 Univer。

### 快照

Univer Docs 使用 [`IDocumentData`](/guides/docs/model/document-data#idocumentdata) 作为快照格式。该快照描述文档正文、文档级样式、页眉页脚、绘图、列表、表格和插件资源。

插件定义的数据存放在可选的 `resources` 字段中。

<Callout type="warning" title="注意事项">
  快照只保存数据，编辑器运行时不会随文档状态变化。如需将当前状态保存为快照，请调用 Facade API 上的快照方法。
</Callout>

### 命令

在 Univer Docs 中，对文档内容和格式的任何修改都通过命令执行。这一机制使改动可追踪，撤销、重做和协同编辑因此成为可能，相关功能也能保持一致。

Facade API 负责准备参数，并执行对应的 Docs 命令。

<Callout type="warning" title="注意事项">
  **不要直接修改 snapshot。** 这种写入不会生效，视图和 UI 也不会更新。请通过命令或 Facade API 修改数据。
</Callout>

### Facade API

办公应用本身复杂，支撑它们的架构同样复杂。Facade API 免去了在这一层面工作的需要：它封装 Univer 的第一方插件，提供更简单的入口。

Facade API 仍在持续完善中。如有问题或需求，请在 GitHub 上提交 issue。

它隐藏底层细节，足以应对日常开发。实现复杂功能时，可能仍需了解 Univer 的架构，并直接使用底层 API。

## 预设模式与插件模式

预设是一组预先配置好的插件。只要两种模式包含的插件相同，提供的能力就相同。预设减少了搭建工作，插件模式则将插件的组成和加载交由应用控制。

<Callout type="warning" title="注意事项">
  - **依赖版本要一致**：无论使用预设模式还是插件模式，所有 Univer 依赖的版本号必须一致。
  - **不要重复注册**：预设已包含的插件无需再次注册。
</Callout>

| 插件模式 | 预设模式 |
| --- | --- |
| 由应用自行引入 Facade 扩展 | 预设自带 Facade 扩展 |
| 由应用控制插件注册顺序 | 预设管理其包含的插件 |
| 按需加载插件 | 已配置的预设在初始化时加载 |
