## 界面语言

`locale` 决定菜单、提示、对话框等界面文案使用哪个语言包；`locales` 只注册语言包，不选择语言。Univer 实例中的各个文档单元共用这两项配置。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有产品：界面**：`locale` 控制菜单、提示、对话框和插件标签的翻译，不会修改用户内容，也不会重命名已有的文档单元。
- **Sheets：单元格格式与公式**：数字和日期的显示依次采用数字格式的 locale 覆盖值、工作簿快照的 `locale`、实例的 `locale`。`region` 不能替代其中任何一项。`DOLLAR`、财务函数结果的货币格式等公式行为仍由 `locale` 决定，中日韩输入归一化也使用 `locale`。
- **Docs：文档统计**：`locale` 决定分词和计数结果。

### 运行时切换语言

切换语言之前，需要先加载已安装插件或预设提供的全部语言包。`loadLocales()` 只合并翻译，不切换语言；`setLocale()` 切换到已加载的翻译，不会下载任何内容。缺少译文的键会显示为键名本身。下面的示例只加载了共享 UI 语言包，其他已安装插件的目标语言包需要加入同一次合并调用。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 在插件模式中注册语言包

在插件模式下，语言包分布在各插件中。从每个提供语言包的插件分别引入，合并为一个对象，再传给 `Univer` 实例：

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignZhCN from '@univerjs/design/locale/zh-CN' // [!code highlight]
import DocsUIZhCN from '@univerjs/docs-ui/locale/zh-CN' // [!code highlight]
import UIZhCN from '@univerjs/ui/locale/zh-CN' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.ZH_CN,
  locales: {
    [LocaleType.ZH_CN]: mergeLocales(
      DesignZhCN, // [!code highlight]
      UIZhCN, // [!code highlight]
      DocsUIZhCN, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="注意事项">
  并非所有插件都包含语言包，各功能的文档会说明。
</Callout>

### 在预设模式中注册语言包

预设包已包含其插件的语言包，可直接从预设引入：

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreZhCN from '@univerjs/preset-docs-core/locales/zh-CN' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univerAPI } = createUniver({
  locale: LocaleType.ZH_CN,
  locales: {
    [LocaleType.ZH_CN]: mergeLocales(
      UniverPresetDocsCoreZhCN, // [!code highlight]
    ),
  },
  presets: [
    UniverDocsCorePreset(),
  ],
})
```

### 合并语言包 [#mergeLocales]

`mergeLocales` 将多个插件或预设的语言包合并为一个完整的语言包对象，用法如下：

<Tabs items={['插件模式', '预设模式']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // 你可以传入多个语言包对象进行合并
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以传入一个语言包对象数组
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/presets'

    // 你可以传入多个语言包对象进行合并
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以传入一个语言包对象数组
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
</Tabs>

### 自定义语言包

也可以自行组装语言包：按需构建对象后传给 `Univer` 实例。预设语言包通常位于 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目录下，可供参考。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 贡献语言包

Univer 内置以下语言包：

- `zh-CN`：简体中文
- `en-US`：英文
- `zh-TW`：繁体中文
- `zh-HK`：繁体中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韩文
- `es-ES`：西班牙文
- `ca-ES`：加泰罗尼亚文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：意大利文
- `pl-PL`：波兰文
- `pt-BR`：葡萄牙文（巴西）

其他语言尚未支持。Univer 是开源项目，欢迎各地的开发者补充或改进语言包。

## 地区设置

`region` 决定相关功能遵循的地区惯例。Univer 实例中的各个文档单元共用这一设置。

两项配置都使用 `LocaleType` 取值：例如 `LocaleType.EN_US` 是 `enUS`，而 `en-US` 是语言包文件名，也是 BCP 47 标签。不要将 `US`、`SG` 这类国家代码传给 `region`。界面使用其他语言时，地区设置不需要对应的语言包。

未显式设置 `region` 时，它会跟随 `locale`，包括之后调用 `setLocale()` 的情况。在初始化时设置 `region` 或调用 `setRegion()` 后，这种自动跟随即停止；此后切换语言时，地区保持已选定的值。目前没有公开 API 可以恢复自动跟随，需要两者同时变化时，请分别设置两个值。

如需在保留界面语言的同时使用德国的地区惯例，可在 `createUniver()` 或 `new Univer()` 中将 `region: LocaleType.DE_DE` 写在 `locale` 旁边。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此时界面切换为英文，地区格式仍为德国。`getCurrentLocale()` 和 `getCurrentRegion()` 返回实际生效的标识。如需同时更改语言和地区，请用同一个 `LocaleType` 值调用两个 setter。

- **Sheets：货币操作**：`region` 决定货币工具栏的图标、货币和会计选项及其预览，以及货币命令应用的格式。更改地区不会重写已有的单元格格式，也不会换算金额。
- **Docs：文档统计**：`region` 决定统计对话框和状态栏中数字的显示格式，包括分组分隔符。更改 `region` 不会改变统计规则。
- **启用评论时**：`region` 决定评论中日期和时间的显示格式，采用 24 小时制和拉丁数字；`locale` 控制评论的界面文案。两者都不会更改已存储的时间戳，`region` 也不是时区设置。
- **Boards、Slides、Bases、PDFs**：`locale` 控制界面翻译；`region` 对读取该设置的共享功能生效，例如接入后的评论，但不会自动重排白板或幻灯片文本、Base 字段和 PDF 内容。

## 从右到左的布局

<Callout type="warning" title="注意">
  目前 RTL 仅支持 UI 层，渲染层尚不支持 RTL。
</Callout>

布局方向是单独的一项设置：在初始化时传入 `direction`，或调用 `univerAPI.setDirection('rtl')` 或 `setDirection('ltr')`。仅更改 `locale` 或 `region` 不会切换布局方向。

```typescript
univerAPI.setDirection('rtl')
```
