## 全局生命周期

- **Starting**: Univer 正在初始化，尚不存在任何业务实例。
- **Ready**: 第一个业务实例已创建。之后创建的实例不会再次触发该阶段。
- **Rendered**: 标准 UI 已完成第一次渲染切换，异步内容可能仍在加载。
- **Steady**: 标准 UI 在 Rendered 之后经过一段延迟进入此阶段，不会等待所有异步任务完成。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="事件监听的范围">

`LifeCycleChanged` 报告 Univer 的全局阶段，而不是某个插件的阶段。例如，在全局进入 `Ready` 之后加载插件 B，B 仍会执行 `onReady()`，但不会再发出一次全局 `Ready` 事件。

新增的监听器可能立即收到当前阶段，`Starting` 也不例外。如果只需了解当前所处阶段，可直接调用 `univerAPI.getCurrentLifecycleStage()`。

</Callout>

如需移除监听器，请使用调用返回的 `disposable` 对象：

```typescript
disposable.dispose()
```

## 插件生命周期钩子

插件加载时执行 `onStarting()`，随后执行到 Univer 当前所处的全局阶段。下面的示例可以改变 B 的加载时机，以展示它的钩子调用与 A 的差异。

<LifecycleDemo />

通用插件在注册时加载。业务类型插件通常在该类型的第一个实例创建之前加载。某个类型已经启动之后，为该类型新增的插件会延后，成批加载。显式依赖可以让该插件提前加载。

同一批插件的钩子同步执行，按依赖顺序逐阶段运行，不会等待钩子中的异步任务。访问业务实例、DOM 元素或资源之前，请先确认对应对象已经就绪。
