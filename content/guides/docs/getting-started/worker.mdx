Docs can run document layout in a Web Worker[^web-worker] through `UniverDocsLayoutWorkerPlugin`. Register it after the Docs core plugin. `workerFactory` creates a fresh Worker for the layout service.

Start with [installation and basic usage](/guides/docs/getting-started/installation). The following snippets extend that setup. Register the plugins before creating or loading content; replace existing registrations rather than registering a plugin twice.

## Main thread

`UniverDocsLayoutWorkerPlugin`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |
| `workerFactory` | `() => Worker` |  | Creates the Worker that runs document layout. This callback is required. |
| <ConfigKey depth={0}>fontFaces</ConfigKey> | `object[]` |  | Loads these fonts in both the editor and the layout Worker before layout. |
| <ConfigKey depth={1}>family</ConfigKey> | `string` |  | Family name to use for document layout. |
| <ConfigKey depth={1}>source</ConfigKey> | `string \| ArrayBuffer` |  | Font bytes or a CSS `FontFace` source such as `url(...)`. |
| <ConfigKey depth={1}>descriptors</ConfigKey> | `FontFaceDescriptors` |  | Font weight, style, or other browser `FontFace` descriptors. |
| `requestTimeoutMs` | `number` | `15_000` | Starts recovery if a Worker request takes longer than this many milliseconds. |

```typescript title="main.ts"
import { UniverDocsLayoutWorkerPlugin } from '@univerjs/docs'

univer.registerPlugin(UniverDocsLayoutWorkerPlugin, {
  workerFactory: () => new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' }),
})
```

## Worker entry

```typescript title="worker.ts"
import { Univer } from '@univerjs/core'
import { UniverDocsWorkerPlugin } from '@univerjs/docs/worker'

const univer = new Univer()
univer.registerPlugin(UniverDocsWorkerPlugin)
```

Use a module Worker and a separate entry file. Keep the Worker and main-thread package versions aligned. Rendering and user interaction stay on the main thread.

[^web-worker]: A Web Worker runs JavaScript outside the browser’s main thread and exchanges messages with it. It cannot access the page DOM directly; moving calculations into a Worker does not move the editor UI there.
