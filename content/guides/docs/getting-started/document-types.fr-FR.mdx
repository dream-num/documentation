Univer Docs propose deux types de documents sur le même moteur de contenu. Choisissez la mise en page de votre application ; le texte, les paragraphes, les styles et la persistance des instantanés utilisent les mêmes API.

| Choisir selon le besoin | Traditionnel | Moderne |
| --- | --- | --- |
| Usage | Rapports, contrats et documents nécessitant des pages physiques. | Pages de connaissances, notes de projet et contenu continu. |
| Mise en page | Pages, sections, en-têtes, pieds de page et colonnes de page. | Flux continu, repli des titres et groupes de colonnes éditables. |
| API de mise en page | API Section | API ColumnGroup |

## Créer un document [#create-document]

Après l’[installation](/guides/docs/getting-started/installation), choisissez un exemple de création ci-dessous. Le mode préréglage/plugin définit l’installation ; Traditionnel/Moderne définit la mise en page. Ces choix sont indépendants. Alignez les versions des paquets Univer ; les exemples utilisent 1.3.0.

<Tabs items={["Documents traditionnels", "Documents modernes"]}>
  <Tab>

```typescript
const doc = univerAPI.createDocument({
  id: 'launch-plan-traditional',
  title: 'Launch plan',
  documentStyle: {
    documentFlavor: univerAPI.Enum.DocumentFlavor.TRADITIONAL,
  },
})

const heading = doc.appendParagraph('Launch plan')
heading.setStyle({ namedStyleType: univerAPI.Enum.NamedStyleType.HEADING_1 })
doc.appendParagraph('Status: Draft')
```

  </Tab>
  <Tab>

```typescript
const doc = univerAPI.createDocument({
```

## Identifier le type [#document-flavor]

Identifiez le type avec `getDocumentFlavor()`, `isTraditional()` et `isModern()`. Un instantané sans type explicite peut être `UNSPECIFIED` : `!isModern()` ne prouve pas qu’il est traditionnel. Conservez le type déclaré lors du chargement.

```typescript
const doc = univerAPI.getActiveDocument()
if (!doc) throw new Error('No active document')
console.log(doc.getDocumentFlavor(), doc.isTraditional(), doc.isModern())
```
