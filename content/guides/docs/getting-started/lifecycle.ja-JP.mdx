## グローバルライフサイクル

- **スタート**:Univerは初期化しており、まだビジネスユニットが存在しません。
- **レディー**:最初のビジネスユニットが作成されました。 ユニットは、このステージを再びトリガーしません。
- **レンダリングされる**:標準UIは最初のレンダリングスイッチを完了しました。非同期のコンテンツはまだロードされるかもしれません。
- **ステアディ**: 標準 UI は、レンダリングされた後、このステージに到達します。すべての非同期タスクが完了するまで待ちません。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="イベントが通知する対象">

`LifeCycleChanged` は、Univer のグローバルステージを報告しています。B がグローバル `Ready` 以降に読み込まれた場合、B は `onReady()` を実行しますが、第 2 回目のグローバル `Ready` イベントは発生しません。

`Starting` を含む現在のステージで、いつでもリスナーがすぐに消火する場合があります。現在のステージだけを決定するには、`univerAPI.getCurrentLifecycleStage()`を直接呼び出します。

</Callout>

リスナーを削除するには、呼び出しによって返される`disposable`オブジェクトを使用します。

```typescript
disposable.dispose()
```

## プラグインのライフサイクルフック

Univer が読み込まれるときにプラグインが `onStarting()`Z を実行します。 B が読み込んだときに、そのホックコールが A とどのように比較するかを示す下のデモ。

<LifecycleDemo />

一般的なプラグインは、登録されたときにロードします。 ビジネス型プラグインは通常、そのタイプの最初のユニットが作成される前にロードします。 既にリリースされたタイプの新しいプラグインは、遅延したバッチで、後続的にロードされます。 明示的な依存関係は、それ以前に読み込むことができます。

Hooks は、ステージと依存関係の順番で、バッチ内で同期的に実行します。ホック内で非同期の作業を待ちません。ユニット、DOM 要素、またはリソースが実際にアクセスする前に準備が整っていることを確認してください。
