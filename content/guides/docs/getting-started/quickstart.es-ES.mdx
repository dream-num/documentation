Univer Docs está compuesto por plugins, almacena un documento en una instantánea, aplica cambios a través de comandos, y normalmente se conduce a través de Facade API. Esta página explica estos cuatro conceptos. Para ejecutar un editor, continúe a [instalación y uso básico](/guides/docs/getting-started/installation) .

## Conceptos básicos [#basic-concepts]

Las páginas restantes utilizan estos cuatro términos a lo largo de:

- Complemento
- Instantánea
- Comando
- Fachada API

### Complementos

Los complementos proporcionan cada característica en Univer y constituyen el bloque de construcción más pequeño de la arquitectura. Una aplicación Univer consiste en un conjunto de plugins.

Un plugin realiza uno de dos roles:

1. `@univerjs/docs-hyper-link`, por ejemplo, añade el modelo de hipervínculo y comandos a Univer Docs.
2. Proporciona una capacidad de base. `@univerjs/engine-render` proporciona renderización.

Incluya sólo los plugins que necesita su aplicación, de modo que el código no utilizado no se carga. Cuando los plugins disponibles no cubren un requisito, escriba un plugin para ampliar Univer.

### Instantánea

Univer Docs almacena un documento como [`IDocumentData`](/guides/docs/model/document-data#idocumentdata). La instantánea describe el cuerpo de documentos, estilos de documento, encabezados y pies, dibujos, listas, tablas y recursos de plugin.

Los datos definidos por un plugin residen en el campo opcional `resources`.

<Callout type="warning" title="Precaución">
  Una instantánea contiene datos solamente. No rastrea el estado de documento mientras el editor está funcionando. Para guardar el estado actual como una instantánea, llame al método de instantáneas en el Facade API.
</Callout>

### Comando

En Univer Docs, cada cambio en el contenido o formato pasa a través de un comando. Este diseño hace posible el seguimiento del cambio, deshacer, redo y la edición colaborativa, y mantiene las características relacionadas de forma compatible con el otro.

El Facade API prepara los argumentos y ejecuta el comando Docs correspondiente.

<Callout type="warning" title="Precaución">
  **No modifique la instantánea directamente.** Tal escritura no tiene efecto y deja vistas y la interfaz de usuario fuera de la fecha. Cambia los datos a través de comandos o el Facade API.
</Callout>

### API de Facade

Las aplicaciones de oficina son inherentemente complejas, y la arquitectura necesaria para apoyarlas es compleja también. El Facade API elimina la necesidad de trabajar a ese nivel: envuelve los plugins de primera parte de Univer y expone puntos de entrada más simples.

El Facade API todavía está en desarrollo activo. Si tiene preguntas o requisitos, abra un problema en GitHub.

Se resumen los detalles subyacentes, que son suficientes para el trabajo cotidiano. Las características complejas pueden requerir todavía una comprensión de la arquitectura de Univer y el uso directo de la API de bajo nivel.

## Modo preset y modo plugin

Un preset es un paquete de plugins que ya están configurados. Cuando ambos modos incluyen los mismos plugins, proporcionan las mismas capacidades. Presets reduce el trabajo de configuración; modo plugin deja composición y carga a la aplicación.

<Callout type="warning">
  Mantenga cada dependencia Univer en la misma versión. Si un preset ya incluye un plugin, no lo registre por segunda vez.
</Callout>

| Modo plugin | Modo preset |
| --- | --- |
| La aplicación importa las extensiones de Facade en sí | El preset incluye las extensiones Facade |
| La aplicación controla el orden de registro de plugins | El preset administra los plugins que incluye |
| Los plugins se cargan a la demanda | Cargar los presets configurados al inicializar |
