Docs peut exécuter la mise en page dans un Web Worker[^web-worker] avec `UniverDocsLayoutWorkerPlugin`. Enregistrez-le après le plugin Docs principal. `workerFactory` crée un nouveau Worker pour le service de mise en page.

Commencez par [l’installation et les premiers pas](/guides/docs/getting-started/installation). Ces extraits complètent la configuration existante. Enregistrez les plugins avant de créer ou charger du contenu ; modifiez les enregistrements existants sans les dupliquer.

## Thread principal

`UniverDocsLayoutWorkerPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `workerFactory` | `() => Worker` |  | Crée le Worker chargé de la mise en page. Cette fonction est obligatoire. |
| <ConfigKey depth={0}>fontFaces</ConfigKey> | `object[]` |  | Charge ces polices dans l’éditeur et le Worker avant la mise en page. |
| <ConfigKey depth={1}>family</ConfigKey> | `string` |  | Nom de la police utilisée pour la mise en page. |
| <ConfigKey depth={1}>source</ConfigKey> | `string \| ArrayBuffer` |  | Octets de la police ou source CSS `FontFace` telle que `url(...)`. |
| <ConfigKey depth={1}>descriptors</ConfigKey> | `FontFaceDescriptors` |  | Descripteurs `FontFace` du navigateur, dont la graisse et le style. |
| `requestTimeoutMs` | `number` | `15_000` | Déclenche la récupération lorsqu’une requête Worker dépasse ce délai en millisecondes. |

```typescript title="main.ts"
import { UniverDocsLayoutWorkerPlugin } from '@univerjs/docs'

univer.registerPlugin(UniverDocsLayoutWorkerPlugin, {
  workerFactory: () => new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' }),
})
```

## Point d’entrée du Worker

```typescript title="worker.ts"
import { Univer } from '@univerjs/core'
import { UniverDocsWorkerPlugin } from '@univerjs/docs/worker'

const univer = new Univer()
univer.registerPlugin(UniverDocsWorkerPlugin)
```

Utilisez un Worker de type module et un fichier d’entrée séparé. Alignez les versions des packages des deux côtés. Le rendu et les interactions restent sur le thread principal.

[^web-worker]: Un Web Worker exécute JavaScript hors du thread principal du navigateur et communique par messages. Il ne peut pas accéder directement au DOM : déplacer les calculs ne déplace pas l’interface de l’éditeur.
