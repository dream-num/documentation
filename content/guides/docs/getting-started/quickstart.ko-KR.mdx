## 스타터 키트

로컬 개발 환경에서 시작하려면 다음 스타터 키트를 사용해 몇 초 만에 새 Univer 앱을 만들 수 있습니다.

<Tabs items={['npm', 'pnpm']}>
  <Tab>
    다음 명령을 실행하려면 기기에 `nodejs >= 18`, `npm >= 8`, `git`이 설치되어 있어야 합니다.

    ```shell
    npx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit
    npm install
    npm run dev
    ```
  </Tab>
  <Tab>
    다음 명령을 실행하려면 기기에 `nodejs >= 18`, `pnpm >= 7`, `git`이 설치되어 있어야 합니다.

    ```shell
    pnpm dlx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit
    pnpm install
    pnpm dev
    ```
  </Tab>
</Tabs>

Univer와 함께한 첫 단계를 잘 마쳤습니다! 첫 프로젝트를 성공적으로 만들었고 Univer로 무엇을 할 수 있는지 간단히 살펴보았습니다.

## 기본 개념 [#basic-concepts]

Univer를 더 깊이 알아보기 전에 이 문서를 읽고 Univer의 기본 개념을 이해해 두세요. Univer를 더욱 원활하게 사용하는 데 도움이 됩니다.

기본 개념은 다음과 같습니다.

- 플러그인
- 스냅샷
- 명령
- Facade API

## 플러그인

Univer의 모든 기능은 플러그인으로 제공됩니다. 플러그인은 Univer의 기본 구성 요소이며, 여러 플러그인을 조합하여 하나의 Univer 애플리케이션을 만듭니다.

플러그인의 역할은 다음과 같습니다.

1. 기능 구현. 예를 들어 `@univerjs/sheets-filter`는 필터링 기능을 제공합니다.
2. 기본 기능 제공. 예를 들어 `@univerjs/engine-render`는 렌더링 기능을 제공합니다.

Univer 플러그인을 조합하여 요구 사항에 맞는 Univer 애플리케이션을 구성하고 불필요한 코드가 로드되지 않도록 할 수 있습니다. 또한 플러그인을 직접 작성하여 필요에 맞게 Univer의 기능을 확장할 수도 있습니다.

### 관련 링크

1. 플러그인 작성법을 알아보려면 [CSV 가져오기 플러그인 작성하기](/guides/recipes/practices/csv-import-plugin)를 참고하세요.
2. Univer의 아키텍처 설계를 자세히 알아보려면 [Univer 아키텍처](/guides/recipes/architecture/univer)를 참고하세요.

## 스냅샷

Univer에서 문서를 불러오려면 스냅샷을 로드해야 합니다. 문서 유형마다 고유한 스냅샷 형식을 제공하므로, 형식 요구 사항에 맞는 스냅샷을 작성하는 방법은 위의 API 문서를 참고하세요.

1. 스프레드시트의 스냅샷 형식은 [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata)입니다.
2. 문서의 스냅샷 형식은 [`IDocumentData`](/guides/docs/model/document-data#idocumentdata)입니다.

기능 플러그인은 `resources` 필드를 통해 이미지 등의 리소스를 저장할 수 있습니다. 자세한 내용은 [플러그인 사용자 정의 모델](/guides/recipes/tutorials/custom-model)을 참고하세요.

<Callout type="warning" title="주의">
  주의하세요! Univer의 스냅샷은 데이터 저장에만 사용되며 런타임의 최신 문서 상태를 반영하지 않습니다! 문서 상태를 스냅샷으로 저장하려면 Facade API의 스냅샷 저장 메서드를 사용하세요.
</Callout>

## 명령

Univer에서는 모든 데이터 변경을 명령을 통해 실행해야 합니다. 명령 기반 방식은 값의 변경을 더 효과적으로 추적하고 실행 취소, 다시 실행, 공동 편집 등의 기능을 구현하며 기능 사이의 복잡한 연계 로직을 처리할 수 있습니다.

명령으로 문서 데이터를 수정하려면 [명령 ID를 찾는 방법](/guides/recipes/practices/find-the-command-id)을 참고하세요. Facade API로 문서 데이터를 수정하는 경우에도 실제로는 Facade API가 내부에서 매개변수를 준비하고 명령을 실행합니다.

<Callout type="warning" title="주의">
  **스냅샷을 직접 수정하지 마세요!** 변경 사항이 적용되지 않으며 뷰나 UI도 업데이트되지 않습니다. 명령 또는 Facade API를 통해 데이터를 수정하세요.
</Callout>

## Facade API

오피스 애플리케이션은 매우 복잡하므로 Univer의 아키텍처 역시 매우 복잡합니다. 개발자가 Univer를 더 쉽게 사용할 수 있도록 Univer의 퍼스트 파티 플러그인을 래핑한 Facade API를 제공합니다. Facade API는 개발자가 Univer를 더 쉽게 사용할 수 있도록 간결한 인터페이스를 제공합니다.

Facade API는 계속해서 개선되고 있습니다. 질문이나 요구 사항이 있다면 GitHub에 이슈를 제출해 주세요.

Facade API는 기반 구현의 세부 사항을 추상화한 고수준 API입니다. 일반적인 작업은 간소화해 주지만, 복잡한 기능을 구현할 때는 Univer의 아키텍처를 이해하고 저수준 API를 직접 사용해야 할 수 있습니다.
