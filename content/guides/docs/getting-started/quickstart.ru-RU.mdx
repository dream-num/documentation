Univer Docs состоит из плагинов, хранит документ в снимке, применяет изменения через команды и обычно проходит через Facade API. Эта страница объясняет эти четыре концепции. Чтобы запустить редактор, продолжайте [Установка и базовое использование](/guides/docs/getting-started/installation) ,

## Основные понятия [#basic-concepts]

Остальные страницы используют эти четыре термина:

- Плагин
- Снимок
- Команда
- Facade API

### Плагины

Плагины предоставляют все функции в Univer и составляют самый маленький строительный блок архитектуры.Приложение Univer состоит из набора плагинов.

Плагин выполняет одну из двух ролей:

1. Например, `@univerjs/docs-hyper-link` добавляет модель гиперссылки и команды в Univer Docs.
2. Он обеспечивает базовые возможности. `@univerjs/engine-render` обеспечивает рендеринг.

Включите только те плагины, которые нужны вашему приложению, чтобы не загружался неиспользованный код.Когда доступные плагины не покрывают требование, напишите плагин для расширения Univer.

### Снимок

Univer Docs хранит документ как [`IDocumentData`](/guides/docs/model/document-data#idocumentdata). Снимок описывает тело документа, стили уровня документа, заголовки и нижние колонтитулы, чертежи, списки, таблицы и ресурсы плагинов.

Данные, определенные плагином, находятся в поле `resources`.

<Callout type="warning" title="Осторожно">
  Снимок содержит только данные. Он не отслеживает состояние документа во время работы редактора. Чтобы сохранить текущее состояние в качестве снимка, вызовите метод снимка на Facade API.
</Callout>

### Команда

В Univer Docs каждое изменение контента или форматирования проходит через команду. Этот дизайн делает возможным отслеживание изменений, отмену, переделку и совместное редактирование и сохраняет связанные функции в соответствии друг с другом.

Facade API подготавливает аргументы и выполняет соответствующую команду Docs.

<Callout type="warning" title="Осторожно">
  **Не изменяйте снимок напрямую.** Такая запись не имеет эффекта и оставляет просмотры и пользовательский интерфейс устаревшими. Измените данные с помощью команд или Facade API.
</Callout>

### Facade API

Офисные приложения по своей сути сложны, и архитектура, необходимая для их поддержки, также сложна. Facade API устраняет необходимость работать на этом уровне: он обертывает сторонние плагины Univer и обнажает более простые точки входа.

Facade API все еще находится в стадии активной разработки.Если у вас есть вопросы или требования, откройте вопрос на GitHub.

Он абстрагирует основные детали, которых достаточно для повседневной работы.Сложные функции могут по-прежнему требовать понимания архитектуры Univer и непосредственного использования API низкого уровня.

## Режим пресетов и режим плагинов

Предустановка представляет собой набор плагинов, которые уже настроены. Когда оба режима включают в себя одни и те же плагины, они обеспечивают одинаковые возможности. Предустанавливающие устройства уменьшают работу настройки; режим плагина оставляет композицию и загрузку в приложение.

<Callout type="warning">
  Сохраняйте все зависимости Univer от одной и той же версии.Если предустановленная версия уже содержит плагин, не регистрируйте его во второй раз.
</Callout>

| Режим плагинов | Режим пресетов |
| --- | --- |
| Заявка импортирует сами расширения Фасада | Предустановка включает в себя расширения Фасада |
| Приложение контролирует порядок регистрации плагинов | Preset управляет плагинами, которые он включает |
| Плагины загружаются по требованию | Загрузка настроенных пресетов при инициализации |
