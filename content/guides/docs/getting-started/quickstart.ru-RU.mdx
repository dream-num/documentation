## Стартовый набор

Если вы предпочитаете локальную среду разработки, воспользуйтесь одним из следующих стартовых наборов, чтобы за несколько секунд создать новое приложение Univer.

<Tabs items={['npm', 'pnpm']}>
  <Tab>
    Для выполнения следующей команды на устройстве должны быть установлены `nodejs >= 18`, `npm >= 8` и `git`.

    ```shell
    npx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit
    npm install
    npm run dev
    ```
  </Tab>
  <Tab>

    ```shell
    pnpm dlx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit

    pnpm dev
    ```
  </Tab>

## Основные понятия [#basic-concepts]

Прежде чем глубже погружаться в Univer, ознакомьтесь с его основными понятиями. Это поможет вам увереннее работать с Univer.

К основным понятиям относятся:

- Плагин
- Снимок
- Команда
- Facade API

## Плагины

Все функции Univer реализованы с помощью плагинов — основных строительных блоков системы. Приложение Univer формируется из нескольких объединённых плагинов.

Плагины выполняют следующие задачи:

1. Реализуют функции. Например, `@univerjs/sheets-filter` предоставляет фильтрацию.
2. Предоставляют базовые возможности. Например, `@univerjs/engine-render` отвечает за отрисовку.

Комбинируя плагины Univer, можно настроить приложение под свои требования и не загружать лишний код. Кроме того, собственные плагины позволяют расширить Univer для решения нестандартных задач.

## Снимок

Чтобы загрузить документ в Univer, необходимо загрузить его снимок. Для каждого типа документов предусмотрен свой формат снимка. Узнать, как подготовить снимок в нужном формате, можно из указанной выше документации API:

1. Формат снимка электронной таблицы — [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata).
2. Формат снимка документа — [`IDocumentData`](/guides/docs/model/document-data#idocumentdata).

Функциональные плагины могут хранить ресурсы, например изображения, в поле `resources`. Подробнее см. в разделе [«Пользовательская модель плагина»](/guides/recipes/tutorials/custom-model).

<Callout type="warning" title="Внимание">
  Снимок Univer предназначен только для хранения данных и не отражает актуальное состояние документа во время выполнения! Чтобы сохранить состояние документа в виде снимка, используйте метод сохранения снимка из Facade API.
</Callout>

## Команда

В Univer любые изменения данных должны выполняться с помощью команд. Такой подход позволяет точнее отслеживать изменения значений, реализовывать отмену, повтор и совместное редактирование, а также обрабатывать сложные взаимосвязи между функциями.

Чтобы изменять данные документа с помощью команд, обратитесь к руководству [«Как найти идентификатор команды»](/guides/recipes/practices/find-the-command-id). Если вы изменяете данные через Facade API, этот API фактически сам подготавливает параметры и выполняет команды.

<Callout type="warning" title="Внимание">
  **Не изменяйте снимок напрямую!** Такие изменения не применятся и не приведут к обновлению представлений или пользовательского интерфейса. Изменяйте данные с помощью команд или Facade API.
</Callout>

## Facade API

Офисные приложения очень сложны, поэтому архитектура Univer тоже устроена непросто. Чтобы разработчикам было удобнее работать с Univer, мы предоставляем Facade API — обёртку над официальными плагинами Univer с более простыми интерфейсами.

Facade API активно развивается. Если у вас есть вопросы или пожелания, создайте issue на GitHub.

Facade API — это высокоуровневый API, который скрывает детали внутренней реализации. Он упрощает типовые задачи, но для сложных функций может потребоваться понимание архитектуры Univer и непосредственное использование низкоуровневого API.
