Univer Docs 由外掛構成，文件內容儲存在快照中，改動透過命令執行，日常呼叫則透過 Facade API 完成。本頁說明這四個概念。如需執行一個編輯器，請繼續閱讀[安裝和基本使用](/guides/docs/getting-started/installation)。

## 基本概念 [#basic-concepts]

後續內容會反覆使用這四個術語：

- 外掛 Plugin
- 快照 Snapshot
- 命令 Command
- Facade API

### 外掛

Univer 的全部功能均由外掛提供，外掛也是 Univer 最小的構成單元。若干外掛組合在一起，構成一個 Univer 應用。

外掛承擔以下兩類職責：

1. 實現具體功能，例如 `@univerjs/docs-hyper-link` 為 Univer Docs 提供超連結模型和命令；
2. 提供基礎能力，例如 `@univerjs/engine-render` 負責渲染。

按需選擇外掛即可組成合適的 Univer 應用，不會載入未使用的程式碼。現有外掛無法滿足需求時，可以編寫外掛來擴充套件 Univer。

### 快照

Univer Docs 使用 [`IDocumentData`](/guides/docs/model/document-data#idocumentdata) 作為快照格式。該快照描述文件正文、文件級樣式、頁首頁尾、繪圖、列表、表格和外掛資源。

外掛定義的資料存放在可選的 `resources` 欄位中。

<Callout type="warning" title="注意事項">
  快照只儲存資料，編輯器執行時不會隨文件狀態變化。如需將當前狀態儲存為快照，請呼叫 Facade API 上的快照方法。
</Callout>

### 命令

在 Univer Docs 中，對文件內容和格式的任何修改都透過命令執行。這一機制使改動可追蹤，撤銷、重做和協同編輯因此成為可能，相關功能也能保持一致。

Facade API 負責準備參數，並執行對應的 Docs 命令。

<Callout type="warning" title="注意事項">
  **不要直接修改 snapshot。** 這種寫入不會生效，檢視和 UI 也不會更新。請透過命令或 Facade API 修改資料。
</Callout>

### Facade API

辦公應用本身複雜，支撐它們的架構同樣複雜。Facade API 免去了在這一層面工作的需要：它封裝 Univer 的第一方外掛，提供更簡單的入口。

Facade API 仍在持續完善中。如有問題或需求，請在 GitHub 上提交 issue。

它隱藏底層細節，足以應對日常開發。實現複雜功能時，可能仍需瞭解 Univer 的架構，並直接使用底層 API。

## 預設模式與外掛模式

預設是一組預先配置好的外掛。只要兩種模式包含的外掛相同，提供的能力就相同。預設減少了搭建工作，外掛模式則將外掛的組成和載入交由應用控制。

<Callout type="warning" title="注意事項">
  - **依賴版本要一致**：無論使用預設模式還是外掛模式，所有 Univer 依賴的版本號必須一致。
  - **不要重複註冊**：預設已包含的外掛無需再次註冊。
</Callout>

| 外掛模式                       | 預設模式                                           |
| ------------------------------ | -------------------------------------------------- |
| 由應用自行引入 Facade 擴充套件 | 預設自帶 Facade 擴充套件 |
| 由應用控制外掛註冊順序 | 預設管理其包含的外掛 |
| 按需載入外掛 | 已配置的預設在初始化時載入 |
