Univer Docs has two document types on the same content engine. Choose the layout for your application; text, paragraphs, styles, and snapshot persistence use the same APIs.

| Choose by task | Traditional | Modern |
| --- | --- | --- |
| Typical use | Reports, contracts, and documents with physical pages. | Knowledge pages, project briefs, and continuously flowing content. |
| Layout | Pages, sections, headers, footers, and page columns. | Continuous layout, heading collapse, and editable column groups. |
| Layout APIs | Section APIs | ColumnGroup APIs |

## Create a document [#create-document]

After [installation](/guides/docs/getting-started/installation), use one of the following creation examples. Preset/plugin mode selects how Univer is installed; Traditional/Modern selects the document layout. These are independent choices. Keep all Univer packages on the same version; examples use 1.3.0.

<Tabs items={["Traditional documents", "Modern documents"]}>
  <Tab>

```typescript
const doc = univerAPI.createDocument({
  id: 'launch-plan-traditional',
  title: 'Launch plan',
  documentStyle: {
    documentFlavor: univerAPI.Enum.DocumentFlavor.TRADITIONAL,
  },
})

const heading = doc.appendParagraph('Launch plan')
heading.setStyle({ namedStyleType: univerAPI.Enum.NamedStyleType.HEADING_1 })
doc.appendParagraph('Status: Draft')
```

  </Tab>

## Read the document type [#document-flavor]

Use `getDocumentFlavor()`, `isTraditional()`, and `isModern()` to identify the document. A snapshot without an explicit flavor can be `UNSPECIFIED`: `!isModern()` does not prove it is Traditional. Preserve the declared flavor when loading a snapshot.

```typescript
const doc = univerAPI.getActiveDocument()
if (!doc) throw new Error('No active document')
console.log(doc.getDocumentFlavor(), doc.isTraditional(), doc.isModern())
```

## Shared content operations [#shared-content]

Continue with [Docs API](/guides/docs/features/core/docs-api) for paragraph IDs, text ranges, editing, styles, and saving. Use [Traditional documents](/guides/docs/features/traditional) for page layout and [Modern documents](/guides/docs/features/modern) for continuous layout. Feature plugins are still required for their respective capabilities.
