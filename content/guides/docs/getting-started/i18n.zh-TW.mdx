## 介面語言

`locale` 決定選單、提示、對話方塊等介面文案使用哪個語言套件；`locales` 只註冊語言套件，不選擇語言。Univer 例項中的各個文件單元共用這兩項配置。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有產品：介面**：`locale` 控制選單、提示、對話方塊和外掛標籤的翻譯，不會修改使用者內容，也不會重新命名已有的文件單元。
- **Sheets：單元格格式與公式**：數字和日期的顯示依次採用數字格式的 locale 覆蓋值、工作簿快照的 `locale`、例項的 `locale`。`region` 不能替代其中任何一項。`DOLLAR`、財務函式結果的貨幣格式等公式行為仍由 `locale` 決定，中日韓輸入歸一化也使用 `locale`。
- **Docs：文件統計**：`locale` 決定分詞和計數結果。

### 執行時切換語言

切換語言之前，需要先載入已安裝外掛或預設提供的全部語言套件。`loadLocales()` 只合並翻譯，不切換語言；`setLocale()` 切換到已載入的翻譯，不會下載任何內容。缺少譯文的鍵會顯示為鍵名本身。下面的範例只載入了共享 UI 語言套件，其他已安裝外掛的目標語言套件需要加入同一次合併呼叫。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 在外掛模式中註冊語言包

在外掛模式下，語言套件分佈在各外掛中。從每個提供語言套件的外掛分別引入，合併為一個物件，再傳給 `Univer` 例項：

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignZhTW from '@univerjs/design/locale/zh-TW' // [!code highlight]
import DocsUIZhTW from '@univerjs/docs-ui/locale/zh-TW' // [!code highlight]
import UIZhTW from '@univerjs/ui/locale/zh-TW' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.ZH_TW,
  locales: {
    [LocaleType.ZH_TW]: mergeLocales(
      DesignZhTW, // [!code highlight]
      UIZhTW, // [!code highlight]
      DocsUIZhTW, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="注意事項">
  並非所有外掛都包含語言套件，各功能的文件會說明。
</Callout>

### 在預設模式中註冊語言包

預設套件已包含其外掛的語言套件，可直接從預設引入：

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreZhTW from '@univerjs/preset-docs-core/locales/zh-TW' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univerAPI } = createUniver({
  locale: LocaleType.ZH_TW,
  locales: {
    [LocaleType.ZH_TW]: mergeLocales(
      UniverPresetDocsCoreZhTW, // [!code highlight]
    ),
  },
  presets: [
    UniverDocsCorePreset(),
  ],
})
```

### 合併語言套件 [#mergeLocales]

`mergeLocales` 將多個外掛或預設的語言套件合併為一個完整的語言套件物件，用法如下：

<Tabs items={['外掛模式', '預設模式']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // 你可以直接傳入多個語系物件
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以傳入語系物件陣列
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/presets'

    // 你可以直接傳入多個語系物件
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以傳入語系物件陣列
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
</Tabs>

### 自訂語系檔

也可以自行組裝語言套件：按需建置物件後傳給 `Univer` 例項。預設語言套件通常位於 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目錄下，可供參考。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 貢獻語系

Univer 內建以下語言套件：

- `zh-CN`：簡體中文
- `en-US`：英文
- `zh-TW`：繁體中文（臺灣）
- `zh-HK`：繁體中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韓文
- `es-ES`：西班牙文
- `ca-ES`：加泰羅尼亞文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：義大利文
- `pl-PL`：波蘭文
- `pt-BR`：葡萄牙文（巴西）

其他語言尚未支援。Univer 是開源專案，歡迎各地的開發者補充或改進語言套件。

## 地區設定

`region` 決定相關功能遵循的地區慣例。Univer 例項中的各個文件單元共用這一設定。

兩項配置都使用 `LocaleType` 取值：例如 `LocaleType.EN_US` 是 `enUS`，而 `en-US` 是語言套件檔名，也是 BCP 47 標籤。不要將 `US`、`SG` 這類國家程式碼傳給 `region`。介面使用其他語言時，地區設定不需要對應的語言套件。

未顯式設定 `region` 時，它會跟隨 `locale`，包括之後呼叫 `setLocale()` 的情況。在初始化時設定 `region` 或呼叫 `setRegion()` 後，這種自動跟隨即停止；此後切換語言時，地區保持已選定的值。目前沒有公開 API 可以恢復自動跟隨，需要兩者同時變化時，請分別設定兩個值。

如需在保留介面語言的同時使用德國的地區慣例，可在 `createUniver()` 或 `new Univer()` 中將 `region: LocaleType.DE_DE` 寫在 `locale` 旁邊。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此時介面切換為英文，地區格式仍為德國。`getCurrentLocale()` 和 `getCurrentRegion()` 返回實際生效的標識。如需同時更改語言和地區，請用同一個 `LocaleType` 值呼叫兩個 setter。

- **Sheets：貨幣操作**：`region` 決定貨幣工具欄的圖示、貨幣和會計選項及其預覽，以及貨幣命令應用的格式。更改地區不會重寫已有的單元格格式，也不會換算金額。
- **Docs：文件統計**：`region` 決定統計對話方塊和狀態列中數字的顯示格式，包括分組分隔符。更改 `region` 不會改變統計規則。
- **啟用評論時**：`region` 決定評論中日期和時間的顯示格式，採用 24 小時制和拉丁數字；`locale` 控制評論的介面文案。兩者都不會更改已儲存的時間戳，`region` 也不是時區設定。
- **Boards、Slides、Bases、PDFs**：`locale` 控制介面翻譯；`region` 對讀取該設定的共享功能生效，例如接入後的評論，但不會自動重排白板或幻燈片文字、Base 欄位和 PDF 內容。

## 從右到左的版面配置

<Callout type="warning" title="注意">
  目前 RTL 僅支援 UI 層，渲染層尚不支援 RTL。
</Callout>

版面配置方向是單獨的一項設定：在初始化時傳入 `direction`，或呼叫 `univerAPI.setDirection('rtl')` 或 `setDirection('ltr')`。僅更改 `locale` 或 `region` 不會切換版面配置方向。

```typescript
univerAPI.setDirection('rtl')
```
