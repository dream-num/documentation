## Ciclo de vida global

- **Comenzar**: Univer está inicializando, y no existe ninguna unidad de negocio todavía.
- **Listo**: La primera unidad de negocio ha sido creada. Unidades creadas más tarde no activan esta etapa de nuevo.
- **Rendered**: La interfaz de usuario estándar ha completado su primer interruptor de renderizado. El contenido asincrono puede estar cargando.
- **Tranquila.**: La interfaz de usuario estándar alcanza esta etapa después de un retraso que sigue Rendered. No espera que todas las tareas asincrónicas terminen.

### API de Facade

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Qué comunica el evento">

`LifeCycleChanged` reporta la etapa global de Univer. Si el plugin B está cargado después del `Ready` global, por ejemplo, B todavía funciona `onReady()`, pero no se emite un segundo evento global `Ready` .

Un oyente añadido en cualquier momento puede disparar inmediatamente con la etapa actual, incluyendo `Starting`. Para determinar la etapa actual sólo, llame directamente a `univerAPI.getCurrentLifecycleStage()` .

</Callout>

Para eliminar un oyente, utilice el objeto `disposable` devuelto por la llamada:

```typescript
disposable.dispose()
```

## Hooks del ciclo de vida de plugins

Un plugin ejecuta `onStarting()` cuando se carga y luego avanza a la etapa global en la que está Univer. La demo a continuación cambia cuando B carga y muestra cómo sus llamadas de gancho se comparan con A's.

<LifecycleDemo />

Los plugins generales cargan cuando están registrados. Los plugins de tipo empresarial suelen cargar antes de que se cree la primera unidad de ese tipo. Un nuevo plugin para un tipo que ya ha comenzado cargas más tarde, en un lote diferido. Las dependencias de gastos pueden cargarlo antes.

Los ganchos corren sincrónicamente dentro de un lote, etapa por etapa y en orden de dependencia. Nada espera para el trabajo asincrónico dentro de un gancho. Confirme que la unidad, elemento DOM, o recurso está realmente listo antes de acceder a él.
