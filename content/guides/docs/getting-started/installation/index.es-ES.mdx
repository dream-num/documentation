---
title: Instalación y uso básico
---

Univer está construido a partir de plugins. Cada característica naves como un módulo separado, por lo que el mismo núcleo se puede montar en aplicaciones de documentos electrónicos de tipos muy diferentes. Esta flexibilidad también conlleva un costo: en el primer uso, una aplicación debe determinar qué plugins necesita.

Univer por lo tanto ofrece dos maneras de integrarlo: **modo plugin** y **modo preset**. Un **preset** es un paquete de plugins que ya se ha configurado. Sin extensiones complejas, ambos modos proporcionan las mismas capacidades.

<Callout type="warning" title="Caution">
  - En ambos modos, cada dependencia debe utilizar el mismo número de versión.
  - Si un preset ya incluye un plugin, no importa ese plugin por separado. El registro de ambos puede causar conflictos de plugins o características que no se comportan como se espera.
</Callout>

Los dos modos difieren como sigue:

| Modo de complemento | Modo preestablecido |
| --- | --- |
| Los paquetes Facade se importan manualmente | Los paquetes Facade son proporcionados por el preset |
| El orden de registro debe ser gestionado para plugins que proporcionan el mismo tipo de función | El preset administra el orden de registro para las características que incluye |
| Los plugins pueden ser cargados de perezoso a la demanda | Carga de Presets sincronizadamente durante la inicialización |

Para **profunda personalización o extensiones**, elija el modo plugin, en el que cada plugin se combina y configura individualmente. El modo Preset proporciona un comienzo más rápido porque el paquete ya está montado.

## Configuración a través del modo complemento

Univer proporciona sus características como plugins. Algunos plugins de núcleo son necesarios para que el producto funcione, y los plugins restantes se añaden sólo cuando sea necesario. El ejemplo a continuación es una aplicación mínima Univer Docs, montado e instalado plugin por plugin.

A diferencia del modo preset, el modo plugin no incluye el Facade API[^facade-entry] por defecto. Los ejemplos a continuación utilizan el Facade API, por lo que importa los paquetes de fachada correspondientes antes de crear la instancia API.

### Uso del administrador de paquetes

#### Instalación

Univer hace su interfaz con React y procesa sus flujos de datos con RxJS; también puede ser incrustado en una aplicación Vue o Angular. Asegúrese de que las `react`, `react-dom`, y `rxjs` dependencias de pares[^peer-dependency] están instaladas. El comando Yarn a continuación los incluye explícitamente.

Todos los paquetes `@univerjs/*` y `@univerjs-pro/*` deben usar **la misma versión**.

#### Uso

Crear el contenedor con una altura explícita antes de inicializar Univer:

```html
<div id="app" style="height: 600px"></div>
```

Importar las entradas de fachada utilizadas por los ejemplos antes de llamar `FUniver.newAPI(univer)`. Cargar los estilos en el orden `@univerjs/design`, `@univerjs/ui` y luego el producto CSS.

<Callout type="warning" title="Caution">
  - No todos los plugins incluyen paquetes de fachada, paquetes de idiomas y archivos de estilo; la documentación para cada característica indica cuál de ellos proporciona.
  - El orden de las importaciones de estilo importa: cargar el `@univerjs/design` y `@univerjs/ui` CSS antes de los estilos de cualquier otro plugin.
</Callout>

<Steps>
  <Step>
    En primer lugar, importar archivos de estilo Univer, paquetes de idiomas, y los plugins que la aplicación requiere:

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    A continuación, importar los paquetes de fachada utilizados por el ejemplo:

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    Entonces, crear una instancia Univer y registrar estos plugins:

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

#### Métodos `univer.registerPlugin` y `univer.registerPlugins` [#registerPlugin]

`univer.registerPlugin` registra un plugin en la instancia Univer y debe ser llamado después de que la instancia haya sido creada.

La firma es `univer.registerPlugin(Plugin, options)`, donde `Plugin` es el plugin para registrarse y `options` se define por cada plugin.

Para registrar varios plugins a la vez, pasar un array a `univer.registerPlugins`. Esto es conveniente cuando los plugins se gestionan en un solo lugar.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### Complementos de carga diferida

El modo Plugin permite controlar el tiempo de carga de cada plugin. Un enfoque común carga sólo los plugins esenciales en el inicio de la aplicación y posterga los plugins restantes hasta que el primer render haya completado.

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

## Compatibilidad móvil [#mobile-support]

<Callout type="warning">
  Estos ejemplos requieren paquetes del SDK que exporten los plugins móviles indicados. Mantenga todas las dependencias `@univerjs/*` y `@univerjs-pro/*` en **la misma versión**.

  `1.0.0-rc.0` no exporta `UniverDocsMobileUIPlugin`; usa una construcción que incluye esta entrada móvil antes de ejecutar el ejemplo.
</Callout>

Para controles táctiles en Univer Docs, registre el **plugins UI móvil**.[^mobile-ui-mode] El modo UI debe ser elegido antes de que el editor sea creado.

En el ejemplo del plugin anterior, **Sustituir la sustitución** la interfaz de usuario importa y registra a continuación, y lo hace antes de `createUnit()`; no los agregue a un editor de escritorio que ya se ha inicializado. Mantenga el modelo plugins, motores, archivos locales, CSS y Facade importa sin cambios. Las clases de escritorio y móviles se denominan exportaciones desde el **mismo paquete de entrada**.

`UniverMobileUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Elemento DOM donde se monta el editor o su ID. |
| `disableAutoFocus` | `true` | `true` | Evita que el editor reciba el foco al iniciarse. |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
```

`UniverSheetsCorePreset` y `UniverDocsCorePreset` actualmente registran plugins de interfaz de escritorio y no proporcionan una opción `mobile: true`. En el móvil, los plugins deben ser montados individualmente; añadir plugins móviles después de un preset de escritorio no reemplaza su interfaz de usuario.

### Contenedor e interacción táctil

Establece una altura explícita en el contenedor y configura el viewport de página. `100dvh` sigue la altura dinámica del puerto de visualización. En los navegadores móviles de destino, prueba el desplazamiento, pinche zoom, selección de texto, acceso a portapapeles y el teclado en pantalla. Reactivar un editor de escritorio no lo cambia a plugins móviles.

`UniverMobileUIPlugin` predetermina a `disableAutoFocus: true`, por lo que el editor no se centra automáticamente durante la inicialización.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Configuración mediante el modo preestablecido

El modo Preset inicia una aplicación de Univer Docs con menos de veinte líneas de código.

### Uso del administrador de paquetes

Si el proyecto ya utiliza herramientas modernas de primera línea, añadir Univer es sencillo. Construir aplicaciones Univer con una herramienta que soporta los módulos ES bien, como [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) o [Webpack 5](https://webpack.js.org/). Otras herramientas, Webpack 4 por ejemplo, pueden requerir configuración adicional.

#### Instalación

Instala `@univerjs/presets` con el gestor de paquetes utilizado por el proyecto:

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### Uso

<Callout type="warning">
  Si la herramienta de construcción no soporta el campo `exports` en package.json (común en Webpack 4), los caminos mapeados deben ser cambiados a los caminos reales manualmente.
</Callout>

El siguiente código comienza una aplicación de Univer Docs:

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

El objeto `univerAPI` devuelto es el Univer Facade API, y la mayor parte de la funcionalidad que proporciona Univer se llama a través de él.

#### Método `createUniver`

`createUniver` acepta un objeto de configuración que describe la instancia, incluyendo el idioma, el tema y los plugins. Devuelve un objeto que contiene la instancia Univer y la instancia Facade API.

Las propiedades más utilizadas son:

- `locale`: el entorno del lenguaje, como un valor de enumeración `LocaleType`.
- `locales`: paquetes de idiomas, claves por el entorno del lenguaje, cada valor de un objeto de paquete de lenguaje.
- `theme`: un objeto de tema opcional.
- `presets`: los presets a registrarse, como `UniverDocsCorePreset`.
- `plugins`: plugins para registrarse además de los presets.

Utilice la propiedad `plugins` para un plugin que ningún paquete preset incluye, o para un plugin implementado por la aplicación. Plugins también se puede registrar en `univer.registerPlugin` después de que se obtenga la instancia Univer.

<Callout>
  Ver [Referencia de API / crearUniver](https://docs.univer.ai/reference/methods/create-univer) para el conjunto completo de opciones.
</Callout>

## Otras versiones

Además de las versiones estables, Univer publica canales alfa / beta y nocturnos, que proporcionan acceso temprano a las características que no han sido publicadas oficialmente. Más características también tienen más riesgo: estas construcciones pueden contener errores, funcionalidad incompleta o características inestables. Evite en entornos de producción donde sea posible.

### Lanzamiento alfa/beta

Cuando el equipo de desarrollo Univer completa una nueva característica o un cambio significativo, puede pre-release el paquete al canal de alfa o beta. Instale un alfa o una beta con el siguiente comando:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Los problemas y la retroalimentación relacionados con una liberación previa pueden ser reportados al equipo de desarrollo a través de [Cuestiones de GitHub](https://github.com/dream-num/univer/issues). La retroalimentacion sobre estas construcciones tempranas es bienvenida.
