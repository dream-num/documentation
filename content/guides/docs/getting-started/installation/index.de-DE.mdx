Univer übernimmt eine Plugin-basierte Designphilosophie, die darauf abzielt, Entwicklern ein flexibles und erweiterbares Framework für Anwendungen für elektronische Dokumente bereitzustellen. Durch dieses Plugin-basierte Design kann Univer problemlos verschiedene Funktionsmodule integrieren, um den Anforderungen verschiedener Benutzer gerecht zu werden. Das Plugin-basierte Design erhöht jedoch die Komplexität der Anwendung, insbesondere für Entwickler, die neu bei Univer sind.

Aus diesem Grund bietet Univer zwei Möglichkeiten, die Ihnen bei der schnellen Integration und Nutzung von Univer helfen: **Plugin-Modus** und **Voreinstellungsmodus**. Das sogenannte **Preset** ist eigentlich eine Kombination aus vorkonfigurierten Plugins, sodass die von beiden Modi bereitgestellten Funktionen ohne komplexe Erweiterungen gleich sind.

<Callout type="warning" title="Caution">
  - **Konsistente Abhängigkeitsversionen**: Unabhängig davon, ob Sie den Preset-Modus oder den Plugin-Modus verwenden, müssen Sie sicherstellen, dass alle Abhängigkeiten konsistente Versionsnummern haben.
  - **Vorsichtiges Mischen von Plugins und Presets**: Wenn ein Plugin bereits in einem Preset enthalten ist, müssen Sie dieses Plugin nicht separat importieren, wenn Sie das Preset verwenden. Andernfalls kann es zu Plugin-Konflikten oder Funktionsanomalien kommen.
</Callout>

Unterschiede zwischen Preset-Modus und Plugin-Modus:

| Plugin-Modus | Voreinstellungsmodus |
| --- | --- |
| Erfordert den manuellen Import entsprechender Fassadenpakete | Kein manueller Import von Fassadenpaketen erforderlich |
| Erfordert Beachtung der Registrierungsreihenfolge von Plugins mit derselben Funktionalität | Keine Beachtung der Registrierungsreihenfolge der in Voreinstellungen enthaltenen Funktionalitäten |
| Unterstützt Lazy Loading bei Bedarf | Unterstützt nur Lazy Loading auf Voreinstellungsebene, Plugins innerhalb der Voreinstellung können nur synchron geladen werden |

## Einrichtung über den Preset-Modus

Hier stellen wir Ihnen kurz vor, wie Sie schnell eine Univer Docs-Anwendung mit weniger als zwanzig Zeilen Code erstellen können.

### Verwendung des Paketmanagers

Wenn Ihr Projekt bereits moderne Frontend-Entwicklungstools verwendet, wird die Integration von Univer sehr einfach sein. Wir empfehlen die Verwendung von Build-Tools wie [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) oder [Webpack 5](https://webpack.js.org/), die ES-Module gut unterstützen, um Univer-Anwendungen zu erstellen. Wenn Sie andere Build-Tools (z. B. Webpack 4) verwenden, benötigen Sie möglicherweise eine zusätzliche Konfiguration.

#### Installation

Wählen Sie Ihren Paketmanager zur Installation von `@unvierjs/presets`:

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### Verwendung

<Callout type="warning">
Wenn Ihr Build-Tool das Feld `exports` in package.json nicht unterstützt (üblich in Webpack 4), müssen Sie die zugeordneten Pfade manuell ändern die tatsächlichen Pfade.
</Callout>

Mit dem folgenden Code können Sie eine Univer Docs-Anwendung starten:

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

Das hier zurückgegebene `univerAPI`-Objekt wird als Univer Facade API bezeichnet, über die Sie viele von Univer bereitgestellte Funktionen aufrufen können.

#### `createUniver`-Methode

Die `createUniver`-Methode akzeptiert ein Konfigurationsobjekt, das die Konfigurationsinformationen für Univer enthält, z. B. Sprache, Design und Plugins. Diese Methode gibt ein Objekt zurück, das die Univer-Instanz und die Univer Facade-API-Instanz enthält.

Einige Eigenschaften des Konfigurationsobjekts lauten wie folgt:

- `locale`: Sprachumgebung, kann ein `LocaleType`-Enumerationswert sein.
- `locales`: Gebietsschemata, ein Objekt, der Schlüssel ist die Sprachumgebung und der Wert ist das Sprachpaketobjekt.
- `theme`: Ein Themenobjekt, das optional ist.
- `presets`: Ein Array von Voreinstellungen, das die zu registrierenden Voreinstellungen enthält, z. B `UniverDocsCorePreset`.
- `plugins`: Ein Array von Plugins, das die Plugins enthält, die zusätzlich registriert werden müssen.

Wenn Sie ein Plugin verwenden, das in keinem voreingestellten Paket enthalten ist, oder Sie Ihr eigenes Plugin implementieren, können Sie diese Plugins über die Eigenschaft `plugins` registrieren. Sie können Plugins auch mit der Methode `univer.registerPlugin` registrieren, nachdem Sie die Univer-Instanz erhalten haben.

<Callout>
Ausführlichere Informationen zur Methode `createUniver` finden Sie in der [API-Referenz / createUniver](https://docs.univer.ai/reference/methods/create-univer).
</Callout>

## Einrichtung über den Plugin-Modus

Univer bietet eine Reihe von Funktionen in Form von Plugins. Zusätzlich zu einigen Kern-Plugins, die für das Produkt wesentlich sind, können Sie bei Bedarf gezielt weitere Plugins einführen. Hier nehmen wir die einfachste Univer Docs-Anwendung als Beispiel, um vorzustellen, wie man Plugins manuell kombiniert und installiert.

Im Gegensatz zum voreingestellten Modus enthält der Plugin-Modus standardmäßig nicht die Facade-API. In den folgenden Beispielen wird die Facade-API verwendet. Importieren Sie daher die entsprechenden Fassadenpakete, bevor Sie die API-Instanz erstellen.

### Verwenden des Paketmanagers

#### Installation

Wir verwenden React zum Entwickeln der Ansicht (dies hat keine Auswirkungen auf Ihre Verwendung von Univer in Vue oder Angular) und Rxjs für die Verarbeitung von Datenströmen. Da diese beiden Bibliotheken in der modernen Front-End-Entwicklung weit verbreitet sind, behandeln wir sie als PeerDependencies. Allerdings weisen verschiedene Paketverwaltungstools unterschiedliche Verhaltensweisen in Bezug auf Peer-Abhängigkeiten auf, daher müssen Sie möglicherweise auf einige Details achten.

<Callout>
  - Wenn Sie npm verwenden, stellen Sie sicher, dass Sie npm@7 oder höher verwenden. Dies liegt daran, dass npm@3 ~ npm@6 `peerDependencies`[^1] nicht korrekt installiert.
  - Wenn Sie pnpm verwenden, stellen Sie sicher, dass Sie pnpm@8 oder höher verwenden. Wenn Sie pnpm@6 ~ pnpm@7 verwenden, können Sie versuchen, `auto-install-peers=true` [^2] zu konfigurieren, um Probleme bei der Abhängigkeitsinstallation zu beheben.
  - Wenn Sie Garn verwenden, müssen Sie das fehlende `peerDependencies`[^3] manuell installieren. Die folgenden Installationsbefehle enthalten diese Abhängigkeiten bereits.
</Callout>

#### Verwendung

<Callout type="warning" title="Caution">
  - Nicht alle Plugins enthalten Fassadenpakete und Sprache Packs und Style-Dateien. Wir werden dies in der Dokumentation für jede Funktion angeben.
  - Die Reihenfolge beim Importieren von Stildateien ist wichtig. Stellen Sie sicher, dass Sie die CSS-Stile von `@univerjs/design` und `@univerjs/ui` importieren, bevor Sie die Stile anderer Plugins importieren.
</Callout>

<Steps>
  <Step>
Sie müssen die Univer-Stildateien, Sprachpakete und einige notwendige Plugins in Ihr Projekt importieren:

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
Importieren Sie die im Beispiel verwendeten Fassadenpakete:

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
Erstellen Sie dann eine Univer-Instanz und registrieren Sie diese Plugins:

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

#### `univer.registerPlugin`-Methode

``univer.registerPlugin`-Methode wird verwendet, um ein Plugin bei der Univer-Instanz zu registrieren. Sie können diese Methode aufrufen, nachdem Sie die Univer-Instanz erstellt haben, um Plugins zu registrieren.

Sie können ein Plugin mit der Methode `univer.registerPlugin(Plugin, options)` registrieren, wobei `Plugin` das zu registrierende Plugin ist und `options` optionale Konfigurationselemente sind, da jedes Plugin unterschiedliche Konfigurationselemente haben kann.

Sie können auch ein Array übergeben, um mehrere Plugins gleichzeitig zu registrieren. Dies ist nützlich für Szenarien, in denen Sie Plugins zentral verwalten müssen.

```typescript
univer.registerPlugin([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### Lazy Loading Plugins

Ein gemeinsamer Vorteil des Plugin-Modus besteht darin, dass Sie den Ladezeitpunkt von Plugins flexibler steuern können. Ein gängiger Ansatz besteht darin, nur die wesentlichen Plugins während der Anwendungsinitialisierung zu laden und das Laden einiger Plugins bis nach Abschluss des ersten Renderings aufzuschieben.

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

Unsere [offizielle Demo](https://github.com/dream-num/univer/blob/dev/examples/src/sheets/main.ts) verwendet diese Optimierungstechnik, auf die Sie sich beziehen können.

## Andere Versionen

Zusätzlich zu stabilen Veröffentlichungen bietet Univer Alpha-/Beta- und Nightly-Kanäle an. Mit diesen Versionen erhalten Sie frühzeitig Zugriff auf die neuesten Funktionen, die noch nicht offiziell veröffentlicht wurden. Bedenken Sie jedoch, dass mehr Funktionen auch mehr Risiken bedeuten. Diese Versionen können Fehler, unvollständige Funktionalität oder instabile Funktionen enthalten. Bitte vermeiden Sie nach Möglichkeit die Verwendung dieser Versionen in Produktionsumgebungen.

### Alpha-/Beta-Release

Wenn das Univer-Entwicklungsteam eine neue Funktion oder wesentliche Änderung fertigstellt, veröffentlicht es diese möglicherweise vorab für den Alpha- oder Beta-Kanal. Sie können die Alpha-/Betaversion eines Univer-Pakets mit dem folgenden Befehl installieren:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Wenn Sie bei der Verwendung von Alpha-/Betaversionen auf Probleme stoßen oder Feedback haben, melden Sie diese bitte dem Univer-Entwicklungsteam über [GitHub Issues](https://github.com/dream-num/univer/issues).

Wir freuen uns über Ihr Feedback zu diesen frühen Versionen.
