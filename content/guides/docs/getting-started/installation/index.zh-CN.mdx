title: 安装和基本使用
---

本文介绍 Univer Docs 的安装和基本使用，以及预设模式与插件模式各自的配置方式。如果对 Univer 的基础术语或这两种模式的区别还不熟悉，建议先阅读[基本概念](/guides/docs/getting-started/quickstart#basic-concepts)。

Univer 提供两种接入方式：*预设模式*和*插件模式*。预设模式以打包形式提供一组预先配置好的插件，配置量较少，接入更快；如果需要**深度定制或扩展**，则应使用插件模式，由开发者自行组合和配置插件。

## 通过插件模式创建

Univer 的功能都以插件形式提供。除产品必需的核心插件外，其余插件按需引入。下面以一个最基础的 Univer Docs 应用为例，说明如何手动挑选并注册插件。

与预设模式不同，插件模式默认不包含 Facade API[^facade-entry]。下面的示例会使用 Facade API，因此需要在创建 API 实例之前引入对应的 facade 包。

### 使用包管理器

#### 安装

Univer 的界面使用 React 构建，数据流使用 RxJS 处理，也可以嵌入 Vue 或 Angular 应用。请确认 `react`、`react-dom` 和 `rxjs` 这几个 peer dependencies[^peer-dependency] 已经安装，下面的 Yarn 命令已显式包含它们。

所有 `@univerjs/*` 和 `@univerjs-pro/*` 包必须保持**相同版本**。

<InstallTabs

#### 使用

初始化 Univer 之前，先创建容器并设置明确的高度：

```html
<div id="app" style="height: 600px"></div>
```

调用 `FUniver.newAPI(univer)` 之前，先引入下面示例用到的 facade 入口。样式文件按 `@univerjs/design`、`@univerjs/ui`、产品样式的顺序引入。

<Callout type="warning" title="注意事项">
  - 并非每个插件都包含 facade 包、语言包和样式文件，具体包含哪些，各功能的文档中会说明。
  - 样式文件的引入顺序很重要：先引入 `@univerjs/design`、`@univerjs/ui` 的 CSS，再引入其他插件的样式。
</Callout>

<Steps>
  <Step>
    首先，在项目中引入 Univer 的样式文件、语言包以及应用所需的插件：

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignZhCN from '@univerjs/design/locale/zh-CN'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIZhCN from '@univerjs/docs-ui/locale/zh-CN'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIZhCN from '@univerjs/ui/locale/zh-CN'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    然后，引入示例用到的 facade 包：

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    最后，创建一个 Univer 实例并注册这些插件：

    ```typescript
    const univer = new Univer({
      locale: LocaleType.ZH_CN,
      locales: {
        [LocaleType.ZH_CN]: mergeLocales(
          DesignZhCN,
          UIZhCN,
          DocsUIZhCN,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | 用于挂载编辑器的元素或其 DOM ID。 |

`UniverWatermarkPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>textWatermarkSettings</ConfigKey> | `object` |  | 文字水印设置。 |
| <ConfigKey depth={1}>content</ConfigKey> | `string` | `''` | 要显示的文字。 |
| <ConfigKey depth={1}>fontSize</ConfigKey> | `number` | `16` | 字号，单位为像素。 |

#### `univer.registerPlugin` 与 `univer.registerPlugins` 方法 [#registerPlugin]

`univer.registerPlugin` 用于将单个插件注册到 Univer 实例上，需要在实例创建完成后调用。

签名是 `univer.registerPlugin(Plugin, options)`，其中 `Plugin` 是要注册的插件，`options` 是可选配置，由各插件自行定义。

需要一次注册多个插件时，可向 `univer.registerPlugins` 传入一个数组。集中管理插件时，这种方式更为方便。

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### 懒加载部分插件

插件模式的一个优势在于可以控制插件的加载时机。常见做法是在应用初始化时只加载必需的插件，其余插件延迟到首次渲染完成之后再加载。

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

## 移动端适配 [#mobile-support]

<Callout type="warning">
  下面示例要求所安装的 SDK 包包含列出的移动端导出。所有 `@univerjs/*` 和 `@univerjs-pro/*` 依赖必须保持**相同版本**。

  `1.0.0-rc.0` 尚未导出 `UniverDocsMobileUIPlugin`，运行示例前请改用包含该移动端入口的构建版本。
</Callout>

在 Univer Docs 中使用触摸操作界面，需要注册**移动端 UI 插件**。[^mobile-ui-mode] UI 模式必须在创建编辑器之前确定。

在上方插件模式的示例中，**替换**下面这些 UI 导入和注册，且必须在 `createUnit()` 之前完成；已经初始化的桌面端编辑器不能再追加移动端插件。模型插件、引擎、语言包、CSS 和 Facade 的导入保持不变。桌面端和移动端的类都是**同一个包入口**的具名导出。

`UniverMobileUIPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | 用于挂载编辑器的元素或其 DOM ID。 |
| `disableAutoFocus` | `true` | `true` | 防止编辑器在启动时自动获取焦点。 |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
```

目前 `UniverSheetsCorePreset` 和 `UniverDocsCorePreset` 注册的都是桌面端 UI 插件，也不提供 `mobile: true` 选项。移动端需要自行组合插件；在桌面端预设之后再追加移动端插件，原有 UI 不会被替换。

### 容器与触摸交互

容器需要设置明确的高度，页面还需要配置 viewport。`100dvh` 会随动态视口高度变化。在目标移动浏览器中，需要实际测试滚动、双指缩放、文字选择、剪贴板访问和软键盘。仅缩小桌面端编辑器不会切换到移动端插件。

`UniverMobileUIPlugin` 默认使用 `disableAutoFocus: true`，编辑器在初始化时不会自动获取焦点。

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## 通过预设模式创建

使用预设模式时，不到二十行代码即可构建一个 Univer Docs 应用。

### 使用包管理器

如果项目已经在使用现代前端工具，接入 Univer 的过程较为简单。建议使用对 ES Module 支持较好的构建工具，例如 [Vite](https://vitejs.dev/)、[esbuild](https://esbuild.github.io/) 或 [Webpack 5](https://webpack.js.org/)。如果使用其他工具（例如 Webpack 4），可能需要额外的配置。

#### 安装

使用项目所用的包管理器安装 `@univerjs/presets`：

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### 使用

<Callout type="warning">
  如果构建工具不支持 package.json 的 `exports` 字段（在 Webpack 4 中较为常见），需要手动将映射路径改为实际路径。
</Callout>

下面的代码即可创建一个 Univer Docs 应用：

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreZhCN from '@univerjs/preset-docs-core/locales/zh-CN'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.ZH_CN,
  locales: {
    [LocaleType.ZH_CN]: mergeLocales(
      UniverPresetDocsCoreZhCN,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

此处返回的 `univerAPI` 对象即 Univer 的 Facade API，Univer 提供的大部分功能都通过它调用。

#### `createUniver` 方法

`createUniver` 接收一个描述实例的配置对象，其中包括语言、主题和插件等。它返回的对象包含 Univer 实例和 Facade API 实例。

配置对象上常用的属性如下：

- `locale`：语言环境，取 `LocaleType` 的枚举值。
- `locales`：语言包对象，键是语言环境，值是对应的语言包。
- `theme`：主题对象，可选。
- `presets`：要注册的预设包数组，例如 `UniverDocsCorePreset`。
- `plugins`：需要额外注册的插件数组。

如果某个插件不属于任何预设包，或者是自行实现的插件，可以通过 `plugins` 属性注册。也可以在获得 Univer 实例之后，通过 `univer.registerPlugin` 注册插件。

<Callout>
  `createUniver` 的完整参数说明见 [API Reference / createUniver](https://docs.univer.ai/reference/methods/create-univer)。
</Callout>

## 其他发布版本

除稳定版外，Univer 还提供 alpha / beta 和 nightly 通道，尚未正式发布的新功能会先出现在这些通道中。功能更多也意味着风险更高：这些版本可能存在 bug，功能不完整，或者尚不稳定。生产环境中应尽量避免使用。

### Alpha / Beta 版本

当 Univer 开发团队完成一个新功能或一项较大改动时，可能会将该包预发布到 alpha 或 beta 通道。安装 alpha / beta 版本的 Univer 包使用以下命令：

```package-install
npm install @univerjs/<package-name>@alpha # Alpha 版本
npm install @univerjs/<package-name>@beta # Beta 版本
```

使用 alpha / beta 版本时遇到的问题或相关反馈，可以通过 [GitHub Issues](https://github.com/dream-num/univer/issues) 提交给 Univer 开发团队。欢迎提供关于这些早期版本的反馈。

[^facade-entry]: Facade 是面向应用的 API，封装已注册插件的能力。导入 Facade 入口会扩展 API 方法，但不会代替功能插件的注册。

[^peer-dependency]: `peerDependencies` 表示需要由宿主项目提供兼容版本的依赖。这样 Univer 可以与应用共享 React 等库，而不是各自携带一份。

[^mobile-ui-mode]: 移动端 UI 插件在初始化时选择触摸控件和移动端服务，不会自动判断设备，也不会在窗口尺寸变化时切换已有实例。若要切换模式，应先保留文档状态，销毁旧实例，再使用所选插件组合初始化。
