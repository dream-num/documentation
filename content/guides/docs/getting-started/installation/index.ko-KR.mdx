title: 설치 및 기본 사용법

Univer는 플러그인 기반 설계 철학을 채택하여 개발자에게 유연하고 확장 가능한 전자 문서 애플리케이션 프레임워크를 제공합니다. 이러한 플러그인 기반 설계 덕분에 Univer는 다양한 기능 모듈을 손쉽게 통합하여 여러 사용자의 요구를 충족할 수 있습니다. 다만 플러그인 기반 설계는 애플리케이션의 복잡성을 높이며, 특히 Univer를 처음 접하는 개발자에게는 어렵게 느껴질 수 있습니다.

이를 위해 Univer는 빠르게 통합하고 사용할 수 있도록 **플러그인 모드**와 **프리셋 모드**라는 두 가지 방식을 제공합니다. **프리셋**은 미리 구성된 플러그인의 조합이므로, 복잡한 확장이 필요하지 않다면 두 모드가 제공하는 기능은 같습니다.

<Callout type="warning" title="주의">
  - **의존성 버전 통일**: 프리셋 모드와 플러그인 모드 중 어느 것을 사용하든 모든 의존성의 버전 번호를 동일하게 맞춰야 합니다.
  - **플러그인과 프리셋 혼용 시 주의**: 플러그인이 이미 프리셋에 포함되어 있다면 프리셋을 사용할 때 해당 플러그인을 별도로 가져올 필요가 없습니다. 중복으로 가져오면 플러그인 충돌이나 기능 이상이 발생할 수 있습니다.
</Callout>

프리셋 모드와 플러그인 모드의 차이점은 다음과 같습니다.

| 플러그인 모드 | 프리셋 모드 |
| --- | --- |
| 해당 facade 패키지를 직접 가져와야 함 | facade 패키지를 직접 가져올 필요가 없음 |
| 같은 기능을 제공하는 플러그인의 등록 순서에 주의해야 함 | 프리셋에 포함된 기능의 등록 순서를 신경 쓸 필요가 없음 |
| 필요할 때 지연 로딩 가능 | 프리셋 단위의 지연 로딩만 지원하며, 프리셋 안의 플러그인은 동기식으로만 로드 가능 |

## 프리셋 모드로 설정하기

여기서는 20줄 미만의 코드로 Univer Docs 애플리케이션을 빠르게 만드는 방법을 간단히 소개합니다.

### 패키지 관리자 사용

프로젝트에서 이미 최신 프런트엔드 개발 도구를 사용하고 있다면 Univer를 매우 간단하게 통합할 수 있습니다. Univer 애플리케이션을 빌드할 때는 ES Modules를 잘 지원하는 [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/), [Webpack 5](https://webpack.js.org/) 같은 빌드 도구를 권장합니다. Webpack 4와 같은 다른 빌드 도구를 사용한다면 추가 설정이 필요할 수 있습니다.

#### 설치

사용 중인 패키지 관리자로 `@unvierjs/presets`를 설치합니다.

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### 사용법

<Callout type="warning">
  빌드 도구가 package.json의 `exports` 필드를 지원하지 않는다면(Webpack 4에서 흔함) 매핑된 경로를 실제 경로로 직접 변경해야 합니다.
</Callout>

다음 코드로 Univer Docs 애플리케이션을 시작할 수 있습니다.

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

여기서 반환되는 `univerAPI` 객체를 Univer Facade API라고 하며, 이 객체를 통해 Univer가 제공하는 다양한 기능을 호출할 수 있습니다.

<PlaygroundFrame lang="en-US" slug="docs/slim-via-preset" clickToShow />

<Callout type="warning">
  `@univerjs/presets/preset-docs-core`에서 `UniverDocsCorePreset`을 가져올 수도 있지만, 빌드 도구가 package.json의 `exports` 필드를 지원하는지 확인해야 합니다.
</Callout>

#### `createUniver` 메서드

`createUniver` 메서드는 언어, 테마, 플러그인 등 Univer의 설정 정보가 담긴 설정 객체를 받습니다. 이 메서드는 Univer 인스턴스와 Univer Facade API 인스턴스가 포함된 객체를 반환합니다.

설정 객체의 주요 속성은 다음과 같습니다.

- `locale`: 언어 환경이며 `LocaleType` 열거형 값을 사용할 수 있습니다.
- `locales`: 로케일 객체입니다. 키는 언어 환경이고 값은 언어 팩 객체입니다.
- `theme`: 선택 사항인 테마 객체입니다.
- `presets`: 등록할 프리셋이 담긴 배열입니다. 예를 들면 `UniverDocsCorePreset`이 있습니다.
- `plugins`: 추가로 등록해야 하는 플러그인이 담긴 배열입니다.

프리셋 패키지에 포함되지 않은 플러그인을 사용하거나 직접 플러그인을 구현한 경우 `plugins` 속성으로 등록할 수 있습니다. Univer 인스턴스를 얻은 뒤 `univer.registerPlugin` 메서드로 플러그인을 등록해도 됩니다.

<Callout>
  `createUniver` 메서드에 관한 자세한 내용은 [API Reference / createUniver](https://docs.univer.ai/reference/methods/create-univer)에서 확인할 수 있습니다.
</Callout>

### CDN에서 가져오기

패키지 관리자를 사용하지 않거나 Univer의 기능을 빠르게 시험해 보고 싶다면 CDN을 통해 Univer 관련 리소스를 가져올 수 있습니다. 자세한 내용은 [CDN으로 Univer 사용하기](/guides/docs/getting-started/installation/cdn#preset-mode)를 참고하세요.

## 플러그인 모드로 설정하기

Univer는 다양한 기능을 플러그인 형태로 제공합니다. 제품에 꼭 필요한 일부 핵심 플러그인 외에는 필요에 따라 다른 플러그인을 선택해서 도입할 수 있습니다. 여기서는 가장 기본적인 Univer Docs 애플리케이션을 예로 들어 플러그인을 직접 조합하고 설치하는 방법을 설명합니다.

프리셋 모드와 달리 플러그인 모드에는 Facade API가 기본으로 포함되지 않습니다. 아래 예제에서는 Facade API를 사용하므로 API 인스턴스를 만들기 전에 해당 facade 패키지를 가져와야 합니다.

### 패키지 관리자 사용

#### 설치

Univer는 뷰 개발에 React를 사용하고(Vue 또는 Angular에서 Univer를 사용하는 데에는 영향을 주지 않음), 데이터 스트림 처리에 Rxjs를 사용합니다. 두 라이브러리는 최신 프런트엔드 개발에서 널리 쓰이므로 peerDependencies로 취급합니다. 하지만 패키지 관리 도구마다 peerDependencies를 처리하는 방식이 다르므로 몇 가지 사항을 확인해야 합니다.

<Callout>
  - npm을 사용한다면 npm@7 이상인지 확인하세요. npm@3 ~ npm@6은 `peerDependencies`[^1]를 올바르게 설치하지 않기 때문입니다.
  - pnpm을 사용한다면 pnpm@8 이상인지 확인하세요. pnpm@6 ~ pnpm@7을 사용한다면 `auto-install-peers=true` [^2]를 설정하여 의존성 설치 문제를 해결할 수 있습니다.
  - yarn을 사용한다면 누락된 `peerDependencies`[^3]를 직접 설치해야 합니다. 아래 설치 명령에는 이러한 의존성이 이미 포함되어 있습니다.
</Callout>

    ```shell

    yarn add @univerjs/core @univerjs/design @univerjs/docs @univerjs/docs-ui @univerjs/engine-formula @univerjs/engine-render @univerjs/ui react react-dom rxjs
    ```
  </Tab>
</Tabs>

#### 사용법

<Callout type="warning" title="주의">
  - 모든 플러그인에 facade 패키지, 언어 팩, 스타일 파일이 포함되는 것은 아닙니다. 각 기능의 문서에서 이를 안내합니다.
  - 스타일 파일을 가져오는 순서가 중요합니다. 다른 플러그인의 스타일을 가져오기 전에 `@univerjs/design`과 `@univerjs/ui`의 CSS 스타일을 먼저 가져와야 합니다.
</Callout>

<Steps>
  <Step>
    프로젝트에서 Univer 스타일 파일, 언어 팩 및 몇 가지 필수 플러그인을 가져옵니다.

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    예제에서 사용하는 facade 패키지를 가져옵니다.

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    그런 다음 Univer 인스턴스를 만들고 플러그인을 등록합니다.

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

#### `univer.registerPlugin` 메서드

``univer.registerPlugin` 메서드는 Univer 인스턴스에 플러그인을 등록할 때 사용합니다. Univer 인스턴스를 만든 뒤 이 메서드를 호출하여 플러그인을 등록할 수 있습니다.

`univer.registerPlugin(Plugin, options)` 메서드로 플러그인을 등록할 수 있습니다. 여기서 `Plugin`은 등록할 플러그인이고, `options`는 선택 사항인 설정 항목입니다. 플러그인마다 설정 항목이 다를 수 있습니다.

배열을 전달하여 여러 플러그인을 한 번에 등록할 수도 있습니다. 플러그인을 한곳에서 관리해야 할 때 유용합니다.

```typescript
univer.registerPlugin([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### 플러그인 지연 로딩

플러그인 모드의 대표적인 장점은 플러그인을 불러오는 시점을 더 유연하게 제어할 수 있다는 것입니다. 일반적으로 애플리케이션을 초기화할 때는 필수 플러그인만 불러오고, 일부 플러그인은 첫 렌더링이 끝난 뒤에 불러오도록 미룹니다.

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

[공식 데모](https://github.com/dream-num/univer/blob/dev/examples/src/sheets/main.ts)에서도 이 최적화 기법을 사용하고 있으니 참고하세요.

## 기타 릴리스

안정 버전 외에도 Univer는 alpha / beta 및 nightly 채널을 제공합니다. 이 버전을 사용하면 아직 정식 출시되지 않은 최신 기능을 미리 이용할 수 있습니다. 다만 기능이 많아지는 만큼 위험도 커진다는 점에 유의하세요. 버그나 미완성 기능, 불안정한 기능이 포함될 수 있으므로 가능하면 프로덕션 환경에서는 사용하지 마세요.

### Alpha / Beta 릴리스

Univer 개발팀이 새로운 기능이나 중요한 변경 사항을 완성하면 alpha 또는 beta 채널에 미리 공개할 수 있습니다. 다음 명령으로 Univer 패키지의 alpha / beta 버전을 설치할 수 있습니다.

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

alpha / beta 버전을 사용하면서 문제가 발생하거나 의견이 있다면 [GitHub Issues](https://github.com/dream-num/univer/issues)를 통해 Univer 개발팀에 알려 주세요.

이러한 초기 릴리스에 대한 여러분의 의견을 기다립니다.
