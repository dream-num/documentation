Univer는 플러그인에서 건축됩니다. 각 특징은 분리되는 단위로 발송합니다, 그래서 동일한 핵심은 아주 다른 종류의 전자 문서 신청으로 조립될 수 있습니다. 이 융통성은 또한 비용을 나릅니다: 첫번째 사용에, 신청은 그것을 필요로 하는 플러그인을 결정해야 합니다.

Univer는 따라서 그것을 통합하는 2가지 방법을 제공합니다: **플러그인 모드**와 **preset 형태**. **제품 정보**은 이미 형성된 플러그인의 뭉치입니다. 복잡한 연장 없이, 형태는 동일한 기능을 제공합니다.

<Callout type="warning" title="주의">
  - 두 모드 모두에서, 각 의존도는 같은 버전 번호를 사용해야합니다.
  - 이미 플러그인을 포함하면 플러그인을 별도로 가져 오지 않습니다. 둘 다 플러그인 충돌을 일으킬 수 있습니다 또는 예상대로 행동하지 않는 기능.
</Callout>

두 가지 모드는 다음과 같습니다.

| 플러그인 모드 | 프리셋 모드 |
| --- | --- |
| Facade 포장은 수동으로 수입됩니다 | Facade 패키지는 미리 설치됩니다. |
| 등록 주문은 같은 종류의 기능을 제공하는 플러그인에 대해 관리해야합니다. | 사전 설정은 기능에 대한 등록 순서를 관리합니다. |
| 플러그인은 수요에 게 게으른 로드 될 수 있습니다 | 초기화 중에 Presets load synchronously |

**깊은 주문화 또는 연장**의 경우 플러그인 모드를 선택하여 각 플러그인이 결합되어 개별적으로 구성됩니다. 미리 설정 모드는 번들가 이미 조립되기 때문에 빠른 시작을 제공합니다.

## 플러그인 모드로 설정하기

Univer는 플러그인으로 그것의 특징을 제공합니다. 몇몇 핵심 플러그인은 기능에 제품을 위해 요구되고, 나머지 플러그인은 필요로 할 때만 추가됩니다. 아래에 예는 최소 Univer Docs 신청, 조립되고 플러그인에 의해 설치된 플러그인입니다.

미리 설정 모드와 달리 플러그인 모드는 기본적으로 Facade API[^facade-entry]를 포함하지 않습니다. 아래 예제는 Facade API을 사용하므로 API 인스턴스를 만들기 전에 해당 정면 패키지를 가져다줍니다.

### 패키지 관리자 사용

#### 설치

Univer는 React와 인터페이스를 렌더링하고 RxJS와 데이터 스트림을 처리합니다. Vue 또는 Angular 응용 프로그램에 포함될 수도 있습니다. `react`, `react-dom` 및 `rxjs` 피어 Dependencies[^peer-dependency]가 설치되어 있는지 확인하십시오. 아래의 원사 명령은 명시적으로 포함합니다.

모든 `@univerjs/*` 및 `@univerjs-pro/*` 패키지는 **같은 버전**를 사용해야합니다.

Univer 초기화하기 전에 명시된 높이로 컨테이너를 만듭니다.

```html
<div id="app" style="height: 600px"></div>
```

`FUniver.newAPI(univer)`를 호출하기 전에 예제에서 사용되는 정면 항목을 가져옵니다. 주문 `@univerjs/design`, `@univerjs/ui`에서 스타일을로드 한 다음 제품 CSS를로드하십시오.

<Callout type="warning" title="주의">
  - 모든 플러그인에는 정면 패키지, 언어 팩 및 스타일 파일이 포함되어 있지 않습니다. 각 기능 상태에 대한 문서는 제공합니다.
  - 스타일 가져 오기의 순서 : 다른 플러그인의 스타일 전에 `@univerjs/design` 및 `@univerjs/ui` CSS를로드하십시오.
</Callout>

<Steps>
  <Step>
    먼저 Univer의 스타일 파일, 언어 팩 및 플러그인을 가져 오는 응용 프로그램은 다음과 같습니다.

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    다음, 예를 들어 사용한 정면 패키지를 가져옵니다.

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    그런 다음 Univer 인스턴스를 만들고이 플러그인을 등록하십시오.

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

| --- | --- | --- | --- |

#### `univer.registerPlugin` 및 `univer.registerPlugins` 메서드 [#registerPlugin]

`univer.registerPlugin`는 Univer 인스턴스에서 하나의 플러그인을 등록하고 인스턴스가 생성 된 후 호출해야합니다.

서명은 `univer.registerPlugin(Plugin, options)`, `Plugin`가 등록하는 플러그인이며 `options`는 각 플러그인에 의해 정의된 옵션 구성입니다.

한 번에 여러 플러그인을 등록하려면 `univer.registerPlugins`에 배열을 통과하십시오. 플러그인이 한 곳에서 관리 될 때 편리합니다.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### 플러그인 지연 로딩

플러그인 모드는 각 플러그인의 로딩 시간을 제어 할 수 있습니다. 일반적인 접근 방식은 응용 프로그램 시작에서 필수 플러그인 만로드하고 첫 번째 렌더링이 완료 될 때까지 나머지 플러그인을 무시합니다.

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

패키지 관리자를 피하거나 Univer를 신속하게 평가하려면 리소스가 CDN에서로드 될 수 있습니다. [CDN을 통해 Univer 사용](/guides/docs/getting-started/installation/cdn#plugin-mode)을 참조하십시오.

## 모바일 지원 [#mobile-support]

<Callout type="warning">
  아래 모바일 플러그인을 내보내는 SDK 패키지가 필요합니다. 모든 `@univerjs/*` 및 `@univerjs-pro/*` 의존성을 **같은 버전**으로 맞추세요.

  `1.0.0-rc.0`는 `UniverDocsMobileUIPlugin`를 수출하지 않습니다; 예를 실행하기 전에이 모바일 항목이 포함 된 빌드를 사용합니다.
</Callout>

Univer Docs의 터치 컨트롤을 위해 **모바일 UI 플러그인**.[^mobile-ui-mode] 편집기가 생성되기 전에 UI 모드를 선택해야합니다.

위의 플러그인 모드 예에서 **제품 설명** UI 가져 오기 및 등록, 그리고 `createUnit()` 전에 이렇게; 이미 초기화 된 데스크톱 편집기에 추가하지 마십시오. 모델 플러그인, 엔진, 로컬 파일, CSS 및 Facade 가져 오기가 변경되지 않았습니다. 데스크톱 및 모바일 클래스는 **동일한 패키지 항목**에서 수출을 명명하고 있습니다.

`UniverMobileUIPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | 편집기를 마운트할 DOM 요소 또는 해당 요소의 ID입니다. |
| `disableAutoFocus` | `true` | `true` | 시작할 때 편집기에 자동으로 포커스를 주지 않습니다. |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
```

`UniverSheetsCorePreset` 및 `UniverDocsCorePreset`는 현재 데스크탑 UI 플러그인을 등록하고 `mobile: true` 옵션을 제공하지 않습니다. 모바일에서 플러그인은 개별적으로 조립되어야합니다. 데스크톱 사전 설정 후 모바일 플러그인을 추가하면 UI를 교체하지 않습니다.

### 컨테이너와 터치 조작

컨테이너에 명시된 높이를 설정하고 페이지 뷰포트를 구성하십시오. `100dvh`는 동적 뷰포트 높이를 따릅니다. 대상 모바일 브라우저에서, 스크롤, pinch 급상승, 텍스트 선택, 클립보드 액세스 및 화면 키보드를 테스트하십시오. 데스크톱 편집기를 Resizing 것은 모바일 플러그인으로 전환하지 않습니다.

`UniverMobileUIPlugin`는 `disableAutoFocus: true`에 기본적으로, 그래서 편집기는 초기화 도중 자동적으로 집중하지 않습니다.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## 프리셋 모드로 설정하기

미리 설치된 형태는 부호의 20의 선 보다는 더 적은을 가진 Univer Docs 신청을 시작합니다.

### 패키지 관리자 사용

이미 프로젝트가 현대 프런트 엔드 툴링을 사용하는 경우 Univer를 바로 추가하십시오. Univer 응용 프로그램을 빌드하면 [뚱 베어](https://vitejs.dev/), [esbuild의](https://esbuild.github.io/) 또는 [웹팩 5](https://webpack.js.org/)와 같은 ES 모듈을 지원하는 도구가 있습니다. 다른 도구, Webpack 4 인스턴스에는 추가 구성이 필요할 수 있습니다.

#### 설치

프로젝트에서 사용되는 패키지 관리자가있는 `@univerjs/presets` 설치 :

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### 사용법

<Callout type="warning">
  빌드 도구가 패키지에 `exports` 필드를 지원하지 않는 경우.json (Webpack 4)에서 데모, 맵핑 경로는 수동으로 실제 경로로 변경해야합니다.
</Callout>

다음 코드는 Univer Docs 응용 프로그램을 시작합니다.

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

반환된 `univerAPI` 객체는 Univer Facade API이며 Univer가 제공하는 기능의 대부분이 그것을 통해 호출됩니다.

#### `createUniver` 메서드

`createUniver`는 언어, 테마 및 플러그인을 포함하여 인스턴스를 설명하는 구성 객체를 허용합니다. Univer 인스턴스와 Facade API 예를 들어 포함 된 객체를 반환합니다.

가장 일반적으로 사용되는 속성은 다음과 같습니다.

- `locale`: 언어 환경, `LocaleType` enumeration 값으로.
- `locales`: 언어 팩, 언어 환경에 의해 키 입력, 언어 팩 개체를 각 값.
- `theme`: 옵션 테마 객체.
- `presets`: `UniverDocsCorePreset`와 같은 등록하는 미리 설치.
- `plugins`: 플러그인은 사전 설정에 추가.

`plugins` 속성을 사용하여 미리 설정 패키지가 포함되지 않은 플러그인 또는 응용 프로그램에 의해 구현 된 플러그인. 플러그인은 `univer.registerPlugin` 후 Univer 인스턴스를 등록 할 수 있습니다.

<Callout>
  [API 참조 / createUniver](https://docs.univer.ai/reference/methods/create-univer) 옵션의 완전한 세트를 참조하십시오.
</Callout>

### CDN에서 가져오기

패키지 관리자를 피하거나 Univer를 신속하게 평가하려면 리소스가 CDN에서로드 될 수 있습니다. [CDN을 통해 Univer 사용](/guides/docs/getting-started/installation/cdn#plugin-mode)을 참조하십시오.

## 기타 릴리스

안정적인 출시 외에도 Univer는 알파 / 베타 및 야간 채널을 게시하여 공식적으로 출시되지 않은 기능을 초기 액세스 할 수 있습니다. 또한 더 많은 기능을 수행 할 수도 있습니다. 이 빌드는 버그, 불완전한 기능 또는 불안정한 기능을 포함 할 수 있습니다. 가능한 생산 환경에서 그들을 피하십시오.

### Alpha / Beta 릴리스

Univer 개발 팀은 새로운 기능 또는 중요한 변경을 완료하면 알파 또는 베타 채널에 패키지를 미리 릴리스 할 수 있습니다. 다음 명령으로 알파 또는 베타 빌드를 설치하십시오.

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

사전 릴리스와 관련된 문제 및 피드백은 [GitHub 문제](https://github.com/dream-num/univer/issues)를 통해 개발 팀에보고 될 수 있습니다. 이러한 초기 빌드에 대한 피드백은 환영합니다.

[^facade-entry]: Facade는 등록된 플러그인의 기능을 애플리케이션에서 사용하는 API입니다. Facade 진입점을 가져오면 API 메서드가 추가되지만 기능 플러그인 자체가 등록되지는 않습니다.

[^peer-dependency]: `peerDependencies`는 호스트 프로젝트가 호환되는 버전으로 제공해야 하는 의존성입니다. 이를 통해 Univer와 애플리케이션이 React 같은 라이브러리를 공유합니다.

[^mobile-ui-mode]: 모바일 UI 플러그인은 초기화할 때 터치 컨트롤과 모바일 서비스를 선택합니다. 기기를 자동 감지하거나 창 크기 변경 시 기존 인스턴스의 모드를 바꾸지 않습니다. 모드를 변경하려면 문서 상태를 보존하고 기존 인스턴스를 폐기한 뒤 선택한 플러그인 조합으로 초기화하세요.
