title: Installation et utilisation de base
---

Univer est construit à partir de plugins. Chaque fonctionnalité est livrée comme un module séparé, de sorte que le même noyau peut être assemblé en applications de documents électroniques de très différents types. Cette flexibilité porte également un coût: en première utilisation, une application doit déterminer quels plugins il a besoin.

Univer fournit donc deux façons de l'intégrer : **mode plugin** et **mode préréglé**. Un **préréglé** est un paquet de plugins déjà configurés. Sans extensions complexes, les deux modes fournissent les mêmes capacités.

<Callout type="warning" title="Attention">
  - Dans les deux modes, chaque dépendance doit utiliser le même numéro de version.
  - Si un preset inclut déjà un plugin, n'importez pas ce plugin séparément. Enregistrer les deux peut causer des conflits de plugin ou des fonctionnalités qui ne se comportent pas comme prévu.
</Callout>

Les deux modes diffèrent comme suit:

| Mode plugin | Mode prédéfini |
| --- | --- |
| Les paquets Facade sont importés manuellement | Les paquets Facade sont fournis par le preset |
| L'ordre d'inscription doit être géré pour les plugins qui fournissent le même type de fonctionnalité | Le preset gère l'ordre d'enregistrement pour les fonctionnalités qu'il inclut |
| Les greffons peuvent être chargés paresseux sur demande | Charge de préréglage synchrone pendant l'initialisation |

Pour **personnalisation profonde ou extensions**, choisissez le mode plugin, dans lequel chaque plugin est combiné et configuré individuellement. Le mode Preset permet un démarrage plus rapide car le paquet est déjà assemblé.

## Configuration en mode plugin

Univer fournit ses fonctionnalités en tant que plugins. Certains plugins de base sont nécessaires pour que le produit fonctionne, et les plugins restants ne sont ajoutés que lorsque nécessaire. L'exemple ci-dessous est une application Univer Docs minimale, assemblé et installé plugin par plugin.

Contrairement au mode préréglé, le mode plugin n'inclut pas le Facade API[^facade-entry] par défaut. Les exemples ci-dessous utilisent le Facade API, donc importez les paquets de façades correspondants avant de créer l'instance API.

### Utilisation d’un gestionnaire de packages

#### Installation

Univer rend son interface avec React et traite ses flux de données avec RxJS; il peut également être intégré dans un Vue ou Angular s'assurer que les `react`, `react-dom`et `rxjs` dépendances des pairs[^peer-dependency] sont installés. La commande Yarn ci-dessous les inclut explicitement.

Tous les paquets `@univerjs/*` et `@univerjs-pro/*` doivent utiliser **la même version**.

#### Utilisation

Créer le conteneur avec une hauteur explicite avant d'initialiser Univer:

```html
<div id="app" style="height: 600px"></div>
```

Importez les entrées de façade utilisées par les exemples avant d'appeler `FUniver.newAPI(univer)`. Chargez les styles dans l'ordre `@univerjs/design`, `@univerjs/ui` puis le produit CSS.

<Callout type="warning" title="Attention">
  - Chaque plugin n'inclut pas les paquets de façade, les paquets de langage et les fichiers de style; la documentation pour chaque état de fonctionnalité qu'il fournit.
  - L'ordre des importations de style est important : charger les CSS `@univerjs/design` et `@univerjs/ui` avant les styles de tout autre plugin.
</Callout>

<Steps>
  <Step>
    Tout d'abord, importez les fichiers de style, les paquets de langues et les plugins de Univer.

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Ensuite, importez les paquets de façade utilisés par l'exemple:

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    Ensuite, créez une instance Univer et enregistrez ces plugins :

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

#### Méthodes `univer.registerPlugin` et `univer.registerPlugins` [#registerPlugin]

`univer.registerPlugin` enregistre un plugin sur l'instance Univer et doit être appelé après la création de l'instance.

La signature est `univer.registerPlugin(Plugin, options)`, où `Plugin` est le plugin à enregistrer et `options` la configuration optionnelle définie par chaque plugin.

Pour enregistrer plusieurs plugins à la fois, passez un tableau à `univer.registerPlugins`. Ceci est pratique lorsque les plugins sont gérés en un seul endroit.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### Chargement différé des plugins

Le mode Plugin permet de contrôler le temps de chargement de chaque plugin. Une approche commune charge uniquement les plugins essentiels au démarrage de l'application et reporte les plugins restants jusqu'à ce que le premier rendu soit terminé.

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

## Prise en charge mobile [#mobile-support]

<Callout type="warning">
  Ces exemples nécessitent des paquets SDK exportant les plugins mobiles ci-dessous. Gardez toutes les dépendances `@univerjs/*` et `@univerjs-pro/*` à **la même version**.

  `1.0.0-rc.0` n'exporte pas `UniverDocsMobileUIPlugin`; utilisez une compilation qui inclut cette entrée mobile avant d'exécuter l'exemple.
</Callout>

Pour les commandes tactiles dans Univer Docs, enregistrez le **plugins d'interface utilisateur mobiles**.[^mobile-ui-mode] Le mode UI doit être choisi avant la création de l'éditeur.

Dans l'exemple de mode plugin ci-dessus, **remplacer** l'interface utilisateur importe et enregistre ci-dessous, et le faire avant `createUnit()`; ne pas les ajouter à un éditeur de bureau qui a déjà été initialisé. Gardez les modèles plugins, moteurs, fichiers locaux, CSS, et Facade importations inchangées. Les classes de bureau et mobile sont nommées exportations de la **même entrée du colis**.

`UniverMobileUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Élément DOM de montage de l’éditeur ou son identifiant. |
| `disableAutoFocus` | `true` | `true` | Empêche l’éditeur de prendre le focus au démarrage. |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
```

`UniverSheetsCorePreset` et `UniverDocsCorePreset` enregistrent actuellement des plugins d'interface utilisateur de bureau et ne fournissent pas d'option `mobile: true`. Sur mobile, les plugins doivent être assemblés individuellement; l'ajout de plugins mobiles après un préréglage de bureau ne remplace pas son interface utilisateur.

### Conteneur et interactions tactiles

Réglez une hauteur explicite sur le conteneur et configurez le port de vue de la page. `100dvh` suit la hauteur de port de vue dynamique. Dans les navigateurs mobiles cibles, test scrolling, pincez zoom, sélection de texte, accès au presse-papiers et clavier à l'écran.

`UniverMobileUIPlugin` par défaut sur `disableAutoFocus: true`, de sorte que l'éditeur ne se concentre pas automatiquement pendant l'initialisation.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Configurer Web SDK en mode prédéfini

Le mode préréglé démarre une application Univer Docs avec moins de vingt lignes de code.

### Utiliser un gestionnaire de paquets

Si le projet utilise déjà l'outillage frontal moderne, l'ajout de Univer est simple. Construisez des applications Univer avec un outil qui supporte bien les modules ES, tels que [Vit](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) ou [Emballage Web 5](https://webpack.js.org/). D'autres outils, Webpack 4 par exemple, peuvent nécessiter une configuration supplémentaire.

#### Installation

Installez `@univerjs/presets` avec le gestionnaire de paquets utilisé par le projet :

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### Utilisation

<Callout type="warning">
  Si l'outil build ne prend pas en charge le champ `exports` dans paquet.json (commun dans Webpack 4), les chemins mappés doivent être modifiés manuellement pour les chemins réels.
</Callout>

Le code suivant démarre une application de Docs Univer :

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

L'objet `univerAPI` retourné est le Univer Facade API, et la plupart des fonctionnalités fournies par Univer sont appelées par lui.

#### Méthode `createUniver`

`createUniver` accepte un objet de configuration qui décrit l'instance, y compris la langue, le thème et les plugins. Il retourne un objet qui contient l'instance Univer et l'instance de Facade API.

Les propriétés les plus couramment utilisées sont:

- `locale` : l'environnement de langage, comme valeur de dénombrement `LocaleType`.
- `locales`: paquets de langues, clé par environnement de langue, chaque valeur d'un objet de paquet de langues.
- `theme` : objet de thème optionnel.
- `presets` : les préréglages à enregistrer, tels que `UniverDocsCorePreset`.
- `plugins`: plugins à enregistrer en plus des presets.

Utilisez la propriété `plugins` pour un plugin qu'aucun paquet prédéfini n'inclut, ou pour un plugin implémenté par l'application. Les plugins peuvent également être enregistrés avec `univer.registerPlugin` après l'obtention de l'instance Univer.

<Callout>
  Voir [API Référence / createUnivers](https://docs.univer.ai/reference/methods/create-univer) pour l'ensemble complet des options.
</Callout>

## Autres versions

Outre les versions stables, Univer publie des canaux alpha / bêta et des canaux nocturnes, qui permettent un accès précoce à des fonctionnalités qui n'ont pas été publiées officiellement. D'autres fonctionnalités comportent également plus de risques : ces constructions peuvent contenir des bogues, des fonctionnalités incomplètes ou des fonctionnalités instables.

### Version alpha / beta

Lorsque l'équipe de développement Univer complète une nouvelle fonctionnalité ou un changement significatif, elle peut pré-libérer le paquet sur le canal alpha ou bêta. Installez une construction alpha ou bêta avec la commande suivante :

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Les problèmes et la rétroaction liés à une pré-libération peuvent être signalés à l'équipe de développement par l'intermédiaire de [GitHub Problèmes](https://github.com/dream-num/univer/issues). La rétroaction sur ces premières constructions est bienvenue.

[^facade-entry]: Facade est l’API applicative des plugins enregistrés. Importer une entrée Facade ajoute des méthodes API, mais n’enregistre pas le plugin fonctionnel lui-même.

[^peer-dependency]: Les `peerDependencies` sont des dépendances que l’application hôte doit fournir dans une version compatible. Elles permettent de partager des bibliothèques comme React avec Univer.

[^mobile-ui-mode]: Un plugin UI mobile sélectionne les commandes tactiles et les services mobiles à l’initialisation. Il ne détecte pas automatiquement l’appareil et ne change pas le mode d’une instance lors du redimensionnement. Pour changer de mode, conservez l’état du document, détruisez l’ancienne instance et initialisez les plugins choisis.
