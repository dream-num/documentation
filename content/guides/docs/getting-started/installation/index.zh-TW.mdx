title: 安裝與基本使用
---

本文介紹 Univer Docs 的安裝和基本使用，以及預設模式與外掛模式各自的配置方式。如果對 Univer 的基礎術語或這兩種模式的區別還不熟悉，建議先閱讀[基本概念](/guides/docs/getting-started/quickstart#basic-concepts)。

Univer 提供兩種接入方式：*預設模式*和*外掛模式*。預設模式以打包形式提供一組預先配置好的外掛，配置量較少，接入更快；如果需要**深度定製或擴充套件**，則應使用外掛模式，由開發者自行組合和配置外掛。

## 透過外掛模式建立

Univer 的功能都以外掛形式提供。除產品必需的核心外掛外，其餘外掛按需引入。下面以一個最基礎的 Univer Docs 應用為例，說明如何手動挑選並註冊外掛。

與預設模式不同，外掛模式預設不包含 Facade API[^facade-entry]。下面的範例會使用 Facade API，因此需要在建立 API 例項之前引入對應的 facade 包。

### 使用套件管理器

#### 安裝

Univer 的介面使用 React 建置，資料流使用 RxJS 處理，也可以嵌入 Vue 或 Angular 應用。請確認 `react`、`react-dom` 和 `rxjs` 這幾個 peer dependencies[^peer-dependency] 已經安裝，下面的 Yarn 命令已顯式包含它們。

所有 `@univerjs/*` 和 `@univerjs-pro/*` 包必須保持**相同版本**。

<InstallTabs
  packages="@univerjs/core @univerjs/design @univerjs/docs @univerjs/docs-ui @univerjs/engine-formula @univerjs/engine-render @univerjs/ui"

#### 使用

初始化 Univer 之前，先建立容器並設定明確的高度：

```html
<div id="app" style="height: 600px"></div>
```

呼叫 `FUniver.newAPI(univer)` 之前，先引入下面範例用到的 facade 入口。樣式檔案按 `@univerjs/design`、`@univerjs/ui`、產品樣式的順序引入。

<Callout type="warning" title="注意事項">
  - 並非每個外掛都包含 facade 包、語言套件和樣式檔案，具體包含哪些，各功能的文件中會說明。
  - 樣式檔案的引入順序很重要：先引入 `@univerjs/design`、`@univerjs/ui` 的 CSS，再引入其他外掛的樣式。
</Callout>

<Steps>
  <Step>
    首先，在專案中引入 Univer 的樣式檔案、語言套件以及應用所需的外掛：

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignZhTW from '@univerjs/design/locale/zh-TW'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIZhTW from '@univerjs/docs-ui/locale/zh-TW'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIZhTW from '@univerjs/ui/locale/zh-TW'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    然後，引入範例用到的 facade 包：

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    最後，建立一個 Univer 例項並註冊這些外掛：

    ```typescript
    const univer = new Univer({
      locale: LocaleType.ZH_TW,
      locales: {
        [LocaleType.ZH_TW]: mergeLocales(
          DesignZhTW,
          UIZhTW,
          DocsUIZhTW,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |

#### `univer.registerPlugin` 與 `univer.registerPlugins` 方法 [#registerPlugin]

`univer.registerPlugin` 用於將單個外掛註冊到 Univer 例項上，需要在例項建立完成後呼叫。

簽名是 `univer.registerPlugin(Plugin, options)`，其中 `Plugin` 是要註冊的外掛，`options` 是可選配置，由各外掛自行定義。

需要一次註冊多個外掛時，可向 `univer.registerPlugins` 傳入一個陣列。集中管理外掛時，這種方式更為方便。

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### 懶載入部分外掛

外掛模式的一個優勢在於可以控制外掛的載入時機。常見做法是在應用初始化時只載入必需的外掛，其餘外掛延遲到首次渲染完成之後再載入。

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

## 行動裝置支援 [#mobile-support]

<Callout type="warning">
  下面範例要求所安裝的 SDK 包包含列出的行動版匯出。所有 `@univerjs/*` 和 `@univerjs-pro/*` 依賴必須保持**相同版本**。

  `1.0.0-rc.0` 尚未匯出 `UniverDocsMobileUIPlugin`，執行範例前請改用包含該行動版入口的建置版本。
</Callout>

在 Univer Docs 中使用觸控操作介面，需要註冊**行動版 UI 外掛**。[^mobile-ui-mode] UI 模式必須在建立編輯器之前確定。

在上方外掛模式的範例中，**替換**下面這些 UI 匯入和註冊，且必須在 `createUnit()` 之前完成；已經初始化的桌面版編輯器不能再追加行動版外掛。模型外掛、引擎、語言套件、CSS 和 Facade 的匯入保持不變。桌面版和行動版的類都是**同一套件入口**的具名匯出。

`UniverMobileUIPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | 用於掛載編輯器的元素或其 DOM ID。 |
| `disableAutoFocus` | `true` | `true` | 防止編輯器在啟動時自動取得焦點。 |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
```

目前 `UniverSheetsCorePreset` 和 `UniverDocsCorePreset` 註冊的都是桌面版 UI 外掛，也不提供 `mobile: true` 選項。行動版需要自行組合外掛；在桌面版預設之後再追加行動版外掛，原有 UI 不會被替換。

### 容器與觸控互動

容器需要設定明確的高度，頁面還需要配置 viewport。`100dvh` 會隨動態視口高度變化。在目標移動瀏覽器中，需要實際測試滾動、雙指縮放、文字選擇、剪貼簿訪問和軟鍵盤。僅縮小桌面版編輯器不會切換到行動版外掛。

`UniverMobileUIPlugin` 預設使用 `disableAutoFocus: true`，編輯器在初始化時不會自動取得焦點。

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## 透過預設模式建立

使用預設模式時，不到二十行程式碼即可建置一個 Univer Docs 應用。

### 使用包管理器

如果專案已經在使用現代前端工具，接入 Univer 的過程較為簡單。建議使用對 ES Module 支援較好的建置工具，例如 [Vite](https://vitejs.dev/)、[esbuild](https://esbuild.github.io/) 或 [Webpack 5](https://webpack.js.org/)。如果使用其他工具（例如 Webpack 4），可能需要額外的配置。

#### 安裝

使用專案所用的包管理器安裝 `@univerjs/presets`：

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### 使用

<Callout type="warning">
  如果建置工具不支援 package.json 的 `exports` 欄位（在 Webpack 4 中較為常見），需要手動將對映路徑改為實際路徑。
</Callout>

下面的程式碼即可建立一個 Univer Docs 應用：

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreZhTW from '@univerjs/preset-docs-core/locales/zh-TW'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.ZH_TW,
  locales: {
    [LocaleType.ZH_TW]: mergeLocales(
      UniverPresetDocsCoreZhTW,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

此處返回的 `univerAPI` 物件即 Univer 的 Facade API，Univer 提供的大部分功能都透過它呼叫。

#### `createUniver` 方法

`createUniver` 接收一個描述例項的配置物件，其中包括語言、主題和外掛等。它返回的物件包含 Univer 例項和 Facade API 例項。

配置物件上常用的屬性如下：

- `locale`：語言環境，取 `LocaleType` 的列舉值。
- `locales`：語言套件物件，鍵是語言環境，值是對應的語言套件。
- `theme`：主題物件，可選。
- `presets`：要註冊的預設套件陣列，例如 `UniverDocsCorePreset`。
- `plugins`：需要額外註冊的外掛陣列。

如果某個外掛不屬於任何預設套件，或者是自行實現的外掛，可以透過 `plugins` 屬性註冊。也可以在獲得 Univer 例項之後，透過 `univer.registerPlugin` 註冊外掛。

<Callout>
  `createUniver` 的完整參數說明見 [API Reference / createUniver](https://docs.univer.ai/reference/methods/create-univer)。
</Callout>

## 其他發佈版本

除穩定版外，Univer 還提供 alpha / beta 和 nightly 通道，尚未正式釋出的新功能會先出現在這些通道中。功能更多也意味著風險更高：這些版本可能存在 bug，功能不完整，或者尚不穩定。生產環境中應儘量避免使用。

### Alpha / Beta 版本

當 Univer 開發團隊完成一個新功能或一項較大改動時，可能會將該包預釋出到 alpha 或 beta 通道。安裝 alpha / beta 版本的 Univer 包使用以下命令：

```package-install
npm install @univerjs/<package-name>@alpha # Alpha 版本
npm install @univerjs/<package-name>@beta # Beta 版本
```

使用 alpha / beta 版本時遇到的問題或相關反饋，可以透過 [GitHub Issues](https://github.com/dream-num/univer/issues) 提交給 Univer 開發團隊。歡迎提供關於這些早期版本的反饋。

[^facade-entry]: Facade 是面向應用程式的 API，封裝已註冊外掛的能力。匯入 Facade 入口會擴充 API 方法，但不會取代功能外掛的註冊。

[^peer-dependency]: `peerDependencies` 表示需要由宿主專案提供相容版本的相依套件，讓 Univer 與應用程式共用 React 等函式庫，而不是各自攜帶一份。

[^mobile-ui-mode]: 行動版 UI 外掛在初始化時選擇觸控元件與行動版服務，不會自動判斷裝置，也不會在視窗大小改變時切換既有實例。如需切換模式，請先保留文件狀態、銷毀舊實例，再以選定的外掛組合初始化。
