title: Установка и основы использования
---

Univer построен из плагинов. Каждая функция поставляется в виде отдельного модуля, поэтому одно и то же ядро может быть собрано в приложения для электронных документов самых разных типов. Эта гибкость также несет в себе стоимость: при первом использовании приложение должно определить, какие плагины ему нужны.

Поэтому Univer предоставляет два способа его интеграции: **режим плагинов** и **заданный режим**. A **предустановленный** - это набор плагинов, который уже был настроен. Без сложных расширений оба режима обеспечивают одинаковые возможности.

<Callout type="warning" title="Внимание">
  - В обоих режимах каждая зависимость должна использовать один и тот же номер версии.
  - Если предустановка уже включает плагин, не импортируйте этот плагин отдельно. Регистрация обоих может вызвать конфликты плагинов или функции, которые ведут себя не так, как ожидалось.
</Callout>

Эти два режима различаются следующим образом:

| Режим плагинов | Режим пресетов |
| --- | --- |
| Фасадные пакеты импортируются вручную | Фасадные пакеты предоставляются заданным |
| Заказ на регистрацию должен управляться для плагинов, которые предоставляют ту же функцию. | Предустановленный управляет заказом на регистрацию для функций, которые он включает |
| Плагины могут быть ленивыми по требованию | Предустановки загружаются синхронно во время инициализации |

Для **Глубокая настройка или расширения** выберите режим плагина, в котором каждый плагин объединен и настроен индивидуально.Предустановленный режим обеспечивает более быстрый запуск, поскольку пакет уже собран.

## Настройка в режиме плагинов

Univer предоставляет свои функции в качестве плагинов. Некоторые основные плагины необходимы для функционирования продукта, а остальные плагины добавляются только при необходимости. Примером ниже является минимальное приложение Univer Docs, собранное и установленное плагином через плагин.

В отличие от предустановленного режима, режим плагина по умолчанию не включает Facade API[^facade-entry].Приведенные ниже примеры используют Facade API, поэтому перед созданием экземпляра API импортируйте соответствующие пакеты фасадов.

### Использование менеджера пакетов

#### Установка

Univer осуществляет рендеринг своего интерфейса с React и обрабатывает свои потоки данных с помощью RxJS; он также может быть встроен в приложение Vue или Angular. Убедитесь, что установлены одноранговые зависимости `react`, `react-dom` а также `rxjs` [^peer-dependency] Команда Yarn ниже включает их явно.

Все пакеты `@univerjs/*` и `@univerjs-pro/*` должны использовать **той же версии**.

#### Использование

Создайте контейнер с явной высотой перед инициализацией Univer:

```html
<div id="app" style="height: 600px"></div>
```

Импортировать фасадные записи, используемые примерами, прежде чем звонить `FUniver.newAPI(univer)`. Загрузить стили в порядке `@univerjs/design`, `@univerjs/ui` и далее продукт CSS.

<Callout type="warning" title="Внимание">
  - Не каждый плагин включает в себя пакеты фасадов, языковые пакеты и файлы стилей; документация для каждой функции указывает, какую из них она предоставляет.
  - Порядок импорта стилей имеет значение: загрузите `@univerjs/design` и `@univerjs/ui` CSS перед стилями любого другого плагина.
</Callout>

<Steps>
  <Step>
    Во-первых, импортируйте файлы стилей Univer, языковые пакеты и плагины, необходимые для приложения:

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Далее импортируйте фасадные пакеты, используемые на примере:

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    Затем создайте экземпляр Univer и зарегистрируйте эти плагины:

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

#### Методы `univer.registerPlugin` и `univer.registerPlugins` [#registerPlugin]

`univer.registerPlugin` регистрирует один плагин на экземпляре Univer и должен быть вызван после создания экземпляра.

Подпись `univer.registerPlugin(Plugin, options)`, где `Plugin` является плагином для регистрации, и `options` - это дополнительная конфигурация, определяемая каждым плагином.

Для регистрации сразу нескольких плагинов передайте массив в `univer.registerPlugins`. Это удобно, когда плагины управляются в одном месте.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### Ленивая загрузка плагинов

Режим плагина позволяет контролировать время загрузки каждого плагина.Обычный подход загружает только необходимые плагины при запуске приложения и откладывает оставшиеся плагины до завершения первого рендеринга.

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

## Поддержка мобильных устройств [#mobile-support]

<Callout type="warning">
  Для примеров нужны пакеты SDK, экспортирующие перечисленные мобильные плагины. Все зависимости `@univerjs/*` и `@univerjs-pro/*` должны иметь **одинаковую версию**.

  `1.0.0-rc.0` не экспортирует `UniverDocsMobileUIPlugin`; используйте сборку, которая включает эту мобильную запись, перед запуском примера.
</Callout>

Для сенсорного управления в Univer Docs необходимо зарегистрировать **Мобильные плагины UI**.[^mobile-ui-mode] Режим пользовательского интерфейса должен быть выбран до создания редактора.

В примере с плагин-режимом, приведенном выше, **заменить** импортирует и регистрирует пользовательский интерфейс ниже, и делает это до `createUnit()`; не добавляйте их в редактор рабочего стола, который уже был инициализирован. Держите плагины модели, движки, локальные файлы, CSS и Facade импорт неизменным. Классы рабочего стола и мобильных устройств называются экспортом из **та же самая упаковка**.

`UniverMobileUIPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | DOM-элемент для размещения редактора или его идентификатор. |
| `disableAutoFocus` | `true` | `true` | Отключает автоматический фокус редактора при запуске. |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
```

`UniverSheetsCorePreset` и `UniverDocsCorePreset` в настоящее время регистрируют плагины пользовательского интерфейса рабочего стола и не предоставляют опцию `mobile: true`. На мобильном телефоне плагины должны собираться индивидуально; добавление мобильных плагинов после предустановки рабочего стола не заменяет его пользовательский интерфейс.

### Контейнер и сенсорное управление

Установите явную высоту на контейнере и настройте видопорт страницы. `100dvh` следует за динамической высотой видопорта. В целевых мобильных браузерах тестовая прокрутка, щипковый зум, выбор текста, доступ к буферу обмена и экранная клавиатура. Изменение размера редактора рабочего стола не переключает его на мобильные плагины.

`UniverMobileUIPlugin` по умолчанию выполняется `disableAutoFocus: true`, поэтому редактор не фокусируется автоматически во время инициализации.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Настройка в режиме пресетов

Запускается приложение Univer Docs с менее чем двадцатью строками кода.

### С помощью менеджера пакетов

Если в проекте уже используется современный интерфейсный инструментарий, добавление Univer является простым.Создайте приложения Univer с помощью инструмента, который хорошо поддерживает модули ES, такие как [Вкусно](https://vitejs.dev/), [строить](https://esbuild.github.io/) или [Webpack 5](https://webpack.js.org/). Другие инструменты, например, Webpack 4, могут потребовать дополнительной конфигурации.

#### Установка

Установите `@univerjs/presets` с помощью менеджера пакетов, используемого в проекте:

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### Использование

<Callout type="warning">
  Если инструмент сборки не поддерживает поле `exports` в package.json (обычное в Webpack 4), отображенные пути должны быть изменены на фактические пути вручную.
</Callout>

Следующий код запускает приложение Univer Docs:

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

Возвращенный объект `univerAPI` — Univer Facade API, и большая часть функциональности, которую предоставляет Univer называется через него.

#### Метод `createUniver`

`createUniver` принимает объект конфигурации, который описывает экземпляр, включая язык, тему и плагины. Он возвращает объект, который содержит экземпляр Univer и экземпляр Facade API.

Наиболее часто используемыми свойствами являются:

- `locale`: языковая среда, как значение переписи `LocaleType`.
- `locales`: языковые пакеты, включаемые в языковую среду, каждый из которых представляет собой объект языкового пакета.
- `theme`: дополнительный объект темы.
- `presets`: предустановки для регистрации, такие как `UniverDocsCorePreset`.
- `plugins`: плагины для регистрации в дополнение к предустановкам.

Используйте свойство `plugins` для плагина, который не содержит предустановленного пакета, или для плагина реализованного приложением. Плагины также могут быть зарегистрированы в `univer.registerPlugin` после получения экземпляра Univer.

<Callout>
  [Ссылка на API / CreateUniver](https://docs.univer.ai/reference/methods/create-univer) для полного набора опций.
</Callout>

## Другие каналы выпуска

Наряду со стабильными релизами Univer публикует альфа/бета и ночные каналы, которые обеспечивают ранний доступ к функциям, которые не были официально выпущены.Больше функций также несут больший риск: эти сборки могут содержать ошибки, неполную функциональность или нестабильные функции. Избегайте их в производственных средах, где это возможно.

### Выпуски Alpha / Beta

Когда команда разработчиков Univer завершает новую функцию или существенное изменение, она может предварительно выпустить пакет на альфа- или бета-канал. Установите альфа-или бета-сборку со следующей командой:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Проблемы и отзывы, связанные с предварительным выпуском, могут быть сообщены команде разработчиков через [Обсуждение GitHub](https://github.com/dream-num/univer/issues).

[^facade-entry]: Facade — прикладной API зарегистрированных плагинов. Импорт точки входа Facade добавляет методы API, но не регистрирует сам функциональный плагин.

[^peer-dependency]: `peerDependencies` — зависимости, совместимые версии которых предоставляет основное приложение. Это позволяет Univer и приложению использовать общую копию библиотек, например React.

[^mobile-ui-mode]: Мобильный UI-плагин выбирает сенсорные элементы управления и мобильные сервисы при инициализации. Он не определяет устройство автоматически и не переключает существующий экземпляр при изменении размера окна. Чтобы сменить режим, сохраните состояние документа, уничтожьте старый экземпляр и инициализируйте выбранный набор плагинов.
