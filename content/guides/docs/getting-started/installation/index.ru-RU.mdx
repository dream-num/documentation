title: Установка и основы использования
---

В основе архитектуры Univer лежит система плагинов. Она предоставляет разработчикам гибкий и расширяемый фреймворк для приложений, работающих с электронными документами. Благодаря такой архитектуре в Univer легко интегрировать различные функциональные модули под потребности разных пользователей. Однако она также усложняет приложение, особенно для разработчиков, которые только начинают знакомство с Univer.

Чтобы упростить быструю интеграцию и начало работы с Univer, предусмотрено два варианта: **режим плагинов** и **режим пресетов**. **Пресет** представляет собой набор предварительно настроенных плагинов, поэтому без сложных расширений оба режима предоставляют одинаковые возможности.

<Callout type="warning" title="Внимание">
  - **Одинаковые версии зависимостей**: независимо от того, используете вы режим пресетов или плагинов, версии всех зависимостей должны совпадать.
  - **Осторожно сочетайте плагины и пресеты**: если плагин уже входит в пресет, при использовании этого пресета не нужно импортировать плагин отдельно. Иначе возможны конфликты плагинов или некорректная работа функций.
</Callout>

Различия между режимами пресетов и плагинов:

| Режим плагинов | Режим пресетов |
| --- | --- |
| Соответствующие пакеты Facade API нужно импортировать вручную | Пакеты Facade API не нужно импортировать вручную |
| Необходимо учитывать порядок регистрации плагинов с одинаковой функциональностью | Не нужно учитывать порядок регистрации функций, входящих в пресеты |
| Поддерживается ленивая загрузка отдельных плагинов | Поддерживается только ленивая загрузка на уровне пресетов; плагины внутри пресета загружаются только синхронно |

## Настройка в режиме пресетов

Ниже показано, как менее чем за двадцать строк кода быстро создать приложение Univer Docs.

### С помощью менеджера пакетов

Если в вашем проекте уже используются современные инструменты фронтенд-разработки, интегрировать Univer будет очень просто. Для сборки приложений Univer рекомендуем инструменты с хорошей поддержкой ES Modules, например [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) или [Webpack 5](https://webpack.js.org/). Для других инструментов сборки, например Webpack 4, может потребоваться дополнительная настройка.

#### Установка

Установите `@unvierjs/presets` с помощью выбранного менеджера пакетов:

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### Использование

<Callout type="warning">
  Если ваш инструмент сборки не поддерживает поле `exports` в package.json, как это часто бывает с Webpack 4, необходимо вручную заменить сопоставленные пути фактическими.
</Callout>

Следующий код запускает приложение Univer Docs:

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-docs-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS,
    ),
  },
  presets: [
    UniverDocsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createDocument({})
```

Возвращаемый объект `univerAPI` называется Univer Facade API. Через него можно обращаться ко многим функциям Univer.

<Callout type="warning">

</Callout>

#### Метод `createUniver`

Метод `createUniver` принимает объект с настройками Univer, например языком, темой и плагинами. Он возвращает объект, содержащий экземпляр Univer и экземпляр Univer Facade API.

Некоторые свойства объекта конфигурации:

- `locale`: языковая среда; может быть значением перечисления `LocaleType`.
- `locales`: объект локалей, в котором ключом служит языковая среда, а значением — объект языкового пакета.
- `theme`: необязательный объект темы.
- `presets`: массив регистрируемых пресетов, например `UniverDocsCorePreset`.
- `plugins`: массив дополнительных регистрируемых плагинов.

Плагины, которые не входят ни в один пакет пресета, а также собственные плагины можно зарегистрировать через свойство `plugins`. Кроме того, после получения экземпляра Univer плагины можно регистрировать методом `univer.registerPlugin`.

<Callout>
  Подробнее о методе `createUniver` см. в [справочнике API: createUniver](https://docs.univer.ai/reference/methods/create-univer).
</Callout>

## Настройка в режиме плагинов

Возможности Univer предоставляются в виде набора плагинов. Помимо основных плагинов, необходимых для работы продукта, вы можете подключать другие по мере необходимости. Ниже на примере простейшего приложения Univer Docs показано, как вручную подобрать и установить плагины.

В отличие от режима пресетов, в режиме плагинов Facade API по умолчанию не подключается. В примерах ниже используется Facade API, поэтому перед созданием его экземпляра импортируйте соответствующие пакеты.

### С помощью менеджера пакетов

#### Установка

Для разработки представления мы используем React (это не мешает использовать Univer во Vue или Angular), а для обработки потоков данных — Rxjs. Поскольку обе библиотеки широко применяются в современной фронтенд-разработке, мы указываем их как peerDependencies. Разные менеджеры пакетов работают с peerDependencies по-разному, поэтому важно учитывать несколько особенностей.

<Callout>
  - Если вы используете npm, убедитесь, что установлена версия npm@7 или новее. Версии npm@3 ~ npm@6 некорректно устанавливают `peerDependencies`[^1].
  - Если вы используете pnpm, убедитесь, что установлена версия pnpm@8 или новее. Для pnpm@6 ~ pnpm@7 можно попробовать задать параметр `auto-install-peers=true` [^2], чтобы устранить проблемы с установкой зависимостей.
  - При использовании yarn отсутствующие `peerDependencies`[^3] нужно устанавливать вручную; они уже включены в приведённые ниже команды.
</Callout>

#### Использование

<Callout type="warning" title="Внимание">
  - Пакеты Facade API, языковые пакеты и файлы стилей есть не у всех плагинов. Это указывается в документации каждой функции.
  - Порядок импорта файлов стилей имеет значение. Импортируйте CSS-стили `@univerjs/design` и `@univerjs/ui` перед стилями остальных плагинов.
</Callout>

<Steps>
  <Step>
    Импортируйте в проект файлы стилей Univer, языковые пакеты и необходимые плагины:

    ```typescript
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Импортируйте пакеты Facade API, используемые в примере:

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs/facade'
    import '@univerjs/docs-ui/facade'
    ```
  </Step>
  <Step>
    Затем создайте экземпляр Univer и зарегистрируйте плагины:

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)

    univerAPI.createDocument({})
    ```
  </Step>
</Steps>

#### Метод `univer.registerPlugin`

Метод ``univer.registerPlugin` используется для регистрации плагина в экземпляре Univer. После создания экземпляра Univer можно вызвать этот метод и зарегистрировать плагины.

Плагин регистрируется методом `univer.registerPlugin(Plugin, options)`, где `Plugin` — регистрируемый плагин, а `options` — необязательные параметры конфигурации, которые могут различаться для разных плагинов.

Для одновременной регистрации нескольких плагинов можно передать массив. Это удобно, если плагинами нужно управлять централизованно.

```typescript
univer.registerPlugin([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
])
```

#### Ленивая загрузка плагинов

Одно из распространённых преимуществ режима плагинов — возможность гибко управлять временем их загрузки. Например, при инициализации приложения можно загрузить только основные плагины, а остальные — после завершения первого рендеринга.

```typescript
// ...

const univerAPI = FUniver.newAPI(univer)

univerAPI.createDocument({})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

Этот способ оптимизации используется в нашем [официальном демонстрационном приложении](https://github.com/dream-num/univer/blob/dev/examples/src/sheets/main.ts).

## Другие каналы выпусков

Помимо стабильных выпусков, Univer предоставляет каналы alpha / beta и nightly. Они позволяют заранее получить доступ к новым функциям, которые ещё не выпущены официально. Однако чем больше новых возможностей, тем выше риски: такие версии могут содержать ошибки, незавершённые функции или нестабильные компоненты. По возможности не используйте их в рабочей среде.

### Версии Alpha / Beta

Завершив работу над новой функцией или существенным изменением, команда разработчиков Univer может предварительно опубликовать их в канале alpha или beta. Alpha- или beta-версию пакета Univer можно установить следующей командой:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Если при использовании alpha- или beta-версий вы обнаружите проблему или захотите поделиться отзывом, сообщите об этом команде разработчиков Univer через [GitHub Issues](https://github.com/dream-num/univer/issues).

Будем рады вашим отзывам о предварительных выпусках.
