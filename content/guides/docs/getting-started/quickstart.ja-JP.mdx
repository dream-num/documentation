Univer Docs はプラグインで構成されており、ドキュメントをスナップショットに保存し、コマンドによる変更を適用し、通常は Facade API. によって駆動されます。このページでは、これらの4つのコンセプトについて説明します。エディタを実行するには、[インストールと基本的な使い方](/guides/docs/getting-started/installation)を続けてください。

## 基本概念 [#basic-concepts]

残りのページでは、次の4つの用語を使用します。

- プラグイン Plugin
- スナップショット Snapshot
- コマンド Command
- Facade API

### プラグイン

プラグインは、Univerですべての機能を提供し、アーキテクチャの最小構成要素です。 Univerアプリケーションは、プラグインのセットで構成されています。

プラグインは2つのロールの1つを実行します。

1. 機能を実行します。たとえば、`@univerjs/docs-hyper-link`は、ハイパーリンクモデルとコマンドをUniver Docsに追加します。
2. ベース機能を提供します。`@univerjs/engine-render`はレンダリングを提供します。

アプリケーションのニーズをプラグインだけ含めて、未使用のコードがロードされていないようにします。利用可能なプラグインが要件をカバーしていない場合は、プラグインを書いて Univerを拡張します。

### スナップショット

Univer Docs は、[`IDocumentData`](/guides/docs/model/document-data#idocumentdata)としてドキュメントを格納します。スナップショットは、ドキュメント ボディ、ドキュメント レベルのスタイル、ヘッダー、フッター、図面、リスト、表、プラグイン リソースについて説明します。

オプションの`resources`フィールドに存在するプラグインで定義されたデータ。

<Callout type="warning" title="キューション">
  スナップショットはデータのみを保持します。エディタが実行中はドキュメントの状態を追跡しません。現在の状態をスナップショットとして保存するには、Facade APIのスナップショットメソッドを呼び出します。
</Callout>

### コマンド

Univer Docs では、コンテンツやフォーマットの変更がコマンドを経由して行われます。この設計により、変更トラッキング、無修正、および共同編集が可能になり、関連する機能が互いに一致して維持されます。

Facade API は引数を準備し、対応する Docs コマンドを実行します。

<Callout type="warning" title="キューション">
  **スナップショットを直接変更しないでください。** そのような書き込みには、影響がなく、日付からビューとUIを残します。 コマンドやFacade APIを介してデータを変更します。
</Callout>

### Facade API

事務所のアプリケーションは複雑であり、それらをサポートするアーキテクチャも複雑です。 Facade APIは、そのレベルで作業する必要があることを取り除きます。Univerのファーストパーティプラグインをラップし、より簡単なエントリポイントを露出します。

Facade APIはまだ活発な開発中です。質問や要件がある場合は、GitHubの問題をオープンしてください。

日常業務にこだわった内容が抽象化されています。複雑な機能もUniverのアーキテクチャの理解や低レベルのAPIの直接利用が求められることがあります。

## プリセットモードとプラグインモード

プリセットは、既に設定されているプラグインのバンドルです。 両方のモードには同じプラグインが含まれている場合、それらは同じ機能を提供します。 プリセットはセットアップ作業を減らします。 プラグインモードは構成を取り除き、アプリケーションにロードします。

<Callout type="warning">
  Univer の依存性を同じバージョンに保ちましょう。プリセットがすでにプラグインが含まれている場合は、2回目の登録は行いません。
</Callout>

| プラグインモード                                     | プリセットモード                                                 |
| ---------------------------------------------------- | ---------------------------------------------------------------- |
| アプリケーションはファサードの拡張をそれ自体輸入します | プリセットには、ファサードの拡張機能が含まれています |
| アプリケーションは、プラグインの登録注文を制御する | プリセットは、含まれているプラグインを管理します。 |
| プラグインは要求にロードされます | 設定したプリセットは初期化時に同期的に読み込まれる |
