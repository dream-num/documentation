## テンプレートから作成

ローカル環境で Univer アプリを作成する場合は、以下のコマンドでテンプレートから作成できます。

<Tabs items={['npm', 'pnpm']}>
  <Tab>
    以下のコマンドを実行するには、`nodejs >= 18`、`npm >= 8`、`git` が必要です。

    ```shell
    npx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit
    npm install
    npm run dev
    ```
  </Tab>
  <Tab>
    以下のコマンドを実行するには、`nodejs >= 18`、`pnpm >= 7`、`git` が必要です。

    ```shell
    pnpm dlx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit
    pnpm install
    pnpm dev
    ```
  </Tab>
</Tabs>

これで最初の Univer プロジェクトを作成し、いくつかの機能を体験できます。

## 基本概念 [#basic-concepts]

Univer をさらに理解する前に、基本概念を把握しておくとスムーズに進められます。

基本概念は次のとおりです。

- プラグイン Plugin
- スナップショット Snapshot
- コマンド Command
- Facade API

### プラグイン

Univer の機能はすべてプラグインで提供されます。プラグインは Univer の基本構成要素で、複数のプラグインを組み合わせて Univer アプリを構成します。

プラグインの役割は次のとおりです。

1. 機能の実装（例：`@univerjs/sheets-filter` はフィルタ機能を提供）
2. 基盤機能の提供（例：`@univerjs/engine-render` は描画機能を提供）

必要なプラグインだけを組み合わせてアプリを構成できるため、不要なコードを避けられます。独自プラグインを作成して機能を拡張することも可能です。

### スナップショット

Univer ではスナップショットを読み込んでドキュメントを表示します。ドキュメント種別ごとにスナップショット形式が異なるため、対応する API ドキュメントを参照してください。

1. スプレッドシートのスナップショット形式は [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata)
2. ドキュメントのスナップショット形式は [`IDocumentData`](/guides/docs/model/document-data#idocumentdata)

機能プラグインは `resources` フィールドに画像などのリソースを保存できます。詳細は [プラグインのカスタムモデル](/guides/recipes/tutorials/custom-model) を参照してください。

<Callout type="warning" title="注意事項">
  **注意**：Univer のスナップショットはデータ保存専用で、実行時の最新状態は反映されません。最新状態を保存したい場合は、Facade API のスナップショット保存メソッドを使用してください。
</Callout>

### コマンド

Univer ではデータの変更はすべてコマンド経由で行われます。これにより、値の変更履歴を追跡しやすくなり、Undo/Redo や共同編集、機能間の複雑な関連処理が可能になります。

コマンド経由でデータを変更する場合は [コマンド ID の探し方](/guides/recipes/practices/find-the-command-id) を参照してください。Facade API を使う場合も、内部的にはコマンドが実行されます。

<Callout type="warning" title="注意事項">
  **スナップショットを直接変更しないでください。** 反映されず、ビューや UI の更新も行われません。コマンドまたは Facade API を使用してください。
</Callout>

### Facade API

オフィスアプリは複雑なため、Univer のアーキテクチャも複雑です。そこで Facade API を提供し、第一級プラグインをラップしたシンプルなインターフェースで利用できるようにしています。

Facade API は現在も継続的に改善中です。要望や提案があれば GitHub で issue を立ててください。

Facade API は低レベルの詳細を抽象化しています。一般的なタスクは簡素化されますが、複雑な機能を実装するには、Univer のアーキテクチャを理解した上で、より低レベルのコマンドやモジュールの API を利用する必要がある場合があります。

## プリセットモードとプラグインモード

Univer はプラグイン志向の設計で、柔軟で拡張可能なドキュメントアプリ基盤を提供します。プラグイン構成により機能モジュールを容易に統合できますが、初めて触れる開発者にとっては複雑に感じることがあります。

そのため Univer では **プラグインモード** と **プリセットモード** の 2 つを用意し、素早く導入できるようにしています。**プリセット**は事前に構成されたプラグインの組み合わせで、複雑な拡張をしない限り両者の機能は同等です。

<Callout type="warning" title="注意事項">
  - **依存バージョンの一致**：プリセット/プラグインどちらの方法でも、依存関係のバージョンは揃える必要があります。
  - **プリセットとプラグインの併用に注意**：プリセットに含まれるプラグインを重複して読み込むと、衝突や不具合の原因になります。
</Callout>

プリセットモードとプラグインモードの違い：

| プラグインモード | プリセットモード |
| --- | --- |
| 対応する facade パッケージを手動で読み込む必要がある | facade パッケージの手動読み込みは不要 |
| 同種の機能プラグインの登録順に注意が必要 | プリセット内の機能は登録順を気にしなくてよい |
| 必要に応じた遅延読み込みが可能 | プリセット単位の遅延読み込みのみ（内部プラグインは同期読み込み） |
