## Язык интерфейса

`locale` выбирает языковой пакет, используемый для меню, подсказок, диалогов и другого переведенного пользовательского интерфейса. `locales` регистрирует языковые пакеты без выбора одного. Каждый блок в экземпляре Univer разделяет эти настройки. Передайте значения `LocaleType`, например `LocaleType.EN_US`.

- **Все продукты: UI**: `locale` меняет переведенные меню, подсказки, диалоги и ярлыки плагинов. Он не изменяет пользовательский контент или не переименовывает существующие блоки.
- **Листы: форматы ячеек и формулы**: Сначала цифры и даты отображаются с переопределением формата номера, затем снимок из книги `locale`, а затем экземпляр `locale`. `region` не заменяет ни один из них. Поведение формулы, такое как `DOLLAR` и валютные форматы, применяемые к финансовым результатам, по-прежнему следует `locale` , а нормализация ввода CJK также использует `locale`
- **Док: статистика**: `locale` определяет сегментацию и подсчет слов.

### Смена языка во время работы

Перед переключением языков загрузите каждый языковой пакет, который предоставляют установленные плагины или предустановки. `loadLocales()` объединяет переводы без переключения языка; `setLocale()` переключается на загруженные переводы без загрузки чего-либо. Ключ без перевода появляется как сам ключ. Следующий пример загружает общий языковой пакет пользовательского интерфейса. Добавьте пакеты целевого языка для других установленных плагинов к тому же вызову слияния.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Регистрация языковых пакетов в режиме плагинов

В режиме плагина импортируйте языковой пакет из каждого плагина, который предоставляет один, объедините их в один объект и передайте этот объект в экземпляр `Univer`:

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignEnUS from '@univerjs/design/locale/en-US' // [!code highlight]
import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US' // [!code highlight]
import UIEnUS from '@univerjs/ui/locale/en-US' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      DesignEnUS, // [!code highlight]
      UIEnUS, // [!code highlight]
      DocsUIEnUS, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="Осторожно">
  Не каждый плагин включает в себя языковой пакет. В документации каждой функции указано, работает ли он.
</Callout>

### Регистрация языковых пакетов в предустановленном режиме

Предустановленные пакеты уже включают языковые пакеты своих плагинов, поэтому их можно импортировать непосредственно из предустановленного пакета:

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS, // [!code highlight]
    ),
  },
  presets: [
    UniverDocsCorePreset(),
  ],
})
```

### Объединение языковых пакетов [#mergeLocales]

`mergeLocales` объединяет несколько плагинов или предустановленных языковых пакетов в один полный объект языкового пакета.

### Пользовательские языковые пакеты

Настраиваемый языковой пакет также может быть собран вручную. Постройте требуемый объект и передайте его в экземпляр `Univer`. Для справки, предустановленные языковые пакеты обычно хранятся под `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Участие в переводе

Univer включает в себя следующие встроенные языковые пакеты:

- `zh-CN`: упрощённый китайский
- `en-US`: английский
- `zh-TW`: традиционный китайский
- `zh-HK`: традиционный китайский (Гонконг)
- `ru-RU`: русский
- `vi-VN`: вьетнамский
- `fa-IR`: персидский
- `fr-FR`: французский
- `ja-JP`: японский
- `ko-KR`: корейский
- `es-ES`: испанский
- `ca-ES`: каталонский
- `sk-SK`: словацкий
- `ar-SA`: арабский
- `de-DE`: немецкий
- `id-ID`: индонезийский
- `it-IT`: итальянский
- `pl-PL`: польский
- `pt-BR`: португальский (Бразилия)

Univer является открытым исходным кодом, и вклады, которые добавляют или улучшают языковой пакет, приветствуются.

## Региональные настройки

`region` определяет региональные конвенции, которые следуют за региональными функциями. Единицы в экземпляре Univer разделяют эту настройку.

Обе настройки принимают значения `LocaleType`. Например, `LocaleType.EN_US` - это `enUS`, а `en-US` является именем файла языкового пакета и тегом BCP 47. Не продавайте коды стран, такие как `US` или `SG` как `region` . Регион не требует своего языкового набора, когда пользовательский интерфейс использует другой `locale`

Когда `region` не установлен явно, он следует за `locale`, включая последующие вызовы `setLocale()`. Настройка `region` при инициализации или вызов `setRegion()` останавливает это автоматическое следование. Изменения языка после этого сохраняют выбранный регион. Не существует общедоступного API для восстановления автоматического следования, поэтому обновляйте оба значения, когда они должны меняться вместе.

Чтобы сохранить язык пользовательского интерфейса при применении немецких региональных конвенций, добавьте `region: LocaleType.DE_DE` рядом с `locale` в `createUniver()` или `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

В этом примере пользовательский интерфейс переключается на английский, а региональное форматирование остается немецким. `getCurrentLocale()` и `getCurrentRegion()` возвращают эффективные идентификаторы. Чтобы изменить оба вместе, вызовите оба сеттера с одинаковым значением `LocaleType`.

- **Листы: валютный контроль**: `region` определяет иконку панели инструментов валюты, параметры валюты и бухгалтерского учета и их предварительные просмотры, а также шаблон, который применяется командой валюты. Изменение не переписывает существующие форматы ячеек или не конвертирует денежные значения.
- **Док: статистика**: `region` форматирует графы, показанные в диалоге статистики и строке состояния, включая разделители групп.Изменение `region` не меняет правил подсчета.
- **Комментарии, когда включено**: `region` контролирует формат даты и времени, показанный в комментариях, используя 24-часовое время и латинские цифры. `locale` управляет комментарием UI-текста. Ни одна настройка не изменяет сохраненные метки времени, а `region` не является настройкой часовой зоны.
- **Доски, слайды, базы, PDF**: `locale` управляет переведенным пользовательским интерфейсом. `region` применяется к общим функциям, которые потребляют его, таким как комментарии потоков после интеграции; он не автоматически переформатирует доску или слайд-текст, поля базы или PDF-контент.

## Расположение справа налево

<Callout type="warning" title="Осторожно">
  RTL в настоящее время поддерживается только в UI-слое.Слой рендеринга не поддерживает RTL.
</Callout>

Настройка направления - отдельная настройка. Установите `direction` при инициализации или вызове `univerAPI.setDirection('rtl')` или `setDirection('ltr')`. Изменение `locale` либо `region` само по себе не меняет направление макета.

```typescript
univerAPI.setDirection('rtl')
```
