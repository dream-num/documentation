## Kit de démarrage

Si vous préférez travailler dans un environnement de développement local, vous pouvez utiliser l’un des kits de démarrage suivants pour créer une nouvelle application Univer en quelques secondes.

<Tabs items={['npm', 'pnpm']}>
  <Tab>
    Pour exécuter la commande suivante, `nodejs >= 18`, `npm >= 8` et `git` doivent être installés sur votre appareil.

    ```shell
    npx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit
    npm install
    npm run dev
    ```

  </Tab>
  <Tab>
    Pour exécuter la commande suivante, `nodejs >= 18`, `pnpm >= 7` et `git` doivent être installés sur votre appareil.

    ```shell
    pnpm dlx degit dream-num/univer-doc-start-kit univer-doc-start-kit
    cd univer-doc-start-kit
    pnpm install
    pnpm dev
    ```

  </Tab>
</Tabs>

Bravo pour vos premiers pas avec Univer ! Vous avez créé votre premier projet et découvert un aperçu des possibilités offertes par Univer.

## Concepts de base [#basic-concepts]

Avant d’aller plus loin avec Univer, lisez cette page pour en comprendre les concepts de base. Ils vous aideront à utiliser Univer plus facilement.

Ces concepts sont les suivants :

- Plugin
- Snapshot
- Commande
- Facade API

## Plugins

Toutes les fonctionnalités d’Univer sont fournies par des plugins, qui constituent ses éléments de base. Plusieurs plugins combinés forment une application Univer.

Les plugins ont notamment pour rôle :

1. D’implémenter des fonctionnalités. Par exemple, `@univerjs/docs-hyper-link` fournit le modèle et les commandes de liens hypertextes pour Univer Docs.
2. De fournir des capacités fondamentales. Par exemple, `@univerjs/engine-render` fournit les capacités de rendu.

Vous pouvez combiner les plugins d’Univer afin de personnaliser une application selon vos besoins, sans charger de code inutile. Vous pouvez également étendre les fonctionnalités d’Univer en écrivant vos propres plugins.

## Snapshot

Univer Docs utilise [`IDocumentData`](/guides/docs/model/document-data#idocumentdata) comme format de snapshot. Il décrit le corps du document, les styles du document, les en-têtes et pieds de page, les dessins, les listes, les tableaux et les ressources des plugins.

Le champ facultatif `resources` stocke les données définies par les plugins.

<Callout type="warning" title="Attention">
  Le snapshot d’Univer sert uniquement à stocker des données. Il ne reflète pas le dernier état du document pendant
  l’exécution ! Pour enregistrer l’état du document sous forme de snapshot, utilisez la méthode d’enregistrement du
  snapshot de la Facade API.
</Callout>

## Commande

Dans Univer Docs, les modifications du contenu et de la mise en forme du document sont effectuées au moyen de commandes. Cette approche permet de suivre les modifications, d’implémenter l’annulation, le rétablissement et l’édition collaborative, et de coordonner les fonctionnalités associées.

La Facade API prépare les paramètres et exécute en arrière-plan les commandes Docs correspondantes.

<Callout type="warning" title="Attention">
  **Ne modifiez pas directement le snapshot !** Vos modifications ne seront pas appliquées et ne déclencheront aucune
  mise à jour des vues ou de l’interface utilisateur. Modifiez les données au moyen de commandes ou de la Facade API.
</Callout>

## Facade API

Les applications bureautiques étant très complexes, l’architecture d’Univer l’est également. Pour faciliter son utilisation par les développeurs, nous proposons la Facade API, une couche d’abstraction autour des plugins officiels d’Univer qui fournit des interfaces plus simples.

La Facade API est activement améliorée. Si vous avez des questions ou des besoins particuliers, ouvrez une issue sur GitHub.

La Facade API est une API de haut niveau qui masque les détails de l’implémentation sous-jacente. Elle simplifie les tâches courantes, mais les fonctionnalités complexes peuvent nécessiter de comprendre l’architecture d’Univer et d’utiliser directement l’API de bas niveau.
