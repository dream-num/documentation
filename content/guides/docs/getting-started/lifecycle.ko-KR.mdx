## 전역 수명 주기

- **을 시작**: Univer는 초기화되고, 사업 단위는 아직 존재하지 않습니다.
- **지원하다**: 첫번째 사업 단위는 창조되었습니다. 단위는 나중에 이 단계를 다시 방아쇠하지 않습니다.
- **이름 ***: 표준 UI는 첫번째 렌더링 스위치를 완료했습니다. 비동기 내용은 아직도 적재될지도 모릅니다.
- **인기 카테고리**: 표준 UI는 렌더링을 따르는 지연 후에 이 단계를 도달합니다. 그것은 끝내기 위하여 모든 비동기 일을 기다리지 않습니다.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="이벤트가 알리는 대상">

`LifeCycleChanged`는 Univer의 글로벌 스테이지를 보고합니다. 플러그인 B가 글로벌 `Ready` 이후 로드되는 경우, 예를 들어, B는 여전히 `onReady()`를 실행하지만, 두 번째 글로벌 `Ready` 이벤트가 방출되지 않습니다.

언제든지 청취자는 `Starting`를 포함하여 현재 단계로 즉시 불을 수 있습니다. 현재 단계를 결정하려면 `univerAPI.getCurrentLifecycleStage()`로 직접 전화하십시오.

</Callout>

청취자를 제거하려면 `disposable` 개체를 호출하여 반환합니다.

```typescript
disposable.dispose()
```

## 플러그인 수명 주기 훅

플러그인은 `onStarting()`를 실행하면 Univer가 들어있는 글로벌 스테이지로 이전됩니다. B 부하가 변경되는 데모는 A의 후크 통화가 어떻게 비교하는지 보여줍니다.

<LifecycleDemo />

일반 플러그인로드가 등록 될 때. 비즈니스 유형 플러그인은 일반적으로 그 유형의 첫 번째 단위 이전에로드됩니다. 이미 시작된 유형의 새로운 플러그인은 나중에로드를 시작했으며, deferred 일괄 배치. Explicit Dependencies는 이전로드 할 수 있습니다.

Hooks는 배치, 단계 및 의존성 순서에 의해 동시에 실행됩니다. 걸이 안쪽에 비동기 일을 기다리지 마십시오. 단위, DOM 성분 또는 자원이 접근하기 전에 실제로 준비되어 있다는 것을 확인하십시오.
