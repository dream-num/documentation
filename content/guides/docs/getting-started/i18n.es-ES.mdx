## Idioma de la interfaz

`locale` selecciona el paquete de idiomas utilizado para menús, puntas de herramientas, diálogos y otros UI traducidos. `locales` registra paquetes de idiomas sin seleccionar uno. Cada unidad en la instancia Univer comparte estos ajustes. Pase `LocaleType` valores, por ejemplo `LocaleType.EN_US`.

- **Todos los productos: UI**: `locale` cambia los menús traducidos, puntas de herramientas, diálogos y etiquetas de plugin. No modifica el contenido de usuario ni renombra las unidades existentes.
- **Hojas: formatos celulares y fórmulas**: Números y fechas renderizan primero con el número-format locale, luego la instantánea del libro `locale`, y luego la instancia `locale`. `region` no reemplaza ninguno de estos. El comportamiento de la fórmula, como `DOLLAR` y los formatos de moneda aplicados a los resultados financieros, sigue `locale`, y la normalización de entrada CJK también utiliza `locale`.
- **Docs: estadística**: `locale` determina la segmentación de palabras y el conteo.

### Cambiar el idioma durante la ejecución

Antes de cambiar idiomas, carga cada paquete de idiomas que proporcionan los plugins instalados o presets. `loadLocales()` fusiona traducciones sin cambiar el idioma; `setLocale()` cambia a las traducciones cargadas sin descargar nada. Una clave sin una traducción aparece como la propia clave. El siguiente ejemplo carga el paquete de idioma UI compartido. Añadir los paquetes de idiomas de destino para los otros plugins instalado en la misma llamada.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Registro de paquetes de idiomas en modo complemento

En modo plugin, importar el paquete de idiomas de cada plugin que proporciona uno, fusionarlos en un solo objeto, y pasar ese objeto a la instancia `Univer`:

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignEnUS from '@univerjs/design/locale/en-US' // [!code highlight]
import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US' // [!code highlight]
import UIEnUS from '@univerjs/ui/locale/en-US' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      DesignEnUS, // [!code highlight]
      UIEnUS, // [!code highlight]
      DocsUIEnUS, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="Precaución">
  No todos los plugins incluyen un paquete de idiomas. La documentación de cada función indica si lo hace.
</Callout>

### Registro de paquetes de idiomas en modo preestablecido

Los paquetes de Preset ya incluyen los paquetes de idiomas de sus plugins, por lo que pueden ser importados directamente desde el preset:

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS, // [!code highlight]
    ),
  },
  presets: [UniverDocsCorePreset()],
})
```

### Paquetes de idiomas personalizados

También se puede montar manualmente un paquete de idiomas personalizado. Construya el objeto requerido y pasarlo a la instancia `Univer`. Para referencia, los paquetes de idiomas preestablecidos generalmente se almacenan bajo `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Configuración regional

`region` determina las convenciones regionales que siguen las características regionales. Unidades en la instancia Univer comparten este ajuste.

Ambos ajustes `LocaleType` valores, por ejemplo, `LocaleType.EN_US` es `enUS`, mientras `en-US` es el nombre del archivo idioma-paquete y la etiqueta BCP 47. No pasar códigos de país como `US` o `SG` como tal `region`. Una región no requiere su paquete de idiomas cuando la UI utiliza una `locale`.

Cuando `region` no se establece explícitamente, sigue `locale`, incluyendo llamadas `setLocale()` posteriores. Configurar `region` en la inicialización o llamar a `setRegion()` detiene este seguimiento automático. Cambios de idioma después de que mantenga la región seleccionada. No hay API pública para restaurar automáticos a continuación, así que actualice ambos valores cuando deben cambiar juntos.

Para mantener el idioma UI al aplicar convenciones regionales alemanas, agregue `region: LocaleType.DE_DE` junto a `locale` en `createUniver()` o `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

En este ejemplo, la interfaz de usuario cambia a formato inglés y regional se mantiene alemán. `getCurrentLocale()` y `getCurrentRegion()` devuelven los identificadores efectivos. Para cambiar ambos juntos, llame a ambos setters con el mismo valor `LocaleType`.

- **Hojas: controles de divisas**: `region` determina el icono de la barra de herramientas de moneda, las opciones de moneda y contabilidad y sus previsiones, y el patrón que el comando de la moneda aplica. Cambiar no reescribir los formatos de celda existentes o convertir los valores monetarios.
- **Docs: estadística**: `region` formatea los recuentos mostrados en la barra de diálogo y estado de las estadísticas, incluyendo separadores de agrupación. Cambiar `region` no cambia las reglas de conteo.
- **Thread comments, when enabled**: `region` controla el formato de fecha y hora mostrado en los comentarios, utilizando el tiempo 24 horas y dígitos latinos. `locale` controles comentario Texto de la interfaz de usuario. Ni el ajuste de los tiempos almacenados, y `region` no es un ajuste de la zona horaria.
- **Boards, Slides, Bases, PDFs**: Controles `locale` traducidos UI. `region` se aplica a las características compartidas que lo consumen, como los comentarios de hilo una vez integrados; no se reforma automáticamente tabla o texto de diapositivas, campos Base, o contenido PDF.

## Diseño de derecha a izquierda

<Callout type="warning" title="Precaución">
  Actualmente RTL es compatible sólo en la capa UI. La capa de renderización no soporta RTL.
</Callout>

La dirección de diseño es un ajuste separado. Establecer `direction` en la inicialización, o llamar `univerAPI.setDirection('rtl')` o `setDirection('ltr')`. Cambiar `locale` y `region` solo no cambia la dirección de diseño.

```typescript
univerAPI.setDirection('rtl')
```
