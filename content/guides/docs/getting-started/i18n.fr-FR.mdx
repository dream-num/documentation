## Langue de l’interface

`locale` sélectionne le paquet de langues utilisé pour les menus, les tooltips, les dialogues et les autres interfaces traduites. `locales` enregistre les paquets de langues sans en sélectionner un. Chaque unité dans le Univer l'instance partage ces paramètres. `LocaleType` valeurs, par exemple `LocaleType.EN_US`.

- **Tous les produits: UI**: `locale` modifie les menus traduits, les tooltips, les dialogues et les étiquettes de plugins. Il ne modifie pas le contenu utilisateur ni ne renomme les unités existantes.
- **Feuilles: formats et formules de cellules**: Les nombres et les dates rendus avec la locale du format number reververver d'abord, puis l'instantané du cahier de travail `locale`, et ensuite l'instance `locale`. `region` ne remplace aucun de ceux-ci. Le comportement de la formule, comme `DOLLAR` et les formats de devises appliqués aux résultats financiers, suit toujours `locale` , et la normalisation d'entrée CJK utilise également `locale` .
- **Docs: statistiques**: `locale` détermine la segmentation et le comptage des mots.

### Changer la langue à l’exécution

Avant de changer de langue, chargez chaque paquet de langue fourni par les plugins ou préréglages installés. `loadLocales()` fusionne les traductions sans changer de langue; `setLocale()` bascule vers les traductions chargées sans télécharger quoi que ce soit. Une clé sans traduction apparaît comme la clé elle-même. L'exemple suivant charge le paquet de langue de l'interface utilisateur partagée.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Enregistrer des packs de langue en mode plugin

En mode plugin, importez le paquet de langue de chaque plugin qui fournit un, fusionnez-les dans un seul objet, et passez cet objet à l'instance `Univer` :

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignEnUS from '@univerjs/design/locale/en-US' // [!code highlight]
import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US' // [!code highlight]
import UIEnUS from '@univerjs/ui/locale/en-US' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      DesignEnUS, // [!code highlight]
      UIEnUS, // [!code highlight]
      DocsUIEnUS, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="Attention">
  Tous les plugins ne comprennent pas un paquet de langues. La documentation de chaque fonctionnalité indique si elle le fait.
</Callout>

### Enregistrer des packs de langue en mode prédéfini

Les paquets prédéfinis incluent déjà les paquets de langue de leurs plugins, afin qu'ils puissent être importés directement à partir du preset:

```typescript
import { UniverDocsCorePreset } from '@univerjs/preset-docs-core'
import UniverPresetDocsCoreEnUS from '@univerjs/preset-docs-core/locales/en-US' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetDocsCoreEnUS, // [!code highlight]
    ),
  },
  presets: [
    UniverDocsCorePreset(),
  ],
})
```

### Fusion des packs de langue [#mergeLocales]

`mergeLocales` fusionne plusieurs paquets de langages plugin ou préréglés en un seul objet complet. Utilisez-le comme suit:

<Tabs items={['Mode plugin', 'Mode préréglage']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // You can pass multiple language pack objects to merge
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // You can also pass an array of language pack objects
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
  <Tab>

### Packs linguistiques personnalisés

Un paquet de langage personnalisé peut également être assemblé manuellement. Construisez l'objet requis et passez-le à l'instance `Univer`. Pour référence, les paquets de langage prédéfinis sont généralement stockés sous `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Contribuer aux traductions

Univer comprend les paquets de langages intégrés suivants:

- `zh-CN` : chinois simplifié
- `en-US` : anglais
- `zh-TW` : chinois traditionnel
- `zh-HK` : chinois traditionnel (Hong Kong)
- `ru-RU` : russe
- `vi-VN` : vietnamien
- `fa-IR` : persan
- `fr-FR` : français
- `ja-JP` : japonais
- `ko-KR` : coréen
- `es-ES` : espagnol
- `ca-ES` : catalan
- `sk-SK` : slovaque
- `ar-SA` : arabe
- `de-DE` : allemand
- `id-ID` : indonésien
- `it-IT` : italien
- `pl-PL` : polonais

Univer est open source, et les contributions qui ajoutent ou améliorent un paquet linguistique sont les bienvenues.

## Paramètres régionaux

`region` détermine les conventions régionales que les caractéristiques régionales suivent. Les unités de l'instance Univer partagent ce paramètre.

Les deux paramètres prennent des valeurs de `LocaleType`. Par exemple, `LocaleType.EN_US` est `enUS`, tandis que `en-US` est le nom de fichier de paquet de langue et l'étiquette BCP 47. Ne passez pas les codes de pays tels que `US` ou `SG` comme `region`. Une région n'a pas besoin de son paquet de langue lorsque l'interface utilisateur utilise un autre `locale`.

Lorsque `region` n'est pas défini explicitement, il suit `locale`, y compris les appels `setLocale()` suivants. La configuration de `region` à l'initialisation ou l'appel `setRegion()` arrête ce suivi automatique. La langue change après cela garde la région sélectionnée. Il n'y a pas d'API publique pour restaurer le suivi automatique, donc mettez à jour les deux valeurs quand elles doivent changer ensemble.

Pour conserver la langue UI tout en appliquant les conventions régionales allemandes, ajoutez `region: LocaleType.DE_DE` à côté de `locale` dans `createUniver()` ou `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Dans cet exemple, l'interface utilisateur passe au formatage anglais et régional reste allemand. `getCurrentLocale()` et `getCurrentRegion()` retournent les identifiants efficaces. Pour changer les deux ensemble, appelez les deux setters avec la même valeur `LocaleType`.

- **Feuilles : contrôles des devises**: `region` détermine l'icône de la barre d'outils de monnaie, les options de monnaie et de comptabilité et leurs prévisualisations, et le modèle que la commande de monnaie applique.
- **Docs: statistiques**: `region` formate les nombres affichés dans la barre de dialogue et d'état des statistiques, y compris les séparateurs de regroupement. La modification de `region` ne modifie pas les règles de comptage.
- **Commentaires de filetage, lorsque activé**: `region` contrôle le format de la date et de l'heure indiqué dans les commentaires, à l'aide d'une heure de 24 heures et de chiffres latins. `locale` ne contrôle pas le texte de l'interface utilisateur. Ni la configuration des changements enregistrés horodatage, et `region` n'est pas un réglage de fuseau horaire.
- **Planches, diapositives, bases, PDFs**: `locale` contrôle l'interface utilisateur traduite. `region` s'applique aux fonctionnalités partagées qui la consomment, comme les commentaires de thread une fois intégré; il ne reformate pas automatiquement le tableau ou le texte de diapositive, les champs de base ou le contenu PDF.

## Disposition de droite à gauche

<Callout type="warning" title="Attention">
  RTL n'est actuellement pris en charge que dans la couche UI. La couche de rendu ne supporte pas RTL.
</Callout>

La direction de mise en page est un réglage séparé. Réglez `direction` à l'initialisation, ou appelez `univerAPI.setDirection('rtl')` ou `setDirection('ltr')`. La modification de `locale` et `region` seule ne change pas la direction de la mise en page.

```typescript
univerAPI.setDirection('rtl')
```
