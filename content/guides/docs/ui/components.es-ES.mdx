Univer no acepta un componente como argumento a una función de renderizado. Un componente debe ser registrado primero a través de Facade API antes de que pueda ser utilizado en cualquier lugar donde Univer monta contenido personalizado.

Si una instancia Facade API no está disponible todavía, consulte [Facade API](/guides/docs/getting-started/facade).

## Registro de componentes personalizados

```typescript
// [!code word:componentKey]
// [!code word:CustomComponent]
// [!code word:options]
univerAPI.registerComponent(componentKey, CustomComponent, options)
```

Utilice `univerAPI.registerComponent` para registrar un componente personalizado. El método acepta tres parámetros:

- `componentKey`: el identificador único del componente, que Univer utiliza para referenciarlo más tarde.
- `CustomComponent`: la implementación del componente, que puede ser un componente React, un componente Vue o un componente Web.
- `options`: Ajustes opcionales, como el marco del componente depende.

### Componentes de React [#react]

Los componentes React no requieren ninguna configuración adicional. Cualquier componente React válido puede ser registrado:

```tsx
function ReactComponent(props: Record<string, any>) {
  return <div>Hello Univer!</div>
}

univerAPI.registerComponent('MyReactComponent', ReactComponent)
```

### Componentes de Vue [#vue]

#### Vue 3.x

Los componentes Vue requieren un adaptador. Instalar y registrar `UniverVue3AdapterPlugin` desde `@univerjs/ui-adapter-vue3`:

```package-install
npm install @univerjs/ui-adapter-vue3
```

```typescript
import { UniverVue3AdapterPlugin } from '@univerjs/ui-adapter-vue3'

univer.registerPlugin(UniverVue3AdapterPlugin)
```

Establecer la opción `framework` a `'vue3'` cuando se registra un componente Vue:

```tsx
const Vue3Component = defineComponent({
  setup(props) {
    return () => <div>Hello Univer!</div>
  },
})

univerAPI.registerComponent('MyVue3Component', Vue3Component, {
  // [!code word:vue3]
  framework: 'vue3',
})
```

#### Vue 2.x

Vue 2.x es EOL (End of Life) y ya no se mantiene, por lo que Univer no proporciona un plugin de adaptador UI para él. Un plugin personalizado puede implementar el adaptador en su lugar. El siguiente ejemplo muestra una implementación:

```typescript title="ui-adapter-vue2.ts"
import { DependentOn, Inject, Injector, Plugin } from '@univerjs/core'
import { ComponentManager, UniverUIPlugin } from '@univerjs/ui'
import Vue from 'vue'

/**
 * The plugin that allows Univer to use Vue 2 components as UI components.
 */
@DependentOn(UniverUIPlugin)
export class UniverVue2AdapterPlugin extends Plugin {
  static override pluginName = 'UNIVER_UI_VUE2_ADAPTER_PLUGIN'

  constructor(
    private readonly _config = {},
    @Inject(Injector) protected readonly _injector: Injector,
    @Inject(ComponentManager) protected readonly _componentManager: ComponentManager,
  ) {
    super()
  }

  override onStarting(): void {
    const { createElement, useEffect, useRef } = this._componentManager.reactUtils

    this._componentManager.setHandler('vue2', (component: any) => {
      return (props: Record<string, any>) =>
        createElement(VueComponentWrapper, {
          component,
          props: Object.keys(props).reduce<Record<string, any>>((acc, key) => {
            if (key !== 'key') {
              acc[key] = props[key]
            }
            return acc
          }, {}),
          reactUtils: { createElement, useEffect, useRef },
        })
    })
  }
}

export function VueComponentWrapper(options: {
  component: any
  props: Record<string, any>
  reactUtils: typeof ComponentManager.prototype.reactUtils
}) {
  const { component, props, reactUtils } = options
  const { createElement, useEffect, useRef } = reactUtils

  const domRef = useRef<HTMLDivElement>(null)

  useEffect(() => {
    if (!domRef.current) return

    const Constructor = Vue.extend(component)

    const instance = new Constructor({
      data: props,
    })
    instance.$mount()

    domRef.current.appendChild(instance.$el)

    return () => {
      instance.$destroy()
    }
  }, [props])

  return createElement('div', { ref: domRef })
}
```

Luego registre el plugin:

```typescript
import { UniverVue2AdapterPlugin } from './ui-adapter-vue2' // [!code ++]

univer.registerPlugin(UniverUIPlugin)
univer.registerPlugin(UniverVue2AdapterPlugin) // [!code ++]
```

Los componentes Vue 2.x requieren la opción `framework` para configurarse en `'vue2'`:

```tsx
const Vue2Component = Vue.component('MyVue2Component', {
  template: '<div>Hello, Univer!</div>',
})

univerAPI.registerComponent('MyVue2Component', Vue2Component, {
  // [!code word:vue2]
  framework: 'vue2',
})
```

### Componentes web [#web-component]

Los componentes web deben seguir el estándar de componentes web. Instalar y registrar `UniverWebComponentAdapterPlugin` desde `@univerjs/ui-adapter-web-component`:

```package-install
npm install @univerjs/ui-adapter-web-component
```

```typescript
import { UniverWebComponentAdapterPlugin } from '@univerjs/ui-adapter-web-component'

univer.registerPlugin(UniverWebComponentAdapterPlugin)
```

Establecer la opción `framework` a `'web-component'` cuando se registra un componente web:

```tsx
class WebComponent extends HTMLElement {
  constructor() {
    super()
    const shadow = this.attachShadow({ mode: 'open' })
    const div = document.createElement('div')
    div.textContent = 'Hello Univer!'
    shadow.appendChild(div)
  }
}

univerAPI.registerComponent('my-web-component', WebComponent, {
  // [!code word:web-component]
  framework: 'web-component',
})
```

### Angular [#angular]

Convierta un componente Angular en un elemento personalizado con `createCustomElement` de `@angular/elements`, a continuación, registre el elemento a través del adaptador Univer Web Component. El componente se puede utilizar en una barra lateral o diálogo Univer.

Mantenga `@angular/elements` en la misma versión que `@angular/core`, y `@univerjs/ui-adapter-web-component` sobre la misma versión como los otros paquetes Univer.

Llame a la función después de que Univer haya sido inicializado, y pase el inyector Angular del componente host. Obtenga el inyección con `private readonly injector = inject(Injector)`, luego llame a `registerAngularPanel(univer, univerAPI, this.injector)`. El componente host importa `inject` y `Injector` de `@angular/core` .

```typescript title="angular-panel.ts"
import type { Injector } from '@angular/core'
import type { FUniver, Univer } from '@univerjs/presets'
import { Component } from '@angular/core'
import { createCustomElement } from '@angular/elements'
import { UniverWebComponentAdapterPlugin } from '@univerjs/ui-adapter-web-component'

@Component({
  selector: 'app-angular-panel',
  standalone: true,
  template: '<p>Hello from Angular!</p>',
})
export class AngularPanelComponent {}

export function registerAngularPanel(univer: Univer, univerAPI: FUniver, injector: Injector) {
  const element = createCustomElement(AngularPanelComponent, { injector })

  univer.registerPlugin(UniverWebComponentAdapterPlugin)
  return univerAPI.registerComponent('univer-angular-panel', element, {
    framework: 'web-component',
  })
}
```

Cuando el editor se haya renderizado, usa la clave registrada como contenido de la barra lateral:

```typescript
const sidebar = univerAPI.openSidebar({
  header: { title: 'Angular' },
  children: { label: 'univer-angular-panel' },
  width: 360,
})
```

Retener el registro devuelto y las manijas laterales y llamar a `dispose()` en cada uno cuando ya no sea necesario. Registre el elemento una vez por aplicación. Su nombre debe contener un hifeno y debe diferir del selector de componentes Angular.

Angular Elements mapas entradas a propiedades de elementos y salidas a eventos DOM `CustomEvent`. El adaptador Univer establece propiedades pero no se suscribe a las salidas Angular . La aplicación se suscribe en aquellos eventos cuando son necesarios.

## Usar componentes personalizados

Los métodos a continuación cubren las formas comunes de colocar un componente personalizado en la interfaz de usuario Univer.

<Callout type="warning" title="Caution">
  1. Espere hasta que Univer haya terminado de renderizar antes de llamar estos métodos. 2. Registra los componentes que requieren registro antes de usar. 3. Llame a `dispose()` para limpiar y eliminar los componentes añadidos; de lo contrario la aplicación filtra la memoria.
</Callout>

### Agregar elementos de menú personalizados

Tanto la barra de menú superior (Ribbon) como el menú de clic derecho ( Menú contextual) pueden contener componentes personalizados. Añadiendo un componente a un elemento de menú requiere un plugin personalizado.

### Reemplazo de componentes integrados

<Callout type="error" title="Advertencia">
  Reemplazar un componente incorporado puede romper otras características que dependen de él. Lea el código fuente y la documentación antes de reemplazar un componente, y proceda con precaución.
</Callout>

`univerAPI.registerComponent` registra una anulación por defecto (`override: true`). La anulación tiene precedencia sobre el componente incorporado si el plugin registra su predeterminación antes o después de esta llamada. Sólo una anulación puede ser activa por `componentKey`, así que descargue el registro anterior antes de registrar otro. Llamar `dispose()` en el registro devuelto restaura el predeterminado incorporado si se registra. Pase `{ override: false }` para registrar un predeterminado en su lugar.

Registrar una anulación antes de que la vista correspondiente se abra por primera vez. Los cambios de registro no reenvian automáticamente las vistas que ya están montadas.

Por ejemplo, reemplazar el componente ColorPicker incorporado requiere una sola llamada:

```tsx
// Following code only replaces the UI of the built-in ColorPicker component, not its functionality
univerAPI.registerComponent('UI_COLOR_PICKER_COMPONENT', () => <input type="color" />)
```

### Reemplazar el renderizado de la información del usuario

`@univerjs/ui` renderiza los nombres y los avatares de los usuarios mediante `UserInfo`. `UserInfo` se renderiza mediante el componente registrado para `USER_INFO_COMPONENT` y recurre a `DefaultUserInfo` cuando no hay ninguno registrado. Registre un componente del host antes de que se abra la vista correspondiente:

```tsx
import { USER_INFO_COMPONENT } from '@univerjs/ui'
import type { IUserInfoProps } from '@univerjs/ui'

function HostUserInfo({ user, part, context, className, fallbackSrc }: IUserInfoProps) {
  if (part === 'avatar') {
    return <img className={className} src={user.avatar ?? fallbackSrc} alt="" />
  }

  return (
    <span className={className} data-user-id={user.userId} data-scene={context.scene}>
      {user.name ?? user.userId}
    </span>
  )
}

univerAPI.registerComponent(USER_INFO_COMPONENT, HostUserInfo)
```

`UserInfo` pasa los siguientes campos:

- `user`: `{ userId?, name?, avatar?, isAnonymous? }`. `userId` es la identidad de origen y está disponible antes de que se cargue el perfil. Nunca es un ID de sesión de colaboración.
- `part`: `'name'` o `'avatar'`. El componente renderiza cada parte por separado.
- `context`: `{ scene, unitId?, subUnitId?, commentId?, threadId?, versionId?, objectId?, tableId?, fieldId?, recordId? }`. `scene` es uno de `'comment-author'`, `'history-author'`, `'history-filter'`, `'permission-member'`, `'permission-creator'` o `'base-person'`. `unitId` está ausente en los controles independientes que no tienen un documento asociado.
- `avatarSize?`, `fallbackSrc?` y `className?`: indicaciones opcionales de renderizado para los avatares y el elemento de nombre.

`DefaultUserInfo` renderiza el nombre y el avatar integrados y se puede usar en escenas que un host no personaliza. `inheritUserInfoComponent(source, target)` registra el componente de información de usuario del `ComponentManager` de origen en otro gestor de componentes, como una instancia `Univer` secundaria para el historial o la vista previa, de modo que la misma anulación se aplique allí. Registra `DefaultUserInfo` cuando el origen no tiene un componente de información de usuario.

La anulación solo cambia el renderizado. No cambia las menciones persistidas, el texto de búsqueda ni la salida de Canvas. Al igual que con otras anulaciones de componentes, registre antes de que la vista se abra por primera vez. Los cambios de registro no vuelven a renderizar las vistas que ya están montadas.

### Usar como componentes de contenido

#### En la barra lateral

`univerAPI.openSidebar` abre una barra lateral en la interfaz Univer cuyo contenido es un componente registrado.

```tsx
// [!code word:MyCustomSidebarComponent]
// You should register the component at an appropriate time (e.g., after Univer has loaded)
univerAPI.registerComponent('MyCustomSidebarComponent', () => <div>Hello Univer!</div>)

const sidebar = univerAPI.openSidebar({
  header: { title: 'My Sidebar' },
  children: { label: 'MyCustomSidebarComponent' },
  onClose: () => {
    console.log('close')
  },
  width: 360,
})

// Later close the sidebar
sidebar.dispose()
```

Ver [`univerAPI.openSidebar`](/reference/facade/univer#opensidebar).

#### En un cuadro de diálogo

`univerAPI.openDialog` abre un diálogo cuyo contenido es un componente personalizado.

```tsx
// [!code word:MyCustomDialogComponent]
// You should register the component at an appropriate time (e.g., after Univer has loaded)
univerAPI.registerComponent('MyCustomDialogComponent', () => <div>Hello Univer!</div>)

const dialog = univerAPI.openDialog({
  id: 'unique-dialog-id', // The unique identifier for the dialog
  draggable: true,
  width: 300,
  title: { title: 'My Dialog' },
  children: {
    label: 'MyCustomDialogComponent',
  },
  destroyOnClose: true,
  preservePositionOnDestroy: true,
  onClose: () => {},
})

// Later close the dialog
dialog.dispose()
```

Ver [`univerAPI.openDialog`](/reference/facade/univer#opendialog).
