Univer へのコントリビューションに興味をお持ちいただき、ありがとうございます！このガイドは、あなたの始め方をお手伝いします。

## 行動規範

すべてのコントリビューターにとって、フレンドリーで安全、かつ歓迎される環境を提供することをお約束します。すべてのやり取りで、敬意を持ち建設的であってください。

## コントリビューションの方法

### バグの報告

バグ報告を作成する前に、以下を行ってください：

1. [既存の issue](https://github.com/dream-num/univer/issues) を検索して重複を避ける
2. 最新の安定版を使用してバグがまだ存在することを確認する
3. 関連情報を収集する：ブラウザーのバージョン、Node.js のバージョン、エラーメッセージ

報告時には以下を含めてください：

- 明確で説明的なタイトル
- 問題を再現する手順
- 期待される動作と実際の動作
- 最小限の再現例（CodeSandbox、StackBlitz、または GitHub リポジトリ）
- 該当する場合は、スクリーンショットや画面録画

### 機能の提案

機能リクエストは歓迎されます！まずディスカッションを開いて、コミュニティやメンテナーからのフィードバックを集めることをお勧めします。

### コードのコントリビューション

#### 開発環境のセットアップ

1. リポジトリをフォークしてクローンします：
   ```bash
   git clone https://github.com/YOUR_USERNAME/univer.git
   cd univer
   ```

2. 依存関係をインストールします：
   ```bash
   pnpm install
   ```

3. プロジェクトをビルドします：
   ```bash
   pnpm build
   ```

4. テストを実行します：
   ```bash
   pnpm test
   ```

#### プロジェクト構造

```
packages/
  core/           # コア インフラストラクチャ（DI、コマンド システム、ライフサイクル）
  design/         # デザイン システムと基本スタイル
  engine-render/  # Canvas レンダリング エンジン
  engine-formula/ # 数式計算エンジン
  sheets/         # スプレッドシート データ モデルとコア ロジック
  sheets-ui/      # スプレッドシート UI コンポーネント
  docs/           # ドキュメント データ モデル
  docs-ui/        # ドキュメント UI コンポーネント
  slides/         # プレゼンテーション データ モデル
  ui/             # 共有 UI フレームワーク
examples/         # 統合例（React、Vue、Angular など）
```

#### プラグインの作成

Univer はプラグイン アーキテクチャで構築されています。新しい機能を追加するには：

1. `packages/` の下に新しいパッケージを作成するか、スタンドアロンのリポジトリを作成します
2. `Plugin` を拡張するプラグイン クラスを実装します
3. `onStarting` でコマンド、サービス、コントローラーを登録します
4. 公開 API を公開する場合は、ファサード拡張を追加します
5. テストとドキュメントを作成します

ステップバイステップのガイドについては、[カスタム プラグイン チュートリアル](/guides/recipes/tutorials/custom-plugin) を参照してください。

#### コミット規約

[Conventional Commits](https://www.conventionalcommits.org/ja/v1.0.0/) を使用しています：

```
<type>(<scope>): <subject>

<body>

<footer>
```

一般的なタイプ：

- `feat`：新機能
- `fix`：バグ修正
- `docs`：ドキュメントの変更
- `style`：コード スタイルの変更（フォーマット、セミコロンなど）
- `refactor`：コードのリファクタリング
- `perf`：パフォーマンスの改善
- `test`：テストの追加または修正
- `chore`：ビルド プロセスまたは補助ツールの変更

例：
```
feat(sheets): カスタム数値形式のサポートを追加

Closes #1234
```

#### Pull Request のプロセス

1. `dev` ブランチから機能ブランチを作成します
2. 明確で焦点を絞ったコミットを行います
3. 必要に応じてテストを追加または更新します
4. `pnpm lint` と `pnpm test` がパスすることを確認します
5. 変更が公開 API に影響する場合は、ドキュメントを更新します
6. `dev` ブランチに対して Pull Request を開きます
7. PR テンプレートに明確な説明を記入します

### ドキュメントへのコントリビューション

ドキュメントの改善も非常に評価されています。ドキュメントを編集するには：

1. ドキュメントは [documentation リポジトリ](https://github.com/dream-num/documentation) にあります
2. 各ページは対応する `.mdx` ファイルを持っています
3. 既存のスタイルとフォーマットに従ってください
4. 該当する場合は、すべての言語バリアントを更新してください（en-US、zh-CN、zh-TW、ja-JP）
