感谢你对贡献 Univer 的兴趣！本文档将帮助你快速上手。

## 行为准则

我们致力于为所有贡献者提供一个友好、安全和受欢迎的环境。请在所有互动中保持尊重和建设性。

## 如何贡献

### 报告缺陷

在创建缺陷报告之前，请：

1. 搜索 [现有 issue](https://github.com/dream-num/univer/issues) 以避免重复
2. 使用最新稳定版验证该缺陷是否仍然存在
3. 收集相关信息：浏览器版本、Node.js 版本、错误信息

报告时请包含：

- 清晰、描述性的标题
- 复现步骤
- 预期行为与实际行为
- 最小可复现示例（CodeSandbox、StackBlitz 或 GitHub 仓库）
- 如有必要，附上截图或录屏

### 提议新功能

欢迎提交功能请求！建议先开启一个 discussion，收集社区和维护者的反馈。

### 提交代码

#### 开发环境搭建

1. Fork 并克隆仓库：
   ```bash
   git clone https://github.com/YOUR_USERNAME/univer.git
   cd univer
   ```

2. 安装依赖：
   ```bash
   pnpm install
   ```

3. 构建项目：
   ```bash
   pnpm build
   ```

4. 运行测试：
   ```bash
   pnpm test
   ```

#### 项目结构

```
packages/
  core/           # 核心基础设施（依赖注入、命令系统、生命周期）
  design/         # 设计系统和基础样式
  engine-render/  # Canvas 渲染引擎
  engine-formula/ # 公式计算引擎
  sheets/         # 电子表格数据模型和核心逻辑
  sheets-ui/      # 电子表格 UI 组件
  docs/           # 文档数据模型
  docs-ui/        # 文档 UI 组件
  slides/         # 演示文稿数据模型
  ui/             # 共享 UI 框架
examples/         # 集成示例（React、Vue、Angular 等）
```

#### 编写插件

Univer 基于插件架构构建。要添加新功能：

1. 在 `packages/` 下创建新包，或建立独立仓库
2. 实现继承自 `Plugin` 的插件类
3. 在 `onStarting` 中注册命令、服务和控制器
4. 如需暴露公共 API，添加 Facade 扩展
5. 编写测试和文档

请参阅 [自定义插件教程](/guides/recipes/tutorials/custom-plugin) 获取分步指南。

#### 提交规范

我们使用 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/v1.0.0/)：

```
<type>(<scope>): <subject>

<body>

<footer>
```

常用类型：

- `feat`：新功能
- `fix`：缺陷修复
- `docs`：文档变更
- `style`：代码格式调整
- `refactor`：代码重构
- `perf`：性能优化
- `test`：测试相关
- `chore`：构建流程或辅助工具变更

示例：
```
feat(sheets): 增加自定义数字格式支持

Closes #1234
```

#### Pull Request 流程

1. 从 `dev` 分支创建功能分支
2. 进行清晰、专注的提交
3. 根据需要添加或更新测试
4. 确保 `pnpm lint` 和 `pnpm test` 通过
5. 如果变更影响公共 API，更新文档
6. 向 `dev` 分支发起 Pull Request
7. 填写 PR 模板，提供清晰的描述

### 贡献文档

文档改进同样受到高度重视。编辑文档的步骤：

1. 文档位于 [documentation 仓库](https://github.com/dream-num/documentation)
2. 每页对应一个 `.mdx` 文件
3. 遵循现有的风格和格式
4. 如适用，请同时更新所有语言版本（en-US、zh-CN、zh-TW、ja-JP）
