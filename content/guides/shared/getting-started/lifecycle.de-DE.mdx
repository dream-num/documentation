---
title: Lebenszyklus
---

Wenn eine Univer-Anwendung ausgeführt wird, durchläuft sie eine Reihe geordneter Lebenszyklusphasen. Das Verständnis dieser Lebenszyklen ist für Entwickler von entscheidender Bedeutung, da es dabei hilft, festzustellen, wann der Zugriff auf Geschäftsinstanzen und DOM-Elemente sicher ist oder zeitaufwändige asynchrone Vorgänge ausgeführt werden können. Verschiedene Phasen eignen sich für die Ausführung verschiedener Arten von Initialisierungs-, Rendering- und Leistungsoptimierungsaufgaben. Durch das Abhören von Lebenszyklusänderungen können Entwickler zum optimalen Zeitpunkt auf Systemstatusänderungen reagieren und so eine Funktionserweiterung, Leistungsverbesserung oder Optimierung der Benutzererfahrung erreichen.

Der Lebenszyklus von Univer umfasst hauptsächlich die folgenden vier Phasen:

<Mermaid chart="flowchart LR; A([Starting]) --> B([Ready]) --> C([Rendered]) -->D([Steady])" />

1. **Beginnt**: Das System beginnt mit der Initialisierung, wo Plugins ausgeführt werden Abhängigkeitsinjektion und Grundkonfiguration.
2. **Bereit**: Die erste Geschäftsinstanz wird erstellt und Plugins führen die Initialisierung der Kernfunktionalität durch.
3. **Rendered**: Die Schnittstelle wird zum ersten Mal gerendert, was eine sichere Manipulation des DOM oder eine schnittstellenbezogene Initialisierung ermöglicht.
4. **Steady**: Das System geht in einen stabilen Zustand über, der für die Ausführung verzögerter Ladevorgänge, unkritischer Aufgaben und anderer Optimierungsvorgänge geeignet ist.

Verschiedene Arten von Plugins oder Komponenten können unterschiedliche Startzeiten in ihrem Lebenszyklus haben, aber der Gesamtprozess folgt der oben beschriebenen Reihenfolge. Entwickler können Lebenszyklusereignisse verwenden, um den Zeitpunkt des Ladens und Ausführens von Funktionen präzise zu steuern.

<Callout>
Um mehr über das Lebenszyklusdesign von Univer und den spezifischen Startzeitpunkt von Plugins zu erfahren, finden Sie relevante Informationen in [《Univer Architecture#Plugin Lifecycle》](/guides/recipes/architecture/univer#plugin-lifecycle).
</Callout>

## Fassaden-API

### Listener hinzufügen

Univer bietet ein einheitliches Ereignis Abonnementschnittstelle, die es Entwicklern ermöglicht, über die Facade-API auf Lebenszyklusänderungen zu warten:

```typescript
const disposable = univerAPI.addEvent(
  univerAPI.Event.LifeCycleChanged,
  ({ stage }) => {
    if (stage === univerAPI.Enum.LifecycleStages.Steady) {
      // Execute custom logic in the Steady stage
    }
  },
)
```

### Listener entfernen

Um einen Listener zu entfernen, können Sie das zurückgegebene Objekt `disposable` verwenden:

```typescript
disposable.dispose()
```

### Lebenszyklusereignisse und Aufzählungen

Univer stellt Entwicklern die folgenden Lebenszyklusereignisse und Aufzählungen zur Verwendung bereit:

- Ereignisname: `univerAPI.Event.LifeCycleChanged`

- Aufzählungen der Lebenszyklusphasen:
  - `univerAPI.Enum.LifecycleStages.Starting`
  - `univerAPI.Enum.LifecycleStages.Ready`
  - `univerAPI.Enum.LifecycleStages.Rendered`
  - `univerAPI.Enum.LifecycleStages.Steady`

### Beispiel

<Callout type="warning" title="Caution">
`univerAPI.Event.LifeCycleChanged` spiegelt nur Lebenszyklusänderungen wider, daher werden während der `Starting`-Phase keine Ereignisse ausgelöst.
</Callout>

```typescript
const disposable = univerAPI.addEvent(
  univerAPI.Event.LifeCycleChanged,
  ({ stage }) => {
    switch (stage) {
      case univerAPI.Enum.LifecycleStages.Ready:
        console.log('The business instance has been created, you can perform core initialization')
        break
      case univerAPI.Enum.LifecycleStages.Rendered:
        console.log('The interface has been rendered, you can safely manipulate the DOM')
        break
      case univerAPI.Enum.LifecycleStages.Steady:
        console.log('The system is stable, you can perform delayed loading and other optimization operations')
        break
    }
  },
)

// Remove the listener
disposable.dispose()
```
