Embed는 하나의 Univer 문서를 다른 곳에서 편집 할 수 있습니다. 스프레드 시트는 문서에 배치 할 수 있으며 보드에 슬라이드 또는 워크북 탭의베이스. **호스트 문서**는 embed를 포함하고 **아이 문서**은 참조 내용입니다. 각 문서는 자체 데이터 모델을 유지합니다.

## 지원하는 삽입 위치

| 부모 | 위치 | 지원하는 자식 |
| --- | --- | --- |
| Sheets | 워크시트의 부동 개체, 통합 문서 탭 | Docs, Slides, Boards, Bases |
| Docs | 본문 콘텐츠 블록 | Sheets, Slides, Boards, Bases |
| Slides | 페이지의 부동 개체, 페이지 목록 | Sheets, Docs, Boards, Bases |
| Boards | 캔버스의 부동 개체 | Sheets, Docs, Slides, Bases |
| Bases | 테이블 목록 | Sheets, Docs, Slides, Boards |

부동물과 몸 블록은 호스트 내부에 아이를 표시하고 편집은 아이 제품의 기능을 사용합니다. 탭 및 목록 항목은 아이를 페이지로 전환 할 수있는 페이지로 전환합니다. 그 페이지가 활성화되면 메뉴 영역은 어린이로 전송됩니다.

<Callout type="warning">
  내장 기능은 PDF를 지원하지 않고 동일한 제품 유형에 삽입하거나 임베디드 아이 안쪽에 다른 문서를 삽입합니다.
</Callout>

## 플러그인 등록

두 제품 및 UI는 동일한 `Univer` 인스턴스에서 처음 실행해야 합니다. Embed는 핵심 플러그인을 대체하지 않습니다. 시트의 Docs를 삽입하면 시트와 Docs 모두가 필요합니다. [라이센스 구성](/server/license)에 설명된 `UniverLicensePlugin`를 정렬하고 구성하십시오.

```package-install
npm install @univerjs-pro/embed @univerjs-pro/embed-ui
```

기존 애플리케이션에 이러한 가져 오기를 추가하고 문서를 생성하기 전에 플러그인을 등록하십시오. `univer`는 기존 `Univer` 인스턴스입니다.

```ts
import { UniverEmbedPlugin } from '@univerjs-pro/embed'
import { UniverEmbedUIPlugin } from '@univerjs-pro/embed-ui'

import '@univerjs-pro/embed/facade'
import '@univerjs-pro/embed-ui/lib/index.css'

univer.registerPlugin(UniverEmbedPlugin)
univer.registerPlugin(UniverEmbedUIPlugin)
```

기존 `locales` 구성으로 `@univerjs-pro/embed-ui/locale/en-US`의 기본 수출을 Merge합니다. 다른 언어는 자신의 Locale 팩을 사용합니다; [국제화](/guides/sheets/getting-started/i18n)를 참조하십시오.

`@univerjs-pro/embed`는 embed 관계, 참고 해결책 및 Facade API를 제공합니다. `@univerjs-pro/embed-ui`에는 콘테이너, 초점 엇바꾸기 및 메뉴를 제공합니다.`@univerjs-pro/embed-unit-ui`은 참고한 문서를 위한 독립 구경꾼을 제공하고 기본적인 embedding를 위해 요구되지 않습니다.

## 스프레드시트에 문서 삽입

다음과 같은 함수는 같은 `Univer` 인스턴스에서 이미 로드된 워크북과 문서가 활성화된 워크시트에 있는 플로팅 문서를 삽입합니다. `ref`의 아이의 실제 ID를 사용하십시오; `type=doc`는 `unitType`와 일치해야 합니다.

```ts
import type { FUniver } from '@univerjs/core/facade'
import type { FDocument } from '@univerjs/docs/facade'
import type { FWorkbook } from '@univerjs/sheets/facade'

import '@univerjs-pro/embed/facade'
import '@univerjs/docs/facade'
import '@univerjs/sheets/facade'

async function embedDocument(
  univerAPI: FUniver,
  workbook: FWorkbook,
  document: FDocument,
) {
  const embed = univerAPI.createEmbed<FDocument>({
    host: {
      unitId: workbook.getId(),
      surface: univerAPI.Enum.FEmbedHostSurface.SheetFloating,
      context: { subUnitId: workbook.getActiveSheet().getSheetId() },
    },
    content: {
      unitType: univerAPI.Enum.UniverInstanceType.UNIVER_DOC,
      ref: `#unit=${encodeURIComponent(document.getId())}&type=doc`,
    },
  })

  await embed.loadAsync()
  return embed
}
```

`createEmbed()`는 관계를 만들고 호스트의 위치를 설정합니다. `loadAsync()`은 아이를로드하고 Facade를 반환합니다. Callers는 `await`이 기능 및로드 실패를 처리해야합니다. 로컬 참조는 현재 인스턴스에서 대상 문서를 필요로합니다. ID는 혼자 만들거나 문서를 다운로드하지 않습니다.

### 삽입 위치 선택

`univerAPI.Enum.FEmbedHostSurface`에서 `host.surface`를 선택하십시오. `host.context`는 내용이 호스트에 있는 곳을 설명합니다.

| 위치 | 열거형 멤버 | 위치 매개변수 |
| --- | --- | --- |
| 워크시트 부동 개체 | `SheetFloating` | `subUnitId`는 워크 시트를 선택합니다. `placement`은 앵커 모드를 선택하여 기본적으로 위치합니다. |
| 통합 문서 탭 | `SheetTab` | `sheetIndex`, `sheetName` |
| 문서 본문 블록 | `DocBlock` | `startIndex`: 몸의 `dataStream`에서 UTF-16 상쇄; 편집 가능한 몸에 부합하기 위하여 그것을 모십시오 |
| 슬라이드 부동 개체 | `SlideFloating` | `subUnitId`는 페이지, `left`, `top`, `width`, `height`는 위치와 크기 |
| 슬라이드 페이지 목록 | `SlidePage` | `pageIndex`, `pageName` |
| 보드 부동 개체 | `BoardFloating` | `subUnitId`는 페이지, `left`, `top`, `width`, `height`는 위치와 크기 |
| 베이스 테이블 목록 | `BaseTable` | `tableIndex`, `tableName` |

목록의 삽입 지수는 0기반이며, 인덱스가 끝으로 부과됩니다. 플로팅 경계는 브라우저 뷰포트 좌표보다는 문서 모델 좌표를 사용합니다. 스크롤 또는 줌 오프셋을 이 값으로 직접 쓰지 마십시오.

### 자식의 기본 보기 지정

`displayTarget`는 어린이가 호스트에 앉아있는 곳과 관계없이 첫 번째를 보여줍니다. embed가 생성되면 전달하거나 `embed.setDisplayTarget()`로 나중에 변경하십시오.

| 자식 | 기본 보기 매개변수 |
| --- | --- |
| Sheets | `{ subUnitId: 'sheet-id' }` |
| Slides | `{ pageId: 'page-id' }` |
| Bases | `{ tableId: 'table-id', viewId: 'view-id' }`; `dashboardId`도 지원 |

디스플레이 이름보다 안정적인 ID를 사용합니다. 대상이 더 이상 존재하지 않는 경우, 아이는 첫 번째 사용 가능한보기로 돌아갑니다. 아이 내부의 탐색은이 기본을 과도하지 않습니다. 문서와 보드는 `displayTarget`를 허용하지 않습니다.

## 저장과 제거

호스트 스냅 샷은 `resources`의 Embed 플러그인 데이터를 유지해야하며, 호스트의 신체, 도면 또는 목록에서 embed 포지션. 관계는 아이와 기본보기에 대한 참조를 저장합니다. **그것은 자동으로 호스트 스냅 샷으로 아이의 현재 내용을 병합하지 않습니다**. 로컬 저장소를 사용하는 응용 프로그램은 별도로 어린이를 저장하고 참조가 복원 후 해결 될 수 있도록해야합니다.

`univerAPI.listEmbeds({ hostUnitId })`는 호스트의 embeds를 나열하고 `univerAPI.getEmbed({ hostUnitId, embedId })`가 단일 embed를 검색합니다. `embed.remove()`은 호스트에서 embed를 제거; 그것은 아이의 persisted 데이터를 삭제하지 않습니다.

## 협업 문서 로드

서버 문서의 경우 [브라우저 협업 통합](/server/collaboration/browser-integration)를 먼저 완료한 다음 협업 브리지를 등록하십시오.

```package-install
npm install @univerjs-pro/collaboration-embed
```

```ts
import { UniverCollaborationEmbedPlugin } from '@univerjs-pro/collaboration-embed'

univer.registerPlugin(UniverCollaborationEmbedPlugin)
```

이 플러그인은 `UniverCollaborationPlugin`, `UniverCollaborationClientPlugin` 및 `UniverEmbedPlugin`에 따라 달라집니다. 그것은 협업 스냅 샷 서비스를 통해 아이를로드하고 그 아이의 협업 세션에 참여합니다. `#unit=...&type=...`의 실제 서버 문서 ID를 전달하십시오. 기존 [ID 및 인증](/server/collaboration/identity-and-authorization) 설정에 의해 액세스가 유지됩니다.

협업 서비스의 대신 사용자 정의 저장을 사용하려면 `UniverEmbedPlugin`에서 `resourceRefUnitProviderRegistrations`를 구성하여 문서 인스턴스에 대한 참조를 수정합니다.

추가 옵션 및 방법은 [API를 덮어](/reference/facade/embed), [FUniver API를](/reference/facade/univer) 및 [Embed 플러그인](/reference/packages/plugins/univerjs-pro/embed)에 문서화됩니다.
