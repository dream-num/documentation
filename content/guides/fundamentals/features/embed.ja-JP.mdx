Embed では、Univer ドキュメントを別の内部で編集することができます。スプレッドシートは、ドキュメント、ボード上のスライド、またはワークブックタブのベースに配置できます。**ホスト文書**には埋め込みが含まれており、**児童文書**は参照するコンテンツです。各ドキュメントは独自のデータモデルを保持します。

## 対応する埋め込み位置

| 親 | 位置 | 対応する子 |
| --- | --- | --- |
| Sheets | ワークシートの浮動オブジェクト、ワークブックのタブ | Docs、Slides、Boards、Bases |
| Docs | 本文ブロック | Sheets、Slides、Boards、Bases |
| Slides | ページ上の浮動オブジェクト、ページ一覧 | Sheets、Docs、Boards、Bases |
| Boards | キャンバス上の浮動オブジェクト | Sheets、Docs、Slides、Bases |
| Bases | テーブル一覧 | Sheets、Docs、Slides、Boards |

フローティングオブジェクトとボディブロックは、ホスト内の子供を表示し、編集は子供の製品の機能を使用します。タブとリストエントリは、子供を切り替えることができるページに変換します。そのページがアクティブになると、メニューエリアは子供に転送されます。

<Callout type="warning">
  組み込み機能では、PDFをサポートしたり、同じ製品タイプを埋め込んだり、埋め込まれた子供の中に別の文書を埋め込むことはできません。
</Callout>

## プラグインの登録

製品とUIの両方が同じで最初に実行する必要があります。 `Univer` 例えば、 Embed はコアプラグインを置き換えません。スプレッドシートに Docs を埋め込むには、Sheet と Docsの両方が必要です。依存関係バージョンを整列して設定してください。 `UniverLicensePlugin` 記載されている通り [ライセンス構成](/server/license).

```package-install
npm install @univerjs-pro/embed @univerjs-pro/embed-ui
```

これらのインポートを既存のアプリケーションに追加し、ドキュメントを作成する前にプラグインを登録します。 `univer` は既存の `Univer`インスタンスです。

```ts
import { UniverEmbedPlugin } from '@univerjs-pro/embed'
import { UniverEmbedUIPlugin } from '@univerjs-pro/embed-ui'

import '@univerjs-pro/embed/facade'
import '@univerjs-pro/embed-ui/lib/index.css'

univer.registerPlugin(UniverEmbedPlugin)
univer.registerPlugin(UniverEmbedUIPlugin)
```

`@univerjs-pro/embed-ui/locale/en-US`のデフォルトエクスポートを既存の`locales`設定にマージします。他の言語は独自のロケールパックを使用しており、[国際化](/guides/sheets/getting-started/i18n)を参照してください。

`@univerjs-pro/embed`は、埋め込まれた関係、参照の決断およびFacade APIを提供します。 `@univerjs-pro/embed-ui` は容器、焦点の転換およびメニューを提供します。 `@univerjs-pro/embed-unit-ui`のは参照された文書のためのスタンドアローンの視聴者を提供し、基本的な埋め込むことを必要としません。

### 参照ユニットのプレビュー

`preset-sheets-advanced` などのプリセットには、参照ユニットのプレビューは含まれていません。数式の参照選択と、参照データで使用される `ReferencedDataSelector` には、`@univerjs-pro/embed-ui` の `UniverEmbedUIPlugin` が必要です。スタイルシートとロケールを登録して使用します。プリセットからアプリケーションを構成する場合は、プラグインを明示的に登録します。

```ts
import { UniverEmbedUIPlugin } from '@univerjs-pro/embed-ui'

import '@univerjs-pro/embed-ui/lib/index.css'

univer.registerPlugin(UniverEmbedUIPlugin)
```

上記のように `@univerjs-pro/embed-ui/locale/en-US` を既存の `locales` 設定にマージします。このプラグインは数式の参照ピッカーと参照データセレクターの両方を登録します。これがないと、参照ユニットをプレビューしたり、数式の参照から選択したりできません。

## 表にドキュメントを埋め込む

以下の関数は、同じ`Univer`インスタンスに既にロードされているワークブックとドキュメントを受け取り、アクティブなワークシートにフローティング文書を差し込みます。 `ref`の子供の実際のIDを使用してください。 `type=doc`は、`unitType`に一致する必要があります。

```ts
import type { FUniver } from '@univerjs/core/facade'
import type { FDocument } from '@univerjs/docs/facade'
import type { FWorkbook } from '@univerjs/sheets/facade'

import '@univerjs-pro/embed/facade'
import '@univerjs/docs/facade'
import '@univerjs/sheets/facade'

async function embedDocument(
  univerAPI: FUniver,
  workbook: FWorkbook,
  document: FDocument,
) {
  const embed = univerAPI.createEmbed<FDocument>({
    host: {
      unitId: workbook.getId(),
      surface: univerAPI.Enum.FEmbedHostSurface.SheetFloating,
      context: { subUnitId: workbook.getActiveSheet().getSheetId() },
    },
    content: {
      unitType: univerAPI.Enum.UniverInstanceType.UNIVER_DOC,
      ref: `#unit=${encodeURIComponent(document.getId())}&type=doc`,
    },
  })

  await embed.loadAsync()
  return embed
}
```

`createEmbed()`は、関係を生成し、ホスト内の位置を設定します。 `loadAsync()` は、子供をロードし、ファサードを返します。 コールアーは、`await` この機能が必要で、読み込みの失敗を処理します。 ローカルリファレンスでは、現在のインスタンスに存在するターゲット文書が必要です。 ID 単独では、ドキュメントを作成またはダウンロードしません。

### 埋め込み位置を選ぶ

`univerAPI.Enum.FEmbedHostSurface`から`host.surface`を選択します。 `host.context`は、コンテンツがホストに配置されている場所について説明します。

| 位置 | 列挙値 | 位置のパラメーター |
| --- | --- | --- |
| ワークシートの浮動オブジェクト | `SheetFloating` | `subUnitId`はワークシートを選択します。 `placement` はアンカーモードを選択します。 |
| ワークブックのタブ | `SheetTab` | `sheetIndex`、`sheetName` |
| 本文ブロック | `DocBlock` | `startIndex`:体の`dataStream`のUTF-16オフセット;編集可能なボディにそれをomit |
| スライドの浮動オブジェクト | `SlideFloating` | `subUnitId` はページ、`left`、`top`、`width`、`height` は位置とサイズ |
| スライドのページ一覧 | `SlidePage` | `pageIndex`、`pageName` |
| ボードの浮動オブジェクト | `BoardFloating` | `subUnitId` はページ、`left`、`top`、`width`、`height` は位置とサイズ |
| ベースのテーブル一覧 | `BaseTable` | `tableIndex`、`tableName` |

リストのインデックスはゼロベースで、インデックスが最後に追加されるのを省略します。フローティング境界は、ブラウザのビューポート座標ではなく、ドキュメントモデルが調整されます。スクロールやズームオフセットはこれらの値に直接書きません。

### 子の初期ビューを指定する

`displayTarget`は、子供がホストに座っている場所に関係なく、子供が最初に表示するものを設定します。埋め込まれたときにそれを渡すか、`embed.setDisplayTarget()`で後で変更します。

| 子 | 初期ビューのパラメーター |
| --- | --- |
| Sheets | `{ subUnitId: 'sheet-id' }` |
| Slides | `{ pageId: 'page-id' }` |
| Bases | `{ tableId: 'table-id', viewId: 'view-id' }`。`dashboardId` にも対応 |

表示名ではなく、安定した ID を使用します。 ターゲットが存在しなくなった場合、子供は最初の利用可能なビューに戻ります。 子供の中のナビゲーションは、このデフォルトを上書きしません。 Docs と Boards は `displayTarget` を受け入れません。

## 保存と削除

ホストのスナップショットは、`resources` の Embed プラグインのデータと、ホストの体内の埋め込まれた位置、図、またはリストを保持しなければなりません。関係は、子供とデフォルトのビューへの参照を格納します。 **子の現在のコンテンツをホストスナップショットに自動的にマージしません。**。ローカルストレージを使用するアプリケーションは、子供を個別に保存し、その参照が復元後に解決することができることを確実にしなければなりません。

`univerAPI.listEmbeds({ hostUnitId })` はホストの埋め込みをリストし、`univerAPI.getEmbed({ hostUnitId, embedId })`は単一の埋め込みを取得します。 `embed.remove()`がホストから埋め込まれた埋め込みを削除します。それは子供の持続的なデータを削除します。

## 共同編集ドキュメントの読み込み

サーバのドキュメントでは、[ブラウザのコラボレーション統合](/server/collaboration/browser-integration) を最初に完成させ、コラボレーションブリッジを登録します。

```package-install
npm install @univerjs-pro/collaboration-embed
```

```ts
import { UniverCollaborationEmbedPlugin } from '@univerjs-pro/collaboration-embed'

univer.registerPlugin(UniverCollaborationEmbedPlugin)
```

このプラグインは`UniverCollaborationPlugin`、`UniverCollaborationClientPlugin`および`UniverEmbedPlugin`に依存します。 コラボレーションスナップショットサービスを介して子供をロードし、その子供のコラボレーションセッションに参加します。 `#unit=...&type=...`で実際のサーバー文書IDを渡します。 アクセスは既存の[アイデンティティと権限](/server/collaboration/identity-and-authorization)セットアップによって管理されています。

コラボレーションサービスの代わりにカスタムストレージを使用するには、`UniverEmbedPlugin` で `resourceRefUnitProviderRegistrations`を設定して、ドキュメントインスタンスに解決します。

[組み込みAPI](/reference/facade/embed)、[FUniver APIの特長](/reference/facade/univer)および[プラグイン API を埋め込む](/reference/packages/plugins/univerjs-pro/embed)で追加のオプションとメソッドを文書化します。
