## Qu’est-ce qu’Univer PDFs ?

Univer PDFs est le produit PDF dans Univer Office SDK. Un PDF devient une unité formelle `UNIVER_PDF` : le document source importé est conservé tel quel, et les modifications acceptées sont stockées dans une couche d'édition durable séparée. L'interface utilisateur du navigateur rend les deux couches comme un document continu.

Univer PDFs est un type d'unité à l'intérieur de [Web SDK](/guides/sheets), pas un SDK de son propre. Web SDK fournit le visionneur et le traitement de contenu sans tête. Collaboration et conversion de fichiers font partie de [Server SDK](/server), et les flux de travail des agents appartiennent à [AI SDK](/ai).

Utilisez les PDF Univer lorsqu'une application doit créer ou ouvrir des PDF, ajouter du contenu modifiable, préserver l'apparence d'un PDF importé, collaborer sur les changements, exporter le résultat ou remettre le document ouvert au flux de travail d'impression du navigateur.

<Callout type="warning" title="Mode greffon seulement">
  Il n'y a pas de paquet PDF prédéfini. Vous enregistrez explicitement le modèle PDF, l'interface utilisateur et tout plugin optionnel.
</Callout>

## Compatibilité avec les navigateurs

Web SDK compile avec une cible Chrome 88, mais cela ne signifie pas que chaque environnement courant est entièrement pris en charge. Web SDK est maintenu pour fonctionner correctement dans les navigateurs suivants et les versions Node.js:

| Edge | Firefox | Chrome | Safari | Electron |
| ---- | ------- | ------ | ------ | -------- |
| >=88 | >=90    | >=88   | >=14.1 | >=12     |

<Callout type="warning">
  Web SDK dépend de `Intl.Segmenter`. Si le navigateur ou l'exécution ne le supporte pas, ajoutez un polyfill en premier. Le polyfill recommandé est `@formatjs/intl-segmenter` .
</Callout>

Lorsqu'un problème de compatibilité se produit, essayez d'abord le polyfill correspondant. Si le problème persiste, [soumettre un problème](https://github.com/dream-num/univer/issues/new/choose).

## Compatibilité avec Node.js

<Callout type="warning">
  Ceci ne s'applique qu'à l'exécution Web SDK à l'intérieur de Node.js. Il ne couvre pas l'exécution de Web SDK dans un navigateur à travers un outil de construction basé sur Node.js.
</Callout>

Web SDK fonctionne dans Node.js v18.17.0 et plus tard.

## Points forts

- Le modèle d'unité PDF conserve le document source, la structure des pages, les ressources et l'intention d'édition durable dans `IPdfUnitData`.
- Les pages peuvent être consultées et insérées, et le texte, les listes, les tableaux, les images, les diviseurs et les annotations peuvent être modifiés.
- L'outil de travail du navigateur rend les pages PDF et les vignettes, et gère la sélection, les contrôles d'édition, le comportement du presse-papiers et l'interface utilisateur de l'inspecteur.
- Les changements acceptés passent par des commandes durables et des lots de mutations, alors sauvegardez, défaire et redémarrer fonctionnent contre le même modèle.
- Le Facade API crée, trouve, modifie et enregistre des unités PDF grâce à des objets PDF, page, élément et texte natif.

## Comment lire la documentation

La navigation de documentation est à gauche. Les pages sont commandées de base à avancée, de sorte qu'elles peuvent être lues en séquence pendant la construction d'une application, ou sautées dans les sections qu'un cas d'utilisation nécessite. Les PDF Univer peuvent également être sélectionnés en haut de la barre latérale.

Pour trouver une autre page, utilisez la barre de recherche en haut ou le raccourci de recherche (Ctrl+K ou Cmd+K).

Commencez avec le guide [Démarrage rapide](/guides/pdfs/getting-started/installation).

## Connaissances préalables

La documentation est écrite pour être accessible, mais elle suppose une base de référence afin qu'elle puisse rester concentrée sur Web SDK.

Les lecteurs tirent le meilleur parti de la documentation avec une compréhension de base de JavaScript et de l'écosystème environnant.

Si vous prévoyez d'exécuter Web SDK sur Node.js, une compréhension de base de Node.js est également recommandée.

La collaboration, l'historique partagé, les commentaires et la conversion de fichiers sont des fonctionnalités côté serveur. Ils sont activés par la composition de modules de [Univer Server SDK](/server) dans le moteur de recherche; l'authentification, les permissions, le stockage et le déploiement restent la responsabilité de l'application.

Web SDK est conçu pour être étendu, de sorte qu'il peut être adapté à l'application cible.
