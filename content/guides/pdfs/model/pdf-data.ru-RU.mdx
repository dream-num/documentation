## IPdfUnitData

`IPdfUnitData` - это снимок, сохраняемый для одного блока `UNIVER_PDF`. Схема - `univer-pdf-unit`, текущая версия схемы - `1` и номера версий начинаются с `1` .

| Свойство            | Тип                                           | Назначение                                                                              |
| ------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------- |
| `schema` | `'univer-pdf-unit'` | Стабильный идентификатор для схемы блока PDF |
| `schemaVersion`     | `1`                                           | Текущая версия схемы модуля PDF                                                         |
| `id`                | `string`                                      | Идентификатор, общий для хранилища, совместной работы, ресурсов и экспорта              |
| `rev` | `number` | Уполномоченный пересмотр подразделения |
| `name` | `string` | Имя PDF, отображаемое пользователям |
| `sourceDocumentRef` | `IPdfSourceDocumentRef` | Неизменное происхождение импортного артефакта PDF |
| `document` | `IPdfDocument` | Импортный базовый уровень или базовый уровень чистого документа |
| `editState` | `IPdfDurableEditState` | Принятые и сохраняющиеся намерения редактирования |
| `documentShell?`    | `IPdfDocumentShell`                           | Небольшой каталог страниц и индекс фрагментов для PDF с блочным хранением               |
| `fragmentIndex?`    | `IPdfUnitFragmentIndex`                       | Логическое сопоставление страниц и общих данных с сохранёнными фрагментами              |
| `resourceBindings?` | `Record<string, PdfDurableResourceBinding>`   | Сохраняемые привязки нативных или управляемых Univer ресурсов                           |
| `fragmentBindings?` | `Record<string, IPdfFragmentArtifactBinding>` | Привязки файлов времени выполнения для независимо загружаемых фрагментов                |
| `capabilityReport?` | `IPdfCapabilityReport` | Решения по импорту и времени выполнения о поддерживаемых действиях и запасных вариантах |
| `metadata?`         | `Record<string, PdfJsonValue>`                | Метаданные приложения или интеграции                                                    |

## Основа и слой правок

Импортируемый `document` является неизменяемым базовым уровнем. Редактирование никогда не переписывает его на месте. Замена текста, вставленные объекты, изменения страницы, подавление источников и управляемые ресурсы регистрируются в `editState`, который затем прогнозируется по базовому уровню для рендеринга и экспорта.

Разделение этих двух слоев сохраняет происхождение исходного PDF-контента и позволяет экспортерам решать, какие операции с источником копировать, подавлять или заменять.

<Callout type="warning" title="Выберите правильный взгляд">
  `pdf.getDocument()` возвращает импортную базовую линию. `pdf.save()` возвращается полный снимок блока с его прочным состоянием редактирования. Продвинутые интеграции могут получить текущую проекцию от `pdf.getModel().getMaterializedDocument()`.
</Callout>

## Создание и сохранение снимка

```ts
const pdf = univerAPI.createPdf({ name: 'Untitled contract' })
const page = pdf.getPageByIndex(0)

page?.insertTextBox({
  text: 'Draft',
  left: 36,
  top: 36,
})

const snapshot = pdf.save()
await applicationStorage.save(snapshot.id, snapshot)
```

Восстановите полный снимок через фасад:

```ts
const snapshot = await applicationStorage.load('pdf-unit-id')
const pdf = univerAPI.createPdf(snapshot)
```

После запуска блока не модифицируйте объект с моментальным снимком. Используйте вместо этого методы Фасада или зарегистрированные команды, чтобы проверка, отмена и переделка, сотрудничество и намерение экспорта оставались последовательными.

## PDF с блочным хранением

Большие PDF-файлы, или PDF-файл, хранящиеся удаленно, могут использовать `documentShell`, `fragmentIndex` и `fragmentBindings`. Оболочка сохраняет размеры страниц, порядок, метки и идентификаторы блоков, доступные до загрузки любого тела страницы. Провайдеры материализуют фрагменты страниц и общие фрагменты, когда им нужен пользовательский интерфейс.

Эти поля являются контрактами на обмен и хранение.Код приложения обычно получает их из служб обмена PDF или совместной работы и сохраняет их неизменными.
