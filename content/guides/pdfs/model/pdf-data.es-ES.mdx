## IPdfUnitData

`IPdfUnitData` es la instantánea persistió para una unidad `UNIVER_PDF`. El esquema es `univer-pdf-unit`, la versión actual del esquema es `1` y los números de revisión comienzan en `1` .

| Propiedad           | Tipo                                          | Finalidad                                                                             |
| ------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------- |
| `schema` | `'univer-pdf-unit'` | Identificador estable para el esquema de unidad PDF |
| `schemaVersion`     | `1`                                           | Versión actual del esquema de unidad PDF                                              |
| `id`                | `string`                                      | Identidad compartida por almacenamiento, colaboración, recursos y exportación         |
| `rev` | `number` | Revisión autorizada de la unidad |
| `name` | `string` | Nombre PDF mostrado a los usuarios |
| `sourceDocumentRef` | `IPdfSourceDocumentRef` | Probación inmutable del artefacto PDF importado |
| `document` | `IPdfDocument` | Base de referencia importada o la base de un documento en blanco |
| `editState` | `IPdfDurableEditState` | Intención de edición aceptada y persistente |
| `documentShell?`    | `IPdfDocumentShell`                           | Directorio de páginas pequeño e índice de fragmentos para PDF respaldados por bloques |
| `fragmentIndex?`    | `IPdfUnitFragmentIndex`                       | Asignación lógica de páginas y datos compartidos a fragmentos almacenados             |
| `resourceBindings?` | `Record<string, PdfDurableResourceBinding>`   | Enlaces persistentes a recursos nativos o administrados por Univer                    |
| `fragmentBindings?` | `Record<string, IPdfFragmentArtifactBinding>` | Enlaces de archivos de ejecución para fragmentos cargados de forma independiente      |
| `capabilityReport?` | `IPdfCapabilityReport` | Importar y ejecutar decisiones sobre acciones apoyadas y retrocesos |
| `metadata?`         | `Record<string, PdfJsonValue>`                | Metadatos de la aplicación o integración                                              |

## Base y capa de edición

El `document` importado es una base de referencia inmutable. La edición nunca lo reescribirá en su lugar. Los reemplazos de texto, objetos insertados, cambios de página, supresiones de fuentes y recursos gestionados se registran en `editState`, que se proyecta sobre la base de referencia para la renderización y exportación.

Separar las dos capas preserva la procedencia del contenido nativo de PDF y permite a los exportadores decidir qué operaciones de origen copiar, suprimir o reemplazar.

<Callout type="warning" title="Elija la vista correcta">
  `pdf.getDocument()` devuelve la base importada. `pdf.save()` vuelve la instantánea completa de la unidad con su estado de edición duradero. Las integraciones avanzadas pueden obtener la proyección actual de `pdf.getModel().getMaterializedDocument()`.
</Callout>

## Crear y conservar una instantánea

```ts
const pdf = univerAPI.createPdf({ name: 'Untitled contract' })
const page = pdf.getPageByIndex(0)

page?.insertTextBox({
  text: 'Draft',
  left: 36,
  top: 36,
})

const snapshot = pdf.save()
await applicationStorage.save(snapshot.id, snapshot)
```

Restaure la instantánea completa mediante Facade:

```ts
const snapshot = await applicationStorage.load('pdf-unit-id')
const pdf = univerAPI.createPdf(snapshot)
```

Después de que la unidad esté funcionando, no modifique un objeto de instantáneas. Utilice métodos Facade o comandos registrados en su lugar, de modo que la validación, deshacer y redo, colaboración y intención de exportación sigan siendo consistentes.

## PDF respaldados por bloques

Los grandes archivos PDF, o PDF almacenados remotamente, pueden utilizar `documentShell`, `fragmentIndex` y `fragmentBindings`. La cáscara mantiene los tamaños de la página, orden, etiquetas y ID de bloqueo disponibles antes de que se cargue cualquier cuerpo de página. Los proveedores materializan fragmentos de página y fragmentos compartidos cuando la interfaz de usuario los necesita.

Estos campos son contratos de intercambio y almacenamiento. El código de aplicación normalmente los obtiene de los servicios de intercambio o colaboración en PDF y los persiste sin cambios.
