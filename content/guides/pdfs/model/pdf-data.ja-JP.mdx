## IPdfUnitData

`IPdfUnitData` スナップショットは、シングルのために主張されます `UNIVER_PDF` 単位。スキーマはあります `univer-pdf-unit`、現在のスキーマバージョンは `1`、およびリビジョン番号が起動します。 `1`.

| プロパティ          | 型                                            | 用途                                                                      |
| ------------------- | --------------------------------------------- | ------------------------------------------------------------------------- |
| `schema` | `'univer-pdf-unit'` | PDFユニットスキーマの安定識別子 |
| `schemaVersion`     | `1`                                           | 現在の PDF ユニットスキーマバージョン                                     |
| `id`                | `string`                                      | ストレージ、共同編集、リソース、エクスポートで共有する識別子              |
| `rev` | `number` | ユニットの権威的なリビジョン |
| `name` | `string` | ユーザに表示されているPDF名 |
| `sourceDocumentRef` | `IPdfSourceDocumentRef` | インポートされたPDFアーティファクトの著しい実績 |
| `document` | `IPdfDocument` | インポートされたベースライン、または空白の文書のベースライン |
| `editState` | `IPdfDurableEditState` | 受け入れられ、主張された編集の意図 |
| `documentShell?`    | `IPdfDocumentShell`                           | ブロックベース PDF 用の小さなページディレクトリとフラグメントインデックス |
| `fragmentIndex?`    | `IPdfUnitFragmentIndex`                       | ページおよび共有データから保存済みフラグメントへの論理マッピング          |
| `resourceBindings?` | `Record<string, PdfDurableResourceBinding>`   | 永続的なネイティブリソースまたは Univer 管理リソースのバインディング      |
| `fragmentBindings?` | `Record<string, IPdfFragmentArtifactBinding>` | 個別に読み込むフラグメント用のランタイムファイルバインディング            |
| `capabilityReport?` | `IPdfCapabilityReport` | サポートされているアクションとフォールバックに関するインポートとランタイムの決定 |
| `metadata?`         | `Record<string, PdfJsonValue>`                | アプリケーションまたは統合のメタデータ                                    |

## ベースラインと編集レイヤー

インポートされた`document`は、不変なベースラインです。 編集は、その場所に書き換えることはありません。 テキストの置換、インサートされたオブジェクト、ページの変更、ソースの抑制、および管理されたリソースは、`editState`で記録され、レンダリングとエクスポートのためのベースライン上に投影されます。

2つの層を分離すると、ネイティブPDFコンテンツの実証を保持し、輸出業者がどのソース操作をコピー、抑制、または交換するかを決定します。

<Callout type="warning" title="正しいビューを選ぶ">
  `pdf.getDocument()`はインポートされたベースラインを返します。 `pdf.save()` は、その耐久性のある編集状態で完全なユニットスナップショットを返します。 高度な統合は、`pdf.getModel().getMaterializedDocument()`から現在の投影を得ることができます。
</Callout>

## スナップショットを作成して永続化する

```ts
const pdf = univerAPI.createPdf({ name: 'Untitled contract' })
const page = pdf.getPageByIndex(0)

page?.insertTextBox({
  text: 'Draft',
  left: 36,
  top: 36,
})

const snapshot = pdf.save()
await applicationStorage.save(snapshot.id, snapshot)
```

Facade を通じて完全なスナップショットを復元します。

```ts
const snapshot = await applicationStorage.load('pdf-unit-id')
const pdf = univerAPI.createPdf(snapshot)
```

ユニットが実行された後、スナップショットオブジェクトを変更しません。ファサードメソッドや登録されたコマンドを使用して、バリデーション、undo、redo、コラボレーション、およびエクスポートインテントが一貫して残します。

## ブロックベース PDF

大容量のPDF、またはリモートで保存されたPDFは、`documentShell`、`fragmentIndex`および`fragmentBindings`を使用できます。 シェルは、ページサイズ、注文、ラベル、およびブロックIDをロードする前に保持します。 UIが必要とするときに、ページフラグメントと共有フラグメントを配信します。

これらのフィールドは、交換とストレージ契約です。 アプリケーションコードは通常、PDF交換またはコラボレーションサービスから取得し、変更されていないことを主張します。
