## IPdfUnitData

`IPdfUnitData` 是單個 `UNIVER_PDF` 單元持久化後的快照。其 schema 為 `univer-pdf-unit`，當前 schema 版本為 `1`，修訂號從 `1` 開始。

| 屬性                | 類型                                          | 用途                                      |
| ------------------- | --------------------------------------------- | ----------------------------------------- |
| `schema` | `'univer-pdf-unit'` | PDF 單元 schema 的穩定標識 |
| `schemaVersion` | `1` | 當前 PDF 單元 schema 版本 |
| `id` | `string` | 儲存、協作、資源和匯出共用的標識 |
| `rev` | `number` | 單元的權威修訂號 |
| `name` | `string` | 展示給使用者的 PDF 名稱 |
| `sourceDocumentRef` | `IPdfSourceDocumentRef`                       | 匯入 PDF 成品的不可變來源資訊             |
| `document` | `IPdfDocument` | 匯入的基線，或空白文件的基線 |
| `editState`         | `IPdfDurableEditState`                        | 已接受並持久化的編輯意圖                  |
| `documentShell?`    | `IPdfDocumentShell`                           | 用於區塊型 PDF 的小型頁面目錄和片段索引   |
| `fragmentIndex?`    | `IPdfUnitFragmentIndex`                       | 從頁面和共用資料到已儲存片段的邏輯對應    |
| `resourceBindings?` | `Record<string, PdfDurableResourceBinding>`   | 持久化的原生或 Univer 管理資源繫結        |
| `fragmentBindings?` | `Record<string, IPdfFragmentArtifactBinding>` | 獨立載入片段的執行階段檔案繫結            |
| `capabilityReport?` | `IPdfCapabilityReport` | 針對支援的操作和回退方案的匯入與執行時決策 |
| `metadata?`         | `Record<string, PdfJsonValue>`                | 應用程式或整合中繼資料                    |

## 基線與編輯層

匯入的 `document` 是不可變基線，編輯不會就地重寫它。文字替換、插入物件、頁面變更、源抑制和託管資源記錄在 `editState` 中，渲染和匯出時再投影到基線上。

將兩者分開可以保留原生 PDF 內容的來源資訊，也讓匯出器能夠決定哪些源操作需要複製、抑制還是替換。

<Callout type="warning" title="選擇正確的檢視">
  `pdf.getDocument()` 返回匯入的基線。`pdf.save()` 返回包含持久化編輯狀態的完整單元快照。高階整合可以透過 `pdf.getModel().getMaterializedDocument()` 取得當前投影。
</Callout>

## 建立並持久化快照

```ts
const pdf = univerAPI.createPdf({ name: 'Untitled contract' })
const page = pdf.getPageByIndex(0)

page?.insertTextBox({
  text: 'Draft',
  left: 36,
  top: 36,
})

const snapshot = pdf.save()
await applicationStorage.save(snapshot.id, snapshot)
```

透過 Facade 還原完整快照：

```ts
const snapshot = await applicationStorage.load('pdf-unit-id')
const pdf = univerAPI.createPdf(snapshot)
```

單元執行後，不要修改快照物件，應改用 Facade 方法或已註冊的命令，以確保校驗、撤銷重做、協作和匯出意圖保持一致。

## 區塊型 PDF

大型 PDF 或遠端儲存的 PDF 可以使用 `documentShell`、`fragmentIndex` 和 `fragmentBindings`。Shell 在載入任何頁面正文之前就能提供頁面大小、順序、標籤和塊 ID。UI 需要時，Provider 會物化頁面分片和共享分片。

這些欄位是 Exchange 和儲存層的契約。應用程式碼通常從 PDF Exchange 或協作服務取得這些欄位，並原樣持久化。
