## Структура документа

`IPdfDocument` содержит нормализованную модель документа PDF:

- `pages` хранит порядок страницы, размер, вращение, слои, ярлыки и нативные PDF-боксы.
- `objects` хранит семантические объекты документа.
- `displayLists` сохраняет операции PDF уровня рендеринга и сохраняет верность исходному файлу.
- `textStories` сохраняет редактируемый текст в виде потока, отдельно от группировки PDF-глифов, которая не является стабильной.
- `assets`, `styles` и `native` сохраняют многоразовые ресурсы и ресурсы, специфичные для источника.
- `sources`, `edits` и `exportPlan` записывают, где возник контент и что должен делать экспорт.

Во время импорта PDF не каждая операция с видимым источником становится редактируемым элементом Фасада.Нативный контент остается в списках дисплеев до тех пор, пока пользовательское действие не продвигает или не заменяет его.

## Страницы

`FPdf` читает страницы в материализованном порядке и может вставлять пустые страницы:

```ts
const pages = pdf.getPages()
const firstPage = pdf.getPageByIndex(0)
const pageById = firstPage ? pdf.getPageById(firstPage.getId()) : null
const appendedPage = pdf.insertPage()
```

`insertPage(index)` принимает целое число от `0` через текущий подсчет страниц. Новая страница наследует размер, вращение и PDF-боксы своего соседа. Если соседа нет, страница использует A4, что составляет 595 на 842 пункта.

## Нативное содержимое и редактируемые наложения

`FPdfPage.getElements()` возвращает прочные редактируемые накладки в Z-порядке. Напечатанные аксессуары ниже фильтруют тот же накладной слой:

| Метод доступа      | Обёртка фасада   |
| ------------------ | ---------------- |
| `getTextBoxes()`   | `FPdfTextBox`    |
| `getParagraphs()`  | `FPdfParagraph`  |
| `getLists()`       | `FPdfList`       |
| `getTables()`      | `FPdfTable`      |
| `getImages()`      | `FPdfImage`      |
| `getDividers()`    | `FPdfDivider`    |
| `getAnnotations()` | `FPdfAnnotation` |

`getTextSpans()` ведет себя по-разному. Он перечисляет снимки видимых нативных текстовых операций. Звонок `replaceText()` на пролете подавляет нативную операцию и создает новый редактируемый текстовый ящик.

## Системы координат

Основная модель и общественный фасад используют различные блоки по дизайну:

| Граница                                                          | Единицы и начало координат                                              |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Позиции и размеры фасада, пути аннотаций и ширина штрихов | PDF точки, расположенные сверху слева |
| Геометрия страниц и объектов основной модели | EMU, происхождение вверху слева |
| Импортированные `pdfBoxes` и сопоставления с нативным источником | Пространство пользователя PDF, начало внизу слева |

Прикладной код использует `getTransform`, `setPosition`, `setSize`, `setRotation` и типизированные варианты вставки Facade.`ptToEmu`, `emuToPt` и связанные с ними помощники преобразования необходимы только при построении данных модели более низкого уровня.

## Публичные ограничения редактирования

Фасад проверяет несколько ограничений модели:

- Ширина и высота должны быть положительными конечными значениями. Позиции и вращения должны быть конечными.
- Уровни списка варьируются от `0` до `8`, и начальный номер упорядоченного списка должен быть положительным целым числом.
- Таблица должна иметь положительные целочисленные размеры и содержать не более 10 000 клеток.
- Вставка аннотаций через фасад поддерживает выделение цветом, подчёркивание, зачёркивание, волнистое подчёркивание и рисование от руки.
- Непрозрачность изображения колеблется от `0` до `1`, а прямоугольник урожая должен иметь положительную площадь.
- В текстовых диапазонах используются офсеты UTF-16 с инклюзивным началом и эксклюзивным концом.

Примеры для конкретных задач см. в разделе [Редактирование PDF](/guides/pdfs/features/core/editing).
