## IPdfUnitData

`IPdfUnitData`는 단일 `UNIVER_PDF` 단위에 대한 스냅 샷 persisted입니다. 스키마는 `univer-pdf-unit`이며, 현재 스키마 버전은 `1`이고, `1`에서 개정 번호 시작.

| 속성                | 유형                                          | 용도                                                           |
| ------------------- | --------------------------------------------- | -------------------------------------------------------------- |
| `schema` | `'univer-pdf-unit'` | PDF 단위 스키마를 위한 안정적인 식별자 |
| `schemaVersion`     | `1`                                           | 현재 PDF 유닛 스키마 버전                                      |
| `id`                | `string`                                      | 저장소, 협업, 리소스 및 내보내기에서 공유하는 식별자           |
| `rev` | `number` | 단위의 권한 개정 |
| `name` | `string` | PDF 이름 사용자가 표시된 |
| `sourceDocumentRef` | `IPdfSourceDocumentRef` | 수입된 PDF artifact의 Immutable 입증 |
| `document` | `IPdfDocument` | 수입된 기본, 또는 공백 문서의 기본 |
| `editState` | `IPdfDurableEditState` | 수락 및 persisted 편집 의도 |
| `documentShell?`    | `IPdfDocumentShell`                           | 블록 기반 PDF를 위한 작은 페이지 디렉터리 및 프래그먼트 인덱스 |
| `fragmentIndex?`    | `IPdfUnitFragmentIndex`                       | 페이지 및 공유 데이터에서 저장된 프래그먼트로의 논리적 매핑    |
| `resourceBindings?` | `Record<string, PdfDurableResourceBinding>`   | 영속적인 네이티브 또는 Univer 관리 리소스 바인딩               |
| `fragmentBindings?` | `Record<string, IPdfFragmentArtifactBinding>` | 독립적으로 불러온 프래그먼트를 위한 런타임 파일 바인딩         |
| `capabilityReport?` | `IPdfCapabilityReport` | 지원된 행동과 낙관에 대한 수입 및 실행 결정 |
| `metadata?`         | `Record<string, PdfJsonValue>`                | 애플리케이션 또는 통합 메타데이터                              |

## 기준 문서 및 편집 레이어

수입된 `document`는 immutable 지선입니다. 편집은 결코 장소에서 그것을 다시 쓰지 않습니다. 원본 보충, 삽입한 목표, 페이지 변화, 근원 억제 및 관리한 자원은 `editState`에서 기록됩니다, 그 때 연출과 수출을 위한 지선에 계획됩니다.

2개의 층을 분리하는 것은 기본 PDF 내용의 입증을 보존하고 수출업자가 사본, 억제하거나 대체하기 위하여 어떤 근원 가동을 결정할 것을 허용합니다.

<Callout type="warning" title="정확한 보기를 선택하십시오.">
  `pdf.getDocument()`는 수입한 지선을 반환합니다. `pdf.save()`은 튼튼한 편집 국가로 완전한 단위 스냅샷을 반환합니다. 진보된 통합은 `pdf.getModel().getMaterializedDocument()`에서 현재 투영을 얻을 수 있습니다.
</Callout>

## 스냅샷 만들기 및 저장

```ts
const pdf = univerAPI.createPdf({ name: 'Untitled contract' })
const page = pdf.getPageByIndex(0)

page?.insertTextBox({
  text: 'Draft',
  left: 36,
  top: 36,
})

const snapshot = pdf.save()
await applicationStorage.save(snapshot.id, snapshot)
```

퍼사드를 통해 전체 스냅샷을 복원하세요.

```ts
const snapshot = await applicationStorage.load('pdf-unit-id')
const pdf = univerAPI.createPdf(snapshot)
```

단위가 실행되면 스냅 샷 객체를 수정하지 마십시오. Facade 방법 또는 등록 명령을 대신 사용하여 유효성 검사, undo 및 redo, 공동 작업 및 수출 의도가 일관성 유지됩니다.

## 블록 기반 PDF

대용량 PDF 또는 PDF는 원격으로 저장되며 `documentShell`, `fragmentIndex` 및 `fragmentBindings`를 사용할 수 있습니다. 쉘은 페이지 크기, 주문, 라벨 및 블록 ID를 모든 페이지 본체가 로드되기 전에 유지합니다. 공급자는 UI가 필요할 때 페이지 파편 및 공유 파편을 지정합니다.

이 필드는 교환 및 저장 계약입니다. 응용 코드는 일반적으로 PDF 교환 또는 협업 서비스에서 그들을 얻고 변경되지 않습니다.
