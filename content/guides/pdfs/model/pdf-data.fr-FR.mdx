## IPdfUnitData

`IPdfUnitData` est l'instantané persistant pour une seule unité `UNIVER_PDF`. Le schéma est `univer-pdf-unit`, la version actuelle du schéma est `1`, et les numéros de révision commencent à `1`.

| Propriété           | Type                                          | Rôle                                                                                                     |
| ------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `schema` | `'univer-pdf-unit'` | Identificateur stable pour le schéma de l'unité PDF |
| `schemaVersion`     | `1`                                           | Version actuelle du schéma d'une unité PDF                                                               |
| `id`                | `string`                                      | Identité partagée par le stockage, la collaboration, les ressources et l'exportation                     |
| `rev` | `number` | Révision autorisée de l'unité |
| `name` | `string` | Nom PDF indiqué aux utilisateurs |
| `sourceDocumentRef` | `IPdfSourceDocumentRef` | Origine immuable de l'artefact PDF importé |
| `document` | `IPdfDocument` | Données de référence importées ou données de base d'un document vierge |
| `editState` | `IPdfDurableEditState` | L'intention d'édition acceptée et persistante |
| `documentShell?`    | `IPdfDocumentShell`                           | Petit répertoire de pages et index de fragments pour les PDF stockés par blocs                           |
| `fragmentIndex?`    | `IPdfUnitFragmentIndex`                       | Mappage logique des pages et des données partagées vers les fragments stockés                            |
| `resourceBindings?` | `Record<string, PdfDurableResourceBinding>`   | Liaisons persistantes de ressources natives ou gérées par Univer                                         |
| `fragmentBindings?` | `Record<string, IPdfFragmentArtifactBinding>` | Liaisons de fichiers à l'exécution pour les fragments chargés indépendamment                             |
| `capabilityReport?` | `IPdfCapabilityReport` | Décisions d'importation et d'exécution concernant les actions soutenues et les replis |
| `metadata?`         | `Record<string, PdfJsonValue>`                | Métadonnées de l'application ou de l'intégration                                                         |

## Référence et couche de modifications

La `document` importée est une base de référence immuable. L'édition ne la réécrit jamais en place. Les remplacements de texte, les objets insérés, les modifications de page, les suppressions de source et les ressources gérées sont enregistrés dans `editState`, qui est ensuite projeté sur la base de référence pour le rendu et l'exportation.

Séparer les deux calques préserve la provenance du contenu PDF natif et permet aux exportateurs de décider quelle source utiliser pour copier, supprimer ou remplacer.

<Callout type="warning" title="Choisissez la vue correcte">
  `pdf.getDocument()` retourne la base de référence importée. `pdf.save()` renvoie l'instantané complet de l'unité avec son état d'édition durable. Les intégrations avancées peuvent obtenir la projection actuelle de `pdf.getModel().getMaterializedDocument()`.
</Callout>

## Créer et conserver un snapshot

```ts
const pdf = univerAPI.createPdf({ name: 'Untitled contract' })
const page = pdf.getPageByIndex(0)

page?.insertTextBox({
  text: 'Draft',
  left: 36,
  top: 36,
})

const snapshot = pdf.save()
await applicationStorage.save(snapshot.id, snapshot)
```

Restaurez le snapshot complet avec la façade :

```ts
const snapshot = await applicationStorage.load('pdf-unit-id')
const pdf = univerAPI.createPdf(snapshot)
```

Une fois l'unité en marche, ne modifiez pas un objet instantané. Utilisez plutôt les méthodes Facade ou les commandes enregistrées, de sorte que la validation, la désactivation et le redécoupage, la collaboration et l'intention d'exporter restent cohérents.

## PDF stockés par blocs

Les grands PDF, ou les PDF stockés à distance, peuvent utiliser `documentShell`, `fragmentIndex` et `fragmentBindings`. Le shell conserve les tailles de page, la commande, les étiquettes et les identifiants de bloc disponibles avant que n'importe quel corps de page soit chargé.

Ces champs sont des contrats d'échange et de stockage. Le code d'application les obtient normalement des services d'échange ou de collaboration PDF et les maintient inchangés.
