## Estructura del documento

`IPdfDocument` contiene el modelo normalizado del documento PDF:

- `pages` almacena el pedido de la página, tamaño, rotación, capas, etiquetas y cajas PDF nativas.
- `objects` almacena los objetos semánticos del documento.
- `displayLists` retiene las operaciones PDF de nivel de renderizado y preserva la fidelidad al archivo fuente.
- `textStories` mantiene el texto editable como un flujo, separado de la agrupación de glifos PDF, que no es estable.
- `assets`, `styles` y `native` conservan recursos y recursos reutilizables específicos para la fuente.
- `sources`, `edits` y `exportPlan` registran dónde se originó el contenido y qué debe hacer la exportación.

Durante la importación de PDF, no toda operación de origen visible se convierte en un elemento Facade editable. El contenido nativo permanece en las listas de visualización hasta que una acción de usuario lo promueve o reemplaza.

## Páginas

`FPdf` lee páginas en orden materializado y puede insertar páginas en blanco:

```ts
const pages = pdf.getPages()
const firstPage = pdf.getPageByIndex(0)
const pageById = firstPage ? pdf.getPageById(firstPage.getId()) : null
const appendedPage = pdf.insertPage()
```

`insertPage(index)` acepta un entero de `0` a través del recuento de página actual. Una nueva página hereda el tamaño, la rotación y las cajas PDF de su vecino. Si no existe un vecino, la página utiliza A4, que es 595 por 842 puntos.

## Contenido nativo y superposiciones editables

`FPdfPage.getElements()` devuelve relés editables duraderos en z-order. Los accesorios tipodos por debajo filtran la misma capa de superposición:

| Accesor            | Wrapper Facade   |
| ------------------ | ---------------- |
| `getTextBoxes()`   | `FPdfTextBox`    |
| `getParagraphs()`  | `FPdfParagraph`  |
| `getLists()`       | `FPdfList`       |
| `getTables()`      | `FPdfTable`      |
| `getImages()`      | `FPdfImage`      |
| `getDividers()`    | `FPdfDivider`    |
| `getAnnotations()` | `FPdfAnnotation` |

`getTextSpans()` se comporta de manera diferente. Enumera instantáneas de las operaciones de texto nativo visible. Llamar `replaceText()` en un lazo suprime la operación nativa y crea una nueva caja de texto editable.

## Sistemas de coordenadas

El modelo básico y el público Facade utilizan diferentes unidades por diseño:

| Límite                                                              | Unidad y origen                                                 |
| ------------------------------------------------------------------- | --------------------------------------------------------------- |
| Posiciones, tamaños, rutas de anotación y anchos de trazo de Facade | Puntos PDF, posicionados desde la parte superior izquierda |
| Geometría de páginas y objetos del modelo principal | EMU, origen en la parte superior izquierda |
| `pdfBoxes` importados y asignaciones del origen nativo | Espacio de usuario PDF, origen en la parte inferior izquierda |

El código de aplicación utiliza `getTransform`, `setPosition` y `setSize` (`setRotation`) y las opciones de inserción tipo Facade. Los ayudantes de conversión `ptToEmu` de `emuToPt` son necesarios sólo cuando se construyen datos de modelo de menor nivel.

## Límites públicos de edición

Facade valida varias restricciones del modelo:

- La anchura y la altura deben ser valores finitos positivos. Las posiciones y las rotaciones deben ser finitas.
- Los niveles de lista varían desde `0` a través de `8`, y el número de inicio de una lista ordenada debe ser un entero positivo.
- Una tabla debe tener dimensiones enteros positivas y contener no más de 10.000 células.
- La inserción de anotaciones mediante Facade admite resaltado, subrayado, tachado, subrayado ondulado y tinta.
- Los rangos de opacidad de imagen desde `0` a través de `1`, y un rectángulo de cultivo debe tener un área positiva.
- Los rangos de texto utilizan los offsets UTF-16, con un inicio inclusivo y un extremo exclusivo.
