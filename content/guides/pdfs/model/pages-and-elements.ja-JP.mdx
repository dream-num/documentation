## ドキュメント構造

`IPdfDocument` には、正規化された PDF ドキュメントモデルが含まれます。

- `pages`は、ページの注文、サイズ、回転、レイヤー、ラベル、およびネイティブPDFボックスを保存します。
- `objects` は、セマンティックなドキュメントオブジェクトを保存します。
- `displayLists`はレンダリングレベルのPDF操作を保持し、ソースファイルへの忠実度を維持します。
- `textStories`は、編集可能なテキストをフローとして保存し、PDFグリフグループ化とは分離し、安定していません。
- `assets`、`styles`および`native`は、ソース固有の再使用可能なリソースとリソースを保持します。
- `sources`、`edits`および`exportPlan`のレコードは、コンテンツが発信され、エクスポートが何をすべきかを記録します。

PDF のインポート中に、すべての可視ソース操作が編集可能なファサード要素になります。 ネイティブコンテンツは、表示リストに保存され、ユーザーアクションが促進または交換されるまで保存されます。

## ページ

`FPdf`は、加工された順番でページを読み込み、空白のページを差し込むことができます。

```ts
const pages = pdf.getPages()
const firstPage = pdf.getPageByIndex(0)
const pageById = firstPage ? pdf.getPageById(firstPage.getId()) : null
const appendedPage = pdf.insertPage()
```

`insertPage(index)`は、現在のページ数で`0`から整数を受け入れます。新しいページは、その隣人のサイズ、回転、PDFボックスを継承します。隣人が存在しない場合、ページはA4を使用しており、これは842ポイントです。

## ネイティブコンテンツと編集可能なオーバーレイ

`FPdfPage.getElements()`はz-orderの耐久の編集可能な上敷を戻します。 同じ上敷の層をろ過する下のタイプされたaccessors:

| アクセサー         | Facade ラッパー  |
| ------------------ | ---------------- |
| `getTextBoxes()`   | `FPdfTextBox`    |
| `getParagraphs()`  | `FPdfParagraph`  |
| `getLists()`       | `FPdfList`       |
| `getTables()`      | `FPdfTable`      |
| `getImages()`      | `FPdfImage`      |
| `getDividers()`    | `FPdfDivider`    |
| `getAnnotations()` | `FPdfAnnotation` |

`getTextSpans()` は異なる動作をします。 可視されたネイティブテキスト操作のスナップショットを列挙します。 スパンで `replaceText()`を呼び出すと、ネイティブ操作を抑制し、新しい編集可能なテキストボックスを作成します。

## 座標系

コアモデルとパブリックファサードは、デザインによって異なるユニットを使用します。

| 境界                                                     | 単位と原点                     |
| -------------------------------------------------------- | ------------------------------ |
| Facade の位置、サイズ、注釈パス、線幅 | 左上から配置されたPDFポイント |
| コアモデルのページとオブジェクトのジオメトリ | 左上にあるEMU、原点 |
| インポートした `pdfBoxes` とネイティブソースのマッピング | PDF ユーザスペース、左下にある原点 |

アプリケーションコードは、`getTransform`、`setPosition`, `setSize`, `setRotation`とタイプされたファサードインサートオプションを使用します。 `ptToEmu`は、`emuToPt`および関連する変換ヘルパーは、低レベルのモデルデータを作成するときにのみ必要です。

## 公開編集 API の制限

Facade は、複数のモデル制約を検証します。

- 幅と高さは正の有限値でなければなりません。位置と回転は有限です。
- `0`から`8`までのリストレベル範囲と、注文リストの開始番号は正式整数でなければなりません。
- 表は正の整数の寸法を持ち、10,000以上の細胞を含んでいません。
- Facade から挿入できる注釈は、ハイライト、下線、取り消し線、波線、インク注釈です。
- `0`から`1`までの画像の不透明度の範囲、および作物の長方形は肯定的な区域を持たなければなりません。
- テキスト範囲は、包括的な開始と排他的な終了で、UTF-16オフセットを使用します。

タスク別の例については、[PDF の編集](/guides/pdfs/features/core/editing)を参照してください。
