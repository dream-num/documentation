## 文件結構

`IPdfDocument` 包含正規化的 PDF 文件模型：

- `pages` 儲存頁面順序、大小、旋轉、圖層、標籤和原生 PDF 邊界方塊。
- `objects` 儲存語意文件物件。
- `displayLists` 保留渲染級 PDF 操作，也保持與原始檔的保真度。
- `textStories` 儲存可編輯的文字流，與不穩定的 PDF 字形分組分開。
- `assets`、`styles` 和 `native` 保留可複用的資源，以及原始檔特有的資源。
- `sources`、`edits` 和 `exportPlan` 記錄內容來源和匯出意圖。

匯入 PDF 時，並非所有可見的源操作都會成為可編輯的 Facade 元素。原生內容會保留在顯示列表中，直到使用者透過某個操作將其提升或替換。

## 頁面

`FPdf` 依具現化後的順序讀取頁面，並可插入空白頁：

```ts
const pages = pdf.getPages()
const firstPage = pdf.getPageByIndex(0)
const pageById = firstPage ? pdf.getPageById(firstPage.getId()) : null
const appendedPage = pdf.insertPage()
```

`insertPage(index)` 接受 `0` 到當前頁面數之間的整數。新頁面沿用相鄰頁面的大小、旋轉和 PDF 邊界框。如果沒有相鄰頁面，則使用 A4 尺寸，即 595 × 842 點。

## 原生內容與可編輯疊加層

`FPdfPage.getElements()` 按 z 序返回持久化的可編輯疊加元素，下列帶型別的訪問器篩選的也是同一疊加層：

| 存取子             | Facade 包裝器    |
| ------------------ | ---------------- |
| `getTextBoxes()`   | `FPdfTextBox`    |
| `getParagraphs()`  | `FPdfParagraph`  |
| `getLists()`       | `FPdfList`       |
| `getTables()`      | `FPdfTable`      |
| `getImages()`      | `FPdfImage`      |
| `getDividers()`    | `FPdfDivider`    |
| `getAnnotations()` | `FPdfAnnotation` |

`getTextSpans()` 的行為不同：它列舉的是可見原生文字操作的快照。對文字片段呼叫 `replaceText()` 會抑制對應的原生操作，並新建一個可編輯文字框。

## 座標系統

核心模型和公共 Facade 使用的單位不同，這是有意設計的：

| 邊界                                  | 單位與原點                 |
| ------------------------------------- | -------------------------- |
| Facade 位置、大小、註解路徑和筆畫寬度 | PDF 點，以左上角定位 |
| 核心模型頁面和物件幾何 | EMU，原點在左上角 |
| 匯入的 `pdfBoxes` 和原生來源對應 | PDF 使用者空間，原點在左下角 |

應用程式碼使用 `getTransform`、`setPosition`、`setSize`、`setRotation` 以及帶型別的 Facade 插入選項。只有在建置底層模型資料時，才需要使用 `ptToEmu`、`emuToPt` 等相關轉換輔助函式。

## 公開編輯限制

Facade 會校驗以下幾項模型約束：

- 寬度和高度必須是有限的正數，位置和旋轉必須是有限值。
- 列表層級範圍為 `0` 到 `8`，有序列表的起始編號必須是正整數。
- 表格的寬高必須是正整數，且單元格總數不能超過 10,000。
- Facade 插入批註時支援高亮、下劃線、刪除線、波浪線和墨跡批註。
- 圖片不透明度範圍為 `0` 到 `1`，裁剪矩形必須有正面積。
- 文字範圍使用 UTF-16 偏移量，起點包含、終點不包含。

如需面向任務的範例，請繼續閱讀[編輯 PDF](/guides/pdfs/features/core/editing)。
