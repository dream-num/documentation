## 문서 구조

`IPdfDocument`에는 정규화된 PDF 문서 모델이 포함됩니다.

- `pages`는 페이지 순서, 크기, 교체, 층, 상표 및 본래 PDF 상자를 저장합니다.
- `objects`는 의미론적 문서 객체를 저장합니다.
- `displayLists`는 렌더링 수준의 PDF 작업을 유지하고 소스 파일에 대한 fidelity를 보존합니다.
- `textStories`는 흐름으로 편집 가능한 텍스트를 유지하며, PDF glyph 그룹화로 분리되어 안정되지 않습니다.
- `assets`, `styles` 및 `native`는 소스에 특정한 재사용할 수 있는 자원 및 자원을 유지합니다.
- `sources`, `edits` 및 `exportPlan` 기록은 내용이 시작되고 수출이해야 하는지 기록합니다.

PDF 가져 오기 동안 모든 눈에 띄는 소스 작동이 편집 가능한 Facade 요소가됩니다. 기본 콘텐츠는 사용자 행동이 촉진하거나 교체 할 때까지 디스플레이 목록에서 남아 있습니다.

## 페이지

`FPdf`는 materialized 순서에 있는 페이지를 읽고 공백 페이지를 삽입할 수 있습니다:

```ts
const pages = pdf.getPages()
const firstPage = pdf.getPageByIndex(0)
const pageById = firstPage ? pdf.getPageById(firstPage.getId()) : null
const appendedPage = pdf.insertPage()
```

`insertPage(index)`는 현재 페이지 수를 통해 `0`에서 정수를받습니다. 새로운 페이지는 이웃의 크기, 회전 및 PDF 상자를 상속합니다. 이웃이 존재하지 않으면 페이지는 A4를 사용하고 842 포인트로 595를 사용합니다.

## 네이티브 콘텐츠 및 편집 가능한 오버레이

`FPdfPage.getElements()`는 z-order에서 튼튼한 편집 가능한 오버레이를 반환합니다. 필터 아래의 입력된 accessors는 동일한 오버레이 레이어를 필터링합니다:

| 접근자             | 퍼사드 래퍼      |
| ------------------ | ---------------- |
| `getTextBoxes()`   | `FPdfTextBox`    |
| `getParagraphs()`  | `FPdfParagraph`  |
| `getLists()`       | `FPdfList`       |
| `getTables()`      | `FPdfTable`      |
| `getImages()`      | `FPdfImage`      |
| `getDividers()`    | `FPdfDivider`    |
| `getAnnotations()` | `FPdfAnnotation` |

`getTextSpans()`는 다르게 행동합니다. 그것은 눈에 보이는 기본 텍스트 작업의 스냅 샷을 삽입합니다. 스팬에 `replaceText()`를 호출하여 기본 작업을 억제하고 새로운 편집 가능한 텍스트 상자를 만듭니다.

## 좌표계

핵심 모형과 대중적인 정면 사용은 디자인에 의하여 다른 단위를 이용합니다:

| 경계                                    | 단위 및 원점                    |
| --------------------------------------- | ------------------------------- |
| 퍼사드 위치, 크기, 주석 경로 및 획 너비 | 왼쪽 상단에 위치한 PDF 포인트 |
| 핵심 모델 페이지 및 객체 기하 정보 | EMU, 왼쪽 상단의 기원 |
| 가져온 `pdfBoxes` 및 네이티브 소스 매핑 | PDF 사용자 공간, 하단의 기원 왼쪽 |

신청 부호는 `getTransform`, `setPosition`의 `setSize`를, `setRotation` 사용하고, 유형화된 정면 삽입 선택권을 이용합니다. `ptToEmu`는, `emuToPt` 및 관련 변환 돕는 더 낮은 수준 모형 자료를 건축할 때만 요구됩니다.

## 공개 편집 제한

퍼사드는 여러 모델 제약 조건을 검증합니다.

- 폭과 고도는 긍정적인 finite 값이어야 합니다. 위치와 교체는 finite이어야 합니다.
- `8`를 통해 `0`에서 레벨 범위를 나열하고 주문 목록의 시작 수는 긍정적 인 정수이어야합니다.
- 테이블에는 긍정적 인 정수 치수가 있어야하며 10,000 개 이상의 세포가 포함되어야합니다.
- 퍼사드 주석 삽입은 강조, 밑줄, 취소선, 물결 밑줄 및 잉크 주석을 지원합니다.
- 이미지 불투명은 `0`에서 `1`를 통해 배열하고, 작물 장방형은 긍정적인 지역을 비치해야 합니다.
- 텍스트 범위는 UTF-16 상쇄, 포괄적 인 시작과 독점 끝.

작업 중심의 예제는 [PDF 편집](/guides/pdfs/features/core/editing)에서 계속 확인하세요.
