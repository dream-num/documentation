## グローバルライフサイクル

Univerは、スタートアップの4つのグローバルステージを通過します。

- **Starting**: 初期化中。業務ユニットは未作成です。
- **レディー**:最初のビジネスユニットが作成されました。後者はこのステージを再びトリガーしません。
- **レンダリングされる**: 標準 UI は、非同期コンテンツがロードされる可能性があるにもかかわらず、最初のレンダリングスイッチを実行しました。
- **ステアディ**: 標準 UI は、レンダリング後の遅延後にこのステージに到達します。すべての非同期タスクを待ちません。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="イベントが通知する対象">

`LifeCycleChanged` グローバルステージのレポート Univer. プラグイン B がグローバル後に読み込まれた場合 `Ready` ステージ、Bはまだ実行します `onReady()`, しかし、第二のグローバル `Ready` イベントが発生します。

リスナーが追加された場合、そのコールバックは、`Starting`を含む現在のステージをすぐに受け取る可能性があります。 リスナーなしで現在のステージを決定するには、`univerAPI.getCurrentLifecycleStage()`を呼び出します。

</Callout>

リスナーを削除するには、返された`disposable`オブジェクトを使用します。

```typescript
disposable.dispose()
```

## プラグインのライフサイクルフック

プラグインは、ロード時に `onStarting()` を実行し、現在のグローバルステージでキャッチします。プラグイン B を異なるポイントにロードして、プラグイン A のそれらのホックコールを比較します。

<LifecycleDemo />

一般的なプラグインは、登録されたときにロードします。 ビジネス型プラグインは通常、そのタイプの最初のユニットが構築される前にロードします。 既に不良なバッチにロードを開始したタイプにプラグインが追加されました。 明示的な依存性は、プラグインが以前のプラグインをロードする可能性があります。

各バッチのホックは同期的に実行します。, ステージと依存性順でステージ, ホック内の非同期作業が待っていません。. 特定のユニットにアクセスする前に, DOM 要素, リソース, 準備が整っていることを確認します。.
