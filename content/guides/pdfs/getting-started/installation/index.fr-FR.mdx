Univer PDFs fait partie du Univer Office SDK et ne fournit pas encore de préréglage, donc une application PDF est assemblée en mode plugin.

Univer prend en charge deux modes d'intégration : le mode préréglé et le mode plugin. Le mode prérégulé fournit un paquet préconfiguré de plugins, ce qui réduit la quantité de câblage. Si vous avez besoin de **personnalisation profonde ou extensions**, utilisez le mode plugin, où chaque plugin est sélectionné et configuré individuellement.

## Configuration en mode plugin

### Utilisation d’un gestionnaire de packages

L'outil de construction doit prendre en charge les modules ES et le champ `exports` dans `package.json`.

#### Installation

Univer construit son UI avec React et ses flux de données avec RxJS, et il peut également être intégré dans une application Vue ou Angular. Vérifiez que les dépendances `react`, `react-dom` et `rxjs` des pairs[^peer-dependency] sont installées. La commande Yarn ci-dessous les ajoute explicitement.

Conservez **la même version** pour tous les packages `@univerjs/*` et `@univerjs-pro/*`.

Conservez tous les packages `@univerjs/*` et `@univerjs-pro/*` à **la même version**.

#### Utilisation

Créer le conteneur avec une hauteur explicite avant d'initialiser Univer:

```html
<div id="app" style="height: 600px"></div>
```

Importez les entrées de façade utilisées ci-dessous avant d'appeler `FUniver.newAPI(univer)`. Importez d'abord `@univerjs/design` CSS, puis `@univerjs/ui` SCC et le produit CSS.

<Steps>
  <Step>
    Importez les styles d'interface utilisateur partagés avant le style d'interface UI PDF, et fusionnez les paquets locaux que l'application permet:

    ```ts
    import { UniverLicensePlugin } from '@univerjs-pro/license'
    import { UniverPdfsPlugin } from '@univerjs-pro/pdfs'
    import { UniverPdfsUIPlugin } from '@univerjs-pro/pdfs-ui'
    import PdfsUIEnUS from '@univerjs-pro/pdfs-ui/locale/en-US'
    import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'
    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    import '@univerjs-pro/pdfs-ui/lib/index.css'
    ```

  </Step>
  <Step>
    Importez l'entrée PDF Facade[^facade-entry]. Cette importation d'effets secondaires ajoute les méthodes et les enums PDF à `FUniver`:

    ```ts
    import '@univerjs-pro/pdfs/facade'
    ```

  </Step>
  <Step>
    Créez l'environnement d'exécution, enregistrez explicitement l'ensemble des plugins, puis créez un PDF :

    ```ts
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
          PdfsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverUIPlugin, { container: 'app' })
    univer.registerPlugin(UniverDocsUIPlugin)
    univer.registerPlugin(UniverLicensePlugin, {
      license: process.env.CLIENT_LICENSE_TEXT,
    })
    univer.registerPlugin(UniverPdfsPlugin)
    univer.registerPlugin(UniverPdfsUIPlugin)

    const univerAPI = FUniver.newAPI(univer)
    univerAPI.createPdf({ name: 'Untitled PDF' })
    ```

  </Step>
</Steps>

#### Configuration des plugins [#plugin-configuration]

`UniverUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Élément DOM où monter l’éditeur, ou son identifiant. |

`UniverLicensePlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `license` | `string` |  | Contenu du fichier de licence client. |

#### Méthodes `univer.registerPlugin` et `univer.registerPlugins` [#registerPlugin]

Après la création de l'instance Univer, appelez `univer.registerPlugin` pour y enregistrer un plugin.

L'appel a le formulaire `univer.registerPlugin(Plugin, options)`. `Plugin` est le plugin à enregistrer et `options` constitue un objet de configuration optionnel. Chaque plugin définit ses propres options.

Pour enregistrer plusieurs plugins à la fois, passez un tableau à `univer.registerPlugins`. Cela maintient la gestion des plugins en un seul endroit.

```typescript
univer.registerPlugins([
  [UniverUIPlugin, { container: 'app' }],
  UniverDocsUIPlugin,
  [UniverLicensePlugin, {
    license: process.env.CLIENT_LICENSE_TEXT,
  }],
  UniverPdfsPlugin,
  UniverPdfsUIPlugin,
])
```

<Callout type="info">
  `UniverPdfsUIPlugin` dépend de `UniverDocsUIPlugin`, donc enregistrez le plugin d'interface document partagé avant lui.
</Callout>

## Prise en charge mobile [#mobile-support]

L'interface PDF mobile est une exportation distincte du même paquet, `UniverPdfsMobileUIPlugin`. Il n'existe ni option `mobile: true` ni préréglage PDF. Choisissez le mode d'interface avant d'ouvrir un PDF et **remplacez** les enregistrements de l'interface de bureau. N'enregistrez pas les deux.

| Paquet | Enregistrement de bureau | Enregistrement mobile |
| --- | --- | --- |
| `@univerjs/ui` | `UniverUIPlugin` | `UniverMobileUIPlugin` |
| `@univerjs/docs-ui` | `UniverDocsUIPlugin` | `UniverDocsMobileUIPlugin` |
| `@univerjs-pro/pdfs-ui` | `UniverPdfsUIPlugin` | `UniverPdfsMobileUIPlugin` |
| `@univerjs-pro/pdfs-print` | `UniverPdfsPrintPlugin` | `UniverPdfsMobilePrintPlugin` |

```ts
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverPdfsMobileUIPlugin } from '@univerjs-pro/pdfs-ui'
import { UniverPdfsMobilePrintPlugin } from '@univerjs-pro/pdfs-print'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin, { footer: false })
univer.registerPlugin(UniverPdfsMobileUIPlugin)

// Optional: add Print to the mobile viewer menu.
univer.registerPlugin(UniverPdfsMobilePrintPlugin)
```

`UniverPdfsMobileUIPlugin` déclare `UniverMobileUIPlugin` et `UniverDocsMobileUIPlugin` comme dépendances, donc enregistrez-les d'abord. Il s'ouvre sur la grille d'aperçu des pages plutôt que sur le rail de miniatures du bureau. C'est l'application hôte qui décide quand monter cette pile, par exemple selon la largeur de la fenêtre d'affichage. Un conteneur étroit autour du plugin de bureau ne produit pas l'interface mobile. Voir [Impression](/guides/pdfs/features/print#mobile-support) pour le plugin d'impression mobile.

## Worker de miniatures facultatif

Les vignettes de page rendent sur le thread principal sans configuration supplémentaire. Pour les documents plus grands, les transmettre à un travailleur de module dédié via `thumbnailWorkerURL`.

Créez un point d'entrée de worker tel que `pdf-thumbnail.worker.ts` :

```ts
import { UniverPdfsUIWorkerPlugin } from '@univerjs-pro/pdfs-ui/worker'
import { Univer } from '@univerjs/core'

const univer = new Univer()
univer.registerPlugin(UniverPdfsUIWorkerPlugin)
```

Passez l'URL du travailleur lors de l'enregistrement du plugin PDF UI:

`UniverPdfsUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `thumbnailWorkerURL` | `string \| URL \| Worker` |  | Génère les miniatures des pages dans un Worker du navigateur. |

```ts
univer.registerPlugin(UniverPdfsUIPlugin, {
  thumbnailWorkerURL: new Worker(new URL('./pdf-thumbnail.worker.ts', import.meta.url), { type: 'module' }),
})
```

L'option accepte également une URL sous forme de chaîne ou un `Worker` existant. Si les workers ou `OffscreenCanvas` ne sont pas disponibles, l'affichage des miniatures revient au thread principal.

## Édition collaborative

`@univerjs-pro/pdfs-editor` ne fait pas partie d'une pile locale seulement, et il ne peut pas fonctionner indépendamment. Installez et enregistrez la pile complète `@univerjs-pro/collaboration`, `@univerjs-pro/collaboration-client` et `@univerjs-pro/collaboration-client-ui` comme décrit dans [Collaboration](/guides/pdfs/features/collaboration) puis installez et enregistrez le plugin du cycle de vie de l'éditeur PDF.

## Utilisation avec Node.js

Un service Node.js peut enregistrer `UniverPdfsPlugin` sans aucun paquet d'interface utilisateur de navigateur. Ajoutez la pile de collaboration au-dessus seulement lorsque le service doit charger ou synchroniser des unités PDF persistantes.

## Autres versions

Outre les versions stables, Univer maintient des canaux alpha et bêta qui fournissent un accès aux fonctionnalités qui ne sont pas encore officiellement publiées. Plus de fonctionnalités signifient aussi plus de risque : ces versions peuvent contenir des bugs, des fonctionnalités incomplètes ou des fonctionnalités instables, donc évitez-les dans la production si possible.

### Version alpha / beta

Lorsque l'équipe Univer complète une nouvelle fonctionnalité ou un changement significatif, elle peut pré-libérer le changement vers le canal alpha ou bêta. Installez une version alpha ou bêta d'un paquet avec :

```package-install
npm install @univerjs-pro/pdfs@alpha # Alpha version
npm install @univerjs-pro/pdfs@beta # Beta version
```

Si un problème survient ou si vous avez des commentaires lors de l'utilisation d'une version alpha ou bêta, signalez-le à l'équipe Univer par l'intermédiaire de [GitHub Problèmes](https://github.com/dream-num/univer/issues).
