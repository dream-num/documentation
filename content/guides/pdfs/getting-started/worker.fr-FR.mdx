Les PDF peuvent rendre les vignettes de page dans un Worker[^web-worker]. En passant `thumbnailWorkerURL` à `UniverPdfsUIPlugin`, le Worker utilise `OffscreenCanvas` . Cette option ne déplace pas l'éditeur PDF entier dans un worker.

Commencez par [l'installation et l'utilisation de base](/guides/pdfs/getting-started/installation) ; les extraits ci-dessous prolongent cette configuration. Enregistrez les plugins avant de créer ou de charger du contenu, et mettez à jour un enregistrement existant plutôt que d'enregistrer le même plugin deux fois.

## Thread principal

`UniverPdfsUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `thumbnailWorkerURL` | `string \| URL \| Worker` |  | Crée les vignettes dans un Worker du navigateur. |

```typescript title="main.ts"
import { UniverPdfsUIPlugin } from '@univerjs-pro/pdfs-ui'

univer.registerPlugin(UniverPdfsUIPlugin, {
  thumbnailWorkerURL: new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' }),
})
```

## Point d’entrée du Worker

```typescript title="worker.ts"
import { UniverPdfsUIWorkerPlugin } from '@univerjs-pro/pdfs-ui/worker'
import { Univer } from '@univerjs/core'

const univer = new Univer()
univer.registerPlugin(UniverPdfsUIWorkerPlugin)
```

Utilisez un module Worker avec un fichier d'entrée séparé. Gardez les versions de paquet dans le Worker et sur le thread principal aligné. Le rendu et l'interaction utilisateur restent sur le think principal.

[^web-worker]: Un Web Worker exécute JavaScript hors du thread principal du navigateur et communique par messages. Il ne peut pas accéder directement au DOM : déplacer les calculs ne déplace pas l’interface de l’éditeur.
