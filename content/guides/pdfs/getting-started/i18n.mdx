## Interface language

`locale` selects the language pack used for menus, tooltips, dialogs, and other translated interface text. `locales` registers language packs without selecting one. All units in the Univer instance share this setting. Values come from `LocaleType`, such as `LocaleType.EN_US`.

- **All products: UI**: `locale` changes translated menus, tooltips, dialogs, and plugin labels. It does not translate user content or rename existing units.
- **Sheets: cell formats and formulas**: Cell numbers and dates render using the number-format locale override first, then the workbook snapshot `locale`, then the instance `locale`. `region` does not replace any of these settings. `locale` still governs formula behavior such as `DOLLAR` and the currency format on financial results. CJK input normalization also uses `locale`.
- **Docs: statistics**: `locale` drives word segmentation and counting.

### Changing language at runtime

Load the language packs for every installed plugin or preset before switching the language. `loadLocales()` merges translations without switching the language, and `setLocale()` selects among the loaded packs without downloading anything. A missing translation key is displayed as the key itself. The example loads the shared UI pack; merge the target-language packs for other installed plugins in the same call.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Merging language packs [#mergeLocales]

`mergeLocales` merges several plugin or preset language packs into one complete language pack object. Both forms below are valid:

<Tabs items={['Plugin Mode', 'Preset Mode']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // You can pass multiple language pack objects to merge
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // You can also pass an array of language pack objects
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/presets'

    // You can pass multiple language pack objects to merge
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // You can also pass an array of language pack objects
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
</Tabs>

### Custom Language Packs

Univer also supports custom language packs. Construct a language pack object as needed and pass it to the `Univer` instance. Preset language packs are usually located in the `<rootDir>/packages/<PLUGIN_NAME>/locale` directory.

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Regional settings

`region` selects the regional conventions used by regional features. All units in the Univer instance share this setting.

Both settings take `LocaleType` values. For example, `LocaleType.EN_US` has the value `enUS`, while `en-US` is the language-pack file name and the BCP 47 tag. Do not pass country codes such as `US` or `SG` as `region`. When the interface uses a different locale, the region does not require a matching language pack.

If `region` is never set, it follows `locale`, including later `setLocale()` calls. Setting `region` during initialization or calling `setRegion()` ends that automatic following, and later language changes keep the selected region. No public API restores automatic following; call both setters when the two values should change together.

Add `region: LocaleType.DE_DE` next to `locale` in `createUniver()` or `new Univer()` to keep the interface language while applying German regional conventions.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

In this example the interface is English and regional formatting remains German. `getCurrentLocale()` and `getCurrentRegion()` return the identifiers that are in effect. To change both together, call both setters with the same `LocaleType` value.

- **Sheets: currency controls**: `region` controls the currency toolbar icon, the currency and accounting choices and their previews, and the pattern applied by the currency command. Changing it does not rewrite existing cell formats or convert monetary values.
- **Docs: statistics**: `region` formats the counts shown in the statistics dialog and status bar, for example the grouping separators. Changing `region` does not change the counting rules.
- **Thread comments, when enabled**: `region` controls the displayed date and time format, with 24-hour time and Latin digits. `locale` controls comment UI text. Neither changes stored timestamps; `region` is not a timezone setting.
- **Boards, Slides, Bases, PDFs**: `locale` controls translated UI. `region` is available for shared features that consume it, such as thread comments when integrated; it does not automatically reformat board or slide text, Base fields, or PDF content.
