## インターフェースの言語

`locale`は、メニュー、ツールチップ、ダイアログ、およびその他の翻訳されたインターフェイステキストに使用される言語パックを選択します。 `locales`では、言語パックを1つ選択せずに登録します。 Univerインスタンス内のすべてのユニットは、この設定を共有します。 値は、`LocaleType.EN_US`などの`LocaleType`から来ています。

- **全製品：UI**：`locale` はメニュー、ツールチップ、ダイアログ、プラグインのラベルを翻訳します。ユーザーの内容や既存ユニット名は変更しません。
- **シート: 細胞のフォーマットおよび方式**: セル番号と日付は、最初にオーバーライドされた番号フォーマットのロケールを使用してレンダリングします。その後、ワークブックスナップショット`locale`、その後、インスタンス`locale`。 `region`は、これらの設定のいずれかを置き換えません。 `locale`はまだ、`DOLLAR`などの公式動作と財務結果の通貨フォーマットを支配します。 CJK入力正規化も`locale`を使用します。
- **Docs: 統計**:`locale`は単語の区分およびカウントを運転します。

### 実行時の言語の切り替え

言語を切り替える前に、すべてのインストールされたプラグインまたはプリセットの言語パックをロードします。 `loadLocales()`は、言語を切り替えることなく、翻訳をマージし、`setLocale()` は、ダウンロードせずにロードされたパックの中から選択します。 欠落した翻訳キーは、キー自体として表示されます。 この例は、共有されたUIパックをロードし、同じ呼び出しで他のインストールされたプラグインのターゲット言語パックをマージします。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 言語パックのマージ [#mergeLocales]

`mergeLocales`は、複数のプラグインまたはプリセット言語パックを1つの完全な言語パックオブジェクトにマージします。以下の両方のフォームが有効です。

<Tabs items={['プラグインモード', 'プリセットモード']}>
  <Tab>
    ````typescript
    import { mergeLocales } from '@univerjs/core'

    // 複数の言語パックオブジェクトを引数で渡してマージできます
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 配列としてまとめて渡すことも可能です
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ````
  </Tab>
  <Tab>
    ````typescript
    import { mergeLocales } from '@univerjs/presets'

    // 複数の言語パックオブジェクトを引数で渡してマージできます

    )
    // 配列としてまとめて渡すことも可能です
    const locales = mergeLocales([
      plugin1Locales,

    ])
    ````

### カスタム言語パック

Univerは、カスタム言語パックもサポートしています。必要に応じて言語パックオブジェクトを構成し、`Univer`インスタンスに渡します。プリセット言語パックは通常、`<rootDir>/packages/<PLUGIN_NAME>/locale`ディレクトリにあります。

````typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
````

### 翻訳への貢献

Univerは現在、以下の組み込み言語パックを出荷しています。

- `zh-CN`: 中国語（簡体字）
- `en-US`: 英語
- `zh-TW`: 中国語（繁体字）
- `zh-HK`: 中国語（繁体字・香港）
- `ru-RU`: ロシア語
- `vi-VN`: ベトナム語
- `fa-IR`: ペルシャ語
- `fr-FR`: フランス語
- `ja-JP`: 日本語
- `ko-KR`: 韓国語
- `es-ES`: スペイン語
- `ca-ES`: カタルーニャ語
- `sk-SK`: スロバキア語
- `ar-SA`: アラビア語
- `de-DE`: ドイツ語
- `id-ID`: インドネシア語
- `it-IT`: イタリア語
- `pl-PL`: ポーランド語
- `pt-BR`: ポルトガル語（ブラジル）

Univerはオープンソースプロジェクトであり、ローカルを追加または改善する貢献を歓迎します。

## 地域設定

`region`は、地域機能で使用される地域の慣行を選択します。 Univerインスタンスのすべてのユニットは、この設定を共有します。

どちらの設定も`LocaleType`値を取ります。例えば、`LocaleType.EN_US`は`enUS`値を持っていますが、`en-US`は言語パックファイル名とBCP 47タグです。`US`や`SG`などの国コードを`region`に渡さないでください。インターフェイスが異なるロケールを使用している場合は、地域は一致する言語パックを必要としません。

`region`が設定されていない場合は、`locale`を後に`setLocale()`呼び出します。 初期化時に`region`を設定したり、`setRegion()`の終了を呼び出して、その後の言語変更は選択した領域を維持します。 パブリックAPIは自動で復元しません。 2つの値が一緒に変更される場合、両方のセッターを呼び出します。

追加する `region: LocaleType.DE_DE` 次へ `locale` サインイン `createUniver()` または `new Univer()` ドイツ地方の慣習を適用する間インターフェイス言語を保つため。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

この例では、インターフェイスは英語と地域の書式がドイツ語のままです。 `getCurrentLocale()` と `getCurrentRegion()`は、効果のある識別子を返します。 両方を変更するには、同じ `LocaleType`値でセッターを呼び出します。

- **シート:通貨コントロール**: `region`は通貨ツールバーのアイコン、通貨と会計の選択と通貨コマンドで適用されたパターンを制御します。 変更は、既存のセルフォーマットを刷新したり、通貨値を変更したりしません。
- **Docs: 統計**:`region`は、統計ダイアログとステータスバーに示されているカウントをフォーマットします。例えば、グループ分けの区切り文字。`region`を変更してもカウントルールを変更しません。
- **スレッドコメント, 有効にしたときに**:`region`は、24時間、ラテンの数字で表示された日付と時刻のフォーマットを制御します。 `locale` はコメントUIのテキストを制御します。 どちらも保存されたタイムスタンプを変更します。`region`にはタイムゾーンの設定はありません。
- **ボード、スライド、ベース、PDF**: `locale`は翻訳されたUIを制御します。 `region` は、統合時にスレッドコメントなどの共有機能で利用できます。それは自動的にボードやスライドテキスト、ベースフィールド、またはPDFコンテンツを再フォーマットしません。
