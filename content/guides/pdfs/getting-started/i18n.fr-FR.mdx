## Langue de l’interface

`locale` sélectionne le paquet de langues utilisé pour les menus, les tooltips, les dialogues et d'autres textes d'interface traduits. `locales` enregistre des paquets de langues sans en sélectionner un. Toutes les unités de l'instance Univer partagent ce paramètre. Les valeurs proviennent de `LocaleType`, comme `LocaleType.EN_US`.

- **Tous les produits : interface**: `locale` change les traductions des menus, infobulles, dialogues et libellés des plugins. Le contenu utilisateur et les noms des unités existantes restent inchangés.
- **Feuilles: formats et formules de cellules**: Numéros de cellule et dates rendus en utilisant le number-format locale d'abord, puis l'instantané du cahier de travail `locale`, puis l'instance `locale`. `region` ne remplace aucun de ces paramètres. `locale` gouverne toujours le comportement de la formule comme `DOLLAR` et le format de la monnaie sur les résultats financiers. La normalisation des entrées CJK utilise également `locale`.
- **Docs: statistiques**: `locale` permet la segmentation et le comptage des mots.

### Changer la langue à l’exécution

Chargez les paquets de langue pour chaque plugin ou preset installé avant de changer de langue. `loadLocales()` fusionne les traductions sans changer de langue, et `setLocale()` sélectionne parmi les paquets chargés sans télécharger quoi que ce soit. Une clé de traduction manquante s'affiche comme la clé elle-même. L'exemple charge le paquet UI partagé; fusionne les paquets de langage cible pour d'autres plugins installés dans le même appel.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

`mergeLocales` fusionne plusieurs paquets de langages plugin ou préréglés en un seul objet complet. Les deux formulaires ci-dessous sont valides :

### Packs linguistiques personnalisés

Univer prend également en charge des paquets de langues personnalisés. Construisez un objet de paquet de langues au besoin et passez-le à l'instance `Univer`. Les paquets de langues prédéfinis sont généralement situés dans le répertoire `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Paramètres régionaux

`region` sélectionne les conventions régionales utilisées par les fonctions régionales. Toutes les unités de l'instance Univer partagent ce paramètre.

Les deux paramètres prennent `LocaleType` valeurs. Par exemple, `LocaleType.EN_US` a la valeur `enUS`, pendant `en-US` est le nom du fichier langue-pack et l'étiquette BCP 47. Ne pas passer les codes de pays tels que `US` ou `SG` comme `region`. Lorsque l'interface utilise une autre localité, la région n'a pas besoin d'un paquet linguistique correspondant.

Si `region` n'est jamais réglé, il suit `locale`, y compris les appels `setLocale()` ultérieurs. Réglage `region` pendant l'initialisation ou l'appel `setRegion()` termine cette suite automatique, et les modifications de langue ultérieures maintiennent la région sélectionnée. Aucune API publique ne restaure automatiquement la suite; appelez les deux setters lorsque les deux valeurs doivent changer ensemble.

Ajouter `region: LocaleType.DE_DE` à côté de `locale` dans `createUniver()` ou `new Univer()` pour conserver la langue de l'interface tout en appliquant les conventions régionales allemandes.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Dans cet exemple, l'interface est anglaise et le formatage régional reste allemand. `getCurrentLocale()` et `getCurrentRegion()` retournent les identifiants en vigueur. Pour changer les deux, appelez les deux setters avec la même valeur `LocaleType`.

- **Feuilles : contrôles des devises**: `region` contrôle l'icône de la barre d'outils de monnaie, les choix de monnaie et de comptabilité et leurs prévisualisations, et le modèle appliqué par la commande de monnaie.
- **Docs: statistiques**: `region` formate les nombres affichés dans la boîte de dialogue statistique et la barre d'état, par exemple les séparateurs de regroupement. La modification de `region` ne modifie pas les règles de comptage.
- **Commentaires de filetage, lorsque activé**: `region` contrôle le format de date et d'heure affiché, avec une heure de 24 heures et des chiffres latins. `locale` commande le texte de l'interface utilisateur. Ni les changements enregistrés horodatages; `region` n'est pas un réglage de fuseau horaire.
- **Planches, diapositives, bases, PDFs**: `locale` contrôle l'interface utilisateur traduite. `region` est disponible pour les fonctions partagées qui la consomment, comme les commentaires de thread lorsqu'ils sont intégrés; il ne reformate pas automatiquement le tableau ou le texte de diapositive, les champs de base ou le contenu PDF.

## Disposition de droite à gauche

<Callout type="warning" title="Attention">
  Le support RTL ne couvre actuellement que la couche UI. La couche de rendu ne supporte pas RTL.
</Callout>

<Callout type="warning" title="Attention">
  Tous les plugins ne comprennent pas les packs de langage. La documentation pour chaque état de fonctionnalité que les plugins fournissent.
</Callout>

```typescript
univerAPI.setDirection('rtl')
```
