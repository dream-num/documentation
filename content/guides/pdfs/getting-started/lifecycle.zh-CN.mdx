## 全局生命周期

Univer 在启动过程中依次经过四个全局阶段：

- **Starting**：初始化阶段，此时还没有任何业务实例。
- **Ready**：第一个业务实例已经创建，之后再创建实例不会重新触发该阶段。
- **Rendered**：标准 UI 已完成首次渲染切换，异步内容可能仍在加载。
- **Steady**：标准 UI 在 Rendered 之后延迟一段时间进入该阶段，不会等待所有异步任务结束。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="事件监听的范围">

`LifeCycleChanged` 报告的是 Univer 的全局阶段。例如，全局进入 `Ready` 阶段之后才加载插件 B，B 仍会执行 `onReady()`，但不会再产生全局 `Ready` 事件。

添加监听器时，其回调可能立即收到当前阶段，`Starting` 也在其中。如果只需要确认当前所处的阶段，可直接调用 `univerAPI.getCurrentLifecycleStage()`。

</Callout>

移除监听器时，使用返回的 `disposable` 对象：

```typescript
disposable.dispose()
```

## 插件生命周期钩子

插件加载时执行 `onStarting()`，随后补齐到当前全局阶段。在不同时机加载插件 B，可以对比它与插件 A 的钩子调用。

<LifecycleDemo />

通用插件在注册时加载。业务类型的插件通常在创建该类型的第一个实例之前加载。如果某个类型已经启动，之后为该类型新增的插件会在延迟批次中加载。显式声明依赖可以使插件提前加载。

每个批次中的钩子按阶段、按依赖顺序同步调用，不等待钩子内的异步任务。在访问具体的实例、DOM 元素或资源之前，先确认其已就绪。
