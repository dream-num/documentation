すべてのPDF統合で再発する4つの概念はUniver PDFを取付ける前に理解の価値があります:

- プラグイン
- スナップショットとデータモデル
- コマンド
- Facade API

## 基本概念 [#basic-concepts]

### プラグイン

Univer PDFはプラグインで構成されています。 `UniverPdfsPlugin`は、`UNIVER_PDF`ユニットモデルと耐久性のあるPDFコマンドを登録します。 `UniverPdfsUIPlugin`では、ブラウザビューアを追加し、デフォルトでは、編集制御します。 アプリケーションがこれらの機能を必要とする場合にのみ、プリント、交換、またはコラボレーションパッケージを追加します。

Univerが製品間で共有するコア、レンダリング、設計、UIサービスで両方のプラグインを実行します。 これらのサービスは、PDFアプリケーションの技術的な依存性であり、PDFプラグインを使用して別のUniver製品の経験を必要としません。

### スナップショットとデータモデル

PDF ユニットは [`IPdfUnitData` スナップショット](/guides/pdfs/model/pdf-data) として永続しています。 `document`フィールドは、インポートまたは空白のソースベースラインを保持しています。 承認された編集は、代わりに `editState`に保存されているので、ベースライン自体は所定の位置に書き込まれません。

`pdf.save()` を呼び出して、完全な現在のスナップショットを取得します。 `pdf.getDocument()`は、ソースベースラインを返します。そのため、ユーザ編集は `save()`. で主張する必要があります。

### コマンド

実行時の変更は、同じパスで検証、ビューの更新、編集履歴、およびエクスポート意図を保持するコマンドで適用されます。 PDFファサードメソッドは、コマンドパラメータを準備し、コマンドを実行します。

<Callout type="warning" title="キューション">
  実行中のPDFユニットのスナップショットやソース文書を直接変更しないでください。代わりにPDFファサードメソッドまたは登録コマンドを使用してください。
</Callout>

### Facade API

コアファサードエントリー後に`@univerjs-pro/pdfs/facade`をインポートして、PDF APIを`FUniver`に追加します。 エントリは、`createPdf()`、`getActivePdf()`、`getPdf()`などのメソッドを提供します。

セットアップの手順と例については、[PDF Facade APIの利用](/guides/pdfs/getting-started/facade)を参照してください。

[インストールと基本的な使い方](/guides/pdfs/getting-started/installation) を続けてください。
