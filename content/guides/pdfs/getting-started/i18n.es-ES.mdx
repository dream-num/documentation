## Idioma de la interfaz

`locale` selecciona el paquete de idiomas utilizado para menús, puntas de herramientas, diálogos y otro texto de interfaz traducido. `locales` registra paquetes de idiomas sin seleccionar uno. Todas las unidades en la instancia Univer comparten este ajuste. Los valores vienen de `LocaleType`, como `LocaleType.EN_US`.

- **Todos los productos: interfaz**: `locale` cambia las traducciones de menús, ayudas, diálogos y etiquetas de plugins. No traduce contenido del usuario ni renombra unidades existentes.
- **Hojas: formatos celulares y fórmulas**: Los números y fechas de las celdas se ejecutan utilizando el formato número locale primero, luego la instantánea del libro `locale`, entonces la instancia `locale`. `region` no reemplaza ninguno de estos ajustes. `locale` todavía rige el comportamiento de las fórmulas como `DOLLAR` y el formato de la moneda en los resultados financieros. La normalización de entrada CJK también utiliza `locale`.
- **Docs: estadística**: `locale` impulsa segmentación de palabras y conteo.

### Cambiar el idioma durante la ejecución

Cargue los paquetes de idiomas para cada plugin instalado o preset antes de cambiar el idioma. `loadLocales()` fusiona las traducciones sin cambiar el idioma, y `setLocale()` selecciona entre los paquetes cargados sin descargar nada. Una clave de traducción perdida se muestra como la propia clave. El ejemplo carga el paquete UI compartido; fusionar los paquetes de lenguaje objetivo para otros plugins instalados en la misma llamada.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

`mergeLocales` fusiona varios paquetes de lenguaje plugin o preestablecido en un objeto completo de paquete de idiomas. Ambos formularios son válidos:

### Paquetes de idiomas personalizados

Univer también admite paquetes de idiomas personalizados. Construir un objeto de paquete de idiomas según sea necesario y pasarlo a la instancia `Univer`. Los paquetes de lenguaje presto se encuentran generalmente en el directorio `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Configuración regional

`region` selecciona las convenciones regionales utilizadas por las características regionales. Todas las unidades de la instancia Univer comparten este ajuste.

Ambos ajustes `LocaleType` valores, por ejemplo, `LocaleType.EN_US` tiene el valor `enUS`, mientras `en-US` es el nombre del archivo idioma-paquete y la etiqueta BCP 47. No pasar códigos de país como `US` o `SG` como tal `region`. Cuando la interfaz utiliza un local diferente, la región no requiere un paquete de idiomas que coincida.

Si `region` nunca se establece, sigue `locale`, incluyendo llamadas `setLocale()` posteriores. Configurar `region` durante la inicialización o llamar `setRegion()` termina que los cambios de lenguaje automático siguen la región seleccionada. Ninguna API pública restaura automáticamente el siguiente; llame a ambos setters cuando los dos valores deben cambiar juntos.

Agregue `region: LocaleType.DE_DE` junto a `locale` en `createUniver()` o `new Univer()` para mantener el lenguaje de la interfaz mientras aplica convenciones regionales alemanas.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

En este ejemplo, la interfaz es el formato inglés y regional sigue siendo alemán. `getCurrentLocale()` y `getCurrentRegion()` devuelven los identificadores que están en efecto. Para cambiar ambos juntos, llame a ambas máquinas con el mismo valor `LocaleType`.

- **Hojas: controles de divisas**: `region` controla el icono de la barra de herramientas de divisas, las opciones de divisas y contabilidad y sus previsiones, y el patrón aplicado por el comando de divisas.
- **Docs: estadística**: `region` formatos los recuentos mostrados en el cuadro de diálogo de estadísticas y la barra de estado, por ejemplo los separadores de agrupación. Cambiar `region` no cambia las reglas de conteo.
- **Thread comments, when enabled**: `region` controla el formato de fecha y hora mostrado, con tiempo de 24 horas y dígitos latinos. `locale` controles comentario Texto de la interfaz de usuario. Ni cambios horarios almacenados; `region` no es un ajuste de la zona horaria.
- **Boards, Slides, Bases, PDFs**: Controles `locale` traducidos UI. `region` está disponible para características compartidas que lo consumen, como comentarios de hilo cuando se integra; no se reforma automáticamente tabla o texto de diapositivas, campos Base, o contenido PDF.
