## Ciclo de vida global

Univer pasa a través de cuatro etapas globales durante la puesta en marcha:

- **Starting**: Inicialización, antes de crear unidades de negocio.
- **Listo**: la primera unidad de negocio ha sido creada. unidades posteriores no activan esta etapa de nuevo.
- **Rendered**: la interfaz de usuario estándar ha realizado su primer interruptor de renderizado, aunque el contenido asincrónico todavía puede estar cargando.
- **Tranquila.**: la interfaz de usuario estándar alcanza esta etapa después de un retraso después de Rendered. No espera todas las tareas asincrónicas.

### API de Facade

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Qué comunica el evento">

`LifeCycleChanged` reporta la etapa global de Univer. Si el plugin B se carga después de la etapa `Ready` global, B todavía funciona `onReady()`, pero no se produce un segundo evento `Ready` mundial.

Cuando se agrega un oyente, su callback puede recibir la etapa actual inmediatamente, incluyendo `Starting`. Para determinar la etapa actual sin un oyente , llame a `univerAPI.getCurrentLifecycleStage()` .

</Callout>

Para eliminar un oyente, utilice el objeto `disposable` devuelto:

```typescript
disposable.dispose()
```

## Hooks del ciclo de vida de plugins

Un plugin funciona `onStarting()` cuando se carga y luego se pone al día con la actual etapa global. Ganar plugin B en diferentes puntos para comparar sus llamadas de gancho con las de plugin A.

Los plugins generales se cargan cuando están registrados. Los plugins de tipo empresarial suelen cargar antes de que se construya la primera unidad de ese tipo. Plugins añadidos para un tipo que ya ha empezado a cargar en un lote diferido. Una dependencia explícita puede causar un plugin para cargar antes.

Los ganchos en cada lote corren sincrónicamente, etapa por etapa y en orden de dependencia, y trabajo asincrónico dentro de un gancho no se espera. Antes de acceder a una unidad específica, elemento DOM, o recurso, confirman que está listo.
