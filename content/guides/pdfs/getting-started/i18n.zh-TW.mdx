## 介面語言

`locale` 決定選單、提示、對話方塊和其他介面文案使用哪套語言套件，`locales` 只註冊語言套件，不指定當前語言。該設定對 Univer 例項中的所有文件單元生效。取值來自 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有產品：介面**：`locale` 切換選單、提示、對話方塊和外掛標籤上的譯文，不會翻譯使用者內容，也不會重新命名已有文件單元。
- **Sheets：單元格格式與公式**：單元格中的數字和日期渲染時，先使用數字格式的 locale 覆蓋值，再使用工作簿快照的 `locale`，最後使用例項的 `locale`。`region` 不會替代上述任何一項。`DOLLAR` 等公式行為以及財務結果上的貨幣格式仍由 `locale` 決定，中日韓輸入歸一化同樣使用 `locale`。
- **Docs：文件統計**：`locale` 決定分詞和字數統計。

### 執行時切換語言

切換語言之前，應載入所有已安裝外掛或預設的語言套件。`loadLocales()` 只合並翻譯，不切換語言；`setLocale()` 只選擇已載入的語言套件，不會下載任何內容。缺失的翻譯鍵會直接顯示為鍵名。下面的範例只載入共享 UI 語言套件；其他已安裝外掛的目標語言套件應在同一次呼叫中一併合併。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 合併語言套件 [#mergeLocales]

`mergeLocales` 將多個外掛或預設的語言套件合併為一個完整的語言套件物件。下面兩種寫法均可使用：

<Tabs items={['外掛模式', '預設模式']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // 你可以直接傳入多個語系物件
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以傳入語系物件陣列
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```

  </Tab>
  <Tab>

    ```typescript
    )
    ```

### 自訂語系檔

Univer 也支援自定義語言套件。按需構造語言套件物件並傳給 `Univer` 例項。預設語言套件通常位於 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目錄下。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## 地區設定

`region` 決定需要地區習慣的功能使用哪套地區規則。該設定同樣對 Univer 例項中的所有文件單元生效。

兩項設定都使用 `LocaleType` 值。例如 `LocaleType.EN_US` 對應的值是 `enUS`，而 `en-US` 既是語言套件檔名，也是 BCP 47 標籤。不要將 `US`、`SG` 等國家程式碼傳給 `region`。介面使用其他語言時，地區不需要對應的語言套件。

如果從未設定 `region`，它會跟隨 `locale`，後續呼叫 `setLocale()` 時也會隨之變化。在初始化時設定 `region` 或呼叫 `setRegion()` 後，不再自動跟隨，之後切換語言會保留已選定的地區。目前沒有恢復自動跟隨的公開 API，兩者需要一起變更時應同時呼叫兩個 setter。

在 `createUniver()` 或 `new Univer()` 中為 `locale` 新增 `region: LocaleType.DE_DE`，即可保留介面語言並使用德國地區習慣。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此時介面為英文，地區格式仍按德國習慣處理。`getCurrentLocale()` 和 `getCurrentRegion()` 返回實際生效的標識。要讓兩者一起變更，使用同一個 `LocaleType` 值分別呼叫兩個 setter。

- **Sheets：貨幣操作**：`region` 決定貨幣工具欄圖示、貨幣和會計格式的選項及預覽，以及貨幣命令應用的格式。更改該設定不會重寫已有單元格格式，也不會換算金額。
- **Docs：文件統計**：`region` 決定統計對話方塊和狀態列中數字的顯示格式，例如分組分隔符。僅更改 `region` 不會改變統計規則。
- **啟用評論時**：`region` 決定日期時間的顯示格式，採用 24 小時制和拉丁數字；`locale` 決定評論介面文案。兩者都不會修改已儲存的時間戳，`region` 也不是時區設定。
- **Boards、Slides、Bases、PDFs**：`locale` 控制介面翻譯。`region` 供讀取它的共享功能使用，例如整合後的評論；它不會自動重新格式化白板或幻燈片文字、Base 欄位或 PDF 內容。
