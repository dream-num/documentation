## 전역 수명 주기

Univer는 4개의 세계적인 단계를 통해 시작 도중 통과합니다:

- **Starting**: 초기화 중이며 업무 단위는 아직 없습니다.
- **지원하다**: 첫번째 사업 단위는 창조되었습니다. 나중에 단위는 이 단계를 다시 방아쇠하지 않습니다.
- **이름 ***: 표준 UI는 비동기 내용이 아직도 적재될지도 모르더라도, 그것의 첫번째 렌더링 스위치를 실행했습니다.
- **인기 카테고리**: 표준 UI는 렌더링 후 지연 후이 단계를 도달합니다. 모든 비동기 작업을 기다릴 수 없습니다.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="이벤트가 알리는 대상">

`LifeCycleChanged`는 Univer의 글로벌 스테이지를 보고합니다. 플러그인 B가 글로벌 `Ready` 스테이지 후 로드되면 B는 여전히 `onReady()`를 실행하지만 두 번째 글로벌 `Ready` 이벤트가 발생하지 않습니다.

청취자가 추가될 때, 콜백은 `Starting`를 포함한 현재 스테이지를 즉시 받게 될 수 있습니다. 청취자 없이 현재 스테이지를 결정하려면 `univerAPI.getCurrentLifecycleStage()`로 전화하십시오.

</Callout>

청취자를 제거하려면 반환된 `disposable` 개체를 사용하십시오.

```typescript
disposable.dispose()
```

## 플러그인 수명 주기 훅

플러그인은 `onStarting()`를 실행하면 현재 글로벌 스테이지로 끌어올릴 수 있습니다. 플러그인 A와 같은 후크 통화를 비교하기 위해 다른 지점에서 플러그인 B를로드하십시오.

<LifecycleDemo />

일반 플러그인로드가 등록 될 때. 비즈니스 유형 플러그인은 일반적으로 그 유형의 첫 번째 단위 전에로드됩니다. 플러그인은 이미 deferred 배치에로드를 시작 한 유형에 추가되었습니다. 명시적 의존도는 이전로드 플러그인을 일으킬 수 있습니다.

각 배치에 있는 걸이는 비동기적으로, 단계 및 의존성 순서에서, 그리고 걸이 안쪽에 비동기 일 기다리고 있지 않습니다. 특정한 단위, DOM 성분, 또는 자원 접근하기 전에, 준비되어 있다는 것을 확인하십시오.
