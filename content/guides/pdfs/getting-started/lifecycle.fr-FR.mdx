## Cycle de vie global

Univer passe par quatre étapes mondiales pendant le démarrage :

- **Starting**: Initialisation, avant la création d’une unité métier.
- **Prêt**: la première unité commerciale a été créée. Les unités ultérieures ne déclenchent pas cette étape à nouveau.
- **Rendu** : l'interface utilisateur standard a effectué son premier commutateur de rendu, bien que le contenu asynchrone puisse encore être chargé.
- **Stabilité** : l'interface utilisateur standard atteint cette étape après un délai après la soumission. Elle n'attend pas toutes les tâches asynchrones.

### API Facade

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Ce que signale l’événement">

`LifeCycleChanged` rapporte la phase globale de Univer. Si le plugin B se charge après la phase globale `Ready`, B exécute toujours `onReady()` mais aucun second événement global `Ready` ne se produit.

Lorsqu'un auditeur est ajouté, son callback peut recevoir immédiatement l'étape courante, y compris `Starting`. Pour déterminer l'étape actuelle sans auditeur, appelez `univerAPI.getCurrentLifecycleStage()` .

</Callout>

Pour supprimer un auditeur, utilisez l'objet `disposable` retourné :

```typescript
disposable.dispose()
```

## Hooks de cycle de vie des plugins

Un plugin exécute `onStarting()` lorsqu'il charge puis rattrape la phase globale actuelle. Chargez le plugin B à différents points pour comparer ses appels de crochet avec ceux du plugin A.

<LifecycleDemo />

Les plugins de type Business chargent généralement avant la construction de la première unité de ce type. Plugins ajoutés pour un type qui a déjà commencé à charger dans un lot différé. Une dépendance explicite peut provoquer une charge d'un plugin plus tôt.

Les crochets dans chaque lot sont exécutés synchronement, étape par étape et dans l'ordre de dépendance, et le travail asynchrone à l'intérieur d'un crochet n'est pas attendu. Avant d'accéder à une unité spécifique, élément DOM, ou ressource, confirmer qu'il est prêt.
