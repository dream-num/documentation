`UniverPdfsUIPlugin` compose l’interface PDF à partir des zones standard de l’espace de travail Univer.

| Mode | Composants montés par le plugin PDF UI |
| --- | --- |
| Toujours | Rail de miniatures dans la barre latérale gauche, canevas PDF dans la zone de contenu et pied de page PDF. |
| `editor.enabled: true` | Ruban et menus contextuels, inspecteur de propriétés, intégration du presse-papiers, contrôles d’insertion et composants de menu de l’éditeur. |

Avec `editor.enabled: false`, les parties de la visionneuse restent présentes et les composants et services réservés à l’éditeur sont omis.

## Limite des composants PDF

Les vues React et identifiants du canevas, du rail de miniatures, du pied de page, de l’inspecteur, du sélecteur de tableau et du libellé de mode sont des détails internes. L’entrée racine de `@univerjs-pro/pdfs-ui` ne les exporte pas et ils ne constituent pas des emplacements de remplacement pris en charge.

Ne déduisez pas et ne copiez pas de clé interne pour remplacer ces vues avec `univerAPI.registerComponent`. Utilisez le [guide de la Facade PDF](/guides/pdfs/getting-started/facade) pour piloter le PDF avec les API prises en charge.

## Ajouter une interface applicative à côté d’un PDF

La Facade UI partagée peut enregistrer un composant applicatif et l’afficher dans une barre latérale ou une boîte de dialogue Univer standard. Cela étend l’application environnante sans remplacer un composant du plugin PDF.

```tsx
const registration = univerAPI.registerComponent(
  'pdf-help-panel',
  () => <div>PDF workflow help</div>,
)

const sidebar = univerAPI.openSidebar({
  id: 'pdf-help',
  header: { title: 'PDF help' },
  children: { label: 'pdf-help-panel' },
  width: 320,
})

// Lorsque l’extension n’est plus nécessaire :
sidebar.dispose()
registration.dispose()
```

Enregistrez le composant après le chargement de la Facade UI et libérez les deux handles lors du retrait de l’extension.
