## Qué es Univer PDFs

Univer PDFs es el producto PDF en Univer Office SDK. Un PDF se convierte en una unidad `UNIVER_PDF` formal: el documento fuente importado se conserva como era, y las ediciones aceptadas se almacenan en una capa de edición duradera separada. El navegador UI renderiza ambas capas como un documento continuo.

Univer PDFs es un tipo de unidad dentro de [Web SDK](/guides/sheets), no un SDK propio. Web SDK proporciona al espectador y el procesamiento de contenidos sin cabeza. La colaboración y la conversión de archivos son parte de [Server SDK](/server), y los flujos de trabajo de agente pertenecen a [AI SDK](/ai).

Utilice Univer PDFs cuando una aplicación necesita crear o abrir PDFs, añadir contenido editable, preservar la apariencia de un PDF importado, colaborar en cambios, exportar el resultado, o entregar el documento abierto al flujo de trabajo de impresión del navegador.

<Callout type="warning" title="Modo de plugin sólo">
  No hay paquete de preset PDF. Usted registra el modelo PDF, la interfaz de usuario, y cualquier plugin de función opcional explícitamente.
</Callout>

## Compatibilidad del navegador

Web SDK compila con un objetivo Chrome 88, pero eso no significa que cada entorno principal sea totalmente compatible. Web SDK se mantiene para funcionar correctamente en los siguientes navegadores y versiones Node.js:

| Edge | Firefox | Chrome | Safari | Electron |
| ---- | ------- | ------ | ------ | -------- |
| >=88 | >=90    | >=88   | >=14.1 | >=12     |

<Callout type="warning">
  Web SDK depende de `Intl.Segmenter`. Si el navegador o el tiempo de ejecución no lo soporta, agregue un polífilo primero. El polifilo recomendado es `@formatjs/intl-segmenter` .
</Callout>

Cuando se produce un problema de compatibilidad, prueba primero el polífilo que coincide. Si el problema persiste, [presentar una cuestión](https://github.com/dream-num/univer/issues/new/choose).

## Compatibilidad con Node.js

<Callout type="warning">
  Esto se aplica sólo para ejecutar Web SDK dentro de Node.js. No cubre la ejecución Web SDK en un navegador a través de una herramienta de construcción basada en Node.js.
</Callout>

Web SDK funciona en Node.js v18.17.0 y más tarde.

## Aspectos destacados

- El modelo de unidad PDF mantiene el documento fuente, la estructura de página, los recursos y la intención de edición duradera en `IPdfUnitData`.
- Las páginas pueden ser navegadas e insertadas, y se pueden editar texto, listas, tablas, imágenes, divisores y anotaciones.
- El banco de trabajo del navegador hace páginas PDF y miniaturas, y maneja selección, controles de edición, comportamiento de portapapeles, y el inspector UI.
- Los cambios aceptados pasan por comandos duraderos y murciélagos de mutación, así que guardar, deshacer y redo operan contra el mismo modelo.
- El Facade API crea, encuentra, edita y ahorra unidades PDF a través de archivos PDF, página, elemento y objetos de texto nativo.

## Cómo leer la documentación

La navegación de la documentación está a la izquierda. Las páginas se ordenan de base a avanzada, por lo que pueden leerse en secuencia mientras construyen una aplicación, o saltan a las secciones que un caso de uso requiere. Los PDFs Univer también se pueden seleccionar en la parte superior de la barra lateral.

La tabla de contenidos en las barras derechas entre secciones de la página actual. Para encontrar otra página, utilice la barra de búsqueda en la parte superior o el atajo de búsqueda (Ctrl+K o Cmd+K).

Empieza con la guía [Inicio rápido](/guides/pdfs/getting-started/installation).

## Conocimientos previos requeridos

La documentación está escrita para ser accesible, pero supone una base de referencia para que pueda mantenerse centrada en Web SDK.

Los lectores obtienen el máximo provecho de la documentación con una comprensión básica de JavaScript y el ecosistema circundante.

Si planea ejecutar Web SDK en Node.js, también se recomienda un entendimiento básico de Node.js.

La colaboración, la historia compartida, los comentarios y la conversión de archivos son funciones del servidor. Están habilitados por componer módulos de [Univer Server SDK](/server) en el backend; autenticación, permisos, almacenamiento y despliegue siguen siendo la responsabilidad de la aplicación. Un PDF editado sólo en el navegador no requiere ninguno de ellos.
