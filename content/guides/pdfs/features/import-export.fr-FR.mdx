Les API ci-dessous nécessitent un moteur de conversion. Commencez par [intégration d'échange de fichiers](/server/import-export) pour connecter les téléchargements, conversions, requêtes de tâches, puis configurer les plugins du navigateur. Les API Snapshot utilisent le même moteur mais ne nécessitent pas de document collaboratif. L'exemple d'échange de collaboration démontre Feuilles, donc confirmer que la version cible supporte les types de fichiers requis.

Si une exportation échoue, voir [codes d'erreur de licence et traitement de l'échec des tâches](/server/import-export#export-errors).

## Formats pris en charge

Le tableau couvre les API du navigateur sur cette page. La conversion de fichier Office nécessite également un moteur de recherche qui prend en charge le même type de document et le même format.

| Importation | Exportation |
| --- | --- |
| `.pdf` | `.pdf` |

Ces API n'importent et n'exportent que des fichiers PDF. Elles ne convertissent pas le contenu PDF en DOCX, XLSX ou PPTX. L'impression par navigateur est un flux de travail séparé.

## Choisir un chemin de données

| Chemin     | Conserve une unité serveur | Collaboration requise | Serveur de conversion |
| ---------- | :------------------------: | :-------------------: | :-------------------: |
| ID d'unité |            Oui             |          Oui          |        Requis         |
| Snapshot   |            Non             |          Non          |        Requis         |

### Importer dans une unité conservée

Passez un navigateur `File` ou une URL, puis chargez l'unité retournée via le client de collaboration configuré.

```ts
const unitId = await univerAPI.importPdfToUnitIdAsync(file)

if (unitId) {
  const pdf = await univerAPI.getCollaboration().loadPdfAsync(unitId)
  console.log(pdf?.getName())
}
```

### Importer dans un snapshot

Utilisez l'import instantané pour une unité PDF locale que la tâche de conversion ne persiste pas :

```ts
const snapshot = await univerAPI.importPdfToSnapshotAsync(file)

if (snapshot) {
  univerAPI.createPdf(snapshot)
}
```

### Exporter et télécharger

Exporter une unité persistante par son ID:

```ts
const file = await univerAPI.exportPdfByUnitIdAsync(unitId)

if (file) {
  univerAPI.downloadFile(file, 'project-brief', 'pdf')
}
```

Exportez le snapshot local actuel sans le conserver au préalable :

```ts
const pdf = univerAPI.getActivePdf()

if (pdf) {
  const file = await univerAPI.exportPdfBySnapshotAsync(pdf.save())

  if (file) {
    univerAPI.downloadFile(file, pdf.getName(), 'pdf')
  }
}
```

Ces API renvoient un `File`. L'impression dans le navigateur est un workflow séparé qui ouvre la boîte de dialogue d'impression du système. Voir [Imprimer](/guides/pdfs/features/print).

## Suppression des menus et des interactions UI d’importation et d’exportation intégrés [#import-export-ui-migration]

<Callout type="warning" title="À noter">
  À partir de la version **1.2.0**, Univer a supprimé les menus et les interactions UI d’importation et d’exportation intégrés. Les services sous-jacents et les API Facade restent disponibles.
</Callout>

Si une application doit conserver les menus d'importation/exportation existants et les interactions UI, le [exemple de migration pour les menus d'importation/exportation intégrés et les interactions d'assurance-chômage](https://office.univer.ai/showcase/pdfs/custom-import-export) montre comment les restaurer avec un plugin personnalisé. L'exemple inclut la source complète, qui peut être visionnée en ligne ou téléchargée.
