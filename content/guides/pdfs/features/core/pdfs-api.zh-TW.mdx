PDF Facade 為 `FUniver` 增加了 PDF 單元和頁面入口。建立 API 物件之前，應先匯入副作用入口。

## 啟用 PDF Facade

```ts
import { FUniver } from '@univerjs/core/facade'

import '@univerjs-pro/pdfs/facade'

const univerAPI = FUniver.newAPI(univer)
```

在 Univer 例項上註冊 `UniverPdfsPlugin`，應用即可承載 PDF 單元。

## 建立、尋找和儲存 PDF 單元

省略 `document` 時，`createPdf()` 會建立一個僅含一張空白 A4 頁面的單元。如需恢復單元，應傳入之前 `save()` 返回的快照。

```ts
const pdf = univerAPI.createPdf({
  id: 'project-brief',
  name: 'Project brief',
})

const activePdf = univerAPI.getActivePdf()
const samePdf = univerAPI.getPdf(pdf.getId())
const snapshot = pdf.save()
```

更新執行中的 PDF 時，應使用 Facade 方法或命令。儲存的快照是獨立的持久化資料。

## 從另一個 PDF 附加頁面 [#append-pages]

`FPdf.appendPdf(source)` 會附加 `IPdfUnitData` 快照的每一頁，並把這次變更記入撤銷與重做歷史。PDF 已不再開啟時，返回 `false`。

Exchange facade 為已經開啟的 PDF 新增了方法。`univerAPI.appendPdfAsync(file, unitId?)` 會匯入檔案，並把它的頁面附加到指定的 PDF。省略單元 ID 時附加到當前 PDF。沒有目標或頁面無法附加時，會解析為 `false`。`univerAPI.exportPdfAsync(unitId?)` 會先提交畫布上仍在編輯的文字，再匯出已開啟的 PDF。提交失敗或文件已不再開啟時，會解析為 `undefined`。

這些 Exchange 方法由 `@univerjs-pro/pdfs-exchange-client/facade` 新增到 `FUniver`：

```ts
const pdf = univerAPI.getActivePdf()
pdf?.appendPdf(importedSnapshot)

await univerAPI.appendPdfAsync(file)          // current PDF
await univerAPI.appendPdfAsync(file, unitId)  // specific PDF
const exported = await univerAPI.exportPdfAsync()
```

## 進入頁面

`FPdfPage` 是訪問頁面可編輯疊加層和匯入原生文字的常用入口：

```ts
const firstPage = pdf.getPageByIndex(0) ?? pdf.insertPage()
const elements = firstPage.getElements()
const nativeText = firstPage.getTextSpans()
```

具體操作請參閱[頁面與元素](/guides/pdfs/features/core/pages-and-elements)、[文字與列表](/guides/pdfs/features/core/text-and-lists)、[表格](/guides/pdfs/features/core/tables)、[圖片與分隔線](/guides/pdfs/features/core/images-and-dividers)或[批註與原生文字](/guides/pdfs/features/core/annotations-and-native-text)。

## 卸載 PDF 單元

不再需要某個 PDF 單元時，應按 ID 解除安裝。僅在銷燬整個應用時，才釋放根 `univer` 例項。

```ts
const pdf = univerAPI.getActivePdf()

if (pdf) {
  univerAPI.disposeUnit(pdf.getId())
}
```

準確的簽名與返回型別請參閱 [PDF Facade 參考](/reference/facade/pdf)。
