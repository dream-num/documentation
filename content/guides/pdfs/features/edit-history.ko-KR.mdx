PDF 단위는 편집 중 undo 및 redo를 지원하지만 시트, Docs, 슬라이드, 보드 및베이스에 대한 그들에 적합한 전용 버전의history 패널 플러그인이 없습니다. PDF의 다른 제품 역사 UI 플러그인을 등록하지 마십시오.

## 실행 취소 및 다시 실행

Undo와 redo는 현재 초점이 있는 Univer Unit에 적용합니다:

```ts
await univerAPI.undo()
await univerAPI.redo()
```

이 호출은 서버 측 버전 목록을 만들지 않으며 이전 세션에서 버전을 검색 할 수 없습니다. 다른 작업의 경우 [일반 API](/guides/pdfs/features/core/general-api)를 참조하십시오.

## 세션 간 버전 관리

[PDF의 협업](/guides/pdfs/features/collaboration)와 함께 시작하십시오. 장기 버전을 유지해야하는 응용 프로그램은 [사무실 역사 서비스](/server/collaboration/extensions)를 검토해야하며 대상 릴리스는 PDF 데이터를 지원하며 버전 목록 및 뷰어를 구현합니다. 일반 역사 서비스 등록은 자체로 PDF 역사 패널을 추가하지 않습니다.

복원 콘텐츠는 페이지에 표시된 데이터를 대체하는 것보다 더 많은 것을 요구합니다. 또한 문서 권한, 활성 협업 세션과 조정 및 관련 PDF 파일의 보존이 필요합니다.
