PDF Unidades soportan el deshacer y redo durante la edición, pero no hay un plugin dedicado de la versión-historia comparable a los de Hojas, Docs, Diapositivas, Juntas y Bases. No registre el plugin UI de otro producto para PDFs.

## Deshacer y rehacer

Deshacer y redo aplicar a la Univer Unit que actualmente tiene foco:

```ts
await univerAPI.undo()
await univerAPI.redo()
```

Estas llamadas no crean una lista de versiones del lado del servidor y no pueden recuperar versiones de sesiones anteriores. Para otras operaciones, consulte [API general](/guides/pdfs/features/core/general-api).

## Versiones entre sesiones

Comience con [Colaboración en PDF](/guides/pdfs/features/collaboration). Las aplicaciones que necesitan mantener las versiones a largo plazo deben revisar el [Servicio de historia de oficinas](/server/collaboration/extensions), confirmar que el lanzamiento de destino soporta los datos PDF, e implementar la lista de versiones y el visor. Registrar el servicio de Historia genérica no añade un panel de historia de PDF por sí mismo.

Restaurar contenido requiere más que reemplazar los datos mostrados en la página. También requiere autorización de documentos, coordinación con la sesión de colaboración activa y retención de los archivos PDF asociados.
