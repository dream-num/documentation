PDF Units support undo and redo during editing, but there is no dedicated version-history panel plugin comparable to those for Sheets, Docs, Slides, Boards, and Bases. Do not register another product's History UI plugin for PDFs.

## Undo and redo

Undo and redo apply to the Univer Unit that currently has focus:

```ts
await univerAPI.undo()
await univerAPI.redo()
```

These calls do not create a server-side version list and cannot retrieve versions from previous sessions. For other operations, see [General API](/guides/pdfs/features/core/general-api).

## Versions across sessions

Begin with [PDFs collaboration](/guides/pdfs/features/collaboration). Applications that need to keep versions long term should review the [Office history service](/server/collaboration/extensions), confirm that the target release supports PDF data, and implement the version list and viewer. Registering the generic History service does not add a PDF history panel by itself.

Restoring content requires more than replacing the data displayed on the page. It also requires document authorization, coordination with the active collaboration session, and retention of the associated PDF files.
