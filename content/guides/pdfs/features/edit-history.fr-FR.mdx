PDFs prend en charge l’annulation et le rétablissement pendant l’édition. Il ne propose actuellement pas de plugin de panneau d’historique des versions équivalent à ceux de Sheets, Docs, Slides, Boards ou Bases. N’enregistrez pas pour PDFs le plugin History UI d’un autre produit.

## Annuler et rétablir

Ces opérations agissent sur l’unité Univer qui a le focus :

```ts
await univerAPI.undo()
await univerAPI.redo()
```

Elles ne créent pas de liste de versions côté serveur et ne récupèrent pas les versions de sessions précédentes. Consultez l’[API générale](/guides/pdfs/features/core/general-api) pour les autres opérations.

## Versions conservées entre les sessions

Commencez par la [collaboration PDFs](/guides/pdfs/features/collaboration). Pour conserver les versions à long terme, consultez le [service d’historique Office](/server/collaboration/extensions), vérifiez la prise en charge des données PDF dans la version ciblée et implémentez la liste des versions et la visionneuse dans votre application. Ajouter le service History générique n’ajoute pas automatiquement un panneau d’historique PDF.

La restauration du contenu nécessite une autorisation sur le document, une coordination avec la session collaborative active et la conservation des fichiers PDF associés. Remplacer les données affichées sur la page ne suffit pas.
