Les unités PDF prennent en charge l'annulation et le redécoupage lors de l'édition, mais il n'y a pas de plugin dédié de panneau d'histoire de version comparable à ceux pour les feuilles, les Docs, les diapositives, les tableaux et les bases.

## Annuler et rétablir

Undo et redo s'appliquent à la Univer Unit qui a actuellement focalisé:

```ts
await univerAPI.undo()
await univerAPI.redo()
```

Ces appels ne créent pas de liste de versions côté serveur et ne peuvent pas récupérer les versions des sessions précédentes. Pour d'autres opérations, voir [API générale](/guides/pdfs/features/core/general-api).

## Versions conservées entre les sessions

Commencez par [Collaboration avec les PDF](/guides/pdfs/features/collaboration). Les applications qui doivent garder les versions à long terme devraient examiner le [Service d'historique des bureaux](/server/collaboration/extensions), confirmer que la version cible supporte les données PDF, et implémenter la liste de versions et le visionneur. L'enregistrement du service d'historique générique n'ajoute pas un panneau d'historique PDF en soi.

La restauration du contenu nécessite plus que le remplacement des données affichées sur la page. Elle nécessite également l'autorisation du document, la coordination avec la session de collaboration active et la conservation des fichiers PDF associés.
