## Что такое Univer Boards

Платы Univer - это холстовый продукт в Univer Office SDK. Он используется, когда документ больше не является сеткой, страницей или слайд-палубой, а рабочим пространством свободной формы: доски, диаграммы, липкие заметки, разъемы, встроенные таблицы и карты разума - все принадлежат здесь.

Платы используют [Web SDK](/guides/sheets) для встроенных холстов в браузере, а Web SDK также обрабатывает безголовую обработку контента. [Server SDK](/server) обеспечивает совместную работу и обмен файлами, а [AI SDK](/ai) позволяет агенту редактировать доску.

Платы являются независимым типом блока в Web SDK. Во время выполнения приложение создает блок `UniverInstanceType.UNIVER_BOARD`, а затем регистрирует модель и плагины пользовательского интерфейса для элементов, которые ему необходимо поддерживать.

## Совместимость с браузерами

Web SDK компилируется с целью Chrome 88. Эта цель не означает, что Web SDK работает в каждой среде. Поддерживаются следующие браузеры и среды Node.js:

| Edge | Firefox | Chrome | Safari | Electron |
| ---- | ------- | ------ | ------ | -------- |
| >=88 | >=90    | >=88   | >=14.1 | >=12     |

<Callout type="warning">
  Web SDK полагается на `Intl.Segmenter`. Если браузер или среда выполнения не поддерживает его, сначала добавьте соответствующий полифилл. Рекомендуемым полифиллом является `@formatjs/intl-segmenter` .
</Callout>

Если возникает проблема совместимости, сначала нанесите соответствующий полифилл. Если проблема сохраняется, [Представить вопрос](https://github.com/dream-num/univer/issues/new/choose).

## Совместимость с Node.js

<Callout type="warning">
  Этот раздел охватывает только запуск Web SDK внутри Node.js. Он не применяется, когда Web SDK запускается в браузере с помощью инструментов сборки на основе Node.js .
</Callout>

Web SDK работает в Node.js v18.17.0 и позже.

## Основные возможности

- **Страницы и порядок элементов**: страницы, хранящиеся в `pages`, и рисуемые объекты, хранящиеся на `elements` каждой страницы, с явным массивом заказов на обоих уровнях.
- **Канвасные элементы**: текст, формы, изображения, разъемы, группы, контейнеры и плавательные бассейны.
- **Редактирование на командной основе**: изменения элементов, порядок и родительские отношения маршрутизируются через один командный уровень, который несет разрешения и крючки для дополнительной истории и интеграции совместной работы.
- **Полотно для браузера**: рендеринг элементов, выбор, преобразования, буфер обмена, редактирование текста, элементы управления портом просмотра и панели.
- **Расширяемые адаптеры**: дополнительные возможности платы, такие как таблицы, карты памяти, диаграммы, ресурсы, печать и обмен.
- **настойчивость**: создание, восстановление и сохранение снимков `IBoardData`, включая страницы, ресурсы, темы и состояние активной страницы.

## Как читать документацию

Навбар слева перечисляет страницы по порядку, от базовых до продвинутых, чтобы читатели могли шаг за шагом следовать за ними при создании приложения. Страницы можно читать в любом порядке, а страницы, которые не относятся к варианту использования, можно пропустить. Заголовок боковой панели обеспечивает переключение на документацию Univer Boards.

Таблица содержимого справа обеспечивает навигацию между разделами текущей страницы. Чтобы быстро найти страницу, используйте строку поиска вверху или ярлык поиска (Ctrl + K или Cmd + K).

Чтобы начать работу, см. руководство [Быстрый старт](/guides/boards/getting-started/installation).

## Необходимые знания

Документация написана для новичков, но она предполагает базовые знания, чтобы она могла сосредоточиться на Web SDK.

Читатели получают максимальную отдачу от документации с базовым пониманием JavaScript и его экосистемы.

Если Web SDK будет работать на Node.js, рекомендуется также базовое понимание Node.js.

Когда несколько человек редактируют одну и ту же доску, или требуется общая история, комментарии или преобразование файлов, добавьте соответствующие модули из [Univer Server SDK](/server) и запустите их в бэкэнде приложения. Аутентификация, разрешения, хранение и развертывание остаются ответственностью приложения. Доска, которая открывается только в браузере, не требует этих услуг.
