## 전역 수명 주기

- **을 시작**: Univer는 초기화됩니다; 사업 단위는 아직 존재하지 않습니다.
- **지원하다**: 첫번째 사업 단위는 창조되었습니다. 나중에 단위는 이 단계를 다시 방아쇠하지 않습니다.
- **이름 ***: 표준 UI는 첫번째 렌더링 스위치를 실행했습니다. 비동기 내용은 아직 로드되지 않을지도 모릅니다.
- **인기 카테고리**: 표준 UI는 렌더링 후 지연 후이 단계를 도달합니다. 그것은 완료 할 비동기 작업을 기다릴 수 없습니다.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="이벤트가 알리는 대상">

`LifeCycleChanged`는 Univer의 글로벌 스테이지를 보고합니다. 글로벌 `Ready` 스테이지 이후 플러그인 B가 로드되면 B는 여전히 `onReady()`를 호출하지만 추가 글로벌 `Ready` 이벤트가 방출되지 않습니다.

청취자는 `Starting`를 포함하여, 추가된 후에 현재 단계를 즉시 받을 수 있습니다. 현재 단계만 읽기 위하여는, `univerAPI.getCurrentLifecycleStage()` 직접 부르십시오.

</Callout>

청취자를 제거하려면 반환된 `disposable` 객체를 분해하십시오.

```typescript
disposable.dispose()
```

## 플러그인 수명 주기 훅

플러그인은 `onStarting()`를 실행할 때로드, 그리고 현재의 글로벌 단계로 잡습니다. B의 로드 시간을 변경하여 A의 그 후크 통화를 비교합니다.

<LifecycleDemo />

일반 플러그인은 등록에로드합니다. 비즈니스 유형 플러그인은 일반적으로 그 유형의 첫 번째 단위 전에로드됩니다. 이미 시작된 유형의 경우, 그 유형의 새로운 플러그인은 deferred 일괄 배치에로드합니다. Explicit Dependencies는 플러그인이 이전로드 될 수 있습니다.

일괄 처리에서 후크는 비동기적으로, 단계 및 의존성 순서로, 그리고 그 안에 비동기적인 일을 기다리지 않습니다. 당신이 접근하기 전에 관련 단위, DOM 성분 또는 자원이 준비되어 있다는 것을 확인하십시오.
