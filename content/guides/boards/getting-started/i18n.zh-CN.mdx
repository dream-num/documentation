## 界面语言

`locale` 决定菜单、提示、对话框等界面文案采用哪套语言包；`locales` 仅注册语言包，不负责选择语言。该配置由 Univer 实例内的各个单元共享。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有产品：界面**：`locale` 决定菜单、提示、对话框和插件标签的语言，不翻译用户内容，也不重命名已有单元。
- **Sheets：单元格格式与公式**：单元格中数字与日期的显示依次取用数字格式的 locale 覆盖值、工作簿快照的 `locale` 和实例的 `locale`。`region` 不替代其中任何一项。`DOLLAR` 等公式行为以及财务结果的货币格式仍使用 `locale`，中日韩输入归一化也使用 `locale`。
- **Docs：文档统计**：`locale` 决定分词和字数统计。

### 运行时切换语言

切换语言前，先加载所有已安装插件和预设的语言包。`loadLocales()` 只合并翻译，不切换语言；`setLocale()` 只选择语言，不下载任何内容。缺失的翻译键会直接显示为键名。下例加载共享 UI 语言包；其他已安装插件的目标语言包需在同一次调用中一并合并。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 合并语言包 [#mergeLocales]

`mergeLocales` 将多个插件或预设的语言包合并为一个完整的语言包对象：

    // 你可以传入多个语言包对象进行合并

### 自定义语言包

Univer 也支持自定义语言包：按需组装语言包对象并传入 `Univer` 实例。预设语言包通常存放在 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目录。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 贡献语言包

Univer 目前提供以下内置语言包：

- `zh-CN`：简体中文
- `en-US`：英文
- `zh-TW`：繁体中文
- `zh-HK`：繁体中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韩文
- `es-ES`：西班牙文
- `ca-ES`：加泰罗尼亚文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：意大利文
- `pl-PL`：波兰文
- `pt-BR`：葡萄牙文（巴西）

Univer 目前尚不支持其他语言。欢迎世界各地的开发者添加或改进语言包。

## 地区设置

`region` 决定地区相关功能所遵循的地区习惯。该配置由 Univer 实例内的各个单元共享。

两项配置均取 `LocaleType` 值。例如 `LocaleType.EN_US` 的值为 `enUS`，而 `en-US` 是语言包文件名，也是 BCP 47 标签。`region` 不要传入 `US`、`SG` 等国家代码。界面使用其他语言时，该地区无需加载对应的语言包。

未显式设置 `region` 时，它会跟随 `locale`，后续调用 `setLocale()` 也会同步更新地区。一旦在初始化时设置 `region` 或调用 `setRegion()`，这种自动跟随即停止，此后切换语言会保留已显式指定的地区。目前没有公开 API 可以恢复跟随行为，需要两者同时变化时，请同时更新两项。

在 `createUniver()` 或 `new Univer()` 中，于 `locale` 旁设置 `region: LocaleType.DE_DE`，即可在保留界面语言的同时使用德国地区习惯。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此时界面为英文，地区格式仍为德国。`getCurrentLocale()` 和 `getCurrentRegion()` 返回当前实际生效的标识。需要语言与地区同时变化时，用同一个 `LocaleType` 值分别调用两个 setter。

- **Sheets：货币操作**：`region` 决定工具栏的货币图标、货币与会计格式选项及其预览，以及货币命令所应用的格式。更改地区不会重写已有单元格格式，也不会换算金额。
- **Docs：文档统计**：`region` 决定统计对话框和状态栏中数字的显示格式，包括分组分隔符。仅更改 `region` 不会改变统计规则。
- **启用评论时**：`region` 决定评论中日期和时间的显示格式，使用 24 小时制和拉丁数字；`locale` 决定评论界面文案。两者都不会修改已存储的时间戳，`region` 也不是时区设置。
- **Boards、Slides、Bases、PDFs**：`locale` 控制界面翻译。`region` 对使用该配置的共享功能生效，例如接入后的评论，但不会重新格式化白板或幻灯片文本、Base 字段或 PDF 内容。
