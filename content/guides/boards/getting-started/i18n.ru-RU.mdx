## Язык интерфейса

`locale` выбирает языковой пакет, используемый для меню, подсказок, диалогов и другого переведенного текста пользовательского интерфейса. `locales` регистрирует языковые пакеты, не выбирая один. Настройка разделяется блоками в экземпляре Univer. Используйте значения `LocaleType`, такие как `LocaleType.EN_US` .

- **Все продукты: UI**: `locale` меняет язык меню, подсказок, диалогов и ярлыков плагинов. Он не переводит пользовательский контент или не переименовывает существующие блоки.
- **Листы: форматы ячеек и формулы**: сначала рендеринг числа и даты в ячейке решается через оверрайд по локальному формату чисел, затем снимок из книги `locale` и, наконец, экземпляр `locale`. `region` не заменяет ни одного из них. Поведение формулы, такое как `DOLLAR`, и валютные форматы в финансовых результатах по-прежнему использует `locale` , а нормализация ввода CJK также использует `locale`
- **Док: статистика**: `locale` определяет сегментацию и подсчет слов.

### Смена языка во время работы

Загрузите языковые пакеты каждого установленного плагина и предустановленного перед переключением языков. `loadLocales()` объединяет переводы без переключения языков; `setLocale()` выбирает язык, но ничего не загружает. Отсутствующий ключ перевода отображается как сам ключ. Пример ниже загружает общий пакет пользовательского интерфейса; пакеты целевого языка других установленных плагинов должны быть объединены в том же вызове.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Пользовательские языковые пакеты

Univer также поддерживает пользовательские языковые пакеты. Соберите объект языкового пакета по мере необходимости и перенесите его в экземпляр `Univer`. Предустановленные языковые наборы обычно хранятся в `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Участие в переводе

В настоящее время Univer включает следующие языковые пакеты:

- `zh-CN`: упрощённый китайский
- `en-US`: английский
- `zh-TW`: традиционный китайский
- `zh-HK`: традиционный китайский (Гонконг)
- `ru-RU`: русский
- `vi-VN`: вьетнамский
- `fa-IR`: персидский
- `fr-FR`: французский
- `ja-JP`: японский
- `ko-KR`: корейский
- `es-ES`: испанский
- `ca-ES`: каталонский
- `sk-SK`: словацкий
- `ar-SA`: арабский
- `de-DE`: немецкий
- `id-ID`: индонезийский
- `it-IT`: итальянский
- `pl-PL`: польский
- `pt-BR`: португальский (Бразилия)

Univer является открытым исходным кодом, и мы приветствуем разработчиков со всего мира, чтобы добавить или улучшить локации.

## Региональные настройки

`region` выбирает региональные конвенции, которые следуют за функциями, знакомыми с регионом. Настройка разделяется блоками в экземпляре Univer.

Обе настройки принимают значение `LocaleType`. Например, `LocaleType.EN_US` - это `enUS`, а `en-US` является именем файла языкового пакета и тегом BCP 47. Не продавайте код страны, такой как `US` или `SG` как `region` . Регион не нуждается в своем собственном языковом пакете, когда пользовательский интерфейс использует другую локализацию.

Без явного `region` следует `locale`, в том числе более поздние вызовы `setLocale()`. Настройка `region` во время инициализации или вызов `setRegion()` останавливает это автоматическое следование. После этого языковые изменения оставляют область неизменной. Ни один публичный API не восстанавливает следующее поведение, поэтому обновляйте оба значения, когда они должны меняться вместе.

Чтобы сохранить язык пользовательского интерфейса при использовании немецких региональных конвенций, добавьте `region: LocaleType.DE_DE` рядом с `locale` в `createUniver()` или `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Здесь UI на английском языке, а региональное форматирование остается немецким. `getCurrentLocale()` и `getCurrentRegion()` возвращают идентификаторы в действие. Чтобы изменить оба сразу, вызовите оба сеттера с одинаковым значением `LocaleType`.

- **Листы: валютный контроль**: `region` управляет значком валюты на панели инструментов, выбором валюты и бухгалтерского учета и их предварительным просмотром, а также шаблоном, который применяется командой валюты. Изменение его не переписывает существующие форматы ячеек или конвертирует денежные значения.
- **Док: статистика**: `region` форматирует цифры, показанные в диалоге статистики и строке состояния, включая разделители групп.Изменение `region` не меняет правил подсчета.
- **Комментарии, когда включено**: `region` управляет форматом даты и времени, который отображает комментарии, с 24-часовым временем и латинскими цифрами. `locale` контролирует текст пользовательского интерфейса комментария. Ни один из них не изменяет сохраненные временные метки, и `region` не является настроем часовой зоны.
- **Доски, слайды, базы, PDF**: `locale` управляет переведенным пользовательским интерфейсом. `region` доступен для общих функций, которые потребляют его, таких как комментарии потоков после интеграции, но он не переформатирует доску или слайд-текст, поля базы или PDF-контент.

  RTL в настоящее время покрывает только слой пользовательского интерфейса. Слой рендеринга его пока не поддерживает.
</Callout>

<Callout type="warning" title="Осторожно">
  Не каждый плагин включает в себя языковой пакет. В документации по каждой функции указано, работает ли он.
</Callout>

```typescript
univerAPI.setDirection('rtl')
```
