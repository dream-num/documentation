## グローバルライフサイクル

- **スタート**: Univer は初期化、ビジネスユニットは存在しません。
- **レディー**:最初のビジネスユニットが作成されました。後者はこのステージを再びトリガーしません。
- **レンダリングされる**: 標準 UI は最初のレンダースイッチを実行しました。非同期のコンテンツはまだ読み込まれません。
- **ステアディ**: 標準UIはレンダリングされた後遅れの後でこの段階に達します。それは非同期の仕事を終えるために待つしません。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="イベントが通知する対象">

`LifeCycleChanged` グローバルステージのレポート Univer. プラグイン B がグローバル後に読み込まれた場合 `Ready` ステージ、Bはまだ呼ばれます `onReady()`、しかし付加的なグローバル無し `Ready` イベントが終了しました。

リスナーは、`Starting` を含む追加直後に現在のステージを受け取ることができます。現在のステージのみを読み取り、`univerAPI.getCurrentLifecycleStage()`を直接呼び出します。

</Callout>

リスナーを削除するには、返された`disposable`オブジェクトをdispose:

```typescript
disposable.dispose()
```

## プラグインのライフサイクルフック

プラグインは、ロード時に `onStarting()` を実行し、現在のグローバルステージまでキャッチします。 B のロード時間を変更して、A の呼び出しとホックコールを比較します。

<LifecycleDemo />

一般的なプラグインは、登録時にロードします。 ビジネスタイプのプラグインは通常、そのタイプの最初のユニットが構築される前にロードします。 既に開始したタイプでは、そのタイプの新しいプラグインは、欠陥のあるバッチでロードします。 Explicitの依存関係は、プラグインが以前のバージョンをロードする可能性があります。

バッチランのホックは、ステージと依存の順番で同期的に実行し、内部で非同期の作業を待ちません。アクセスする前に、関連するユニット、DOM要素、またはリソースが準備されていることを確認してください。
