Univerボードをインストールする前に、APIとドキュメント全体に表示される4つの概念を確認します。 一緒に、彼らは、ボードが組み立て、保存、変更、および制御される方法を説明しています。

## 基本概念 [#basic-concepts]

### プラグイン

Univerは、プラグインを介して機能を提供します。 `@univerjs-pro/boards` は、ボードモデル、コマンド、`UniverBoardsPlugin`を提供します。`@univerjs-pro/boards-ui`では、キャンバス、編集インターフェイス、`UniverBoardsUIPlugin`を提供しています。リッチテキスト、描画、インク、および形状の編集は、セットアップ中に登録された依存性をレンダリングする技術的です。別のUniver製品の事前の知識は必要ありません。テーブルとマインドマップの要素は、オプションのボードから提供可能です。

アプリケーションが使用している製品プラグインのみを登録します。 [インストールガイド](/guides/boards/getting-started/installation) は、完全なブラウザの設定とその依存関係をリストします。

### スナップショットとデータモデル

`IBoardData`は、ボードユニットの持続的な形態です。 `pages`にページが保存され、`pageOrder`で注文されます。各ページは`elements`および`elementOrder`のレンダリング順序でその要素を保存します。リソース、テーマ、アクティブなページ、ズーム、およびボードの設定もスナップショットの一部です。

スナップショットを使用して、ボードを作成、保存、または復元します。 ユニットが実行されると、スナップショットオブジェクトを直接変更しないでください。 [ボードのデータ構造](/guides/boards/model/board-data)と[ボード要素](/guides/boards/model/board-elements)はスキーマを記述します。

### コマンド

コマンドでランタイムの変更が適用されます。要素をインサートしたり、変換を変更したり、コンテナに移動したり、ページの状態を変更すると、モデル、キャンバス、undo/redo、変更がコマンドレイヤーまたはファサードレイヤーを通過したときに一貫したコラボレーションパスが保持されます。

アプリケーションコードでは、Facade API を好みます。Facade が露出しない低レベルの統合のために直接コマンド ID を使用します。

### Facade API

Facade APIは、`FBoard`と要素ハンドルのボードコマンドとモデルレイヤーをラップします。`@univerjs-pro/boards/facade`をインポートし、プラグインを登録し、`FUniver.newAPI(univer)`でAPIを作成します。APIは、ボードを作成または見つけ、アクティブなページと要素を読み込み、コンテナとスイムレーンを管理できます。

[インストールと基本的な使い方](/guides/boards/getting-started/installation) を続けて、[ボードFacade APIガイド](/guides/boards/getting-started/facade)をフォローして、ボードコンテンツを作成および編集します。
