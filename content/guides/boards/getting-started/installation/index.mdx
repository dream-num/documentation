title: Installation & Basic Usage
---

Univer Boards is part of the Univer Office SDK and currently ships in plugin mode. This page covers installation and the steps required to render a first editor.

If you are unfamiliar with Univer's core concepts, read [Quickstart](/guides/boards/getting-started/quickstart) first.

Univer supports two integration modes: *Preset Mode* and *Plugin Mode*. Preset Mode reduces setup work by bundling a preconfigured set of plugins. If you need **deep customization or extensions**, Plugin Mode is the appropriate choice, because you combine and configure the plugins individually.

## Setting up via plugin mode

Boards is distributed as a set of plugins. A browser editor usually registers the shared Univer runtime and the license plugin first, then the document and drawing dependencies, and finally the Board model and UI plugins.

### Using package manager

The build tool must support ES Modules and the `exports` field in `package.json`.

#### Installation

Univer builds its UI with React and handles data streams with RxJS; it can also be embedded in Vue or Angular applications. Confirm that the `react`, `react-dom`, and `rxjs` peer dependencies[^peer-dependency] are installed. The Yarn command below lists them explicitly.

Keep all `@univerjs/*` and `@univerjs-pro/*` packages on **the same version**.

#### Usage

Create the container before initializing Univer, and give it an explicit height:

```html
<div id="app" style="height: 600px"></div>
```

Import the facade entries used on this page before calling `FUniver.newAPI(univer)`. Load the `@univerjs/design` CSS first, then the `@univerjs/ui` CSS, and the product CSS last.

<Callout type="warning" title="Caution">
  - Register `UniverLicensePlugin` before the Board plugins.
  - Import shared UI CSS before product UI CSS.
  - Register optional element plugins before opening a snapshot that contains those element types.
  - `UniverBoardsUIPlugin` loads `UniverProFormulaEnginePlugin` automatically for shapes. If the same `Univer` instance also registers `UniverFormulaEnginePlugin`, install `@univerjs-pro/engine-formula` and replace that engine's import and registration with `UniverProFormulaEnginePlugin` in the initialization code. Do not register both formula engines.
</Callout>

<Steps>
  <Step>
    Import styles, locale packs, and the required plugins:

    ```ts
    import { UniverBoardsPlugin } from '@univerjs-pro/boards'
    import { UniverBoardsUIPlugin } from '@univerjs-pro/boards-ui'
    import BoardsUIEnUS from '@univerjs-pro/boards-ui/locale/en-US'
    import { UniverInkUIPlugin } from '@univerjs-pro/ink-ui'
    import InkUIEnUS from '@univerjs-pro/ink-ui/locale/en-US'
    import { UniverLicensePlugin } from '@univerjs-pro/license'
    import { LocaleType, mergeLocales, Univer, UniverInstanceType } from '@univerjs/core'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverDrawingPlugin } from '@univerjs/drawing'
    import { UniverDrawingUIPlugin } from '@univerjs/drawing-ui'
    import DrawingUIEnUS from '@univerjs/drawing-ui/locale/en-US'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    import '@univerjs/drawing-ui/lib/index.css'
    import '@univerjs-pro/ink-ui/lib/index.css'
    import '@univerjs-pro/boards-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Import the facade entry if the Facade API[^facade-entry] is required:

    ```ts
    import { FUniver } from '@univerjs/core/facade'
    import '@univerjs-pro/boards/facade'
    ```
  </Step>
  <Step>
    Create a Univer instance, register the plugins, and create a Board unit:

    ```ts
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
          DrawingUIEnUS,
          InkUIEnUS,
          BoardsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverUIPlugin, { container: 'app' })
    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)
    univer.registerPlugin(UniverDrawingPlugin)
    univer.registerPlugin(UniverDrawingUIPlugin)
    univer.registerPlugin(UniverInkUIPlugin)
    univer.registerPlugin(UniverLicensePlugin, {
      license: process.env.CLIENT_LICENSE_TEXT,
    })
    univer.registerPlugin(UniverBoardsPlugin)
    univer.registerPlugin(UniverBoardsUIPlugin)

    univer.createUnit(UniverInstanceType.UNIVER_BOARD, {})

    const univerAPI = FUniver.newAPI(univer)
    ```
  </Step>
</Steps>

#### Plugin configuration [#plugin-configuration]

`UniverUIPlugin`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Element to mount into, or its DOM ID. |

`UniverLicensePlugin`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |
| `license` | `string` |  | Contents of the client license file. |

#### `univer.registerPlugin` and `univer.registerPlugins` methods [#registerPlugin]

`univer.registerPlugin` adds a plugin to the Univer instance. Call it after creating the instance.

The call takes the form `univer.registerPlugin(Plugin, options)`, where `Plugin` is the plugin to register and `options` is optional configuration that varies from plugin to plugin.

`univer.registerPlugins` accepts an array and registers several plugins in one call, which keeps the plugin list in one place.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  [UniverUIPlugin, { container: 'app' }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverDrawingPlugin,
  UniverDrawingUIPlugin,
  UniverInkUIPlugin,
  [UniverLicensePlugin, {
    license: process.env.CLIENT_LICENSE_TEXT,
  }],
  UniverBoardsPlugin,
  UniverBoardsUIPlugin,
])
```

`FUniver.newAPI(univer)` returns the `univerAPI` object, which is Univer's Facade API. Use it to create boards and to operate on board elements.

## Mobile support [#mobile-support]

<Callout type="warning">
  These examples require SDK packages that export the mobile plugins listed below. Keep all `@univerjs/*` and `@univerjs-pro/*` dependencies on **the same version**.

  `1.0.0-rc.0` does not export `UniverBoardsMobileUIPlugin`. Use a build that includes this mobile entry before following the example.
</Callout>

For touch-oriented controls in Univer Boards, use the **mobile UI plugins**.[^mobile-ui-mode] Choose the UI mode before creating the editor.

In the plugin-mode example above, **replace** these UI imports and registrations before `createUnit()`. Do not append them to a desktop editor that has already started. Keep the model plugins, engines, locale files, CSS, and Facade imports. The desktop and mobile classes are named exports of the **same package entry**.

`UniverMobileUIPlugin`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Element to mount into, or its DOM ID. |
| `disableAutoFocus` | `true` | `true` | Stops the editor from taking focus at startup. |

```typescript
import { UniverBoardsMobileUIPlugin } from '@univerjs-pro/boards-ui'
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverDrawingMobileUIPlugin } from '@univerjs/drawing-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
univer.registerPlugin(UniverDrawingMobileUIPlugin)
univer.registerPlugin(UniverBoardsMobileUIPlugin)
```

### Plugin mapping

Register only the features you use, and keep their model plugins and required dependencies. A mobile UI export does not mean that the desktop and mobile interfaces have the same controls. Pro features still require the appropriate license. If a feature needs a backend, integrate it on the application side with [Univer Server SDK](/server).

### Container and touch interaction

Give the container an explicit height and set up the page viewport. `100dvh` follows the dynamic viewport height. Test scrolling, pinch zoom, text selection, clipboard access, and the on-screen keyboard in the target mobile browsers. Shrinking a desktop editor does not switch it to the mobile plugins.

`UniverMobileUIPlugin` defaults to `disableAutoFocus: true`, so the editor does not take focus automatically during initialization.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Optional feature packages

Add a feature package when the Board editor needs the corresponding element type:

```shell
pnpm add @univerjs-pro/boards-table @univerjs-pro/boards-table-ui
pnpm add @univerjs-pro/boards-mind @univerjs-pro/boards-mind-ui
```

## Other releases

Besides stable releases, Univer also publishes alpha and beta channels. They provide early access to features that have not shipped officially. The trade-off is higher risk: these builds may contain bugs, unfinished features, or unstable behavior. Avoid them in production whenever possible.

### Alpha / beta release

When the Univer development team completes a new feature or a significant change, it may pre-release the work to the alpha or beta channel. Install an alpha or beta build of a Univer package with the following command:

```package-install
npm install @univerjs-pro/boards@alpha # Alpha version
npm install @univerjs-pro/boards@beta # Beta version
```

If a problem occurs with an alpha or beta build, or you have feedback, report it to the Univer development team through [GitHub Issues](https://github.com/dream-num/univer/issues).

[^peer-dependency]: `peerDependencies` declare dependencies that the host application must provide with compatible versions. They let Univer share libraries such as React instead of bundling a separate copy.

[^facade-entry]: Facade is the application-facing API over registered plugins. Importing a Facade entry adds API methods; it does not register the feature plugin itself.

[^mobile-ui-mode]: A mobile UI plugin selects touch controls and mobile services during initialization. It does not automatically detect the device or switch an existing instance when the window is resized. To change modes, preserve the document state, dispose of the old instance and initialize the chosen plugin set.
