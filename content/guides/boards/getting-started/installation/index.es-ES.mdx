title: Instalación y uso básico
---

Univer Boards es parte del Univer Office SDK y actualmente se envía en modo plugin. Esta página cubre la instalación y los pasos necesarios para renderizar un primer editor.

Si no está familiarizado con los conceptos básicos de Univer, lea primero [Quickstart](/guides/boards/getting-started/quickstart).

Univer admite dos modos de integración: *Modo de inicio* y * Modo de plugin*. El modo de presto reduce el trabajo de configuración mediante la agrupación de un conjunto preconfigurado de plugins. Si necesita **profunda personalización o extensiones**, el modo de enchufe es la opción apropiada, ya que combina y configura los plugins individualmente.

## Configuración a través del modo complemento

Las juntas se distribuyen como un conjunto de plugins. Un editor del navegador generalmente registra el tiempo de ejecución Univer compartido y el plugin de licencia primero, luego el documento y dependencias de dibujo, y finalmente el modelo de la Junta y los plugins UI.

### Uso del administrador de paquetes

La herramienta de construcción debe apoyar ES Modules y el campo `exports` en `package.json`.

#### Instalación

Univer construye su interfaz de usuario con React y maneja flujos de datos con RxJS; también se puede incrustar en Vue o Angular aplicaciones. Confirma que las `react`, `react-dom`, y `rxjs` dependencias de pares[^peer-dependency] están instaladas.

Mantén todos los paquetes `@univerjs/*` y `@univerjs-pro/*` en **la misma versión**.

#### Uso

Crear el contenedor antes de inicializar Univer, y darle una altura explícita:

```html
<div id="app" style="height: 600px"></div>
```

Importar las entradas de fachada utilizadas en esta página antes de llamar a `FUniver.newAPI(univer)`. Cargar el `@univerjs/design` CSS primero, luego el `@univerjs/ui`CSS, y el producto CSS último.

<Callout type="warning" title="Caution">
  - Registrar `UniverLicensePlugin` antes de los plugins de la Junta.
  - Importe CSS de UI compartido antes que CSS de UI del producto.
  - Registrar plugins de elementos opcionales antes de abrir una instantánea que contenga esos tipos de elementos.
  - `UniverBoardsUIPlugin` carga `UniverProFormulaEnginePlugin` automáticamente para formas. Si la misma instancia `Univer` también registra `UniverFormulaEnginePlugin`, instale `@univerjs-pro/engine-formula` y reemplace la importación y registro de ese motor con `UniverProFormulaEnginePlugin` en el código de inicialización. No registre ambos motores de fórmula.
</Callout>

<Steps>
  <Step>
Importe estilos, paquetes de configuración regional y los complementos necesarios:

    ```ts
    import { UniverBoardsPlugin } from '@univerjs-pro/boards'
    import { UniverBoardsUIPlugin } from '@univerjs-pro/boards-ui'
    import BoardsUIEnUS from '@univerjs-pro/boards-ui/locale/en-US'
    import { UniverInkUIPlugin } from '@univerjs-pro/ink-ui'
    import InkUIEnUS from '@univerjs-pro/ink-ui/locale/en-US'
    import { UniverLicensePlugin } from '@univerjs-pro/license'
    import { LocaleType, mergeLocales, Univer, UniverInstanceType } from '@univerjs/core'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverDrawingPlugin } from '@univerjs/drawing'
    import { UniverDrawingUIPlugin } from '@univerjs/drawing-ui'
    import DrawingUIEnUS from '@univerjs/drawing-ui/locale/en-US'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    import '@univerjs/drawing-ui/lib/index.css'
    import '@univerjs-pro/ink-ui/lib/index.css'
    import '@univerjs-pro/boards-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Importar la entrada de fachada si se requiere el Facade API[^facade-entry]:

    ```ts
    import { FUniver } from '@univerjs/core/facade'
    import '@univerjs-pro/boards/facade'
    ```
  </Step>
  <Step>
    Crear una instancia Univer, registrar los plugins, y crear una unidad de la Junta:

    ```ts
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
          DrawingUIEnUS,
          InkUIEnUS,
          BoardsUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverUIPlugin, { container: 'app' })
    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)
    univer.registerPlugin(UniverDrawingPlugin)
    univer.registerPlugin(UniverDrawingUIPlugin)
    univer.registerPlugin(UniverInkUIPlugin)
    univer.registerPlugin(UniverLicensePlugin, {
      license: process.env.CLIENT_LICENSE_TEXT,
    })
    univer.registerPlugin(UniverBoardsPlugin)
    univer.registerPlugin(UniverBoardsUIPlugin)

    univer.createUnit(UniverInstanceType.UNIVER_BOARD, {})

    const univerAPI = FUniver.newAPI(univer)
    ```
  </Step>
</Steps>

#### Configuración de plugins [#plugin-configuration]

`UniverUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Elemento DOM donde se monta el editor o su ID. |

`UniverLicensePlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `license` | `string` |  | Contenido del archivo de licencia del cliente. |

#### Métodos `univer.registerPlugin` y `univer.registerPlugins` [#registerPlugin]

`univer.registerPlugin` añade un plugin a la instancia Univer. Llámalo después de crear la instancia.

La llamada toma el formulario `univer.registerPlugin(Plugin, options)`, donde `Plugin` es el plugin para registrarse y `options` de configuración opcional que varía de plugin a plugin.

`univer.registerPlugins` acepta un array y registra varios plugins en una llamada, que mantiene la lista de plugins en un solo lugar.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  [UniverUIPlugin, { container: 'app' }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverDrawingPlugin,
  UniverDrawingUIPlugin,
  UniverInkUIPlugin,
  [UniverLicensePlugin, {
    license: process.env.CLIENT_LICENSE_TEXT,
  }],
  UniverBoardsPlugin,
  UniverBoardsUIPlugin,
])
```

`FUniver.newAPI(univer)` devuelve el objeto `univerAPI`, que es Univer's Facade API. Úsalo para crear tablas y para operar a bordo elementos.

## Compatibilidad móvil [#mobile-support]

<Callout type="warning">
  Estos ejemplos requieren paquetes del SDK que exporten los plugins móviles indicados. Mantenga todas las dependencias `@univerjs/*` y `@univerjs-pro/*` en **la misma versión**.

  `1.0.0-rc.0` no exporta `UniverBoardsMobileUIPlugin`. Utilice una compilación que incluya esta entrada móvil antes de seguir el ejemplo.
</Callout>

Para los controles orientados al tacto en las juntas Univer, utilice el **plugins UI móvil**.[^mobile-ui-mode] Elija el modo UI antes de crear el editor.

En el ejemplo del plugin anterior, **Sustituir la sustitución** estos UI importan y registran antes de `createUnit()`. No los anexen a un editor de escritorio que ya ha comenzado. Mantenga los plugins modelo, motores, archivos locales, CSS, y las importaciones Facade. Las clases de escritorio y móviles se nombran exportaciones de la **mismo paquete de entrada** .

`UniverMobileUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Elemento DOM donde se monta el editor o su ID. |
| `disableAutoFocus` | `true` | `true` | Para que el editor se concentre en la puesta en marcha. |

```typescript
import { UniverBoardsMobileUIPlugin } from '@univerjs-pro/boards-ui'
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverDrawingMobileUIPlugin } from '@univerjs/drawing-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
univer.registerPlugin(UniverDrawingMobileUIPlugin)
univer.registerPlugin(UniverBoardsMobileUIPlugin)
```

### Correspondencia de plugins

Registrar sólo las características que utiliza, y mantener sus plugins modelo y dependencias requeridas. Una exportación UI móvil no significa que las interfaces de escritorio y móvil tienen los mismos controles. Las características Pro todavía requieren la licencia adecuada. Si una característica necesita un backend, integre en el lado de la aplicación con [Univer Server SDK](/server).

### Contenedor e interacción táctil

Dar al contenedor una altura explícita y configurar el viewport de página. `100dvh` sigue la altura dinámica del puerto de visualización. Prueba de desplazamiento, zoom de pellizco, selección de texto, acceso a portapapeles, y el teclado en pantalla en los navegadores móviles de destino. Arrancar un editor de escritorio no lo cambia a los plugins móviles.

`UniverMobileUIPlugin` predetermina a `disableAutoFocus: true`, por lo que el editor no se centra automáticamente durante la inicialización.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Paquetes de funciones opcionales

Agregue un paquete de características cuando el editor de la Junta necesite el tipo de elemento correspondiente:

```shell
pnpm add @univerjs-pro/boards-table @univerjs-pro/boards-table-ui
pnpm add @univerjs-pro/boards-mind @univerjs-pro/boards-mind-ui
```

Para ejemplos de registro, consulte [Cuadro](/guides/boards/features/tables), [Mapas mentales](/guides/boards/features/mind-maps) y [Importación y exportación](/guides/boards/features/import-export).

## Otras versiones

Además de los lanzamientos estables, Univer también publica canales alfa y beta. Proporcionan acceso temprano a las características que no han enviado oficialmente. El desvío es mayor riesgo: estos edificios pueden contener errores, características inacabadas o comportamiento inestable. Evitelos en producción siempre que sea posible.

### Lanzamiento alfa/beta

Cuando el Univer el equipo de desarrollo completa una nueva característica o un cambio significativo, puede pre-liberar el trabajo al canal de alfa o beta. Instalar una construcción alfa o de beta de un Univer paquete con el siguiente comando:

```package-install
npm install @univerjs-pro/boards@alpha # Alpha version
npm install @univerjs-pro/boards@beta # Beta version
```

Si un problema ocurre con una construcción alfa o beta, o tiene comentarios, informe al equipo de desarrollo Univer a través de [Cuestiones de GitHub](https://github.com/dream-num/univer/issues).

[^peer-dependency]: Las `peerDependencies` son dependencias que la aplicación anfitriona debe proporcionar con versiones compatibles. Permiten compartir bibliotecas como React con Univer.

[^facade-entry]: Facade es la API de aplicación de los plugins registrados. Importar una entrada de Facade añade métodos a la API, pero no registra el plugin de la función.

[^mobile-ui-mode]: Un plugin de UI móvil selecciona controles táctiles y servicios móviles durante la inicialización. No detecta automáticamente el dispositivo ni cambia una instancia existente al redimensionar la ventana. Para cambiar de modo, conserve el estado del documento, destruya la instancia anterior e inicialice los plugins elegidos.
