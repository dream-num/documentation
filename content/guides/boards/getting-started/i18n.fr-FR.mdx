## Langue de l’interface

`locale` sélectionne le paquet de langues utilisé pour les menus, les tooltips, les dialogues et autres textes traduits de l'interface utilisateur. `locales` enregistre les paquets de langues sans en sélectionner un. Le paramètre est partagé par les unités de l'instance Univer. Utilisez les valeurs `LocaleType`, telles que `LocaleType.EN_US` .

- **Tous les produits: UI**: `locale` modifie la langue des menus, tooltips, dialogues et étiquettes de plugins. Il ne traduit pas le contenu utilisateur ou ne renomme pas les unités existantes.
- **Feuilles: formats et formules de cellules**: Le rendu des nombres et des dates dans une cellule résout en premier lieu par la commande locale number-format, puis l'instantané du cahier de travail `locale`, et enfin l'instance `locale`. `region` ne remplace aucun d'entre eux. Le comportement de la formule comme `DOLLAR` et les formats de devises dans les résultats financiers utilise toujours `locale`; et la normalisation des entrées de CJK utilise également `locale` .
- **Docs: statistiques**: `locale` détermine la segmentation et le comptage des mots.

### Changer la langue à l’exécution

Chargez les paquets de langue de chaque plugin installé et préréglagez avant de changer de langue. `loadLocales()` fusionne les traductions sans changer de langue; `setLocale()` sélectionne une langue mais ne télécharge rien. Une clé de traduction manquante est affichée comme la clé elle-même. L'exemple ci-dessous charge le pack d'interface utilisateur partagé; les paquets de langage cible d'autres plugins installés doivent être fusionnés dans le même appel.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Packs linguistiques personnalisés

Univer prend également en charge des paquets de langues personnalisés. Assemblez un objet de paquet de langues au besoin et passez-le à l'instance `Univer`. Les paquets de langues prédéfinis sont généralement stockés dans `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Paramètres régionaux

`region` sélectionne les conventions régionales que suivent les fonctions régionales. Le réglage est partagé par les unités de l'instance Univer.

Les deux paramètres prennent une valeur `LocaleType`. Par exemple, `LocaleType.EN_US` est `enUS`, tandis que `en-US` est le nom de fichier de paquet de langue et l'étiquette BCP 47. Ne pas passer un code de pays comme `US` ou `SG` comme `region`. Une région n'a pas besoin de son propre paquet de langue lorsque l'interface utilisateur utilise une autre localité.

Sans `region` explicite, il suit `locale`, y compris les appels `setLocale()` ultérieurs. La configuration de `region` pendant l'initialisation, ou l'appel `setRegion()` stoppe cette suite automatique. Après cela, les changements de langue laissent la région inchangée. Aucune API publique ne restaure le comportement suivant, donc mettez à jour les deux valeurs quand elles doivent changer ensemble.

Pour conserver la langue de l'interface utilisateur en utilisant des conventions régionales allemandes, ajoutez `region: LocaleType.DE_DE` à côté de `locale` dans `createUniver()` ou `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Ici, l'interface utilisateur est en anglais tandis que le formatage régional reste allemand. `getCurrentLocale()` et `getCurrentRegion()` retournent les identifiants en vigueur. Pour changer les deux à la fois, appelez les deux setters avec la même valeur `LocaleType`.

- **Feuilles : contrôles des devises**: `region` contrôle l'icône de la monnaie dans la barre d'outils, les choix de monnaie et de comptabilité et leurs prévisualisations, et le modèle que la commande de monnaie s'applique.
- **Docs: statistiques**: `region` formate les nombres affichés dans la boîte de dialogue statistique et la barre d'état, y compris les séparateurs de regroupement. La modification de `region` ne modifie pas les règles de comptage.
- **Commentaires de filetage, lorsque activé**: `region` contrôle le format de la date et de l'heure qui commente l'affichage, avec 24 heures et des chiffres latins. `locale` contrôle le texte de l'interface utilisateur de commentaire. Ni les changements stockés horodatage, et `region` n'est pas un réglage de fuseau horaire.
- **Planches, diapositives, bases, PDFs**: `locale` contrôle l'interface utilisateur traduite. `region` est disponible pour les fonctionnalités partagées qui la consomment, comme les commentaires de thread une fois intégré, mais il ne reformate pas le tableau ou le texte de diapositive, les champs de base ou le contenu PDF.
