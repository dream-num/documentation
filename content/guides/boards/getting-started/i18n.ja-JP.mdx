## インターフェースの言語

`locale`は、メニュー、ツールチップ、ダイアログ、その他の翻訳されたUIテキストに使用される言語パックを選択します。`locales`は、言語パックを1つ選択せずに登録します。設定はUniverインスタンスの単位で共有されます。`LocaleType.EN_US`などの`LocaleType`値を使用してください。

- **すべての製品: UI**: `locale`はメニュー、ツールチップ、ダイアログ、プラグインラベルの言語を変更します。 ユーザーのコンテンツを翻訳したり、既存のユニットの名前を変更したりすることはありません。
- **シート: 細胞のフォーマットおよび方式**: セル内の数値と日付のレンダリングは、番号形式の locale を最初にオーバーライドし、ワークブックのスナップショットで解決します。 `locale`, そして、最終的にインスタンス `locale`. `region` それらのいずれかを交換しません。 などの式挙動 `DOLLAR` 財務結果の通貨フォーマットはまだ使用しています `locale`, CJK 入力正規化も使用 `locale`.
- **Docs: 統計**:`locale`は単語の区分およびカウントを決定します。

### 実行時の言語の切り替え

言語を切り替える前に、すべてのインストールされたプラグインとプリセットの言語パックを読み込みます。 `loadLocales()`は、言語を切り替えることなく、翻訳をマージします。 `setLocale()` は言語を選択していますが、何もダウンロードしません。 欠落した翻訳キーは、キー自体として表示されます。 以下の例は、共有されたUIパックをロードします。 他のインストールされたプラグインのターゲット言語パックは、同じ呼び出しでマージする必要があります。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### カスタム言語パック

Univerはカスタム言語パックも対応しています。必要に応じて言語パックオブジェクトを組み立て、`Univer`インスタンスに渡します。プリセット言語パックは通常、`<rootDir>/packages/<PLUGIN_NAME>/locale`に保存されます。

````typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
````

## 地域設定

`region` は、地域に関心のある機能が続く地域の慣行を選択します。この設定は、Univerインスタンスのユニットによって共有されます。

どちらの設定も取ります `LocaleType` 値。例えば、 `LocaleType.EN_US` です。 `enUS`, しばらくの間 `en-US` 言語パックファイル名とBCP 47タグです。 などの国コードを渡さないでください。 `US` または `SG` として `region`. UI が異なるロケールを使用する際、地域は独自の言語パックを必要としません。

明示的な`region`がなければ、後者の`setLocale()`コールを含む`locale`に続いています。 初期化中に`region`を設定したり、`setRegion()`を呼び出すと、この自動で次の自動で停止します。 その後、言語変更は変更されていない領域を残します。 パブリックAPIは、次の動作を復元しません。そのため、変更を行う必要があるときに両方の値を更新します。

ドイツの地方慣習を使ってUI言語を維持するために、`createUniver()`または`new Univer()`の`locale`にZXQXZの隣に`region: LocaleType.DE_DE`を加えて下さい。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

ここでは、ローカルのフォーマットがドイツ語のままであるときに UI は英語です。 `getCurrentLocale()` と `getCurrentRegion()`は、識別子をエフェクトで返します。 両方を一度に変更するには、同じ `LocaleType`値で両方のセッターを呼び出します。

- **シート:通貨コントロール**: `region`は、ツールバー、通貨、会計選択とプレビューのパターン、通貨コマンドが適用されるパターンで通貨アイコンを制御します。 変更は、既存のセルフォーマットを書き換えたり、通貨値を変更したりしません。
- **Docs: 統計**: `region`は、統計ダイアログとセパレータをグループ化を含むステータスバーに示した数字をフォーマットします。 `region`を変更しても、カウントルールは変更されません。
- **スレッドコメント, 有効にしたときに**: `region`は、コメントが表示する日付と時刻の形式を24時間、ラテン数字で制御します。 `locale`では、コメントUIテキストを制御します。 保存されたタイムスタンプを変更し、`region`がタイムゾーンの設定ではありません。
- **ボード、スライド、ベース、PDF**: `locale`は翻訳されたUIを制御します。 `region` は、スレッドコメントが統合されるなど、消費する機能を共有できますが、ボードやスライドテキスト、ベースフィールド、またはPDFコンテンツを再フォーマットしません。
