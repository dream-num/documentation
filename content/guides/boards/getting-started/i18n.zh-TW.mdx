## 介面語言

`locale` 決定選單、提示、對話方塊等介面文案採用哪套語言套件；`locales` 僅註冊語言套件，不負責選擇語言。該配置由 Univer 例項內的各個單元共享。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有產品：介面**：`locale` 決定選單、提示、對話方塊和外掛標籤的語言，不翻譯使用者內容，也不重新命名已有單元。
- **Sheets：單元格格式與公式**：單元格中數字與日期的顯示依次取用數字格式的 locale 覆蓋值、工作簿快照的 `locale` 和例項的 `locale`。`region` 不替代其中任何一項。`DOLLAR` 等公式行為以及財務結果的貨幣格式仍使用 `locale`，中日韓輸入歸一化也使用 `locale`。
- **Docs：文件統計**：`locale` 決定分詞和字數統計。

### 執行時切換語言

切換語言前，先載入所有已安裝外掛和預設的語言套件。`loadLocales()` 只合並翻譯，不切換語言；`setLocale()` 只選擇語言，不下載任何內容。缺失的翻譯鍵會直接顯示為鍵名。下例載入共享 UI 語言套件；其他已安裝外掛的目標語言套件需在同一次呼叫中一併合併。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 合併語言套件 [#mergeLocales]

`mergeLocales` 將多個外掛或預設的語言套件合併為一個完整的語言套件物件：

<Tabs items={['外掛模式', '預設模式']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // 你可以直接傳入多個語系物件
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    ```

### 自訂語系檔

Univer 也支援自定義語言套件：按需組裝語言套件物件並傳入 `Univer` 例項。預設語言套件通常存放在 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目錄。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 貢獻語系

Univer 目前提供以下內建語言套件：

- `zh-CN`：簡體中文
- `en-US`：英文
- `zh-TW`：繁體中文（臺灣）
- `zh-HK`：繁體中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韓文
- `es-ES`：西班牙文
- `ca-ES`：加泰羅尼亞文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：義大利文
- `pl-PL`：波蘭文
- `pt-BR`：葡萄牙文（巴西）

Univer 目前尚不支援其他語言。歡迎世界各地的開發者新增或改進語言套件。

## 地區設定

`region` 決定地區相關功能所遵循的地區習慣。該配置由 Univer 例項內的各個單元共享。

兩項配置均取 `LocaleType` 值。例如 `LocaleType.EN_US` 的值為 `enUS`，而 `en-US` 是語言套件檔名，也是 BCP 47 標籤。`region` 不要傳入 `US`、`SG` 等國家程式碼。介面使用其他語言時，該地區無需載入對應的語言套件。

未顯式設定 `region` 時，它會跟隨 `locale`，後續呼叫 `setLocale()` 也會同步更新地區。一旦在初始化時設定 `region` 或呼叫 `setRegion()`，這種自動跟隨即停止，此後切換語言會保留已顯式指定的地區。目前沒有公開 API 可以恢復跟隨行為，需要兩者同時變化時，請同時更新兩項。

在 `createUniver()` 或 `new Univer()` 中，於 `locale` 旁設定 `region: LocaleType.DE_DE`，即可在保留介面語言的同時使用德國地區習慣。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此時介面為英文，地區格式仍為德國。`getCurrentLocale()` 和 `getCurrentRegion()` 返回當前實際生效的標識。需要語言與地區同時變化時，用同一個 `LocaleType` 值分別呼叫兩個 setter。

- **Sheets：貨幣操作**：`region` 決定工具欄的貨幣圖示、貨幣與會計格式選項及其預覽，以及貨幣命令所應用的格式。更改地區不會重寫已有單元格格式，也不會換算金額。
- **Docs：文件統計**：`region` 決定統計對話方塊和狀態列中數字的顯示格式，包括分組分隔符。僅更改 `region` 不會改變統計規則。
- **啟用評論時**：`region` 決定評論中日期和時間的顯示格式，使用 24 小時制和拉丁數字；`locale` 決定評論介面文案。兩者都不會修改已儲存的時間戳，`region` 也不是時區設定。
- **Boards、Slides、Bases、PDFs**：`locale` 控制介面翻譯。`region` 對使用該配置的共享功能生效，例如接入後的評論，但不會重新格式化白板或幻燈片文字、Base 欄位或 PDF 內容。
