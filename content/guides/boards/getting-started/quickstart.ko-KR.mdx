Univer 보드를 설치하기 전에 API 및 문서 전체에 나타나는 4 가지 개념을 검토하십시오. 보드가 조립 된 방법, 저장, 변경 및 제어 설명합니다.

## 기본 개념 [#basic-concepts]

### 플러그인

Univer는 플러그인을 통해 기능을 제공합니다. `@univerjs-pro/boards`은 보드 모델, 명령 및 `UniverBoardsPlugin`를 제공합니다. `@univerjs-pro/boards-ui` 캔버스, 편집 인터페이스 및 `UniverBoardsUIPlugin`. Rich text, drawing, Ink 및 Shape 편집은 설정 중에 등록 된 기술 렌더링 의존성입니다. 다른 Univer 제품의 사전 지식이 필요하지 않습니다. 테이블 및 마음지도 요소는 선택 사항으로 제공됩니다.

애플리케이션이 사용하는 제품 플러그인 만 등록하십시오. [설치 가이드](/guides/boards/getting-started/installation)는 완전한 브라우저 구성과 의존성을 나열합니다.

### 스냅샷 및 데이터 모델

`IBoardData`는 보드 단위의 지속된 형태입니다. 페이지는 `pageOrder`에 있는 그들의 순서와 더불어 `pages`에서 저장됩니다; 각 페이지는 `elements`와 `elementOrder`의 그들의 연출 순서에 있는 그것의 성분을 저장합니다. 자원, 테마, 활동적인 페이지, 급상승 및 널 조정은 또한 스냅샷의 일부입니다.

스냅 샷을 사용하여 만들거나 저장하거나 보드를 복원하십시오. 단위가 실행되면 스냅 샷 객체를 직접 수정하지 마십시오. [Board Data 구조](/guides/boards/model/board-data) 및 [Board Elements의 장점](/guides/boards/model/board-elements)는 스키마를 설명합니다.

### 명령

실행 시간은 명령을 통해 적용됩니다. 요소를 삽입하고 변형을 변경하거나 컨테이너로 이동하거나 페이지 상태를 변경하는 것은 모델, 캔버스, undo/redo를 유지하고, 변경이 명령 레이어 또는 Facade 레이어를 통해 진행될 때 일관성있는 협업 경로.

애플리케이션 코드에서 Facade API를 선호합니다. Facade가 노출되지 않는 저수준 통합에서만 명령 ID를 직접 사용하십시오.

### Facade API

Facade API는 `FBoard` 및 요소 핸들에서 보드 명령 및 모델 레이어를 포장합니다. `@univerjs-pro/boards/facade`를 가져 와서 플러그인을 등록하고 `FUniver.newAPI(univer)`로 API를 만듭니다. API를 만들거나 보드를 찾을 수 있으며 활성 페이지와 요소를 읽고 컨테이너와 수영을 관리합니다.

[설치 및 기본 사용](/guides/boards/getting-started/installation)로 계속, 다음 [보드 Facade API 가이드](/guides/boards/getting-started/facade)를 따르고 보드 콘텐츠를 편집합니다.
