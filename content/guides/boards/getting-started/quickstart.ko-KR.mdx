Univer Boards를 설치하기 전에 API와 문서 전반에서 사용하는 네 가지 개념을 알아봅니다. 이 개념은 Board가 구성되고, 저장되고, 변경되고, 제어되는 방식을 설명합니다.

## 기본 개념 [#basic-concepts]

### 플러그인

Univer 기능은 플러그인으로 제공됩니다. `@univerjs-pro/boards`는 Board 모델, 명령, `UniverBoardsPlugin`을 제공하고, `@univerjs-pro/boards-ui`는 캔버스, 편집 UI, `UniverBoardsUIPlugin`을 제공합니다. 리치 텍스트, 드로잉, 잉크, 도형 편집 패키지는 설정할 때 등록하는 기술적 렌더링 종속성이므로 다른 Univer 제품을 미리 알 필요가 없습니다. 표와 마인드맵 요소는 선택적 Board 플러그인입니다.

애플리케이션에 필요한 제품 플러그인만 등록하세요. [설치 가이드](/guides/boards/getting-started/installation)에서 전체 브라우저 설정과 종속성을 확인할 수 있습니다.

### 스냅샷 및 데이터 모델

`IBoardData`는 하나의 Board 유닛을 영구 저장하는 형식입니다. `pages`에 페이지를, `pageOrder`에 페이지 순서를 저장합니다. 각 페이지는 `elements`에 요소를, `elementOrder`에 렌더링 순서를 저장합니다. 리소스, 테마, 활성 페이지, 확대/축소, Board 설정도 스냅샷에 포함됩니다.

스냅샷으로 Board를 생성, 저장 또는 복원합니다. 유닛이 실행된 후에는 스냅샷 객체를 직접 변경하지 마세요. 스키마는 [Board 데이터 구조](/guides/boards/model/board-data)와 [Board 요소](/guides/boards/model/board-elements)를 참고하세요.

### 명령

런타임 변경은 명령을 거칩니다. 명령 또는 Facade 계층으로 요소를 삽입하거나 변형을 바꾸고, 컨테이너로 이동하거나 페이지 상태를 변경하면 모델, 캔버스, 실행 취소/다시 실행, 공동 작업 경로가 일관되게 유지됩니다.

애플리케이션 코드에서는 Facade API를 우선 사용하세요. Facade가 제공하지 않는 하위 수준 통합이 필요한 경우에만 명령 ID를 직접 사용합니다.

### Facade API

Facade API는 `FBoard`와 요소 핸들로 Board의 명령 및 모델 계층을 감쌉니다. `@univerjs-pro/boards/facade`를 가져오고 플러그인을 등록한 뒤 `FUniver.newAPI(univer)`로 API를 생성합니다. 그런 다음 Board를 생성하거나 찾고, 활성 페이지와 요소를 읽고, 컨테이너와 스윔레인을 관리할 수 있습니다.

다음으로 [설치 및 기본 사용법](/guides/boards/getting-started/installation)을 읽고 [Boards Facade API 가이드](/guides/boards/getting-started/facade)에서 Board 콘텐츠 생성과 편집을 알아보세요.
