## Глобальный жизненный цикл

- **Начинать**: Univer является инициализацией; бизнес-единицы еще не существует.
- **Готовы**: Создано первое бизнес-подразделение. Позднее подразделения не запускают этот этап снова.
- **отданный**: Стандартный пользовательский интерфейс выполнил свой первый переключатель рендеринга. Асинхронный контент еще не может быть загружен.
- **стойкий**: Стандартный пользовательский интерфейс достигает этой стадии после задержки после Rendered. Он не ждет завершения асинхронных задач.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Что сообщает событие">

`LifeCycleChanged` сообщает о глобальном этапе Univer. Если плагин B загружается после глобального этапа `Ready`, B по-прежнему вызывает `onReady()` , но никакого дополнительного глобального события `Ready` не излучается.

Слушатели могут получить текущий этап сразу после его добавления, в том числе `Starting`. Чтобы читать только текущий этап, звоните `univerAPI.getCurrentLifecycleStage()` напрямую.

</Callout>

Чтобы удалить слушателя, удалите возвращенный объект `disposable`:

```typescript
disposable.dispose()
```

## Хуки жизненного цикла плагинов

Плагин запускает `onStarting()`, когда он загружается, а затем догоняет текущую глобальную стадию. Измените время загрузки B, чтобы сравнить его крючковые вызовы с вызовами A.

<LifecycleDemo />

Общие плагины загружаются при регистрации. Плагины бизнес-типа обычно загружаются до того, как построен первый блок этого типа. Для типа, который уже начался, новые плагины этого типа загружаются в отложенной партии. Явные зависимости могут вызвать загрузку плагина раньше.

Крючки в партии выполняются синхронно, поэтапно и в порядке зависимости, и не ждут внутри них асинхронной работы.Подтвердить, что соответствующий блок, DOM-элемент или ресурс готов до того, как вы к нему обратитесь.
