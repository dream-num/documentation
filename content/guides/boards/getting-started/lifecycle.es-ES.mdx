## Ciclo de vida global

- **Comenzar**: Univer está inicializando; todavía no existe una unidad de negocio.
- **Listo**: La primera unidad de negocio ha sido creada. Unidades posteriores no activan esta etapa de nuevo.
- **Rendered**: La interfaz de usuario estándar ha realizado su primer interruptor de renderizado. El contenido asincrono puede no ser cargado todavía.
- **Tranquila.**: La interfaz de usuario estándar llega a esta etapa después de un retraso después de Rendered. No espera que las tareas asincrónicas terminen.

### API de Facade

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="Qué comunica el evento">

`LifeCycleChanged` reporta la etapa global de Univer. Si el plugin B se carga después de la etapa `Ready` global, B todavía llama `onReady()`, pero no se emite ningún evento `Ready` adicional.

Un oyente puede recibir la etapa actual inmediatamente después de que se añada, incluyendo `Starting`. Para leer sólo la etapa actual, llame directamente a `univerAPI.getCurrentLifecycleStage()` .

</Callout>

Para eliminar un oyente, deseche el objeto `disposable` devuelto:

```typescript
disposable.dispose()
```

## Hooks del ciclo de vida de plugins

Un plugin funciona `onStarting()` cuando se carga, y luego se alcanza hasta la etapa global actual. Cambia el tiempo de carga de B para comparar sus llamadas de gancho con las de A.

<LifecycleDemo />

Los plugins generales cargan en el registro. Los plugins de tipo empresarial suelen cargar antes de que se construya la primera unidad de ese tipo. Para un tipo que ya ha comenzado, nuevos plugins de esa carga tipo en un lote diferido. Las dependencias de gastos pueden causar un plugin para cargar antes.

Los ganchos en una carrera de lotes sincrónicamente, etapa por etapa y en orden de dependencia, y no esperan trabajo asincrónico dentro de ellos. Confirme que la unidad pertinente, elemento DOM, o recurso está listo antes de acceder a él.
