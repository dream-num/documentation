Before installing Univer Boards, review the four concepts that appear throughout its API and documentation. Together they explain how a Board is assembled, stored, changed, and controlled.

## Basic Concepts [#basic-concepts]

### Plugins

Univer delivers features through plugins. `@univerjs-pro/boards` provides the Board model, commands, and `UniverBoardsPlugin`; `@univerjs-pro/boards-ui` provides the canvas, editing interface, and `UniverBoardsUIPlugin`. Rich text, drawing, ink, and shape editing are technical rendering dependencies that are registered during setup. You do not need prior knowledge of another Univer product. Table and mind-map elements are provided by optional Board plugins.

Register only the product plugins that your application uses. The [installation guide](/guides/boards/getting-started/installation) lists the complete browser configuration and its dependencies.

### Snapshot and data model

`IBoardData` is the persisted form of a Board unit. Pages are stored in `pages`, with their order in `pageOrder`; each page stores its elements in `elements` and their rendering order in `elementOrder`. Resources, themes, the active page, zoom, and Board settings are also part of the snapshot.

Use a snapshot to create, save, or restore a Board. After the unit is running, do not modify the snapshot object directly. [Board Data Structure](/guides/boards/model/board-data) and [Board Elements](/guides/boards/model/board-elements) describe the schema.

### Command

Runtime changes are applied through commands. Inserting an element, changing its transform, moving it into a container, or changing page state keeps the model, canvas, undo/redo, and collaboration paths consistent when the change goes through the command layer or the Facade layer.

In application code, prefer the Facade API. Use command IDs directly only for a lower-level integration that the Facade does not expose.

### Facade API

The Facade API wraps the Board command and model layers in `FBoard` and element handles. Import `@univerjs-pro/boards/facade`, register the plugins, and create the API with `FUniver.newAPI(univer)`. The API can then create or find a Board, read its active page and elements, and manage containers and swimlanes.

Continue with [Installation & Basic Usage](/guides/boards/getting-started/installation), then follow the [Boards Facade API guide](/guides/boards/getting-started/facade) to create and edit Board content.
