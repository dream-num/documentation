## Idioma de la interfaz

`locale` selecciona el paquete de idiomas utilizado para menús, puntas de herramientas, diálogos y otro texto UI traducido. `locales` registra paquetes de idiomas sin seleccionar uno. El ajuste es compartido por las unidades en la instancia Univer. Utilice los valores `LocaleType`, como `LocaleType.EN_US` .

- **Todos los productos: UI**: `locale` cambia el idioma de los menús, puntas de herramientas, diálogos y etiquetas de plugin. No traduce el contenido de usuario ni renombra las unidades existentes.
- **Hojas: formatos celulares y fórmulas**: El número y la fecha de entrega en una célula se resuelve a través de la anulación número-formato primero, luego la instantánea `locale`, y finalmente la instancia `locale`. `region` no reemplaza ninguno de ellos. El comportamiento de la fórmula como `DOLLAR` y formatos de moneda en los resultados financieros todavía utiliza `locale`, y la normalización de entrada CJK también utiliza `locale`.
- **Docs: estadística**: `locale` determina la segmentación de palabras y el conteo.

### Cambiar el idioma durante la ejecución

Cargue los paquetes de idiomas de cada plugin instalado y preset antes de cambiar idiomas. `loadLocales()` fusiona traducciones sin conmutar idiomas; `setLocale()` selecciona un idioma pero no descarga nada. Una clave de traducción falta se muestra como la propia clave. El ejemplo a continuación carga el paquete UI compartido; los paquetes de lenguaje objetivo de otros plugins instalados deben ser fusionados en la misma llamada.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Paquetes de idiomas personalizados

Univer también admite paquetes de idiomas personalizados. Assemble un objeto de paquete de idiomas según sea necesario y pasarlo a la instancia `Univer`. Los paquetes de idiomas preestablecidos se almacenan generalmente en `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Configuración regional

`region` selecciona las convenciones regionales que siguen las características de la región. El ajuste es compartido por las unidades en la instancia Univer.

Ambos ajustes tienen un valor de `LocaleType`. Por ejemplo, `LocaleType.EN_US` es `enUS`, mientras que `en-US` es el nombre de archivo del paquete de idioma y la etiqueta BCP 47. No pase un código de país como `US` o `SG` como `region`. Una región no necesita su propio paquete de idiomas cuando la UI utiliza un local diferente.

Sin un `region` explícito, sigue `locale`, incluyendo llamadas `setLocale()` posteriores. El establecimiento de `region` durante la inicialización, o llamando a `setRegion()` detiene este seguimiento automático. Después de eso, los cambios de idioma dejan la región sin cambios. Ninguna API pública restaura el siguiente comportamiento, así que actualice ambos valores cuando deben cambiar juntos.

Para mantener el idioma UI utilizando convenciones regionales alemanas, agregue `region: LocaleType.DE_DE` junto a `locale` en `createUniver()` o `new Univer()`.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Aquí la interfaz de usuario está en inglés mientras que el formato regional sigue siendo alemán. `getCurrentLocale()` y `getCurrentRegion()` devuelven los identificadores en efecto. Para cambiar ambos a la vez, llame a ambas máquinas con el mismo valor `LocaleType`.

- **Hojas: controles de divisas**: `region` controla el icono de la moneda en la barra de herramientas, las opciones de divisas y contabilidad y sus previsiones, y el patrón que el comando de la moneda aplica.
- **Docs: estadística**: `region` formatea los números mostrados en el diálogo de estadísticas y la barra de estado, incluyendo separadores de agrupación. Cambiar `region` no cambia las reglas de contabilidad.
- **Thread comments, when enabled**: `region` controla el formato de fecha y hora que muestran los comentarios, con tiempo de 24 horas y dígitos latinos. `locale` controles el texto UI de comentario. Ni cambios horarios almacenados, y `region` no es un ajuste de la zona horaria.
- **Boards, Slides, Bases, PDFs**: `locale` controla la interfaz de usuario traducida. `region` está disponible para funciones compartidas que la consumen, tales como comentarios de hilo una vez integrado, pero no reformatea la tabla o el texto de diapositivas, campos de base o contenido PDF.
