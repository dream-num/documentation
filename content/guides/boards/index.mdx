## What is Univer Boards

Univer Boards is the canvas product in Univer Office SDK. It is used when a document is no longer a grid, a page, or a slide deck but a free-form workspace: whiteboards, diagrams, sticky notes, connectors, embedded tables, and mind maps all belong here.

Boards uses [Web SDK](/guides/sheets) for embedded canvases in the browser, and Web SDK also handles headless content processing. [Server SDK](/server) provides collaboration and file exchange, and [AI SDK](/ai) enables an agent to edit a board.

Boards is an independent unit type in Web SDK. At runtime, an application creates a `UniverInstanceType.UNIVER_BOARD` unit and then registers the model and UI plugins for the elements it needs to support.

## Browser Compatibility

Web SDK compiles to a Chrome 88 target. That target does not imply that Web SDK runs in every environment. The following browsers and Node.js environments are supported:

| Edge | Firefox | Chrome | Safari | Electron |
| ---- | ------- | ------ | ------ | -------- |
| >=88 | >=90    | >=88   | >=14.1 | >=12     |

<Callout type="warning">
  Web SDK relies on `Intl.Segmenter`. If the browser or runtime environment does not support it, add the corresponding polyfill first. The recommended polyfill is `@formatjs/intl-segmenter`.
</Callout>

If a compatibility problem occurs, apply the corresponding polyfill first. If the problem persists, [submit an issue](https://github.com/dream-num/univer/issues/new/choose).

## Node.js Compatibility

<Callout type="warning">
  This section covers running Web SDK inside Node.js only. It does not apply when Web SDK runs in a browser through build tools based on Node.js.
</Callout>

Web SDK runs in Node.js v18.17.0 and later.

## Highlights

- **Pages and element ordering**: pages stored in `pages` and drawable objects stored in each page's `elements`, with an explicit order array at both levels.
- **Canvas elements**: text, shapes, images, connectors, groups, containers, and swimlanes.
- **Command-driven editing**: element changes, ordering, and parent relationships routed through one command layer that carries permissions and hooks for optional history and collaboration integrations.
- **Browser canvas**: element rendering, selection, transforms, clipboard, text editing, viewport controls, and panels.
- **Extensible adapters**: optional Board capabilities such as tables, mind maps, charts, resources, print, and exchange.
- **Persistence**: creation, restoration, and saving of an `IBoardData` snapshot, including pages, resources, themes, and active-page state.

## Pre-Requisite Knowledge

The documentation is written for newcomers, but it assumes baseline knowledge so that it can stay focused on Web SDK.

Readers get the most out of the documentation with a basic understanding of JavaScript and its ecosystem.

If Web SDK is to run on Node.js, a basic understanding of Node.js is also recommended.

When several people edit the same board, or shared history, comments, or file conversion are required, add the corresponding modules from [Univer Server SDK](/server) and run them in the application backend. Authentication, permissions, storage, and deployment remain the responsibility of the application. A board that only opens in the browser does not require these services.
