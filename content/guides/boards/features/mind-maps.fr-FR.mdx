La prise en charge de la carte mentale de la carte est facultative. Ajoutez-la lorsque le produit a besoin de nœuds de carte mentale et d'interactions dans la toile de la carte.

## Enregistrer la prise en charge des cartes mentales

```ts
import { UniverBoardsMindPlugin } from '@univerjs-pro/boards-mind'
import { UniverBoardsMindUIPlugin } from '@univerjs-pro/boards-mind-ui'
import BoardsMindUIFrFR from '@univerjs-pro/boards-mind-ui/locale/fr-FR'
import '@univerjs-pro/boards-mind/facade'
import '@univerjs-pro/boards-mind-ui/lib/index.css'

univer.registerPlugin(UniverBoardsMindPlugin)
univer.registerPlugin(UniverBoardsMindUIPlugin)
```

## Prise en charge mobile [#mobile-support]

Configurez d'abord le [éditeur mobile](/guides/boards/getting-started/installation#mobile-support). Dans la configuration en mode plugin décrite sur cette page, remplacez les enregistrements de bureau ci-dessous avec les exportations mobiles des mêmes paquets, et faites-le **avant d'ouvrir un document** . Gardez les plugins modèles, styles, locaux et importations de Facade, et ne enregistrez pas les deux variantes.

| Paquet | Inscription de bureau | Inscription mobile |
| --- | --- | --- |
| `@univerjs-pro/boards-mind-ui` | `UniverBoardsMindUIPlugin` | `UniverBoardsMindMobileUIPlugin` |

## Rôle des packages

- `@univerjs-pro/boards-mind` intègre les éléments de carte mentale au modèle Board.
- `@univerjs-pro/boards-mind-ui` ajoute le rendu, l'édition et l'interface utilisateur. Il fournit également les fichiers locaux `@univerjs-pro/boards-mind-ui/locale/*` et la feuille de style `@univerjs-pro/boards-mind-ui/lib/index.css` dont les éditeurs de navigateur ont besoin.

## Choix selon l'environnement d'exécution

Un éditeur de navigateur nécessite les deux paquets. Pour le traitement d'instantanés côté serveur, enregistrez le paquet modèle avec `UniverBoardsPlugin` et omettez les paquets UI.

Enregistrez le support de la carte mentale avant d'ouvrir un instantané qui contient des éléments de la carte intellectuelle.

## Facade API

Utilisez la Facade structurée plutôt que d'éditer les formes et les connecteurs de la carte sous-jacente individuellement.

```ts
const board = univerAPI.getActiveBoard()
if (!board) throw new Error('No active Board')

const mindMap = board.insertMindMap({
  left: 180,
  top: 180,
  root: {
    text: 'Release',
    children: [
      { text: 'Product', children: [{ text: 'Scope' }, { text: 'UX' }] },
      { text: 'Engineering', children: [{ text: 'API' }, { text: 'QA' }] },
      { text: 'Launch', children: [{ text: 'Docs' }] },
    ],
  },
})
if (!mindMap) throw new Error('Cannot insert mind map')

const qa = mindMap.getNodes().find(node => node.getText() === 'QA')
qa?.addChild({ text: 'Automation' })
```

`FBoard` fournit `insertMindMap`, `getMindMap`, et `getMindMaps`. `FBoardMindMap` fournit la recherche des nœuds, les descendants, la mise en page, les limites, `reflow`, `setLayout`, `setBranchLineType`, et `remove`. Node gère le texte de soutien, l'insertion des enfants et des frères et sœurs, le reparentage, la promotion, le détachement, l'ordre, le style et l'état d'effondrement.

## Réorganiser dans des limites

`reflow()` installe atomiquement et centre une carte mentale à l'intérieur d'un rectangle spécifié dans les coordonnées du tableau. Il conserve les tailles de nœud et de texte. Par défaut, l'appel retrie avec les plus petites lacunes prises en charge. Si la mise en page ne correspond toujours pas ou reste lisible, le tableau reste inchangé et l'appel retourne `reason: 'bounds-too-small'` avec `requiredBounds`.

```ts
const result = mindMap.reflow({
  bounds: { left: 80, top: 80, width: 1_000, height: 600 },
  padding: 24,
})

if (!result.success) {
  console.warn(result.reason, result.requiredBounds)
}
```

Le rectangle cible détermine seulement l'endroit où la carte mentale est placée. Le reflow ne reparent pas, ne clip ou redimensionner le conteneur de la carte mentale, et un reflow réussi devient un seul élément défaire.
