Registrar los plugins de comentarios después de que el editor de productos y la configuración de licencia estén completos, y cargar los estilos compartidos y de producto UI junto con los recursos locales. El plugin de producto posee sus recursos de comentario, por lo que debe ser registrado antes de que se restablezca una instantánea.

```package-install
npm install @univerjs/thread-comment @univerjs/thread-comment-ui @univerjs-pro/boards-thread-comment @univerjs-pro/boards-thread-comment-ui
```

```ts
import { UniverBoardsThreadCommentPlugin } from '@univerjs-pro/boards-thread-comment'
import { UniverBoardsThreadCommentUIPlugin } from '@univerjs-pro/boards-thread-comment-ui'
import ProductLocale from '@univerjs-pro/boards-thread-comment-ui/locale/es-ES'
import { LocaleType, mergeLocales } from '@univerjs/core'
import SharedLocale from '@univerjs/thread-comment-ui/locale/es-ES'

import '@univerjs/thread-comment-ui/lib/index.css'
import '@univerjs-pro/boards-thread-comment-ui/lib/index.css'

univerAPI.loadLocales(LocaleType.ES_ES, mergeLocales(SharedLocale, ProductLocale))
univer.registerPlugin(UniverBoardsThreadCommentPlugin)
univer.registerPlugin(UniverBoardsThreadCommentUIPlugin)
```

## Compatibilidad móvil [#mobile-support]

Configure el [editor móvil](/guides/boards/getting-started/installation#mobile-support) primero. En la configuración de modo plugin descrito en esta página, sustitúyase los registros de escritorio a continuación con las exportaciones móviles de los mismos paquetes, y lo haga **antes de abrir un documento**. Mantenga los plugins modelo, estilos, locales y las importaciones Facade, y no registre ambas variantes.

| Paquete | Registro de escritorio | Registro móvil |
| --- | --- | --- |
| `@univerjs-pro/boards-thread-comment-ui` | `UniverBoardsThreadCommentUIPlugin` | `UniverBoardsThreadCommentMobileUIPlugin` |

## Facade de comentarios [#comment-facade]

Importar el comentario compartido Facade y el producto Facade antes de que se llamen estos métodos. Los ayudantes del producto crean anclas estables, y la API compartida maneja respuestas, actualizaciones, resolución y eliminación. `getComments()` lee el estado local. `listCommentsAsync()` sincroniza los hilos que ya sabe a través de la fuente de datos configurada; no descubre cada hilo en el servidor.

```ts
import '@univerjs/thread-comment/facade'
import '@univerjs-pro/boards-thread-comment/facade'

const board = univerAPI.getActiveBoard()
if (board) {
  await board.createPositionCommentAsync({ x: 320, y: 180 }, 'Review this area.')
  console.log(await board.listCommentsAsync())
}
```

```ts
import '@univerjs/thread-comment/facade'

const [thread] = univerAPI.getComments({ resolved: false })
if (thread) {
  await univerAPI.replyCommentAsync({
    unitId: thread.unitId,
    subUnitId: thread.subUnitId,
    threadId: thread.threadId,
    content: 'Reviewed.',
  })
}
```

## Conversaciones compartidas [#shared-discussions]

Para debates compartidos, integre el servicio de comentarios y el punto final a través de [Server SDK](/server/collaboration/extensions), luego regístrese `UniverThreadCommentDataSourcePlugin` desde `@univerjs-pro/thread-comment-datasource` después de que la configuración de la colaboración y la licencia esté completa. La fuente de datos suministrada llama `/universer-api/comment/unit/{unitId}/...` y `/universer-api/user/list` así que la aplicación debe exponer estas rutas.
