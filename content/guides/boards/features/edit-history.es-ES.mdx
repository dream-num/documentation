Después de mover elementos, editar texto o cambiar conectores, abrir historia para inspeccionar versiones anteriores, comparar cambios y restaurar una versión cuando está permitido. La historia lee las versiones que el servidor persiste. Deshacer y rehacer se aplican a la sesión de edición actual y no requieren el servicio de historia.

## Preparar los servicios de colaboración e historial

Configurar [integración de la colaboración](/server/collaboration/browser-integration) y [configuración de licencias](/server/license). A continuación, verifique que dos sesiones pueden editar el mismo documento de las tablas y que los cambios sobreviven a una recarga.

Siga [Ampliación de la colaboración de las oficinas](/server/collaboration/extensions) y el [Ejemplo de historia](/server/collaboration/examples#history) para conectar el almacenamiento de historia y los permisos. La colaboración básica no permite la historia por sí sola, y el backend también debe servir listas de historia, contenido de versión y restauración.

## Añadir los plugins de historial

Agregue lo siguiente a una configuración de producto, licencia y colaboración existente. Si un preset o una configuración existente ya registra estos plugins, actualice esa configuración en lugar de registrarlos dos veces.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/boards-history @univerjs-pro/boards-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBoardsHistoryPlugin } from '@univerjs-pro/boards-history'
import { UniverBoardsHistoryUIPlugin } from '@univerjs-pro/boards-history-ui'
import HistoryLocale from '@univerjs-pro/boards-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/boards-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBoardsHistoryPlugin)
univer.registerPlugin(UniverBoardsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuración de plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |

`UniverBoardsHistoryUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |
| `univerContainerId` | `string` |  | ID DOM del contenedor del editor. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Plugins adicionales del visor de historial. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Constructor del plugin. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Opciones aceptadas por el constructor del plugin. |

Reemplazar `/api/history` con el endpoint de la historia de su aplicación y verificar que su API coincida con las solicitudes que envía el cliente. Mantenga ambos valores `historyServerUrl` idénticos. Establecer `univerContainerId` al DOM ID del contenedor de editor, y cargar el local que coincida con el editor.

El visor de historia crea un editor independiente de sólo lectura. Cuando el documento contiene contenido personalizado, utilice `viewerPlugins` para agregar los plugins que el visor no incluye. No registre los plugins de visualización incorporado de nuevo.

## Consultar y restaurar versiones

Abrir la historia del menú del editor y seleccionar una versión para inspeccionar su contenido y cambios. Restaurar una versión modifica el documento compartido, por lo que sólo los usuarios con permiso de restauración deben ser capaces de hacerlo, y el servidor debe hacer cumplir ese permiso.

Para verificar la integración, mover elementos, editar texto, o cambiar conectores, esperar la confirmación de la colaboración, luego inspeccionar la lista de historia y el contenido de la versión. Reabrir la aplicación y reiniciar el servicio para confirmar que los datos persisten. Restaurar una versión anterior y confirmar que otra sesión del navegador recibe el estado restaurado.

Si la lista está vacía, compruebe si la historia fue grabada para este documento, luego comprueba el documento ID y URL de servicio. Si la visualización de obras pero la restauración falla, comprima permisos de restauración y la conexión de colaboración. La historia de la lectura también requiere autorización, porque las versiones anteriores pueden contener datos que se han borrado desde entonces.

## Comparar snapshots [#compare-snapshots]

Para construir una pantalla de revisión o proporcionar cambios a un agente de inteligencia artificial, utilice `compareUnitData()`, o computar la comparación una vez con `prepareUnitComparison()`. Registrar el producto Plugin de historia e importar la entrada de Facade, luego pasar dos instantáneas totalmente materializadas de la misma unidad que `beforeSnapshot` y `afterSnapshot` . La comparación es sólo lectura: no requiere servicio de historia y no se restable o se fusiona.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BOARD,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` lista las vistas disponibles. Pase un alcance seleccionado para `query()` para filtrar el resultado sin recortar la comparación. Una página devuelve 100 artículos por defecto y acepta hasta 1.000. `page.hasMore` con `offset` para recuperar otros elementos. `summary` describe toda la comparación incluso cuando los elementos son filtrados. `diagnostics.readiness` y `diagnostics.codes` antes de tratar el resultado como una comparación completa. Para Node.js o uso de CLI sin un editor, ver el [API de comparación sin cabeza](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
