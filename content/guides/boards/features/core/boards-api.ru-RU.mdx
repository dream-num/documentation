---

Facade API предоставляет прикладной уровень поверх сервисов и моделей модулей Univer. Используйте его для типичных операций с досками: создания досок, чтения активных страниц, добавления элементов, обновления контейнеров и управления дорожками.

<Callout type="warning" title="Внимание">
  Изменения Board выполняются синхронно и возвращают `boolean` или nullable-объект. Проверяйте возвращаемое значение.
</Callout>

## Подключение точки входа Facade

Boards распространяется в виде плагинов Web SDK. Импортируйте точку входа Facade для возможностей Boards, которые использует ваше приложение:

```ts
import { FUniver } from '@univerjs/core/facade'
import '@univerjs-pro/boards/facade'
```

Для проверки компоновки и снимков ниже также зарегистрируйте `UniverBoardsUIPlugin` и добавьте следующий импорт.

```ts
import '@univerjs-pro/boards-ui/facade'
```

Создайте объект API после регистрации экземпляра Univer и необходимых плагинов:

```ts
const univerAPI = FUniver.newAPI(univer)
```

## Создание и чтение доски

Используйте `createBoard`, чтобы создать модуль доски через уровень Facade. В низкоуровневом коде конфигурации создавайте модуль с помощью `univer.createUnit(UniverInstanceType.UNIVER_BOARD, snapshot)`.

```ts
const board = univerAPI.createBoard({
  id: 'board-demo',
  name: 'Board Demo',
})

const activeBoard = univerAPI.getActiveBoard()
const sameBoard = univerAPI.getBoard(board.getId())
```

## Переход к основным возможностям

Возвращённый объект `FBoard` служит точкой входа к активной странице и её содержимому. Подробные операции описаны в отдельных руководствах:

- [Элементы](/guides/boards/features/core/elements) — чтение, вставка, соединение, преобразование, размещение и удаление элементов Board.
- [Контейнеры и дорожки](/guides/boards/features/core/containers) — группы с рамками, принадлежность элементов и структура дорожек.

## Проверка компоновки и снимки доски [#rendered-layout]

Запускайте примеры ниже после того, как доска появится в браузере.

### Найти проблемы компоновки [#inspect-layout]

Вызовите `analyzeRenderedLayout()`, чтобы найти, например, пересекающиеся соединители или текст, который не помещается в фигуре. Проверка не меняет компоновку. Для каждой проблемы `rule` указывает её тип, а `focusBounds` — область, которую нужно проверить.

```ts
const board = univerAPI.getActiveBoard()
if (!board) throw new Error('No active board')

const analysis = board.analyzeRenderedLayout()
if (!analysis) throw new Error('The board is not ready for layout inspection')

for (const { rule, focusBounds } of analysis.issues) {
  console.log(rule, focusBounds)
}
```

[`analyzeRenderedLayout()`](/reference/facade/board#analyzerenderedlayout)

### Сделать снимок конкретного элемента [#capture-element]

Чтобы добавить в отчёт шаг блок-схемы, замените `review-step` на идентификатор элемента. Метод `resolveCaptureBounds()` определит область снимка. Передайте её в `getScreenshot()` и используйте полученный `dataUrl` как адрес изображения PNG.

```ts
const board = univerAPI.getActiveBoard()
if (!board) throw new Error('No active board')

const target = board.resolveCaptureBounds({ elementIds: ['review-step'], padding: 16 })
if (!target || !target.ok) throw new Error('Cannot locate the element to capture')

const screenshot = await board.getScreenshot({ bounds: target.bounds })
if (!screenshot) throw new Error('Cannot capture the selected area')

console.log(screenshot.dataUrl)
```

[`resolveCaptureBounds()`](/reference/facade/board#resolvecapturebounds) · [`getScreenshot()`](/reference/facade/board#getscreenshot)
