title: Univer Boards API

---

Facade API fournit une couche destinée aux applications au-dessus des services et des modèles d’unité Univer. Utilisez-la pour les opérations Board courantes, comme créer des boards, lire les pages actives, ajouter des éléments, mettre à jour des conteneurs et gérer les couloirs.

<Callout type="warning" title="Attention">
  Les mutations Board sont synchrones et renvoient un `boolean` ou un objet nullable. Vérifiez la valeur de retour.
</Callout>

## Activer le point d’entrée de Facade

Boards est distribué sous forme de plugins Web SDK. Importez le point d’entrée de Facade correspondant à la fonctionnalité Board utilisée par votre application :

```ts
import { FUniver } from '@univerjs/core/facade'
import '@univerjs-pro/boards/facade'
```

La vérification de la disposition et les captures ci-dessous nécessitent aussi l’enregistrement de `UniverBoardsUIPlugin` et cet import.

```ts
import '@univerjs-pro/boards-ui/facade'
```

Créez l’objet API après avoir enregistré l’instance Univer et les plugins requis :

```ts
const univerAPI = FUniver.newAPI(univer)
```

## Créer et lire un board

Utilisez `createBoard` pour créer une unité Board par l’intermédiaire de la couche Facade. Dans le code de configuration de plus bas niveau, créez l’unité avec `univer.createUnit(UniverInstanceType.UNIVER_BOARD, snapshot)`.

```ts
const board = univerAPI.createBoard({
  id: 'board-demo',
  name: 'Board Demo',
})

const activeBoard = univerAPI.getActiveBoard()
const sameBoard = univerAPI.getBoard(board.getId())
```

## Poursuivre avec les fonctionnalités principales

L’objet `FBoard` renvoyé est le point d’entrée vers la page active et son contenu. Consultez les guides spécialisés pour les opérations détaillées :

## Vérifier la disposition du tableau et prendre des captures [#rendered-layout]

Exécutez les exemples ci-dessous une fois le tableau affiché dans le navigateur.

### Repérer les problèmes de disposition [#inspect-layout]

Utilisez `analyzeRenderedLayout()` pour repérer, par exemple, des connecteurs qui se croisent ou du texte qui dépasse d’une forme. La vérification ne modifie pas la disposition. Pour chaque problème, `rule` indique sa nature et `focusBounds` la zone à examiner.

```ts
const board = univerAPI.getActiveBoard()
if (!board) throw new Error('No active board')

const analysis = board.analyzeRenderedLayout()
if (!analysis) throw new Error('The board is not ready for layout inspection')

for (const { rule, focusBounds } of analysis.issues) {
  console.log(rule, focusBounds)
}
```

[`analyzeRenderedLayout()`](/reference/facade/board#analyzerenderedlayout)

### Capturer un élément précis [#capture-element]

Pour insérer une étape de votre diagramme dans un rapport, remplacez `review-step` par l’identifiant de l’élément. `resolveCaptureBounds()` détermine la zone à capturer. Passez-la à `getScreenshot()` pour obtenir une URL de données PNG utilisable comme source d’image.

```ts
const board = univerAPI.getActiveBoard()
if (!board) throw new Error('No active board')

const target = board.resolveCaptureBounds({ elementIds: ['review-step'], padding: 16 })
if (!target || !target.ok) throw new Error('Cannot locate the element to capture')

const screenshot = await board.getScreenshot({ bounds: target.bounds })
if (!screenshot) throw new Error('Cannot capture the selected area')

console.log(screenshot.dataUrl)
```

[`resolveCaptureBounds()`](/reference/facade/board#resolvecapturebounds) · [`getScreenshot()`](/reference/facade/board#getscreenshot)
