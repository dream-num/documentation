Après avoir déplacé des éléments, modifié du texte ou modifié des connecteurs, ouvrez l'historique pour inspecter les versions antérieures, comparer les modifications et restaurer une version lorsque cela est permis. L'historique lit les versions que le serveur persiste.

## Préparer les services de collaboration et d’historique

Configurez [l'intégration de la collaboration](/server/collaboration/browser-integration) et [configuration de licence](/server/license). Vérifiez ensuite que deux sessions peuvent modifier le même document Boards et que les modifications survivent à un rechargement.

Suivez [Prolongation de la collaboration avec les bureaux](/server/collaboration/extensions) et le [Exemple historique](/server/collaboration/examples#history) pour connecter le stockage historique et les permissions. La collaboration de base ne permet pas l'historique en soi, et le moteur doit également servir les listes d'historique, le contenu de la version et la restauration.

## Ajouter les plugins d’historique

Ajouter ce qui suit à une configuration existante de produit, licence et collaboration. Si un préréglage ou une configuration existante enregistre déjà ces plugins, mettez à jour cette configuration au lieu de les enregistrer deux fois.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/boards-history @univerjs-pro/boards-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBoardsHistoryPlugin } from '@univerjs-pro/boards-history'
import { UniverBoardsHistoryUIPlugin } from '@univerjs-pro/boards-history-ui'
import HistoryLocale from '@univerjs-pro/boards-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/boards-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBoardsHistoryPlugin)
univer.registerPlugin(UniverBoardsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuration des plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |

`UniverBoardsHistoryUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |
| `univerContainerId` | `string` |  | ID DOM du conteneur de l’éditeur. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Plugins supplémentaires du visualiseur d’historique. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Constructeur du plugin. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Options acceptées par le constructeur du plugin. |

Remplacez `/api/history` avec le paramètre historique de votre application et vérifiez que son API correspond aux demandes envoyées par le client. Gardez les deux valeurs `historyServerUrl` identiques. Définissez `univerContainerId` à l'ID DOM du conteneur de l'éditeur et chargez la locale qui correspond à l'éditeur.

Lorsque le document contient du contenu personnalisé, utilisez `viewerPlugins` pour ajouter les plugins que le visionneur n'inclut pas. N'enregistrez pas les plugins de visionneuse intégrés à nouveau.

## Consulter et restaurer des versions

Ouvrez l'historique dans le menu de l'éditeur et sélectionnez une version pour inspecter son contenu et ses modifications. La restauration d'une version modifie le document partagé, de sorte que seuls les utilisateurs avec la permission de restauration devraient pouvoir le faire, et le serveur doit faire respecter cette autorisation.

Pour vérifier l'intégration, déplacer les éléments, modifier le texte ou modifier les connecteurs, attendre la confirmation de collaboration, puis inspecter la liste d'historique et le contenu de la version. Réouvrir l'application et redémarrer le service pour confirmer que les données persistent. Restaurer une version antérieure et confirmer qu'une autre session du navigateur reçoit l'état restauré.

Si la liste est vide, vérifiez si l'historique a été enregistré pour ce document, puis vérifiez l'ID du document et l'URL du service. Si la visualisation fonctionne mais que la restauration échoue, vérifiez les autorisations de restauration et la connexion de collaboration.

## Comparer des snapshots [#compare-snapshots]

Pour créer un écran d'examen ou apporter des modifications à un agent AI, utilisez `compareUnitData()`, ou calculez la comparaison une fois avec `prepareUnitComparison()`. Enregistrez le plugin Historique du produit et importez l'entrée Facade, puis passez deux instantanés entièrement matérialisés de la même unité que `beforeSnapshot` et `afterSnapshot` . La comparaison est en lecture seule : elle ne nécessite aucun service d'historique et ne restaure pas ou ne fusionne pas de contenu.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BOARD,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` liste les vues disponibles. Passez une zone sélectionnée à `query()` pour filtrer le résultat sans revérifier la comparaison. Une page retourne 100 éléments par défaut et accepte jusqu'à 1000. Utilisez `page.hasMore` avec `offset` afin de récupérer d'autres éléments. `summary` décrit la comparaison en entier même lorsque les éléments sont filtrés. Vérifiez `diagnostics.readiness` et `diagnostics.codes` avant de traiter le résultat comme une comparaison complète. Pour l'utilisation de Node.js ou CLI sans éditeur, consultez [API de comparaison sans tête](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
