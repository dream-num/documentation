移动元素、修改文字或调整连线之后，可以打开历史记录查看先前的版本、比较变化，并在有权限时恢复版本。历史记录读取服务端保存的版本。撤销和重做作用于当前编辑会话，不需要历史服务。

## 先准备协同和历史服务

先完成[协同集成](/server/collaboration/browser-integration)与[许可证配置](/server/license)，再确认两个会话能够编辑同一份 Boards 文档，并且刷新后内容仍然保留。

接着按 [Office 协同扩展模块](/server/collaboration/extensions)与 [History 示例](/server/collaboration/examples#history)接入历史存储和权限。核心协同不会自动启用历史记录，后端还需提供历史列表、版本内容和恢复操作。

## 添加历史记录插件

将以下内容加入已有的产品、许可证与协同配置。如果预设或现有配置已经注册了这些插件，应修改原有配置，不要重复注册。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/boards-history @univerjs-pro/boards-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/zh-CN'
import { UniverBoardsHistoryPlugin } from '@univerjs-pro/boards-history'
import { UniverBoardsHistoryUIPlugin } from '@univerjs-pro/boards-history-ui'
import HistoryLocale from '@univerjs-pro/boards-history-ui/locale/zh-CN'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/boards-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.ZH_CN, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBoardsHistoryPlugin)
univer.registerPlugin(UniverBoardsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 插件配置

`UniverEditHistoryPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的地址。 |

`UniverBoardsHistoryUIPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 历史记录服务的地址。 |
| `univerContainerId` | `string` |  | 编辑器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 为历史版本查看器注册附加插件。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 插件的构造函数。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 该插件构造函数接受的配置。 |

将 `/api/history` 替换为应用实际的历史接口地址，并确认接口与客户端发送的请求一致。两个 `historyServerUrl` 必须保持一致，`univerContainerId` 填写编辑器容器的 DOM ID，语言资源应与编辑器当前语言一致。

历史查看器会另外创建一个只读编辑器。文档包含自定义内容时，通过 `viewerPlugins` 添加查看器自身未包含的插件；不要重复注册内置插件。

## 查看和恢复版本

从编辑器菜单打开历史记录，选择一个版本查看其内容与变化。恢复版本会修改共享文档，因此只应向具有恢复权限的用户开放，服务端也必须校验该权限。

接入完成后，移动元素、修改文字或调整连线，等待协同确认，再检查历史列表与版本内容。重新打开应用并重启服务，确认数据仍然保留。恢复一个较早的版本，确认另一个浏览器会话也能收到恢复后的状态。

如果列表为空，先检查该文档是否记录了历史，再检查文档 ID 与服务地址。版本可以查看但恢复失败时，检查恢复权限与协同连接。较早的版本可能包含后来被删除的数据，因此读取历史同样需要权限校验。

## 比较快照 [#compare-snapshots]

如需构建审阅界面，或向 AI Agent 提供变更信息，可以调用 `compareUnitData()`，也可以先用 `prepareUnitComparison()` 计算一次。先注册本产品的 History 插件并导入 Facade 入口，再将同一份 Unit 的两份完整快照分别作为 `beforeSnapshot` 与 `afterSnapshot` 传入。比较是只读的，不需要历史服务，也不会恢复或合并内容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BOARD,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` 列出可用的视图，将选中的 scope 传给 `query()` 即可筛选结果，无需重新执行比较。每页默认返回 100 项，最多 1,000 项。使用 `page.hasMore` 配合 `offset` 获取后续条目。`summary` 描述整个比较，不随条目筛选变化。在将结果视为完整比较之前，检查 `diagnostics.readiness` 与 `diagnostics.codes`。无需编辑器的 Node.js 或 CLI 用法见[无界面比较 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
