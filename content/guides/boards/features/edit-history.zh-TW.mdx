移動元素、修改文字或調整連線之後，可以開啟歷史記錄檢視先前的版本、比較變化，並在有權限時恢復版本。歷史記錄讀取伺服器端儲存的版本。撤銷和重做作用於當前編輯會話，不需要歷史服務。

## 準備協同與歷史服務

先完成[協同整合](/server/collaboration/browser-integration)與[許可證配置](/server/license)，再確認兩個會話能夠編輯同一份 Boards 文件，並且重新整理後內容仍然保留。

接著按 [Office 協同擴充套件模組](/server/collaboration/extensions)與 [History 範例](/server/collaboration/examples#history)接入歷史儲存和權限。核心協同不會自動啟用歷史記錄，後端還需提供歷史列表、版本內容和恢復操作。

## 加入歷史外掛

將以下內容加入已有的產品、許可證與協同配置。如果預設或現有配置已經註冊了這些外掛，應修改原有配置，不要重複註冊。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/boards-history @univerjs-pro/boards-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBoardsHistoryPlugin } from '@univerjs-pro/boards-history'
import { UniverBoardsHistoryUIPlugin } from '@univerjs-pro/boards-history-ui'
import HistoryLocale from '@univerjs-pro/boards-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/boards-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBoardsHistoryPlugin)
univer.registerPlugin(UniverBoardsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 外掛設定

`UniverEditHistoryPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的位址。 |

`UniverBoardsHistoryUIPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 歷史記錄服務的位址。 |
| `univerContainerId` | `string` |  | 編輯器容器的 DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 為歷史版本檢視器註冊額外外掛。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 外掛的建構函式。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 該外掛建構函式接受的設定。 |

將 `/api/history` 替換為應用實際的歷史介面地址，並確認介面與客戶端傳送的請求一致。兩個 `historyServerUrl` 必須保持一致，`univerContainerId` 填寫編輯器容器的 DOM ID，語言資源應與編輯器當前語言一致。

歷史檢視器會另外建立一個只讀編輯器。文件包含自定義內容時，透過 `viewerPlugins` 新增檢視器自身未包含的外掛；不要重複註冊內建外掛。

## 檢視與還原版本

從編輯器選單開啟歷史記錄，選擇一個版本檢視其內容與變化。恢復版本會修改共享文件，因此只應向具有恢復權限的使用者開放，伺服器端也必須校驗該權限。

接入完成後，移動元素、修改文字或調整連線，等待協同確認，再檢查歷史列表與版本內容。重新開啟應用並重啟服務，確認資料仍然保留。恢復一個較早的版本，確認另一個瀏覽器會話也能收到恢復後的狀態。

如果列表為空，先檢查該文件是否記錄了歷史，再檢查文件 ID 與服務地址。版本可以檢視但恢復失敗時，檢查恢復權限與協同連線。較早的版本可能包含後來被刪除的資料，因此讀取歷史同樣需要權限校驗。

## 比較快照 [#compare-snapshots]

如需建置審閱介面，或向 AI Agent 提供變更資訊，可以呼叫 `compareUnitData()`，也可以先用 `prepareUnitComparison()` 計算一次。先註冊本產品的 History 外掛並匯入 Facade 入口，再將同一份 Unit 的兩份完整快照分別作為 `beforeSnapshot` 與 `afterSnapshot` 傳入。比較是隻讀的，不需要歷史服務，也不會恢復或合併內容。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BOARD,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` 列出可用的檢視，將選中的 scope 傳給 `query()` 即可篩選結果，無需重新執行比較。每頁預設返回 100 項，最多 1,000 項。使用 `page.hasMore` 配合 `offset` 取得後續條目。`summary` 描述整個比較，不隨條目篩選變化。在將結果視為完整比較之前，檢查 `diagnostics.readiness` 與 `diagnostics.codes`。無需編輯器的 Node.js 或 CLI 用法見[無介面比較 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)。
