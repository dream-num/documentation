要素を移動した後、テキストを編集したり、コネクターを変更したり、以前のバージョンを検査したり、変更を比較したり、許可されたときにバージョンを復元したりします。 履歴は、サーバーが永続するバージョンを読みます。 undoとredoは現在の編集セッションに適用され、履歴サービスを必要としません。

## 共同編集と履歴サービスの準備

[コラボレーション統合](/server/collaboration/browser-integration)と[ライセンス構成](/server/license)を設定し、2つのセッションが同じボードの文書を編集でき、その変更が再ロードされることを確認します。

[オフィスのコラボレーション拡張](/server/collaboration/extensions)と[歴史例](/server/collaboration/examples#history)をフォローして、歴史の保存と権限を接続します。コアコラボレーションは、独自の履歴を有効にせず、バックエンドは履歴リスト、バージョンコンテンツ、および復元にも役立つ必要があります。

## 履歴プラグインの追加

既存の製品、ライセンス、およびコラボレーション構成に以下を追加します。プリセットまたは既存の設定がすでにこれらのプラグインを登録している場合は、その設定を2回登録する代わりに更新します。

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/boards-history @univerjs-pro/boards-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBoardsHistoryPlugin } from '@univerjs-pro/boards-history'
import { UniverBoardsHistoryUIPlugin } from '@univerjs-pro/boards-history-ui'
import HistoryLocale from '@univerjs-pro/boards-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/boards-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBoardsHistoryPlugin)
univer.registerPlugin(UniverBoardsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### プラグイン設定

`UniverEditHistoryPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |

`UniverBoardsHistoryUIPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |
| `univerContainerId` | `string` |  | エディターコンテナの DOM ID。 |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 履歴ビューアーに追加するプラグイン。 |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | プラグインのコンストラクター。 |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | プラグインのコンストラクターに渡す設定。 |

`/api/history` をアプリケーションの歴史エンドポイントに置き換え、クライアントが送信するリクエストと API が一致することを確認します。`historyServerUrl`の両方の値を同一に保ちます。`univerContainerId`をエディタコンテナの DOM ID に設定し、エディタに一致するロケールをロードします。

履歴ビューアは別々の読み取り専用エディタを作成します。ドキュメントにカスタムコンテンツが含まれている場合は、ビューアが含まないプラグインを追加するには、`viewerPlugins`を使用します。組み込みビューアプラグインを再度登録しないでください。

## バージョンの表示と復元

エディタメニューから履歴を開き、バージョンを選択してコンテンツと変更を調べます。バージョンを修復すると、共有文書を変更します。そのため、復元権限を持つユーザーは、その許可を強制する必要があります。

統合を確認するために、要素を移動したり、テキストを編集したり、コネクタを変更したり、コラボレーションの確認を待ち、履歴リストとバージョンのコンテンツを検査します。アプリケーションを再オープンし、データを永続的に確認するためにサービスを再起動します。以前のバージョンを復元し、別のブラウザセッションが復元された状態を受け取ることを確認します。

リストが空の場合、このドキュメントの履歴が記録されたかどうかを確認し、ドキュメント ID とサービス URL を確認してください。 閲覧作品が失敗した場合は、復元権限とコラボレーション接続を確認します。 読み上げ履歴には、古いバージョンが削除されたデータを含む可能性があるため、許可が必要です。

## スナップショットの比較 [#compare-snapshots]

レビュー画面を作成するか、AIエージェントに変更を加えるには、`compareUnitData()` を使用するか、`prepareUnitComparison()`と一度比較を計算します。製品履歴プラグインを登録し、ファサードエントリーをインポートし、`beforeSnapshot`および`afterSnapshot`と同じユニットの2つの完全に材料化されたスナップショットを渡します。比較は読み取り専用です:それは履歴サービスを必要としず、コンテンツを復元するか、またはマージしません。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BOARD,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` は利用可能なビューをリストします。 選択したスコープを `query()` に渡して、比較を再実行せずに結果をフィルタリングします。 ページは 100 個の項目をデフォルトで返し、最大 1,000 まで受け入れます。 `offset` で `page.hasMore` を使用して、さらにアイテムを取り出します。 `summary` は、項目がフィルタリングされた場合でも、全体の比較について説明します。 完全な比較として結果を処理する前に `diagnostics.readiness` と `diagnostics.codes` をチェックしてください。 エディタなしで Node.js または CLI の使用については、[ヘッドレス比較API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison) を参照してください。
