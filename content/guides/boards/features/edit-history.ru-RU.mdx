После перемещения элементов, редактирования текста или смены разъемов откройте историю, чтобы проверить более ранние версии, сравнить изменения и восстановить версию, когда это разрешено. История читает версии, которые сервер сохраняет. Отменить и переделать применяются к текущей сессии редактирования и не требуют службы истории.

## Подготовка сервисов совместного редактирования и истории

Настройте [Интеграция сотрудничества](/server/collaboration/browser-integration) и [Конфигурация лицензии](/server/license). Затем проверьте, что две сессии могут редактировать один и тот же документ, и что изменения выдерживают перезагрузку.

Следуйте за [Расширение сотрудничества с офисом](/server/collaboration/extensions) и [Пример истории](/server/collaboration/examples#history) для подключения хранилища истории и разрешений. Основное сотрудничество не позволяет историю самостоятельно, и бэкэнд также должен обслуживать списки истории, содержание версии и восстановление.

## Добавление плагинов истории

Добавьте следующее в существующую конфигурацию продукта, лицензии и совместной работы. Если предустановленная или существующая конфигурация уже регистрирует эти плагины, обновите эту конфигурацию вместо того, чтобы регистрировать их дважды.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/boards-history @univerjs-pro/boards-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBoardsHistoryPlugin } from '@univerjs-pro/boards-history'
import { UniverBoardsHistoryUIPlugin } from '@univerjs-pro/boards-history-ui'
import HistoryLocale from '@univerjs-pro/boards-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/boards-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBoardsHistoryPlugin)
univer.registerPlugin(UniverBoardsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Настройка плагинов

`UniverEditHistoryPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |

`UniverBoardsHistoryUIPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |
| `univerContainerId` | `string` |  | DOM ID контейнера редактора. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | Дополнительные плагины для просмотра истории. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | Конструктор плагина. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | Параметры конструктора плагина. |

Замените `/api/history` конечной точкой истории вашего приложения и убедитесь, что его API соответствует запросам, которые отправляет клиент. Сохраните оба значения `historyServerUrl` идентичными. Установите `univerContainerId` на DOM-идентификатор контейнера редактора и загрузите локалку, которая соответствует редактору.

Просмотрщик истории создает отдельный редактор только для чтения. Когда документ содержит пользовательский контент, используйте `viewerPlugins` для добавления плагинов, которые зритель не включает. Не регистрируйте встроенные плагины просмотра снова.

## Просмотр и восстановление версий

Откройте историю из меню редактора и выберите версию, чтобы проверить ее содержимое и изменения. Восстановление версии изменяет общий документ, поэтому только пользователи с разрешением на восстановление должны быть в состоянии сделать это, и сервер должен обеспечить соблюдение этого разрешения.

Чтобы проверить интеграцию, переместить элементы, отредактировать текст или изменить разъемы, дождаться подтверждения совместной работы, затем проверить список истории и содержание версии. Откройте приложение и перезапустите сервис, чтобы подтвердить, что данные сохраняются. Восстановите более раннюю версию и подтвердите, что другой сеанс браузера получает восстановленное состояние.

Если список пуст, проверьте, была ли история записана для этого документа, затем проверьте идентификатор документа и URL-адрес службы. Если просмотр работает, но восстановление не удается, проверяйте разрешения на восстановление и соединение для совместной работы. Чтение истории также требует авторизации, потому что более старые версии могут содержать данные, которые с тех пор были удалены.

## Сравнение снимков [#compare-snapshots]

Чтобы построить экран обзора или предоставить изменения в AI Agent, используйте `compareUnitData()` или вычислите сравнение один раз с `prepareUnitComparison()`. Зарегистрируйте плагин истории продукта и импортируйте запись Facade, затем передайте два полностью материализованных снимка того же устройства, что и `beforeSnapshot` и `afterSnapshot`: сравнение только для чтения: оно не требует службы истории и не восстанавливает или объединяет контент.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BOARD,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` перечисляет доступные просмотры. Передайте выбранный объем `query()` для фильтрации результата без повторного повторения сравнения. Страница возвращает 100 элементов по умолчанию и принимает до 1000. Используйте `page.hasMore` с `offset`, чтобы получить дополнительные элементы. `summary` описывает все сравнение даже при фильтрации элементов. Проверяйте `diagnostics.readiness` и `diagnostics.codes` перед тем, как рассматривать результат как полное сравнение. Для использования Node.js или CLI без редактора см. [безголовое сравнение API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
