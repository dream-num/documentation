Enregistrez les plugins de commentaires après que l'éditeur de produit et la configuration de la licence sont terminées, et chargez les styles d'interface utilisateur partagé et produit avec les ressources locales. Le plugin produit possède ses ressources de commentaires, de sorte qu'il doit être enregistré avant qu'un instantané soit restauré.

```package-install
npm install @univerjs/thread-comment @univerjs/thread-comment-ui @univerjs-pro/boards-thread-comment @univerjs-pro/boards-thread-comment-ui
```

```ts
import { UniverBoardsThreadCommentPlugin } from '@univerjs-pro/boards-thread-comment'
import { UniverBoardsThreadCommentUIPlugin } from '@univerjs-pro/boards-thread-comment-ui'
import ProductLocale from '@univerjs-pro/boards-thread-comment-ui/locale/fr-FR'
import { LocaleType, mergeLocales } from '@univerjs/core'
import SharedLocale from '@univerjs/thread-comment-ui/locale/fr-FR'

import '@univerjs/thread-comment-ui/lib/index.css'
import '@univerjs-pro/boards-thread-comment-ui/lib/index.css'

univerAPI.loadLocales(LocaleType.FR_FR, mergeLocales(SharedLocale, ProductLocale))
univer.registerPlugin(UniverBoardsThreadCommentPlugin)
univer.registerPlugin(UniverBoardsThreadCommentUIPlugin)
```

## Prise en charge mobile [#mobile-support]

Configurez d'abord le [éditeur mobile](/guides/boards/getting-started/installation#mobile-support). Dans la configuration en mode plugin décrite sur cette page, remplacez les enregistrements de bureau ci-dessous avec les exportations mobiles des mêmes paquets, et faites-le **avant d'ouvrir un document** . Gardez les plugins modèles, styles, locaux et importations de Facade, et ne enregistrez pas les deux variantes.

| Paquet | Inscription de bureau | Inscription mobile |
| --- | --- | --- |
| `@univerjs-pro/boards-thread-comment-ui` | `UniverBoardsThreadCommentUIPlugin` | `UniverBoardsThreadCommentMobileUIPlugin` |

## Facade des commentaires [#comment-facade]

Importez le commentaire partagé Facade et le produit Facade avant que ces méthodes ne soient appelées. Les helpers du produit créent des ancres stables, et l'API partagée gère les réponses, les mises à jour, la résolution et la suppression. `getComments()` lit l'état local. `listCommentsAsync()` synchronise les threads qu'il connaît déjà à travers la source de données configurée; il ne découvre pas tous les thread sur le serveur.

```ts
import '@univerjs/thread-comment/facade'
import '@univerjs-pro/boards-thread-comment/facade'

const board = univerAPI.getActiveBoard()
if (board) {
  await board.createPositionCommentAsync({ x: 320, y: 180 }, 'Review this area.')
  console.log(await board.listCommentsAsync())
}
```

```ts
import '@univerjs/thread-comment/facade'

const [thread] = univerAPI.getComments({ resolved: false })
if (thread) {
  await univerAPI.replyCommentAsync({
    unitId: thread.unitId,
    subUnitId: thread.subUnitId,
    threadId: thread.threadId,
    content: 'Reviewed.',
  })
}
```

## Discussions partagées [#shared-discussions]

Pour les discussions partagées, intégrez le Service de commentaires et le Point d'arrivée via le [Server SDK](/server/collaboration/extensions), puis enregistrez `UniverThreadCommentDataSourcePlugin` depuis `@univerjs-pro/thread-comment-datasource` après la fin de la configuration de la collaboration et de la licence. La source de données fournie appelle `/universer-api/comment/unit/{unitId}/...` et `/universer-api/user/list`. L'application doit donc exposer ces itinéraires.
