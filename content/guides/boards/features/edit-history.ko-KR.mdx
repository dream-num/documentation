이동 요소, 편집 텍스트, 또는 변경 커넥터, 이전 버전을 검사하는 오픈 역사, 변경을 비교하고 허용 될 때 버전을 복원. 역사는 서버가 주장하는 버전을 읽는다. Undo 및 redo는 현재 편집 세션에 적용하고 역사 서비스가 필요하지 않습니다.

## 공동 편집 및 기록 서비스 준비

[협업 통합](/server/collaboration/browser-integration) 및 [인증 구성](/server/license)를 설정하십시오. 그런 다음 두 세션이 동일한 보드 문서를 편집하고 변경하는 것은 다시로드를 생존 할 수 있습니다.

[Office 협업 확장](/server/collaboration/extensions)와 [연혁 예](/server/collaboration/examples#history)를 따라 역사 저장 및 권한을 연결하십시오. 핵심 협력은 자체에 역사를 활성화하지 않으며, 백엔드는 역사 목록, 버전 내용 및 복원을 제공해야합니다.

## 기록 플러그인 추가

기존 제품, 라이센스 및 협업 구성에 다음을 추가하십시오. 미리 설정 또는 기존 구성이 이미이 플러그인을 등록하면 두 번 등록 대신 구성을 업데이트합니다.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/boards-history @univerjs-pro/boards-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverBoardsHistoryPlugin } from '@univerjs-pro/boards-history'
import { UniverBoardsHistoryUIPlugin } from '@univerjs-pro/boards-history-ui'
import HistoryLocale from '@univerjs-pro/boards-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/boards-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverBoardsHistoryPlugin)
univer.registerPlugin(UniverBoardsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 플러그인 설정

`UniverEditHistoryPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |

`UniverBoardsHistoryUIPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |
| `univerContainerId` | `string` |  | 편집기 컨테이너의 DOM ID입니다. |
| <ConfigKey depth={0}>viewerPlugins</ConfigKey> | `[PluginCtor, object?][]` |  | 기록 뷰어에 추가할 플러그인입니다. |
| <ConfigKey depth={1}>[0]</ConfigKey> | `PluginCtor` |  | 플러그인 생성자입니다. |
| <ConfigKey depth={1}>[1]</ConfigKey> | `object` |  | 플러그인 생성자에 전달할 설정입니다. |

응용 프로그램의 역사 엔드 포인트와 `/api/history`를 대체하고 API가 클라이언트가 보낸 요청을 확인합니다. 동일한 `historyServerUrl` 값을 모두 유지하십시오. 편집기 컨테이너의 DOM ID에 `univerContainerId`을 설정하고 편집기에 맞는 Locale를로드하십시오.

역사 뷰어는 별도의 읽기 전용 편집기를 만듭니다. 문서가 사용자 정의 콘텐츠를 포함 할 때, 뷰어가 포함되지 않는 플러그인을 추가하려면 `viewerPlugins`를 사용하십시오. 내장 뷰어 플러그인을 다시 등록하지 마십시오.

## 버전 보기 및 복원

편집기 메뉴에서 역사를 열고 콘텐츠를 검사하고 변경하는 버전을 선택하십시오. 공유 문서를 수정하는 버전은 복원 권한을 사용하여 사용자 만 그렇게 할 수 있어야하며 서버는 그 권한을 시행해야합니다.

통합, 이동 요소, 편집 텍스트, 또는 변경 커넥터를 확인하려면, 협력 확인을 기다리는 다음 역사 목록과 버전 콘텐츠를 검사합니다. 응용 프로그램을 열고 데이터 persists가 확인하는 서비스를 다시 시작합니다. 이전 버전을 복원하고 다른 브라우저 세션이 복원 된 상태로 수신 확인.

목록이 비어있는 경우, 이 문서에 기록 된지 확인한 후 문서 ID 및 서비스 URL을 확인하십시오. 보기가 작동하지만 복원이 실패하면 복원 권한 및 협업 연결을 확인하십시오. 이전 버전이 삭제 된 데이터가 포함되기 때문에 이전 버전이 승인해야합니다.

## 스냅샷 비교 [#compare-snapshots]

검토 화면을 구축하거나 AI 에이전트에 변경을 제공하려면 `compareUnitData()`를 사용하거나 `prepareUnitComparison()`와 함께 한 번 비교를 계산하십시오. 제품 역사 플러그인을 등록하고 Facade 항목을 가져 오면 `beforeSnapshot` 및 `afterSnapshot`과 같은 두 개의 완전히 재료 스냅 샷을 전달합니다. 비교는 읽기 전용입니다 : 그것은 역사 서비스가 필요하지 않으며 복원하거나 결합 콘텐츠를하지 않습니다.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'

import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_BOARD,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes` 목록은 유효한 전망입니다. `query()`에 선정한 범위를 비교 없이 결과를 거르기 위하여 통과하십시오. 페이지는 과태에 의하여 100개의 품목을 돌려보내고 1,000까지 받아들입니다. `page.hasMore`를 `offset`로 더 많은 품목을 검색하기 위하여 사용하십시오. `summary`는 품목이 거르면 전체적인 비교를 설명합니다. 완전한 비교로 결과를 대우하기 전에 `diagnostics.readiness`와 `diagnostics.codes`를 검사하십시오. 편집기 없이 Node.js 또는 CLI 사용법을 위해, [headless 비교 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)를 보십시오.
