Board-Seiten speichern zeichnbare Objekte in `elements` und ihre visuelle Reihenfolge in `elementOrder`. Jedes Element verfügt über einen stabilen `id`, einen `type` und einen `transform`, der seine Position und Größe auf der Leinwand beschreibt.

## Gemeinsame Elementfelder

| Feld | Typ | Beschreibung |
| --- | --- | --- |
| id | `string` | Element-ID, eindeutig innerhalb der Seite. |
| type | `BoardElementType` | Elementart, z. B. `text`, `shape`, `image`, `connector`, `container`, `table` oder `group`. |
| transform | `IBoardElementTransform` | Werte für Position, Größe, Drehung, Skalierung, Neigung und Spiegelung. |
| parentId? | `string` | ID des übergeordneten Containers oder der Gruppe. |
| laneId? | `string` | Swimlane-Spur-ID beim Element befindet sich innerhalb einer Swimlane. |
| name? | `string` | Menschenlesbarer Elementname. |
| description? | `string` | Barrierefreiheit oder Anwendungsmetadaten. |
| visible? | `boolean` | Gibt an, ob das Element gerendert werden soll. |
| selectable? | `boolean` | Ob der Editor das Element auswählen kann. |
| locked? | `boolean` | Ob die Bearbeitung gesperrt ist. |
| custom? | `Datensatz\<string, unbekannt\> | null` | Anwendungsdefinierte Metadaten. |

## Elementtypen

| Typ | Zusätzliche Daten | Typisch Verwenden Sie |
| --- | --- | --- |
| `text` | `text`, `textStyle`, `textData` | Haftnotizen, Beschriftungen und Rich-Text-Blöcke. |
| `shape` | `shapeData` | Rechtecke, Pfeile, Beschriftungen und benutzerdefinierte Formen. |
| `image` | `source`, `imageSourceType`, `crop` | Eingebettete Bilder. |
| `connector` | `connectorData` | Linien und Pfeile, die an freie Punkte oder Formen angehängt sind. |
| `container` | `containerData` | Rahmen, Bereiche, Schwimmbahnen, UML-Pakete und Systemgrenzen. |
| `table` | `tableId` | Board-Tabellenelemente, die vom Tabellen-Plugin bereitgestellt werden. |
| `chart` | `chartId` | Diagrammelemente. |
| `media` | `mediaType`, `source` | Audio- und Video-Platzhalter. |
| `group` | `children` | Gruppierte Elementsammlungen. |

## Container

Container definieren das Mitgliedschaftsverhalten mit `containerData.behavior` und erfassen Regeln mit `containerData.capturePolicy`. Verwenden Sie die Fassadencontainermethoden, um Elemente hinein und heraus zu verschieben, damit die Reihenfolge und die übergeordneten Beziehungen konsistent bleiben.

```ts
board.wrapElementsInContainer(['task-1', 'task-2'], {
  title: 'Sprint 1',
})
```

## Swimlanes

Eine Swimlane ist ein Container mit `containerData.swimlane`. Lanes verfügen über stabile IDs, Titel, Bestellwerte, Größen und optional einen reduzierten Status.

```ts
board.setSwimlaneLanes('lane-board', {
  orientation: 'horizontal',
  lanes: [
    { id: 'todo', title: 'Todo', order: 0, size: 240 },
    { id: 'doing', title: 'Doing', order: 1, size: 240 },
  ],
})
```

## Connectoren

Connectoren verwenden Endpunkte und Routing-Daten. Endpunkte können freie Punkte, Formgrenzen, Verbindungsstellen oder Lebenslinien sein. Bevorzugen Sie Fassadenvorgänge oder UI-Aktionen für die Bearbeitung von Anschlüssen, da Routing-Daten häufig von der Geometrie abhängen.
