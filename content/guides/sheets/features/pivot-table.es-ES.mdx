Las tablas dinámicas son una poderosa herramienta de análisis de datos que permite a los usuarios resumir, analizar y visualizar rápidamente grandes cantidades de datos. Admite varias operaciones de datos y opciones de formato para ayudar a los usuarios a comprender mejor sus datos.

## Introducción

Las tablas dinámicas de datos se usan generalmente en los siguientes escenarios:

- Resumir datos: las tablas dinámicas pueden ayudarlo a resumir rápidamente los datos para comprender mejor la situación general.
- Analizar datos: las tablas dinámicas pueden ayudarlo a analizar datos para identificar patrones y relaciones.
- Explorar datos: las tablas dinámicas pueden ayudarlo a explorar datos para descubrir reglas y tendencias.
- Visualización de datos: las tablas dinámicas pueden ayudarle a visualizar datos para una mejor comprensión.

Una tabla dinámica generalmente incluye los siguientes elementos:

- Etiquetas de filas: las etiquetas de filas en una tabla dinámica se usan para agrupar datos.
- Etiquetas de columnas: las etiquetas de columnas en una tabla dinámica se usan para agrupar datos.
- Valores: los valores en una tabla dinámica se usan para resumir datos.

En una tabla dinámica, puede ajuste las etiquetas de fila, las etiquetas de columna y los valores según sea necesario para analizar mejor los datos.

### Fuente de datos

En Univer Sheets, la fuente de datos para una tabla dinámica puede ser una hoja de trabajo o un rango de datos. Puede elegir diferentes fuentes de datos según sea necesario para analizar mejor sus datos.
Tomamos la primera fila de la fuente de datos como etiquetas de columna predeterminadas y el resto como fuente de datos. Por lo tanto, requerimos que la fuente de datos esté lo más organizada posible, evitando filas y columnas vacías tanto como sea posible.
Para los datos en la misma columna, reconoceremos automáticamente el tipo de datos para admitir mejor la funcionalidad de la tabla dinámica. Si el tipo de datos es inconsistente en una columna, estableceremos de forma predeterminada el tipo de datos de esa columna como cadena.

En Univer Sheets, las tablas dinámicas responderán automáticamente a los cambios en los datos. Cuando cambie la fuente de datos, la tabla dinámica se actualizará automáticamente para analizar mejor los datos.

### Filtrado

Las tablas dinámicas de datos admiten el filtrado por etiquetas de filas y columnas, y también proporcionan un campo de filtro que no participa en la clasificación de datos principal ni en el diseño de resumen de la tabla dinámica, pero se puede usar para filtrar datos.

Las tablas dinámicas de datos admiten dos métodos de filtrado:
- Filtrado de etiquetas: el filtrado de etiquetas se aplica directamente a los elementos de la dimensión de etiqueta actual. Por ejemplo, en la dimensión de provincia, podemos filtrar ciertas provincias.
- Filtrado de valores: el filtrado de valores requiere especificar una dimensión de valor y luego filtrar los resultados resumidos del campo de valor. Por ejemplo, podemos filtrar datos con ventas inferiores a 1000.

### Clasificación

La clasificación de la tabla dinámica de datos solo tiene efecto en los campos de fila/columna y admite orden ascendente y descendente. El método de clasificación utiliza el método `localCompare`. En el futuro, admitiremos más métodos de clasificación, como la clasificación pinyin.

Las tablas dinámicas de datos admiten dos métodos de clasificación:
- Clasificación de etiquetas: la clasificación de etiquetas se aplica directamente a los elementos de la dimensión de etiqueta actual. Por ejemplo, en la dimensión de provincia, podemos ordenar por nombre de provincia.
- Clasificación de valores: la clasificación de valores requiere especificar una dimensión de valor y luego ordenar los resultados resumidos del campo de valor. Por ejemplo, podemos ordenar por monto de ventas.

### Agregación

Las tablas dinámicas de datos admiten 11 métodos de agregación admitidos por Excel, que incluyen: suma, recuento, recuento de datos, promedio, máximo, mínimo, factorial, desviación estándar, varianza, desviación estándar de población y varianza de población.

Las tablas dinámicas de datos admiten múltiples dimensiones de valor y permiten la personalización del área de dimensión de valor (posición de valor) y la posición (índice de valor).

Esta es una lógica de diseño compleja, por lo que solo vista de tabla de soporte por ahora. En el futuro, admitiremos más vistas según la demanda.

### Profundizar

Profundizar se refiere a la capacidad de los usuarios de hacer doble clic en una celda en el área de valores de una tabla dinámica para ver los datos detallados correspondientes a esa celda. Por ejemplo, los usuarios pueden hacer clic en una celda de la tabla dinámica para ver los datos detallados detrás de ella, lo que permite un mejor seguimiento de los datos originales.

### Agrupación

Las tablas dinámicas de datos admiten la funcionalidad de agrupación, que aún no es compatible con Univer Sheets.

La agrupación se puede realizar de las siguientes maneras:
- Agrupación por fechas: esto implica agrupar datos de fechas por año, mes, día, etc.
- Agrupación numérica: esto implica agrupar datos numéricos en rangos específicos.
- Agrupación de elementos: esto implica agrupar datos de elementos de acuerdo con reglas específicas.

### Registro Complementos

El complemento de tabla dinámica admite el registro flexible para diferentes escenarios de uso, proporcionando dos modos para adaptarse a diversas necesidades computacionales.

**Registro solo en el proceso principal**

El complemento de tabla dinámica solo se puede registrar en el proceso principal. Este modo es adecuado para tareas livianas, operaciones simples y no requiere configuración adicional de la configuración del complemento. Los desarrolladores solo necesitan importar `UniverSheetsPivotTablePlugin`.

```typescript
univer.registerPlugin(UniverSheetsPivotTablePlugin)
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)
```

**Registrarse tanto en el proceso principal como en el de trabajo**

Para escenarios que requieren un alto rendimiento, el complemento de tabla dinámica admite el registro tanto en el proceso principal como en el de trabajo. Este modo permite que el complemento aproveche una arquitectura de subprocesos múltiples para una distribución de datos y un procesamiento de cálculo eficientes, lo que reduce significativamente la carga computacional del proceso principal y mejora el rendimiento general.

En este modo, el proceso principal es el principal responsable de la distribución, sincronización y representación de datos, mientras que el proceso de trabajo se centra en tareas computacionales complejas. Para implementar este modo, se requiere un ajuste fino de la configuración durante el registro a través de la configuración.

```typescript
// main process file
// Setting notExecuteFormula to true indicates that the main process does not perform calculations. It is only responsible for data distribution, synchronization, and rendering.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: true })
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)

// web worker process file
// Setting notExecuteFormula to false indicates that the worker process performs the calculations.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: false })
```

Si tiene una licencia comercial para Univer, consulte [Uso de licencia en el cliente](/guides/pro/license#in-plugin-mode) para la configuración.

### Agregar una tabla dinámica

El método [`FWorkbook.addPivotTable`](https://docs.univer.ai/reference/facade/workbook#addpivottable) se utiliza para agregar una tabla dinámica y devolverá la instancia `FPivotTable` si tiene éxito.

```typescript
// should ensure the sheet range A1:G9 is not empty
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()
const sheetName = fSheet.getSheetName()
const sourceInfo = {
  unitId,
  subUnitId,
  sheetName,
  range: {
    startRow: 0,
    startColumn: 0,
    endRow: 8,
    endColumn: 6,
  },
}
const anchorCellInfo = {
  unitId,
  subUnitId,
  row: 20,
  col: 8,
}
const fPivotTable = await fWorkbook.addPivotTable(sourceInfo, univerAPI.Enum.PositionTypeEnum.Existing, anchorCellInfo)
const pivotTableId = fPivotTable.getPivotTableId()
// add flag to avoid add pivot fields multiple times
let hasAdded = false
// the addPivotTable is async, you can add pivot fields after the pivot table is added
univerAPI.addEvent(univerAPI.Event.PivotTableRendered, (params) => {
  if (!hasAdded && params.pivotTableId === pivotTableId) {
    fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Row, 0)
    fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Value, 0)
    hasAdded = true
  }
})
```

### Obtener una tabla dinámica Tabla

El método [`FWorkbook.getPivotTableByCell`](https://docs.univer.ai/reference/facade/workbook#getpivottablebycell) se utiliza para obtener una instancia de tabla dinámica mediante la celda ancla, y devolverá la instancia `FPivotTable` si la celda de destino está en una tabla dinámica.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()

// get pivot table by the cell in FWorkbook.
const fPivotTable = fWorkbook.getPivotTableByCell(unitId, subUnitId, 0, 8)

// get pivot table by the cell in FWorksheet.
const pivotTable2 = fSheet.getPivotTableByCell(0, 8)
```

```typescript
class FPivotTable {
/**
 * @description Get the pivot table config by the pivot table id.
 * @typedef PivotTableConfig
 * @property {TargetInfo} targetCellInfo  The target cell info of the pivot table.
 * @property {SourceInfo} sourceRangeInfo The source data range info of the pivot table.
 * @property {boolean} isEmpty The pivot table is empty or not.
 * @property {object} fieldsConfig The snapshot of the pivot table fields config.
 * @returns {PivotTableConfig|undefined} The pivot table config or undefined.
 */
  getConfig(): IPivotTableConfig
  /**
   * @description Remove a pivot table from the workbook by pivot table id
   */
  async remove(): void
  /**
   *@description Add a pivot field to the pivot table.
   * @param {string|number} dataFieldIdOrIndex The data field id.
   * @param {PivotTableFiledAreaEnum} fieldArea The area of the field.
   * @param {number} index The index of the field in the target area.
   * @returns {boolean} Whether the pivot field is added successfully.
   */
  async addField(dataFieldIdOrIndex: string | number, fieldArea: PivotTableFiledAreaEnum, index: number): Promise<boolean>
  /**
   * @description Remove a pivot field from the pivot table
   * @param {string[]} fieldIds The deleted field ids.
   * @returns {boolean} Whether the pivot field is removed successfully.
   */
  async removeField(fieldIds: string[]): Promise<boolean>
  /**
   * @description Update the pivot table field position.
   * @param {string} fieldId - The moved field id.
   * @param {PivotTableFiledAreaEnum} area - The target area of the field.
   * @param {number} index - The target index of the field, if the index is bigger than the field count in the target area, the field will be moved to the last, if the index is smaller than 0, the field will be moved to the first.
   * @returns {boolean} Whether the pivot field is moved successfully.
   */
  async updateFieldPosition(fieldId: string, area: PivotTableFiledAreaEnum, index: number): Promise<boolean>
  /**
   * @description If there are multiple value fields in the pivot table, you can update the position of the value field, which only can be position in row or column.
   * @param {PivotTableValuePositionEnum} position - The position of the value field.
   * @param {number} index - The index of the value field.
   * @returns {boolean} Whether the pivot value field is moved successfully.
   */
  async updateValuePosition(position: PivotTableValuePositionEnum, index: number): Promise<boolean>
  /**
   * @description Set the pivot table subtotal type for value field, it only works for the value field.
   * @param {string} fieldId - The field id.
   * @param {PivotSubtotalTypeEnum} subtotalType - The subtotal type of the field.
   * @returns {boolean} Whether the pivot table subtotal type is set successfully.
   */
  async setSubtotalType(fieldId: string, subtotalType: PivotSubtotalTypeEnum): Promise<boolean>
  /**
   * @description Set the pivot table sort info.
   * @param {string} tableFieldId - The field id of the sort.
   * @param {PivotTableSortInfo} info - The sort info.
   * @typedef PivotTableSortInfo
   * @property {PivotDataFieldSortOperatorEnum} type The sort operator of the field items.
   * @returns {boolean} Whether the pivot table sort info is set successfully.
   */
  async setLabelSort(tableFieldId: string, info: IPivotTableSortInfo): Promise<boolean>
  /**
   * @description Set the pivot table filter.
   * @param {string} tableFieldId - The field id of the filter.
   * @param {string[]} items - The items of the filter.
   * @returns {boolean} Whether the pivot table filter is set successfully.
   */
  async setLabelFilter(tableFieldId: string, items: string[], isAll?: boolean): Promise<boolean>
  /**
   * @description Rename the pivot table field.
   * @param {string} fieldId - The field id.
   * @param {string} name - The new name of the field.
   * @returns {boolean} Whether the pivot table field is renamed successfully.
   */
  async renameField(fieldId: string, name: string): Promise<boolean>
  /**
   * @description Set the pivot table value filter. A value filter is used to filter the data based on the value of a field.
   * @param {string} fieldId - The field id of the filter. Only one value filer can be set for a field.
   * @param {Omit<IPivotTableValueFilter, 'type'>} filterInfo - The filter info. The undefined value will be removed from the old filter.
   * @typedef filterInfo
   * @property {valueGreaterThan} operator - The filter operator is used to compare the value of the field with the expected value.Currently, The following operators are supported: valueBetween, valueEqual, valueGreaterThan, valueGreaterThanOrEqual, valueLessThan, valueLessThanOrEqual,valueNotBetween,valueNotEqual.
   * @property {number} expected - The expected value.
   * @property {string} valueFieldId - The value field id.
   * @returns {boolean} Whether the pivot table value filter is set successfully.
   */
  async setValueFilter(fieldId: string, filterInfo: Omit<IPivotTableValueFilter, 'type'>): Promise<boolean>
  /**
   * @description Clear the fields by provided field area or clear all fields.
   * @param {PivotTableFiledAreaEnum} [resetArea] The area of the field to reset or undefined to reset all fields.
   * @returns {Promise<boolean>} Whether the pivot table fields are reset successfully.
   */
  reset(resetArea?: PivotTableFiledAreaEnum): Promise<boolean>
  /**
   * @description Set the pivot table fields config.It will add fields to the pivot table from provided config.Before setting the fields config, you should ensure the pivot table is empty to avoid the conflict.
   * @param {IPivotTableConfig['fieldsConfig']} config The pivot table fields config.
   * @returns {Promise<boolean>} Whether the pivot table fields config is set successfully.
   */
  setFieldsConfig(config: IPivotTableConfig['fieldsConfig']): Promise<boolean>
  /**
   * Get all value filters of the pivot table. In pivot table, the value filter must be applied in order.So the order of the value filter is important.
   * @returns {IValueFilterInfoItem[]} The value filter info list.
   */
  getValueFilters(): IValueFilterInfoItem[]
}
```

### Escuchas de eventos

Las definiciones completas de tipos de eventos se pueden encontrar en [Eventos](https://docs.univer.ai/reference/facade/events).

Se activa el evento `univerAPI.Event.BeforePivotTableAdd` antes de agregar una tabla dinámica.

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.BeforePivotTableAdd, (params) => {
  const { positionType, targetCellInfo } = params
  if (positionType === univerAPI.Enum.PositionTypeEnum.Existing && targetCellInfo.sheetName === 'Sheet 1') {
    // Cancel the pivot table adding operation
    params.cancel = true
    console.log(`The pivot table can't be added to the sheet ${targetCellInfo.sheetName}`)
  }
})

// Remove the event listener, use `disposable.dispose()`
```

El evento `univerAPI.Event.PivotTableAdded` se activa después de agregar una tabla dinámica.

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.PivotTableAdded, (params) => {
  const { positionType, targetCellInfo } = params
  if (positionType === univerAPI.Enum.PositionTypeEnum.Existing) {
    console.log('A pivot table created in an existing sheet')
    console.log(`
      The target sheet name is ${targetCellInfo.sheetName},
      the target row is ${targetCellInfo.row}, the target column is ${targetCellInfo.column}
    `)
  } else {
    console.log('A pivot table created in a new sheet')
  }
})

// Remove the event listener, use `disposable.dispose()`
```

El evento `univerAPI.Event.BeforePivotTableMove` se activa antes de mover una tabla dinámica.

