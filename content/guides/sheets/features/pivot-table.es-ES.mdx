Una tabla de pivotes reduce un amplio rango de datos a un resumen compacto. Admite la resumición, el análisis y la visualización de datos, y proporciona las operaciones de datos y opciones de formato que facilitan el resultado.

## Introducción

Las tablas de pivote se utilizan típicamente para uno de los cuatro propósitos:

- Resumiendo una amplia gama de datos para hacer visible la imagen general.
- Analizar los datos para identificar patrones y relaciones.
- Explorando los datos para descubrir reglas y tendencias.
- Visualizar el resultado para facilitar la comprensión.

Una tabla de pivotes consta de tres partes:

- Las etiquetas de fila agrupan los datos por fila.
- Las etiquetas de columna agrupan los datos por columna.
- Los valores resumen los números en cada intersección.

Las etiquetas de fila, las etiquetas de columna y los valores se pueden reorganizar en cualquier momento, según el análisis.

![Missing Locale](./pivot-table/pivot.png)

### Fuente de datos

En las Hojas Univer, una tabla de pivotes toma una hoja de trabajo o un rango de datos como su fuente.

La primera fila de la fuente se convierte en las etiquetas de la columna, y las filas restantes contienen los datos. Las filas vacías y las columnas vacías interfieren con este diseño, por lo que la fuente debe mantenerse ordenada.

El tipo de datos de cada columna se detecta automáticamente, lo que determina cómo la tabla de pivotes puede usar ese campo. Si una columna contiene tipos mixtos, toda la columna se trata como cadena.

Las tablas Pivot rastrean los cambios en su fuente: cuando un valor en los datos fuente cambia, la tabla actualiza automáticamente.

### Filtrado

Las etiquetas de fila y las etiquetas de columna pueden ser filtradas. También hay un campo de filtro separado; no participa en la fila y la distribución de columnas del informe, pero los valores seleccionados en él todavía restringen los datos.

Existen dos métodos de filtrado:

- El filtrado de etiquetas se aplica a los elementos de la dimensión actual de la etiqueta; por ejemplo, en una dimensión de provincia se pueden filtrar las provincias individuales.
- El filtrado de valor requiere una dimensión de valor y filtros en el resultado agregado; por ejemplo, los datos cuyas ventas están por debajo de 1000 pueden ser ocultos.

### Clasificación

La clasificación se aplica únicamente a los campos de fila y columna, en cualquier dirección. Las comparaciones utilizan el método `localCompare`. Se planean métodos adicionales de comparación, clasificación de pinyin entre ellos.

Existen dos métodos de clasificación:

- La clasificación de etiquetas se aplica a los elementos de la dimensión actual de la etiqueta; en una dimensión provincia, esta clase es por nombre provincia.
- La clasificación de valores requiere una dimensión de valor y clasifica el resultado agregado, por ejemplo por la cantidad de ventas.

### Agregación

Las tablas de pivotes apoyan los 11 métodos de agregación Excel ofrece: suma, cuenta, cuenta de datos, promedio, máximo, mínimo, factorial, desviación estándar, varianza, desviación estándar de población y varianza de población.

Se pueden añadir varias dimensiones de valor, y tanto el área que ocupan (la posición de valor) como su orden dentro de ese área (índice de valor) se pueden configurar.

Este diseño es complejo, por lo que sólo la vista de la tabla se apoya actualmente. Se añadirán puntos de vista adicionales basados en la demanda.

### Profundizar

La perforación se refiere a hacer doble clic en una celda en el área de valor de una tabla de pivotes para ver el detalle detrás de esa célula. El detalle enumera las filas que produjeron el número, lo que permite que un total se rastree de nuevo a los datos de origen.

### Agrupación

Univer Sheets admite la agrupación por fechas, numérica y manual.

- Fecha de agrupación: utilizar [`setDateGroupType`](/reference/facade/pivot-table#setdategrouptype) para un campo de fecha derivada. Para agrupar un campo de etiqueta de fecha original por unidad de calendario, establecer [`setDateGroupingMode`](/reference/facade/pivot-table#setdategroupingmode) a `univerAPI.Enum.PivotDateGroupingMode.ExcelLike`, entonces llamar [`setExcelDateGroup`](/reference/facade/pivot-table#setexceldategroup).
- Grupo numérico: pasar un ID de campo de etiquetas y la configuración de intervalos a [`setNumberGroup`](/reference/facade/pivot-table#setnumbergroup).
- Grupo manual: pasar el ID original de campo fuente y grupos de miembros tipo [`setManualGroups`](/reference/facade/pivot-table#setmanualgroups). Cada grupo requiere al menos dos miembros; un array vacío elimina todos los grupos manuales para ese campo.

### Registro Complementos

El plugin de mesa pivote se puede registrar de una de dos maneras, dependiendo de cuánto cálculo debe retener el proceso principal.

**Proceso principal sólo**

Este modo es adecuado para tareas ligeras y operaciones simples: el plugin puede permanecer vacío, e importar `UniverSheetsPivotTablePlugin` es suficiente.

```typescript
univer.registerPlugin(UniverSheetsPivotTablePlugin)
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)
```

**Procesos principales y de trabajo**

Cuando el cálculo del pivote es pesado, registre el plugin tanto en el proceso principal como en el proceso de trabajo. El plugin puede entonces utilizar un diseño multi-teleada para la distribución y cálculo de datos, que mueve la mayoría del cálculo fuera del proceso principal y mejora el rendimiento general.

En este modo, el proceso principal maneja la distribución, sincronización y renderización de datos, mientras que el proceso del trabajador realiza el cálculo complejo. El modo se selecciona en la llamada de registro a través del config.

```typescript
// main process file
// Setting notExecuteFormula to true indicates that the main process does not perform calculations. It is only responsible for data distribution, synchronization, and rendering.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: true })
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)

// web worker process file
// Setting notExecuteFormula to false indicates that the worker process performs the calculations.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: false })
```

### Agregar una tabla dinámica

[`FWorkbook.addPivotTable`](https://docs.univer.ai/reference/facade/workbook#addpivottable) añade una tabla de pivotes y devuelve una instancia `FPivotTable` cuando tiene éxito.

```typescript
// should ensure the sheet range A1:G9 is not empty
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()
const sheetName = fSheet.getSheetName()
const sourceInfo = {
  unitId,
  subUnitId,
  sheetName,
  range: {
    startRow: 0,
    startColumn: 0,
    endRow: 8,
    endColumn: 6,
  },
}
const anchorCellInfo = {
  unitId,
  subUnitId,
  row: 20,
  col: 8,
}
const fPivotTable = await fWorkbook.addPivotTable(sourceInfo, univerAPI.Enum.PositionTypeEnum.Existing, anchorCellInfo)
const pivotTableId = fPivotTable.getPivotTableId()
// add flag to avoid add pivot fields multiple times
let hasAdded = false
// the addPivotTable is async, you can add pivot fields after the pivot table is added
univerAPI.addEvent(univerAPI.Event.PivotTableRendered, async (params) => {
  if (!hasAdded && params.pivotTableId === pivotTableId) {
    hasAdded = true
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Row, 0)
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Value, 0)
  }
})
```

### Escuchas de eventos

Las definiciones completas del tipo de evento están en [Eventos](https://docs.univer.ai/reference/facade/events).

`univerAPI.Event.BeforePivotTableAdd` dispara antes de añadir una tabla de pivotes.

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.BeforePivotTableAdd, (params) => {
  const { positionType, targetCellInfo } = params
  if (positionType === univerAPI.Enum.PositionTypeEnum.Existing && targetCellInfo.sheetName === 'Sheet 1') {
    // Cancel the pivot table adding operation
    params.cancel = true
    console.log(`The pivot table can't be added to the sheet ${targetCellInfo.sheetName}`)
  }
})

// Remove the event listener, use `disposable.dispose()`
```

`univerAPI.Event.PivotTableAdded` se dispara después de añadir una tabla de pivotes.

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.PivotTableAdded, (params) => {
```

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
const disposable = univerAPI.addEvent(univerAPI.Event.PivotTableValuePositionChanged, (params) => {
  const { pivotTableId, valueId, position } = params
  const pivotTable = fWorkbook.getPivotTableById(pivotTableId)
  const valueSetting = pivotTable.getValueSetting(valueId)
  console.log(`The source name ${valueSetting.sourceName} the display name ${valueSetting.displayName}`)
})

// Remove the event listener, use `disposable.dispose()`
```

## Área de salida ocupada [#blocked-output]

El informe necesita espacio para expandirse. El contenido celular existente, las células fusionadas u otra tabla de pivotes pueden bloquear el área de salida. Limpiar la obstrucción o mover el informe a un rango vacío.

## Mostrar valores como [#show-values-as]

`setShowDataAs()` en un campo de valor cambia el valor que muestra el campo: su parte de una fila, una columna, o un gran total, o su diferencia de un elemento base. Sólo los cambios de cálculo mostrados; los datos de origen no se modifican. `getShowDataAs()` lee el ajuste actual, y `resetShowDataAs()` restaura el cálculo normal.

```ts
const valueId = fPivotTable.getFieldIdsByArea(
  univerAPI.Enum.PivotTableFiledAreaEnum.Value,
)[0]
if (valueId) {
  await fPivotTable.setShowDataAs(valueId, {
    type: univerAPI.Enum.PivotShowAsTypeEnum.percentOfGrandTotal,
  })
  console.log(fPivotTable.getShowDataAs(valueId))
}
```

El ejemplo asume un `fPivotTable` existente. El argumento es un ID de campo de valor, no una columna de origen o un ID del campo de fila. Los modos de diferenciación y ejecución-total también requieren la configuración de campo base correspondiente y elementos base.

## Copiar tablas dinámicas junto con una hoja [#copy-with-worksheet]

Con el plugin de pivote registrado, duplicando una hoja de trabajo también copia las tablas de pivote en esa hoja de trabajo y conserva su configuración de campo. Cada copia recibe un nuevo ID de pivote. Un rango de fuente ubicado en la hoja de trabajo copiada se redirige a la nueva hoja de trabajo, mientras que una fuente en otra hoja de trabajo o libro de trabajo conserva su referencia original.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const copiedSheet = workbook.duplicateActiveSheet()
console.log(copiedSheet.getSheetName())
```

## Filtros múltiples y condiciones de fecha [#multiple-filters]

`setOptions({ allowMultipleFilters: true })` permite una selección de miembros, una condición de etiqueta o fecha, y un filtro de valor para coexistir en el mismo campo. Si la opción se omite o se establece en `false`, un nuevo filtro sustituye al anterior en lugar de añadirlo; desactivar la opción mientras las categorías conflicto elimina los filtros de informe. Un campo todavía acepta en la mayoría de un filtro de valores.

`setDateFilter()` acepta los operadores de fecha fija, incluyendo `dateEqual`, `dateOlderThan`, y `dateBetween`. `expected` ostenciones Excel Valores de serie en el sistema de fecha del libro de trabajo, y una condición entre dos de ellos. `useWholeDay: true` ignora el tiempo del día y compara días enteros; si la opción se omite o se establece para `false`, la comparación utiliza series exactas. El argumento es el ID de campo de reporte, no un índice de columna fuente. El siguiente ejemplo se basa en el `fPivotTable` arriba y una columna fuente llamada `Date`.

`getDateFilter()` devuelve una copia separada de la condición, y `clearDateFilter()` aclara la condición de la fecha y nada más. Ambos comandos participan en el deshacer y la colaboración. Compruebe el valor booleano que devuelven: un rebanador activo puede evitar que se aplique un filtro incompatible.

```ts
if (!fPivotTable) throw new Error('PivotTable not found')
await fPivotTable.setOptions({ allowMultipleFilters: true })

const dateField = Object.values(fPivotTable.getConfig()?.fieldsConfig.dimension ?? {})
  .find((field) => field.sourceName === 'Date')
if (!dateField) throw new Error('Add the Date field to the report first')

await fPivotTable.setDateFilter(dateField.id, {
  operator: univerAPI.Enum.ST_PivotFilterOperatorEnum.dateEqual,
  expected: 45293,
  useWholeDay: true,
})
console.log(fPivotTable.getDateFilter(dateField.id))
await fPivotTable.clearDateFilter(dateField.id)
```

## GETPIVOTDATA [#getpivotdata]

`=GETPIVOTDATA("Sales",$I$1,"Region","East")` lee un agregado de un informe de pivote visible cuya célula superior es I1. El campo de valor puede ser especificado por su capción mostrada o por su nombre de fuente. El ancla debe ser una referencia de celda única, y los pares de campo/objeto deben ser suministrados en su totalidad.

La implementación actual sólo lee el informe visible, escaneando hasta 200 filas hacia abajo y 50 columnas desde el ancla. No consulta registros de fuentes ocultas. Un par de campo/tema que no coincide, o un resultado que no está disponible, devuelve `#REF!`. Un recuento de argumento incorrecto, o un ancla que no es una sola célula, devuelve el `#VALUE!` .
