After you edit cell values, formulas, or formatting, open history to inspect earlier versions, compare changes, and restore a version when permitted. History reads server-persisted versions. Undo and redo apply to the current editing session and do not require a history service.

<Callout type="warning" title="Using 0.25.x?">
  Read the [archived 0.25.x Pro documentation](https://dream-num.github.io/documentation/v0.25/zh-CN/guides/pro/).
</Callout>

## Prepare collaboration and history services

Complete [collaboration integration](/guides/server-integration/collaboration) and [license configuration](/guides/server-integration/license). Verify that two sessions can edit the same Sheets document and that changes survive a reload.

Follow [Office collaboration extensions](https://office.univer.ai/collaboration/extensions) and the [History example](https://office.univer.ai/collaboration/examples#history) to connect history storage and permissions. Core collaboration does not enable history automatically. The backend must also support history lists, version content, and restoration.

## Add the history plugins

Add this to your existing product, license, and collaboration setup. If a preset or existing configuration already registers these plugins, update that configuration instead of registering them twice.

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/sheets-history @univerjs-pro/sheets-history-ui
```

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSheetsHistoryPlugin } from '@univerjs-pro/sheets-history'
import { UniverSheetsHistoryUIPlugin } from '@univerjs-pro/sheets-history-ui'
import HistoryLocale from '@univerjs-pro/sheets-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'

import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/sheets-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSheetsHistoryPlugin)
univer.registerPlugin(UniverSheetsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

Replace `/api/history` with your application's history endpoint and ensure its API matches the client requests. Keep both `historyServerUrl` values identical. Set `univerContainerId` to the editor container's DOM ID, and load the locale that matches the editor.

Sheets history also requires `UniverCollaborationClientUIPlugin` in the collaboration setup.

## View and restore versions

Open history from the editor menu and select a version to inspect its content and changes. Restoring changes the current shared document. Only users with restore permission should be able to do so, and the server must enforce that permission.

To verify the integration, edit cell values, formulas, or formatting, wait for collaboration confirmation, and inspect the history list and version content. Reopen the application and restart the service to check persistence. Restore an earlier version and verify that another browser session receives the restored state.

If the list is empty, check whether history was recorded for this document, then check the document ID and service URL. If viewing works but restoration fails, check restore permissions and the collaboration connection. Reading history also requires authorization because older versions may contain data that has since been deleted.
