Use a workbook mode to control editing and commenting across a spreadsheet. To let selected collaborators edit a sheet or a range, protect that sheet or range. In a collaborative deployment, the server must also authorize reads, session joins, and document changes. See [Identity and authorization](/server/collaboration/identity-and-authorization).

## Common tasks [#permission-tasks]

### Make a workbook read-only or allow comments

The `viewer` mode allows viewing and printing. Use `'commenter'` instead to allow comments while keeping cells read-only. A mode sets several permission points at once. To change one person’s role, use the [collaborator APIs](#collaborators).

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
```

To change a single point, call `setPoint`. For example, `await permission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)` turns off workbook editing. When the value changes, the SDK calls `IAuthzIoService.update` with the policy role `Editor` for `true` or `Owner` for `false`. To keep the policy when the document reopens, [connect an authorization service](#authorization-service).

### Let selected collaborators edit a worksheet

Replace `user1` and `user2` with IDs of existing workbook collaborators. Create the protection rule with `protect()` before setting individual worksheet permission points. Call `worksheetPermission.unprotect()` to remove worksheet protection.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})
```

### Restrict viewing and editing of A1:B2 to selected collaborators

`allowedUsers` identifies the collaborators who can edit the range. Set `allowViewByOthers: false` to also restrict who can see it. Call `rule.remove()` on the returned rule to remove just that protection.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
```

Call `rangePermission.listRules()` to list the rules intersecting the range. `rangePermission.unprotect()` removes all intersecting rules.

### Manage protected ranges

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('D1:D4')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('E1:E4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])

await createdRules[0].updateRanges([fWorksheet.getRange('D1:D5')])
```

### Diagnose why a value cannot be entered in A1

The example shows the permissions required to enter a plain cell value. Any `false` value blocks the edit. `debugCellPermission(0, 0)` returns the protection rule covering A1, or `undefined` if none applies.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const worksheet = fWorkbook.getActiveSheet().getWorksheetPermission()
const rule = await worksheet.debugCellPermission(0, 0)

console.table({
  workbookEdit: fWorkbook.getWorkbookPermission().canEdit(),
  worksheetEdit: worksheet.canEdit(),
  setCellValue: worksheet.getPoint(univerAPI.Enum.WorksheetPermissionPoint.SetCellValue),
  rangeEdit: rule?.canEdit() ?? true,
})
```

## List of permission points [#point-list]

### Worksheet actions and their points

Each operation checks its own points. A workbook point always applies alongside the worksheet or range points listed in the same row. When a row includes a range point, every protected range the operation touches must also allow the edit. Hiding a row or column widens the check to the whole row or column.

| Action | Required points |
| --- | --- |
| Enter a cell value (excluding formulas) | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `RangeProtectionPermissionEditPoint` |
| Insert a worksheet | `WorkbookEditablePermission`, `WorkbookCreateSheetPermission` |
| Copy a worksheet | `WorkbookEditablePermission`, `WorkbookCopySheetPermission` |
| Move a worksheet | `WorkbookEditablePermission`, `WorkbookMoveSheetPermission` |
| Rename a worksheet | `WorkbookEditablePermission`, `WorkbookRenameSheetPermission` |
| Hide or show a worksheet | `WorkbookEditablePermission`, `WorkbookHideSheetPermission` |
| Delete a worksheet | `WorkbookEditablePermission`, `WorkbookDeleteSheetPermission` |
| Hide or show rows or columns | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` or `WorksheetSetColumnStylePermission`, and the edit point of each intersecting protected range |
| Resize rows or columns, or fit them to their content | `WorksheetSetRowStylePermission` or `WorksheetSetColumnStylePermission` |
| Merge or unmerge cells | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `WorksheetSetCellStylePermission`, and the edit point of each intersecting protected range |
| Sort a range | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSortPermission`, and the edit point of each intersecting protected range |
| Freeze or unfreeze panes | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| Show or hide gridlines, or change their color | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| Add, update, or delete an annotation | `WorkbookEditablePermission`, `WorksheetEditPermission`, and the edit point of each protected range that contains the cell |
| Group or ungroup rows or columns | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` or `WorksheetSetColumnStylePermission`, and the edit point of each intersecting protected range |
| Create a protection rule | `WorkbookCreateProtectPermission` |
| Manage the collaborators of a protection rule | `WorksheetManageCollaboratorPermission` or `RangeProtectionPermissionManageCollaPoint` |
| Delete a protection rule | `WorksheetDeleteProtectionPermission` or `RangeProtectionPermissionDeleteProtectionPoint` |

When a required point is `false`, the command is rejected before it changes the document.

Annotations follow the cell edit points. Reading an annotation is not permission-checked.

### Comment permissions

Reading a Sheets comment requires workbook `View`. Posting requires workbook `Comment`. Both require worksheet `View`. For a comment anchored to a cell, each protection rule covering that cell must also allow viewing. Authors can update or delete their own comments.

## Protected range shadow strategy [#permission-ui]

Use `non-editable` to distinguish the protected areas the current user can edit from those they cannot. Editable areas receive no shadow, areas with editing disabled keep their shadow, and non-viewable ranges stay masked.

The setting affects only how range and worksheet protection is displayed. It does not create protection rules, does not change edit or view permissions, and does not add shadows to unprotected areas. Configure the protection rules and the current user’s permissions first, as described above.

| Strategy | Display behavior |
| --- | --- |
| `true` / `'always'` | Show shadows for all protected areas (default). |
| `'non-editable'` | Hide shadows on editable protected areas; keep them on non-editable areas. |
| `'non-viewable'` | Show shadows only on non-viewable protected areas. |
| `false` / `'none'` | Hide all protection shadows; permission checks still apply. |

## Update permission UI with the Facade API [#permission-ui-api]

### Protected range shadow strategy [#protected-range-shadow-api]

The Facade API below changes existing workbooks in the current Univer instance. In plugin mode, import `@univerjs/sheets-ui/facade` first; the Sheets Core preset already includes that module.

```typescript
// Set to only show shadows for non-editable ranges
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// Get the current protected range shadow display strategy
console.log(univerAPI.getProtectedRangeShadowStrategy())

// Subscribe to changes in the protected range shadow strategy
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // Update UI or perform other actions
})

// Later, unsubscribe to clean up
subscription.unsubscribe()
```

### Custom user component [#permission-user-picker-api]

Call `setSelectUserList()` from the change handler of your user picker. The React example below clears the selection. `useDependency` runs inside the component, and the service is updated only after a click. Build the remaining parts of the picker against `IPermissionDetailUserPartProps`.

### Integrating a third-party authorization service (advanced) [#authorization-service]

Register your [`IAuthzIoService`](https://github.com/dream-num/univer/blob/v1.6.0/packages/core/src/services/authz-io/type.ts) implementation before creating the workbook. The service must save protection rules and collaborator changes, return permissions for the current user, and propagate request failures to the caller.

```typescript
import { IAuthzIoService, Univer } from '@univerjs/core'
import { YourAuthzService } from './authorization-service'

const univer = new Univer({
  override: [[IAuthzIoService, { useClass: YourAuthzService }]],
})
```

### Collaborator management [#collaborators]

- Get the collaborator list

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

const collaborators = await workbookPermission.listCollaborators()
console.log(collaborators)
```

- Add collaborators

Use `addCollaborator` to add one person. `setCollaborators` replaces the entire list, so include everyone who should retain access.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.addCollaborator(
  { userID: 'user1', name: 'John Doe', avatar: '' },
  univerAPI.Enum.UnitRole.Editor,
)
```

- Replace the collaborator list

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.setCollaborators([
  {
    user: { userID: 'user1', name: 'John Doe', avatar: '' },
    role: univerAPI.Enum.UnitRole.Editor,
  },
  {
    user: { userID: 'user2', name: 'Jane Smith', avatar: '' },
    role: univerAPI.Enum.UnitRole.Reader,
  },
])
```

- Update collaborator roles

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.updateCollaborator(
  { userID: 'user1', name: 'John Doe Updated', avatar: '' },
  univerAPI.Enum.UnitRole.Reader,
)
```

- Remove collaborators

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.removeCollaborators(['user1', 'user2'])
```

## Extend permissions in a plugin

### Extended usage

To check permissions inside your own plugin, work with the permission points directly.

The example below uses `WorkbookEditablePermission`. Other permission points follow the same pattern.

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

[List of permission points](#point-list)

`SheetPermissionCheckController.permissionCheckByPoints(points)` checks an explicit list of permission points and returns `false` when any of them is disabled. Use it when a command already knows the points it needs, such as the points of a specific protection rule.

### How to extend permission points

For custom permission points, implement `IPermissionPoint` and register it with the permission service:

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // Default value
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // The id must be unique within `IPermissionService`.
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// How to use it elsewhere
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // This returns an RxJS observable that lets you listen for permission changes
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```
