Формулы являются основной частью Univer. Пользователи пишут формулы в ячейках, а Univer вычисляет значения. Поддерживаемые функции соответствуют Excel и охватывают математику, логику, текст, дату и другие категории.

Рабочая тетрадь, содержащая множество формул, может занимать основную нить в течение длительных периодов времени и замедлять страницу. Запуск вычисления формулы в Рабочем ограничивает влияние на рендеринг и взаимодействие с пользователем. Для деталей конфигурации см. [Веб-работники](/guides/sheets/getting-started/worker).

`initialFormulaComputing` управляет тем, как вычисляются формулы при загрузке книги. Если результаты хранимой формулы несвежие, `CalculationMode.FORCED` пересчитывает их. В заданном режиме та же опция вложена под `formula`.

Выберите режим интеграции, который вы используете, и добавьте эти параметры к существующей инициализации.Сохраните другие плагины, локализацию, тему и настройки контейнера неизменными и не регистрируйте один и тот же плагин дважды.

- `CalculationMode.FORCED` пересчитывает все формулы.
- `CalculationMode.WHEN_EMPTY` является стандартом и вычисляет только ячейки формул, которые не имеют сохраненного значения `v`.
- `CalculationMode.NO_CALCULATION` пропускает вычисления во время инициализации.

## Настройка плагинов [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | Устанавливает, как вычисляются формулы при открытии книги. |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

## Настройка пресетов [#preset-configuration]

`UniverSheetsCorePreset`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>formula</ConfigKey> | `object` |  | Функции формулы, описания, режим вычисления и настройки подсказок экрана. |
| <ConfigKey depth={1}>initialFormulaComputing</ConfigKey> | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | Устанавливает, как вычисляются формулы при открытии книги. |

```typescript
import { CalculationMode, UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import { createUniver } from '@univerjs/presets'

const { univerAPI } = createUniver({
  presets: [
    UniverSheetsCorePreset({
      formula: {
        initialFormulaComputing: CalculationMode.FORCED,
      },
    }),
  ],
})
```

## Ссылки между книгами

Формула кросс-книги считывает данные из другой книги, например, для общего объема продаж в `Sales.xlsx` от `Report`. В отличие от ссылки на другой рабочий лист в той же книге, она также идентифицирует исходную книгу.

### Синтаксис ссылок

| Сценарий | Пример | Источник |
| --- | --- | --- |
| Другой лист той же книги | `=SUM(Data!A1:A10)` | Лист Data текущей книги |
| Диапазон другой книги | `=SUM('[Sales.xlsx]Data'!A1:A10)` | Лист Data книги Sales.xlsx |
| Таблица другой книги | `=SUM(Sales.xlsx!SalesTable[Amount])` | Столбец Amount существующей таблицы SalesTable |

`Sales.xlsx` - это название книги, а не путь к файлу или URL-адрес загрузки. Написание формулы не читает файл, не загружает книгу Excel или не подключается к редактору на другой странице браузера. Чтобы использовать ссылку на структурированную таблицу, сначала создайте соответствующий [столбик](/guides/sheets/features/table).

### Ссылки на книги в одном экземпляре

С движком базовой формулы обе книги должны быть загружены в один и тот же экземпляр Univer и совместно использовать одну и ту же среду вычисления формулы. Запустите этот пример после инициализации листов. В режиме плагина также импортируйте расширения Facade, описанные на этой странице.

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false` загружает исходную рабочую книгу, не делая ее текущей рабочей книгой.Продолжайте использовать явные ручки `source` и `report`, чтобы изменение активной рабочей книги не отправляло формулу в неправильную рабочую тетрадь.

Сопоставление имен не зависит от конкретного случая. Совпадение полного имени имеет приоритет; когда его нет, сопоставление игнорирует общие расширения Excel, такие как `.xlsx` и `.xlsm`. Имя, которое не существует или соответствует нескольким рабочим книгам, возвращает `#REF!` . Поэтому имена источников должны быть явными и уникальными.

### Привязка к постоянному ID источника

Используйте настроенный выше движок Pro, чтобы привязать имена книг в формулах к постоянным идентификаторам документов.

Пример использует книги выше в среде с настроенным Pro-движком:

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId` идентифицирует рабочую книгу, содержащую формулу. `unit.unitId` является стабильным идентификатором исходной книги, а `formulaQualifier` - это имя, которое исходная рабочая книга использует в тексте формулы. Координаты диапазона основаны на нуле, а конечная позиция является инклюзивной.

`buildReference()` возвращает опорный фрагмент без `=` и сохраняет привязку кросс-книги. Он не загружает исходную книгу или не запускает вычисление. Исходные данные по-прежнему должны поступать из рабочей книги, загруженной в среду вычислений, или от настроенного поставщика данных.

Для рукописного или прикладного текста формулы свяжите источник перед написанием формулы:

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

Повторение идентичной привязки в одной и той же книге является идемпотентным.Проходите `qualifier` без скобок или цитат, и не используйте положительное целое число, такое как `1` или `2`. Excel резервирует такие номера для слотов внешних ссылок, а не для идентификаторов документов приложения. Импортированные внешние ссылки Excel также требуют своих ресурсов ссылок; копирование текста формулы само по себе недостаточно.

### Обновление, сохранение и выгрузка

После изменения исходных данных через Фасад вычислите в явном виде и дождитесь, пока результаты не будут применены, прежде чем читать цель.Возврат от `setFormula()` или `setValue()` не означает, что асинхронный расчет закончился.

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

Сохранение цели с помощью `report.save()` для сохранения полного снимка, включая его ресурсы, связывающие ссылки. Сохранения только текста формулы ячейки теряет отображение между публичными именами и идентификаторами источников. Сохранять и загружать данные из книги с исходным кодом отдельно.

После выгрузки исходной книги обычные ссылки на загруженные рабочие книги больше не могут ее читать. Pro внешние ссылки продолжают вычислять только тогда, когда сконфигурированные поставщики данных и доступные кэши поставляют требуемые данные. Привязка не содержит исходных данных и не гарантирует автономный расчет. Ранее отображаемый результат не доказывает, что данные являются текущими.

Удалить привязку Pro, когда она больше не требуется:

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

Удаление связывания не удаляет и не переписывает существующие формулы. Следующий расчет снова разрешает их имена. Если загруженная рабочая тетрадь все еще соответствует имени, ссылка может продолжать разрешать; если ничего не совпадает, она возвращает `#REF!`. Чтобы вообще прекратить ссылаться на источник, изменить или очистить формулы ячейки.

См. [FFormula reference-binding API](/reference/facade/formula) для полных параметров и значений возврата.

## Трёхмерные ссылки

3D-ссылка охватывает последовательные рабочие листы в рабочей книге. Она отличается от ссылки на другую рабочую книгу:

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

Диапазон включает в себя `Jan`, `Mar` и каждый лист между ними, в порядке книги, а не в алфавитном порядке. Переупорядочение рабочих листов может изменить то, что агрегирует диапазон, поэтому подтвердите диапазон после переупорядочивания.

### Открытие диалогового окна выбора диапазона

`@univerjs/sheets-formula-ui/facade` добавляет `univerAPI.showRangeSelectorDialog`. Пользовательский интерфейс, который требует от пользователей выбора одного или нескольких диапазонов, может называться этим API, который открывает тот же селектор, который используют панели, связанные с формулой.

```typescript
const workbook = univerAPI.getActiveWorkbook()
const worksheet = workbook?.getActiveSheet()

if (workbook && worksheet) {
  await univerAPI.showRangeSelectorDialog({
    unitId: workbook.getId(),
    subUnitId: worksheet.getSheetId(),
    initialValue: [
      {
        unitId: workbook.getId(),
        sheetName: worksheet.getSheetName(),
        range: worksheet.getRange('A1:B2').getRange(),
      },
    ],
    maxRangeCount: 2,
    supportAcrossSheet: true,
    callback: (ranges, isCancel) => {
      console.log(ranges, isCancel)
    },
  })
}
```

### Установка режима вычисления формул при инициализации данных

```typescript
const formulaEngine = univerAPI.getFormula()
formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
```

При вызове после жизненного цикла `Starting` этот API вступает в силу в следующий раз, когда создается спецификация Univer.

Чтобы применить его во время текущей инициализации спецификации Univer, назовите его перед жизненным циклом `Ready`.

```typescript
univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### Итерационные вычисления [#iterative-calculation]

Итеративный расчет — это настройка уровня рабочей книги, хранящаяся в поле `calculationSettings` своего снимка. Он отключен по умолчанию, поэтому круговые формулы сохраняют свои кэшированные значения, или ноль, когда значение не кэшируется. Включите его для моделей, которые намеренно содержат круговые ссылки.

| Параметр | По умолчанию | Поведение |
| --- | --- | --- |
| `iterativeCalculation` | `false` | Оцените круговые ссылки итеративно. |
| `maxIterations` | `100` | Целое число между 1 и 32767. |
| `maxChange` | `0.001` | Итерация останавливается, когда каждый численный результат в круговой группе изменяется не более чем на это количество. |

Обновление всех трех настроек вместе с помощью программы Facade. Команда поддерживает отмену и переделку, а также совместную работу, и возвращает `false`, если книга недоступна или не может быть отредактирована. Недействительные настройки нормализуются до значений по умолчанию.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

`calculationSettings` также может поставляться при вызове `createWorkbook()`. Каждая книга сохраняет свои собственные настройки. Лента Формулы выставляет те же элементы управления с помощью опций расчета.

Циркулярно-справочная диагностика может быть прочитана после применения результатов расчета. `getCircularReferences()` не запускает расчет; его результаты включают идентификаторы рабочих листов, координаты строк и столбцов на нулевой основе, идентификаторы групп, подсчеты итерации и информацию о конвергенции, когда она доступна.

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### Получение результатов выполнения строковых формул

Выполните партию формул асинхронно и получите результаты расчета:

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // Full formula:
          '=SUM(A1:A10) + SQRT(D7)',

          // Decomposed sub-formulas (each one can be evaluated independently):
          'SUM(A1:A10)', // sub-formula 1
          'SQRT(D7)', // sub-formula 2
          'A1:A10', // range reference
          'D7', // single-cell reference
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## Семантика значений формул [#formula-value-semantics]

`ISBLANK(A1)` проверяет, содержит ли эталонная ячейка контент, а не только является ли ее отображаемый результат пустым. Очищенная ячейка, в том числе та, которая сохраняет форматирование, пуста; формула, которая возвращает `""`, отсутствует. Буквальный `ISBLANK("")` также `FALSE`. `UNIQUE` сравнивает текст без чувствительности к регистру и сохраняет первое правописание. `PROPER` распознает буквы Unicode, включая акцентированные латинские, греческие и кириллические буквы. `AVERAGE` объединяет весь массив, возвращаемый такими функциями, как `FILTER` .

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
