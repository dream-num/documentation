公式是 Univer 的核心能力之一。使用者在單元格中寫入公式，由 Univer 計算其值。支援的函式與 Excel 一致，涵蓋數學、邏輯、文字、日期等型別。

工作簿中的公式較多時，公式計算可能長時間佔用主執行緒，頁面響應隨之變慢。把公式計算放到 Worker 中執行，可以減輕對渲染和使用者互動的影響。配置方式見 [Web Workers](/guides/sheets/getting-started/worker)。

`initialFormulaComputing` 控制工作簿載入時的公式計算方式。如果已儲存的公式結果已經過期，`CalculationMode.FORCED` 會重新計算這些結果。在預設模式下，該選項位於 `formula` 之下。

根據所採用的接入模式，把這些選項加入現有的初始化配置。其他外掛、語言、主題和容器設定保持原樣，同一個外掛不要註冊兩次。

- `CalculationMode.FORCED` 重新計算所有公式。
- `CalculationMode.WHEN_EMPTY` 是預設值，只計算沒有已儲存 `v` 值的公式單元格。
- `CalculationMode.NO_CALCULATION` 初始化時不計算公式。

## 外掛設定 [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | 設定工作簿開啟時公式的計算方式。 |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

## 預設設定 [#preset-configuration]

`UniverSheetsCorePreset`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>formula</ConfigKey> | `object` |  | 設定公式函數、說明、計算模式與函數提示。 |
| <ConfigKey depth={1}>initialFormulaComputing</ConfigKey> | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | 設定工作簿開啟時公式的計算方式。 |

```typescript
import { CalculationMode, UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import { createUniver } from '@univerjs/presets'

const { univerAPI } = createUniver({
  presets: [
    UniverSheetsCorePreset({
      formula: {
        initialFormulaComputing: CalculationMode.FORCED,
      },
    }),
  ],
})
```

## 設定跨活頁簿繫結 [#cross-workbook-configuration]

如果應用需要把公式中的名稱與固定的文件 ID 關聯起來，可以使用 `@univerjs-pro/engine-formula` 提供的引用繫結 API。這是一項 Pro 擴充套件：需要先配置[客戶端許可證](/server/license)，初始化時用 `UniverProFormulaEnginePlugin` 替換 `UniverFormulaEnginePlugin`，並引入 Pro Facade。公式引擎只能註冊一個。僅引入 Facade 不會註冊外掛。

## 跨活頁簿引用

跨工作簿公式從另一個工作簿讀取資料，例如在 `Report` 中彙總 `Sales.xlsx` 的銷售額。與引用同一工作簿中的其他工作表不同，跨工作簿公式還需要指明來源工作簿。

### 引用語法

| 情境 | 範例 | 意義 |
| --- | --- | --- |
| 同一工作簿中的另一張工作表 | `=SUM(Data!A1:A10)` | 目前活頁簿的 Data 工作表 |
| 另一工作簿中的單元格區域 | `=SUM('[Sales.xlsx]Data'!A1:A10)` | Sales.xlsx 的 Data 工作表 |
| 其他活頁簿的表格 | `=SUM(Sales.xlsx!SalesTable[Amount])` | 已存在的 SalesTable 表格的 Amount 欄 |

`Sales.xlsx` 是工作簿名稱，不是檔案路徑，也不是下載地址。寫入公式不會讀取檔案、下載 Excel 工作簿，也不會連線到另一個瀏覽器頁面中的編輯器。需要使用表格結構化引用時，先建立對應的[表格](/guides/sheets/features/table)。

### 引用同一實例中已載入的活頁簿

使用基礎公式引擎時，兩個工作簿必須載入到同一個 Univer 例項中，並處於同一個公式計算環境。下面的程式碼應在 Sheets 初始化之後執行。在外掛模式下，還需要按本頁的說明引入 Facade 擴充套件。

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false` 使來源工作簿載入後不會成為當前工作簿。後續始終使用 `source` 和 `report` 這兩個顯式引用，即使活動工作簿發生變化，公式也不會被寫到其他工作簿。

名稱匹配不區分大小寫。優先按完整名稱匹配；如果沒有完整名稱匹配，則忽略 `.xlsx`、`.xlsm` 這類常見 Excel 副檔名後再匹配。名稱不存在，或者匹配到多個工作簿時，都會返回 `#REF!`。來源名稱應當明確且唯一。

### 綁定固定的來源 ID

使用前面配置好的 Pro 引擎，可以把公式中的名稱繫結到固定的文件 ID。

下面的範例沿用前面兩個工作簿，但執行在配置了 Pro 引擎的環境中：

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId` 表示包含該公式的工作簿。`unit.unitId` 是來源工作簿的固定 ID，`formulaQualifier` 是該工作簿在公式文字中使用的名稱。區域座標從 `0` 開始，且結束位置包含在內。

`buildReference()` 返回不帶 `=` 的引用片段，同時持久化儲存跨工作簿繫結。它不會載入來源工作簿，也不會觸發計算。來源資料仍然需要來自載入到計算環境中的工作簿，或者來自已配置的資料提供方。

如果公式文字由人工編寫或由應用生成，應先繫結來源，再寫入公式：

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

在同一個工作簿中重複寫入相同的繫結是冪等操作。`qualifier` 不要帶方括號或引號，也不要使用 `1`、`2` 這類正整數，因為 Excel 將這些編號保留給外部連結槽位，而不是用於應用文件 ID。從 Excel 匯入的外部連結還需要對應的連結資源，僅複製公式文字並不夠。

### 更新、儲存與卸載

透過 Facade 修改來源資料後，需要顯式執行計算，並在結果寫回之後再讀取目標值。`setFormula()` 或 `setValue()` 返回，並不表示非同步計算已經完成。

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

使用 `report.save()` 儲存目標工作簿，可以保留完整的快照，其中包含引用繫結資源。如果只儲存單元格中的公式文字，公開名稱與來源 ID 之間的對映就會丟失。來源工作簿的資料需要單獨儲存和載入。

來源工作簿解除安裝後，普通的已載入工作簿引用就無法再讀取它。Pro 外部引用能否繼續計算，取決於已配置的資料提供方和可用快取是否能夠提供所需資料。繫結本身不包含來源資料，也不保證可以離線計算。此前顯示過的結果並不能證明當前資料仍然有效。

不再需要某個 Pro 繫結時，可以將其移除：

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

移除繫結不會刪除或改寫已有的公式，下一次計算會重新解析這些名稱。如果仍有同名工作簿處於載入狀態，引用可能繼續解析成功；如果沒有任何匹配，則返回 `#REF!`。如果要徹底停止引用該來源，還需要修改或清空相關單元格的公式。

完整參數和返回值見 [FFormula 引用繫結 API](/reference/facade/formula)。

## 三維引用

三維引用指同一工作簿中連續的一組工作表，與引用另一個工作簿不同：

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

範圍包含 `Jan`、`Mar` 以及兩者之間的所有工作表，按工作簿中的排列順序計算，而不是按名稱排序。調整工作表順序後，需要重新確認彙總範圍。

### 開啟範圍選擇器

`@univerjs/sheets-formula-ui/facade` 會新增 `univerAPI.showRangeSelectorDialog`。自定義 UI 需要使用者選擇一個或多個區域時，可以使用該 API，其開啟的選擇器與公式相關面板使用的是同一個。

```typescript
const workbook = univerAPI.getActiveWorkbook()
const worksheet = workbook?.getActiveSheet()

if (workbook && worksheet) {
  await univerAPI.showRangeSelectorDialog({
    unitId: workbook.getId(),
    subUnitId: worksheet.getSheetId(),
    initialValue: [
      {
        unitId: workbook.getId(),
        sheetName: worksheet.getSheetName(),
        range: worksheet.getRange('A1:B2').getRange(),
      },
    ],
    maxRangeCount: 2,
    supportAcrossSheet: true,
    callback: (ranges, isCancel) => {
      console.log(ranges, isCancel)
    },
  })
}
```

### 設定初始化資料時公式的計算模式

```typescript
const formulaEngine = univerAPI.getFormula()

```

如果該 API 在 `Starting` 生命週期之後才被呼叫，則要等到下次建立 Univer Sheet 時才生效。

如果希望它在本次初始化時生效，可以在 `Ready` 生命週期之前呼叫，例如：

```typescript
univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### 反覆運算 [#iterative-calculation]

迭代計算按工作簿配置，儲存在快照的 `calculationSettings` 欄位中。該功能預設關閉，此時迴圈引用公式保留快取值，沒有快取值則使用零。僅在模型確實有意包含迴圈引用時才需要啟用。

| 選項 | 預設值 | 行為 |
| --- | --- | --- |
| `iterativeCalculation` | `false` | 對迴圈引用做迭代求值。 |
| `maxIterations` | `100` | 1 到 32767 之間的整數。 |
| `maxChange` | `0.001` | 有限的正數，用作收斂閾值。迴圈組中每個數值結果的變化都不超過這個值時停止迭代。 |

三個設定需要一起透過工作簿 Facade 提交。該命令支援撤銷、重做和協同，工作簿不存在或不可編輯時返回 `false`。無效的設定會歸一為預設值。

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

呼叫 `createWorkbook()` 時也可以傳入 `calculationSettings`。每個工作簿儲存各自的設定。公式工具欄的「計算選項」中提供了相同的控制元件。

計算結果顯示之後，才能讀取迴圈引用診斷資訊。`getCircularReferences()` 不會觸發計算，返回結果包含工作表 ID、從零開始的行列座標、迴圈組 ID、迭代次數，以及可取得時的收斂資訊。

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### 取得公式字串的計算結果

非同步執行一批公式，並取得計算結果：

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // 完整公式：
          '=SUM(A1:A10) + SQRT(D7)',

          // 分解後的子公式（每個都可以獨立計算）：
          'SUM(A1:A10)', // 子公式1
          'SQRT(D7)', // 子公式2
          'A1:A10', // 範圍參考
          'D7', // 單元格參考
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## 公式值的語意 [#formula-value-semantics]

`ISBLANK(A1)` 檢查的是引用的單元格是否包含內容，而不僅僅是顯示結果是否為空。已清空的單元格（即使保留了格式）視為空，返回 `""` 的公式則不算空。直接量 `ISBLANK("")` 同樣返回 `FALSE`。`UNIQUE` 比較文字時不區分大小寫，並保留首次出現的拼寫。`PROPER` 能識別 Unicode 字母，包括帶重音的拉丁字母、希臘字母和西裡爾字母。`AVERAGE` 會聚合 `FILTER` 等函式返回的完整陣列。

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
