フォーミュラはUniverのコア部分です。ユーザーはセルで数式を記述し、Univerは値を計算します。サポートされている機能は、Excelにマッチし、数学、論理的、テキスト、日付、およびその他のカテゴリをカバーします。

多くの式を含むワークブックは、長期間のメインスレッドを占有し、ページを遅くすることができます。 Worker での実行式計算は、レンダリングとユーザーインタラクションへの影響を制限します。 構成の詳細については、[ウェブワーカー](/guides/sheets/getting-started/worker) を参照してください。

`initialFormulaComputing`は、ワークブックが読み込まれると、式がどのように計算されるかを制御します。保存された式の結果がスタイルの場合、`CalculationMode.FORCED`がそれらを再計算します。プリセットモードでは、同じオプションは`formula`の下にネストされます。

使用するインテグレーションモードを選択し、これらのオプションを既存の初期化に追加します。他のプラグイン、ロケール、テーマ、およびコンテナの設定は変更されず、同じプラグインを2回登録しないでください。

- `CalculationMode.FORCED`はすべての式を再計算します。
- `CalculationMode.WHEN_EMPTY`はデフォルトで、保存されていない`v`値の公式セルのみを計算します。
- `CalculationMode.NO_CALCULATION`は初期化時に計算をスキップします。

## プラグイン設定 [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | ワークブックが開いているときに計算される式を設定します。 |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

`UniverSheetsCorePreset`

## ブック間のバインド設定 [#cross-workbook-configuration]

アプリケーションが安定したドキュメント ID で式名を関連付ける必要がある場合は、`@univerjs-pro/engine-formula` が提供する参照結合 API を使用できます。これは Pro 拡張です。[クライアントライセンス](/server/license) を設定し、`UniverFormulaEnginePlugin` を初期化時に `UniverProFormulaEnginePlugin` に置換し、Pro Facade をインポートします。1 式エンジンのみを登録できます。Facade を単独でインポートすると、プラグインは登録されません。

## ブック間参照

クロスワークブックの式は、`Report`から`Sales.xlsx`での販売を合計するなど、別のワークブックからデータを読み込みます。同じワークブックの別のワークシートへの参照とは異なり、ソースのワークブックも識別します。

### 参照の構文

| 用途 | 例 | 対象 |
| --- | --- | --- |
| 同じブックの別シート | `=SUM(Data!A1:A10)` | 現在のブックの Data シート |
| 別ブックのセル範囲 | `=SUM('[Sales.xlsx]Data'!A1:A10)` | Sales.xlsx の Data シート |
| 別ブックのテーブル | `=SUM(Sales.xlsx!SalesTable[Amount])` | 既存の SalesTable の Amount 列 |

`Sales.xlsx`は、ファイルパスやダウンロードURLではなく、ワークブック名です。 式を書くことは、ファイルを読みません、Excelのワークブックをダウンロードし、別のブラウザページでエディタに接続します。 構造化されたテーブルの参照を使用するには、対応する[テーブルテーブル](/guides/sheets/features/table)を最初に作成します。

### 同じインスタンスに読み込んだブックを参照する

コア式エンジンでは、両方のワークブックが同じUniverインスタンスにロードされ、同じ式計算環境を共有しなければなりません。シートを初期化した後、この例を実行します。プラグインモードでは、このページに記載されているファサード拡張もインポートします。

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false`は、現在のワークブックを作ることなく、ソースのワークブックをロードします。 explicit `source`と`report`ハンドルを使用して、アクティブなワークブックの変更が間違ったワークブックに式を送信しません。

名前の一致はケース・インセンティブです。 フルネームの一致は優先されます; どれもあれば、一致は共通を無視します Excel などの拡張子 `.xlsx` そして、 `.xlsm`. 存在しない名前、または複数のワークブックにマッチする名前、 `#REF!`. ソース名は明示的かつユニークなものでなければなりません。

### 安定した参照元 ID にバインドする

上記で設定した Pro エンジンを使い、数式に含まれるブック名を安定したドキュメント ID に結び付けます。

Pro エンジンを設定済みの環境で、上のブックを使用します。

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId`は、式を含むワークブックを識別します。 `unit.unitId` は、ソースワークブックの安定した ID であり、 `formulaQualifier` (修飾子) は、ソースコードのワークブックが式テキストで使用している名前です。 範囲座標はゼロベースであり、終点は含んでいます。

`buildReference()`は、`=`なしで参照フラグメントを返し、クロスワークブックの結合を主張します。 ソースワークブックをロードしたり、計算を開始したりしません。 ソースデータは、計算環境にロードされたワークブックから、または構成されたデータプロバイダから来なければなりません。

手書きやアプリケーション生成式テキストの場合は、式を書く前にソースをバインドします。

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

同じワークブックで同一の結合を繰り返すことは、意図的です。`qualifier`をブラケットや引用符なしで渡し、`1`や`2`などの正式整数を使用しないでください。 Excelは、アプリケーション文書IDではなく、外部リンクスロットのそのような番号を予約します。 インポートされたExcel外部リンクは、リンクリソースも必要です。 式テキストをコピーすることは、それだけではありません。

### 更新・保存・アンロード

ファサードを介してソースデータを変更した後、, 明示的に計算し、ターゲットを読む前に結果が適用されるまで待つ. `setFormula()`または`setValue()`からのリターンは非同期計算が終了したという意味ではありません.

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

参照結合リソースを含む完全なスナップショットを保存するために、`report.save()`でターゲットを保存します。 セルの式テキストのみを保存して、パブリック名とソースIDの間のマッピングを失います。 ソースのワークブックデータを個別に保存および読み込みます。

ソースのワークブックがアンロードされた後、ロードされたワークブックへの通常の参照はもはやそれを読むことができません。 Proの外部参照は、構成されたデータプロバイダと利用可能なキャッシュが必要なデータを供給したときにのみ計算し続けます。 結合はソースデータを含んでおり、オフラインの計算を保証するものではありません。 以前に表示された結果は、データが現在のものであることを証明しません。

不要になったときにプロバインディングを削除します。

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

結合を取除くことは既存の方式を削除し、または書き換えません。次の計算は、再びその名前を解決します。ロードされたワークブックがまだ名前と一致している場合、参照は解決し続けるかもしれません。何もマッチしない場合、それは`#REF!`を返します。ソースを完全に参照し、変更するか、または細胞の式をクリアするのを止めてください。

削除しても数式は削除・書き換えされません。次の計算では名前を再解決し、同名の読み込み済みブックがあれば参照が解決する場合があります。なければ `#REF!` になります。参照を停止するには数式も変更・消去してください。詳細は [FFormula 参照 API](/reference/facade/formula) を参照してください。

## 3D 参照

3Dリファレンスは、ワークブックで連続したワークシートに分類されます。これは、別のワークブックへの参照とは異なるものです。

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

範囲は、`Jan`、`Mar`およびそれらの間のすべてのシート、アルファベット順ではなくワークブックの順番に含まれています。ワークシートを並べ替えると、範囲の合計を変更することができますので、再注文後に範囲を確認することができます。

### 初期化データ時の数式計算モードの設定

```typescript
const formulaEngine = univerAPI.getFormula()

```

`Starting` のライフサイクル後に呼び出されると、この API は、Univerシートが作成される次の時間に有効になります。

Univerシートの初期化中に適用するために、次の例のように、`Ready`のライフサイクルの前にそれを呼び出します。

```typescript

  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### 反復計算 [#iterative-calculation]

反復的な計算は、スナップショットの`calculationSettings`フィールドに格納されているワークブックレベルの設定です。デフォルトでは無効になっています。そのため、円式はキャッシュされた値を保持し、値がキャッシュされていない場合はゼロです。意図的に円参照を含むモデルを有効にします。

| オプション | 既定値 | 動作 |
| --- | --- | --- |
| `iterativeCalculation` | `false` | 円周参照を反復的に評価する。 |
| `maxIterations` | `100` | 1～32767の整数。 |
| `maxChange` | `0.001` | 有限、肯定的な収斂しきい値。この値よりも、円グループが変化するすべての数値の結果が、反復が止まります。 |

ワークブックファサードを通じて、すべての3つの設定を一緒に更新します。 コマンドは、undoとredoだけでなく、コラボレーションをサポートし、ワークブックが利用できなくなったり、編集できない場合は、`false`を返します。 無効な設定は、デフォルト値に正規化されます。

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

`createWorkbook()` を呼び出すと、`calculationSettings`も供給できます。各ワークブックは独自の設定を保持します。フォーミュラリボンは、計算オプションを介して同じ制御をexposesします。

計算結果が適用された後、円形参照の診断は読むことができます。`getCircularReferences()`は計算を始めません;結果は利用できるときワークシートID、ゼロ ベースの列およびコラムの座標、グループID、反復の計算およびconvergence情報を含んでいます。

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### 数式文字列の計算結果の取得

数式を非同期的に実行し、計算結果を受け取る:

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // 完全な数式:
          '=SUM(A1:A10) + SQRT(D7)',

          // 分解されたサブ数式（それぞれ独立して評価可能）:
          'SUM(A1:A10)', // サブ数式1
          'SQRT(D7)', // サブ数式2
          'A1:A10', // 範囲参照
          'D7', // 単一セル参照
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## 数式の値の扱い [#formula-value-semantics]

`ISBLANK(A1)`は、参照されたセルに表示された結果が空であるかどうかだけでなく、コンテンツが含まれているかどうかを確認します。 クリアされたセルは、フォーマットを保持する1つを含む、空白です。 `""`を返す式はありません。 文字`ISBLANK("")`も`FALSE`です。 `UNIQUE`は、ケースの感度なしでテキストを比較し、最初のスペルを保持します。 `PROPER`は、アクセント付きラテン、ギリシャ、およびCyrillic文字を含むUnicode文字を認識しています。 `AVERAGE`は、そのような機能として返された配列全体を集計します。 `FILTER`

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
