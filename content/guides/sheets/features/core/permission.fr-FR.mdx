Le contrôle de la permission dans Univer détermine ce qu'un utilisateur peut faire sur un cahier de travail, une feuille de travail ou une plage. Lorsqu'un utilisateur tente une opération sans la permission requise, Univer arrête l'opération et signale la permission manquante.

<Callout type="warning">
Votre service doit persister les règles de protection et les changements de collaborateur, retourner les permissions de l'utilisateur actuel, et passer les échecs de requête à l'appelant. Une maquette qui renvoie une liste vide n'est pas une couche de persistance. En collaboration, le moteur doit également vérifier les autorisations de lecture, JOIN et mutation elle-même; voir [Identité et autorisation](/server/collaboration/identity-and-authorization). La protection dans l'interface utilisateur et les ombres cachées ne remplacent pas l'autorisation du serveur.

[Intégration du service d’autorisation](#authorization-service)
</Callout>

## Concepts fondamentaux

- Portée : Les autorisations s'appliquent à trois niveaux : cahier de travail, feuille de travail et fourchette.
- Points de permission : Chaque fonction a un point de permission, et modifier sa valeur permet ou désactive cette fonction.
- Règles de protection : Une feuille de travail ou une plage a besoin d'une règle de protection avant que ses points de permission puissent être définis.

<Callout type="info">
Les permissions locales non persistantes se modifient via les points de permission. Pour la persistance, consultez [Intégration du service d’autorisation](#authorization-service).

Dans l'édition collaborative, la mise à jour d'un point d'autorisation met également à jour l'état du serveur :
  - `false` : le point d’autorisation exige au minimum le rôle `owner`
  - `true` : le point d’autorisation exige au minimum le rôle `reader`
</Callout>

## Exemple de base

Avant d'utiliser les exemples `allowedUsers`, remplacez `user1` et `user2` par de vrais identifiants de collaborateurs retournés par votre service d'autorisation.

Les exemples ci-dessous montrent la façon habituelle de définir les permissions à chacun des trois niveaux : cahier de travail, feuille de travail et portée.

### Exemple de code pour les autorisations d’un classeur

Définissez les autorisations au niveau du cahier de travail directement via le [Facade API](/guides/sheets/getting-started/facade).

L'exemple ci-dessous désactive l'édition pour l'ensemble du workbook. Pour contrôler une autre fonctionnalité, remplacez le point de permission par celui correspondant; voir le [liste des points d'autorisation du cahier](#workbook-point):

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Set the workbook to be non-editable
await workbookPermission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)
```

Les points d'autorisation du cahier de travail peuvent être définis directement, sans créer une règle de protection en premier.

### Exemple de code pour les autorisations d’une feuille de calcul

Les permissions de feuille de travail et de portée peuvent être définies par l'intermédiaire de Facade API ou par des commandes. Cet exemple définit la permission d'éditer la feuille de travail. Pour contrôler une autre fonctionnalité, remplacez le point de permission par celui correspondant; voir la [liste des points d'autorisation de feuille de travail](#worksheet-point):

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// Create worksheet protection, allow specified users to edit
const permissionId = await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})

// To set permission points, you must first protect the worksheet
await worksheetPermission.setPoint(univerAPI.Enum.WorksheetPermissionPoint.Edit, false)
```

#### Supprimer les autorisations d’une feuille de calcul

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// Remove worksheet protection
await worksheetPermission.unprotect()
```

### Exemple de code pour les autorisations d’une plage personnalisée

Les permissions de portée peuvent être définies de la même manière : à travers l'API ou les commandes. L'exemple ci-dessous utilise la permission de modification de portée. D'autres fonctionnalités de portée nécessitent un point de permission différent; voir le [liste des points d'autorisation - Gamme](#range-point) pour plus de détails.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// Set range protection permission, allow specified users to edit but not allow others to view
const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
console.log(rule)

// To set permission points, you must first create a range protection rule.
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.Edit, false)
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.View, true)
```

#### Supprimer les autorisations de protection d’une plage

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// delete all rules within the range
await rangePermission.unprotect()

// Or delete specific rules within the range
const rules = await rangePermission.listRules()
if (rules.length > 0) {
  await rules[0].remove()
}
```

## Tâches courantes [#permission-tasks]

### Passer un classeur en lecture seule

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
console.log(permission.getSnapshot())
```

### Gérer les plages protégées

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('A1:B2')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('C3:D4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])
console.log(createdRules)

const rules = await permission.listRangeProtectionRules()
const firstRule = rules[0]
if (firstRule) {
  await firstRule.updateRanges([fWorksheet.getRange('A1:B3')])
}
```

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()

console.log(permission.debugCellPermission(0, 0))
```

## Stratégie d’ombrage des plages protégées [#permission-ui]

Utilisez `non-editable` pour distinguer les zones protégées que l'utilisateur actuel peut éditer de celles qu'il ne peut pas. Les zones modifiables ne reçoivent pas d'ombre, les zones dont l'édition est désactivée gardent leur ombre et les plages non visualisées restent masquées.

Le paramètre n'affecte que la façon dont la protection de la plage et de la feuille de travail est affichée. Il ne crée pas de règles de protection, ne modifie pas les permissions d'édition ou d'affichage, et n'ajoute pas d'ombres à des zones non protégées.

| Stratégie | Affichage |
| --- | --- |
| `true` / `'always'` | Afficher l’ombrage de toutes les zones protégées (par défaut). |
| `'non-editable'` | Masquer l’ombrage des zones protégées modifiables et le conserver sur les zones non modifiables. |
| `'non-viewable'` | Afficher l’ombrage uniquement sur les zones protégées non consultables. |
| `false` / `'none'` | Masquer tous les ombrages de protection ; les contrôles des droits restent actifs. |

## Mettre à jour l’interface des autorisations avec l’API Facade [#permission-ui-api]

### Stratégie d’ombrage des plages protégées [#protected-range-shadow-api]

Le Facade API ci-dessous modifie les cahiers de travail existants dans l'instance actuelle Univer. En mode plugin, importez d'abord `@univerjs/sheets-ui/facade` ; le préréglage de base de feuilles inclut déjà ce module.

```typescript
// Set to only show shadows for non-editable ranges
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// Get the current protected range shadow display strategy
console.log(univerAPI.getProtectedRangeShadowStrategy())

// Subscribe to changes in the protected range shadow strategy
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // Update UI or perform other actions
})

// Later, unsubscribe to clean up
subscription.unsubscribe()
```

## Intégration du service d’autorisation [#permission-integration]

### Utilisation avancée

Pour vérifier les permissions à l'intérieur de votre propre plugin, travaillez directement avec les points de permission.

L'exemple ci-dessous utilise `WorkbookEditablePermission`. D'autres points d'autorisation suivent le même modèle.

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

[Liste des points d’autorisation](#point-list)

### Étendre les points d’autorisation

Pour les points d'autorisation personnalisés, implémentez `IPermissionPoint` et enregistrez-le avec le service d'autorisation :

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // Default value
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // The id must be unique within `IPermissionService`.
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// How to use it elsewhere
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // This returns an RxJS observable that lets you listen for permission changes
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```

### Intégrer un service d’autorisation tiers (avancé) [#authorization-service]

Implémentez [Service IAuthzIo](https://github.com/dream-num/univer/blob/dev/packages/core/src/services/authz-io/type.ts) dans votre application et connectez ses méthodes d'autorisation, de rôle et de collaborateur à votre backend. L'exemple suppose que `./authorization-service` exporte l'implémentation sous la forme de `YourAuthzService`. Enregistrez-le avant de créer des cahiers de travail, et conservez les autres options d'initialisation et les enregistrements de plugins.

```typescript
import { IAuthzIoService, Univer } from '@univerjs/core'
import { YourAuthzService } from './authorization-service'

const univer = new Univer({
  override: [[IAuthzIoService, { useClass: YourAuthzService }]],
})
```

Votre service authz doit persister les règles de protection et les changements de collaborateur, retourner les permissions de l'utilisateur actuel, et les défaillances de la requête de surface. Une maquette qui renvoie des listes vides ne persiste rien. En collaboration, le moteur doit toujours vérifier les autorisations de lecture, JOIN et mutation elle-même ; voir [Identité et autorisation](/server/collaboration/identity-and-authorization). La protection de l'interface utilisateur et les ombres cachées ne remplacent pas l'autorisation du serveur.

### Gestion des collaborateurs

<Callout>
  La gestion des collaborateurs appartient à votre application et à son service d'autorisation. Connectez votre propre utilisateur et modèle ACL, et appliquez des politiques de lecture, JOIN et d'édition sur le serveur ; voir [identité et autorisation](/server/collaboration/identity-and-authorization). Les API frontend ci-dessous nécessitent une implémentation de service d'approbation correspondante ; elles ne configurent pas l'autorisation du serveur.
</Callout>

- Obtenez la liste des collaborateurs

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

const collaborators = await workbookPermission.listCollaborators()
console.log(collaborators)
```

- Ajouter des collaborateurs

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Add multiple collaborators at once
await workbookPermission.setCollaborators([
  {
    user: { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
    role: univerAPI.Enum.UnitRole.Editor,
  },
  {
    user: { userID: 'user2', name: 'Jane Smith', avatar: '' },
    role: univerAPI.Enum.UnitRole.Reader,
  },
])

// Add a single collaborator
await workbookPermission.addCollaborator(
  { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Editor,
)
```

- Mettre à jour les rôles des collaborateurs

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()

const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.updateCollaborator(
  { userID: 'user1', name: 'John Doe Updated', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Reader,
)
```

- Supprimer des collaborateurs

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
```
