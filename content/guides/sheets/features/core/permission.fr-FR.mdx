Le mode du classeur détermine si les utilisateurs peuvent modifier les cellules ou publier des commentaires. Pour réserver la modification d’une feuille ou d’une plage à certains collaborateurs, protégez-la. En mode collaboratif, le serveur doit aussi autoriser la lecture, l’accès à la session et les modifications du document. Voir [Identité et autorisation](/server/collaboration/identity-and-authorization).

## Tâches courantes [#permission-tasks]

### Ouvrir un classeur en lecture seule ou autoriser les commentaires

Le mode `viewer` permet de consulter et d’imprimer le classeur. Utilisez `'commenter'` dans l’exemple pour autoriser aussi les commentaires tout en gardant les cellules en lecture seule. Un mode règle l’ensemble des permissions du classeur. Pour changer le rôle d’une personne, utilisez les [API de gestion des collaborateurs](#collaborators).

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
```

Pour modifier une seule permission, appelez `setPoint`. Par exemple, `await permission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)` désactive la modification du classeur. Si la valeur change, le SDK appelle `IAuthzIoService.update` avec le rôle `Editor` pour `true` ou `Owner` pour `false`. Pour conserver ce réglage à la réouverture du document, [connectez un service d’autorisation](#authorization-service).

### Autoriser certains collaborateurs à modifier une feuille

Remplacez `user1` et `user2` par les identifiants de collaborateurs du classeur. Créez une règle avec `protect()` avant de régler les permissions de la feuille individuellement. Appelez `worksheetPermission.unprotect()` pour retirer la protection de la feuille.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})
```

### Réserver la lecture et la modification de A1:B2 à certains collaborateurs

`allowedUsers` désigne les collaborateurs autorisés à modifier la plage. Avec `allowViewByOthers: false`, la lecture est aussi restreinte. Pour retirer uniquement cette protection, appelez `rule.remove()` sur la règle renvoyée.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
```

Appelez `rangePermission.listRules()` pour lister les règles qui recoupent la plage. `rangePermission.unprotect()` supprime toutes ces règles.

### Gérer les plages protégées

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('D1:D4')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('E1:E4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])

await createdRules[0].updateRanges([fWorksheet.getRange('D1:D5')])
```

### Déterminer pourquoi la saisie est bloquée en A1

L’exemple affiche les permissions nécessaires à la saisie d’une valeur simple. Toute valeur `false` bloque la saisie. `debugCellPermission(0, 0)` renvoie la règle qui couvre A1, ou `undefined` en l’absence de règle.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const worksheet = fWorkbook.getActiveSheet().getWorksheetPermission()
const rule = await worksheet.debugCellPermission(0, 0)

console.table({
  workbookEdit: fWorkbook.getWorkbookPermission().canEdit(),
  worksheetEdit: worksheet.canEdit(),
  setCellValue: worksheet.getPoint(univerAPI.Enum.WorksheetPermissionPoint.SetCellValue),
  rangeEdit: rule?.canEdit() ?? true,
})
```

## Liste des points d’autorisation [#point-list]

### Actions sur la feuille de calcul et leurs points d’autorisation

Chaque opération vérifie ses propres points d'autorisation. Un point de classeur s'applique avec les points de feuille de calcul et de plage de la même ligne, et un point de plage désigne le point d'édition de chaque plage protégée que l'opération croise. Masquer une ligne ou une colonne élargit la vérification à la ligne ou à la colonne entière.

| Action | Points d’autorisation requis |
| --- | --- |
| Saisir une valeur dans une cellule (hors formules) | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `RangeProtectionPermissionEditPoint` |
| Insérer une feuille de calcul | `WorkbookEditablePermission`, `WorkbookCreateSheetPermission` |
| Copier une feuille de calcul | `WorkbookEditablePermission`, `WorkbookCopySheetPermission` |
| Déplacer une feuille de calcul | `WorkbookEditablePermission`, `WorkbookMoveSheetPermission` |
| Renommer une feuille de calcul | `WorkbookEditablePermission`, `WorkbookRenameSheetPermission` |
| Masquer ou afficher une feuille de calcul | `WorkbookEditablePermission`, `WorkbookHideSheetPermission` |
| Supprimer une feuille de calcul | `WorkbookEditablePermission`, `WorkbookDeleteSheetPermission` |
| Masquer ou afficher des lignes ou des colonnes | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` ou `WorksheetSetColumnStylePermission`, et le point d’édition de chaque plage protégée croisée |
| Redimensionner des lignes ou des colonnes, ou les ajuster à leur contenu | `WorksheetSetRowStylePermission` ou `WorksheetSetColumnStylePermission` |
| Fusionner ou fractionner des cellules | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `WorksheetSetCellStylePermission`, et le point d’édition de chaque plage protégée croisée |
| Trier une plage | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSortPermission`, et le point d’édition de chaque plage protégée croisée |
| Figer ou libérer les volets | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| Afficher ou masquer le quadrillage, ou changer sa couleur | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| Ajouter, mettre à jour ou supprimer une note | `WorkbookEditablePermission`, `WorksheetEditPermission`, et le point d’édition de chaque plage protégée qui contient la cellule |
| Grouper ou dissocier des lignes ou des colonnes | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` ou `WorksheetSetColumnStylePermission`, et le point d’édition de chaque plage protégée croisée |
| Créer une règle de protection | `WorkbookCreateProtectPermission` |
| Gérer les collaborateurs d’une règle de protection | `WorksheetManageCollaboratorPermission` ou `RangeProtectionPermissionManageCollaPoint` |
| Supprimer une règle de protection | `WorksheetDeleteProtectionPermission` ou `RangeProtectionPermissionDeleteProtectionPoint` |

Lorsqu’un point requis vaut `false`, la commande est rejetée avant de modifier le document.

Les notes suivent les points d’édition des cellules. La lecture d’une note n’est pas soumise à autorisation.

### Autorisations des commentaires

La lecture d’un commentaire requiert la permission `View` du classeur et sa publication requiert `Comment`. Les deux opérations requièrent aussi `View` sur la feuille. Pour un commentaire associé à une cellule, chaque règle qui couvre cette cellule doit en autoriser la lecture. Les auteurs peuvent modifier ou supprimer leurs propres commentaires.

## Stratégie d’ombrage des plages protégées [#permission-ui]

Utilisez `non-editable` pour distinguer les zones protégées que l'utilisateur actuel peut éditer de celles qu'il ne peut pas. Les zones modifiables ne reçoivent pas d'ombre, les zones dont l'édition est désactivée gardent leur ombre et les plages non visualisées restent masquées.

Le paramètre n'affecte que la façon dont la protection de la plage et de la feuille de travail est affichée. Il ne crée pas de règles de protection, ne modifie pas les permissions d'édition ou d'affichage, et n'ajoute pas d'ombres à des zones non protégées.

| Stratégie | Affichage |
| --- | --- |
| `true` / `'always'` | Afficher l’ombrage de toutes les zones protégées (par défaut). |
| `'non-editable'` | Masquer l’ombrage des zones protégées modifiables et le conserver sur les zones non modifiables. |
| `'non-viewable'` | Afficher l’ombrage uniquement sur les zones protégées non consultables. |
| `false` / `'none'` | Masquer tous les ombrages de protection ; les contrôles des droits restent actifs. |

## Mettre à jour l’interface des autorisations avec l’API Facade [#permission-ui-api]

### Stratégie d’ombrage des plages protégées [#protected-range-shadow-api]

Le Facade API ci-dessous modifie les cahiers de travail existants dans l'instance actuelle Univer. En mode plugin, importez d'abord `@univerjs/sheets-ui/facade` ; le préréglage de base de feuilles inclut déjà ce module.

```typescript
// Set to only show shadows for non-editable ranges
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// Get the current protected range shadow display strategy
console.log(univerAPI.getProtectedRangeShadowStrategy())

// Subscribe to changes in the protected range shadow strategy
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // Update UI or perform other actions
})

// Later, unsubscribe to clean up
subscription.unsubscribe()
```

### Gestion des collaborateurs [#collaborators]

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()

const collaborators = await workbookPermission.listCollaborators()
```

Utilisez `addCollaborator` pour ajouter une personne. `setCollaborators` remplace toute la liste. Incluez chaque collaborateur qui doit conserver son accès.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.addCollaborator(
```

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()

await workbookPermission.setCollaborators([
  {
    user: { userID: 'user1', name: 'John Doe', avatar: '' },
```

## Étendre les permissions dans un plugin

### Utilisation avancée

Pour vérifier les permissions à l'intérieur de votre propre plugin, travaillez directement avec les points de permission.

L'exemple ci-dessous utilise `WorkbookEditablePermission`. D'autres points d'autorisation suivent le même modèle.

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

[Liste des points d’autorisation](#point-list)

`SheetPermissionCheckController.permissionCheckByPoints(points)` vérifie une liste explicite de points d’autorisation et renvoie `false` lorsque l’un d’eux est désactivé. Utilisez-la lorsqu’une commande connaît déjà les points dont elle a besoin, par exemple les points d’une règle de protection spécifique.

### Étendre les points d’autorisation

Pour les points d'autorisation personnalisés, implémentez `IPermissionPoint` et enregistrez-le avec le service d'autorisation :

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // Default value
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // The id must be unique within `IPermissionService`.
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// How to use it elsewhere
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // This returns an RxJS observable that lets you listen for permission changes
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
```
