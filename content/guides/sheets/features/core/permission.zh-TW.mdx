用活頁簿模式控制整份試算表能否編輯或留言。要讓指定協作者填寫某張工作表或某個範圍，請為該範圍建立保護規則。多人協作時，伺服器也須分別檢查讀取、加入協作工作階段及修改文件的權限，詳見[身分與權限](/server/collaboration/identity-and-authorization)。

## 常用任務 [#permission-tasks]

### 將活頁簿設為唯讀或開放留言

`viewer` 模式允許檢視及列印。若要開放留言並讓儲存格維持唯讀，將下方參數改為 `'commenter'`。模式會一併設定活頁簿的各項權限。若要調整個別協作者的角色，請使用[協作者管理](#collaborators)的 API。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
```

只需變更一項權限時，可呼叫 `setPoint`。例如，`await permission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)` 會關閉活頁簿編輯權限。當權限值改變，SDK 會呼叫 `IAuthzIoService.update`。傳入 `true` 時送出的策略角色為 `Editor`，傳入 `false` 時為 `Owner`。若要在重新開啟文件後保留設定，請[接入權限服務](#authorization-service)。

### 允許指定協作者編輯工作表

將 `user1` 和 `user2` 換成這份活頁簿既有協作者的 ID。設定個別工作表權限前，先以 `protect()` 建立保護規則。若要解除整張工作表的保護，呼叫 `worksheetPermission.unprotect()`。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})
```

### 只允許指定協作者檢視及編輯 A1:B2

`allowedUsers` 指定可編輯該範圍的協作者。`allowViewByOthers: false` 也會限制其他人的檢視權限。若要單獨移除這條規則，對傳回的物件呼叫 `rule.remove()`。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
```

若要列出與該範圍相交的規則，可呼叫 `rangePermission.listRules()`。`rangePermission.unprotect()` 會移除所有相交的規則。

### 管理保護範圍

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('D1:D4')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('E1:E4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])

await createdRules[0].updateRanges([fWorksheet.getRange('D1:D5')])
```

### 排查為何無法在 A1 輸入資料

下例列出輸入一般儲存格值所需的權限。任一項為 `false` 就無法輸入。`debugCellPermission(0, 0)` 會傳回涵蓋 A1 的保護規則，沒有符合的規則時傳回 `undefined`。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const worksheet = fWorkbook.getActiveSheet().getWorksheetPermission()
const rule = await worksheet.debugCellPermission(0, 0)

console.table({
  workbookEdit: fWorkbook.getWorkbookPermission().canEdit(),
  worksheetEdit: worksheet.canEdit(),
  setCellValue: worksheet.getPoint(univerAPI.Enum.WorksheetPermissionPoint.SetCellValue),
  rangeEdit: rule?.canEdit() ?? true,
})
```

## 權限點位列表 [#point-list]

### 工作表操作及其權限點位

每個操作都會檢查各自的一組權限點位。工作簿點位需要與同一行的 worksheet、range 點位同時滿足。區域點位指操作所涉及之每個保護規則的編輯點位。隱藏行或列時，檢查範圍會擴展到整行或整列。

| 操作 | 需要的權限點位 |
| --- | --- |
| 寫入儲存格值（不含公式） | `WorkbookEditablePermission`、`WorksheetEditPermission`、`WorksheetSetCellValuePermission`、`RangeProtectionPermissionEditPoint` |
| 插入工作表 | `WorkbookEditablePermission`、`WorkbookCreateSheetPermission` |
| 複製工作表 | `WorkbookEditablePermission`、`WorkbookCopySheetPermission` |
| 移動工作表 | `WorkbookEditablePermission`、`WorkbookMoveSheetPermission` |
| 重新命名工作表 | `WorkbookEditablePermission`、`WorkbookRenameSheetPermission` |
| 隱藏或顯示工作表 | `WorkbookEditablePermission`、`WorkbookHideSheetPermission` |
| 刪除工作表 | `WorkbookEditablePermission`、`WorkbookDeleteSheetPermission` |
| 隱藏或顯示行或列 | `WorkbookEditablePermission`、`WorksheetEditPermission`、`WorksheetSetRowStylePermission` 或 `WorksheetSetColumnStylePermission`，以及每個相交保護規則的編輯點位 |
| 調整行高或列寬，或依內容自動調整 | `WorksheetSetRowStylePermission` 或 `WorksheetSetColumnStylePermission` |
| 合併或取消合併單元格 | `WorkbookEditablePermission`、`WorksheetEditPermission`、`WorksheetSetCellValuePermission`、`WorksheetSetCellStylePermission`，以及每個相交保護規則的編輯點位 |
| 對區域排序 | `WorkbookEditablePermission`、`WorksheetEditPermission`、`WorksheetSortPermission`，以及每個相交保護規則的編輯點位 |
| 凍結或取消凍結窗格 | `WorkbookEditablePermission`、`WorksheetEditPermission` |
| 顯示或隱藏網格線，或修改網格線顏色 | `WorkbookEditablePermission`、`WorksheetEditPermission` |
| 新增、更新或刪除批註 | `WorkbookEditablePermission`、`WorksheetEditPermission`，以及批註所在儲存格相交的每個保護規則的編輯點位 |
| 群組或取消群組列或欄 | `WorkbookEditablePermission`、`WorksheetEditPermission`、`WorksheetSetRowStylePermission` 或 `WorksheetSetColumnStylePermission`，以及每個相交保護規則的編輯點位 |
| 建立保護規則 | `WorkbookCreateProtectPermission` |
| 管理保護規則的協作者 | `WorksheetManageCollaboratorPermission` 或 `RangeProtectionPermissionManageCollaPoint` |
| 刪除保護規則 | `WorksheetDeleteProtectionPermission` 或 `RangeProtectionPermissionDeleteProtectionPoint` |

任一必需點位為 `false` 時，命令會在變更內容之前被拒絕，文件不會改變。

批註遵循儲存格的編輯點位，讀取批註不檢查權限。

### 評論權限

讀取試算表留言需要活頁簿的 `View`，發表留言需要活頁簿的 `Comment`。兩者都需要工作表的 `View`。留言附在儲存格上時，也會檢查涵蓋該儲存格的保護規則是否允許檢視。作者可以修改或刪除自己的留言。

## 權限保護範圍陰影策略 [#permission-ui]

如需區分當前使用者可以編輯和不能編輯的保護區域，使用 `non-editable`。可編輯的區域不顯示陰影，編輯被禁用的區域保留陰影，不可檢視的區域繼續遮罩。

該設定隻影響範圍保護和工作表保護的顯示方式：它不會建立保護規則，不會修改編輯、檢視權限，也不會為未受保護的區域新增陰影。請先按上文配置好保護規則和當前使用者的權限。

| 策略 | 顯示效果 |
| --- | --- |
| `true` / `'always'` | 顯示所有保護區域的陰影（預設）。 |
| `'non-editable'` | 隱藏可編輯保護區域的陰影，保留不可編輯區域的陰影。 |
| `'non-viewable'` | 僅顯示不可檢視保護區域的陰影。 |
| `false` / `'none'` | 隱藏全部保護陰影，權限檢查仍然生效。 |

## 用 Facade API 更新權限介面 [#permission-ui-api]

### 權限保護範圍陰影策略 [#protected-range-shadow-api]

下面的 Facade API 修改的是當前 Univer 例項中已有工作簿的顯示策略。外掛模式下需要先匯入 `@univerjs/sheets-ui/facade`；Sheets Core 預設已經包含該模組。

```typescript
// 設定只顯示不可編輯範圍的陰影
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// 獲取當前的權限保護範圍陰影顯示策略
console.log(univerAPI.getProtectedRangeShadowStrategy())

// 監聽權限保護範圍陰影顯示策略的變化
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // 更新 UI 或執行其他操作
})

// 稍後，取消訂閱以進行清理
subscription.unsubscribe()
```

## 權限服務整合 [#permission-integration]

### 第三方權限服務接入(進階用法) [#authorization-service]

在建立活頁簿前註冊 [`IAuthzIoService`](https://github.com/dream-num/univer/blob/v1.6.0/packages/core/src/services/authz-io/type.ts) 的實作。服務須儲存保護規則與協作者變更，依目前使用者身分傳回權限，並將請求錯誤傳回給呼叫端。

```typescript
import { IAuthzIoService, Univer } from '@univerjs/core'
import { YourAuthzService } from './authorization-service'

const univer = new Univer({
  override: [[IAuthzIoService, { useClass: YourAuthzService }]],
})
```

### 協作者管理 [#collaborators]

- 獲取協作者列表

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

const collaborators = await workbookPermission.listCollaborators()
console.log(collaborators)
```

- 新增協作者

`addCollaborator` 會新增一位協作者。`setCollaborators` 會取代完整名單，呼叫時請包含所有仍須保留的協作者。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.addCollaborator(
  { userID: 'user1', name: 'John Doe', avatar: '' },
  univerAPI.Enum.UnitRole.Editor,
)
```

- 取代協作者名單

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.setCollaborators([
  {
    user: { userID: 'user1', name: 'John Doe', avatar: '' },
    role: univerAPI.Enum.UnitRole.Editor,
  },
  {
    user: { userID: 'user2', name: 'Jane Smith', avatar: '' },
    role: univerAPI.Enum.UnitRole.Reader,
  },
])
```

- 更新協作者角色

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.updateCollaborator(
  { userID: 'user1', name: 'John Doe Updated', avatar: '' },
  univerAPI.Enum.UnitRole.Reader,
)
```

- 刪除協作者

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.removeCollaborators(['user1', 'user2'])
```

## 在外掛中擴充權限

### 拓展使用

如需在自己的外掛中校驗權限，可直接操作權限點位。

下面以 `WorkbookEditablePermission` 為例，其他權限點位的用法相同：

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

[權限點位列表](#point-list)

`SheetPermissionCheckController.permissionCheckByPoints(points)` 會檢查明確指定的權限點位清單，只要其中任一項被停用就返回 `false`。當命令已經知道自己需要哪些點位時（例如某個保護規則的點位），可以使用它。

### 第三方外掛如何擴充權限點位

自定義權限點位需要實現 `IPermissionPoint` 並註冊到權限服務中：

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // 權限的初始值
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // 這裡自行拼湊一個 id，id 屬性需要保證在整個 IPermissionService 中是唯一的憑證。
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// 在其他地方如何使用
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // 這將獲得一個 Rx 物件，使得你能夠監聽當前權限的變化作出一些改變
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```
