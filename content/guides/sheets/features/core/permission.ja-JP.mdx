Univerのパーミッション制御は、ユーザーがワークブック、ワークシート、または範囲で行うことができるかを決定します。 ユーザーが必要な権限なしで操作を試みるとき、Univerは動作を停止し、不足している権限を報告します。 たとえば、コラビエーターが編集、ビュー、コピー、またはその中のコンテンツをフィルタリングできるかどうかを制御する。

<Callout type="warning">
本サービスは、保護ルールとコラベーターの変更を永続させ、現在のユーザーの権限を返し、リクエストの失敗を呼び出し元に戻す必要があります。空のリストを返すモックは、永続レイヤーではありません。コラボレーションでは、バックエンドは、読み取り、JOIN、およびミューテーション権限自体をチェックする必要があります。[アイデンティティと認可](/server/collaboration/identity-and-authorization)を参照してください。UIおよび非表示のシャドウの保護は、サーバーの許可を置き換えません。

[権限サービスの統合](#authorization-service)
</Callout>

## 基本概念

- スコープ: 権限は、ワークブック、ワークシート、範囲の3つのレベルで適用されます。
- パーミッションポイント:各機能には1つのパーミッションポイントがあり、その値を変更することで、その機能が有効または無効化されます。
- 保護規則: ワークシートまたは範囲は、その許可ポイントが設定できる前に保護ルールを必要とします。

<Callout type="info">
永続化しないローカル権限は権限ポイントで変更できます。永続化については次を参照してください： [権限サービスの統合](#authorization-service)。

共同編集では、許可ポイントを更新して、サーバーの状態を更新します。
  - false：その権限ポイントには少なくとも `owner` ロールが必要
  - true：その権限ポイントには少なくとも `reader` ロールが必要
</Callout>

## 基本例

`allowedUsers`の例を使用する前に、`user1`と`user2`を実際のコラボレーターIDで置き換えてください。

以下の例では、ワークブック、ワークシート、レンジの各3つのレベルの許可を設定する通常の方法を示します。

### ワークブック権限コード例

[Facade API](/guides/sheets/getting-started/facade)から直接ワークブックレベルの権限を設定します。

以下の例では、ワークブック全体で編集を無効にします。別の機能を制御するには、その設定を一致させる権限ポイントに置き換えてください。[ワークブック許可ポイントリスト](#workbook-point)を参照してください。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// ワークブックを編集不可に設定
await workbookPermission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)
```

ワークブックの許可ポイントは、保護ルールを最初に作成することなく、直接設定できます。

### ワークシート権限コード例

ワークシートと範囲のパーミッションは、Facade API またはコマンドを介して設定できます。この例では、ワークシートの編集権限を設定します。別の機能を制御するには、権限ポイントを一致するものに置き換えてください。[ワークシートのパーミッションポイントリスト](#worksheet-point)を参照してください。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// ワークシート保護を作成し、指定したユーザーのみ編集可能に設定
const permissionId = await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})

// 権限ポイントを設定する必要がある場合は、まずワークシート保護を作成する必要があります
await worksheetPermission.setPoint(univerAPI.Enum.WorksheetPermissionPoint.Edit, false)
```

#### ワークシート権限の削除

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// ワークシート保護を削除します
await worksheetPermission.unprotect()
```

### カスタム範囲権限コード例

範囲の権限は、API またはコマンドを介して同じ2つの方法で設定できます。以下の例では、範囲の編集権限を使用します。その他の範囲の機能には、異なる権限ポイントが必要です。詳細は [許可ポイントの一覧 - 範囲](#range-point) を参照してください。

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// 指定したユーザーのみ編集可能、他のユーザーは閲覧不可
const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
console.log(rule)

// 権限ポイントを設定する必要がある場合は、まず範囲保護を作成する必要があります
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.Edit, false)
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.View, true)
```

#### 範囲保護権限の削除

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// スコープ内のすべての保護ルールを削除
await rangePermission.unprotect()

// または、指定されたルールを削除
const rules = await rangePermission.listRules()
if (rules.length > 0) {
  await rules[0].remove()
}
```

## よく使う操作 [#permission-tasks]

### ブックを読み取り専用にする

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
console.log(permission.getSnapshot())
```

### 保護範囲を管理する

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('A1:B2')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('C3:D4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])
console.log(createdRules)

const rules = await permission.listRangeProtectionRules()
const firstRule = rules[0]
if (firstRule) {
  await firstRule.updateRanges([fWorksheet.getRange('A1:B3')])
}
```

### セルの権限を調べる

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getActiveSheet().getWorksheetPermission()
console.log(permission.debugCellPermission(0, 0))
```

## 権限保護範囲シャドウ戦略 [#permission-ui]

`non-editable` を使用して、保護された領域を区別するために、現在のユーザーはそれらから編集することができます。 編集可能な領域は影を受け取り、無効に編集された領域は影を保持し、非閲覧可能な範囲はマスクされたままです。

設定は、範囲とワークシートの保護が表示される方法だけに影響します。 保護ルールを作成せず、編集やビュー権限を変更せず、保護されていない領域に影を追加しません。 上記のように、保護ルールと現在のユーザーの許可を設定します。

| 戦略 | 表示動作 |
| --- | --- |
| `true` / `'always'` | すべての保護領域にシャドウを表示します（デフォルト）。 |
| `'non-editable'` | 編集可能な保護領域のシャドウを非表示にし、編集不可の領域では維持します。 |
| `'non-viewable'` | 閲覧できない保護領域にのみシャドウを表示します。 |
| `false` / `'none'` | すべての保護シャドウを非表示にします。権限チェックは引き続き有効です。 |

## Facade API で権限 UI を更新する [#permission-ui-api]

### 権限保護範囲シャドウ戦略 [#protected-range-shadow-api]

Facade API は、現在の Univerインスタンスの既存のワークブックを変更します。プラグインモードでは、`@univerjs/sheets-ui/facade`を最初にインポートします。シートコアプリセットには、そのモジュールが含まれています。

```typescript
// 編集不可範囲の影のみ表示に設定
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// 現在の保護範囲影表示戦略を取得
console.log(univerAPI.getProtectedRangeShadowStrategy())

// 保護範囲影表示戦略の変更を監視
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // UIの更新や他のアクションを実行
})

// 後で購読解除
subscription.unsubscribe()
```

## 権限サービスの統合 [#permission-integration]

### 拡張利用

自分のプラグイン内のパーミッションを確認するには、パーミッションポイントを直接使用してください。

以下の例では、`WorkbookEditablePermission` を使用します。その他の許可ポイントは同じパターンに従います。

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

[権限ポイントビット一覧](#point-list)

### 権限ポイントの拡張方法

カスタムのパーミッションポイントのために、`IPermissionPoint`を実装し、許可サービスに登録します。

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // 任意のタイプ
  subType = UnitAction.View // 任意のサブタイプ
  status = PermissionStatus.INIT
  value = true // 初期値
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // id は IPermissionService 全体で一意である必要がある
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// 他所での利用例
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // これは Rx オブジェクトを取得し、権限変更を監視したりリストを更新したりできる
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```

### サードパーティ認可サービスの統合（高度な利用） [#authorization-service]

アプリケーションで[IAuthzIoサービス](https://github.com/dream-num/univer/blob/dev/packages/core/src/services/authz-io/type.ts)を実装し、その許可、役割、および協力者メソッドをバックエンドに接続します。この例では、`./authorization-service`が実装を`YourAuthzService`としてエクスポートします。任意のワークブックを作成する前に登録し、他の初期化オプションとプラグイン登録を維持します。

```typescript
import { IAuthzIoService, Univer } from '@univerjs/core'
import { YourAuthzService } from './authorization-service'

const univer = new Univer({
  override: [[IAuthzIoService, { useClass: YourAuthzService }]],
})
```

お使いのauthzサービスは、保護ルールとコラベーターの変更を持続させ、現在のユーザーの許可を返し、表面要求の失敗を返さなければなりません。空のリストが何も主張しないままを返すモック。コラボレーションでは、バックエンドは引き続き、読み取り、JOIN、およびミューテーションの権限自体をチェックする必要があります。[アイデンティティと認可](/server/collaboration/identity-and-authorization)を参照してください。UI保護と隠しシャドウは、サーバーの認可の代替ではありません。

### 共同編集者管理

<Callout>
  Collaborator管理は、アプリケーションとその権限サービスに属しています。独自のユーザーとACLモデルを接続し、サーバー上での読み込み、JOIN、および編集ポリシーを実行します。[アイデンティティと権限](/server/collaboration/identity-and-authorization)を参照してください。以下のフロントエンドAPIは、マッチング権限サービス実装が必要です。サーバーの認可を設定していません。
</Callout>

- コラボレーターリストを取得する

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

const collaborators = await workbookPermission.listCollaborators()
console.log(collaborators)
```

- 共同編集者の追加

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// 複数の共同編集者を一度に追加
await workbookPermission.setCollaborators([
  {
    user: { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
    role: univerAPI.Enum.UnitRole.Editor,
  },
  {
    user: { userID: 'user2', name: 'Jane Smith', avatar: '' },
    role: univerAPI.Enum.UnitRole.Reader,
  },
])

// 単一の共同編集者を追加
await workbookPermission.addCollaborator(
  { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Editor,
)
```

- 共同作業者の役割を更新する

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.updateCollaborator(
  { userID: 'user1', name: 'John Doe Updated', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Reader,
)
```

- 共同編集者の削除

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// 複数の共同編集者を一度に削除
await workbookPermission.removeCollaborators(['user1', 'user2'])

// 単一の共同編集者を削除
await workbookPermission.removeCollaborator('user1')
```
