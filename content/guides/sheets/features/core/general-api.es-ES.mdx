Las API de Facade disponibles en Univer dependen del tipo de documento. Esta página cubre las API generales, que se comportan de la misma manera en cada tipo de documento .

## Importación

```typescript
import { FUniver } from '@univerjs/core/facade'

const univerAPI = FUniver.newAPI(univer)
```

## Conceptos

### Comandos

La mayoría de las operaciones en Univer están registradas con el sistema de comandos y se ejecutan a través de él. Debido a que cada operación sigue el mismo camino, Univer puede soportar deshacer, redo y colaboración.

<Callout>Para la racionalidad del diseño, vea [Sistema de comando Univer](/blog/univer#command-system).</Callout>

### Comandos

Casi todas las operaciones en Univer se registran con el sistema de comandos y se activan a través de él. Centralizar todas las operaciones de un solo lugar es lo que hace que las características como deshacer, redo y colaboración sean prácticas.

<Callout>
  Un comando se puede entender como un "evento" único dentro de Univer. Para los detalles del diseño, vea [sistema de comandos](/blog/univer#command-system) .
</Callout>

### Escuchar comandos

Univer ofrece dos puntos en los que escuchar un comando: antes de ejecutar y después de ejecutar.

- `Event.BeforeCommandExecute` ejecuta lógica personalizada antes de ejecutar el comando.
- `Event.CommandExecuted` ejecuta lógica personalizada después de que el comando ejecuta.

#### Escuchar comandos antes de la ejecución

Pase `Event.BeforeCommandExecute` a `FUniver.addEvent` para registrar un oyente de preprocesamiento. El código del oyente se ejecuta antes de ejecutar el comando.

```typescript
const univerAPI = FUniver.newAPI(univer)

univerAPI.addEvent(univerAPI.Event.BeforeCommandExecute, ({ id, type, params }) => {
  // Custom logic executed before the command is executed
})
```

Para evitar que el comando ejecute, establece `event.cancel` a `true` en el callback.

```typescript
const univerAPI = FUniver.newAPI(univer)

univerAPI.addEvent(univerAPI.Event.BeforeCommandExecute, (event) => {
  event.cancel = true
})
```

#### Escuchar comandos después de la ejecución

Pase `Event.CommandExecuted` a `FUniver.addEvent` para registrar un oyente post-procesador. Su código se ejecuta después de que el comando ha ejecutado.

```typescript
const univerAPI = FUniver.newAPI(univer)

univerAPI.addEvent(univerAPI.Event.CommandExecuted, ({ id, type, params }) => {
  // Custom logic executed after the command is executed
})
```

### Cancelar escucha

Registrar un oyente de comandos devuelve un objeto `IDisposable`. Llame a `IDisposable.dispose` para destruirlo.

Destruir a los oyentes que ya no están en uso. Liberarlos ayuda a mantener el programa estable.

```typescript
const univerAPI = FUniver.newAPI(univer)

// Register a listener
const disposable = univerAPI.addEvent(univerAPI.Event.BeforeCommandExecute, () => {
  // custom preprocessing logic before the command is executed
})

// Example: Destroy the listener after 1 second
setTimeout(() => {
  // Destroy the listener
  disposable.dispose()
}, 1000)
```

### Ejecutar comandos

Si ya conoce el ID de comando y sus parámetros, puede ejecutar el comando directamente con `FUniver.executeCommand`.

Por ejemplo, el siguiente código establece el valor de la celda A1 con el comando `sheet.command.set-range-values`:

```typescript
const univerAPI = FUniver.newAPI(univer)

// Execute the command
univerAPI.executeCommand('sheet.command.set-range-values', {
  value: { v: 'Hello, Univer!' },
  range: { startRow: 0, startColumn: 0, endRow: 0, endColumn: 0 },
})
```

## API de eventos

Univer envía eventos para cambios que ocurren dentro de una hoja de cálculo, por lo que una aplicación puede escucharlos y responder. Los eventos se encuentran en grupos como operaciones de portapapeles, cambios de selección, interacciones celulares, modificaciones de hoja, y algunos otros.

### Categorías de eventos

Lista completa de eventos: /reference/facade/events

1. **Eventos del portapapeles**
   - `BeforeClipboardChange`: incendios antes de que el contenido del portapapeles cambie; establece `params.cancel = true` para bloquear el cambio
   - `BeforeClipboardPaste`: se pegan fuegos antes de que el contenido; establece `params.cancel = true` para bloquear la pasta
   - `ClipboardChanged`: incendios después de que el contenido del portapapeles cambie, con el nuevo contenido
   - `ClipboardPasted`: fuegos después de que el contenido se pega, con el contenido pegado

2. **Eventos de selección**
   - `SelectionChanged`: incendios cuando la selección cambia, con el nuevo rango de selección
   - `SelectionMoveStart`: incendios cuando la selección comienza a moverse, lo que permite efectos de selección personalizados
   - `SelectionMoveEnd`: incendios cuando la selección deja de moverse, con el rango final
   - `SelectionMoving`: incendios mientras la selección se mueve, que soporta actualizaciones de interfaz de usuario en vivo
   - `DragOver`: fuegos mientras el contenido se arrastra sobre las células
   - `Drop`: incendios cuando el contenido arrastrado se deja caer

3. **Eventos de celda**
   - `CellClicked`: fuegos cuando se hace clic en una celda, con su posición y contenido
   - `CellHover`: fuegos cuando el puntero se acuesta sobre una célula, que soporta el puntaje de herramientas
   - `CellPointerDown`: incendios cuando el puntero se presiona en una celda; se utiliza para iniciar una arrastre o una selección
   - `CellPointerUp`: incendios cuando el puntero es liberado en una celda; usado para terminar una operación
   - `CellPointerMove`: incendios cuando el puntero se mueve sobre las células

4. **Eventos de hoja**
   - `SheetValueChanged`: fuegos cuando los valores de la hoja cambian, con el rango cambiado y los nuevos valores
   - `SheetZoomChanged`: incendios cuando el nivel de zoom cambia, con la nueva relación de zoom
   - `SheetSkeletonChanged`: fuegos cuando la estructura de la hoja cambia, por ejemplo cuando se insertan o eliminan filas o columnas
   - `BeforeSheetEditStart`: incendios antes de que comience la edición de celdas; usados para controlar si se permite la edición
   - `SheetEditStarted`: incendios cuando comienza la edición de celdas; utilizado para el comportamiento de editor personalizado
   - `BeforeSheetEditEnd`: incendios antes de que finalice la edición celular; usados para validar el contenido
   - `SheetEditEnded`: incendios cuando finaliza la edición de celdas, con el valor editado
   - `SheetEditChanging`: incendios durante la edición de celdas; usados para validación en vivo o formatear
   - `Scroll`: fuegos cuando la hoja se desplaza, con la posición de desplazamiento
   - `CrosshairHighlightEnabledChanged`: fuegos cuando se activa el cruce de puntos de vista o se desactiva

5. **Eventos de encabezado**
   - `RowHeaderClick`: fuegos cuando se hace clic en un encabezado de fila
   - `RowHeaderHover`: fuegos cuando el puntero se acuesta sobre un encabezado de fila
   - `ColumnHeaderClick`: fuegos cuando se hace clic en un encabezado de columna
   - `ColumnHeaderHover`: fuegos cuando el puntero se acuesta sobre un encabezado de columna

6. **Validación de datos Eventos**
   - `BeforeSheetDataValidationAdd`: incendios antes de añadir una regla de validación de datos
   - `SheetDataValidationChanged`: incendios cuando las reglas de validación de datos cambian
   - `SheetDataValidatorStatusChanged`: incendios cuando el estado de validación de datos cambia

7. **Eventos de comentarios**
   - `BeforeCommentAdd`: fuegos antes de añadir un comentario
   - `CommentAdded`: fuegos después de un comentario se añade
   - `BeforeCommentUpdate`: incendios antes de que se actualice un comentario
   - `CommentUpdated`: incendios después de que un comentario se actualice
   - `BeforeCommentDeleted`: fuegos antes de que se suprima un comentario
   - `CommentDeleted`: fuegos después de que se elimina un comentario

8. **Procesamiento de datos Eventos**
   - `SheetBeforeRangeSort`: incendios antes de que se ordene un rango
   - `SheetRangeSorted`: incendios después de una gama se clasifica
   - `SheetBeforeRangeFilter`: incendios antes de que se filtra un rango
   - `SheetRangeFiltered`: fuegos después de que se filtra una gama
   - `BeforePivotTableAdd`: fuegos antes de añadir una tabla de pivotes
   - `PivotTableAdded`: fuegos después de que se añada una tabla de pivotes

### Uso de eventos

Llame a `addEvent` en `univerAPI` para registrar un oyente. El patrón es el mismo para cada evento:

```typescript
univerAPI.addEvent(univerAPI.Event.EventName, (params) => {
  // Handle event parameters
})
```

#### Ejemplo: escuchar clics en celdas

```typescript
univerAPI.addEvent(univerAPI.Event.CellClicked, (params) => {
  const { worksheet, workbook, row, column } = params
  console.log(`Cell clicked at row ${row}, column ${column}`)
})
```

#### Ejemplo: monitorear operaciones del portapapeles

```typescript
univerAPI.addEvent(univerAPI.Event.BeforeClipboardPaste, (params) => {
  const { text, html } = params
  // If you want to cancel the clipboard paste
  params.cancel = true
})
```

#### Ejemplo: rastrear cambios en la selección

```typescript
univerAPI.addEvent(univerAPI.Event.SelectionChanged, (params) => {
  const { worksheet, workbook, selections } = params
  console.log('Selection changed:', selections)
})
```

### Cancelar escuchas de eventos

Los oyentes del evento devuelven un objeto `IDisposable`; utilízalo para eliminar al oyente cuando ya no sea necesario:

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.SheetValueChanged, (params) => {
  // Handle value changes
})

// Later, when you want to remove the listener:
disposable.dispose()
```

### Mejores prácticas

1. Disponer de los oyentes de eventos que ya no son necesarios; de lo contrario filtran la memoria.
2. Elija el evento que coincida con el caso de uso, y prefiera un evento específico sobre un evento general.
3. Manejadores de eventos ligeros, porque corren cada vez que el evento se dispara.
4. Para bloquear el comportamiento predeterminado, utilice `BeforeClipboardChange` u otro evento "antes".

## Portapapeles del sistema

`FUniver.copy()` y `FUniver.paste()` leen y escriben al portapapeles del sistema.

<Callout>
  Copiar y pegar dependen de la API nativa del navegador. Si el medio ambiente o sus permisos no los permiten, ni tampoco funciona. [Documentación MDN](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText).
</Callout>

El siguiente ejemplo copia y pega un rango de hojas.

```typescript
// Prevent failure due to loss of focus when executing copy and paste code in the console,
// this example listens for the cell click event and executes the copy and paste code.
univerAPI.addEvent(univerAPI.Event.CellClicked, async (params) => {
  const fWorkbook = univerAPI.getActiveWorkbook()
  const fWorksheet = fWorkbook.getActiveSheet()

  // Copy the range A1:B2 to the clipboard
  const fRange = fWorksheet.getRange('A1:B2')
  fRange.activate().setValues([
    [1, 2],
    [3, 4],
  ])
  await univerAPI.copy()

  // Paste the copied content to the range C1:D2
  const fRange2 = fWorksheet.getRange('C1')
  fRange2.activate()
  await univerAPI.paste()

  // Check the pasted content
  console.log(fWorksheet.getRange('C1:D2').getValues()) // [[1, 2], [3, 4]]
})
```

Los comandos de portapapeles también se pueden ejecutar a través del sistema de comandos:

```typescript
import { CopyCommand, PasteCommand } from '@univerjs/ui'

// Copy
univerAPI.executeCommand(CopyCommand.id)
// Paste
univerAPI.executeCommand(PasteCommand.id)
```

## WebSocket

El Facade API proporciona `createSocket`. Dada una URL, abre una conexión WebSocket. La conexión expone los eventos abiertos, de mensaje, de cierre y error; los mensajes se envían con el método `send`, y la conexión está cerrada con el método de `close` .

En una instalación de Presets, `univerAPI.createSocket(url)` se puede llamar directamente. En una instalación fragmentaria, instale el paquete [`@univerjs/network`](/reference/packages/plugins/univerjs/network) y registre `UniverNetworkPlugin`.

```typescript
// ... Omits other plugin imports
import { UniverNetworkPlugin } from '@univerjs/network'

// ... Omits other facade imports
import '@univerjs/network/facade'

// ... Omits other plugin registrations
univer.registerPlugin(UniverNetworkPlugin)
```

El siguiente es un ejemplo mínimo:

```typescript
// Replace the URL with the address of your own WebSocket service
const ws = univerAPI.createSocket('ws://47.100.177.253:8449/ws')

ws.open$.subscribe(() => {
  console.log('websocket opened')
  ws.send('hello')
})

ws.message$.subscribe((message) => {
  console.log('websocket message', message)
  const content = JSON.parse(message.data).content
  if (!content.includes('command')) {
    return
  }

  const commandInfo = JSON.parse(content)
  const { command, options } = commandInfo
  const { id, params } = command

  // Upon receiving collaborative data, it is locally saved
  univerAPI.executeCommand(id, params, options)
})

ws.close$.subscribe(() => {
  console.log('websocket closed')
})

ws.error$.subscribe((error) => {
  console.log('websocket error', error)
})

univerAPI.addEvent(univerAPI.Event.CommandExecuted, ({ id, type, params, options }) => {
  // Only synchronize local mutations
  if (
    type !== univerAPI.Enum.CommandType.MUTATION ||
    options?.fromCollab ||
    options?.onlyLocal ||
    id === 'doc.mutation.rich-text-editing'
  ) {
    return
  }

  const commandInfo = JSON.stringify({ command: { id, type, params }, options: { fromCollab: true } })
  ws.send(commandInfo)
})
```

Univer debe comenzar con un unitID; la colaboración no funciona sin uno.

## Registrar fórmula

Las fórmulas personalizadas se pueden registrar en la instancia Univer actual a través del Facade API.

El siguiente ejemplo llama a [`registerFunction`](https://docs.univer.ai/reference/facade/formula#registerfunction) una vez para registrar el algoritmo, el nombre y la descripción que una fórmula `CUSTOMSUM` requiere en el plugin de fórmula. La fórmula está disponible: escribiendo `=CUSTOMSUM` en cualquier célula en blanco muestra el impulso.

```typescript
// Registered formulas support lambda functions
const formulaEngine = univerAPI.getFormula()
formulaEngine.registerFunction(
  'CUSTOMSUM',
  (...variants) => {
    let sum = 0
    const last = variants[variants.length - 1]

    if (last.isLambda && last.isLambda()) {
      variants.pop()
      const variantsList = variants.map((variant) => (Array.isArray(variant) ? variant[0][0] : variant))
      sum += last.executeCustom(...variantsList).getValue()
    }

    for (const variant of variants) {
      sum += Number(variant) || 0
    }

    return sum
  },
  'Adds its arguments',
)

// Use the function in a cell
const fWorkbook = univerAPI.getActiveWorkbook()
const fWorksheet = fWorkbook.getActiveSheet()
const cellA1 = fWorksheet.getRange('A1')
cellA1.setValue(1)
const cellA2 = fWorksheet.getRange('A2')
cellA2.setValue(2)
const cellA3 = fWorksheet.getRange('A3')
cellA3.setValue({ f: '=CUSTOMSUM(A1,A2,LAMBDA(x,y,x*y))' })

// A3 will display: 5
formulaEngine.calculationEnd((functionsExecutedState) => {
  if (functionsExecutedState === 3) {
    console.log(cellA3.getValue()) // 5
  }
})
```

Llame a `dispose` para desregistrar la fórmula.

```typescript
const functionDisposable = formulaEngine.registerFunction({
  // calculate
})

// Unregister the function
functionDisposable.dispose()
```

Para proporcionar contenido y descripciones más completos internacionalizados, establezca los campos `locales` y `description` también:

Las opciones se describen a continuación.

- `func` contiene el algoritmo y el nombre de la fórmula. Su entrada es lo que el usuario entra al usar la fórmula, que puede ser un número, una cadena, un valor booleano, o un array.
- `description` establece la descripción de la fórmula personalizada.
- `locales` puede tener varios idiomas; las reglas de nombres se describen en [LocaleType](/reference/enums/locale-type). `functionList` pueden realizar traducciones para más de una fórmula. Para detalles de campo, consulte la sección [Cómo añadir fórmulas en Fórmula Motor](/blog/custom-formula#how-to-add-formulas-in-formula-engine) .

<Callout>
  Para reutilizar el algoritmo que el sistema de fórmulas ya proporciona y lo extiende, registre una fórmula personalizada a través de la configuración del plugin. Ver [Fórmula personalizada](/blog/custom-formula) para el avance.
</Callout>

console.log(univerAPI.Enum)
