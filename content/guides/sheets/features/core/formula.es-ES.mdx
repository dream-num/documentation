Las fórmulas son una parte central de Univer. Los usuarios escriben fórmulas en las células, y Univer calcula los valores. Las funciones soportadas coinciden con Excel y cubren matemáticas, lógicas, texto, fecha y otras categorías.

Un libro de trabajo que contiene muchas fórmulas puede ocupar el hilo principal durante largos períodos y ralentizar la página. Ejecutar cálculo de fórmulas en un Trabajador limita el impacto en la renderización y la interacción de los usuarios. Para detalles de la configuración, consulte [Web Workers](/guides/sheets/getting-started/worker).

`initialFormulaComputing` controla cómo se calculan las fórmulas cuando se carga un libro de trabajo. Si los resultados de las fórmulas almacenadas son estancados, `CalculationMode.FORCED` las recalcula. En modo preestablecido, la misma opción se anidada bajo `formula`.

Elija el modo de integración que utilice, y agregue estas opciones a la inicialización existente. Mantenga los otros plugins, locale, tema y configuración de contenedores sin cambios, y no registre el mismo plugin dos veces.

- `CalculationMode.FORCED` recalcula todas las fórmulas.
- `CalculationMode.WHEN_EMPTY` es el valor predeterminado y calcula solamente las células de fórmula que no tienen valor `v` almacenado.
- `CalculationMode.NO_CALCULATION` salta el cálculo durante la inicialización.

## Configuración de plugins [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | Establece cómo se calculan las fórmulas cuando se abre un libro de trabajo. |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

`UniverSheetsCorePreset`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |

| <ConfigKey depth={1}>initialFormulaComputing</ConfigKey> | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | Establece cómo se calculan las fórmulas cuando se abre un libro de trabajo. |

```typescript
const { univerAPI } = createUniver({
  presets: [
    UniverSheetsCorePreset({
      formula: {
        initialFormulaComputing: CalculationMode.FORCED,
      },
    }),
  ],
})
```

## Configurar vínculos entre libros [#cross-workbook-configuration]

Si una aplicación necesita asociar un nombre de fórmula con un ID de documento estable, puede utilizar las APIs de unión de referencia proporcionadas por `@univerjs-pro/engine-formula`. Esta es una extensión Pro. Configure a [licencia cliente](/server/license), reemplazar `UniverFormulaEnginePlugin` con `UniverProFormulaEnginePlugin` durante la inicialización, e importar el Pro Facade. Sólo un motor de fórmula puede ser registrado. Importar el Facade por sí mismo no registra el plugin.

## Referencias entre libros

Una fórmula de libro cruzado lee datos de otro libro de trabajo, por ejemplo para total las ventas en `Sales.xlsx` de `Report`. A diferencia de una referencia a otra hoja de trabajo en el mismo libro de trabajo , también identifica el libro de trabajo fuente .

### Sintaxis de referencia

| Caso | Ejemplo | Destino |
| --- | --- | --- |
| Otra hoja del mismo libro | `=SUM(Data!A1:A10)` | Hoja Data del libro actual |
| Rango de otro libro | `=SUM('[Sales.xlsx]Data'!A1:A10)` | Hoja Data de Sales.xlsx |
| Tabla de otro libro | `=SUM(Sales.xlsx!SalesTable[Amount])` | Columna Amount de la tabla SalesTable existente |

`Sales.xlsx` es un nombre de libro de trabajo, no una ruta de archivo o una URL de descarga. Escribir una fórmula no lee un archivo, descargar un libro de trabajo Excel, o conectarse a un editor en otra página del navegador. Para utilizar una referencia de tabla estructurada, crear el [cuadro](/guides/sheets/features/table) correspondiente primero.

### Referenciar libros cargados en la misma instancia

Con el motor de fórmulas núcleo, ambos libros de trabajo deben ser cargados en la misma instancia Univer y compartir el mismo entorno de cálculo de fórmulas. Ejecute este ejemplo después de la inicialización de hojas. En modo plugin, también importa las extensiones Facade descritas en esta página.

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false` carga el libro de trabajo de origen sin hacerlo el manual de trabajo actual. Continúe utilizando los mangos explícitos `source` y `report`, para que un cambio del libro de trabajo activo no envíe una fórmula al libro de trabajo incorrecto.

El nombre coincidente es caso-insensible. Un partido de nombre completo tiene precedencia; cuando no hay ninguno, el emparejamiento ignora las extensiones comunes Excel como `.xlsx` y `.xlsm`. Un nombre que no existe, o que coincide con varios libros de trabajo, devuelve `#REF!` . Los nombres de fuentes por lo tanto deben ser explícitos y únicos.

### Vincular una referencia a un ID de origen estable

Usa el motor Pro configurado arriba para vincular los nombres de libros de las fórmulas con identificadores de documento estables.

Este ejemplo reutiliza los libros anteriores en un entorno configurado con el motor Pro:

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId` identifica el libro de trabajo que contiene la fórmula. `unit.unitId` es el ID estable del libro de trabajo de origen, y `formulaQualifier` se llama el libro de datos de origen que utiliza en texto de fórmula. Las coordenadas de rango son cero, y la posición final es inclusiva.

`buildReference()` devuelve un fragmento de referencia sin `=` y persiste el enlace cruzado de libros de trabajo. No carga el libro de trabajo de origen o el cálculo de inicio. Los datos fuente deben venir de un libro de trabajo cargado en el entorno de cálculo, o de un proveedor de datos configurado.

Para el texto de fórmula generado a mano o por aplicación, atan la fuente antes de escribir la fórmula:

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

Repetir una unión idéntica en el mismo libro de trabajo es idempotent. Pase `qualifier` sin soportes o presupuestos, y no utilice un entero positivo como `1` o `2`. Excel se reserva tales números para ranuras de enlace externo, no para documentos de aplicación IDs. Los enlaces externos de texto importados Excel también requieren sus recursos de enlace;

### Actualizar, guardar y descargar de memoria

Después de cambiar los datos de la fuente a través de la Facade, calcular explícitamente y esperar hasta que los resultados se hayan aplicado antes de leer el objetivo. Un retorno de `setFormula()` o `setValue()` no significa que el cálculo asincrónico haya terminado.

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

Guardar el objetivo con `report.save()` para preservar la instantánea completa, incluyendo sus recursos de unión de referencia. Salvar sólo el texto de fórmula celular pierde la asignación entre los nombres públicos y los IDs de origen. Guardar y cargar datos de la fuente de trabajo por separado.

Después de que se descarga un libro de trabajo fuente, las referencias ordinarias a los libros de trabajo cargados ya no pueden leerlo. Las referencias externas Pro siguen calculando sólo cuando los proveedores de datos configurados y los caches disponibles suministran los datos requeridos. Un enlace no contiene datos de origen y no garantiza el cálculo fuera de línea. Un resultado previamente mostrado no prueba que los datos están actualizados.

Eliminar una unión Pro cuando ya no es necesario:

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

La eliminación de una unión no elimina o reescribe las fórmulas existentes. El siguiente cálculo resuelve sus nombres de nuevo. Si un libro de trabajo cargado todavía coincide con un nombre, la referencia puede seguir resolviendo; si nada coincide, devuelve `#REF!`. Para dejar de hacer referencia a la fuente, cambiar o limpiar las fórmulas de la célula también.

Vea el [FFormula APIs de conexión de referencia](/reference/facade/formula) para parámetros completos y valores de retorno.

## Referencias 3D

Una referencia 3D abarca hojas de trabajo consecutivas en un libro de trabajo. Se distingue de una referencia a otro libro de trabajo:

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

El rango incluye `Jan`, `Mar` y cada hoja entre ellos, en orden de libro de trabajo en lugar de orden alfabético. Las hojas de trabajo reordenantes pueden cambiar lo que el rango agrega, así que confirme el rango después de reordenar.

### Mostrar cuadro de diálogo de selección de rango

`@univerjs/sheets-formula-ui/facade` añade `univerAPI.showRangeSelectorDialog`. Una interfaz de usuario personalizada que necesita que los usuarios seleccionen uno o más rangos puede llamar a esta API, que abre el mismo selector que los paneles relacionados con la fórmula usan.

```typescript
const workbook = univerAPI.getActiveWorkbook()
const worksheet = workbook?.getActiveSheet()

if (workbook && worksheet) {
  await univerAPI.showRangeSelectorDialog({
    unitId: workbook.getId(),
    subUnitId: worksheet.getSheetId(),
    initialValue: [
      {
        unitId: workbook.getId(),
        sheetName: worksheet.getSheetName(),
        range: worksheet.getRange('A1:B2').getRange(),
      },
    ],
    maxRangeCount: 2,
    supportAcrossSheet: true,
    callback: (ranges, isCancel) => {
      console.log(ranges, isCancel)
    },
  })
}
```

### Establecer el modo de cálculo de la fórmula al inicializar los datos

```typescript
const formulaEngine = univerAPI.getFormula()
formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
```

Cuando se llama después del ciclo de vida `Starting`, esta API tiene efecto la próxima vez que se crea una hoja Univer.

Para hacerlo aplicable durante la inicialización actual de la hoja Univer, llámalo antes del ciclo de vida `Ready` como en el siguiente ejemplo:

```typescript
univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### Cálculo iterativo [#iterative-calculation]

El cálculo iterativo es un ajuste de nivel de libro de trabajo, almacenado en el campo `calculationSettings` de su instantánea. Se desactiva por defecto, por lo que las fórmulas circulares mantienen sus valores caché, o cero cuando no se cache ningún valor. Hágalo para modelos que contienen intencionalmente referencias circulares.

| Opción | Predeterminado | Comportamiento |
| --- | --- | --- |
| `iterativeCalculation` | `false` | Evaluar las referencias circulares iterativamente. |
| `maxIterations` | `100` | Un entero entre 1 y 32767. |
| `maxChange` | `0.001` | Un umbral de convergencia finita y positiva. La iteración se detiene cuando cada resultado numérico en el grupo circular cambia por no más que esta cantidad. |

Actualizar los tres ajustes juntos a través del libro de trabajo Facade. El comando soporta deshacer y redo así como la colaboración, y devuelve `false` si el libro de trabajo no está disponible o no puede ser editado. Los ajustes inválidos se normalizan a los valores predeterminados.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

`calculationSettings` también se puede suministrar al llamar `createWorkbook()`. Cada libro de trabajo mantiene su propia configuración. La cinta de Fórmula expone los mismos controles a través de Opciones de cálculo.

Los diagnósticos de referencia circular se pueden leer después de que se hayan aplicado los resultados de cálculo. `getCircularReferences()` no comienza el cálculo; sus resultados incluyen los ID de hoja de trabajo, coordenadas de fila cero y columna, IDs de grupo, recuentos de iteración y información de convergencia cuando está disponible.

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### Obtener resultado de ejecución de cadenas de fórmula

Ejecutar un lote de fórmulas de forma asincrónica y recibir los resultados de cálculo:

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // Full formula:
          '=SUM(A1:A10) + SQRT(D7)',

          // Decomposed sub-formulas (each one can be evaluated independently):
          'SUM(A1:A10)', // sub-formula 1
          'SQRT(D7)', // sub-formula 2
          'A1:A10', // range reference
          'D7', // single-cell reference
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## Semántica de los valores de fórmula [#formula-value-semantics]

`ISBLANK(A1)` comprueba si la célula referenciada contiene contenido, no sólo si su resultado mostrado está vacío. Una célula despejada, incluyendo una que conserva el formato, está en blanco; una fórmula que devuelve `""` No lo es. `ISBLANK("")` también `FALSE`. `UNIQUE` compara texto sin sensibilidad de caso y mantiene la primera ortografía. `PROPER` reconoce letras Unicode, incluyendo letras latinas acentuadas, griegas y cirílicas. `AVERAGE` agrega todo el conjunto devuelto por funciones tales como `FILTER`.

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
