Univer Sheets core features include a spreadsheet editor, formula engine, rendering engine, number formatting engine, design system, and UI component library. Together, they form a powerful platform for handling spreadsheets, supporting various formats and complex operations.

## Features

Univer Sheets core features include:

- **Spreadsheet Rendering**: Supports rendering of Univer Sheets, including cursor and selection drawing.
- **Cell Styling**: Allows styling of cells in the spreadsheet, including font, color, borders, and alignment.
- **Formula Calculation**: Supports adding and calculating formulas in the spreadsheet, covering nearly all Excel functions, including mathematical, statistical, text, and date functions.
- **Number Formatting**: Enables formatting of numbers in the spreadsheet, including currency, percentage, date formats, etc.
- **Gridlines and Frozen Panes**: Supports displaying gridlines and frozen panes, making it easier for users to view and edit large datasets.
- **Default Styles**: Allows setting default styles for the spreadsheet, including default font, size, color, etc.
- **Plugin System**: Supports a plugin system that allows for custom plugins, such as formula plugins, image plugins, chart plugins, etc. This is also one of the core architectural capabilities of Univer.

The `menu` configuration option can be used to simply set the display or hidden state of certain specific menu items:

```typescript
univer.registerPlugin(UniverUIPlugin, {
  menu: {
    'sheet.command.set-range-bold': {
      hidden: true,
    },
    'sheet.command.set-range-italic': {
      hidden: true,
      disabled: true,
    },
  },
})
```

Here, `'sheet.command.set-range-bold'` and `'sheet.command.set-range-italic'` are menu item IDs. You can refer to the [Menu Item ID List](#menu-item-id-list) below.

## Toolbar Layout and `RibbonType`

By configuring the `ribbonType` property in `IUniverSheetsCorePresetConfig` or `IUniverUIConfig`, you can set the layout of the toolbar.

`ribbonType` supports the following four modes:

- `classic`: Default classic mode, with groups on top and the toolbar laid out below, suitable for users accustomed to traditional layouts.
- `grid`: Grid mode, retaining tabs at the top and arranging each group's tools below in a two-row grid, suitable for desktop layouts that need more tools visible at once.
- `collapsed`: Compact mode, where groups and the toolbar are laid out in the same row, suitable for scenarios with limited vertical screen space.
- `simple`: Ungrouped mode, where all tools are placed in a flat list, suitable for users familiar with toolbar functions.

When a `grid` Ribbon no longer fits the container, complete groups move into **More**, where their controls use a compact layout. Enlarging the container restores the groups. This happens automatically with the available width; keep the existing `gridLayout` configuration for the main Ribbon. The overflow menu retains the same commands, disabled states, and permission checks.

## Menu order and grid layout [#menu-order-and-grid-layout]

In `menu`, use a Ribbon tab key such as `ribbon.insert`, a group key such as `ribbon.start.format`, or a menu item ID.

`order` sorts siblings in ascending order: tabs within the Ribbon, groups within a tab, and items within a group or submenu. It does not move a menu into another group. You can use `RibbonPosition` and the group enums exported by `@univerjs/ui` instead of string keys.

Choose your integration mode and merge these options into the existing initialization. Keep your other plugins, locale, theme, and container settings; do not register the same plugin twice.

```ts
import type { MenuConfig } from '@univerjs/ui'

const menu: MenuConfig = {
  'ribbon.insert': { order: -1 },
  'ribbon.start.format': { order: -1 },
  'sheet.command.set-range-font-family': {
    order: 0,
    gridLayout: { row: 1, column: 1, width: 160 },
  },
}
```

## Selection and dragging [#selection-interaction]

### Keyboard navigation at worksheet boundaries [#keyboard-navigation]

`allowArrowKeyWrapOnSheetBoundary` controls whether arrow keys can wrap to another row or column at a worksheet edge. It defaults to `true`; set it to `false` to stop at the edge. Enter/Tab cycling within selected ranges is unaffected. In preset mode, place it under `sheets`; in plugin mode, pass it directly to `UniverSheetsUIPlugin`.

Disable the selection outline animation when clicking between cells with `selectionAnimation: false`. The system reduced-motion preference takes precedence. Hide the fill handle with `enableFillHandle: false` while keeping fill commands and Facade APIs. Skip the drag overwrite prompt with `warnBeforeDragOverwrite: false`. Move validation and undo/redo still apply. All three default to `true`. Pass them under `sheets` in `UniverSheetsCorePreset`, or directly to `UniverSheetsUIPlugin`.

## Update menus with the Facade API [#menu-facade]

### Runtime updates

The public Facade merges the changes and refreshes the UI immediately. Unspecified properties retain their previous values or schema defaults, and overrides also apply to menus registered later. In plugin mode, import `@univerjs/ui/facade` first.

```ts
import '@univerjs/ui/facade'

univerAPI.updateMenuConfig({
  'sheet.command.set-range-bold': {
    order: 0,
    gridLayout: { row: 2, column: 2 },
  },
  'sheet.command.set-range-italic': {
    gridLayout: { row: 2, column: 1 },
  },
})
```

`gridLayout` only applies to `ribbonType: 'grid'`. Each group has two rows; `row` and `column` start at 1. Explicit coordinates control placement, so changing only `order` does not move an explicitly positioned button. Update both buttons when swapping positions to avoid overlap. Optional fields include `rowSpan`, `columnSpan`, `showLabel`, `width`, and `iconSize`; sizes are in pixels. See [`IRibbonGridLayout`](/reference/packages/plugins/univerjs/ui#iribbongridlayout) for constraints and defaults.

### Custom menu placement

`createMenu()` and `createSubmenu()` also accept `order` and `gridLayout`. For a submenu, these fields position its Ribbon trigger, not the popup contents. For example, add a button in the third column of the History group:

```ts
univerAPI
  .createMenu({
    id: 'custom-action',
    title: 'Custom action',
    action: () => console.log('Custom action clicked'),
    order: 4,
    gridLayout: { row: 1, column: 3, showLabel: true, width: 96 },
  })
  .appendTo('ribbon.start.history')
```
