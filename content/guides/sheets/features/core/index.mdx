The core of Univer Sheets consists of a spreadsheet editor and the components that the editor requires: the formula engine, rendering engine, number formatting engine, design system, and UI component library. Together these parts support a wide range of spreadsheet formats and the complex operations that a real workbook involves.

## Features

The core feature set covers:

- **Spreadsheet rendering**: Draws the sheet content, the cursor, and the selection.
- **Cell styling**: Sets fonts, colors, borders, and alignment on cells.
- **Formula calculation**: Adds and calculates formulas, with support for nearly every Excel function, including math, statistical, text, and date functions.
- **Number formatting**: Applies currency, percentage, date, and other number formats to values.
- **Gridlines and frozen panes**: Shows gridlines and frozen panes, which makes large datasets easier to read and edit.
- **Default styles**: Sets the default font, size, color, and other styles for a spreadsheet.
- **Plugin system**: Allows the addition of custom plugins, such as formula, image, and chart plugins. The plugin system is also one of Univer's core architectural capabilities.

Use `menu` to control the visibility of specific menu items:

```typescript
univer.registerPlugin(UniverUIPlugin, {
  menu: {
    'sheet.command.set-range-bold': {
      hidden: true,
    },
    'sheet.command.set-range-italic': {
      hidden: true,
      disabled: true,
    },
  },
})
```

Both keys, `'sheet.command.set-range-bold'` and `'sheet.command.set-range-italic'`, are menu item IDs; the [Menu Item ID List](#menu-item-id-list) below contains the full list.

import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'

univerAPI.createWorkbook({})

## Toolbar Layout and `RibbonType`

Set `ribbonType` in `IUniverSheetsCorePresetConfig` or `IUniverUIConfig` to choose the toolbar layout.

There are four modes:

- `classic`: The default layout. Groups occupy the upper row and the toolbar runs below them, matching what users of traditional layouts expect.
- `grid`: Keeps the tabs and arranges each group's tools below them in a two-row grid. It suits desktop layouts that need more tools visible at once.
- `collapsed`: Places the groups and the toolbar on the same row, which conserves vertical space when it is limited.
- `simple`: Removes grouping and places every tool in a single flat list, for users who already know what each button does.

When a `grid` Ribbon has insufficient width, entire groups move into **More** and their controls switch to a compact layout. They return when the container is widened. This follows the available width automatically, so keep the existing `gridLayout` for the main Ribbon. The overflow menu retains the same commands, disabled states, and permission checks.

## Menu order and grid layout [#menu-order-and-grid-layout]

A key in `menu` can be a Ribbon tab such as `ribbon.insert`, a group such as `ribbon.start.format`, or a menu item ID.

`order` sorts siblings from low to high: tabs within the Ribbon, groups within a tab, and items within a group or submenu. It does not move a menu item into another group. In place of string keys, you can use `RibbonPosition` and the group enums exported by `@univerjs/ui`.

Merge these options into the existing initialization for the current mode. Keep the other plugins, locale, theme, and container settings, and do not register the same plugin twice.

```ts
import type { MenuConfig } from '@univerjs/ui'

const menu: MenuConfig = {
  'ribbon.insert': { order: -1 },
  'ribbon.start.format': { order: -1 },
  'sheet.command.set-range-font-family': {
    order: 0,
    gridLayout: { row: 1, column: 1, width: 160 },
  },
}
```

## Selection and dragging [#selection-interaction]

### Keyboard navigation at worksheet boundaries [#keyboard-navigation]

`allowArrowKeyWrapOnSheetBoundary` determines whether arrow keys wrap to the next row or column at a worksheet edge. It defaults to `true`; set it to `false` to stop at the edge. Enter/Tab cycling inside a selected range is not affected. In preset mode, set it under `sheets`; in plugin mode, pass it directly to `UniverSheetsUIPlugin`.

`selectionAnimation: false` disables the selection outline animation when the selection moves between cells; the system reduced-motion preference takes precedence. `enableFillHandle: false` hides the fill handle while fill commands and Facade APIs remain available. `warnBeforeDragOverwrite: false` skips the confirmation prompt before a drag overwrites existing content; move validation and undo/redo still apply. All three options default to `true`. Pass them under `sheets` in `UniverSheetsCorePreset`, or directly to `UniverSheetsUIPlugin`.

## Update menus with the Facade API [#menu-facade]

### Runtime updates

The public Facade merges the changes and refreshes the UI immediately. Properties that are omitted keep their previous values or the schema defaults, and the overrides also apply to menus registered later. In plugin mode, import `@univerjs/ui/facade` first.

```ts
import '@univerjs/ui/facade'

univerAPI.updateMenuConfig({
  'sheet.command.set-range-bold': {
    order: 0,
    gridLayout: { row: 2, column: 2 },
  },
  'sheet.command.set-range-italic': {
    gridLayout: { row: 2, column: 1 },
  },
})
```

`gridLayout` only has an effect with `ribbonType: 'grid'`. Every group has two rows, and `row` and `column` start at 1. Coordinates are explicit, so changing only `order` does not move a button that was placed explicitly. When two buttons are swapped, both must be updated, or they overlap. The optional fields are `rowSpan`, `columnSpan`, `showLabel`, `width`, and `iconSize`, with sizes in pixels. [`IRibbonGridLayout`](/reference/packages/plugins/univerjs/ui#iribbongridlayout) lists the constraints and defaults.

### Custom menu placement

`createMenu()` and `createSubmenu()` also accept `order` and `gridLayout`. On a submenu, these fields position the Ribbon trigger rather than the contents of the popup. The following example adds a button in the third column of the History group:

```ts
univerAPI
  .createMenu({
    id: 'custom-action',
    title: 'Custom action',
    action: () => console.log('Custom action clicked'),
    order: 4,
    gridLayout: { row: 1, column: 3, showLabel: true, width: 96 },
  })
  .appendTo('ribbon.start.history')
```
