Режим книги определяет, можно ли редактировать ячейки и оставлять комментарии. Чтобы разрешить редактирование листа или диапазона только выбранным участникам, создайте для него правило защиты. При совместной работе сервер также должен проверять права на чтение, подключение к сеансу и изменение документа. См. [Идентификация и авторизация](/server/collaboration/identity-and-authorization).

## Типовые задачи [#permission-tasks]

### Открыть книгу только для чтения или разрешить комментарии

В режиме `viewer` книгу можно просматривать и печатать. Чтобы разрешить также комментарии и сохранить ячейки доступными только для чтения, передайте `'commenter'` в примере ниже. Режим задаёт сразу все разрешения книги. Для изменения роли одного пользователя используйте [API управления участниками](#collaborators).

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
```

Для изменения одного разрешения вызовите `setPoint`. Например, `await permission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)` отключает редактирование книги. При изменении значения SDK вызывает `IAuthzIoService.update`, передавая в политике роль `Editor` для `true` или `Owner` для `false`. Чтобы настройка сохранялась при повторном открытии документа, [подключите службу авторизации](#authorization-service).

### Разрешить редактировать лист выбранным участникам

Замените `user1` и `user2` идентификаторами участников этой книги. Прежде чем задавать отдельные разрешения листа, создайте правило защиты с помощью `protect()`. Для снятия защиты листа вызовите `worksheetPermission.unprotect()`.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})
```

### Ограничить просмотр и редактирование A1:B2 выбранными участниками

В `allowedUsers` укажите участников, которым разрешено редактировать диапазон. Параметр `allowViewByOthers: false` также ограничивает его просмотр. Чтобы снять только эту защиту, вызовите `rule.remove()` у полученного правила.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
```

Вызовите `rangePermission.listRules()`, чтобы получить список правил, пересекающих диапазон. Метод `rangePermission.unprotect()` удаляет все такие правила.

### Управлять защищёнными диапазонами

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('D1:D4')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('E1:E4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])

await createdRules[0].updateRanges([fWorksheet.getRange('D1:D5')])
```

### Выяснить, почему нельзя ввести значение в A1

Пример показывает разрешения, необходимые для ввода обычного значения. Если хотя бы одно равно `false`, ввод блокируется. Метод `debugCellPermission(0, 0)` возвращает правило защиты для A1 или `undefined`, если такого правила нет.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const worksheet = fWorkbook.getActiveSheet().getWorksheetPermission()
const rule = await worksheet.debugCellPermission(0, 0)

console.table({
  workbookEdit: fWorkbook.getWorkbookPermission().canEdit(),
  worksheetEdit: worksheet.canEdit(),
  setCellValue: worksheet.getPoint(univerAPI.Enum.WorksheetPermissionPoint.SetCellValue),
  rangeEdit: rule?.canEdit() ?? true,
})
```

## Список точек разрешений [#point-list]

### Действия с листом и их точки разрешений

Каждая операция проверяет собственный набор точек. Точка книги применяется вместе с точками листа и диапазона в той же строке, а точка диапазона означает точку редактирования каждого защищённого диапазона, который пересекает операция. При скрытии строки или столбца проверка расширяется на всю строку или столбец.

| Действие | Требуемые точки |
| --- | --- |
| Ввод значения в ячейку (кроме формул) | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `RangeProtectionPermissionEditPoint` |
| Вставка листа | `WorkbookEditablePermission`, `WorkbookCreateSheetPermission` |
| Копирование листа | `WorkbookEditablePermission`, `WorkbookCopySheetPermission` |
| Перемещение листа | `WorkbookEditablePermission`, `WorkbookMoveSheetPermission` |
| Переименование листа | `WorkbookEditablePermission`, `WorkbookRenameSheetPermission` |
| Скрытие или показ листа | `WorkbookEditablePermission`, `WorkbookHideSheetPermission` |
| Удаление листа | `WorkbookEditablePermission`, `WorkbookDeleteSheetPermission` |
| Скрытие или показ строк или столбцов | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` или `WorksheetSetColumnStylePermission`, а также точка редактирования каждого пересекаемого защищённого диапазона |
| Изменение размера строк или столбцов или подгонка по содержимому | `WorksheetSetRowStylePermission` или `WorksheetSetColumnStylePermission` |
| Объединение или разделение ячеек | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `WorksheetSetCellStylePermission`, а также точка редактирования каждого пересекаемого защищённого диапазона |
| Сортировка диапазона | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSortPermission`, а также точка редактирования каждого пересекаемого защищённого диапазона |
| Закрепить или снять закрепление областей | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| Показать или скрыть линии сетки, или изменить их цвет | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| Добавить, обновить или удалить примечание | `WorkbookEditablePermission`, `WorksheetEditPermission`, а также точка редактирования каждого защищённого диапазона, содержащего ячейку |
| Сгруппировать или разгруппировать строки или столбцы | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` или `WorksheetSetColumnStylePermission`, а также точка редактирования каждого пересекаемого защищённого диапазона |
| Создание правила защиты | `WorkbookCreateProtectPermission` |
| Управление участниками правила защиты | `WorksheetManageCollaboratorPermission` или `RangeProtectionPermissionManageCollaPoint` |
| Удаление правила защиты | `WorksheetDeleteProtectionPermission` или `RangeProtectionPermissionDeleteProtectionPoint` |

Когда требуемая точка равна `false`, команда отклоняется до изменения документа.

Примечания подчиняются точкам редактирования ячеек. Чтение примечания не проверяется.

### Разрешения на комментарии

Для чтения комментария нужно разрешение `View` книги, а для публикации нужно `Comment`. В обоих случаях требуется также разрешение `View` листа. Если комментарий привязан к ячейке, все применимые к ней правила защиты должны разрешать просмотр. Авторы могут изменять и удалять собственные комментарии.

## Стратегия затенения защищённого диапазона [#permission-ui]

Используйте `non-editable`, чтобы отличить защищенные области, которые текущий пользователь может редактировать, от тех, которые он не может. Редактируемые области не получают тени, области с отключенным редактированием сохраняют свою тень, а не просматриваемые диапазоны остаются замаскированными.

Настройка влияет только на то, как отображается дальность и защита рабочих листов. Она не создает правила защиты, не меняет правки или разрешения на просмотр и не добавляет тени в незащищенные области. Сначала настройте правила защиты и текущие разрешения пользователя, как описано выше.

| Стратегия | Отображение |
| --- | --- |
| `true` / `'always'` | Показывать затенение всех защищённых областей (по умолчанию). |
| `'non-editable'` | Скрывать затенение редактируемых защищённых областей и сохранять его для нередактируемых. |
| `'non-viewable'` | Показывать затенение только для защищённых областей, недоступных для просмотра. |
| `false` / `'none'` | Скрывать всё затенение защиты; проверки прав продолжают действовать. |

## Обновление интерфейса разрешений через Facade API [#permission-ui-api]

### Стратегия затенения защищённого диапазона [#protected-range-shadow-api]

Facade API ниже меняет существующие рабочие книги в текущем экземпляре Univer. В режиме плагина сначала импортируйте `@univerjs/sheets-ui/facade`; предустановленное ядро Sheets уже включает этот модуль.

```typescript
// Set to only show shadows for non-editable ranges
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// Get the current protected range shadow display strategy
console.log(univerAPI.getProtectedRangeShadowStrategy())

// Subscribe to changes in the protected range shadow strategy
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // Update UI or perform other actions
})

// Later, unsubscribe to clean up
subscription.unsubscribe()
```

## Интеграция сервиса авторизации [#permission-integration]

### Интеграция со сторонней службой авторизации (для опытных пользователей) [#authorization-service]

Зарегистрируйте реализацию [`IAuthzIoService`](https://github.com/dream-num/univer/blob/v1.6.0/packages/core/src/services/authz-io/type.ts) до создания книги. Служба должна сохранять правила защиты и изменения списка участников, возвращать права текущего пользователя и передавать ошибки запроса вызывающей стороне.

```typescript
import { IAuthzIoService, Univer } from '@univerjs/core'
import { YourAuthzService } from './authorization-service'

const univer = new Univer({
  override: [[IAuthzIoService, { useClass: YourAuthzService }]],
})
```

### Управление участниками [#collaborators]

- Получите список сотрудников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

const collaborators = await workbookPermission.listCollaborators()
console.log(collaborators)
```

- Добавление участников

Для добавления одного участника используйте `addCollaborator`. Метод `setCollaborators` заменяет весь список. Включите в него всех участников, которым нужно сохранить доступ.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.addCollaborator(
  { userID: 'user1', name: 'John Doe', avatar: '' },
  univerAPI.Enum.UnitRole.Editor,
)
```

## Расширение разрешений в плагине

### Расширенное использование

Чтобы проверить разрешения внутри собственного плагина, работайте с точками разрешения напрямую.

В приведенном ниже примере используется `WorkbookEditablePermission`. Другие точки разрешения следуют той же схеме.

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

[Список точек разрешений](#point-list)

`SheetPermissionCheckController.permissionCheckByPoints(points)` проверяет явный список точек разрешения и возвращает `false`, если любая из них отключена. Используйте его, когда команда уже знает необходимые точки, например точки конкретного правила защиты.

### Расширение точек разрешений

Для пользовательских точек разрешения, реализуйте `IPermissionPoint` и зарегистрируйте его в службе разрешений:

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // Default value
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // The id must be unique within `IPermissionService`.
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// How to use it elsewhere
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // This returns an RxJS observable that lets you listen for permission changes
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```
