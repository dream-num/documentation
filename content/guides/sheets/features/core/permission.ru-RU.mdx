Контроль разрешений в Univer определяет, что пользователь может делать на рабочей книге, листе или диапазоне. Когда пользователь пытается выполнить операцию без требуемого разрешения, Univer останавливает операцию и сообщает о недостающих разрешениях. Защита диапазона, например, контролирует, могут ли сотрудники редактировать, просматривать, копировать или фильтровать содержимое внутри него.

<Callout type="warning">
Ваша служба должна сохранять правила защиты и изменения сотрудника, возвращать текущие разрешения пользователя и передавать сбои запроса обратно абоненту. Имитация, которая возвращает пустой список, не является уровнем стойкости. В сотрудничестве бэкэнд также должен проверять сами разрешения на чтение, JOIN и мутации; см. [Идентификация и авторизация](/server/collaboration/identity-and-authorization). Защита в пользовательском интерфейсе и скрытые тени не заменяют авторизацию сервера.

[Интеграция сервиса авторизации](#authorization-service)
</Callout>

## Основные понятия

- Объем: Разрешения применяются на трех уровнях: рабочая тетрадь, рабочий лист и диапазон.
- Точки разрешения: каждая функция имеет одну точку разрешения, и изменение ее значения позволяет или отключает эту функцию.
- Правила защиты: Рабочий лист или диапазон требуют правила защиты до того, как могут быть установлены точки разрешения.

<Callout type="info">
Локальные права без сохранения изменяются через точки прав. Для сохранения см. [Интеграция сервиса авторизации](#authorization-service).

При совместном редактировании обновление точки разрешения также обновляет состояние сервера:
  - `false`: для точки разрешения требуется роль не ниже `owner`
  - `true`: для точки разрешения требуется роль не ниже `reader`
</Callout>

## Базовый пример

Перед использованием примеров `allowedUsers` замените `user1` и `user2` реальными идентификаторами сотрудников, возвращенными службой авторизации.

Приведенные ниже примеры показывают обычный способ установки разрешений на каждом из трех уровней: рабочая тетрадь, рабочий лист и диапазон.

### Пример разрешений для книги

Установите разрешения на уровне книги непосредственно через [Facade API](/guides/sheets/getting-started/facade).

Приведенный ниже пример отключает редактирование для всей книги. Для управления другой функцией замените точку разрешения на соответствующую; см. [Список точек разрешения на работу](#workbook-point):

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Set the workbook to be non-editable
await workbookPermission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)
```

Точки разрешения на работу могут быть установлены непосредственно, без создания правила защиты.

### Пример разрешений для листа

Рабочий лист и разрешения диапазона могут быть установлены через Facade API или через команды. Этот пример устанавливает разрешение редактирования рабочего листа. Чтобы управлять другой функцией, замените точку разрешения на соответствующую; см. [список точек разрешения рабочего листа](#worksheet-point):

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// Create worksheet protection, allow specified users to edit
const permissionId = await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})

// To set permission points, you must first protect the worksheet
await worksheetPermission.setPoint(univerAPI.Enum.WorksheetPermissionPoint.Edit, false)
```

#### Удаление разрешений листа

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// Remove worksheet protection
await worksheetPermission.unprotect()
```

### Пример пользовательских разрешений диапазона

Разрешения диапазона могут быть установлены одними и теми же двумя способами: через API или через команды. В приведенном ниже примере используется разрешение редактирования диапазона. Другие функции диапазона требуют другой точки разрешения; см. [Список точек разрешения - диапазон](#range-point) для деталей.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// Set range protection permission, allow specified users to edit but not allow others to view
const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
console.log(rule)

// To set permission points, you must first create a range protection rule.
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.Edit, false)
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.View, true)
```

#### Удаление разрешений защиты диапазона

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// delete all rules within the range
await rangePermission.unprotect()

// Or delete specific rules within the range
const rules = await rangePermission.listRules()
if (rules.length > 0) {
  await rules[0].remove()
}
```

## Типовые задачи [#permission-tasks]

### Перевести книгу в режим чтения

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
console.log(permission.getSnapshot())
```

### Управлять защищёнными диапазонами

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('A1:B2')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('C3:D4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])
console.log(createdRules)

const rules = await permission.listRangeProtectionRules()
const firstRule = rules[0]
if (firstRule) {
  await firstRule.updateRanges([fWorksheet.getRange('A1:B3')])
}
```

### Проверить права ячейки

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getActiveSheet().getWorksheetPermission()
console.log(permission.debugCellPermission(0, 0))
```

## Стратегия затенения защищённого диапазона [#permission-ui]

Используйте `non-editable`, чтобы отличить защищенные области, которые текущий пользователь может редактировать, от тех, которые он не может. Редактируемые области не получают тени, области с отключенным редактированием сохраняют свою тень, а не просматриваемые диапазоны остаются замаскированными.

Настройка влияет только на то, как отображается дальность и защита рабочих листов. Она не создает правила защиты, не меняет правки или разрешения на просмотр и не добавляет тени в незащищенные области. Сначала настройте правила защиты и текущие разрешения пользователя, как описано выше.

| Стратегия | Отображение |
| --- | --- |
| `true` / `'always'` | Показывать затенение всех защищённых областей (по умолчанию). |
| `'non-editable'` | Скрывать затенение редактируемых защищённых областей и сохранять его для нередактируемых. |
| `'non-viewable'` | Показывать затенение только для защищённых областей, недоступных для просмотра. |
| `false` / `'none'` | Скрывать всё затенение защиты; проверки прав продолжают действовать. |

## Обновление интерфейса разрешений через Facade API [#permission-ui-api]

### Стратегия затенения защищённого диапазона [#protected-range-shadow-api]

Facade API ниже меняет существующие рабочие книги в текущем экземпляре Univer. В режиме плагина сначала импортируйте `@univerjs/sheets-ui/facade`; предустановленное ядро Sheets уже включает этот модуль.

```typescript
// Set to only show shadows for non-editable ranges
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// Get the current protected range shadow display strategy
console.log(univerAPI.getProtectedRangeShadowStrategy())

// Subscribe to changes in the protected range shadow strategy
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // Update UI or perform other actions
})

// Later, unsubscribe to clean up
subscription.unsubscribe()
```

## Интеграция сервиса авторизации [#permission-integration]

### Расширенное использование

Чтобы проверить разрешения внутри собственного плагина, работайте с точками разрешения напрямую.

В приведенном ниже примере используется `WorkbookEditablePermission`. Другие точки разрешения следуют той же схеме.

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

### Расширение точек разрешений

Для пользовательских точек разрешения, реализуйте `IPermissionPoint` и зарегистрируйте его в службе разрешений:

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // Default value
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // The id must be unique within `IPermissionService`.
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// How to use it elsewhere
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // This returns an RxJS observable that lets you listen for permission changes
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```

### Интеграция со сторонней службой авторизации (для опытных пользователей) [#authorization-service]

Внедряйте [IAuthzIoService](https://github.com/dream-num/univer/blob/dev/packages/core/src/services/authz-io/type.ts) в ваше приложение и подключите его методы разрешения, роли и соавтора к вашему бэкэнду. Пример предполагает, что `./authorization-service` экспортирует реализацию как `YourAuthzService`. Зарегистрируйте его перед созданием любых рабочих книг и сохраните другие варианты инициализации и регистрации плагинов.

```typescript
import { IAuthzIoService, Univer } from '@univerjs/core'
import { YourAuthzService } from './authorization-service'

const univer = new Univer({
  override: [[IAuthzIoService, { useClass: YourAuthzService }]],
})
```

Ваша служба authz должна сохранять правила защиты и изменения сотрудника, возвращать текущие разрешения пользователя и сбои в запросе поверхности. Имитация, которая возвращает пустые списки, ничего не сохраняется. В сотрудничестве бэкэнд должен все еще проверять сами разрешения на чтение, JOIN и мутации; см. [Идентификация и авторизация](/server/collaboration/identity-and-authorization). Защита пользовательского интерфейса и скрытые тени не заменяют авторизацию сервера.

### Управление участниками

<Callout>
  Управление коллаборационистами относится к вашему приложению и его службе разрешений. Подключите своего пользователя и модель ACL и примените политики чтения, соединения и редактирования на сервере; см. [удостоверение личности и разрешение](/server/collaboration/identity-and-authorization). Приведенные ниже интерфейсные API требуют соответствующей реализации службы разрешений; они не настраивают авторизацию сервера.
</Callout>

- Получите список сотрудников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

const collaborators = await workbookPermission.listCollaborators()
console.log(collaborators)
```

- Добавление участников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Add multiple collaborators at once
await workbookPermission.setCollaborators([
  {
    user: { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
    role: univerAPI.Enum.UnitRole.Editor,
  },
  {
    user: { userID: 'user2', name: 'Jane Smith', avatar: '' },
    role: univerAPI.Enum.UnitRole.Reader,
  },
])

// Add a single collaborator
await workbookPermission.addCollaborator(
  { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Editor,
)
```

- Обновление ролей сотрудников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.updateCollaborator(
  { userID: 'user1', name: 'John Doe Updated', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Reader,
)
```

- Удаление участников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Remove multiple collaborators
await workbookPermission.removeCollaborators(['user1', 'user2'])

// Remove a single collaborator
await workbookPermission.removeCollaborator('user1')
```
