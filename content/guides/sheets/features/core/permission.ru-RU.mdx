Univer позволяет управлять разрешениями и ограничивать действия пользователей с книгами, листами и диапазонами. Если пользователь пытается выполнить действие без необходимого разрешения, операция прерывается, а пользователь получает уведомление. Например, можно защитить диапазон и определить, смогут ли участники редактировать, просматривать, копировать или фильтровать данные в нём.

<Callout type="warning">
Сервис должен сохранять правила защиты и изменения участников, возвращать права текущего пользователя и передавать ошибки запросов вызывающему коду. Пустые списки в заглушке не обеспечивают сохранение данных. При совместной работе сервер отдельно проверяет чтение, JOIN и изменение; см. [Идентификация и авторизация](/server/collaboration/identity-and-authorization). Защита интерфейса и скрытие затенения не заменяют серверную авторизацию.

[Интеграция сервиса авторизации](#authorization-service)
</Callout>

## Основные понятия

- Область действия: разрешения применяются на трёх уровнях — книга, лист и диапазон.
- Точки разрешений: каждой функции соответствует точка разрешения. Изменяя её, можно управлять доступностью функции.
- Правила защиты: прежде чем настраивать точки разрешений для листов и диапазонов, необходимо создать правило защиты.

<Callout type="info">
Локальные права без сохранения изменяются через точки прав. Для сохранения см. [Интеграция сервиса авторизации](#authorization-service)

При совместном редактировании обновление точки разрешения синхронизирует состояние сервера:
  - `false`: для точки разрешения требуется роль не ниже `owner`
  - `true`: для точки разрешения требуется роль не ниже `reader`
</Callout>

## Базовый пример

Перед использованием примеров `allowedUsers` замените `user1` и `user2` реальными идентификаторами участников, возвращаемыми вашим сервисом авторизации.

Ниже показаны наиболее распространённые способы настройки разрешений на трёх уровнях: книги, листа и диапазона.

### Пример разрешений для книги

Разрешения на уровне книги можно настроить напрямую через [Facade API](/guides/sheets/getting-started/facade).

В следующем примере редактирование отключается для всей книги. Для управления другими функциями замените точку разрешения на соответствующую (см. [список точек разрешений книги](#workbook-point)):

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Set the workbook to be non-editable
await workbookPermission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)
```

Важно:
- точки разрешений книги можно настраивать напрямую, не создавая правил защиты.

### Пример разрешений для листа

Разрешения листа и диапазона можно настраивать через Facade API или команды. В следующем примере задаётся разрешение на редактирование листа. Для других функций замените точку разрешения на соответствующую (см. [список точек разрешений листа](#worksheet-point)):

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// Create worksheet protection, allow specified users to edit
const permissionId = await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})

// To set permission points, you must first protect the worksheet
await worksheetPermission.setPoint(univerAPI.Enum.WorksheetPermissionPoint.Edit, false)
```

#### Удаление разрешений листа

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

// Remove worksheet protection
await worksheetPermission.unprotect()
```

### Пример пользовательских разрешений диапазона

Разрешения диапазона также можно настраивать через API и команды. Здесь в качестве примера используется разрешение на редактирование диапазона. Для других функций диапазона замените точки разрешений; подробности см. в [списке точек разрешений диапазона](#range-point).

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// Set range protection permission, allow specified users to edit but not allow others to view
const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
console.log(rule)

// To set permission points, you must first create a range protection rule.
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.Edit, false)
await rule.setPoint(univerAPI.Enum.RangePermissionPoint.View, true)
```

#### Удаление разрешений защиты диапазона

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

// delete all rules within the range
await rangePermission.unprotect()

// Or delete specific rules within the range
const rules = await rangePermission.listRules()
if (rules.length > 0) {
  await rules[0].remove()
}
```

## Типовые задачи [#permission-tasks]

### Перевести книгу в режим чтения

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
console.log(permission.getSnapshot())
```

### Управлять защищёнными диапазонами

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('A1:B2')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('C3:D4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])
console.log(createdRules)

const rules = await permission.listRangeProtectionRules()
const firstRule = rules[0]
if (firstRule) {
  await firstRule.updateRanges([fWorksheet.getRange('A1:B3')])
}
```

### Проверить права ячейки

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getActiveSheet().getWorksheetPermission()
console.log(permission.debugCellPermission(0, 0))
```

## Настройка интерфейса прав [#permission-ui]

### Стратегия затенения защищённого диапазона

Чтобы различать защищённые области, которые текущий пользователь может и не может редактировать, используйте `non-editable`. Затенение скрывается для доступных для редактирования защищённых областей и сохраняется там, где право редактирования отключено. Защищённые диапазоны, недоступные для просмотра, остаются замаскированными.

Эта настройка управляет отображением защиты диапазонов и листов. Она не создаёт правила защиты, не меняет права редактирования или просмотра и не добавляет затенение к незащищённым областям. Сначала настройте правила и права текущего пользователя, как показано выше.

| Стратегия | Отображение |
| --- | --- |
| `true` / `'always'` | Показывать затенение всех защищённых областей (по умолчанию). |
| `'non-editable'` | Скрывать затенение редактируемых защищённых областей и сохранять его для нередактируемых. |
| `'non-viewable'` | Показывать затенение только для защищённых областей, недоступных для просмотра. |
| `false` / `'none'` | Скрывать всё затенение защиты; проверки прав продолжают действовать. |

## Интеграция сервиса авторизации [#permission-integration]

### Расширенное использование

Если в собственном плагине требуется проверять разрешения, можно работать с точками разрешений напрямую.

В следующем примере на основе `WorkbookEditablePermission` показано, как проверять разрешения в собственном плагине. Другие точки разрешений работают аналогично.

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

### Расширение точек разрешений

Чтобы настроить собственную точку разрешения, реализуйте `IPermissionPoint` и зарегистрируйте её в службе разрешений:

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // Default value
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // The id must be unique within `IPermissionService`.
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// How to use it elsewhere
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // This returns an RxJS observable that lets you listen for permission changes
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```

### Интеграция со сторонней службой авторизации (для опытных пользователей) [#authorization-service]

Реализуйте [IAuthzIoService](https://github.com/dream-num/univer/blob/dev/packages/core/src/services/authz-io/type.ts) в приложении и свяжите методы прав, ролей и участников с сервером. В примере предполагается, что `./authorization-service` экспортирует эту реализацию как `YourAuthzService`. Зарегистрируйте её до создания книг, сохранив остальные параметры и плагины.

```typescript
import { IAuthzIoService, Univer } from '@univerjs/core'
import { YourAuthzService } from './authorization-service'

const univer = new Univer({
  override: [[IAuthzIoService, { useClass: YourAuthzService }]],
})
```

Сервис должен сохранять правила защиты и изменения участников, возвращать права текущего пользователя и передавать ошибки запросов вызывающему коду. Пустые списки в заглушке не обеспечивают сохранение данных. При совместной работе сервер отдельно проверяет чтение, JOIN и изменение; см. [Идентификация и авторизация](/server/collaboration/identity-and-authorization). Защита интерфейса и скрытие затенения не заменяют серверную авторизацию.

### Управление участниками

<Callout>
  Управление участниками реализуется через пользователей, ACL и сервис прав вашего приложения. Защитите чтение, JOIN и изменения согласно [Identity and authorization](/server/collaboration/identity-and-authorization). Для API ниже требуется соответствующая реализация сервиса прав.
</Callout>

- Получение списка участников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

const collaborators = await workbookPermission.listCollaborators()
console.log(collaborators)
```

- Добавление участников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Add multiple collaborators at once
await workbookPermission.setCollaborators([
  {
    user: { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
    role: univerAPI.Enum.UnitRole.Editor,
  },
  {
    user: { userID: 'user2', name: 'Jane Smith', avatar: '' },
    role: univerAPI.Enum.UnitRole.Reader,
  },
])

// Add a single collaborator
await workbookPermission.addCollaborator(
  { userID: 'user1', name: 'John Doe', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Editor,
)
```

- Изменение роли участника

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

await workbookPermission.updateCollaborator(
  { userID: 'user1', name: 'John Doe Updated', avatar: 'https://...' },
  univerAPI.Enum.UnitRole.Reader,
)
```

- Удаление участников

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const workbookPermission = fWorkbook.getWorkbookPermission()

// Remove multiple collaborators
await workbookPermission.removeCollaborators(['user1', 'user2'])

// Remove a single collaborator
await workbookPermission.removeCollaborator('user1')
```
