통합 문서 모드로 문서 전체의 편집과 댓글 작성을 제어할 수 있습니다. 특정 공동 작업자만 시트나 범위를 편집하게 하려면 해당 시트나 범위에 보호 규칙을 만드세요. 공동 편집 환경에서는 서버에서도 문서 읽기, 세션 참여, 문서 변경 권한을 각각 확인해야 합니다. [사용자 식별 및 권한 부여](/server/collaboration/identity-and-authorization)를 참고하세요.

## 일반적인 작업 [#permission-tasks]

### 통합 문서를 읽기 전용으로 설정하거나 댓글 허용하기

`viewer` 모드는 보기와 인쇄를 허용합니다. 셀을 읽기 전용으로 유지하면서 댓글도 허용하려면 아래 인수를 `'commenter'`로 바꾸세요. 모드는 통합 문서의 권한을 한꺼번에 설정합니다. 한 사용자의 역할을 변경하려면 [공동 작업자 관리 API](#collaborators)를 사용하세요.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const permission = fWorkbook.getWorkbookPermission()
await permission.setMode('viewer')
```

권한 하나만 바꾸려면 `setPoint`를 호출하세요. 예를 들어 `await permission.setPoint(univerAPI.Enum.WorkbookPermissionPoint.Edit, false)`는 통합 문서 편집을 끕니다. 값이 바뀌면 SDK가 `IAuthzIoService.update`를 호출하고 `true`이면 `Editor`, `false`이면 `Owner`를 정책의 역할로 전달합니다. 문서를 다시 열어도 설정을 유지하려면 [권한 서비스를 연결하세요](#authorization-service).

### 지정한 공동 작업자에게 시트 편집 허용하기

`user1`과 `user2`를 이 통합 문서에 이미 등록된 공동 작업자의 ID로 바꾸세요. 개별 시트 권한을 설정하기 전에 `protect()`로 보호 규칙을 만드세요. 시트 보호를 해제하려면 `worksheetPermission.unprotect()`를 호출하세요.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const worksheetPermission = fWorksheet.getWorksheetPermission()

await worksheetPermission.protect({
  allowedUsers: ['user1', 'user2'],
  name: 'My Worksheet Protection',
})
```

### 지정한 공동 작업자에게만 A1:B2 보기 및 편집 허용하기

`allowedUsers`에 범위를 편집할 공동 작업자를 지정합니다. `allowViewByOthers: false`는 다른 사용자의 열람도 제한합니다. 이 규칙만 제거하려면 반환된 규칙에서 `rule.remove()`를 호출하세요.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const fRange = fWorksheet.getRange('A1:B2')
const rangePermission = fRange.getRangePermission()

const rule = await rangePermission.protect({
  name: 'My protected range',
  allowViewByOthers: false,
  allowedUsers: ['user1', 'user2'],
})
```

범위와 겹치는 규칙을 조회하려면 `rangePermission.listRules()`를 호출하세요. `rangePermission.unprotect()`는 겹치는 규칙을 모두 제거합니다.

### 보호 범위 관리

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const fWorksheet = fWorkbook.getActiveSheet()
const permission = fWorksheet.getWorksheetPermission()

const createdRules = await permission.protectRanges([
  {
    ranges: [fWorksheet.getRange('D1:D4')],
    options: { name: 'Public area', allowViewByOthers: true },
  },
  {
    ranges: [fWorksheet.getRange('E1:E4')],
    options: { name: 'Private area', allowViewByOthers: false, allowedUsers: ['user1'] },
  },
])

await createdRules[0].updateRanges([fWorksheet.getRange('D1:D5')])
```

### A1에 값을 입력할 수 없는 원인 찾기

다음 예제는 일반 셀 값을 입력하는 데 필요한 권한을 보여 줍니다. 하나라도 `false`이면 입력이 차단됩니다. `debugCellPermission(0, 0)`은 A1을 포함하는 보호 규칙을 반환하며, 해당 규칙이 없으면 `undefined`를 반환합니다.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
if (!fWorkbook) throw new Error('No active workbook')
const worksheet = fWorkbook.getActiveSheet().getWorksheetPermission()
const rule = await worksheet.debugCellPermission(0, 0)

console.table({
  workbookEdit: fWorkbook.getWorkbookPermission().canEdit(),
  worksheetEdit: worksheet.canEdit(),
  setCellValue: worksheet.getPoint(univerAPI.Enum.WorksheetPermissionPoint.SetCellValue),
  rangeEdit: rule?.canEdit() ?? true,
})
```

## 권한 포인트 목록 [#point-list]

### 워크시트 작업과 필요한 포인트

각 작업은 자체 포인트를 검사합니다. 통합 문서 포인트는 같은 행의 워크시트 및 범위 포인트와 함께 적용되며, 범위 포인트는 작업이 교차하는 모든 보호 범위의 편집 포인트를 의미합니다. 행이나 열을 숨기면 검사가 해당 행 또는 열 전체로 확장됩니다.

| 작업 | 필요한 포인트 |
| --- | --- |
| 셀 값 입력(수식 제외) | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `RangeProtectionPermissionEditPoint` |
| 워크시트 삽입 | `WorkbookEditablePermission`, `WorkbookCreateSheetPermission` |
| 워크시트 복사 | `WorkbookEditablePermission`, `WorkbookCopySheetPermission` |
| 워크시트 이동 | `WorkbookEditablePermission`, `WorkbookMoveSheetPermission` |
| 워크시트 이름 변경 | `WorkbookEditablePermission`, `WorkbookRenameSheetPermission` |
| 워크시트 숨기기 또는 표시 | `WorkbookEditablePermission`, `WorkbookHideSheetPermission` |
| 워크시트 삭제 | `WorkbookEditablePermission`, `WorkbookDeleteSheetPermission` |
| 행 또는 열 숨기기 또는 표시 | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` 또는 `WorksheetSetColumnStylePermission`, 그리고 교차하는 각 보호 범위의 편집 포인트 |
| 행 또는 열 크기 조정, 콘텐츠에 맞추기 | `WorksheetSetRowStylePermission` 또는 `WorksheetSetColumnStylePermission` |
| 셀 병합 또는 병합 해제 | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetCellValuePermission`, `WorksheetSetCellStylePermission`, 그리고 교차하는 각 보호 범위의 편집 포인트 |
| 범위 정렬 | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSortPermission`, 그리고 교차하는 각 보호 범위의 편집 포인트 |
| 틀 고정 또는 고정 해제 | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| 눈금선 표시/숨기기 또는 색 변경 | `WorkbookEditablePermission`, `WorksheetEditPermission` |
| 주석 추가, 업데이트 또는 삭제 | `WorkbookEditablePermission`, `WorksheetEditPermission`, 그리고 셀이 포함된 각 보호 범위의 편집 포인트 |
| 행 또는 열 그룹화/그룹 해제 | `WorkbookEditablePermission`, `WorksheetEditPermission`, `WorksheetSetRowStylePermission` 또는 `WorksheetSetColumnStylePermission`, 그리고 교차하는 각 보호 범위의 편집 포인트 |
| 보호 규칙 만들기 | `WorkbookCreateProtectPermission` |
| 보호 규칙의 공동 작업자 관리 | `WorksheetManageCollaboratorPermission` 또는 `RangeProtectionPermissionManageCollaPoint` |
| 보호 규칙 삭제 | `WorksheetDeleteProtectionPermission` 또는 `RangeProtectionPermissionDeleteProtectionPoint` |

필요한 포인트가 `false`이면 명령은 문서를 변경하기 전에 거부됩니다.

주석은 셀 편집 포인트를 따릅니다. 주석 읽기에는 권한 검사가 적용되지 않습니다.

### 댓글 권한

댓글을 읽으려면 통합 문서의 `View` 권한이, 작성하려면 `Comment` 권한이 필요합니다. 두 작업 모두 시트의 `View` 권한이 필요합니다. 셀에 연결된 댓글은 해당 셀을 포함하는 모든 보호 규칙이 보기를 허용해야 합니다. 작성자는 자신의 댓글을 수정하거나 삭제할 수 있습니다.

## 보호 범위 음영 표시 전략 [#permission-ui]

`non-editable`를 사용하여 보호 된 영역을 구별 할 수 있습니다. 현재 사용자는 할 수 없습니다. 편집 가능한 영역은 그림자, 편집이 불가능한 영역을 수신하지 않고 그림자를 유지하고 비보기 가능한 범위는 마스크를 유지합니다.

설정은 범위 및 워크 시트 보호가 표시된 방법 만 영향을 미칩니다. 보호 규칙을 만들지 않으며 편집 또는 볼 권한을 변경하지 않으며 보호되지 않은 영역에 그림자를 추가하지 않습니다. 보호 규칙과 현재의 사용자의 권한을 우선 구성하십시오. 위에서 설명한대로.

| 전략 | 표시 동작 |
| --- | --- |
| `true` / `'always'` | 모든 보호 영역에 음영을 표시합니다(기본값). |
| `'non-editable'` | 편집 가능한 보호 영역의 음영을 숨기고 편집 불가능한 영역의 음영은 유지합니다. |
| `'non-viewable'` | 볼 수 없는 보호 영역에만 음영을 표시합니다. |
| `false` / `'none'` | 모든 보호 음영을 숨깁니다. 권한 검사는 계속 적용됩니다. |

## Facade API로 권한 UI 업데이트 [#permission-ui-api]

### 보호 범위 음영 표시 전략 [#protected-range-shadow-api]

Facade API는 현재 Univer 인스턴스에서 기존의 워크북을 변경합니다. 플러그인 모드에서 `@univerjs/sheets-ui/facade`를 먼저 가져 오기; 시트 코어 프리셋은 이미 모듈을 포함합니다.

```typescript
// Set to only show shadows for non-editable ranges
univerAPI.setProtectedRangeShadowStrategy('non-editable')

// Get the current protected range shadow display strategy
console.log(univerAPI.getProtectedRangeShadowStrategy())

// Subscribe to changes in the protected range shadow strategy
const subscription = univerAPI.getProtectedRangeShadowStrategy$().subscribe((strategy) => {
  console.log('Global strategy changed to:', strategy)
  // Update UI or perform other actions
})

// Later, unsubscribe to clean up
subscription.unsubscribe()
```

## 플러그인에서 권한 확장하기

### 확장 사용법

자신의 플러그인 내에서 권한을 확인하려면, 권한 포인트와 직접 작업.

아래 예제는 `WorkbookEditablePermission`를 사용합니다. 다른 권한은 동일한 패턴을 따릅니다.

```typescript
import { IPermissionService } from '@univerjs/core'
import { WorkbookEditablePermission } from '@univerjs/sheets'

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  setWorkbookNotEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, false)
  }

  setWorkbookEditable() {
    this._permissionService.updatePermissionPoint(new WorkbookEditablePermission('unitId').id, true)
  }
}
```

[권한 포인트 목록](#point-list)

`SheetPermissionCheckController.permissionCheckByPoints(points)`는 명시적인 권한 포인트 목록을 검사하고 그중 하나라도 비활성화되어 있으면 `false`를 반환합니다. 명령이 필요한 포인트를 이미 알고 있을 때, 예를 들어 특정 보호 규칙의 포인트를 사용할 때 이 메서드를 사용하세요.

### 권한 포인트 확장 방법

사용자 정의 권한 포인트를 위해, `IPermissionPoint`를 실행하고 권한 서비스로 등록하십시오:

```typescript
import type { IPermissionPoint } from '@univerjs/core'
import { IPermissionService, PermissionStatus } from '@univerjs/core'
import { UnitAction, UnitObject } from '@univerjs/protocol'

export class CustomPermissionPoint implements IPermissionPoint {
  type = UnitObject.Unkonwn // your type
  subType = UnitAction.View // your subType
  status = PermissionStatus.INIT
  value = true // Default value
  id: string
  constructor(unitId: string, subUnitId: string, customId: string) {
    // The id must be unique within `IPermissionService`.
    this.id = `${unitId}.${subUnitId}.${customId}`
  }
}

class YourService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
    this._init()
  }

  _init() {
    this._permissionService.addPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id'))
  }
}

// How to use it elsewhere
class ConsumeService {
  constructor(@IPermissionService private _permissionService: IPermissionService) {
  }

  doSomething() {
    const point = this._permissionService.getPermissionPoint(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point?.value)
  }

  bindEvent() {
    // This returns an RxJS observable that lets you listen for permission changes
    const point$ = this._permissionService.getPermissionPoint$(new CustomPermissionPoint('unitId', 'subUnitId', 'my-id').id)
    console.log(point$)
  }
}
```
