Formulas are a core part of Univer. Users write formulas in cells, and Univer calculates the values. The supported functions match Excel and cover math, logical, text, date, and other categories.

A workbook that contains many formulas can occupy the main thread for extended periods and slow down the page. Running formula calculation in a Worker limits the impact on rendering and user interaction. For configuration details, see [Web Workers](/guides/sheets/getting-started/worker).

`initialFormulaComputing` controls how formulas are calculated when a workbook loads. If the stored formula results are stale, `CalculationMode.FORCED` recalculates them. In preset mode, the same option is nested under `formula`.

Choose the integration mode you use, and add these options to the existing initialization. Keep the other plugins, locale, theme, and container settings unchanged, and do not register the same plugin twice.

- `CalculationMode.FORCED` recalculates all formulas.
- `CalculationMode.WHEN_EMPTY` is the default and calculates only formula cells that have no stored `v` value.
- `CalculationMode.NO_CALCULATION` skips calculation during initialization.

## Plugin configuration [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | Sets how formulas are calculated when a workbook opens. |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

`UniverSheetsCorePreset`

| <span data-config-options="">Option</span> | Type | Default | What it does |
| --- | --- | --- | --- |

```typescript
const { univerAPI } = createUniver({
  presets: [
    UniverSheetsCorePreset({
      formula: {
        initialFormulaComputing: CalculationMode.FORCED,
      },
    }),
  ],
})
```

## Configure cross-workbook bindings [#cross-workbook-configuration]

If an application needs to associate a formula name with a stable document ID, it can use the reference-binding APIs provided by `@univerjs-pro/engine-formula`. This is a Pro extension. Configure a [client license](/server/license), replace `UniverFormulaEnginePlugin` with `UniverProFormulaEnginePlugin` during initialization, and import the Pro Facade. Only one formula engine can be registered. Importing the Facade alone does not register the plugin.

## Cross-workbook references

A cross-workbook formula reads data from another workbook, for example to total the sales in `Sales.xlsx` from `Report`. Unlike a reference to another worksheet in the same workbook, it also identifies the source workbook.

### Reference syntax

| Scenario | Example | Meaning |
| --- | --- | --- |
| Another sheet in the same workbook | `=SUM(Data!A1:A10)` | Cells in the current workbook's `Data` sheet |
| A range in another workbook | `=SUM('[Sales.xlsx]Data'!A1:A10)` | Cells in the `Data` sheet of `Sales.xlsx` |
| A table in another workbook | `=SUM(Sales.xlsx!SalesTable[Amount])` | The `Amount` column of an existing `SalesTable` table in the source workbook |

`Sales.xlsx` is a workbook name, not a file path or a download URL. Writing a formula does not read a file, download an Excel workbook, or connect to an editor in another browser page. To use a structured table reference, create the corresponding [table](/guides/sheets/features/table) first.

### Reference workbooks loaded in the same instance

With the core formula engine, both workbooks must be loaded into the same Univer instance and share the same formula calculation environment. Run this example after initializing Sheets. In plugin mode, also import the Facade extensions described on this page.

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false` loads the source workbook without making it the current workbook. Continue to use the explicit `source` and `report` handles, so that a change of the active workbook does not send a formula to the wrong workbook.

Name matching is case-insensitive. A full-name match takes precedence; when there is none, matching ignores common Excel extensions such as `.xlsx` and `.xlsm`. A name that does not exist, or that matches several workbooks, returns `#REF!`. Source names should therefore be explicit and unique.

### Bind a reference to a stable source ID

Use the Pro engine configured above to bind the names used in formulas to stable document IDs.

The following example reuses the workbooks above in an environment configured with the Pro engine:

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId` identifies the workbook that contains the formula. `unit.unitId` is the stable ID of the source workbook, and `formulaQualifier` is the name the source workbook uses in formula text. Range coordinates are zero-based, and the end position is inclusive.

`buildReference()` returns a reference fragment without `=` and persists the cross-workbook binding. It does not load the source workbook or start calculation. Source data must still come from a workbook loaded into the calculation environment, or from a configured data provider.

For hand-written or application-generated formula text, bind the source before writing the formula:

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

Repeating an identical binding in the same workbook is idempotent. Pass `qualifier` without brackets or quotes, and do not use a positive integer such as `1` or `2`. Excel reserves such numbers for external-link slots, not for application document IDs. Imported Excel external links also require their link resources; copying the formula text alone is insufficient.

### Update, save, and unload

After changing source data through the Facade, calculate explicitly and wait until the results have been applied before reading the target. A return from `setFormula()` or `setValue()` does not mean that asynchronous calculation has finished.

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

Save the target with `report.save()` to preserve the complete snapshot, including its reference-binding resources. Saving only the cell formula text loses the mapping between public names and source IDs. Save and load source workbook data separately.

After a source workbook is unloaded, ordinary references to loaded workbooks can no longer read it. Pro external references continue to calculate only when the configured data providers and the available caches supply the required data. A binding contains no source data and does not guarantee offline calculation. A previously displayed result does not prove that the data is current.

Remove a Pro binding when it is no longer required:

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

Removing a binding does not delete or rewrite existing formulas. The next calculation resolves their names again. If a loaded workbook still matches a name, the reference may keep resolving; if nothing matches, it returns `#REF!`. To stop referencing the source altogether, change or clear the cell formulas as well.

See the [FFormula reference-binding APIs](/reference/facade/formula) for full parameters and return values.

## 3D references

A 3D reference spans consecutive worksheets in a workbook. It is distinct from a reference to another workbook:

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

The range includes `Jan`, `Mar`, and every sheet between them, in workbook order rather than alphabetical order. Reordering worksheets can change what the range aggregates, so confirm the range after reordering.

## Supported formula functions

Use `AMORDEGRC` for declining-balance depreciation and `EUROCONVERT` to convert between participating currencies at their fixed euro rates. `=ISO.CEILING(-4.3)` returns `-4`.

### Show range selector dialog

`@univerjs/sheets-formula-ui/facade` adds `univerAPI.showRangeSelectorDialog`. A custom UI that needs users to select one or more ranges can call this API, which opens the same selector that the formula-related panels use.

```typescript
const workbook = univerAPI.getActiveWorkbook()
const worksheet = workbook?.getActiveSheet()

if (workbook && worksheet) {
  await univerAPI.showRangeSelectorDialog({
    unitId: workbook.getId(),
    subUnitId: worksheet.getSheetId(),
    initialValue: [
      {
        unitId: workbook.getId(),
        sheetName: worksheet.getSheetName(),
        range: worksheet.getRange('A1:B2').getRange(),
      },
    ],
    maxRangeCount: 2,
    supportAcrossSheet: true,
    callback: (ranges, isCancel) => {
      console.log(ranges, isCancel)
    },
  })
}
```

### Set formula calculation mode when initializing data

```typescript
const formulaEngine = univerAPI.getFormula()
formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
```

When called after the `Starting` lifecycle, this API takes effect the next time a Univer Sheet is created.

To make it apply during the current initialization of the Univer Sheet, call it before the `Ready` lifecycle, as in the following example:

```typescript
univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### Iterative calculation [#iterative-calculation]

Iterative calculation is a workbook-level setting, stored in the `calculationSettings` field of its snapshot. It is disabled by default, so circular formulas keep their cached values, or zero when no value is cached. Enable it for models that intentionally contain circular references.

| Option | Default | Behavior |
| --- | --- | --- |
| `iterativeCalculation` | `false` | Evaluate circular references iteratively. |
| `maxIterations` | `100` | An integer between 1 and 32767. |
| `maxChange` | `0.001` | A finite, positive convergence threshold. Iteration stops when every numeric result in the circular group changes by no more than this amount. |

Update all three settings together through the workbook Facade. The command supports undo and redo as well as collaboration, and returns `false` if the workbook is unavailable or cannot be edited. Invalid settings are normalized to the default values.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

`calculationSettings` can also be supplied when calling `createWorkbook()`. Each workbook keeps its own settings. The Formula ribbon exposes the same controls through Calculation Options.

Circular-reference diagnostics can be read after calculation results have been applied. `getCircularReferences()` does not start calculation; its results include worksheet IDs, zero-based row and column coordinates, group IDs, iteration counts, and convergence information when available.

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### Get formula strings execution result

Execute a batch of formulas asynchronously and receive the calculation results:

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // Full formula:
          '=SUM(A1:A10) + SQRT(D7)',

          // Decomposed sub-formulas (each one can be evaluated independently):
          'SUM(A1:A10)', // sub-formula 1
          'SQRT(D7)', // sub-formula 2
          'A1:A10', // range reference
          'D7', // single-cell reference
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## Formula value semantics [#formula-value-semantics]

`ISBLANK(A1)` checks whether the referenced cell contains content, not merely whether its displayed result is empty. A cleared cell, including one that retains formatting, is blank; a formula that returns `""` is not. The literal `ISBLANK("")` is also `FALSE`. `UNIQUE` compares text without case sensitivity and keeps the first spelling. `PROPER` recognizes Unicode letters, including accented Latin, Greek, and Cyrillic letters. `AVERAGE` aggregates the entire array returned by functions such as `FILTER`.

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
