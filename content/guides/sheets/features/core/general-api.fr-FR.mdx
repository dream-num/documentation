Les API Facade disponibles dans Univer dépendent du type de document. Cette page couvre les API générales, qui se comportent de la même manière dans chaque type de document .

## Importation

```typescript
import { FUniver } from '@univerjs/core/facade'

const univerAPI = FUniver.newAPI(univer)
```

## Concepts

### Commandes

La plupart des opérations de Univer sont enregistrées avec le système de commande et passent par celui-ci. Parce que chaque opération suit le même chemin, Univer peut prendre en charge l'annulation, le redécoupage et la collaboration.

<Callout>Pour la justification de la conception, voir [Système de commande Univer](/blog/univer#command-system).</Callout>

### Commandes

Presque toutes les opérations de Univer sont enregistrées avec le système de commande et déclenchées par celui-ci. La centralisation de toutes les opérations en un seul endroit est ce qui rend pratiques les fonctionnalités telles que l'annulation, le redémarrage et la collaboration.

<Callout>
  Une commande peut être comprise comme un "événement" unique à l'intérieur de Univer. Pour les détails de conception, voir [système de commande](/blog/univer#command-system) .
</Callout>

### Écoute des commandes

Univer fournit deux points pour écouter une commande : avant qu'elle ne s'exécute et après qu'elle n'ait été exécutée.

- `Event.BeforeCommandExecute` exécute une logique personnalisée avant l'exécution de la commande.
- `Event.CommandExecuted` exécute une logique personnalisée après l'exécution de la commande.

#### Écoute des commandes avant leur exécution

Passez `Event.BeforeCommandExecute` à `FUniver.addEvent` pour enregistrer un auditeur pré-traitement. Le code de l'auditeur s'exécute avant l'exécution de la commande.

```typescript
const univerAPI = FUniver.newAPI(univer)

univerAPI.addEvent(univerAPI.Event.BeforeCommandExecute, ({ id, type, params }) => {
  // Custom logic executed before the command is executed
})
```

Pour empêcher l'exécution de la commande, définissez `event.cancel` à `true` dans le callback.

```typescript
const univerAPI = FUniver.newAPI(univer)

univerAPI.addEvent(univerAPI.Event.BeforeCommandExecute, (event) => {
  event.cancel = true
})
```

#### Écoute des commandes après leur exécution

Passer `Event.CommandExecuted` à `FUniver.addEvent` pour enregistrer un auditeur post-traitement. Son code fonctionne après l'exécution de la commande.

```typescript
const univerAPI = FUniver.newAPI(univer)

univerAPI.addEvent(univerAPI.Event.CommandExecuted, ({ id, type, params }) => {
  // Custom logic executed after the command is executed
})
```

### Arrêt de l’écoute

Enregistrer une commande auditeur renvoie un objet `IDisposable`. Appelez `IDisposable.dispose` pour le détruire.

Détruisez les auditeurs qui ne sont plus en usage. Les libérer aide à maintenir le programme stable.

```typescript
const univerAPI = FUniver.newAPI(univer)

// Register a listener
const disposable = univerAPI.addEvent(univerAPI.Event.BeforeCommandExecute, () => {
  // custom preprocessing logic before the command is executed
})

// Example: Destroy the listener after 1 second
setTimeout(() => {
  // Destroy the listener
  disposable.dispose()
}, 1000)
```

### Exécution de commandes

Si vous connaissez déjà l'ID de la commande et ses paramètres, vous pouvez exécuter la commande directement avec `FUniver.executeCommand`.

Par exemple, le code suivant définit la valeur de la cellule A1 avec la commande `sheet.command.set-range-values` :

```typescript
const univerAPI = FUniver.newAPI(univer)

// Execute the command
univerAPI.executeCommand('sheet.command.set-range-values', {
  value: { v: 'Hello, Univer!' },
  range: { startRow: 0, startColumn: 0, endRow: 0, endColumn: 0 },
})
```

## API des événements

Univer envoie des événements pour les changements qui se produisent à l'intérieur d'un tableur, de sorte qu'une application peut les écouter et répondre. Les événements se retrouvent dans des groupes tels que les opérations de presse-papiers, les changements de sélection, les interactions cellulaires, les modifications de feuilles, et quelques autres.

### Catégories d’événements

Liste complète des événements : /reference/facade/events

1. **Événements du presse-papiers**
   - `BeforeClipboardChange`: s'allume avant que le contenu du presse-papiers ne change; définissez `params.cancel = true` pour bloquer la modification
   - `BeforeClipboardPaste`: feu avant le collage du contenu; définissez `params.cancel = true` pour bloquer la pâte
   - `ClipboardChanged`: s'allume après que le contenu du presse-papiers ait changé, avec le nouveau contenu
   - `ClipboardPasted`: feux après le collage du contenu, avec le collage

2. **Événements de sélection**
   - `SelectionChanged`: s'allume lorsque la sélection change, avec la nouvelle gamme de sélection
   - `SelectionMoveStart`: s'allume lorsque la sélection commence à se déplacer, ce qui permet des effets de sélection personnalisés
   - `SelectionMoveEnd`: s'allume lorsque la sélection cesse de se déplacer, avec la gamme finale
   - `SelectionMoving`: s'allume pendant que la sélection se déplace, qui prend en charge les mises à jour de l'interface utilisateur en direct
   - `DragOver`: feu alors que le contenu est traîné sur les cellules
   - `Drop` : s'allume lorsque le contenu traîné est tombé

3. **Événements de cellule**
   - `CellClicked`: s'allume lorsqu'une cellule est cliquée, avec sa position et son contenu
   - `CellHover`: s'allume lorsque le pointeur vole sur une cellule, qui prend en charge les tooltips
   - `CellPointerDown`: s'allume lorsque le pointeur est appuyé sur une cellule; utilisé pour lancer une traînée ou une sélection
   - `CellPointerUp`: feu lorsque le pointeur est libéré sur une cellule; utilisé pour terminer une opération
   - `CellPointerMove`: s'allume lorsque le pointeur se déplace sur les cellules

4. **Événements de feuille**
   - `SheetValueChanged`: s'allume lorsque les valeurs de feuille changent, avec la plage modifiée et les nouvelles valeurs
   - `SheetZoomChanged`: s'allume lorsque le niveau de zoom change, avec le nouveau rapport de zoom
   - `SheetSkeletonChanged`: s'allume lorsque la structure de la feuille change, par exemple lorsque des lignes ou des colonnes sont insérées ou supprimées
   - `BeforeSheetEditStart`: feu avant le démarrage de l'édition de cellules; utilisé pour contrôler si l'édition est autorisée
   - `SheetEditStarted`: s'allume lorsque l'édition de cellules commence; utilisé pour le comportement de l'éditeur personnalisé
   - `BeforeSheetEditEnd`: feu avant la fin de l'édition de cellules; utilisé pour valider le contenu
   - `SheetEditEnded`: s'allume lorsque l'édition de cellules se termine, avec la valeur éditée
   - `SheetEditChanging`: feux lors de l'édition de cellules; utilisé pour la validation ou le formatage en direct
   - `Scroll`: s'allume lorsque la feuille défile, avec la position du rouleau
   - `CrosshairHighlightEnabledChanged`: feu lorsque le surbrillance est activé ou désactivé

5. **Événements d’en-tête**
   - `RowHeaderClick`: s'allume lorsqu'un en-tête de ligne est cliqué
   - `RowHeaderHover` : s'allume lorsque le pointeur vole sur une ligne en-tête
   - `ColumnHeaderClick`: s'allume lorsqu'un en-tête de colonne est cliqué
   - `ColumnHeaderHover` : s'allume lorsque le pointeur survole un en-tête de colonne

6. **Événements de validation des données**
   - `BeforeSheetDataValidationAdd`: s'allume avant l'ajout d'une règle de validation des données
   - `SheetDataValidationChanged`: s'allume lorsque les règles de validation des données changent
   - `SheetDataValidatorStatusChanged`: s'allume lorsque l'état de validation des données change

7. **Événements de commentaire**
   - `BeforeCommentAdd`: feu avant l'ajout d'un commentaire
   - `CommentAdded`: feu après ajout d'un commentaire
   - `BeforeCommentUpdate`: s'allume avant la mise à jour d'un commentaire
   - `CommentUpdated`: feu après la mise à jour d'un commentaire
   - `BeforeCommentDeleted`: allume avant qu'un commentaire ne soit supprimé
   - `CommentDeleted`: feux après la suppression d'un commentaire

8. **Événements de traitement des données**
   - `SheetBeforeRangeSort`: feu avant qu'une plage ne soit triée
   - `SheetRangeSorted`: feu après tri d'une plage
   - `SheetBeforeRangeFilter`: s'allume avant qu'une plage ne soit filtrée
   - `SheetRangeFiltered`: feu après une gamme filtrée
   - `BeforePivotTableAdd`: s'allume avant l'ajout d'une table pivot
   - `PivotTableAdded`: s'allume après l'ajout d'une table pivot

### Utilisation des événements

Appelez `addEvent` sur `univerAPI` pour enregistrer un auditeur. Le motif est le même pour chaque événement :

```typescript
univerAPI.addEvent(univerAPI.Event.EventName, (params) => {
  // Handle event parameters
})
```

#### Exemple : écouter les clics sur les cellules

```typescript
univerAPI.addEvent(univerAPI.Event.CellClicked, (params) => {
  const { worksheet, workbook, row, column } = params
  console.log(`Cell clicked at row ${row}, column ${column}`)
})
```

#### Exemple : surveiller les opérations du presse-papiers

```typescript
univerAPI.addEvent(univerAPI.Event.BeforeClipboardPaste, (params) => {
  const { text, html } = params
  // If you want to cancel the clipboard paste
  params.cancel = true
})
```

#### Exemple : suivre les changements de sélection

```typescript
univerAPI.addEvent(univerAPI.Event.SelectionChanged, (params) => {
  const { worksheet, workbook, selections } = params
  console.log('Selection changed:', selections)
})
```

### Suppression des écouteurs d’événements

Les auditeurs d'événements retournent un objet `IDisposable` ; utilisez-le pour supprimer l'auditeur lorsqu'il n'est plus nécessaire :

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.SheetValueChanged, (params) => {
  // Handle value changes
})

// Later, when you want to remove the listener:
disposable.dispose()
```

### Bonnes pratiques

1. Éliminer les auditeurs d'événements qui ne sont plus nécessaires; sinon ils fuient la mémoire.
2. Choisissez l'événement qui correspond au cas d'utilisation, et préférez un événement spécifique à un événement général.
3. Gardez les gestionnaires d'événements légers, parce qu'ils courent chaque fois que l'événement tire.
4. Pour bloquer le comportement par défaut, utilisez `BeforeClipboardChange` ou un autre événement "avant".

## Presse-papiers système

`FUniver.copy()` et `FUniver.paste()` lisent depuis le presse-papiers système et l'écrivent.

<Callout>
  Copier et coller dépend de l'API native du navigateur. Si l'environnement ou ses permissions ne leur permettent pas, aucune opération ne fonctionne. Voir le [Documentation concernant le MDN](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText).
</Callout>

L'exemple suivant copie et colle une plage de feuilles.

```typescript
// Prevent failure due to loss of focus when executing copy and paste code in the console,
// this example listens for the cell click event and executes the copy and paste code.
univerAPI.addEvent(univerAPI.Event.CellClicked, async (params) => {
  const fWorkbook = univerAPI.getActiveWorkbook()
  const fWorksheet = fWorkbook.getActiveSheet()

  // Copy the range A1:B2 to the clipboard
  const fRange = fWorksheet.getRange('A1:B2')
  fRange.activate().setValues([
    [1, 2],
    [3, 4],
  ])
  await univerAPI.copy()

  // Paste the copied content to the range C1:D2
  const fRange2 = fWorksheet.getRange('C1')
  fRange2.activate()
  await univerAPI.paste()

  // Check the pasted content
  console.log(fWorksheet.getRange('C1:D2').getValues()) // [[1, 2], [3, 4]]
})
```

Les commandes de presse-papiers peuvent également être exécutées via le système de commande :

```typescript
import { CopyCommand, PasteCommand } from '@univerjs/ui'

// Copy
univerAPI.executeCommand(CopyCommand.id)
// Paste
univerAPI.executeCommand(PasteCommand.id)
```

## WebSocket

Le Facade API fournit `createSocket`. Avec une URL, il ouvre une connexion WebSocket. La connexion expose les événements ouverts, message, close et erreur; les messages sont envoyés avec la méthode `send`, et la connexion est fermée avec la méthode de `close` .

Dans une installation Presets, `univerAPI.createSocket(url)` peut être appelé directement. Dans une installation à la pièce, installer le paquet [`@univerjs/network`](/reference/packages/plugins/univerjs/network) et enregistrer `UniverNetworkPlugin`.

```typescript
// ... Omits other plugin imports
import { UniverNetworkPlugin } from '@univerjs/network'

// ... Omits other facade imports
import '@univerjs/network/facade'

// ... Omits other plugin registrations
univer.registerPlugin(UniverNetworkPlugin)
```

Voici un exemple minimal :

```typescript
// Replace the URL with the address of your own WebSocket service
const ws = univerAPI.createSocket('ws://47.100.177.253:8449/ws')

ws.open$.subscribe(() => {
  console.log('websocket opened')
  ws.send('hello')
})

ws.message$.subscribe((message) => {
  console.log('websocket message', message)
  const content = JSON.parse(message.data).content
  if (!content.includes('command')) {
    return
  }

  const commandInfo = JSON.parse(content)
  const { command, options } = commandInfo
  const { id, params } = command

  // Upon receiving collaborative data, it is locally saved
  univerAPI.executeCommand(id, params, options)
})

ws.close$.subscribe(() => {
  console.log('websocket closed')
})

ws.error$.subscribe((error) => {
  console.log('websocket error', error)
})

univerAPI.addEvent(univerAPI.Event.CommandExecuted, ({ id, type, params, options }) => {
  // Only synchronize local mutations
  if (
    type !== univerAPI.Enum.CommandType.MUTATION ||
    options?.fromCollab ||
    options?.onlyLocal ||
    id === 'doc.mutation.rich-text-editing'
  ) {
    return
  }

  const commandInfo = JSON.stringify({ command: { id, type, params }, options: { fromCollab: true } })
  ws.send(commandInfo)
})
```

Univer doit commencer par un unitID; la collaboration ne fonctionne pas sans un.

## Enregistrement d’une formule

Les formules personnalisées peuvent être enregistrées sur l'instance Univer actuelle via le Facade API.

L'exemple suivant appelle [`registerFunction`](https://docs.univer.ai/reference/facade/formula#registerfunction) une fois pour enregistrer l'algorithme, le nom et la description qu'une formule `CUSTOMSUM` nécessite dans le plugin formule. La formule est alors disponible : taper `=CUSTOMSUM` dans n'importe quelle cellule vide affiche l'invite.

```typescript
// Registered formulas support lambda functions
const formulaEngine = univerAPI.getFormula()
formulaEngine.registerFunction(
  'CUSTOMSUM',
  (...variants) => {
    let sum = 0
    const last = variants[variants.length - 1]

    if (last.isLambda && last.isLambda()) {
      variants.pop()
      const variantsList = variants.map((variant) => (Array.isArray(variant) ? variant[0][0] : variant))
      sum += last.executeCustom(...variantsList).getValue()
    }

    for (const variant of variants) {
      sum += Number(variant) || 0
    }

    return sum
  },
  'Adds its arguments',
)

// Use the function in a cell
const fWorkbook = univerAPI.getActiveWorkbook()
const fWorksheet = fWorkbook.getActiveSheet()
const cellA1 = fWorksheet.getRange('A1')
cellA1.setValue(1)
const cellA2 = fWorksheet.getRange('A2')
cellA2.setValue(2)
const cellA3 = fWorksheet.getRange('A3')
cellA3.setValue({ f: '=CUSTOMSUM(A1,A2,LAMBDA(x,y,x*y))' })

// A3 will display: 5
formulaEngine.calculationEnd((functionsExecutedState) => {
  if (functionsExecutedState === 3) {
    console.log(cellA3.getValue()) // 5
  }
})
```

Appelez `dispose` pour désenregistrer la formule.

```typescript
const functionDisposable = formulaEngine.registerFunction({
  // calculate
})

// Unregister the function
functionDisposable.dispose()
```

Pour fournir un contenu et des descriptions internationalisés plus complets, définissez également les champs `locales` et `description` :

Les options sont décrites ci-dessous.

- `func` détient l'algorithme et le mapping de nom pour la formule. Son entrée est ce que l'utilisateur entre lors de l'utilisation de la formule, qui peut être un nombre, une chaîne, une valeur booléenne ou un tableau.
- `description` définit la description de la formule personnalisée.
- `locales` peut contenir plusieurs langues ; les règles de nommage sont décrites dans [Type local](/reference/enums/locale-type). `functionList` peuvent contenir des traductions pour plus d'une formule. Pour les détails des champs, voir la section [Comment ajouter des formules dans Formula Engine](/blog/custom-formula#how-to-add-formulas-in-formula-engine) .

<Callout>
  Pour réutiliser l'algorithme que le système de formule fournit déjà et l'étendre, enregistrez une formule personnalisée via la configuration du plugin. Voir [Formule personnalisée](/blog/custom-formula) pour le passage.
</Callout>

## API des énumérations

Le Facade API inclut les types d'enum utilisés pendant le développement, par exemple:

```typescript
console.log(univerAPI.Enum)
console.log(univerAPI.Enum.UniverInstanceType.UNIVER_SHEET)
console.log(univerAPI.Enum.LifecycleStages.Rendered)
```

```typescript
console.log(univerAPI.Util)
console.log(univerAPI.Util.tools.chatAtABC(10))
console.log(univerAPI.Util.tools.ABCatNum('K'))
```
