Les formules sont une partie centrale de Univer. Les utilisateurs écrivent des formules dans les cellules, et Univer calcule les valeurs. Les fonctions prises en charge correspondent à Excel et couvrent les mathématiques, logiques, texte, date et autres catégories.

Un classeur contenant de nombreuses formules peut occuper le thread principal pendant de longues périodes et ralentir la page. Le calcul de la formule dans un Worker limite l'impact sur le rendu et l'interaction utilisateur. Pour les détails de configuration, voir [Travailleurs du Web](/guides/sheets/getting-started/worker).

`initialFormulaComputing` contrôle la façon dont les formules sont calculées lorsqu'un cahier de travail est chargé. Si les résultats de la formule stockée sont statiques, `CalculationMode.FORCED` les recalcule. En mode préréglé, la même option est imbriquée sous `formula`.

Choisissez le mode d'intégration que vous utilisez, et ajoutez ces options à l'initialisation existante. Gardez les autres plugins, local, thème et paramètres de conteneur inchangés, et n'enregistrez pas le même plugin deux fois.

- `CalculationMode.FORCED` recalcule toutes les formules.
- `CalculationMode.WHEN_EMPTY` est la valeur par défaut et calcule seulement les cellules de formule qui n'ont pas de valeur `v` stockée.
- `CalculationMode.NO_CALCULATION` saute le calcul lors de l'initialisation.

## Configuration des plugins [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | Définit comment les formules sont calculées lorsqu'un classeur s'ouvre. |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

`UniverSheetsCorePreset`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>formula</ConfigKey> | `object` |  | Fonctions de formule, descriptions, mode de calcul et paramètres de pointe de l'écran. |
| <ConfigKey depth={1}>initialFormulaComputing</ConfigKey> | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | Définit comment les formules sont calculées lorsqu'un classeur s'ouvre. |

```typescript
const { univerAPI } = createUniver({

```

## Configurer les liaisons entre classeurs [#cross-workbook-configuration]

Si une application doit associer un nom de formule à un ID de document stable, elle peut utiliser les API de reference-liant fournies par `@univerjs-pro/engine-formula`. Il s'agit d'une extension Pro. Configurer un [licence client](/server/license), remplacer `UniverFormulaEnginePlugin` par `UniverProFormulaEnginePlugin` lors de l'initialisation, et importer le Pro Facade. Un seul moteur de formule peut être enregistré. Importer le Facade seul n'enregistre pas le plugin.

## Références entre classeurs

Une formule de livre croisé lit les données d'un autre cahier, par exemple pour totaliser les ventes en `Sales.xlsx` de `Report`. Contrairement à une référence à une autre feuille de travail dans le même cahier, elle identifie également le cahier de travail source.

### Syntaxe des références

| Cas | Exemple | Cible |
| --- | --- | --- |
| Autre feuille du même classeur | `=SUM(Data!A1:A10)` | Feuille Data du classeur courant |
| Plage d’un autre classeur | `=SUM('[Sales.xlsx]Data'!A1:A10)` | Feuille Data de Sales.xlsx |
| Tableau d’un autre classeur | `=SUM(Sales.xlsx!SalesTable[Amount])` | Colonne Amount du tableau SalesTable existant |

`Sales.xlsx` est un nom de classeur, pas un chemin de fichier ou une URL de téléchargement. L'écriture d'une formule ne lit pas un fichier, le téléchargement d'un classeur Excel, ou se connecter à un éditeur dans une autre page de navigateur. Pour utiliser une référence de table structurée, créez d'abord le [Tableau](/guides/sheets/features/table) correspondant.

### Référencer des classeurs chargés dans la même instance

Avec le moteur de formule de base, les deux cahiers de travail doivent être chargés dans la même instance Univer et partager le même environnement de calcul de formule. Exécutez cet exemple après initialisation des feuilles. En mode plugin, importez également les extensions Facade décrites sur cette page.

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false` charge le cahier source sans en faire le cahier courant. Continuez à utiliser les poignées explicites `source` et `report`, de sorte qu'un changement du cahier actif n'envoie pas de formule au mauvais cahier.

La correspondance des noms est insensible à la casse. Une correspondance des noms complets a priorité; lorsqu'il n'y en a pas, la correspondance ignore les extensions communes Excel telles que `.xlsx` et `.xlsm`. Un nom qui n'existe pas, ou qui correspond à plusieurs cahiers de travail, renvoie `#REF!` . Les noms de sources doivent donc être explicites et uniques.

### Associer une référence à un ID source stable

Utilisez le moteur Pro configuré ci-dessus pour associer les noms de classeur dans les formules à des identifiants stables.

Cet exemple reprend les classeurs précédents dans un environnement configuré avec le moteur Pro :

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId` identifie le cahier de travail qui contient la formule. `unit.unitId` est l'ID stable du cahier de travail source, et `formulaQualifier` le nom utilisé dans le cahier de travaux source dans le texte de la formule. Les coordonnées de la plage sont basées sur zéro, et la position finale est inclusive.

`buildReference()` retourne un fragment de référence sans `=` et persiste la liaison entre les cahiers de travail. Il ne charge pas le cahier de travail source ou ne commence pas le calcul. Les données source doivent toujours provenir d'un cahier de travail chargé dans l'environnement de calcul, ou d'un fournisseur de données configuré.

Pour le texte de la formule manuscrite ou générée par la demande, lier la source avant d'écrire la formule :

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

La répétition d'une liaison identique dans le même cahier est idempotent. Passez `qualifier` sans crochets ou guillemets, et n'utilisez pas d'entier positif comme `1` ou `2`. Excel réserve ces numéros pour les emplacements de liens externes, pas pour les ID de documents d'application. Les liens externes importés Excel nécessitent également leurs ressources de liens; copier le texte de la formule seule est insuffisant.

### Mettre à jour, enregistrer et décharger

Après avoir modifié les données sources à travers la Facade, calculer explicitement et attendre que les résultats aient été appliqués avant de lire la cible. Un retour de `setFormula()` ou `setValue()` ne signifie pas que le calcul asynchrone a été terminé.

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

Enregistrer la cible avec `report.save()` pour préserver l'instantané complet, y compris ses ressources de référence. Enregistrer seulement le texte de la formule cellulaire perd la correspondance entre les noms publics et les identifiants sources. Enregistrer et charger les données du cahier de travail source séparément.

Après le déchargement d'un cahier de travail source, les références ordinaires aux cahiers de travail chargés ne peuvent plus le lire. Les références externes pro continuent à calculer uniquement lorsque les fournisseurs de données configurés et les caches disponibles fournissent les données requises. Une liaison ne contient aucune donnée source et ne garantit pas le calcul hors ligne. Un résultat précédemment affiché ne prouve pas que les données sont courantes.

Supprimer une liaison Pro quand elle n'est plus nécessaire:

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

La suppression d'une liaison ne supprime pas ou réécrit les formules existantes. Le calcul suivant résout leurs noms. Si un cahier de travail chargé correspond toujours à un nom, la référence peut continuer à résoudre ; si rien ne correspond, il renvoie `#REF!`. Pour arrêter de référencer la source, modifier ou effacer les formules cellulaires aussi bien.

Voir le [API de référence de FFormula](/reference/facade/formula) pour les paramètres complets et les valeurs de retour.

## Références 3D

Une référence 3D couvre des feuilles de travail consécutives dans un cahier de travail. Elle est distincte d'une référence à un autre cahier de travail :

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

La plage comprend `Jan`, `Mar` et chaque feuille entre eux, dans l'ordre du cahier plutôt que l'ordre alphabétique. La réorganisation des feuilles de travail peut changer ce que les agrégats de la plage, ainsi confirmer la plage après la réorganisation.

## Fonctions de formule prises en charge

`AMORDEGRC` calcule un amortissement dégressif. `EUROCONVERT` convertit les monnaies participantes aux taux de conversion fixes de l’euro. `=ISO.CEILING(-4.3)` renvoie `-4`.

### Afficher la boîte de dialogue de sélection de plages

`@univerjs/sheets-formula-ui/facade` ajoute `univerAPI.showRangeSelectorDialog`. Une interface utilisateur personnalisée qui a besoin d'utilisateurs pour sélectionner une ou plusieurs gammes peut appeler cette API, qui ouvre le même sélecteur que les panneaux liés à la formule.

```typescript
const workbook = univerAPI.getActiveWorkbook()
const worksheet = workbook?.getActiveSheet()

if (workbook && worksheet) {
  await univerAPI.showRangeSelectorDialog({
    unitId: workbook.getId(),
    subUnitId: worksheet.getSheetId(),
    initialValue: [
      {
        unitId: workbook.getId(),
        sheetName: worksheet.getSheetName(),
        range: worksheet.getRange('A1:B2').getRange(),
      },
    ],
    maxRangeCount: 2,
    supportAcrossSheet: true,
    callback: (ranges, isCancel) => {
      console.log(ranges, isCancel)
    },
  })
}
```

### Définir le mode de calcul des formules lors de l’initialisation des données

```typescript
const formulaEngine = univerAPI.getFormula()
formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
```

Lorsqu'elle est appelée après le cycle de vie de `Starting`, cette API prend effet la prochaine fois qu'une feuille Univer est créée.

Pour l'appliquer lors de l'initialisation actuelle de la feuille Univer, appelez-la avant le cycle de vie `Ready` comme dans l'exemple suivant :

```typescript
univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### Calcul itératif [#iterative-calculation]

Le calcul itératif est un réglage de niveau du cahier, stocké dans le champ `calculationSettings` de son instantané. Il est désactivé par défaut, de sorte que les formules circulaires gardent leurs valeurs mises en cache, ou zéro quand aucune valeur n'est mise en cache. Activez-le pour les modèles qui contiennent intentionnellement des références circulaires.

| Option | Valeur par défaut | Comportement |
| --- | --- | --- |
| `iterativeCalculation` | `false` | Évaluer les références circulaires itératives. |
| `maxIterations` | `100` | Un entier entre 1 et 32767. |
| `maxChange` | `0.001` | Un seuil de convergence fini et positif. L'itération s'arrête lorsque chaque résultat numérique dans le groupe circulaire change de pas plus que ce montant. |

Mettre à jour les trois paramètres ensemble à travers le cahier de travail Facade. La commande prend en charge l'annulation et le redécoupage ainsi que la collaboration, et renvoie `false` si le cahier de cours n'est pas disponible ou ne peut pas être édité. Les paramètres non valides sont normalisés aux valeurs par défaut.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

`calculationSettings` peut également être fourni lors de l'appel à `createWorkbook()`. Chaque classeur conserve ses propres paramètres. Le ruban Formula expose les mêmes commandes grâce aux options de calcul.

Les diagnostics de référence circulaire peuvent être lus après l'application des résultats de calcul. `getCircularReferences()` ne commence pas le calcul; ses résultats incluent les ID de feuille de travail, les coordonnées de ligne et de colonne zéro, les ID de groupe, les nombres d'itération et les informations de convergence lorsque disponibles.

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### Obtenir le résultat de l’exécution de chaînes de formule

Exécuter un lot de formules asynchrones et recevoir les résultats de calcul:

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // Full formula:
          '=SUM(A1:A10) + SQRT(D7)',

          // Decomposed sub-formulas (each one can be evaluated independently):
          'SUM(A1:A10)', // sub-formula 1
          'SQRT(D7)', // sub-formula 2
          'A1:A10', // range reference
          'D7', // single-cell reference
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## Sémantique des valeurs de formule [#formula-value-semantics]

`ISBLANK(A1)` vérifie si la cellule référencée contient du contenu, et non seulement si son résultat affiché est vide. Une cellule effacée, y compris celle qui conserve le formatage, est vide; une formule qui renvoie `""` n'est pas. La `ISBLANK("")` littérale est aussi `FALSE`. `UNIQUE` compare le texte sans sensibilité de cas et conserve la première orthographe. `PROPER` reconnaît les lettres Unicode, y compris les lettres latines, grecques et cyrilliques accentuées. `AVERAGE` regroupe l'ensemble du tableau retourné par des fonctions telles que `FILTER`.

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
