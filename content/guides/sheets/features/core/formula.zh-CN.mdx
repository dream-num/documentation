公式是 Univer 的核心能力之一。用户在单元格中写入公式，由 Univer 计算其值。支持的函数与 Excel 一致，涵盖数学、逻辑、文本、日期等类型。

工作簿中的公式较多时，公式计算可能长时间占用主线程，页面响应随之变慢。把公式计算放到 Worker 中执行，可以减轻对渲染和用户交互的影响。配置方式见 [Web Workers](/guides/sheets/getting-started/worker)。

`initialFormulaComputing` 控制工作簿加载时的公式计算方式。如果已存储的公式结果已经过期，`CalculationMode.FORCED` 会重新计算这些结果。在预设模式下，该选项位于 `formula` 之下。

根据所采用的接入模式，把这些选项加入现有的初始化配置。其他插件、语言、主题和容器设置保持原样，同一个插件不要注册两次。

- `CalculationMode.FORCED` 重新计算所有公式。
- `CalculationMode.WHEN_EMPTY` 是默认值，只计算没有已存储 `v` 值的公式单元格。
- `CalculationMode.NO_CALCULATION` 初始化时不计算公式。

## 插件配置 [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | 设置工作簿打开时公式的计算方式。 |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

## 预设配置 [#preset-configuration]

`UniverSheetsCorePreset`

| <span data-config-options="">配置项</span> | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>formula</ConfigKey> | `object` |  | 配置公式函数、说明、计算模式和函数提示。 |
| <ConfigKey depth={1}>initialFormulaComputing</ConfigKey> | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | 设置工作簿打开时公式的计算方式。 |

```typescript
import { CalculationMode, UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import { createUniver } from '@univerjs/presets'

const { univerAPI } = createUniver({
  presets: [
    UniverSheetsCorePreset({
      formula: {
        initialFormulaComputing: CalculationMode.FORCED,
      },
    }),
  ],
})
```

## 配置跨工作簿绑定 [#cross-workbook-configuration]

如果应用需要把公式中的名称与固定的文档 ID 关联起来，可以使用 `@univerjs-pro/engine-formula` 提供的引用绑定 API。这是一项 Pro 扩展：需要先配置[客户端许可证](/server/license)，初始化时用 `UniverProFormulaEnginePlugin` 替换 `UniverFormulaEnginePlugin`，并引入 Pro Facade。公式引擎只能注册一个。仅引入 Facade 不会注册插件。

## 跨工作簿引用

跨工作簿公式从另一个工作簿读取数据，例如在 `Report` 中汇总 `Sales.xlsx` 的销售额。与引用同一工作簿中的其他工作表不同，跨工作簿公式还需要指明来源工作簿。

### 引用语法

| 场景 | 示例 | 含义 |
| --- | --- | --- |
| 同一工作簿中的另一张工作表 | `=SUM(Data!A1:A10)` | 当前工作簿中 `Data` 表的数据 |
| 另一工作簿中的单元格区域 | `=SUM('[Sales.xlsx]Data'!A1:A10)` | `Sales.xlsx` 中 `Data` 表的数据 |
| 另一工作簿中的表格 | `=SUM(Sales.xlsx!SalesTable[Amount])` | 来源工作簿内已存在的 `SalesTable` 表格的 `Amount` 列 |

`Sales.xlsx` 是工作簿名称，不是文件路径，也不是下载地址。写入公式不会读取文件、下载 Excel 工作簿，也不会连接到另一个浏览器页面中的编辑器。需要使用表格结构化引用时，先创建对应的[表格](/guides/sheets/features/table)。

### 引用同一实例中已加载的工作簿

使用基础公式引擎时，两个工作簿必须加载到同一个 Univer 实例中，并处于同一个公式计算环境。下面的代码应在 Sheets 初始化之后运行。在插件模式下，还需要按本页的说明引入 Facade 扩展。

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false` 使来源工作簿加载后不会成为当前工作簿。后续始终使用 `source` 和 `report` 这两个显式引用，即使活动工作簿发生变化，公式也不会被写到其他工作簿。

名称匹配不区分大小写。优先按完整名称匹配；如果没有完整名称匹配，则忽略 `.xlsx`、`.xlsm` 这类常见 Excel 扩展名后再匹配。名称不存在，或者匹配到多个工作簿时，都会返回 `#REF!`。来源名称应当明确且唯一。

### 使用固定来源 ID 绑定引用

使用前面配置好的 Pro 引擎，可以把公式中的名称绑定到固定的文档 ID。

下面的示例沿用前面两个工作簿，但运行在配置了 Pro 引擎的环境中：

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId` 表示包含该公式的工作簿。`unit.unitId` 是来源工作簿的固定 ID，`formulaQualifier` 是该工作簿在公式文本中使用的名称。区域坐标从 `0` 开始，且结束位置包含在内。

`buildReference()` 返回不带 `=` 的引用片段，同时持久化保存跨工作簿绑定。它不会加载来源工作簿，也不会触发计算。来源数据仍然需要来自加载到计算环境中的工作簿，或者来自已配置的数据提供方。

如果公式文本由人工编写或由应用生成，应先绑定来源，再写入公式：

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

在同一个工作簿中重复写入相同的绑定是幂等操作。`qualifier` 不要带方括号或引号，也不要使用 `1`、`2` 这类正整数，因为 Excel 将这些编号保留给外部链接槽位，而不是用于应用文档 ID。从 Excel 导入的外部链接还需要对应的链接资源，仅复制公式文本并不够。

### 数据更新、保存与卸载

通过 Facade 修改来源数据后，需要显式执行计算，并在结果写回之后再读取目标值。`setFormula()` 或 `setValue()` 返回，并不表示异步计算已经完成。

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

使用 `report.save()` 保存目标工作簿，可以保留完整的快照，其中包含引用绑定资源。如果只保存单元格中的公式文本，公开名称与来源 ID 之间的映射就会丢失。来源工作簿的数据需要单独保存和加载。

来源工作簿卸载后，普通的已加载工作簿引用就无法再读取它。Pro 外部引用能否继续计算，取决于已配置的数据提供方和可用缓存是否能够提供所需数据。绑定本身不包含来源数据，也不保证可以离线计算。此前显示过的结果并不能证明当前数据仍然有效。

不再需要某个 Pro 绑定时，可以将其移除：

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

移除绑定不会删除或改写已有的公式，下一次计算会重新解析这些名称。如果仍有同名工作簿处于加载状态，引用可能继续解析成功；如果没有任何匹配，则返回 `#REF!`。如果要彻底停止引用该来源，还需要修改或清空相关单元格的公式。

完整参数和返回值见 [FFormula 引用绑定 API](/reference/facade/formula)。

## 三维引用

三维引用指同一工作簿中连续的一组工作表，与引用另一个工作簿不同：

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

范围包含 `Jan`、`Mar` 以及两者之间的所有工作表，按工作簿中的排列顺序计算，而不是按名称排序。调整工作表顺序后，需要重新确认汇总范围。

## 已经支持的公式函数

### 打开范围选择器

`@univerjs/sheets-formula-ui/facade` 会添加 `univerAPI.showRangeSelectorDialog`。自定义 UI 需要用户选择一个或多个区域时，可以使用该 API，其打开的选择器与公式相关面板使用的是同一个。

```typescript
const workbook = univerAPI.getActiveWorkbook()
const worksheet = workbook?.getActiveSheet()

if (workbook && worksheet) {
  await univerAPI.showRangeSelectorDialog({
    unitId: workbook.getId(),
    subUnitId: worksheet.getSheetId(),
    initialValue: [
      {
        unitId: workbook.getId(),
        sheetName: worksheet.getSheetName(),
        range: worksheet.getRange('A1:B2').getRange(),
      },
    ],
    maxRangeCount: 2,
    supportAcrossSheet: true,
    callback: (ranges, isCancel) => {
      console.log(ranges, isCancel)
    },
  })
}
```

### 设置初始化数据时公式的计算模式

```typescript
const formulaEngine = univerAPI.getFormula()
formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
```

如果该 API 在 `Starting` 生命周期之后才被调用，则要等到下次创建 Univer Sheet 时才生效。

如果希望它在本次初始化时生效，可以在 `Ready` 生命周期之前调用，例如：

```typescript
univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### 迭代计算 [#iterative-calculation]

迭代计算按工作簿配置，保存在快照的 `calculationSettings` 字段中。该功能默认关闭，此时循环引用公式保留缓存值，没有缓存值则使用零。仅在模型确实有意包含循环引用时才需要启用。

| 选项 | 默认值 | 行为 |
| --- | --- | --- |
| `iterativeCalculation` | `false` | 对循环引用做迭代求值。 |
| `maxIterations` | `100` | 1 到 32767 之间的整数。 |
| `maxChange` | `0.001` | 有限的正数，用作收敛阈值。循环组中每个数值结果的变化都不超过这个值时停止迭代。 |

三个设置需要一起通过工作簿 Facade 提交。该命令支持撤销、重做和协同，工作簿不存在或不可编辑时返回 `false`。无效的设置会归一为默认值。

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

调用 `createWorkbook()` 时也可以传入 `calculationSettings`。每个工作簿保存各自的设置。公式工具栏的「计算选项」中提供了相同的控件。

计算结果显示之后，才能读取循环引用诊断信息。`getCircularReferences()` 不会触发计算，返回结果包含工作表 ID、从零开始的行列坐标、循环组 ID、迭代次数，以及可获取时的收敛信息。

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### 获取公式字符串的计算结果

异步执行一批公式，并获取计算结果：

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // 完整公式：
          '=SUM(A1:A10) + SQRT(D7)',

          // 分解后的子公式（每个都可以独立计算）：
          'SUM(A1:A10)', // 子公式 1
          'SQRT(D7)', // 子公式 2
          'A1:A10', // 范围引用
          'D7', // 单个单元格引用
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## 公式值的语义 [#formula-value-semantics]

`ISBLANK(A1)` 检查的是引用的单元格是否包含内容，而不仅仅是显示结果是否为空。已清空的单元格（即使保留了格式）视为空，返回 `""` 的公式则不算空。直接量 `ISBLANK("")` 同样返回 `FALSE`。`UNIQUE` 比较文本时不区分大小写，并保留首次出现的拼写。`PROPER` 能识别 Unicode 字母，包括带重音的拉丁字母、希腊字母和西里尔字母。`AVERAGE` 会聚合 `FILTER` 等函数返回的完整数组。

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
