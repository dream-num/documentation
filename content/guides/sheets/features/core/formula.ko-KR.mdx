공식은 Univer의 핵심 부분입니다. 사용자는 세포에 공식을 쓰고, Univer는 가치를 산출합니다. 지원된 기능 일치 Excel 및 덮개 수학, 논리, 원본, 날짜 및 다른 종류.

많은 수식이 포함 된 작업 책은 확장 된 기간 동안 주요 스레드를 차지하고 페이지를 느리게 할 수 있습니다. 노동자의 수식 계산은 렌더링 및 사용자 상호 작용에 영향을 제한합니다. 구성 세부 사항에 대해서는 [웹 노동자](/guides/sheets/getting-started/worker)를 참조하십시오.

`initialFormulaComputing`는 워크북로드가 될 때 공식이 계산되는 방법을 제어합니다. 저장 된 공식 결과는 stale 인 `CalculationMode.FORCED`가 계산합니다. 미리 설정 모드에서 동일한 옵션은 `formula`에서 배열됩니다.

통합 모드를 선택하고 기존 초기화에 이러한 옵션을 추가하십시오. 다른 플러그인, Locale, 테마 및 컨테이너 설정 변경되지 않고 동일한 플러그인을 두 번 등록하지 마십시오.

- `CalculationMode.FORCED`는 모든 공식을 재 계산합니다.
- `CalculationMode.WHEN_EMPTY`는 기본이며 `v` 값을 저장하지 않은 유일한 공식 셀을 계산합니다.
- `CalculationMode.NO_CALCULATION`는 초기화 중에 계산을 건너 뛸 수 있습니다.

## 플러그인 설정 [#plugin-configuration]

`UniverSheetsFormulaPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `initialFormulaComputing` | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | 작업북이 열릴 때 공식이 계산되는 방법을 설정한다. |

```typescript
import { CalculationMode, UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'

univer.registerPlugin(UniverSheetsFormulaPlugin, {
  initialFormulaComputing: CalculationMode.FORCED,
})
```

## 프리셋 설정 [#preset-configuration]

`UniverSheetsCorePreset`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| <ConfigKey depth={0}>formula</ConfigKey> | `object` |  | 공식 기능, 설명, 계산 모드 및 화면 팁 설정. |
| <ConfigKey depth={1}>initialFormulaComputing</ConfigKey> | `CalculationMode` | `CalculationMode.WHEN_EMPTY` | 작업북이 열릴 때 공식이 계산되는 방법을 설정한다. |

```typescript
import { CalculationMode, UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import { createUniver } from '@univerjs/presets'

const { univerAPI } = createUniver({
  presets: [
    UniverSheetsCorePreset({
      formula: {
        initialFormulaComputing: CalculationMode.FORCED,
      },
    }),
  ],
})
```

## 통합 문서 간 바인딩 설정 [#cross-workbook-configuration]

응용 프로그램은 안정적인 문서 ID로 공식 이름을 연결해야 할 경우 `@univerjs-pro/engine-formula`가 제공하는 참조 바인딩 API를 사용할 수 있습니다. 이것은 프로 확장입니다. [고객 라이센스](/server/license)를 구성하고 초기화 중에 `UniverProFormulaEnginePlugin`와 `UniverFormulaEnginePlugin`을 대체하고 Pro Facade를 가져올 수 있습니다. 하나의 공식 엔진 만 등록 할 수 있습니다. Facade 혼자 가져 오기 플러그인을 등록하지 않습니다.

## 통합 문서 간 참조

크로스 워크북 공식은 `Report`의 `Sales.xlsx`에서 판매하는 예를 들어 다른 워크북에서 데이터를 읽습니다. 동일한 워크북에서 다른 워크시트와는 달리 소스 워크북을 식별합니다.

### 참조 구문

| 용도 | 예시 | 대상 |
| --- | --- | --- |
| 같은 문서의 다른 시트 | `=SUM(Data!A1:A10)` | 현재 문서의 Data 시트 |
| 다른 문서의 셀 범위 | `=SUM('[Sales.xlsx]Data'!A1:A10)` | Sales.xlsx의 Data 시트 |
| 다른 문서의 테이블 | `=SUM(Sales.xlsx!SalesTable[Amount])` | 기존 SalesTable의 Amount 열 |

`Sales.xlsx`는 파일 경로 또는 다운로드 URL이 아닌 워크북 이름입니다. 공식을 작성하면 Excel 작업북을 다운로드하거나 다른 브라우저 페이지에 편집기에 연결하십시오. 구조 테이블 참조를 사용하려면 해당 [뚱 베어](/guides/sheets/features/table)를 먼저 만듭니다.

### 같은 인스턴스에 로드된 통합 문서 참조

핵심 공식 엔진으로, 둘 다 workbooks는 동일한 Univer 인스턴스로 적재되고 동일한 공식 계산 환경을 공유해야 합니다. 초기화 장 후에 이 예제를 실행하십시오. 플러그인 모드에서는 이 페이지에서 설명된 Facade 확장을 가져올 수도 있습니다.

```typescript
const source = univerAPI.createWorkbook({
  id: 'sales-workbook',
  name: 'Sales.xlsx',
  sheetOrder: ['sales-data'],
  sheets: {
    'sales-data': {
      id: 'sales-data',
      name: 'Data',
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: { 0: { v: 100 } },
        1: { 0: { v: 200 } },
      },
    },
  },
}, { makeCurrent: false })

const report = univerAPI.createWorkbook({ id: 'report-workbook', name: 'Report' })
const resultCell = report.getActiveSheet().getRange('A1')
resultCell.setFormula("=SUM('[Sales.xlsx]Data'!A1:A2)")

const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 300
```

`makeCurrent: false`는 현재 워크북을 만들지 않고 소스 워크북을로드합니다. 명시된 `source` 및 `report` 핸들을 사용하려면 활성 워크북의 변경이 잘못 된 워크북에 공식을 보내지 않습니다.

이름 일치는 경우에 과민합니다. 가득 차있 이름 일치는 우선권이 걸립니다; 아무도가 없을 때, 일치는 `.xlsx`와 `.xlsm`과 같은 일반적인 Excel 연장을 무시합니다. 존재하지 않는 이름, 또는 몇몇 워크북에 일치하는 것은, `#REF!`를 돌려보내야 합니다. 근원 이름은 그러므로 표적으로 하고 독특해야 합니다.

### 고정 원본 ID에 참조 바인딩

위에서 설정한 Pro 엔진으로 수식에 사용된 통합 문서 이름을 고정 문서 ID에 연결합니다.

Pro 엔진이 설정된 환경에서 위 문서를 사용합니다.

```typescript
import '@univerjs-pro/engine-formula/facade'

const reference = univerAPI.getFormula().buildReference({
  hostUnitId: report.getId(),
  unit: {
    unitId: source.getId(),
    formulaQualifier: 'Sales Source',
  },
  target: {
    kind: univerAPI.Enum.FormulaReferenceType.SHEET_RANGE,
    sheetName: 'Data',
    range: { startRow: 0, endRow: 1, startColumn: 0, endColumn: 0 },
  },
})

resultCell.setFormula(`=SUM(${reference})`)
```

`hostUnitId`는 공식을 포함하는 워크북을 식별합니다. `unit.unitId`은 소스 워크북의 안정적인 ID이며 `formulaQualifier` 는 공식 텍스트에서 소스 워크북 용도의 이름입니다. 범위 좌표는 0 기반이며, 최종 위치는 포함됩니다.

`buildReference()`는 `=`없이 참조 파편을 반환하고 크로스 워크북 바인딩을 주장합니다. 그것은 소스 워크북을로드하지 않거나 계산을 시작하지 않습니다. 소스 데이터는 계산 환경에로드 된 워크북에서, 또는 구성 된 데이터 제공 업체에서 있어야합니다.

수식 또는 응용 프로그램 생성 공식 텍스트를 위해, 공식을 쓰기 전에 소스를 바인딩:

```typescript
const formula = univerAPI.getFormula()
const bound = formula.upsertExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
  sourceUnitId: source.getId(),
  sourceUnitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
})
if (!bound) throw new Error('Could not bind Sales Source')

resultCell.setFormula("=SUM('[Sales Source]Data'!A1:A2)")
```

동일한 워크북에 동일한 바인딩을 반복하는 것은 idempotent입니다. 부류 또는 인용 없이 `qualifier`를 통과하고, `1` 또는 `2`와 같은 긍정적인 정수를 사용하지 마십시오. Excel는 외부 링크 슬롯에 대한 이러한 숫자를 예약, 응용 프로그램 문서 ID에 대 한. 수입된 Excel 외부 링크는 또한 그들의 링크 리소스를 필요로 합니다; 공식 텍스트를 복사 혼자서 충분하다.

### 업데이트, 저장 및 언로드

Facade를 통해 소스 데이터를 변경 한 후 결과가 대상을 읽기 전에 명시적으로 계산됩니다. `setFormula()` 또는 `setValue()`에서 반환은 비동기 계산이 완료 된 것을 의미하지 않습니다.

```typescript
const sourceSheet = source.getSheetBySheetId('sales-data')
if (!sourceSheet) throw new Error('Source sheet not found')
sourceSheet.getRange('A1').setValue(150)
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.log(resultCell.getValue()) // 350
```

`report.save()`를 사용하여 규칙 바인딩 리소스를 포함하여 완전한 스냅 샷을 보존합니다. 셀 공식 텍스트 만 저장하면 공공 이름과 소스 ID 사이에 매핑을 잃습니다. 저장 및로드 소스 워크북 데이터를 별도로 저장하십시오.

소스 워크북이 언로드 된 후, 일반 참조로드 된 워크북은 더 이상 그것을 읽을 수 없습니다. 프로 외부 참조는 구성 된 데이터 제공 업체 및 사용 가능한 캐시가 필요한 데이터를 공급 할 때만 계산하는 것을 계속합니다. 바인딩에는 소스 데이터가 포함되어 있지 않으며 오프라인 계산을 보장하지 않습니다. 이전에 표시된 결과는 데이터가 현재임을 증명하지 않습니다.

더 이상 필요하지 않을 때 Pro 바인딩을 제거하십시오:

```typescript
univerAPI.getFormula().removeExternalReference({
  unitId: report.getId(),
  qualifier: 'Sales Source',
})
```

바인딩을 제거하거나 기존의 공식을 다시 작성하지 않습니다. 다음 계산은 자신의 이름을 다시 해결합니다. 로드 된 워크북이 여전히 이름을 일치하면 참조는 해결을 유지할 수 있습니다. 아무것도 일치하면 `#REF!`를 반환합니다. 소스 altogether를 참조하거나 셀 수식뿐만 아니라 수정을 취소하려면.

[FFormula 참조 바인딩 APIs](/reference/facade/formula)를 전체 매개 변수와 반환 값에 대한 참조.

## 3D 참조

3D 참조는 워크북에서 연속 작업 시트를 경간합니다. 그것은 다른 워크북에 대한 참조와 구별됩니다 :

```text
=SUM(Jan:Mar!B2:C3)
=SUM('Jan':'Mar'!B2)
```

범위에는 `Jan`, `Mar` 및 알파벳 순서 보다는 오히려 workbook 순서에서 각 장이 포함됩니다. 주문 작업표는 범위를 집계하는 것을 바꾸어서, 그래서 reordering 후에 범위를 확인합니다.

### 범위 선택기 대화 상자 표시

`@univerjs/sheets-formula-ui/facade`는 `univerAPI.showRangeSelectorDialog`를 추가합니다. 사용자가 하나 이상의 범위를 선택해야 할 사용자 정의 UI는 공식 관련 패널 사용과 동일한 선택기를 열 수있는이 API를 호출 할 수 있습니다.

```typescript
const workbook = univerAPI.getActiveWorkbook()
const worksheet = workbook?.getActiveSheet()

if (workbook && worksheet) {
  await univerAPI.showRangeSelectorDialog({
    unitId: workbook.getId(),
    subUnitId: worksheet.getSheetId(),
    initialValue: [
      {
        unitId: workbook.getId(),
        sheetName: worksheet.getSheetName(),
        range: worksheet.getRange('A1:B2').getRange(),
      },
    ],
    maxRangeCount: 2,
    supportAcrossSheet: true,
    callback: (ranges, isCancel) => {
      console.log(ranges, isCancel)
    },
  })
}
```

### 데이터 초기화 시 수식 계산 모드 설정

```typescript
const formulaEngine = univerAPI.getFormula()
formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
```

`Starting` 수명주기 후 호출하면이 API는 다음 시간 Univer 시트가 생성됩니다.

Univer 시트의 현재 초기화 중에 적용하려면 다음 예에서 `Ready` 수명주기 전에 전화하십시오.

```typescript
univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === LifecycleStages.Starting) {
    const formulaEngine = univerAPI.getFormula()
    formulaEngine.setInitialFormulaComputing(CalculationMode.FORCED)
  }
})
```

### 반복 계산 [#iterative-calculation]

Iterative 계산은 스냅샷의 `calculationSettings` 필드에 저장된 작업 책 수준 조정입니다. 그것은 기본적으로 비활성화되어 있으므로 원형 공식은 캐시된 값을 유지하거나 값이 캐시되지 않을 때 0을 유지합니다. 의도적으로 원형 참조를 포함시키는 모델에 대해 사용 가능 합니다.

| 옵션 | 기본값 | 동작 |
| --- | --- | --- |
| `iterativeCalculation` | `false` | 원형 참조를 철저히 구합니다. |
| `maxIterations` | `100` | 1과 32767 사이의 정수. |
| `maxChange` | `0.001` | 무한, 긍정적인 융합 임계 값. 이 금액보다 더 이상 원형 그룹 변경에서 모든 수치 결과가 될 때 반복. |

workbook Facade를 통해 모든 세 가지 설정을 업데이트하십시오. 명령은 undo 및 redo뿐만 아니라 협업을 지원하며, 워크북이 사용할 수 없거나 편집 할 수없는 경우 `false`를 반환합니다. 잘못된 설정은 기본 값으로 정상화됩니다.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const applied = workbook.setCalculationSettings({
  iterativeCalculation: true,
  maxIterations: 100,
  maxChange: 0.001,
})
if (!applied) throw new Error('Could not update calculation settings')

console.log(workbook.getCalculationSettings())
```

`calculationSettings`는 또한 `createWorkbook()`를 호출할 때 공급될 수 있습니다. 각 워크북은 그것의 자신의 조정을 지킵니다. 공식 리본은 계산 선택권을 통해서 동일한 통제를 드러냅니다.

원형 설정 진단은 계산 결과가 적용된 후 읽을 수 있습니다. `getCircularReferences()`는 계산을 시작하지 않습니다. 결과에는 worksheet ID, 0기반 행 및 열 좌표, 그룹 ID, 반복 수 및 사용 가능한 경우의 융합 정보가 포함됩니다.

```ts
const formula = univerAPI.getFormula()
formula.executeCalculation()
await formula.onCalculationResultApplied()
console.table(workbook.getCircularReferences())
```

### 수식 문자열 실행 결과 가져오기

비동기적으로 수식의 배치를 실행하고 계산 결과를받을 :

```typescript
const formulaEngine = univerAPI.getFormula()
const formulas = {
  Book1: {
    Sheet1: {
      2: {
        3: [
          // Full formula:
          '=SUM(A1:A10) + SQRT(D7)',

          // Decomposed sub-formulas (each one can be evaluated independently):
          'SUM(A1:A10)', // sub-formula 1
          'SQRT(D7)', // sub-formula 2
          'A1:A10', // range reference
          'D7', // single-cell reference
        ],
      },
      4: {
        5: ['=A2 + B2 + SQRT(C5)', 'A2', 'B2', 'SQRT(C5)'],
      },
    },
  },
}
const result = await formulaEngine.executeFormulas(formulas)
console.log(result)
```

## 수식 값의 의미 [#formula-value-semantics]

`ISBLANK(A1)`는 참조된 세포가 내용이 비어있을지 여부, 뿐만 아니라 표시된 결과가 비어 있는지 여부를 검사합니다. 형식을 유지 한 것을 포함하는 명확한 세포는 공백입니다; `""`를 반환하는 공식은 아닙니다. 리터 `ISBLANK("")`는 또한 `FALSE`입니다. `UNIQUE`는 케이스 감도 없이 원본을 비교하고 첫번째 철자 유지합니다. `PROPER`는 악센트 라틴, 그리스 및 Cyrillic 편지를 포함하여 Unicode 편지를 인식합니다. `AVERAGE`는 `FILTER`와 같은 기능에 의해 반환된 전체 배열을 집계합니다.

```text
=ISBLANK("")                         → FALSE
=UNIQUE({"Univer";"univer";"Sheets"})  → {"Univer";"Sheets"}
=PROPER("élise müller")               → Élise Müller
=AVERAGE({3;7})                      → 5
```
