셀 값, 공식 또는 형식을 편집 한 후, 이전 버전을 검토하기 위해 역사 패널을 열고, 변경 사항을 비교하고, 해당 권한을 가지고있는 경우 버전을 복원합니다. 역사는 서버에서 persisted 버전을 읽습니다. Undo 및 redo는 현재 편집 세션에만 적용하고 역사 서비스를 필요로하지 않습니다.

## 협업 및 기록 서비스 준비

[협업 통합](/server/collaboration/browser-integration) 및 [인증 구성](/server/license)를 먼저 완료하면 두 세션이 동일한 시트 문서를 편집하고 다시로드를 살아남을 수 있다는 것을 확인합니다.

[Office 협업 확장](/server/collaboration/extensions)와 [연혁 예](/server/collaboration/examples#history)는 역사 저장과 권한을 연결하는 방법을 설명합니다. 핵심 협력은 자신의 역사가 활성화되지 않습니다. 백엔드는 또한 역사 목록, 버전 내용 및 복원을 제공해야합니다.

기존 제품, 라이센스 및 협업 설정에 이 구성을 추가하십시오. 미리 설정 또는 기존 구성이 이미이 플러그인을 등록하면 두 번째 시간을 등록하는 대신 구성을 업데이트합니다.

## 플러그인 모드 [#plugin-mode]

### 설치

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/sheets-history @univerjs-pro/sheets-history-ui
```

### 사용법

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSheetsHistoryPlugin } from '@univerjs-pro/sheets-history'
import { UniverSheetsHistoryUIPlugin } from '@univerjs-pro/sheets-history-ui'
import HistoryLocale from '@univerjs-pro/sheets-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/sheets-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSheetsHistoryPlugin)
univer.registerPlugin(UniverSheetsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### 플러그인 설정

`UniverEditHistoryPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |

`UniverSheetsHistoryUIPlugin`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 기록 서비스의 기본 URL입니다. |
| `univerContainerId` | `string` |  | 편집기 컨테이너의 DOM ID입니다. |

응용 프로그램의 실제 역사 엔드포인트와 `/api/history`를 대체하고 클라이언트가 보낸 요청을 최종 포인트 일치한다는 것을 보장합니다. `historyServerUrl` 값 모두 동일해야합니다. 편집기 컨테이너의 DOM ID에 `univerContainerId`을 설정하고 편집기가 사용하는 로컬을로드합니다.

시트 역사는 또한 `UniverCollaborationClientUIPlugin`가 공동 설정에 등록해야합니다.

## 모바일 지원 [#mobile-support]

[모바일 편집기](/guides/sheets/getting-started/installation#mobile-support)를 먼저 설정하십시오. 이 페이지의 플러그인 모드 설정에서 동일한 패키지에서 모바일 내보내기로 아래 데스크탑 등록을 대체하고 **문서 열기**을 수행하십시오. 모델 플러그인, 스타일, 로컬 및 Facade 가져 오기를 유지하고 하나의 변형 만 등록하십시오.

| 패키지 | 데스크톱 등록 | 모바일 등록 |
| --- | --- | --- |
| `@univerjs-pro/sheets-history-ui` | `UniverSheetsHistoryUIPlugin` | `UniverSheetsHistoryMobileUIPlugin` |

## 프리셋 모드 [#preset-mode]

### 설치

```package-install
npm install @univerjs/preset-sheets-collaboration
```

### 사용법

`UniverSheetsCollaborationPreset`는 역사 UI와 플러그인을 포함합니다. 기존 편집기 및 라이센스 설정을 유지하십시오. 미리 설정이 이미 등록되면 미리 설정 또는 역사 플러그인을 두 번째로 등록하는 것보다 오히려 업데이트하십시오.

```ts
import { UniverSheetsCollaborationPreset } from '@univerjs/preset-sheets-collaboration'
import CollaborationLocale from '@univerjs/preset-sheets-collaboration/locales/en-US'
import '@univerjs/preset-sheets-collaboration/lib/index.css'

const collaborationPreset = UniverSheetsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### 프리셋 설정

`UniverSheetsCollaborationPreset`

| <span data-config-options="">옵션</span> | 유형 | 기본값 | 동작 |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | 공동 편집 서버의 기본 URL입니다. |
| `univerContainerId` | `string` | `'app'` | 편집기 컨테이너의 DOM ID입니다. |

기존 `createUniver()` 통화의 `presets` 배열에 `collaborationPreset`를 추가하고 `CollaborationLocale`을 매칭 로컬 항목에 병합합니다. `universerEndpoint`는 서버와 `univerContainerId`의 기본 URL로 설정하여 편집기 컨테이너 ID에 통합합니다. 미리 설정은 `{universerEndpoint}/universer-api/history`로 기록 URL을 구성하므로 사용자 정의 `historyServerUrl`XZ 또는 ZX`viewerPlugins`가 필요한 경우 플러그인 모드를 사용합니다.

## 버전 확인 및 복원

편집 메뉴에서 역사 패널을 열고 컨텐츠와 변경 사항을 검사하는 버전을 선택하십시오. 복원은 현재 공유 문서를 다시 작성, 그래서 복원 권한을 가진 사용자만 수행 할 수 있어야, 서버는 그 권한을 시행해야합니다.

통합을 확인하려면 셀 값, 공식, 또는 일부 형식을 편집하고 변경을 확인하기 위해 협력을 기다립니다. 그리고 그 후 역사 목록과 버전 콘텐츠를 검사합니다. 응용 프로그램을 열고 모든 데이터가 지속된다는 것을 확인하기 위해 서비스를 다시 시작하십시오. 이전 버전을 복원하고 다른 브라우저 세션이 복원 된 상태를 확인합니다.

목록이 비어있는 경우, 역사가 모든 문서에 기록되었는지 확인한 후 문서 ID 및 서비스 URL을 확인하십시오. 보기 작품이 아니라 복원 실패하면 복원 권한 및 협업 연결을 확인하십시오. 이전 버전이 삭제 된 데이터를 포함 할 수 있기 때문에, 이전 버전이 승인해야합니다.

## 스냅샷 비교 [#compare-snapshots]

리뷰 화면을 구축하거나 AI 에이전트로 변경 사항을 전달하려면 `compareUnitData()`를 호출하거나 `prepareUnitComparison()`로 한 번 비교를 계산하고 반복적으로 쿼리하십시오. 제품의 역사 플러그인을 등록하고 Facade 항목을 가져 와서 `beforeSnapshot` 및 `afterSnapshot`와 같은 두 개의 완전히 Materialized 스냅 샷을 전달하십시오. 비교는 읽기 전용이며, 역사 서비스가 필요 없으며 복원하거나 내용과 상호 작용하지 않습니다.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SHEET,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

`scopes`을 읽을 수 있는 전망을 발견하기 위하여, 그 후에 비교를 rerunning 없이 결과를 거르기 위하여 그(것)들을 `query()`에 그들 중 하나를 통과하십시오. 페이지는 과태에 의하여 100개의 품목을 돌려보내고 1,000까지 돌려보냅니다. 남아있는 품목을 검색하기 위하여 `offset`와 함께 `page.hasMore`를 사용하십시오. `summary`는 품목이 거르는 때 전체 비교를 설명합니다. 완전한 비교로 결과를 대우하기 전에 `diagnostics.readiness`와 `diagnostics.codes`를 검사하십시오. 편집기 없이 Node.js 또는 CLI 사용법을 위해, [headless 비교 API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)를 보십시오.
