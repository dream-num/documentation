Un tableau de pivot réduit une large gamme de données à un résumé compact. Il permet de résumer, d'analyser et de visualiser les données, et il fournit les opérations de données et les options de formatage qui rendent le résultat plus facile à comprendre.

## Introduction

Les tableaux pivots sont généralement utilisés à l'une des quatre fins suivantes :

- Résumant une large gamme de données pour rendre l'image globale visible.
- Analyser les données pour identifier les modèles et les relations.
- Explorer les données pour découvrir les règles et les tendances.
- Visualiser le résultat pour le rendre plus facile à comprendre.

Une table de pivot se compose de trois parties:

- Les étiquettes de lignes regroupent les données par ligne.
- Les étiquettes des colonnes regroupent les données par colonne.
- Les valeurs résument les nombres à chaque intersection.

Les étiquettes de lignes, les étiquettes de colonnes et les valeurs peuvent être réaménagées à tout moment selon les besoins de l'analyse.

![Missing Locale](./pivot-table/pivot.png)

### Source de données

Dans les feuilles Univer, une table pivote prend soit une feuille de travail, soit une plage de données comme source.

La première ligne de la source devient l'étiquette des colonnes, et les lignes restantes contiennent les données. Les lignes vides et les colonnes vides interfèrent avec cette disposition, de sorte que la source doit être tenue en ordre.

Le type de données de chaque colonne est détecté automatiquement, ce qui détermine comment la table pivote peut utiliser ce champ. Si une colonne contient des types mixtes, la colonne entière est traitée comme une chaîne.

Les tables de pivots suivent les changements dans leur source : lorsqu'une valeur dans les données source change, le tableau se met à jour automatiquement.

### Filtrage

Les étiquettes de lignes et les étiquettes de colonnes peuvent être filtrées. Un champ de filtres séparé est également disponible; il ne participe pas à la mise en page de lignes et de colonnes du rapport, mais les valeurs sélectionnées dans celui-ci restreignent encore les données.

Deux méthodes de filtrage sont disponibles :

- Le filtrage des étiquettes s'applique aux éléments de la dimension actuelle de l'étiquette; dans une dimension provinciale, par exemple, les provinces peuvent être filtrées.
- Le filtrage de valeur nécessite une dimension de valeur et des filtres sur le résultat agrégé; par exemple, les données dont les ventes sont inférieures à 1000 peuvent être cachées.

### Tri

Le tri s'applique uniquement aux champs ligne et colonne, dans les deux sens. Les comparaisons utilisent la méthode `localCompare`. Des méthodes de comparaison supplémentaires, le tri pinyin parmi eux, sont prévues.

Deux méthodes de tri sont disponibles:

- Le tri d'étiquettes s'applique aux éléments de la dimension actuelle de l'étiquette; dans une dimension provinciale, ce genre d'étiquette par nom de province.
- Le tri de la valeur nécessite une dimension de valeur et des tris sur le résultat agrégé, par exemple par le montant des ventes.

### Agrégation

Les tableaux de pivots supportent les 11 méthodes d'agrégation Excel offre : somme, nombre, nombre de données, moyenne, maximum, minimum, factorial, écart-type, variance, écart-étalon de population et variance de population.

Plusieurs dimensions de valeur peuvent être ajoutées, et à la fois la zone qu'elles occupent (position de valeur) et leur ordre dans cette zone (indice de valeur) peuvent être configurés.

Cette mise en page est complexe, donc seule la vue de table est prise en charge actuellement. D'autres vues seront ajoutées en fonction de la demande.

### Exploration détaillée

Le drill down fait référence à un double-clic sur une cellule dans la zone de valeur d'une table de pivot pour voir le détail derrière cette cellule. Le détail énumère les lignes qui ont produit le nombre, ce qui permet de remonter un total aux données sources.

### Regroupement

Univer Sheets prend en charge les regroupements par date, numériques et manuels.

- Groupe de dates : utilisez [`setDateGroupType`](/reference/facade/pivot-table#setdategrouptype) pour un champ de dates dérivé. Pour grouper un champ d'étiquettes de dates d'origine par unité de calendrier, définissez [`setDateGroupingMode`](/reference/facade/pivot-table#setdategroupingmode) à `univerAPI.Enum.PivotDateGroupingMode.ExcelLike`, puis appelez [`setExcelDateGroup`](/reference/facade/pivot-table#setexceldategroup).
- Groupe numérique : passez un identifiant de champ d'étiquette et les paramètres d'intervalle à [`setNumberGroup`](/reference/facade/pivot-table#setnumbergroup).
- Groupe manuel : passez l'ID du champ source d'origine et les groupes de membres dactylographiés à [`setManualGroups`](/reference/facade/pivot-table#setmanualgroups). Chaque groupe nécessite au moins deux membres ; un tableau vide supprime tous les groupes manuels pour ce champ.

Les tables de filtre [Éclairage et échéancier](/guides/sheets/features/slicer) et les rapports de pivot interactifs.

### Enregistrement des plugins

Le plugin table pivot peut être enregistré de l'une des deux manières, selon le nombre de calculs que le processus principal doit retenir.

**Processus principal seulement**

Ce mode est adapté aux tâches légères et aux opérations simples : la configuration du plugin peut rester vide et l'importation de `UniverSheetsPivotTablePlugin` est suffisante.

```typescript
univer.registerPlugin(UniverSheetsPivotTablePlugin)
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)
```

**Principaux procédés et processus ouvriers**

Lorsque le calcul du pivot est lourd, enregistrez le plugin à la fois dans le processus principal et le processus du travailleur. Le plugin peut ensuite utiliser une mise en page multi-fils pour la distribution et le calcul des données, qui déplace la plupart du calcul hors du processus principal et améliore les performances globales.

Dans ce mode, le processus principal gère la distribution de données, la synchronisation et le rendu, tandis que le processus ouvrier effectue le calcul complexe. Le mode est sélectionné dans l'appel d'enregistrement par la configuration.

```typescript
// main process file
// Setting notExecuteFormula to true indicates that the main process does not perform calculations. It is only responsible for data distribution, synchronization, and rendering.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: true })
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)

// web worker process file
// Setting notExecuteFormula to false indicates that the worker process performs the calculations.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: false })
```

Si vous avez une licence commerciale pour Univer, consultez [Utilisation de la licence dans le client](/server/license#in-plugin-mode) pour la configuration côté client.

### Ajouter un tableau croisé dynamique

[`FWorkbook.addPivotTable`](https://docs.univer.ai/reference/facade/workbook#addpivottable) ajoute une table pivotante et renvoie une instance `FPivotTable` quand elle réussit.

```typescript
// should ensure the sheet range A1:G9 is not empty
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()
const sheetName = fSheet.getSheetName()
const sourceInfo = {
  unitId,
  subUnitId,
  sheetName,
  range: {
    startRow: 0,
    startColumn: 0,
    endRow: 8,
    endColumn: 6,
  },
}
const anchorCellInfo = {
  unitId,
  subUnitId,
  row: 20,
  col: 8,
}
const fPivotTable = await fWorkbook.addPivotTable(sourceInfo, univerAPI.Enum.PositionTypeEnum.Existing, anchorCellInfo)
const pivotTableId = fPivotTable.getPivotTableId()
// add flag to avoid add pivot fields multiple times
let hasAdded = false
// the addPivotTable is async, you can add pivot fields after the pivot table is added
univerAPI.addEvent(univerAPI.Event.PivotTableRendered, async (params) => {
  if (!hasAdded && params.pivotTableId === pivotTableId) {
    hasAdded = true
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Row, 0)
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Value, 0)
  }
})
```

### Obtenir un tableau croisé dynamique

[`FWorkbook.getPivotTableByCell`](https://docs.univer.ai/reference/facade/workbook#getpivottablebycell) trouve une table de pivot par sa cellule d'ancrage et renvoie une `FPivotTable` si la cellule cible se trouve à l'intérieur d'une table de pivot.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()

// get pivot table by the cell in FWorkbook.
const fPivotTable = fWorkbook.getPivotTableByCell(unitId, subUnitId, 0, 8)

// get pivot table by the cell in FWorksheet.
const pivotTable2 = fSheet.getPivotTableByCell(0, 8)
```

### Écouteurs d’événements

Les définitions complètes du type d'événement sont dans [Événements](https://docs.univer.ai/reference/facade/events).

`univerAPI.Event.BeforePivotTableAdd` s'allume avant d'ajouter une table pivotante.

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.BeforePivotTableAdd, (params) => {
  const { positionType, targetCellInfo } = params
  if (positionType === univerAPI.Enum.PositionTypeEnum.Existing && targetCellInfo.sheetName === 'Sheet 1') {
    // Cancel the pivot table adding operation
    params.cancel = true
    console.log(`The pivot table can't be added to the sheet ${targetCellInfo.sheetName}`)
  }
})

// Remove the event listener, use `disposable.dispose()`
```

`univerAPI.Event.PivotTableAdded` s'allume après l'ajout d'une table de pivot.

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.PivotTableAdded, (params) => {

  const pivotTable = fWorkbook.getPivotTableById(pivotTableId)
  const valueSetting = pivotTable.getValueSetting(valueId)
  console.log(`The source name ${valueSetting.sourceName} the display name ${valueSetting.displayName}`)
})

// Remove the event listener, use `disposable.dispose()`
```

## Zone de sortie occupée [#blocked-output]

Le rapport a besoin d'espace pour s'étendre. Le contenu de cellules existantes, les cellules fusionnées ou une autre table de pivot peut bloquer la zone de sortie. Effacer l'obstruction ou déplacer le rapport vers une plage vide.

## Afficher les valeurs sous forme de [#show-values-as]

`setShowDataAs()` sur un champ de valeur change la valeur que le champ affiche : sa part d'une ligne, d'une colonne ou d'un total global, ou sa différence par rapport à un élément de base. Seul le calcul affiché change; les données sources ne sont pas modifiées. `getShowDataAs()` lit le réglage courant, et `resetShowDataAs()` restaure le calcul normal.

```ts
const valueId = fPivotTable.getFieldIdsByArea(
  univerAPI.Enum.PivotTableFiledAreaEnum.Value,
)[0]
if (valueId) {
  await fPivotTable.setShowDataAs(valueId, {
    type: univerAPI.Enum.PivotShowAsTypeEnum.percentOfGrandTotal,
  })
  console.log(fPivotTable.getShowDataAs(valueId))
}
```

L'exemple suppose un `fPivotTable` existant. L'argument est un ID de champ de valeur, et non un ID de colonne source ou de champ de ligne. Les modes de différence et d'exécution-total nécessitent également les paramètres correspondants du champ de base et de l'élément de base.

## Copier les tableaux croisés dynamiques avec une feuille [#copy-with-worksheet]

Avec le plugin pivot enregistré, dupliquer une feuille de travail copie également les tables pivots sur cette feuille de travail et préserve leur configuration de champ. Chaque copie reçoit un nouvel ID pivotable. Une plage de sources située sur la feuille de travail copiée est redirigée vers la nouvelle feuille de travail, tandis qu'une source sur une autre feuille de travail ou un cahier de travail conserve sa référence originale. Les tables copiées participent à l'annulation et à la recopie de la copie de la feuille de calcul.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const copiedSheet = workbook.duplicateActiveSheet()
console.log(copiedSheet.getSheetName())
```

## Filtres multiples et conditions de date [#multiple-filters]

`setOptions({ allowMultipleFilters: true })` permet à une sélection de membres, à une condition d'étiquette ou de date, ainsi qu'à un filtre de valeur de coexister sur le même champ. Si l'option est omise ou définie à `false`, un nouveau filtre remplace le précédent au lieu de l'ajouter; désactiver l'option tandis que les catégories de conflit effacent les filtres de rapport. Un champ accepte toujours au plus un filtre de valeurs.

`setDateFilter()` accepte les opérateurs à date fixe, y compris `dateEqual`, `dateOlderThan`, et `dateBetween`. `expected` détient des valeurs série Excel dans le système de date du cahier de travail, et une condition entre deux prend deux d'entre eux. `useWholeDay: true` ignore l'heure de la journée et compare des jours entiers; si l'option est omise ou réglée à `false`, la comparaison utilise des séries exactes. L'argument est l'ID du champ de déclaration, et non un index de colonne source. L'exemple suivant se fonde sur la `fPivotTable` ci-dessus et une colonne source nommée `Date`.

`getDateFilter()` retourne une copie détachée de la condition, et `clearDateFilter()` efface la condition de date et rien d'autre. Les deux commandes participent à l'annulation et à la collaboration. Vérifiez la valeur booléenne qu'elles retournent : un trancheur actif peut empêcher l'application d'un filtre incompatible.

```ts
if (!fPivotTable) throw new Error('PivotTable not found')
await fPivotTable.setOptions({ allowMultipleFilters: true })

const dateField = Object.values(fPivotTable.getConfig()?.fieldsConfig.dimension ?? {})
  .find((field) => field.sourceName === 'Date')
if (!dateField) throw new Error('Add the Date field to the report first')

await fPivotTable.setDateFilter(dateField.id, {
  operator: univerAPI.Enum.ST_PivotFilterOperatorEnum.dateEqual,
  expected: 45293,
  useWholeDay: true,
})
console.log(fPivotTable.getDateFilter(dateField.id))
await fPivotTable.clearDateFilter(dateField.id)
```

## GETPIVOTDATA [#getpivotdata]

`=GETPIVOTDATA("Sales",$I$1,"Region","East")` lit un agrégat à partir d'un rapport de pivot visible dont la cellule supérieure gauche est I1. Le champ de valeur peut être spécifié par sa légende affichée ou par son nom de source. L'ancre doit être une référence de cellule unique, et les paires champ/item doivent être fournies en entier.

L'implémentation courante ne lit que le rapport visible, balayant jusqu'à 200 lignes vers le bas et 50 colonnes à partir de l'ancre. Elle ne demande pas les enregistrements de sources cachées. Une paire de champs/éléments qui ne correspond pas, ou un résultat non disponible, renvoie `#REF!`. Un nombre d'arguments incorrects, ou un ancre qui n'est pas une cellule unique, renvoie `#VALUE!` .
