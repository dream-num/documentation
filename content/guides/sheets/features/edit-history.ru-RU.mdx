После редактирования значений ячеек, формул или форматирования откройте панель истории, чтобы просмотреть более ранние версии, сравнить изменения и восстановить версию, когда у вас есть соответствующее разрешение. История читает версии, сохраненные на сервере. Отменить и переделать применяются только к текущей сессии редактирования и не требуют службы истории.

## Подготовка совместного редактирования и истории

Сначала заполните [Интеграция сотрудничества](/server/collaboration/browser-integration) и [Конфигурация лицензии](/server/license), а затем проверьте, что два сеанса могут редактировать один и тот же документ Sheets и что изменения выдерживают перезагрузку.

[Расширение сотрудничества с офисом](/server/collaboration/extensions) и [Пример истории](/server/collaboration/examples#history) описывают, как подключить хранилище истории и разрешения. Основная коллаборация не позволяет историю самостоятельно. Бэкэнд также должен предоставлять списки истории, содержание версии и восстановление.

Добавьте эту конфигурацию к существующему продукту, лицензии и настройке совместной работы.Если предустановленная или существующая конфигурация уже регистрирует эти плагины, обновите эту конфигурация вместо того, чтобы регистрировать их во второй раз.

## Режим плагина [#plugin-mode]

### Установка

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/sheets-history @univerjs-pro/sheets-history-ui
```

### Использование

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSheetsHistoryPlugin } from '@univerjs-pro/sheets-history'
import { UniverSheetsHistoryUIPlugin } from '@univerjs-pro/sheets-history-ui'
import HistoryLocale from '@univerjs-pro/sheets-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/sheets-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSheetsHistoryPlugin)
univer.registerPlugin(UniverSheetsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Настройка плагинов

`UniverEditHistoryPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |

`UniverSheetsHistoryUIPlugin`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | Базовый URL службы истории. |
| `univerContainerId` | `string` |  | DOM ID контейнера редактора. |

Замените `/api/history` на конечную точку истории приложения и убедитесь, что конечная точка соответствует запросам, которые отправляет клиент. Оба значения `historyServerUrl` должны быть идентичны. Установите `univerContainerId` в DOM-идентификатор контейнера редактора и загрузите локализацию, которую использует редактор.

История листов также требует, чтобы `UniverCollaborationClientUIPlugin` был зарегистрирован в настройках совместной работы.

## Режим предустановки [#preset-mode]

### Установка

```package-install
npm install @univerjs/preset-sheets-collaboration
```

### Использование

`UniverSheetsCollaborationPreset` включает в себя пользовательский интерфейс истории и плагины, от которых он зависит. Сохраняйте существующий редактор и настройку лицензии. Если предустановка уже зарегистрирована, обновите ее, а не регистрируйте предустанавливаемые или исторические плагины во второй раз.

```ts
import { UniverSheetsCollaborationPreset } from '@univerjs/preset-sheets-collaboration'
import CollaborationLocale from '@univerjs/preset-sheets-collaboration/locales/en-US'
import '@univerjs/preset-sheets-collaboration/lib/index.css'

const collaborationPreset = UniverSheetsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### Настройка пресетов

`UniverSheetsCollaborationPreset`

| <span data-config-options="">Параметр</span> | Тип | По умолчанию | Действие |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | Базовый URL сервера совместной работы. |
| `univerContainerId` | `string` | `'app'` | DOM ID контейнера редактора. |

Добавьте `collaborationPreset` в массив `presets` существующего вызова `createUniver()` и объедините `CollaborationLocale` с соответствующим входом в локальную строку. Установите `universerEndpoint` на базовый URL сервера и `univerContainerId` к идентификатору контейнера редактора. Предустановленный URL-адрес истории в виде `{universerEndpoint}/universer-api/history`, поэтому используйте режим плагина, когда требуется пользовательский `historyServerUrl` или `viewerPlugins`. Дополнительные службы, описанные выше, остаются необходимыми.

## Просмотр и восстановление версий

Откройте панель истории из меню редактора и выберите версию, чтобы проверить ее содержимое и изменения. Восстановление переписывает текущий общий документ, поэтому только пользователи с разрешением на восстановление должны быть в состоянии выполнить его, и сервер должен обеспечить соблюдение этого разрешения.

Чтобы проверить интеграцию, отредактировать значение ячейки, формулу или некоторое форматирование, дождитесь совместной работы, чтобы подтвердить изменение, а затем проверьте список истории и содержание версии. Откройте приложение и перезагрузите сервис, чтобы подтвердить, что все данные сохранились. Восстановите более раннюю версию и подтвердите, что другая сессия браузера получает восстановленное состояние.

Если список пуст, сначала проверьте, была ли история записана для этого документа вообще, затем проверьте идентификатор документа и URL-адрес службы. Если просмотр работает, но восстановление не удается, проверьте разрешения на восстановление и соединение для совместной работы. Чтение истории также требует авторизации, потому что более старые версии могут содержать данные, которые с тех пор были удалены.

## Сравнение снимков [#compare-snapshots]

Чтобы построить экран обзора или передать изменения агенту ИИ, позвоните `compareUnitData()` или вычислите сравнение один раз с `prepareUnitComparison()` и запросите его несколько раз. Зарегистрируйте плагин истории продукта и импортируйте запись Facade, затем передайте два полностью материализованных снимка того же устройства, что и `beforeSnapshot` и `afterSnapshot`. Сравнение только для чтения, не требует обслуживания истории и не восстанавливает и не объединяет контент.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SHEET,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Прочтите `scopes`, чтобы найти доступные просмотры, затем передайте один из них `query()` для фильтрации результата без повторного сравнения. Страница возвращает 100 элементов по умолчанию и до 1000. Используйте `page.hasMore` вместе с `offset` чтобы извлечь оставшиеся элементы. `summary` описывает все сравнение даже при фильтрации элементов. Проверьте `diagnostics.readiness` и `diagnostics.codes` перед тем, как рассматривать результат как полное сравнение. Для использования Node.js или CLI без редактора см. [безголовое сравнение API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
