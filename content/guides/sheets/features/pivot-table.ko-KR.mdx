Pivot 테이블은 컴팩트한 요약에 큰 데이터 범위를 줄입니다. 그것은 요약, 분석 및 시각화 데이터를 지원하며, 결과가 쉽게 이해할 수 있도록 데이터 작업 및 포맷 옵션을 제공합니다.

## 소개

피벗 테이블은 일반적으로 4개의 목적을 위해 사용됩니다:

- 큰 데이터 범위를 요약하면 전체 그림이 볼 수 있습니다.
- 패턴과 관계를 식별하는 데이터를 분석합니다.
- 규칙과 트렌드를 발견하는 데이터를 탐험.
- 결과를 시각화하여 쉽게 이해할 수 있습니다.

피벗 테이블은 3개 부품으로 이루어져 있습니다:

- 행 라벨 그룹은 행에 의해 데이터입니다.
- 칼럼 라벨 그룹 열에 의해 데이터.
- 각 교차로에서 숫자를 합산합니다.

행 라벨, 열 라벨 및 값은 분석이 필요한 한 번에 리어링 할 수 있습니다.

![로케일 없음](./pivot-table/pivot.png)

### 데이터 원본

Univer 시트에서 피벗 테이블은 작업 시트 또는 소스로 데이터 범위가 걸립니다.

소스의 첫 번째 행은 열 라벨이되고 나머지 행은 데이터를 포함합니다. 빈 행과 빈 열은이 레이아웃과 방해하므로 소스는 호랑이를 유지해야합니다.

각 열의 데이터 유형은 자동으로 감지되어 피벗 테이블이 필드를 사용할 수있는 방법을 결정합니다. 열이 혼합 유형이 포함되면 전체 열은 문자열로 처리됩니다.

Pivot 테이블 트랙은 소스에서 변경됩니다. 소스 데이터 변경의 값이면 테이블 업데이트가 자동으로 업데이트됩니다.

### 필터링

행 라벨과 열 라벨 모두 필터링 할 수 있습니다. 별도의 필터 필드도 사용할 수 있습니다. 보고서의 행 및 열 레이아웃에 참여하지 않지만 여전히 데이터를 제한하는 값이 없습니다.

2개의 거르는 방법은 유효합니다:

- 라벨 필터링은 현재 라벨 치수의 항목에 적용됩니다. 예를 들어, 개별 지방은 필터링 할 수 있습니다.
- 값 필터링은 값 치수와 필터를 집계 결과에 필요로 합니다. 예를 들어, 1000 미만의 데이터는 숨겨져 있습니다.

### 정렬

정렬은 행과 열 필드에만 적용됩니다. 방향 중 하나. 비교는 `localCompare` 방법을 사용합니다. 추가 비교 방법, 그들 중 정렬 핀틴은 계획되어 있습니다.

두 가지 정렬 방법은 다음과 같습니다:

- 상표 분류는 현재 상표 차원의 품목에 적용합니다; 지방 차원에서, 이 종류는 지방명으로 분류합니다.
- Value Sorting은 값의 치수와 일종의 집계 결과가 필요합니다. 예를 들어 판매량에 따라.

### 집계

피벗 테이블은 11 집계 방법을 지원 Excel 제공 : 정상, 카운트, 데이터 카운트, 평균, 최대, 최소, Factorial, 표준 편차, 가변, 인구 표준 편차 및 인구 차이.

몇 가지 값 치수를 추가 할 수 있으며, 해당 영역 내에서 해당 영역 (값 인덱스)의 주문이 구성 될 수 있습니다.

이 레이아웃은 단지, 그래서 테이블보기는 현재 지원됩니다. 추가 전망은 수요에 따라 추가됩니다.

### 드릴다운

드릴 다운은 피벗 테이블의 값 영역에서 셀을 더블 클릭하고 그 셀 뒤에 세부 사항을 볼 수 있습니다. 세부 사항은 번호를 생성 한 행을 나열하여 소스 데이터로 추적 할 수 있습니다.

### 그룹화

Univer Sheets는 날짜, 숫자 및 수동 그룹화를 지원합니다.

- 날짜 그룹화: 생성한 날짜 분야를 위한 [`setDateGroupType`](/reference/facade/pivot-table#setdategrouptype)를 이용합니다. 달력 단위에 의하여 본래 날짜 상표 분야를, 놓으십시오 [`setDateGroupingMode`](/reference/facade/pivot-table#setdategroupingmode)에 `univerAPI.Enum.PivotDateGroupingMode.ExcelLike`를, 그 후에 [`setExcelDateGroup`](/reference/facade/pivot-table#setexceldategroup)를 부릅니다.
- 숫자 그룹화: 라벨 필드 ID와 [`setNumberGroup`](/reference/facade/pivot-table#setnumbergroup)의 간격 설정을 전달합니다.
- 수동 그룹: 원래 소스 필드 ID 및 [`setManualGroups`](/reference/facade/pivot-table#setmanualgroups)에 유형 회원의 그룹을 전달합니다. 각 그룹은 적어도 두 명의 회원이 필요합니다. 빈 어레이는 해당 필드에 대한 모든 수동 그룹을 제거합니다.

[슬라이서 및 타임라인](/guides/sheets/features/slicer) 필터 테이블과 피벗은 보고는 상호 작용으로.

### 플러그인 등록

pivot 테이블 플러그인은 기본 프로세스가 유지되어야하는 방법에 따라 두 가지 방법 중 하나에 등록 할 수 있습니다.

**주요공정만**

이 모드는 경량 작업과 간단한 작업에 적합 합니다: 플러그인 구성 빈 남아 있을 수 있고, `UniverSheetsPivotTablePlugin`를 가져올 충분.

```typescript
univer.registerPlugin(UniverSheetsPivotTablePlugin)
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)
```

**주요 및 작업자 프로세스**

pivot 계산이 무거운 경우, 메인 프로세스와 노동자 프로세스 모두에서 플러그인을 등록하십시오. 플러그인은 데이터 배포 및 계산을위한 멀티 스레드 레이아웃을 사용할 수 있으며, 주요 프로세스에서 계산의 대부분을 이동하고 전반적인 성능을 향상시킵니다.

이 모드에서는, 주요 프로세스는 데이터 배포, 동기화 및 렌더링을 처리하고, 작업자 프로세스는 복잡한 계산을 수행합니다. 모드는 구성을 통해 등록 통화에서 선택됩니다.

```typescript
// main process file
// Setting notExecuteFormula to true indicates that the main process does not perform calculations. It is only responsible for data distribution, synchronization, and rendering.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: true })
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)

// web worker process file
// Setting notExecuteFormula to false indicates that the worker process performs the calculations.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: false })
```

Univer의 상용 라이센스가 있는 경우, 클라이언트 측 설정에 [Client의 라이센스 사용](/server/license#in-plugin-mode)를 참조하십시오.

### 피벗 테이블 추가

[`FWorkbook.addPivotTable`](https://docs.univer.ai/reference/facade/workbook#addpivottable)는 피벗 테이블을 추가하고 성공할 때 `FPivotTable` 인스턴스를 반환합니다.

```typescript
// should ensure the sheet range A1:G9 is not empty
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()
const sheetName = fSheet.getSheetName()
const sourceInfo = {
  unitId,
  subUnitId,
  sheetName,
  range: {
    startRow: 0,
    startColumn: 0,
    endRow: 8,
    endColumn: 6,
  },
}
const anchorCellInfo = {
  unitId,
  subUnitId,
  row: 20,
  col: 8,
}
const fPivotTable = await fWorkbook.addPivotTable(sourceInfo, univerAPI.Enum.PositionTypeEnum.Existing, anchorCellInfo)
const pivotTableId = fPivotTable.getPivotTableId()
// add flag to avoid add pivot fields multiple times
let hasAdded = false
// the addPivotTable is async, you can add pivot fields after the pivot table is added
univerAPI.addEvent(univerAPI.Event.PivotTableRendered, async (params) => {
  if (!hasAdded && params.pivotTableId === pivotTableId) {
    hasAdded = true
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Row, 0)
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Value, 0)
  }
})
```

### 피벗 테이블 가져오기

[`FWorkbook.getPivotTableByCell`](https://docs.univer.ai/reference/facade/workbook#getpivottablebycell)는 닻 세포에 의해 피벗 테이블을 찾아 표적 세포가 피벗 테이블 안쪽에 있는 경우에 `FPivotTable`를 돌려보냅니다.

```typescript
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()

// get pivot table by the cell in FWorkbook.
const fPivotTable = fWorkbook.getPivotTableByCell(unitId, subUnitId, 0, 8)

// get pivot table by the cell in FWorksheet.
const pivotTable2 = fSheet.getPivotTableByCell(0, 8)
```

## 출력 영역이 막힌 경우 [#blocked-output]

보고서는 확장 할 방이 필요합니다. 세포 함량, 병합 셀, 또는 다른 피벗 테이블은 출력 영역을 차단할 수 있습니다. 방해를 지우거나 빈 범위에 보고서를 이동하십시오.

## 값 표시 방식 [#show-values-as]

값 필드에 `setShowDataAs()`는 필드 디스플레이의 값을 변경합니다. 열, 열, 또는 그랜드 총 또는 기본 항목의 차이. 만 표시된 계산 변경 만; 소스 데이터는 변경되지 않습니다. `getShowDataAs()`은 현재 설정, `resetShowDataAs()`가 정상 계산을 복원합니다.

```ts
const valueId = fPivotTable.getFieldIdsByArea(
  univerAPI.Enum.PivotTableFiledAreaEnum.Value,
)[0]
if (valueId) {
  await fPivotTable.setShowDataAs(valueId, {
    type: univerAPI.Enum.PivotShowAsTypeEnum.percentOfGrandTotal,
  })
  console.log(fPivotTable.getShowDataAs(valueId))
}
```

예를 들어 기존 `fPivotTable`를 가정합니다. 인수는 소스 열 또는 행 필드 ID가 아닌 값 필드 ID입니다. 차이 및 실행 총 모드는 해당 기본 필드와 기본 항목 설정을 요구합니다.

## 워크시트와 함께 피벗 테이블 복사 [#copy-with-worksheet]

Pivot 플러그인을 등록한 상태에서 작업 시트를 복사하여 작업 시트에 피벗 테이블을 복사하고 필드 구성을 보존합니다. 각 복사는 새로운 피벗 테이블 ID를받습니다. 복사 된 워크 시트에 위치한 소스 범위는 새로운 워크 시트에 리디렉션되며 다른 워크 시트 또는 워크북의 소스는 원래 참조를 유지합니다. 복사 된 테이블은 워크 시트 사본의 undo 및 redo에 참여합니다.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const copiedSheet = workbook.duplicateActiveSheet()
console.log(copiedSheet.getSheetName())
```

## 다중 필터와 날짜 조건 [#multiple-filters]

`setOptions({ allowMultipleFilters: true })`는 회원 선택, 라벨 또는 날짜 조건 및 동일한 필드에 coexist에 값 필터를 허용합니다. 옵션이 잘못되었거나 `false`로 설정하면 새로운 필터는 이전을 대신 교체합니다. 범주가 보고서 필터를 명확하게하면서 옵션을 비활성화합니다. 필드는 여전히 대부분의 값 필터에 받아들입니다.

`setDateFilter()` 고정 날짜 연산자를 허용, 포함 `dateEqual`, `dateOlderThan`, 및 `dateBetween`. `expected` 관련 기사 Excel workbook의 날짜 체계에 있는 일련 가치, 그리고 조건 사이 2개는 그(것)들의 가지고 갑니다. `useWholeDay: true` 하루의 시간을 무시하고 하루를 비교합니다; 옵션이 omitted 또는 설정하면 `false`, 비교는 정확한 serials를 사용합니다. 인수는 소스 열 색인이 아닌 보고서 필드 ID입니다. 다음 예제는 빌드에서 `fPivotTable` 위와 소스 열 명명 `Date`.

`getDateFilter()`는 상태의 분리된 복사본을 반환하고 `clearDateFilter()`가 날짜 상태를 명확하게 하고 다른 아무것도. 두 명령은 undo 및 협력에 참여합니다. 그들이 돌려보내는 불린값을 검사하십시오: 활동적인 슬라이더는 적용에서 incompatible 여과기를 방지할 수 있습니다.

```ts
if (!fPivotTable) throw new Error('PivotTable not found')
await fPivotTable.setOptions({ allowMultipleFilters: true })

const dateField = Object.values(fPivotTable.getConfig()?.fieldsConfig.dimension ?? {})
  .find((field) => field.sourceName === 'Date')
if (!dateField) throw new Error('Add the Date field to the report first')

await fPivotTable.setDateFilter(dateField.id, {
  operator: univerAPI.Enum.ST_PivotFilterOperatorEnum.dateEqual,
  expected: 45293,
  useWholeDay: true,
})
console.log(fPivotTable.getDateFilter(dateField.id))
await fPivotTable.clearDateFilter(dateField.id)
```

## GETPIVOTDATA [#getpivotdata]

`=GETPIVOTDATA("Sales",$I$1,"Region","East")`는 위 왼쪽 세포가 I1인 눈에 보이는 피벗 보고서에서 골재를 읽습니다. 값 필드는 표시된 캡션에 의해 지정되거나 소스 이름에 의해 지정될 수 있습니다. 앵커는 단일 셀 참조가 있어야 하며, 필드/item 쌍은 전체에서 공급되어야 합니다.

현재 구현은 닻에서 200까지 줄을 스캔하고 50 열을 스캔 한 눈에 볼 수있는 보고서 만 읽습니다. 숨겨진 소스 레코드를 쿼리하지 않습니다. 일치하지 않는 필드 /item 쌍, 또는 사용할 수없는 결과, `#REF!`를 반환합니다. 잘못된 인수 수 또는 단일 셀이 아닌 앵커는 `#VALUE!`을 반환합니다.
