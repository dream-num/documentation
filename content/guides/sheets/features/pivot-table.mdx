A pivot table reduces a large data range to a compact summary. It supports summarizing, analyzing, and visualizing data, and it provides the data operations and formatting options that make the result easier to understand.

## Introduction

Pivot tables are typically used for one of four purposes:

- Summarizing a large data range to make the overall picture visible.
- Analyzing the data to identify patterns and relationships.
- Exploring the data to discover rules and trends.
- Visualizing the result to make it easier to understand.

A pivot table consists of three parts:

- Row labels group the data by row.
- Column labels group the data by column.
- Values summarize the numbers at each intersection.

Row labels, column labels, and values can be rearranged at any time as the analysis requires.

### Data Source

In Univer Sheets, a pivot table takes either a worksheet or a data range as its source.

The first row of the source becomes the column labels, and the remaining rows contain the data. Empty rows and empty columns interfere with this layout, so the source should be kept tidy.

The data type of each column is detected automatically, which determines how the pivot table can use that field. If a column contains mixed types, the entire column is treated as string.

Pivot tables track changes in their source: when a value in the source data changes, the table updates automatically.

### Filtering

Row labels and column labels can both be filtered. A separate filter field is also available; it does not participate in the row and column layout of the report, but the values selected in it still restrict the data.

Two filtering methods are available:

- Label filtering applies to the items of the current label dimension; in a province dimension, for example, individual provinces can be filtered out.
- Value filtering requires a value dimension and filters on the aggregated result; for example, data whose sales are below 1000 can be hidden.

### Sorting

Sorting applies to row and column fields only, in either direction. Comparisons use the `localCompare` method. Additional comparison methods, pinyin sorting among them, are planned.

Two sorting methods are available:

- Label sorting applies to the items of the current label dimension; in a province dimension, this sorts by province name.
- Value sorting requires a value dimension and sorts on the aggregated result, for example by sales amount.

### Aggregation

Pivot tables support the 11 aggregation methods Excel offers: sum, count, data count, average, maximum, minimum, factorial, standard deviation, variance, population standard deviation, and population variance.

Several value dimensions can be added, and both the area they occupy (value position) and their order within that area (value index) can be configured.

This layout is complex, so only the table view is supported at present. Additional views will be added based on demand.

### Drill Down

Drill down refers to double-clicking a cell in the value area of a pivot table to view the detail behind that cell. The detail lists the rows that produced the number, which allows a total to be traced back to the source data.

### Grouping

Univer Sheets supports date, numeric, and manual grouping.

- Date grouping: use [`setDateGroupType`](/reference/facade/pivot-table#setdategrouptype) for a derived date field. To group an original date label field by calendar unit, set [`setDateGroupingMode`](/reference/facade/pivot-table#setdategroupingmode) to `univerAPI.Enum.PivotDateGroupingMode.ExcelLike`, then call [`setExcelDateGroup`](/reference/facade/pivot-table#setexceldategroup).
- Numeric grouping: pass a label field ID and the interval settings to [`setNumberGroup`](/reference/facade/pivot-table#setnumbergroup).
- Manual grouping: pass the original source field ID and groups of typed members to [`setManualGroups`](/reference/facade/pivot-table#setmanualgroups). Each group requires at least two members; an empty array removes all manual groups for that field.

[Slicers and timelines](/guides/sheets/features/slicer) filter tables and pivot reports interactively.

### Registering Plugins

The pivot table plugin can be registered in one of two ways, depending on how much calculation the main process should retain.

**Main process only**

This mode is suitable for lightweight tasks and simple operations: the plugin config can remain empty, and importing `UniverSheetsPivotTablePlugin` is sufficient.

```typescript
univer.registerPlugin(UniverSheetsPivotTablePlugin)
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)
```

**Main and worker processes**

When pivot calculation is heavy, register the plugin in both the main process and the worker process. The plugin can then use a multi-threaded layout for data distribution and calculation, which moves most of the calculation off the main process and improves overall performance.

In this mode, the main process handles data distribution, synchronization, and rendering, while the worker process performs the complex calculation. The mode is selected in the registration call through the config.

```typescript
// main process file
// Setting notExecuteFormula to true indicates that the main process does not perform calculations. It is only responsible for data distribution, synchronization, and rendering.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: true })
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)

// web worker process file
// Setting notExecuteFormula to false indicates that the worker process performs the calculations.
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: false })
```

### Add a Pivot Table

[`FWorkbook.addPivotTable`](https://docs.univer.ai/reference/facade/workbook#addpivottable) adds a pivot table and returns an `FPivotTable` instance when it succeeds.

```typescript
// should ensure the sheet range A1:G9 is not empty
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()
const sheetName = fSheet.getSheetName()
const sourceInfo = {
  unitId,
  subUnitId,
  sheetName,
  range: {
    startRow: 0,
    startColumn: 0,
    endRow: 8,
    endColumn: 6,
  },
}
const anchorCellInfo = {
  unitId,
  subUnitId,
  row: 20,
  col: 8,
}
const fPivotTable = await fWorkbook.addPivotTable(sourceInfo, univerAPI.Enum.PositionTypeEnum.Existing, anchorCellInfo)
const pivotTableId = fPivotTable.getPivotTableId()
// add flag to avoid add pivot fields multiple times
let hasAdded = false
// the addPivotTable is async, you can add pivot fields after the pivot table is added
univerAPI.addEvent(univerAPI.Event.PivotTableRendered, async (params) => {
  if (!hasAdded && params.pivotTableId === pivotTableId) {
    hasAdded = true
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Row, 0)
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Value, 0)
  }
})
```

## Blocked output [#blocked-output]

The report needs room to expand. Existing cell content, merged cells, or another pivot table can block the output area. Clear the obstruction or move the report to an empty range.

## Show values as [#show-values-as]

`setShowDataAs()` on a value field changes the value that field displays: its share of a row, a column, or a grand total, or its difference from a base item. Only the displayed calculation changes; the source data is not modified. `getShowDataAs()` reads the current setting, and `resetShowDataAs()` restores the normal calculation.

```ts
const valueId = fPivotTable.getFieldIdsByArea(
  univerAPI.Enum.PivotTableFiledAreaEnum.Value,
)[0]
if (valueId) {
  await fPivotTable.setShowDataAs(valueId, {
    type: univerAPI.Enum.PivotShowAsTypeEnum.percentOfGrandTotal,
  })
  console.log(fPivotTable.getShowDataAs(valueId))
}
```

The example assumes an existing `fPivotTable`. The argument is a value field ID, not a source column or row field ID. Difference and running-total modes also require the corresponding base field and base item settings.

## Copy pivot tables with a worksheet [#copy-with-worksheet]

With the pivot plugin registered, duplicating a worksheet also copies the pivot tables on that worksheet and preserves their field configuration. Each copy receives a new pivot-table ID. A source range located on the copied worksheet is redirected to the new worksheet, while a source on another worksheet or workbook retains its original reference. The copied tables participate in the undo and redo of the worksheet copy.

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const copiedSheet = workbook.duplicateActiveSheet()
console.log(copiedSheet.getSheetName())
```

## Multiple filters and date conditions [#multiple-filters]

`setOptions({ allowMultipleFilters: true })` allows a member selection, a label or date condition, and a value filter to coexist on the same field. If the option is omitted or set to `false`, a new filter replaces the previous one instead of adding to it; disabling the option while categories conflict clears the report filters. A field still accepts at most one value filter.

`setDateFilter()` accepts the fixed date operators, including `dateEqual`, `dateOlderThan`, and `dateBetween`. `expected` holds Excel serial values in the workbook's date system, and a between condition takes two of them. `useWholeDay: true` ignores the time of day and compares whole days; if the option is omitted or set to `false`, the comparison uses exact serials. The argument is the report field ID, not a source column index. The following example builds on the `fPivotTable` above and a source column named `Date`.

`getDateFilter()` returns a detached copy of the condition, and `clearDateFilter()` clears the date condition and nothing else. Both commands participate in undo and collaboration. Check the boolean value they return: an active slicer can prevent an incompatible filter from being applied.

```ts
if (!fPivotTable) throw new Error('PivotTable not found')
await fPivotTable.setOptions({ allowMultipleFilters: true })

const dateField = Object.values(fPivotTable.getConfig()?.fieldsConfig.dimension ?? {})
  .find((field) => field.sourceName === 'Date')
if (!dateField) throw new Error('Add the Date field to the report first')

await fPivotTable.setDateFilter(dateField.id, {
  operator: univerAPI.Enum.ST_PivotFilterOperatorEnum.dateEqual,
  expected: 45293,
  useWholeDay: true,
})
console.log(fPivotTable.getDateFilter(dateField.id))
await fPivotTable.clearDateFilter(dateField.id)
```

## GETPIVOTDATA [#getpivotdata]

`=GETPIVOTDATA("Sales",$I$1,"Region","East")` reads an aggregate from a visible pivot report whose upper-left cell is I1. The value field may be specified by its displayed caption or by its source name. The anchor must be a single cell reference, and field/item pairs must be supplied in full.

The current implementation reads only the visible report, scanning up to 200 rows down and 50 columns right from the anchor. It does not query hidden source records. A field/item pair that does not match, or a result that is unavailable, returns `#REF!`. An incorrect argument count, or an anchor that is not a single cell, returns `#VALUE!`.
