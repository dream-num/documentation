ピボットテーブルは、大量のデータ範囲をコンパクトなサマリーに削減します。データのまとめ、分析、視覚化をサポートし、データ操作とフォーマットオプションを提供し、結果が分かりやすくなります。

## 概要

ピボットテーブルは、通常4つの目的のために使用されます。

- 全体像を見えるようにするために、大きなデータ範囲をまとめます。
- パターンと関係を識別するためにデータを分析します。
- ルールやトレンドを発見するためにデータを探ります。
- 結果を視覚化して理解しやすくなります。

ピボットテーブルは3つの部分で構成されます。

- Row ラベルは、データを行ごとにグループ化します。
- 列ラベルは、列でデータをグループ化します。
- 各交差点で数字をまとめる値。

列ラベル、列ラベル、値がいつでも解析が要求されるように再配置できます。

![ロケールが見つかりません](./pivot-table/pivot.png)

### データソース

Univerシートでは、ピボットテーブルは、ワークシートまたはデータ範囲をソースとして取得します。

ソースの最初の行は、列ラベルになり、残りの行はデータを含んでいます。空の行と空の列はこのレイアウトに干渉するので、ソースは整頓されているはずです。

各列のデータタイプが自動的に検出され、ピボットテーブルがそのフィールドをどのように使用できるかが決定されます。 カラムが混在するタイプが含まれている場合は、列全体が文字列として扱われます。

ピボットテーブルは、ソースのデータが変更されると、テーブルが自動的に更新されます。

### フィルター

列ラベルと列ラベルの両方をフィルタリングできます。別のフィルタフィールドも利用できます。レポートの行と列レイアウトには参加しませんが、選択した値はデータが制限されます。

2つのろ過方法は利用できます:

- ラベルのろ過は現在のラベル次元の項目に適用します; 州次元では、例えば、個々の州はろ過することができます。
- 値のフィルタリングは、集計された結果に値の寸法とフィルタを必要とします。例えば、1000未満の売上が隠すことができます。

### 並べ替え

ソートは、行と列フィールドにのみ適用されます。 比較は、`localCompare`メソッドを使用します。 追加の比較方法、それらの間で並べ替えのピニインが計画されています。

2つのソート方法が利用可能です。

- ラベルのソートは、現在のラベルの寸法の項目に適用されます。 州の寸法では、この並べ替えは州の名前で行います。
- 値のソートは、例えば、売上金額など、集計結果に値の寸法とソートが必要です。

### 集計

Pivotテーブルは、11の集計方法Excelの提供をサポートしています:合計、カウント、データカウント、平均値、最大値、最小値、ファクチャリティー、標準偏差、分散、人口標準偏差および集団の分散。

いくつかの値の寸法を追加することができ、その領域(値のインデックス)内の値の位置(値の位置)と順序の両方を設定することができます。

このレイアウトは複雑なので、現在ではテーブルビューのみがサポートされています。追加ビューは、需要に応じて追加されます。

### ドリルダウン

ドリルダウンは、ピボットテーブルの値をダブルクリックして、そのセルの背後にある詳細を表示します。 詳細は、番号を生成した行をリストし、合計がソースデータに戻ってトレースすることができます。

### グループ化

Univer Sheets は日付、数値、手動のグループ化をサポートしています。

- 日付のグループ化: 派生した日付フィールドに [`setDateGroupType`](/reference/facade/pivot-table#setdategrouptype) を使用します。 カレンダーユニットによって元の日付ラベルフィールドをグループ化するには、[`setDateGroupingMode`](/reference/facade/pivot-table#setdategroupingmode)を `univerAPI.Enum.PivotDateGroupingMode.ExcelLike`に設定し、[`setExcelDateGroup`](/reference/facade/pivot-table#setexceldategroup)を呼び出す。
- 数値グループ化: ラベルフィールド ID と [`setNumberGroup`](/reference/facade/pivot-table#setnumbergroup) への間隔設定を渡す。
- マニュアルグループ化: 元のソースフィールド ID とタイプされたメンバーのグループを [`setManualGroups`](/reference/facade/pivot-table#setmanualgroups) に渡します。各グループには少なくとも 2 人が必要です。空の配列は、そのフィールドのすべてのマニュアルグループを削除します。

[スライサーとタイムライン](/guides/sheets/features/slicer)のフィルター テーブルおよびピボットは相互に報告します。

### プラグインの登録

pivotテーブルプラグインは、メインプロセスが保持されるどのくらいの計算に応じて、2つの方法で登録できます。

**主な工程のみ**

このモードは、軽量なタスクと簡単な操作に適しています。プラグインの設定は空のままで、`UniverSheetsPivotTablePlugin`をインポートするのに十分です。

```typescript
univer.registerPlugin(UniverSheetsPivotTablePlugin)
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)
```

**主工程と作業工程**

ピボット計算が重くなったら、メインプロセスとワーカープロセスの両方でプラグインを登録します。プラグインは、データ分布と計算のためのマルチスレッドレイアウトを使用して、主要なプロセスをオフに計算の大部分を移動し、全体的なパフォーマンスを向上させることができます。

このモードでは、メインプロセスは、データ分布、同期、レンダリングを処理します。ただし、ワーカープロセスは複雑な計算を実行します。このモードは、コンフィグを介して登録呼び出しで選択されます。

```typescript
// main process file
// notExecuteFormula を true に設定すると、メインプロセスは計算を行いません。データ分配・同期・レンダリングのみを担当します。
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: true })
univer.registerPlugin(UniverSheetsPivotTableUIPlugin)

// web worker process file
// notExecuteFormula を false に設定すると、ワーカー プロセスが計算を実行します。
univer.registerPlugin(UniverSheetsPivotTablePlugin, { notExecuteFormula: false })
```

Univer の商用ライセンスをお持ちの方は、クライアント側の設定で [クライアントでのライセンスの使用](/server/license#in-plugin-mode)を参照してください。

### ピボットテーブルの追加

[`FWorkbook.addPivotTable`](https://docs.univer.ai/reference/facade/workbook#addpivottable)はピボットテーブルを追加し、成功すると`FPivotTable`インスタンスを返します。

```typescript
// シート範囲 A1:G9 が空でないことを確認してください
const fWorkbook = univerAPI.getActiveWorkbook()
const unitId = fWorkbook.getId()
const fSheet = fWorkbook.getActiveSheet()
const subUnitId = fSheet.getSheetId()
const sheetName = fSheet.getSheetName()
const sourceInfo = {
  unitId,
  subUnitId,
  sheetName,
  range: {
    startRow: 0,
    startColumn: 0,
    endRow: 8,
    endColumn: 6,
  },
}
const anchorCellInfo = {
  unitId,
  subUnitId,
  row: 20,
  col: 8,
}
const fPivotTable = await fWorkbook.addPivotTable(sourceInfo, univerAPI.Enum.PositionTypeEnum.Existing, anchorCellInfo)
const pivotTableId = fPivotTable.getPivotTableId()
// 複数回フィールドを追加しないように制御するフラグ
let hasAdded = false
// addPivotTable は非同期のため、ピボットテーブル追加後にフィールドを追加できます
univerAPI.addEvent(univerAPI.Event.PivotTableRendered, async (params) => {
  if (!hasAdded && params.pivotTableId === pivotTableId) {
    hasAdded = true
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Row, 0)
    await fPivotTable.addField(1, univerAPI.Enum.PivotTableFiledAreaEnum.Value, 0)
  }
})
```

### イベントリスナー

[イベント](https://docs.univer.ai/reference/facade/events) では、完全なイベント型定義が定義されています。

`univerAPI.Event.BeforePivotTableAdd` はピボットテーブルの前に火をつけます。

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.BeforePivotTableAdd, (params) => {
  const { positionType, targetCellInfo } = params
  if (positionType === univerAPI.Enum.PositionTypeEnum.Existing && targetCellInfo.sheetName === 'Sheet 1') {
  // ピボットテーブルの追加操作をキャンセル
    params.cancel = true
    console.log(`The pivot table can't be added to the sheet ${targetCellInfo.sheetName}`)
  }
})

// イベントリスナーを削除するには `disposable.dispose()` を使用します
```

`univerAPI.Event.PivotTableAdded`はピボットテーブルが追加された後に火をつけます。

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.PivotTableAdded, (params) => {
  const { positionType, targetCellInfo } = params
  if (positionType === univerAPI.Enum.PositionTypeEnum.Existing) {
    console.log('A pivot table created in an existing sheet')
    console.log(`
      The target sheet name is ${targetCellInfo.sheetName},
      the target row is ${targetCellInfo.row}, the target column is ${targetCellInfo.column}
    `)
  } else {
    console.log('A pivot table created in a new sheet')
  }
})

// イベントリスナーを削除するには `disposable.dispose()` を使用します
```

`univerAPI.Event.BeforePivotTableMove`はピボットテーブルが動かされる前に火を燃やします。

レポートは、拡張する部屋が必要です。 既存のセルコンテンツ、マージセル、または別のピボットテーブルは、出力領域をブロックすることができます。 閉塞を解除するか、レポートを空の範囲に移動します。

## 値の表示方法 [#show-values-as]

`setShowDataAs()` は、フィールド表示の値をフィールドに変更します。行、列、またはグランド合計のシェア、またはベース項目の違い。 表示された計算の変更のみ。 ソースデータは変更されません。 `getShowDataAs()` 現在の設定を読み、 `resetShowDataAs()`は通常の計算を復元します。

```ts
const valueId = fPivotTable.getFieldIdsByArea(
  univerAPI.Enum.PivotTableFiledAreaEnum.Value,
)[0]
if (valueId) {
  await fPivotTable.setShowDataAs(valueId, {
    type: univerAPI.Enum.PivotShowAsTypeEnum.percentOfGrandTotal,
  })
  console.log(fPivotTable.getShowDataAs(valueId))
}
```

たとえば、既存の `fPivotTable` を想定しています。 引数は、 ソース列や行フィールド ID ではなく、値フィールド ID です。 違いと実行中のtotal モードは、対応するベースフィールドとベース項目の設定も必要です。

## ワークシートと一緒にピボットテーブルをコピーする [#copy-with-worksheet]

登録されたピボットプラグインでは、ワークシートを複製し、そのワークシートにピボットテーブルをコピーし、フィールドの設定を保存します。各コピーは新しいピボットテーブルIDを受け取ります。コピーされたワークシートにあるソース範囲は新しいワークシートにリダイレクトされますが、別のワークシートまたはワークブックのソースは元の参照を保持します。コピーテーブルはワークシートのコピーのundoとredoに参加します。

```ts
const workbook = univerAPI.getActiveWorkbook()
if (!workbook) throw new Error('No active workbook')

const copiedSheet = workbook.duplicateActiveSheet()
console.log(copiedSheet.getSheetName())
```

## 複数フィルターと日付条件 [#multiple-filters]

`setOptions({ allowMultipleFilters: true })`は、メンバーの選択、ラベルまたは日付の状態、および同じフィールドで共存する値フィルタを可能にします。オプションが省略されている場合、または`false`に設定されている場合、新しいフィルタは、それを追加する代わりに、以前のフィルタを置き換えます。カテゴリが競合する間、オプションを無効にすると、レポートフィルタがクリアされます。フィールドは、ほとんどの値フィルタで引き続き受け入れます。

`setDateFilter()` 固定日付演算子を受け付けます。 `dateEqual`, `dateOlderThan`, と `dateBetween`. `expected` ホールド Excel ワークブックの日付システム内のシリアル値、条件はそれぞれ2つをとります。 `useWholeDay: true` 日の時刻を無視し、全日を比較します。オプションが省略されている場合、または設定します。 `false`, 比較は、正確なシリアルを使用します. 引数は、レポートフィールドIDです, ソース列のインデックスではありません. 次の例は、上に構築します `fPivotTable` 上記と名前のソース列 `Date`.

`getDateFilter()`は条件の切り離されたコピーを返し、`clearDateFilter()` は日付の状態を取り除き、他に何もしません。どちらのコマンドも undo とコラボレーションに参加します。それらが返すブール値を確認してください。アクティブスライサーは、互換性のないフィルターが適用されるのを防ぐことができます。

```ts
if (!fPivotTable) throw new Error('PivotTable not found')
await fPivotTable.setOptions({ allowMultipleFilters: true })

const dateField = Object.values(fPivotTable.getConfig()?.fieldsConfig.dimension ?? {})
  .find((field) => field.sourceName === 'Date')
if (!dateField) throw new Error('Add the Date field to the report first')

await fPivotTable.setDateFilter(dateField.id, {
  operator: univerAPI.Enum.ST_PivotFilterOperatorEnum.dateEqual,
  expected: 45293,
  useWholeDay: true,
})
console.log(fPivotTable.getDateFilter(dateField.id))
await fPivotTable.clearDateFilter(dateField.id)
```

## GETPIVOTDATA [#getpivotdata]

`=GETPIVOTDATA("Sales",$I$1,"Region","East")`は、左上セルがI1である可視ピボットレポートから集計を読み取ります。値フィールドは、表示されたキャプションまたはソース名で指定できます。アンカーは単一セル参照であり、フィールド/項目のペアはフルで供給する必要があります。

現在の実装は、表示されたレポートのみを読み、200行までスキャンし、アンカーから右50列をスキャンします。 隠れたソースレコードをクエリしません。 一致しないフィールド/項目のペア、または利用できなくなった結果、`#REF!`を返します。 誤った引数カウント、または単一のセルではないアンカーは、`#VALUE!`を返す。
