セルの値、式、または書式を編集した後、以前のバージョンをレビューするために履歴パネルを開き、変更を比較し、対応する権限を持っているときにバージョンを復元します。 履歴は、サーバー上で主張するバージョンを読みます。 未だ、またはredoは、現在の編集セッションにのみ適用され、履歴サービスを必要としません。

## 共同編集と履歴サービスの準備

[コラボレーション統合](/server/collaboration/browser-integration)と[ライセンス構成](/server/license)を最初に完了し、2つのセッションが同じスプレッドシートの文書を編集でき、その変更が再ロードされることを確認します。

[オフィスのコラボレーション拡張](/server/collaboration/extensions)と[歴史例](/server/collaboration/examples#history)は、歴史の保存と許可を結ぶ方法について説明します。コアコラボレーションは、独自の履歴を有効にしません。バックエンドは、履歴リスト、バージョンコンテンツ、および復元を提供する必要があります。

この設定を既存の製品、ライセンス、およびコラボレーション設定に追加します。プリセットまたは既存の設定がすでにこれらのプラグインを登録している場合は、その設定を2回目の登録ではなく更新します。

## プラグインモード [#plugin-mode]

### インストール

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/sheets-history @univerjs-pro/sheets-history-ui
```

### 使い方

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSheetsHistoryPlugin } from '@univerjs-pro/sheets-history'
import { UniverSheetsHistoryUIPlugin } from '@univerjs-pro/sheets-history-ui'
import HistoryLocale from '@univerjs-pro/sheets-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/sheets-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSheetsHistoryPlugin)
univer.registerPlugin(UniverSheetsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### プラグイン設定

`UniverEditHistoryPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |

`UniverSheetsHistoryUIPlugin`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | 履歴サービスのベース URL。 |
| `univerContainerId` | `string` |  | エディターコンテナの DOM ID。 |

`/api/history` をアプリケーションの実際の履歴エンドポイントに置換し、エンドポイントがクライアントが送信するリクエストと一致することを確認します。 `historyServerUrl`の値も同じでなければなりません。 `univerContainerId`をエディタコンテナの DOM ID に設定し、エディタが使用するロケールを読み込みます。

シートの履歴は、`UniverCollaborationClientUIPlugin`を連携セットアップに登録する必要があります。

## モバイル対応 [#mobile-support]

[モバイルエディタ](/guides/sheets/getting-started/installation#mobile-support)を最初にセットアップします。このページのプラグインモード設定では、同じパッケージからモバイルエクスポートでデスクトップ登録を交換し、**ドキュメントを開く前に**を実行します。モデルプラグイン、スタイル、ロケール、ファサードのインポートを保存し、1つのバリアントだけを登録します。

| パッケージ | デスクトップの登録 | モバイルの登録 |
| --- | --- | --- |
| `@univerjs-pro/sheets-history-ui` | `UniverSheetsHistoryUIPlugin` | `UniverSheetsHistoryMobileUIPlugin` |

## プリセットモード [#preset-mode]

### インストール

```package-install
npm install @univerjs/preset-sheets-collaboration
```

### 使い方

`UniverSheetsCollaborationPreset`には、履歴UIとそれに依存するプラグインが含まれています。 既存のエディタとライセンス設定を保持します。 プリセットが既に登録されている場合は、プリセットを登録するか、または歴史プラグインを秒間登録するのではなく、更新してください。

```ts
import { UniverSheetsCollaborationPreset } from '@univerjs/preset-sheets-collaboration'
import CollaborationLocale from '@univerjs/preset-sheets-collaboration/locales/en-US'
import '@univerjs/preset-sheets-collaboration/lib/index.css'

const collaborationPreset = UniverSheetsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### プリセット設定

`UniverSheetsCollaborationPreset`

| <span data-config-options="">オプション</span> | 型 | 既定値 | 動作 |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | 共同編集サーバーのベース URL。 |
| `univerContainerId` | `string` | `'app'` | エディターコンテナの DOM ID。 |

追加する `collaborationPreset` にほんご `presets` 既存の配列 `createUniver()` 呼び出しと合併 `CollaborationLocale` マッチするロケールエントリーへ。セット `universerEndpoint` サーバーのベース URL に、 `univerContainerId` エディタコンテナ ID に。プリセットは、履歴 URL を次のように構成します。 `{universerEndpoint}/universer-api/history`なので、カスタム時にプラグインモードを使用する `historyServerUrl` または `viewerPlugins` 上記のバックエンドサービスは必須です。

## バージョンの表示と復元

エディタメニューから履歴パネルを開き、バージョンを選択してコンテンツと変更を調べます。復元は現在の共有文書を書き換えます。そのため、復元権限を持つユーザーは実行できるようにし、サーバーはその許可を強制しなければなりません。

統合を確認するために、セル値、式、またはいくつかのフォーマットを編集し、コラボレーションを待ち合わせると、変更を確認し、履歴リストとバージョンコンテンツを確認します。アプリケーションを再起動し、すべてのデータが永続していることを確認します。以前のバージョンを復元し、別のブラウザセッションが復元された状態を受け取ることを確認します。

リストが空の場合、最初にこの文書の履歴が記録されたかどうかを調べて、ドキュメント ID とサービス URL を確認します。 閲覧作品が正常に機能しない場合は、復元権限とコラボレーション接続を確認してください。 古いバージョンが削除されたデータを含む可能性があるため、履歴を読んでも許可が必要です。

## スナップショットの比較 [#compare-snapshots]

レビュー画面を作成したり、AIエージェントに変更を渡すには、`compareUnitData()` を呼び出したり、`prepareUnitComparison()` に一度比較を計算したり、繰り返しクエリを繰り返します。製品の履歴プラグインを登録し、ファサードエントリーをインポートし、`beforeSnapshot` と `afterSnapshot` と同じユニットの2つの完全に材料化されたスナップショットを渡します。比較は読み取り専用であり、履歴サービスは不要で、コンテンツの復元やマージも不要です。

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SHEET,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

読みます `scopes` 利用可能なビューを発見し、その1つを`query()`に渡して、結果を再実行することなくフィルタリングします。 ページは、デフォルトで最大1,000アイテムを返します。 `page.hasMore`を`offset`と一緒に使用して残りのアイテムを取得してください。 `summary`は、アイテムがフィルタリングされた場合でも、全体の比較について説明します。 結果を完全な比較として扱う前に`diagnostics.readiness`と`diagnostics.codes`をチェックしてください。 Node.jsまたはCLIの使用については、エディタなしで[ヘッドレス比較API](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison)を参照してください。
