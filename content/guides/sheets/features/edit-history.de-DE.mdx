<Callout type="warning" title="Caution">
Die Funktion zum Bearbeiten des Verlaufs erfordert Unterstützung vom Univer-Server. Bitte stellen Sie sicher, dass Sie den Univer-Server korrekt installiert und konfiguriert haben. Einzelheiten finden Sie unter: [Upgrade auf Pro](/guides/pro)
</Callout>

Verlauf bearbeiten ermöglicht Benutzern das Anzeigen und Wiederherstellen historischer Versionen von Dokumenten und unterstützt verschiedene Filter- und Suchmethoden, um Benutzern die effiziente Verwaltung von Dokumentinhalten zu erleichtern.

<Callout type="warning" title="Caution">
Die Funktion „Verlauf bearbeiten“ erstellt eine unabhängige Univer-Instanz, die das Laden und Anzeigen historischer Datensätze übernimmt. Wenn Sie die Univer-Instanz für historische Datensätze betreiben oder konfigurieren müssen (z. B. Schnittstellenanforderungsheader ändern, Plugins registrieren usw.), lesen Sie bitte den Abschnitt [Univer-Instanz für den Bearbeitungsverlauf abrufen](#get-edit-history-univer-instance).
</Callout>

## Voreingestellter Modus

### Installation

<Callout>
Die Voreinstellung `UniverSheetsAdvancedPreset` von `@univerjs/preset-sheets-advanced` hängt davon ab die Voreinstellung `UniverSheetsDrawingPreset` zur Laufzeit. Bitte installieren Sie zuerst `@univerjs/preset-sheets-drawing`.
</Callout>

```package-install
npm install @univerjs/preset-sheets-drawing @univerjs/preset-sheets-advanced @univerjs/preset-sheets-collaboration
```

### Nutzung

```typescript
import { UniverSheetsAdvancedPreset } from '@univerjs/preset-sheets-advanced' // [!code ++]
import UniverPresetSheetsAdvancedEnUS from '@univerjs/preset-sheets-advanced/locales/en-US' // [!code ++]

### Voreinstellungen und Konfiguration

Die `UniverSheetsCollaborationPreset`-Konfiguration Optionen:

```typescript

## Plugin-Modus

### Installation

```package-install
npm install @univerjs-pro/edit-history-viewer @univerjs-pro/edit-history-loader
```

### Nutzung

```typescript
import { UniverEditHistoryLoaderPlugin } from '@univerjs-pro/edit-history-loader' // [!code ++]
import EditHistoryViewerEnUS from '@univerjs-pro/edit-history-viewer/locale/en-US' // [!code ++]
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'

import '@univerjs-pro/edit-history-viewer/lib/index.css' // [!code ++]

const univer = new Univer({
  locale: LocaleType.En_US,
  locales: {
    [LocaleType.En_US]: mergeLocales(
      EditHistoryViewerEnUS, // [!code ++]
    ),
  },
})

univer.registerPlugin(UniverEditHistoryLoaderPlugin, { // [!code ++]
  univerContainerId: 'your-univer-container-id', // [!code ++]
}) // [!code ++]
```

Wenn Sie eine kommerzielle Lizenz für Univer haben, finden Sie Informationen zur Konfiguration unter [Lizenz im Client verwenden](/guides/pro/license#in-plugin-mode).

### Plugins und Konfiguration

Die `UniverEditHistoryLoaderPlugin` Konfigurationsoptionen:

```typescript
interface IUniverEditHistoryLoaderConfig {
  univerContainerId?: string
  // The server url of the history list
  historyListServerUrl?: string
  /**
   * If the data calculation in the history requires the use of Worker (such as formulas), you can configure this field.
   * 1. If workerURL is provided and workerURL is a Worker instance, it will be destroyed when the history is closed, so a new Worker instance needs to be provided each time the history is opened.
   * ```typescript
   * import { EDIT_HISTORY_LOADER_PLUGIN_CONFIG_KEY, ToggleEditHistoryOperation } from '@univerjs-pro/edit-history-loader';
   *
   * univerAPI.addEvent(univerAPI.Event.BeforeCommandExecute, (event) => {
   *   if (event.id === ToggleEditHistoryOperation.id) {
   *     const workerURL = new Worker(new URL('./worker.ts', import.meta.url));
   *     const configService = univer.__getInjector().get(IConfigService);
   *     configService.setConfig(EDIT_HISTORY_LOADER_PLUGIN_CONFIG_KEY, {
   *       workerURL,
   *     });
   *   }
   * });
   * 2.Wenn die bereitgestellte workerURL keine Worker-Instanz ist, Es ist keine zusätzliche Verarbeitung erforderlich.
   * ```
   */
  workerURL?: string | URL | Worker
}
```

Wenn Sie den Bearbeitungsverlauf aktivieren, lädt `UniverEditHistoryLoaderPlugin` eine neue Univer-Instanz und mountet sie auf dem angegebenen DOM-Knoten. Daher müssen Sie bei der Registrierung eine geeignete DOM-Knoten-ID (z. B. den Container der ursprünglichen Univer-Instanz) angeben, um den Zweck des Verlaufsfensters zu erreichen, das das ursprüngliche Univer-Panel abdeckt. Wenn die Knoten-ID nicht angegeben ist, ist sie standardmäßig `univer-container`.

Wenn Sie die Serveradresse für die Verlaufsliste ändern müssen, können Sie sie über die Konfigurationsoption `historyListServerUrl` festlegen, die standardmäßig `/universer-api/history` lautet.

## Abrufen der Univer-Instanz für den Bearbeitungsverlauf [#get-edit-history-univer-instance]

<Callout title="Good to Know">
Die Univer-Instanz für den Bearbeitungsverlauf wird nur erstellt, wenn das Verlaufsfenster zum ersten Mal geöffnet wird.
</Callout>

Wenn Sie die Univer-Instanz für den Bearbeitungsverlauf bedienen oder konfigurieren müssen (z. B. Schnittstellenanforderungsheader ändern, Plugins registrieren usw.), können Sie die Instanz über `HistoryLoaderService` erhalten.

<Tabs items={['Preset Mode', 'Plugin Mode']}>
  <Tab>
    ```typescript
    import { HistoryLoaderService } from '@univerjs/preset-sheets-collaboration'

    const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
      if (stage === univerAPI.Enum.LifecycleStages.Steady) {
        const injector = univer.__getInjector()
        const historyLoaderService = injector.get(HistoryLoaderService)

        historyLoaderService.historyUniver$.subscribe((historyUniver) => {
          // 在这里可以使用 historyUniver 实例进行操作
        })
      }
    })

    // Remove the event listener using `disposable.dispose()`
    ```
  </Tab>
  <Tab>
    ```typescript
    import { HistoryLoaderService } from '@univerjs-pro/edit-history-loader'

    const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
      if (stage === univerAPI.Enum.LifecycleStages.Steady) {
        const injector = univer.__getInjector()
        const historyLoaderService = injector.get(HistoryLoaderService)

        historyLoaderService.historyUniver$.subscribe((historyUniver) => {
          if (!historyUniver) return

          // You can perform operations on the historyUniver instance here
        })
      }
    })

    // Remove the event listener using `disposable.dispose()`
    ```
  </Tab>
</Tabs>

### Drittanbieter-Plugin Anpassung

Die Univer-Instanz für den Bearbeitungsverlauf lädt standardmäßig nur offizielle Plugins. Funktions-Plugins von Drittanbietern, die für geschäftliche Anforderungen entwickelt wurden, müssen bei `HistoryLoaderService` registriert werden, um korrekt im Verlauf angezeigt zu werden.

```typescript
const injector = univer.__getInjector()
const historyLoaderService = injector.get(HistoryLoaderService)

// [!code focus:4]
// The registration method is the same as that of PluginService. The Univer instance for edit history will register the corresponding plugins according to the following configuration after creation.
historyLoaderService.registerPlugin(YourPlugin, YourPluginConfig)
// Configure the officially registered plugin, set the true parameter to indicate that the original configuration should be overridden
historyLoaderService.registerPlugin(ExamplePlugin, ExamplePluginConfig, true)
```
