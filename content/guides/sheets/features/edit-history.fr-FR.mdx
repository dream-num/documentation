Après avoir modifié des valeurs cellulaires, des formules ou un formatage, ouvrez le panneau d'historique pour examiner les versions antérieures, comparer les modifications et restaurer une version lorsque vous avez la permission correspondante. L'historique lit les versions persistantes sur le serveur. Undo et redo s'appliquent uniquement à la session d'édition actuelle et ne nécessitent pas le service d'historique.

## Préparer la collaboration et l’historique

Compléter d'abord [l'intégration de la collaboration](/server/collaboration/browser-integration) et [configuration de licence](/server/license), puis vérifier que deux sessions peuvent modifier le même document de feuilles et que les modifications survivent à un rechargement.

[Prolongation de la collaboration avec les bureaux](/server/collaboration/extensions) et le [Exemple historique](/server/collaboration/examples#history) décrivent comment connecter le stockage d'historique et les permissions. La collaboration de base ne permet pas l'historique seul. Le moteur doit également fournir des listes d'historique, du contenu de version et de restauration.

Ajouter cette configuration à la configuration existante du produit, de la licence et de la collaboration. Si un préréglage ou une configuration existante enregistre déjà ces plugins, mettre à jour cette configuration au lieu de les enregistrer une seconde fois.

## Mode plugin [#plugin-mode]

### Installation

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/sheets-history @univerjs-pro/sheets-history-ui
```

### Utilisation

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSheetsHistoryPlugin } from '@univerjs-pro/sheets-history'
import { UniverSheetsHistoryUIPlugin } from '@univerjs-pro/sheets-history-ui'
import HistoryLocale from '@univerjs-pro/sheets-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/sheets-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSheetsHistoryPlugin)
univer.registerPlugin(UniverSheetsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuration des plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |

`UniverSheetsHistoryUIPlugin`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL de base du service d’historique. |
| `univerContainerId` | `string` |  | ID DOM du conteneur de l’éditeur. |

Remplacez `/api/history` par le paramètre d'historique réel de l'application, et assurez-vous que le paramètre correspond aux demandes envoyées par le client. Les deux valeurs `historyServerUrl` doivent être identiques. Définissez `univerContainerId` sur l'ID DOM du conteneur de l'éditeur et chargez la localité utilisée par l'éditeur.

L'historique des feuilles exige également que le `UniverCollaborationClientUIPlugin` soit enregistré dans la configuration de la collaboration.

## Prise en charge mobile [#mobile-support]

Configurez d'abord le [éditeur mobile](/guides/sheets/getting-started/installation#mobile-support). Dans la configuration en mode plugin sur cette page, remplacez les enregistrements de bureau ci-dessous par les exportations mobiles des mêmes paquets, et faites-le **avant d'ouvrir un document** . Gardez les plugins modèles, styles, locaux et importations de Facade, et enregistrez une seule variante.

| Paquet | Inscription de bureau | Inscription mobile |
| --- | --- | --- |
| `@univerjs-pro/sheets-history-ui` | `UniverSheetsHistoryUIPlugin` | `UniverSheetsHistoryMobileUIPlugin` |

## Mode prédéfini [#preset-mode]

### Installation

```package-install
npm install @univerjs/preset-sheets-collaboration
```

### Utilisation

`UniverSheetsCollaborationPreset` inclut l'interface d'historique et les plugins dont elle dépend. Gardez l'éditeur existant et la configuration de la licence. Si le préréglage est déjà enregistré, mettez-le à jour plutôt que d'enregistrer le préréglé ou les plugins d'historique une seconde fois.

```ts
import { UniverSheetsCollaborationPreset } from '@univerjs/preset-sheets-collaboration'
import CollaborationLocale from '@univerjs/preset-sheets-collaboration/locales/en-US'
import '@univerjs/preset-sheets-collaboration/lib/index.css'

const collaborationPreset = UniverSheetsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### Configuration des préréglages

`UniverSheetsCollaborationPreset`

| <span data-config-options="">Option</span> | Type | Valeur par défaut | Effet |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | URL de base du serveur de collaboration. |
| `univerContainerId` | `string` | `'app'` | ID DOM du conteneur de l’éditeur. |

Ajouter `collaborationPreset` au tableau `presets` de l'appel `createUniver()` existant, et fusionner `CollaborationLocale` dans l'entrée locale correspondante. Définissez `universerEndpoint` à l'URL de base du serveur et `univerContainerId` vers l'ID du conteneur de l'éditeur. Le préréglage compose l'URL d'historique comme `{universerEndpoint}/universer-api/history`, donc utilisez le mode Plugin lorsqu'un `historyServerUrl` ou `viewerPlugins` personnalisé est requis.

## Consulter et restaurer une version

Ouvrez le panneau d'historique dans le menu de l'éditeur et sélectionnez une version pour inspecter son contenu et ses modifications. La restauration réécrit le document partagé courant, de sorte que seuls les utilisateurs avec la permission de restauration devraient être en mesure de l'exécuter, et le serveur doit faire respecter cette autorisation.

Pour vérifier l'intégration, modifier une valeur de cellule, une formule ou un formatage, attendre que la collaboration confirme le changement, puis inspecter la liste d'historique et le contenu de la version. Réouvrir l'application et redémarrer le service pour confirmer que toutes les données persistaient. Restaurer une version antérieure et confirmer qu'une autre session du navigateur reçoit l'état restauré.

Si la liste est vide, vérifiez d'abord si l'historique a été enregistré pour ce document, puis vérifiez l'ID du document et l'URL du service. Si la visualisation fonctionne mais que la restauration échoue, vérifiez les permissions de restauration et la connexion de collaboration.

## Comparer des snapshots [#compare-snapshots]

Pour créer un écran d'examen ou passer des modifications à un agent AI, appelez `compareUnitData()`, ou calculez la comparaison une fois avec `prepareUnitComparison()` et interrogez-la à plusieurs reprises. Enregistrez le plugin History du produit et importez l'entrée Facade, puis passez deux instantanés entièrement matérialisés de la même unité que `beforeSnapshot` ou `afterSnapshot`. La comparaison est en lecture seule, ne nécessite aucun service d'historique, et ne restaure ni ne fusionne de contenu.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SHEET,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Lisez `scopes` pour découvrir les vues disponibles, puis passez l'une d'entre elles à `query()` afin de filtrer le résultat sans re-running de la comparaison. Une page retourne 100 éléments par défaut et jusqu'à 1000. Utilisez `page.hasMore` avec `offset` et pour récupérer les éléments restants. `summary` décrit l'ensemble de la comparaison même lorsque les éléments sont filtrés. Vérifiez `diagnostics.readiness` and `diagnostics.codes` avant de traiter le résultat comme une comparaison complète. Pour Node.js ou CLI sans éditeur, consultez [API de comparaison sans tête](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
