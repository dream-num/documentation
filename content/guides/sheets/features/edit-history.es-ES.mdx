Después de editar valores de celda, fórmulas o formato, abre el panel de historia para revisar versiones anteriores, comparar cambios y restaurar una versión cuando tiene el permiso correspondiente. La historia lee las versiones persistidas en el servidor. Deshacer y redo sólo se aplican a la sesión de edición actual y no requieren el servicio de historia.

## Preparar la colaboración y el historial

Completa [integración de la colaboración](/server/collaboration/browser-integration) y [configuración de licencias](/server/license) primero, a continuación, verificar que dos sesiones pueden editar el mismo documento de Hojas y que los cambios sobreviven a una recarga.

[Ampliación de la colaboración de las oficinas](/server/collaboration/extensions) y el [Ejemplo de historia](/server/collaboration/examples#history) describen cómo conectar el almacenamiento de la historia y los permisos. La colaboración básica no permite la historia por sí sola. El backend también debe proporcionar listas de historia, contenido de la versión y restauración.

Agregue esta configuración al producto existente, licencia y configuración de colaboración. Si un preset o una configuración existente ya registra estos plugins, actualice esa configuración en lugar de registrarlos por segunda vez.

## Modo de complemento [#plugin-mode]

### Instalación

```package-install
npm install @univerjs-pro/edit-history @univerjs-pro/edit-history-ui @univerjs-pro/sheets-history @univerjs-pro/sheets-history-ui
```

### Uso

```ts
import { UniverEditHistoryPlugin } from '@univerjs-pro/edit-history'
import EditHistoryLocale from '@univerjs-pro/edit-history-ui/locale/en-US'
import { UniverSheetsHistoryPlugin } from '@univerjs-pro/sheets-history'
import { UniverSheetsHistoryUIPlugin } from '@univerjs-pro/sheets-history-ui'
import HistoryLocale from '@univerjs-pro/sheets-history-ui/locale/en-US'
import { LocaleType, mergeLocales } from '@univerjs/core'
import '@univerjs-pro/edit-history-ui/lib/index.css'
import '@univerjs-pro/sheets-history-ui/lib/index.css'

const historyServerUrl = '/api/history'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(EditHistoryLocale, HistoryLocale))
univer.registerPlugin(UniverEditHistoryPlugin, { historyServerUrl })
univer.registerPlugin(UniverSheetsHistoryPlugin)
univer.registerPlugin(UniverSheetsHistoryUIPlugin, {
  univerContainerId: 'app',
  historyServerUrl,
})
```

### Configuración de plugins

`UniverEditHistoryPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |

`UniverSheetsHistoryUIPlugin`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `historyServerUrl` | `string` | `'/universer-api/history'` | URL base del servicio de historial. |
| `univerContainerId` | `string` |  | ID DOM del contenedor del editor. |

Reemplazar `/api/history` con el punto final de la historia real de la aplicación, y asegurar que el punto final coincida con las solicitudes que envía el cliente. Ambos valores `historyServerUrl` deben ser idénticos. Establecer `univerContainerId` al DOM ID del contenedor de editor, y cargar el local que el editor utiliza.

La historia de las hojas también requiere que el `UniverCollaborationClientUIPlugin` esté registrado en la configuración de la colaboración.

## Compatibilidad móvil [#mobile-support]

En la configuración de modo plugin en esta página, sustitúyase los registros de escritorio a continuación con las exportaciones móviles de los mismos paquetes, y lo haga **antes de abrir un documento**. ## Modo preestablecido [#preset-mode]

### Instalación

```package-install
npm install @univerjs/preset-sheets-collaboration
```

### Uso

`UniverSheetsCollaborationPreset` incluye la historia UI y los plugins en los que depende. Mantenga el editor existente y la configuración de licencia. Si el preset ya está registrado, actualícelo en lugar de registrar el preset o los plugins de historia por segunda vez.

```ts
import { UniverSheetsCollaborationPreset } from '@univerjs/preset-sheets-collaboration'
import CollaborationLocale from '@univerjs/preset-sheets-collaboration/locales/en-US'
import '@univerjs/preset-sheets-collaboration/lib/index.css'

const collaborationPreset = UniverSheetsCollaborationPreset({
  universerEndpoint: 'https://your-server.example',
  univerContainerId: 'app',
})
```

### Configuración de preajustes

`UniverSheetsCollaborationPreset`

| <span data-config-options="">Opción</span> | Tipo | Valor predeterminado | Efecto |
| --- | --- | --- | --- |
| `universerEndpoint` | `string` | `window.location.origin` | URL base del servidor de colaboración. |
| `univerContainerId` | `string` | `'app'` | ID DOM del contenedor del editor. |

Añada `collaborationPreset` a la matriz `presets` de la llamada existente `createUniver()` y fusione `CollaborationLocale` en la entrada local concordante. Establecer `universerEndpoint` a la URL base del servidor y `univerContainerId` al ID del contenedor del editor. El preset compone la URL de la historia como `{universerEndpoint}/universer-api/history`, así que utilice el modo Plugin cuando se requiere un `historyServerUrl` o `viewerPlugins` personalizado. Los servicios de backend descritos anteriormente permanecen necesarios.

## Consultar y restaurar versiones

Abra el panel de historia del menú del editor y seleccione una versión para inspeccionar su contenido y cambios. La restauración reescribirá el documento compartido actual, por lo que sólo los usuarios con el permiso de restauración deben poder realizarlo, y el servidor debe hacer cumplir ese permiso.

Para verificar la integración, editar un valor celular, una fórmula, o algún formato, esperar la colaboración para confirmar el cambio, y luego inspeccionar la lista de historia y el contenido de la versión. Reabrir la aplicación y reiniciar el servicio para confirmar que todos los datos persisten. Restaurar una versión anterior y confirmar que otra sesión del navegador recibe el estado restaurado.

Si la lista está vacía, primero compruebe si la historia fue registrada para este documento en absoluto, luego comprueba el documento ID y la URL del servicio. Si la visualización de obras pero la restauración falla, compruebo los permisos de restauración y la conexión de colaboración. La historia de la lectura también requiere autorización, ya que las versiones anteriores pueden contener datos que se han borrado.

## Comparar snapshots [#compare-snapshots]

Para construir una pantalla de revisión o pasar cambios a un agente de inteligencia artificial, llame a `compareUnitData()`, o computar la comparación una vez con `prepareUnitComparison()` y consultarla repetidamente. Registrar el plugin de historia del producto e importar la entrada de Facade, luego pasar dos instantáneas totalmente materializadas de la misma unidad que `beforeSnapshot` y `afterSnapshot`. La comparación es sólo lectura, no requiere servicio de historia, y ni restaura ni fusiona contenido.

```ts
import { UnitComparisonDetailLevel, UnitComparisonFidelity } from '@univerjs-pro/edit-history'
import { UniverInstanceType } from '@univerjs/core'
import '@univerjs-pro/edit-history/facade'

const comparison = univerAPI.prepareUnitComparison({
  comparisonId: 'review-1',
  unitId: beforeSnapshot.id,
  type: UniverInstanceType.UNIVER_SHEET,
  fidelity: UnitComparisonFidelity.SNAPSHOT,
  leftData: beforeSnapshot,
  rightData: afterSnapshot,
})
const overview = comparison.query({ detail: UnitComparisonDetailLevel.SUMMARY })
const scope = overview.scopes[0]
const page = comparison.query({ scope, offset: 0, limit: 100 })
console.log(page.items, page.page.hasMore, page.diagnostics)
```

Leer `scopes` para descubrir las vistas disponibles, luego pasar uno de ellos a `query()` para filtrar el resultado sin recortar la comparación. Una página devuelve 100 artículos por defecto y hasta 1.000. `page.hasMore` junto con `offset` para recuperar los elementos restantes. `summary` describe toda la comparación incluso cuando los elementos son filtrados. `diagnostics.readiness` y `diagnostics.codes` antes de tratar el resultado como una comparación completa. Para Node.js o uso de CLI sin un editor, ver el [API de comparación sin cabeza](/reference/packages/plugins/univerjs-pro/edit-history#headless-comparison).
