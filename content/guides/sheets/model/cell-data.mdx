## Cell position

Univer Sheets stores cell data in the [cellData](/reference/types/worksheet-data#celldata) field of an [IWorksheetData](/reference/types/worksheet-data) object. That field holds all information about a cell, including its value, style, and type.

The code below shows the shape of cellData.

```typescript
interface IWorksheetData {
  cellData: {
    // first row
    0: {
      // first column
      0: { v: 'A1' }
      // second column
      1: { v: 'B1' }
    }
    // second row
    1: {
      // first column
      0: { v: 'A2' }
      // second column
      1: { v: 'B2' }
    }
  }
}
```

## Cell data

A cell has the following properties.

| Property | Description |
| --- | --- |
| v | Cell original value |
| s | Cell style id or style object |
| t | Cell type |
| p | Rich text, also a 📝 Univer Docs |
| f | Formula |
| si | Formula id |
| custom | Custom field |

See [ICellData](/reference/types/cell-data) for the type of each property.

### Cell original value

`cellData.v` holds the original value of a cell, which is either a string or a number. In a cell that has a formula, `v` holds the result of that formula.

The example below stores a string in one cell and a number in the other.

```typescript
interface IWorksheetData {
  cellData: {
    0: {
      0: { v: 'A1' }
      1: { v: 1 }
    }
  }
}
```

### Cell style

`cellData.s` holds either a style id or a style object.

When `s` is a string, it is a style id. Univer Sheets optimizes styles by reference, so a repeated style object is stored once, in the [styles](/reference/types/workbook-data#styles) field of IWorkbookData. That field is a map: each key is a style id, and each value is a style object.

<Callout type="warning">
  Avoid color values that carry transparency, such as rgba. When a cell with that kind of background enters the editing state, the content of the cell underneath shows through.
</Callout>

```typescript
interface IWorkbookData {
  styles: {
    random_style_id_1: {
      fs: 12
      bg: {
        rgb: '#ff0000'
      }
    }
  }
}
```

When a cell references that id, the style object is reused.

```typescript
interface IWorksheetData {
  cellData: {
    0: {
      0: {
        v: 'A1'
        s: 'random_style_id_1'
      }
      1: {
        v: 'B1'
        s: 'random_style_id_1'
      }
    }
  }
}
```

When `s` is an object, it is a complete style object ([IStyleData](/reference/types/style-data)).

The style fields are listed below.

| Property | Description |
| --- | --- |
| ff | Font |
| fs | Font size |
| it | Italic |
| bl | Bold |
| ul | Underline |
| st | Strikethrough |
| ol | Overline |
| bg | Background color |
| bd | Border |
| cl | Font color |
| va | Superscript or subscript |
| tr | Text rotation |
| ht | Horizontal alignment |
| vt | Vertical alignment |
| tb | Truncate overflow |
| pd | Padding |
| n | Number format |

See [IStyleData](/reference/types/style-data) for the type of each field.

#### Font

`ff` is the font name, as a string.

```typescript
interface IStyleData {
  ff: 'Arial' // Font name is Arial
}
```

#### Font size

`fs` is a number, in **pt**.

```typescript
interface IStyleData {
  fs: 12 // Font size is 12 pt
}
```

#### Italic

`it` is a boolean number: `0` means not italic, and `1` means italic.

```typescript
interface IStyleData {
  it: 1 // Italic
}
```

#### Bold

`bl` is a boolean number: `0` means not bold, and `1` means bold.

```typescript
interface IStyleData {
  bl: 1 // Bold
}
```

#### Underline

`ul` is an object that describes the underline style.

```typescript
interface IStyleData {
  ul: {
    s: 1 // Whether to show underline
    c: 0 // Whether the color follows the font color. When `c` is 1 (TRUE), cl does not work. The default value is 1
    cl: { // Underline color
      rgb: '#ff0000'
    }
    t: 0 // Underline type
  }
}
```

#### Strikethrough

`st` is an object that describes the strikethrough style.

```typescript
interface IStyleData {
  st: {
    s: 1 // Whether to show strikethrough
    c: 0 // Whether the color follows the font color. When `c` is 1 (TRUE), cl does not work. The default value is 1
    cl: { // Strikethrough color
      rgb: '#ff0000'
    }
    t: 0 // Strikethrough type
  }
}
```

#### Overline

`ol` is an object that describes the overline style.

```typescript
interface IStyleData {
  ol: {
    s: 1 // Whether to show overline
    c: 0 // Whether the color follows the font color. When `c` is 1 (TRUE), cl does not work. The default value is 1
    cl: { // Overline color
      rgb: '#ff0000'
    }
    t: 0 // Overline type
  }
}
```

#### Background color

`bg` is an object that describes the background color.

```typescript
interface IStyleData {
  bg: {
    rgb: '#ff0000' // Background color is red
  }
}
```

#### Border

`bd` is an object that describes the border style.

```typescript
interface IStyleData {
  bd: {
    // Top border
    t: {
      s: 0 // Border style
      cl: { // Border color
        rgb: '#ff0000'
      }
    }
    // Bottom border
    b: {
      s: 0 // Border style
      cl: { // Border color
        rgb: '#ff0000'
      }
    }
    // Left border
    l: {
      s: 0 // Border style
      cl: { // Border color
        rgb: '#ff0000'
      }
    }
    // Right border
    r: {
      s: 0 // Border style
      cl: { // Border color
        rgb: '#ff0000'
      }
    }
  }
}
```

#### Font color

`cl` is an object that describes the font color.

```typescript
interface IStyleData {
  cl: {
    rgb: '#ff0000' // Font color is red
  }
}
```

#### Superscript or subscript

`va` is an enum number: `1` means normal, `2` means subscript, and `3` means superscript.

```typescript
interface IStyleData {
  va: 2 // Subscript
}
```

#### Text rotation

`tr` is an object that describes text rotation.

```typescript
interface IStyleData {
  tr: {
    a: 0 // Text rotation angle
    v: 0 // Whether it is vertical. 1 means vertical, 0 means horizontal. The default value is 0. When v is 1, a is invalid
  }
}
```

#### Horizontal alignment

`ht` is an enum number: `1` means left alignment, `2` means center, and `3` means right alignment.

```typescript
interface IStyleData {
  ht: 1 // Left alignment
}
```

#### Vertical alignment

`vt` is an enum number: `1` means top alignment, `2` means center, and `3` means bottom alignment.

```typescript
interface IStyleData {
  vt: 1 // Top alignment
}
```

#### Truncate overflow

`tb` is an enum number: `1` means overflow, `2` means truncate, and `3` means wrap.

```typescript
interface IStyleData {
  tb: 1 // Overflow
}
```

#### Padding

`pd` is an object that describes padding.

```typescript
interface IStyleData {
  pd: {
    t: 0 // Top padding
    b: 0 // Bottom paddingAdd commentMore actions
    l: 0 // Left padding
    r: 0 // Right padding
  }
}
```

#### Number format [#number-format]

`n` is an object. Its `pattern` field holds the number format as a string. Microsoft documents the format codes [here](https://support.microsoft.com/en-us/office/number-format-codes-5026bbd6-04bc-48cd-bf33-80f18b4eae68).

If `n` is `null`, or if `pattern` is `null`, the cell uses the general format.

```typescript
import type { DEFAULT_TEXT_FORMAT_EXCEL } from '@univerjs/core'

interface IStyleData {
  n: {
    pattern: DEFAULT_TEXT_FORMAT_EXCEL // text format
  }
}
```

To keep a number that starts with 0, or one that could be converted to a date format, from being converted automatically, see [number formatting](/guides/sheets/features/core/numfmt#usage).

### Cell type [#cell-type]

`cellData.t` is a [CellValueType](/reference/enums/cell-value-type) enum that sets the type of the cell. `1` means string, `2` means number, `3` means boolean, and `4` means force text. When the field is not set, Univer recognizes the type automatically.

A boolean cell stores `cellData.v` as `0` or `1`: `0` means false, and `1` means true.

```typescript
interface IWorksheetData {
  cellData: {
    0: {
      0: {
        v: 'A1'
        t: 1 // String
      }
      1: {
        v: 1
        t: 2 // Number
      }
      2: {
        v: 1 // TRUE
        t: 3 // Boolean
      }
      3: {
        v: '012.0'
        t: 4 // Force text
      }
    }
  }
}
```

The force text alert and mark are controlled by `disableForceStringAlert` and `disableForceStringMark`. You can configure them in:
  - [Preset Mode](/guides/sheets/features/core#univerjspreset-sheets-core)
  - [Plugin Mode](/guides/sheets/features/core#univerjssheets-ui)

### Rich text

`cellData.p` is an object that holds rich text, and that object is itself a Univer Doc. See [IDocumentData](/reference/types/document-data) for the full structure.

<Callout>
  When a cell has both `p` and `v` set, only the contents of `p` are displayed.
</Callout>

`cellData.p.body.dataStream` is the rich text content.

### Formula

`cellData.f` is a formula, stored as a string.

```typescript
interface IWorksheetData {
  cellData: {
    0: {
      0: {
        f: '=SUM(A1:B1)' // function SUM
      }
    }
  }
}
```

### Formula ID

`cellData.si` is a string that holds a formula id. Univer Sheets optimizes formulas by reference: once a cell associates its formula with an `si`, other cells can refer to that same formula through the `si`. The cell that carries the `si` must be at the lower right corner of the reference cell; otherwise, exporting to XLSX raises an error.

Call the Facade API `range.getFormulas()` to get the actual formula. It takes the formula `f` that `si` points to and then computes the real formula from the offset between the current cell position and the reference position.

```typescript
interface IWorksheetData {
  cellData: {
    0: {
      0: {
        f: '=SUM(A1:B1)' // Sum formula
        si: 'random_formula_id_1' // ID of the current formula
      }
      1: {
        si: 'random_formula_id_1' // Take the formula corresponding to this ID during calculation
      }
    }
  }
}
```

### Custom field

`cellData.custom` is an object that serves as a custom field. It accepts any data that is valid JSON, so it can store additional information of your own.

Updating `custom` data overwrites the existing `custom` data rather than merging into it. To keep the existing `custom` data, read the `custom` data first, merge it into the new data, and then update.

<Callout type="warning">
  The `custom` field applies only to a few special scenarios. Any user operation can overwrite or delete the data stored in this field, so use it with caution.
</Callout>

```typescript
interface IWorksheetData {
  cellData: {
    0: {
      0: {
        custom: {
          key: 'value'
        }
      }
    }
  }
}
```
