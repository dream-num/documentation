## グローバルライフサイクル

- **スタート**:Univerは初期化しており、まだビジネスユニットが存在しません。
- **レディー**:最初のビジネスユニットが作成されました。後者はこのステージを再びトリガーしません。
- **レンダリングされる**:標準UIは最初のレンダリングスイッチを完了しました。非同期コンテンツは終了できません。
- **ステアディ**:標準UIはレンダリングされた後遅れの後でこの段階に入ります。それはすべての非同期の仕事を待っていません。

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="イベントが通知する対象">

`LifeCycleChanged`は、Univerのグローバルステージを報告しています。例えば、グローバルステージの後にプラグインBが読み込まれると、`Ready`、Bの`onReady()`が実行されましたが、追加のグローバル`Ready`イベントが放出されます。

リスナーを追加すると、そのコールバックは、`Starting`を含む、すぐに現在のステージを受け取ることができます。 現在のステージだけを決定するには、`univerAPI.getCurrentLifecycleStage()`を直接呼び出します。

</Callout>

リスナーを削除するには、コールが返す`disposable`オブジェクトを使用します。

```typescript
disposable.dispose()
```

## プラグインのライフサイクルフック

プラグインが読み込まれると、`onStarting()` を実行し、現在のグローバルステージのホックを追い出します。 A のものとホックコールを比較するために、異なる点で B をロードします。

<LifecycleDemo />

一般的なプラグインは、登録されたときにロードします。 ビジネス型プラグインは通常、そのタイプの最初のユニットが構築される前にロードします。 既に不良なバッチでロードを開始したタイプの新しいプラグイン。 明示的な依存関係は、以前のロードをトリガーすることができます。

バッチ内では、ホックはステージバイステージ、依存性順で同期的に呼び出されます。ホック内の非同期作業は待っていません。ユニット、DOM要素、またはリソースがアクセスする前に存在していることを確認してください。
