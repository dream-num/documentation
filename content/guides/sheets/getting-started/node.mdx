Univer has an isomorphic feature, which means it can run not only in the browser but also in a Node.js environment. You can develop data processing services based on Headless Univer to generate or modify documents on the server side and interact with Univer Sheets through the Facade API.

In Node.js, use plugin mode and register the plugins you need without browser UI plugins.

## Installation

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## Usage

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsEnUS from '@univerjs/sheets/locale/en-US'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      SheetsEnUS,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## Collaborative editing in Node.js [#node-collaboration-example]

Node.js can act as a collaboration client: load an existing workbook from the server, modify it through the Facade API, and synchronize changes to other clients with the same document open. Before running the example, prepare a [collaboration service](/server/collaboration/quick-start), a [client license](/server/license), and an accessible document ID.

### Example files

Organize the files as follows:

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`: Creates Univer and registers the feature plugins, collaboration client, and optional RPC main-process plugin.
- `worker.ts`: Registers the calculation-side formula engine, remote formula, filter, and pivot table plugins, and communicates with the main process over RPC.
- `main.ts`: Loads the collaborative document and demonstrates permissions, basic sheet operations, conditional formatting, data validation, tables, pivot tables, sparklines, images, charts, shapes, grouping, and hyperlinks.

Replace `your-license` in both files with the same license, and replace the server URL, Cookie, document ID, and user IDs. The permission example in `main.ts` also configures collaborators and protected ranges; use actual application users and an identity with the required management permissions.

export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.EN_US,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],
  })

  univer.registerPlugin(UniverLicensePlugin, {
    license: 'your-license',
  })

  registerBasicPlugins(univer, useComputingWorker)
  registerSharedPlugins(univer)

  if (useComputingWorker) {
    registerRPCPlugin(univer)
  }

  registerDocPlugins(univer)
  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer
}

  const fWorkbook = univerAPI.getActiveWorkbook()

function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // Set the workbook name
  fWorkbook.setName('Test Workbook - Node Collaboration Client')

  const fWorksheet = fWorkbook.getActiveSheet()

  // Set a value in cell A1
  fWorksheet
    .getRange('A1')
    .setValue(`Hello! A message from the Node Collaboration Client. The current time is: ${new Date().toString()}.`)

  // Merge the cells in C2:E4
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // Create a defined name for cell A1 and use it in cell A6
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // Insert a new sheet
  const newSheet = fWorkbook.insertSheet('New Sheet from Node Client', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // Insert 3 rows after row 3 (zero-based index).
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // Rename the first sheet and set its row and column counts
    sheets[0].setName('Renamed Sheet 1').setRowCount(100).setColumnCount(10)
    // Freeze the first row and first column of the first sheet
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // Set the gridline color to red in the first sheet
    sheets[0].setGridLinesColor('#FF0000')
    // Get the first sheet’s data range and log its A1 notation
    const dataRange = sheets[0].getDataRange()
    console.warn(`Renamed Sheet 1 Data Range A1 Notation: ${dataRange.getA1Notation()}`)
    // Clear the data range after 5 seconds
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}

### Enable the calculation worker

`createUniverOnNode()` defaults to `useComputingWorker: false`, so formulas run in the current process. The `main.ts` example above explicitly passes `useComputingWorker: true` to enable the calculation worker:

1. In the main process, `UniverProFormulaEnginePlugin`, `UniverSheetsPlugin`, `UniverSheetsFormulaPlugin`, and `UniverSheetsPivotTablePlugin` all set `notExecuteFormula: true` to delegate calculation to the child process through RPC.
2. `UniverRPCNodeMainPlugin` starts the built `worker.js` specified by `workerSrc`.
3. The child process receives data and performs calculations through `UniverRPCNodeWorkerPlugin` and `UniverRemoteSheetsFormulaPlugin`.

`UniverSheetsPivotTablePlugin` distinguishes three modes: set `true` in the main process when using a worker, set `false` in the worker, and omit the option or set `undefined` when running without a worker so that both pivot table services and calculation logic are registered in the current process. Therefore, the main process uses `useComputingWorker ? true : undefined` rather than passing `useComputingWorker` directly.

Node.js starts this worker with `child_process.fork()`. Use your existing build tool to build `main.ts` and `worker.ts` as separate entry points, and set `workerSrc` to the built worker file. The example assumes `worker.js` is in the same directory as the main entry output; adjust the path, extension, and module format to match your build. It uses CommonJS `__dirname` to locate the file; ESM projects should use the corresponding path resolution method.

### Runtime notes

`loadSheetAsync()` loads an existing server document; you do not need to call `createWorkbook()`. The collaboration service identifies the user and checks permissions through authentication information such as the Cookie in `customHeaders`. The server returns the connection’s `memberID`.

This example disables browser offline caching and the single-active-instance lock across tabs, so there is no need to call `setCurrentUser()` for cache isolation between accounts. If you later use features such as comments that depend on the local current user, you can set the application user through `UserManagerService`; this does not replace server authentication.

The example keeps the collaboration connection open after running. Open the same document in a browser to see the changes. `flush()` waits for server acknowledgement of queued collaboration changes. For a one-shot script, call `univer.dispose()` after all asynchronous operations and synchronization have finished.
