## Idioma de la interfaz

`locale` selecciona el paquete de idiomas utilizado para menús, puntas de herramientas, diálogos y otros UI traducidos. `locales` registra esos paquetes sin seleccionar uno. Todas las unidades en la misma instancia Univer comparten este ajuste. Pase `LocaleType` valores como `LocaleType.EN_US`.

- **Todos los productos: interfaz**: `locale` cambia las traducciones de menús, ayudas, diálogos y etiquetas de plugins. No traduce contenido del usuario ni renombra unidades existentes.
- **Hojas: formatos celulares y fórmulas**: Los números y las fechas de las células se renderizan con el número-format locale override primero, luego la instantánea del libro de trabajo `locale`, luego la instancia `locale`. `region` no reemplaza ninguna de estas configuraciones. El comportamiento de las fórmulas como `DOLLAR` y los formatos de moneda aplicados a los resultados financieros todavía utiliza la entrada `locale` normal, como CJK
- **Docs: estadística**: `locale` determina cómo se segmentan y cuentan las palabras.

### Cambiar el idioma durante la ejecución

Antes de cambiar idiomas, carga cada paquete de idiomas para los plugins instalados o presets. `loadLocales()` fusiona traducciones sin conmutación, y `setLocale()` selecciona un idioma sin descargar nada. Una clave de traducción sin coincidencia se muestra como la propia clave. El siguiente ejemplo carga sólo el paquete UI compartido; fusionar los paquetes de idiomas de destino para los otros plugins instalado en la misma llamada.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Registro de paquetes de idiomas en modo complemento

En modo plugin, importar los paquetes de idiomas de los plugins que los proporcionan, fusionarlos en un solo objeto, y pasar ese objeto a la instancia `Univer`:

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignEnUS from '@univerjs/design/locale/en-US' // [!code highlight]
import SheetsUIEnUS from '@univerjs/sheets-ui/locale/en-US' // [!code highlight]
import UIEnUS from '@univerjs/ui/locale/en-US' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      DesignEnUS, // [!code highlight]
      UIEnUS, // [!code highlight]
      SheetsUIEnUS, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="Precaución">
  No todos los plugins incluyen paquetes de idiomas. Cada página de características indica si lo hace.
</Callout>

### Registro de paquetes de idiomas en modo preestablecido

Los paquetes de Preset ya contienen los paquetes de idiomas para sus plugins. Importarlos desde el preset:

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS, // [!code highlight]
    ),
  },
  presets: [UniverSheetsCorePreset()],
})
```

### Paquetes de idiomas personalizados

También se puede construir un paquete de lenguaje personalizado. Agrupe un objeto de paquete de idiomas según sea necesario y pásalo a la instancia `Univer`. Los paquetes de lenguaje presto generalmente residen en el directorio `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Configuración regional

`region` selecciona las convenciones regionales que usan las características regionales. Todas las unidades de la misma instancia Univer la comparten.

Pase `LocaleType` valores para ambos ajustes. Por ejemplo, `LocaleType.EN_US` es `enUS`, mientras que `en-US` es el nombre del archivo del paquete de idiomas y la etiqueta BCP 47. No pase los códigos de país como `US` o `SG` como `region`. Cuando la UI utiliza un local diferente, la región no requiere su paquete de idiomas.

Sin un `region` explícito, el ajuste sigue `locale`, incluyendo llamadas `setLocale()` posteriores. Configurar `region` en la inicialización, o llamar `setRegion()` para que los cambios automáticos sigan, y luego los cambios de idioma mantengan la región seleccionada. Ninguna API pública restaura el siguiente automático, así que actualice ambos valores cuando deben cambiar juntos.

Añadir `region: LocaleType.DE_DE` junto a `locale` en `createUniver()` o `new Univer()` para mantener el idioma UI utilizando convenciones regionales alemanas.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Aquí la interfaz de usuario cambia a inglés mientras que el formato regional permanece alemán. `getCurrentLocale()` y `getCurrentRegion()` devuelven los identificadores que están en efecto. Para cambiar ambos ajustes juntos, llame a ambos sellos con el mismo valor `LocaleType`.

- **Hojas: controles de divisas**: `region` controla el icono de la barra de herramientas de divisas, las opciones de divisas y contabilidad y sus previsiones, y el formato que el comando de divisas aplica.
- **Docs: estadística**: `region` formatea los recuentos mostrados en el cuadro de diálogo y la barra de estado de las estadísticas, como separadores de agrupación. Cambiar `region` no cambia las reglas de contabilidad.
- **Thread comments, when enabled**: `region` controla el formato de fecha y hora mostrados, que utiliza tiempo 24 horas y dígitos latinos, y `locale` controles el texto UI del comentario. Ni cambios horarios almacenados, y `region` no es un ajuste de la zona horaria.
- **Boards, Slides, Bases, PDFs**: `locale` controla la interfaz de usuario traducida. `region` está disponible para funciones compartidas que la consumen, tales como comentarios de hilo una vez integrado, pero no reforma automáticamente tabla o texto de diapositivas, campos de base o contenido PDF.

## Diseño de derecha a izquierda

<Callout type="warning" title="Atención">
  Actualmente, RTL solo es compatible con la capa de UI. La capa de renderizado no admite RTL.
</Callout>

La dirección de diseño es un ajuste separado. Establecer `direction` en la inicialización, o llamar `univerAPI.setDirection('rtl')` / `setDirection('ltr')`. Cambiar `locale` o `region` por sí solo no cambia la dirección de diseño.

```typescript
univerAPI.setDirection('rtl')
```
