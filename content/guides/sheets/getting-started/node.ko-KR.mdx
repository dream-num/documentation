Univer는 동형(isomorphic) 기능을 지원하므로 브라우저뿐 아니라 Node.js 환경에서도 실행할 수 있습니다. 헤드리스 Univer를 기반으로 데이터 처리 서비스를 개발하여 서버 측에서 문서를 생성하거나 수정하고, Facade API를 통해 Univer Sheets와 상호 작용할 수 있습니다.

Node.js에서는 플러그인 모드를 사용하고 브라우저 UI에 의존하지 않는 필요한 플러그인만 등록하세요.

## 설치

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

```typescript
univerAPI.createWorkbook({})
```

## Node.js 환경의 공동 편집 예제 [#node-collaboration-example]

Node.js를 공동 편집 클라이언트로 사용하여 서버에 있는 기존 통합 문서를 불러오고 Facade API로 내용을 수정한 뒤, 같은 문서를 연 다른 클라이언트에 변경 사항을 동기화할 수 있습니다. 실행 전에 [공동 편집 서비스](/server/collaboration/quick-start), [클라이언트 라이선스](/server/license), 접근 가능한 문서 ID를 준비하세요.

### 예제 파일

파일을 다음 구조로 배치합니다.

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`: Univer를 만들고 전체 기능 플러그인, 공동 편집 클라이언트, 선택적인 RPC 메인 프로세스 플러그인을 등록합니다.
- `worker.ts`: 계산 측 수식 엔진, 원격 수식, 필터, 피벗 테이블 플러그인을 등록하고 RPC로 메인 프로세스와 통신합니다.
- `main.ts`: 공동 편집 문서를 불러오고 권한, 기본 시트 작업, 조건부 서식, 데이터 유효성 검사, 테이블, 피벗 테이블, 스파크라인, 이미지, 차트, 도형, 그룹화, 하이퍼링크 API를 차례로 보여 줍니다.

두 파일의 `your-license`를 동일한 라이선스로 바꾸고 서버 주소, Cookie, 문서 ID와 사용자 ID도 실제 값으로 변경하세요. `main.ts`의 권한 예제에는 공동 작업자 및 보호 범위 설정도 포함되어 있으므로 실제 업무 사용자와 필요한 관리 권한을 가진 인증 정보를 사용해야 합니다.

```typescript title="univer.ts"
export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.KO_KR,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],
  })

  univer.registerPlugin(UniverLicensePlugin, {
    license: 'your-license',
  })

  registerBasicPlugins(univer, useComputingWorker)
  registerSharedPlugins(univer)

  if (useComputingWorker) {
    registerRPCPlugin(univer)
  }

  registerDocPlugins(univer)
  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer
}
```

```typescript title="main.ts"
function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // 통합 문서 이름을 설정합니다
  fWorkbook.setName('테스트 통합 문서 - Node 공동 편집 클라이언트')

  const fWorksheet = fWorkbook.getActiveSheet()

  // A1 셀의 값을 설정합니다
  fWorksheet
    .getRange('A1')
    .setValue(`안녕하세요! Node 공동 편집 클라이언트의 메시지입니다. 현재 시각: ${new Date().toString()}.`)

  // C2:E4 범위의 셀을 병합합니다
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // A1 셀의 정의된 이름을 만들고 A6에서 사용합니다
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // 새 시트를 삽입합니다
  const newSheet = fWorkbook.insertSheet('Node 클라이언트의 새 시트', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // 3행 뒤에 3개 행을 삽입합니다(인덱스는 0부터 시작).
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // 첫 번째 시트의 이름을 바꾸고 행 수와 열 수를 설정합니다
    sheets[0].setName('이름을 바꾼 시트 1').setRowCount(100).setColumnCount(10)
    // 첫 번째 시트의 첫 행과 첫 열을 고정합니다
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // 첫 번째 시트의 눈금선 색상을 빨간색으로 설정합니다
    sheets[0].setGridLinesColor('#FF0000')
    // 첫 번째 시트의 데이터 범위를 가져와 A1 표기를 출력합니다
    const dataRange = sheets[0].getDataRange()
    console.warn(`이름을 바꾼 시트 1의 데이터 범위 A1 표기: ${dataRange.getA1Notation()}`)
    // 5초 후 데이터 범위의 내용을 지웁니다
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}
```

### 계산 worker 활성화

`createUniverOnNode()`의 기본값은 `useComputingWorker: false`이며 현재 프로세스에서 수식을 계산합니다. 위의 `main.ts`는 `useComputingWorker: true`를 명시적으로 전달하여 계산 worker를 활성화합니다.

1. 메인 프로세스의 `UniverProFormulaEnginePlugin`, `UniverSheetsPlugin`, `UniverSheetsFormulaPlugin`, `UniverSheetsPivotTablePlugin`에 모두 `notExecuteFormula: true`를 설정하여 RPC를 통해 자식 프로세스에 계산을 맡깁니다.
2. `UniverRPCNodeMainPlugin`이 `workerSrc`에 지정된 빌드된 `worker.js`를 실행합니다.
3. 자식 프로세스는 `UniverRPCNodeWorkerPlugin`과 `UniverRemoteSheetsFormulaPlugin`을 통해 데이터를 수신하고 계산합니다.

`UniverSheetsPivotTablePlugin` 설정은 세 가지 모드를 구분합니다. worker를 사용하는 메인 프로세스에서는 `true`, worker에서는 `false`를 설정합니다. worker를 사용하지 않을 때는 생략하거나 `undefined`를 지정하여 현재 프로세스에 피벗 테이블 서비스와 계산 로직을 함께 등록합니다. 따라서 메인 프로세스에서는 `useComputingWorker`를 직접 전달하지 않고 `useComputingWorker ? true : undefined`를 사용합니다.

이 worker는 Node.js의 `child_process.fork()`로 실행됩니다. 프로젝트에서 사용하는 빌드 도구로 `main.ts`와 `worker.ts`를 각각 독립적인 진입점으로 빌드하고 `workerSrc`가 빌드된 worker 파일을 가리키도록 설정하세요. 예제는 `worker.js`가 메인 진입점 결과물과 같은 디렉터리에 있다고 가정합니다. 경로, 확장자, 모듈 형식은 실제 빌드 결과에 맞춰야 합니다. 예제는 CommonJS의 `__dirname`으로 파일을 찾으므로 ESM 프로젝트에서는 해당 모듈 방식에 맞는 경로 해석을 사용하세요.

### 실행 안내

`loadSheetAsync()`는 서버의 기존 문서를 불러오므로 `createWorkbook()`을 호출할 필요가 없습니다. 공동 편집 서비스는 `customHeaders`에 포함된 Cookie 등의 인증 정보로 사용자를 식별하고 권한을 확인하며, 연결의 `memberID`는 서버가 반환합니다.

이 예제는 브라우저 오프라인 캐시와 여러 탭 간 인스턴스 잠금을 비활성화하므로 계정별 캐시 격리를 위해 `setCurrentUser()`를 호출할 필요가 없습니다. 나중에 댓글처럼 로컬 현재 사용자에 의존하는 기능을 사용할 경우 `UserManagerService`로 업무 사용자를 설정할 수 있습니다. 이 설정은 서버 인증을 대체하지 않습니다.

예제는 실행 후에도 공동 편집 연결을 유지합니다. 브라우저에서 같은 문서를 열면 변경 사항을 확인할 수 있습니다. `flush()`는 대기 중인 공동 편집 변경 사항에 대한 서버 확인을 기다립니다. 일회성 스크립트로 변경한다면 모든 비동기 작업과 동기화가 완료된 뒤 `univer.dispose()`를 호출하여 인스턴스를 해제하세요.
