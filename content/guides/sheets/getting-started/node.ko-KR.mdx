Headless Univer는 대화 형 편집기 UI없이 콘텐츠를 처리하는 Univer의 일부입니다. 그것은 콘텐츠 모델, 명령, 계산 및 브라우저 편집기가있는 Facade API를 공유합니다. 그것은 Node.js에서 실행하거나 UI가 필요없는 작업을위한 브라우저에서 작동합니다. 그 기능은 등록하는 제품 및 기능 플러그인에 따라 다릅니다.

Node.js에서 Headless Univer는 워크북을 생성하거나로드하고, 셀 및 포맷, 변경 행 및 열을 작성하고, 공식을 계산하고, Univer 스냅 샷을 저장합니다. 필터링, 정렬, 유효성, 피벗 테이블 및 차트는 해당 콘텐츠 플러그인이 등록 될 때만 작동합니다. 차트 데이터를 변경하지 않습니다.

아래 예제는 플러그인 모드를 사용합니다. `@univerjs/core` 및 제품 콘텐츠 플러그인은 헤드리스 콘텐츠 레이어에 속합니다. `@univerjs/ui`, 제품 `*-ui` 패키지 및 기본 브라우저 코어 사전 설정은 아닙니다. 예는 여전히 `@univerjs/engine-render`에 의존하지만 캔버스 또는 편집기를 마운트하지 않습니다. [Headless 패키지 경계](/overview/features/shared/server-calculation#headless-packages)는 완전한 분류 및 예외를 나열합니다.

로컬 스냅 샷 작업은 협업 서비스가 필요하지 않습니다. 협업 예로는 클라이언트, 서버 및 인증이 필요합니다. 사무실 변환은 [Server SDK](/server/import-export/node)를 필요로하며 스크린 샷은 [렌더링 런타임](/ai/visual-inspection)가 필요합니다. `/facade` 가져 오기는 기능 플러그인이없고, UI API를 헤드리스 API로 전환하지 않습니다.

## 설치

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## 사용법

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsKoKR from '@univerjs/sheets/locale/ko-KR'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.KO_KR,
  locales: {
    [LocaleType.KO_KR]: mergeLocales(
      SheetsKoKR,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## Node.js 환경의 공동 편집 예제 [#node-collaboration-example]

### 예제 파일

다음과 같이 파일들을 Lay:

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`는 Univer를 생성하고, 기능 플러그인, 협업 클라이언트 및 선택적인 RPC 주요 과정 플러그인을 등록합니다.
- `worker.ts`는 계산 측, 먼 공식, 여과기 및 피벗 테이블 플러그인에 공식적인 엔진을 등록하고 RPC에 주요 과정과 통신합니다.
- `main.ts`는 협업 문서를로드하고 권한, 기본 시트 운영, 조건 서식, 데이터 검증, 테이블, 피벗 테이블, 스파클, 이미지, 차트, 모양, 그룹화 및 하이퍼 링크가 표시됩니다.

`your-license`를 동일한 라이선스로 두 파일로 바꾸고 서버 URL, 쿠키, 문서 ID 및 사용자 ID를 업데이트합니다. `main.ts`의 권한 예제는 필요한 관리 권한을 가진 실제 애플리케이션 사용자 및 ID가 필요한 콜러레이터 및 보호 범위를 구성합니다.

export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.KO_KR,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],

  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer

### 계산 worker 활성화

`createUniverOnNode()`는 `useComputingWorker: false`에 기본적으로, 그래서 공식은 현재 과정에 산출됩니다. `main.ts`의 위 `useComputingWorker: true`를, 계산 노동자를 가능하게 하는 위 예:

1. 주요 과정에서 `UniverProFormulaEnginePlugin`, `UniverSheetsPlugin`의 `UniverSheetsFormulaPlugin` 및 `UniverSheetsPivotTablePlugin`는 모든 세트 `notExecuteFormula: true`를 설정하여 RPC 이상의 어린이 프로세스로 계산합니다.
2. `UniverRPCNodeMainPlugin`는 `workerSrc`에 의해 참조된 붙박이 `worker.js` 시작합니다.
3. 아이 프로세스는 데이터를 수신하고 `UniverRPCNodeWorkerPlugin` 및 `UniverRemoteSheetsFormulaPlugin`를 통해 계산을 수행합니다.

`UniverSheetsPivotTablePlugin`는 그것 달리기에 따라서 이 선택권을 다르게 대우합니다. 노동자로, 주 과정에서 `true`에 그것을 놓고 노동자에 있는 `false`에. 노동자 없이, omit 선택권 또는 `undefined`에 그것을 놓으십시오; 피벗 테이블 서비스 및 계산 논리는 그 때 현재 과정에 등록됩니다. 이 이유를 위해, 주요 과정은 `useComputingWorker ? true : undefined` 보다는 오히려 `useComputingWorker`를 직접 통과합니다.

Node.js는 `child_process.fork()`를 사용하여 노동자를 시작합니다. `main.ts` 및 `worker.ts`을 빌드 도구로 이미 사용하는 별도의 항목 포인트로 빌드 도구로 빌드 도구에 `workerSrc`가 내장 된 작업자 파일에 있습니다. 예를 들어 `worker.js`이 주요 입력 출력과 동일한 디렉토리에 거주하므로 빌드 출력과 일치하도록 경로, 확장 및 모듈 형식을 조정합니다. 예를 들어, ZXQXQ5qXZ는 해당 프로젝트의 `__dirname` 파일을 찾습니다.

### 실행 안내

`loadSheetAsync()`는 이미 서버에서 존재하는 문서를로드하므로 `createWorkbook()`를 호출해야합니다. 공동 서비스는 사용자를 식별하고 `customHeaders`에서 수행 한 인증 정보와 권한을 확인합니다. 서버는 `memberID` 연결을 반환합니다.

예를 들어 브라우저 오프라인 캐싱과 탭의 단일 활성 인스턴스 잠금을 해제하므로 `setCurrentUser()`는 다른 하나의 계정의 캐시를 격리 할 필요가 없습니다. 나중에 로컬 현재 사용자에 따라 기능을 사용하는 경우 `UserManagerService`를 통해 애플리케이션 사용자를 설정할 수 있습니다. 그 설정은 서버 인증을 대체하지 않습니다.

예를 들어, 협업 연결이 완료된 후 열립니다. 변경 사항을 관찰하기 위해 브라우저에서 동일한 문서를 엽니다. `flush()`는 서버가 퀴즈 협업 변경 사항을 인식할 때까지 기다립니다. 한 샷 스크립트를 위해 `univer.dispose()`를 모든 비동기 작동 및 동기화가 완료된 후 호출합니다.
