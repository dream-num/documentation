Use the Facade API to read and write workbook data, apply formatting, and respond to editor events from your application. Its workbook, worksheet, and range objects provide the entry points for common tasks.

Choose your integration mode below to obtain `univerAPI`, or go directly to [finding an API or command](#find-apis-and-commands).

<Callout type="warning" title="Caution">
  For a method that returns a Promise, wait with `await` or `.then()` before reading the result or starting a dependent step. Other methods return a value or Facade object directly. Check the method’s return type in the API reference.
</Callout>

## Integrating Facade API in Plugin Mode

### Installation

To integrate Facade API in the case of installing Univer through plugin mode, the implementation of Facade API is distributed across various plugins and mounted on the global Facade API root object. This means that for those plugins that provide Facade API, you can import their corresponding Facade API implementations as needed.

```typescript
import { FUniver } from '@univerjs/core/facade'
import '@univerjs/ui/facade'
import '@univerjs/docs-ui/facade'
```

<Callout type="warning" title="Caution">
  Not all plugins include a facade package; we will specify this in the documentation for each feature.
</Callout>

### Usage

Facade API is a wrapper around the Univer instance, so you need to wrap the Univer instance with `FUniver` after creating it:

```typescript
import { FUniver } from '@univerjs/core/facade'

const univerAPI = FUniver.newAPI(univer)
```

## Integrating Facade API in Preset Mode

If you integrate Univer with preset mode, it will automatically import the Facade API for the included features and return a corresponding Facade API instance `univerAPI` when you create a Univer instance. You can use it directly.

## Cautions

Not all Facade APIs can be called immediately; some APIs need to be used at specific lifecycle stages. If you encounter issues with immediate execution, please refer to the following method to choose the appropriate lifecycle stage for execution:

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === univerAPI.Enum.LifecycleStages.Rendered) {
    // Code to be executed when the lifecycle stage is Rendered
  }
  if (stage === univerAPI.Enum.LifecycleStages.Steady) {
    // Code to be executed when the lifecycle stage is Steady
  }
})
```

## Find an API or command [#find-apis-and-commands]

Start with the feature guide, then follow its Facade reference to the object you need: [workbook](/reference/facade/workbook), [worksheet](/reference/facade/worksheet), or [range](/reference/facade/range). A method requires both its owning plugin and, in plugin mode, its Facade import.

If a Facade method does not cover your task, look up the exported command in the [owning package](/reference/packages/plugins/univerjs/sheets) and use its `.id`. Menu item IDs, commands, and mutations are different concepts; do not infer one from a toolbar label.

```typescript
import { SetRangeValuesCommand } from '@univerjs/sheets'

console.log(SetRangeValuesCommand.id)
```

To identify the command behind an interaction, register this listener, perform the action in the editor, and inspect the output. It observes commands; it does not execute them or make every observed mutation suitable for direct use.

```typescript
const commandLog = univerAPI.addEvent(univerAPI.Event.CommandExecuted, ({ id, type }) => {
  console.log(id, type)
})
```

Remove the listener when finished. For command registration, parameters, and undo/redo, see [custom commands](/blog/custom-command).

```typescript
commandLog.dispose()
```
