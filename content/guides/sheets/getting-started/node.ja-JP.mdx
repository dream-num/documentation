Univer にはアイソモーフィックな機能があり、ブラウザだけでなく Node.js 環境でも動作します。Headless Univer でデータ処理サービスを開発し、サーバーサイドでドキュメントを生成・編集したり、Facade API を通じて Univer Sheets と連携することができます。

Node.js ではプラグインモードを使用し、ブラウザー UI に依存しない必要なプラグインを登録します。

## インストール

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## 使い方

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsJaJP from '@univerjs/sheets/locale/ja-JP'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: mergeLocales(
      SheetsJaJP,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## Node.js 環境での共同編集の例 [#node-collaboration-example]

Node.js を共同編集クライアントとして使用し、サーバー上の既存のワークブックを読み込み、Facade API で内容を変更して、同じドキュメントを開いている他のクライアントに同期できます。実行前に、[共同編集サービス](/server/collaboration/quick-start)、[クライアントライセンス](/server/license)、アクセス可能なドキュメント ID を用意してください。

### サンプルファイル

次の構成でファイルを配置します。

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`：Univer を作成し、各機能のプラグイン、共同編集クライアント、必要に応じて RPC メインプロセスプラグインを登録します。
- `worker.ts`：計算側の数式エンジン、リモート数式、フィルター、ピボットテーブルの各プラグインを登録し、RPC でメインプロセスと通信します。
- `main.ts`：共同編集ドキュメントを読み込み、権限、基本的なシート操作、条件付き書式、データ入力規則、テーブル、ピボットテーブル、スパークライン、画像、グラフ、図形、グループ化、ハイパーリンクの API を順に示します。

両方のファイルの `your-license` を同じライセンスに置き換え、サーバー URL、Cookie、ドキュメント ID、ユーザー ID も実際の値に変更してください。`main.ts` の権限の例では共同編集者と保護範囲も設定するため、実際の業務ユーザーと、必要な管理権限を持つ認証情報を使用してください。

export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.JA_JP,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],
  })

  univer.registerPlugin(UniverLicensePlugin, {
    license: 'your-license',
  })

  registerBasicPlugins(univer, useComputingWorker)
  registerSharedPlugins(univer)

  if (useComputingWorker) {
    registerRPCPlugin(univer)
  }

  registerDocPlugins(univer)
  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer
}

function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // ワークブック名を設定します
  fWorkbook.setName('テストワークブック - Node 共同編集クライアント')

  const fWorksheet = fWorkbook.getActiveSheet()

  // セル A1 に値を設定します
  fWorksheet
    .getRange('A1')
    .setValue(`こんにちは！Node 共同編集クライアントからのメッセージです。現在の時刻：${new Date().toString()}。`)

  // C2:E4 のセルを結合します
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // セル A1 に定義名を作成し、A6 で使用します
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // 新しいシートを挿入します
  const newSheet = fWorkbook.insertSheet('Node クライアントの新規シート', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // 3 行目の後に 3 行挿入します（インデックスは 0 始まり）。
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // 最初のシートの名前を変更し、行数と列数を設定します
    sheets[0].setName('名前変更後のシート 1').setRowCount(100).setColumnCount(10)
    // 最初のシートの先頭行と先頭列を固定します
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // 最初のシートのグリッド線を赤に設定します
    sheets[0].setGridLinesColor('#FF0000')
    // 最初のシートのデータ範囲を取得し、A1 形式で出力します
    const dataRange = sheets[0].getDataRange()
    console.warn(`名前変更後のシート 1 のデータ範囲（A1 形式）：${dataRange.getA1Notation()}`)
    // 5 秒後にデータ範囲の内容を消去します
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}

### 計算 worker を有効にする

`createUniverOnNode()` の既定値は `useComputingWorker: false` で、現在のプロセスで数式を計算します。上記の `main.ts` は `useComputingWorker: true` を明示的に渡し、計算 worker を有効にしています。

1. メインプロセスの `UniverProFormulaEnginePlugin`、`UniverSheetsPlugin`、`UniverSheetsFormulaPlugin`、`UniverSheetsPivotTablePlugin` にすべて `notExecuteFormula: true` を設定し、RPC を通じて子プロセスに計算を委譲します。
2. `UniverRPCNodeMainPlugin` が `workerSrc` で指定されたビルド済みの `worker.js` を起動します。
3. 子プロセスは `UniverRPCNodeWorkerPlugin` と `UniverRemoteSheetsFormulaPlugin` を通じてデータを受信し、計算します。

`UniverSheetsPivotTablePlugin` の設定には 3 つのモードがあります。worker を使うメインプロセスでは `true`、worker 内では `false` を設定します。worker を使わない場合は省略するか `undefined` を指定し、現在のプロセスにピボットテーブルのサービスと計算処理の両方を登録します。そのため、メインプロセスでは `useComputingWorker` を直接渡さず、`useComputingWorker ? true : undefined` を使用します。

この worker は Node.js の `child_process.fork()` で起動します。プロジェクトで使用しているビルドツールで `main.ts` と `worker.ts` を別々のエントリーポイントとしてビルドし、`workerSrc` をビルド後の worker ファイルに設定してください。サンプルでは `worker.js` がメインエントリーの出力と同じディレクトリにあることを想定しています。パス、拡張子、モジュール形式は実際の出力に合わせてください。ファイルの場所には CommonJS の `__dirname` を使っているため、ESM プロジェクトでは対応するパス解決方法に変更してください。

### 実行時の注意点

`loadSheetAsync()` はサーバー上の既存ドキュメントを読み込むため、`createWorkbook()` を呼び出す必要はありません。共同編集サービスは `customHeaders` の Cookie などの認証情報からユーザーを識別し、権限を確認します。接続の `memberID` はサーバーから返されます。

この例ではブラウザのオフラインキャッシュと複数タブ間のインスタンスロックを無効にしているため、アカウントごとのキャッシュ分離を目的とした `setCurrentUser()` の呼び出しは不要です。後からコメントなどローカルの現在のユーザーに依存する機能を使用する場合は、`UserManagerService` で業務ユーザーを設定できます。これはサーバー認証の代わりにはなりません。

サンプルは実行後も共同編集接続を維持します。ブラウザで同じドキュメントを開くと変更を確認できます。`flush()` はキュー内の変更に対するサーバーの確認を待ちます。単発のスクリプトにする場合は、すべての非同期処理と同期が完了してから `univer.dispose()` でインスタンスを解放してください。
