## Langue de l’interface

`locale` sélectionne le paquet de langues utilisé pour les menus, les tooltips, les dialogues et les autres interfaces traduites. `locales` enregistre ces paquets sans en sélectionner un. Toutes les unités de la même instance Univer partagent ce paramètre. Passez des valeurs `LocaleType` telles que `LocaleType.EN_US`.

- **Tous les produits : interface**: `locale` change les traductions des menus, infobulles, dialogues et libellés des plugins. Le contenu utilisateur et les noms des unités existantes restent inchangés.
- **Feuilles: formats et formules de cellules**: Les numéros de cellules et les dates rendus avec la locale du format de nombres remplacent d'abord, puis l'instantané du cahier de travail `locale`, puis l 'instance `locale`. `region` ne remplace aucun de ces paramètres. Le comportement de la formule comme `DOLLAR` et les formats de devises appliqués aux résultats financiers utilisent toujours `locale` comme la normalisation des entrées CJK.
- **Docs: statistiques**: `locale` détermine comment les mots sont segmentés et comptés.

### Changer la langue à l’exécution

Avant de changer de langue, chargez chaque paquet de langue pour les plugins ou presets installés. `loadLocales()` fusionne les traductions sans commutation, et `setLocale()` sélectionne une langue sans téléchargement. Une clé de traduction sans correspondance est affichée comme la clé elle-même. L'exemple suivant ne charge que le paquet UI partagé; fusionne les paquets de langue cible pour les autres plugins installés dans le même appel.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Enregistrer des packs de langue en mode plugin

En mode plugin, importez les paquets de langues des plugins qui les fournissent, fusionnez-les en un seul objet et passez cet objet à l'instance `Univer` :

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignEnUS from '@univerjs/design/locale/en-US' // [!code highlight]
import SheetsUIEnUS from '@univerjs/sheets-ui/locale/en-US' // [!code highlight]
import UIEnUS from '@univerjs/ui/locale/en-US' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      DesignEnUS, // [!code highlight]
      UIEnUS, // [!code highlight]
      SheetsUIEnUS, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="Attention">
  Chaque plugin n'inclut pas les paquets de langue. Chaque page de fonctionnalité indique si elle le fait.
</Callout>

### Enregistrer des packs de langue en mode prédéfini

Les paquets prédéfinis contiennent déjà les paquets de langue pour leurs plugins. Importez-les à partir du preset:

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS, // [!code highlight]
    ),
  },
  presets: [UniverSheetsCorePreset()],
})
```

### Packs linguistiques personnalisés

Un paquet de langage personnalisé peut également être construit. Assemblez un objet de paquet de langage au besoin et passez-le à l'instance `Univer`. Les paquets de langages prédéfinis résident généralement dans le répertoire `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Paramètres régionaux

`region` sélectionne les conventions régionales que les fonctionnalités régionales utilisent. Toutes les unités de la même instance Univer le partagent.

Passons `LocaleType` valeurs pour les deux paramètres. Par exemple, `LocaleType.EN_US` est `enUS`, alors que `en-US` est le nom du fichier de paquet de langue et l'étiquette BCP 47. Ne pas passer les codes de pays tels que `US` ou `SG` comme `region`. Lorsque l'interface utilisateur utilise un local différent, la région n'a pas besoin de son paquet linguistique.

Sans `region` explicite, le réglage suit `locale`, y compris les appels `setLocale()` ultérieurs. Le réglage `region` à l'initialisation ou l'appel `setRegion()` arrête ce suivi automatique, et les changements de langage ultérieurs conservent la région sélectionnée. Aucune API publique ne restaure le suivant automatique, donc mettez à jour les deux valeurs quand elles doivent changer ensemble.

Ajouter `region: LocaleType.DE_DE` à côté de `locale` dans `createUniver()` ou `new Univer()` pour conserver la langue de l'interface utilisateur tout en utilisant les conventions régionales allemandes.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Ici, l'interface utilisateur passe à l'anglais pendant que le formatage régional reste allemand. `getCurrentLocale()` et `getCurrentRegion()` retournent les identifiants qui sont effectivement en vigueur. Pour modifier les deux paramètres ensemble, appelez les deux setters avec la même valeur `LocaleType`.

- **Feuilles : contrôles des devises**: `region` contrôle l'icône de la barre d'outils de la monnaie, les choix de la monnaie et de la comptabilité et leurs prévisualisations, et le format que la commande de la monnaie s'applique.
- **Docs: statistiques**: `region` formate les nombres affichés dans la boîte de dialogue statistique et la barre d'état, comme le regroupement des séparateurs. La modification de `region` ne modifie pas les règles de comptage.
- **Commentaires de filetage, lorsque activé**: `region` contrôle le format de date et d'heure affiché, qui utilise 24 heures sur 24 et des chiffres latins, et `locale` contrôle le texte de l'interface utilisateur de commentaire. Ni les changements stockés horodatage, et `region` n'est pas un réglage de fuseau horaire.
- **Planches, diapositives, bases, PDFs**: `locale` contrôle l'interface utilisateur traduite. `region` est disponible pour les fonctionnalités partagées qui la consomment, comme les commentaires de thread une fois intégré, mais il ne reformate pas automatiquement le tableau ou le texte de diapositive, les champs de base ou le contenu PDF.

## Disposition de droite à gauche

<Callout type="warning" title="Attention">
  RTL est actuellement pris en charge uniquement par la couche UI. La couche de rendu ne prend pas en charge RTL.
</Callout>

La direction de mise en page est un paramètre séparé. Réglez `direction` à l'initialisation ou appelez `univerAPI.setDirection('rtl')` / `setDirection('ltr')`. La modification de `locale` ou `region` seule ne change pas la direction de mise au point.

```typescript
univerAPI.setDirection('rtl')
```
