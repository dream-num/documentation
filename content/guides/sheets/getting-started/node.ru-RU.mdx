Univer изоморфен: он может работать не только в браузере, но и в среде Node.js. На основе Headless Univer можно создавать сервисы обработки данных, которые генерируют или изменяют документы на сервере и взаимодействуют с Univer Sheets через Facade API.

В Node.js используйте режим плагинов и регистрируйте нужные плагины без компонентов браузерного интерфейса.

## Установка

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## Использование

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsRuRU from '@univerjs/sheets/locale/ru-RU'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.RU_RU,
  locales: {
    [LocaleType.RU_RU]: mergeLocales(
      SheetsRuRU,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## Пример совместного редактирования в Node.js [#node-collaboration-example]

Node.js может работать как клиент совместного редактирования: загружать существующую книгу с сервера, изменять её содержимое через API Facade и синхронизировать изменения с другими клиентами, открывшими тот же документ. Перед запуском подготовьте [сервис совместного редактирования](/server/collaboration/quick-start), [клиентскую лицензию](/server/license) и ID доступного документа.

### Файлы примера

Расположите файлы следующим образом:

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`: создаёт Univer и регистрирует плагины функций, клиент совместного редактирования и необязательный RPC-плагин основного процесса.
- `worker.ts`: регистрирует вычислительный движок формул, плагины удалённых формул, фильтров и сводных таблиц и обменивается данными с основным процессом через RPC.
- `main.ts`: загружает совместный документ и демонстрирует API прав доступа, базовых операций с листами, условного форматирования, проверки данных, таблиц, сводных таблиц, спарклайнов, изображений, диаграмм, фигур, группировки и гиперссылок.

Замените `your-license` в обоих файлах одной и той же лицензией, а также укажите URL сервера, Cookie, ID документа и ID пользователей. Пример прав доступа в `main.ts` также настраивает соавторов и защищённые диапазоны: используйте реальных пользователей приложения и учётную запись с необходимыми правами управления.

  useComputingWorker?: boolean

export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.RU_RU,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],
  })

  univer.registerPlugin(UniverLicensePlugin, {
    license: 'your-license',
  })

  registerBasicPlugins(univer, useComputingWorker)
  registerSharedPlugins(univer)

  if (useComputingWorker) {
    registerRPCPlugin(univer)
  }

  registerDocPlugins(univer)
  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer
}

function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // Задаём название книги
  fWorkbook.setName('Тестовая книга — клиент совместного редактирования Node')

  const fWorksheet = fWorkbook.getActiveSheet()

  // Задаём значение ячейки A1
  fWorksheet
    .getRange('A1')
    .setValue(`Привет! Сообщение от клиента совместного редактирования Node. Текущее время: ${new Date().toString()}.`)

  // Объединяем ячейки диапазона C2:E4
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // Создаём именованный диапазон для A1 и используем его в A6
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // Вставляем новый лист
  const newSheet = fWorkbook.insertSheet('Новый лист клиента Node', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // Вставляем 3 строки после третьей строки (индексация с 0).
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // Переименовываем первый лист и задаём число строк и столбцов
    sheets[0].setName('Переименованный лист 1').setRowCount(100).setColumnCount(10)
    // Закрепляем первую строку и первый столбец первого листа
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // Задаём красный цвет сетки на первом листе
    sheets[0].setGridLinesColor('#FF0000')
    // Получаем диапазон данных первого листа и выводим его в нотации A1
    const dataRange = sheets[0].getDataRange()
    console.warn(`Диапазон данных переименованного листа 1 в нотации A1: ${dataRange.getA1Notation()}`)
    // Очищаем содержимое диапазона через 5 секунд
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}

    .setBackground('red')
    .setFontColor('green')
    .build()
  newSheet.addConditionalFormattingRule(rule)
}

### Включение вычислительного worker

`createUniverOnNode()` по умолчанию использует `useComputingWorker: false` и вычисляет формулы в текущем процессе. В приведённом выше `main.ts` явно передаётся `useComputingWorker: true`, чтобы включить вычислительный worker:

1. В основном процессе плагины `UniverProFormulaEnginePlugin`, `UniverSheetsPlugin`, `UniverSheetsFormulaPlugin` и `UniverSheetsPivotTablePlugin` получают `notExecuteFormula: true` и передают вычисления дочернему процессу через RPC.
2. `UniverRPCNodeMainPlugin` запускает собранный файл `worker.js`, указанный в `workerSrc`.
3. Дочерний процесс получает данные и выполняет вычисления через `UniverRPCNodeWorkerPlugin` и `UniverRemoteSheetsFormulaPlugin`.

`UniverSheetsPivotTablePlugin` различает три режима: `true` в основном процессе при использовании worker, `false` в worker и отсутствие параметра или значение `undefined` без worker, чтобы зарегистрировать и сервисы сводных таблиц, и вычислительную логику в текущем процессе. Поэтому основной процесс использует `useComputingWorker ? true : undefined`, а не передаёт `useComputingWorker` напрямую.

Node.js запускает этот worker через `child_process.fork()`. Используйте инструмент сборки проекта, чтобы собрать `main.ts` и `worker.ts` как отдельные точки входа, и задайте в `workerSrc` путь к собранному файлу worker. В примере предполагается, что `worker.js` расположен в одном каталоге с выходным файлом основной точки входа; путь, расширение и формат модулей должны соответствовать результату сборки. Для поиска файла используется `__dirname` из CommonJS; в проектах ESM нужен соответствующий способ разрешения пути.

### Примечания по запуску

`loadSheetAsync()` загружает существующий документ с сервера, поэтому вызывать `createWorkbook()` не требуется. Сервис совместного редактирования определяет пользователя и проверяет права по данным аутентификации, например Cookie в `customHeaders`. Сервер возвращает `memberID` соединения.

В примере отключены офлайн-кеш браузера и блокировка экземпляра между вкладками, поэтому вызывать `setCurrentUser()` для разделения кеша по учётным записям не нужно. Если позже понадобятся функции, зависящие от локального текущего пользователя, например комментарии, его можно задать через `UserManagerService`. Это не заменяет серверную аутентификацию.

После выполнения пример сохраняет соединение совместного редактирования. Откройте тот же документ в браузере, чтобы увидеть изменения. `flush()` ожидает подтверждения сервера для изменений в очереди. Для одноразового скрипта вызовите `univer.dispose()` после завершения всех асинхронных операций и синхронизации.
