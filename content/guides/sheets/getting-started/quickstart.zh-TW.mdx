本頁介紹 Univer Sheets 的五個核心概念：Unit（內容單元）、外掛、快照、命令和 Facade API。如需在編輯器中檢視這些概念的實際效果，請參閱[安裝和基本使用](/guides/sheets/getting-started/installation)。

## 基本概念 [#basic-concepts]

以下五個術語在 Univer 中反覆出現：

- Unit（內容單元）
- Plugin（外掛）
- Snapshot（快照）
- Command（命令）
- Facade API

### Unit（內容單元） [#unit]

**Unit（內容單元）** 是 Univer 管理的一份完整內容例項：工作簿、文件、簡報、Base、畫板或 PDF。每個 Unit 都有自己的 ID（`unitId`），因此同一型別的兩份文件是兩個不同的 Unit。

包含多個工作表的工作簿仍然是一個 Unit。工作表、單元格區域和單元格都是它的內部物件，不是獨立的 Unit。幻燈片同理，它屬於所在的簡報 Unit。

一個 Univer 例項可以載入多個 Unit。**Snapshot（快照）** 是描述某個 Unit 內容狀態的可序列化資料，與正在編輯的執行時 Unit 不是同一個物件。Unit 級權限作用於整份內容，物件級權限則細化到內部的工作表、段落或元素。

### 外掛

Univer 的功能都以外掛形式提供。外掛是 Univer 應用的基本組成單元，註冊的外掛集合定義了這個應用。

外掛承擔兩類工作：

1. 增加功能。例如 `@univerjs/sheets-filter` 提供篩選功能。
2. 提供其他外掛依賴的基礎能力。例如 `@univerjs/engine-render` 提供渲染能力。

按需組合外掛可以建置符合需求的 Univer 應用，不必載入用不到的程式碼。Univer 沒有提供所需外掛時，也可以自行編寫外掛來擴充套件功能。

### 快照

Univer 透過載入快照來載入文件。每種文件型別有自己的快照格式，編寫快照時必須與 API 型別一致：

1. 試算表的快照格式為 [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata)。
2. 文件的快照格式為 [`IDocumentData`](/reference/types/document-data)。

功能外掛使用 `resources` 欄位儲存資源，例如圖片。具體做法見[外掛自定義模型](/blog/custom-model)。

<Callout type="warning" title="注意事項">
  快照只用於儲存資料。Univer 執行之後，快照並不反映文件的最新狀態。如需把當前狀態儲存為快照，請使用 Facade API 上的儲存快照方法。
</Callout>

### 命令

在 Univer 中，所有對文件資料的修改都透過命令完成。命令讓 Univer 在一個位置觀察變化，撤銷、重做和協同編輯都建立在這一機制之上，功能之間的依賴關係也由 Univer 統一處理。

如需自行傳送命令，請參閱[如何查詢命令 ID](/blog/find-the-command-id)。如果改為透過 Facade API 修改資料，它會準備命令參數併傳送對應的命令。

<Callout type="warning" title="注意事項">
  **不要直接修改 snapshot。** 這樣修改不會生效，也不會觸發檢視或 UI 更新。資料應透過命令或 Facade API 修改。
</Callout>

### Facade API

辦公應用本身較為複雜，Univer 的架構同樣如此。Facade API 在第一方外掛之上提供了一層更簡單的介面，因此不必先理解整套架構即可完成開發任務。

Facade API 仍在持續完善。如有建議或需求，可以在 GitHub 上提交 issue。

Facade API 屬於高層 API，隱藏了底層細節。常見任務的程式碼因此更短；複雜功能可能仍需理解 Univer 的架構，並直接呼叫底層 API。

## 預設模式與外掛模式

預設是一組已經配置好的外掛。兩種模式在外掛相同時提供相同的能力，區別在於應用需要自行提供多少配置。如需快速開始，使用預設；如需明確控制外掛組合和載入時機，使用外掛模式。

<Callout type="warning" title="注意事項">
  所有 Univer 依賴的版本號要保持一致。如果某個預設已經包含了某個外掛，就不要再單獨註冊它，否則可能出現外掛衝突或功能異常。
</Callout>

| 外掛模式                       | 預設模式                                       |
| ------------------------------ | ---------------------------------------------- |
| 需要手動引入對應的 Facade 套件 | facade 包已包含在預設裡 |
| 需要注意同型別功能外掛的註冊順序 | 預設管理它包含的外掛 |
| 支援按需（懶）載入 | 配置好的預設在初始化時一起載入 |
