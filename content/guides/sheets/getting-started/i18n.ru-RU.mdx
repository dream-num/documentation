## Язык интерфейса

`locale` выбирает языковой пакет, используемый для меню, подсказок, диалогов и другого переведенного пользовательского интерфейса. `locales` регистрирует эти пакеты, не выбирая один. Все единицы в одном экземпляре Univer разделяют эту настройку. Передайте значения `LocaleType`, такие как `LocaleType.EN_US`.

- **Все продукты: интерфейс**: `locale` меняет переводы меню, подсказок, диалогов и подписей плагинов. Пользовательский текст и имена существующих документов не меняются.
- **Листы: форматы ячеек и формулы**: Номера ячеек и даты отображаются сначала с переопределением локального формата номера, затем снимок из книги `locale`, затем экземпляр `locale`. `region` не заменяет ни одну из этих настроек. Поведение формулы, такое как `DOLLAR` и валютные форматы, применяемые к финансовым результатам, по-прежнему использует `locale` , как и нормализация ввода CJK.
- **Док: статистика**: `locale` определяет, как слова сегментируются и подсчитываются.

### Смена языка во время работы

Перед переключением языков загрузите каждый языковой пакет для установленных плагинов или предустановок. `loadLocales()` сливает переводы без переключения, а `setLocale()` выбирает язык без скачивания. В качестве самого ключа отображается ключ перевода без совпадения. Следующий пример загружает только общий пакет пользовательского интерфейса; слить пакеты целевого языка для других установленных плагина в тот же вызов.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Регистрация языковых пакетов в режиме плагинов

В режиме плагина импортируйте языковые пакеты из плагинов, которые их предоставляют, объединяйте их в один объект и передайте этот объект в экземпляр `Univer`:

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignEnUS from '@univerjs/design/locale/en-US' // [!code highlight]
import SheetsUIEnUS from '@univerjs/sheets-ui/locale/en-US' // [!code highlight]
import UIEnUS from '@univerjs/ui/locale/en-US' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      DesignEnUS, // [!code highlight]
      UIEnUS, // [!code highlight]
      SheetsUIEnUS, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="Осторожно">
  Не каждый плагин включает языковые пакеты. Каждая страница функции указывает, делает ли это.
</Callout>

### Регистрация языковых пакетов в предустановленном режиме

Предустановленные пакеты уже содержат языковые пакеты для своих плагинов. Импортируйте их из предустановленного:

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS, // [!code highlight]
    ),
  },
  presets: [
    UniverSheetsCorePreset(),
  ],
})
```

### Объединение языковых пакетов [#mergeLocales]

`mergeLocales` объединяет несколько плагинов или предустановленных языковых пакетов в один полный объект языкового пакета:

### Пользовательские языковые пакеты

Также может быть построен пользовательский языковой пакет. Соберите объект языкового пакета по мере необходимости и передайте его в экземпляр `Univer`. Предустановленные языковые пакеты обычно находятся в каталоге `<rootDir>/packages/<PLUGIN_NAME>/locale` .

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### Участие в переводе

В настоящее время Univer включает следующие языковые пакеты:

- `zh-CN`: упрощённый китайский
- `en-US`: английский
- `zh-TW`: традиционный китайский
- `zh-HK`: традиционный китайский (Гонконг)
- `ru-RU`: русский
- `vi-VN`: вьетнамский
- `fa-IR`: персидский
- `fr-FR`: французский
- `ja-JP`: японский
- `ko-KR`: корейский
- `es-ES`: испанский
- `ca-ES`: каталонский
- `sk-SK`: словацкий
- `ar-SA`: арабский
- `de-DE`: немецкий
- `id-ID`: индонезийский
- `it-IT`: итальянский
- `pl-PL`: польский
- `pt-BR`: португальский (Бразилия)

Univer является открытым исходным кодом, и мы приветствуем разработчиков из любого места, чтобы добавить новые локации или улучшить существующие.

## Региональные настройки

`region` выбирает региональные конвенции, которые используют региональные функции. Все единицы в одном экземпляре Univer разделяют его.

Передайте значения `LocaleType` для обеих настроек. Например, `LocaleType.EN_US` - это `enUS`, тогда как `en-US` - это имя файла языкового пакета и тег BCP 47. Не пропускайте коды стран, такие как `US` или `SG`, как `region`. Когда пользовательский интерфейс использует другую локализацию, регион не требует своего языкового набора.

Без явного `region` настройка следует за `locale`, включая более поздние вызовы `setLocale()`. Настройка `region` при инициализации или вызов `setRegion()` останавливает это автоматическое следование, а более поздний языковой переход сохраняет выбранную область. Ни один публичный API не восстанавливает автоматическое следования, поэтому обновляйте оба значения, когда они должны меняться вместе.

Добавьте `region: LocaleType.DE_DE` рядом с `locale` в `createUniver()` или `new Univer()`, чтобы сохранить язык пользовательского интерфейса при использовании региональных конвенций Германии.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Здесь пользовательский интерфейс переключается на английский, а региональное форматирование остается немецким. `getCurrentLocale()` и `getCurrentRegion()` возвращают идентификаторы, которые фактически действуют. Чтобы изменить обе настройки вместе, вызовите оба установщика с одинаковым значением `LocaleType`.

- **Листы: валютный контроль**: `region` управляет значком панели инструментов валюты, выбором валюты и учетной записи, а также форматом, который применяется командой валюты. Изменение его не переписывает существующие форматы ячеек или конвертирует денежные значения.
- **Док: статистика**: `region` форматирует счета, отображаемые в диалоге статистики и строке состояния, такие как разделители групп.Изменение `region` не изменяет правила подсчета.
- **Комментарии, когда включено**: `region` управляет отображаемым форматом даты и времени, в котором используются 24-часовые временные и латинские цифры, а `locale` контролирует текст пользовательского интерфейса комментария. Ни один из них не изменяет сохраненные временные метки, а `region` не является настроем часовой зоны.
- **Доски, слайды, базы, PDF**: `locale` управляет переведенным пользовательским интерфейсом. `region` доступен для общих функций, которые потребляют его, таких как комментарии потоков после интеграции, но он не автоматически переформатирует доску или слайд-текст, поля базы или PDF-контент.

## Расположение справа налево

<Callout type="warning" title="Внимание">
  В настоящее время RTL поддерживается только на уровне UI. Уровень рендеринга не поддерживает RTL.
</Callout>

Настройка направления - отдельная настройка. Установите `direction` при инициализации или вызове `univerAPI.setDirection('rtl')`/`setDirection('ltr')`. Изменение `locale` или `region` само по себе не меняет направление макета.

```typescript
univerAPI.setDirection('rtl')
```
