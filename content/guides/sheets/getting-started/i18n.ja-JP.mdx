## インターフェースの言語

`locale` は、メニュー、ツールチップ、ダイアログ、その他の翻訳された UI に使用される言語パックを選択します。`locales` は、選択せずにそれらのパックを登録します。同じ Univer インスタンスのすべてのユニットは、この設定を共有します。`LocaleType.EN_US` などの`LocaleType` 値を渡します。

- **全製品：UI**：`locale` はメニュー、ツールチップ、ダイアログ、プラグインのラベルを翻訳します。ユーザーの内容や既存ユニット名は変更しません。
- **シート: 細胞のフォーマットおよび方式**: セル番号と日付は、最初にオーバーライドされた番号フォーマットのロケールでレンダリングします。その後、ワークブックスナップショット`locale`、その後、インスタンス`locale`。 `region`は、これらの設定のいずれかを置き換えません。 `DOLLAR`などのフォーミュラ動作や、財務結果に適用される通貨フォーマットは、CJK入力正規化を行うため、`locale`を使用します。
- **Docs: 統計**: `locale`は、単語のセグメント化とカウント方法を決定します。

### 実行時の言語の切り替え

言語を切り替える前に、インストールされたプラグインやプリセットにすべての言語パックをロードします。 `loadLocales()`は、変換せずに翻訳をマージし、`setLocale()`では、何もダウンロードせずに言語を選択しています。 一致のない翻訳キーは、キー自体として表示されません。 次の例は共有されたUIパックだけをロードします; 別のインストールされたプラグインを同じ呼び出しにマージします。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### プラグインモードでの言語パックの登録

プラグインモードでは、それらを提供するプラグインから言語パックをインポートし、それらを単一のオブジェクトにマージし、そのオブジェクトを`Univer`インスタンスに渡します。

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignJaJP from '@univerjs/design/locale/ja-JP' // [!code highlight]
import SheetsUIJaJP from '@univerjs/sheets-ui/locale/ja-JP' // [!code highlight]
import UIJaJP from '@univerjs/ui/locale/ja-JP' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: mergeLocales(
      DesignJaJP, // [!code highlight]
      UIJaJP, // [!code highlight]
      SheetsUIJaJP, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="キューション">
  すべてのプラグインには、言語パックが含まれています。各機能ページは、それが実行するかどうかを状態にします。
</Callout>

### プリセットモードでの言語パックの登録

プリセットパッケージには、プラグインの言語パックが含まれています。プリセットからインポートします。

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreJaJP from '@univerjs/preset-sheets-core/locales/ja-JP' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: mergeLocales(
      UniverPresetSheetsCoreJaJP, // [!code highlight]
    ),
  },
  presets: [
    UniverSheetsCorePreset(),
  ],
})
```

### 言語パックのマージ [#mergeLocales]

`mergeLocales`は複数のプラグインまたはプリセット言語パックを1つの完全な言語パックオブジェクトにマージします。

<Tabs items={['プラグインモード', 'プリセットモード']}>
  <Tab>
    ````typescript
    import { mergeLocales } from '@univerjs/core'

    // 複数の言語パックオブジェクトを引数で渡してマージできます
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 配列としてまとめて渡すことも可能です
    const locales = mergeLocales([
      plugin1Locales,
    ````

### カスタム言語パック

カスタム言語パックも構築できます。必要に応じて言語パックオブジェクトを組み立てて、`Univer`インスタンスに渡します。プリセット言語は、一般的に`<rootDir>/packages/<PLUGIN_NAME>/locale`ディレクトリに残ります。

````typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
````

### 翻訳への貢献

Univer には、現在以下の組み込み言語パックが用意されています：

- `zh-CN`: 中国語（簡体字）
- `en-US`: 英語
- `zh-TW`: 中国語（繁体字）
- `zh-HK`: 中国語（繁体字・香港）
- `ru-RU`: ロシア語
- `vi-VN`: ベトナム語
- `fa-IR`: ペルシャ語
- `fr-FR`: フランス語
- `ja-JP`: 日本語
- `ko-KR`: 韓国語
- `es-ES`: スペイン語
- `ca-ES`: カタルーニャ語
- `sk-SK`: スロバキア語
- `ar-SA`: アラビア語
- `de-DE`: ドイツ語
- `id-ID`: インドネシア語
- `it-IT`: イタリア語
- `pl-PL`: ポーランド語
- `pt-BR`: ポルトガル語（ブラジル）

Univerはオープンソースであり、どこにいても開発者が新しいロケールを追加したり、既存のものを改善したりすることができます。

## 地域設定

`region`は、地域機能が使用する地域の慣習を選択します。同じUniverインスタンスのすべてのユニットは、それを共有します。

`LocaleType` は、両方の設定で値を渡します。たとえば、`LocaleType.EN_US`は `enUS`、`en-US`が言語パックファイル名と BCP 47 タグです。 `US`や`SG`などの国コードを `region`として渡しません。 UI が異なるロケールを使用している場合は、その地域は言語パックを必要としません。

明示的な`region`がなければ、設定は`locale`に続き、後の`setLocale()`呼び出しも含みます。 `region`を初期化時に設定するか、`setRegion()`を呼び出すか、その後の言語変更は選択した領域を維持します。 パブリックAPIは、自動フォローを復元しません。そのため、両方の値が一緒に変更する必要があります。

追加する `region: LocaleType.DE_DE` 次へ `locale` いずれかの `createUniver()` または `new Univer()` ドイツの地方慣習を使ってUI言語を保ちましょう。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

ここでは、ローカルのフォーマットがドイツにとどまる間に、UIスイッチを英語に切り替えます。 `getCurrentLocale()`と`getCurrentRegion()`は、実際に効果のある識別子を返します。 両方の設定を変更するには、同じ`LocaleType`値で両方のセッターを呼び出します。

- **シート:通貨コントロール**: `region`は通貨ツールバーのアイコン、通貨と会計の選択肢、および通貨のコマンドが適用するフォーマットを制御します。 変更は、既存のセルのフォーマットを刷新したり、通貨の値を変換しません。
- **Docs: 統計**:`region`は、セパレータをグループ化するなど、統計ダイアログとステータスバーに表示されたカウントをフォーマットします。 `region`を変更してもカウントルールは変更されません。
- **スレッドコメント, 有効にしたときに**: `region`は、24時間時間およびラテンの数字を使用する表示された日付および時間フォーマットを制御し、`locale` はコメントUIのテキストを制御します。各変更は保存されたタイムスタンプを変え、`region`がタイムゾーンの設定ではありません。
- **ボード、スライド、ベース、PDF**: `locale`は翻訳されたUIを制御します。 `region` は、スレッドコメントが統合されるなど、消費する機能を共有するために利用できますが、自動的にボードやスライドテキスト、ベースフィールド、またはPDFコンテンツを再フォーマットしません。

## 右から左へのレイアウト

<Callout type="warning" title="注意">
  現在、RTL は UI レイヤーのみでサポートされています。レンダリングレイヤーでは RTL をサポートしていません。
</Callout>

レイアウトの方向は別の設定です。 `direction` を初期化に設定するか、`univerAPI.setDirection('rtl')` / `setDirection('ltr')`. 変更 `locale` or `region`単独ではレイアウトの方向を切り替えません。

```typescript
univerAPI.setDirection('rtl')
```
