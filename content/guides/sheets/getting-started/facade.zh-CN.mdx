Univer 的架构需要应对复杂的需求，核心 API 也随之体现了这种复杂性，为此我们提供了面板 API（Facade API）：一个更简单的封装层，由应用代码直接调用。

本页介绍如何在应用中添加 Facade API。后续的功能章节会列出每个功能的主要 Facade API；如需查看全部 Facade API，请参考各个插件的 API 文档。

<Callout type="warning" title="注意事项">
  部分 Facade API 是异步的，修改数据的 API 大多会返回一个 Promise。如果在修改数据后立即读取，需要使用 await 或 .then() 等待调用完成，否则可能得到不符合预期的结果。如需了解哪些 API 会返回 Promise，请查看对应的 API 参考手册。
</Callout>

## 插件模式引入 Facade API

### 安装

以插件模式安装 Univer 时，Facade API 的实现分散在各个插件中，并统一挂载到全局的 Facade API 根对象上。因此，对于提供了 Facade API 的插件，需要按需引入其对应的实现。

```typescript
import { FUniver } from '@univerjs/core/facade'
import '@univerjs/ui/facade'
import '@univerjs/docs-ui/facade'
```

<Callout type="warning" title="注意事项">
  并非所有插件都包含 facade 包，每个功能的文档会说明该插件是否提供。
</Callout>

### 使用

Facade API 是对 Univer 实例的封装。先创建 Univer 实例，再用 `FUniver` 封装该实例：

```typescript
import { FUniver } from '@univerjs/core/facade'

const univerAPI = FUniver.newAPI(univer)
```

## 预设模式引入 Facade API

以预设模式安装时，预设会自动引入所含功能的 Facade API。创建 Univer 实例时会返回对应的 `univerAPI` 实例，可直接使用。

## 注意事项

并非所有 Facade API 都可以立即调用，有些只在特定的生命周期阶段生效。如果立即调用未生效，可按以下方式选择相应的阶段再调用：

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === univerAPI.Enum.LifecycleStages.Rendered) {
    // 在生命周期阶段为 Rendered 时执行的代码
  }
  if (stage === univerAPI.Enum.LifecycleStages.Steady) {
    // 在生命周期阶段为 Steady 时执行的代码
  }
})
```
