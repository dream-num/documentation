Univer 的架構需要應對複雜的需求，核心 API 也隨之體現了這種複雜性，為此我們提供了面板 API（Facade API）：一個更簡單的封裝層，由應用程式碼直接呼叫。

本頁介紹如何在應用中新增 Facade API。後續的功能章節會列出每個功能的主要 Facade API；如需檢視全部 Facade API，請參考各個外掛的 API 文件。

<Callout type="warning" title="注意事項">
  部分 Facade API 是非同步的，修改資料的 API 大多會返回一個 Promise。如果在修改資料後立即讀取，需要使用 await 或 .then() 等待呼叫完成，否則可能得到不符合預期的結果。如需瞭解哪些 API 會返回 Promise，請檢視對應的 API 參考手冊。
</Callout>

## 外掛模式引入 Facade API

### 安裝

以外掛模式安裝 Univer 時，Facade API 的實現分散在各個外掛中，並統一掛載到全域性的 Facade API 根物件上。因此，對於提供了 Facade API 的外掛，需要按需引入其對應的實現。

```typescript
import { FUniver } from '@univerjs/core/facade'
import '@univerjs/ui/facade'
import '@univerjs/docs-ui/facade'
```

<Callout type="warning" title="注意事項">
  並非所有外掛都包含 facade 包，每個功能的文件會說明該外掛是否提供。
</Callout>

### 使用

Facade API 是對 Univer 例項的封裝。先建立 Univer 例項，再用 `FUniver` 封裝該例項：

```typescript
import { FUniver } from '@univerjs/core/facade'

const univerAPI = FUniver.newAPI(univer)
```

## 預設模式引入 Facade API

以預設模式安裝時，預設會自動引入所含功能的 Facade API。建立 Univer 例項時會返回對應的 `univerAPI` 例項，可直接使用。

## 注意事項

並非所有 Facade API 都可以立即呼叫，有些只在特定的生命週期階段生效。如果立即呼叫未生效，可按以下方式選擇相應的階段再呼叫：

```typescript
const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  if (stage === univerAPI.Enum.LifecycleStages.Rendered) {
    // 在生命週期 Rendered 階段執行的程式
  }
  if (stage === univerAPI.Enum.LifecycleStages.Steady) {
    // 在生命週期 Steady 階段執行的程式
  }
})
```
