Univer 具备同构特性，不仅可在浏览器端运行，还能在 Node.js 环境下使用。你可以基于 Headless Univer 开发数据处理服务，在服务器端生成或修改文档，并通过 Facade API 与 Univer Sheets 进行交互。

在 Node.js 中使用插件模式，按需注册不依赖浏览器 UI 的插件。

## 安装

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## 使用

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsZhCN from '@univerjs/sheets/locale/zh-CN'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.ZH_CN,
  locales: {
    [LocaleType.ZH_CN]: mergeLocales(
      SheetsZhCN,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## 协同在 Node.js 环境下的使用示例 [#node-collaboration-example]

Node.js 作为协同客户端加载服务端已有的工作簿，通过 Facade API 修改内容，并将修改同步到打开同一文档的其他客户端。运行前，请准备好[协同服务](/server/collaboration/quick-start)、[客户端许可证](/server/license)和可访问的文档 ID。

### 示例文件

按以下结构组织文件：

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`：创建 Univer，注册完整功能插件、协同客户端和可选的 RPC 主进程插件。
- `worker.ts`：注册计算侧的公式引擎、远程公式、筛选与透视表插件，通过 RPC 与主进程通信。
- `main.ts`：加载协同文档，依次演示权限、基础表格、条件格式、数据验证、表格、透视表、迷你图、图片、图表、形状、分组和超链接 API。

将两个文件中的 `your-license` 替换为同一份许可证，并替换服务地址、Cookie、文档 ID 和用户 ID。`main.ts` 中的权限示例还包含协作者与保护范围设置，需要使用实际业务用户及具备相应管理权限的身份。

function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // Set workbook name
  fWorkbook.setName('Test Workbook - Node Collaboration Client')

  const fWorksheet = fWorkbook.getActiveSheet()

  // Set a value in a cell A1
  fWorksheet
    .getRange('A1')
    .setValue(`Hello! message from the Node Collaboration Client! The current time is: ${new Date().toString()}.`)

  // Merge C2:E4 range cells
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // Create a defined name for cell A1 and use it in cell A6
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // Insert a new sheet
  const newSheet = fWorkbook.insertSheet('New Sheet from Node Client', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // Insert 3 rows after row 3 (0-based index).
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // Rename the first sheet and set its row and column count
    sheets[0].setName('Renamed Sheet 1').setRowCount(100).setColumnCount(10)
    // Freeze first row and first column in the first sheet
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // Set grid lines color to red in the first sheet
    sheets[0].setGridLinesColor('#FF0000')
    // Get data range of the first sheet and log its A1 notation
    const dataRange = sheets[0].getDataRange()
    console.warn(`Renamed Sheet 1 Data Range A1 Notation: ${dataRange.getA1Notation()}`)
    // Clear content of the data range after 5 seconds
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}

`createUniverOnNode()` 默认使用 `useComputingWorker: false`，在当前进程执行公式计算。上面的 `main.ts` 显式传入 `useComputingWorker: true`，启用计算 worker：

1. 主进程中的 `UniverProFormulaEnginePlugin`、`UniverSheetsPlugin`、`UniverSheetsFormulaPlugin` 和 `UniverSheetsPivotTablePlugin` 均设置 `notExecuteFormula: true`，配合 RPC 将计算交给子进程。
2. `UniverRPCNodeMainPlugin` 根据 `workerSrc` 启动已构建的 `worker.js`。
3. 子进程通过 `UniverRPCNodeWorkerPlugin` 和 `UniverRemoteSheetsFormulaPlugin` 接收数据并计算。

`UniverSheetsPivotTablePlugin` 的配置区分三种模式：主进程启用 worker 时设置 `true`，worker 中设置 `false`，不启用 worker 时省略或设置为 `undefined`，在当前进程中同时注册透视表服务和计算逻辑。因此主进程使用 `useComputingWorker ? true : undefined`，不能直接传入 `useComputingWorker`。

这里的 worker 由 Node.js `child_process.fork()` 启动。请使用项目现有的构建工具，将 `main.ts` 和 `worker.ts` 分别作为入口构建，并让 `workerSrc` 指向构建后的 worker 文件。示例假设 `worker.js` 与主入口产物位于同一目录；路径、扩展名及模块格式应与实际构建结果一致。示例使用 CommonJS 的 `__dirname` 定位文件，ESM 项目需改用相应的路径解析方式。

### 运行说明

`loadSheetAsync()` 加载服务端已有文档，无需再调用 `createWorkbook()`。协同服务通过 `customHeaders` 携带的 Cookie 等认证信息识别用户并检查权限，连接的 `memberID` 由服务端返回。

本例未启用浏览器离线缓存和多标签页实例锁，无需为了缓存账号隔离调用 `setCurrentUser()`。如果后续使用评论等依赖本地当前用户的功能，可以再通过 `UserManagerService` 设置业务用户；这不会替代服务端认证。

示例运行后保持协同连接，可在浏览器打开同一文档查看修改。`flush()` 等待已排队的协同修改得到服务端确认；如果改成一次性脚本，应在所有异步操作和同步完成后调用 `univer.dispose()` 释放实例。
