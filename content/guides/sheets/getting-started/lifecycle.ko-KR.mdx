## 전역 수명 주기

- **을 시작**: Univer는 초기화되고, 사업 단위는 아직 존재하지 않습니다.
- **지원하다**: 첫번째 사업 단위는 창조되었습니다. 나중에 단위는 이 단계를 다시 방아쇠하지 않습니다.
- **이름 ***: 표준 UI는 첫번째 렌더링 스위치를 완료했습니다. 비동기 내용은 끝날지도 모릅니다.
- **인기 카테고리**: 표준 UI는 렌더링 후 지연 후이 단계를 입력합니다. 그것은 모든 비동기 작업을 기다릴 수 없습니다.

### Facade API

```typescript
const currentStage = univerAPI.getCurrentLifecycleStage()

const disposable = univerAPI.addEvent(univerAPI.Event.LifeCycleChanged, ({ stage }) => {
  console.log(stage)
})
```

<Callout type="warning" title="이벤트가 알리는 대상">

`LifeCycleChanged`는 Univer의 글로벌 스테이지를 보고 있습니다. 예를 들어, 글로벌 스테이지가 `Ready`에 도달한 후 플러그인 B가 로드되는 경우, B의 `onReady()`가 실행되지만, 추가 글로벌 `Ready` 이벤트가 방출되지 않습니다.

청취자가 추가될 때, 콜백은 `Starting`를 포함한 현재 단계를 즉시 받게 될 수 있습니다. 현재 단계만 결정하려면 `univerAPI.getCurrentLifecycleStage()`로 직접 전화하십시오.

</Callout>

청취자를 제거하려면 `disposable` 개체를 사용하여 통화가 반환됩니다.

```typescript
disposable.dispose()
```

## 플러그인 수명 주기 훅

플러그인로드가되면 `onStarting()`를 실행하고 현재 글로벌 스테이지의 후크를 통해 잡습니다. A의 후크 통화를 비교 할 때 다른 지점에서 B를로드하십시오.

<LifecycleDemo />

일반 플러그인로드가 등록 될 때. 비즈니스 유형 플러그인은 일반적으로 그 유형의 첫 번째 단위 전에로드됩니다. 이미 deferred 배치에로드를 시작 한 유형을위한 새로운 플러그인. Explicit Dependencies는 이전 로딩을 트리거 할 수 있습니다.

일괄 처리 내에서, 후크는 비동기적으로 호출되며, 단계별, 종속 순서. 후크 내부의 비동기 작업은 기다리지 않습니다. 단위, DOM 요소 또는 리소스가 액세스하기 전에 존재한다는 것을 확인하십시오.
