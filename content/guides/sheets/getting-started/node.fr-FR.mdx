Univer est isomorphe, ce qui signifie qu’il peut s’exécuter aussi bien dans un navigateur que dans un environnement Node.js. Vous pouvez développer des services de traitement de données basés sur Univer sans interface graphique afin de générer ou de modifier des documents côté serveur, et interagir avec Univer Sheets au moyen de la Facade API.

Dans Node.js, utilisez le mode plugin et enregistrez les plugins nécessaires sans inclure ceux de l’interface du navigateur.

## Installation

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## Utilisation

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'

import { UniverRenderEnginePlugin } from '@univerjs/engine-render'

import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsFrFR from '@univerjs/sheets/locale/fr-FR'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.FR_FR,
  locales: {
    [LocaleType.FR_FR]: mergeLocales(
      SheetsFrFR,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## Exemple de collaboration dans Node.js [#node-collaboration-example]

Node.js peut servir de client de collaboration : charger un classeur existant depuis le serveur, modifier son contenu avec l’API Facade et synchroniser les changements avec les autres clients ayant ouvert le même document. Avant l’exécution, préparez un [service de collaboration](/server/collaboration/quick-start), une [licence client](/server/license) et un ID de document accessible.

### Fichiers de l’exemple

Organisez les fichiers comme suit :

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts` : crée Univer et enregistre les plugins fonctionnels, le client de collaboration et, si nécessaire, le plugin RPC du processus principal.
- `worker.ts` : enregistre le moteur de formules côté calcul, ainsi que les plugins de formules distantes, de filtres et de tableaux croisés dynamiques, puis communique avec le processus principal par RPC.
- `main.ts` : charge le document collaboratif et illustre les API de permissions, d’opérations de base sur les feuilles, de mise en forme conditionnelle, de validation des données, de tableaux, de tableaux croisés dynamiques, de mini-graphiques, d’images, de graphiques, de formes, de regroupement et de liens hypertextes.

Remplacez `your-license` dans les deux fichiers par la même licence, puis adaptez l’URL du serveur, le Cookie, l’ID du document et les ID des utilisateurs. L’exemple de permissions dans `main.ts` configure aussi les collaborateurs et les plages protégées : utilisez des utilisateurs réels de votre application et une identité disposant des droits de gestion nécessaires.

  useComputingWorker?: boolean

export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.FR_FR,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],
  })

  univer.registerPlugin(UniverLicensePlugin, {
    license: 'your-license',
  })

  registerBasicPlugins(univer, useComputingWorker)
  registerSharedPlugins(univer)

  if (useComputingWorker) {
    registerRPCPlugin(univer)
  }

  registerDocPlugins(univer)
  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer
}

function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // Définir le nom du classeur
  fWorkbook.setName('Classeur de test - Client de collaboration Node')

  const fWorksheet = fWorkbook.getActiveSheet()

  // Définir une valeur dans la cellule A1
  fWorksheet
    .getRange('A1')
    .setValue(`Bonjour ! Message du client de collaboration Node. Heure actuelle : ${new Date().toString()}.`)

  // Fusionner les cellules de C2:E4
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // Créer un nom défini pour A1 et l’utiliser dans A6
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // Insérer une nouvelle feuille
  const newSheet = fWorkbook.insertSheet('Nouvelle feuille du client Node', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // Insérer 3 lignes après la troisième ligne (indice à partir de 0).
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // Renommer la première feuille et définir ses nombres de lignes et de colonnes
    sheets[0].setName('Feuille 1 renommée').setRowCount(100).setColumnCount(10)
    // Figer la première ligne et la première colonne de la première feuille
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // Définir la couleur du quadrillage en rouge dans la première feuille
    sheets[0].setGridLinesColor('#FF0000')
    // Obtenir la plage de données de la première feuille et afficher sa notation A1
    const dataRange = sheets[0].getDataRange()
    console.warn(`Plage de données de la feuille 1 renommée en notation A1 : ${dataRange.getA1Notation()}`)
    // Effacer le contenu de la plage après 5 secondes
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}

  await fRange.updateHyperLink('https://www.google.com/', 'Google')

### Activer le worker de calcul

`createUniverOnNode()` utilise par défaut `useComputingWorker: false` et calcule les formules dans le processus courant. Le fichier `main.ts` ci-dessus passe explicitement `useComputingWorker: true` pour activer le worker de calcul :

1. Dans le processus principal, `UniverProFormulaEnginePlugin`, `UniverSheetsPlugin`, `UniverSheetsFormulaPlugin` et `UniverSheetsPivotTablePlugin` définissent tous `notExecuteFormula: true` pour déléguer les calculs au processus enfant par RPC.
2. `UniverRPCNodeMainPlugin` démarre le fichier `worker.js` compilé indiqué par `workerSrc`.
3. Le processus enfant reçoit les données et effectue les calculs via `UniverRPCNodeWorkerPlugin` et `UniverRemoteSheetsFormulaPlugin`.

`UniverSheetsPivotTablePlugin` distingue trois modes : `true` dans le processus principal avec un worker, `false` dans le worker, et une option omise ou définie à `undefined` sans worker pour enregistrer les services et les calculs de tableaux croisés dynamiques dans le processus courant. Le processus principal utilise donc `useComputingWorker ? true : undefined` au lieu de passer directement `useComputingWorker`.

Node.js démarre ce worker avec `child_process.fork()`. Utilisez votre outil de compilation habituel pour compiler `main.ts` et `worker.ts` comme deux points d’entrée distincts, puis faites pointer `workerSrc` vers le fichier worker compilé. L’exemple suppose que `worker.js` est dans le même répertoire que la sortie principale ; adaptez le chemin, l’extension et le format de module à votre compilation. L’exemple utilise `__dirname` de CommonJS pour localiser le fichier ; un projet ESM doit employer la méthode de résolution correspondante.

### Notes d’exécution

`loadSheetAsync()` charge un document existant sur le serveur ; il est inutile d’appeler `createWorkbook()`. Le service de collaboration identifie l’utilisateur et vérifie les permissions à partir des informations d’authentification, telles que le Cookie dans `customHeaders`. Le serveur renvoie le `memberID` de la connexion.

Cet exemple désactive le cache hors ligne du navigateur et le verrou d’instance entre onglets. Il est donc inutile d’appeler `setCurrentUser()` pour isoler le cache entre comptes. Si vous utilisez ensuite des fonctions comme les commentaires, qui dépendent de l’utilisateur courant local, vous pouvez définir l’utilisateur de l’application avec `UserManagerService` ; cela ne remplace pas l’authentification du serveur.

L’exemple maintient la connexion collaborative après son exécution. Ouvrez le même document dans un navigateur pour voir les modifications. `flush()` attend l’accusé de réception du serveur pour les modifications en attente. Pour un script exécuté une seule fois, appelez `univer.dispose()` une fois toutes les opérations asynchrones et la synchronisation terminées.
