Univerシートは、ユニット、プラグイン、スナップショット、コマンド、Facade APIの小さな概念のセットに組み込まれています。 このページでは、各用語の意味について説明します。 エディタで動作するこれらの概念を見るには、[インストールと基本的な使い方](/guides/sheets/getting-started/installation)を続行します。

## 基本概念 [#basic-concepts]

Univer を通る5つの条件:

- Unit
- プラグイン
- スナップショット
- コマンド
- Facade API

### Unit（コンテンツ単位） [#unit]

**ユニット** は、Univer: ワークブック、ドキュメント、プレゼンテーション、ベース、ボード、または PDF によって管理される完全なコンテンツインスタンスです。各ユニットは、独自の ID (`unitId`) を持ち、同じタイプの2つの文書は、2つの異なるユニットです。

複数のワークシートを含むワークブックは1つのユニットに残ります。ワークシート、セル範囲、セルは、ユニットではなく内部オブジェクトです。スライドは同じルールに従い、それを含むプレゼンテーションユニットに所属します。

1つのUniverインスタンスは、複数のユニットをロードできます。 **スナップショット**は、ユニットのコンテンツの状態を記述するシリアライズ可能なデータであり、それは、編集されるライブユニットと同じオブジェクトではありません。 ユニットにセットされたパーミッションは、コンテンツのインスタンス全体に適用されますが、オブジェクトのパーミッションはコンテンツの内側に適用される。

### プラグイン

Univerの機能はプラグインとして提供されます。プラグインはビルドブロックであり、登録したセットはUniverアプリケーションを定義します。

プラグインは2種類の作業を実行します。

1. 機能を追加します。たとえば、`@univerjs/sheets-filter`は、フィルタリングを提供します。
2. 他のプラグインに依存する基本的な機能を提供します。 `@univerjs/engine-render`はレンダリングを提供します。

プラグインを組み合わせると、要件の周りのアプリケーションを形作り、必要ないコードを除外できます。 Univer が要件のプラグインがない場合、自分で書き込むことができます。

### スナップショット

Univer は、スナップショットをロードすることでドキュメントをロードします。各ドキュメントタイプには独自のスナップショット形式がありますので、スナップショットは API の種類にマッチしなければなりません。

1. スプレッドシートスナップショットは[`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata)を使用します。
2. ドキュメントスナップショットは、[`IDocumentData`](/reference/types/document-data)を使用します。

機能プラグインは、`resources`フィールド内の画像などのリソースを保存します。 [プラグインカスタムモデル](/blog/custom-model)は、その仕組みを説明しています。

<Callout type="warning" title="キューション">
  スナップショットはデータのみを保存します。 Univer が実行中は、ドキュメントの現在の状態を反映しません。 現在の状態をスナップショットとしてキャプチャするには、Facade APIの保存スナップショットメソッドを使用します。
</Callout>

### コマンド

Univerの文書データへの変更は、コマンドを経由します。コマンドは、変更されたものを観察するための単一の場所をUniverに与えます。これは、やり直し、やりとりの基礎です。また、Univerは、機能間の依存関係を解決させます。

コマンドを直接ディスパッチするには、[コマンド ID の検索方法](/blog/find-the-command-id)を参照してください。 Facade APIを介してデータを変更すると、コマンドパラメータを用意し、コマンドをディスパッチします。

<Callout type="warning" title="キューション">
  **スナップショットを直接変更しないでください。** 変更は、効果がなく、ビューやUIをリフレッシュしません。 コマンドやFacade APIでデータを変更します。
</Callout>

### Facade API

オフィスアプリケーションは複雑で、Univerのアーキテクチャです。 Facade APIはUniverの最初のパーティプラグインをシンプルなインターフェイスで包みます。そのため、タスクを完了する前にアーキテクチャ全体を学ぶ必要はありません。

Facade APIのカバレッジは成長し続けています。ギャップや何かが不明な場合は、GitHubで問題を開きます。

Facade APIは、基礎的な詳細を隠す高レベルのAPIです。 共通のタスクはより短くなります。 複雑なタスクは、Univerのアーキテクチャの理解と低レベルのAPIへの直接呼び出しを必要とするかもしれません。

## プリセットモードとプラグインモード

プリセットは、既に設定されているプラグインの束です。 両方のモードが同じプラグインを受け取ると、同じ機能を公開します。 違いは、アプリケーションが提供しなければならない設定の量にあります。 クイックスタート、およびプラグインモードのプリセットを使用して、コンポジションと読み込みを明示的に制御する必要があります。

<Callout type="warning">
  Univer の依存性を同じバージョンに保ちましょう。プリセットにプラグインが既に含まれている場合は、再度登録しないでください。プラグインの競合や機能の誤動作が発生することがあります。
</Callout>

| プラグインモード                                           | プリセットモード                                                                               |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 対応する facade パッケージを手動でインポートする必要がある | facade パッケージを手動でインポートする必要はない                                              |
| 同一機能を持つプラグインの登録順序に注意する必要がある     | プリセットに含まれる機能の登録順序に注意する必要はない                                         |
| プラグインをオンデマンドにロード | 設定したプリセットは初期化時に同期的に読み込まれる |
