## Interface language

`locale` selects the language pack used for menus, tooltips, dialogs, and other translated UI. `locales` registers those packs without selecting one. All units in the same Univer instance share this setting. Pass `LocaleType` values such as `LocaleType.EN_US`.

- **All products: UI**: `locale` changes translated menus, tooltips, dialogs, and plugin labels. It does not translate user content or rename existing units.
- **Sheets: cell formats and formulas**: Cell numbers and dates render with the number-format locale override first, then the workbook snapshot `locale`, then the instance `locale`. `region` does not replace any of these settings. Formula behavior such as `DOLLAR` and the currency formats applied to financial results still uses `locale`, as does CJK input normalization.
- **Docs: statistics**: `locale` determines how words are segmented and counted.

### Changing language at runtime

Before switching languages, load every language pack for the installed plugins or presets. `loadLocales()` merges translations without switching, and `setLocale()` selects a language without downloading anything. A translation key with no match is displayed as the key itself. The following example loads only the shared UI pack; merge the target-language packs for the other installed plugins into the same call.

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### Registering language packs in plugin mode

In plugin mode, import the language packs from the plugins that provide them, merge them into a single object, and pass that object to the `Univer` instance:

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignEnUS from '@univerjs/design/locale/en-US' // [!code highlight]
import SheetsUIEnUS from '@univerjs/sheets-ui/locale/en-US' // [!code highlight]
import UIEnUS from '@univerjs/ui/locale/en-US' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      DesignEnUS, // [!code highlight]
      UIEnUS, // [!code highlight]
      SheetsUIEnUS, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="Caution">
  Not every plugin includes language packs. Each feature page states whether it does.
</Callout>

### Registering language packs in preset mode

Preset packages already contain the language packs for their plugins. Import them from the preset:

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS, // [!code highlight]
    ),
  },
  presets: [
    UniverSheetsCorePreset(),
  ],
})
```

### Merging language packs [#mergeLocales]

`mergeLocales` merges several plugin or preset language packs into one complete language pack object:

    // You can pass multiple language pack objects to merge
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // You can also pass an array of language pack objects
    const locales = mergeLocales([

### Custom language packs

A custom language pack can also be built. Assemble a language pack object as needed and pass it to the `Univer` instance. Preset language packs generally reside in the `<rootDir>/packages/<PLUGIN_NAME>/locale` directory.

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

## Regional settings

`region` selects the regional conventions that regional features use. All units in the same Univer instance share it.

Pass `LocaleType` values for both settings. For example, `LocaleType.EN_US` is `enUS`, whereas `en-US` is the language pack file name and BCP 47 tag. Do not pass country codes such as `US` or `SG` as `region`. When the UI uses a different locale, the region does not require its language pack.

Without an explicit `region`, the setting follows `locale`, including later `setLocale()` calls. Setting `region` at initialization, or calling `setRegion()`, stops that automatic following, and later language changes keep the selected region. No public API restores the automatic following, so update both values when they should change together.

Add `region: LocaleType.DE_DE` next to `locale` in either `createUniver()` or `new Univer()` to keep the UI language while using German regional conventions.

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

Here the UI switches to English while regional formatting stays German. `getCurrentLocale()` and `getCurrentRegion()` return the identifiers that are actually in effect. To change both settings together, call both setters with the same `LocaleType` value.

- **Sheets: currency controls**: `region` controls the currency toolbar icon, the currency and accounting choices and their previews, and the format that the currency command applies. Changing it does not rewrite existing cell formats or convert monetary values.
- **Docs: statistics**: `region` formats the counts displayed in the statistics dialog and status bar, such as grouping separators. Changing `region` does not change the counting rules.
- **Thread comments, when enabled**: `region` controls the displayed date and time format, which uses 24-hour time and Latin digits, and `locale` controls the comment UI text. Neither changes stored timestamps, and `region` is not a timezone setting.
- **Boards, Slides, Bases, PDFs**: `locale` controls the translated UI. `region` is available to shared features that consume it, such as thread comments once integrated, but it does not automatically reformat board or slide text, Base fields, or PDF content.

## Right-to-left layout

<Callout type="warning" title="Caution">
  RTL currently supports only the UI layer. The rendering layer does not support RTL.
</Callout>

Layout direction is a separate setting. Set `direction` at initialization, or call `univerAPI.setDirection('rtl')` / `setDirection('ltr')`. Changing `locale` or `region` alone does not switch the layout direction.

```typescript
univerAPI.setDirection('rtl')
```
