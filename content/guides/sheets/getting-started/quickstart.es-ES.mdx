Univer Sheets se construye en un pequeño conjunto de conceptos: Unidades, Plugins, Snapshots, Commands y Facade API. Esta página explica lo que significa cada término. Para ver estos conceptos trabajando en un editor, continúe con [instalación y uso básico](/guides/sheets/getting-started/installation) .

## Conceptos básicos [#basic-concepts]

Cinco términos se repiten a través de Univer:

- Unit
- Complemento
- Instantánea
- Comando
- API de Fachada

### Unit (unidad de contenido) [#unit]

Un **Dependencia** es una instancia de contenido completa gestionada por Univer: un libro de trabajo, un documento, una presentación, una Base, una tabla o un PDF. Cada Unidad tiene su propio ID (`unitId`), por lo que dos documentos del mismo tipo son dos unidades distintas.

Un libro de trabajo que contiene varias hojas de trabajo sigue siendo una Unidad. Sus hojas de trabajo, los rangos de celdas y las células son objetos internos en lugar de Unidades propias. Una diapositiva sigue la misma regla y pertenece a la Unidad de presentación que la contiene.

Una instancia Univer puede cargar varias Unidades. Un **Snapshot** es datos serializables que describen el estado de contenido de una Unidad, y no es el mismo objeto que la unidad en vivo que se está editando. Permisos establecidos en una Unidad se aplican a toda la instancia de contenido, mientras que los permisos de objetos se aplican al contenido dentro de ella.

### Complementos

Las características de Univer se proporcionan como plugins. Los plugins son los bloques de construcción, y el conjunto que se registra define la aplicación Univer.

Los plugins realizan dos tipos de trabajo:

1. Añaden una característica. `@univerjs/sheets-filter`, por ejemplo, proporciona filtrado.
2. Suministran las capacidades básicas de las que dependen otros plugins. `@univerjs/engine-render` proporciona renderización.

Combinar plugins le permite configurar la aplicación alrededor de sus requisitos y excluir el código que no necesita. Cuando Univer no tiene plugin para un requisito, puede escribir su propio.

### Instantánea

Univer carga un documento cargando su instantánea. Cada tipo de documento tiene su propio formato de instantánea, por lo que la instantánea debe coincidir con los tipos de API:

1. Una instantánea de hoja de cálculo utiliza [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata).
2. Una instantánea de documento utiliza [`IDocumentData`](/reference/types/document-data).

Los plugins de alimentación almacenan recursos como imágenes en el campo `resources`. [Modelo personalizado de plugin](/blog/custom-model) explica cómo funciona.

<Callout type="warning" title="Precaución">
  Una instantánea sólo almacena datos. Mientras Univer está funcionando, no refleja el estado actual del documento. Para capturar el estado actual como una instantánea, utilice el método de captura de captura en el Facade API.
</Callout>

### Comando

Cada cambio para documentar datos en Univer pasa por un comando. Los comandos dan a Univer un solo lugar para observar lo que cambió, que es la base de undo, redo y edición colaborativa. También permiten que Univer resuelva las dependencias entre características.

Para enviar los comandos directamente, consulte [Cómo encontrar el ID del Comando](/blog/find-the-command-id). Al cambiar los datos a través de Facade API, prepara los parámetros de comando y envía el comando.

<Callout type="warning" title="Precaución">
  **No modifique la instantánea directamente.** Los cambios realizados de esa manera no tienen ningún efecto y no refrescan la vista ni la interfaz de usuario. Cambia los datos a través de un comando o el Facade API.
</Callout>

### API de Facade

Las aplicaciones de oficina son complejas, y también la arquitectura de Univer. El Facade API envuelve los plugins de Univer de primera parte en interfaces más simples, por lo que no necesita aprender toda la arquitectura antes de que pueda completar una tarea.

La cobertura de Facade API sigue creciendo. Si encuentras una brecha o algo no está claro, abre un problema en GitHub.

El Facade API es una API de alto nivel que oculta los detalles subyacentes. Las tareas comunes se vuelven más cortas. Las labores complejas todavía pueden requerir una comprensión de la arquitectura de Univer y llamadas directas a la API de menor nivel.

## Modo preset y modo plugin

Un preset es un paquete de plugins que ya están configurados. Cuando ambos modos reciben los mismos plugins, exponen las mismas capacidades. La diferencia radica en la cantidad de configuración que debe proporcionar la aplicación. Utilice un preset para un inicio rápido, y modo plugin cuando usted necesita control explícito sobre la composición y la carga.

<Callout type="warning">
  Mantenga cada dependencia Univer en la misma versión. Si un preset ya incluye un plugin, no lo registre de nuevo; de lo contrario, pueden ocurrir conflictos de plugins o funciones malfuncionales.
</Callout>

| Modo plugin | Modo preset |
| --- | --- |
| Importar explícitamente las extensiones Facade | Extensiones Facade incluidas |
| Controlar el orden de registro | El preset gestiona sus plugins |
| plugins de carga bajo demanda | Cargar los presets configurados al inicializar |
