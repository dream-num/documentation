Les feuilles Univer sont construites sur un petit ensemble de concepts : Unités, Plugins, Snapshots, Commandes et Facade API. Cette page explique ce que signifie chaque terme. Pour voir ces concepts travailler dans un éditeur, continuez avec [l'installation et l'utilisation de base](/guides/sheets/getting-started/installation) .

## Concepts de base [#basic-concepts]

Cinq termes réapparaissent dans Univer :

- Unit
- Plugin
- Instantané
- Commande
- Facade API

### Unit (unité de contenu) [#unit]

Un **Unité** est une instance de contenu complète gérée par Univer : un cahier d'exercices, un document, une présentation, une base, une planche ou un PDF. Chaque unité a son propre ID (`unitId`), donc deux documents du même type sont deux unités distinctes.

Un cahier de travail qui contient plusieurs feuilles de travail reste une unité. Ses feuilles de travail, les gammes de cellules et les cellules sont des objets internes plutôt que des unités de leur propre. Une diapositive suit la même règle et appartient à l'unité de présentation qui le contient.

Une instance Univer peut charger plusieurs Unités. Une **Coup d'oeil instantané** est des données sérialisables qui décrivent l'état du contenu d'une Unité, et ce n'est pas le même objet que l'Unité live en cours d'édition. Les autorisations définies sur une Unité s'appliquent à l'ensemble de l'instance de contenu, tandis que les autorisations d'objets s'appliquent au contenu à l'intérieur.

### Plugins

Les fonctionnalités de Univer sont fournies sous forme de plugins. Les plugins sont les blocs de construction, et le jeu que vous enregistrez définit l'application Univer.

Les greffons effectuent deux types de travail:

1. Ils ajoutent une fonctionnalité. `@univerjs/sheets-filter`, par exemple, fournit le filtrage.
2. Ils fournissent les capacités de base sur lesquelles les autres plugins dépendent. `@univerjs/engine-render` fournit le rendu.

Combiner des plugins vous permet de façonner l'application autour de vos exigences et d'exclure le code dont vous n'avez pas besoin. Lorsque Univer n'a pas de plugin pour une exigence, vous pouvez écrire votre propre.

### Instantané

Univer charge un document en chargeant son instantané. Chaque type de document a son propre format d'instantané, de sorte que l'instantanés doit correspondre aux types d'API:

1. Un snapshot de tableur utilise [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata).
2. Un instantané de document utilise [`IDocumentData`](/reference/types/document-data).

Les plugins de fonctionnalité stockent des ressources telles que des images dans le champ `resources`. [Modèle personnalisé de greffon](/blog/custom-model) explique comment cela fonctionne.

<Callout type="warning" title="Attention">
  Un snapshot ne stocke que les données. Alors que Univer est en cours d'exécution, il ne reflète pas l'état actuel du document. Pour capturer l'état courant en tant qu'instantané, utilisez la méthode save-snapshot sur le Facade API.
</Callout>

### Commande

Chaque changement aux données de documents dans Univer passe par une commande. Les commandes donnent à Univer un seul endroit pour observer ce qui a changé, qui est la base de l'édition non faite, refaite et collaborative. Ils laissent également Univer résoudre les dépendances entre les fonctionnalités.

Pour l'expédition des commandes directement, voir [Comment trouver l'ID de commande](/blog/find-the-command-id). Lorsque vous changez de données via le Facade API, il prépare les paramètres de commande et envoie la commande.

<Callout type="warning" title="Attention">
  **Ne modifiez pas l'instantané directement.** Les modifications effectuées de cette façon n'ont aucun effet et ne rafraîchissent pas la vue ou l'interface utilisateur. Changez les données via une commande ou la Facade API.
</Callout>

### Facade API

Les applications Office sont complexes, tout comme l'architecture de Univer. Le Facade API enveloppe les plugins de première partie de Univer dans des interfaces plus simples, de sorte que vous n'avez pas besoin d'apprendre toute l'architecture avant de pouvoir accomplir une tâche.

La couverture Facade API continue de croître. Si vous rencontrez un écart ou quelque chose n'est pas clair, ouvrez un problème sur GitHub.

La Facade API est une API de haut niveau qui masque les détails sous-jacents. Les tâches courantes deviennent plus courtes. Les tâches complexes peuvent encore nécessiter une compréhension de l'architecture de Univer et des appels directs vers l'API de bas niveau.

## Mode preset et mode plugin

Un preset est un paquet de plugins déjà configurés. Lorsque les deux modes reçoivent les mêmes plugins, ils exposent les mêmes capacités. La différence réside dans la quantité de configuration que l'application doit fournir. Utilisez un preset pour un démarrage rapide, et le mode plugin lorsque vous avez besoin de contrôle explicite sur la composition et le chargement.

<Callout type="warning">
  Gardez chaque dépendance de Univer sur la même version. Si un preset inclut déjà un plugin, ne l'enregistrez pas à nouveau; sinon des conflits de plugin ou des dysfonctionnements de fonctionnalité peuvent survenir.
</Callout>

| Mode plugin | Mode preset |
| --- | --- |
| Importer explicitement les extensions Facade | Extensions Facade incluses |
| Contrôler l’ordre d’enregistrement | Le preset gère ses plugins |
| Charger les plugins sur demande | Charger les presets configurés à l’initialisation |
