## Concepts de base [#basic-concepts]

Avant d’aller plus loin avec Univer, lisez ce document pour en comprendre les concepts de base. Vous pourrez ainsi utiliser Univer plus facilement.

Ces concepts de base sont les suivants :

- Plugin
- Instantané
- Commande
- Facade API

### Plugins

Toutes les fonctionnalités d’Univer sont fournies par des plugins, qui en constituent les briques fondamentales. La combinaison de plusieurs plugins forme une application Univer.

Les plugins ont notamment les responsabilités suivantes :

1. Implémenter des fonctionnalités, par exemple `@univerjs/sheets-filter` fournit une fonction de filtrage.
2. Fournir des capacités de base, par exemple `@univerjs/engine-render` fournit les capacités de rendu.

Vous pouvez combiner les plugins d’Univer pour créer une application adaptée à vos besoins tout en évitant de charger du code inutile. Vous pouvez également étendre les fonctionnalités d’Univer en écrivant vos propres plugins afin de répondre à des besoins spécifiques.

### Instantané

Pour charger un document dans Univer, vous devez charger un instantané. Chaque type de document possède son propre format d’instantané. Consultez la documentation de l’API mentionnée ci-dessus pour savoir comment créer un instantané conforme au format requis :

1. Le format d’instantané d’une feuille de calcul est [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata).
2. Le format d’instantané d’un document est [`IDocumentData`](https://reference.univer.ai/en-US/interfaces/IDocumentData).

Les plugins fonctionnels peuvent stocker des ressources, telles que des images, dans le champ `resources`. Pour plus d’informations, consultez [Modèle de plugin personnalisé](/guides/recipes/tutorials/custom-model).

<Callout type="warning" title="Attention">
  Remarque : l’instantané d’Univer sert uniquement à stocker les données. Il ne reflète pas le dernier état du document au moment de l’exécution ! Pour enregistrer l’état du document sous forme d’instantané, utilisez la méthode d’enregistrement d’instantané de la Facade API.
</Callout>

### Commande

Dans Univer, toute modification des données doit être effectuée au moyen de commandes. Cette approche permet de mieux suivre l’évolution des valeurs, de mettre en œuvre des fonctions telles que l’annulation, le rétablissement et l’édition collaborative, ainsi que de gérer les interactions complexes entre les fonctionnalités.

Pour modifier les données d’un document au moyen de commandes, consultez [Comment trouver l’ID d’une commande](/guides/recipes/practices/find-the-command-id). Si vous choisissez d’utiliser la Facade API, celle-ci prépare en réalité les paramètres à votre place et exécute les commandes en arrière-plan.

<Callout type="warning" title="Attention">
  **Ne modifiez pas directement l’instantané !** La modification ne prendra pas effet et ne déclenchera pas la mise à jour des vues ni de l’interface utilisateur. Modifiez les données au moyen de commandes ou de la Facade API.
</Callout>

### Facade API

Les applications bureautiques étant très complexes, l’architecture d’Univer l’est également. Afin de faciliter l’utilisation d’Univer par les développeurs, nous proposons la Facade API. Cette couche enveloppe les plugins officiels d’Univer et fournit des interfaces plus simples.

La Facade API fait l’objet d’améliorations continues. Si vous avez des questions ou des besoins particuliers, veuillez ouvrir une issue sur GitHub.

La Facade API est une API de haut niveau qui masque les détails sous-jacents. Elle simplifie les tâches courantes, mais les fonctionnalités complexes peuvent nécessiter de comprendre l’architecture d’Univer et d’utiliser directement l’API de bas niveau.
