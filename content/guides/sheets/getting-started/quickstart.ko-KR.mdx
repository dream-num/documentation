Univer 시트는 단위, 플러그인, Snapshots, Commands 및 Facade API의 작은 세트에 내장되어 있습니다. 이 페이지는 각 용어의 의미를 설명합니다. 편집기에서 작동하는이 개념을 보려면 [설치 및 기본 사용](/guides/sheets/getting-started/installation)를 계속하십시오.

## 기본 개념 [#basic-concepts]

Univer를 통하여 5개의 기간 반복:

- Unit
- 플러그인
- 스냅샷
- 명령
- Facade API

### Unit(콘텐츠 단위) [#unit]

**제품정보**는 Univer에서 관리한 완전한 내용 인스턴스입니다: 워크북, 문서, 발표, 기초, 널, 또는 PDF. 각 단위에는 그것의 자신의 ID (`unitId`)가 있습니다, 그래서 동일한 유형의 2개의 문서는 2개의 명백한 단위입니다.

몇몇 워크시트가 1개의 단위를 남아 있는 워크북. 그것의 워크시트, 세포 범위 및 세포는 단위 보다는 오히려 내부 목표입니다. 활주는 동일한 규칙을 따르고 그것을 포함하는 발표 단위에 속합니다.

한 Univer 인스턴스는 여러 단위를로드 할 수 있습니다. **스냅샷**는 단위의 내용 상태를 설명하는 직렬 데이터이며, 실제 단위로 동일한 객체가 편집되지 않습니다. 단위에 설정된 권한은 전체 콘텐츠 인스턴스에 적용되며, 객체 권한이 내부의 내용에 적용됩니다.

### 플러그인

Univer의 기능은 플러그인으로 제공됩니다. 플러그인은 건물 블록이며, 등록 설정은 Univer 응용 프로그램을 정의합니다.

플러그인은 작업의 두 가지 종류를 수행:

1. 그들은 기능을 추가합니다. `@univerjs/sheets-filter`, 예를 들어, 필터링을 제공합니다.
2. 다른 플러그인이 의존하는 기본 기능을 제공합니다. `@univerjs/engine-render`는 렌더링을 제공합니다.

플러그인을 결합하면 요구 사항 및 필요한 코드를 제외한 응용 프로그램을 형성 할 수 있습니다. Univer가 요구 사항에 대한 플러그인이 없습니다.

#### 관련 링크

1. [CSV 가져오기 플러그인 작성](/blog/csv-import-plugin)는 하나를 구축하는 방법을 설명합니다.
2. [Univer 건축](/blog/univer)는 구성 요소가 어떻게 함께 맞는지 설명합니다.

### 스냅샷

Univer는 스냅 샷을로드하여 문서를로드합니다. 각 문서 유형에는 자체 스냅 샷 형식이 있으므로 스냅 샷은 API 유형과 일치해야합니다.

1. 스프레드 시트 스냅 샷은 [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata)를 사용합니다.
2. 문서 스냅 샷은 [`IDocumentData`](/reference/types/document-data)를 사용합니다.

`resources` 필드의 이미지와 같은 기능 플러그인 저장소 리소스. [플러그인 사용자 정의 모델](/blog/custom-model)는 그 작동 방법을 설명합니다.

<Callout type="warning" title="주 메뉴">
  스냅샷만 저장 데이터입니다. Univer는 실행 중 문서의 현재 상태를 반영하지 않습니다. 스냅샷으로 현재 상태를 캡처하려면 Facade API의 저장 스냅샷 메소드를 사용하십시오.
</Callout>

### 명령

Univer의 문서 데이터에 대한 모든 변경은 명령을 통해 진행됩니다. 명령은 변경되지 않은 상태, 재도 및 협업 편집을 기준으로 한 자리에 Univer를 단일 위치로 제공합니다. 또한 Univer는 기능 간의 의존성을 해결합니다.

직접 명령을 파견하려면 [명령 ID 찾기](/blog/find-the-command-id)를 참조하십시오. Facade API을 통해 데이터를 변경하면 명령 매개 변수를 준비하고 명령을 파견합니다.

<Callout type="warning" title="주 메뉴">
  **스냅샷을 직접 수정하지 마십시오.** 변경은 그 방법이 영향을받지 않고보기 또는 UI를 재생하지 않습니다. 명령 또는 Facade API를 통해 데이터 변경.
</Callout>

### Facade API

사무실 응용 프로그램은 복잡하며 Univer의 아키텍처입니다. Facade API는 Univer를 간단한 인터페이스에서 최초의 플러그인으로 감싸고 작업을 완료하기 전에 전체 아키텍처를 배울 필요가 없습니다.

Facade API 적용은 계속 성장합니다. 당신이 간격 또는 무언가를 만난 경우에, GitHub에 문제점을 엽니다.

Facade API는 기본 정보를 숨기는 고급 API입니다. 일반적인 작업은 더 짧습니다. 복잡한 작업은 여전히 Univer의 아키텍처와 낮은 수준의 API로 직접 통화의 이해를 필요로 할 수 있습니다.

## 프리셋 모드와 플러그인 모드

미리 설정은 이미 구성 된 플러그인의 번들입니다. 두 모드 모두 동일한 플러그인을받을 때, 그들은 동일한 기능을 노출합니다. 차이는 얼마나 많은 구성 응용 프로그램을 제공해야합니다. 빠른 시작을위한 미리 설정 및 플러그인 모드를 사용하여 구성 및 로딩에 명시된 제어가 필요할 때.

<Callout type="warning">
  동일한 버전에 Univer 의존도를 유지하십시오. 미리 설정하면 플러그인이 포함되어 있지 않습니다. 그렇지 않으면 플러그인 충돌이나 기능 장애가 발생할 수 있습니다.
</Callout>

| 플러그인 모드 | 프리셋 모드 |
| --- | --- |
| Facade 확장을 직접 가져오기 | Facade 확장 포함 |
| 등록 순서를 직접 제어 | 프리셋이 포함된 플러그인을 관리 |
| Load plugins 에 수요 | 구성한 프리셋은 초기화 시 로드 |
