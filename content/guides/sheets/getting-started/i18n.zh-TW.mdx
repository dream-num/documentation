## 介面語言

`locale` 決定選單、提示、對話方塊以及其他介面文案使用哪個語言套件；`locales` 只負責註冊語言套件，不負責選擇語言。同一 Univer 例項中的各個文件單元共享這項設定。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有產品：介面**：`locale` 改變選單、提示、對話方塊和外掛標籤的翻譯，但不會翻譯使用者內容，也不會重新命名已有的文件單元。
- **Sheets：單元格格式與公式**：單元格中的數字和日期在渲染時依次使用數字格式的 locale 覆蓋值、工作簿快照的 `locale` 和例項的 `locale`，`region` 不會替代其中任何一項。`DOLLAR` 以及財務函式結果的貨幣格式等公式行為仍使用 `locale`，中日韓輸入歸一化也使用 `locale`。
- **Docs：文件統計**：`locale` 決定文字如何分詞和計數。

### 執行時切換語言

切換語言之前，需要先載入已安裝外掛或預設對應的全部語言套件。`loadLocales()` 合併翻譯但不切換語言；`setLocale()` 只選擇語言，不會下載任何內容。沒有對應翻譯的鍵會直接顯示為鍵名。下面的範例只載入共享的 UI 語言套件，其他已安裝外掛的目標語言套件需要在同一次呼叫中一併合併。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 在外掛模式中註冊語言包

外掛模式下，需要從提供語言套件的外掛中逐個引入語言套件，合併成一個物件後再傳給 `Univer` 例項：

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignZhTW from '@univerjs/design/locale/zh-TW' // [!code highlight]
import SheetsUIZhTW from '@univerjs/sheets-ui/locale/zh-TW' // [!code highlight]
import UIZhTW from '@univerjs/ui/locale/zh-TW' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.ZH_TW,
  locales: {
    [LocaleType.ZH_TW]: mergeLocales(
      DesignZhTW, // [!code highlight]
      UIZhTW, // [!code highlight]
      SheetsUIZhTW, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="注意事項">
  並非所有外掛都包含語言套件，每個功能的文件會說明。
</Callout>

### 在預設模式中註冊語言包

預設套件已經包含其外掛的語言套件，可直接從預設引入：

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreZhTW from '@univerjs/preset-sheets-core/locales/zh-TW' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.ZH_TW,
  locales: {
    [LocaleType.ZH_TW]: mergeLocales(
      UniverPresetSheetsCoreZhTW, // [!code highlight]
    ),
  },
  presets: [
    UniverSheetsCorePreset(),
  ],
})
```

### 合併語言套件 [#mergeLocales]

`mergeLocales` 將多個外掛或預設的語言套件合併為一個完整的語言套件物件，以下兩種傳參方式均可：

<Tabs items={['外掛模式', '預設模式']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // 你可以直接傳入多個語系物件
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以傳入語系物件陣列
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/presets'

    // 你可以直接傳入多個語系物件
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以傳入語系物件陣列
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
</Tabs>

### 自訂語系檔

也可以自行定義語言套件：按需要構造一個語言套件物件並傳給 `Univer` 例項。預設語言套件一般位於 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目錄下。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 貢獻語系

Univer 目前內建以下語言套件：

- `zh-CN`：簡體中文
- `en-US`：英文
- `zh-TW`：繁體中文（臺灣）
- `zh-HK`：繁體中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韓文
- `es-ES`：西班牙文
- `ca-ES`：加泰羅尼亞文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：義大利文
- `pl-PL`：波蘭文
- `pt-BR`：葡萄牙文（巴西）

其他語言暫不支援。歡迎世界各地的開發者為 Univer 新增新的語言套件，或改進現有語言套件。

## 地區設定

`region` 決定具有地區特性的功能使用哪套地區習慣，同一 Univer 例項中的各個文件單元共享這項設定。

兩項配置都使用 `LocaleType` 取值：`LocaleType.EN_US` 的值是 `enUS`，而 `en-US` 是語言套件檔名和 BCP 47 標籤。不要把 `US`、`SG` 這類國家程式碼傳給 `region`。介面使用其他語言時，地區無需載入對應的語言套件。

不顯式設定 `region` 時，該設定會跟隨 `locale`，之後呼叫 `setLocale()` 時同樣如此。在初始化時設定 `region`，或呼叫 `setRegion()`，這種自動跟隨即停止，之後切換語言會保留已選定的地區。目前沒有恢復自動跟隨的公開 API，需要兩者同時變化時，應分別更新這兩個值。

在 `createUniver()` 或 `new Univer()` 中，將 `region: LocaleType.DE_DE` 寫在 `locale` 旁邊，即可保留介面語言，同時使用德國地區習慣。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此時介面切換為英文，地區格式仍為德國。`getCurrentLocale()` 和 `getCurrentRegion()` 返回實際生效的標識。需要同時切換兩者時，使用同一個 `LocaleType` 值分別呼叫兩個 setter。

- **Sheets：貨幣操作**：`region` 決定貨幣工具欄圖示、貨幣和會計格式的選項與預覽，以及貨幣命令所應用的格式。切換地區不會重寫已有的單元格格式，也不會換算金額。
- **Docs：文件統計**：`region` 決定統計對話方塊和狀態列中統計數字的顯示格式，例如分組分隔符。僅修改 `region` 不會改變統計規則。
- **啟用評論時**：`region` 決定評論中日期和時間的顯示格式，固定使用 24 小時制和拉丁數字；`locale` 決定評論介面文案。兩者都不會修改已儲存的時間戳，`region` 也不是時區設定。
- **Boards、Slides、Bases、PDFs**：`locale` 控制介面翻譯；`region` 可供已接入的共享功能使用，例如評論，但不會自動重新格式化白板、幻燈片文字、Base 欄位或 PDF 內容。

## 從右到左的版面配置

<Callout type="warning" title="注意">
  目前 RTL 僅支援 UI 層，渲染層不支援 RTL。
</Callout>

版面配置方向是獨立的設定：可在初始化時指定 `direction`，或呼叫 `univerAPI.setDirection('rtl')` / `setDirection('ltr')`。僅修改 `locale` 或 `region` 不會切換版面配置方向。

```typescript
univerAPI.setDirection('rtl')
```
