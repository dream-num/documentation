Univer 具備同構特性，不僅可在瀏覽器端執行，也能在 Node.js 環境下使用。你可以基於 Headless Univer 開發資料處理服務，在伺服器端產生或修改文件，並透過 Facade API 與 Univer Sheets 進行互動。

在 Node.js 中使用外掛模式，按需註冊不依賴瀏覽器 UI 的外掛。

## 安裝

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## 使用

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsZhTW from '@univerjs/sheets/locale/zh-TW'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.ZH_TW,
  locales: {
    [LocaleType.ZH_TW]: mergeLocales(
      SheetsZhTW,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## 協同在 Node.js 環境下的使用範例 [#node-collaboration-example]

Node.js 作為協同用戶端載入伺服器上既有的活頁簿，透過 Facade API 修改內容，並將修改同步至開啟同一份文件的其他用戶端。執行前，請準備好[協同服務](/server/collaboration/quick-start)、[用戶端授權](/server/license)及可存取的文件 ID。

### 範例檔案

依下列結構組織檔案：

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`：建立 Univer，註冊完整功能外掛程式、協同用戶端及選用的 RPC 主程序外掛程式。
- `worker.ts`：註冊計算端的公式引擎、遠端公式、篩選與樞紐分析表外掛程式，透過 RPC 與主程序通訊。
- `main.ts`：載入協同文件，依序示範權限、基本表格、條件式格式、資料驗證、表格、樞紐分析表、迷你圖、圖片、圖表、圖形、分組和超連結 API。

將兩個檔案中的 `your-license` 替換為同一份授權，並替換伺服器位址、Cookie、文件 ID 和使用者 ID。`main.ts` 中的權限範例也包含協作者與保護範圍設定，需要使用實際業務使用者及具備相應管理權限的身分。

export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.ZH_TW,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],
  })

  univer.registerPlugin(UniverLicensePlugin, {
    license: 'your-license',
  })

  registerBasicPlugins(univer, useComputingWorker)
  registerSharedPlugins(univer)

  if (useComputingWorker) {
    registerRPCPlugin(univer)
  }

  registerDocPlugins(univer)
  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer
}

function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // 設定活頁簿名稱
  fWorkbook.setName('測試活頁簿 - Node 協同用戶端')

  const fWorksheet = fWorkbook.getActiveSheet()

  // 設定儲存格 A1 的值
  fWorksheet
    .getRange('A1')
    .setValue(`你好！這是 Node 協同用戶端傳來的訊息！目前時間：${new Date().toString()}。`)

  // 合併 C2:E4 範圍內的儲存格
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // 為儲存格 A1 建立定義名稱，並在 A6 使用
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // 插入新工作表
  const newSheet = fWorkbook.insertSheet('Node 用戶端新增工作表', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // 在第 3 列之後插入 3 列（索引從 0 開始）。
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // 重新命名第一張工作表，並設定列數與欄數
    sheets[0].setName('已重新命名的工作表 1').setRowCount(100).setColumnCount(10)
    // 凍結第一張工作表的第一列與第一欄
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // 將第一張工作表的格線設為紅色
    sheets[0].setGridLinesColor('#FF0000')
    // 取得第一張工作表的資料範圍，並輸出其 A1 表示法
    const dataRange = sheets[0].getDataRange()
    console.warn(`已重新命名的工作表 1 資料範圍 A1 表示法：${dataRange.getA1Notation()}`)
    // 5 秒後清除資料範圍的內容
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}

### 啟用計算 worker

`createUniverOnNode()` 預設使用 `useComputingWorker: false`，在目前程序執行公式計算。上方的 `main.ts` 明確傳入 `useComputingWorker: true`，啟用計算 worker：

1. 主程序中的 `UniverProFormulaEnginePlugin`、`UniverSheetsPlugin`、`UniverSheetsFormulaPlugin` 和 `UniverSheetsPivotTablePlugin` 均設定 `notExecuteFormula: true`，搭配 RPC 將計算交給子程序。
2. `UniverRPCNodeMainPlugin` 依 `workerSrc` 啟動已建置的 `worker.js`。
3. 子程序透過 `UniverRPCNodeWorkerPlugin` 和 `UniverRemoteSheetsFormulaPlugin` 接收資料並計算。

`UniverSheetsPivotTablePlugin` 的設定區分三種模式：主程序啟用 worker 時設定 `true`，worker 中設定 `false`，不啟用 worker 時省略或設定為 `undefined`，在目前程序同時註冊樞紐分析表服務和計算邏輯。因此主程序使用 `useComputingWorker ? true : undefined`，不能直接傳入 `useComputingWorker`。

此處的 worker 由 Node.js `child_process.fork()` 啟動。請使用專案現有的建置工具，將 `main.ts` 和 `worker.ts` 分別作為入口建置，並讓 `workerSrc` 指向建置後的 worker 檔案。範例假設 `worker.js` 與主入口產物位於同一目錄；路徑、副檔名及模組格式應與實際建置結果一致。範例使用 CommonJS 的 `__dirname` 定位檔案，ESM 專案需改用對應的路徑解析方式。

### 執行說明

`loadSheetAsync()` 載入伺服器上既有的文件，無需再呼叫 `createWorkbook()`。協同服務透過 `customHeaders` 攜帶的 Cookie 等驗證資訊識別使用者並檢查權限，連線的 `memberID` 由伺服器回傳。

本例未啟用瀏覽器離線快取和多分頁執行個體鎖，無需為了快取帳號隔離呼叫 `setCurrentUser()`。若後續使用評論等依賴本機目前使用者的功能，可以再透過 `UserManagerService` 設定業務使用者；這不會取代伺服器端驗證。

範例執行後保持協同連線，可在瀏覽器開啟同一份文件查看修改。`flush()` 等待已排入佇列的協同修改獲得伺服器確認；若改為一次性指令碼，應在所有非同步操作和同步完成後呼叫 `univer.dispose()` 釋放執行個體。
