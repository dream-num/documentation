Univer tiene una característica isomórfica, lo que significa que puede ejecutarse no solo en el navegador sino también en un entorno Node.js. Puede desarrollar servicios de procesamiento de datos basados en Headless Univer para generar o modificar documentos en el lado del servidor e interactuar con Univer Sheets a través de la API de Facade.

En Node.js, usa el modo complemento y registra los complementos necesarios sin incluir los de interfaz del navegador.

## Instalación

```package-install
npm install @univerjs/core @univerjs/engine-render @univerjs/engine-formula @univerjs/docs @univerjs/sheets @univerjs/sheets-formula @univerjs/sheets-numfmt
```

## Uso

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import { FUniver } from '@univerjs/core/facade'
import { UniverDocsPlugin } from '@univerjs/docs'
import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
import { UniverSheetsPlugin } from '@univerjs/sheets'
import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
import SheetsEsES from '@univerjs/sheets/locale/es-ES'
import '@univerjs/engine-formula/facade'
import '@univerjs/sheets/facade'
import '@univerjs/sheets-formula/facade'
import '@univerjs/sheets-numfmt/facade'

const univer = new Univer({
  locale: LocaleType.ES_ES,
  locales: {
    [LocaleType.ES_ES]: mergeLocales(
      SheetsEsES,
    ),
  },
})

univer.registerPlugin(UniverRenderEnginePlugin)
univer.registerPlugin(UniverFormulaEnginePlugin)
univer.registerPlugin(UniverDocsPlugin)
univer.registerPlugin(UniverSheetsPlugin)
univer.registerPlugin(UniverSheetsFormulaPlugin)
univer.registerPlugin(UniverSheetsNumfmtPlugin)

const univerAPI = FUniver.newAPI(univer)
univerAPI.createWorkbook({})
```

## Ejemplo de colaboración en Node.js [#node-collaboration-example]

Node.js puede actuar como cliente de colaboración: cargar un libro existente del servidor, modificar su contenido mediante la API de Facade y sincronizar los cambios con otros clientes que tengan abierto el mismo documento. Antes de ejecutarlo, prepara un [servicio de colaboración](/server/collaboration/quick-start), una [licencia de cliente](/server/license) y un ID de documento accesible.

### Archivos del ejemplo

Organiza los archivos con esta estructura:

```text
src/sheets/node/
├── main.ts
├── univer.ts
└── worker.ts
```

- `univer.ts`: crea Univer y registra los plugins de funciones, el cliente de colaboración y el plugin RPC opcional del proceso principal.
- `worker.ts`: registra el motor de fórmulas del lado de cálculo y los plugins de fórmulas remotas, filtros y tablas dinámicas, y se comunica con el proceso principal mediante RPC.
- `main.ts`: carga el documento colaborativo y muestra las API de permisos, operaciones básicas de hojas, formato condicional, validación de datos, tablas, tablas dinámicas, minigráficos, imágenes, gráficos, formas, agrupación e hipervínculos.

Sustituye `your-license` en ambos archivos por la misma licencia y adapta la URL del servidor, la Cookie, el ID del documento y los ID de usuario. El ejemplo de permisos de `main.ts` también configura colaboradores y rangos protegidos; usa usuarios reales de tu aplicación y una identidad con los permisos de administración necesarios.

  useComputingWorker?: boolean

export function createUniverOnNode(options: ICreateUniverOnNodeOptions = {}): Univer {
  const { useComputingWorker = false } = options

  const univer = new Univer({
    locale: LocaleType.ES_ES,
    locales: {},
    override: [
      [IAuthzIoService, null],
      [IUndoRedoService, null],
    ],
  })

  univer.registerPlugin(UniverLicensePlugin, {
    license: 'your-license',
  })

  registerBasicPlugins(univer, useComputingWorker)
  registerSharedPlugins(univer)

  if (useComputingWorker) {
    registerRPCPlugin(univer)
  }

  registerDocPlugins(univer)
  registerSheetPlugins(univer, useComputingWorker)
  registerCollaborationPlugins(univer)

  return univer
}

function TestSheetsFacadeAPI(univerAPI: FUniver) {
  const fWorkbook = univerAPI.getActiveWorkbook()
  if (!fWorkbook) return

  // Definir el nombre del libro
  fWorkbook.setName('Libro de prueba - Cliente de colaboración Node')

  const fWorksheet = fWorkbook.getActiveSheet()

  // Definir un valor en la celda A1
  fWorksheet
    .getRange('A1')
    .setValue(`¡Hola! Mensaje del cliente de colaboración Node. Hora actual: ${new Date().toString()}.`)

  // Combinar las celdas de C2:E4
  const fRange2 = fWorksheet.getRange('C2:E4')
  if (fRange2.isPartOfMerge() || fRange2.isMerged()) {
    fRange2.breakApart()
  }
  fRange2.merge().setValue(1234).setNumberFormat('#,##0.00')

  // Crear un nombre definido para A1 y usarlo en A6
  const definedNameBuilder = fWorkbook
    .newDefinedNameBuilder()
    .setRef(`${fWorksheet.getSheetName()}!$A$1`)
    .setName('MyDefinedName')
    .build()
  fWorkbook.insertDefinedNameBuilder(definedNameBuilder)
  fWorksheet.getRange('A6').setValue('=MyDefinedName')

  // Insertar una hoja nueva
  const newSheet = fWorkbook.insertSheet('Nueva hoja del cliente Node', {
    index: 1,
    sheet: {
      rowCount: 100,
      columnCount: 20,
      cellData: {
        0: {
          0: {
            v: 1,
          },
        },
        1: {
          1: {
            v: 2,
          },
        },
        2: {
          2: {
            v: 3,
          },
        },
        3: {
          3: {
            v: 4,
          },
        },
      },
    },
  })

  // Insertar 3 filas después de la tercera fila (índice desde 0).
  newSheet.insertRowsAfter(2, 3)

  const sheets = fWorkbook.getSheets()
  if (sheets.length) {
    // Renombrar la primera hoja y definir su número de filas y columnas
    sheets[0].setName('Hoja 1 renombrada').setRowCount(100).setColumnCount(10)
    // Inmovilizar la primera fila y la primera columna de la primera hoja
    sheets[0].setFrozenRows(1).setFrozenColumns(1)
    // Cambiar a rojo el color de las líneas de cuadrícula de la primera hoja
    sheets[0].setGridLinesColor('#FF0000')
    // Obtener el rango de datos de la primera hoja y mostrar su notación A1
    const dataRange = sheets[0].getDataRange()
    console.warn(`Rango de datos de la hoja 1 renombrada en notación A1: ${dataRange.getA1Notation()}`)
    // Borrar el contenido del rango después de 5 segundos
    setTimeout(() => {
      dataRange.clearContent()
    }, 5000)
  }
}

  await fRange4.setHyperLink(definedNameHyperlinkUrl, 'Enlace a MyDefinedName')

  await fRange.updateHyperLink('https://www.google.com/', 'Google')

  const hyperlinks = fRange2.getHyperLinks()

    await fRange2.cancelHyperLink(hyperlinks[0])

  // Eliminar todos los hipervínculos de A1 después de 2 segundos
  await new Promise((resolve) => setTimeout(resolve, 2000))

### Activar el worker de cálculo

`createUniverOnNode()` usa `useComputingWorker: false` de forma predeterminada y calcula las fórmulas en el proceso actual. El archivo `main.ts` anterior pasa explícitamente `useComputingWorker: true` para activar el worker de cálculo:

1. En el proceso principal, `UniverProFormulaEnginePlugin`, `UniverSheetsPlugin`, `UniverSheetsFormulaPlugin` y `UniverSheetsPivotTablePlugin` establecen `notExecuteFormula: true` para delegar el cálculo al proceso hijo mediante RPC.
2. `UniverRPCNodeMainPlugin` inicia el archivo `worker.js` compilado indicado por `workerSrc`.
3. El proceso hijo recibe los datos y realiza los cálculos mediante `UniverRPCNodeWorkerPlugin` y `UniverRemoteSheetsFormulaPlugin`.

`UniverSheetsPivotTablePlugin` distingue tres modos: `true` en el proceso principal con worker, `false` en el worker y la opción omitida o con valor `undefined` sin worker, para registrar tanto los servicios de tablas dinámicas como la lógica de cálculo en el proceso actual. Por eso el proceso principal usa `useComputingWorker ? true : undefined` en lugar de pasar `useComputingWorker` directamente.

Node.js inicia este worker con `child_process.fork()`. Usa la herramienta de compilación de tu proyecto para compilar `main.ts` y `worker.ts` como puntos de entrada independientes y configura `workerSrc` para que apunte al archivo worker compilado. El ejemplo supone que `worker.js` está en el mismo directorio que el resultado de la entrada principal; adapta la ruta, la extensión y el formato de módulo a tu compilación. El ejemplo usa `__dirname` de CommonJS para localizar el archivo; los proyectos ESM deben usar el método de resolución correspondiente.

### Notas de ejecución

`loadSheetAsync()` carga un documento existente del servidor; no necesitas llamar a `createWorkbook()`. El servicio de colaboración identifica al usuario y comprueba sus permisos mediante la información de autenticación, como la Cookie incluida en `customHeaders`. El servidor devuelve el `memberID` de la conexión.

Este ejemplo desactiva la caché sin conexión del navegador y el bloqueo de instancia entre pestañas, por lo que no es necesario llamar a `setCurrentUser()` para aislar la caché por cuenta. Si más adelante usas funciones como comentarios, que dependen del usuario actual local, puedes establecer el usuario de la aplicación mediante `UserManagerService`; esto no sustituye la autenticación del servidor.

El ejemplo mantiene la conexión colaborativa después de ejecutarse. Abre el mismo documento en un navegador para ver los cambios. `flush()` espera la confirmación del servidor para los cambios pendientes. Si lo conviertes en un script de una sola ejecución, llama a `univer.dispose()` cuando hayan terminado todas las operaciones asíncronas y la sincronización.
