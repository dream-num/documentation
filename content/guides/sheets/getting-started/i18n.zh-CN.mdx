## 界面语言

`locale` 决定菜单、提示、对话框以及其他界面文案使用哪个语言包；`locales` 只负责注册语言包，不负责选择语言。同一 Univer 实例中的各个文档单元共享这项设置。取值使用 `LocaleType`，例如 `LocaleType.EN_US`。

- **所有产品：界面**：`locale` 改变菜单、提示、对话框和插件标签的翻译，但不会翻译用户内容，也不会重命名已有的文档单元。
- **Sheets：单元格格式与公式**：单元格中的数字和日期在渲染时依次使用数字格式的 locale 覆盖值、工作簿快照的 `locale` 和实例的 `locale`，`region` 不会替代其中任何一项。`DOLLAR` 以及财务函数结果的货币格式等公式行为仍使用 `locale`，中日韩输入归一化也使用 `locale`。
- **Docs：文档统计**：`locale` 决定文本如何分词和计数。

### 运行时切换语言

切换语言之前，需要先加载已安装插件或预设对应的全部语言包。`loadLocales()` 合并翻译但不切换语言；`setLocale()` 只选择语言，不会下载任何内容。没有对应翻译的键会直接显示为键名。下面的示例只加载共享的 UI 语言包，其他已安装插件的目标语言包需要在同一次调用中一并合并。

```typescript
import { LocaleType, mergeLocales } from '@univerjs/core'
import UIEnUS from '@univerjs/ui/locale/en-US'

univerAPI.loadLocales(LocaleType.EN_US, mergeLocales(UIEnUS))
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentLocale()) // enUS
```

### 在插件模式中注册语言包

插件模式下，需要从提供语言包的插件中逐个引入语言包，合并成一个对象后再传给 `Univer` 实例：

```typescript
import { LocaleType, mergeLocales, Univer } from '@univerjs/core'
import DesignZhCN from '@univerjs/design/locale/zh-CN' // [!code highlight]
import SheetsUIZhCN from '@univerjs/sheets-ui/locale/zh-CN' // [!code highlight]
import UIZhCN from '@univerjs/ui/locale/zh-CN' // [!code highlight]

const univer = new Univer({
  locale: LocaleType.ZH_CN,
  locales: {
    [LocaleType.ZH_CN]: mergeLocales(
      DesignZhCN, // [!code highlight]
      UIZhCN, // [!code highlight]
      SheetsUIZhCN, // [!code highlight]
    ),
  },
})
```

<Callout type="warning" title="注意事项">
  并非所有插件都包含语言包，每个功能的文档会说明。
</Callout>

### 在预设模式中注册语言包

预设包已经包含其插件的语言包，可直接从预设引入：

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreZhCN from '@univerjs/preset-sheets-core/locales/zh-CN' // [!code highlight]
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

const { univerAPI } = createUniver({
  locale: LocaleType.ZH_CN,
  locales: {
    [LocaleType.ZH_CN]: mergeLocales(
      UniverPresetSheetsCoreZhCN, // [!code highlight]
    ),
  },
  presets: [
    UniverSheetsCorePreset(),
  ],
})
```

### 合并语言包 [#mergeLocales]

`mergeLocales` 将多个插件或预设的语言包合并为一个完整的语言包对象，以下两种传参方式均可：

<Tabs items={['插件模式', '预设模式']}>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/core'

    // 你可以传入多个语言包对象进行合并
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以传入一个语言包对象数组
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
  <Tab>
    ```typescript
    import { mergeLocales } from '@univerjs/presets'

    // 你可以传入多个语言包对象进行合并
    const locales = mergeLocales(
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    )
    // 也可以传入一个语言包对象数组
    const locales = mergeLocales([
      plugin1Locales,
      plugin2Locales,
      presetLocales,
    ])
    ```
  </Tab>
</Tabs>

### 自定义语言包

也可以自行定义语言包：按需要构造一个语言包对象并传给 `Univer` 实例。预设语言包一般位于 `<rootDir>/packages/<PLUGIN_NAME>/locale` 目录下。

```typescript
import { LocaleType, Univer } from '@univerjs/core'

const univer = new Univer({
  locale: LocaleType.JA_JP,
  locales: {
    [LocaleType.JA_JP]: {
      ui: {
        shortcut: {
          undo: '元に戻す',
          redo: 'やり直す',
        },
      },
    },
  },
})
```

### 贡献语言包

Univer 目前内置以下语言包：

- `zh-CN`：简体中文
- `en-US`：英文
- `zh-TW`：繁体中文
- `zh-HK`：繁体中文（香港）
- `ru-RU`：俄文
- `vi-VN`：越南文
- `fa-IR`：波斯文
- `fr-FR`：法文
- `ja-JP`：日文
- `ko-KR`：韩文
- `es-ES`：西班牙文
- `ca-ES`：加泰罗尼亚文
- `sk-SK`：斯洛伐克文
- `ar-SA`：阿拉伯文
- `de-DE`：德文
- `id-ID`：印尼文
- `it-IT`：意大利文
- `pl-PL`：波兰文
- `pt-BR`：葡萄牙文（巴西）

其他语言暂不支持。欢迎世界各地的开发者为 Univer 添加新的语言包，或改进现有语言包。

## 地区设置

`region` 决定具有地区特性的功能使用哪套地区习惯，同一 Univer 实例中的各个文档单元共享这项设置。

两项配置都使用 `LocaleType` 取值：`LocaleType.EN_US` 的值是 `enUS`，而 `en-US` 是语言包文件名和 BCP 47 标签。不要把 `US`、`SG` 这类国家代码传给 `region`。界面使用其他语言时，地区无需加载对应的语言包。

不显式设置 `region` 时，该设置会跟随 `locale`，之后调用 `setLocale()` 时同样如此。在初始化时设置 `region`，或调用 `setRegion()`，这种自动跟随即停止，之后切换语言会保留已选定的地区。目前没有恢复自动跟随的公开 API，需要两者同时变化时，应分别更新这两个值。

在 `createUniver()` 或 `new Univer()` 中，将 `region: LocaleType.DE_DE` 写在 `locale` 旁边，即可保留界面语言，同时使用德国地区习惯。

```typescript
import { LocaleType } from '@univerjs/core'

univerAPI.setRegion(LocaleType.DE_DE)
univerAPI.setLocale(LocaleType.EN_US)

console.log(univerAPI.getCurrentRegion()) // deDE
```

此时界面切换为英文，地区格式仍为德国。`getCurrentLocale()` 和 `getCurrentRegion()` 返回实际生效的标识。需要同时切换两者时，使用同一个 `LocaleType` 值分别调用两个 setter。

- **Sheets：货币操作**：`region` 决定货币工具栏图标、货币和会计格式的选项与预览，以及货币命令所应用的格式。切换地区不会重写已有的单元格格式，也不会换算金额。
- **Docs：文档统计**：`region` 决定统计对话框和状态栏中统计数字的显示格式，例如分组分隔符。仅修改 `region` 不会改变统计规则。
- **启用评论时**：`region` 决定评论中日期和时间的显示格式，固定使用 24 小时制和拉丁数字；`locale` 决定评论界面文案。两者都不会修改已存储的时间戳，`region` 也不是时区设置。
- **Boards、Slides、Bases、PDFs**：`locale` 控制界面翻译；`region` 可供已接入的共享功能使用，例如评论，但不会自动重新格式化白板、幻灯片文本、Base 字段或 PDF 内容。

## 从右到左的布局

<Callout type="warning" title="注意">
  目前 RTL 仅支持 UI 层，渲染层不支持 RTL。
</Callout>

布局方向是独立的设置：可在初始化时指定 `direction`，或调用 `univerAPI.setDirection('rtl')` / `setDirection('ltr')`。仅修改 `locale` 或 `region` 不会切换布局方向。

```typescript
univerAPI.setDirection('rtl')
```
