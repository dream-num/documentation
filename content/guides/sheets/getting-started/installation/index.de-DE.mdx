Univer übernimmt eine Plugin-basierte Designphilosophie, die darauf abzielt, Entwicklern ein flexibles und erweiterbares Framework für Anwendungen für elektronische Dokumente bereitzustellen. Durch dieses Plugin-basierte Design kann Univer problemlos verschiedene Funktionsmodule integrieren, um den Anforderungen verschiedener Benutzer gerecht zu werden. Das Plugin-basierte Design erhöht jedoch die Komplexität der Anwendung, insbesondere für Entwickler, die neu bei Univer sind.

Aus diesem Grund bietet Univer zwei Möglichkeiten, die Ihnen bei der schnellen Integration und Nutzung von Univer helfen: **Plugin-Modus** und **Voreinstellungsmodus**. Das sogenannte **Preset** ist eigentlich eine Kombination aus vorkonfigurierten Plugins, sodass die von beiden Modi bereitgestellten Funktionen ohne komplexe Erweiterungen gleich sind.

<Callout type="warning" title="Caution">
  - **Konsistente Abhängigkeitsversionen**: Unabhängig davon, ob Sie den Preset-Modus oder den Plugin-Modus verwenden, müssen Sie sicherstellen, dass alle Abhängigkeiten konsistente Versionsnummern haben.
  - **Vorsichtiges Mischen von Plugins und Presets**: Wenn ein Plugin bereits in einem Preset enthalten ist, müssen Sie dieses Plugin nicht separat importieren, wenn Sie das Preset verwenden. Andernfalls kann es zu Plugin-Konflikten oder Funktionsanomalien kommen.
</Callout>

Unterschiede zwischen Preset-Modus und Plugin-Modus:

| Plugin-Modus | Voreingestellter Modus |
| --- | --- |
| Erfordert den manuellen Import der entsprechenden Fassadenpakete | Kein manueller Import von Fassadenpaketen erforderlich |
| Erfordert Beachtung der Registrierungsreihenfolge von Plugins mit derselben Funktionalität | Es ist nicht erforderlich, auf die Registrierungsreihenfolge der darin enthaltenen Funktionalitäten zu achten Voreinstellungen |
| Unterstützt verzögertes Laden bei Bedarf | Unterstützt nur verzögertes Laden auf Voreinstellungsebene, Plugins innerhalb der Voreinstellung können nur synchron geladen werden |

## Einrichtung über den Preset-Modus

Hier stellen wir Ihnen kurz vor, wie Sie mit weniger als zwanzig Zeilen Code schnell eine Univer Sheets-Anwendung erstellen können.

### Paketmanager verwenden

Wenn Ihr Projekt bereits moderne Front-End-Entwicklungstools verwendet, wird die Integration von Univer sehr einfach sein. Wir empfehlen die Verwendung von Build-Tools wie [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) oder [Webpack 5](https://webpack.js.org/), die ES-Module gut unterstützen, um Univer-Anwendungen zu erstellen. Wenn Sie andere Build-Tools (z. B. Webpack 4) verwenden, benötigen Sie möglicherweise eine zusätzliche Konfiguration.

#### Installation

Wählen Sie Ihren Paketmanager zur Installation von `@univerjs/presets`:

```package-install
npm install @univerjs/presets @univerjs/preset-docs-core
```

#### Verwendung

<Callout type="warning">
Wenn Ihr Build-Tool das Feld `exports` in package.json nicht unterstützt (üblich in Webpack 4), müssen Sie die zugeordneten Pfade manuell ändern die tatsächlichen Pfade.
</Callout>

Mit dem folgenden Code können Sie eine Univer Sheets-Anwendung starten:

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-sheets-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
    ),
  },
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createWorkbook({})
```

Das hier zurückgegebene `univerAPI`-Objekt wird als Univer Facade API bezeichnet, über die Sie viele von Univer bereitgestellte Funktionen aufrufen können.

#### `createUniver`-Methode

Die `createUniver`-Methode akzeptiert ein Konfigurationsobjekt, das die Konfigurationsinformationen für Univer enthält, z. B. Sprache, Design und Plugins. Diese Methode gibt ein Objekt zurück, das die Univer-Instanz und die Univer-Facade-API-Instanz enthält.

Einige Eigenschaften des Konfigurationsobjekts sind wie folgt:

- `locale`: Sprachumgebung, kann ein `LocaleType`-Enumerationswert sein.
- `locales`: Gebietsschemas, ein Objekt, der Schlüssel ist die Sprachumgebung und der Wert ist das Sprachpaketobjekt.
- `theme`: Ein Designobjekt, das ist optional.
- `presets`: Ein Array von Voreinstellungen, das die zu registrierenden Voreinstellungen enthält, z. B. `UniverSheetsCorePreset`.
- `plugins`: Ein Array von Plugins, das die Plugins enthält, die zusätzlich registriert werden müssen.

Wenn Sie ein Plugin verwenden, das in keinem Voreinstellungspaket enthalten ist, oder Sie Ihr eigenes Plugin implementieren, können Sie diese registrieren Plugins über die Eigenschaft `plugins`. Sie können Plugins auch mit der Methode `univer.registerPlugin` registrieren, nachdem Sie die Univer-Instanz erhalten haben.

<Callout>
Ausführlichere Informationen zur Methode `createUniver` finden Sie in der [API-Referenz / createUniver](https://docs.univer.ai/reference/methods/create-univer).
</Callout>

## Einrichtung über den Plugin-Modus

Univer stellt eine Reihe von Funktionen in Form von Plugins zur Verfügung. Zusätzlich zu einigen Kern-Plugins, die für das Produkt wesentlich sind, können Sie bei Bedarf gezielt weitere Plugins einführen. Hier nehmen wir die einfachste Univer Sheets-Anwendung als Beispiel, um vorzustellen, wie man Plugins manuell kombiniert und installiert.

Im Gegensatz zum voreingestellten Modus enthält der Plugin-Modus standardmäßig nicht die Facade-API. Die Teile, die sich auf die Facade-API in den folgenden Codebeispielen beziehen, sind optional, und Sie können je nach Bedarf entscheiden, ob Sie sie entfernen möchten.

### Verwenden des Paketmanagers

#### Installation

Wir verwenden React zum Entwickeln der Ansicht (dies hat keine Auswirkungen auf Ihre Verwendung von Univer in Vue oder Angular) und Rxjs für die Verarbeitung von Datenströmen. Da diese beiden Bibliotheken in der modernen Front-End-Entwicklung weit verbreitet sind, behandeln wir sie als PeerDependencies. Allerdings weisen verschiedene Paketverwaltungstools unterschiedliche Verhaltensweisen in Bezug auf Peer-Abhängigkeiten auf, daher müssen Sie möglicherweise auf einige Details achten.

<Callout>
  - Wenn Sie npm verwenden, stellen Sie sicher, dass Sie npm@7 oder höher verwenden. Dies liegt daran, dass npm@3 ~ npm@6 `peerDependencies`[^1] nicht korrekt installiert.
  - Wenn Sie pnpm verwenden, stellen Sie sicher, dass Sie pnpm@8 oder höher verwenden. Wenn Sie pnpm@6 ~ pnpm@7 verwenden, können Sie versuchen, `auto-install-peers=true` [^2] zu konfigurieren, um Probleme bei der Abhängigkeitsinstallation zu beheben.
  - Wenn Sie Garn verwenden, müssen Sie das fehlende `peerDependencies`[^3] manuell installieren. Die folgenden Installationsbefehle enthalten diese Abhängigkeiten bereits.
</Callout>

#### Verwendung

<Callout type="warning" title="Caution">
  - Nicht alle Plugins enthalten Fassadenpakete, Sprachpakete und Stildateien. Wir werden dies in der Dokumentation für jede Funktion angeben.
  - Die Reihenfolge beim Importieren von Stildateien ist wichtig. Stellen Sie sicher, dass Sie die CSS-Stile von `@univerjs/design` und `@univerjs/ui` importieren, bevor Sie die Stile anderer Plugins importieren.
</Callout>

<Steps>
  <Step>
Sie müssen die Univer-Stildateien, Sprachpakete und einige notwendige Plugins in Ihr Projekt importieren:

    ```typescript
    import { LocaleType, mergeLocales, Univer, UniverInstanceType } from '@univerjs/core'
    import { FUniver } from '@univerjs/core/facade'
    import DesignEnUS from '@univerjs/design/locale/en-US'
    import { UniverDocsPlugin } from '@univerjs/docs'
    import { UniverDocsUIPlugin } from '@univerjs/docs-ui'
    import DocsUIEnUS from '@univerjs/docs-ui/locale/en-US'
    import { UniverFormulaEnginePlugin } from '@univerjs/engine-formula'
    import { UniverRenderEnginePlugin } from '@univerjs/engine-render'
    import { UniverSheetsPlugin } from '@univerjs/sheets'
    import { UniverSheetsFormulaPlugin } from '@univerjs/sheets-formula'
    import { UniverSheetsFormulaUIPlugin } from '@univerjs/sheets-formula-ui'
    import SheetsFormulaUIEnUS from '@univerjs/sheets-formula-ui/locale/en-US'
    import { UniverSheetsNumfmtPlugin } from '@univerjs/sheets-numfmt'
    import { UniverSheetsNumfmtUIPlugin } from '@univerjs/sheets-numfmt-ui'
    import SheetsNumfmtUIEnUS from '@univerjs/sheets-numfmt-ui/locale/en-US'
    import { UniverSheetsUIPlugin } from '@univerjs/sheets-ui'
    import SheetsUIEnUS from '@univerjs/sheets-ui/locale/en-US'
    import SheetsEnUS from '@univerjs/sheets/locale/en-US'
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/design/lib/index.css'
    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    import '@univerjs/sheets-ui/lib/index.css'
    import '@univerjs/sheets-formula-ui/lib/index.css'
    import '@univerjs/sheets-numfmt-ui/lib/index.css'
    ```
  </Step>
  <Step>
Wenn Sie die Facade-API verwenden müssen, können Sie die relevanten Fassadenpakete hier importieren. Dies ist optional, wird aber empfohlen:

    ```typescript
    import '@univerjs/engine-formula/facade'
    import '@univerjs/ui/facade'
    import '@univerjs/docs-ui/facade'
    import '@univerjs/sheets/facade'
    import '@univerjs/sheets-ui/facade'
    import '@univerjs/sheets-formula/facade'
    import '@univerjs/sheets-numfmt/facade'
    ```
  </Step>
  <Step>
Erstellen Sie dann eine Univer-Instanz und registrieren Sie diese Plugins:

    ```typescript
    const univer = new Univer({
      locale: LocaleType.EN_US,
      locales: {
        [LocaleType.EN_US]: mergeLocales(
          DesignEnUS,
          UIEnUS,
          DocsUIEnUS,
          SheetsEnUS,
          SheetsUIEnUS,
          SheetsFormulaUIEnUS,
          SheetsNumfmtUIEnUS,
        ),
      },
    })

    univer.registerPlugin(UniverRenderEnginePlugin)
    univer.registerPlugin(UniverFormulaEnginePlugin)

    univer.registerPlugin(UniverUIPlugin, {
      container: 'app',
    })

    univer.registerPlugin(UniverDocsPlugin)
    univer.registerPlugin(UniverDocsUIPlugin)

    univer.registerPlugin(UniverSheetsPlugin)
    univer.registerPlugin(UniverSheetsUIPlugin)
    univer.registerPlugin(UniverSheetsFormulaPlugin)
    univer.registerPlugin(UniverSheetsFormulaUIPlugin)
    univer.registerPlugin(UniverSheetsNumfmtPlugin)
    univer.registerPlugin(UniverSheetsNumfmtUIPlugin)

    univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

    const univerAPI = FUniver.newAPI(univer)
    ```
  </Step>
</Steps>

#### `univer.registerPlugin` Methode [#registerPlugin]

Die Methode `univer.registerPlugin` wird verwendet, um ein Plugin bei der Univer-Instanz zu registrieren. Sie können diese Methode aufrufen, nachdem Sie die Univer-Instanz erstellt haben, um Plugins zu registrieren.

Sie können ein Plugin mit der Methode `univer.registerPlugin(Plugin, options)` registrieren, wobei `Plugin` das zu registrierende Plugin ist und `options` optionale Konfigurationselemente sind, da jedes Plugin unterschiedliche Konfigurationselemente haben kann.

Sie können auch ein Array übergeben, um mehrere Plugins gleichzeitig zu registrieren. Dies ist nützlich für Szenarien, in denen Sie Plugins zentral verwalten müssen.

```typescript
univer.registerPlugin([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverSheetsPlugin,
  UniverSheetsUIPlugin,
  UniverSheetsFormulaPlugin,
  UniverSheetsFormulaUIPlugin,
  UniverSheetsNumfmtPlugin,
  UniverSheetsNumfmtUIPlugin,
])
```

#### Lazy Loading Plugins

Ein gemeinsamer Vorteil des Plugin-Modus besteht darin, dass Sie den Ladezeitpunkt von Plugins flexibler steuern können. Ein gängiger Ansatz besteht darin, während der Anwendungsinitialisierung nur die wesentlichen Plugins zu laden und das Laden einiger Plugins aufzuschieben, bis das erste Rendering abgeschlossen ist.

```typescript
// ...

univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

Unsere [offizielle Demo](https://github.com/dream-num/univer/blob/dev/examples/src/sheets/main.ts) verwendet diese Optimierungstechnik, auf die Sie sich beziehen können.

### Mobiler Support

Univer bietet **experimentellen** mobilen Support. Die mobile Version ist für Touch-Interaktionen optimiert und bietet UI-Komponenten und Interaktionserlebnisse, die auf mobile Geräte zugeschnitten sind.

- **UI-Plugins**: Um sich an unterschiedliche Interaktionsmuster auf verschiedenen Geräten anzupassen, bieten einige UI-Plugins sowohl Desktop- als auch Mobilvarianten. Diese beiden Varianten befinden sich im selben npm-Paket und unterscheiden sich durch unterschiedliche Exportpfade.
- **Kernlogik-Plugins**: Wie die Formel-Engine (`UniverFormulaEnginePlugin`) und die Render-Engine (`UniverRenderEnginePlugin`) bleiben auf Desktop und Mobilgeräten gleich, sodass keine Unterscheidung zwischen Versionen erforderlich ist.

<Callout type="info">
Mobile- und Desktop-Plugins sind keine zwei völlig separaten Pakete – es handelt sich um dasselbe Paket, das auf unterschiedlichen Geräten unterschiedlich dargestellt wird Plattformen. Beispielsweise stellt `@univerjs/sheets-ui` sowohl den Desktop `UniverSheetsUIPlugin` als auch den mobilen `UniverSheetsMobileUIPlugin` bereit.
</Callout>

<Callout type="warning" title="Notes">
  - Mobile Unterstützung ist derzeit experimentell und einige Funktionen sind möglicherweise unvollständig.
  - Mobile UI-Plugins und Desktop-UI-Plugins können nicht gleichzeitig verwendet werden; Wählen Sie das entsprechende Plugin basierend auf dem Gerätetyp aus.
  - Vor der Bereitstellung in der Produktion wird ein gründliches Testen empfohlen.
</Callout>

#### Wechseln Sie zu mobilen Plugins

Ersetzen Sie einfach das entsprechende UI-Plugin durch seine mobile Variante:

````typescript
import { UniverSheetsUIPlugin } from '@univerjs/sheets-ui' // [!code --]
import { UniverSheetsMobileUIPlugin } from '@univerjs/sheets-ui' // [!code ++]

univer.registerPlugin(UniverSheetsUIPlugin) // [!code --]
univer.registerPlugin(UniverSheetsMobileUIPlugin) // [!code ++]
````

#### Desktop vs. Mobile Plugin Mapping

Die folgende Tabelle listet alle UI-Plugins auf, die mobile Varianten bereitstellen. Wenn Sie Plugins basierend auf dem Gerätetyp dynamisch auswählen müssen, sehen Sie sich die Zuordnungstabelle an:

| Desktop-Plugin | Mobiles Plugin | Paket |
| --- | --- | --- |
| `UniverUIPlugin` | `UniverMobileUIPlugin` | `@univerjs/ui` |
| `UniverSheetsUIPlugin` | `UniverSheetsMobileUIPlugin` | `@univerjs/sheets-ui` |

Wenn in der nachfolgenden Feature-Dokumentation ein Feature über ein mobiles Anpassungs-Plugin verfügt, werden wir dies im entsprechenden Abschnitt vermerken.

## Andere Versionen

Zusätzlich zu stabilen Versionen bietet Univer Alpha-/Beta- und Nightly-Kanäle. Mit diesen Versionen erhalten Sie frühzeitig Zugriff auf die neuesten Funktionen, die noch nicht offiziell veröffentlicht wurden. Bedenken Sie jedoch, dass mehr Funktionen auch mehr Risiken bedeuten. Diese Versionen können Fehler, unvollständige Funktionalität oder instabile Funktionen enthalten. Bitte vermeiden Sie nach Möglichkeit die Verwendung dieser Versionen in Produktionsumgebungen.

### Alpha-/Beta-Release

Wenn das Univer-Entwicklungsteam eine neue Funktion oder wesentliche Änderung fertigstellt, veröffentlicht es diese möglicherweise vorab für den Alpha- oder Beta-Kanal. Sie können die Alpha-/Betaversion eines Univer-Pakets mit dem folgenden Befehl installieren:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Wenn Sie bei der Verwendung von Alpha-/Betaversionen auf Probleme stoßen oder Feedback haben, melden Sie diese bitte dem Univer-Entwicklungsteam über [GitHub Issues](https://github.com/dream-num/univer/issues).

Wir freuen uns über Ihr Feedback zu diesen frühen Versionen.
