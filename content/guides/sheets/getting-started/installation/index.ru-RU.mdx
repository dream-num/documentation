title: Установка и основы использования
---

В основе Univer лежит архитектура плагинов, призванная предоставить разработчикам гибкий и расширяемый фреймворк для создания приложений для работы с электронными документами. Такая архитектура позволяет легко подключать различные функциональные модули с учетом потребностей разных пользователей. Однако она также усложняет приложение, особенно для разработчиков, которые только знакомятся с Univer.

Поэтому Univer предлагает два способа быстрой интеграции и начала работы: **режим плагинов** и **режим предустановок**. **Предустановка** представляет собой набор заранее настроенных плагинов, поэтому без сложных расширений оба режима предоставляют одинаковые возможности.

<Callout type="warning" title="Внимание">
  - **Одинаковые версии зависимостей**: независимо от выбранного режима — предустановок или плагинов — номера версий всех зависимостей должны совпадать.
  - **Осторожное совместное использование плагинов и предустановок**: если плагин уже входит в предустановку, при ее использовании не нужно импортировать его отдельно. Иначе возможны конфликты плагинов или неполадки в работе функций.
</Callout>

Различия между режимами плагинов и предустановок:

| Режим плагинов | Режим предустановок |
| --- | --- |
| Требуется вручную импортировать соответствующие пакеты Facade | Не требуется вручную импортировать пакеты Facade |
| Необходимо учитывать порядок регистрации плагинов с одинаковой функциональностью | Порядок регистрации функций, включенных в предустановки, учитывать не нужно |
| Поддерживается отложенная загрузка по требованию | Настроенные предустановки загружаются синхронно при инициализации |

## Настройка в режиме предустановок

Ниже показано, как быстро создать приложение Univer Sheets менее чем в двадцать строк кода.

### Использование менеджера пакетов

Если в проекте уже применяются современные инструменты фронтенд-разработки, интегрировать Univer будет очень просто. Для сборки приложений Univer рекомендуем использовать инструменты с хорошей поддержкой ES Modules, например [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) или [Webpack 5](https://webpack.js.org/). Для других инструментов сборки, таких как Webpack 4, может потребоваться дополнительная настройка.

#### Установка

Установите `@univerjs/presets` с помощью выбранного менеджера пакетов:

```package-install
npm install @univerjs/presets @univerjs/preset-sheets-core
```

#### Использование

<Callout type="warning">
  Если инструмент сборки не поддерживает поле `exports` в package.json (это часто встречается в Webpack 4), необходимо вручную заменить сопоставленные пути фактическими.
</Callout>

Следующий код запускает приложение Univer Sheets:

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-sheets-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
    ),
  },
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createWorkbook({})
```

Возвращаемый здесь объект `univerAPI` называется Univer Facade API. Через него можно обращаться ко многим функциям Univer.

#### Метод `createUniver`

Метод `createUniver` принимает объект конфигурации Univer, в котором задаются язык, тема, плагины и другие параметры. Он возвращает объект с экземпляром Univer и экземпляром Univer Facade API.

Некоторые свойства объекта конфигурации:

- `locale`: языковая среда; можно использовать значение перечисления `LocaleType`.
- `locales`: объект локалей, где ключ — языковая среда, а значение — объект языкового пакета.
- `theme`: необязательный объект темы.
- `presets`: массив регистрируемых предустановок, например `UniverSheetsCorePreset`.
- `plugins`: массив дополнительных плагинов, которые необходимо зарегистрировать.

Плагины, не входящие ни в один пакет предустановок, а также собственные плагины можно зарегистрировать через свойство `plugins`. Кроме того, после получения экземпляра Univer плагины можно регистрировать методом `univer.registerPlugin`.

<Callout>
  Подробнее о методе `createUniver` см. в разделе [Справочник API / createUniver](https://docs.univer.ai/reference/methods/create-univer).
</Callout>

### Импорт из CDN

Если вы не хотите использовать менеджер пакетов или желаете быстро попробовать возможности Univer, необходимые ресурсы можно импортировать через CDN. Подробнее см. в разделе [Использование Univer через CDN](/guides/sheets/getting-started/installation/cdn#preset-mode).

## Настройка в режиме плагинов

Возможности Univer предоставляются в виде набора плагинов. Помимо нескольких основных плагинов, необходимых для работы продукта, остальные можно подключать по мере необходимости. Ниже на примере простейшего приложения Univer Sheets показано, как вручную подобрать, объединить и установить плагины.

В отличие от режима предустановок, режим плагинов по умолчанию не включает Facade API. Поэтому фрагменты следующих примеров, связанные с Facade API, необязательны и при необходимости их можно удалить.

### Использование менеджера пакетов

#### Установка

Для разработки представления мы используем React (это не мешает использовать Univer с Vue или Angular), а для обработки потоков данных — Rxjs. Обе библиотеки широко применяются в современной фронтенд-разработке, поэтому мы указываем их как peerDependencies. Однако менеджеры пакетов по-разному работают с peerDependencies, и здесь важно учесть несколько особенностей.

<Callout>
  - При использовании npm убедитесь, что установлена версия npm@7 или новее. Версии npm@3 ~ npm@6 некорректно устанавливают `peerDependencies`[^1].
  - При использовании pnpm убедитесь, что установлена версия pnpm@8 или новее. Для pnpm@6 ~ pnpm@7 можно попробовать задать `auto-install-peers=true` [^2], чтобы устранить проблемы с установкой зависимостей.
  - При использовании yarn недостающие `peerDependencies` необходимо устанавливать вручную[^3]. В приведенные ниже команды установки эти зависимости уже включены.
</Callout>

#### Методы `univer.registerPlugin` и `univer.registerPlugins` [#registerPlugin]

Метод ``univer.registerPlugin` используется для регистрации плагина в экземпляре Univer. После создания экземпляра Univer вызовите этот метод, чтобы зарегистрировать плагины.

Плагин можно зарегистрировать с помощью метода `univer.registerPlugin(Plugin, options)`, где `Plugin` — регистрируемый плагин, а `options` — необязательные параметры конфигурации, которые могут различаться в зависимости от плагина.

Для одновременной регистрации нескольких плагинов передайте массив в `univer.registerPlugins`. Это удобно, когда требуется централизованно управлять плагинами.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverSheetsPlugin,
  UniverSheetsUIPlugin,
  UniverSheetsFormulaPlugin,
  UniverSheetsFormulaUIPlugin,
  UniverSheetsNumfmtPlugin,
  UniverSheetsNumfmtUIPlugin,
])
```

#### Отложенная загрузка плагинов

Одно из преимуществ режима плагинов — возможность гибко управлять моментом их загрузки. Обычно при инициализации приложения загружают только необходимые плагины, а загрузку остальных откладывают до завершения первого рендеринга.

```typescript
// ...

univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

В нашей [официальной демонстрации](https://github.com/dream-num/univer/blob/dev/examples/src/sheets/main.ts) используется этот способ оптимизации — при необходимости можно ориентироваться на нее.

### Поддержка мобильных устройств

Univer предоставляет **экспериментальную** поддержку мобильных устройств. Мобильная версия оптимизирована для сенсорного управления и предлагает компоненты интерфейса и способы взаимодействия, адаптированные к мобильным устройствам.

- **Плагины интерфейса**: для адаптации к разным способам взаимодействия на различных устройствах некоторые плагины интерфейса доступны в настольном и мобильном вариантах. Оба варианта находятся в одном npm-пакете и различаются путями экспорта.
- **Плагины основной логики**: например, движок формул (`UniverFormulaEnginePlugin`) и движок рендеринга (`UniverRenderEnginePlugin`) одинаковы для настольных и мобильных устройств, поэтому разделять их версии не требуется.

<Callout type="info">
  Плагины для мобильных и настольных устройств — не два отдельных пакета, а разные варианты одного пакета для разных платформ. Например, `@univerjs/sheets-ui` предоставляет и настольный `UniverSheetsUIPlugin`, и мобильный `UniverSheetsMobileUIPlugin`.
</Callout>

<Callout type="warning" title="Примечания">
  - Поддержка мобильных устройств пока экспериментальная, поэтому некоторые функции могут быть реализованы не полностью.
  - Мобильные и настольные плагины интерфейса нельзя использовать одновременно. Выберите подходящий плагин с учетом типа устройства.
  - Перед развертыванием в рабочей среде рекомендуется провести тщательное тестирование.
</Callout>

#### Переход на мобильные плагины

Просто замените соответствующий плагин интерфейса его мобильным вариантом:

````typescript
import { UniverSheetsUIPlugin } from '@univerjs/sheets-ui' // [!code --]
import { UniverSheetsMobileUIPlugin } from '@univerjs/sheets-ui' // [!code ++]

univer.registerPlugin(UniverSheetsUIPlugin) // [!code --]
univer.registerPlugin(UniverSheetsMobileUIPlugin) // [!code ++]
````

## Другие каналы выпуска

Помимо стабильных выпусков, Univer предлагает каналы alpha / beta и nightly. Они позволяют заранее получить доступ к новейшим функциям, которые еще не выпущены официально. Однако вместе с новыми возможностями возрастают и риски: такие версии могут содержать ошибки, неполные или нестабильные функции. По возможности не используйте их в рабочей среде.

### Выпуски Alpha / Beta

После завершения работы над новой функцией или существенным изменением команда разработчиков Univer может предварительно опубликовать их в канале alpha или beta. Установить alpha- или beta-версию пакета Univer можно следующей командой:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Если при использовании alpha- или beta-версий вы обнаружите проблему или захотите поделиться отзывом, сообщите об этом команде разработчиков Univer через [GitHub Issues](https://github.com/dream-num/univer/issues).

Мы будем рады вашим отзывам о предварительных выпусках.
