title: Instalación y uso básico
---

Univer es un marco para aplicaciones electrónicas de documentos, y se monta a partir de plugins. El núcleo sigue siendo pequeño, y una aplicación añade sólo los módulos que necesita. El trade-off es una configuración más involucrada, especialmente cuando trabaja con Univer por primera vez.

Para reducir ese esfuerzo, Univer ofrece dos estilos de integración: **modo plugin** y **modo preset**. Un **preset** es un conjunto de plugins configurados por adelantado, por lo que sin extensiones personalizadas ambos modos proporcionan las mismas capacidades.

<Callout type="warning" title="Caution">
  - **Mantenga las versiones de dependencia en sincronización.** En cualquier modo, cada dependencia debe resolverse a la misma versión.
  - **Mezcle plugins y presets con cuidado.** Si un preset ya incluye un plugin, no importa ese plugin por separado. De lo contrario, pueden ocurrir conflictos de plugins o comportamientos de características inesperados.
</Callout>

Los dos modos difieren como sigue:

| Modo de complemento | Modo preestablecido |
| --- | --- |
| Importa los paquetes de fachada requeridos. | Los paquetes Facade vienen con el preset |
| Usted controla el orden de registro de plugins que proporcionan la misma funcionalidad | El preset ya maneja la orden de registro |
| Los plugins pueden ser cargados de perezoso a la demanda | Presets configurados cargan sincronizadamente durante la inicialización |

El modo Preset mantiene la configuración corta: una sola importación trae un paquete de plugins preconfigurados. Para **profunda personalización o extensiones**, utilice el modo plugin, que permite combinar y configurar los plugins individualmente.

## Integrar con ayuda de un Agent (opcional) [#agent-skills]

Utilice [`univer-integrate`](https://github.com/dream-num/skills/tree/main/skills/univer-integrate) cuando añada el Web SDK a una aplicación existente. Guía a un agente de codificación a través de configuración preestablecida o plugin, inicialización del editor, y el uso de Facade API.

```bash
npx skills add dream-num/skills --skill univer-integrate
```

Ejecute este comando en el directorio del proyecto que el agente ha abierto. Agregue `-g` para utilizar la habilidad a través de proyectos, o especifique un agente con `-a codex` o `-a claude-code`. A continuación, enumera las habilidades instaladas:

```bash
npx skills list
```

La lista debe incluir `univer-integrate`. Si la habilidad falta, verifique que `SKILL.md` existe en la ruta de instalación y reabrir la sesión de agente si es necesario.

Los tutoriales más antiguos pueden hacer referencia a `dream-num/univer-sdk-skills`. Utilice el comando `dream-num/skills` actual mostrado anteriormente; el nombre de habilidad sigue siendo `univer-integrate` . Verifique la base SDK que la habilidad espera, e integre en la documentación actual y las versiones instaladas en su proyecto.

## Configuración a través del modo complemento

Univer ofrece sus características como plugins. Se requieren algunos plugins de núcleo para que el producto funcione; los plugins restantes se importan según sea necesario. Esta sección construye una aplicación mínima Univer Hojas manualmente y registra sus plugins uno por uno.

A diferencia del modo preset, el modo plugin no incluye el Facade API[^facade-entry] por defecto. Las partes relacionadas con Facade del código de abajo son opcionales y se pueden eliminar cuando no es necesario.

### Uso del Administrador de paquetes

#### Instalación

Univer utiliza React para sus puntos de vista (esto no impide utilizarlo en Vue o Angular) y Rxjs para los flujos de datos. Ambas bibliotecas son ampliamente utilizadas en el desarrollo de vanguardia moderno, por lo que Univer los trata como parDependencies[^peer-dependency].

<Callout>
  - Con npm, utilice npm@7 o posterior. npm@3 ~ npm@6 no instalar `peerDependencies`[^1] correctamente.
  - Con pnpm, utilice pnpm@8 o posterior. En pnpm @6 ~ pnpm x7, el ajuste `auto-install-peers=true` [^2] puede resolver problemas de instalación de dependencia.
  - Con hilo, instale manualmente el `peerDependencies`[^3] desaparecido. Los comandos de instalación a continuación ya los incluyen.
</Callout>

#### Métodos `univer.registerPlugin` y `univer.registerPlugins` [#registerPlugin]

El método `univer.registerPlugin` registra un plugin con la instancia Univer. Llámalo después de que se haya creado la instancia.

Pase el plugin y sus opciones: `univer.registerPlugin(Plugin, options)`. `Plugin` es el plugin para registrarse, y `options` son elementos de configuración opcionales que difieren de un plugin a otro.

Para registrar varios plugins a la vez, pasar un array a `univer.registerPlugins`. Este enfoque es útil cuando los plugins se gestionan en un solo lugar.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverSheetsPlugin,
  UniverSheetsUIPlugin,
  UniverSheetsFormulaPlugin,
  UniverSheetsFormulaUIPlugin,
  UniverSheetsNumfmtPlugin,
  UniverSheetsNumfmtUIPlugin,
])
```

#### Complementos de carga diferida

Una ventaja clave del modo plugin es el control sobre cuando los plugins cargan. Un patrón común carga sólo los plugins esenciales durante la inicialización y posterga el resto hasta después del primer renderizado.

```typescript
// ...

univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

El [demo oficial](https://github.com/dream-num/univer/blob/0d849012594882307186f33734b8b89d80a729e9/examples/src/sheets/main.ts) aplica la misma optimización y vale la pena revisar.

### Compatibilidad móvil [#mobile-support]

<Callout type="warning">
  Estos ejemplos requieren paquetes del SDK que exporten los plugins móviles indicados. Mantenga todas las dependencias `@univerjs/*` y `@univerjs-pro/*` en **la misma versión**.
</Callout>

El **plugins UI móvil** proporciona controles táctiles en las hojas Univer.[^mobile-ui-mode] Elige el modo UI antes de crear el editor.

El soporte móvil para las hojas sigue siendo **experimental**. Prueba las características que tu aplicación requiere en los dispositivos a los que apuntas.

En el ejemplo de modo plugin anterior, **Sustituir la sustitución** la UI importa y registra los siguientes datos antes de `createUnit()`. No los anexes a un editor de escritorio que ya se ha inicializado. Retener los plugins de modelo, motores, archivos locales, CSS y Facade importa. Clases de escritorio y móviles se nombran exportaciones de la **mismo paquete de entrada** .

`UniverMobileUIPlugin`

| `container` | `string \| HTMLElement` |  | Elemento DOM donde se monta el editor o su ID. |
| `disableAutoFocus` | `true` | `true` | Evita que el editor reciba el foco al iniciarse. |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverSheetsFormulaMobileUIPlugin } from '@univerjs/sheets-formula-ui'
import { UniverSheetsNumfmtMobileUIPlugin } from '@univerjs/sheets-numfmt-ui'
import { UniverSheetsMobileUIPlugin } from '@univerjs/sheets-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
univer.registerPlugin(UniverSheetsMobileUIPlugin)
univer.registerPlugin(UniverSheetsFormulaMobileUIPlugin)
univer.registerPlugin(UniverSheetsNumfmtMobileUIPlugin)
```

En el móvil, también reemplazar `UniverDocsUIPlugin` con `UniverDocsMobileUIPlugin` para que los documentos dentro de las células puedan ser editados, y registrarlo antes de `UniverSheetsMobileUIPlugin`.

`UniverSheetsCorePreset` y `UniverDocsCorePreset` actualmente registran plugins de interfaz de escritorio y no tienen opción `mobile: true`. Para móviles, ensamblar los plugins explícitamente. Agregar plugins móviles después de un preset de escritorio no reemplaza la interfaz de usuario del preset.

## Configuración mediante el modo preestablecido

El modo Preset produce una aplicación Univer en funcionamiento en menos de veinte líneas de código.

### Uso del Administrador de paquetes

Si el proyecto ya utiliza herramientas modernas de vanguardia, integrar Univer es sencillo. Utilice una herramienta de construcción con soporte sólido ES Módulo, como [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) o [Webpack 5](https://webpack.js.org/). Las herramientas más antiguas como Webpack 4 pueden requerir configuración adicional.

#### Instalación

Instala `@univerjs/presets` con tu gestor de paquetes:

```package-install
npm install @univerjs/presets @univerjs/preset-sheets-core
```

#### Uso

<Callout type="warning">
  Si la herramienta de construcción no admite el campo `exports` en package.json (común con Webpack 4), cambia los caminos mapeados a los caminos reales manualmente.
</Callout>

Estos dos archivos son suficientes para iniciar una aplicación de hojas Univer:

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-sheets-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
    ),
  },
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createWorkbook({})
```

El objeto `univerAPI` devuelto es el Univer Facade API. Es la interfaz a través de la cual usted llama las características que Univer proporciona.

#### Método `createUniver`

`createUniver` acepta un objeto de configuración que contiene ajustes para Univer, como el idioma, el tema y los plugins. Devuelve un objeto que contiene la instancia Univer y la instancia Univer Facade API.

Las principales propiedades son:

- `locale`: el entorno del lenguaje, como un valor `LocaleType`.
- `locales`: un objeto de paquetes locales, clave por el entorno del lenguaje.
- `theme`: un objeto de tema opcional.
- `presets`: los presets a registrarse, como `UniverSheetsCorePreset`.
- `plugins`: plugins para registrarse además de los presets.

Cuando un plugin no pertenece a ningún paquete preset, o cuando escriba su propio, regístrelo a través de la propiedad `plugins`. También puede llamar a `univer.registerPlugin` después de obtener la instancia Univer .

<Callout>
  Para obtener más información sobre `createUniver`, consulte [Referencia de API / crearUniver](https://docs.univer.ai/reference/methods/create-univer).
</Callout>

## Otras versiones

Más allá de los lanzamientos estables, Univer ofrece canales alfa, beta y nocturnos. Estos edificios ofrecen acceso temprano a nuevas características antes de que sean liberados como estables. Más características también traen más riesgo: estas versiones pueden contener fallos, funcionalidad incompleta o comportamiento inestable. Evite en la producción donde sea posible.

### Lanzamiento alfa/beta

Cuando el equipo Univer completa una nueva característica o un cambio significativo, puede pre-renunciar el cambio al canal de alfa o beta. Instalar un alpha o beta con:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Si encuentra un problema o tiene comentarios mientras usa una versión alfa o beta, informe al equipo Univer a través de [Cuestiones de GitHub](https://github.com/dream-num/univer/issues).
