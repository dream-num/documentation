title: Installation et utilisation de base
---

Univer adopte une conception basée sur des plugins afin d’offrir aux développeurs un framework flexible et extensible pour les applications de documents électroniques. Grâce à cette approche, Univer peut facilement intégrer différents modules fonctionnels pour répondre aux besoins de chaque utilisateur. Elle accroît toutefois la complexité de l’application, en particulier pour les développeurs qui découvrent Univer.

C’est pourquoi Univer propose deux méthodes pour faciliter une intégration et une prise en main rapides : le **mode plugin** et le **mode prédéfini**. Un **préréglage** est en réalité un ensemble de plugins préconfigurés. Les deux modes offrent donc les mêmes fonctionnalités lorsqu’aucune extension complexe n’est nécessaire.

<Callout type="warning" title="Attention">
  - **Versions de dépendances cohérentes** : que vous utilisiez le mode prédéfini ou le mode plugin, vous devez veiller à ce que toutes les dépendances aient le même numéro de version.
  - **Prudence lors de l’utilisation conjointe de plugins et de préréglages** : si un plugin est déjà inclus dans un préréglage, vous n’avez pas besoin de l’importer séparément lorsque vous utilisez ce préréglage. Cela pourrait sinon provoquer des conflits entre plugins ou des anomalies de fonctionnement.
</Callout>

Différences entre le mode prédéfini et le mode plugin :

| Mode plugin | Mode prédéfini |
| --- | --- |
| Nécessite l’importation manuelle des packages Facade correspondants | Ne nécessite l’importation manuelle d’aucun package Facade |
| Nécessite de respecter l’ordre d’enregistrement des plugins proposant la même fonctionnalité | Ne nécessite pas de se préoccuper de l’ordre d’enregistrement des fonctionnalités incluses dans les préréglages |
| Prend en charge le chargement différé à la demande | Charge les préréglages configurés de manière synchrone pendant l’initialisation |

Univer propose deux modes d’intégration : *le mode prédéfini* et *le mode plugin*. Le mode prédéfini simplifie la configuration grâce à des ensembles de plugins préconfigurés. Pour une **personnalisation ou des extensions approfondies**, nous recommandons le mode plugin, qui permet de combiner et de configurer les plugins individuellement.

## Configuration en mode plugin

Univer propose une série de fonctionnalités sous forme de plugins. Outre certains plugins essentiels au produit, vous pouvez ajouter les autres de manière sélective selon vos besoins. Nous prendrons ici l’application Univer Sheets la plus simple comme exemple pour expliquer comment combiner et installer manuellement des plugins.

Contrairement au mode prédéfini, le mode plugin n’inclut pas l’API Facade[^facade-entry] par défaut. Dans les exemples de code suivants, les éléments liés à l’API Facade sont facultatifs et peuvent être supprimés selon vos besoins.

### Utilisation d’un gestionnaire de packages

#### Installation

Nous utilisons React pour développer l’interface, ce qui n’empêche pas d’utiliser Univer avec Vue ou Angular, et Rxjs pour gérer les flux de données. Ces deux bibliothèques étant largement utilisées dans le développement front-end moderne, nous les traitons comme des peerDependencies[^peer-dependency]. Toutefois, les outils de gestion de packages ne gèrent pas tous les peerDependencies de la même manière ; certains détails méritent donc votre attention.

<Callout>
  - Si vous utilisez npm, assurez-vous d’utiliser npm@7 ou une version ultérieure. En effet, npm@3 ~ npm@6 n’installe pas correctement les `peerDependencies`[^1].
  - Si vous utilisez pnpm, assurez-vous d’utiliser pnpm@8 ou une version ultérieure. Avec pnpm@6 ~ pnpm@7, vous pouvez essayer de définir `auto-install-peers=true` [^2] pour résoudre les problèmes d’installation des dépendances.
  - Si vous utilisez yarn, vous devez installer manuellement les `peerDependencies` manquantes[^3]. Les commandes d’installation ci-dessous incluent déjà ces dépendances.
</Callout>

<Callout type="warning" title="Attention">
  - Tous les plugins n’incluent pas de packages Facade, de packs linguistiques ni de fichiers de style. La documentation de chaque fonctionnalité le précisera.

    ```typescript
    import { UniverUIPlugin } from '@univerjs/ui'
    import UIEnUS from '@univerjs/ui/locale/en-US'

    import '@univerjs/ui/lib/index.css'
    import '@univerjs/docs-ui/lib/index.css'
    import '@univerjs/sheets-ui/lib/index.css'

    import '@univerjs/sheets-numfmt-ui/lib/index.css'
    ```
  </Step>
  <Step>
    Si vous avez besoin de l’API Facade, vous pouvez importer ici les packages Facade correspondants. Cette étape est facultative, mais recommandée :

    ```typescript

    import '@univerjs/ui/facade'
    import '@univerjs/docs-ui/facade'
    import '@univerjs/sheets/facade'
    ```

    Créez ensuite une instance Univer et enregistrez ces plugins :

    ```typescript
    const univer = new Univer({

    ```
  </Step>
</Steps>

#### Méthodes `univer.registerPlugin` et `univer.registerPlugins` [#registerPlugin]

La méthode ``univer.registerPlugin` sert à enregistrer un plugin dans l’instance Univer. Vous pouvez l’appeler après avoir créé l’instance Univer afin d’y enregistrer des plugins.

Vous pouvez enregistrer un plugin avec la méthode `univer.registerPlugin(Plugin, options)`, où `Plugin` désigne le plugin à enregistrer et `options` les paramètres de configuration facultatifs, qui peuvent varier d’un plugin à l’autre.

Vous pouvez également utiliser `univer.registerPlugins` pour passer un tableau et enregistrer plusieurs plugins en une seule fois. Cette possibilité est utile lorsque vous devez centraliser la gestion des plugins.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverSheetsPlugin,
  UniverSheetsUIPlugin,
  UniverSheetsFormulaPlugin,
  UniverSheetsFormulaUIPlugin,
  UniverSheetsNumfmtPlugin,
  UniverSheetsNumfmtUIPlugin,
])
```

#### Chargement différé des plugins

L’un des principaux avantages du mode plugin est de pouvoir contrôler plus finement le moment où les plugins sont chargés. Une approche courante consiste à ne charger que les plugins indispensables lors de l’initialisation de l’application, puis à différer le chargement de certains plugins jusqu’à la fin du premier rendu.

```typescript
// ...

univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

Notre [démo officielle](https://github.com/dream-num/univer/blob/0d849012594882307186f33734b8b89d80a729e9/examples/src/sheets/main.ts) utilise cette technique d’optimisation ; vous pouvez vous y référer.

### Prise en charge mobile [#mobile-support]

<Callout type="warning">
  Ces exemples nécessitent des paquets SDK exportant les plugins mobiles ci-dessous. Gardez toutes les dépendances `@univerjs/*` et `@univerjs-pro/*` à **la même version**.
</Callout>

Utilisez les **plugins UI mobiles** pour les commandes tactiles de Univer Sheets.[^mobile-ui-mode] Choisissez le mode avant de créer l’éditeur.

La prise en charge mobile de Sheets reste **expérimentale** ; vérifiez les fonctionnalités nécessaires sur les appareils ciblés.

Dans l’exemple en mode plugin ci-dessus, **remplacez** les imports et inscriptions UI suivants avant `createUnit()`. Ne les ajoutez pas à un éditeur de bureau déjà initialisé. Conservez les modèles, moteurs, traductions, CSS et imports Facade. Les classes sont des exports nommés du **même point d’entrée du paquet**.

```typescript
import { UniverSheetsFormulaMobileUIPlugin } from '@univerjs/sheets-formula-ui'
import { UniverSheetsNumfmtMobileUIPlugin } from '@univerjs/sheets-numfmt-ui'
import { UniverSheetsMobileUIPlugin } from '@univerjs/sheets-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverSheetsMobileUIPlugin)
univer.registerPlugin(UniverSheetsFormulaMobileUIPlugin)
univer.registerPlugin(UniverSheetsNumfmtMobileUIPlugin)
```

**Conservez `UniverDocsUIPlugin` dans Sheets.** `UniverSheetsMobileUIPlugin` en dépend pour l’édition de texte dans les cellules. L’éditeur Docs indépendant utilise `UniverDocsMobileUIPlugin`.

Actuellement, `UniverSheetsCorePreset` et `UniverDocsCorePreset` enregistrent des UI de bureau et ne proposent pas d’option `mobile: true`. Assemblez explicitement les plugins mobiles. Les ajouter après un preset de bureau ne remplace pas son UI.

#### Conteneur et interactions tactiles

Définissez une hauteur explicite et le viewport de la page. `100dvh` suit la hauteur dynamique du viewport. Vérifiez le défilement, le zoom par pincement, la sélection de texte, le presse-papiers et le clavier virtuel sur les navigateurs mobiles ciblés. Réduire la largeur ne sélectionne pas les plugins mobiles.

`UniverMobileUIPlugin` utilise `disableAutoFocus: true` par défaut pour éviter que l’éditeur ne prenne automatiquement le focus à l’initialisation.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## Configuration en mode prédéfini

Nous allons présenter brièvement comment créer rapidement une application Univer Sheets en moins de vingt lignes de code.

### Utilisation d’un gestionnaire de packages

Si votre projet utilise déjà des outils de développement front-end modernes, l’intégration d’Univer sera très simple. Pour créer des applications Univer, nous recommandons des outils de build offrant une bonne prise en charge des modules ES, comme [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) ou [Webpack 5](https://webpack.js.org/). Si vous utilisez d’autres outils de build, tels que Webpack 4, une configuration supplémentaire peut être nécessaire.

#### Installation

Utilisez le gestionnaire de packages de votre choix pour installer `@univerjs/presets` :

```package-install
npm install @univerjs/presets @univerjs/preset-sheets-core
```

#### Utilisation

<Callout type="warning">
  Si votre outil de build ne prend pas en charge le champ `exports` de package.json, ce qui est courant avec Webpack 4, vous devez remplacer manuellement les chemins mappés par les chemins réels.
</Callout>

Le code suivant permet de démarrer une application Univer Sheets :

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-sheets-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
    ),
  },
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createWorkbook({})
```

L’objet `univerAPI` renvoyé ici est appelé API Facade d’Univer. Il vous permet d’utiliser de nombreuses fonctionnalités proposées par Univer.

#### Méthode `createUniver`

La méthode `createUniver` accepte un objet de configuration contenant les paramètres d’Univer, tels que la langue, le thème et les plugins. Elle renvoie un objet qui contient l’instance Univer et l’instance de l’API Facade d’Univer.

Voici quelques propriétés de l’objet de configuration :

- `locale` : environnement linguistique, qui peut être une valeur de l’énumération `LocaleType`.
- `locales` : objet de paramètres régionaux dont la clé correspond à l’environnement linguistique et la valeur au pack linguistique.
- `theme` : objet de thème facultatif.
- `presets` : tableau contenant les préréglages à enregistrer, comme `UniverSheetsCorePreset`.
- `plugins` : tableau contenant les plugins supplémentaires à enregistrer.

Lorsque vous utilisez un plugin qui n’est inclus dans aucun package de préréglage ou que vous créez votre propre plugin, vous pouvez l’enregistrer avec la propriété `plugins`. Vous pouvez aussi choisir d’enregistrer des plugins à l’aide de la méthode `univer.registerPlugin` après avoir obtenu l’instance Univer.

<Callout>
  Vous trouverez des informations plus détaillées sur la méthode `createUniver` dans la [Référence de l’API / createUniver](https://docs.univer.ai/reference/methods/create-univer).
</Callout>

## Autres versions

Outre les versions stables, Univer propose des canaux alpha / beta et nightly. Ces versions vous donnent un accès anticipé aux fonctionnalités les plus récentes qui n’ont pas encore été publiées officiellement. Gardez toutefois à l’esprit que davantage de fonctionnalités implique aussi davantage de risques. Ces versions peuvent contenir des bugs, des fonctionnalités incomplètes ou instables. Évitez autant que possible de les utiliser dans des environnements de production.

### Version alpha / beta

Lorsque l’équipe de développement d’Univer termine une nouvelle fonctionnalité ou une modification importante, elle peut la publier en avant-première sur le canal alpha ou beta. Vous pouvez installer la version alpha / beta d’un package Univer à l’aide de la commande suivante :

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Si vous rencontrez un problème ou souhaitez faire part de vos commentaires lors de l’utilisation des versions alpha / beta, signalez-les à l’équipe de développement d’Univer via les [issues GitHub](https://github.com/dream-num/univer/issues).

Vos retours sur ces versions préliminaires sont les bienvenus.
