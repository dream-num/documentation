title: Installation et utilisation de base
---

Univer est un framework pour les applications de documents électroniques, et il est assemblé à partir de plugins. Le noyau reste petit, et une application ajoute seulement les modules dont elle a besoin. L'échange est une configuration plus impliquée, particulièrement lorsque vous travaillez pour la première fois avec Univer.

Pour réduire cet effort, Univer fournit deux styles d'intégration : **mode plugin** et **mode préréglé**. Un **préréglé** est un ensemble de plugins configurés à l'avance, donc sans extensions personnalisées, les deux modes fournissent les mêmes capacités.

<Callout type="warning" title="Attention">
  - **Conservez les versions de dépendance en synchronisation.** Dans les deux modes, chaque dépendance doit se résoudre à la même version.
  - **Mélanger les plugins et les préréglages avec soin.** Si un préréglage inclut déjà un plugin, n'importez pas ce plugin séparément. Sinon des conflits de plugin ou un comportement inattendu de fonctionnalité peuvent survenir.
</Callout>

Les deux modes diffèrent comme suit:

| Mode plugin | Mode prédéfini |
| --- | --- |
| Vous importez les paquets de façade requis vous-même | Les paquets Facade sont livrés avec le préréglage |
| Vous contrôlez l'ordre d'enregistrement des plugins qui fournissent la même fonctionnalité | Le préréglage gère déjà l'ordre d'enregistrement |
| Les greffons peuvent être chargés paresseux sur demande | Les préréglages configurés se chargent synchronement pendant l'initialisation |

Le mode préréglage reste court : une seule importation apporte un paquet de plugins préconfigurés. Pour **personnalisation profonde ou extensions**, utilisez le mode plugin, ce qui permet de combiner et de configurer les plugins individuellement.

## Faire appel à un Agent pour l’intégration (facultatif) [#agent-skills]

Utilisez [`univer-integrate`](https://github.com/dream-num/skills/tree/main/skills/univer-integrate) lors de l'ajout du Web SDK à une application existante. Il guide un agent de codage par configuration préréglée ou plugin, initialisation de l'éditeur et utilisation de Facade API.

```bash
npx skills add dream-num/skills --skill univer-integrate
```

Exécutez cette commande dans le répertoire de projets que l'agent a ouvert. Ajoutez `-g` pour utiliser les compétences pour tous les projets, ou spécifiez un agent avec `-a codex` ou `-a claude-code`.

```bash
npx skills list
```

La liste doit inclure `univer-integrate`. Si la compétence est manquante, vérifier que `SKILL.md` existe dans le chemin d'installation et rouvrir la session d'agent si nécessaire.

Les tutoriels plus anciens peuvent renvoyer à `dream-num/univer-sdk-skills`. Utilisez la commande `dream-num/skills` actuelle montrée ci-dessus; le nom de compétence reste `univer-integrate` . Vérifiez la base de référence SDK que la compétence attend, et intégrez-la à la documentation actuelle et aux versions installées dans votre projet.

## Configuration en mode plugin

Univer fournit ses fonctionnalités comme plugins. Quelques plugins de base sont nécessaires pour que le produit fonctionne; les plugins restants sont importés au besoin. Cette section construit une application minimale Univer Sheets manuellement et enregistre ses plugins un par un.

Contrairement au mode préréglé, le mode plugin n'inclut pas le Facade API[^facade-entry] par défaut. Les parties du code liées à Facade ci-dessous sont optionnelles et peuvent être supprimées lorsque ce n'est pas nécessaire.

### Utilisation d’un gestionnaire de packages

#### Installation

Univer utilise React pour ses vues (ce qui n'empêche pas de l'utiliser dans Vue ou Angular) et Rxjs pour les flux de données. Les deux bibliothèques sont largement utilisées dans le développement front-end moderne, de sorte que Univer les traite comme peerDependencies[^peer-dependency]. Les gestionnaires de paquets gèrent différemment les dépendances des pairs, et plusieurs détails nécessitent une attention particulière:

<Callout>
  - Avec npm, utilisez npm@7 ou plus tard. npm @3 ~ npm=6 n'installez pas correctement `peerDependencies`[^1].
  - Avec pnpm, utilisez pnpmm@8 ou plus tard. Sur pnpM@6 ~ pnpms@7, le paramètre `auto-install-peers=true` [^2] peut résoudre les problèmes d'installation de dépendance.
  - Avec le fil, installez manuellement le `peerDependencies`[^3] manquant. Les commandes d'installation ci-dessous les incluent déjà.
</Callout>

#### Méthodes `univer.registerPlugin` et `univer.registerPlugins` [#registerPlugin]

La méthode `univer.registerPlugin` enregistre un plugin avec l'instance Univer. Appelez-le après la création de l'instance.

Passez le plugin et ses options: `univer.registerPlugin(Plugin, options)`. `Plugin` est le plugin à enregistrer, et `options` sont des éléments de configuration optionnels qui diffèrent d'un plugin à l'autre.

Pour enregistrer plusieurs plugins à la fois, passez un tableau à `univer.registerPlugins`. Cette approche est utile lorsque les plugins sont gérés en un seul endroit.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverSheetsPlugin,
  UniverSheetsUIPlugin,
  UniverSheetsFormulaPlugin,
  UniverSheetsFormulaUIPlugin,
  UniverSheetsNumfmtPlugin,
  UniverSheetsNumfmtUIPlugin,
])
```

#### Chargement différé des plugins

Un avantage clé du mode plugin est le contrôle sur quand les plugins chargent. Un modèle commun charge uniquement les plugins essentiels pendant l'initialisation et reporte le reste jusqu'après le premier rendu.

```typescript
// ...

univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

Le [démo officielle](https://github.com/dream-num/univer/blob/0d849012594882307186f33734b8b89d80a729e9/examples/src/sheets/main.ts) applique la même optimisation et mérite d'être examiné.

### Prise en charge mobile [#mobile-support]

<Callout type="warning">
  Ces exemples nécessitent des paquets SDK exportant les plugins mobiles ci-dessous. Gardez toutes les dépendances `@univerjs/*` et `@univerjs-pro/*` à **la même version**.
</Callout>

Le **plugins d'interface utilisateur mobiles** fournit des commandes tactiles dans les feuilles Univer.[^mobile-ui-mode] Choisissez le mode UI avant de créer l'éditeur.

Le support mobile pour les feuilles reste **expérimental**. Testez les fonctionnalités que votre application nécessite sur les appareils que vous ciblez.

Dans l'exemple de mode plugin ci-dessus, **remplacer** l'interface utilisateur importe et enregistre avec ceux ci-dessous avant `createUnit()`. Ne pas les ajouter à un éditeur de bureau qui a déjà été initialisé. Conserver les plugins modèles, moteurs, fichiers locaux, CSS et importations Facade. Les classes de bureau et mobiles sont nommées exportations de **même entrée du colis** .

`UniverMobileUIPlugin`

| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | Élément DOM de montage de l’éditeur ou son identifiant. |
| `disableAutoFocus` | `true` | `true` | Empêche l’éditeur de prendre le focus au démarrage. |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverSheetsFormulaMobileUIPlugin } from '@univerjs/sheets-formula-ui'
import { UniverSheetsNumfmtMobileUIPlugin } from '@univerjs/sheets-numfmt-ui'
import { UniverSheetsMobileUIPlugin } from '@univerjs/sheets-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
univer.registerPlugin(UniverSheetsMobileUIPlugin)
univer.registerPlugin(UniverSheetsFormulaMobileUIPlugin)
univer.registerPlugin(UniverSheetsNumfmtMobileUIPlugin)
```

Sur mobile, remplacez également `UniverDocsUIPlugin` par `UniverDocsMobileUIPlugin` afin que les documents à l'intérieur des cellules puissent être édités, et enregistrez-les avant `UniverSheetsMobileUIPlugin`.

`UniverSheetsCorePreset` et `UniverDocsCorePreset` enregistrent actuellement des plugins d'interface utilisateur de bureau et n'ont pas d'option `mobile: true`. Pour le mobile, assemblez les plugins explicitement. L'ajout de plugins mobiles après un préréglage de bureau ne remplace pas l'interface utilisateur du préréglage.

#### Conteneur et interactions tactiles

Définissez une hauteur explicite pour le conteneur et configurez le port de vue de la page. `100dvh` suit la hauteur du port de vue dynamique. Dans les navigateurs mobiles cibles, vérifiez le défilement, pincez le zoom, la sélection de texte, l'accès au presse-papiers et le clavier à l'écran.

`UniverMobileUIPlugin` par défaut sur `disableAutoFocus: true`, de sorte que l'éditeur ne se concentre pas automatiquement pendant l'initialisation.

```html

<div id="app" style="height: 100dvh"></div>
```

## Configuration en mode prédéfini

Le mode Preset produit une application de feuilles Univer en cours d'exécution dans moins de vingt lignes de code.

### Utilisation d’un gestionnaire de packages

Si le projet utilise déjà des outils frontaux modernes, l'intégration de Univer est simple. Utilisez un outil de construction avec une prise en charge solide du module ES, comme [Vit](https://vitejs.dev/), [esbuild](https://esbuild.github.io/) ou [Emballage Web 5](https://webpack.js.org/). Des outils plus anciens comme Webpack 4 peuvent nécessiter une configuration supplémentaire.

#### Installation

Installez `@univerjs/presets` avec votre gestionnaire de paquets :

```package-install
npm install @univerjs/presets @univerjs/preset-sheets-core
```

#### Utilisation

<Callout type="warning">
  Si l'outil build ne prend pas en charge le champ `exports` dans package.json (commun avec Webpack 4), changez manuellement les chemins mappés vers les chemins réels.
</Callout>

Ces deux fichiers sont suffisants pour démarrer une application de feuilles Univer :

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-sheets-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
    ),
  },
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createWorkbook({})
```

L'objet `univerAPI` retourné est le Univer Facade API. C'est l'interface à travers laquelle vous appelez les fonctionnalités fournies par Univer .

#### Méthode `createUniver`

`createUniver` accepte un objet de configuration qui contient des paramètres pour Univer, tels que la langue, le thème et les plugins. Il retourne un objet qui contient l'instance Univer et l'instance Univer Facade API.

Les principales propriétés sont les suivantes:

- `locale` : l'environnement de la langue, comme valeur `LocaleType`.
- `locales` : objet de paquets locaux, clé par environnement linguistique.
- `theme` : objet de thème optionnel.
- `presets` : les préréglages à enregistrer, tels que `UniverSheetsCorePreset`.
- `plugins`: plugins à enregistrer en plus des presets.

Lorsqu'un plugin n'appartient à aucun paquet prédéfini, ou lorsque vous écrivez le vôtre, enregistrez-le via la propriété `plugins`. Vous pouvez également appeler `univer.registerPlugin` après avoir obtenu l'instance Univer .

<Callout>
  Pour plus de détails sur `createUniver`, voir [API Référence / createUnivers](https://docs.univer.ai/reference/methods/create-univer).
</Callout>

## Autres versions

Au-delà des versions stables, Univer fournit des canaux alpha, bêta et nocturne. Ces constructions offrent un accès précoce à de nouvelles fonctionnalités avant qu'elles ne soient publiées comme stables. Plus de fonctionnalités apportent également plus de risque: ces versions peuvent contenir des bugs, des fonctionnalités incomplètes, ou un comportement instable.

### Version alpha / beta

Lorsque l'équipe Univer complète une nouvelle fonctionnalité ou un changement significatif, elle peut pré-libérer le changement vers le canal alpha ou bêta. Installez une construction alpha ou bêta avec:

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

Si vous rencontrez un problème ou si vous avez des commentaires lors de l'utilisation d'une version alpha ou bêta, signalez-le à l'équipe Univer via [GitHub Problèmes](https://github.com/dream-num/univer/issues).
