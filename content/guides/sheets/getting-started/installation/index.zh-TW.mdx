title: 安裝與基本使用
---

本章介紹 Univer Sheets 的安裝與基本使用，包括預設模式和外掛模式的配置流程。如果尚未熟悉 Univer 的基礎術語，建議先閱讀 [基本概念](/guides/sheets/getting-started/quickstart#basic-concepts)。

Univer 是一個電子文件應用框架，由外掛組合而成。核心部分保持精簡，應用只引入自身需要的模組。代價是搭建過程更為繁瑣，首次整合 Univer 時尤其明顯。

為此，Univer 提供**外掛模式**和**預設模式**兩種整合方式。預設是一組預先配置好的外掛，因此在不做自定義擴充套件的情況下，兩種模式提供的能力相同。預設模式可以縮短配置流程，一次匯入即可引入一組已配置好的外掛；如果需要**深度擴充套件**，則應使用外掛模式，逐一組合和配置外掛。

## 讓 Agent 協助整合（選用） [#agent-skills]

在向現有應用接入 Web SDK 時，可以使用 [`univer-integrate`](https://github.com/dream-num/skills/tree/main/skills/univer-integrate)。該 Skill 會引導程式設計 Agent 完成預設或外掛的配置、編輯器初始化以及 Facade API 的使用。

```bash
npx skills add dream-num/skills --skill univer-integrate
```

在 Agent 開啟的專案目錄中執行該命令。需要跨專案使用時加 `-g`，也可以用 `-a codex` 或 `-a claude-code` 指定 Agent。隨後檢視已安裝的 Skills：

```bash
npx skills list
```

列表中應包含 `univer-integrate`。如果未找到該項，請檢查安裝路徑中是否存在 `SKILL.md`，必要時重新開啟 Agent 會話。

舊教程中可能使用 `dream-num/univer-sdk-skills`。請改用上面的 `dream-num/skills` 命令，Skill 名稱仍為 `univer-integrate`。接入前應核對該 Skill 要求的 SDK 版本基線，並以當前文件和專案實際安裝的版本為準。

## 透過外掛模式建立

Univer 以外掛的形式提供各項功能。少數核心外掛是產品正常執行所必需的，其餘外掛按需引入。本節手動建置一個最小的 Univer Sheets 應用，並逐一註冊其中的外掛。

與預設模式不同，外掛模式預設不包含 Facade API[^facade-entry]。下面程式碼中與 Facade 相關的部分是可選的，不需要時可以刪除。

### 使用套件管理器

#### 安裝

Univer 使用 React 渲染檢視（這不影響在 Vue 或 Angular 中使用 Univer），並使用 Rxjs 處理資料流。這兩個庫在現代前端開發中應用廣泛，因此 Univer 將它們作為 peerDependencies[^peer-dependency] 處理。不同包管理器對 peer dependencies 的處理方式不同，有幾點需要注意：

<Callout>
  - 使用 npm 時，版本不得低於 npm@7。npm@3 ~ npm@6 無法正確安裝 `peerDependencies`[^1]。
  - 使用 pnpm 時，版本不得低於 pnpm@8。使用 pnpm@6 ~ pnpm@7 時，可以嘗試設定 `auto-install-peers=true` [^2] 以解決依賴安裝問題。
  - 使用 yarn 時，需要自行安裝缺失的 `peerDependencies`[^3]。下面的安裝命令已經包含這些依賴。
</Callout>

    如需使用 Facade API，在此處引入相關的 facade 包。這一步是可選的，但建議完成：

#### `univer.registerPlugin` 與 `univer.registerPlugins` 方法 [#registerPlugin]

`univer.registerPlugin` 方法用於向 Univer 例項註冊外掛，應在建立例項之後呼叫。

註冊時傳入外掛和配置項：`univer.registerPlugin(Plugin, options)`。其中 `Plugin` 是要註冊的外掛，`options` 是可選的配置項，不同外掛的配置項各不相同。

如需一次註冊多個外掛，可以向 `univer.registerPlugins` 傳入陣列。這種方式適合集中管理外掛。

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverSheetsPlugin,
  UniverSheetsUIPlugin,
  UniverSheetsFormulaPlugin,
  UniverSheetsFormulaUIPlugin,
  UniverSheetsNumfmtPlugin,
  UniverSheetsNumfmtUIPlugin,
])
```

#### 懶載入部分外掛

外掛模式的一個優勢是可以控制外掛的載入時機。常見的做法是在初始化時只載入必需的外掛，將其餘外掛推遲到首次渲染完成之後再載入。

```typescript
// ...

univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

Univer 的[官方 demo](https://github.com/dream-num/univer/blob/0d849012594882307186f33734b8b89d80a729e9/examples/src/sheets/main.ts) 採用了同樣的最佳化，可供參考。

### 行動裝置支援 [#mobile-support]

<Callout type="warning">
  這些範例要求所安裝的 SDK 包匯出下文列出的行動版外掛。所有 `@univerjs/*` 和 `@univerjs-pro/*` 依賴必須保持**同一個版本**。
</Callout>

Univer Sheets 的觸控互動由**行動版 UI 外掛**提供。[^mobile-ui-mode] UI 模式需要在建立編輯器之前確定。

Sheets 的行動版支援仍處於**實驗階段**。應用所需的功能需要在目標裝置上驗證。

在上面的外掛模式範例中，應將 UI 外掛的匯入和註冊**替換**為下文列出的內容，並在 `createUnit()` 之前完成。不要將它們追加到已經初始化的桌面版編輯器上。模型外掛、引擎、語言檔案、CSS 和 Facade 匯入均需保留。桌面版與行動版的類都是**同一套件入口**的具名匯出。

`UniverMobileUIPlugin`

| <span data-config-options="">設定項目</span> | 類型 | 預設值 | 作用 |
| --- | --- | --- | --- |
| `container` | `string \| HTMLElement` |  | 編輯器掛載到的 DOM 元素，或它的 ID。 |
| `disableAutoFocus` | `true` | `true` | 編輯器啟動時不會自動獲得焦點。 |

```typescript
import { UniverDocsMobileUIPlugin } from '@univerjs/docs-ui'
import { UniverSheetsFormulaMobileUIPlugin } from '@univerjs/sheets-formula-ui'
import { UniverSheetsNumfmtMobileUIPlugin } from '@univerjs/sheets-numfmt-ui'
import { UniverSheetsMobileUIPlugin } from '@univerjs/sheets-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverDocsMobileUIPlugin)
univer.registerPlugin(UniverSheetsMobileUIPlugin)
univer.registerPlugin(UniverSheetsFormulaMobileUIPlugin)
univer.registerPlugin(UniverSheetsNumfmtMobileUIPlugin)
```

在行動版，還需要將 `UniverDocsUIPlugin` 替換為 `UniverDocsMobileUIPlugin`，以便編輯單元格內的文件，並應在 `UniverSheetsMobileUIPlugin` 之前註冊。

`UniverSheetsCorePreset` 和 `UniverDocsCorePreset` 目前註冊的是桌面版 UI 外掛，也沒有 `mobile: true` 選項。在行動版需要顯式組合外掛。在桌面版預設之後追加行動版外掛，無法替換預設的 UI。

#### 容器與觸控互動

為容器指定明確的高度，並配置頁面 viewport。`100dvh` 會跟隨動態視口高度變化。滾動、雙指縮放、文字選擇、剪貼簿訪問和軟鍵盤，均需在目標移動瀏覽器上驗證。僅調整桌面版編輯器的尺寸，不會切換到行動版外掛。

`UniverMobileUIPlugin` 預設使用 `disableAutoFocus: true`，編輯器在初始化時不會自動獲得焦點。

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

## 透過預設模式建立

使用預設模式，不到二十行程式碼即可執行一個 Univer Sheets 應用。

### 使用套件管理器

如果專案已經使用現代前端工具，接入 Univer 的過程較為直接。建議使用對 ES Module 支援較完整的建置工具，例如 [Vite](https://vitejs.dev/)、[esbuild](https://esbuild.github.io/) 或 [Webpack 5](https://webpack.js.org/)。使用 Webpack 4 等較早的工具時，可能需要額外的配置。

#### 安裝

使用包管理器安裝 `@univerjs/presets`：

```package-install
npm install @univerjs/presets @univerjs/preset-sheets-core
```

#### 使用

<Callout type="warning">
  如果建置工具不支援 package.json 的 `exports` 欄位（Webpack 4 中較為常見），需要自行將對映路徑改為實際路徑。
</Callout>

以下兩個檔案即可啟動一個 Univer Sheets 應用：

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreZhTW from '@univerjs/preset-sheets-core/locales/zh-TW'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-sheets-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.ZH_TW,
  locales: {
    [LocaleType.ZH_TW]: mergeLocales(
      UniverPresetSheetsCoreZhTW,
    ),
  },
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createWorkbook({})
```

返回的 `univerAPI` 物件就是 Univer Facade API。Univer 提供的各項功能都透過它呼叫。

#### `createUniver` 方法

`createUniver` 接收一個配置物件，其中包含 Univer 的語言、主題和外掛等設定。它返回一個物件，包含 Univer 例項和 Univer Facade API 例項。

配置物件的主要屬性如下：

- `locale`：語言環境，取值為 `LocaleType` 列舉值。
- `locales`：語言套件物件，鍵為語言環境，值為對應的語言套件。
- `theme`：主題物件，可選。
- `presets`：要註冊的預設，例如 `UniverSheetsCorePreset`。
- `plugins`：除預設之外需要額外註冊的外掛。

如果外掛不屬於任何預設套件，或是自行編寫的外掛，可以透過 `plugins` 屬性註冊。也可以在獲得 Univer 例項後呼叫 `univer.registerPlugin` 註冊。

<Callout>
  `createUniver` 的更多細節見 [API Reference / createUniver](https://docs.univer.ai/reference/methods/create-univer)。
</Callout>

## 其他發佈版本

除穩定版本外，Univer 還提供 alpha、beta 和 nightly 通道。這些版本可以提前使用尚未正式釋出的新功能，同時也帶來更高的風險：可能包含 bug、功能不完整或行為不穩定。生產環境中應儘量避免使用這些版本。

### Alpha / Beta 版本

Univer 開發團隊完成新功能或較大改動後，可能會先將其預釋出到 alpha 或 beta 通道。安裝 alpha 或 beta 版本使用以下命令：

```package-install
npm install @univerjs/<package-name>@alpha # Alpha 版本
npm install @univerjs/<package-name>@beta # Beta 版本
```

使用 alpha 或 beta 版本時遇到問題或有反饋，可以透過 [GitHub Issues](https://github.com/dream-num/univer/issues) 報告給 Univer 開發團隊。
