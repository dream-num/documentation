Univer는 플러그인 기반 설계 철학을 채택하여 개발자에게 유연하고 확장 가능한 전자 문서 애플리케이션 프레임워크를 제공하는 것을 목표로 합니다. 이러한 설계를 통해 다양한 기능 모듈을 손쉽게 통합하여 여러 사용자의 요구를 충족할 수 있습니다. 다만 플러그인 기반 설계는 애플리케이션의 복잡성을 높이며, 특히 Univer를 처음 접하는 개발자에게는 어려울 수 있습니다.

이를 위해 Univer는 빠르게 통합하고 사용할 수 있도록 **플러그인 모드**와 **프리셋 모드**라는 두 가지 방식을 제공합니다. **프리셋**은 미리 구성된 플러그인의 조합이므로, 복잡한 확장을 사용하지 않는다면 두 모드가 제공하는 기능은 동일합니다.

<Callout type="warning" title="주의">
  - **종속성 버전 통일**: 프리셋 모드와 플러그인 모드 중 어느 것을 사용하든 모든 종속성의 버전 번호가 일치해야 합니다.
  - **플러그인과 프리셋 혼용 시 주의**: 프리셋에 이미 포함된 플러그인은 프리셋을 사용할 때 별도로 가져올 필요가 없습니다. 별도로 가져오면 플러그인 충돌이나 기능 이상이 발생할 수 있습니다.
</Callout>

프리셋 모드와 플러그인 모드의 차이점은 다음과 같습니다.

| 플러그인 모드 | 프리셋 모드 |
| --- | --- |
| 해당 Facade 패키지를 직접 가져와야 함 | Facade 패키지를 직접 가져올 필요 없음 |
| 같은 기능을 제공하는 플러그인의 등록 순서에 주의해야 함 | 프리셋에 포함된 기능의 등록 순서를 신경 쓸 필요 없음 |
| 필요할 때 지연 로딩 가능 | 구성된 프리셋을 초기화할 때 동기식으로 로드함 |

Univer는 *프리셋 모드*와 *플러그인 모드*의 두 가지 통합 방식을 제공합니다. 프리셋 모드는 미리 구성된 플러그인 묶음으로 설정을 간소화하여 쉽게 시작할 수 있습니다. **심층적인 커스터마이징이나 확장**이 필요하다면 플러그인을 개별적으로 조합하고 설정할 수 있는 플러그인 모드를 권장합니다.

## 플러그인 모드로 설정하기

Univer는 여러 기능을 플러그인 형태로 제공합니다. 제품에 필수적인 일부 핵심 플러그인 외에는 필요에 따라 원하는 플러그인만 선택적으로 추가할 수 있습니다. 여기서는 가장 기본적인 Univer Sheets 애플리케이션을 예로 들어 플러그인을 직접 조합하고 설치하는 방법을 소개합니다.

프리셋 모드와 달리 플러그인 모드에는 Facade API[^facade-entry]가 기본으로 포함되지 않습니다. 다음 코드 예제에서 Facade API와 관련된 부분은 선택 사항이므로 필요에 따라 제거할 수 있습니다.

### 패키지 관리자 사용

#### 설치

뷰 개발에는 React를 사용하고(Vue 또는 Angular에서 Univer를 사용하는 데는 영향을 주지 않음), 데이터 스트림 처리에는 Rxjs를 사용합니다. 이 두 라이브러리는 최신 프런트엔드 개발에서 널리 사용되므로 peerDependencies[^peer-dependency]로 취급합니다. 다만 패키지 관리 도구마다 peerDependencies를 처리하는 방식이 다르므로 몇 가지 사항에 주의해야 합니다.

<Callout>
  - npm을 사용한다면 npm@7 이상인지 확인하세요. npm@3 ~ npm@6은 `peerDependencies`를 올바르게 설치하지 않기 때문입니다[^1].
  - pnpm을 사용한다면 pnpm@8 이상인지 확인하세요. pnpm@6 ~ pnpm@7을 사용한다면 `auto-install-peers=true` [^2]를 설정하여 종속성 설치 문제를 해결할 수 있습니다.
  - yarn을 사용한다면 누락된 `peerDependencies`를 직접 설치해야 합니다[^3]. 아래 설치 명령에는 이러한 종속성이 이미 포함되어 있습니다.
</Callout>

#### `univer.registerPlugin` 및 `univer.registerPlugins` 메서드 [#registerPlugin]

``univer.registerPlugin` 메서드는 Univer 인스턴스에 플러그인을 등록하는 데 사용합니다. Univer 인스턴스를 만든 뒤 이 메서드를 호출하여 플러그인을 등록할 수 있습니다.

`univer.registerPlugin(Plugin, options)` 메서드로 플러그인을 등록할 수 있습니다. 여기서 `Plugin`은 등록할 플러그인이고, `options`는 선택적 구성 항목입니다. 플러그인마다 구성 항목은 다를 수 있습니다.

`univer.registerPlugins`에 배열을 전달하여 여러 플러그인을 한 번에 등록할 수도 있습니다. 플러그인을 중앙에서 관리해야 할 때 유용합니다.

```typescript
univer.registerPlugins([
  UniverRenderEnginePlugin,
  UniverFormulaEnginePlugin,
  [UniverUIPlugin, {
    container: 'app',
  }],
  UniverDocsPlugin,
  UniverDocsUIPlugin,
  UniverSheetsPlugin,
  UniverSheetsUIPlugin,
  UniverSheetsFormulaPlugin,
  UniverSheetsFormulaUIPlugin,
  UniverSheetsNumfmtPlugin,
  UniverSheetsNumfmtUIPlugin,
])
```

#### 플러그인 지연 로딩

플러그인 모드의 대표적인 장점은 플러그인 로딩 시점을 더 유연하게 제어할 수 있다는 것입니다. 일반적으로 애플리케이션 초기화 중에는 필수 플러그인만 로드하고, 일부 플러그인은 첫 렌더링이 완료된 뒤로 로딩을 미룹니다.

```typescript
// ...

univer.createUnit(UniverInstanceType.UNIVER_SHEET, {})

import('@univerjs/watermark').then(({ UniverWatermarkPlugin }) => {
  univer.registerPlugin(UniverWatermarkPlugin, {
    textWatermarkSettings: {
      content: 'Hello, Univer!',
      fontSize: 36,
    },
  })
})
```

[공식 데모](https://github.com/dream-num/univer/blob/0d849012594882307186f33734b8b89d80a729e9/examples/src/sheets/main.ts)에서도 이 최적화 기법을 사용하므로 참고할 수 있습니다.

### 모바일 지원 [#mobile-support]

<Callout type="warning">
  아래 모바일 플러그인을 내보내는 SDK 패키지가 필요합니다. 모든 `@univerjs/*` 및 `@univerjs-pro/*` 의존성을 **같은 버전**으로 맞추세요.
</Callout>

Univer Sheets에서 터치 조작을 제공하려면 **모바일 UI 플러그인**을 사용합니다.[^mobile-ui-mode] 에디터를 만들기 전에 UI 모드를 선택하세요.

Sheets 모바일 지원은 아직 **실험적**입니다. 대상 기기에서 앱에 필요한 기능을 검증하세요.

위 플러그인 모드 예제에서 다음 UI 가져오기와 등록을 `createUnit()` 전에 **교체**하세요. 이미 초기화한 데스크톱 에디터에 추가하지 마세요. 모델 플러그인, 엔진, 언어 파일, CSS 및 Facade 가져오기는 유지합니다. 두 클래스는 **동일한 패키지 진입점**의 서로 다른 이름으로 내보내집니다.

```typescript
import { UniverSheetsFormulaMobileUIPlugin } from '@univerjs/sheets-formula-ui'
import { UniverSheetsNumfmtMobileUIPlugin } from '@univerjs/sheets-numfmt-ui'
import { UniverSheetsMobileUIPlugin } from '@univerjs/sheets-ui'
import { UniverMobileUIPlugin } from '@univerjs/ui'

univer.registerPlugin(UniverMobileUIPlugin, { container: 'app' })
univer.registerPlugin(UniverSheetsMobileUIPlugin)
univer.registerPlugin(UniverSheetsFormulaMobileUIPlugin)
univer.registerPlugin(UniverSheetsNumfmtMobileUIPlugin)
```

**Sheets에서는 `UniverDocsUIPlugin`을 유지하세요.** `UniverSheetsMobileUIPlugin`이 셀 내부 문서 편집에 이 플러그인을 사용합니다. 독립된 Docs 에디터에서는 `UniverDocsMobileUIPlugin`을 사용합니다.

현재 `UniverSheetsCorePreset`과 `UniverDocsCorePreset`은 데스크톱 UI를 등록하며 `mobile: true` 옵션이 없습니다. 모바일에서는 플러그인을 직접 구성하세요. 데스크톱 프리셋 뒤에 모바일 플러그인을 추가해도 기존 UI가 교체되지 않습니다.

#### 컨테이너와 터치 조작

컨테이너 높이를 명시하고 페이지 viewport를 설정하세요. `100dvh`는 동적 뷰포트 높이를 따릅니다. 대상 모바일 브라우저에서 스크롤, 핀치 확대/축소, 텍스트 선택, 클립보드 및 화면 키보드 표시 후 배치를 확인하세요. 데스크톱 에디터의 폭만 줄여서는 모바일 플러그인으로 전환되지 않습니다.

`UniverMobileUIPlugin`은 기본적으로 `disableAutoFocus: true`를 사용하여 초기화 시 에디터가 자동으로 포커스를 가져오지 않도록 합니다.

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<div id="app" style="height: 100dvh"></div>
```

패키지 관리자를 사용하고 싶지 않거나 Univer의 기능을 빠르게 체험하려면 CDN을 통해 관련 리소스를 가져올 수 있습니다. 자세한 내용은 [CDN으로 Univer 사용하기](/guides/sheets/getting-started/installation/cdn#plugin-mode)를 참고하세요.

## 프리셋 모드로 설정하기

여기서는 20줄 미만의 코드로 Univer Sheets 애플리케이션을 빠르게 구축하는 방법을 간단히 소개합니다.

### 패키지 관리자 사용

프로젝트에서 이미 최신 프런트엔드 개발 도구를 사용하고 있다면 Univer를 매우 간단하게 통합할 수 있습니다. Univer 애플리케이션을 빌드할 때는 ES Modules를 잘 지원하는 [Vite](https://vitejs.dev/), [esbuild](https://esbuild.github.io/), [Webpack 5](https://webpack.js.org/) 같은 빌드 도구를 권장합니다. 다른 빌드 도구(예: Webpack 4)를 사용한다면 추가 설정이 필요할 수 있습니다.

#### 설치

사용하는 패키지 관리자로 `@univerjs/presets`를 설치하세요.

```package-install
npm install @univerjs/presets @univerjs/preset-sheets-core
```

#### 사용법

<Callout type="warning">
  빌드 도구가 package.json의 `exports` 필드를 지원하지 않는 경우(Webpack 4에서 흔함), 매핑된 경로를 실제 경로로 직접 변경해야 합니다.
</Callout>

다음 코드로 Univer Sheets 애플리케이션을 시작할 수 있습니다.

```html title="index.html"
<div id="app" style="height: 600px"></div>
```

```typescript
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'

import '@univerjs/preset-sheets-core/lib/index.css'

const { univer, univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: {
    [LocaleType.EN_US]: mergeLocales(
      UniverPresetSheetsCoreEnUS,
    ),
  },
  presets: [
    UniverSheetsCorePreset({
      container: 'app',
    }),
  ],
})

univerAPI.createWorkbook({})
```

여기서 반환되는 `univerAPI` 객체를 Univer Facade API라고 하며, 이를 통해 Univer가 제공하는 다양한 기능을 호출할 수 있습니다.

<Callout type="warning">
  `UniverSheetsCorePreset`을 `@univerjs/presets/preset-sheets-core`에서 가져올 수도 있지만, 빌드 도구가 package.json의 `exports` 필드를 지원하는지 확인해야 합니다.
</Callout>

#### `createUniver` 메서드

`createUniver` 메서드는 언어, 테마, 플러그인 등 Univer의 설정 정보가 담긴 구성 객체를 받습니다. 이 메서드는 Univer 인스턴스와 Univer Facade API 인스턴스를 포함하는 객체를 반환합니다.

구성 객체의 주요 속성은 다음과 같습니다.

- `locale`: 언어 환경입니다. `LocaleType` 열거형 값을 사용할 수 있습니다.
- `locales`: 로케일 객체입니다. 키는 언어 환경이고 값은 언어 팩 객체입니다.
- `theme`: 선택 사항인 테마 객체입니다.
- `presets`: `UniverSheetsCorePreset`처럼 등록할 프리셋을 담은 배열입니다.
- `plugins`: 추가로 등록할 플러그인을 담은 배열입니다.

프리셋 패키지에 포함되지 않은 플러그인을 사용하거나 자체 플러그인을 구현한 경우 `plugins` 속성을 통해 등록할 수 있습니다. Univer 인스턴스를 얻은 뒤 `univer.registerPlugin` 메서드로 등록할 수도 있습니다.

<Callout>
  `createUniver` 메서드에 대한 자세한 내용은 [API 참조 / createUniver](https://docs.univer.ai/reference/methods/create-univer)에서 확인할 수 있습니다.
</Callout>

## 기타 릴리스

Univer는 안정 릴리스 외에도 alpha / beta 및 nightly 채널을 제공합니다. 이러한 버전에서는 아직 정식 출시되지 않은 최신 기능을 미리 사용할 수 있습니다. 하지만 기능이 많아지는 만큼 위험도 커진다는 점에 유의하세요. 버그, 미완성 기능 또는 불안정한 기능이 포함될 수 있으므로 가능한 한 프로덕션 환경에서는 사용하지 마세요.

### Alpha / Beta 릴리스

Univer 개발팀이 새 기능이나 중요한 변경을 완료하면 alpha 또는 beta 채널에 사전 출시할 수 있습니다. 다음 명령으로 Univer 패키지의 alpha / beta 버전을 설치할 수 있습니다.

```package-install
npm install @univerjs/<package-name>@alpha # Alpha version
npm install @univerjs/<package-name>@beta # Beta version
```

alpha / beta 버전을 사용하면서 문제가 발생하거나 의견이 있다면 [GitHub Issues](https://github.com/dream-num/univer/issues)를 통해 Univer 개발팀에 알려 주세요.

이러한 초기 릴리스에 대한 의견을 환영합니다.
