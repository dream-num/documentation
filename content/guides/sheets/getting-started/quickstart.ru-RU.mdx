Univer Sheets построен на небольшом наборе понятий: Units, Plugins, Snapshots, Commands и Facade API. На этой странице объясняется, что означает каждый термин. Чтобы увидеть эти понятия, работающие в редакторе, продолжайте с [Установка и базовое использование](/guides/sheets/getting-started/installation) .

## Основные понятия [#basic-concepts]

Пять терминов повторяются в Univer:

- Unit
- Плагин
- Снимок
- Команда
- Facade API

### Unit (единица контента) [#unit]

**Подразделение** - это полный экземпляр контента, управляемый Univer: книга, документ, презентация, база, доска или PDF. Каждый блок имеет свой собственный идентификатор (`unitId`), поэтому два документа одного типа - это два отдельных блока.

Рабочая тетрадь, содержащая несколько рабочих листов, остается одной Единицей. Её рабочие листы, диапазоны ячеек и ячейки являются внутренними объектами, а не собственными Единицами. Слайд следует тому же правилу и принадлежит единице представления, которая содержит его.

Один экземпляр Univer может загружать несколько блоков. **Снимок** - это сериализуемые данные, которые описывают состояние содержимого блока, и это не тот же объект, что и редактируемый живой блок. Разрешения, установленные на блоке, применяются ко всему экземпляру контента, в то время как разрешения на объекты применяются к содержанию внутри него.

### Плагины

Функции Univer предоставляются в виде плагинов. Плагины являются строительными блоками, а набор, который вы регистрируете, определяет приложение Univer.

Плагины выполняют два вида работы:

1. Они добавляют функцию. `@univerjs/sheets-filter`, например, обеспечивает фильтрацию.
2. Они предоставляют основные возможности, от которых зависят другие плагины. `@univerjs/engine-render` обеспечивает рендеринг.

Комбинирование плагинов позволяет формировать приложение вокруг ваших требований и исключать код, который вам не нужен.Когда у Univer нет плагина для требования, вы можете написать свой собственный.

### Снимок

Univer загружает документ, загружая его снимок. Каждый тип документа имеет свой собственный формат снимка, поэтому снимок должен соответствовать типам API:

1. Снимок электронной таблицы использует [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata).
2. Снимок документа использует [`IDocumentData`](/reference/types/document-data).

Функциональные плагины хранят ресурсы, такие как изображения в поле `resources`. [Пользовательская модель Plugin](/blog/custom-model) объясняет, как это работает.

<Callout type="warning" title="Осторожно">
  В то время как Univer работает, он не отражает текущее состояние документа. Для захвата текущего состояния в качестве снимка используйте метод сохранения-снимка на Facade API.
</Callout>

### Команда

Каждое изменение в данных документа в Univer проходит через команду. Команды дают Univer единственное место для наблюдения за тем, что изменилось, что является основой для отмены, переделки и совместного редактирования. Они также позволяют Univer разрешать зависимости между функциями.

Чтобы отправлять команды напрямую, см. [Как найти командный идентификатор](/blog/find-the-command-id). Когда вы меняете данные через Facade API, он подготавливает параметры команды и отправляет команду.

<Callout type="warning" title="Осторожно">
  **Не изменяйте снимок напрямую.** Изменения, внесенные таким образом, не имеют никакого эффекта и не обновляют вид или пользовательский интерфейс.Изменить данные с помощью команды или Facade API.
</Callout>

### Facade API

Офисные приложения сложны, как и архитектура Univer. Facade API обертывает сторонние плагины Univer в более простые интерфейсы, поэтому вам не нужно изучать всю архитектуру, прежде чем вы сможете выполнить задачу.

Покрытие Facade API продолжает расти. Если вы столкнулись с пробелом или что-то неясно, откройте проблему на GitHub.

Facade API - это API высокого уровня, который скрывает основные детали. Общие задачи становятся короче. Сложные задачи могут по-прежнему требовать понимания архитектуры Univer и прямых вызовов к API более низкого уровня.

## Режим пресетов и режим плагинов

Предустановка представляет собой набор плагинов, которые уже настроены. Когда оба режима получают одни и те же плагины, они выставляют одни и теже возможности. Разница заключается в том, сколько конфигурации должно обеспечить приложение. Используйте предустановку для быстрого запуска и режим плагина, когда вам нужен явный контроль над составом и загрузкой.

<Callout type="warning">
  Сохраняйте зависимость от каждой версии Univer. Если предустановленная версия уже содержит плагин, не регистрируйте его снова; в противном случае могут возникнуть конфликты плагинов или сбои функций.
</Callout>

| Режим плагинов | Режим пресетов |
| --- | --- |
| Явный импорт расширений Facade | Расширения Facade включены |
| Контроль порядка регистрации | Пресет управляет своими плагинами |
| Плагины Load по требованию | Загрузка настроенных пресетов при инициализации |
