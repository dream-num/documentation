**Univer Office SDK se compose de trois parties : Web SDK, Server SDK et AI SDK.** Ils partagent un environnement d'exécution de contenu Office pour les feuilles de calcul, les documents, les diapositives, les tableaux relationnels, les tableaux et les PDF, permettant aux utilisateurs et aux agents AI de travailler avec le même contenu dans votre produit.

**Noms des produits :** [Table relationnelle](/docs/features/relational-table) est nommé `Base` dans le SDK et les API ; [Canevas](/docs/features/canvas) est nommé `Board`.

Web SDK fournit le moteur de contenu partagé, exécutant à la fois les éditeurs de navigateur et le traitement de contenu sans tête. Server SDK et AI SDK dépendent tous deux de ce runtime sans tête. Server SDK ajoute la collaboration et le traitement des fichiers, tandis que AI SDK ajoute les opérations de contenu et la vérification pour les agents.

## Architecture et rôle des SDK [#sdk-architecture-and-responsibilities]

Web SDK fournit le moteur de contenu Office partagé avec navigateur et exécution sans tête. Server SDK fournit des services de collaboration et de fichiers, tandis que AI SDK fournit des opérations et une vérification pour les agents. Ensemble, ils permettent aux personnes et aux agents de collaborer sur le même contenu.

### Web SDK : le moteur de contenus partagés [#web-sdk-the-shared-content-engine]

Pour les développeurs qui affichent, modifient ou traitent du contenu Office dans leur application. Utilisez Facade APIs pour travailler avec du contenu, des données et UI dans des éditeurs de navigateur ou des applications Node.js sans tête.

Web SDK utilise une architecture de plug-in : les capacités du produit, l'éditeur UI et les fonctionnalités individuelles telles que la recherche et le remplacement peuvent être composées via des plug-ins. Commencez avec un préréglage ou sélectionnez les plugins de produits et de fonctionnalités dont votre application a besoin et assemblez-les avec leurs dépendances.

Vous pouvez également développer des plugins personnalisés pour des fonctionnalités spécifiques à votre entreprise sans modifier le code principal de Univer. Différentes combinaisons de plugins adaptent le même moteur de contenu à chaque environnement : les applications de navigateur chargent l'éditeur UI, tandis que les applications sans tête omettent les plugins de navigateur UI. Voir [Architecture Univer : conception de plugins](/blog/univer#plugins).

**Rendu Canvas partagé.** Le contenu Office utilise une architecture de rendu basée sur Canvas partagée, permettant aux types de contenu de réutiliser les fonctionnalités de mise en page et de dessin et de prendre en charge le contenu imbriqué. Par exemple, le texte des cellules d’une feuille de calcul réutilise la mise en page et le rendu du document pour une présentation cohérente du contenu. Voir [Architecture du moteur de rendu](/blog/rendering).

**Calcul hybride.** Le moteur de formule prend en charge un modèle de calcul hybride dans lequel le calcul frontal fonctionne avec un moteur Rust côté serveur, combinant une édition réactive avec des performances pour les charges de travail de formule volumineuses. Explorez [capacités de formule](/guides/sheets/features/core/formula) et [calcul côté serveur](/docs/features/shared/server-calculation).

[Commencez avec des feuilles de calcul](/guides/sheets/getting-started/quickstart), ou choisissez [documents](/guides/docs), [diapositives](/guides/slides), [tables relationnelles](/guides/bases), [canevas](/guides/boards) et [PDF](/guides/pdfs).

### Server SDK : connecter la collaboration et les fichiers [#server-sdk-connect-collaboration-and-files]

Pour les développeurs qui ajoutent des extensions d’édition partagée, de conversion de fichiers et de backend. Tirez parti des capacités de contenu sans tête d'Web SDK, intégrez les modules dans votre propre backend et utilisez l'identité, les autorisations et le stockage de votre application.

**Collaboration en temps réel.** OT (Operational Transformation) gère les opérations simultanées telles que les modifications de ligne/colonne et les modifications de contenu. Les modifications s'appliquent d'abord localement, puis convergent entre les réplicas tout en préservant l'intention de l'utilisateur lorsque cela est possible. Ajoutez un historique, des commentaires et Worktree si nécessaire. Voir [conception d'édition collaborative](/blog/ot) et [démarrage rapide de la collaboration](/server/collaboration/quick-start).

**Conversion de fichiers.** Convertissez entre des fichiers Office et des données de documents Univer pour connecter l'importation, la modification et l'exportation, avec ou sans collaboration. Voir [Importation et exportation de fichiers Office](/server/import-export/node) pour les API de conversion et [intégration d'échange de fichiers](/server/import-export) pour les chargements, les tâches et les téléchargements.

**Déploiement et mise à l'échelle.** Assemblez les modules dans votre propre application Node.js. Commencez sur une seule machine, séparez la conversion des fichiers à mesure que la charge augmente, puis évoluez vers plusieurs nœuds de collaboration. Voir [architecture des applications](/server/architecture) et [guide de déploiement](/server/deployment).

[Explorez Server SDK](/server).

### AI SDK : donnez aux agents un point d'entrée [#ai-sdk-give-agents-an-entry-point]

Pour les développeurs qui ajoutent des fonctionnalités Office aux agents existants, à l’automatisation et aux CLI spécifiques aux applications. S'appuient sur le moteur d'exécution sans tête Web SDK et Facade APIs pour les opérations, les calculs et l'inspection du contenu.

**Connectez votre pile d'agents existante.** Exposez les outils Office via les API TypeScript ou une application CLI assemblée à partir de SDK. Votre application possède la sélection de modèles, l'orchestration des tâches et les compétences. Les agents reçoivent les résultats d'exécution et les commentaires d'inspection, puis poursuivent leurs flux de travail.

**Créez un contenu qui reste modifiable.** Les agents lisent la structure du document, localisent des plages ou des paragraphes, puis utilisent Facade APIs pour créer et modifier des feuilles de calcul, des documents, des diapositives et d'autres contenus, y compris le calcul de formules. Les résultats conservent leur structure de contenu et leurs capacités d'édition afin que les utilisateurs puissent continuer à les affiner. Voir [opérations de contenu](/ai/content-operations).

**Inspectez, puis révisez.** Relisez les valeurs et les résultats des formules, et inspectez les captures d'écran de la page réelle. Pour les diapositives, les vérifications de mise en page identifient également le texte hors page, qui déborde et qui se chevauche. Les agents utilisent les commentaires pour réviser et vérifier à nouveau, formant une boucle lecture → modification et calcul → inspection → révision. Voir [inspection visuelle](/ai/visual-inspection).

Connectez-vous à Server SDK et utilisez [Worktree](/ai/worktree) pour isoler les modifications d'agent intermédiaire avant l'examen humain et la fusion dans l'application Web. [Explorez AI SDK](/ai).

## Flux de travail des applications [#application-workflow]

<Mermaid chart={"flowchart TB\n    Human[\"Utilisateur humain\"] --> Browser\n    Agent[\"Agent AI / Automatisation\"] --> AI[\"AI SDK · Opérations et vérification\"]\n    subgraph WebSDK[\"Web SDK · Moteur de contenu partagé\"]\n      Browser[\"Éditeurs de navigateur\"]\n      Headless[\"Headless · Modèle de contenu et Facade APIs\"]\n    end\n    Server[\"Server SDK · Collaboration, conversion et extensions\"] -->|Dépend de| Headless\n    AI -->|Dépend de| Headless\n    Browser <-->|Contenu partagé| Server\n    AI -.->|Collaboration et révision| Server\n    Server --> Storage[\"Identité, autorisations et stockage de l'application\"]\n    classDef default rx:8,ry:8,stroke-width:1px"} />

- **Éditeur intégré**: utilisez Web SDK pour afficher et modifier le contenu de votre application.
- **Application collaborative**: combinez Web SDK et Server SDK afin que les utilisateurs puissent modifier ensemble des documents partagés.
- **Collaboration humaine et agent**: les agents modifient et vérifient les brouillons via AI SDK, Server SDK gère les versions et la fusion, et l'application Web permet des interactions de visualisation, de comparaison et de révision humaine. Tous les trois contribuent au flux de travail complet de révision.

<Callout title="Socle commun et dépendances">
  Web SDK peut fonctionner indépendamment en tant qu'éditeur ou moteur de contenu sans tête. Server SDK et AI SDK dépendent tous deux des capacités sans tête de Web SDK : l'exécution sans navigateur UI nécessite toujours le runtime de contenu. Activez les services et modules dont votre application a besoin ; un flux de travail humain-agent complet combine généralement les trois SDK.
</Callout>

## Prochaines étapes [#next-steps]

Commencez avec le moteur d'exécution de contenu Web SDK, combinez-le avec Server SDK et AI SDK pour terminer votre premier flux de travail d'application, puis ajoutez des modules progressivement. Gardez les versions du package Univer associées alignées et préparez l'environnement, l'autorisation et les licences requis par les modules que vous avez choisis.
