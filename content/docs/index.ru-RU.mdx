Univer Office SDK состоит из трех частей: Web SDK, Server SDK и AI SDK. Он охватывает электронные таблицы, документы, слайды, реляционную таблицу, холсты и PDF-файлы.

Web SDK - это механизм совместного контента. Он запускает редакторы браузера, а также работает без головы для обработки контента без пользовательского интерфейса. Два других SDK основаны на этом безголовом режиме выполнения: Server SDK добавляет совместную работу и обработку файлов, а AI SDK добавляет операции с контентом и проверку результатов для агентов.

### Web SDK: механизм общего контента [#web-sdk-the-shared-content-engine]

Используйте Web SDK для отображения, редактирования или обработки содержимого Office в приложении. API-интерфейсы Facade - это интерфейс к контенту, данным и пользовательскому интерфейсу, независимо от того, работает ли код в редакторе браузера или в безголовом процессе Node.js.

Web SDK построен полностью из плагинов, включая возможности продукта, пользовательский интерфейс редактора и отдельные функции, такие как поиск и замена.Приложение может начинаться с предустановленного или выбирать нужные ему плагины продукта и функции и собирать их с помощью своих зависимостей.

Бизнес-специфические функции могут быть реализованы в пользовательских плагинах без изменения основного кода Univer. Один и тот же движок контента адаптируется к каждой среде через свой набор плагинов: приложение браузера загружает пользовательский интерфейс редактора, в то время как приложение без головы опускает эти плагины пользовательского интерфейса. См. [Архитектура Univer: дизайн плагинов](/blog/univer#plugins) .

**Общий рендеринг Canvas.** Весь контент Office визуализируется через одну и ту же архитектуру Canvas, поэтому типы контента могут повторно использовать макет и код чертежа и могут содержать вложенный контент. Текст сотовой таблицы, например, следует за макетом документа и траекторией рендеринга, что поддерживает согласованность представления. См. [Архитектура Rendering Engine](/blog/rendering).

**Гибридные вычисления.** Двигатель формулы вычисляет в интерфейсе и на серверной стороне движка Rust. Расчет Frontend сохраняет редактирование отзывчивым, в то время как движок Rust обрабатывает большие рабочие нагрузки формул. См. [Формула возможностей](/guides/sheets/features/core/formula) и [вычисление на стороне сервера](/overview/features/shared/server-calculation).

Начнем с [таблицы](/guides/sheets/getting-started/quickstart).Тот же SDK охватывает также [документы](/guides/docs), [слайды](/guides/slides), [реляционные таблицы](/guides/bases), [доски](/guides/boards) и [PDF](/guides/pdfs).

### Server SDK: соедините совместную работу и файлы [#server-sdk-connect-collaboration-and-files]

Server SDK добавляет совместное редактирование, преобразование файлов и расширения бэкэнда. Он опирается на возможности безголового контента Web SDK: модули запускаются внутри вашего бэкенда и используют собственную личность приложения, разрешения и хранилище.

**Сотрудничество в реальном времени.** OT (Operational Transformation) обрабатывает одновременные операции, такие как изменения строк или столбцов и редактирование контента. Сначала редактируется локально, а затем реплики сходятся, сохраняя при этом намерение каждого пользователя, где это возможно. История, комментарии и Worktree являются отдельными модулями, которые приложение добавляет при необходимости. См. [Совместное редактирование дизайна](/blog/ot) и [Быстрый старт сотрудничества](/server/collaboration/quick-start).

**Преобразование файлов.** Conversion перемещает контент между файлами Office и данными документов Univer и соединяет этапы импорта, редактирования и экспорта. Он работает с сотрудничеством или без него. См. [Офисные файлы импорт и экспорт](/server/import-export/node) для API преобразования и [Обмен файлами интеграция](/server/import-export) - для загрузок, задач и загрузок.

**Развертывание и масштабирование.** Модули собраны внутри вашего собственного приложения Node.js, и для запуска достаточно одной машины. По мере роста нагрузки приложение может перемещать преобразование файлов в отдельную службу, а затем масштабировать на несколько узлов совместной работы. См. [Архитектура приложений](/server/architecture) и [Руководство по развертыванию](/server/deployment).

[Обзор Server SDK](/server) описывает модули более подробно.

### AI SDK: предоставить агентам точку входа. [#ai-sdk-give-agents-an-entry-point]

AI SDK добавляет возможности Office к существующим агентам, автоматизации и прикладным CLI. Он основан на безголовом времени выполнения и API-интерфейсах Facade Web SDK для операций с контентом, расчета и проверки.

Инструменты **Подключите существующий стек агентов.** Office могут быть представлены как API TypeScript или как CLI, собранные из SDK. Выбор модели, оркестровка задач и навыки остаются в приложении. Агенты получают результаты выполнения и обратную связь проверки, а затем продолжают свой рабочий процесс.

**Создайте контент, который остается редактируемым.** Агент считывает структуру документа, находит нужный ему диапазон или абзац и использует API Facade для создания и изменения электронных таблиц, документов, слайдов и другого контента, включая вычисление формул. Результат сохраняет свою структуру контента и остается редактируемым, чтобы люди могли продолжать его дорабатывать. См. [контент-операции](/ai/content-operations).

**Проверь, потом пересмотри.** Агент считывает обратные значения и результаты формулы и проверяет скриншот фактической страницы. Для слайдов проверки макета также идентифицируют текст, который запускается со страницы, переполняется или перекрывается. Агент использует эту обратную связь для пересмотра контента и его повторной проверки, которая завершает чтение → редактирование и вычисление → проверка → пересмотр цикла. См. [визуальный осмотр](/ai/visual-inspection).

С Server SDK [Worktree](/ai/worktree) изолирует промежуточные изменения, вносимые агентом, до тех пор, пока человек не просмотрит и не сольет их в веб-приложение.Начните с [Обзор AI SDK](/ai).

- **Встроенный редактор**: Web SDK отображает и редактирует контент внутри приложения.
- **Совместное применение**: Web SDK и Server SDK позволяют пользователям редактировать общие документы.
- **Сотрудничество человека и агента**: агенты редактируют и проверяют черновики через AI SDK, Server SDK управляет версиями и слиянием, а веб-приложение обеспечивает просмотр, сравнение и человеческий обзор.Полный рабочий процесс обзора включает все три.

<Callout title="Общий фонд и зависимости">
  Web SDK работает независимо, как редактор или как движок безголового контента. Server SDK и AI SDK зависят от возможностей безголовного интерфейса Web SDK: для работы без пользовательского интерфейса браузера все еще требуется время выполнения контента. Приложение обеспечивает необходимые услуги и модули, а полный рабочий процесс человека-агента обычно объединяет все три SDK.
</Callout>
