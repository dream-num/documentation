Univer Office SDK는 3개의 부품으로 이루어져 있습니다: Web SDK, Server SDK 및 AI SDK. 그것은 스프레드 시트, 문서, 슬라이드, 관계 테이블, 캔버스 및 PDF를 포함합니다.

Web SDK는 공유 콘텐츠 엔진입니다. 브라우저 편집기를 실행하고 UI없이 콘텐츠를 처리하는 데 도움이됩니다. 다른 두 SDK는 헤드리스 런타임에 구축합니다. Server SDK은 협업 및 파일 처리를 추가하고 AI SDK가 에이전트에 대한 콘텐츠 작동 및 결과 검사를 추가합니다.

### Web SDK: 공유 콘텐츠 엔진 [#web-sdk-the-shared-content-engine]

Web SDK를 사용하여 응용 프로그램에서 디스플레이, 편집 또는 프로세스 오피스 콘텐츠를 표시합니다. Facade API는 브라우저 편집기 또는 헤드리스 Node.js 프로세스에서 코드가 실행되는지 여부, 콘텐츠, 데이터 및 UI에 인터페이스입니다.

Web SDK는 제품 기능, 편집기 UI 및 개별 기능을 포함하여 플러그인에서 완전히 구축되어 있습니다. 응용 프로그램은 사전 설정에서 시작하거나 제품 및 기능 플러그인을 선택하고 의존성으로 조립 할 수 있습니다.

Business-specific 기능은 Univer의 핵심 코드를 수정하지 않고 사용자 정의 플러그인에서 구현할 수 있습니다. 동일한 콘텐츠 엔진은 플러그인 세트를 통해 각 환경에 적응합니다. 브라우저 응용 프로그램은 편집기 UI를로드하고, 헤드리스 응용 프로그램은 UI 플러그인을 미끼는 동안. [Univer 건축술: 플러그인 디자인](/blog/univer#plugins)를 참조하십시오.

**공유 캔버스 렌더링.** 모든 오피스 콘텐츠는 동일한 캔버스 아키텍처를 통해 렌더링되므로 콘텐츠 유형은 레이아웃 및 그림 코드를 재사용하고 배열 된 콘텐츠를 유지할 수 있습니다. 스프레드 시트 셀 텍스트는 예를 들어 문서 레이아웃 및 렌더링 경로를 따라 프리젠 테이션을 일관된 유지합니다. [Rendering Engine의 건축](/blog/rendering)를 참조하십시오.

**하이브리드 컴퓨팅.** 공식 엔진은 프론트엔드 및 서버 측 Rust 엔진에서 계산합니다. 프론트엔드는 반응을 유지하면서 Rust 엔진은 큰 공식 작업 부하를 처리합니다. [관련 기능](/guides/sheets/features/core/formula) 및 [서버 측 계산](/overview/features/shared/server-calculation)를 참조하십시오.

[스프레드시트](/guides/sheets/getting-started/quickstart)로 시작. 동일한 SDK는 또한 [의논문](/guides/docs), [제품정보](/guides/slides)의 [관계 표](/guides/bases) 및 [회사연혁](/guides/boards)와 [PDF 파일](/guides/pdfs)를 포함합니다.

### Server SDK: 협업 및 파일 연결 [#server-sdk-connect-collaboration-and-files]

Server SDK는 공유된 편집, 파일 변환 및 백엔드 확장을 추가합니다. 그것은 Web SDK의 헤드리스 콘텐츠 기능을 구축합니다. 모듈은 자신의 백엔드 내부에서 실행되며 응용 프로그램의 자체 정체성, 권한 및 저장을 사용합니다.

**실시간 협업.** OT (Operational Transformation)은 연속 또는 열 변경 및 내용 편집과 같은 동시 작업을 처리합니다. 편집은 로컬로 먼저 적용되며 복제는 가능한 한 각 사용자의 의도를 보존하면서도 통합됩니다. 기록, 의견 및 Worktree는 응용 프로그램이 필요할 때 추가되는 별도의 모듈입니다. [협력 편집 디자인](/blog/ot) 및 [협력 빠른 시작](/server/collaboration/quick-start)를 참조하십시오.

**파일 변환.** 변환은 Office 파일과 Univer 문서 데이터 사이의 콘텐츠를 이동하고 수입, 편집 및 내보내기 단계를 연결합니다. 그것은 공동 작업없이 작동합니다. 변환 API 및 [파일 교환 통합](/server/import-export)를 변환하는 [Office 파일 가져 오기 및 내보내기](/server/import-export/node) 업로드, 작업 및 다운로드하십시오.

**배포 및 스케일링.** 모듈은 자신의 Node.js 응용 프로그램에 조립되며 단일 머신은 시작해야 합니다. 로드가 성장함에 따라 애플리케이션은 별도의 서비스로 파일 변환을 이동하고 여러 협업 노드로 스케일 할 수 있습니다. [신청 건축](/server/architecture)와 [설치 가이드](/server/deployment)를 참조하십시오.

[Server SDK 개요](/server)는 더 상세하게 모듈을 설명합니다.

### AI SDK: 에이전트에 진입점 제공 [#ai-sdk-give-agents-an-entry-point]

AI SDK는 기존 에이전트, 자동화 및 애플리케이션 별 CLI에 Office 기능을 추가합니다. 콘텐츠 운영, 계산 및 검사를 위해 Web SDK의 헤드리스 런타임 및 Facade API를 구축합니다.

**기존 에이전트 스택을 연결합니다.** 오피스 도구는 TypeScript API로 노출되거나 SDK에서 조립된 CLI로 노출될 수 있습니다. 모델 선택, 작업 오케스트라 조정 및 기술이 응용 프로그램에 남아 있습니다. 에이전트는 실행 결과 및 검사 피드백을 수신하고 작업 흐름을 계속합니다.

**편집할 수 있는 콘텐츠를 만듭니다.** 에이전트는 문서 구조를 읽고, 범위 또는 단락을 찾습니다, 그리고 Facade API를 사용하여 스프레드 시트, 문서, 슬라이드 및 기타 콘텐츠를 생성하고 수정합니다. 결과는 내용 구조를 유지하고 편집 할 수 있으므로 사람들은 그것을 계속 제거 할 수 있습니다. [콘텐츠 운영](/ai/content-operations)를 참조하십시오.

**검사, 그 후 부활.** 에이전트는 다시 값과 공식 결과를 읽고 실제 페이지의 스크린 샷을 검사합니다. 슬라이드의 경우 레이아웃 체크는 페이지, 오버 플로우 또는 오버랩을 실행하는 텍스트를 식별합니다. 에이전트는 콘텐츠를 수정하고 다시 확인하기 위해이 피드백을 사용하여 읽고 → 편집 및 계산 → 검사 → 루프를 완료합니다. [시각 검사](/ai/visual-inspection)를 참조하십시오.

Server SDK로, [Worktree](/ai/worktree)는 웹 애플리케이션에서 개인 리뷰 및 합병까지 에이전트가 만든 중간 변경을 격리합니다. [AI SDK 개요](/ai)를 시작하십시오.

- **임베디드 편집기**: Web SDK는 신청 안쪽에 내용을 전시하고 편집합니다.
- **협력 신청**: Web SDK와 Server SDK는 함께 공유 문서를 편집할 수 있습니다.
- **인간 및 대리인 협력**: 에이전트 편집 및 AI SDK를 통해 초안 확인, Server SDK는 버전과 합병을 관리, 웹 응용 프로그램은보기, 비교, 인간의 검토를 제공합니다. 전체 검토 워크플로는 모든 세 가지를 포함합니다.

<Callout title="공유 기초 및 종속">
  Web SDK는 독립적으로 운영되며 편집기 또는 헤드리스 콘텐츠 엔진으로 작동합니다. Server SDK 및 AI SDK 모두는 Web SDK의 헤드리스 기능에 따라 달라집니다. 브라우저 UI가 여전히 콘텐츠 실행 시간을 필요로하지 않고 실행됩니다. 응용 프로그램은 서비스와 모듈을 필요로하며, 일반 인간 시약 워크플로우는 일반적으로 모든 3 개의 SDK를 결합합니다.
</Callout>
