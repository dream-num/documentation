Univer Office SDK는 Web SDK, Server SDK, AI SDK로 구성되며 스프레드시트, 문서, 슬라이드, 관계형 테이블, 보드, PDF를 지원합니다.

**제품 이름:** [관계형 테이블](/overview/features/relational-table)는 SDK 및 API에서 `Base`로 명명되었습니다. [캔버스](/overview/features/canvas)의 이름은 `Board`입니다.

Web SDK는 브라우저 편집기와 헤드리스 콘텐츠 처리를 모두 실행하는 공유 콘텐츠 엔진을 제공합니다. Server SDK 및 AI SDK는 모두 이 헤드리스 런타임에 의존합니다. Server SDK는 협업 및 파일 처리를 추가하고, AI SDK는 에이전트를 위한 콘텐츠 작업 및 확인을 추가합니다.

### Web SDK: 공유 콘텐츠 엔진 [#web-sdk-the-shared-content-engine]

응용 프로그램에서 Office 콘텐츠를 표시, 편집 또는 처리하는 개발자용입니다. Facade APIs를 사용하여 브라우저 편집기 또는 헤드리스 Node.js 애플리케이션에서 콘텐츠, 데이터 및 UI로 작업합니다.

Web SDK는 플러그인 아키텍처를 사용합니다. 제품 기능, UI 편집기, 찾기 및 바꾸기와 같은 개별 기능을 플러그인을 통해 구성할 수 있습니다. 사전 설정으로 시작하거나 애플리케이션에 필요한 제품 및 기능 플러그인을 선택하고 종속성과 함께 조합하세요.

Univer의 핵심 코드를 수정하지 않고도 비즈니스별 기능을 위한 맞춤형 플러그인을 개발할 수도 있습니다. 다양한 플러그인 조합은 동일한 콘텐츠 엔진을 각 환경에 맞게 조정합니다. 브라우저 애플리케이션은 편집기 UI를 로드하는 반면, 헤드리스 애플리케이션은 브라우저 UI 플러그인을 생략합니다. [Univer 아키텍처: 플러그인 디자인](/blog/univer#plugins)를 참조하세요.

**공유 캔버스 렌더링.** Office 콘텐츠는 공유 캔버스 기반 렌더링 아키텍처를 사용하므로 콘텐츠 유형이 레이아웃 및 그리기 기능을 재사용하고 중첩된 콘텐츠를 지원할 수 있습니다. 예를 들어 스프레드시트 셀 텍스트는 일관된 콘텐츠 표시를 위해 문서 레이아웃과 렌더링을 재사용합니다. [렌더링 엔진의 아키텍처](/blog/rendering)를 참조하세요.

**하이브리드 계산.** 수식 엔진은 프런트엔드 계산이 서버측 Rust 엔진과 함께 작동하여 반응형 편집과 대규모 수식 워크로드에 대한 성능을 결합하는 하이브리드 계산 모델을 지원합니다. [수식 기능](/guides/sheets/features/core/formula) 및 [서버측 계산](/overview/features/shared/server-calculation)를 살펴보세요.

[스프레드시트로 시작](/guides/sheets/getting-started/quickstart) 또는 [문서](/guides/docs), [슬라이드](/guides/slides), [관계형 테이블](/guides/bases), [캔버스](/guides/boards) 및 [PDF](/guides/pdfs)를 선택합니다.

### Server SDK: 협업 및 파일 연결 [#server-sdk-connect-collaboration-and-files]

공유 편집, 파일 변환, 백엔드 확장 기능을 추가하는 개발자를 위한 제품입니다. Web SDK의 헤드리스 콘텐츠 기능을 기반으로 구축하고, 모듈을 자체 백엔드에 통합하고, 애플리케이션의 ID, 권한 및 스토리지를 사용하세요.

**실시간 협업.** OT(Operational Transformation)는 행/열 변경 및 콘텐츠 편집과 같은 동시 작업을 처리합니다. 편집 내용은 먼저 로컬에 적용된 다음 가능한 경우 사용자 의도를 유지하면서 복제본 전체에 수렴됩니다. 필요에 따라 기록, 설명 및 Worktree를 추가합니다. [공동 편집 디자인](/blog/ot) 및 [협업 빠른 시작](/server/collaboration/quick-start)를 참조하세요.

**파일 변환.** Office 파일과 Univer 문서 데이터 간에 변환하여 공동 작업 유무에 관계없이 가져오기, 편집 및 내보내기를 연결합니다. 변환 API는 [Office 파일 가져오기 및 내보내기](/server/import-export/node)를, 업로드, 작업 및 다운로드는 [파일 교환 통합](/server/import-export)를 참조하세요.

**배포 및 확장.** 자체 Node.js 애플리케이션에서 모듈을 어셈블합니다. 하나의 시스템에서 시작하여 로드가 증가함에 따라 별도의 파일 변환을 수행한 다음 여러 협업 노드로 확장합니다. [애플리케이션 아키텍처](/server/architecture) 및 [배포 가이드](/server/deployment)를 참조하세요.

[Server SDK 살펴보기](/server).

### AI SDK: 에이전트에 진입점 제공 [#ai-sdk-give-agents-an-entry-point]

기존 에이전트, 자동화, 애플리케이션별 CLI에 Office 기능을 추가하는 개발자를 위한 것입니다. 콘텐츠 작업, 계산 및 검사를 위해 Web SDK의 헤드리스 런타임과 Facade APIs를 기반으로 구축하세요.

**기존 에이전트 스택을 연결합니다.** TypeScript API 또는 SDK에서 조립된 애플리케이션 CLI를 통해 Office 도구를 노출합니다. 귀하의 애플리케이션은 모델 선택, 작업 조정 및 기술을 소유합니다. 에이전트는 실행 결과와 검사 피드백을 받은 후 워크플로를 계속합니다.

**편집 가능한 콘텐츠를 생성합니다.** 상담원은 문서 구조를 읽고, 범위 또는 단락을 찾은 다음 Facade APIs를 사용하여 스프레드시트, 문서, 슬라이드 및 수식 계산을 포함한 기타 콘텐츠를 생성 및 수정합니다. 결과는 콘텐츠 구조와 편집 기능을 유지하므로 사람들은 계속해서 결과를 수정할 수 있습니다. [콘텐츠 운영](/ai/content-operations)를 참조하세요.

**검사한 후 수정하세요.** 값과 수식 결과를 다시 읽고 실제 페이지의 스크린샷을 검사하세요. 슬라이드의 경우 레이아웃 검사를 통해 페이지 외부, 넘치고 겹치는 텍스트도 식별합니다. 에이전트는 피드백을 사용하여 다시 수정하고 확인하여 읽기 → 편집 및 계산 → 검사 → 수정 루프를 형성합니다. [육안 검사](/ai/visual-inspection)를 참조하세요.

Server SDK에 연결하고 [Worktree](/ai/worktree)를 사용하여 웹 애플리케이션에서 사람이 검토하고 병합하기 전에 중간 에이전트 변경 사항을 격리합니다. [AI SDK 살펴보기](/ai).

- **내장 편집기**: Web SDK를 사용하여 애플리케이션의 콘텐츠를 표시하고 편집합니다.
- **협업 애플리케이션**: Web SDK와 Server SDK를 결합하면 사용자가 공유 문서를 함께 편집할 수 있습니다.
- **인간과 에이전트의 협업**: 에이전트는 AI SDK를 통해 초안을 편집 및 확인하고, Server SDK는 버전 및 병합을 관리하며, 웹 애플리케이션은 보기, 비교 및 인적 검토 상호 작용을 제공합니다. 세 가지 모두 전체 검토 작업 흐름에 기여합니다.

<Callout title="공유 기반 및 종속성">
  Web SDK는 편집기 또는 헤드리스 콘텐츠 엔진으로 독립적으로 실행될 수 있습니다. Server SDK 및 AI SDK는 모두 Web SDK의 헤드리스 기능에 의존합니다. 즉, 브라우저 없이 UI를 실행하려면 여전히 콘텐츠 런타임이 필요합니다. 애플리케이션에 필요한 서비스와 모듈을 활성화합니다. 완전한 인간-에이전트 워크플로는 일반적으로 세 가지 SDK를 모두 결합합니다.
</Callout>
