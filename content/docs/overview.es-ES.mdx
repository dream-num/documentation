**Univer Office SDK consta de tres partes: Web SDK, Server SDK y AI SDK.** Comparten un tiempo de ejecución de contenido de Office para hojas de cálculo, documentos, diapositivas, tablas relacionales, tableros y archivos PDF, lo que permite que las personas y los agentes AI trabajen con el mismo contenido dentro de su producto.

**Nombres de productos:** [Tabla relacional](/docs/features/relational-table) se denomina `Base` en SDK y API; [Lienzos](/docs/features/canvas) se denomina `Board`.

Web SDK proporciona el motor de contenido compartido, que ejecuta editores de navegador y procesamiento de contenido sin cabeza. Server SDK y ​​AI SDK dependen de este tiempo de ejecución sin cabeza. Server SDK agrega colaboración y procesamiento de archivos, mientras que AI SDK agrega operaciones de contenido y verificación para agentes.

Juntos, permiten que personas y agentes colaboren en el mismo contenido.

### Web SDK: el motor de contenidos compartidos [#web-sdk-the-shared-content-engine]

Para desarrolladores que muestran, editan o procesan contenido de Office en su aplicación. Utilice Facade APIs para trabajar con contenido, datos y UI en editores de navegador o aplicaciones Node.js sin cabeza.

Web SDK utiliza una arquitectura de complemento: las capacidades del producto, el editor UI y funciones individuales como buscar y reemplazar se pueden componer a través de complementos. Comience con un ajuste preestablecido o seleccione los complementos de funciones y productos que su aplicación necesita y ensamblelos con sus dependencias.

También puede desarrollar complementos personalizados para funciones específicas de la empresa sin modificar el código principal de Univer. Diferentes combinaciones de complementos adaptan el mismo motor de contenido a cada entorno: las aplicaciones del navegador cargan el editor UI, mientras que las aplicaciones sin cabeza omiten los complementos del navegador UI. Consulte [Arquitectura Univer: diseño de complemento](/blog/univer#plugins).

**Representación de Canvas compartido.** El contenido de Office utiliza una arquitectura de representación compartida basada en Canvas, lo que permite que los tipos de contenido reutilicen capacidades de diseño y dibujo y admitan contenido anidado. Por ejemplo, el texto de las celdas de una hoja de cálculo reutiliza el diseño y la representación del documento para lograr una presentación coherente del contenido. Ver [Arquitectura del motor de renderizado](/blog/rendering).

**Cómputo híbrido.** El motor de fórmulas admite un modelo de cálculo híbrido en el que el cálculo frontal funciona con un motor Rust del lado del servidor, combinando edición responsiva con rendimiento para grandes cargas de trabajo de fórmulas. Explore [capacidades de fórmula](/guides/sheets/features/core/formula) y [cálculo del lado del servidor](/docs/features/shared/server-calculation).

[Comience con hojas de cálculo](/guides/sheets/getting-started/quickstart) o elija [documentos](/guides/docs), [diapositivas](/guides/slides), [tablas relacionales](/guides/bases), [lienzos](/guides/boards) y [PDF](/guides/pdfs).

### Server SDK: conecta colaboración y archivos [#server-sdk-connect-collaboration-and-files]

Para desarrolladores que agregan edición compartida, conversión de archivos y extensiones de backend. Aproveche las capacidades de contenido headless de Web SDK, integre los módulos en su propio backend y utilice la identidad, los permisos y el almacenamiento de su aplicación.

**Colaboración en tiempo real.** OT (Transformación operativa) maneja operaciones simultáneas, como cambios de filas/columnas y ediciones de contenido. Las ediciones se aplican primero localmente y luego convergen entre las réplicas, preservando al mismo tiempo la intención del usuario siempre que sea posible. Agregue historial, comentarios y Worktree según sea necesario. Consulte [diseño de edición colaborativa](/blog/ot) y [inicio rápido de colaboración](/server/collaboration/quick-start).

**Conversión de archivos.** Convierta entre archivos de Office y datos de documentos Univer para conectar la importación, edición y exportación, con o sin colaboración. Consulte [Importación y exportación de archivos de Office](/server/import-export/node) para las API de conversión y [integración de intercambio de archivos](/server/import-export) para cargas, tareas y descargas.

**Implementación y escalado.** Ensamble los módulos en su propia aplicación Node.js. Comience en una máquina, separe la conversión de archivos a medida que aumenta la carga y luego escale a múltiples nodos de colaboración. Consulte [arquitectura de aplicaciones](/server/architecture) y [guía de implementación](/server/deployment).

[Explorar Server SDK](/server).

### AI SDK: proporcione a los agentes un punto de entrada [#ai-sdk-give-agents-an-entry-point]

Para desarrolladores que agregan capacidades de Office a agentes existentes, automatización y CLI específicas de aplicaciones. Utilice el tiempo de ejecución sin cabeza de Web SDK y Facade APIs para operaciones, cálculos e inspección de contenido.

**Conecte su pila de agentes existente.** Exponga las herramientas de Office a través de las API TypeScript o una aplicación CLI ensamblada a partir de SDK. Su aplicación posee selección de modelos, orquestación de tareas y habilidades. Los agentes reciben resultados de ejecución y comentarios de inspección y luego continúan con sus flujos de trabajo.

**Cree contenido que siga siendo editable.** Los agentes leen la estructura del documento, ubican rangos o párrafos y luego usan Facade APIs para crear y modificar hojas de cálculo, documentos, diapositivas y otro contenido, incluido el cálculo de fórmulas. Los resultados conservan su estructura de contenido y capacidades de edición para que las personas puedan seguir perfeccionándolos. Ver [operaciones de contenido](/ai/content-operations).

**Inspeccione y luego revise.** Vuelva a leer los valores y los resultados de las fórmulas, e inspeccione las capturas de pantalla de la página real. Para las diapositivas, las comprobaciones de diseño también identifican texto fuera de página, desbordado y superpuesto. Los agentes utilizan la retroalimentación para revisar y verificar nuevamente, formando un ciclo de lectura → edición y cálculo → inspección → revisión. Consulte [inspección visual](/ai/visual-inspection).

Conéctese a Server SDK y use [Worktree](/ai/worktree) para aislar los cambios del agente intermedio antes de la revisión humana y la fusión en la aplicación web. [Explorar AI SDK](/ai).

## Flujo de trabajo de la aplicación [#application-workflow]

- **editor integrado**: utilice Web SDK para mostrar y editar contenido en su aplicación.
- **Aplicación colaborativa**: combine Web SDK y Server SDK para que los usuarios puedan editar documentos compartidos juntos.
- **Colaboración humana y de agentes**: los agentes editan y verifican borradores a través de AI SDK, Server SDK administra las versiones y las fusiones, y la aplicación web proporciona interacciones de visualización, comparación y revisión humana. Los tres contribuyen al flujo de trabajo de revisión completo.

<Callout title="Base compartida y dependencias">
  Web SDK puede ejecutarse de forma independiente como editor o motor de contenido sin cabeza. Server SDK y AI SDK dependen de las capacidades sin cabeza de Web SDK: ejecutar UI sin navegador aún requiere el tiempo de ejecución del contenido. Habilite los servicios y módulos que su aplicación necesita; un flujo de trabajo completo entre humanos y agentes normalmente combina los tres SDK.
</Callout>
