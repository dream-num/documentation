Univer Office SDK consta de tres partes: Web SDK, Server SDK y AI SDK. Cubre hojas de cálculo, documentos, diapositivas, Tabla de Relación, Canvasos y PDFs.

Web SDK es el motor de contenido compartido. Corre los editores del navegador y también funciona sin cabeza para procesar contenido sin interfaz de usuario. Los otros dos SDKs se basan en ese tiempo de ejecución sin cabeza: Server SDK añade colaboración y procesamiento de archivos, y AI SDK agrega operaciones de contenido e inspección de resultados para los agentes.

### Web SDK: el motor de contenidos compartidos [#web-sdk-the-shared-content-engine]

Utilice Web SDK para mostrar, editar o procesar contenido de Office en una aplicación. Las API de Facade son la interfaz a contenido, datos e interfaz de usuario, ya sea que el código se ejecuta en un editor de navegadores o en un proceso Node.js sin cabeza.

Web SDK se construye completamente desde plugins, incluyendo capacidades de producto, editor UI, y características individuales como encontrar y reemplazar. Una aplicación puede comenzar desde un preset, o seleccionar el producto y los plugins de características que necesita y ensamblarlos con sus dependencias.

Las características específicas de negocio se pueden implementar en plugins personalizados sin modificar Univer's core code. El mismo motor de contenido se adapta a cada entorno a través de su conjunto de plugins: una aplicación del navegador carga al editor UI, mientras que una aplicación sin cabeza omite esos plugins UI. Ver [Univer Arquitectura: diseño plugin](/blog/univer#plugins).

**Representación de lienzos compartidos.** Todo el contenido de Office se hace a través de la misma arquitectura de Canvas, por lo que los tipos de contenido pueden reutilizar el código de diseño y dibujo y pueden contener contenido anidado. El texto de la celda de hoja de cálculo, por ejemplo, sigue el diseño de documentos y el camino de renderización, que mantiene la presentación consistente. [Arquitectura del motor de rendering](/blog/rendering).

**Computación híbrida.** El motor de fórmulas calcula en el frontend y en un motor Rust lado del servidor. El cálculo Frontend sigue editando, mientras que el motor Rust maneja grandes cargas de trabajo de fórmula. Ver [Capacidades de fórmula](/guides/sheets/features/core/formula) y [cálculo lado del servidor](/overview/features/shared/server-calculation).

Empieza con [hojas de cálculo](/guides/sheets/getting-started/quickstart). El mismo SDK también cubre [documentos](/guides/docs), [diapositivas](/guides/slides), [cuadros relacionales](/guides/bases), [tableros](/guides/boards), y [PDF](/guides/pdfs).

### Server SDK: conecta colaboración y archivos [#server-sdk-connect-collaboration-and-files]

Server SDK añade ediciones compartidas, conversión de archivos y extensiones de backend. Se basa en las capacidades de contenido sin cabeza de Web SDK: los módulos funcionan dentro de su propio backend y usan la propia identidad, permisos y almacenamiento de la aplicación.

**Colaboración en tiempo real.** OT (Transformación Operacional) maneja operaciones concurrentes tales como cambios de fila o columna y ediciones de contenido. Una edición se aplica localmente primero, y las réplicas entonces convergen preservando la intención de cada usuario cuando sea posible. Historia, comentarios y Worktree son módulos separados que una aplicación añade cuando sea necesario. Véase [diseño de edición colaborativa](/blog/ot) y [colaboración rápido](/server/collaboration/quick-start).

**Conversión de archivos.** Conversion mueve contenido entre archivos de Office y datos de documentos Univer y conecta los pasos de importación, edición y exportación. Funciona con o sin colaboración. Ver [Importación y exportación de archivos de oficinas](/server/import-export/node) para las API de conversión y [integración del intercambio de archivos](/server/import-export) de cargas, tareas y descargas.

**Despliegue y escalado.** Los módulos se montan dentro de su propia aplicación Node.js y una sola máquina es suficiente para comenzar. A medida que crece la carga, la aplicación puede mover la conversión de archivos a un servicio separado y luego escala a múltiples nodos de colaboración. Ver [aplicación arquitectura](/server/architecture) y [Guía para el despliegue](/server/deployment).

El [Vista general de Server SDK](/server) describe los módulos con más detalle.

### AI SDK: proporcione a los agentes un punto de entrada [#ai-sdk-give-agents-an-entry-point]

AI SDK añade capacidades de oficina a los agentes existentes, automatización y CLIs específicos para aplicaciones. Se basa en el tiempo de ejecución sin cabeza y API de Facade de Web SDK para operaciones de contenido, cálculo e inspección.

Las herramientas de **Conecta tu pila de agente existente.** Office pueden ser expuestas como API TypeScript o como CLI montado desde el SDK. Selección de modelos, orquestación de tareas y habilidades permanecen en la aplicación. Los agentes reciben resultados de ejecución y retroalimentación de inspección, luego continúan su flujo de trabajo.

**Cree contenido que se mantenga editable.** Un agente lee la estructura de documentos, localiza el rango o párrafo que necesita y utiliza las API de Facade para crear y modificar hojas de cálculo, documentos, diapositivas y otros contenidos, incluyendo el cálculo de fórmulas. El resultado mantiene su estructura de contenido y sigue siendo editable, para que la gente pueda seguir refinando. [operaciones de](/ai/content-operations).

**Inspeccione, luego revise.** El agente lee los valores y los resultados de la fórmula e inspecciona una captura de pantalla de la página real. Para diapositivas, cheques de diseño también identifican el texto que se ejecuta fuera de la página, desbordamientos o superposiciones. El agente utiliza esta retroalimentación para revisar el contenido y verificarlo de nuevo, que completa la lectura → editar y calcular → inspeccionar el bucle. Ver [inspección visual](/ai/visual-inspection).

Con Server SDK, [Worktree](/ai/worktree) aísla los cambios intermedios realizados por un agente hasta que una persona revise y se fusione con la aplicación Web. Comience con el [Vista general de AI SDK](/ai).

## Flujo de trabajo de la aplicación [#application-workflow]

<Mermaid chart={"flowchart TB\n    Human[\"Usuario humano\"] --> Browser\n    Agent[\"Agente AI / Automatización\"] --> AI[\"AI SDK · Operaciones y verificación\"]\n    subgraph WebSDK[\"Web SDK · Motor de contenido compartido\"]\n      Browser[\"Editores del navegador\"]\n      Headless[\"Headless · Modelo de contenido y Facade APIs\"]\n    end\n    Server[\"Server SDK · Colaboración, conversión y extensiones\"] -->|Depende de| Headless\n    AI -->|Depende de| Headless\n    Browser <-->|Contenido compartido| Server\n    AI -.->|Colaboración y revisión.| Server\n    Server --> Storage[\"Identidad, permisos y almacenamiento de la aplicación\"]\n    classDef default rx:8,ry:8,stroke-width:1px"} />

- **Editor adjunto**: Web SDK muestra y edita contenido dentro de una aplicación.
- **Aplicación colaborativa**: Web SDK y Server SDK juntos permiten editar documentos compartidos.
- **Colaboración humana y agente**: los agentes editan y verifican los borradores a través de AI SDK, Server SDK gestiona versiones y fusiones, y la aplicación Web proporciona visualización, comparación y revisión humana. El flujo de trabajo de revisión completo implica los tres.

<Callout title="Fundamentos y dependencias compartidos">
  Web SDK funciona independientemente, como editor o como motor de contenido sin cabeza. Server SDK y AI SDK dependen de las capacidades sin cabeza de Web SDK: correr sin un navegador UI todavía requiere el tiempo de ejecución de contenidos. Una aplicación permite los servicios y módulos que necesita, y un flujo de trabajo humano-agente completo normalmente combina los tres SDKs.
</Callout>

## Próximos pasos [#next-steps]

Comience con el tiempo de ejecución de contenidos Web SDK. Server SDK y AI SDK completan el primer flujo de trabajo de aplicaciones, y se pueden añadir módulos adicionales según sea necesario. Mantenga las versiones relacionadas Univer paquetes alineados, y prepare el medio ambiente, autorización y licencias que los módulos elegidos requieren.

[Ejemplos](/overview/examples) recopila aplicaciones de código abierto, integraciones de agentes, demos y repositorios. También puede probar los productos de Office en el [escaparate en línea](https://office.univer.ai).
