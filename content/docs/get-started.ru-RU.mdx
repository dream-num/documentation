На этой странице представлены три рабочих примера: электронная таблица, связанная с входами страниц, настройка совместной работы с документами от двух человек и CLI, который может работать агент. Выберите один пример, дайте его вашему агенту кодирования, а затем выполните шаги интеграции и развертывания.

## Выберите первое приложение

Office SDK охватывает листы, документы, слайды, реляционные таблицы, холсты и PDF-файлы. Определите путь интеграции, который соответствует вашей цели приложения:

| Ваша цель | С чего начать | Первый критерий успеха |
| --- | --- | --- |
| Встроить Office-редактор | [Установка Web SDK](/guides/sheets/getting-started/installation) | Создать содержимое, изменить, сохранить и снова открыть его. |
| Связать содержимое с бизнес-интерфейсом | [Facade API](/guides/sheets/getting-started/facade) | Свяжите входные данные страницы и ячейки в обоих направлениях и покажите реальные результаты расчета. |
| Добавить совместное редактирование | [Быстрый старт Server SDK](/server/collaboration/quick-start) | Два независимых сеанса редактируют одно содержимое и получают изменения друг друга. |
| Импортировать, обрабатывать и экспортировать Office-файлы | [Конвертация файлов](/server/import-export/node) | Импортировать реальный файл, изменить, экспортировать и проверить результат. |
| Дать агенту или CLI работать с содержимым | [Операции AI SDK](/ai/content-operations) | Загрузить содержимое, проверить структуру, изменить и проверить фиксацию или вывод. |
| Создать пространство для людей и агентов | [Worktree и рецензирование](/ai/worktree) | Держите изменения агента в изолированном черновике, чтобы человек мог сравнить, рассмотреть и объединить их. |

[Особенности](/overview/features) перечисляет, что поддерживает каждый продукт; в трех примерах ниже представлен один полный рабочий процесс от начала до конца.

## Начните с агентом

Дайте своему агенту требования и ссылку на индекс документации [llms.txt](/llms.txt). Вам не нужно копировать всю документацию SDK в подсказку. Начните с шаблона многоразового использования ниже или вставьте один из трех полных примеров.

### Шаблон запроса

Замените `<…>` своими требованиями. Опишите один видимый результат, прежде чем планировать целый офисный пакет.

```text
Создай локально запускаемое <название приложения> с Univer Office SDK.
Сначала прочитай https://docs.univer.ai/ru-RU/llms.txt и полные примеры по теме.
Используй одну версию всех пакетов SDK.

Начальное содержимое: <немного готовых к редактированию данных или текста>.
Основной эффект: <одно действие пользователя и сразу видимый результат>.
Критерии приёмки: <два-три конкретных результата для проверки действиями>.

Реализуй только этот сценарий с родным редактором Univer и настоящим SDK.
Запусти приложение, проверь его в браузере и дай ссылку на предпросмотр.
Укажи, какие обязательные настройки отсутствуют, если они нужны.
```

### Пример 1: связь таблицы с интерфейсом

Свяжите поле количества с ячейкой в обоих направлениях и выведите на странице итог, рассчитанный формулой.

```text
Создай локальную одностраничную форму расчёта стоимости с Univer Office SDK.
Прочитай https://docs.univer.ai/ru-RU/llms.txt и полные примеры по теме.
Используй одну версию всех пакетов SDK.

Встрой редактируемую таблицу с базовым пресетом Sheets.
Подготовь 2 монитора по 1200, 5 клавиатур по 300 и 3 гарнитуры по 200.
Суммы строк и итог рассчитай формулами таблицы.

Рядом размести поле количества мониторов и карточку общей суммы.
Свяжи поле с ячейкой в обе стороны. Карточка читает настоящий результат формулы;
не рассчитывай сумму повторно в коде страницы. Добавь сохранение в браузере
и восстановление при обновлении страницы.

Проверь: начальная сумма 4500, при количестве 3 — 5700; изменение ячейки
обновляет поле и карточку; сохранение и обновление восстанавливают изменения.
Реализуй только эти функции, проверь работающее приложение
и дай ссылку на предпросмотр.
```

**Попробуй:** Изменить количество монитора с 2 до 3, а общее идет с 4500 до 5700. Редактирование листа также напрямую обновляет страницу. После сохранения и обновления данные восстанавливаются. Продолжайте с [Установка Web SDK](/guides/sheets/getting-started/installation) и [Фасад APIs](/guides/sheets/getting-started/facade).

### Пример 2: совместное редактирование документа

Откройте две независимые сессии по одному и тому же документу и проверьте, что правки появляются с обеих сторон.

```text
Создай локальное демо совместного редактирования для двух человек с Univer Office SDK.
Прочитай https://docs.univer.ai/ru-RU/llms.txt и актуальные примеры из
https://github.com/dream-num/univer-collaboration-examples.
Версии SDK на клиенте и сервере должны совпадать.

Размести рядом родные редакторы современных документов для Alice и Bob.
Используй независимые среды и онлайн-сеансы с настоящим сервисом совместной работы
Server SDK. По официальному примеру явно загрузи один документ, созданный сервером.
Добавь несколько коротких предложений.

Ввод слева появляется справа и наоборот через протокол совместной работы SDK.
Используй двух фиксированных пользователей, хранение в памяти и один локальный сервис
для клиента и сервера. Не добавляй вход, управление файлами или ИИ-чат.
Читай Pro License из окружения; без неё сохрани стандартное поведение и сообщения SDK.

Проверь совпадение текста после ввода с обеих сторон, фиксацию изменений сервером
и восстановление после обновления страницы. Объясни сброс памяти при перезапуске сервиса.
Реализуй только эти функции, проверь работающее приложение
и дай ссылку на предпросмотр.
```

**Попробуй:** Введите предложение слева, затем продолжайте вводить справа. Обе стороны получают обновления. Обновите страницу, и текст останется. Эта демо-версия хранит все данные в памяти, поэтому сервисный перезапуск очищает ее; подключите постоянную базу данных перед развертыванием. Продолжайте с [Сотрудничество Server SDK быстрое](/server/collaboration/quick-start).

### Пример 3: создайте собственный you-cli

Создайте свой собственный инструментарий Office и предоставьте его агенту, которого вы уже используете. Инструментарий должен охватывать лист, док, слайд, реляционный стол и холсты, но начните с одного документа, чтобы попробовать рабочий процесс «генерировать → предварительный просмотр → пересмотреть через разговор».

```text
Создай локальный для проекта you-cli и Web-предпросмотр с Univer Office SDK.
Прочитай https://docs.univer.ai/ru-RU/llms.txt и полные примеры работы с содержимым:
https://github.com/dream-num/univer-cli-examples.
Согласуй версии frontend, сервера и AI SDK; сверяй API с установленными типами.

Поддержи Sheet, Doc, Slide, Relational Table, Canvases; начни с Doc.
Добавь ./you-cli create <type> --name <name>, inspect --unit <id>,
execute --unit <id> --file <path>, open --unit <id> и --help.
Оставь инструмент в проекте и дай текущему агенту инструкции или Skill для чтения.
Возвращай JSON с соответствующими unitId, типом, результатом фиксации и URL.

CLI и Web работают с одним настоящим совместным документом и открытым родным редактором.
Дождись подтверждения записи, прочитай результат и сохраняй содержимое и каталог постоянно.
open возвращает URL; агент открывает его в панели предпросмотра, если среда это поддерживает.
Язык понимает текущий агент. Лицензии читай из окружения, сохраняя необходимые сообщения.

Проверь в диалоге: создать недельный отчёт и открыть предпросмотр;
добавить риск и ответственного в тот же unitId с обновлением открытого предпросмотра.
После обновления страницы и перезапуска данные должны восстанавливаться. Проверь это,
дай ссылку и инструкции. Запускай только сервис этого примера.
```

#### Использование через диалог

После того, как инструмент существует и агент прочитал инструкции по проекту, введите следующее в том же разговоре:

```text
Создай через you-cli недельный отчёт с прогрессом, рисками и планами.
Открой его Web-предпросмотр.
```

После того, как вы просмотрели результат, продолжайте:

```text
Добавь в тот же отчёт риск задержки поставки и назначь ответственной Alice.
Обнови уже открытый предпросмотр.
```

Агент повторно использует `unitId` того же документа.Если хост предоставляет панель предварительного просмотра, страница появляется рядом с разговором; другие среды используют обратную ссылку браузера.

#### Справочник команд you-cli

Ниже приведены проектно-локальные команды, которые указывает подсказка. Замените `UNIT_ID` на `unitId`, который возвращает `create`. Агент пишет `edit.js` с помощью API Facade.

| Действие | Команда | Результат |
| --- | --- | --- |
| Создать | `./you-cli create doc --name "Недельный отчёт"` | Создаёт документ и возвращает `unitId`; другие типы: `sheet`, `slide`, `base`, `board`. |
| Проверить | `./you-cli inspect --unit UNIT_ID` | Прочитайте реальный контент и текущий обзор. |
| Изменить | `./you-cli execute --unit UNIT_ID --file edit.js` | Выполните изменения, дождитесь совершения и верните результат. |
| Показать | `./you-cli open --unit UNIT_ID` | Возвращает Web-URL того же документа, который открывает агент. |

`./you-cli --help` печатает полный интерфейс. Для API, стоящих за этими командами, см. [Содержание AI SDK](/ai/content-operations) и полный [Примеры CLI SDK](/overview/examples/cli-sdk).

## Подключите первый сценарий к приложению

Web SDK обеспечивает совместное время выполнения контента. Добавить Server SDK, когда несколько человек должны редактировать вместе, и AI SDK когда агент должен управлять контентом. См. [Обзор Office SDK](/overview) для роли каждого пакета.

| Шаг | Что подключить в приложении | Подробнее |
| --- | --- | --- |
| Встроить редактор | Соберите предустановленный набор, подключите деловые взаимодействия через API Facade, сохраните снимки и удалите экземпляры. | [Интеграция Web SDK](/guides/sheets/getting-started/installation) |
| Подключить сервер | Повторное использование существующих идентификаторов и разрешений, настройка базы данных для общих документов и добавление импорта и экспорта файлов по мере необходимости. | [Совместная работа](/server/collaboration/quick-start), [конвертация](/server/import-export/node) |
| Подключить агента | Экспонировать операции с контентом, вычисления и проверки в качестве инструментов или CLI; добавить Worktree, когда требуется обзор. | [Операции AI SDK](/ai/content-operations), [Worktree](/ai/worktree) |

## Архитектура приложения

Ваше приложение и агент, которым вы уже управляете, могут работать на одном и том же контенте Office. Интерфейс обрабатывает взаимодействие, агент вызывает инструменты, а ваш бэкэнд сохраняет право собственности на личность, разрешения и хранилище.

**Синие узлы поставляются и управляются вами:** ваш интерфейс, ваш существующий агент, бизнес-API с идентификатором и разрешениями, база данных и хранилище файлов. Узлы, помеченные SDK, - это возможности Univer, которые вы интегрируете в приложение.

Если вы встраиваете только редактор, достаточно локальных снимков; для совместного редактирования требуется бэкэнд. Сохраните модель и оркестровку, которые уже использует ваш агент, позвольте AI SDK обрабатывать операции с контентом и добавьте Worktree, когда вам нужны отдельные изменения, сравнение и обзор.

## Сборка и развёртывание на примере Workspace

[Рабочее пространство Univer](https://github.com/dream-num/univer-workspace) объединяет все три SDK в полном рабочем пространстве офиса. Запустите следующие команды из корня репозитория Workspace и следуйте его [ЧИТАТЬ](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md) для предварительных условий.

1. **Развивайте локально.** Установите зависимости, запустите `pnpm workspace:dev:server` и `pnpm workspace:dev:web` в двух отдельных терминалах и откройте `http://127.0.0.1:5173`. Прокси-сервер веб-разработки API и запросы WebSocket на бэкэнд.
2. **Сборка и запуск.** Соберите только приложение Workspace и запустите production-вход:

```bash
pnpm --filter @univerjs/univer-workspace build
pnpm workspace:start
```

Сборка размещает веб-активы в `dist/public` и серверный код в `dist/server`; один процесс Node.js обслуживает как статические страницы, так и API.

3. **Подготовьте развертывание.** Настройка лицензий, идентификационных данных и каталогов данных. Сохраняйте данные о продукте, данные о совместной работе и загруженные активы, затем перезапустите сервис и подтвердите, что данные восстановлены. См. [Развертывание Docker](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) и [архитектура](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/docs/architecture.md).

Когда одного процесса уже недостаточно, [Руководство по развертыванию Server SDK](/server/deployment) объясняет, как разделить услуги.
