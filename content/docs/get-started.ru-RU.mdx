В руководстве разобраны три примера: связь таблицы с интерфейсом, совместное редактирование документа и CLI для агентов. Выберите пример, передайте его промпт агенту для программирования и выполните шаги по интеграции и развёртыванию.

## Выберите первое приложение

Office SDK поддерживает Sheets, Docs, Slides, Relational Tables, Canvases и PDF. Выберите путь интеграции для своей задачи.

| Ваша цель | С чего начать | Первый критерий успеха |
| --- | --- | --- |
| Встроить Office-редактор | [Установка Web SDK](/guides/sheets/getting-started/installation) | Создать содержимое, изменить, сохранить и снова открыть его. |
| Связать содержимое с бизнес-интерфейсом | [Facade API](/guides/sheets/getting-started/facade) | Синхронизировать поля и ячейки в обе стороны и показывать реальные результаты вычислений. |
| Добавить совместное редактирование | [Быстрый старт Server SDK](/server/collaboration/quick-start) | Два независимых сеанса редактируют одно содержимое и получают изменения друг друга. |
| Импортировать, обрабатывать и экспортировать Office-файлы | [Конвертация файлов](/server/import-export/node) | Импортировать реальный файл, изменить, экспортировать и проверить результат. |
| Дать агенту или CLI работать с содержимым | [Операции AI SDK](/ai/content-operations) | Загрузить содержимое, проверить структуру, изменить и проверить фиксацию или вывод. |
| Создать пространство для людей и агентов | [Worktree и рецензирование](/ai/worktree) | Оставлять изменения агента в отдельном черновике для сравнения, проверки и слияния человеком. |

Эти возможности можно сочетать. Поддержка по продуктам указана в [списке функций](/overview/features), а три примера ниже помогают сначала попробовать один полный сценарий.

## Начните с агентом

Передайте агенту для программирования требования и ссылку на индекс документации [llms.txt](/llms.txt). Копировать всю документацию SDK не нужно. Используйте шаблон или один из трёх готовых примеров ниже.

### Шаблон запроса

Замените `<…>` своими требованиями. Сначала опишите один видимый результат, а не проектируйте весь офисный пакет.

```text
Создай локально запускаемое <название приложения> с Univer Office SDK.
Сначала прочитай https://docs.univer.ai/ru-RU/llms.txt и полные примеры по теме.
Используй одну версию всех пакетов SDK.

Начальное содержимое: <немного готовых к редактированию данных или текста>.
Основной эффект: <одно действие пользователя и сразу видимый результат>.
Критерии приёмки: <два-три конкретных результата для проверки действиями>.

Реализуй только этот сценарий с родным редактором Univer и настоящим SDK.
Запусти приложение, проверь его в браузере и дай ссылку на предпросмотр.
Укажи, какие обязательные настройки отсутствуют, если они нужны.
```

### Пример 1: связь таблицы с интерфейсом

Свяжите поле количества с ячейкой в обоих направлениях и выведите на странице итог, рассчитанный формулой.

```text
Создай локальную одностраничную форму расчёта стоимости с Univer Office SDK.
Прочитай https://docs.univer.ai/ru-RU/llms.txt и полные примеры по теме.
Используй одну версию всех пакетов SDK.

Встрой редактируемую таблицу с базовым пресетом Sheets.
Подготовь 2 монитора по 1200, 5 клавиатур по 300 и 3 гарнитуры по 200.
Суммы строк и итог рассчитай формулами таблицы.

Рядом размести поле количества мониторов и карточку общей суммы.
Свяжи поле с ячейкой в обе стороны. Карточка читает настоящий результат формулы;
не рассчитывай сумму повторно в коде страницы. Добавь сохранение в браузере
и восстановление при обновлении страницы.

Проверь: начальная сумма 4500, при количестве 3 — 5700; изменение ячейки
обновляет поле и карточку; сохранение и обновление восстанавливают изменения.
Реализуй только эти функции, проверь работающее приложение
и дай ссылку на предпросмотр.
```

**Попробуйте:** Измените количество мониторов с 2 на 3: итог должен измениться с 4500 на 5700. Затем измените ячейку напрямую и проверьте обновление страницы приложения. Сохраните и обновите её для проверки восстановления. Далее см. [установку Web SDK](/guides/sheets/getting-started/installation) и [Facade API](/guides/sheets/getting-started/facade).

### Пример 2: совместное редактирование документа

Откройте один документ в двух независимых сеансах и проверьте синхронизацию изменений в обоих направлениях.

```text
Создай локальное демо совместного редактирования для двух человек с Univer Office SDK.
Прочитай https://docs.univer.ai/ru-RU/llms.txt и актуальные примеры из
https://github.com/dream-num/univer-collaboration-examples.
Версии SDK на клиенте и сервере должны совпадать.

Размести рядом родные редакторы современных документов для Alice и Bob.
Используй независимые среды и онлайн-сеансы с настоящим сервисом совместной работы
Server SDK. По официальному примеру явно загрузи один документ, созданный сервером.
Добавь несколько коротких предложений.

Ввод слева появляется справа и наоборот через протокол совместной работы SDK.
Используй двух фиксированных пользователей, хранение в памяти и один локальный сервис
для клиента и сервера. Не добавляй вход, управление файлами или ИИ-чат.
Читай Pro License из окружения; без неё сохрани стандартное поведение и сообщения SDK.

Проверь совпадение текста после ввода с обеих сторон, фиксацию изменений сервером
и восстановление после обновления страницы. Объясни сброс памяти при перезапуске сервиса.
Реализуй только эти функции, проверь работающее приложение
и дай ссылку на предпросмотр.
```

**Попробуйте:** Введите предложение слева, затем продолжите справа. Проверьте обмен в обе стороны и сохранность текста после обновления страницы. Данные демо хранятся в памяти и сбрасываются при перезапуске сервиса; для развёртывания подключите постоянную базу. См. [быстрый старт совместной работы Server SDK](/server/collaboration/quick-start).

### Пример 3: создайте собственный you-cli

Дайте текущему агенту собственный Office-инструмент. Поддерживаются Sheet, Doc, Slide, Relational Table и Canvases. Начните с Doc: генерация, предпросмотр, затем правки через диалог.

```text
Создай локальный для проекта you-cli и Web-предпросмотр с Univer Office SDK.
Прочитай https://docs.univer.ai/ru-RU/llms.txt и полные примеры работы с содержимым:
https://github.com/dream-num/univer-cli-examples.
Согласуй версии frontend, сервера и AI SDK; сверяй API с установленными типами.

Поддержи Sheet, Doc, Slide, Relational Table, Canvases; начни с Doc.
Добавь ./you-cli create <type> --name <name>, inspect --unit <id>,
execute --unit <id> --file <path>, open --unit <id> и --help.
Оставь инструмент в проекте и дай текущему агенту инструкции или Skill для чтения.
Возвращай JSON с соответствующими unitId, типом, результатом фиксации и URL.

CLI и Web работают с одним настоящим совместным документом и открытым родным редактором.
Дождись подтверждения записи, прочитай результат и сохраняй содержимое и каталог постоянно.
open возвращает URL; агент открывает его в панели предпросмотра, если среда это поддерживает.
Язык понимает текущий агент. Лицензии читай из окружения, сохраняя необходимые сообщения.

Проверь в диалоге: создать недельный отчёт и открыть предпросмотр;
добавить риск и ответственного в тот же unitId с обновлением открытого предпросмотра.
После обновления страницы и перезапуска данные должны восстанавливаться. Проверь это,
дай ссылку и инструкции. Запускай только сервис этого примера.
```

#### Использование через диалог

Передайте запрос выше агенту для программирования. Когда он создаст инструмент и прочитает инструкции проекта, продолжите в том же диалоге:

```text
Создай через you-cli недельный отчёт с прогрессом, рисками и планами.
Открой его Web-предпросмотр.
```

Посмотрев результат, продолжите:

```text
Добавь в тот же отчёт риск задержки поставки и назначь ответственной Alice.
Обнови уже открытый предпросмотр.
```

Агент повторно использует `unitId` документа. При поддержке панель покажет результат рядом с диалогом; в других средах используется возвращённая ссылка для браузера.

#### Справочник команд you-cli

Эти локальные команды задаются запросом выше. Замените `UNIT_ID` на `unitId` из результата `create`. Агент пишет `edit.js` с помощью Facade API.

| Действие | Команда | Результат |
| --- | --- | --- |
| Создать | `./you-cli create doc --name "Недельный отчёт"` | Создаёт документ и возвращает `unitId`; другие типы: `sheet`, `slide`, `base`, `board`. |
| Проверить | `./you-cli inspect --unit UNIT_ID` | Читает настоящее содержимое и текущую ревизию. |
| Изменить | `./you-cli execute --unit UNIT_ID --file edit.js` | Выполняет изменения, ждёт фиксации и возвращает результат. |
| Показать | `./you-cli open --unit UNIT_ID` | Возвращает Web-URL того же документа, который открывает агент. |

Также используйте `./you-cli --help`. См. [операции AI SDK](/ai/content-operations) и полные [CLI SDK Examples](/overview/examples/cli-sdk).

## Подключите первый сценарий к приложению

Web SDK предоставляет общую среду работы с содержимым. Подключайте Server SDK и AI SDK для совместного редактирования и операций агента. Их роли описаны в [обзоре Office SDK](/overview).

| Шаг | Что подключить в приложении | Подробнее |
| --- | --- | --- |
| Встроить редактор | Разместить пресет, связать действия через Facade API, сохранять снимки и освобождать экземпляры. | [Интеграция Web SDK](/guides/sheets/getting-started/installation) |
| Подключить сервер | Использовать существующих пользователей и права, настроить базу общих документов, при необходимости добавить импорт и экспорт. | [Совместная работа](/server/collaboration/quick-start), [конвертация](/server/import-export/node) |
| Подключить агента | Предоставить чтение, запись, вычисления и проверку через инструменты или CLI; добавить Worktree для рецензирования. | [Операции AI SDK](/ai/content-operations), [Worktree](/ai/worktree) |

## Архитектура приложения

Ваше приложение и существующий агент могут работать с общим Office-содержимым. Интерфейс отвечает за взаимодействие, агент вызывает инструменты, а бизнес-сервис управляет пользователями, правами и хранением.

**Синие узлы предоставляете и обслуживаете вы:** интерфейс, существующий агент, бизнес-API с пользователями и правами, база данных и файловое хранилище. Остальные узлы с отметкой SDK — встроенные возможности Univer.

## Сборка и развёртывание на примере Workspace

[Univer Workspace](https://github.com/dream-num/univer-workspace) объединяет три SDK в полноценное офисное пространство. Команды выполняются из корня его репозитория. Требования к среде указаны в [README](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md).

1. **Локальная разработка.** Установите зависимости и запустите `pnpm workspace:dev:server` и `pnpm workspace:dev:web` в разных терминалах. Откройте `http://127.0.0.1:5173`. Web-сервер разработки перенаправляет API и WebSocket на backend.
2. **Сборка и запуск.** Соберите только приложение Workspace и запустите production-вход:

```bash
pnpm --filter @univerjs/univer-workspace build
pnpm workspace:start
```

Web собирается в `dist/public`, Server — в `dist/server`. Один процесс Node.js обслуживает статические страницы и API.

3. **Подготовка к развёртыванию.** Настройте лицензии, пользователей и каталоги данных. Сохраняйте бизнес-данные, данные совместной работы и загруженные файлы постоянно; проверьте восстановление после перезапуска. См. [Docker](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) и [архитектуру](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/docs/architecture.md).

При росте приложения используйте [руководство по развёртыванию Server SDK](/server/deployment) для разделения сервисов.
