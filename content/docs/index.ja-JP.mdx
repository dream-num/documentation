Univer Office SDKは3つの部分から成っています:Web SDK、Server SDKおよびAI SDK。それはスプレッドシート、文書、スライド、リレーショナルテーブル、キャンバスおよびPDFをカバーします。

Web SDKは共有コンテンツエンジンです。ブラウザエディタを実行し、UIなしでコンテンツを処理するためにヘッドレスを実行します。他の2つのSDKは、そのヘッドレスランタイムで構築します。Server SDKでは、コラボレーションとファイル処理を追加し、AI SDKには、コンテンツの操作とエージェントの結果を検査します。

## 機能を調べる [#explore-features]

[機能カタログ](/overview/features)は、製品とカテゴリによってグループ化され、各製品がサポートしているもののリストです。 また、機能がオープンソースであるか、統合の範囲であるかにかかわらず、サポートレベルも記録します。 チャート、ファイル変換、コラボレーション、Worktree、および埋め込みは、製品間で共有されます。

### Web SDK: 共有コンテンツ エンジン [#web-sdk-the-shared-content-engine]

Web SDKを使用して、アプリケーション内のOfficeコンテンツを表示、編集、または処理します。 ファサードAPIは、コードがブラウザエディタで実行するか、ヘッドレスNode.jsプロセスで実行されるかにかかわらず、コンテンツ、データ、UIのインターフェイスです。

Web SDKは、製品の機能、エディタUI、および個々の機能を含むプラグインから完全に構築されています。 アプリケーションはプリセットから始めるか、製品や機能のプラグインを選択して、依存関係でそれらを組み立てることができます。

Univerのコアコードを変更することなく、カスタムプラグインでビジネス固有の機能を実行できます。同じコンテンツエンジンは、プラグインセットを使用して各環境に適応します。ブラウザアプリケーションは、エディタUIをロードし、ヘッドレスアプリケーションはこれらのUIプラグインを省略します。 [Univerアーキテクチャ:プラグイン設計](/blog/univer#plugins)を参照してください。

**共有キャンバスレンダリング。** すべてのオフィスコンテンツは同じキャンバスアーキテクチャを介してレンダリングされます。そのため、コンテンツタイプはレイアウトと描画コードを再利用し、ネストされたコンテンツを保持することができます。例えば、スプレッドシートのセルテキストは、ドキュメントレイアウトとレンダリングパスに従い、プレゼンテーションを一貫して維持します。 [レンダリングエンジンのアーキテクチャ](/blog/rendering)を参照してください。

**ハイブリッド計算。** 式エンジンは、フロントエンドとサーバー側のRustエンジンで計算します。 フロントエンドの計算は、Rustエンジンが大きな式ワークロードを処理する間、応答性を編集します。 [方式の機能](/guides/sheets/features/core/formula)と[サーバ側計算](/overview/features/shared/server-calculation)を参照してください。

[スプレッドシート](/guides/sheets/getting-started/quickstart) で起動します。同じ SDK は [ドキュメント](/guides/docs)、[スライド](/guides/slides), [リレーショナルテーブル](/guides/bases)・[ボード](/guides/boards)と [PDFファイル](/guides/pdfs)もカバーしています。

### Server SDK: コラボレーションとファイルを接続する [#server-sdk-connect-collaboration-and-files]

Server SDKは、共有編集、ファイル変換、およびバックエンド拡張機能を追加します。Web SDKのヘッドレスコンテンツ機能上に構築します。モジュールは、独自のバックエンド内で実行され、アプリケーション自身のアイデンティティ、パーミッション、ストレージを使用します。

**リアルタイムコラボレーション** OT(Operational Transformation)は、行や列の変更やコンテンツ編集などの同時操作を処理します。編集はローカルで最初に適用され、各ユーザーの意図を可能な限り保存している間、レプリカはコンバージされます。履歴、コメント、Worktreeは、アプリケーションが必要に応じて追加するモジュールを別々に提供しています。[共同編集設計](/blog/ot)と[コラボレーションクイックスタート](/server/collaboration/quick-start)を参照してください。

**ファイル変換。** 変換は、Office ファイルと Univer の文書データ間でコンテンツを移動し、インポート、編集、およびエクスポートの手順を接続します。 これは、コラボレーションの有無にかかわらず動作します。 アップロード、タスク、およびダウンロードのコンバージョン API と [ファイル交換統合](/server/import-export) については、[オフィスファイルのインポートとエクスポート](/server/import-export/node) を参照してください。

**展開とスケーリング。** モジュールは、独自のNode.jsアプリケーション内で組み立てられ、単一のマシンは起動するのに十分です。 負荷が増加するにつれて、アプリケーションは別のサービスにファイル変換を移動し、複数のコラボレーションノードにスケールを移動することができます。 [アプリケーションアーキテクチャ](/server/architecture)と[展開ガイド](/server/deployment)を参照してください。

[Server SDKの概要](/server)はモジュールを詳しく説明しています。

### AI SDK: エージェントにエントリ ポイントを与える [#ai-sdk-give-agents-an-entry-point]

AI SDKは、既存のエージェント、自動化、およびアプリケーション固有のCLIにオフィス機能を追加します。これは、コンテンツ操作、計算、および検査のためのWeb SDKのヘッドレスランタイムとファサードAPI上に構築されます。

**既存のエージェントスタックを接続します。**オフィスツールは、TypeScript API や、SDK から組み立てられた CLI として公開することができます。モデル選択、タスクオーケストレーション、スキルはアプリケーションにとどまります。エージェントは、実行結果と検査フィードバックを受信し、ワークフローを継続します。

**編集可能なコンテンツを作成する。** エージェントは、ドキュメント構造を読み、必要な範囲または段落を見つけ、Facade API を使用して、式計算を含むスプレッドシート、文書、スライド、その他のコンテンツを作成および変更します。 結果は、そのコンテンツ構造を維持し、編集可能なままにし、人々がそれを改良し続けることができます。 [コンテンツの操作](/ai/content-operations)を参照してください。

**その後、修正します。** エージェントは、バック値と式の結果を読み、実際のページのスクリーンショットを検査します。 スライドの場合、レイアウトは、ページ、オーバーフロー、またはオーバーラップを解除するテキストも識別します。 エージェントはこのフィードバックを使用して、コンテンツを修正し、再びそれを検証し、読み取り→編集を完了し、→検査→リベスループを計算します。 [ビジュアル検査](/ai/visual-inspection)を参照してください。

Server SDKでは、[Worktree](/ai/worktree)はエージェントが作った中間変更を、個人レビューまで分離し、Webアプリケーションに統合します。 [AI SDKの概要](/ai)から始めます。

## アプリケーションの処理フロー [#application-workflow]

<Mermaid chart={"flowchart TB\n    Human[\"人間のユーザー\"] --> Browser\n    Agent[\"AI エージェント / 自動化\"] --> AI[\"AI SDK · 操作と検証\"]\n    subgraph WebSDK[\"Web SDK · 共有コンテンツ エンジン\"]\n      Browser[\"ブラウザエディタ\"]\n      Headless[\"Headless · コンテンツ モデルと Facade APIs\"]\n    end\n    Server[\"Server SDK · コラボレーション、変換、拡張\"] -->|依存| Headless\n    AI -->|依存| Headless\n    Browser <-->|共有コンテンツ| Server\n    AI -.->|コラボレーションとレビュー| Server\n    Server --> Storage[\"アプリケーションの ID、権限、およびストレージ\"]\n    classDef default rx:8,ry:8,stroke-width:1px"} />

- **組込みエディタ**:Web SDKは、アプリケーション内のコンテンツを表示および編集します。
- **連携アプリケーション**: Web SDKとServer SDKは、ユーザーが共有文書を編集できるようにします。
- **人間とエージェントのコラボレーション**:AI SDK、Server SDKによるエージェントの編集と検証は、バージョンとマージを管理し、Webアプリケーションは閲覧、比較、およびヒューマンレビューを提供します。 完全なレビューワークフローには、すべての3が含まれます。

<Callout title="基礎と依存関係の共有">
  Web SDKは、エディタとして、またはヘッドレスのコンテンツエンジンとして独立して実行します。 Server SDKとAI SDKの両方がWeb SDKのヘッドレス機能に依存します。ブラウザUIなしで実行しても、コンテンツランタイムが必要です。アプリケーションは、必要なサービスとモジュールを有効にし、完全なヒューマンエージェントワークフローは通常、すべての3つのSDKを組み合わせます。
</Callout>
