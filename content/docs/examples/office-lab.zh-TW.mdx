**Office Lab** 把儲存庫式協作帶進產品與研發工作。它以 **[Univer Office SDK](/overview)** 建構，使用 Workspace Repo 模式，將需求文件、試算表、互動原型、Issue 與 PR 放進同一專案。進入專案，就能瞭解要解決什麼、修改了什麼，以及哪些成果已可使用。

產品經理與工程師各自使用熟悉的 Agent 準備和檢查資料，人類討論體驗、審閱變更並決定交付。需求持續演進，文件、資料與原型也一起完善。

圖片取自真實[雲端 Workspace](https://space.univer.ai)，使用虛構英文案例資料；兩種 Agent 的角色分工是建議的協作方式。

## 一個專案，兩種專業視角 [#case-study]

**Team Invitations** 從邀請同事、選擇角色與確認結果開始。重複邀請待加入的信箱，成為串起原型、驗收標準、事件追蹤與排程的改進點。

| 角色 | 熟悉的 Agent | 工作 |
| --- | --- | --- |
| Maya · 產品經理 | 例如 Codex | 定義體驗、需求、驗收標準與追蹤方案，審閱成果。 |
| Alex · 工程師 | 例如 Claude Code | 閱讀需求、體驗原型、提出 Issue，準備改進並驗證行為。 |

| 專案資料 | 作用 |
| --- | --- |
| Product brief · 文件 | 目標、邀請規則、驗收標準與發布條件。 |
| Tracking plan · 文件 | 事件觸發時機、屬性與統計定義。 |
| Event catalog · 試算表 | 管理事件、負責人與準備狀態。 |
| Delivery schedule · 試算表 | 工作、負責人、日期、進度與估算。 |
| Invite Prototype / Team Access Console · Web App | 可以直接操作的邀請表單原型。 |

## 瀏覽 Repo，集中工作資料 [#repository]

以 Repo 模式開啟團隊 Space。**Code** 集中可編輯文件與應用檔案，支援搜尋與預覽。Issues、Pull requests、Pages 和 Settings 就在資料旁邊。

這是同一個 Workspace Space 的另一種視圖，沿用內容與權限。專案首頁也能展示選定的 Web App，讓團隊立即體驗原型。

![瀏覽 Repo，集中工作資料](/assets/examples/office-lab/cloud-repository-rich.png)

## 把發現變成可執行的 Issue [#issues]

Alex 發現重複邀請的回饋不清楚，建立 **Prevent duplicate invitations**，說明預期提示、攔截事件與 QA 工作，並連結需求、追蹤文件、事件表和排程。

利用描述、評論、負責人和標籤明確下一步。Issue 屬於團隊 Space；Agent 能以 Workspace CLI 讀取任務與資料。回饋保留在 Issue 或相關文件的評論中。

![把發現變成可執行的 Issue](/assets/examples/office-lab/cloud-issue.png)

## 透過 PR 提出可審閱的修改 [#pull-requests]

PR 將 Workspace Worktree 呈現為可審閱的提案：建立草稿、加入現有文件、修改並標記 Ready。提案有標題、摘要、作者、狀態與變更清單，團隊繼續使用共享內容。

圖中 PR 在事件表加入 `invite_duplicate_blocked`，調整 QA 排程，摘要引用 Issue #1。產品與研發可使用各自草稿，開放給有權限的審閱者，根據相同來源檢查成果。

![透過 PR 提出可審閱的修改](/assets/examples/office-lab/cloud-pull-request.png)

## 用 Worktree 與 Compare 審閱內容 [#review]

先讀摘要，再開啟 **Files changed**。**View** 提供成果的唯讀審閱；**Compare** 並排顯示正式版本與提議版本，搭配可定位的差異清單，檢查事件、負責人及排程影響。

[Worktree](/overview/features/shared/worktree) 隔離任務修改，[內容比較](/overview/features/shared/compare) 以內容模型、Snapshot 和 Changeset 呈現差異。有權限的人類審閱後決定是否合入；本例雙檔案 PR 保持 Ready，尚未合入。

![用 Worktree 與 Compare 審閱內容](/assets/examples/office-lab/cloud-compare.png)

### 把交付影響放進同一次審閱 [#delivery-plan]

同一個 PR 將 Usability and QA 結束日期從 11 月 9 日改為 11 月 10 日，估算從 2 天改為 3 天。連同事件修改檢查負責人、日期與狀態，讓驗收也涵蓋交付所需的工作。

![把交付影響放進同一次審閱](/assets/examples/office-lab/cloud-schedule.png)

## 產生、發布與管理 Web App [#web-apps]

在 **Pages** 集中查看已發布的 Web App，開啟頁面、複製地址或選擇首頁預覽。預設頁面只對目前瀏覽器生效，檔案與權限由 Workspace 管理。

邀請原型進一步擴充為 **Team Access Console**：成員與角色清單、狀態篩選、搜尋、邀請與取消、最近操作、驗收清單和工作階段事件計數集中在同一頁。新增範例信箱會更新清單與待處理數量，重複邀請會被攔截。範例資料只儲存在記憶體，不寄送郵件或上報分析事件；產品經理可直接驗證行為，再建立 Issue。

原生 Office 內容經 Worktree 審閱與合入；HTML View 使用獨立的儲存及授權發布流程。本例原型單獨發布，文件 PR 仍待審閱。即時連動 Office 資料可參考實驗性的[雙向綁定](/overview/features/shared/binding)。

## 為團隊建立清楚的協作邊界 [#team-settings]

**Settings** 組織名稱、說明、可見性、成員與回收站。擁有者和管理員安排存取範圍；編輯、審閱與合入依目前使用者的有效權限，專案連結也遵循權限。

產品經理驗收體驗，工程師檢查實作與事件追蹤，有權限的人合入 Office 修改、檢查發布原型，工作完成後關閉 Issue。

![為團隊建立清楚的協作邊界](/assets/examples/office-lab/cloud-settings.png)

## 體驗 Office Lab [#quick-start]

1. 登入[雲端 Workspace](https://space.univer.ai)，或開啟自己的[私有部署](/overview/examples/workspace#self-host)，建立或開啟一個**團隊 Space**。
2. 開啟 **Application settings → Page theme → Repository (experimental)**。這是同一個 Space 的另一種檢視，切換偏好僅儲存在目前瀏覽器。
3. 在 **Code** 瀏覽文件，透過 **Issues** 追蹤問題，在 **Pull requests** 審閱變更，從 **Pages** 開啟已發布的 Web App。

![將團隊 Space 切換至 Repository 模式，再瀏覽文件、Issue、PR 與 Web App](/assets/examples/office-lab/cloud-office-lab-tour.gif)

若希望使用自己的 Agent，請依 [Workspace CLI 接入說明](/overview/examples/workspace#cli-start)連接。每個 Agent 使用其使用者已授權的帳號；以下任務範本可直接用於實踐。

## 以同一套 SDK 與 Skills 繼續建構 [#skills]

雙方共用與版本配套的 CLI Skills：`core` 負責發現與 Worktree，`doc`、`sheet` 處理需求和計畫，`html-view` 製作原型。Agent 讀取有權存取的資料與 Issue 回饋，人類保留交付決定。

Web SDK 提供內容模型、編輯器與 Headless；Server SDK 提供協同、版本與 Worktree；AI SDK 提供操作及檢查。Workspace 組織專案、身分、Issue、Repo 與發布。可重用這套組合打造產品實驗室或內部交付工作台。
