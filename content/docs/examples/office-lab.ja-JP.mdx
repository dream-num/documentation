**オフィスラボ**は、リポジトリのワークフローを日常の製品作業に適用します。**[Univer Office SDK](/overview)**上に構築され、要件、スプレッドシート、インタラクティブなプロトタイプ、問題、プルリクエストが1つのプロジェクトを共有しているワークスペースのRepoモードで実行されます。すべてのチームメンバーは、要求されたもの、変更されたもの、および使用準備が整ったものを見ることができます。

製品マネージャーとエンジニアがチーム招待状フローを開発することを検討してください。 彼らのエージェントは材料を準備し、検査し、フローがどのように振る舞うべきか、変更を検討し、そして成果を出すべきかについて議論しています。 作業コンテキストは、会話が発展するにつれてプロジェクトに残っています。

[ひとつのプロジェクト、ふたつの視点](#case-study) · [発見を具体的な Issue にする](#issues) · [Worktree と Compare で内容をレビューする](#review) · [Web App の作成・公開・管理](#web-apps) · [Office Lab を試す](#quick-start)

スクリーンショットは、ライブ[クラウドワークスペース](https://space.univer.ai)から撮影され、フィクション・イングリッシュ・ケース・データを使用します。 それらは、リポジトリ・ワークフローを実践しています。 名前の2つのエージェントは、作業の1つの提案された分裂を示しています。

## Repo で作業資料を読む [#repository]

Repo モードでチーム スペースを開きます。 **コードコード** は編集可能なドキュメントとアプリケーション ファイルを集めます。 ファイルを検索、プレビューし、あなたの場所を失うことなくプロジェクトに戻ることができます。 問題、プル リクエスト、ページ、および設定は、懸念する材料の横に表示されます。

Repo モードは、同じワークスペースの別のビューで、そのスペースのコンテンツと権限を使用します。リポジトリのホームページは、選択した Web App をプレビューすることもできます。そのため、プロジェクトは、両方の読み取りと使用が可能なコンテンツで開きます。

![Repo で作業資料を読む](/assets/examples/office-lab/cloud-repository-rich.png)

## 発見を具体的な Issue にする [#issues]

アレックスは、プロトタイプを試行し、重複招待パスが不明です。 **重複の招待を防ぎます**は、予想されるメッセージ、ブロックされた招待状イベント、QAフォローアップを記録します。 リンクされたファイルは、製品概要、追跡計画、イベントカタログ、およびディスカッションへのスケジュールをもたらします。

説明、コメント、割り当て、ラベルは、次のアクションをクリアします。 問題はチームスペースに属します。 エージェントは、ワークスペース CLI を使用して、同じタスクとリンクされた素材を読み込み、具体的な提案に戻すことができます。 フィードバックは問題や問題の文書に留まります。

![発見を具体的な Issue にする](/assets/examples/office-lab/cloud-issue.png)

## PR で変更を提案する [#pull-requests]

PRは、ワークスペースWorktreeを他の人がレビューできる提案に変えます。 タスク草案を作成し、必要な既存の文書を追加し、変更を行い、Readyの草案をマークします。 提案には、独自のタイトル、概要、著者、状態、および変更ファイルリストがあります。 草案が変更されると、共有されたコンテンツが利用できなくなります。

スクリーンショットの PR は、イベントカタログに `invite_duplicate_blocked` を追加し、配信スケジュールで QA を拡張します。 その要約は、問題#1 を参照します。 製品とエンジニアリングは、別々の草案で動作し、それらが許可を得て、同じソース素材に対して、お互いの作業をチェックすることができます。

![PR で変更を提案する](/assets/examples/office-lab/cloud-pull-request.png)

## Worktree と Compare で内容をレビューする [#review]

要約で始まり、**変更されたファイル**を開きます。 **プロフィール**は、変更されたコンテンツを読み取り専用のレビューとして開きます。 **比較する** は、提案されたリビジョンの横にある公式バージョンを配置し、ナビゲートできる変更リストを提供します。 ネイティブオフィスのコンテキストでイベント名、トリガー、所有者、およびスケジューリングの影響を調べることができます。

[Worktree](/overview/features/shared/worktree)はタスクの変更を隔離し、[比較する](/overview/features/shared/compare) はコンテンツモデル、スナップショット、およびチェンジセットを通して相違をexposes。 人は、承認されたときにリビジョンを要求するか、合併を確認することができます。 キャプチャされた例では、2-file PR は Ready のままで、マージされません。

![Worktree と Compare で内容をレビューする](/assets/examples/office-lab/cloud-compare.png)

### 日程への影響も一緒に確認する [#delivery-plan]

同じPRは、11月9日から11月10日までのユーザビリティとQAを移動し、2〜3日間で見積もりを上げます。イベント変更の横にある所有者、日付、およびステータスをチェックし、受諾の決定は変更を出荷するために必要な作業をカバーしています。

## Web App の作成・公開・管理 [#web-apps]

プロトタイプは、ライブHTMLビューです。プロジェクトが公開したWeb Appsを見つけるために**ページトップへ**を開き、そのアドレスをコピーするか、ホームページのプレビューとして設定します。選択したデフォルトページは、現在のブラウザの好みです。ファイル構成とアクセスは、ワークスペースに残ります。

招待状プロトタイプは、メンバーとロールディレクトリ、ステータスフィルタ、検索、招待状およびキャンセル、最近のアクティビティ、受諾条件、およびセッションイベントのカウンターを単一のページで提供する**チームアクセスコンソール**になります。 サンプルメールの更新をリストと保留数の両方に追加し、招待状を複製します。 データはメモリにとどまり、電子メールや分析リクエストはありません。 製品管理者は、行動をテストし、問題の発見を回すことができます。

ネイティブオフィスの変更は、Worktreeのレビューとマージを介して行われます。 HTMLビューの出版物は、独自の保存と認可フローを持っているので、この例では、ペンディング文書PRから別々にプロトタイプを公開しています。 Web Appをライブオフィスデータに接続するには、実験的である[ビンディング](/overview/features/shared/binding)を参照してください。

## チームの作業範囲を明確にする [#team-settings]

**コンテンツ**は、リポジトリ名、説明、および可視性を、共同作業者管理とTrash.所有者と管理者がアクセスを整理します。編集、レビュー、および合併は、現在のユーザーの有効な権限に従い、プロジェクトリンクはそれらの権限を尊重します。

リリースの決定は明示的に残るべきです。製品管理者は、経験と受諾基準を確認し、エンジニアリングは実装と測定を点検し、承認された人はオフィスの変更をマージし、公表されたプロトタイプを検証し、作業が完了したときに問題を閉じます。

![チームの作業範囲を明確にする](/assets/examples/office-lab/cloud-settings.png)

## Office Lab を試す [#quick-start]

1. [クラウド Workspace](https://space.univer.ai) にログインするか、[自社環境](/overview/examples/workspace#self-host)を開き、**Team Space** を作成または選択します。
2. **アプリケーション設定 → ページテーマ → リポジトリ(実験)** を開きます。この設定は同じスペースのビューを変更し、設定はこのブラウザでのみ保存されます。
3. **Code** でドキュメントを参照し、**Issues** で課題を追跡し、**Pull requests** で変更をレビューし、**Pages** から公開済み Web App を開きます。

![Team Space を Repository モードに切り替え、ドキュメント、Issue、PR、Web App を確認する](/assets/examples/office-lab/cloud-office-lab-tour.gif)

自分のエージェントと連携するには、[ワークスペース CLI セットアップ](/overview/examples/workspace#cli-start) に従ってください。各エージェントは、そのユーザーの権限のあるアカウントを使用します。下のタスクは、再現できるワークフローを提供します。

## 同じ SDK と Skills で拡張する [#skills]

両方のエージェントは、同じバージョンにマッチしたワークスペース CLI スキルを使用できます。`core` ディスカバリーとワークツリー、`doc`、および `sheet`の要件と計画、`html-view` for プロトタイプ。各エージェントは、他のユーザーがアクセスできる材料と問題のフィードバックを読むことができます。人々は最終的な配信決定を保持します。

Web SDKは、コンテンツモデル、エディタ、およびヘッドレス操作、Server SDKサポートコラボレーション、バージョン、およびワークツリー、AI SDKでは、コンテンツの操作と検査を提供します。ワークスペースは、プロジェクト、アイデンティティ、問題、リポジトリビュー、およびワークフローの公開を追加します。この組み合わせは、製品ラボ、リサーチワークスペース、または内部配信ハブをサポートします。
