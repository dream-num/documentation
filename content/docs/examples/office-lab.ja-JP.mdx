**Office Lab** は **[Univer Office SDK](/docs/overview)** と Workspace の Repo モードで構築する、製品・開発チームの作業例です。要件文書、表計算、動くプロトタイプ、Issue、PR を同じプロジェクトに集め、依頼、変更、成果をたどれるようにします。

プロダクトマネージャーとエンジニアが、それぞれ使い慣れた Agent で資料を準備・確認します。人が体験を議論し、変更をレビューして公開を判断します。

[ひとつのプロジェクト、ふたつの視点](#case-study) · [発見を具体的な Issue にする](#issues) · [Worktree と Compare で内容をレビューする](#review) · [Web App の作成・公開・管理](#web-apps) · [自分の Agent で試す](#quick-start)

画像は実際の[クラウド Workspace](https://space.univer.ai) で撮影した架空の英語事例です。ふたつの Agent の役割分担は実践するための提案です。

**Team Invitations** では、同僚の招待、ロール選択、結果確認を扱います。保留中のメールアドレスへの重複招待が、原型、受け入れ条件、計測と日程を改善するきっかけです。

## Repo で作業資料を読む [#repository]

Team Space を Repo モードで開くと、**Code** に編集可能な文書とアプリのファイルがまとまります。検索やプレビューのそばに Issues、Pull requests、Pages、Settings があり、同じ資料を基に作業を進められます。

Repo は同じ Space の別の表示方法で、内容と権限を引き継ぎます。選んだ Web App をプロジェクトのホームで表示し、すぐに体験することもできます。

![Repo で作業資料を読む](/assets/examples/office-lab/cloud-repository-rich.png)

## 発見を具体的な Issue にする [#issues]

Alex は重複招待の説明不足を見つけ、**Prevent duplicate invitations** を作成します。期待する表示、ブロック時のイベント、QA の追加を記述し、要件やイベント表、日程をリンクします。

説明、コメント、担当者、ラベルで次の作業を明確にします。Issue は Team Space の機能で、Agent も Workspace CLI から同じタスクと資料を読めます。フィードバックは Issue または関連文書のコメントに残します。

![発見を具体的な Issue にする](/assets/examples/office-lab/cloud-issue.png)

## PR で変更を提案する [#pull-requests]

PR は Workspace Worktree をレビュー可能な提案として表示します。タスク用草稿に既存文書を追加し、修正して Ready にします。タイトル、概要、作成者、状態、変更ファイルを確認でき、共有内容はそのまま使えます。

画像の PR はイベント表に `invite_duplicate_blocked` を追加し、QA 日程を調整して Issue #1 を概要で参照しています。各担当は別の草稿で作業し、権限のあるレビュアーに公開して互いの成果を確認できます。

![PR で変更を提案する](/assets/examples/office-lab/cloud-pull-request.png)

## Worktree と Compare で内容をレビューする [#review]

概要から **Files changed** を開きます。**View** で完成内容を読み取り専用で確認し、**Compare** で正式版と提案版を並べ、差分一覧から対象へ移動します。イベント、担当、日程への影響を元の Office 表示で把握できます。

[Worktree](/docs/features/shared/worktree) が作業を分離し、[Compare](/docs/features/shared/compare) が内容モデル、Snapshot、Changeset から差分を示します。権限のある人が修正依頼やマージを判断します。画像の PR は Ready のままで未マージです。

![Worktree と Compare で内容をレビューする](/assets/examples/office-lab/cloud-compare.png)

### 日程への影響も一緒に確認する [#delivery-plan]

同じ PR で Usability and QA の終了日を11月9日から10日へ、見積もりを2日から3日へ変更しています。イベントの修正と担当・日付・状態を一緒に確認し、公開に必要な作業も含めて判断できます。

![日程への影響も一緒に確認する](/assets/examples/office-lab/cloud-schedule.png)

## Web App の作成・公開・管理 [#web-apps]

**Pages** では公開済み Web App の表示、リンクのコピー、ホームのプレビュー選択ができます。既定ページの選択は現在のブラウザーにのみ適用され、ファイルとアクセス権は Workspace が管理します。

招待プロトタイプを **Team Access Console** に拡張しました。メンバーとロールの一覧、状態フィルター、検索、招待と取り消し、最近の操作、受け入れ条件、セッション内のイベント件数をひとつの画面で確認できます。新しいサンプルアドレスでは一覧と保留数が更新され、重複招待はブロックされます。データはメモリー内だけに保持され、メールや分析イベントは送信されません。操作を試して発見した点を Issue にできます。

Office の変更は Worktree のレビューとマージを使い、HTML View は別の保存・公開承認フローを使います。この原型は文書 PR と別に公開しています。Office データとの連動には実験的な [Binding](/docs/features/shared/binding) を参照してください。

## チームの作業範囲を明確にする [#team-settings]

**Settings** から名前、説明、公開範囲、共同作業者、ゴミ箱を管理します。所有者や管理者がアクセス範囲を整え、編集・レビュー・マージには利用者の有効な権限が適用されます。

プロダクト担当が体験を、開発担当が実装と計測を確認し、権限のある人が Office の変更をマージします。公開原型を確認し、作業完了後に Issue を閉じます。

![チームの作業範囲を明確にする](/assets/examples/office-lab/cloud-settings.png)

## 自分の Agent で試す [#quick-start]

[クラウド](https://space.univer.ai) または[自社環境](/docs/examples/workspace#self-host)で [Workspace CLI](/docs/examples/workspace#cli-start) を接続します。アプリ設定の **Repository（実験的）** を選び、Team Space を開きます。Agent は各利用者が承認したアカウントで動作します。以下は実践用の役割分担です。

### 1. プロダクト：共通の資料を作る

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Team Invitations の Team Space に英語の要件、計測計画、イベント表、日程と招待 Web App のプレビューを作成してください。担当、日付、受け入れ条件を明記し、Office の変更は Worktree に保持して検証し、レビューリンクを返してください。マージや原型の公開は私の承認を待ってください。
```

</div>

### 2. 開発：焦点を絞った改善を提案する

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
要件、イベント表、日程、原型を読み、保留中アドレスへの重複招待を調べてください。再現手順と期待動作の Issue を作り、Office の変更は別 Worktree、原型は専用の公開フローで準備してください。検証後に PR 概要で Issue を参照し、人のレビューを待ってください。
```

</div>

### 3. レビュー：受け入れ条件と変更を照合する

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Compare で PR を確認し、重複招待イベント、受け入れ条件、QA 日程を照合して原型を試してください。不足を Issue に記録して修正を依頼し、準備済みと未完了を要約してください。承認前にマージや公開をしないでください。
```

</div>

## 同じ SDK と Skills で拡張する [#skills]

両者は同じバージョンの CLI Skills を使えます。`core` は探索と Worktree、`doc` と `sheet` は要件や計画、`html-view` は原型を担当します。Agent はアクセス可能な相手の資料と Issue を読み、人が最終判断をします。

Web SDK は内容モデル、エディター、Headless、Server SDK は共同編集・バージョン・Worktree、AI SDK は操作と検証を提供します。Workspace はプロジェクト、認証、Issue、Repo と公開を組み立てます。この構成を独自の製品ラボや社内作業環境に再利用できます。
