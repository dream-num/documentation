**Univer Office for WorkBuddy**（`workbuddy-univer-office`）是基於 **[Univer Office SDK](/overview)** 公開 API 的本地 Office 整合。本地 MCP 服務和 Skill 將內容建立、檢查、預覽和草稿審閱引入 WorkBuddy，檔案保留在本地工作區。

<Callout type="info">
本外掛為開發預覽版。公開的 npm 執行包支援本地接入；官方市場安裝和宿主內的完整審閱仍需透過驗收測試。
</Callout>

## 安裝與接入 [#quick-start]

需要 WorkBuddy 5.8.3 或更新版本，以及 Node.js 22（22.12 或更新版本）。本範例使用公開執行包 0.1.6，Office 內容預設儲存在本機 `~/.univer-office/workspace` 目錄。

### 1. 安裝本機執行套件

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

請在連線 MCP 之前完成安裝。否則首次依賴下載會在宿主等待握手期間發生，可能導致握手超時。本地連線不需要雲賬號，也不需要 Office API Key。

### 2. 接入本機 MCP

在 WorkBuddy 中開啟一個允許使用的工作目錄，新增自定義 stdio MCP 服務，配置如下：

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

如果 WorkBuddy 找不到 `univer-office`，請將 `command` 替換為安裝後的絕對路徑。在 macOS 或 Linux 上可透過 `command -v univer-office` 取得該路徑，在 Windows 上可使用 `Get-Command univer-office`。請讓 WorkBuddy 啟動該 stdio 服務，不要為同一儲存目錄另行啟動獨立的 HTTP 服務。如需更換儲存目錄，請將環境變數 `WORKBUDDY_OFFICE_WORKSPACE` 設為絕對路徑。

### 3. 匯入操作 Skill

只要本機已安裝 Git 和 Python 3，即可從公開倉庫生成只包含操作說明的 Skill ZIP，不需要建置應用：

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

在 WorkBuddy 的 Skills 管理器中匯入 `.data/packages/univer-office-workbuddy-skill.zip`。MCP 連線後，先讓助手檢查 Office 服務狀態，再傳送下面的任務。Skill 提供操作指引，MCP 服務負責實際執行，兩者需要配合使用。

## 直接體驗一個任務 [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
使用 Univer Office，新建本機檔案 sales-review.univer，製作一張英文銷售試算表：5 筆示例記錄，包含 Product、Quantity、Unit Price、Revenue，以公式計算收入，並加入總收入與各產品收入圖表。
先檢查寫入與公式結果，再只顯示這張 Sheet 的右側預覽，並給我瀏覽器審閱連結。所有變更放在獨立草稿中，等我確認後再合入。
```

</div>

### 你會看到什麼

WorkBuddy 右側只顯示一張只讀的表格預覽。完整檢視、Compare 和確認合入均在瀏覽器中完成，Office 檔案始終保留在本機。第一個任務只使用一張 Sheet，公式和圖表可以立即看到，同時避開宿主對同一回覆中多張預覽卡片的路由限制。

### 繼續體驗

確認併合入第一份結果後，可傳送以下訊息：“在同一份銷售表的新草稿裡，把第一條記錄的單價提高 10%，更新總收入，開啟 Compare 對比已確認的版本，等我審閱。”這樣可以獲得修改前後的實際對比。

## Skills 與工具如何協作 [#skills]

整個流程由一個 [`univer-office` Skill](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office) 統籌，七份產品與跨內容參考文件按需載入。Agent 使用 `univer_api` 查詢公開的 Facade API，再透過 MCP 編輯、確認寫入、讀回內容並預覽。Office SDK 的同一套內容模型同時驅動 Headless 處理與瀏覽器渲染，版本和 Worktree 使每處修改都可以定位、比較和審閱。

## 你可以用它做什麼

- 在常用的助手中建立內容：讓 WorkBuddy 建立或修改電子表格、文件、簡報、關係型表格和畫布。
- 透過即時預覽跟蹤進度：在宿主中檢視只讀預覽，或開啟外部瀏覽器使用完整的 View 和 Compare 介面。
- 決定前審閱改動：Draft View 和 Compare 均為只讀。可比較固定版本、檢查語義差異，並定位到受影響的內容。
- 從草稿到交付：Agent 在 Worktree 中編輯，由人決定合併、繼續修改或丟棄，最後從你選定的已確認版本匯出受支援的格式。

## Office SDK 如何支撐 [#sdk-integration]

WorkBuddy 負責對話和 MCP 工具呼叫。本地服務組合 Office SDK 的 Headless 執行時、Facade 內容操作、協同版本和 Worktree，瀏覽器預覽渲染的是同一套內容模型。本專案演示如何將 SDK 能力打包為供 Agent 宿主使用的本地工具和審閱介面。
