**Univer 작업 공간**는 **[Univer Office SDK](/overview)**에 내장된 오픈 소스 오피스 작업 공간입니다. 편집 가능한 오피스 콘텐츠 및 데이터-바운드 웹 앱은 공유, 협업, 버전 및 변경 리뷰와 함께 개인 및 팀 공간으로 구성됩니다. [소스 저장소](https://github.com/dream-num/univer-workspace)에는 응용 프로그램, 배포 구성, CLI 및 데스크톱 클라이언트가 포함되어 있습니다.

Workspace를 자체 인프라에 배포하거나 [클라우드 평가](https://space.univer.ai)로 시작할 수 있습니다. 기존 에이전트는 Workspace CLI를 통해 연결됩니다. Workspace 데스크톱은 에이전트 대화와 같은 작업 공간을 로컬 애플리케이션으로 가져옵니다. 이러한 경로 모두 동일한 서비스와 동일한 파일에서 작동합니다.

## 기존 Agent를 클라우드 Workspace에 연결하기 [#cli-start]

에이전트가 실행되는 환경에서 CLI와 발견 스킬을 설치합니다. Node.js 22.12 또는 newer가 필요한 경우 Node.js 24는 권장됩니다. 명령을 실행할 수 있는 에이전트는 자체 모델과 대화를 제공하기 위해 계속되는 동안이 도구를 사용합니다. 브라우저와 에이전트가 동일한 작업 공간에서 작동하는 것처럼 클라우드 서비스를 설정하십시오.

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>최초 연결: 브라우저에서 한 번 로그인</summary>

이 단계는 유효한 세션이 이미 존재할 때 건너 뛸 수 있습니다. 로그인이 필요한 경우, 실행:

```bash
uvw auth login
```

반환된 링크, 로그인을 열고, 브라우저에서 코드를 확인합니다. 사용자가 완료를 확인한 후, 실행:

```bash
uvw auth login --complete
```

이 단계는 세션을 설정할 때만 필요합니다. [Workspace CLI 가이드](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md) 문서는 전체 명령 설정 및 인증입니다.

</details>

브라우저가 CLI를 한 번 승인 한 후, CLI는 나중에 작업에 대한 세션을 재사용합니다. 에이전트 별 로그인 페이지 또는 인증 통합이 필요하지 않습니다. 연결 된 에이전트에게 작업을 제공 한 다음 웹에서 반환 된 링크를 엽니 다. 콘텐츠는 동일하며 에이전트의 기본 오피스 변경은 합병 전에 검토 될 수 있습니다.

## 같은 흐름을 자체 배포로 옮기기 [#self-host]

[오픈 소스 저장소](https://github.com/dream-num/univer-workspace)에는 서버와 웹이 포함되어 있습니다. [설치 가이드](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)와 응용 프로그램을 구축 한 다음 도메인, 서명 인, 지속적 저장 및 실행 시간 설정을 구성합니다. 소스에서 개발은 Node.js 24 및 pnpm 11을 사용합니다. 가이드는 생산 배포 세부 사항을 유지합니다.

배포하기 전에, 4 부품을 준비:

| 항목 | 설정할 내용 |
| --- | --- |
| 서비스 | 접근성 가능한 Workspace URL과 Server + Web 애플리케이션. 데스크톱과 CLI 모두 이 배포에 연결됩니다. |
| 영구 데이터 | 제품 데이터베이스, 협업 데이터베이스 및 업로드 파일, 함께 유지. 기본 배포는 `.data` 아래 저장; 도커 용, 지속적 볼륨을 마운트. |
| 인증 | 로그인 구성. 데스크탑이 연결되면, 정확한 콜백 URL 일치로 에이전트 OAuth 클라이언트를 등록하십시오. |
| SDK 라이선스 | `VITE_UNIVER_LICENSE` 배포 도메인에 대한 웹을 구축하고 Node.js 콘텐츠 실행에 의해 필요한 라이센스를 구성 할 때. |

모델 자격은 에이전트 호스트에 속하며 Workspace Sign-in에서 별도로 구성됩니다. [설치 가이드](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) 및 [에이전트 설정](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md)는 현재 설정을 설명합니다.

같은 CLI를 구성하여 개인 배포를 사용하고 그 서비스에 계정을 승인합니다. 실제 서비스 원산지와 함께 예를 들어 주소를 대체하십시오.

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

에이전트는 동일한 도구와 스킬을 유지하고 이제 개인 서비스의 파일 및 권한에 작동합니다. 데스크톱은 그 서비스에 연결할 수 있습니다. [에이전트 연결 가이드](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) 문서 클라이언트 등록 및 콜백 구성.

## Workspace를 로컬 Desktop 클라이언트로 가져오기 [#desktop-start]

**Workspace 데스크탑**는 Workspace, 에이전트 실행 시간, 오피스 도구 및 콘텐츠 미리보기를 하나의 로컬 클라이언트에서 결합합니다. Office 작업은 Codex 또는 Cowork에서 익숙한 대화 및 Preview 패턴을 따릅니다. 원하는 결과를 설명하고 대화 옆에 문서 또는 웹 앱을 검사하고 개정을 요청하고 결과를 검토하십시오.

데스크톱은 위에서 설명한 클라우드 워크스페이스에 연결할 수 있으며, 전용 배포 또는 로컬 머신에서 실행되는 워크스페이스 서비스에 연결할 수 있습니다. 모델과 대화는 구성된 에이전트 호스트를 통해 실행되며 연결된 워크스페이스는 파일과 액세스를 관리합니다. 아래 데스크탑 예제는 생성, 관리 및 협업이 연결되는 방법을 보여줍니다.

[설치하고 연결하기](#desktop-install) · [첫 작업: 두 문서로 예산 검토](#desktop-first-task)

### 일상적인 Office 작업으로 확장되는 에이전트 경험 [#why-desktop]

Office 작업은 대화가 다운로드 가능한 파일을 반환 한 후 계속됩니다. 사람들은 실제 데이터를 편집하고 계산하며 팀 동료와 함께 작업하고 받아들이는 변경 사항을 결정합니다. 데스크탑은 이러한 활동을 하나의 작업 환경에 배치합니다.

- **상태 유지:** 대화, 파일, 로컬 참조 및 작업 공간 자료는 사용할 수 있습니다.
- **네이티브 Office 콘텐츠와 Web App:** 스프레드시트, 문서, 프레젠테이션, Relational Tables, Canvases를 생성·미리보기·편집하고, Office 데이터를 활용하는 대화형 페이지도 만들 수 있습니다.
- **결과 보고 수정:**는 대화 옆에 내용을 열고, 공식 및 레이아웃을 검사하고, 특정 변경을 요청합니다.
- **리뷰 제공:** 에이전트의 네이티브 오피스 변경에 남아 Worktree 사람에 대한 리뷰 그들과 결합 공유 작업 공간에.

### Workspace와 Agent의 실제 연계 [#workspace-and-agent]

아래 스크린 샷은 로컬 워크 스페이스에 연결 된 실제 macOS 데스크톱을 표시하고 피션 실행 자료를 사용하여. 이 통합 미리보기는 확장 가능한 에이전트 호스트, 공간 기능 플러그인 및 Univer 브랜드 스킨을 결합합니다. 가용성은 프로젝트의 릴리스를 따르십시오.

#### 일반 대화에서 만들고 바로 확인하기 [#conversation-creation]

### 설치하고 연결하기 [#desktop-install]

확장 가능한 에이전트 데스크톱이 이미 사용중인 경우, 통합 경로는 설치하고 스페이스 기능 플러그인을 활성화하고, 스페이스에서 연결, 모델을 구성하고, 브랜드 스킨을 추가합니다. 이 페이지의 스크린 샷은이 구성을 사용합니다. 풀 워크 스페이스 데스크탑 릴리스 및 플러그인 미리보기는 별도의 배달 경로를 따릅니다. 게시 된 릴리스 또는 설치 된 버전의 저장소 지침을 사용하십시오.

1. [GitHub 출시](https://github.com/dream-num/univer-workspace/releases)에서 데스크톱 설치 프로그램을 선택하십시오. 데스크톱 버전은 에이전트 V 태그를 사용하므로 Windows x64, macOS Apple Silicon 또는 Linux x64 artifact를 선택하십시오. 데스크탑 배송은 실험적이고 가용성은 게시 된 릴리스를 따릅니다.

2. **설정 → 작업 공간**에서 Workspace 서비스를 선택하고 브라우저를 통해 로그인하고 액세스 권한을 부여합니다. 배포된 서비스에 연결하거나 [현지 설정](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)를 따라 로컬 서비스 실행을 수행합니다.

3. 모델 설정에서 지원되는 공급자, 모델 및 자격 구성을 구성합니다. Workspace sign-in 및 모델 액세스는 별도로 구성됩니다. [모델 구성](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)를 참조하십시오.

4. 접근 가능한 개인 또는 팀 공간 추가, 대화를 시작, 그리고 @ 참조 소스 자료에 사용. 아래의 작업을 실행, 다음 내용을 엽니다 미리보기 및 변경 검토.

설치 프로그램은 에이전트 응용 프로그램 및 오피스 도구를 포함합니다. 작업 공간 서비스는 별도로 실행되며 로컬 또는 원격으로, 모델 액세스는 구성 된 공급자를 사용합니다.

### Office SDK가 Workspace를 구성하는 방식 [#desktop-architecture]

Workspace는 네이티브 편집기, 에이전트 콘텐츠 운영, 팀 협업을 동일한 문서 및 권한으로 연결합니다. 이 오픈 소스 애플리케이션과 Office SDK를 구축하고 비즈니스 워크플로우, 인터페이스 및 통합에 대한 노력을 집중할 수 있습니다.

<Mermaid chart={"flowchart LR\nA[\"Agent\"] <--> S[\"Workspace Server\"] <--> E[\"편집기\"]"} />

에이전트는 CLI 또는 데스크톱을 통해 Node.js의 콘텐츠에 작동하고, 사람들이 웹 또는 데스크탑 편집기에서 편집하고 검토합니다. Workspace Server는 문서를 공유, 초안 및 협업 상태 저장하고, 로컬로 실행할 수 있습니다, 개인 서버, 또는 클라우드에서.

| 계층 | 역할 |
| --- | --- |
| [Web SDK](/guides/sheets) | 콘텐츠 모델, 수식, 공개 Facade API, 네이티브 편집기. |
| [AI SDK](/ai/content-operations) | API 검색, 구조화된 콘텐츠 검사, 지정 문서에 대한 Facade 실행. |
| [Server SDK](/server) | 협업, 리비전, Worktree 초안, 파일 변환. |
| 애플리케이션 계층 | Workspace는 Space, 파일, 권한, 공유, 검토를 담당합니다. Agent 호스트는 대화, 모델 호출, 도구 실행을 담당합니다. |

CLI 및 데스크톱은 [내용 가동 층](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core)를 공유합니다. 이 런타임 풀은 호스트의 수명과 실행하기 전에 버전 동기화를 위해 살아있는 문서를 유지합니다. 다른 클라이언트는 따라서 동일한 편집 및 제출 논리를 재사용합니다. [런타임 재사용](/ai/runtime-architecture) 참조.

[비주얼 검사](/ai/visual-inspection)는 구조화된 검사를 보완합니다. 스크린샷은 브라우저 렌더링에서 와서, 자동 레이아웃 진단은 현재 슬라이드에서 텍스트 오버플로와 오버랩을 감지합니다.

#### Agent의 편집이 검토 가능한 변경이 되는 과정 [#agent-editing-flow]

예산 검토 예에서 에이전트는 공식 및 스타일을 포함하는 스프레드 시트를 편집합니다. 기본 사무실 편집 경로는 다음과 같이 진행합니다.

1. **위치와 짐.** 에이전트는 문서와 Worktree를 선택하여 스냅 샷 및 변경 설정을로드하고 선택한 개정에 동기화합니다. 단위는 워크북과 같은 하나의 문서 인스턴스입니다.
2. **Facade를 통해 편집합니다.** Node.js 런타임은 그 단위에 대한 공개 Facade 호출을 실행합니다. 콘텐츠 변경은 변경 사항으로 수집되며 초안으로 제출됩니다.
3. **결과 확인.** 에이전트는 값과 공식을 다시 읽고 필요한 경우 렌더링 된 출력을 검사합니다. 결과가 검토 할 준비가 될 때까지 동일한 초안에서 계속 편집.
4. **검토 후 병합합니다.** 사람이 [콘텐츠 비교](/overview/features/shared/compare)에서 변경을 확인하고 [Worktree](/ai/worktree)를 공유 버전에 병합할지 결정합니다.

**초안으로의 변경을 저장하지 않습니다.** Workspace는 제출이 확인된 후만 성공적으로 작성을 보고합니다. 분쟁과 확인되지 않은 제출은 오류를 반환합니다. 데스크톱 플러그인에서 합병 및 디카운트 도구는 사용자 승인을 필요로 합니다. 이 응용 프로그램 도구 워크플로가 시행됩니다.

#### Web App을 같은 Office 데이터에 연결하기 [#web-app-data-flow]

시작 대시보드는 예산 편집기와 동일한 스프레드 시트를 사용합니다. HTML View는 샌드 박스형 iframe의 페이지를 렌더링합니다. Workspace 호스트는 사용자가 액세스 할 수있는 소스 문서를 해결하고 허가 된 콘텐츠 엔진을 공급 할 수 있습니다. 미터 카드 및 차트는 소스 데이터에 가입하므로 예산의 두 번째 사본이 필요하지 않습니다.

편집 가능한 바인딩을 위해, 쓰기는 소스 문서에 서명된 ID 및 편집 권한을 요구합니다. 사용자가 페이지를 떠올릴 때, 호스트는 보류 쓰기 및 협업 확인을 기다리며, 실패를 저장합니다. HTML 페이지 게시 및 바인딩은 자신의 저장 경로를 사용하고 자동으로 네이티브 오피스 Worktree 병합 흐름을 따르지 않습니다. [실험 데이터 바인딩](/overview/features/shared/binding)와 [HTML 보기 호스트 구현](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer)를 참조하십시오.

### 자체 업무 흐름으로 확장하기

| 목표 | 시작점 |
| --- | --- |
| 분야별 문서와 작업 | 도메인 스킬, 템플릿 및 도구 지도를 추가하고 내용 및 시각적 검사를 유지합니다. |
| 자체 ID, 저장소와 공유 | Workspace 앱과 서버 측 제품 정책을 확장합니다. |
| 당신의 자신의 대리인 근거한 사무실 클라이언트 | 에이전트 호스트, 기능 플러그인 및 브랜드 스킨을 결합하면 선택한 모델과 비즈니스 도구를 연결합니다. |

#### 예: 예산 검토 Skill 추가 [#domain-skill]

도메인 스킬은 기존 오피스 도구를 재사용하면서 팀의 검토 규칙을 인코딩 할 수 있습니다.

- 소스 워크북, 기간 및 예산 / 일반 열을 찾아서 편집하기 전에 모든 누락 된 비즈니스 정의에 대해 문의하십시오.
- 스프레드시트 지침을 읽고 Worktree를 만든 뒤 Facade로 수식을 갱신하고 검토 문서를 준비합니다.
- 총, 수식 결과 및 발표를 확인하고 변경된 파일과 체크가 수행된 후, 검토를 위한 사람에 초안을 손으로 작성합니다.

비즈니스 규칙과 템플릿은 기술에 속합니다. 액세스 체크, 초안 지속, 합병 승인은 응용 프로그램에 남아 있습니다. ERP 또는 CRM을 연결하려면 필요한 데이터를 반환하고 동일한 Office 편집 및 검토 흐름을 재사용하는 응용 도구를 추가하십시오. 기술 가이드 실행; 그것은 파일에 액세스 권한을 부여하지 않습니다.
