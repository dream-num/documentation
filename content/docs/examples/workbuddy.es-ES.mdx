**Univer Oficina de WorkBuddy** (`workbuddy-univer-office`) es una integración local de Oficina construida en las API públicas de la **[Univer Office SDK](/overview)**. Un servicio local de MCP y una Habilidad traen autorización, inspección, previsualización y borrador de revisión en WorkBuddy, y los archivos permanecen en un espacio de trabajo local.

<Callout type="info">
Esta es una vista previa del desarrollo. La npm pública es compatible con la integración local; la instalación oficial del mercado y la revisión completa en el huésped todavía requieren pruebas de aceptación.
</Callout>

## Instalar y conectar [#quick-start]

Necesita WorkBuddy 5.8.3 o más reciente y Node.js 22 (22.12 o más reciente). Este ejemplo utiliza el tiempo de ejecución público 0.1.6, y el contenido de Office predeterminado al directorio `~/.univer-office/workspace` local.

### 1. Instalar el entorno local

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

Complete la instalación antes de conectar MCP. De lo contrario, la primera descarga de dependencia funciona mientras el host espera el apretón de manos y puede superar el tiempo de salida. Una conexión local no requiere ni una cuenta de nube ni una clave de Office API.

### 2. Conectar el servidor MCP local

Abra un directorio de trabajo autorizado en WorkBuddy, a continuación, agregue un servidor stdio MCP personalizado con la siguiente configuración:

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

Si WorkBuddy no puede localizar `univer-office`, sustitúyase `command` por el camino absoluto de la instalación. En macOS o Linux, obtenga ese camino con `command -v univer-office`; en Windows, utilice `Get-Command univer-office`. Permita WorkBuddy iniciar el servidor stdio, y no inicie un servicio HTTP independiente para el mismo directorio de almacenamiento. Para utilizar un directorio de almacenamiento diferente, establezca la variable de entorno `WORKBUDDY_OFFICE_WORKSPACE` a un camino absoluto.

### 3. Importar el Skill operativo

Con Git y Python 3 disponibles, generar el ZIP de habilidad sólo instrucciones del repositorio público. No se requiere ninguna construcción de aplicaciones:

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

Importe `.data/packages/univer-office-workbuddy-skill.zip` en el administrador de Habilidades de WorkBuddy. Una vez conectado MCP, pida al asistente que revise el estado de servicio de Office, luego envíe la tarea a continuación. La Habilidad proporciona la guía y el servidor MCP realiza la ejecución, así que úsalos juntos.

## Prueba una tarea de inmediato [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Usa Univer Office para crear el archivo local sales-review.univer con una hoja de ventas en inglés y cinco registros: Product, Quantity, Unit Price y Revenue. Calcula Revenue con fórmulas y añade el total y un gráfico de ingresos por producto.
Verifica las escrituras confirmadas y las fórmulas, muestra solo esta Sheet en el panel derecho y dame el enlace de revisión en el navegador. Mantén los cambios en un borrador aislado y espera mi aprobación antes de integrar.
```

</div>

### Qué verás

WorkBuddy muestra una vista previa de la hoja de cálculo sólo lectura a la derecha. Vista completa, Compare y la confirmación de fusión abierta en el navegador, mientras que el archivo Office permanece local. Empezando con una hoja única hace que las fórmulas y gráficos inmediatamente visibles y evita la limitación de enrutamiento del host en múltiples tarjetas de vista previa en la misma respuesta.

### Sigue explorando

Después de aprobar y fusionar el primer resultado, pregunte: “En un nuevo borrador de la misma hoja de ventas, aumente el precio unitario del primer registro en un 10%, actualice los ingresos totales y abra Compare contra la versión confirmada. Espere a mi revisión.” Esto produce una comparación concreta antes y después.

## Cómo trabajan juntos los Skills y las herramientas [#skills]

One [`univer-office` Habilidad](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office) define el flujo de trabajo, con siete referencias de producto y de contenido cruzado cargadas según sea necesario. El agente consulta APIs públicas Facade con `univer_api`, luego edita, confirma escribe, lee el contenido de nuevo, y previsúa a través de MCP. El mismo modelo Office SDK conduce el procesamiento sin cabeza y la renderización del navegador, y versiones más Worktrees hacen cada cambio comparable, y revisor.

## Qué puedes crear

- Cree contenido en su asistente existente: pida a WorkBuddy que cree o actualice hojas de cálculo, documentos, presentaciones, tablas relacionales y lienzos.
- Siga las previsualizaciones en vivo: inspeccione las previsiones de sólo lectura en el host, o abra un navegador externo para las interfaces de visualización y comparación completas.
- Revisar los cambios antes de decidir: Borrador de Vista y Comparación son sólo lectura. Comparar versiones fijas, inspeccionar las diferencias semánticas y navegar al contenido afectado.
- Muévete del borrador a la entrega: el agente edita un Worktree, una persona elige fusionar, revisar o descartar, y los formatos soportados se exportan a partir de la versión confirmada que seleccione.

## Cómo lo hace posible Office SDK [#sdk-integration]

WorkBuddy maneja la conversación y las llamadas de herramientas MCP. El servicio local compone el tiempo de ejecución sin cabeza de Office SDK, autoría de Facade, versiones de colaboración y Worktrees, y el navegador prevea que renderice el mismo modelo de contenido. El proyecto demuestra cómo empaquetar las capacidades de SDK como herramientas locales y una interfaz de revisión para un anfitrión de agente.
