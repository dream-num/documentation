**Univer Office for WorkBuddy** (`workbuddy-univer-office`) est une intégration Office locale fondée sur les API publiques d’**[Univer Office SDK](/docs/overview)**. Un service MCP local et une Skill apportent création, inspection, aperçu et révision de brouillons à WorkBuddy ; les fichiers restent dans l’espace local.

<Callout type="info">
Aperçu de développement. Un environnement d’exécution npm public permet l’intégration locale ; l’installation officielle depuis le catalogue et la revue complète dans l’hôte restent à valider.
</Callout>

[Installer et connecter](#quick-start) · [Essayer une tâche](#first-task) · [Skills et outils](#skills)

## Installer et connecter [#quick-start]

Préparez WorkBuddy 5.8.3 ou ultérieur et Node.js 22, version 22.12 ou ultérieure. Cet exemple utilise le paquet public 0.1.6. Le contenu Office est stocké par défaut dans le dossier local `~/.univer-office/workspace`.

### 1. Installer l’environnement local

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

Terminez l’installation avant la connexion MCP pour que le premier téléchargement ne consomme pas le délai de connexion de l’hôte. Aucun compte cloud ni clé API Office n’est requis pour la connexion locale.

### 2. Connecter le serveur MCP local

Ouvrez un dossier de travail autorisé dans WorkBuddy et ajoutez un serveur MCP stdio personnalisé avec cette configuration :

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

Si WorkBuddy ne trouve pas `univer-office`, remplacez `command` par son chemin absolu d’installation. Utilisez `command -v univer-office` sous macOS/Linux ou `Get-Command univer-office` sous Windows pour le trouver. Laissez WorkBuddy lancer stdio ; ne lancez pas un service HTTP indépendant sur le même dossier. Pour un autre dossier de stockage, définissez `WORKBUDDY_OFFICE_WORKSPACE` avec un chemin absolu.

### 3. Importer le Skill opérationnel

Avec Git et Python 3 disponibles, générez le ZIP d’instructions depuis le dépôt public, sans compiler l’application :

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

Importez `.data/packages/univer-office-workbuddy-skill.zip` dans le gestionnaire de Skills de WorkBuddy. Après la connexion MCP, demandez à l’assistant de vérifier le service Office, puis envoyez la tâche ci-dessous. Le Skill fournit les instructions et le serveur MCP l’exécution ; les deux sont nécessaires.

## Essayez une tâche immédiatement [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Avec Univer Office, crée le fichier local sales-review.univer contenant une feuille de ventes en anglais avec cinq exemples : Product, Quantity, Unit Price et Revenue. Calcule Revenue par formule, ajoute le total et un graphique des revenus par produit.
Vérifie les écritures confirmées et les formules, affiche seulement cette Sheet dans l’aperçu de droite et donne-moi le lien de revue dans le navigateur. Garde les modifications dans un brouillon isolé et attends mon accord avant de fusionner.
```

</div>

### Ce que vous verrez

WorkBuddy affiche une feuille en lecture seule à droite. La vue complète, Compare et la confirmation de fusion s’ouvrent dans le navigateur ; le fichier reste local. Une seule Sheet rend immédiatement visibles formules et graphiques, tout en évitant la limite de routage de plusieurs cartes dans une même réponse de l’hôte.

### Poursuivre l’essai

Après avoir approuvé et fusionné le premier résultat, demandez : « Dans un nouveau brouillon de la même feuille, augmente de 10 % le prix unitaire du premier enregistrement, actualise le total et ouvre Compare avec la version confirmée. Attends ma revue. » Vous verrez ainsi une véritable comparaison avant/après.

## Comment les Skills et les outils coopèrent [#skills]

Un seul [Skill `univer-office`](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office) pilote le processus, avec sept références produit et intercontenus chargées au besoin. L’agent consulte Facade avec `univer_api`, modifie, confirme les écritures, relit et affiche les aperçus via MCP. Le même modèle Office SDK sert au traitement sans interface et au rendu web ; versions et Worktrees rendent les modifications localisables, comparables et révisables.

## Ce que vous pouvez créer

- **Créer avec votre assistant :** Demandez à WorkBuddy de créer ou modifier feuilles, documents, présentations, tables relationnelles et canevas.
- **Suivre les aperçus :** Consultez les aperçus en lecture seule dans l’hôte ou ouvrez un navigateur externe pour les interfaces complètes View et Compare.
- **Comprendre les changements :** View et Compare restent en lecture seule pour les brouillons. Comparez des versions fixes, examinez les différences sémantiques et accédez au contenu concerné.
- **Du brouillon à la livraison :** L’agent modifie un Worktree ; une personne choisit fusion, reprise ou abandon, puis exporte un format compatible depuis la version confirmée sélectionnée.

## Le rôle d’Office SDK [#sdk-integration]

WorkBuddy gère conversation et outils MCP. Le service local compose runtime Headless, Facade, versions collaboratives et Worktrees d’Office SDK ; les aperçus du navigateur rendent le même modèle. Le projet illustre l’intégration de ces capacités dans des outils locaux et une interface de révision pour un hôte d’agents.
