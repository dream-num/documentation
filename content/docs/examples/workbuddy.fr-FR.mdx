**Univer Bureau pour le travailBuddy** (`workbuddy-univer-office`) est une intégration locale de bureau construite sur les API publiques de la **[Univer Office SDK](/overview)**. Un service local MCP et une compétence apportent auteur, inspection, prévisualisations, et examen préliminaire dans WorkBuddy, et les fichiers restent dans un espace de travail local.

<Callout type="info">
Il s'agit d'un aperçu de développement. Le public npm runtime supporte l'intégration locale; l'installation officielle du marché et l'examen complet à l'hôte nécessitent toujours des tests d'acceptation.
</Callout>

## Installer et connecter [#quick-start]

Vous avez besoin de WorkBuddy 5.8.3 ou plus récent et Node.js 22 (22.12 ou plus récent). Cet exemple utilise public runtime 0.1.6, et le contenu Office par défaut dans le répertoire local `~/.univer-office/workspace`.

### 1. Installer l’environnement local

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

Terminez l'installation avant de connecter MCP. Sinon, le premier téléchargement de dépendance s'exécute pendant que l'hôte attend la poignée de main et peut dépasser le délai d'arrêt. Une connexion locale ne nécessite ni un compte cloud ni une clé API Office.

### 2. Connecter le serveur MCP local

Ouvrez un répertoire de travail autorisé dans WorkBuddy, puis ajoutez un serveur MCP stdio personnalisé avec la configuration suivante:

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

Si WorkBuddy ne peut pas localiser `univer-office`, remplacez `command` par le chemin absolu de l'installation. Sur macOS ou Linux, obtenez ce chemin avec `command -v univer-office`; sur Windows, utilisez `Get-Command univer-office`. Autorisez WorkBuddie à démarrer le serveur stdio, et ne démarrez pas un service HTTP indépendant pour le même répertoire de stockage. Pour utiliser un répertoire de stockage différent, définissez la variable d'environnement `WORKBUDDY_OFFICE_WORKSPACE` sur un chemin absolu.

### 3. Importer le Skill opérationnel

Avec Git et Python 3 disponibles, générer les instructions uniquement Skill ZIP à partir du dépôt public. Aucune compilation d'application n'est nécessaire :

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

Importez `.data/packages/univer-office-workbuddy-skill.zip` dans le gestionnaire des compétences de WorkBuddy. Une fois que MCP est connecté, demandez à l'assistant de vérifier l'état du service Office, puis envoyez la tâche ci-dessous. La compétence fournit les conseils et le serveur MCP effectue l'exécution, alors utilisez-les ensemble.

## Essayez une tâche immédiatement [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Avec Univer Office, crée le fichier local sales-review.univer contenant une feuille de ventes en anglais avec cinq exemples : Product, Quantity, Unit Price et Revenue. Calcule Revenue par formule, ajoute le total et un graphique des revenus par produit.
Vérifie les écritures confirmées et les formules, affiche seulement cette Sheet dans l’aperçu de droite et donne-moi le lien de revue dans le navigateur. Garde les modifications dans un brouillon isolé et attends mon accord avant de fusionner.
```

</div>

### Ce que vous verrez

WorkBuddy affiche une prévisualisation en lecture seule sur la droite. Full View, Compare et la confirmation de fusion s'ouvrent dans le navigateur, tandis que le fichier Office reste local. En commençant par une seule feuille, on rend les formules et les graphiques immédiatement visibles et on évite la limitation de routage de l'hôte sur plusieurs cartes d'aperçu dans la même réponse.

### Poursuivre l’essai

Après avoir approuvé et fusionné le premier résultat, demandez : -Dans une nouvelle ébauche de la même feuille de ventes, augmenter le prix unitaire du premier disque de 10%, mettre à jour le chiffre d'affaires total, et ouvrir Comparer par rapport à la version confirmée.

## Comment les Skills et les outils coopèrent [#skills]

Un [Compétence `univer-office`](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office) définit le workflow, avec sept références produit et cross-content chargées au besoin. L'agent interroge les API publiques Facade avec `univer_api`, puis édite, confirme les écritures, lit le contenu en arrière, et prévisualise par MCP. Le même modèle Office SDK conduit le traitement sans tête et le rendu du navigateur, et les versions plus Worktrees rendent chaque changement identifiable, comparable et revisible.

## Ce que vous pouvez créer

- Créez du contenu dans votre assistant existant : demandez à WorkBuddy de créer ou de mettre à jour des feuilles de calcul, des documents, des présentations, des tableaux relationnels et des toiles.
- Suivez les prévisualisations en direct : inspectez les prévisualisations en lecture seule dans l'hôte, ou ouvrez un navigateur externe pour les interfaces Voir et Comparer.
- Examiner les changements avant de décider : Le brouillon et le comparatif sont en lecture seule. Comparez les versions fixes, vérifiez les différences sémantiques et naviguez vers le contenu affecté.
- Passer du brouillon à la livraison : l'agent édite un Worktree, une personne choisit de fusionner, de réviser ou de supprimer, et les formats pris en charge sont ensuite exportés à partir de la version confirmée que vous sélectionnez.

## Le rôle d’Office SDK [#sdk-integration]

WorkBuddy gère la conversation et les appels de l'outil MCP. Le service local compose l'exécution Headless de l'Office SDK, la création de Facade, les versions de collaboration et Worktrees, et les prévisualisations du navigateur rendent le même modèle de contenu. Le projet montre comment emballer les capacités SDK comme outils locaux et une interface de révision pour un agent hôte.
