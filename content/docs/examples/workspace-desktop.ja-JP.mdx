**Univer Workspace Desktop** は、Codex や Claude Code でなじみのあるエージェントの作業方法を Office に広げます。依頼と資料を渡し、文書操作を任せ、横のプレビューを確認して変更をレビューします。**[Univer Office SDK](/docs/overview)** と既存のエージェント実行環境を組み合わせた、自社向け Office 協働空間の実装例です。

## 日常の Office 作業にエージェントの流れを取り入れる [#why-desktop]

Office の成果物には、継続的な編集、数式計算、共同作業、変更レビューが必要です。Desktop はこれらを同じ環境にまとめ、編集・計算・共有できる内容を中心に会話を進めます。

- **文脈を維持：** 会話、ファイル、Workspace 資料、ローカル参照を手元に置けます。
- **ネイティブな成果：** 編集可能なスプレッドシート、文書、スライド、Relational Table、Canvases を作成します。
- **確認しながら修正：** 横で内容を開き、数式とレイアウトを確認して具体的な変更を依頼できます。
- **レビュー後に共有：** Office の変更は Worktree に保持し、人が差分を確認して共有空間へマージします。

## デスクトップに統合される機能

| 機能 | 体験 |
| --- | --- |
| エージェントセッション | 会話とタスクの文脈を保持し、モデルプロバイダーと認証情報をローカルで設定。 |
| ファイルと参照 | アクセス可能な Space を閲覧し、@ で Workspace ファイル、フォルダー、ローカル資料を参照。 |
| Office プレビュー | 実際の Office 内容を横に開き、結果と変更を切り替えて確認。 |
| レビューと引き渡し | Worktree の追加・変更・削除を確認し、修正、マージ、破棄を選択。 |
| ローカルとオンライン | チームのサービスまたは自分のマシン上の Workspace に接続。 |

## 1つのデスクトップで5種類のネイティブコンテンツを扱う [#desktop-tour]

英語の Aurora プロジェクトでは架空のデータを使い、事業モデル、意思決定文書、プレゼンテーション、タスク管理、戦略キャンバスをつないでいます。画面はデスクトップ内のネイティブ Office エディターです。Agent が読み書きする同じコンテンツを、人も引き続き編集できます。

スクリーンショットはデスクトップ統合のプレビューです。ホストの拡張ポイントで Univer のブランド外観を適用しています。拡張可能な Agent ホストと Space プラグインを組み合わせており、プレビュー版プラグインの配布状況はプロジェクトのリリースに従います。

### Sheets：計算できる事業モデル [#desktop-sheets]

前提、数式、シナリオ別シート、グラフをまとめて保持します。Agent は Facade API でセル値と数式を検査し、計算して結果を説明できます。この例ではチャネル別の入力が売上、利益、注文数の集計につながります。

![Sheets：計算できる事業モデル](/assets/examples/workspace-desktop/native-sheets.jpg)

### Docs：根拠を意思決定につなげる [#desktop-docs]

見出し、段落スタイル、リスト、表で判断の根拠を残します。Aurora の文書はモデルの数値を優先事項と受け入れ条件に整理しています。会話で特定の段落だけを修正でき、本文も編集可能です。

![Docs：根拠を意思決定につなげる](/assets/examples/workspace-desktop/native-docs.jpg)

### Slides：事業の流れを伝える [#desktop-slides]

編集可能なテキスト、図形、グラフで複数ページの説明を作成します。Aurora は主要指標からチャネル戦略、マイルストーン、必要な判断へと展開します。同じアプリでレイアウトの調整や発表ができます。

![Slides：事業の流れを伝える](/assets/examples/workspace-desktop/native-slides.jpg)

### Relational Table：実行と納品を管理する [#desktop-relational-table]

型付きフィールド、担当者、優先度、ステータスで計画を共有タスクにします。例にはカンバン、タスク一覧、タイムライン、カレンダーがあります。SDK/API の製品名は `Base` です。

![Relational Table：実行と納品を管理する](/assets/examples/workspace-desktop/native-relational-table.jpg)

### Canvases：戦略と実行をつなぐ [#desktop-canvases]

ネイティブ図形、テキスト、コネクターで工程やシステムを説明します。Aurora は戦略、根拠、実行を結び、表計算、文書、スライド、タスクの関係を可視化します。SDK/API 名は `Board` です。

![Canvases：戦略と実行をつなぐ](/assets/examples/workspace-desktop/native-canvases.jpg)

## インストールして接続する [#quick-start]

拡張可能な Agent デスクトップに Space プラグインをインストールして有効化し、Space からサービスに接続してモデルとブランド外観を設定する方法もあります。本ページの画面はこの構成です。完成版 Desktop とプレビュープラグインは配布経路が異なるため、使用する版のリリース情報またはリポジトリの手順に従ってください。

1. [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) から Desktop を選びます。agent-v タグの Windows x64、macOS Apple Silicon、Linux x64 が対象です。デスクトップ提供は実験段階で、公開版の状況を確認してください。

2. **Settings → Workspace** で接続先を指定し、ブラウザーでログイン・認可します。既存サービス、または[ローカル環境](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)に接続できます。

3. Models 設定で対応するプロバイダー、モデル、認証情報を設定します。Workspace ログインとは別の設定です。[モデル設定](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)を参照してください。

4. アクセスできる個人またはチーム Space を追加し、会話を作って @ で資料を参照します。下のタスクでプレビューと変更レビューを試してください。

インストーラーはエージェントと Office ツールを含みます。Workspace サービスはローカルまたはサーバーで別途実行し、モデル接続も設定します。

## Skills が依頼を実行可能な Office 操作につなぐ [#skills]

能力プラグインには **univer** Skill と参照資料が同梱されます。Space と文書の特定、Office API、Worktree の作成・確認・引き渡しを案内します。エージェントは API を調べ、ネイティブ内容に実行し、結果を検査できます。

[能力プラグイン](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md)は文書検索・作成、Headless Facade 編集、構造検査、インポート・エクスポート、Worktree ツールを組み合わせます。マージと破棄はホストの承認を通ります。業務固有の Skills、テンプレート、ツールも追加できます。

### タスクに応じた操作ガイド

プレビュープラグインには9つの Skills が含まれます。共通 Skill は検索、ID、納品の流れを、製品別 Skill は API と検証方法を説明します。Agent はタスクに必要なガイドを読みます。

| Skill | 操作ガイド |
| --- | --- |
| `univer` | Space、ファイル、ドラフトのライフサイクルと納品 |
| `univer-sheet` | 数式、スタイル、グラフ、表計算の検証 |
| `univer-doc` | 文書構造、段落、表 |
| `univer-slide` | スライド作成と視覚的なレイアウト検査 |
| `univer-base` | フィールド、レコード、ビュー |
| `univer-board` | 図形、コネクター、キャンバス配置 |
| `univer-embed` | 別の Office 製品を埋め込む |
| `univer-cross-unit-formula` | Unit 間の参照と計算 |
| `univer-html-view` | Office データにバインドした HTML ページの作成と検査 |

### 実際のセッション：モデルから意思決定メモへ [#agent-task]

Aurora のデスクトップセッションは、元ファイルの読み取り、ネイティブ文書の修訂、後続レビューをつなぎます。既存の草稿は Ready のまま人間の承認を待ちます。[実際のデスクトップ会話](#conversation-preview)と[ネイティブの Worktree 比較](#workspace-review)をご覧ください。

## Office 内容から Web App へ [#web-apps]

HTML View は操作用の入力欄やグラフをシートのデータにつなぎ、Office モデルを対話型レポートや予算ダッシュボードの基盤にします。[双方向バインディング](/docs/features/shared/binding)は実験段階で、変更される可能性があります。

HTML 公開とバインディング書き込みには固有の保存・認可フローがあり、ネイティブ Office 下書きは Worktree でレビューします。

Project Summit は、19枚のワークシートを持つ共有モデルを読む買収判断ダッシュボードです。成長率、提示価格、現金比率を元セルに結び、予測カードとグラフで影響を示します。レビュー文書や取締役会向け資料も参照でき、業務アプリとネイティブ Office 資料を同じワークスペースで扱えます。

## 独自のエージェント Office 空間を構築する [#build-your-own]

Workspace Desktop は既存の部品を完全な製品に組み合わせる例です。エージェントホストと Workspace を再利用し、必要な Office 機能を選ぶことで、業務データ、ツール、テンプレート、引き渡しに集中できます。

### Agent の実行ループと Office 機能を分けて組み立てる [#desktop-architecture]

Skills が作業を案内し、ツールが Headless ランタイムで構造化コンテンツを操作し、ネイティブエディターが人向けの表示と編集を担います。Workspace はファイルと共同作業の文脈を提供します。モデル、業務ツール、ブランド外観を変更しても、Office エンジンを作り直す必要はありません。

<Mermaid chart={"flowchart LR\nA[\"Agent とモデル\"]\nB[\"Skills とツール\"]\nC[\"Office SDK<br/>Headless 操作と検証\"]\nD[\"Workspace サービス<br/>ファイル・共同作業・バージョン\"]\nE[\"デスクトッププレビュー<br/>ネイティブエディターと Web App\"]\nF[\"Worktree と Compare<br/>人によるレビュー\"]\nA --> B --> C --> D\nD <--> E\nD --> F\nF --> E"} />

| 構成要素 | 役割 |
| --- | --- |
| [Web SDK](/guides/sheets) | 共通モデル、Office 編集、描画、数式、Headless Facade 操作。 |
| [Server SDK](/server) | アプリのバックエンドにつながる共同編集、バージョン、Worktree。 |
| [AI SDK](/ai) | エージェント向けの内容操作、検査、検証。 |
| 実行環境と Skills | DSH が会話、モデル、ツール実行、承認を提供し、Workspace プラグインが Office に接続。 |
| Workspace と Desktop | Space、ファイル、ID 連携、レビュー画面をアプリが提供し、Electron がデスクトップとして配布。 |

依頼 → ツール → 編集可能な内容 → プレビュー → レビュー → 共有、という流れを再利用できます。Office SDK が Office 層、ホストが会話と実行ループを担います。[既存アプリとプラグイン](https://github.com/dream-num/univer-workspace/tree/main/apps/agent)を拡張することも独自ホストに接続することもできます。
