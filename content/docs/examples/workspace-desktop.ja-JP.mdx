**Univer Workspace Desktop** は、Codex や Claude Code でなじみのあるエージェントの作業方法を Office に広げます。依頼と資料を渡し、文書操作を任せ、横のプレビューを確認して変更をレビューします。**[Univer Office SDK](/docs/overview)** と既存のエージェント実行環境を組み合わせた、自社向け Office 協働空間の実装例です。

**会話で作成し、Space で管理・共有・共同編集。** 通常のエージェントセッションで Office 文書や Web App を作成・修正し、会話の横で結果を確認します。Space は生成されたファイルを整理し、共有と共同編集につなげます。次の会話からも同じファイルを参照でき、作成からチームでの活用までをつなぎます。

## 日常の Office 作業にエージェントの流れを取り入れる [#why-desktop]

Office の成果物には、継続的な編集、数式計算、共同作業、変更レビューが必要です。Desktop はこれらを同じ環境にまとめ、編集・計算・共有できる内容を中心に会話を進めます。

- **文脈を維持：** 会話、ファイル、Workspace 資料、ローカル参照を手元に置けます。
- **Office と Web App を作成：** 編集可能なスプレッドシート、文書、スライド、Relational Table、Canvases と、それらのデータを使う対話型ページを生成します。
- **確認しながら修正：** 横で内容を開き、数式とレイアウトを確認して具体的な変更を依頼できます。
- **レビュー後に共有：** Office の変更は Worktree に保持し、人が差分を確認して共有空間へマージします。

## 依頼からレビュー可能な成果物へ [#workflow]

通常の会話で Office 文書と Web App を作成・修正し、Space でまとめて管理・共有します。ネイティブ Office の変更は Worktree でレビューしてマージします。HTML 公開とバインディング書き込みは固有の保存・認可フローを使います。次の会話でも同じファイルやデータを参照できます。

## デスクトップに統合される機能

| 機能 | 体験 |
| --- | --- |
| エージェントセッション | 会話とタスクの文脈を保持し、モデルプロバイダーと認証情報をローカルで設定。 |
| ファイルと参照 | アクセス可能な Space を閲覧し、@ で Workspace ファイル、フォルダー、ローカル資料を参照。 |
| コンテンツのプレビュー | 会話の横でネイティブ Office ファイルや Web App を開き、内容・操作・データを確認。 |
| レビューと引き渡し | Worktree の追加・変更・削除を確認し、修正、マージ、破棄を選択。 |
| ローカルとオンライン | チームのサービスまたは自分のマシン上の Workspace に接続。 |
| Space の管理と共同作業 | 会話で作成したファイルを整理し、共有権限を管理して、チームで同じ内容を編集。 |

## Workspace と Agent の連携を実際の画面で見る [#workspace-and-agent]

以下の画像と操作シーケンスは、新規のローカル Workspace に接続した macOS デスクトップアプリで撮影しています。アカウント、Space、ファイル名、本文、Agent の会話には英語の架空データを使用しています。

### 通常の会話で作成し、その場でプレビュー [#conversation-creation]

**Build Five-File Launch Demo** は、スプレッドシート、文書、スライド、Relational Table、キャンバスを作成した通常のエージェント会話です。実際の会話での引き渡しと、Desktop のブラウザーパネルで編集できる **02 Launch Brief** を並べています。会話で修正を依頼し、生成されたファイルを Space で管理・共有できます。

![通常の会話で作成し、その場でプレビュー](/assets/examples/workspace-desktop/local-chat-creation.jpg)

<span id="web-apps" className="block scroll-m-24" />

Agent は通常の会話で対話型レポート、業務ページ、ダッシュボードも作成できます。後続の会話では公開済み予算表から **06 Launch Dashboard** を作成しました。3つのカードが予算・実績・差額を表示し、比較グラフが HTML View のライブバインディングで6領域のデータに追従します。この例は同じネイティブ表計算を読み取るだけで、書き戻しは行いません。[双方向バインディング](/docs/features/shared/binding)は実験段階で、変更される可能性があります。

### 成果物を Space で管理・共有・共同編集 [#workspace-context]

会話で作成した5つのネイティブファイルと **06 Launch Dashboard** を **Aurora Launch Studio** にまとめています。同じ Space で予算、概要文書、3枚のスライド、タスク台帳、プロセス図、Web App を整理し、アクセスを管理してチームと共有します。チームがネイティブ Office 内容を共同編集すると、連携ページも元データに追従します。Web と Desktop は同じファイルを使い、Agent の追加修正は独立した Worktree でレビューを待ちます。

![成果物を Space で管理・共有・共同編集](/assets/examples/workspace-desktop/local-space-overview.jpg)

### Desktop でコンテンツを開き、草稿をレビュー [#space-walkthrough]

実際の Desktop 操作で、ローカル Space のファイルを開き、各製品のネイティブエディターを確認して、実際の Agent 会話に戻ります。内容はアプリ内で引き続き編集できます。

### Desktop で共有コンテンツを共同編集 [#cross-device-collaboration]

Web と Desktop は同じローカルアカウントで **01 Launch Budget** を開きます。Web で入力したメモが実際の Desktop エディターに現れ、Desktop の確認メモも Web に同期されます。画像には2つのメモと同期済み状態が表示されています。これは同一アカウントのクライアント間同期の例です。Agent の草稿は Worktree に分離されています。

### 対話で生成し、修正してレビューに渡す [#conversation-preview]

Agent は独立した Worktree で **02 Launch Brief** を修正します。2週間の承認ゲートと担当者の作業を追加し、再訪率の目標を40%から45%へ変更して、リスクと対策を記録します。画像は実際の会話とネイティブ文書プレビューで、共有元の文書は変更していません。

![対話で生成し、修正してレビューに渡す](/assets/examples/workspace-desktop/local-agent-conversation.jpg)

### Desktop で共有設定を確認 [#desktop-sharing]

Desktop の Space 共有パネルでは、チーム Space のメンバーの役割とリンクのアクセス設定を確認できます。メンバーは役割に応じて共有コンテンツにアクセスし、リンクをコピーしてもアクセス権は追加されません。撮影時に共有権限は変更していません。

## 1つのデスクトップで5種類のネイティブコンテンツを扱う [#desktop-tour]

英語の Aurora プロジェクトでは架空データを使い、予算、概要文書、プレゼンテーション、タスク台帳、プロセス図をつないでいます。画面は Desktop 内のネイティブ Office エディターです。Agent が操作する同じ内容を人も編集できます。

スクリーンショットはデスクトップ統合のプレビューです。ホストの拡張ポイントで Univer のブランド外観を適用しています。拡張可能な Agent ホストと Space プラグインを組み合わせており、プレビュー版プラグインの配布状況はプロジェクトのリリースに従います。

### Sheets：計算できる事業モデル [#desktop-sheets]

予算表は6つの作業領域を管理し、Budget、Actual、Variance を数式で計算し、ネイティブの比較グラフを表示します。合計は予算 USD 102,000、実績 USD 100,000、予算内の差額 USD 2,000 です。Agent は Facade API で計算結果を検証します。

![Sheets：計算できる事業モデル](/assets/examples/workspace-desktop/local-sheets.jpg)

### Docs：根拠を意思決定につなげる [#desktop-docs]

見出し、段落スタイル、リスト、ネイティブ表で、目的、計画、成功指標、担当者を整理します。続く会話では、同じ編集可能な文書の一部を Worktree で修正できます。

![Docs：根拠を意思決定につなげる](/assets/examples/workspace-desktop/local-docs.jpg)

### Slides：事業の流れを伝える [#desktop-slides]

3枚のスライドは、編集可能なテキストと図形、統一したスタイルで、価値提案、4段階の計画、成功指標と担当者を説明します。同じアプリでレイアウトの調整と発表ができます。

![Slides：事業の流れを伝える](/assets/examples/workspace-desktop/local-slides.jpg)

### Relational Table：実行と納品を管理する [#desktop-relational-table]

6件のタスクに、ステータス、優先度、担当者、期限、メモの型付きフィールドを設定しています。色付き選択肢で進捗と優先度を確認できます。SDK/API 名は `Base` です。

![Relational Table：実行と納品を管理する](/assets/examples/workspace-desktop/local-relational-table.jpg)

### Canvases：戦略と実行をつなぐ [#desktop-canvases]

ネイティブ図形、テキスト、コネクターで **Align → Activate → Share → Learn** の4段階を示し、短いメモで作業と根拠を結びます。SDK/API 名は `Board` です。

![Canvases：戦略と実行をつなぐ](/assets/examples/workspace-desktop/local-canvases.jpg)

## インストールして接続する [#quick-start]

拡張可能な Agent デスクトップに Space プラグインをインストールして有効化し、Space からサービスに接続してモデルとブランド外観を設定する方法もあります。本ページの画面はこの構成です。完成版 Desktop とプレビュープラグインは配布経路が異なるため、使用する版のリリース情報またはリポジトリの手順に従ってください。

1. [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) から Desktop を選びます。agent-v タグの Windows x64、macOS Apple Silicon、Linux x64 が対象です。デスクトップ提供は実験段階で、公開版の状況を確認してください。

2. **Settings → Workspace** で接続先を指定し、ブラウザーでログイン・認可します。既存サービス、または[ローカル環境](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)に接続できます。

3. Models 設定で対応するプロバイダー、モデル、認証情報を設定します。Workspace ログインとは別の設定です。[モデル設定](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)を参照してください。

4. アクセスできる個人またはチーム Space を追加し、会話を作って @ で資料を参照します。下のタスクでプレビューと変更レビューを試してください。

インストーラーはエージェントと Office ツールを含みます。Workspace サービスはローカルまたはサーバーで別途実行し、モデル接続も設定します。

## Skills が依頼を実行可能な Office 操作につなぐ [#skills]

能力プラグインには **univer** Skill と参照資料が同梱されます。Space と文書の特定、Office API、Worktree の作成・確認・引き渡しを案内します。エージェントは API を調べ、ネイティブ内容に実行し、結果を検査できます。

[機能プラグイン](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md)は、ファイル探索、Headless Facade 編集、構造化検査、インポート・エクスポート、Worktree 管理をつなぎます。このプレビューは草稿をレビュー可能な状態にし、公開にはデプロイしたアプリのレビューとマージの手順を使います。同じ Office ランタイムに業務 Skills、テンプレート、ツールを追加できます。

### タスクに応じた操作ガイド

プレビュープラグインには9つの Skills が含まれます。共通 Skill は検索、ID、納品の流れを、製品別 Skill は API と検証方法を説明します。Agent はタスクに必要なガイドを読みます。

| Skill | 操作ガイド |
| --- | --- |
| `univer` | Space、ファイル、ドラフトのライフサイクルと納品 |
| `univer-sheet` | 数式、スタイル、グラフ、表計算の検証 |
| `univer-doc` | 文書構造、段落、表 |
| `univer-slide` | スライド作成と視覚的なレイアウト検査 |
| `univer-base` | フィールド、レコード、ビュー |
| `univer-board` | 図形、コネクター、キャンバス配置 |
| `univer-embed` | 別の Office 製品を埋め込む |
| `univer-cross-unit-formula` | Unit 間の参照と計算 |
| `univer-html-view` | Office データにバインドした HTML ページの作成と検査 |

## 独自のエージェント Office 空間を構築する [#build-your-own]

Workspace Desktop は既存の部品を完全な製品に組み合わせる例です。エージェントホストと Workspace を再利用し、必要な Office 機能を選ぶことで、業務データ、ツール、テンプレート、引き渡しに集中できます。

### Agent の実行ループと Office 機能を分けて組み立てる [#desktop-architecture]

Skills が作業を案内し、ツールが Headless ランタイムで構造化コンテンツを操作し、ネイティブエディターが人向けの表示と編集を担います。Workspace はファイルと共同作業の文脈を提供します。モデル、業務ツール、ブランド外観を変更しても、Office エンジンを作り直す必要はありません。

| 構成要素 | 役割 |
| --- | --- |
| [Web SDK](/guides/sheets) | 共通モデル、Office 編集、描画、数式、Headless Facade 操作。 |
| [Server SDK](/server) | アプリのバックエンドにつながる共同編集、バージョン、Worktree。 |
| [AI SDK](/ai) | エージェント向けの内容操作、検査、検証。 |
| 実行環境と Skills | DSH が会話、モデル、ツール実行、承認を提供し、Workspace プラグインが Office に接続。 |

依頼 → ツール → 編集可能な内容 → プレビュー → レビュー → 共有、という流れを再利用できます。Office SDK が Office 層、ホストが会話と実行ループを担います。[既存アプリとプラグイン](https://github.com/dream-num/univer-workspace/tree/main/apps/agent)を拡張することも独自ホストに接続することもできます。
