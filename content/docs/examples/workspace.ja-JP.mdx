**Univer ワークスペース**は、**[Univer Office SDK](/overview)**上に構築されたオープンソースのオフィスワークスペースです。これにより、人々とエージェントが連携しています。編集可能なOfficeコンテンツとデータバウンドWebアプリは、個人とチームスペースに編成され、共有、コラボレーション、バージョン、およびレビューを変更します。 [ソースリポジトリ](https://github.com/dream-num/univer-workspace)には、アプリケーション、デプロイメント構成、CLI、デスクトップクライアントが含まれています。

ワークスペースを自分のインフラにデプロイしたり、[クラウドトライアル](https://space.univer.ai) で起動したりすることができます。既存のエージェントは、ワークスペース CLI を介して接続します。ワークスペースデスクトップは、エージェントの会話と、ローカルアプリケーションに同じワークスペースをもたらします。これらのすべてのルートは、同じサービスと同じファイルで動作します。

[クラウド体験](#entry-points) · [Agent を接続](#cli-start) · [セルフホスト](#self-host) · [Desktop 体験](#desktop-start) · [ソースとカスタマイズ](#build-your-own)

## まずクラウドで Workspace を体験する [#entry-points]

<span id="web-start" />

[クラウドトライアル](https://space.univer.ai)を開き、サインインして、アクセスできるパーソナルスペースまたはチームスペースを入力します。ドキュメントを作成または開いたり、直接編集、ファイル組織、共有を試したりします。ワークスペースサービスは既に実行中なので、エージェントは下記のCLIを通して接続することもできます。トライアルはサンプルデータのために意図されており、そのデータはリセットされる可能性があります。

**ワークスペース サーバー**は、アイデンティティ、スペース、パーミッション、ストレージ、コラボレーション、およびバージョンを管理します。 **ウェブページ** は、編集とレビューのためのブラウザインターフェイスです。 プライベートのデプロイメントは、同じサーバーとWebアプリケーションを実行します。

## 既存 Agent をクラウド Workspace に接続する [#cli-start]

エージェントが実行する環境でCLIと発見スキルをインストールします。 Node.js 22.12 または newer が必要です。Node.js 24 が推奨されます。 コマンドを実行できるエージェントは、独自のモデルと会話を提供し続けます。 ブラウザとエージェントが同じワークスペースで動作するように、クラウドサービスを明示的に設定します。

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>初回接続：ブラウザで一度ログイン</summary>

有効なセッションが既に存在すると、このステップはスキップできます。 サインインが必要な場合は、次の手順を実行します。

```bash
uvw auth login
```

返されたリンクを開き、サインインし、ブラウザのコードを確認します。 ユーザーが完了を確認した後、実行します。

```bash
uvw auth login --complete
```

この手順は、セッションの確立時にのみ必要です。 [ワークスペース CLIガイド](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md) は、完全なコマンドセットと認証を文書化します。

</details>

ブラウザがCLIを一度承認した後、CLIは、後続のタスクのセッションを再利用します。エージェント固有のログインページや認証統合は必要ありません。接続されたエージェントをタスクにし、Webで返されるリンクを開きます。コンテンツは同じです。エージェントのネイティブオフィスの変更は、マージする前に確認することができます。

## 同じワークフローを自社環境へ移す [#self-host]

[オープンソースリポジトリ](https://github.com/dream-num/univer-workspace)はサーバーおよびWebを含んでいます。[展開ガイド](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)と適用を造り、そしてドメイン、印、永続的な貯蔵およびランタイム設定を構成して下さい。源からの開発はNode.js 24およびpnpm 11を使用します;ガイドは生産の配置の細部を維持します。

導入前に、4つの部品を用意します。

| 項目 | 設定内容 |
| --- | --- |
| サービス | 到達可能なワークスペース URL と Server + Web アプリケーション。デスクトップと CLI は、このデプロイメントに接続します。 |
| 永続データ | 製品データベース、コラボレーションデータベース、アップロードされたファイルをまとめて保存します。デフォルトのデプロイメントは、`.data`で保存されます。Dockerの場合、永続的なボリュームをマウントします。 |
| 認証 | サインインの設定。デスクトップ接続時に、エージェント OAuth クライアントに正確なコールバック URL マッチを登録します。 |
| SDK ライセンス | デプロイドメイン用のWebを構築し、Node.jsコンテンツの実行時間別に必要なライセンスを設定する際に、`VITE_UNIVER_LICENSE`を提供します。 |

モデルの資格情報は、エージェントホストに属し、ワークスペースのサインインから別々に設定されています。 [展開ガイド](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)と[エージェントのセットアップ](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md)は、現在の設定を記述します。

同じCLIを設定して、プライベート展開を使用して、そのサービスのアカウントを承認します。 実際のサービス起源で、以下の例アドレスを置き換えます。

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

エージェントは、同じツールとスキルを維持し、プライベートサービスのファイルと権限で動作します。デスクトップは、そのサービスに接続することもできます。 [エージェント接続ガイド](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)ドキュメントクライアント登録とコールバック設定。

## Workspace をローカル Desktop クライアントへ [#desktop-start]

**ワークスペースデスクトップ**は、ワークスペース、エージェントのランタイム、オフィスツール、コンテンツプレビューをローカルクライアント1つにまとめています。オフィスワークは、コーデックスやコワークからよく知られる会話とレビューパターンに従います。目的の結果を記述し、会話の横にあるドキュメントまたはWebアプリを調べ、修正をリクエストし、結果を見直します。

デスクトップは、上記のクラウドワークスペースに接続したり、プライベート展開や、ローカルマシン上で実行されるワークスペースサービスに接続することができます。接続されたワークスペースがファイルとアクセスを管理している間、モデルと会話は、構成されたエージェントホストを介して実行されます。下のデスクトップの例では、作成、管理、コラボレーションがどのように接続するかを示しています。

[インストールして接続する](#desktop-install) · [最初のタスク：2つの文書で予算をレビューする](#desktop-first-task)

### 日常の Office 作業にエージェントの流れを取り入れる [#why-desktop]

会話がダウンロード可能なファイルを返すと、オフィスワークは継続します。 人々は、編集を維持し、実際のデータから計算し、チームメイトと連携し、どの変更を受け付けるかを決定します。 デスクトップは、これらの活動を1つの作業環境に配置します。

- **コンテキストを保ちましょう:**の会話、ファイル、ローカルリファレンス、およびワークスペースの資料は利用できます。
- **ネイティブ Office コンテンツと Web App：** スプレッドシート、文書、スライド、Relational Tables、Canvases の作成・プレビュー・編集に対応し、Office データを使った対話型ページも構築できます。
- **結果を見て、修正します。**は会話の横にコンテンツを開き、式とレイアウトを調べ、特定の変更を要求します。
- **レビューを通して渡して下さい:** エージェントのネイティブオフィスの変更は、Worktreeに残り、人がレビューし、共有されたワークスペースに統合します。

### インストールして接続する [#desktop-install]

拡張可能なエージェントデスクトップが既に使用している場合は、統合パスはスペース機能プラグインをインストールして有効化し、スペースから接続し、モデルを設定し、ブランドスキンを追加します。このページのスクリーンショットは、この構成を使用します。フルワークスペースデスクトップリリースとプラグインプレビューは、別々のデリバリーパスに従います。公開されたリリースまたはインストールされたバージョンのリポジトリの指示を使用してください。

1. [GitHubリリース](https://github.com/dream-num/univer-workspace/releases)からデスクトップインストーラを選択します。デスクトップリリースはエージェントvタグを使用していますので、Windows x64、macOS Apple Silicon、またはLinux x64のアーティファクトを選択します。 デスクトップデリバリーは実験的であり、公開されたリリースに従います。

2. **設定 → ワークスペース**では、ワークスペースサービスを選択し、ブラウザでサインインし、アクセスを承認します。 デプロイされたサービスに接続するか、[ローカルセットアップ](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)に従ってローカルサービスを実行します。

3. モデル設定では、サポートされているプロバイダ、モデル、および認証情報を設定します。 ワークスペースのサインインとモデルアクセスは別々に設定されています。 [モデル構成](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)を参照してください。

4. アクセス可能な個人またはチームスペースを追加し、会話を開始し、@を使用してソース素材を参照します。 下のタスクを実行し、コンテンツのプレビューと変更レビューを開きます。

インストーラには、エージェントアプリケーションとOfficeツールが含まれています。ワークスペースサービスは、ローカルまたはリモートで実行され、モデルアクセスは、設定されたプロバイダを使用します。

### Skills：作業環境の理解からタスクの完了まで [#skills]

これらのスキルは、既存のエージェントが接続されたワークスペースでOfficeコンテンツとWeb Appsを作成および編集し、レビューのために変更をオフにすることができます。 [エージェントをワークスペースに接続する](#cli-start)は、最初に、以下のガイダンスは、そのサービスのファイルと権限で動作します。

#### 既存 Agent 向けの Skills

既存のエージェントにインストールされた[`univer-workspace-cli` スキル](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md)は、検出エントリポイントです。 ターゲットを接続、検索し、運用ガイダンスをロードする方法を説明しています。 完全なランタイムスキルは、CLIで出荷し、そのコマンドとFacade APIにマッチします。 デスクトップの組み込み機能プラグインは、タスクガイダンスとツールを提供します。

| ガイド | 対象 |
| --- | --- |
| `core` | スペースとファイルを取り込む, タスクドラフトで作業, コンテンツをチェックし、レビューのためにオフに渡す. |
| `sheet` · `doc` · `slide` · `base` · `board` | 表計算、文書、プレゼンテーション、Relational Table、Canvases。 |
| `blob` | 元のファイルをアップロード、ダウンロード、および置き換えます。 |
| `html-view` | インタラクティブなWebアプリ用のライブHTMLページの作成と管理。 |
| `embed` · `cross-unit-formula` | 他のコンテンツの埋め込みや、コンテンツタイプ間でのデータと式を繋ぐ。 |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

`core`を最初にロードし、タスクで必要な製品やトピック。 `skills get`は参照パスをリストします。 `uvw skills read <name> <path>`で1つのドキュメントを読み、 `--full`を追加して、それらすべてを読みます。 既存のエージェントは、CLIを通してこれらの機能を使用します。デスクトップはツールと会話ワークフローにガイダンスを統合します。

#### Desktop 内の作業ガイド [#desktop-skills]

デスクトップ機能プラグインには、**ユニバー** スキルとその参照が含まれています。 スペースと文書がどのように関連するか、Office API の使用方法、および Worktreeの作成、チェック、および配信方法について説明します。 手順は実行可能なツールに同行しているため、エージェントは API を調べ、ネイティブコンテンツで実行し、結果を検査することができます。

### Office SDK が Workspace を支える仕組み [#desktop-architecture]

Workspace は、ネイティブ エディター、エージェント コンテンツ オペレーション、チーム コラボレーションを同じドキュメントとパーミッションに接続します。このオープンソース アプリケーションと Office SDK 上でビルドでき、ビジネス ワークフロー、インターフェイス、統合に関する作業に集中できます。

<Mermaid chart={"flowchart LR\nA[\"Agent\"] <--> S[\"Workspace Server\"] <--> E[\"エディター\"]"} />

エージェントは、CLI またはデスクトップを介して Node.js でコンテンツを操作し、Web またはデスクトップエディタで表示、編集、およびレビューします。ワークスペース サーバーは、共有文書、ドラフト、コラボレーション状態を保存し、プライベートサーバー、またはクラウド上でローカルで実行できます。

| 層 | 役割 |
| --- | --- |
| [Web SDK](/guides/sheets) | コンテンツモデル、数式、公開 Facade API、ネイティブエディター。 |
| [AI SDK](/ai/content-operations) | API 検索、構造化された内容検査、指定文書に対する Facade 実行。 |
| [Server SDK](/server) | 共同編集、リビジョン、Worktree の下書き、ファイル変換。 |
| アプリケーション層 | Workspace は Space、ファイル、権限、共有、レビューを担当。Agent ホストは会話、モデル呼び出し、ツール実行を担当します。 |

CLI とデスクトップは [コンテンツオペレーションレイヤー](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core) を共有します。ランタイムプールは、ホストの寿命を延ばし、実行前にバージョンを同期させます。異なるクライアントは、同じ編集と送信ロジックを再利用します。[ランタイムリユース](/ai/runtime-architecture)を参照してください。

[外観検査](/ai/visual-inspection)は構造化された点検を補足します。スクリーンショットはブラウザのレンダリングから来、自動レイアウトの診断は現在のスライドのテキストの流出および重複を検出します。

#### Agent の編集からレビュー可能な変更へ [#agent-editing-flow]

予算レビュー例では、エージェントは式とスタイルを含むスプレッドシートを編集します。 ネイティブオフィス編集パスは次の通りです。

1. **積荷を積んで下さい。** エージェントは、ドキュメントとWorktreeを選択し、スナップショットとチェンジセットをロードし、選択したリビジョンに同期します。 ユニットは、ワークブックなどの1つのドキュメントインスタンスです。
2. **ファサードを通して編集する。** Node.jsのランタイムは、そのユニットに対するパブリックファサード呼び出しを実行します。 コンテンツの変更は、変化に収集され、ドラフトに提出されたミューテーションを生成します。
3. **結果を確認してください。** エージェントは、必要に応じて、値と式を読み取り、レンダリングされた出力を検査します。 編集は、結果がレビューの準備ができるまで、同じ草案で継続します。
4. **レビューしてマージする。** 人が[内容比較](/overview/features/shared/compare)で変更を確認し、[Worktree](/ai/worktree) を共有版へマージするか決めます。

**ドラフトへのチェンジセットを節約することは、それをマージしません。** ワークスペースは、投稿が確認された直後にのみ、書き込みを成功に報告します。 競合と未確認の投稿は、エラーを返します。 デスクトッププラグインでは、マージと廃棄ツールは、アプリケーションのツールワークフローが強制するユーザーの承認を必要とします。

#### Web App を同じ Office データにつなぐ [#web-app-data-flow]

起動ダッシュボードは、同じスプレッドシートを予算エディタとして使用しています。 HTMLビューは、サンドボックス化されたiframeのページをレンダリングします。 Workspaceホストは、ユーザーが許可されたコンテンツエンジンにアクセスし、供給できるソース文書を解決します。 メトリックカードとチャートは、ソースデータに購読しますので、予算の2番目のコピーは必要ありません。

編集可能なバインディングでは、帳票は署名入りのアイデンティティと編集権限をソース文書に要求します。ユーザーがページを離れると、ホストは書き込みとコラボレーションの確認を保留し、エラーを保存します。HTMLページのパブリッシングとバインディングの書き込みは、独自の保存パスを使用しており、ネイティブOffice Worktreeのマージフローは自動的に従わない。[実験的なデータ結合](/overview/features/shared/binding)と[HTML ホストの実装を見る](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer)を参照してください。

### 自社の業務フローへ拡張する

| 目的 | 開始場所 |
| --- | --- |
| 業界固有の文書やタスク | ドメインスキル、テンプレート、ツールガイドを追加し、コンテンツとビジュアルチェックを保持します。 |
| 独自の ID、ストレージ、共有 | Workspace アプリとサーバー側の業務ポリシーを拡張します。 |
| 独自のエージェントベースのOfficeクライアント | エージェントホスト、機能プラグイン、ブランドスキンを組み合わせて、選択したモデルとビジネスツールを接続します。 |

#### 例：予算レビュー用 Skill を追加する [#domain-skill]

ドメインスキルは、既存のOfficeツールを再利用しながら、チームのレビュールールをエンコードできます。

- ソースのワークブック、期間、予算/実例の列を探し、編集前に欠落したビジネス定義について尋ねます。
- スプレッドシートのガイドを読み、Worktree を作成し、Facade で数式を更新してレビュー文書を用意します。
- 合計、式の結果、およびプレゼンテーションをチェックし、変更されたファイルとチェックを報告し、レビューのために人に草案を渡します。

ビジネスルールとテンプレートは、スキルに所属しています。アクセスチェック、永続草案、および合併承認は、アプリケーションに残ります。ERPまたはCRMを接続するには、必要なデータを返すアプリケーションツールを追加し、同じOffice編集とレビューフローを再使用してください。スキルガイド実行。それはファイルへのアクセスを許可しません。
