**Univer Workspace** は **[Univer Office SDK](/docs/overview)** で構築したオープンソースの Office ワークスペースです。編集できる Office コンテンツやデータ連動の Web App を Personal / Team Space にまとめ、共有、共同編集、バージョン管理、変更レビューをつなぎます。[リポジトリ](https://github.com/dream-num/univer-workspace)にはアプリ、デプロイ構成、CLI、デスクトップクライアントが含まれます。

自社環境にデプロイすることも、[クラウド体験](https://space.univer.ai)から始めることもできます。既存 Agent は Workspace CLI で接続し、Workspace Desktop は Agent の会話とワークスペースをローカルアプリにまとめます。いずれも同じサービスとファイルを利用します。

## まずクラウドで Workspace を体験する [#entry-points]

<span id="web-start" />

**Workspace Server** は ID、Space、権限、ストレージ、共同編集、バージョンを管理し、**Web** は編集とレビューのブラウザー画面を提供します。プライベート環境でも同じ Server と Web をデプロイします。

## 既存 Agent をクラウド Workspace に接続する [#cli-start]

Agent の実行環境に CLI と発見用 Skill をインストールします。Node.js 22.12 以降が必要で、24 を推奨します。コマンドを実行できる Agent は、自身のモデルと会話を維持したまま利用できます。ブラウザーと Agent が同じ Workspace を使うよう、クラウドの接続先を明示します：

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>初回接続：ブラウザで一度ログイン</summary>

有効なセッションがあれば省略できます。ログインが必要な場合は次を実行します。

```bash
uvw auth login
```

返された URL を開き、ブラウザでログインしてコードを確認します。ユーザーが完了を伝えてから次を実行します。

```bash
uvw auth login --complete
```

セッションを確立する場合の手順です。詳細は [Workspace CLI ガイド](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md)をご覧ください。

</details>

初回のブラウザー承認後は、CLI がセッションを再利用します。Agent ごとのログイン画面や認証統合は不要です。接続した Agent に依頼し、返されたリンクを Web で開けば、同じコンテンツを確認して Office の変更をマージ前にレビューできます。

## 同じワークフローを自社環境へ移す [#self-host]

[リポジトリ](https://github.com/dream-num/univer-workspace)には Server と Web が含まれます。[デプロイガイド](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)に従って、ドメイン、ログイン、永続ストレージ、実行設定を構成してください。ソース開発は Node.js 24 と pnpm 11 を使用します。

同じ CLI の接続先を変更し、そのサービスのアカウントを承認します。以下の例を実際のサービス URL に置き換えてください：

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

Agent のツールと Skills は同じまま、自社サービスのファイルと権限を使います。Desktop も接続できます。クライアント登録とコールバック設定は [Agent 接続ガイド](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)を参照してください。

## Workspace をローカル Desktop クライアントへ [#desktop-start]

**Workspace Desktop** は Workspace、Agent ランタイム、Office ツール、プレビューをローカルアプリに統合します。Codex や Cowork のように、目標を伝え、会話の横で文書や Web App を確認し、修正を依頼して成果をレビューできます。

クラウド、自社環境、またはローカルで動く Workspace サービスに接続します。モデルと会話は設定した Agent ホストが担当し、ファイルとアクセス権は接続先 Workspace が管理します。以下の実際のデスクトップ事例で、作成、管理、共同作業の流れを紹介します。

[インストールして接続する](#desktop-install) · [最初のタスク：2つの文書で予算をレビューする](#desktop-first-task)

### 日常の Office 作業にエージェントの流れを取り入れる [#why-desktop]

Office の成果物には、継続的な編集、数式計算、共同作業、変更レビューが必要です。Desktop はこれらを同じ環境にまとめ、編集・計算・共有できる内容を中心に会話を進めます。

- **文脈を維持：** 会話、ファイル、Workspace 資料、ローカル参照を手元に置けます。
- **Office と Web App を作成：** 編集可能なスプレッドシート、文書、スライド、Relational Table、Canvases と、それらのデータを使う対話型ページを生成します。
- **確認しながら修正：** 横で内容を開き、数式とレイアウトを確認して具体的な変更を依頼できます。
- **レビュー後に共有：** Office の変更は Worktree に保持し、人が差分を確認して共有空間へマージします。

### インストールして接続する [#desktop-install]

拡張可能な Agent デスクトップに Space プラグインをインストールして有効化し、Space からサービスに接続してモデルとブランド外観を設定する方法もあります。本ページの画面はこの構成です。完成版 Desktop とプレビュープラグインは配布経路が異なるため、使用する版のリリース情報またはリポジトリの手順に従ってください。

1. [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) から Desktop を選びます。agent-v タグの Windows x64、macOS Apple Silicon、Linux x64 が対象です。デスクトップ提供は実験段階で、公開版の状況を確認してください。

2. **Settings → Workspace** で接続先を指定し、ブラウザーでログイン・認可します。既存サービス、または[ローカル環境](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)に接続できます。

3. Models 設定で対応するプロバイダー、モデル、認証情報を設定します。Workspace ログインとは別の設定です。[モデル設定](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)を参照してください。

4. アクセスできる個人またはチーム Space を追加し、会話を作って @ で資料を参照します。下のタスクでプレビューと変更レビューを試してください。

インストーラーはエージェントと Office ツールを含みます。Workspace サービスはローカルまたはサーバーで別途実行し、モデル接続も設定します。

### Skills：作業環境の理解からタスクの完了まで [#skills]

#### 既存 Agent 向けの Skills

既存のエージェントに入れる [`univer-workspace-cli` Skill](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) は、接続、対象の特定、ガイドの読み込みを案内する入口です。完全なランタイム Skills は CLI に同梱され、コマンドと Facade API のバージョンに対応します。Desktop の内蔵プラグインもタスク向けガイドとツールを提供します。

| ガイド | 対象 |
| --- | --- |
| `core` | Space・ファイルの特定、タスク下書き、検証、レビューへの受け渡し。 |
| `sheet` · `doc` · `slide` · `base` · `board` | 表計算、文書、プレゼンテーション、Relational Table、Canvases。SDK/API 名は Base・Board のままです。 |
| `blob` | 元ファイルのアップロード、ダウンロード、置き換え。 |
| `html-view` | ライブ HTML ページを生成・管理し、対話型 Web App を作成。 |
| `embed` · `cross-unit-formula` | 別コンテンツの埋め込みとコンテンツ間のデータ・数式参照。 |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

まず `core`、次に対象製品やトピックを読み込みます。`skills get` に参考パスが表示され、`uvw skills read <name> <path>` で個別に、`--full` でまとめて読めます。既存エージェントは CLI、Desktop は会話に統合したツールとガイドを使います。

#### Desktop 内の作業ガイド [#desktop-skills]

能力プラグインには **univer** Skill と参照資料が同梱されます。Space と文書の特定、Office API、Worktree の作成・確認・引き渡しを案内します。エージェントは API を調べ、ネイティブ内容に実行し、結果を検査できます。

[機能プラグイン](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md)は、ファイル探索、Headless Facade 編集、構造化検査、インポート・エクスポート、Worktree 管理をつなぎます。このプレビューは草稿をレビュー可能な状態にし、公開にはデプロイしたアプリのレビューとマージの手順を使います。同じ Office ランタイムに業務 Skills、テンプレート、ツールを追加できます。

プレビュープラグインには9つの Skills が含まれます。共通 Skill は検索、ID、納品の流れを、製品別 Skill は API と検証方法を説明します。Agent はタスクに必要なガイドを読みます。

| Skill | 操作ガイド |
| --- | --- |
| `univer` | Space、ファイル、ドラフトのライフサイクルと納品 |
| `univer-sheet` | 数式、スタイル、グラフ、表計算の検証 |
| `univer-doc` | 文書構造、段落、表 |
| `univer-slide` | スライド作成と視覚的なレイアウト検査 |
| `univer-base` | フィールド、レコード、ビュー |
| `univer-board` | 図形、コネクター、キャンバス配置 |
| `univer-embed` | 別の Office 製品を埋め込む |
| `univer-cross-unit-formula` | Unit 間の参照と計算 |
| `univer-html-view` | Office データにバインドした HTML ページの作成と検査 |

### Agent の実行ループと Office 機能を分けて組み立てる [#desktop-architecture]

Skills が作業を案内し、ツールが Headless ランタイムで構造化コンテンツを操作し、ネイティブエディターが人向けの表示と編集を担います。Workspace はファイルと共同作業の文脈を提供します。モデル、業務ツール、ブランド外観を変更しても、Office エンジンを作り直す必要はありません。

<Mermaid chart={"flowchart LR\nA[\"Agent とモデル\"]\nB[\"Skills とツール\"]\nC[\"Office SDK<br/>Headless 操作と検証\"]\nD[\"Workspace サービス<br/>ファイル・共同作業・バージョン\"]\nE[\"デスクトッププレビュー<br/>ネイティブエディターと Web App\"]\nF[\"Worktree と Compare<br/>人によるレビュー\"]\nA --> B --> C --> D\nD <--> E\nD --> F\nF --> E"} />

| 構成要素 | 役割 |
| --- | --- |
| [Web SDK](/guides/sheets) | 共通モデル、Office 編集、描画、数式、Headless Facade 操作。 |
| [Server SDK](/server) | アプリのバックエンドにつながる共同編集、バージョン、Worktree。 |
| [AI SDK](/ai) | エージェント向けの内容操作、検査、検証。 |
| 実行環境と Skills | DSH が会話、モデル、ツール実行、承認を提供し、Workspace プラグインが Office に接続。 |
| Workspace と Desktop | Space、ファイル、ID 連携、レビュー画面をアプリが提供し、Electron がデスクトップとして配布。 |

依頼 → ツール → 編集可能な内容 → プレビュー → レビュー → 共有、という流れを再利用できます。Office SDK が Office 層、ホストが会話と実行ループを担います。[既存アプリとプラグイン](https://github.com/dream-num/univer-workspace/tree/main/apps/agent)を拡張することも独自ホストに接続することもできます。

### 自社の業務フローへ拡張する

| 目的 | 開始場所 |
| --- | --- |
| 業界固有の文書やタスク | 業務 Skills、テンプレート、ツールガイドを追加し、内容と表示の検証を維持します。 |
| 独自の ID、ストレージ、共有 | Workspace アプリとサーバー側の業務ポリシーを拡張します。 |
| 独自の Agent Office クライアント | Agent ホスト、機能プラグイン、ブランドを組み合わせ、モデルや業務ツールを接続します。 |
