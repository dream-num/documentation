**Univer Office Copilot** is an open-source reference web application built with the **[Univer Office SDK](/overview)**, LangChain, React, and TypeScript. It places editable spreadsheets, documents, slides, relational tables, and canvases next to a conversation assistant. The code sample runs without modification and can serve as the starting point for your own Office copilot.

[Run locally](#quick-start) · [Editable examples](https://github.com/dream-num/univer-office-copilot#included-examples) · [Source repository](https://github.com/dream-num/univer-office-copilot)

## Run the reference app locally [#quick-start]

The reference application requires **Node.js 24+** and **pnpm 10.33.4**:

```bash
git clone https://github.com/dream-num/univer-office-copilot.git
cd univer-office-copilot
pnpm install --frozen-lockfile
pnpm dev
```

Open [http://127.0.0.1:5173](http://127.0.0.1:5173). A new local demo account starts with six private, editable examples that cover all five products and both document modes. Browsing and manual editing do not require a model key, Docker, or an external database.

To use Copilot, open the model menu in the chat and select **Add model** or **Manage models**. Set the provider, model ID, and API key. The application supports OpenAI, Anthropic, Google Gemini, DeepSeek, OpenRouter, and custom OpenAI-compatible HTTPS endpoints. Choose **Ask** to inspect a file, or **Edit** to change the current file directly.

AI text measurement and rendered checks require Chrome, Chromium, or Edge installed locally. Model configuration, attachments, import and export, and browser setup are described in the [local development guide](https://github.com/dream-num/univer-office-copilot/blob/main/docs/local-development.md).

## How Office SDK powers it [#sdk-integration]

The React workspace holds the editors and the chat interface. The Node backend runs the LangChain tool loop, product Skills, and bounded editing scripts against a headless Univer client. Confirmed edits reach the browser over the same collaboration channel that people use, and native readback together with rendered checks provide the verification feedback.

Modern Docs use Markdown, Paged Docs use Typst, and Slides use SVG compiled into editable elements. The application also supports multiple conversations per file, attachment context, per-turn change inspection, native file history, owner-controlled restore, and separate sharing for files and conversations.
