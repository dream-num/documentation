**Univer Workspace** 是基于 **[Univer Office SDK](/overview)** 构建的开源办公空间，供人与 Agent 协同工作。可编辑的 Office 内容与绑定数据的 Web App 放在个人与团队 Space 中，分享、协同、版本和变更审阅也一并在这些空间中提供。[开源仓库](https://github.com/dream-num/univer-workspace)包含应用、部署方案、CLI 和桌面客户端。

你可以把 Workspace 部署在自己的基础设施上，也可以先从[云端在线试用](https://space.univer.ai)开始。已有 Agent 通过 Workspace CLI 接入。Workspace Desktop 把 Agent 对话和同一套工作区整合进本地应用。这几种方式使用的是同一个服务和同一批文件。

## 让已有 Agent 连接云端 Workspace [#cli-start]

在 Agent 的运行环境中安装 CLI 和发现入口 Skill。需要 Node.js 22.12 或更新版本，推荐 Node.js 24。能执行命令的 Agent 可以使用这些工具，模型和对话仍由该 Agent 提供。请显式设置云端服务地址，使浏览器和 Agent 操作同一个 Workspace：

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>首次连接：完成一次浏览器登录</summary>

已有有效会话时可以跳过这一步。如果需要登录，执行：

```bash
uvw auth login
```

打开返回的链接，在浏览器中登录并确认验证码。待用户确认完成后，执行：

```bash
uvw auth login --complete
```

这一步只在建立会话时需要。完整命令与认证说明见 [Workspace CLI 指南](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md)。

</details>

浏览器完成首次授权后，CLI 会在后续任务中复用该会话。不需要为特定 Agent 编写登录页面或鉴权集成。给已连接的 Agent 下达任务，打开它返回的链接，即可在 Web 中看到同一份内容，并在合入前审阅 Agent 对原生 Office 内容的修改。

### 从一份可计算、可审阅的文档开始 [#first-task]

## 把同样的工作流程迁到私有部署 [#self-host]

[开源仓库](https://github.com/dream-num/univer-workspace)包含 Server 和 Web。按照[部署指南](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)构建应用，再配置自己的域名、登录方式、持久化存储和运行参数。从源码开发使用 Node.js 24 和 pnpm 11，生产部署细节以该指南为准。

部署前需要准备四个部分：

| 部分 | 需要配置什么 |
| --- | --- |
| 服务 | 可访问的 Workspace 地址，以及 Server + Web 应用。Desktop 和 CLI 都连接这套部署。 |
| 持久化数据 | 产品数据库、协同数据库和上传文件需要一起保留。默认部署将它们存放在 `.data` 下；使用 Docker 时需要挂载持久化卷。 |
| 身份 | 配置登录方式。接入 Desktop 时，注册 Agent OAuth 客户端，回调地址必须完全匹配。 |
| SDK 许可证 | 为部署域名构建 Web 时提供 `VITE_UNIVER_LICENSE`，并单独配置 Node.js 内容运行时所需的许可证。 |

模型凭据由 Agent 宿主管理，与 Workspace 登录分开配置。当前设置见[部署指南](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)和 [Agent 接入说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md)。

继续使用同一个 CLI，把服务地址指向自己的部署，并在该服务中授权一个账号。把下面的示例地址替换为实际的服务地址：

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

Agent 使用的工具和 Skills 不变，操作对象变为私有服务中的文件和权限。Desktop 也可以连接该服务。客户端注册和回调配置见 [Agent 连接指南](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)。

## 把 Workspace 装进本地 Desktop 客户端 [#desktop-start]

**Workspace Desktop** 把 Workspace、Agent 运行时、Office 工具和内容预览整合进一个本地客户端。办公过程采用与 Codex 或 Cowork 类似的对话与预览配合方式：描述所需结果，在对话旁查看文档或 Web App，提出修改，再审阅结果。

Desktop 可以连接前文试用的云端 Workspace、私有部署，也可以连接本机运行的 Workspace 服务。模型和对话通过配置好的 Agent 宿主运行，文件和访问权限由所连接的 Workspace 管理。下面的桌面案例展示生成、管理与协作如何衔接。

[安装并连接工作区](#desktop-install) · [体验任务：用两份原生内容完成预算审阅](#desktop-first-task)

### 把 Agent 工作方式带进日常办公 [#why-desktop]

办公工作不会在对话返回一个可下载文件后结束。人还需要继续编辑、基于真实数据计算、与同事协作，并决定接受哪些修改。Desktop 把这些环节放在同一个工作环境中。

- **保持上下文：** 对话、文件、本地引用和工作区资料始终可以访问。
- **原生 Office 内容与 Web App：** 可以创建、预览和编辑电子表格、文档、演示文稿、Relational Tables 和 Canvases，也可以构建由 Office 数据支撑的交互页面。
- **查看并修改结果：** 在对话旁打开内容，检查公式和排版，再提出具体修改。
- **经审阅后交付：** Agent 对原生 Office 内容的修改保留在 Worktree 中，直到有人审阅并合入共享工作区。

### 一个桌面应用中有哪些能力

| 能力 | 使用体验 |
| --- | --- |
| Agent 会话 | 对话和任务上下文保存在本地，模型服务商与模型也在本地配置。 |
| 文件与资料引用 | 浏览有权限访问的空间。使用 @ 引用 Workspace 文件或文件夹，以及本地资料。 |
| 内容预览 | 在对话旁打开原生 Office 文件或 Web App，检查内容、交互和数据。 |

| Space 管理与协作 | 整理对话生成的文件，管理分享，并与同事编辑同一份内容。 |

### 安装并连接工作区 [#desktop-install]

如果已经在使用可扩展的 Agent 桌面，集成方式是安装并启用 Space 能力插件，从 Space 连接服务、配置模型，再添加品牌皮肤。本页截图使用这套组合。完整的 Workspace Desktop 发行版和插件预览遵循不同的交付路径，请按所安装版本的发布内容或仓库说明操作。

1. 从 [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) 选择 Desktop 安装包。桌面版使用 agent-v 标签，按平台选择 Windows x64、macOS Apple Silicon 或 Linux x64 构建产物。桌面交付仍为实验性，可用版本以已发布的内容为准。

2. 在 **Settings → Workspace** 中选择 Workspace 服务，通过浏览器登录并授权。可以连接已部署的服务，也可以按照[本地运行说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)在本机运行一个 Workspace 服务。

3. 在 Models 设置中配置支持的服务商、模型和凭据。Workspace 登录与模型访问分开配置，详见[模型配置说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)。

4. 添加有权限访问的个人或团队 Space，开始对话，并使用 @ 引用源资料。运行下面的任务，然后打开内容预览和变更审阅。

安装包包含 Agent 应用和 Office 工具。Workspace 服务独立运行，可以在本机或远程服务器上；模型访问使用所配置的服务商。

### Skills：让 Agent 理解工作区并完成任务 [#skills]

这组 Skills 让已有 Agent 在已连接的 Workspace 中创建和编辑 Office 内容与 Web App，再把修改交付审阅。请先[把 Agent 连接到 Workspace](#cli-start)；下面的指引操作该服务中的文件，并遵循其权限。

#### 让已有 Agent 学会使用 Workspace

安装到已有 Agent 中的 [`univer-workspace-cli` Skill](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) 是发现入口，说明如何连接 Workspace、定位目标和加载操作指引。完整的运行时 Skills 随 CLI 发布，与命令和 Facade API 保持一致。Desktop 内置的能力插件也提供任务指引和工具。

| 指引 | 覆盖内容 |
| --- | --- |
| `core` | 定位空间和文件、在任务草稿中工作、检查内容并交付审阅。 |
| `sheet` · `doc` · `slide` · `base` · `board` | 电子表格、文档、演示文稿、关系型表格（Relational Table）与画布（Canvases）。 |
| `blob` | 原始文件的上传、下载与替换。 |
| `html-view` | 创建和管理用于交互式 Web App 的实时 HTML 页面。 |
| `embed` · `cross-unit-formula` | 嵌入其他内容，以及跨内容类型连接数据和公式。 |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

先加载 `core`，再按任务加载所需的产品或主题。`skills get` 列出参考路径；读取单份文档可使用 `uvw skills read <name> <path>`，添加 `--full` 可以全部读取。已有 Agent 通过 CLI 使用这些能力，Desktop 则把工具和指引整合进对话流程。

#### Desktop 内置的任务指引 [#desktop-skills]

Desktop 的能力插件包含 **univer** Skill 及其参考资料。它说明空间与文档之间的关系、如何使用 Office API，以及如何创建、检查并交付 Worktree。这些说明与可执行工具配套，Agent 可以查询 API、在原生内容上执行并检查结果。

[能力插件](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md)把文件发现、Headless Facade 编辑、结构化检查、导入导出和 Worktree 生命周期工具组合在一起。当前预览把草稿准备到可审阅状态；正式发布经过所部署应用的审阅与合入流程。自己的应用可以在同一 Office 运行时上增加行业 Skills、模板和业务工具。

预览插件包含九个 Skills。通用 Skill 说明发现、身份和交付，各产品 Skill 说明其 API 和结果验证方式。Agent 按当前任务读取相应部分。

| Skill | 操作指引 |
| --- | --- |
| `univer` | 空间、文件、草稿生命周期与交付 |
| `univer-sheet` | 公式、样式、图表与表格验证 |
| `univer-doc` | 文档结构、段落与表格 |
| `univer-slide` | 演示文稿创作与视觉布局检查 |
| `univer-base` | 字段、记录与视图 |
| `univer-board` | 形状、连接线与画布布局 |
| `univer-embed` | 在一个 Office 产品中嵌入另一个产品 |
| `univer-cross-unit-formula` | 跨 Unit 引用与计算 |
| `univer-html-view` | 构建和检查绑定 Office 数据的 HTML 页面 |

### Office SDK 如何支撑 Workspace [#desktop-architecture]

Workspace 把原生编辑器、Agent 对内容的操作和团队协同连接到同一套文档与权限上。可以基于这套开源应用和 Office SDK 开发，把精力集中在自己的业务流程、界面和集成上。

<Mermaid chart={"flowchart LR\nA[\"Agent\"] <--> S[\"Workspace Server\"] <--> E[\"编辑器\"]"} />

Agent 通过 CLI 或 Desktop 在 Node.js 中操作内容，用户在 Web 或 Desktop 编辑器中查看、编辑和审阅。Workspace Server 保存共享文档、草稿和协同状态，可以运行在本机、自己的服务器或云端。

| 层次 | 负责什么 |
| --- | --- |
| [Web SDK](/guides/sheets) | 内容模型、公式、公开 Facade API 和原生编辑器。 |
| [AI SDK](/ai/content-operations) | API 查询、结构化内容检查，以及针对指定文档执行 Facade 代码。 |
| [Server SDK](/server) | 协同、修订版本、Worktree 草稿和文件转换。 |
| 应用层 | Workspace 负责空间、文件、权限、分享和审阅。Agent 宿主负责会话、模型调用与工具编排。 |

CLI 和 Desktop 共用同一个[内容操作层](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core)。它的运行时池在宿主运行期间保持已加载的文档，并在执行前同步版本。不同客户端因此复用同一套编辑与提交逻辑，详见[运行时复用](/ai/runtime-architecture)。

[视觉检查](/ai/visual-inspection)补充结构化检查无法覆盖的内容。截图来自浏览器渲染，自动布局诊断目前能发现演示文稿中的文字溢出与重叠。

#### Agent 的修改如何成为可审阅的变更 [#agent-editing-flow]

以预算审阅为例，Agent 编辑的是一张包含公式和样式的电子表格。原生 Office 的编辑路径如下：

1. **定位并加载。** Agent 选择文档和 Worktree，加载快照与 changeset，同步到选定的修订版本。Unit 指一个文档实例，例如一个工作簿。
2. **通过 Facade 编辑。** Node.js 运行时对该 Unit 执行公开 Facade 调用。内容变更产生 mutation，这些 mutation 会被收集为 changeset 并提交到草稿。
3. **检查结果。** Agent 读回数值和公式，必要时检查渲染结果。Agent 继续在同一草稿中编辑，直到结果可以交付审阅。
4. **审阅并合入。** 人在[内容比较](/overview/features/shared/compare)中检查变更，再决定是否将 [Worktree](/ai/worktree) 合入共享版本。

**把 changeset 保存到草稿并不等于合入。** 只有提交得到确认，Workspace 才报告写入成功；冲突和未确认的提交会返回错误。在 Desktop 插件中，合入和放弃工具也需要用户批准，这一要求由应用的工具流程执行。

#### Web App 如何连接同一份办公数据 [#web-app-data-flow]

发布仪表盘和预算编辑器使用同一份电子表格。HTML View 在沙箱 iframe 中渲染页面。Workspace 宿主解析用户可访问的源文档，并提供其已授权的内容引擎。指标卡和图表订阅源数据，因此不需要维护另一份预算副本。

对于可编辑绑定，写入需要已登录身份和源文档的编辑权限。离开页面时，宿主等待未完成的写入和协同确认，并报告保存失败。HTML 页面发布和绑定写回使用各自的保存路径，不会自动遵循原生 Office 的 Worktree 合入流程。详见[实验性双向绑定](/overview/features/shared/binding)和 [HTML View 宿主实现](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer)。

| 你想实现的目标 | 从哪里开始 |
| --- | --- |
| 行业文档与专属任务 | 增加行业 Skills、模板和工具指引，并保留内容与视觉检查。 |

#### 例如：增加预算审阅 Skill [#domain-skill]

行业 Skill 可以承载团队的审阅规则，同时复用已有的 Office 工具：

- 定位源工作簿、账期和预算／实际支出列，编辑前询问缺失的业务定义。
- 加载表格操作指引，创建 Worktree，并使用 Facade 更新公式、准备审阅文档。
- 检查合计、公式结果和展示效果，报告变更文件和已执行的检查，再把草稿交给审阅人。

业务规则和模板放在 Skill 中，访问检查、草稿保存和合入批准留在应用层。接入 ERP 或 CRM 时，增加一个返回所需数据的应用工具，然后复用同一套 Office 编辑与审阅流程。Skill 负责指导执行，不授予文件访问权限。
