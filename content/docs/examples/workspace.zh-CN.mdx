**Univer Workspace** 是基于 **[Univer Office SDK](/overview)** 构建的开源办公空间。它把可编辑的 Office 内容和与数据联动的 Web App 放进个人与团队 Space，连接分享、协同、版本和变更审阅。[开源仓库](https://github.com/dream-num/univer-workspace)提供应用、部署方案、CLI 和桌面客户端。

你可以把 Workspace 私有部署在自己的环境，也可以先用[云端在线试用](https://space.univer.ai)。已有 Agent 通过 Workspace CLI 操作这个工作区；Workspace Desktop 则把 Agent 对话和同一套工作区整合进本地客户端。它们围绕同一个服务、同一批文件工作。

<span id="web-start" />

## 让已有 Agent 连接云端 Workspace [#cli-start]

在 Agent 的运行环境中安装 CLI 和发现入口 Skill。需要 Node.js 22.12 或更新版本，推荐 Node.js 24。具备命令执行能力的 Agent 可以直接使用这些工具，模型和对话仍由它自己提供。先明确设置云端服务地址，让浏览器和 Agent 操作同一个 Workspace：

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>首次连接：完成一次浏览器登录</summary>

已有有效会话时可跳过。需要登录时执行：

```bash
uvw auth login
```

打开返回的链接，在浏览器中登录并确认验证码。用户确认完成后，再执行：

```bash
uvw auth login --complete
```

这一步只在需要建立会话时进行。完整命令与认证说明见 [Workspace CLI 指南](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md)。

</details>

首次浏览器授权后，CLI 会在后续任务中复用会话，不需要为每种 Agent 编写登录页面或单独的鉴权集成。给已连接的 Agent 下达任务，打开它返回的链接，就能在 Web 中查看同一份内容，并在合入前审阅原生 Office 的修改。

## 把同样的工作流程迁到私有部署 [#self-host]

[开源仓库](https://github.com/dream-num/univer-workspace)包含 Server 和 Web。按照[部署指南](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)构建应用，配置自己的域名、登录方式、持久化存储和运行环境。源码开发使用 Node.js 24 与 pnpm 11，生产部署细节以该指南为准。

部署前需要准备四部分：

| 部分 | 需要配置什么 |
| --- | --- |
| 服务 | 可访问的 Workspace 地址，以及 Server + Web 应用；Desktop 和 CLI 都连接这套部署。 |
| 持久化数据 | 一起保留产品数据库、协同数据库和上传文件。默认部署存放在 `.data` 下，Docker 需要挂载持久化卷。 |
| 身份 | 配置登录方式；接入 Desktop 时，注册 Agent OAuth 客户端及准确匹配的回调地址。 |
| SDK 许可证 | 为部署域名构建 Web 时提供 `VITE_UNIVER_LICENSE`，并单独配置 Node.js 内容运行时所需的许可证。 |

模型凭据由 Agent 宿主管理，与 Workspace 登录分别配置。具体选项见[部署指南](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)和 [Agent 接入说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md)。

继续使用同一个 CLI，把服务地址切换为自己的部署，再授权该服务中的账号。下面的示例地址需要替换成你的实际服务地址：

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

Agent 使用的工具和 Skills 不变，操作的目标变成你私有服务中的文件和权限。Desktop 也可以连接这个服务；客户端注册和回调配置参考 [Agent 连接指南](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)。

## 把 Workspace 装进本地 Desktop 客户端 [#desktop-start]

**Workspace Desktop** 将 Workspace、Agent 运行时、Office 工具和内容预览整合进一个本地客户端，带来类似 Codex 或 Cowork 的办公体验：描述目标，在对话旁查看文档或 Web App，继续提出修改，再审阅成果。

Desktop 可以连接刚才试用的云端 Workspace、私有部署，也可以连接本机运行的 Workspace 服务。模型和对话由配置好的 Agent 宿主驱动，文件和访问权限由所连接的 Workspace 管理。下面用真实桌面案例，展示创作、管理与协作如何连成一条工作流。

[安装并连接工作区](#desktop-install) · [体验任务：用两份原生内容完成预算审阅](#desktop-first-task)

### 把 Agent 工作方式带进日常办公 [#why-desktop]

办公任务的成果需要持续编辑、公式计算、团队协作和变更审阅。Desktop 将这些环节放到同一个工作环境中，让对话直接围绕可编辑、可计算、可协作的内容展开。

- **上下文连贯：** 对话、文件、工作区资料和本地引用随手可用。
- **原生 Office 内容与 Web App：** 支持电子表格、文档、演示文稿、Relational Tables 和 Canvases 的生成、预览与编辑，也可以基于 Office 数据创建交互式页面。
- **边看边改：** 右侧直接预览内容，检查公式和排版，再通过对话提出具体修改。
- **审阅后交付：** Agent 对原生 Office 内容的修改保留在 Worktree 中，由人类查看差异、确认后合入共享空间。

### 一个桌面应用中有哪些能力

| 能力 | 使用体验 |
| --- | --- |
| Agent 会话 | 保留对话和任务上下文，在本机配置模型服务商、模型及凭据。 |
| 文件与资料引用 | 浏览有权限访问的空间，通过 @ 引用 Workspace 文件、文件夹和本地资料。 |
| 内容预览 | 在会话旁打开原生 Office 文件或 Web App，直接查看内容、交互与数据。 |
| 审阅与交付 | 查看 Worktree 中新增、修改、删除的文档，继续调整，或合入、放弃草稿。 |
| 本地与在线空间 | 连接团队已部署的在线服务，也可以连接本机运行的 Workspace 服务。 |
| Space 管理与协作 | 集中整理会话生成的文件，管理分享权限，与团队编辑同一份内容。 |

### 安装并连接工作区 [#desktop-install]

已有可扩展 Agent 桌面时，也可以安装并启用 Space 能力插件，从 Space 连接服务、配置模型，再接入品牌皮肤。本页截图采用这一组合。完整 Workspace Desktop 发行版与插件预览的交付路径不同，请按所安装版本的发布内容或仓库说明操作。

1. 从 [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) 选择 Desktop 安装包。桌面版本使用 agent-v 标签，按平台选择 Windows x64、macOS Apple Silicon 或 Linux x64。当前为实验性桌面交付，版本与平台以已发布内容为准。

2. 在 **Settings → Workspace** 中选择服务地址，经浏览器登录并授权。可以连接已部署的在线服务，也可以按照[本地运行说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)准备本机服务。

3. 在 Models 设置中配置支持的模型服务商、模型与凭据。Workspace 登录和模型访问分别配置，详见[模型配置说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)。

4. 添加有权限访问的个人或团队空间，创建会话，通过 @ 引用资料。尝试下面的任务，再打开内容预览与变更审阅。

安装包包含 Agent 应用与 Office 工具。Workspace 服务独立运行在本机或服务器上；模型访问使用你配置的服务商。

### Skills：让 Agent 理解工作区并完成任务 [#skills]

这组 Skills 用于让已有 Agent 在已连接的 Workspace 中生成和编辑 Office 内容、Web App，再交付审阅。先[将 Agent 连接到 Workspace](#cli-start)，下方指引操作的是该服务中的文件，并遵循其访问权限。

#### 让已有 Agent 学会使用 Workspace

安装给已有 Agent 的 [`univer-workspace-cli` Skill](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) 是发现入口，告诉它如何连接 Workspace、定位目标并加载操作指引。完整的运行时 Skills 随 CLI 发布，与命令和 Facade API 版本配套；Desktop 的内置能力插件也提供面向任务的指引和工具。

| 指引 | 覆盖内容 |
| --- | --- |
| `core` | 空间与文件定位、任务草稿、内容检查和审阅交付。 |
| `sheet` · `doc` · `slide` · `base` · `board` | 电子表格、文档、演示文稿、关系型表格（Relational Table）与画布（Canvases）。 |
| `blob` | 原始文件上传、下载与替换。 |
| `html-view` | 生成并管理实时 HTML 页面，构建可交互的 Web App。 |
| `embed` · `cross-unit-formula` | 嵌入其他内容，以及跨内容的数据引用与公式。 |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

先加载 `core`，再按任务读取产品或主题。`skills get` 会列出参考路径，使用 `uvw skills read <name> <path>` 读取所需文档，或用 `--full` 一并读取。已有 Agent 通过 CLI 使用这些能力，Desktop 则把相关工具和指引整合进对话流程。

<span id="按任务加载对应的操作指引" />

#### Desktop 内置的任务指引 [#desktop-skills]

Desktop 的能力插件内置 **univer** Skill 及参考资料，告诉 Agent 如何定位空间与文档、使用 Office API，以及创建、检查和交付 Worktree。这些指引与实际工具配合：Agent 可以先查 API，再在原生内容上执行操作并检查结果。

[能力插件](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md)组合了文件发现、Headless Facade 编辑、结构化检查、导入导出与 Worktree 生命周期工具。当前预览将草稿准备到可审阅状态；正式发布使用所部署应用的审阅与合入流程。构建自己的产品时，可在同一 Office 运行时加入行业 Skills、模板和业务工具。

预览插件内置九个 Skills。通用 Skill 说明内容发现、身份与交付流程；各产品 Skill 提供 API 和验证指引，Agent 按当前任务读取需要的内容。

| Skill | 操作指引 |
| --- | --- |
| `univer` | 空间、文件、草稿生命周期与交付 |
| `univer-sheet` | 公式、样式、图表与表格验证 |
| `univer-doc` | 文档结构、段落与表格 |
| `univer-slide` | 演示文稿创作与视觉布局检查 |
| `univer-base` | 字段、记录与视图 |
| `univer-board` | 形状、连接线与画布布局 |
| `univer-embed` | 在一个 Office 产品中嵌入另一个产品 |
| `univer-cross-unit-formula` | 跨 Unit 引用与计算 |
| `univer-html-view` | 构建和检查绑定 Office 数据的 HTML 页面 |

### Office SDK 如何支撑 Workspace [#desktop-architecture]

Workspace 将三个 SDK 组合成应用：Web SDK 提供共同的内容引擎，Server SDK 提供协同与版本，AI SDK 让 Agent 在 Node.js 中读取、编辑和验证内容。Agent 宿主负责会话、模型调用和工具编排；Workspace 负责空间、文件访问与交付。

<Mermaid chart={"flowchart LR\nA[\"Agent<br/>CLI / Desktop\"]\nS[\"Workspace Server<br/>身份 · 协同 · 版本\"] --> D[(\"持久化存储<br/>产品 · 协同 · 文件\")]\nA <-->|读取内容／提交变更| S\nV[\"Web / Desktop<br/>原生编辑 · 审阅\"] <--> S"} />

CLI 和 Desktop 通过 Node.js 执行内容操作，Workspace 服务保存共享文件与协同状态。服务可部署在本机、私有服务器或云端。

| 层次 | 可以复用的能力 |
| --- | --- |
| [Web SDK](/guides/sheets) | 内容模型、公式、公开 Facade API，以及用于预览和人工编辑的原生编辑器。 |
| [AI SDK](/ai/content-operations) | API 查询、结构化内容检查，以及绑定明确文档 ID 的 Facade 执行；Agent 可以定位目标文档，不必依赖编辑器当前选中项。 |
| [视觉检查](/ai/visual-inspection) | 将确定的内容状态渲染成截图；演示文稿还可通过布局诊断发现文字溢出与重叠。需要 Render Page 与兼容的浏览器。 |
| [Server SDK](/server) | 与应用后端集成的协同、修订版本和 Worktree 草稿。 |
| Workspace 应用 | 身份权限、空间与文件组织、Web App 承载，以及审阅和分享界面。 |

Workspace 的[共用 Node.js 客户端层](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core)使用 AI SDK 的 Worker 运行时池，在宿主生命周期内复用已加载的内容，按服务、文档、主线或 Worktree 区分目标，并在执行前同步。应用负责目标与凭据，SDK 负责运行时的租用和回收。改造时可进一步阅读[运行时复用](/ai/runtime-architecture)。

#### Agent 的修改如何成为可审阅的变更 [#agent-editing-flow]

以预算审阅为例，Agent 操作的是包含公式与样式的真实电子表格。原生 Office 内容的编辑流程如下：

<Mermaid chart={"flowchart LR\nA[\"选择文档<br/>与 Worktree\"] --> B[\"Facade 编辑<br/>保存草稿变更\"] --> C[\"检查数据<br/>与渲染结果\"] --> D[\"人类审阅<br/>确认后合入\"]\nC -->|继续修改| B"} />

1. **定位并加载。** 选择文档和 Worktree，加载快照与 changeset，同步到选定的修订版本。Unit 指一个文档实例，例如一个工作簿。
2. **通过 Facade 编辑。** Node.js 运行时对这个 Unit 执行公开 Facade 调用；内容变更产生 mutation，再组织为 changeset 提交到草稿。
3. **检查结果。** 读回数值和公式，按需检查渲染后的画面；在同一草稿中继续修改，直到可以交付审阅。
4. **审阅并合入。** 人在[内容比较](/overview/features/shared/compare)中检查变更，再决定是否将 [Worktree](/ai/worktree) 合入共享版本。

**变更已保存到草稿，不代表已经合入。** Workspace 在提交得到确认后才返回写入成功；冲突或无法确认的提交会返回错误。Desktop 插件的合入、放弃工具也会要求用户批准，批准检查由应用的工具流程执行。

#### Web App 如何连接同一份办公数据 [#web-app-data-flow]

发布仪表盘与预算编辑器使用同一份表格。HTML View 在沙箱 iframe 中渲染页面；Workspace 宿主解析有权限访问的源文档，提供已授权的内容引擎。指标卡和图表可以订阅源数据，无需另行维护一份预算副本。

对于可编辑绑定，写入需要已登录身份以及源文档的编辑权限。离开页面时，宿主等待待处理写入与协同确认，并呈现保存失败。HTML 页面发布和绑定写回有各自的保存流程，不会自动进入原生 Office 的 Worktree 合入流程。详见[实验性双向绑定](/overview/features/shared/binding)和 [HTML View 宿主实现](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer)。

| 你想实现的目标 | 从哪里开始 |
| --- | --- |
| 行业文档与专属任务 | 增加行业 Skills、模板和工具指引，保留内容与视觉检查。 |

| 自己的 Agent 办公客户端 | 组合 Agent 宿主、能力插件和品牌皮肤，接入选定的模型与业务工具。 |

#### 例如：增加预算审阅 Skill [#domain-skill]

行业 Skill 可以定义团队的审阅规则，继续复用已有的 Office 工具：

- 确认源工作簿、账期及预算／实际支出列；业务口径缺失时先向用户确认。
- 加载表格操作指引，建立 Worktree，通过 Facade 更新公式并准备审阅文档。
- 检查合计、公式结果和展示效果，列出变更文件与检查结果，再交给人审阅草稿。

把业务规则和模板放进 Skill，把访问检查、草稿保存和合入批准留在应用层。接入 ERP 或 CRM 时，可增加返回所需数据的业务工具，再复用同一套 Office 编辑与审阅流程。Skill 负责指导操作，本身不会授予文件访问权限。
