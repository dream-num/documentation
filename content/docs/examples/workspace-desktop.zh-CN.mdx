**Univer Workspace Desktop** 将 Codex、Claude Code 这类工具中熟悉的 Agent 工作方式带到办公场景：描述需求、引用资料，让 Agent 操作文档，在侧边查看结果，再审阅变更。它基于 **[Univer Office SDK](/docs/overview)** 和现成的 Agent 运行时构建，为开发自己的 Agent 办公协同空间提供了完整的应用参考。

[为什么需要 Desktop](#why-desktop) · [工作流程](#workflow) · [开始使用](#quick-start) · [Skills](#skills) · [体验任务](#first-task) · [构建自己的应用](#build-your-own)

## 把 Agent 工作方式带进日常办公 [#why-desktop]

办公任务的成果需要持续编辑、公式计算、团队协作和变更审阅。Desktop 将这些环节放到同一个工作环境中，让对话直接围绕可编辑、可计算、可协作的内容展开。

- **上下文连贯：** 对话、文件、工作区资料和本地引用随手可用。
- **成果是原生内容：** Agent 创建的是可继续编辑的电子表格、文档、演示文稿、Relational Table（关系型表格）与 Canvases（画布）。
- **边看边改：** 右侧直接预览内容，检查公式和排版，再通过对话提出具体修改。
- **审阅后交付：** 原生 Office 内容的修改保留在 Worktree 中，由人类查看差异、确认后合入共享空间。

## 一个桌面应用中有哪些能力

| 能力 | 使用体验 |
| --- | --- |
| Agent 会话 | 保留对话和任务上下文，在本机配置模型服务商、模型及凭据。 |
| 文件与资料引用 | 浏览有权限访问的空间，通过 @ 引用 Workspace 文件、文件夹和本地资料。 |
| 原生 Office 预览 | 在侧边直接打开 Office 内容，在结果与变更视图之间切换。 |
| 审阅与交付 | 查看 Worktree 中新增、修改、删除的文档，继续调整，或合入、放弃草稿。 |
| 本地与在线空间 | 连接团队已部署的在线服务，也可以连接本机运行的 Workspace 服务。 |

## 安装并连接工作区 [#quick-start]

1. 从 [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) 选择 Desktop 安装包。桌面版本使用 agent-v 标签，按平台选择 Windows x64、macOS Apple Silicon 或 Linux x64。当前为实验性桌面交付，版本与平台以已发布内容为准。

2. 在 **Settings → Workspace** 中选择服务地址，经浏览器登录并授权。可以连接已部署的在线服务，也可以按照[本地运行说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)准备本机服务。

3. 在 Models 设置中配置支持的模型服务商、模型与凭据。Workspace 登录和模型访问分别配置，详见[模型配置说明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)。

4. 添加有权限访问的个人或团队空间，创建会话，通过 @ 引用资料。尝试下面的任务，再打开内容预览与变更审阅。

安装包包含 Agent 应用与 Office 工具。Workspace 服务独立运行在本机或服务器上；模型访问使用你配置的服务商。

## Skills 将需求连接到可执行的 Office 操作 [#skills]

Desktop 的能力插件内置 **univer** Skill 及参考资料，告诉 Agent 如何定位空间与文档、使用 Office API，以及创建、检查和交付 Worktree。这些指引与实际工具配合：Agent 可以先查 API，再在原生内容上执行操作并检查结果。

[能力插件](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md)组合了文档发现与创建、Headless Facade 编辑、结构化检查、导入导出和 Worktree 生命周期工具。合入与放弃请求经过宿主的审批机制。构建自己的产品时，可在同一 Office 运行时上加入行业 Skills、模板和业务工具。

## 从办公内容延伸到 Web App [#web-apps]

同一个工作区还可以承载交互报告、业务页面和预算看板。HTML View 将输入控件、图表与表格数据连接起来，让 Office 内容模型成为 Web App 的数据与计算基础。[双向绑定](/docs/features/shared/binding)仍为实验性能力，后续可能发生变化。

HTML 页面发布与绑定写回使用各自的保存和授权流程；原生 Office 内容的草稿修改通过 Worktree 审阅。

## 复用这套结构，构建自己的 Agent 办公空间 [#build-your-own]

Workspace Desktop 展示了如何将现成模块组合成完整产品。复用 Agent 宿主和 Workspace 应用，按需组装 Office 能力，就能将研发重点放在行业数据、业务工具、模板与交付流程上，缩短从 SDK 接入到完整办公应用的路径。

| 组成部分 | 承担的职责 |
| --- | --- |
| [Web SDK](/guides/sheets) | 统一内容模型、可编辑的 Office 界面、渲染、公式，以及 Headless Facade 内容操作。 |
| [Server SDK](/server) | 协同、版本与 Worktree 等能力，与应用后端集成。 |
| [AI SDK](/ai) | 面向 Agent 的内容操作、检查与验证能力。 |
| Agent 运行时与 Skills | DSH 提供会话、模型调用、工具编排与审批；Workspace 能力插件接入 Office 工具和任务指引。 |
| Workspace 与 Desktop | 应用提供空间、文件、身份接入和审阅界面；Electron 桌面交付将这些能力带到一个桌面应用中。 |

值得复用的是这条完整链路：需求 → 工具 → 可编辑内容 → 预览 → 审阅 → 共享交付。Office SDK 提供办公能力层，Agent 宿主提供对话与执行循环。可以直接扩展现有的[应用与插件](https://github.com/dream-num/univer-workspace/tree/main/apps/agent)，也可以把 SDK 接入自己的宿主与业务服务。
