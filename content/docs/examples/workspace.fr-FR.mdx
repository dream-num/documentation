**Univer Espace de travail** est un espace de travail bureau open-source construit sur **[Univer Office SDK](/overview)**, dans lequel les personnes et les agents travaillent ensemble. Le contenu de bureau modifiable et les applications Web liées aux données sont organisés en espaces personnels et d'équipe, ainsi que le partage, la collaboration, les versions, et l'examen du changement. [dépôt source](https://github.com/dream-num/univer-workspace) contient l'application, la configuration de déploiement, le CLI, et le client de bureau.

Vous pouvez déployer Workspace sur votre propre infrastructure ou commencer avec le [essai en nuage](https://space.univer.ai). Un agent existant se connecte à travers Workspace CLI. Workspace Desktop apporte une conversation d'agent et le même espace de travail dans une application locale. Toutes ces routes fonctionnent sur le même service et les mêmes fichiers.

<span id="web-start" />

Le service Workspace est déjà en cours, de sorte qu'un agent peut également se connecter à celui-ci via le CLI décrit ci-dessous. L'essai est destiné aux données d'échantillon, et ces données peuvent être réinitialisées.

**Serveur d'espace de travail** gère l'identité, les espaces, les permissions, le stockage, la collaboration et les versions. **Site Web** est l'interface du navigateur pour l'édition et la révision.

## Connecter votre agent au Workspace cloud [#cli-start]

Installez le CLI et la découverte Skill dans l'environnement où votre agent fonctionne. Node.js 22.12 ou plus récent est nécessaire, et Node.js 24 est recommandé. Un agent qui peut exécuter des commandes utilise ces outils tout en continuant à fournir son propre modèle et conversation.

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>Première connexion : se connecter une fois dans le navigateur</summary>

Cette étape peut être ignorée lorsqu'une session valide existe déjà. Si une connexion est requise, exécutez :

```bash
uvw auth login
```

Ouvrez le lien retourné, connectez-vous et validez le code dans le navigateur. Après que l'utilisateur confirme l'achèvement, exécutez :

```bash
uvw auth login --complete
```

Cette étape n'est requise que lors de l'établissement d'une session. Le [Guide de l'ICL sur l'espace de travail](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md) documente l'ensemble complet de la commande et l'authentification.

</details>

Après que le navigateur autorise la CLI une fois, la CLI réutilise cette session pour des tâches ultérieures. Aucune page de connexion ou intégration d'authentification spécifique à un agent n'est requise. Donnez à l'agent connecté une tâche, puis ouvrez le lien qu'il retourne dans Web : le contenu est le même, et les modifications natives Office de l'Agent peuvent être examinées avant la fusion.

### Commencer avec un document calculable et révisable [#first-task]

```text
Crée dans mon espace personnel Workspace une feuille de dépenses mensuelles en anglais avec dates, catégories, montants et cinq exemples. Ajoute un total par formule et un graphique par catégorie.
```

## Transposer le même parcours sur votre infrastructure [#self-host]

Le [dépôt open-source](https://github.com/dream-num/univer-workspace) contient le serveur et le Web. Construisez l'application avec le [guide de déploiement](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker), puis configurez le domaine, connectez-vous, stockage persistant et paramètres d'exécution. Le développement à partir de la source utilise Node.js 24 et pnpm 11; le guide maintient les détails de déploiement de la production.

Avant le déploiement, préparer quatre parties :

| Élément | Configuration |
| --- | --- |
| Service | Une URL de Workspace accessible et l'application Server + Web. Desktop et CLI se connectent à ce déploiement. |
| Données persistantes | La base de données produit, la base de données de collaboration et les fichiers téléchargés, conservés ensemble. Le déploiement par défaut les stocke sous `.data`; pour Docker, monter un volume persistant. |
| Identité | Configurez l'ouverture de session. Lorsque Desktop se connecte, enregistrez le client Agent OAuth avec une URL de rappel exacte. |
| Licence SDK | Fournissez `VITE_UNIVER_LICENSE` lors de la construction du Web pour le domaine de déploiement, et configurez séparément la licence requise par le contenu Node.js. |

Les identifiants de modèle appartiennent à l'hôte Agent et sont configurés séparément à partir de la connexion Workspace. Les [guide de déploiement](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) et [Configuration de l'agent](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md) décrivent les paramètres actuels.

Configurer le même CLI pour utiliser le déploiement privé et autoriser un compte sur ce service. Remplacer l'adresse d'exemple ci-dessous par l'origine du service :

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

L'agent conserve les mêmes outils et compétences et fonctionne maintenant sur les fichiers et les autorisations du service privé. Desktop peut également se connecter à ce service. Le [Guide de connexion de l'agent](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) documente l'enregistrement client et la configuration de callback.

## Retrouver Workspace dans un client Desktop local [#desktop-start]

**Bureau de l'espace de travail** combine Workspace, un agent runtime, des outils Office et des prévisualisations de contenu dans un client local. Le travail de bureau suit le modèle de conversation et de prévisualiser familier de Codex ou de Cowork : décrire le résultat souhaité, inspecter le document ou l'application Web à côté de la conversation, demander une révision et examiner le résultat.

Desktop peut se connecter au cloud Workspace décrit ci-dessus, à un déploiement privé, ou à un service Workspace fonctionnant sur la machine locale. Modèles et conversations passent par l'hôte d'agent configuré, tandis que le Workspace connecté gère les fichiers et l'accès. Les exemples de bureau ci-dessous montrent comment la création, la gestion et la collaboration se connectent.

[Installer et connecter](#desktop-install) · [Première tâche : réviser un budget avec deux documents](#desktop-first-task)

### Un workflow d’agent pour le travail Office quotidien [#why-desktop]

Le travail de bureau continue après une conversation renvoie un fichier téléchargeable. Les gens continuent à éditer, calculer à partir de données réelles, travailler avec des coéquipiers, et décider quels changements accepter. Desktop place ces activités dans un environnement de travail.

- Les conversations, fichiers, références locales et matériel Workspace **Conservez le contexte :** restent disponibles.
- **Contenu Office natif et Web Apps :** créer, prévisualiser et modifier des feuilles de calcul, documents, présentations, Relational Tables et Canvases, ainsi que des pages interactives fondées sur les données Office.
- **Voir et réviser le résultat:** ouvre le contenu à côté de la conversation, inspecte les formules et la mise en page, puis demande un changement spécifique.
- **Exécuter par l'examen :** les modifications natives Office de l'Agent restent dans un Worktree jusqu'à ce qu'une personne les examine et les fusionne dans l'espace de travail partagé.

### Installer et connecter [#desktop-install]

Si un bureau d'agent extensible est déjà utilisé, le chemin d'intégration est d'installer et d'activer le plugin de capacité Espace, de se connecter depuis Space, de configurer le modèle et d'ajouter une peau de marque. Les captures d'écran sur cette page utilisent cette composition. La version complète de Workspace Desktop et l'aperçu du plugin suivent des chemins de livraison séparés; utilisez la version publiée ou les instructions du dépôt pour la version installée.

1. Choisissez un installateur de bureau à partir de [GitHub sort](https://github.com/dream-num/univer-workspace/releases). Desktop libère l'utilisation des balises agent-v, alors sélectionnez l'artefact Windows x64, macOS Apple Silicon ou Linux x64 pour votre machine. La livraison de bureau est expérimentale, et la disponibilité suit les versions publiées.

2. Dans **Paramètres → Espace de travail**, choisissez le service Workspace, connectez-vous par le navigateur et autorisez l'accès. Connectez-vous à un service déployé ou suivez [configuration locale](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) pour exécuter un service localement.

3. Dans les paramètres Models, configurer un fournisseur, un modèle et des identifiants pris en charge. L'accès à l'espace de travail et au modèle sont configurés séparément; voir [configuration du modèle](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Ajoutez un espace personnel ou d'équipe accessible, commencez une conversation et utilisez @ pour le matériel source de référence. Exécutez la tâche ci-dessous, puis ouvrez l'aperçu du contenu et la revue de changement.

L'installateur comprend l'application agent et les outils Office. Le service Workspace fonctionne séparément, localement ou à distance, et l'accès au modèle utilise le fournisseur configuré.

### Skills : comprendre l’espace et réaliser les tâches [#skills]

#### Skills pour votre agent

Le [Compétence `univer-workspace-cli`](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) installé dans l'agent existant est le point d'entrée de la découverte. Le plugin de capacité intégré dans Desktop fournit également des conseils et des outils de tâches.

| Guide | Couverture |
| --- | --- |
| `core` | Localiser des espaces et des fichiers, travailler dans des ébauches de tâches, vérifier le contenu, et remettre pour examen. |
| `sheet` · `doc` · `slide` · `base` · `board` | Feuilles de calcul, documents, présentations, Relational Table et Canvases. |

```bash
uvw skills list

uvw skills get html-view
```

Chargez d'abord `core`, puis le produit ou le sujet requis par la tâche. `skills get` liste les chemins de référence; lisez un document avec `uvw skills read <name> <path>` ou ajoutez `--full` pour les lire tous. ### Comment Office SDK fait fonctionner Workspace [#desktop-architecture]

Workspace connecte les éditeurs natifs, les opérations de contenu d'agent et la collaboration d'équipe aux mêmes documents et permissions. Les agents opèrent sur le contenu de Node.js par l'intermédiaire de la CLI ou du Bureau, et les gens le voient, l'éditent et le examinent dans l'éditeur Web ou du Bureau. Workspace Server stocke des documents partagés, des brouillons et l'état de collaboration, et il peut fonctionner localement, sur des serveurs privés ou dans le cloud.

#### D’une modification de l’agent à une revue [#agent-editing-flow]

Dans l'exemple de budget-révision, l'agent modifie un tableur qui contient des formules et des styles. Le chemin d'édition natif Office procède comme suit:

1. **Localiser et charger.** L'agent sélectionne le document et Worktree, charge l'instantané et les modifications, et synchronise la révision sélectionnée. Une unité est une instance de document, comme un cahier de travail.
2. **Éditer par Facade.** L'exécution Node.js exécute des appels publics Facade contre cette unité. Les modifications de contenu produisent des mutations, qui sont collectées dans un ensemble de modifications et soumises à l'ébauche.
3. **Vérifiez le résultat.** L'agent lit les valeurs et les formules en retour et inspecte la sortie rendue si nécessaire. L'édition se poursuit dans la même ébauche jusqu'à ce que le résultat soit prêt à être examiné.
4. **Relire et fusionner.** Une personne examine les différences avec [Compare](/overview/features/shared/compare) et décide de fusionner le [Worktree](/ai/worktree) dans la version partagée.

**L'enregistrement d'un jeu de changements dans un projet ne le fusionne pas.** Workspace rapporte un écrit comme réussi seulement après la confirmation de la soumission; conflits et les soumissions non confirmées retournent des erreurs. Dans le plugin Desktop, les outils de fusion et de rejet nécessitent également l'approbation de l'utilisateur, ce que le workflow de l'outil de l'application fait appliquer.

#### Relier les Web Apps aux mêmes données Office [#web-app-data-flow]

Le tableau de bord de lancement utilise le même table de calcul que l'éditeur de budget. HTML View rend la page dans un iframe sandboxed. L'hôte Workspace résout les documents sources que l'utilisateur peut accéder et fournit leurs moteurs de contenu autorisés.

Lorsque l'utilisateur quitte la page, l'hôte attend la confirmation d'écriture et de collaboration en attente, et il signale les échecs d'enregistrement. L'édition et la reliure HTML des pages écrit utilisent leurs propres chemins de sauvegarde et ne suivent pas automatiquement le flux de fusion natif Office Worktree. Voir [fixation des données expérimentales](/overview/features/shared/binding) et [Mise en œuvre de l'hôte de la vue HTML](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer) .

#### Exemple : ajouter un Skill de revue budgétaire [#domain-skill]

Une compétence de domaine peut encoder les règles d'examen de l'équipe tout en réutilisant les outils Office existants :

- Localisez le cahier de travail source, la période et les colonnes du budget/réel, et demandez-vous toute définition d'entreprise manquante avant de modifier.
- Charger le guide des feuilles de calcul, créer un Worktree, mettre à jour les formules avec Facade et préparer le document de revue.
- Vérifiez les totaux, les résultats de la formule et la présentation, signalez les fichiers modifiés et les vérifications effectuées, puis remettez l'ébauche à une personne pour examen.

Pour connecter un ERP ou un CRM, ajoutez un outil d'application qui retourne les données requises et réutiliser le même flux d'édition et d'examen Office. Une exécution de Skills guide; il ne permet pas d'accéder à un fichier.
