Univer Workspace est une application Office open source fondée sur **[Univer Office SDK](/docs/overview)** pour les personnes et agents. Déployez l’édition en ligne **Server et Web**, puis connectez vos agents via **Workspace CLI + Skills**.

[Workspace + agent](#workspace-context) · [Édition en ligne](#entry-points) · [Connecter votre agent](#cli-start) · [Desktop](/docs/examples/workspace-desktop) · [Skills](#skills)

## Les fichiers partagés donnent le contexte de travail [#workspace-context]

![Les fichiers partagés donnent le contexte de travail](/assets/examples/workspace-desktop/workspace-overview.jpg)

Le Space Aurora réunit un modèle opérationnel avec des formules, une note de décision, une présentation, un registre de tâches et un canevas stratégique. Web et Desktop se connectent aux mêmes fichiers partagés. L’agent lit les sources et prépare les modifications dans un Worktree ; un nouveau document reste dans le brouillon jusqu’à ce qu’une personne approuve la fusion. Consultez la [conversation et l’aperçu dans Desktop](/docs/examples/workspace-desktop#conversation-preview) pour ce même exemple.

## Workspace CLI : connecter tout agent à votre espace [#cli-start]

Une fois l’édition en ligne déployée, une intégration Office par agent n’est plus nécessaire. Installez la CLI et le Skill dans son environnement. Un agent capable d’exécuter des commandes peut chercher des fichiers, créer, modifier, calculer, capturer, vérifier et fournir des liens de revue. L’agent choisi conserve le modèle et la conversation.

Utilisez Node.js 22.12 ou ultérieur, de préférence 24. Le paquet npm `univer-workspace-cli` fournit les commandes `uvw` et `univer-workspace-cli` pour le même programme.

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
```

La connexion par défaut est la démonstration. Pour votre déploiement, définissez l’adresse du service :

```bash
uvw config set workspace.origin https://space.univer.ai
```

Suivez une fois la procédure de connexion de la CLI. Elle gère ensuite la session, réutilisable entre les tâches. Vous n’avez pas à créer de page de connexion, de callback OAuth ni d’intégration d’authentification propre à chaque agent.

<details>

<summary>Première connexion : se connecter une fois dans le navigateur</summary>

Ignorez cette étape si une session valide existe déjà. Sinon, exécutez :

```bash
uvw auth login
```

Ouvrez le lien, connectez-vous et confirmez le code dans le navigateur. Après confirmation explicite de l’utilisateur, exécutez :

```bash
uvw auth login --complete
```

Cette étape établit la session. Les commandes et détails figurent dans le [guide Workspace CLI](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md).

</details>

## Skills : comprendre l’espace et réaliser les tâches [#skills]

Le [Skill `univer-workspace-cli`](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) installé dans votre agent sert de point de découverte : connexion, identification de la cible et chargement des guides. Les Skills complets sont livrés avec la CLI et correspondent à ses commandes et API Facade. Le plugin intégré de Desktop fournit aussi des guides et outils orientés tâches.

| Guide | Couverture |
| --- | --- |
| `core` | Espaces et fichiers, brouillons de tâche, vérification et remise pour revue. |
| `sheet` · `doc` · `slide` · `base` · `board` | Feuilles de calcul, documents, présentations, Relational Table et Canvases ; Base et Board restent les noms SDK/API. |
| `blob` | Télécharger, importer et remplacer les fichiers d’origine. |
| `html-view` | Créer et gérer des pages HTML actives pour des Web Apps interactives. |
| `embed` · `cross-unit-formula` | Intégrer des contenus et relier données et formules entre contenus. |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

Chargez `core`, puis le produit ou sujet utile. `skills get` liste les références ; `uvw skills read <name> <path>` lit un document et `--full` les inclut ensemble. Les agents existants passent par la CLI ; Desktop intègre outils et guides à la conversation.

## Commencer avec un document calculable et révisable [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Crée dans mon espace personnel Workspace une feuille de dépenses mensuelles en anglais avec dates, catégories, montants et cinq exemples. Ajoute un total par formule et un graphique par catégorie.
Garde les modifications dans un brouillon isolé, vérifie données, formules et rendu, puis donne-moi un lien d’aperçu ou de revue. Ne fusionne pas avant ma confirmation.
```

</div>

Envoyez cette tâche à un agent connecté ou utilisez Desktop. L’agent crée et vérifie ; vous demandez des retouches, révisez et décidez de fusionner. Vous pouvez ouvrir le même contenu dans l’édition en ligne.

## Des documents Office aux Web Apps [#web-apps]

Au-delà des feuilles, documents, présentations, tables relationnelles et canevas, demandez des Web Apps basées sur ces contenus : tableaux de bord, rapports interactifs, simulateurs budgétaires ou pages métier. HTML Views et la liaison bidirectionnelle relient indicateurs, graphiques, champs et curseurs aux feuilles. La page modifie les données, leurs changements reviennent dans la page, avec une collaboration possible.

```text
À partir de la feuille de dépenses créée, construis un tableau de bord Web App avec total, graphique par catégorie et champ de budget. Lie affichage et saisie aux données de la feuille, vérifie les deux sens et donne-moi les accès d’aperçu et de revue.
```

</div>

Regardez la [démonstration de mini-app](https://youtu.be/4PBVltY_WEc) ou découvrez la [liaison bidirectionnelle expérimentale](/docs/features/shared/binding).

## Relier demande, changements et révision

Workspace CLI fournit aussi `uvw issue` et `uvw pr`. Les Issues portent demandes et discussions ; les PR portent les changements à réviser et reposent sur des Worktrees. L’agent peut lire la tâche, modifier le contenu natif, le vérifier et transmettre les changements à une personne, reliant demandes d’équipe et livrables Office.

## Examiner le brouillon avant de décider de la fusion [#agent-review]

La révision native de Desktop présente côte à côte le contenu partagé et les changements proposés. Ouvrez le même brouillon dans Workspace pour examiner son état Ready, les fichiers modifiés et la vue native du document. Utilisez View et Compare avant de décider de la fusion. La fin d’une tâche de l’agent ne modifie pas automatiquement les fichiers sources partagés.

## Le rôle d’Office SDK [#sdk-integration]

Web SDK apporte modèle partagé, éditeurs, rendu et traitement sans interface ; Server SDK, collaboration, versions et Worktrees ; AI SDK, opérations et vérification pour les agents. Workspace en fait un Server et une application en ligne déployables. La CLI les ouvre aux agents existants, et Desktop les réunit dans une application Office avec agent.
