**Univer Workspace** transforme **[Univer Office SDK](/overview)** en un espace de travail open source pour les personnes et les agents. Il réunit contenus Office modifiables et Web Apps liées aux données dans des Spaces personnels ou partagés, avec collaboration, versions et revue des changements. Le [dépôt](https://github.com/dream-num/univer-workspace) comprend application, déploiement, CLI et client de bureau.

Déployez-le sur votre infrastructure ou commencez par [l’essai cloud](https://space.univer.ai). Votre agent se connecte via Workspace CLI ; Workspace Desktop réunit conversation et espace de travail dans une application locale. Tous utilisent le même service et les mêmes fichiers.

## Commencer par Workspace dans le cloud [#entry-points]

<span id="web-start" />

Ouvrez [l’essai cloud](https://space.univer.ai), connectez-vous et entrez dans votre Space personnel ou un Space d’équipe accessible. Créez, modifiez, organisez et partagez des documents. La CLI ci-dessous peut également connecter un agent à ce service. Utilisez des données d’exemple : les données de l’essai peuvent être réinitialisées.

**Workspace Server** gère identité, Spaces, permissions, stockage, collaboration et versions. **Web** fournit l’interface de modification et de revue dans le navigateur. Un déploiement privé utilise la même application Server et Web.

## Connecter votre agent au Workspace cloud [#cli-start]

Installez la CLI et la Skill de découverte dans l’environnement de votre agent. Node.js 22.12 ou ultérieur est requis ; la version 24 est recommandée. Un agent capable d’exécuter des commandes conserve son modèle et sa conversation. Définissez explicitement le service cloud pour utiliser le même Workspace dans le navigateur et avec l’agent :

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>Première connexion : se connecter une fois dans le navigateur</summary>

Ignorez cette étape si une session valide existe déjà. Sinon, exécutez :

```bash
uvw auth login
```

Ouvrez le lien, connectez-vous et confirmez le code dans le navigateur. Après confirmation explicite de l’utilisateur, exécutez :

```bash
uvw auth login --complete
```

Cette étape établit la session. Les commandes et détails figurent dans le [guide Workspace CLI](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md).

</details>

Après la première autorisation dans le navigateur, la CLI réutilise la session. Aucune page de connexion ou intégration d’authentification propre à chaque agent n’est nécessaire. Confiez-lui une tâche, puis ouvrez son lien dans Web pour examiner le contenu et revoir les modifications Office avant fusion.

### Commencer avec un document calculable et révisable [#first-task]

Crée dans mon espace personnel Workspace une feuille de dépenses mensuelles en anglais avec dates, catégories, montants et cinq exemples. Ajoute un total par formule et un graphique par catégorie.

## Transposer le même parcours sur votre infrastructure [#self-host]

Le [dépôt open source](https://github.com/dream-num/univer-workspace) inclut Server et Web. Suivez le [guide de déploiement](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) pour configurer domaine, connexion, stockage persistant et environnement. Le développement utilise Node.js 24 et pnpm 11.

Pointez la même CLI vers votre service et autorisez un compte de ce service. Remplacez cette adresse d’exemple par votre adresse réelle :

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

L’agent conserve outils et Skills ; il utilise désormais les fichiers et permissions de votre service privé. Desktop peut aussi s’y connecter. Consultez le [guide de connexion Agent](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) pour l’enregistrement du client et les callbacks.

## Retrouver Workspace dans un client Desktop local [#desktop-start]

**Workspace Desktop** réunit Workspace, environnement d’agent, outils Office et aperçus dans un client local. L’expérience rappelle Codex ou Cowork : décrivez un objectif, examinez le document ou la Web App à côté de la conversation, demandez une révision et validez le résultat.

Connectez Desktop au cloud, à un déploiement privé ou à un service Workspace local. L’hôte de l’agent fournit modèle et conversation ; le Workspace connecté gère fichiers et accès. Les exemples réels suivants relient création, gestion et collaboration.

[Installer et connecter](#desktop-install) · [Première tâche : réviser un budget avec deux documents](#desktop-first-task)

### Un workflow d’agent pour le travail Office quotidien [#why-desktop]

Les livrables Office doivent rester modifiables, calculables et accessibles à l’équipe. Desktop réunit conversation, édition, collaboration et revue des changements dans le même environnement.

- **Conserver le contexte :** conversations, fichiers, sources Workspace et références locales restent disponibles.
- **Créer du contenu Office et des Web Apps :** générer des feuilles, documents, présentations, Relational Table et Canvases modifiables, ainsi que des pages interactives fondées sur leurs données.
- **Voir puis ajuster :** ouvrir le résultat à côté du chat, vérifier les formules et la mise en page, demander une correction précise.
- **Livrer après revue :** conserver les changements Office dans un Worktree et les fusionner dans l’espace partagé après vérification humaine.

### De la demande au livrable révisable [#workflow]

Créez et modifiez des documents Office et des Web Apps dans les conversations normales, puis gérez-les et partagez-les dans Space. Les changements Office natifs sont examinés dans un Worktree avant fusion. Publication HTML et écritures liées suivent leurs propres règles de sauvegarde et d’accès. Les conversations suivantes peuvent reprendre les mêmes fichiers et données.

### Ce que le bureau réunit

| Fonction | Expérience |
| --- | --- |
| Sessions agent | Conversations et contexte, avec fournisseurs, modèles et identifiants configurés localement. |
| Fichiers et références | Espaces autorisés ; @ référence les fichiers et dossiers Workspace ou les sources locales. |
| Aperçu du contenu | Ouvrir les fichiers Office natifs ou les Web Apps à côté du chat pour vérifier contenu, interactions et données. |

| Gestion et collaboration dans Space | Organiser les fichiers créés dans la conversation, gérer leur partage et modifier le même contenu en équipe. |

### Installer et connecter [#desktop-install]

Avec un bureau d’agents extensible, installez et activez Space, connectez le service depuis Space, configurez le modèle puis ajoutez l’identité visuelle. Les captures utilisent cette composition. Desktop complet et plugin d’aperçu ont des modes de distribution différents ; suivez la publication ou les instructions du dépôt de votre version.

1. Choisir Desktop dans [GitHub Releases](https://github.com/dream-num/univer-workspace/releases), sous les tags agent-v, pour Windows x64, macOS Apple Silicon ou Linux x64. Cette distribution est expérimentale ; vérifier les versions réellement publiées.

2. Dans **Settings → Workspace**, choisir le service, se connecter dans le navigateur et autoriser l’accès. Utiliser un service déployé ou la [configuration locale](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace).

3. Configurer un fournisseur, un modèle et les identifiants pris en charge dans Models. La connexion Workspace est distincte : voir la [configuration des modèles](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Ajouter un espace personnel ou d’équipe accessible, commencer une conversation et référencer les sources avec @. Essayer la tâche ci-dessous puis ouvrir aperçu et revue.

L’installeur fournit l’application agent et les outils Office. Le service Workspace s’exécute séparément, localement ou sur un serveur ; l’accès au modèle doit être configuré.

### Skills : comprendre l’espace et réaliser les tâches [#skills]

#### Skills pour votre agent

Le [Skill `univer-workspace-cli`](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) installé dans votre agent sert de point de découverte : connexion, identification de la cible et chargement des guides. Les Skills complets sont livrés avec la CLI et correspondent à ses commandes et API Facade. Le plugin intégré de Desktop fournit aussi des guides et outils orientés tâches.

| Guide | Couverture |
| --- | --- |
| `core` | Espaces et fichiers, brouillons de tâche, vérification et remise pour revue. |
| `sheet` · `doc` · `slide` · `base` · `board` | Feuilles de calcul, documents, présentations, Relational Table et Canvases ; Base et Board restent les noms SDK/API. |
| `blob` | Télécharger, importer et remplacer les fichiers d’origine. |
| `html-view` | Créer et gérer des pages HTML actives pour des Web Apps interactives. |
| `embed` · `cross-unit-formula` | Intégrer des contenus et relier données et formules entre contenus. |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

Chargez `core`, puis le produit ou sujet utile. `skills get` liste les références ; `uvw skills read <name> <path>` lit un document et `--full` les inclut ensemble. Les agents existants passent par la CLI ; Desktop intègre outils et guides à la conversation.

### Séparer la boucle de l’agent des capacités Office [#desktop-architecture]

Les Skills guident l’agent, les outils manipulent le contenu structuré via Headless et les éditeurs natifs le rendent accessible aux personnes. Workspace fournit fichiers et contexte collaboratif.
