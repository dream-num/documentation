**Рабочее пространство Univer** - это рабочее пространство Office с открытым исходным кодом, построенное на **[Univer Office SDK](/overview)**, в котором люди и агенты работают вместе. Редактируемый контент Office и веб-приложения, связанные с данными, организованы в личные и командные пространства вместе с обменом, сотрудничеством, версиями и обзором изменений. [Источник репозитория](https://github.com/dream-num/univer-workspace) содержит приложение, конфигурацию развертывания, CLI и настольный клиент.

Можно развернуть Workspace на собственной инфраструктуре или начать с [облачный тест](https://space.univer.ai). Существующий агент подключается через Workspace CLI. Workspace Desktop приносит в локальное приложение разговор агента и то же рабочее пространство. Все эти маршруты работают на одном сервисе и одних и тех же файлах.

## Подключите своего агента к облачному Workspace [#cli-start]

Установите CLI и Discovery Skill в среде, где работает ваш агент. Требуется Node.js 22.12 или новее, и рекомендуется Node.js 24. Агент, который может выполнять команды, использует эти инструменты, продолжая предоставлять свою собственную модель и разговор. Установите облачный сервис явно так, чтобы браузер и агент работали в одном рабочем пространстве:

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>Первое подключение: один вход в браузере</summary>

Этот шаг можно пропустить, когда уже существует действительный сеанс. Если требуется вход, запустите:

```bash
uvw auth login
```

Откройте обратную ссылку, войдите и подтвердите код в браузере. После того, как пользователь подтвердит завершение, запустите:

```bash
uvw auth login --complete
```

Этот шаг требуется только при установлении сеанса. [Руководство Workspace CLI](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md) документирует полный набор команд и аутентификацию.

</details>

После того, как браузер авторизует CLI один раз, CLI повторно использует этот сеанс для более поздних задач. Не требуется никакой страницы входа в систему или интеграции аутентификации для конкретного агента. Дайте подключенному агенту задачу, а затем откройте ссылку, которую он возвращает в Интернете: контент тот же, и изменения нативного офиса агента могут быть рассмотрены перед слиянием.

## Перенесите тот же процесс в свою инфраструктуру [#self-host]

[репозиторий с открытым исходным кодом](https://github.com/dream-num/univer-workspace) содержит Server и Web.Создайте приложение с помощью [Руководство по развертыванию](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker), затем настройте домен, вход, постоянное хранилище и настройки времени выполнения.Разработка из источника использует Node.js 24 и pnpm 11; руководство поддерживает детали развертывания производства.

Перед развертыванием подготовьте четыре части:

| Составляющая | Что настроить |
| --- | --- |
| Сервис | Доступный URL рабочего пространства и веб-приложение Server +. Настольный компьютер и CLI подключаются к этому развертыванию. |
| Постоянные данные | База данных продуктов, база данных совместной работы и загруженные файлы сохранялись вместе.Развертывание по умолчанию хранит их под `.data`; для Docker установите постоянный том. |
| Идентификация | Настройка входа. Когда Desktop подключается, зарегистрируйте клиент Agent OAuth с точным соответствием URL обратного вызова. |
| Лицензия SDK | Обеспечить `VITE_UNIVER_LICENSE` при создании Web для домена развертывания и настроить лицензию, требуемую временем выполнения контента Node.js, отдельно. |

Модели учетных данных принадлежат хосту Агента и настроены отдельно от входа в Workspace. [Руководство по развертыванию](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) и [Подстава агента](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md) описывают текущие настройки.

Настройте тот же CLI для использования частного развертывания и авторизации учетной записи в этой службе. Замените приведенный ниже примерный адрес фактическим происхождением службы:

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

Агент хранит те же инструменты и навыки и теперь работает с файлами и разрешениями частной службы. Настольный компьютер также может подключиться к этой службе. [Руководство по подключению агентов](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) документирует регистрацию клиента и конфигурацию обратного вызова.

## Откройте Workspace в локальном клиенте Desktop [#desktop-start]

**Рабочий стол Workspace** сочетает в себе Workspace, время выполнения агента, инструменты Office и предварительные просмотры контента в одном локальном клиенте. Работа Office следует шаблону разговора и предварительного просмотра, знакомому из Codex или Cowork: опишите желаемый результат, проверьте документ или веб-приложение рядом с разговором, запросите пересмотр и просмотрите результат.

Настольный компьютер может подключаться к описанному выше облаку Workspace, к частному развертыванию или к службе Workspace, работающей на локальной машине. Модели и разговоры проходят через настроенный хост-агент, в то время как подключенное Workspace управляет файлами и доступом. Примеры рабочего стола ниже показывают, как подключаются создание, управление и совместная работа.

[Установка и подключение](#desktop-install) · [Первая задача: ревью бюджета в двух документах](#desktop-first-task)

### Агентный процесс для повседневной Office-работы [#why-desktop]

Офисная работа продолжается после того, как разговор возвращает загружаемый файл. Люди продолжают редактировать, вычислять по реальным данным, работать с товарищами по команде и решать, какие изменения принять. Настольный компьютер размещает эти действия в одной рабочей среде.

- Разговоры **Сохраняйте контекст:**, файлы, локальные ссылки и материалы Workspace остаются доступными.
- **Нативный Office-контент и Web Apps:** создавайте, просматривайте и редактируйте таблицы, документы, презентации, Relational Tables и Canvases, а также интерактивные страницы на основе данных Office.
- **Смотрите и пересматривайте результат:** открывает контент рядом с разговором, проверяет формулы и макет, а затем запрашивает конкретные изменения.
- **Провести через обзор:** изменения в офисе агента остаются в Worktree до тех пор, пока человек не проверит их и не объединит их в общее рабочее пространство.

### От запроса к результату для ревью [#workflow]

### Установка и подключение [#desktop-install]

Если рабочий стол расширяемого агента уже используется, путь интеграции заключается в установке и включении плагина возможностей Space, подключении из Space, настройке модели и добавлении скина бренда. Скриншоты на этой странице используют эту композицию. Полный выпуск рабочего стола Workspace и предварительный просмотр плагина следуют отдельным путям доставки; используйте опубликованный выпуск или инструкции репозитория для установленной версии.

1. Выберите установщик рабочего стола из [GitHub выпустили](https://github.com/dream-num/univer-workspace/releases). В релизах рабочего стола используются теги agent-v, поэтому выберите Windows x64, macOS Apple Silicon или Linux x64 для вашей машины. Доставка рабочего стола является экспериментальной, а доступность следует за опубликованными релизами.

2. В **Настройки → Рабочее пространство** выберите службу Workspace, войдите через браузер и авторизуйте доступ.Подключитесь к развернутой службе или следуйте за [локальная установка](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) для запуска службы локально.

3. В настройках моделей настройте поддерживаемого провайдера, модель и учетные данные. Вход в рабочее пространство и доступ к модели настроены отдельно; см. [конфигурация модели](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Добавьте доступное личное или командное пространство, начните разговор и используйте @ для ссылки на исходный материал. Запустите задачу ниже, затем откройте предварительный просмотр контента и обзор изменений.

Установщик включает в себя приложение агента и инструменты Office.Сервис Workspace работает отдельно, локально или удаленно, а модельный доступ использует настроенный провайдер.

### Skills: от понимания пространства до выполнения задачи [#skills]

Эти навыки позволяют существующему агенту создавать и редактировать контент Office и веб-приложения в подключенном рабочем пространстве, а затем передавать изменения для просмотра. [Подключите агента к рабочему пространству](#cli-start); приведенное ниже руководство работает с файлами и разрешениями этой службы.

#### Skills для вашего агента

[Навыки `univer-workspace-cli`](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md), установленный в существующем агенте, является точкой входа обнаружения. Он объясняет, как подключать, находить цель и загружать операционное руководство. Полный корабль навыков выполнения с CLI и соответствовать его командам и API Facade. Встроенный плагин возможностей в Desktop также обеспечивает руководство задачами и инструментами.

| Инструкция | Охват |
| --- | --- |
| `core` | Поиск Пространств и файлов, работа в черновиках задач, проверка контента и передача для обзора. |
| `sheet` · `doc` · `slide` · `base` · `board` | Таблицы, документы, презентации, Relational Table и Canvases. |
| `blob` | Загрузка, загрузка и замена оригинальных файлов. |
| `html-view` | Создание и управление живыми HTML-страницами для интерактивных веб-приложений. |
| `embed` · `cross-unit-formula` | Встраивание другого контента и соединение данных и формул между типами контента. |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

Сначала загрузите `core`, затем продукт или тему, требуемые задачей. `skills get` перечисляет справочные пути; прочитайте один документ с `uvw skills read <name> <path>` или добавьте `--full` для чтения всех их. Существующие агенты используют эти возможности через CLI, тогда как Desktop интегрирует инструменты и руководство в рабочий процесс разговора.

### Как Office SDK обеспечивает работу Workspace [#desktop-architecture]

Workspace соединяет нативные редакторы, операции с контентом агентов и совместную работу с одними и теми же документами и разрешениями. Вы можете опираться на это приложение с открытым исходным кодом и на Office SDK и сосредоточить свои усилия на бизнес-процессах, интерфейсе и интеграции.

<Mermaid chart={"flowchart LR\nA[\"Agent\"] <--> S[\"Workspace Server\"] <--> E[\"Редакторы\"]"} />

Агенты работают с контентом в Node.js через CLI или Desktop, и люди просматривают, редактируют и просматривают его в редакторе Web или Deskton. Workspace Server хранит общие документы, черновики и состояние совместной работы, и он может работать локально, на частных серверах или в облаке.

| Слой | Ответственность |
| --- | --- |
| [Web SDK](/guides/sheets) | Модели контента, формулы, публичные Facade API и нативные редакторы. |
| [AI SDK](/ai/content-operations) | Поиск API, структурная проверка контента и выполнение Facade для указанного документа. |
| [Server SDK](/server) | Совместное редактирование, ревизии, черновики Worktree и преобразование файлов. |
| Приложение | Workspace управляет пространствами, файлами, правами, общим доступом и ревью. Хост агента отвечает за диалоги, вызовы модели и инструменты. |

CLI и Desktop совместно используют [Уровень контентных операций](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core). Его пул времени выполнения сохраняет загруженные документы живыми в течение всего срока службы хоста и синхронизирует версии перед выполнением. Поэтому разные клиенты повторно используют одну и ту же логику редактирования и представления. См. [использование Runtime](/ai/runtime-architecture) .

[Визуальный осмотр](/ai/visual-inspection) дополняет структурированные проверки.Скриншоты поступают от рендеринга браузера, а автоматическая диагностика макета в настоящее время обнаруживает переполнение и перекрытие текста в слайдах.

#### От правки агента к проверяемому изменению [#agent-editing-flow]

В примере с обзором бюджета агент редактирует электронную таблицу, содержащую формулы и стили. Нативный путь редактирования Office протекает следующим образом:

1. **Найти и загрузить.** Агент выбирает документ и Worktree, загружает снимки и изменения и синхронизируется с выбранной версией. Единица - это один экземпляр документа, такой как рабочая тетрадь.
2. **Редактировать через Фасад.** Среда выполнения Node.js выполняет публичные вызовы Фасада против этого блока. Изменения контента вызывают мутации, которые собираются в набор изменений и представляются в проект.
3. **Проверьте результат.** Агент считывает значения и формулы обратно и проверяет отданный результат при необходимости.Редактирование продолжается в том же проекте до тех пор, пока результат не будет готов к рассмотрению.
4. **Провести ревью и слияние.** Человек проверяет различия через [Compare](/overview/features/shared/compare) и решает, объединять ли [Worktree](/ai/worktree) с общей версией.

**Сохранение изменений в черновике не сливает его.** Workspace сообщает о записи как успешной только после подтверждения представления; конфликты и неподтвержденные представления возвращают ошибки.В плагине Desktop инструменты слияния и отбрасывания также требуют одобрения пользователя, что обеспечивает рабочий процесс инструмента приложения.

#### Как Web App подключается к тем же данным Office [#web-app-data-flow]

Панель запуска использует ту же электронную таблицу, что и редактор бюджета. HTML View отображает страницу в песочнице iframe. Хост Workspace разрешает исходные документы, к которым пользователь может получить доступ и поставляет свои авторизованные движки контента. Метрические карты и диаграммы подписываются на исходные данные, поэтому вторая копия бюджета не требуется.

Для редактируемых привязок запись требует подписанного идентификатора и разрешения на редактирование исходного документа. Когда пользователь покидает страницу, хост ждет отложенных записей и подтверждения совместной работы, и он сообщает о сохранении сбоев. HTML-страница, публикующая и привязывающая записи, использует свои собственные пути сохранения и автоматически не следует за нативным потоком слияния Office Worktree. См. [Связь экспериментальных данных](/overview/features/shared/binding) и [HTML View host реализация](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer) .

#### Пример: Skill для ревью бюджета [#domain-skill]

Навык домена может кодировать правила обзора команды при повторном использовании существующих инструментов Office:

- Найдите исходную книгу, период и столбцы «Бюджет/Актуальный» и спросите о любых недостающих бизнес-определениях перед редактированием.
- Загрузить руководство по таблицам, создать Worktree, обновить формулы через Facade и подготовить документ для ревью.
- Проверяйте итоговые данные, результаты формул и представление, сообщайте об изменённых файлах и выполненных проверках, а затем передайте черновик человеку для ознакомления.

Бизнес-правила и шаблоны относятся к Skill. В приложении остаются проверки доступа, сохранение проекта и согласование слияния. Для подключения ERP или CRM добавьте инструмент приложения, который возвращает необходимые данные и повторно использует тот же поток редактирования и обзора Office. Выполнение Skill направляет; он не предоставляет доступ к файлу.
