**Univer Workspace** turns **[Univer Office SDK](/overview)** into an open-source Office workspace for people and agents. It brings editable Office content and data-bound Web Apps into Personal and Team Spaces, with sharing, collaboration, versions, and change review. The [source repository](https://github.com/dream-num/univer-workspace) includes the application, deployment, CLI, and desktop client.

You can deploy Workspace on your own infrastructure, or start with the [cloud trial](https://space.univer.ai). Your existing agent connects through Workspace CLI; Workspace Desktop brings an agent conversation and the same workspace into a local application. These are ways to work with the same service and files.

## Start with the cloud Workspace [#entry-points]

<span id="web-start" />

Open the [cloud trial](https://space.univer.ai), sign in, and enter your Personal Space or an accessible Team Space. Create or open a document and try direct editing, file organization, and sharing. This is a running Workspace service: you can also connect an agent to it through the CLI below. Use sample data in the trial; its data may be reset.

**Workspace Server** owns identity, Spaces, permissions, storage, collaboration, and versions. **Web** is the browser interface for editing and review. A private deployment runs this same Server and Web application.

## Connect your existing agent to the cloud Workspace [#cli-start]

Install the CLI and discovery Skill where your agent runs. Node.js 22.12 or newer is required; Node.js 24 is recommended. An agent with command execution can use these tools while continuing to provide its own model and conversation. Set the cloud service explicitly so the browser and agent work in the same Workspace:

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>First connection: sign in once in the browser</summary>

Skip this when a valid session already exists. If sign-in is required, run:

```bash
uvw auth login
```

Open the returned link, sign in, and confirm the code in your browser. Only after the user confirms completion, run:

```bash
uvw auth login --complete
```

This step is needed when establishing a session. See the [Workspace CLI guide](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md) for full commands and authentication details.

</details>

After the first browser approval, the CLI reuses its session for later tasks. There is no agent-specific login page or authentication integration to build. Give the connected agent a task; open its returned link in Web to inspect the same content and review native Office changes before merging.

### Start with a document you can calculate and review [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Create an English monthly expense Sheet in my Personal Workspace Space with dates, categories, amounts, and five sample rows. Add a total formula and a chart by category.
Keep changes in an isolated draft, verify the data, formulas, and rendered result, and give me a preview or review link. Do not merge before I confirm.
```

</div>

Send this to a connected agent or use it in Desktop. The agent creates and verifies; you can request changes, review, and decide whether to merge. You can open the same content in the online edition.

## Move the same workflow to your own deployment [#self-host]

The [open-source repository](https://github.com/dream-num/univer-workspace) includes Server and Web. Follow the [deployment guide](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) to build the application and configure your domain, sign-in, persistent storage, and runtime settings. Source development uses Node.js 24 and pnpm 11; production deployment details are maintained in the guide.

Point the same CLI at your deployment and authorize an account there. Replace the example address below with your actual service origin:

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

Your agent keeps the same tools and Skills; it now operates the files and permissions of your private service. Desktop can connect to that service too. Follow the [Agent connection guide](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) for its client registration and callback configuration.

## Bring Workspace into a local Desktop client [#desktop-start]

**Workspace Desktop** combines Workspace, an agent runtime, Office tools, and content previews in a local client. It gives Office work the conversation-and-preview experience familiar from Codex or Cowork: describe an outcome, inspect the document or Web App beside the conversation, request a revision, and review the result.

Connect Desktop to the cloud Workspace you just tried, your private deployment, or a locally running Workspace service. The model and conversation run through the configured agent host; the connected Workspace remains responsible for files and access. The following real desktop examples show how creation, management, and collaboration connect.

[Install and connect](#desktop-install) · [Try a budget review with two native documents](#desktop-first-task)

### Bring the agent workflow to everyday Office work [#why-desktop]

Office work needs more than a conversation that returns a downloadable file. People need to keep editing, calculate with real data, work with teammates, and decide which changes to accept. Desktop keeps those steps in the same working environment.

- **Keep context:** conversations, files, local references, and Workspace material stay within reach.
- **Native Office content and Web Apps:** create, preview, and edit spreadsheets, documents, presentations, Relational Tables, and Canvases, and build interactive pages backed by Office data.
- **See and revise the result:** open content beside the conversation, inspect formulas and layout, then ask for a targeted change.
- **Deliver through review:** the agent’s native Office changes stay in a Worktree until reviewed and merged into the shared workspace.

<span id="connect-the-request-changes-and-review" />

### From a request to a reviewed deliverable [#workflow]

Generate and revise Office documents and Web Apps in normal conversations, then manage and share them in Space. Native Office changes use Worktree review before merging; HTML publication and binding writes use their own save and authorization flows. Later conversations can reference the same files and data.

### Install and connect [#desktop-install]

For an existing extensible agent desktop, the integration route is to install and enable the Space capability plugin, connect from Space, configure the model, and add a brand skin. The screenshots on this page use that composition. The full Workspace Desktop release and the plugin preview have separate delivery paths; use the published release or the repository setup instructions for the version you are installing.

1. Choose a Desktop installer from [GitHub Releases](https://github.com/dream-num/univer-workspace/releases). Desktop releases use agent-v tags; select the matching Windows x64, macOS Apple Silicon, or Linux x64 artifact. Desktop delivery is experimental; availability follows the published releases.

2. In **Settings → Workspace**, choose the Workspace service, sign in through the browser, and authorize access. You can connect to a deployed service or follow [local setup](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) to run one locally.

3. Configure a supported provider, model, and credentials in Models settings. Workspace sign-in and model access are separate; see [model configuration](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Add an accessible Personal or Team Space, start a conversation, and use @ to reference source material. Try the task below, then open its document preview and changes.

The installer packages the agent application and Office tools. The Workspace service runs separately, locally or remotely; configure model access for the provider you use.

### Skills: help agents understand the workspace and complete tasks [#skills]

Use these Skills to have your existing agent create and edit Office content and Web Apps in a connected Workspace, then hand off the changes for review. First [connect the agent to Workspace](#cli-start); the guidance below operates on the files and permissions of that service.

#### Skills for your existing agent

The [`univer-workspace-cli` Skill](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) installed in your existing agent is the discovery entry: it explains how to connect, locate the target, and load operational guidance. Full runtime Skills ship with the CLI and match its commands and Facade APIs. Desktop’s built-in capability plugin also provides task guidance and tools.

| Guidance | Coverage |
| --- | --- |
| `core` | Locate Spaces and files, work in task drafts, verify content, and hand off for review. |
| `sheet` · `doc` · `slide` · `base` · `board` | Spreadsheets, documents, presentations, Relational Table, and Canvases. |
| `blob` | Upload, download, and replace original files. |
| `html-view` | Create and manage live HTML pages for interactive Web Apps. |
| `embed` · `cross-unit-formula` | Embed other content and connect data and formulas across content types. |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

Load `core` first, then the product or topic needed for the task. `skills get` lists reference paths; use `uvw skills read <name> <path>` for a selected document or `--full` to include them together. Existing agents access these capabilities through the CLI, while Desktop integrates its tools and guidance into the conversation workflow.

#### Skills inside Desktop [#desktop-skills]

Desktop’s capability plugin includes the **univer** Skill and its references. It teaches the agent how Spaces and documents relate, how to use Office APIs, and how to create, verify, and deliver a Worktree. These instructions accompany executable tools; the agent can look up an API, run it against native content, and inspect the result.

The [capability plugin](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md) connects file discovery, headless Facade editing, structured inspection, import/export, and Worktree lifecycle tools. This preview prepares drafts for review; publishing uses the deployed application’s review and merge workflow. Your application can add domain Skills, templates, and business tools on the same Office runtime.

The preview plugin includes nine Skills. The common Skill explains discovery, identity, and delivery; product Skills provide API and verification guidance. The agent reads the relevant guidance for the current task.

| Skill | Guidance |
| --- | --- |
| `univer` | Spaces, files, draft lifecycle, and delivery |
| `univer-sheet` | Formulas, styles, charts, and spreadsheet verification |
| `univer-doc` | Document structure, paragraphs, and tables |
| `univer-slide` | Slide authoring and visual layout checks |
| `univer-base` | Fields, records, and views |
| `univer-board` | Shapes, connectors, and canvas layout |
| `univer-embed` | Embed one Office product inside another |
| `univer-cross-unit-formula` | Reference and calculate across Units |
| `univer-html-view` | Build and inspect HTML pages bound to Office data |

### Separate the agent loop from the Office capabilities [#desktop-architecture]

Skills guide the agent, tools operate structured content through the Headless runtime, and native editors render it for people. Workspace supplies the file and collaboration context. This separation lets you change the model, add business tools, or replace the brand without rebuilding an Office engine.

<Mermaid chart={"flowchart LR\nA[\"Agent + model\"]\nB[\"Skills + tools\"]\nC[\"Office SDK<br/>Headless operations + verification\"]\nD[\"Workspace service<br/>Files + collaboration + versions\"]\nE[\"Desktop preview<br/>Native editors + Web Apps\"]\nF[\"Worktree + Compare<br/>Human review\"]\nA --> B --> C --> D\nD <--> E\nD --> F\nF --> E"} />

| Part | Responsibility |
| --- | --- |
| [Web SDK](/guides/sheets) | Shared content models, editable Office views, rendering, formulas, and headless Facade operations. |
| [Server SDK](/server) | Collaboration, versions, and Worktree capabilities connected to the application’s backend. |
| [AI SDK](/ai) | Agent-oriented content operations and inspection/verification primitives. |
| Agent runtime and Skills | DSH provides sessions, model access, tool orchestration, and approval; the Workspace capability plugin connects Office tools and task guidance. |
| Workspace and Desktop | The application supplies Spaces, files, identity integration, and review UI; the Electron delivery makes that agent workspace available as a desktop app. |

This composition is the reusable pattern: request → tools → editable content → preview → review → shared delivery. The Office SDK supplies the Office layer; an agent host supplies the conversation and execution loop. You can extend the existing [application and plugins](https://github.com/dream-num/univer-workspace/tree/main/apps/agent), or connect the SDKs to your own host and business services.
