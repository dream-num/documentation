**Univer Workspace** convierte **[Univer Office SDK](/overview)** en un espacio de trabajo de código abierto para personas y agentes. Reúne contenido Office editable y Web Apps vinculadas a datos en Spaces personales y de equipo, con uso compartido, colaboración, versiones y revisión de cambios. El [repositorio](https://github.com/dream-num/univer-workspace) incluye la aplicación, el despliegue, la CLI y el cliente de escritorio.

Puedes desplegarlo en tu infraestructura o empezar con la [prueba en la nube](https://space.univer.ai). Tu agente se conecta mediante Workspace CLI; Workspace Desktop integra la conversación y el mismo espacio en una aplicación local. Son formas de trabajar con el mismo servicio y los mismos archivos.

## Empieza con Workspace en la nube [#entry-points]

<span id="web-start" />

Abre la [prueba en la nube](https://space.univer.ai), inicia sesión y entra en tu Space personal o en uno de equipo al que tengas acceso. Crea, edita, organiza y comparte documentos. También puedes conectar un agente a este servicio mediante la CLI que se explica a continuación. Usa datos de ejemplo: los datos de prueba pueden restablecerse.

**Workspace Server** gestiona identidad, Spaces, permisos, almacenamiento, colaboración y versiones. **Web** ofrece la interfaz de edición y revisión en el navegador. El despliegue privado utiliza esta misma aplicación Server y Web.

## Conecta tu agente al Workspace en la nube [#cli-start]

Instala la CLI y la Skill de descubrimiento donde se ejecuta tu agente. Se requiere Node.js 22.12 o posterior; se recomienda 24. Un agente que ejecuta comandos puede utilizar estas herramientas manteniendo su modelo y conversación. Configura el servicio de nube para trabajar con el mismo Workspace desde el navegador y el agente:

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>Primera conexión: iniciar sesión una vez en el navegador</summary>

Omite este paso si ya existe una sesión válida. Si necesitas iniciar sesión, ejecuta:

```bash
uvw auth login
```

Abre el enlace, inicia sesión y confirma el código en el navegador. Solo después de que el usuario confirme que ha terminado, ejecuta:

```bash
uvw auth login --complete
```

Este paso sirve para establecer la sesión. Consulta los comandos y detalles en la [guía de Workspace CLI](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md).

</details>

Tras la primera autorización en el navegador, la CLI reutiliza la sesión. No necesitas crear una integración de inicio de sesión para cada agente. Pídele una tarea, abre el enlace que devuelve y revisa el mismo contenido y los cambios Office antes de fusionarlos.

### Empieza con un documento que puedas calcular y revisar [#first-task]

```text
Crea una hoja de gastos mensuales en inglés en mi espacio personal Workspace con fechas, categorías, importes y cinco filas de ejemplo. Añade una fórmula de total y un gráfico por categoría.
Trabaja en un borrador aislado, verifica datos, fórmulas y aspecto, y dame un enlace de vista previa o revisión. No integres antes de mi confirmación.
```

## Lleva el mismo flujo a tu propio despliegue [#self-host]

El [repositorio](https://github.com/dream-num/univer-workspace) incluye Server y Web. Sigue la [guía de despliegue](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) y configura dominio, acceso, almacenamiento persistente y entorno. El desarrollo utiliza Node.js 24 y pnpm 11.

Prepara estos cuatro elementos antes del despliegue:

| Elemento | Configuración |
| --- | --- |
| Servicio | Una URL de Workspace accesible y la aplicación Server + Web. Desktop y la CLI se conectan a este despliegue. |
| Datos persistentes | Conserva juntas las bases de datos de producto y colaboración y los archivos subidos. El despliegue predeterminado usa `.data`; monta un volumen persistente en Docker. |
| Identidad | Configura el inicio de sesión y, para Desktop, registra el cliente OAuth de Agent con su URL de retorno exacta. |
| Licencia del SDK | Proporciona `VITE_UNIVER_LICENSE` al compilar Web para tu dominio y configura por separado la licencia del runtime de contenido Node.js. |

El host del agente gestiona las credenciales del modelo por separado del inicio de sesión en Workspace. Consulta la [guía de despliegue](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) y la [configuración de Agent](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md).

Apunta la misma CLI a tu servicio y autoriza una cuenta allí. Sustituye esta dirección de ejemplo por la dirección real:

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

El agente conserva herramientas y Skills, pero opera sobre los archivos y permisos de tu servicio. Desktop también puede conectarse. Consulta la [guía de conexión del Agent](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) para registrar el cliente y configurar las devoluciones de llamada.

## Lleva Workspace a un cliente Desktop local [#desktop-start]

**Workspace Desktop** combina Workspace, un entorno de agente, herramientas Office y vistas previas en un cliente local. Ofrece una experiencia de trabajo similar a Codex o Cowork: describe el objetivo, inspecciona el documento o Web App junto a la conversación, pide cambios y revisa el resultado.

Conecta Desktop a la nube, a tu despliegue privado o a un servicio Workspace local. El host del agente proporciona modelo y conversación; Workspace gestiona archivos y acceso. Los siguientes ejemplos reales muestran creación, gestión y colaboración.

[Instalar y conectar](#desktop-install) · [Primera tarea: revisar un presupuesto con dos documentos](#desktop-first-task)

### El flujo del agente en el trabajo Office diario [#why-desktop]

Los resultados Office necesitan edición continua, fórmulas, colaboración y revisión de cambios. Desktop conecta estos pasos en el mismo entorno para trabajar sobre contenido editable y compartido.

- **Mantén el contexto:** conversaciones, archivos, fuentes Workspace y referencias locales.
- **Contenido Office nativo y Web Apps:** crea, previsualiza y edita hojas de cálculo, documentos, presentaciones, Relational Tables y Canvases, además de páginas interactivas basadas en datos Office.
- **Mira y ajusta:** abre el contenido junto al chat, comprueba fórmulas y diseño y pide cambios concretos.
- **Entrega tras revisión:** conserva los cambios Office en un Worktree hasta que una persona revise y fusione.

<span id="conecta-solicitud-cambios-y-revisión" />

### De la petición al resultado revisable [#workflow]

Genera y modifica documentos Office y Web Apps en conversaciones normales; después, gestiónalos y compártelos en Space. Los cambios Office nativos se revisan en Worktree antes de fusionarlos. La publicación HTML y las escrituras enlazadas usan sus propios procesos de guardado y autorización. Las siguientes conversaciones pueden consultar los mismos archivos y datos.

### Instalar y conectar [#desktop-install]

Si ya tienes un escritorio de agentes extensible, puedes instalar y habilitar Space, conectar el servicio desde Space, configurar el modelo y añadir la marca. Las capturas usan esta composición. La aplicación Desktop completa y el complemento de prueba tienen vías de distribución distintas; sigue la publicación o las instrucciones del repositorio correspondientes a tu versión.

1. Elige Desktop en [GitHub Releases](https://github.com/dream-num/univer-workspace/releases), con etiquetas agent-v, para Windows x64, macOS Apple Silicon o Linux x64. La distribución es experimental; consulta las versiones publicadas.

2. En **Settings → Workspace**, elige el servicio, inicia sesión en el navegador y autoriza. Usa un servicio desplegado o la [configuración local](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace).

3. Configura un proveedor, modelo y credenciales compatibles en Models. Es independiente del inicio de sesión Workspace: consulta [configuración de modelos](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Añade un Space personal o de equipo accesible, abre una conversación y usa @ para aportar fuentes. Prueba la tarea siguiente y abre vista previa y revisión.

El instalador incluye la aplicación agente y las herramientas Office. El servicio Workspace funciona por separado, localmente o en un servidor; configura el acceso al modelo.

### Cómo Office SDK hace funcionar Workspace [#desktop-architecture]

Workspace conecta editores nativos, operaciones del agente y colaboración de equipo con los mismos documentos y permisos. Puedes partir de esta aplicación de código abierto y Office SDK para centrar el desarrollo en tus procesos de negocio, interfaz e integraciones.

<Mermaid chart={"flowchart LR\nA[\"Agent\"] <--> S[\"Workspace Server\"] <--> E[\"Editores\"]"} />

Los agentes operan sobre el contenido en Node.js mediante la CLI o Desktop; las personas lo consultan, editan y revisan en los editores Web o Desktop. Workspace Server guarda documentos compartidos, borradores y estado colaborativo. El servicio puede ejecutarse localmente, en tus servidores o en la nube.

| Capa | Responsabilidad |
| --- | --- |
| [Web SDK](/guides/sheets) | Modelos de contenido, fórmulas, API Facade públicas y editores nativos. |
| [AI SDK](/ai/content-operations) | Búsqueda de API, inspección estructurada y ejecución Facade sobre un documento concreto. |
| [Server SDK](/server) | Colaboración, revisiones, borradores Worktree y conversión de archivos. |
| Aplicación | Workspace gestiona Spaces, archivos, permisos, uso compartido y revisión. El host del agente gestiona conversaciones, llamadas al modelo y herramientas. |

La CLI y Desktop comparten una [capa de operaciones de contenido](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core). Su pool de runtimes reutiliza los documentos cargados durante la vida del host y sincroniza versiones antes de ejecutar. Así, distintos clientes reutilizan la misma lógica de edición y envío. Consulta la [reutilización de runtimes](/ai/runtime-architecture).

La [inspección visual](/ai/visual-inspection) complementa las comprobaciones estructuradas: las capturas se renderizan en el navegador y el diagnóstico automático detecta actualmente desbordamientos y solapamientos de texto en las presentaciones.

#### De una edición del agente a un cambio revisable [#agent-editing-flow]

En la revisión presupuestaria, el agente edita una hoja de cálculo real con fórmulas y estilos. La edición de contenido Office nativo sigue este proceso:

1. **Localizar y cargar.** Seleccionar documento y Worktree, cargar el snapshot y los changesets y sincronizar con la revisión elegida. Un Unit es una instancia de documento, como un libro de cálculo.
2. **Editar mediante Facade.** El runtime Node.js ejecuta llamadas Facade públicas sobre ese Unit. Los cambios producen mutaciones, agrupadas en un changeset que se envía al borrador.
3. **Verificar.** Volver a leer valores y fórmulas y comprobar el resultado visual cuando sea necesario. Refinar el mismo borrador hasta que esté listo para revisión.
4. **Revisar y fusionar.** Una persona comprueba las diferencias con [Compare](/overview/features/shared/compare) y decide si fusiona el [Worktree](/ai/worktree) con la versión compartida.

**Guardar en un borrador no equivale a fusionarlo.** Workspace comunica una escritura correcta tras confirmar el envío; los conflictos o envíos sin confirmar devuelven un error. El plugin de Desktop también solicita aprobación para sus herramientas de fusión y descarte. La aprobación se controla en el flujo de ejecución de herramientas de la aplicación.

#### Conectar las Web Apps a los mismos datos Office [#web-app-data-flow]

El panel de lanzamiento y el editor de presupuesto usan la misma hoja de cálculo. HTML View representa la página en un iframe aislado; el host de Workspace resuelve los documentos de origen accesibles y proporciona sus motores de contenido autorizados. Los indicadores y gráficos pueden suscribirse a los datos originales sin mantener otra copia del presupuesto.

Escribir mediante vínculos editables requiere una identidad autenticada y permiso de edición sobre el documento de origen. Al abandonar la página, el host espera las escrituras pendientes y la confirmación colaborativa, y muestra los fallos de guardado. La publicación HTML y la escritura de datos vinculados tienen sus propios procesos de guardado; no pasan automáticamente por la fusión Worktree de Office nativo. Consulta el [enlace bidireccional experimental](/overview/features/shared/binding) y la [implementación del host HTML View](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer).

#### Ejemplo: añadir un Skill de revisión presupuestaria [#domain-skill]

Un Skill de negocio puede definir las reglas de revisión del equipo reutilizando las herramientas Office existentes:

- Identificar el libro, el período y las columnas de presupuesto y gasto real; preguntar por las definiciones de negocio que falten antes de editar.
- Cargar la guía de hojas de cálculo, crear un Worktree, actualizar las fórmulas con Facade y preparar el documento de revisión.
- Verificar totales, resultados de fórmulas y presentación; indicar los archivos modificados y las comprobaciones y entregar el borrador para revisión humana.

Mantén las reglas y plantillas en el Skill. La aplicación conserva los controles de acceso, la persistencia del borrador y la aprobación de fusión. Para conectar un ERP o CRM, añade una herramienta de negocio que devuelva los datos necesarios y reutiliza el mismo proceso Office. Un Skill guía las operaciones; no concede acceso a los archivos.
