**Univer Workspace** es un espacio de trabajo de oficina de código abierto construido en **[Univer Office SDK](/overview)**, en el que las personas y los agentes trabajan juntos. El contenido de oficina editable y las aplicaciones web con datos se organizan en espacios personales y de equipo, junto con el intercambio, colaboración, versiones y revisión de cambios. El [repositorio de fuentes](https://github.com/dream-num/univer-workspace) contiene la aplicación, la configuración de implementación, el CLI y el cliente de escritorio.

Usted puede desplegar Workspace en su propia infraestructura o comenzar con el [prueba de nubes](https://space.univer.ai). Un agente existente se conecta a través de Workspace CLI. Workspace Desktop trae una conversación de agente y el mismo espacio de trabajo en una aplicación local. Todas estas rutas operan en el mismo servicio y los mismos archivos.

## Empieza con Workspace en la nube [#entry-points]

<span id="web-start" />

Abra el [prueba de nubes](https://space.univer.ai), inicie y entre en su Espacio Personal o en un Espacio de Equipo que pueda acceder. Cree o abra un documento, luego trate de edición directa, organización de archivos y compartir. El servicio Workspace ya está funcionando, por lo que un agente también puede conectarse a él a través del CLI descrito a continuación. El ensayo está destinado a datos de muestra, y que los datos pueden ser reajustados.

**Servidor de espacio de trabajo** gestiona identidad, espacios, permisos, almacenamiento, colaboración y versiones. **Web** es la interfaz del navegador para la edición y revisión. Un despliegue privado ejecuta la misma aplicación Server y Web.

## Conecta tu agente al Workspace en la nube [#cli-start]

Instala el CLI y el descubrimiento Habilidad en el ambiente donde se ejecuta su agente. Node.js 22.12 o más nuevo es necesario, y Node.js 24 es recomendado. Un agente que puede ejecutar comandos utiliza estas herramientas mientras continúa proporcionando su propio modelo y conversación. Establecer el servicio de la nube explícitamente para que el navegador y el agente funcionen en el mismo espacio de trabajo:

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>Primera conexión: iniciar sesión una vez en el navegador</summary>

Este paso puede ser saltado cuando ya existe una sesión válida. Si se requiere el registro, ejecute:

```bash
uvw auth login
```

Abra el enlace devuelto, inicie sesión y confirme el código en el navegador. Después de que el usuario confirme la terminación, ejecute:

```bash
uvw auth login --complete
```

Este paso sólo se requiere cuando se establece una sesión. El [Workspace Guía CLI](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md) documenta el conjunto completo de comandos y la autenticación.

</details>

Después de que el navegador autorice el CLI una vez, el CLI reutiliza esa sesión para tareas posteriores. No se requiere ninguna página de inicio de sesión específica de agente o la integración de autenticación. Dar al agente conectado una tarea, a continuación, abrir el enlace que devuelve en Web: el contenido es el mismo, y los cambios de la Oficina nativa del Agente pueden ser revisados antes de fusionarse.

## Lleva el mismo flujo a tu propio despliegue [#self-host]

El [repositorio de código abierto](https://github.com/dream-num/univer-workspace) contiene Server y Web. Construya la aplicación con el [Guía para el despliegue](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker), luego configure el dominio, registro, almacenamiento persistente y configuración de tiempo de ejecución. El desarrollo de la fuente utiliza Node.js 24 y pnpm 11; la guía mantiene los detalles de implementación de la producción.

Antes del despliegue, preparar cuatro partes:

| Elemento | Configuración |
| --- | --- |
| Servicio | Una URL del espacio de trabajo accesible y la aplicación Server + Web. El escritorio y CLI ambos se conectan a este despliegue. |
| Datos persistentes | La base de datos del producto, la base de datos de colaboración y los archivos cargados, se retuvieron juntos. El despliegue predeterminado los almacena bajo `.data`; para Docker, montar un volumen persistente. |
| Identidad | Configurar el registro. Cuando el Escritorio se conecta, registre el cliente Agente OAuth con un partido de URL de llamada exacto. |
| Licencia del SDK | Proporcione `VITE_UNIVER_LICENSE` cuando construya Web para el dominio de implementación, y configure la licencia requerida por el tiempo de ejecución de contenido Node.js por separado. |

Las credenciales modelo pertenecen al host del Agente y se configuran separadamente del registro del espacio de trabajo. El [Guía para el despliegue](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) y [Configuración del agente](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md) describen la configuración actual.

Configurar el mismo CLI para utilizar el despliegue privado y autorizar una cuenta en ese servicio. Reemplazar la dirección de ejemplo a continuación con el origen real del servicio:

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

El agente mantiene las mismas herramientas y habilidades y ahora opera en los archivos y permisos del servicio privado. El escritorio también puede conectarse a ese servicio. El [Guía de conexión del agente](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) documenta el registro del cliente y la configuración de callback.

## Lleva Workspace a un cliente Desktop local [#desktop-start]

**Workspace Desktop** combina espacio de trabajo, un agente de tiempo de ejecución, herramientas de oficina y previsiones de contenido en un cliente local. El trabajo de oficina sigue el patrón de conversación y vista previa familiarizado con Codex o Cowork: describir el resultado deseado, inspeccionar el documento o aplicación web junto a la conversación, solicitar una revisión y revisar el resultado.

El escritorio puede conectarse al espacio de trabajo de la nube descrito anteriormente, a un despliegue privado, o a un servicio Workspace que funciona en la máquina local. Modelos y conversaciones se ejecutan a través del host de agente configurado, mientras que el espacio de trabajo conectado gestiona archivos y acceso. Los ejemplos de escritorio a continuación muestran cómo se conecta la creación, la gestión y la colaboración.

[Instalar y conectar](#desktop-install) · [Primera tarea: revisar un presupuesto con dos documentos](#desktop-first-task)

### El flujo del agente en el trabajo Office diario [#why-desktop]

El trabajo de oficina continúa después de que una conversación devuelve un archivo descargable. La gente sigue editando, calculando contra datos reales, trabaja con compañeros de equipo, y decide qué cambios aceptar. El escritorio coloca estas actividades en un entorno de trabajo.

- **Mantener el contexto:** conversaciones, archivos, referencias locales y material Workspace permanecen disponibles.
- **Contenido Office nativo y Web Apps:** crea, previsualiza y edita hojas de cálculo, documentos, presentaciones, Relational Tables y Canvases, además de páginas interactivas basadas en datos Office.
- **Vea y revise el resultado:** abre contenido junto a la conversación, inspeccionar fórmulas y diseño, y luego solicitar un cambio específico.
- **Entrega mediante revisión:** los cambios de la oficina nativa del agente permanecen en un Worktree hasta que una persona los revisa y los fusiona en el espacio de trabajo compartido.

### De la petición al resultado revisable [#workflow]

Los documentos de oficina y las aplicaciones web se generan y revisan en la conversación ordinaria, luego gestionados y compartidos en el espacio. Los cambios de la Oficina Nativa pasan a través de la revisión Worktree antes de fusionarse. La publicación HTML y los escritos vinculantes siguen sus propios flujos de ahorro y autorización.

### Instalar y conectar [#desktop-install]

Si un agente extensible de escritorio ya está en uso, la ruta de integración es instalar y habilitar el plugin de la capacidad espacial, conectarse desde el espacio, configurar el modelo, y añadir una piel de marca. Las capturas de pantalla en esta página utilizan esta composición. La versión completa del Workspace Desktop y la vista previa del plugin siguen caminos de entrega separados; use la versión publicada o las instrucciones del repositorio para la versión instalada.

1. Elija un instalador de escritorio de [GitHub Releases](https://github.com/dream-num/univer-workspace/releases). Las versiones de escritorio utilizan etiquetas agente-v, así que seleccione el dispositivo Windows x64, macOS Apple Silicon o Linux x64 para su máquina. La entrega de escritorio es experimental, y la disponibilidad sigue las versiones publicadas.

2. En **Ajustes → Espacio de trabajo**, elija el servicio Workspace, inicie sesión a través del navegador y autorice el acceso. Conéctese a un servicio desplegado o siga [local setup](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) para ejecutar un servicio localmente.

3. En la configuración de Modelos, configura un proveedor, modelo y credenciales compatibles. El registro de espacio de trabajo y el acceso de modelo se configuran por separado; véase [configuración modelo](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Agregue un espacio personal o de equipo accesible, inicie una conversación, y utilice @ para material de referencia. Ejecute la tarea a continuación, a continuación, abra la vista previa del contenido y la revisión del cambio.

El instalador incluye la aplicación del agente y las herramientas de Office. El servicio Workspace funciona por separado, local o remotamente, y el acceso del modelo utiliza el proveedor configurado.

### Skills: entender el espacio y completar tareas [#skills]

Estas Habilidades permiten que un agente existente cree y edite contenido de Office y aplicaciones Web en un espacio de trabajo conectado, a continuación, desactivar los cambios para su revisión. [Conectar el agente al espacio de trabajo](#cli-start) primero; la guía a continuación funciona en los archivos y permisos de ese servicio.

#### Skills para tu agente

El [`univer-workspace-cli` Habilidad](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) instalado en el agente existente es el punto de entrada de descubrimiento. Explica cómo conectar, localizar el objetivo y cargar la guía operacional. El barco de Skills de tiempo completo con el CLI y coincide con sus comandos y APIs de Facade. El plugin de capacidad incorporado en Desktop también proporciona orientación de tareas y herramientas.

| Guía | Cobertura |
| --- | --- |
| `core` | Localización de espacios y archivos, trabajando en proyectos de tareas, comprobando contenido y entregando para su revisión. |
| `sheet` · `doc` · `slide` · `base` · `board` | Hojas de cálculo, documentos, presentaciones, Relational Table y Canvases. |
| `blob` | Subir, descargar y reemplazar archivos originales. |
| `html-view` | Creación y gestión de páginas HTML en vivo para aplicaciones web interactivas. |
| `embed` · `cross-unit-formula` | Insertar otro contenido, y conectar datos y fórmulas a través de tipos de contenido. |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

Cargar `core` primero, luego el producto o tema requerido por la tarea. `skills get` lista las rutas de referencia; leer un documento con `uvw skills read <name> <path>`, o añadir `--full` para leer todos ellos. Los agentes existentes utilizan estas capacidades a través del CLI, mientras que el Escritorio integra las herramientas y la guía en el flujo de trabajo de conversación.

#### Guías integradas en Desktop [#desktop-skills]

El plugin de capacidad de escritorio incluye la habilidad **univer** y sus referencias. Una aplicación puede añadir dominio Habilidades, plantillas y herramientas de negocio en el mismo tiempo de oficina.

El plugin de previsualización contiene nueve Habilidades. La Habilidad común cubre el descubrimiento, la identidad y la entrega, y cada producto La Habilidad cubre sus API y cómo verificar los resultados. El agente lee la guía requerida por la tarea actual.

| `univer-slide` | Creación de diapositivas y revisión visual |
| `univer-base` | Campos, registros y vistas |

### Cómo Office SDK hace funcionar Workspace [#desktop-architecture]

Workspace conecta editores nativos, operaciones de contenido de agente y colaboración de equipo con los mismos documentos y permisos. Puede aprovechar esta aplicación de código abierto y en Office SDK, y centrar su esfuerzo en los flujos de trabajo de negocios, la interfaz y las integraciones.

<Mermaid chart={"flowchart LR\nA[\"Agent\"] <--> S[\"Workspace Server\"] <--> E[\"Editores\"]"} />

Los agentes operan en contenido en Node.js a través del CLI o Desktop, y la gente ve, edita y lo revisa en el editor Web o Desktop. Workspace Server almacena documentos compartidos, borradores y estado de colaboración, y puede funcionar localmente, en servidores privados, o en la nube.

| Capa | Responsabilidad |
| --- | --- |
| [Web SDK](/guides/sheets) | Modelos de contenido, fórmulas, API Facade públicas y editores nativos. |
| [AI SDK](/ai/content-operations) | Búsqueda de API, inspección estructurada y ejecución Facade sobre un documento concreto. |

CLI y Desktop compartir un [capa de operaciones de contenido](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core). Su piscina de tiempo de ejecución mantiene los documentos cargados vivos para la vida del anfitrión y sincroniza las versiones antes de la ejecución. Diferentes clientes por lo tanto reutilizan la misma lógica de edición y presentación. [reutilización del tiempo de ejecución](/ai/runtime-architecture).

[Inspección visual](/ai/visual-inspection) complementa cheques estructurados. Imágenes vienen de rendering del navegador, y el diagnóstico de diseño automático actualmente detectan el flujo de texto y superposición en diapositivas.

#### De una edición del agente a un cambio revisable [#agent-editing-flow]

En el ejemplo de revisión presupuestaria, el agente edita una hoja de cálculo que contiene fórmulas y estilos. La ruta de edición de la Oficina nativa procede de la siguiente manera:

1. **Localizar y cargar.** El agente selecciona el documento y Worktree, carga la instantánea y los cambios, y sincroniza la revisión seleccionada. Una unidad es una instancia de documento, como un libro de trabajo.
2. **Edita por Facade.** El tiempo de ejecución Node.js ejecuta llamadas públicas Facade contra esa Unidad. Los cambios de contenido producen mutaciones, que se recogen en un cambio y se presentan al borrador.
3. **Revisa el resultado.** El agente lee los valores y fórmulas de vuelta e inspecciona la salida cuando sea necesario. La edición continúa en el mismo borrador hasta que el resultado esté listo para su revisión.
4. **Revisar y fusionar.** Una persona comprueba las diferencias con [Compare](/overview/features/shared/compare) y decide si fusiona el [Worktree](/ai/worktree) con la versión compartida.

**Salvar un cambio a un borrador no es fusionarlo.** Workspace reporta un escrito tan exitoso sólo después de que se confirme la presentación; conflictos y comunicaciones no confirmadas devuelven errores. En el plugin de escritorio, las herramientas de fusión y descarte también requieren la aprobación del usuario, que el flujo de trabajo de la herramienta de la aplicación impone.

#### Conectar las Web Apps a los mismos datos Office [#web-app-data-flow]

El panel de lanzamiento utiliza la misma hoja de cálculo que el editor de presupuestos. HTML View hace la página en un iframe de sandboxed. El host Workspace resuelve los documentos fuente que el usuario puede acceder y abastecer sus motores de contenido autorizados. Tarjetas métricas y gráficos se suscriben a los datos de origen, por lo que no se requiere una segunda copia del presupuesto.

Para enlaces editables, una escritura requiere una identidad firmada y permiso de edición en el documento fuente. Cuando el usuario sale de la página, el host espera a los escritos pendientes y confirmación de la colaboración, e informa que ahorra fallos. La publicación de páginas HTML y los escritos vinculantes utilizan sus propios caminos de ahorro y no siguen automáticamente a la Oficina nativa Worktree flujo de fusión. #### Ejemplo: añadir un Skill de revisión presupuestaria [#domain-skill]

Una habilidad de dominio puede codificar las reglas de revisión del equipo mientras reutiliza las herramientas de Office existentes:

- Localice el libro de trabajo fuente, el período, y las columnas Presupuesto/Actual, y pregunte acerca de cualquier definición de negocio que falta antes de la edición.
- Cargar la guía de hojas de cálculo, crear un Worktree, actualizar las fórmulas con Facade y preparar el documento de revisión.
- Compruebe los totales, los resultados de las fórmulas y la presentación, reporte los archivos cambiados y los cheques realizados, luego entregar el borrador a una persona para su revisión.

Las reglas y plantillas de negocio pertenecen a la Habilidad. Los controles de acceso, el borrador de la persistencia y la fusión de la aprobación permanecen en la aplicación. Para conectar un ERP o CRM, agregue una herramienta de aplicación que devuelve los datos necesarios y reutiliza el mismo flujo de edición y revisión de la Oficina.
