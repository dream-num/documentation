**Univer Workspace** convierte **[Univer Office SDK](/overview)** en un espacio de trabajo de código abierto para personas y agentes. Reúne contenido Office editable y Web Apps vinculadas a datos en Spaces personales y de equipo, con uso compartido, colaboración, versiones y revisión de cambios. El [repositorio](https://github.com/dream-num/univer-workspace) incluye la aplicación, el despliegue, la CLI y el cliente de escritorio.

Puedes desplegarlo en tu infraestructura o empezar con la [prueba en la nube](https://space.univer.ai). Tu agente se conecta mediante Workspace CLI; Workspace Desktop integra la conversación y el mismo espacio en una aplicación local. Son formas de trabajar con el mismo servicio y los mismos archivos.

## Empieza con Workspace en la nube [#entry-points]

<span id="web-start" />

Abre la [prueba en la nube](https://space.univer.ai), inicia sesión y entra en tu Space personal o en uno de equipo al que tengas acceso. Crea, edita, organiza y comparte documentos. También puedes conectar un agente a este servicio mediante la CLI que se explica a continuación. Usa datos de ejemplo: los datos de prueba pueden restablecerse.

**Workspace Server** gestiona identidad, Spaces, permisos, almacenamiento, colaboración y versiones. **Web** ofrece la interfaz de edición y revisión en el navegador. El despliegue privado utiliza esta misma aplicación Server y Web.

## Conecta tu agente al Workspace en la nube [#cli-start]

Instala la CLI y la Skill de descubrimiento donde se ejecuta tu agente. Se requiere Node.js 22.12 o posterior; se recomienda 24. Un agente que ejecuta comandos puede utilizar estas herramientas manteniendo su modelo y conversación. Configura el servicio de nube para trabajar con el mismo Workspace desde el navegador y el agente:

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>Primera conexión: iniciar sesión una vez en el navegador</summary>

Omite este paso si ya existe una sesión válida. Si necesitas iniciar sesión, ejecuta:

```bash
uvw auth login
```

Abre el enlace, inicia sesión y confirma el código en el navegador. Solo después de que el usuario confirme que ha terminado, ejecuta:

```bash
uvw auth login --complete
```

Este paso sirve para establecer la sesión. Consulta los comandos y detalles en la [guía de Workspace CLI](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md).

</details>

Tras la primera autorización en el navegador, la CLI reutiliza la sesión. No necesitas crear una integración de inicio de sesión para cada agente. Pídele una tarea, abre el enlace que devuelve y revisa el mismo contenido y los cambios Office antes de fusionarlos.

## Lleva el mismo flujo a tu propio despliegue [#self-host]

El [repositorio](https://github.com/dream-num/univer-workspace) incluye Server y Web. Sigue la [guía de despliegue](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) y configura dominio, acceso, almacenamiento persistente y entorno. El desarrollo utiliza Node.js 24 y pnpm 11.

Apunta la misma CLI a tu servicio y autoriza una cuenta allí. Sustituye esta dirección de ejemplo por la dirección real:

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

El agente conserva herramientas y Skills, pero opera sobre los archivos y permisos de tu servicio. Desktop también puede conectarse. Consulta la [guía de conexión del Agent](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) para registrar el cliente y configurar las devoluciones de llamada.

## Lleva Workspace a un cliente Desktop local [#desktop-start]

**Workspace Desktop** combina Workspace, un entorno de agente, herramientas Office y vistas previas en un cliente local. Ofrece una experiencia de trabajo similar a Codex o Cowork: describe el objetivo, inspecciona el documento o Web App junto a la conversación, pide cambios y revisa el resultado.

Conecta Desktop a la nube, a tu despliegue privado o a un servicio Workspace local. El host del agente proporciona modelo y conversación; Workspace gestiona archivos y acceso. Los siguientes ejemplos reales muestran creación, gestión y colaboración.

[Instalar y conectar](#desktop-install) · [Primera tarea: revisar un presupuesto con dos documentos](#desktop-first-task)

### El flujo del agente en el trabajo Office diario [#why-desktop]

Los resultados Office necesitan edición continua, fórmulas, colaboración y revisión de cambios. Desktop conecta estos pasos en el mismo entorno para trabajar sobre contenido editable y compartido.

- **Mantén el contexto:** conversaciones, archivos, fuentes Workspace y referencias locales.
- **Crea contenido Office y Web Apps:** genera hojas, documentos, presentaciones, Relational Table y Canvases editables, además de páginas interactivas basadas en sus datos.
- **Mira y ajusta:** abre el contenido junto al chat, comprueba fórmulas y diseño y pide cambios concretos.
- **Entrega tras revisión:** conserva los cambios Office en un Worktree hasta que una persona revise y fusione.

<span id="conecta-solicitud-cambios-y-revisión" />

### De la petición al resultado revisable [#workflow]

Genera y modifica documentos Office y Web Apps en conversaciones normales; después, gestiónalos y compártelos en Space. Los cambios Office nativos se revisan en Worktree antes de fusionarlos. La publicación HTML y las escrituras enlazadas usan sus propios procesos de guardado y autorización. Las siguientes conversaciones pueden consultar los mismos archivos y datos.

### Instalar y conectar [#desktop-install]

Si ya tienes un escritorio de agentes extensible, puedes instalar y habilitar Space, conectar el servicio desde Space, configurar el modelo y añadir la marca. Las capturas usan esta composición. La aplicación Desktop completa y el complemento de prueba tienen vías de distribución distintas; sigue la publicación o las instrucciones del repositorio correspondientes a tu versión.

1. Elige Desktop en [GitHub Releases](https://github.com/dream-num/univer-workspace/releases), con etiquetas agent-v, para Windows x64, macOS Apple Silicon o Linux x64. La distribución es experimental; consulta las versiones publicadas.

2. En **Settings → Workspace**, elige el servicio, inicia sesión en el navegador y autoriza. Usa un servicio desplegado o la [configuración local](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace).

3. Configura un proveedor, modelo y credenciales compatibles en Models. Es independiente del inicio de sesión Workspace: consulta [configuración de modelos](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Añade un Space personal o de equipo accesible, abre una conversación y usa @ para aportar fuentes. Prueba la tarea siguiente y abre vista previa y revisión.

El instalador incluye la aplicación agente y las herramientas Office. El servicio Workspace funciona por separado, localmente o en un servidor; configura el acceso al modelo.

### Skills: entender el espacio y completar tareas [#skills]

#### Skills para tu agente

El [Skill `univer-workspace-cli`](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) instalado en tu agente es el punto de descubrimiento: explica la conexión, la localización del objetivo y la carga de guías. Los Skills completos se distribuyen con la CLI y corresponden a sus comandos y API Facade. El complemento integrado de Desktop también proporciona guías y herramientas por tarea.

| Guía | Cobertura |
| --- | --- |
| `core` | Espacios y archivos, borradores de tarea, verificación y entrega para revisión. |
| `sheet` · `doc` · `slide` · `base` · `board` | Hojas de cálculo, documentos, presentaciones, Relational Table y Canvases. |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

Carga primero `core` y después el producto o tema necesario. `skills get` enumera referencias; `uvw skills read <name> <path>` lee una concreta y `--full` las incluye juntas. Los agentes existentes acceden mediante la CLI; Desktop integra herramientas y guías en la conversación.
