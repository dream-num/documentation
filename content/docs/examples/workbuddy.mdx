**Univer Office for WorkBuddy** (`workbuddy-univer-office`) is a local Office integration built on public **[Univer Office SDK](/docs/overview)** APIs. A local MCP service and Skill bring authoring, inspection, previews, and draft review into WorkBuddy, with files stored in a local workspace.

<Callout type="info">
Development preview. A public npm runtime is available for local integration; official marketplace installation and full in-host review still require acceptance testing.
</Callout>

[Install and connect](#quick-start) · [Try a task](#first-task) · [Skills and tools](#skills)

## Install and connect [#quick-start]

Prepare WorkBuddy 5.8.3 or newer and Node.js 22 (22.12 or newer). This example uses public runtime 0.1.6. Office content defaults to the local `~/.univer-office/workspace` directory.

### 1. Install the local runtime

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

Finish installation before connecting MCP so the initial dependency download does not consume the host’s handshake timeout. A local connection requires no cloud account or Office API key.

### 2. Connect the local MCP server

Open an authorized working directory in WorkBuddy and add a custom stdio MCP server with this configuration:

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

If WorkBuddy cannot find `univer-office`, replace `command` with its installed absolute path. Find it with `command -v univer-office` on macOS/Linux or `Get-Command univer-office` on Windows. Let WorkBuddy start the stdio server; do not also start an independent HTTP service for the same storage directory. To use another storage directory, set the absolute-path environment variable `WORKBUDDY_OFFICE_WORKSPACE`.

### 3. Import the operational Skill

With Git and Python 3 available, generate the instructions-only Skill ZIP from the public repository; no application build is needed:

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

Import `.data/packages/univer-office-workbuddy-skill.zip` in WorkBuddy’s Skills manager. Once MCP is connected, ask the assistant to check the Office service status, then send the task below. The Skill supplies guidance and the MCP server supplies execution; use them together.

## Try a task right away [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Use Univer Office to create a local sales-review.univer file containing an English sales Sheet with five sample records: Product, Quantity, Unit Price, and Revenue. Calculate Revenue with formulas, add total revenue and a revenue-by-product chart.
Verify confirmed writes and formula results, show only this Sheet in the right-side preview, and give me the browser review link. Keep every change in an isolated draft and wait for my approval before merging.
```

</div>

### What you will see

WorkBuddy shows one read-only spreadsheet preview on the right. Full View, Compare, and merge confirmation open in the browser, while the Office file stays local. Starting with one Sheet makes formulas and charts immediately visible and avoids the host’s same-response routing limitation for multiple preview cards.

### Keep exploring

After approving and merging the first result, ask: “In a new draft of the same sales Sheet, raise the first record’s unit price by 10%, update total revenue, and open Compare against the confirmed version. Wait for my review.” This produces a meaningful before-and-after comparison.

## How Skills and tools work together [#skills]

One [`univer-office` Skill](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office) owns the workflow, with seven product and cross-content references loaded as needed. The agent queries public Facade APIs with `univer_api`, then edits, confirms writes, reads back, and previews through MCP. The same Office SDK model drives headless processing and browser rendering; versions and Worktrees make changes identifiable, comparable, and reviewable.

## What you can build

- **Create in your existing assistant:** Ask WorkBuddy to create or update spreadsheets, documents, presentations, relational tables, and canvases.
- **Follow live previews:** Inspect read-only previews in the host, or open an external browser for the full View and Compare interfaces.
- **Understand changes before deciding:** Draft View and Compare remain read-only. Compare fixed versions, inspect semantic differences, and navigate to the affected content.
- **Move from draft to delivery:** The agent edits a Worktree. A person chooses to merge, revise, or discard, then exports supported formats from a selected confirmed version.

## How Office SDK powers it [#sdk-integration]

WorkBuddy owns conversation and MCP tool calls. The local service composes Office SDK’s Headless runtime, Facade authoring, collaboration versions, and Worktrees; browser previews render the same content model. The project shows how to package SDK capabilities as local tools and a review interface for an agent host.
