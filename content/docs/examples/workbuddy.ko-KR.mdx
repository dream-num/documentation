**Univer 직장 동료 사무실** (`workbuddy-univer-office`)는 **[Univer Office SDK](/overview)**의 공공 API에 내장 된 지역 오피스 통합입니다. 로컬 MCP 서비스 및 기술이 저자, 검사, 미리보기 및 워크 버디로 마이그레이션 검토를 가져와 로컬 작업 공간에서 파일 남아 있습니다.

<Callout type="info">
이 개발 미리보기입니다. 공개 npm 런타임은 로컬 통합을 지원합니다. 공식 마켓 플레이스 설치 및 전체 in-host 리뷰는 여전히 합격 테스트를 요구합니다.
</Callout>

## 설치 및 연결 [#quick-start]

WorkBuddy 5.8.3 또는 newer 및 Node.js 22 (22.12 또는 newer)가 필요합니다. 이 예제는 공공 실행 시간 0.1.6 및 Office 콘텐츠 기본값을 로컬 `~/.univer-office/workspace` 디렉토리에 사용합니다.

### 1. 로컬 실행 패키지 설치

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

MCP를 연결하기 전에 설치를 완료하십시오. 그렇지 않으면 호스트가 Handhake를 기다리는 동안 첫 번째 의존성 다운로드가 실행되고 타임 아웃을 초과 할 수 있습니다. 로컬 연결은 클라우드 계정과 Office API 키가 필요하지 않습니다.

### 2. 로컬 MCP 연결

WorkBuddy의 공인 작업 디렉토리를 열고 다음 구성으로 사용자 정의 stdio MCP 서버를 추가하십시오.

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

WorkBuddy가 `univer-office`를 찾을 수없는 경우 설치의 절대 경로로 `command`을 교체하십시오. macOS 또는 Linux에서 `command -v univer-office`로 경로가 있는지 확인하십시오. Windows에서 `Get-Command univer-office` 를 사용하십시오. WorkBuddy를 사용하여 stdio 서버를 시작하고 동일한 저장 디렉토리에 독립적 인 HTTP 서비스를 시작할 수 없습니다. 다른 스토리지 디렉토리를 사용하려면 `WORKBUDDY_OFFICE_WORKSPACE` 환경 변수를 절대 경로로 설정하십시오.

### 3. 작업 Skill 가져오기

Git 및 Python 3을 사용할 수 있는 경우, public repository에서 지침 전용 스킬 ZIP을 생성합니다. 애플리케이션 빌드가 필요하지 않습니다.

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

WorkBuddy의 Skills Manager에서 `.data/packages/univer-office-workbuddy-skill.zip` 가져 오기. MCP가 연결되면 사무실 서비스 상태를 확인하기 위해 보조를 요청하고 아래 작업을 보내주십시오. 기술 공급 지침 및 MCP 서버는 실행을 수행하므로 함께 사용하십시오.

### 확인할 수 있는 결과

WorkBuddy는 한 번의 읽기 전용 스프레드 시트 미리보기를 표시합니다. 전체보기, 비교 및 합병 확인은 브라우저에서 열립니다. Office 파일이 로컬로 남아 있습니다. 단일 시트로 시작하면 공식 및 차트가 즉시 볼 수 있으며 동일한 응답에서 여러 미리보기 카드에 호스트의 라우팅 제한을 방지합니다.

### 계속 체험하기

첫 번째 결과를 승인하고 합병 한 후, "같은 판매 시트의 새로운 초안에서 10 %의 첫 번째 기록의 단위 가격을 인상하고 총 매출을 업데이트하고 확인 된 버전에 대한 비교를 엽니 다. 내 리뷰에 대한 기대." 이것은 구체적인 전후 비교를 생산합니다.

## Skills와 도구의 연동 [#skills]

[`univer-office` 기술](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office)는 작업 흐름을 정의하고, 7개의 제품 및 크로스 컨텐츠 참조가 필요한대로 로드됩니다. `univer_api`를 사용한 에이전트 쿼리 공개 Facade API를 사용하면, 쓰기를 확인하고, MCP를 통해 콘텐츠를 다시 읽고, 미리보기를 확인합니다. 동일한 Office SDK 모델은 헤드리스 처리 및 브라우저 렌더링을 구동하며, Worktrees는 모든 변경 식별 가능하고, 비교할 수 있으며, 검토할 수 있습니다.

## 무엇을 만들 수 있나요

- 기존의 조수에 대한 내용을 작성하십시오. WorkBuddy를 사용하여 스프레드 시트, 문서, 프리젠 테이션, 관계 표 및 캔버스를 만들거나 업데이트하십시오.
- 라이브 미리보기를 따르십시오 : 호스트의 읽기 전용 미리보기를 검사하거나 전체보기 및 인터페이스를 비교하기위한 외부 브라우저를 엽니 다.
- 검토 변경 전에 : 초안 전망과 비교는 읽기 전용입니다. 고정 버전과 비교하여, semantic 차이를 검사하고 영향을받는 내용으로 이동합니다.
- 납품에 초안에서 이동하십시오: 대리인은 Worktree를 편집하고, 사람이 병합하고, 개정하거나, 또는 discard를 선택하고, 지원한 체재는 당신이 선정한 버전에서 그 후에 수출됩니다.

## Office SDK가 담당하는 부분 [#sdk-integration]

WorkBuddy는 대화와 MCP 도구 통화를 처리합니다. 로컬 서비스는 Office SDK의 헤드리스 런타임, Facade Authoring, 협업 버전 및 Worktrees 및 브라우저 미리보기를 구성하며 동일한 콘텐츠 모델을 렌더링합니다. 이 프로젝트는 로컬 도구와 에이전트 호스트에 대한 검토 인터페이스로 SDK 기능을 패키지하는 방법을 보여줍니다.
