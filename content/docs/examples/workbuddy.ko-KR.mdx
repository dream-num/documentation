**Univer Office for WorkBuddy**(`workbuddy-univer-office`)는 **[Univer Office SDK](/docs/overview)**의 공개 API로 만든 로컬 Office 통합입니다. 로컬 MCP 서비스와 Skill이 생성, 검사, 미리 보기와 초안 검토를 WorkBuddy에 연결하며 파일은 로컬 작업 공간에 저장됩니다.

<Callout type="info">
개발 미리 보기입니다. 공개 npm 실행 패키지로 로컬 연결이 가능하지만 공식 마켓 설치와 호스트 내 전체 검토는 추가 검증이 필요합니다.
</Callout>

## 설치 및 연결 [#quick-start]

WorkBuddy 5.8.3 이상과 Node.js 22(22.12 이상)를 준비하세요. 이 예제는 공개 패키지 0.1.6을 사용하며 Office 콘텐츠는 기본적으로 로컬 `~/.univer-office/workspace`에 저장됩니다.

### 1. 로컬 실행 패키지 설치

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

초기 다운로드가 호스트의 연결 제한 시간을 소모하지 않도록 설치 완료 후 MCP를 연결하세요. 로컬 연결에는 클라우드 계정이나 Office API 키가 필요 없습니다.

### 2. 로컬 MCP 연결

WorkBuddy에서 사용을 허용한 작업 폴더를 열고 다음 설정으로 사용자 지정 stdio MCP 서버를 추가하세요.

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

WorkBuddy가 `univer-office`를 찾지 못하면 `command`를 설치된 절대 경로로 바꾸세요. macOS/Linux는 `command -v univer-office`, Windows는 `Get-Command univer-office`로 확인합니다. stdio는 WorkBuddy가 시작하도록 하고 같은 저장 폴더에 별도 HTTP 서비스를 함께 실행하지 마세요. 다른 저장 폴더는 `WORKBUDDY_OFFICE_WORKSPACE` 환경 변수에 절대 경로로 지정합니다.

### 3. 작업 Skill 가져오기

Git과 Python 3를 준비하고 공개 저장소에서 안내만 포함한 Skill ZIP을 생성합니다. 앱 빌드는 필요 없습니다.

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

WorkBuddy Skills 관리에서 `.data/packages/univer-office-workbuddy-skill.zip`을 가져오세요. MCP 연결 후 Office 서비스 상태를 확인하도록 요청하고 아래 작업을 전달합니다. Skill은 지침을, MCP 서버는 실행 기능을 제공하므로 함께 사용해야 합니다.

## 바로 체험할 수 있는 작업 [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
Univer Office로 로컬 sales-review.univer 파일을 만들고 영어 판매 Sheet를 작성해 주세요. Product, Quantity, Unit Price, Revenue 열에 예시 5개를 넣고 Revenue는 수식으로 계산하세요. 총매출과 제품별 매출 차트도 추가하세요.
확정된 쓰기와 수식 결과를 검사하고 이 Sheet 하나만 오른쪽에 미리 보기로 표시한 뒤 브라우저 검토 링크를 주세요. 독립 초안에서 작업하고 승인 전에는 병합하지 마세요.
```

</div>

### 확인할 수 있는 결과

WorkBuddy 오른쪽에 읽기 전용 표가 표시됩니다. 전체 보기, Compare, 병합 확인은 브라우저에서 진행하며 파일은 로컬에 남습니다. 첫 작업을 Sheet 하나로 제한해 수식과 차트를 바로 확인하고 같은 응답의 여러 미리 보기 카드에 대한 호스트 라우팅 제한을 피합니다.

### 계속 체험하기

첫 결과를 승인하고 병합한 뒤 ‘같은 판매 표의 새 초안에서 첫 기록의 단가를 10% 올리고 총매출을 갱신한 다음 확정 버전과의 Compare를 열어 검토를 기다려 주세요’라고 요청하세요. 실제 변경 전후를 비교할 수 있습니다.

## Skills와 도구의 연동 [#skills]

하나의 [`univer-office` Skill](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office)이 흐름을 관리하고 제품 및 콘텐츠 간 참조 7개를 필요에 따라 불러옵니다. 에이전트는 `univer_api`로 공개 Facade를 조회하고 MCP로 편집, 쓰기 확인, 데이터 읽기, 미리 보기를 수행합니다. 같은 Office SDK 모델이 헤드리스 처리와 브라우저 렌더링에 사용되며 버전과 Worktree로 변경을 식별, 비교, 검토합니다.

## 무엇을 만들 수 있나요

- **익숙한 도우미에서 생성:** WorkBuddy에 표, 문서, 프레젠테이션, 관계형 테이블, 캔버스 생성·수정을 요청할 수 있습니다.
- **실시간 미리 보기:** 호스트에서 읽기 전용 미리 보기를 확인하고 전체 View·Compare 화면은 외부 브라우저로 열 수 있습니다.
- **변경을 이해하고 결정:** 초안의 View와 Compare는 읽기 전용입니다. 고정 버전의 의미 단위 차이를 비교하고 해당 콘텐츠로 이동합니다.
- **초안에서 전달까지:** 에이전트가 Worktree를 수정하고 사람이 병합·추가 수정·폐기를 결정합니다. 선택한 확정 버전에서 지원 형식으로 내보냅니다.

## Office SDK가 담당하는 부분 [#sdk-integration]

WorkBuddy는 대화와 MCP 도구 호출을 담당합니다. 로컬 서비스는 Office SDK의 Headless 실행, Facade 조작, 협업 버전과 Worktree를 조합하며 브라우저는 같은 모델을 렌더링합니다. SDK를 에이전트 호스트용 로컬 도구와 검토 화면으로 구성하는 예제입니다.
