**Univer Office for WorkBuddy**（`workbuddy-univer-office`）是基于 **[Univer Office SDK](/overview)** 公开 API 的本地 Office 集成。本地 MCP 服务和 Skill 将内容创建、检查、预览和草稿审阅引入 WorkBuddy，文件保留在本地工作区。

<Callout type="info">
本插件为开发预览版。公开的 npm 运行包支持本地接入；官方市场安装和宿主内的完整审阅仍需通过验收测试。
</Callout>

[安装与接入](#quick-start) · [直接体验](#first-task) · [Skills 与工具](#skills)

## 安装与接入 [#quick-start]

需要 WorkBuddy 5.8.3 或更新版本，以及 Node.js 22（22.12 或更新版本）。本示例使用公开运行包 0.1.6，Office 内容默认保存在本机 `~/.univer-office/workspace` 目录。

### 1. 安装本地运行包

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

请在连接 MCP 之前完成安装。否则首次依赖下载会在宿主等待握手期间发生，可能导致握手超时。本地连接不需要云账号，也不需要 Office API Key。

### 2. 接入本地 MCP

在 WorkBuddy 中打开一个允许使用的工作目录，添加自定义 stdio MCP 服务，配置如下：

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

如果 WorkBuddy 找不到 `univer-office`，请将 `command` 替换为安装后的绝对路径。在 macOS 或 Linux 上可通过 `command -v univer-office` 获取该路径，在 Windows 上可使用 `Get-Command univer-office`。请让 WorkBuddy 启动该 stdio 服务，不要为同一存储目录另行启动独立的 HTTP 服务。如需更换存储目录，请将环境变量 `WORKBUDDY_OFFICE_WORKSPACE` 设为绝对路径。

### 3. 导入操作 Skill

只要本机已安装 Git 和 Python 3，即可从公开仓库生成只包含操作说明的 Skill ZIP，不需要构建应用：

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

在 WorkBuddy 的 Skills 管理器中导入 `.data/packages/univer-office-workbuddy-skill.zip`。MCP 连接后，先让助手检查 Office 服务状态，再发送下面的任务。Skill 提供操作指引，MCP 服务负责实际执行，两者需要配合使用。

## 直接体验一个任务 [#first-task]

<div className="[&_pre]:whitespace-pre-wrap [&_code]:whitespace-pre-wrap [&_code]:w-full! [&_pre]:wrap-anywhere">

```text
使用 Univer Office，新建本地文件 sales-review.univer，制作一张英文销售表：5 条示例记录，包含 Product、Quantity、Unit Price、Revenue，收入用公式计算，并添加总收入和产品收入图表。
先检查写入和公式结果，再只展示这一张 Sheet 的右侧预览，并给我浏览器审阅链接。所有修改放在独立草稿中，等我确认后再合入。
```

</div>

### 你会看到什么

WorkBuddy 右侧只显示一张只读的表格预览。完整查看、Compare 和确认合入均在浏览器中完成，Office 文件始终保留在本机。第一个任务只使用一张 Sheet，公式和图表可以立即看到，同时避开宿主对同一回复中多张预览卡片的路由限制。

### 继续体验

确认并合入第一份结果后，可发送以下消息：“在同一份销售表的新草稿里，把第一条记录的单价提高 10%，更新总收入，打开 Compare 对比已确认的版本，等我审阅。”这样可以获得修改前后的实际对比。

## Skills 与工具如何协作 [#skills]

整个流程由一个 [`univer-office` Skill](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office) 统筹，七份产品与跨内容参考文档按需加载。Agent 使用 `univer_api` 查询公开的 Facade API，再通过 MCP 编辑、确认写入、读回内容并预览。Office SDK 的同一套内容模型同时驱动 Headless 处理与浏览器渲染，版本和 Worktree 使每处修改都可以定位、比较和审阅。

## 你可以用它做什么

- 在常用的助手中创建内容：让 WorkBuddy 创建或修改电子表格、文档、演示文稿、关系型表格和画布。
- 通过实时预览跟踪进度：在宿主中查看只读预览，或打开外部浏览器使用完整的 View 和 Compare 界面。
- 决定前审阅改动：Draft View 和 Compare 均为只读。可比较固定版本、检查语义差异，并定位到受影响的内容。
- 从草稿到交付：Agent 在 Worktree 中编辑，由人决定合并、继续修改或丢弃，最后从你选定的已确认版本导出受支持的格式。

## Office SDK 如何支撑 [#sdk-integration]

WorkBuddy 负责对话和 MCP 工具调用。本地服务组合 Office SDK 的 Headless 运行时、Facade 内容操作、协同版本和 Worktree，浏览器预览渲染的是同一套内容模型。本项目演示如何将 SDK 能力打包为供 Agent 宿主使用的本地工具和审阅界面。
