**Univer Workspace Desktop** brings the familiar agent workflow of tools such as Codex and Claude Code to Office work: describe a task, reference your material, let the agent operate documents, inspect the preview, and review the changes. Built with **[Univer Office SDK](/docs/overview)** and an existing agent runtime, it is a concrete starting point for building your own agent Office workspace.

**Create in conversation; manage and collaborate in Space.** Start a normal Agent session to generate and revise Office documents or a Web App while viewing the result beside the chat. Space brings the files together for organization, sharing, and collaborative editing. You can reference the same files in a later conversation, keeping creation and teamwork connected.

## Bring the agent workflow to everyday Office work [#why-desktop]

Office work needs more than a conversation that returns a downloadable file. People need to keep editing, calculate with real data, work with teammates, and decide which changes to accept. Desktop keeps those steps in the same working environment.

- **Keep context:** conversations, files, local references, and Workspace material stay within reach.
- **Create Office content and Web Apps:** generate editable spreadsheets, documents, presentations, Relational Table, and Canvases, plus interactive pages backed by Office data.
- **See and revise the result:** open content beside the conversation, inspect formulas and layout, then ask for a targeted change.
- **Deliver through review:** the agent’s native Office changes stay in a Worktree until reviewed and merged into the shared workspace.

## From a request to a reviewed deliverable [#workflow]

Generate and revise Office documents and Web Apps in normal conversations, then manage and share them in Space. Native Office changes use Worktree review before merging; HTML publication and binding writes use their own save and authorization flows. Later conversations can reference the same files and data.

## Install and connect [#quick-start]

For an existing extensible agent desktop, the integration route is to install and enable the Space capability plugin, connect from Space, configure the model, and add a brand skin. The screenshots on this page use that composition. The full Workspace Desktop release and the plugin preview have separate delivery paths; use the published release or the repository setup instructions for the version you are installing.

1. Choose a Desktop installer from [GitHub Releases](https://github.com/dream-num/univer-workspace/releases). Desktop releases use agent-v tags; select the matching Windows x64, macOS Apple Silicon, or Linux x64 artifact. Desktop delivery is experimental; availability follows the published releases.

2. In **Settings → Workspace**, choose the Workspace service, sign in through the browser, and authorize access. You can connect to a deployed service or follow [local setup](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace) to run one locally.

3. Configure a supported provider, model, and credentials in Models settings. Workspace sign-in and model access are separate; see [model configuration](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials).

4. Add an accessible Personal or Team Space, start a conversation, and use @ to reference source material. Try the task below, then open its document preview and changes.

The installer packages the agent application and Office tools. The Workspace service runs separately, locally or remotely; configure model access for the provider you use.

## Skills connect intent to reliable Office operations [#skills]

Desktop’s capability plugin includes the **univer** Skill and its references. It teaches the agent how Spaces and documents relate, how to use Office APIs, and how to create, verify, and deliver a Worktree. These instructions accompany executable tools; the agent can look up an API, run it against native content, and inspect the result.

The [capability plugin](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md) connects file discovery, headless Facade editing, structured inspection, import/export, and Worktree lifecycle tools. This preview prepares drafts for review; publishing uses the deployed application’s review and merge workflow. Your application can add domain Skills, templates, and business tools on the same Office runtime.

### Guidance for each kind of work

The preview plugin includes nine Skills. The common Skill explains discovery, identity, and delivery; product Skills provide API and verification guidance. The agent reads the relevant guidance for the current task.

| Skill | Guidance |
| --- | --- |
| `univer` | Spaces, files, draft lifecycle, and delivery |
| `univer-sheet` | Formulas, styles, charts, and spreadsheet verification |
| `univer-doc` | Document structure, paragraphs, and tables |
| `univer-slide` | Slide authoring and visual layout checks |
| `univer-base` | Fields, records, and views |
| `univer-board` | Shapes, connectors, and canvas layout |
| `univer-embed` | Embed one Office product inside another |
| `univer-cross-unit-formula` | Reference and calculate across Units |
| `univer-html-view` | Build and inspect HTML pages bound to Office data |

## Use this example to build your own agent Office workspace [#build-your-own]

Workspace Desktop shows how to assemble a complete product from reusable parts. You can reuse the agent host and Workspace application, compose the Office capabilities you need, and focus on your domain’s data, tools, templates, and delivery workflow.

### Separate the agent loop from the Office capabilities [#desktop-architecture]

Skills guide the agent, tools operate structured content through the Headless runtime, and native editors render it for people. Workspace supplies the file and collaboration context. This separation lets you change the model, add business tools, or replace the brand without rebuilding an Office engine.

<Mermaid chart={"flowchart LR\nA[\"Agent + model\"]\nB[\"Skills + tools\"]\nC[\"Office SDK<br/>Headless operations + verification\"]\nD[\"Workspace service<br/>Files + collaboration + versions\"]\nE[\"Desktop preview<br/>Native editors + Web Apps\"]\nF[\"Worktree + Compare<br/>Human review\"]\nA --> B --> C --> D\nD <--> E\nD --> F\nF --> E"} />

| Part | Responsibility |
| --- | --- |
| [Web SDK](/guides/sheets) | Shared content models, editable Office views, rendering, formulas, and headless Facade operations. |
| [Server SDK](/server) | Collaboration, versions, and Worktree capabilities connected to the application’s backend. |
| [AI SDK](/ai) | Agent-oriented content operations and inspection/verification primitives. |
| Agent runtime and Skills | DSH provides sessions, model access, tool orchestration, and approval; the Workspace capability plugin connects Office tools and task guidance. |
| Workspace and Desktop | The application supplies Spaces, files, identity integration, and review UI; the Electron delivery makes that agent workspace available as a desktop app. |

This composition is the reusable pattern: request → tools → editable content → preview → review → shared delivery. The Office SDK supplies the Office layer; an agent host supplies the conversation and execution loop. You can extend the existing [application and plugins](https://github.com/dream-num/univer-workspace/tree/main/apps/agent), or connect the SDKs to your own host and business services.
