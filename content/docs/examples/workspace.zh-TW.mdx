**Univer Workspace** 是以 **[Univer Office SDK](/overview)** 建構的開源辦公空間。它把可編輯的 Office 內容與資料連動的 Web App 放進個人及團隊 Space，串起分享、協同、版本與變更審閱。[開源儲存庫](https://github.com/dream-num/univer-workspace)提供應用、部署、CLI 與桌面客戶端。

你可以私有部署 Workspace，也能先使用[雲端線上試用](https://space.univer.ai)。既有 Agent 透過 Workspace CLI 操作工作區；Workspace Desktop 則把 Agent 對話與同一套工作區整合進本機客戶端。它們使用同一服務與同一批檔案。

## 先在雲端體驗完整的 Workspace [#entry-points]

<span id="web-start" />

開啟[雲端線上試用](https://space.univer.ai)，登入後進入個人空間或有權存取的團隊 Space。建立或開啟文件，體驗編輯、整理與分享。這是已部署的 Workspace 服務，也可以透過下方 CLI 連接 Agent。試用請使用示範資料，資料可能重設。

**Workspace Server** 管理身分、空間、權限、儲存、協同與版本；**Web** 提供瀏覽器內的編輯及審閱介面。私有部署使用相同的 Server 與 Web 應用。

## 讓既有 Agent 連接雲端 Workspace [#cli-start]

在 Agent 的執行環境安裝 CLI 與發現入口 Skill。需要 Node.js 22.12 以上，建議 Node.js 24。可執行命令的 Agent 能直接使用工具，模型及對話仍由它提供。先明確設定雲端服務地址，讓瀏覽器與 Agent 操作同一個 Workspace：

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>首次連接：完成一次瀏覽器登入</summary>

已有有效工作階段時可略過。需要登入時執行：

```bash
uvw auth login
```

開啟回傳連結，在瀏覽器登入並確認驗證碼。使用者確認完成後再執行：

```bash
uvw auth login --complete
```

僅在建立工作階段時需要此步驟。完整指令與驗證說明見 [Workspace CLI 指南](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md)。

</details>

首次瀏覽器授權後，CLI 會在後續任務重用會話，無須為每種 Agent 開發登入頁面或獨立驗證整合。向已連接的 Agent 下達任務，開啟它回傳的連結，即可在 Web 查看同一份內容，並在合入前審閱原生 Office 變更。

## 把相同流程搬到私有部署 [#self-host]

[開源儲存庫](https://github.com/dream-num/univer-workspace)包含 Server 與 Web。依[部署指南](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)建構應用，設定網域、登入方式、持久化儲存與執行環境。原始碼開發使用 Node.js 24 與 pnpm 11，正式部署細節請依該指南。

繼續使用同一個 CLI，改為自己的服務地址，再授權該服務中的帳號。下方範例地址須替換成實際地址：

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

Agent 的工具與 Skills 不變，操作目標改為私有服務中的檔案與權限。Desktop 也能連接此服務；客戶端註冊與回呼設定請參考 [Agent 連接指南](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)。

## 把 Workspace 放進本機 Desktop 客戶端 [#desktop-start]

**Workspace Desktop** 將 Workspace、Agent 執行環境、Office 工具與內容預覽整合進本機客戶端，帶來類似 Codex 或 Cowork 的辦公體驗：描述目標，在對話旁查看文件或 Web App，提出修改，再審閱成果。

Desktop 可以連接剛才試用的雲端 Workspace、私有部署或本機 Workspace 服務。模型與對話由設定好的 Agent 宿主驅動，檔案和存取權限由所連接的 Workspace 管理。以下真實桌面案例展示創作、管理與協作如何連成工作流程。

[安裝並連接工作區](#desktop-install) · [體驗任務：用兩份原生內容完成預算審閱](#desktop-first-task)

### 把 Agent 工作方式帶進日常辦公 [#why-desktop]

辦公成果需要持續編輯、公式計算、團隊協作與變更審閱。Desktop 將這些環節放在同一工作環境，讓對話圍繞可編輯、可計算、可協作的內容展開。

- **連貫的上下文：** 隨時使用對話、檔案、工作區資料與本機引用。
- **產生 Office 內容與 Web App：** 建立可編輯的試算表、文件、簡報、關聯式表格與畫布，也可依 Office 資料產生互動頁面。
- **邊看邊改：** 在側邊預覽內容、檢查公式與版面，再透過對話要求具體修改。
- **審閱後交付：** 原生 Office 變更留在 Worktree，由人查看差異並確認合入共享空間。

### 安裝並連接工作區 [#desktop-install]

已有可擴充 Agent 桌面時，也可以安裝並啟用 Space 能力外掛，從 Space 連接服務、設定模型，再接入品牌外觀。本頁截圖採用此組合。完整 Workspace Desktop 發行版與外掛預覽的交付路徑不同，請依所安裝版本的發布內容或儲存庫說明操作。

1. 從 [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) 選擇 Desktop 安裝程式。桌面版本使用 agent-v 標籤，支援 Windows x64、macOS Apple Silicon 與 Linux x64。此交付方式仍為實驗性，版本與平台以實際發佈為準。

2. 在 **Settings → Workspace** 選擇服務位址，透過瀏覽器登入並授權。可連接既有服務，或依[本機執行說明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)準備本機服務。

3. 在 Models 設定支援的模型服務商、模型與憑證。Workspace 登入與模型存取分開設定，詳見[模型設定](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)。

4. 新增可存取的個人或團隊空間，建立對話並透過 @ 引用資料，再嘗試下方任務及變更審閱。

安裝程式包含 Agent 應用與 Office 工具；Workspace 服務另行在本機或伺服器執行，模型使用你設定的服務商。

### Skills：讓 Agent 理解工作區並完成任務 [#skills]

#### 讓既有 Agent 學會使用 Workspace

安裝給既有 Agent 的 [`univer-workspace-cli` Skill](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) 是探索入口，說明如何連接、定位目標並載入指引。完整執行階段 Skills 隨 CLI 發佈，與指令和 Facade API 版本配套；Desktop 的內建能力外掛也提供任務指引與工具。

| 指引 | 涵蓋內容 |
| --- | --- |
| `core` | 空間與檔案定位、任務草稿、內容驗證與審閱交付。 |
| `sheet` · `doc` · `slide` · `base` · `board` | 試算表、文件、簡報、關聯式表格與畫布。 |
| `blob` | 原始檔案上傳、下載與替換。 |
| `html-view` | 產生及管理即時 HTML 頁面，建立可互動的 Web App。 |
| `embed` · `cross-unit-formula` | 嵌入其他內容，以及跨內容的資料參照與公式。 |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

先載入 `core`，再依任務讀取產品或主題。`skills get` 列出參考路徑，透過 `uvw skills read <name> <path>` 讀取所需文件，或用 `--full` 一起載入。既有 Agent 透過 CLI 使用這些能力，Desktop 則將工具與指引整合進對話流程。

#### Desktop 內建的任務指引 [#desktop-skills]

Desktop 能力外掛內建 **univer** Skill 與參考資料，指引 Agent 定位空間和文件、使用 Office API、建立與檢查 Worktree。Agent 可查詢 API，在原生內容上執行並驗證結果。

[能力外掛](https://github.com/dream-num/univer-workspace/blob/main/packages/dsh-univer-workspace-plugin/README.md)組合檔案探索、Headless Facade 編輯、結構化檢查、匯入匯出與 Worktree 生命週期工具。目前預覽將草稿準備至可審閱狀態；正式發布使用已部署應用程式的審閱與合併流程。可在同一 Office 執行環境加入產業 Skills、範本與業務工具。

預覽外掛內建九個 Skills。通用 Skill 說明內容探索、身分與交付流程；各產品 Skill 提供 API 與驗證指引，Agent 依目前任務讀取需要的內容。

| Skill | 操作指引 |
| --- | --- |
| `univer` | 空間、檔案、草稿生命週期與交付 |
| `univer-sheet` | 公式、樣式、圖表與試算表驗證 |
| `univer-doc` | 文件結構、段落與表格 |
| `univer-slide` | 簡報製作與視覺版面檢查 |
| `univer-base` | 欄位、記錄與檢視 |
| `univer-board` | 圖形、連接線與畫布版面 |
| `univer-embed` | 在一個 Office 產品內嵌入另一個產品 |
| `univer-cross-unit-formula` | 跨 Unit 引用與計算 |
| `univer-html-view` | 構建及檢查綁定 Office 資料的 HTML 頁面 |

### 將 Agent 執行循環與 Office 能力分開組裝 [#desktop-architecture]

Skills 提供任務指引，工具透過 Headless 執行環境操作結構化內容，原生編輯器負責供人類展示和編輯。Workspace 提供檔案與協同脈絡，因此可以更換模型、加入業務工具或替換品牌介面，而不必重新實作 Office 引擎。

<Mermaid chart={"flowchart LR\nA[\"Agent 與模型\"]\nB[\"Skills 與工具\"]\nC[\"Office SDK<br/>Headless 操作與驗證\"]\nD[\"Workspace 服務<br/>檔案、協同與版本\"]\nE[\"桌面預覽<br/>原生編輯器與 Web App\"]\nF[\"Worktree 與內容比較<br/>人類審閱\"]\nA --> B --> C --> D\nD <--> E\nD --> F\nF --> E"} />

| 組成部分 | 職責 |
| --- | --- |
| [Web SDK](/guides/sheets) | 統一內容模型、Office 編輯介面、渲染、公式與 Headless Facade 操作。 |
| [Server SDK](/server) | 協同、版本與 Worktree 等能力，整合應用後端。 |
| [AI SDK](/ai) | 面向 Agent 的內容操作、檢查與驗證。 |
| Agent 執行環境與 Skills | DSH 提供對話、模型呼叫、工具編排與審批；Workspace 外掛接入 Office 工具與指引。 |
| Workspace 與 Desktop | 應用提供空間、檔案、身分整合及審閱介面；Electron 將這些能力交付為桌面應用。 |

可復用的是完整鏈路：需求 → 工具 → 可編輯內容 → 預覽 → 審閱 → 共享交付。Office SDK 提供辦公能力層，Agent 宿主提供對話與執行循環。可擴充現有[應用與外掛](https://github.com/dream-num/univer-workspace/tree/main/apps/agent)，或接入自有宿主與服務。
