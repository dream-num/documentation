**Univer Workspace** 是基於 **[Univer Office SDK](/overview)** 建置的開源辦公空間，供人與 Agent 協同工作。可編輯的 Office 內容與繫結資料的 Web App 放在個人與團隊 Space 中，分享、協同、版本和變更審閱也一併在這些空間中提供。[開源倉庫](https://github.com/dream-num/univer-workspace)包含應用、部署方案、CLI 和桌面客戶端。

你可以把 Workspace 部署在自己的基礎設施上，也可以先從[雲端線上試用](https://space.univer.ai)開始。已有 Agent 透過 Workspace CLI 接入。Workspace Desktop 把 Agent 對話和同一套工作區整合進本地應用。這幾種方式使用的是同一個服務和同一批檔案。

## 先在雲端體驗完整的 Workspace [#entry-points]

<span id="web-start" />

## 讓既有 Agent 連接雲端 Workspace [#cli-start]

在 Agent 的執行環境中安裝 CLI 和發現入口 Skill。需要 Node.js 22.12 或更新版本，推薦 Node.js 24。能執行命令的 Agent 可以使用這些工具，模型和對話仍由該 Agent 提供。請顯式設定雲端服務地址，使瀏覽器和 Agent 操作同一個 Workspace：

```bash
npm install --global univer-workspace-cli@latest
npx skills add dream-num/univer-workspace --skill univer-workspace-cli -g
uvw --version
uvw config set workspace.origin https://space.univer.ai
```

<details>

<summary>首次連接：完成一次瀏覽器登入</summary>

已有有效會話時可以跳過這一步。如果需要登入，執行：

```bash
uvw auth login
```

開啟返回的連結，在瀏覽器中登入並確認驗證碼。待使用者確認完成後，執行：

```bash
uvw auth login --complete
```

這一步只在建立會話時需要。完整命令與認證說明見 [Workspace CLI 指南](https://github.com/dream-num/univer-workspace/blob/main/apps/cli/README.md)。

</details>

瀏覽器完成首次授權後，CLI 會在後續任務中複用該會話。不需要為特定 Agent 編寫登入頁面或鑑權整合。給已連線的 Agent 下達任務，開啟它返回的連結，即可在 Web 中看到同一份內容，並在合入前審閱 Agent 對原生 Office 內容的修改。

## 把相同流程搬到私有部署 [#self-host]

[開源倉庫](https://github.com/dream-num/univer-workspace)包含 Server 和 Web。按照[部署指南](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)建置應用，再配置自己的域名、登入方式、持久化儲存和執行參數。從原始碼開發使用 Node.js 24 和 pnpm 11，生產部署細節以該指南為準。

部署前需要準備四個部分：

| 部分 | 需要設定什麼 |
| --- | --- |
| 服務 | 可訪問的 Workspace 地址，以及 Server + Web 應用。Desktop 和 CLI 都連線這套部署。 |
| 持久化資料 | 產品資料庫、協同資料庫和上傳檔案需要一起保留。預設部署將它們存放在 `.data` 下；使用 Docker 時需要掛載持久化卷。 |
| 身分 | 配置登入方式。接入 Desktop 時，註冊 Agent OAuth 客戶端，回撥地址必須完全匹配。 |
| SDK 授權 | 為部署網域建置 Web 時提供 `VITE_UNIVER_LICENSE`，並另外設定 Node.js 內容執行環境所需的授權。 |

模型憑據由 Agent 宿主管理，與 Workspace 登入分開配置。當前設定見[部署指南](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)和 [Agent 接入說明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md)。

繼續使用同一個 CLI，把服務地址指向自己的部署，並在該服務中授權一個賬號。把下面的範例地址替換為實際的服務地址：

```bash
uvw config set workspace.origin https://workspace.example.com
uvw auth login
```

Agent 使用的工具和 Skills 不變，操作物件變為私有服務中的檔案和權限。Desktop 也可以連線該服務。客戶端註冊和回撥配置見 [Agent 連線指南](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)。

## 把 Workspace 放進本機 Desktop 客戶端 [#desktop-start]

**Workspace Desktop** 把 Workspace、Agent 執行時、Office 工具和內容預覽整合進一個本地客戶端。辦公過程採用與 Codex 或 Cowork 類似的對話與預覽配合方式：描述所需結果，在對話旁檢視文件或 Web App，提出修改，再審閱結果。

Desktop 可以連線前文試用的雲端 Workspace、私有部署，也可以連線本機執行的 Workspace 服務。模型和對話透過配置好的 Agent 宿主執行，檔案和訪問權限由所連線的 Workspace 管理。下面的桌面案例展示生成、管理與協作如何銜接。

[安裝並連接工作區](#desktop-install) · [體驗任務：用兩份原生內容完成預算審閱](#desktop-first-task)

### 把 Agent 工作方式帶進日常辦公 [#why-desktop]

辦公工作不會在對話返回一個可下載檔案後結束。人還需要繼續編輯、基於真實資料計算、與同事協作，並決定接受哪些修改。Desktop 把這些環節放在同一個工作環境中。

- **保持上下文：** 對話、檔案、本地引用和工作區資料始終可以訪問。
- **原生 Office 內容與 Web App：** 可以建立、預覽和編輯電子表格、文件、簡報、Relational Tables 和 Canvases，也可以建置由 Office 資料支撐的互動頁面。
- **檢視並修改結果：** 在對話旁開啟內容，檢查公式和排版，再提出具體修改。
- **經審閱後交付：** Agent 對原生 Office 內容的修改保留在 Worktree 中，直到有人審閱併合入共享工作區。

### 桌面應用整合的能力

| 能力 | 使用體驗 |
| --- | --- |
| Agent 工作階段 | 對話和任務上下文儲存在本地，模型服務商與模型也在本地配置。 |

| 內容預覽 | 在對話旁開啟原生 Office 檔案或 Web App，檢查內容、互動和資料。 |

### 安裝並連接工作區 [#desktop-install]

如果已經在使用可擴充套件的 Agent 桌面，整合方式是安裝並啟用 Space 能力外掛，從 Space 連線服務、配置模型，再新增品牌皮膚。本頁截圖使用這套組合。完整的 Workspace Desktop 發行版和外掛預覽遵循不同的交付路徑，請按所安裝版本的釋出內容或倉庫說明操作。

1. 從 [GitHub Releases](https://github.com/dream-num/univer-workspace/releases) 選擇 Desktop 安裝包。桌面版使用 agent-v 標籤，按平臺選擇 Windows x64、macOS Apple Silicon 或 Linux x64 建置產物。桌面交付仍為實驗性，可用版本以已釋出的內容為準。

2. 在 **Settings → Workspace** 中選擇 Workspace 服務，透過瀏覽器登入並授權。可以連線已部署的服務，也可以按照[本地執行說明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#connect-to-a-local-workspace)在本機執行一個 Workspace 服務。

3. 在 Models 設定中配置支援的服務商、模型和憑據。Workspace 登入與模型訪問分開配置，詳見[模型配置說明](https://github.com/dream-num/univer-workspace/blob/main/apps/agent/README.md#model-credentials)。

4. 新增有權限訪問的個人或團隊 Space，開始對話，並使用 @ 引用源資料。執行下面的任務，然後開啟內容預覽和變更審閱。

安裝包包含 Agent 應用和 Office 工具。Workspace 服務獨立執行，可以在本機或遠端伺服器上；模型訪問使用所配置的服務商。

### Skills：讓 Agent 理解工作區並完成任務 [#skills]

這組 Skills 讓已有 Agent 在已連線的 Workspace 中建立和編輯 Office 內容與 Web App，再把修改交付審閱。請先[把 Agent 連線到 Workspace](#cli-start)；下面的指引操作該服務中的檔案，並遵循其權限。

#### 讓既有 Agent 學會使用 Workspace

安裝到已有 Agent 中的 [`univer-workspace-cli` Skill](https://github.com/dream-num/univer-workspace/blob/main/skills/univer-workspace-cli/SKILL.md) 是發現入口，說明如何連線 Workspace、定位目標和載入操作指引。完整的執行時 Skills 隨 CLI 釋出，與命令和 Facade API 保持一致。Desktop 內建的能力外掛也提供任務指引和工具。

| 指引 | 涵蓋內容 |
| --- | --- |
| `core` | 定位空間和檔案、在任務草稿中工作、檢查內容並交付審閱。 |
| `sheet` · `doc` · `slide` · `base` · `board` | 試算表、文件、簡報、關聯式表格（Relational Table）與畫布（Canvases）。 |
| `blob` | 原始檔案的上傳、下載與替換。 |
| `html-view` | 建立和管理用於互動式 Web App 的即時 HTML 頁面。 |
| `embed` · `cross-unit-formula` | 嵌入其他內容，以及跨內容型別連線資料和公式。 |

```bash
uvw skills list
uvw skills get core
uvw skills get sheet
uvw skills get html-view
```

先載入 `core`，再按任務載入所需的產品或主題。`skills get` 列出參考路徑；讀取單份文件可使用 `uvw skills read <name> <path>`，新增 `--full` 可以全部讀取。已有 Agent 透過 CLI 使用這些能力，Desktop 則把工具和指引整合進對話流程。

#### Desktop 內建的任務指引 [#desktop-skills]

Desktop 的能力外掛套件含 **univer** Skill 及其參考資料。它說明空間與文件之間的關係、如何使用 Office API，以及如何建立、檢查並交付 Worktree。這些說明與可執行工具配套，Agent 可以查詢 API、在原生內容上執行並檢查結果。

預覽外掛套件含九個 Skills。通用 Skill 說明發現、身分和交付，各產品 Skill 說明其 API 和結果驗證方式。Agent 按當前任務讀取相應部分。

### Office SDK 如何支撐 Workspace [#desktop-architecture]

Workspace 把原生編輯器、Agent 對內容的操作和團隊協同連線到同一套文件與權限上。可以基於這套開源應用和 Office SDK 開發，把精力集中在自己的業務流程、介面和整合上。

<Mermaid chart={"flowchart LR\nA[\"Agent\"] <--> S[\"Workspace Server\"] <--> E[\"編輯器\"]"} />

Agent 透過 CLI 或 Desktop 在 Node.js 中操作內容，使用者在 Web 或 Desktop 編輯器中檢視、編輯和審閱。Workspace Server 儲存共享文件、草稿和協同狀態，可以執行在本機、自己的伺服器或雲端。

| 層次 | 負責什麼 |
| --- | --- |
| [Web SDK](/guides/sheets) | 內容模型、公式、公開 Facade API 和原生編輯器。 |
| [AI SDK](/ai/content-operations) | API 查詢、結構化內容檢查，以及針對指定文件執行 Facade 程式碼。 |
| [Server SDK](/server) | 協同、修訂版本、Worktree 草稿和檔案轉換。 |
| 應用層 | Workspace 負責空間、檔案、權限、分享和審閱。Agent 宿主負責會話、模型呼叫與工具編排。 |

CLI 和 Desktop 共用同一個[內容操作層](https://github.com/dream-num/univer-workspace/tree/main/packages/client-core)。它的執行時池在宿主執行期間保持已載入的文件，並在執行前同步版本。不同客戶端因此複用同一套編輯與提交邏輯，詳見[執行時複用](/ai/runtime-architecture)。

[視覺檢查](/ai/visual-inspection)補充結構化檢查無法覆蓋的內容。截圖來自瀏覽器渲染，自動版面配置診斷目前能發現簡報中的文字溢位與重疊。

#### Agent 的修改如何成為可審閱的變更 [#agent-editing-flow]

以預算審閱為例，Agent 編輯的是一張包含公式和樣式的電子表格。原生 Office 的編輯路徑如下：

1. **定位並載入。** Agent 選擇文件和 Worktree，載入快照與 changeset，同步到選定的修訂版本。Unit 指一個文件例項，例如一個工作簿。
2. **透過 Facade 編輯。** Node.js 執行時對該 Unit 執行公開 Facade 呼叫。內容變更產生 mutation，這些 mutation 會被收集為 changeset 並提交到草稿。
3. **檢查結果。** Agent 讀回數值和公式，必要時檢查渲染結果。Agent 繼續在同一草稿中編輯，直到結果可以交付審閱。
4. **審閱並合入。** 人員在[內容比較](/overview/features/shared/compare)中檢查變更，再決定是否將 [Worktree](/ai/worktree) 合入共用版本。

**把 changeset 儲存到草稿並不等於合入。** 只有提交得到確認，Workspace 才報告寫入成功；衝突和未確認的提交會返回錯誤。在 Desktop 外掛中，合入和放棄工具也需要使用者批准，這一要求由應用的工具流程執行。

#### Web App 如何連接同一份辦公資料 [#web-app-data-flow]

釋出儀表盤和預算編輯器使用同一份電子表格。HTML View 在沙箱 iframe 中渲染頁面。Workspace 宿主解析使用者可訪問的源文件，並提供其已授權的內容引擎。指標卡和圖表訂閱源資料，因此不需要維護另一份預算副本。

對於可編輯繫結，寫入需要已登入身分和源文件的編輯權限。離開頁面時，宿主等待未完成的寫入和協同確認，並報告儲存失敗。HTML 頁面釋出和繫結寫回使用各自的儲存路徑，不會自動遵循原生 Office 的 Worktree 合入流程。詳見[實驗性雙向繫結](/overview/features/shared/binding)和 [HTML View 宿主實現](https://github.com/dream-num/univer-workspace/tree/main/packages/workspace-html-viewer)。

### 依自己的業務流程繼續擴充

| 目標 | 起點 |
| --- | --- |
| 產業文件與專屬任務 | 增加行業 Skills、模板和工具指引，並保留內容與視覺檢查。 |
| 自己的身分、儲存與分享方式 | 擴充套件 Workspace 應用及其伺服器端產品策略。 |
| 自己的 Agent 辦公客戶端 | 組合 Agent 宿主、能力外掛和品牌皮膚，再接入所需的模型和業務工具。 |

#### 例如：增加預算審閱 Skill [#domain-skill]

行業 Skill 可以承載團隊的審閱規則，同時複用已有的 Office 工具：

- 定位源工作簿、賬期和預算／實際支出列，編輯前詢問缺失的業務定義。
- 載入表格操作指引，建立 Worktree，並使用 Facade 更新公式、準備審閱文件。
- 檢查合計、公式結果和展示效果，報告變更檔案和已執行的檢查，再把草稿交給審閱人。

業務規則和模板放在 Skill 中，訪問檢查、草稿儲存和合入批准留在應用層。接入 ERP 或 CRM 時，增加一個返回所需資料的應用工具，然後複用同一套 Office 編輯與審閱流程。Skill 負責指導執行，不授予檔案訪問權限。
