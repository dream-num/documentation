**Univer ワークバスディのオフィス**(`workbuddy-univer-office`)は、**[Univer Office SDK](/overview)**の公開API上に構築されたローカルオフィス統合です。 ローカルMCPサービスとスキルは、ワーブディに作者、検査、プレビュー、およびレビューを草案化し、ファイルはローカルワークスペースに残ります。

<Callout type="info">
これは開発プレビューです。 パブリックnpmランタイムは、ローカルの統合をサポートしています。 正式なマーケットプレースインストールとフルインホストレビューはまだ受け入れテストが必要です。
</Callout>

[インストールと接続](#quick-start) · [タスクを試す](#first-task) · [Skills とツール](#skills)

## インストールと接続 [#quick-start]

WorkBuddy 5.8.3 または newer と Node.js 22 (22.12 または newers) が必要です。この例では、パブリックランタイム 0.1.6 を使用し、ローカル `~/.univer-office/workspace` ディレクトリに Office コンテンツのデフォルト値を使用します。

### 1. ローカル実行パッケージをインストール

```bash
npm install --global --ignore-scripts workbuddy-univer-office@0.1.6 --registry=https://registry.npmjs.org/
univer-office --version
```

MCP を接続する前にインストールを完了します。 それ以外の場合は、ホストがハンシャケを待ち、タイムアウトを超過することができます。 ローカル接続は、クラウドアカウントやOffice API キーを必要としません。

### 2. ローカル MCP を接続

WorkBuddy で認証された作業ディレクトリを開き、次の設定でカスタム stdio MCP サーバーを追加します。

```json
{
  "mcpServers": {
    "univer-office": {
      "type": "stdio",
      "command": "univer-office",
      "args": []
    }
  }
}
```

WorkBuddyが`univer-office`を見つけることができない場合は、インストールの絶対パスで`command`を置き換えます。 macOSまたはLinuxで、`command -v univer-office`でそのパスを取得する。 Windowsでは、`Get-Command univer-office`を使用します。 WorkBudDYがstdioサーバーを起動し、同じストレージディレクトリに独立したHTTPサービスを開始することはできません。 異なるストレージディレクトリを使用するには、`WORKBUDDY_OFFICE_WORKSPACE`環境を絶対パスに設定します。

### 3. 操作 Skill をインポート

Git と Python 3 で、パブリックリポジトリから指示のみのスキル ZIP を生成します。アプリケーションビルドは必要ありません。

```bash
git clone https://github.com/dream-num/workbuddy-univer-office.git
cd workbuddy-univer-office
python3 scripts/package-workbuddy-skills.py
```

WorkBuddy のスキルマネージャーで `.data/packages/univer-office-workbuddy-skill.zip` をインポートします。MCP が接続されると、アシスタントに Office サービスの状態をチェックし、下のタスクを送信します。このスキルはガイダンスを供給し、MCP サーバーが実行を実行しますので、一緒に使用してください。

## すぐに試せるタスク [#first-task]

```text
Univer Office でローカルファイル sales-review.univer を作成し、5件のサンプルを持つ英語の売上表を作ってください。列は Product、Quantity、Unit Price、Revenue です。Revenue は数式で計算し、売上合計と製品別売上グラフを追加してください。
確定した書き込みと計算結果を検証し、この Sheet だけを右側にプレビュー表示して、ブラウザのレビューリンクを渡してください。独立した下書きで作業し、私が承認するまでマージしないでください。
```

### 確認できる結果

WorkBuddy は、右上の 1 つの読み取り専用のスプレッドシートプレビューを表示します。Office ファイルがローカルに残っている間、完全なビュー、比較、およびマージの確認がブラウザーで開きます。 1 つのシートから、式とチャートがすぐに表示され、同じ応答で複数のプレビューカードにホストのルーティング制限を回避します。

### 続けて試す

最初の結果の承認と統合後、「同じ販売シートの新しい草案で、最初のレコードの単価を10%上昇させ、合計収益を更新し、確認されたバージョンと比較して開く」と尋ねます。 私のレビューを待ってください。 これは、前後の比較のためにコンクリートを生成します。

## Skills とツールの連携 [#skills]

1つの[`univer-office` スキル](https://github.com/dream-num/workbuddy-univer-office/tree/main/skills/univer-office)は、必要に応じてロードされた7つの製品とクロスコンテンツの参照で、ワークフローを定義します。エージェントは、`univer_api`で公開ファサードAPIを問い合わせ、編集、書き込みの確認、コンテンツの読み込み、MCPによるプレビューを行います。同じOffice SDKモデルは、ヘッドレス処理とブラウザのレンダリングを駆動し、バージョンに加えて、Worktreeは、すべての変更を識別可能、比較可能、およびレビュー可能にします。

## できること

- 既存のアシスタントでコンテンツを作成する:WorkBuddyにスプレッドシート、文書、プレゼンテーション、リレーショナルテーブル、キャンバスを作成または更新するように依頼してください。
- ライブプレビューに従ってください: ホスト内の読み取り専用のプレビューを調べたり、フルビューとインターフェイスを比較するための外部ブラウザを開きます。
- 決定前の変更を確認する: ドラフトビューと比較は読み取り専用です。固定バージョンを比較し、セマンティックの違いを調べ、影響を受けるコンテンツに移動します。
- ドラフトから配達に移動: エージェントは、Worktreeを編集します。, 人がマージすることを選択します。, 変更, または廃棄, そして、サポートされているフォーマットは、選択した確認されたバージョンからエクスポートされます。.

## Office SDK が担う部分 [#sdk-integration]

WorkBuddy は、会話と MCP ツールの呼び出しを処理します。ローカルサービスは、Office SDK の Headless ランタイム、ファサードのオーサリング、コラボレーションバージョン、および Worktrees を構成し、ブラウザのプレビューは同じコンテンツモデルをレンダリングします。このプロジェクトでは、ローカルツールとして SDK の機能と、エージェントホスト用のレビューインターフェイスをパッケージ化する方法を説明します。
