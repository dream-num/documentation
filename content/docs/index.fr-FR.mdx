Univer Office SDK se compose de trois parties : Web SDK, Server SDK et AI SDK. Il couvre les feuilles de calcul, les documents, les diapositives, la table relationnelle, les toiles et les PDF.

Web SDK est le moteur de contenu partagé. Il exécute les éditeurs de navigateurs et fonctionne aussi sans tête pour traiter le contenu sans interface utilisateur. Les deux autres SDK s'appuient sur ce temps d'exécution sans tête : Server SDK ajoute la collaboration et le traitement de fichiers, et AI SDK apporte des opérations de contenu et d'inspection des résultats pour les agents.

### Web SDK : le moteur de contenus partagés [#web-sdk-the-shared-content-engine]

Utilisez Web SDK pour afficher, modifier ou traiter le contenu Office dans une application. Les API Facade sont l'interface vers le contenu, les données et l'interface utilisateur, que le code fonctionne dans un éditeur de navigateur ou dans un processus Node.js sans tête.

Web SDK est entièrement construit à partir de plugins, y compris les capacités de produit, l'interface utilisateur de l'éditeur et des fonctionnalités individuelles telles que trouver et remplacer. Une application peut démarrer à partir d'un préréglage, ou sélectionner le produit et les plugins de fonctionnalité dont elle a besoin et les assembler avec leurs dépendances.

Les fonctionnalités spécifiques à l'entreprise peuvent être implémentées dans des plugins personnalisés sans modifier le code de base de Univer. Le même moteur de contenu s'adapte à chaque environnement à travers son ensemble de plugins : une application de navigateur charge l'interface utilisateur de l'éditeur, tandis qu'une application sans tête omet ces plugins d'interface utilisateur. Voir [Architecture Univer: conception de plugins](/blog/univer#plugins).

**rendu de toile partagée.** Tout le contenu Office rend par la même architecture Canvas, de sorte que les types de contenu peuvent réutiliser le code de mise en page et de dessin et peuvent contenir du contenu imbriqué. Par exemple, le texte de la cellule Spreadsheet suit la mise en page du document et le chemin de rendu, qui maintient la présentation cohérente. Voir [Architecture du moteur de rendu](/blog/rendering).

**Calcul hybride.** Le moteur de formule calcule dans le frontend et sur un moteur Rust côté serveur. Le calcul de frontend maintient la fonction d'édition réactive, tandis que le moteur Rust gère de grandes charges de travail de formule. Voir [capacités de la formule](/guides/sheets/features/core/formula) et [calcul côté serveur](/overview/features/shared/server-calculation).

Commencer par [feuilles de calcul](/guides/sheets/getting-started/quickstart). Le même SDK couvre également [Documents](/guides/docs), [Diapositives](/guides/slides), [Tableaux relationnels](/guides/bases), [planches](/guides/boards) et [PDF](/guides/pdfs).

### Server SDK : connecter la collaboration et les fichiers [#server-sdk-connect-collaboration-and-files]

Server SDK ajoute des extensions partagées d'édition, de conversion de fichiers et de backend. Il s'appuie sur les capacités de contenu sans tête de Web SDK : les modules s'exécutent dans votre propre backend et utilisent la propre identité, permissions et stockage de l'application.

**Collaboration en temps réel.** OT (Operational Transformation) gère des opérations simultanées telles que les changements de ligne ou de colonne et les modifications de contenu. Une modification s'applique localement d'abord, et les répliques convergent alors tout en préservant l'intention de chaque utilisateur lorsque c'est possible. Worktree sont des modules distincts qu'une application ajoute au besoin. Voir [conception d'édition collaborative](/blog/ot) et les [collaboration démarrage rapide](/server/collaboration/quick-start).

**Conversion de fichiers.** Conversion déplace le contenu entre les fichiers Office et les données de document Univer et connecte les étapes d'importation, de modification et d'exportation. Il fonctionne avec ou sans collaboration. Voir [Importation et exportation de fichiers bureautiques](/server/import-export/node) pour les API de conversion et [intégration d'échange de fichiers](/server/import-export) pour les téléchargements, les tâches et les téléchargements.

**Déploiement et mise à l'échelle.** Les modules sont assemblés à l'intérieur de votre propre application Node.js, et une seule machine est suffisante pour démarrer. À mesure que la charge augmente, l'application peut déplacer la conversion de fichiers vers un service séparé et ensuite passer à plusieurs nœuds de collaboration. Voir [architecture de l'application](/server/architecture) et [guide de déploiement](/server/deployment).

Le [Aperçu de Server SDK](/server) décrit les modules plus en détail.

### AI SDK : donnez aux agents un point d'entrée [#ai-sdk-give-agents-an-entry-point]

AI SDK ajoute des capacités Office aux agents existants, à l'automatisation et aux CLI spécifiques à l'application. Il s'appuie sur les API sans tête d'exécution et Facade de Web SDK pour les opérations de contenu, le calcul et l'inspection.

Les outils de bureau **Connectez votre pile d'agents existante.** peuvent être exposés sous la forme d'API TypeScript ou d'un CLI assemblé à partir du SDK. La sélection des modèles, l'orchestration des tâches et les compétences restent dans l'application.

**Créer du contenu qui reste modifiable.** Un agent lit la structure du document, localise la plage ou le paragraphe dont il a besoin et utilise les API Facade pour créer et modifier des feuilles de calcul, des documents, des diapositives et d'autres contenus, y compris le calcul de la formule. Le résultat conserve sa structure de contenu et reste modifiable afin que les gens puissent continuer à l'affiner. Voir [Opérations de contenu](/ai/content-operations).

**Inspecter, puis réviser.** L'agent lit les valeurs et les résultats de la formule et inspecte une capture d'écran de la page réelle. Pour les diapositives, les vérifications de mise en page identifient également le texte qui s'écoule hors de la page, déborde ou se chevauche. L'agent utilise cette rétroaction pour réviser le contenu et le vérifier à nouveau, ce qui complète la lecture → modifier et calculer → inspecter → réviser la boucle. Voir [Contrôle visuel](/ai/visual-inspection).

Avec Server SDK, [Worktree](/ai/worktree) isole les changements intermédiaires effectués par un agent jusqu'à ce qu'une personne les examine et les fusionne dans l'application Web. Commencez par [Aperçu de AI SDK](/ai).

## Flux de travail des applications [#application-workflow]

<Mermaid chart={"flowchart TB\n    Human[\"Utilisateur humain\"] --> Browser\n    Agent[\"Agent AI / Automatisation\"] --> AI[\"AI SDK · Opérations et vérification\"]\n    subgraph WebSDK[\"Web SDK · Moteur de contenu partagé\"]\n      Browser[\"Éditeurs de navigateur\"]\n      Headless[\"Headless · Modèle de contenu et Facade APIs\"]\n    end\n    Server[\"Server SDK · Collaboration, conversion et extensions\"] -->|Dépend de| Headless\n    AI -->|Dépend de| Headless\n    Browser <-->|Contenu partagé| Server\n    AI -.->|Collaboration et révision| Server\n    Server --> Storage[\"Identité, autorisations et stockage de l'application\"]\n    classDef default rx:8,ry:8,stroke-width:1px"} />

- **Éditeur intégré**: Web SDK affiche et modifie le contenu dans une application.
- **Demande de collaboration**: Web SDK et Server SDK ensemble permettent aux utilisateurs de modifier des documents partagés.
- **Collaboration humaine et agent** : les agents édifient et vérifient les ébauches par AI SDK, Server SDK gère les versions et fusionne, et l'application Web fournit la visualisation, la comparaison et l'examen humain.

<Callout title="Fondement et dépendances partagés">
  Web SDK fonctionne indépendamment, en tant qu'éditeur ou en tant que moteur de contenu sans tête. Server SDK et AI SDK dépendent tous les deux des capacités sans tête de Web SDK: fonctionner sans interface utilisateur nécessite toujours le contenu. Une application permet les services et les modules dont elle a besoin, et un workflow humain complet combine généralement les trois SDK.
</Callout>

## Prochaines étapes [#next-steps]

Commencez par l'exécution du contenu Web SDK. Server SDK et AI SDK complètent le premier flux de travail de l'application, et des modules supplémentaires peuvent être ajoutés au besoin. Conservez les versions de paquets Univer associées alignées et préparez l'environnement, l'autorisation et les licences dont les modules choisis ont besoin.

[Exemples](/overview/examples) collecte des applications open-source, des intégrations d'agents, des démos et des dépôts. Vous pouvez également essayer les produits Office dans le [vitrine en ligne](https://office.univer.ai).
