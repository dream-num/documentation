このページでは、スプレッドシートがページ入力、双方向のドキュメントコラボレーションセットアップ、およびエージェントが操作できる CLI に拘束される3つの作業例を紹介します。 1つの例を選択し、コーディングエージェントにプロンプトが表示され、統合とデプロイ手順に従います。

## 最初に作るものを決める

オフィスSDKは、シート、ドキュメント、スライド、リレーショナルテーブル、キャンバス、およびPDFをカバーしています。 アプリケーション目標に合った統合パスを特定します。

| 目的 | 開始するガイド | 最初の完了条件 |
| --- | --- | --- |
| Office エディターを組み込む | [Web SDK のインストール](/guides/sheets/getting-started/installation) | コンテンツを作成、編集、保存し、再度開ける。 |
| コンテンツと業務画面を連動させる | [Facade API](/guides/sheets/getting-started/facade) | 両方の方向にページ入力とセルを結合し、実際の計算結果を表示します。 |
| 共同編集を追加する | [Server SDK 共同編集クイックスタート](/server/collaboration/quick-start) | 独立した2つのセッションで同じ内容を編集し、互いの変更が同期される。 |
| Office ファイルを取り込み、処理し、書き出す | [ファイル変換](/server/import-export/node) | 実際のファイルを取り込み、編集、書き出し、結果を確認できる。 |
| Agent や CLI からコンテンツを操作する | [AI SDK コンテンツ操作](/ai/content-operations) | 読み込み、構造確認、変更を実行し、確定結果や出力を検証できる。 |
| 人と Agent の共通ワークスペースを作る | [Worktree とレビュー](/ai/worktree) | エージェントが分離されたドラフトで変更されるので、人はそれらを比較、見直し、そしてマージすることができます。 |

これらの機能を必要に応じて組み合わせます。 [おすすめ商品](/overview/features)は、各製品がサポートしているもののリストをリストします。 以下の3つの例では、開始から終了までの1つの完全なワークフローを紹介します。

## Agent と開発を始める

エージェントに要件と[llms.txt の使い方](/llms.txt)のドキュメントのインデックスリンクを指定します。SDK全体のドキュメントをプロンプトにコピーする必要はありません。再利用可能なテンプレートから始めて、3つの完全な例のいずれかを貼り付けます。

### 例1：表計算との連動

数量の入力欄とセルを双方向に連動させ、数式で計算した見積総額をページに表示します。

```text
Univer Office SDK で、ローカルで動作する単一ページの見積アプリを作ってください。
https://docs.univer.ai/ja-JP/llms.txt と関連する完全な例を読み、
SDK パッケージのバージョンを揃えてください。

基本の Sheets プリセットで編集可能なネイティブシートを組み込みます。
モニター2台×1200、キーボード5個×300、ヘッドセット3個×200を用意し、
各行の金額と合計はシートの数式で計算してください。

横に「モニター数量」の入力欄と「見積合計」のカードを置きます。
入力欄とセルを双方向に連動させ、カードは実際の数式結果を読み取ります。
画面側で金額を再計算せず、ブラウザーへの保存と再読み込みでの復元に対応します。

初期合計4500、数量を3にすると5700になることを確認してください。
セルを直接編集しても入力欄と合計が更新され、保存後の再読み込みで復元されること。
この機能だけを実装し、実際に動作確認してプレビューリンクを提示してください。
```

**それを試みて下さい:** モニターの数量を 2 から 3 に変更し、合計が 4500 から 5700 に移行します。シートを編集すると、ページを直接更新します。保存してリフレッシュした後、データは復元されます。[Web SDKのインストール](/guides/sheets/getting-started/installation)、[ファサードAPI](/guides/sheets/getting-started/facade)。

### 例2：文書の共同編集

同じ文書で2つの独立したセッションを開き、編集が両側に表示されることを確認します。

```text
Univer Office SDK で、ローカルで動作する2人の文書共同編集デモを作ってください。
https://docs.univer.ai/ja-JP/llms.txt と、次のリポジトリの現行例を参照し、
https://github.com/dream-num/univer-collaboration-examples
フロントエンドとサーバーの SDK バージョンを揃えてください。

Alice と Bob 用のネイティブなモダン文書エディターを左右に置きます。
独立した実行環境とオンラインセッションで実際の Server SDK 共同編集サービスに接続し、
公式例に従ってサーバーが作成した同じ文書を明示的に読み込みます。短い文章を用意します。

左で入力すると右に表示され、右で続けて入力すると左も更新されるようにします。
SDK の共同編集プロトコルを使い、固定のデモユーザー2人とメモリー内ストレージだけを使います。
前後端を1つのローカルサービスで提供し、ログイン、ファイル管理、AI チャットは追加しません。
Pro License は環境変数から読み込み、未設定なら SDK の既定の動作と表示を維持します。

双方向の入力後に内容が一致し、サーバーで更新が確定することを確認してください。
再読み込み後も内容が復元されること、サービスの再起動でメモリー内データが消えることも説明します。
この機能だけを実装し、実際に動作確認してプレビューリンクを提示してください。
```

**それを試みて下さい:** 左に文をタイプし、右に入力し続けます。両側は更新を受け取ります。ページをリフレッシュし、テキストは残ります。このデモはすべてのデータをメモリに保存するので、サービスの再起動はそれをクリアします。デプロイ前に永続的なデータベースを接続します。 [Server SDKコラボレーションクイックスタート](/server/collaboration/quick-start)で続けてください。

### 例3：自分の you-cli を作る

あなた自身のオフィスのツールを構築し、あなたが既に使用しているエージェントにそれを提供. ツーリングは、シートをカバーする必要があります, Doc, スライド, リレーショナルテーブル, そして、キャンバス, しかし、単一のDocで開始します "生成 → プレビュー → 会話を通じて変更する" ワークフロー.

```text
Univer Office SDK で、このプロジェクト専用の you-cli と Web プレビューを作ってください。
https://docs.univer.ai/ja-JP/llms.txt と、以下の完全な内容操作例を読んでください。
https://github.com/dream-num/univer-cli-examples
前後端と AI SDK のバージョンを揃え、インストール済みの型で API を確認してください。

Sheet、Doc、Slide、Relational Table、Canvases に対応し、まず Doc で実装します。
./you-cli create <type> --name <name>、inspect --unit <id>、
execute --unit <id> --file <path>、open --unit <id>、--help を用意してください。
ツールをこのプロジェクトに置き、現在の Agent が読む説明または Skill を作成してください。
unitId、種類、確定結果、プレビュー URL などを対応する JSON 結果に含めてください。

CLI と Web は同じ実際の共同編集コンテンツを扱い、開いているネイティブエディターを更新します。
書き込みの確定を待って読み戻し、コンテンツと一覧を永続化してください。
open は URL を返し、Agent が宿主のプレビュー機能で開きます。利用可能なら右側に表示します。
自然言語理解は現在の Agent を使い、ライセンスは環境から読み込んで必要な表示を保ってください。

会話で週次レポートを生成して開き、続く会話でリスクと担当者を追加してください。
同じ unitId と開いているプレビューを使い、再読み込み・サービス再起動後も復元してください。
実際に検証し、プレビューと使い方を提示してください。この例のサービスだけを起動してください。
```

#### 会話で使う

上記のプロンプトをコーディングエージェントに送ります。 ツールが存在すると、エージェントはプロジェクトの指示を読んでいると、同じ会話で次のようになります。

```text
you-cli で進捗、リスク、来週の計画を含む週次レポートを作り、Web プレビューを開いてください。
```

結果を見直した後、次の手順を実行します。

```text
同じレポートに「納期が遅れる可能性がある」というリスクを追加し、担当者を林さんにしてください。
すでに開いているプレビューを更新してください。
```

エージェントは同じドキュメントの`unitId`を再利用します。 ホストがプレビューパネルを提供する場合、ページは会話の横に表示されます。 他の環境では、返されたブラウザリンクを使用します。

#### you-cli コマンド一覧

プロンプトが指定する project-local コマンドです。置換 `UNIT_ID` と、 `unitId` ということで `create` を返します。 エージェントは書きます `edit.js` ファサード API を使用します。

| 操作 | コマンド | 結果 |
| --- | --- | --- |
| 作成 | `./you-cli create doc --name "週次レポート"` | 文書を作り `unitId` を返します。`sheet`、`slide`、`base`、`board` も選べます。 |
| 確認 | `./you-cli inspect --unit UNIT_ID` | 実際のコンテンツと現在のリビジョンをお読みください。 |
| 変更 | `./you-cli execute --unit UNIT_ID --file edit.js` | 変更を実行し、コミットを待ち、結果を返します。 |
| 表示 | `./you-cli open --unit UNIT_ID` | 同じ文書の Web URL を返し、Agent が開きます。 |

`./you-cli --help`は完全なインターフェイスを出力します。これらのコマンドの背後にあるAPIについては、[AI SDKコンテンツ操作](/ai/content-operations)と完全な[CLI SDK の例](/overview/examples/cli-sdk)を参照してください。

## アプリに最初の流れを組み込む

Web SDKは共有コンテンツランタイムを提供します。複数の人が一緒に編集する必要がある場合、Server SDKとエージェントがコンテンツを操作する必要がある場合は、AI SDKを追加します。各パッケージの役割については、[オフィスSDKの概要](/overview)を参照してください。

| 手順 | アプリで接続するもの | 関連ガイド |
| --- | --- | --- |
| エディターの組み込み | プリセットをマウントし、ファサード API を使用してビジネスインタラクションを接続し、スナップショットを保存し、インスタンスをディスポースします。 | [Web SDK 導入](/guides/sheets/getting-started/installation) |
| バックエンドの接続 | 既存のアイデンティティと権限を再利用し、共有文書のデータベースを設定し、必要に応じてファイルインポートとエクスポートを追加します。 | [共同編集](/server/collaboration/quick-start)、[ファイル変換](/server/import-export/node) |
| 既存 Agent の接続 | コンテンツの操作、計算、検証をツールやCLIとして公開します。レビューが必要な場合は、Worktreeを追加します。 | [AI SDK コンテンツ操作](/ai/content-operations)、[Worktree](/ai/worktree) |

## アプリケーション構成

既に実行しているアプリケーションとエージェントは、同じOfficeコンテンツで動作することができます。インターフェイスは、インタラクション、エージェントコールツール、バックエンドは、ID、パーミッション、ストレージの所有権を保持します。

**ブルーノードは、あなたによって供給され、管理されます。** インターフェイス、既存のエージェント、アイデンティティと権限を持つビジネス API、データベース、およびファイルストレージ。 マークされたノードは、アプリケーションに統合する Univer機能です。

エディタを埋め込むだけで、ローカルのスナップショットが十分です。共有編集にはバックエンドが必要です。エージェントが既に使用しているモデルとオーケストレーションを保持し、AI SDK がコンテンツ操作を処理し、分離した編集、比較、レビューが必要な場合は Worktreeを追加します。

## Workspace を使ったビルドとデプロイ

[Univer ワークスペース](https://github.com/dream-num/univer-workspace)は、完全なオフィスワークスペースですべての3つのSDKを結合します。ワークスペースリポジトリのルートから次のコマンドを実行し、前提条件の[フィードバック](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md)に従ってください。

1. **現地で開発。** 依存関係をインストールし、`pnpm workspace:dev:server` と `pnpm workspace:dev:web` を 2 つの別々のターミナルで実行し、`http://127.0.0.1:5173` を開きます。 Web 開発サーバーは、バックエンドへの API と WebSocket リクエストをプロキシします。
2. **ビルドと実行。** Workspace アプリだけをビルドし、本番用エントリーを起動します。

```bash
pnpm --filter @univerjs/univer-workspace build
pnpm workspace:start
```

ビルドは、Webアセットを`dist/public`に置き、`dist/server`にサーバーコードを配置します。 単一のNode.jsプロセスは、静的なページとAPIの両方を提供します。

3. **展開の準備** ライセンス、アイデンティティ、およびデータディレクトリを構成します。 持続的な製品データ、コラボレーションデータ、アップロードされたアセットは、サービスを再始動し、データを復元していることを確認します。 [Docker デプロイメント](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker)と[建築設計](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/docs/architecture.md)を参照してください。

単一プロセスが不十分な場合、[Server SDK展開ガイド](/server/deployment) はサービスの分割方法を説明します。
