**Univer Office SDK состоит из трех частей: Web SDK, Server SDK и AI SDK.** Они используют среду выполнения контента Office для электронных таблиц, документов, слайдов, реляционных таблиц, досок и PDF-файлов, позволяя людям и агентам AI работать с одним и тем же контентом внутри вашего продукта.

**Названия продуктов:** [Реляционная таблица](/docs/features/relational-table) называется `Base` в SDK и API; [Холсты](/docs/features/canvas) называется `Board`.

Web SDK предоставляет механизм общего контента, позволяющий использовать как браузерные редакторы, так и автономную обработку контента. Server SDK и AI SDK зависят от этой автономной среды выполнения. Server SDK добавляет совместную работу и обработку файлов, а AI SDK — операции с контентом и проверку для агентов.

### Web SDK: механизм общего контента [#web-sdk-the-shared-content-engine]

Для разработчиков, отображающих, редактирующих или обрабатывающих содержимое Office в своих приложениях. Используйте Facade APIs для работы с контентом, данными и UI в редакторах браузера или автономных приложениях Node.js.

Web SDK использует архитектуру плагинов: возможности продукта, редактор UI и отдельные функции, такие как поиск и замена, могут быть объединены с помощью плагинов. Начните с предустановки или выберите плагины продуктов и функций, необходимые вашему приложению, и соберите их с их зависимостями.

Вы также можете разрабатывать собственные плагины для конкретных бизнес-функций без изменения основного кода Univer. Различные комбинации плагинов адаптируют один и тот же механизм контента к каждой среде: приложения браузера загружают редактор UI, а безголовые приложения не включают плагины браузера UI. См. [Архитектура Univer: дизайн плагина](/blog/univer#plugins).

**Визуализация на основе общего холста.** Содержимое Office использует общую архитектуру рендеринга на основе холста, что позволяет типам контента повторно использовать возможности макета и рисования, а также поддерживать вложенный контент. Например, текст ячейки электронной таблицы повторно использует макет и рендеринг документа для единообразного представления содержимого. См. [Архитектура механизма рендеринга](/blog/rendering).

**Гибридные вычисления.** Механизм формул поддерживает гибридную модель вычислений, в которой внешние вычисления работают с серверным механизмом Rust, сочетая быстрое редактирование с производительностью для больших рабочих нагрузок с формулами. Изучите [возможности формулы](/guides/sheets/features/core/formula) и [расчет на стороне сервера](/docs/features/shared/server-calculation).

[Начните с электронных таблиц](/guides/sheets/getting-started/quickstart) или выберите [документы](/guides/docs), [слайды](/guides/slides), [реляционные таблицы](/guides/bases), [холсты](/guides/boards) и [PDF-файлы](/guides/pdfs).

### Server SDK: соедините совместную работу и файлы [#server-sdk-connect-collaboration-and-files]

Для разработчиков, добавляющих совместное редактирование, преобразование файлов и внутренние расширения. Используйте возможности автономного контента Web SDK, интегрируйте модули в свою собственную серверную часть и используйте удостоверения, разрешения и хранилище вашего приложения.

**Совместная работа в режиме реального времени.** OT (Оперативное преобразование) обрабатывает параллельные операции, такие как изменения строк/столбцов и редактирование содержимого. Изменения сначала применяются локально, а затем распространяются на реплики, сохраняя при этом намерения пользователя, где это возможно. При необходимости добавьте историю, комментарии и Worktree. См. [дизайн для совместного редактирования](/blog/ot) и [быстрый старт сотрудничества](/server/collaboration/quick-start).

**Преобразование файлов.** Преобразование между файлами Office и данными документа Univer для импорта, редактирования и экспорта с возможностью совместной работы или без нее. См. [Импорт и экспорт файлов Office](/server/import-export/node) для API-интерфейсов преобразования и [интеграция обмена файлами](/server/import-export) для загрузки, задач и скачиваний.

**Развертывание и масштабирование.** Соберите модули в собственное приложение Node.js. Начните на одном компьютере, раздельно конвертируйте файлы по мере роста нагрузки, а затем масштабируйтесь до нескольких узлов совместной работы. См. [архитектура приложения](/server/architecture) и [руководство по развертыванию](/server/deployment).

[Explore Server SDK](/server).

### AI SDK: предоставить агентам точку входа. [#ai-sdk-give-agents-an-entry-point]

Для разработчиков, добавляющих возможности Office к существующим агентам, средствам автоматизации и интерфейсам командной строки для конкретных приложений. Используйте среду автономного выполнения Web SDK и Facade APIs для операций с контентом, вычислений и проверки.

**Подключите существующий стек агентов.** Предоставляйте доступ к инструментам Office через API-интерфейсы TypeScript или приложение CLI, собранное на основе SDK. Ваше приложение управляет выбором модели, оркестровкой задач и навыками. Агенты получают результаты выполнения и отзывы о проверке, а затем продолжают свои рабочие процессы.

**Создавайте контент, который можно редактировать.** Агенты читают структуру документа, находят диапазоны или абзацы, а затем используют Facade APIs для создания и изменения электронных таблиц, документов, слайдов и другого контента, включая вычисления по формулам. Результаты сохраняют структуру контента и возможности редактирования, поэтому люди могут продолжать их совершенствовать. См. [операции с контентом](/ai/content-operations).

**Проверьте, затем исправьте.** Прочитайте значения и результаты формул, а также просмотрите снимки экрана фактической страницы. Для слайдов проверки макета также выявляют выходящий за пределы страницы, перекрывающийся и перекрывающийся текст. Агенты используют обратную связь для пересмотра и повторной проверки, образуя цикл чтения → редактирования и расчета → проверки → проверки. См. [визуальный осмотр](/ai/visual-inspection).

Подключитесь к Server SDK и используйте [Worktree](/ai/worktree) для изоляции изменений промежуточного агента перед проверкой человеком и объединением в веб-приложении. [Explore AI SDK](/ai).

- **Встроенный редактор**: используйте Web SDK для отображения и редактирования содержимого вашего приложения.
- **Совместное приложение**: объединить Web SDK и Server SDK, чтобы пользователи могли вместе редактировать общие документы.
- **Сотрудничество человека и агента**: агенты редактируют и проверяют черновики через AI SDK, Server SDK управляет версиями и объединением, а веб-приложение обеспечивает просмотр, сравнение и взаимодействие с человеком. Все три вносят вклад в полный рабочий процесс проверки.

<Callout title="Общая основа и зависимости">
  Web SDK может работать независимо как редактор или автономный движок контента. Server SDK и AI SDK зависят от возможностей автономного управления Web SDK: для работы без браузера UI по-прежнему требуется среда выполнения контента. Включите службы и модули, необходимые вашему приложению; Полный рабочий процесс «человек-агент» обычно объединяет все три SDK.
</Callout>
