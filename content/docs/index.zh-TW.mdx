Univer Office SDK 包含三部分：Web SDK、Server SDK 和 AI SDK，覆蓋電子表格、文件、簡報、關係型表格、畫布和 PDF。

Web SDK 是共用的內容引擎，既執行瀏覽器編輯器，也以 Headless 方式在無介面環境中處理內容。另外兩個 SDK 都建立在它的 Headless 執行時之上：Server SDK 增加協同和檔案處理能力，AI SDK 增加面向 Agent 的內容操作和結果檢查能力。

### Web SDK：統一內容引擎 [#web-sdk-the-shared-content-engine]

要在應用中展示、編輯或處理 Office 內容，可使用 Web SDK。無論在瀏覽器編輯器中執行，還是在無介面的 Node.js 程序中執行，內容、資料和介面都透過 Facade API 操作。

Web SDK 的各個部分都由外掛構成，包括產品能力、編輯器介面以及查詢替換等具體功能。應用可以從預設（Preset）開始，也可以選擇所需的產品外掛和功能外掛，連同依賴一起組裝。

業務特有的功能可以透過自定義外掛實現，無需修改 Univer 核心程式碼。同一套內容引擎透過更換外掛適配不同環境：瀏覽器應用載入編輯器 UI，Headless 應用則不載入這些 UI 外掛。詳見 [Univer 架構：外掛化設計](/blog/univer#plugins)。

**統一的 Canvas 渲染。** Office 內容都透過同一套 Canvas 渲染體系呈現，因此不同內容型別可以複用排版和繪製程式碼，也支援巢狀內容。例如，電子表格單元格中的文字沿用了文件的排版和渲染路徑，從而保持一致的表現。詳見[渲染引擎架構設計](/blog/rendering)。

**前後端混合計算。** 公式引擎既可以在前端計算，也可以在伺服器端的 Rust 引擎中計算。前端計算保證編輯時的響應速度，大規模公式計算由 Rust 引擎承擔。相關能力見[公式功能](/guides/sheets/features/core/formula)與[伺服器端計算](/overview/features/shared/server-calculation)。

建議從[電子表格](/guides/sheets/getting-started/quickstart)開始。同一套 SDK 還支援[文件](/guides/docs)、[簡報](/guides/slides)、[關係型表格](/guides/bases)、[畫布](/guides/boards)和 [PDF](/guides/pdfs)。

### Server SDK：連線協作與文件 [#server-sdk-connect-collaboration-and-files]

Server SDK 提供多人協同、檔案轉換和後端擴充套件能力。它基於 Web SDK 的 Headless 內容能力：各模組在應用自己的後端中執行，並使用應用自身的身分、權限和儲存。

**即時協同。** OT（操作轉換）處理行列變更和內容修改等並行操作。一次修改先在本地生效，隨後各副本趨於一致，並儘可能保留使用者原本的意圖。歷史記錄、評論和 Worktree 是獨立模組，需要時再新增。詳見[協同編輯設計](/blog/ot)與[協同接入](/server/collaboration/quick-start)。

**檔案格式轉換。** 轉換負責在 Office 檔案和 Univer 文件資料之間轉移內容，並銜接匯入、編輯和匯出三個環節。無論是否啟用協同服務，轉換都可以使用。轉換 API 見[Office 檔案匯入匯出](/server/import-export/node)，上傳、任務和下載介面見[檔案交換整合](/server/import-export)。

**部署與擴充套件。** 各模組組裝在自己的 Node.js 應用中，單臺機器即可開始。隨著負載增長，可以將檔案轉換拆分為獨立服務，再擴充套件到多個協同節點。詳見[應用架構](/server/architecture)與[部署指引](/server/deployment)。

[Server SDK 總覽](/server)對各模組有更詳細的說明。

### AI SDK：為 Agent 提供操作入口 [#ai-sdk-give-agents-an-entry-point]

AI SDK 為已有的 Agent、自動化流程和業務 CLI 增加 Office 能力。它基於 Web SDK 的 Headless 執行時和 Facade API，提供內容操作、計算和檢查能力。

**接入已有 Agent 體系。** Office 工具既可以封裝為 TypeScript API，也可以封裝為從 SDK 組裝的 CLI。模型選擇、任務編排和 Skills 仍由應用負責。Agent 收到執行結果和檢查反饋後，繼續執行自身的工作流。

**建立可繼續編輯的內容。** Agent 先讀取文件結構，定位所需的區域或段落，再透過 Facade API 建立和修改電子表格、文件、簡報等內容，並可以執行公式計算。產出保留內容結構和編輯能力，使用者可以繼續完善。見[內容操作](/ai/content-operations)。

**檢查結果，再繼續修正。** Agent 回讀數值和公式結果，並檢查實際頁面的截圖。對於簡報，版面配置檢查還能發現超出頁面、溢位和重疊的文字。Agent 根據這些反饋修改內容並再次驗證，從而形成“讀取 → 編輯與計算 → 檢查 → 修正”的迴圈。見[視覺檢查](/ai/visual-inspection)。

配合 Server SDK，[Worktree](/ai/worktree) 可以將 Agent 的中間修改隔離起來，直到有人在 Web 應用中審閱併合並。從 [AI SDK 總覽](/ai)開始。

## 應用程式中的協作流程 [#application-workflow]

<Mermaid chart={"flowchart TB\n    Human[\"人類使用者\"] --> Browser\n    Agent[\"AI Agent / 自動化\"] --> AI[\"AI SDK · 操作與驗證\"]\n    subgraph WebSDK[\"Web SDK · 統一內容引擎\"]\n      Browser[\"瀏覽器編輯器\"]\n      Headless[\"Headless · 內容模型與 Facade API\"]\n    end\n    Server[\"Server SDK · 協同、檔案轉換與擴充\"] -->|依賴| Headless\n    AI -->|依賴| Headless\n    Browser <-->|分享內容| Server\n    AI -.->|協同與審閱| Server\n    Server --> Storage[\"應用程式身分、權限與存儲\"]\n    classDef default rx:8,ry:8,stroke-width:1px"} />

- **嵌入式編輯器**：Web SDK 在應用中展示和編輯內容。
- **多人協同應用**：Web SDK 與 Server SDK 組合，讓多個使用者共同編輯共享文件。
- **人類與 Agent 協作**：Agent 透過 AI SDK 編輯和驗證草稿，Server SDK 管理版本與合併，Web 應用提供檢視、比較和人工審閱。完整的審閱流程需要三者共同參與。

<Callout title="共同基礎與依賴關係">
  Web SDK 可以獨立執行，既可以作為編輯器，也可以作為 Headless 內容引擎。Server SDK 和 AI SDK 都依賴 Web SDK 的 Headless 能力：即使沒有瀏覽器介面，仍然需要內容執行時。應用按需啟用所需的服務和模組，而完整的人類與 Agent 協作流程通常需要三個 SDK 組合使用。
</Callout>
