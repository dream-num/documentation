Embed blocks place one Univer product inside another. A project document can hold budgets and tasks, a slide can carry a working spreadsheet, and a canvas can present plans together with notes. The embedded content keeps its own data model and its native editor, so activating the block moves focus and menus to the child Unit.

## How it works: host and child Units [#principle]

The **host Unit** stores the placement and size of the block, the reference to the child Unit, and the default view. The **child Unit** stores the actual cells, paragraphs, or records. Loading a block resolves that reference, loads the child Unit, and mounts its editor inside the host. A [Unit](/guides/sheets/getting-started/quickstart#unit) can be a workbook, a document, a presentation, a relational table, or a canvas.

<Mermaid chart={"flowchart LR\n    A[\"Host Unit<br/>Document, page or canvas\"]\n    B[\"Embed descriptor<br/>Placement + child reference\"]\n    C[\"Resolve reference<br/>Load child Unit\"]\n    D[\"Native child editor<br/>Display and interaction\"]\n    E[\"Edit / save<br/>Update child Unit\"]\n    A --> B --> C --> D --> E"} />

The relationship and the content are persisted separately. Editing a cell in an embedded spreadsheet updates the child Sheet. Moving or resizing the block updates the anchor stored in the host.

## Supported locations [#locations]

| Host product | Embed locations | Typical use |
| --- | --- | --- |
| Sheet | Floating object or a workbook tab | A brief beside a calculation model, or a task database on a separate tab. |
| Doc | Body content block | Narrative, budgets, and tasks on one project page. |
| Slide | Floating object or a presentation page | Editable source data beside the conclusion. |
| Relational Table | Table-list entry | Project documentation that stays inside a business database. |
| Canvases | Floating canvas object | Data, proposals, and discussion on a single canvas. |

## How formulas stay connected [#formulas]

Embedding covers display and editing; calculation comes from references. Inserting a block does not create a summary formula, so cross-Unit references must be configured first. Once they are in place, Sheet cells and formula-driven Shapes in Doc, Slide, and Canvases can read Sheet ranges or Relational Table fields, and Relational Table formula fields can also reference a Sheet. When source data and change notifications are available, relevant edits trigger recalculation.

<Mermaid chart={"flowchart LR\n    A[\"Edit embedded Sheet / Relational Table\"]\n    B[\"Child Unit data changes\"]\n    C[\"Update references and dependencies\"]\n    D[\"Recalculate formula\"]\n    E[\"Update cell / formula Shape\"]\n    A --> B --> C --> D --> E"} />

| Scenario and formula | Verified result |
| --- | --- |
| Slide budget total: `=SUM('[Leadership Budget]Budget'!C5:C8)` | Changing `C7` from 17,100 to 18,000 updates the total from **61,200 → 62,100**. |
| Sheet total from Relational Table: `=SUM([Control Tasks]!Launch_tasks[Cost])` | Changing one Cost from 4,000 to 4,500 updates the total from **18,000 → 18,500**. |

Formula names serve as readable qualifiers, and an integration must also persist the stable Unit IDs behind them. Use `getFormula().buildReference()` to generate a reference together with the host-owned external mapping it requires. For a table in Relational Table, use `table.getFormulaName()` instead of concatenating a display name or ID. Formula-driven Shapes use `shape.setFormula({ formula, externalReferences })`; read the result after calculation completes. See [Formula Facade](/reference/facade/formula#buildreference), [Shape Facade](/reference/facade/shape#setformula) and [Relational Table formulas](/guides/bases/features/core/formulas).

## Create and integrate [#integration]

Register the host product, the child product, and their UI in the same Univer instance, then add Embed and Embed UI. The example below inserts an existing Sheet into a Doc body; `hostDocument` and `budgetWorkbook` are the corresponding Facades.

```ts
import '@univerjs-pro/embed/facade'

const block = univerAPI.createEmbed({
  host: {
    unitId: hostDocument.getId(),
    surface: univerAPI.Enum.FEmbedHostSurface.DocBlock,
  },
  content: {
    unitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
    ref: `#unit=${encodeURIComponent(budgetWorkbook.getId())}&type=sheet`,
  },
})

const embeddedWorkbook = await block.loadAsync()
```

`createEmbed()` creates the relationship and the host anchor. `loadAsync()` loads the child Unit and returns its Facade. `displayTarget` selects the initial worksheet, Slide page, or Relational Table view. The [embedding guide](/guides/fundamentals/features/embed) covers plugins, styles, locales, and loaders. [Embed Facade](/reference/facade/embed) covers the other surfaces and methods.

## Persistence, collaboration and scope [#scope]

- The host Snapshot keeps the references, placement, and display settings, but it does not package the latest child content automatically. Removing a block does not delete the child document.
- Server SDK provides child snapshots and the collaboration services that accompany them. With `@univerjs-pro/collaboration-embed`, the browser loads the child and joins its collaboration session. Parent and child keep separate changes and versions.
- The application resolves references, loads data, and authorizes access. Being able to open the host does not by itself grant editing rights on the child.
- The Sheet, Doc, Slide, Relational Table, and Canvases types can be embedded in each other. PDF, same-type embedding, and deeper nesting are excluded. Within one Univer runtime, a child Unit can belong to only one active embed.

Use [two-way binding](/overview/features/shared/binding) to drive the application's own inputs, metrics, and charts from a spreadsheet. Use Embed Block when you need the child product's editor.
