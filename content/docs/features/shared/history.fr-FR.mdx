L’historique organise les changements collaboratifs confirmés en versions consultables. Il permet de voir les auteurs, les heures, les actions et le contenu antérieur, puis de restaurer une version avec les autorisations nécessaires. Il reste accessible entre les sessions et après un rechargement.

## Fonctionnement de l’historique

- **Mutation**: Une modification rejouable du contenu, par exemple modifier une cellule ou insérer un paragraphe.
- **Changeset**: Une soumission collaborative contenant un groupe ordonné de mutations.

### 1. Enregistrer les changements

**Lors de l’envoi des modifications.** Les changements d’un utilisateur ou d’un Agent produisent des mutations regroupées dans un changeset, envoyé au service de collaboration pour confirmation et enregistrement.

<Mermaid chart={"flowchart LR\n    A[\"Modifier le contenu\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"Confirmer et enregistrer<br/>Noter la revision\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Une **revision** identifie la position d’une soumission confirmée dans l’historique. History indexe les changesets confirmés et les regroupe par heure et opération pour construire la chronologie des versions.

### 2. Reconstruire le contenu historique

**Lors de la sélection d’une version historique.** Un snapshot contient l’état complet du contenu à une revision. Le système charge un snapshot de référence et les changesets suivants jusqu’à la revision cible, puis rejoue leurs mutations dans l’ordre pour créer une vue en lecture seule.

<Mermaid chart={"flowchart LR\n    A[\"Choisir la version<br/>revision N\"]\n    B[\"Charger le snapshot<br/>et les changesets suivants\"]\n    C[\"Rejouer les mutations<br/>dans l’ordre\"]\n    D[\"Contenu historique<br/>Lecture seule\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Exemple : **snapshot de la revision 10 + changesets des révisions 11 à 15 = contenu de la revision 15.**

### 3. Restaurer le document actuel

**Lors de la sélection de Restaurer cette version.**

> Choisir la version → Soumettre une mutation de restauration → Confirmation collaborative → Mettre à jour le document avec une nouvelle revision

La restauration crée une nouvelle entrée ; les versions précédentes restent disponibles.

## Consulter les versions et les changements

1. Ouvrez l’historique depuis l’éditeur et sélectionnez une version.
2. Développez un groupe pour consulter chaque revision et ses différences dans une visionneuse en lecture seule.
3. Sélectionnez Restaurer cette version pour mettre à jour le document partagé via la collaboration. Les autres participants reçoivent la mise à jour.

Un groupe peut réunir les modifications d’un intervalle de temps. Une entrée ne correspond pas nécessairement à une frappe ou à la création d’un Snapshot.

### Lire les couleurs

| Repère | Signification |
| --- | --- |
| 🟦 **Bleu : modification** | Changement d’un contenu, d’un format ou d’une propriété existants. |
| 🟩 **Vert : ajout** | Nouvelle ligne, nouveau paragraphe, enregistrement ou objet. |
| 🟥 **Rouge : suppression** | Le contenu supprimé conserve un repère dans la vue historique. |

Les couleurs indiquent les types de changement. Un remplacement de texte peut afficher un ajout et une suppression. Chaque visionneuse détermine la portée du surlignage.

## Intégration dans votre application

- **Serveur** : ajoutez History Service, Endpoint et un Database Adapter persistant à Core Collaboration. Les événements de création de Unit et de confirmation des changesets alimentent l’index et les requêtes de versions et de changements.
- **Navigateur** : enregistrez la fonction commune et les plugins History / History UI du produit, puis connectez l’API. La visionneuse charge la revision sélectionnée et ses différences. Ajoutez les plugins nécessaires au contenu personnalisé.
- **Autorisations** : votre application fournit identité et autorisation ; le serveur vérifie la lecture de l’historique et la restauration. Les anciennes versions peuvent contenir des données supprimées du document actuel.

Consultez les [extensions de collaboration](/server/collaboration/extensions) et l’[exemple History](/server/collaboration/examples#history), puis les guides produit pour connecter l’interface.

L’index est une donnée dérivée reconstructible. Les changesets confirmés restent la source de référence. L’application gère persistance et rétention ; le panneau ne remplace pas les sauvegardes.

## Liens avec les autres fonctions

- **Annuler / rétablir** : inverse ou réapplique des opérations sans service d’historique.
- **Historique** : retrace les versions confirmées entre les sessions et restaure le contenu partagé.
- [Comparaison de contenu](/overview/features/shared/compare) : compare deux états en lecture seule, sans les restaurer.
- [Worktree](/overview/features/shared/worktree) : isole les brouillons pour décider de leur fusion après examen.

Les modifications d’un Agent via Facade API peuvent suivre le même historique une fois confirmées par la collaboration. La comparaison permet d’ajouter des examens et contrôles automatiques.
