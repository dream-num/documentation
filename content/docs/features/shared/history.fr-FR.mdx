Pour chaque changement confirmé, les développeurs et les utilisateurs peuvent voir l'auteur, l'horodatage et l'action, ouvrir le document tel qu'il se trouvait à ce moment-là, examiner la différence et restaurer une version lorsqu'ils ont la permission. L'historique reste disponible après la fin de la session d'édition et recharge la page.

## Fonctionnement de l’historique

A **mutation** est un changement de contenu rejouable, comme le réglage d'une cellule ou l'insertion d'un paragraphe. A **changement** est une soumission de collaboration qui porte un groupe ordonné de mutations.

### 1. Enregistrer les changements

Chaque édition d'un utilisateur ou d'un Agent produit des mutations. Univer emballe ces mutations dans un ensemble de modifications et les soumet pour la collaboration pour confirmer et persister.

<Mermaid chart={"flowchart LR\n    A[\"Modifier le contenu\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"Confirmer et enregistrer<br/>Noter la revision\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Après confirmation, une soumission reçoit un **révision**, qui identifie sa position dans l'historique du document. L'historique indexe les changements confirmés, les regroupe par temps et par fonctionnement, et construit le calendrier de version.

### 2. Reconstruire le contenu historique

Un **instantané** est l'état complet du contenu lors d'une révision. Lorsqu'une version historique est sélectionnée, Univer charge un instantané de base et les changements qui le suivent jusqu'à la révision cible, puis rejoue leurs mutations dans l'ordre. Le résultat est une vue en lecture seule du contenu tel qu'il se trouvait à cette révision.

<Mermaid chart={"flowchart LR\n    A[\"Choisir la version<br/>revision N\"]\n    B[\"Charger le snapshot<br/>et les changesets suivants\"]\n    C[\"Rejouer les mutations<br/>dans l’ordre\"]\n    D[\"Contenu historique<br/>Lecture seule\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Exemple : **snapshot de la revision 10 + changesets des révisions 11 à 15 = contenu de la revision 15.**

### 3. Restaurer le document actuel

La sélection de **Restaurer cette version** démarre le flux suivant :

> Choisir la version → Soumettre une mutation de restauration → Confirmation collaborative → Mettre à jour le document avec une nouvelle revision

L'opération de restauration crée un nouvel enregistrement historique. Les versions antérieures restent disponibles.

## Consulter les versions et les changements

1. Ouvrez l’historique depuis l’éditeur et sélectionnez une version.
2. Élargir un groupe de versions pour inspecter les révisions individuelles. Sélectionnez une révision pour lire son contenu et les changements dans un visionneur en lecture seule.
3. Sélectionnez **Restaurer cette version** lorsqu'un retour en arrière est nécessaire. La restauration met à jour le document partagé par la collaboration, de sorte que chaque autre participant reçoit la modification.

Un groupe de version peut combiner les modifications faites dans une fenêtre de temps. Élargir le groupe pour inspecter les révisions individuelles. **Une entrée d'historique ne correspond pas nécessairement à une frappe ou à un Snapshot généré.**

### Lire les couleurs

| Repère | Signification |
| --- | --- |
| 🟦 **Bleu: mis à jour** | Le contenu actuel a changé. | Une valeur, un format de paragraphe ou une propriété objet a été mise à jour. |
| 🟩 **Vert : ajout** | Nouvelle ligne, nouveau paragraphe, enregistrement ou objet. |
| 🟥 **Rouge: supprimé** | Contenu supprimé dans cette version. | Le texte ou les objets supprimés conservent un marqueur dans la vue d'historique. |

Les couleurs indiquent le **type de changement**. Le remplacement du texte peut produire à la fois une insertion et une suppression. Le visionneur de chaque produit détermine la quantité de contenu surlignée.

## Intégration dans votre application

L'historique des versions combine l'extension History en Server SDK avec les plugins d'historique des produits en Web SDK.

- Sur le serveur, ajoutez History Service, Endpoint et un adaptateur de base de données persistant à Core Collaboration. Le service s'inscrit à la création d'unité et aux changements engagés, construit un index d'historique et expose les requêtes pour les versions et les changements.
- Dans le navigateur, enregistrez la capacité d'historique commune et les plugins d'interface History / History du produit, puis connectez le paramètre d'historique. Le visionneur charge la révision sélectionnée et affiche ses modifications.
- Votre application fournit l'identité et l'autorisation, et le serveur vérifie l'historique et restaure les autorisations. Une version historique peut contenir des données que le document actuel a déjà supprimées.

Voir [extensions de la collaboration](/server/collaboration/extensions) et assembler le service avec le [Exemple historique](/server/collaboration/examples#history), puis connecter l'interface utilisateur aux guides de produits ci-dessus.

Les index d'historiques sont des données dérivées reconstructibles. **Les modifications confirmées demeurent la source de contenu faisant autorité.** Votre application contrôle la persistance et la rétention. Le panneau d'historique ne remplace pas les sauvegardes.

## Liens avec les autres fonctions

| Capacité | Objet |
| --- | --- |
| Annuler / refaire | Revenir ou réappliquer une opération d'édition sans service d'historique. |
| Historique de la version | Tracez les versions confirmées à travers les sessions, inspectez les changements et restaurez le contenu partagé. |
| [Comparaison du contenu](/overview/features/shared/compare) | Comparez deux états de contenu pour une UI ou un Agent. Une comparaison en lecture seule ne restaure pas le contenu. |
| [Worktree](/overview/features/shared/worktree) | Isolez les modifications provisoires à examiner avant de les fusionner en contenu partagé. |

Les changements d'agents effectués par l'intermédiaire des API Facade entrent dans le même pipeline d'historique une fois la collaboration confirmée. Les applications peuvent combiner l'historique avec la comparaison de contenu pour l'examen automatisé et les vérifications.
