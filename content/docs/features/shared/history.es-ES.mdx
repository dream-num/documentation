La historia de la versión organiza cambios de colaboración confirmados en las versiones disponibles. Para cada cambio confirmado, los desarrolladores y los usuarios pueden ver al autor, el timetamp, y la acción, abrir el documento tal como estaba en ese punto, revisar la diferencia y restaurar una versión cuando tienen permiso. La historia permanece disponible después de que la sesión de edición termine y recargas en la página.

## Cómo funciona el historial

A **mutación** es un cambio de contenido repetible, como establecer una célula o insertar un párrafo. A **Cambios** es una presentación de colaboración que lleva un grupo ordenado de mutaciones.

### 1. Registrar los cambios

Cada edición de un usuario o un agente produce mutaciones. Univer empaca estas mutaciones en un cambio y lo presenta para la colaboración para confirmar y persistir.

<Mermaid chart={"flowchart LR\n    A[\"Editar contenido\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"Confirmar y guardar<br/>Registrar revision\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Después de la confirmación, una presentación recibe un **revisión**, que identifica su posición en la historia del documento. La historia indexa los cambios confirmados, los agrupa por el tiempo y la operación, y construye el cronograma de la versión.

### 2. Reconstruir contenido histórico

Un **instantánea** es el estado de contenido completo en una revisión. Cuando se selecciona una versión histórica, Univer carga una instantánea de referencia y los cambios que la siguen hasta la revisión de destino, entonces replaya sus mutaciones en orden. El resultado es una visión de sólo lectura del contenido como se presentó en esa revisión.

<Mermaid chart={"flowchart LR\n    A[\"Seleccionar versión<br/>revision N\"]\n    B[\"Leer snapshot<br/>y changesets posteriores\"]\n    C[\"Reproducir mutations<br/>en orden\"]\n    D[\"Contenido histórico<br/>Solo lectura\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Ejemplo: **snapshot de la revision 10 + changesets de las revisiones 11–15 = contenido de la revision 15.**

### 3. Restaurar el documento actual

Seleccionar **Restaurar esta versión** comienza el siguiente flujo:

> Seleccionar versión → Enviar mutation de restauración → Confirmación colaborativa → Actualizar el documento con una nueva revision

La operación de restauración crea un nuevo registro de historia. Las versiones anteriores permanecen disponibles.

## Consultar versiones y cambios

1. Abre el historial desde el editor y selecciona una versión.
2. Ampliar un grupo de versión para inspeccionar las revisiones individuales. Seleccione una revisión para leer su contenido y cambios en un solo lector de lectura.
3. Seleccione **Restaurar esta versión** cuando se requiere una devolución. La restauración actualiza el documento compartido a través de la colaboración, por lo que cada otro participante recibe el cambio.

Un grupo de versión puede combinar las ediciones realizadas dentro de una ventana de tiempo. Ampliar el grupo para inspeccionar las revisiones individuales. **Una entrada de historia no corresponde necesariamente a una pulsación de teclas o una instantánea generada.**

### Colores de los cambios

| Marca | Significado |
| --- | --- |
| 🟦 **Azul: actualizado** | El contenido existente cambió. | Se actualizó un valor, un formato de párrafo o una propiedad de objeto. |
| 🟩 **Verde: añadido** | Nuevas filas, párrafos, registros u objetos del tablero. |
| 🟥 **Rojo: borrado** | Contenido eliminado en esta versión. | El texto o los objetos eliminados mantienen un marcador en la vista de la historia. |

Los colores indican el **tipo de cambio**. El texto de reposición puede producir una inserción y una eliminación. El visor de cada producto determina cuánto del contenido se destaca.

## Integración en tu aplicación

La historia de la versión combina la extensión de la historia en Server SDK con los plugins de historia del producto en Web SDK.

- En el servidor, agregue el Servicio de Historia, Endpoint y un adaptador de base de datos persistente a la colaboración básica. El servicio se suscribe a la creación de Unidades y a los cambios comprometidos, construye un índice de historia y expone las consultas para versiones y cambios.
- En el navegador, regístrese la capacidad de historia común y los plugins de historia / historia del producto UI, a continuación, conecte el endpoint de la historia. El espectador carga la revisión seleccionada y muestra sus cambios. Para contenido personalizado, registre los plugins para el espectador.
- Su aplicación proporciona identidad y autorización, y el servidor revisa los permisos de lectura y restauración de la historia. Una versión histórica puede contener datos que el documento actual ya ha eliminado.

Ver [Extensiones de colaboración](/server/collaboration/extensions) y montar el servicio con el [Ejemplo de historia](/server/collaboration/examples#history), luego conectar la interfaz de usuario con las guías de productos anteriores.

Los índices de historia son datos derivados reconstruibles. **Los cambios confirmados siguen siendo la fuente de contenido autorizada.** Su aplicación controla la persistencia y la retención. El panel de historia no reemplaza las copias de seguridad.

## Relación con otras funciones

| Capacidad | Propósito |
| --- | --- |
| Deshacer / redo | Revertir o volver a aplicar una operación de edición sin un servicio de historia. |
| Historia de la versión | Trace confirmó versiones en todas las sesiones, inspeccionar cambios y restaurar contenido compartido. |
| [Comparación de contenidos](/overview/features/shared/compare) | Compare dos estados de contenido para una interfaz de usuario o un agente. Una comparación de sólo lectura no restaura el contenido. |
| [Worktree](/overview/features/shared/worktree) | Aislar los cambios de proyecto para su revisión antes de fusionarlos en contenido compartido. |

Los cambios de agente realizados a través de las API de Facade introducen el mismo oleoducto de historia una vez que la colaboración los confirma. Las aplicaciones pueden combinar la historia con la comparación de contenidos para revisión y cheques automatizados.
