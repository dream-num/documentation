El historial organiza los cambios confirmados de colaboración en versiones consultables. Permite ver autores, horas, acciones y contenido anterior, y restaurar una versión con los permisos adecuados. Sigue disponible entre sesiones y después de recargar la página.

## Cómo funciona el historial

- **Mutation**: Un cambio reproducible de contenido, como establecer una celda o insertar un párrafo.
- **Changeset**: Una entrega de colaboración que contiene un grupo ordenado de mutations.

### 1. Registrar los cambios

**Al enviar las ediciones.** Los cambios del usuario o Agent producen mutations, que se agrupan en un changeset y se envían al servicio de colaboración para confirmarlos y guardarlos.

<Mermaid chart={"flowchart LR\n    A[\"Editar contenido\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"Confirmar y guardar<br/>Registrar revision\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Una **revision** identifica la posición de una entrega confirmada en el historial. History indexa los changesets confirmados y los agrupa por tiempo y operación para construir la línea de versiones.

### 2. Reconstruir contenido histórico

**Al seleccionar una versión histórica.** Un snapshot contiene el estado completo de una revision. El sistema lee un snapshot base y los changesets posteriores hasta la revision de destino, y reproduce sus mutations en orden para generar una vista histórica de solo lectura.

<Mermaid chart={"flowchart LR\n    A[\"Seleccionar versión<br/>revision N\"]\n    B[\"Leer snapshot<br/>y changesets posteriores\"]\n    C[\"Reproducir mutations<br/>en orden\"]\n    D[\"Contenido histórico<br/>Solo lectura\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Ejemplo: **snapshot de la revision 10 + changesets de las revisiones 11–15 = contenido de la revision 15.**

### 3. Restaurar el documento actual

**Al seleccionar Restaurar esta versión.**

> Seleccionar versión → Enviar mutation de restauración → Confirmación colaborativa → Actualizar el documento con una nueva revision

La restauración crea un nuevo registro; las versiones anteriores se conservan.

## Consultar versiones y cambios

1. Abre el historial desde el editor y selecciona una versión.
2. Expande un grupo para consultar cada revision y revisar el contenido y las diferencias en un visor de solo lectura.
3. Selecciona Restaurar esta versión para actualizar el documento compartido mediante colaboración. Los demás participantes reciben la actualización.

Un grupo puede reunir cambios de un intervalo de tiempo. Una entrada no equivale necesariamente a una pulsación ni a la generación de un Snapshot.

### Colores de los cambios

| Marca | Significado |
| --- | --- |
| 🟦 **Azul: modificado** | Cambios en contenido, formato o propiedades existentes. |
| 🟩 **Verde: añadido** | Nuevas filas, párrafos, registros u objetos del tablero. |
| 🟥 **Rojo: eliminado** | El contenido eliminado conserva una marca en la vista histórica. |

Los colores representan tipos de cambio. Una sustitución de texto puede mostrar una inserción y una eliminación. Cada visor determina el alcance del resaltado.

## Integración en tu aplicación

- **Servidor**: añade History Service, Endpoint y un Database Adapter persistente a Core Collaboration. Los eventos de creación de Unit y confirmación de changeset alimentan el índice y las consultas de versiones y cambios.
- **Navegador**: registra la función común y los plugins History / History UI del producto y conecta la API. El visor carga la revision seleccionada y sus diferencias. Añade los plugins de visor necesarios para contenido personalizado.
- **Permisos**: la aplicación proporciona identidad y autorización; el servidor comprueba el acceso al historial y la restauración. Las versiones pueden contener datos eliminados del documento actual.

Consulta las [extensiones de colaboración](/server/collaboration/extensions) y el [ejemplo History](/server/collaboration/examples#history), y conecta la interfaz con las guías de producto.

El índice es un dato derivado que puede reconstruirse. Los changesets confirmados siguen siendo la fuente autorizada. La aplicación controla persistencia y retención; el panel no sustituye las copias de seguridad.

## Relación con otras funciones

- **Deshacer / rehacer**: revierte o reaplica operaciones de edición sin servicio de historial.
- **Historial**: consulta versiones confirmadas entre sesiones y restaura contenido compartido.
- [Comparación de contenido](/overview/features/shared/compare): compara dos estados en modo de solo lectura, sin restaurarlos.
- [Worktree](/overview/features/shared/worktree): aísla cambios de borrador para revisarlos antes de fusionarlos.

Los cambios de un Agent mediante Facade API pueden entrar en el mismo historial al confirmarse por colaboración. La comparación permite añadir revisiones y comprobaciones automáticas.
