Les blocs intégrés placent un produit Univer dans un autre : budgets et tâches dans un document de projet, tableur calculable sur une diapositive, ou plans et notes sur un canevas. Le contenu enfant conserve son modèle de données et son éditeur natif ; son activation adapte le focus et les menus.

## Principe : Unit hôte et Unit enfant [#principle]

L’**Unit hôte** conserve la position, la taille, la référence à l’enfant et la vue initiale. L’**Unit enfant** conserve les cellules, paragraphes ou enregistrements réels. Embed résout la référence, charge l’enfant et installe son éditeur dans l’hôte. Une [Unit](/guides/sheets/getting-started/quickstart#unit) peut être un classeur, un document, une présentation, une table relationnelle ou un canevas.

<Mermaid chart={"flowchart LR\n    A[\"Unit hôte<br/>Document, page ou canevas\"]\n    B[\"Descripteur Embed<br/>Position + référence enfant\"]\n    C[\"Résoudre la référence<br/>Charger l’Unit enfant\"]\n    D[\"Éditeur natif enfant<br/>Affichage et interaction\"]\n    E[\"Modifier / enregistrer<br/>Mettre à jour l’enfant\"]\n    A --> B --> C --> D --> E"} />

La relation et le contenu sont enregistrés séparément. Modifier une cellule intégrée met à jour la Sheet enfant ; déplacer ou redimensionner le bloc met à jour son ancrage dans l’hôte.

## Emplacements pris en charge [#locations]

| Produit hôte | Emplacement | Usage courant |
| --- | --- | --- |
| Sheet | Objet flottant ou onglet du classeur | Ajouter une note au modèle de calcul ou ouvrir une base de tâches. |
| Doc | Bloc dans le corps | Réunir texte, budgets et tâches dans une page de projet. |
| Slide | Objet flottant ou page indépendante | Examiner des données sources modifiables à côté des conclusions. |
| Relational Tables | Entrée de la liste des tables | Accéder aux documents du projet dans la base métier. |
| Canvases | Objet flottant sur le canevas | Réunir données, propositions et discussion sur un canevas. |

## Comment les formules restent liées [#formulas]

**L’intégration assure l’affichage et l’édition ; les références assurent le calcul.** Insérer un bloc ne crée pas de formule de synthèse. Avec les références entre Units, les cellules de Sheet et les Shapes à formule de Doc, Slide et Canvases peuvent lire des plages Sheet ou des champs Relational Tables. Les champs de formule Relational Tables peuvent aussi référencer Sheet. Lorsque les données et notifications sont disponibles, les modifications pertinentes déclenchent un recalcul.

<Mermaid chart={"flowchart LR\n    A[\"Modifier Sheet / Relational Tables intégrée\"]\n    B[\"Données de l’enfant modifiées\"]\n    C[\"Actualiser références et dépendances\"]\n    D[\"Recalculer la formule\"]\n    E[\"Actualiser cellule / Shape\"]\n    A --> B --> C --> D --> E"} />

| Scénario et formule | Résultat vérifié |
| --- | --- |
| Budget dans Slide : `=SUM('[Leadership Budget]Budget'!C5:C8)` | Passer `C7` de 17,100 à 18,000 actualise le total de **61,200 → 62,100**. |
| Total Relational Tables dans Sheet : `=SUM([Control Tasks]!Launch_tasks[Cost])` | Passer un Cost de 4,000 à 4,500 actualise le total de **18,000 → 18,500**. |

Les noms lisibles doivent être associés aux ID stables des Units. Utilisez `getFormula().buildReference()` pour créer la référence et sa correspondance externe dans l’hôte. Pour une table Relational Tables, utilisez `table.getFormulaName()` au lieu de concaténer nom affiché ou ID. Les Shapes calculées utilisent `shape.setFormula({ formula, externalReferences })` ; lisez le résultat après le calcul. Voir [Formula Facade](/reference/facade/formula#buildreference), [Shape Facade](/reference/facade/shape#setformula) et [formules Relational Tables](/guides/bases/features/core/formulas).

## Création et intégration [#integration]

Enregistrez les produits hôte et enfant et leurs interfaces dans la même instance Univer, puis Embed et Embed UI. Cet exemple insère une Sheet existante dans un Doc ; `hostDocument` et `budgetWorkbook` désignent leurs Facades.

```ts
import '@univerjs-pro/embed/facade'

const block = univerAPI.createEmbed({
  host: {
    unitId: hostDocument.getId(),
    surface: univerAPI.Enum.FEmbedHostSurface.DocBlock,
  },
  content: {
    unitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
    ref: `#unit=${encodeURIComponent(budgetWorkbook.getId())}&type=sheet`,
  },
})

const embeddedWorkbook = await block.loadAsync()
```

`createEmbed()` crée la relation et l’ancrage ; `loadAsync()` charge l’enfant et renvoie sa Facade. `displayTarget` choisit la feuille, la page Slide ou la vue Relational Tables initiale. Le [guide d’intégration](/guides/fundamentals/features/embed) décrit plugins, styles, langues et chargeurs ; [Embed Facade](/reference/facade/embed) couvre les autres emplacements et méthodes.

## Persistance, collaboration et périmètre [#scope]

- **Enregistrement séparé :** le Snapshot hôte conserve références, position et réglages d’affichage ; il n’empaquette pas automatiquement le contenu enfant à jour. Supprimer un bloc ne supprime pas le document enfant.
- **Chargement collaboratif :** Server SDK fournit les snapshots et services collaboratifs de l’enfant. Avec `@univerjs-pro/collaboration-embed`, le navigateur charge l’Unit enfant et rejoint sa session. Parent et enfant conservent leurs propres modifications et versions.
- **Accès et droits :** l’application résout les références, charge les données et autorise les accès. Accéder à l’hôte ne donne pas automatiquement le droit de modifier l’enfant.
- **Périmètre actuel :** les types distincts Sheet, Doc, Slide, Relational Tables et Canvases sont pris en charge. PDF, intégration du même type et imbrication supplémentaire sont exclus. Dans un même environnement Univer, une Unit enfant ne peut appartenir qu’à une seule intégration active.

Utilisez la [liaison bidirectionnelle](/overview/features/shared/binding) pour piloter les champs, indicateurs et graphiques propres à votre application depuis un tableur. Utilisez Embed Block pour conserver l’éditeur du produit enfant.
