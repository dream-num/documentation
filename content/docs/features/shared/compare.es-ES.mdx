Compare recibe dos snapshots de Unit completamente reconstruidos y devuelve diferencias semánticas por celda, párrafo, página o registro. Sirve para revisar historial, resultados de agentes y Worktrees.

## Objetos comparables

| Producto | Ejemplos |
| --- | --- |
| Sheet | Hojas, valores y fórmulas, filas, columnas, estilos y recursos registrados, como gráficos. |
| Doc | Párrafos, texto, estilos, tablas, bloques y dibujos. |
| Slide | Páginas, elementos, geometría, estilos, diseños y temas. |
| Base | Tablas, campos, registros y vistas. |
| Board | Páginas, elementos y recursos asociados. |

Los cambios se clasifican en adiciones, eliminaciones y actualizaciones. Se excluyen estados temporales como zoom y selección. La cobertura depende del adaptador; PDF queda fuera.

## Cómo intervienen Snapshot y changeset en la comparación

Un Snapshot guarda el estado completo del contenido en una revisión. Una mutation describe un cambio concreto; un changeset agrupa mutations en una confirmación ordenada. El historial conserva y reconstruye versiones; Compare explica las diferencias entre dos versiones reconstruidas.

Para comparar el historial o un Worktree, se carga un Snapshot base y se aplican los changesets posteriores en orden hasta reconstruir cada revisión. Los estados completos se entregan al adaptador del producto. Los changesets disponibles también pueden mejorar la correspondencia en cambios estructurales, como insertar o eliminar filas y columnas. Si solo se dispone de dos estados completos, se puede comparar por snapshots.

Los resultados siguen el modelo de cada producto: celdas y filas o columnas de Sheet, párrafos de Doc, elementos de Slide y Board, y campos y registros de Base. La selección temporal y el zoom no son cambios de contenido. Compare es de solo lectura; restaurar una versión y fusionar un Worktree son operaciones independientes.

## Integración con Server SDK y AI SDK

**Server SDK** proporciona Snapshots, changesets y números de revisión, y reconstruye el contenido. La aplicación entrega ambos estados y el historial disponible a Compare, obtiene diferencias estructuradas y muestra una interfaz de revisión web. Consulta el [historial](/overview/features/shared/history) y las [extensiones del servicio de colaboración](/server/collaboration/extensions).

**AI SDK** carga y edita contenido en un Worktree y confirma el resultado del Agent. Las aplicaciones pueden usar las diferencias estructuradas para verificaciones del Agent y procesos posteriores, mientras las personas revisan visualmente los mismos cambios antes de fusionarlos. Consulta el [flujo Worktree del Agent](/ai/worktree) y las [operaciones de contenido](/ai/content-operations).

## Ejemplos de comparación de cinco productos

Estos ejemplos comparten un plan de lanzamiento Northstar: primero creamos y enviamos una versión base completa, después la editamos en un Worktree y abrimos Compare para revisar los cambios.

En la lista de cambios, el **azul** indica modificaciones, el **verde** adiciones y el **rojo** eliminaciones. Los paneles de solo lectura muestran el antes y el después. Haz clic en una imagen para ampliarla.

### Sheet: presupuesto y estructura de filas

Actualizar las previsiones de investigación y del editor, eliminar Legacy tooling, añadir Accessibility QA y recalcular los totales. Revisar los valores y resultados de fórmulas junto a sus filas correspondientes.

![Sheet: presupuesto y estructura de filas](/assets/features/compare/sheets.jpg)

### Doc: plan de lanzamiento y párrafos

Actualizar la fecha, el número de equipos piloto y el objetivo de finalización. Sustituir la aprobación anterior por un control de calidad, conservando el contexto para revisar los párrafos.

![Doc: plan de lanzamiento y párrafos](/assets/features/compare/docs.jpg)

### Slide: métricas y elementos de página

Actualizar tres tarjetas de métricas, eliminar el bloque de aprobación anterior y añadir un control de calidad. Comparar texto y elementos de la misma página.

![Slide: métricas y elementos de página](/assets/features/compare/slides.jpg)

### Base: campos y registros de tareas

**Producto:** [Relational Table (tabla relacional)](/overview/features/relational-table), denominado Base en el SDK y las API.

Actualizar progreso, estado y fechas; renombrar el campo de fecha; eliminar la aprobación anterior y añadir una tarea de accesibilidad. Revisar por tabla, campo y registro.

![Base: campos y registros de tareas](/assets/features/compare/bases.jpg)

### Board: flujo y elementos del lienzo

**Producto:** [Canvases (lienzos)](/overview/features/canvas), denominado Board en el SDK y las API.

Actualizar el tamaño del piloto y la fecha, mover el nodo de revisión y sustituir la tarjeta de aprobación por un control de calidad. Revisar contenido y disposición en contexto.

![Board: flujo y elementos del lienzo](/assets/features/compare/boards.jpg)

## Consultar resultados

Registra los plugins de comparación y las extensiones Facade del producto y llama a `compareUnitData()`. Para filtrar y paginar repetidamente, usa `prepareUnitComparison()` y `query()`.

Presenta un resumen y después detalles por hoja, página o tabla. Solicita listas de cambios o valores completos según sea necesario. Los resultados detallados tienen límites: la primera página puede no contener todas las diferencias. Revisa los diagnósticos y la cobertura.

Consulta la [API](/reference/facade/unit-comparison), el [historial](/overview/features/shared/history) y [Worktree](/overview/features/shared/worktree).
