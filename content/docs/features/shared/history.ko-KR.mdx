버전 기록은 수정 가능한 버전으로 협업 변경을 확인했습니다. 각 확인된 변경, 개발자 및 사용자는 저자, 타임스탬프 및 행동을 볼 수 있으며 그 시점에 서서 문서를 열고, 차이점을 검토하고, 권한이있을 때 버전을 복원 할 수 있습니다. 기록은 편집 세션 종료 후 사용 가능하고 페이지 재로드를 통해 사용할 수 있습니다.

## 버전 기록의 원리

**뚱 베어**는 세포를 설정하거나 단락을 삽입하는 것과 같은 1개의 재생 가능한 내용 변화입니다. **관련 기사**에는 mutations의 주문한 그룹을 나르는 1개의 협력 제출입니다.

### 1. 변경 기록

사용자 또는 에이전트에서 모든 편집은 mutations를 생산합니다. Univer는 이러한 mutations을 변경으로 포장하고 협업을 위해 협업을 확인하고 persist를 제출합니다.

<Mermaid chart={"flowchart LR\n    A[\"콘텐츠 편집\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"확정 및 저장<br/>revision 기록\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

확인 후, 제출은 문서의 역사에 그것의 위치를 식별하는 **- 연혁**를받습니다. 기록은 확인 된 변경 세트를 색인, 시간 및 작업에 의해 그룹, 버전 타임 라인을 구축합니다.

### 2. 과거 콘텐츠 재구성

**스냅 샷**는 하나의 개정에서 완전한 내용 상태입니다. 역사적인 버전이 선택되면 Univer가 기본 스냅 샷을로드하고 대상 개정을 따르는 변경 세트를로드하고 주문에서 자신의 mutations를 재생합니다. 결과는 그 개정에 서있는 것처럼 내용의 읽기 전용보기입니다.

<Mermaid chart={"flowchart LR\n    A[\"버전 선택<br/>revision N\"]\n    B[\"Snapshot 및<br/>후속 Changeset 조회\"]\n    C[\"Mutation을<br/>순서대로 재실행\"]\n    D[\"과거 콘텐츠 표시<br/>읽기 전용\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

예: **revision 10의 Snapshot + revision 11~15의 Changeset = revision 15의 콘텐츠.**

### 3. 현재 문서 복원

**이 버전 복원** 선택은 다음과 같은 흐름을 시작합니다.

> 대상 버전 선택 → 복원 Mutation 제출 → 협업에서 확정 → 현재 문서를 갱신하고 새 revision 생성

복원 작업은 새로운 역사 기록을 만듭니다. Earlier 버전은 사용할 수 있습니다.

## 버전과 변경 확인

1. 편집기에서 버전 기록을 열고 버전을 선택합니다.
2. 개별 개정을 검사하기 위해 버전 그룹을 확장합니다. 내용을 읽고 읽기 전용 뷰어의 변경을 읽으려면 한 가지 개정을 선택하십시오.
3. **이 버전 복원**를 선택하면 롤백이 필요합니다. 협업을 통해 공유된 문서를 복원하므로 다른 참가자는 변경 사항을받습니다.

버전 그룹은 시간 창 내에서 편집을 결합 할 수 있습니다. 개별 개정을 검사하기 위해 그룹을 확장합니다. **1개의 역사 입장은 반드시 1개의 중요한 치기 또는 1개의 생성된 스냅샷에 대응하지 않습니다.**

### 변경 색상 읽기

| 표시 | 의미 |
| --- | --- |
| 🟦 **파란색: 업데이트** | Existing 내용이 변경되었습니다. | 값, 단락 형식 또는 객체 속성이 업데이트되었습니다. |
| 🟩 **초록색: 추가** | 새 행, 문단, 레코드 또는 보드 개체입니다. |
| 🟥 **빨강: 삭제** | 이 버전에서 제거된 내용. | 제거된 텍스트 또는 개체는 역사보기에 마크를 유지합니다. |

색상은 **변화의 유형**를 나타냅니다. 텍스트를 파싱하면 삽입과 탈letion을 모두 생산할 수 있습니다. 각 제품의 뷰어는 내용의 얼마나 많은 것을 강조합니다.

## 애플리케이션에 통합

버전 역사는 Server SDK의 제품 역사 플러그인과 Web SDK에서 역사 확장을 결합합니다.

- 서버에서 History Service, Endpoint 및 Core Collaboration에 persistent Database Adapter를 추가합니다. 이 서비스는 Unit 생성 및 투입된 changesets에 가입하고, 역사 인덱스를 구축하고, 버전 및 변경 설정에 대한 쿼리를 노출합니다.
- 브라우저에서, 일반적인 역사 기능 및 제품 역사 / 역사 UI 플러그인을 등록하고, 역사 엔드포인트를 연결합니다. 뷰어는 선택한 개정을로드하고 변경 사항을 표시합니다. 사용자 정의 콘텐츠의 경우, 일치하는 뷰어 플러그인을 등록하십시오.
- 응용 프로그램 공급 정체성 및 승인, 서버는 역사 읽기 및 복원 권한을 확인합니다. 과거 버전은 현재 문서가 이미 제거 된 데이터를 포함 할 수 있습니다.

[협업 확장](/server/collaboration/extensions)를 참조하고 [연혁 예](/server/collaboration/examples#history)로 서비스를 조립 한 다음 위의 제품 가이드와 UI를 연결하십시오.

역사 색인은 재건 가능한 파생된 자료입니다. **확인된 changesets는 권한이 있는 내용 근원을 남아 있습니다.** 당신의 신청은 persistence와 보유를 통제합니다. 역사 패널은 백업을 대체하지 않습니다.

## 관련 기능과의 관계

| 기능 제품 | 제품정보 |
| --- | --- |
| 취소 / 취소 | Revert 또는 reapply 역사 서비스없이 편집 작업. |
| 버전 역사 | 세션을 통해 확인 된 버전, 변경을 검사하고 공유 콘텐츠를 복원합니다. |
| [콘텐츠 비교](/overview/features/shared/compare) | UI 또는 에이전트에 대한 두 가지 내용 상태를 비교합니다. 읽기 전용 비교는 콘텐츠를 복원하지 않습니다. |
| [Worktree](/overview/features/shared/worktree) | 공유 콘텐츠로 이전하기 전에 검토를위한 Isolate 초안 변화. |

Facade APIs를 통해 이루어진 에이전트 변경은 동일한 역사 파이프라인을 한 번 협력을 확인합니다. 응용 프로그램은 자동화 된 검토 및 검사에 대한 콘텐츠 비교와 역사를 결합 할 수 있습니다.
