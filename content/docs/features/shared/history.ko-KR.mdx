버전 기록은 협업에서 확정된 변경을 탐색 가능한 버전으로 정리합니다. 작성자, 시간, 작업과 과거 내용을 확인하고 권한이 있으면 복원할 수 있습니다. 페이지를 새로 고쳐도 기록을 조회할 수 있습니다.

## 버전 기록의 원리

- **Mutation**: 셀 값 설정이나 문단 삽입처럼 재실행할 수 있는 콘텐츠 변경입니다.
- **Changeset**: 순서가 있는 Mutation들을 묶은 협업 제출 단위입니다.

### 1. 변경 기록

**편집 내용을 제출할 때 실행됩니다.** 사용자 또는 Agent의 변경을 Mutation으로 표현하고 Changeset으로 묶어 협업 서비스에 제출한 뒤 확정하여 저장합니다.

<Mermaid chart={"flowchart LR\n    A[\"콘텐츠 편집\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"확정 및 저장<br/>revision 기록\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

**Revision**은 문서 기록에서 확정된 제출의 위치를 나타냅니다. History는 확정된 Changeset의 색인을 만들고 시간과 작업에 따라 그룹화하여 버전 타임라인을 구성합니다.

### 2. 과거 콘텐츠 재구성

**과거 버전을 선택할 때 실행됩니다.** Snapshot은 특정 revision의 전체 콘텐츠 상태입니다. 기준 Snapshot과 목표 revision까지의 후속 Changeset을 읽고 Mutation을 순서대로 재실행하여 읽기 전용 기록 화면을 만듭니다.

<Mermaid chart={"flowchart LR\n    A[\"버전 선택<br/>revision N\"]\n    B[\"Snapshot 및<br/>후속 Changeset 조회\"]\n    C[\"Mutation을<br/>순서대로 재실행\"]\n    D[\"과거 콘텐츠 표시<br/>읽기 전용\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

예: **revision 10의 Snapshot + revision 11~15의 Changeset = revision 15의 콘텐츠.**

### 3. 현재 문서 복원

**이 버전 복원을 선택할 때 실행됩니다.**

> 대상 버전 선택 → 복원 Mutation 제출 → 협업에서 확정 → 현재 문서를 갱신하고 새 revision 생성

복원 작업도 새 기록을 만들며 이전 버전은 계속 유지됩니다.

## 버전과 변경 확인

1. 편집기에서 버전 기록을 열고 버전을 선택합니다.
2. 버전 그룹을 펼쳐 개별 revision 을 확인하고 읽기 전용 뷰어에서 내용과 차이를 검토합니다.
3. 이 버전 복원을 선택하면 협업을 통해 현재 공유 문서가 갱신되고 다른 참여자에게도 반영됩니다.

일정 시간 내의 수정은 그룹으로 묶일 수 있습니다. 기록 항목은 각 키 입력이나 Snapshot 생성과 일대일로 대응하지 않습니다.

### 변경 색상 읽기

| 표시 | 의미 |
| --- | --- |
| 🟦 **파란색: 수정** | 기존 내용, 서식 또는 개체 속성이 변경되었습니다. |
| 🟩 **초록색: 추가** | 새 행, 문단, 레코드 또는 보드 개체입니다. |
| 🟥 **빨간색: 삭제** | 삭제한 내용을 기록 화면에 표시해 추적할 수 있습니다. |

색상은 변경 유형을 나타냅니다. 텍스트 교체는 추가와 삭제를 함께 표시할 수 있으며, 강조 범위는 제품 뷰어가 결정합니다.

## 애플리케이션에 통합

- **서버**: Core Collaboration 에 History Service, Endpoint 및 영구 저장용 Database Adapter 를 추가합니다. Unit 생성과 changeset 확정 이벤트로 기록 색인을 만들고 버전 및 변경 조회를 제공합니다.
- **브라우저**: 공통 기록 기능과 제품별 History / History UI 플러그인을 등록하고 기록 API 에 연결합니다. 뷰어는 선택한 revision 과 차이를 불러옵니다. 사용자 정의 콘텐츠에는 해당 뷰어 플러그인이 필요합니다.
- **권한**: 애플리케이션이 인증 및 인가를 제공하고 서버가 기록 조회와 복원 권한을 확인합니다. 과거 버전에는 현재 삭제된 데이터도 포함될 수 있습니다.

[협업 확장](/server/collaboration/extensions)과 [History 예제](/server/collaboration/examples#history)를 참고하여 서비스를 구성하고 제품별 가이드로 UI 를 연결하세요.

기록 색인은 다시 만들 수 있는 파생 데이터이며 확정된 changeset 이 권위 있는 원본입니다. 영구 저장과 보존 정책은 애플리케이션이 관리합니다. 기록 패널은 백업을 대체하지 않습니다.

## 관련 기능과의 관계

- **실행 취소 / 다시 실행**: 편집 작업을 되돌리거나 재적용합니다. 기록 서비스가 필요하지 않습니다.
- **버전 기록**: 세션을 넘어 확정된 버전을 추적하고 공유 콘텐츠를 복원합니다.
- [콘텐츠 비교](/overview/features/shared/compare): 두 상태를 읽기 전용으로 비교하며 복원하지 않습니다.
- [Worktree](/overview/features/shared/worktree): 초안 변경을 격리하고 검토 후 병합을 결정합니다.

Facade API 로 수행한 Agent 변경도 협업에서 확정된 뒤 같은 기록 흐름에 포함할 수 있습니다. 콘텐츠 비교와 결합해 자동 검토를 구성할 수 있습니다.
