历史记录将已经协同确认的修改组织成可浏览的版本。开发者和用户可以沿时间线查看修改者、时间与操作，打开历史内容，检查变化，并在有权限时恢复版本。刷新页面后仍可追溯，不受当前编辑会话限制。

## 历史记录的原理

- **Mutation**：一条可重放的内容变更，例如修改单元格或插入段落。
- **Changeset**：按顺序封装一组 Mutation 的一次协同提交。

### 1. 记录变更

**编辑提交时发生。** 用户或 Agent 产生的内容变更，以 Mutation 的形式封装进 Changeset，提交给协同服务确认并保存。

<Mermaid chart={"flowchart LR\n    A[\"编辑内容\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"协同确认并保存<br/>记录 revision\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

**Revision（修订号）** 标识已确认提交在文档历史中的位置。History 基于已确认的 Changeset 建立索引，并按时间和操作分组，组织成版本时间线。

### 2. 重建历史内容

**选择历史版本时发生。** Snapshot（快照）是某个 revision 的完整内容状态。系统读取基准 Snapshot，以及此后直到目标 revision 的 Changeset，按顺序重放其中的 Mutation，生成只读历史视图。

<Mermaid chart={"flowchart LR\n    A[\"选择版本<br/>revision N\"]\n    B[\"读取 Snapshot<br/>及后续 Changeset\"]\n    C[\"顺序重放<br/>Mutation\"]\n    D[\"显示历史内容<br/>只读视图\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

例如：**revision 10 的 Snapshot + revision 11～15 的 Changeset = revision 15 的内容。**

### 3. 恢复为当前版本

**点击“恢复此版本”时发生。**

> 选定目标版本 → 提交恢复 Mutation → 协同确认 → 更新当前文档，产生新 revision

恢复操作本身也会形成新的历史记录，原有版本继续保留。

## 查看版本与变更

1. 从编辑器的**历史记录**入口打开时间线，选择要查看的版本。
2. 展开版本分组，查看其中更细的修改记录；选择记录后，在只读查看器中查看对应内容与差异。
3. 需要回退时，选择**恢复此版本**。恢复通过协同修改当前共享文档，其他参与者也会收到更新。

时间线可以将一段时间内的修改合并为一个版本分组，展开后再查看具体 revision。**历史条目不等于每次按键，也不等于每次生成 Snapshot。**

### 三种颜色如何阅读

| 标记 | 含义 | 示例 |
| --- | --- | --- |
| 🟦 **蓝色：修改** | 已有内容发生变化。 | 修改数值、段落格式或对象属性。 |
| 🟩 **绿色：新增** | 这一版本中加入的内容。 | 新增行、段落、记录或画布对象。 |
| 🟥 **红色：删除** | 这一版本中移除的内容。 | 删除的文字或对象在历史视图中保留标记，便于追溯。 |

颜色表示**变更类型**。文字替换可能同时展示新增与删除；具体高亮范围由各产品的历史查看器确定。

## 在应用中接入

历史记录由 Server SDK 的 History 扩展与 Web SDK 的产品历史插件共同提供：

- **服务端**：在核心协同之上接入 History Service、Endpoint 与持久化 Database Adapter。服务订阅 Unit 创建和 changeset 提交事件，建立历史索引，并提供版本列表与修改查询。
- **浏览器**：注册通用历史能力及对应产品的 History / History UI 插件，连接历史接口。查看器加载选定 revision 的内容并呈现差异；自定义内容需按产品接入相应查看器插件。
- **权限**：应用负责身份与授权，服务端检查历史读取与恢复权限。历史版本可能包含当前文档已经删除的数据。

从[协同扩展模块](/server/collaboration/extensions)了解模块关系，按 [History 示例](/server/collaboration/examples#history)组装服务，再使用上面的产品指南接入界面。

历史索引是可重建的派生数据，**已确认的 changeset 仍是内容的权威来源**。持久化与保留策略由应用配置；历史面板不能替代备份。

## 与撤销、比较和 Worktree 的关系

| 能力 | 解决什么问题 |
| --- | --- |
| 撤销 / 重做 | 在编辑过程中撤回或重做操作，不需要历史服务。 |
| 历史记录 | 跨会话追溯已确认的版本，查看变化并恢复共享内容。 |
| [内容比较](/overview/features/shared/compare) | 比较两份内容，得到可供界面或 Agent 使用的差异；只读比较本身不恢复内容。 |
| [Worktree](/overview/features/shared/worktree) | 隔离草稿修改，在审阅后决定是否合入共享内容。 |

Agent 通过 Facade API 产生的修改，在接入协同并获服务端确认后，也可进入同一条历史链路。应用可结合内容比较构建自动审阅与检查流程。
