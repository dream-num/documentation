历史记录把已协同确认的修改组织成可浏览的版本。每条已确认的修改都带有作者、时间和操作，开发者和用户可以据此打开当时的内容、查看差异，并在有权限时恢复某个版本。历史记录不随编辑会话结束而消失，刷新页面后仍然可以查看。

## 历史记录的原理

**Mutation** 是一条可以重放的内容变更，例如修改单元格或插入段落。**Changeset** 是一次协同提交，包含一组按顺序排列的 Mutation。

### 1. 记录变更

用户或 Agent 的每次编辑都会产生 Mutation。Univer 把这些 Mutation 打包成一个 Changeset 提交，由协同服务确认并保存。

<Mermaid chart={"flowchart LR\n    A[\"编辑内容\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"协同确认并保存<br/>记录 revision\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

提交确认后会获得一个 **Revision（修订号）**，用来标识这次提交在文档历史中的位置。History 为已确认的 Changeset 建立索引，按时间和操作分组，并构建版本时间线。

### 2. 重建历史内容

**Snapshot（快照）** 是某个 revision 对应的完整内容状态。选中某个历史版本后，系统从基准 Snapshot 开始，加载该 Snapshot 之后直至目标 revision 的 Changeset，按顺序重放其中的 Mutation，得到一份只读的历史视图。

<Mermaid chart={"flowchart LR\n    A[\"选择版本<br/>revision N\"]\n    B[\"读取 Snapshot<br/>及后续 Changeset\"]\n    C[\"顺序重放<br/>Mutation\"]\n    D[\"显示历史内容<br/>只读视图\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

例如：**revision 10 的 Snapshot + revision 11～15 的 Changeset = revision 15 的内容。**

### 3. 恢复为当前版本

选中**恢复此版本**后，执行流程如下：

> 选定目标版本 → 提交恢复 Mutation → 协同确认 → 更新当前文档，产生新 revision

恢复操作本身会成为一条新的历史记录。此前的版本仍然保留。

## 查看版本与变更

1. 在编辑器中打开**历史记录**，选择一个版本。
2. 展开版本分组，查看其中各个 revision。选中某个 revision，即可在只读查看器中查看当时的内容和变化。
3. 需要回退时，选择**恢复此版本**。恢复操作通过协同更新共享文档，其他参与者会收到这次改动。

一个版本分组可能合并一段时间内的多次编辑，展开后才能看到各个 revision。**一条历史记录不一定对应一次按键，也不一定对应一次生成的 Snapshot。**

### 三种颜色如何阅读

| 标记 | 含义 | 示例 |
| --- | --- | --- |
| 🟦 **蓝色：修改** | 已有内容发生变化。 | 数值、段落格式或对象属性被修改。 |
| 🟩 **绿色：新增** | 这一版中加入的内容。 | 新增的行、段落、记录或画布对象。 |
| 🟥 **红色：删除** | 这一版中移除的内容。 | 删掉的文字或对象在历史视图中保留标记。 |

颜色表示**变更类型**。替换文字时可能同时产生新增和删除。高亮范围由各产品的查看器决定。

## 在应用中接入

历史记录由两部分组成：Server SDK 的 History 扩展，以及 Web SDK 中各产品的历史插件。

- 服务端需要在核心协同之上接入 History Service、Endpoint 和持久化的 Database Adapter。该服务订阅 Unit 创建和已确认的 Changeset，建立历史索引，并对外提供版本和 Changeset 查询。
- 在浏览器端，需要注册通用历史能力和对应产品的 History / History UI 插件，然后连接历史接口。查看器加载选定的 revision 并展示其变更。自定义内容需要注册对应的查看器插件。
- 身份和授权由应用提供，服务端检查历史读取和恢复权限。历史版本可能包含当前文档已经删除的数据。

参见[协同扩展模块](/server/collaboration/extensions)，按 [History 示例](/server/collaboration/examples#history)组装服务，再通过上面的产品指南接入界面。

历史索引是可重建的派生数据。**已确认的 Changeset 仍是内容的权威来源。** 持久化和保留策略由应用控制，历史面板不能替代备份。

## 与撤销、比较和 Worktree 的关系

| 能力 | 解决什么问题 |
| --- | --- |
| 撤销 / 重做 | 不需要历史服务即可撤回或重做一次编辑操作。 |
| 历史记录 | 跨会话追溯已确认的版本，查看变更并恢复共享内容。 |
| [内容比较](/overview/features/shared/compare) | 比较两份内容，供界面或 Agent 使用。只读比较不会恢复内容。 |
| [Worktree](/overview/features/shared/worktree) | 隔离草稿中的修改，审阅后再合并到共享内容。 |

Agent 通过 Facade API 所做的修改，经协同确认后会进入同一条历史链路。应用可以将历史记录与内容比较结合，用于自动审阅和检查。
