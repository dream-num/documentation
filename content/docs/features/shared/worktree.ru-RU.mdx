Worktree предоставляет изолированные черновики контента Office, которые люди и агенты все еще могут редактировать вместе. Агент может пересматривать бюджет, реорганизовывать данные или переписывать краткое сообщение, в то время как люди продолжают редактирование основного документа, который называется стволом. Проект проверяется и пересматривается до того, как его изменения достигают ствола.

Изоляция относится к содержанию документа и его изменениям, а не к рабочему каталогу Git.Одна задача может охватывать несколько [Подразделения](/guides/sheets/getting-started/quickstart#unit), например, книгу, документ и презентацию.

## Изоляция: развитие от общей базы [#isolation]

Когда Worktree создается для существующего блока, служба записывает, что текущий пересмотр багажника Unit как **исходный**. Проект начинается с этого пересмотра и имеет свои собственные снимки, изменения, изменения, присутствие и комнаты совместной работы. Редакции, сделанные в проекте, не влияют на багажник.

| Понятие | Роль |
| --- | --- |
| Baseline | Версия, с которой начинался черновик, использовалась для сравнения и слияния. |
| Draft head | Последний подтвержденный проект пересмотренного варианта. Проекты представлений продвигают его вперед. |
| Ready head | Замороженный проект пересмотра, который определяет, что будет рассмотрено и объединено. |

Пересмотры с каждой стороны образуют отдельную последовательность представления, поэтому большее число не указывает, какой контент новее. Вытягивание черновика синхронизирует собственные изменения проекта. Новые правки багажника не вносятся в рецензируемую версию самостоятельно; слияние предварительного просмотра и само слияние примиряют два.

## Как AI SDK подключает тот же черновик [#ai-sdk]

AI SDK Collaboration Runtime управляет одним блоком снимков, изменений и доработок. На стороне Server SDK сервис Worktree владеет созданием, жизненным циклом и слиянием. Runtime не требует второго механизма редактирования для работы с Worktrees.

Приложение разрешает `worktreeID + unitID` в снимке проекта, отправляет, WebSocket и Session Ticket URL-адреса, а затем передает их в Runtime.Те же инструменты проверки и редактирования могут затем нацеливаться либо на багажник, либо на черновик.

<Mermaid chart={"flowchart LR\n    A[\"Агент / бизнес-CLI\"]\n    B[\"Проверка в Web\"]\n    C[\"Адаптер цели приложения\"]\n    D[\"Worktree Endpoint\"]\n    E[\"Тот же черновой Unit\"]\n    A --> C\n    B --> C\n    C --> D --> E"} />

Один идентификатор блока может существовать в багажнике и в нескольких рабочих деревьях одновременно. Цель должна включать в себя Worktree, в котором он живет, а проверка, выполнение, скриншоты и веб-предварительный просмотр должны использовать одну и ту же цель. В противном случае инструмент может читать из черновика и писать в багажник. Веб-клиент загружает один и тот же черновик с конфигурацией совместной работы, которая соответствует ему.

| Компонент | Задача |
| --- | --- |
| Web SDK | Движок общего контента, для операций агента без головы и для редактирования в браузере. |
| Server SDK | Изоляция, хранение изменений и ревизий, состояния, OT. |
| AI SDK | Составляемое время выполнения, инспекция, поиск API, выполнение Facade и визуальные проверки. |
| Приложение | Выбор модели, отображение целей, идентичность, авторизация, задачи и пользовательский интерфейс обзора. |

## От работы агента к передаче результата [#agent-workflow]

Приложение может выполнять задачи параллельно, предоставляя каждому агенту свой собственный Worktree. Каждый агент редактирует свой черновик, проверяет результат и отмечает его Готово. Затем человек просматривает черновики по одному за раз, повторно открывает черновик , который требует больше работы, и объединяет принятые черновики в текущий багажник.

<Mermaid chart={"flowchart TB\n    TRUNK[\"Основной документ · Trunk\"]\n    subgraph PARALLEL[\"Параллельная работа агентов\"]\n        direction LR\n        AGENT_A[\"Agent A<br/>Worktree A<br/>Изменить и проверить\"]\n        AGENT_B[\"Agent B<br/>Worktree B<br/>Изменить и проверить\"]\n        AGENT_C[\"Agent C<br/>Worktree C<br/>Изменить и проверить\"]\n    end\n    REVIEW[\"Проверка человеком<br/>Черновик<br/>Предпросмотр\"]\n    MERGE[\"Merge по отдельности<br/>С актуальным trunk\"]\n    RESULT[\"Новая версия trunk\"]\n    TRUNK --> AGENT_A\n    AGENT_A -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_B\n    AGENT_B -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_C\n    AGENT_C -->|\"Ready\"| REVIEW\n    REVIEW -->|\"Одобрить\"| MERGE\n    REVIEW -.->|\"Reopen нужного черновика\"| PARALLEL\n    MERGE --> RESULT"} />

1. Создайте Worktree и загрузите его. Выберите блоки, которые покрывает задача, подключите цель Worktree, и вытащите ее последний контент.
2. Проверяйте структуру с помощью Инспекции, ищите API по мере необходимости и вносите изменения через Фасады.
3. Отправьте проект, прочитайте данные и результаты расчета, и захватите скриншоты, когда это необходимо. Слайды также могут запускать Layout Lint. Если чеки сообщают о проблеме, отредактируйте проект снова.
4. Марк Готов. Это замораживает пересмотр проекта каждого подразделения, и редактирование прекращается до завершения обзора.
5. Объединить принятые проекты. Откройте черновик обратно в черновик до того, как человек или агент снова отредактирует. Отбросьте проекты, которые не нужны.

| Операция | Результат |
| --- | --- |
| `runtime.commit()` | Представляет только проект и продвигает проект пересмотра вперед. |
| `markReady()` | Замораживает обзорную версию, не сливая ничего в багажник. |
| `reopenWorktree()` | Принимает черновик от Ready к Draft, поэтому редактирование может продолжаться. |
| `mergeWorktree()` | Слияние замороженных изменений в багажнике, Отряд за Отрядом. |

Обязательство, готовность и слияние - это три отдельные операции. Как только черновик готов, ни человек, ни агент не могут редактировать его до тех пор, пока он не будет вновь открыт. Для связи между Runtime и CLI см. [Рабочий процесс AI SDK](/ai/worktree).

## Объединение с актуальным trunk [#merge]

Для Подразделения, пришедшего из багажника, служба считывает черновые наборы изменений от **Оригинальное название: Ready Head**, собирает их мутации и отправляет их через службу совместной работы багажника.Если багажник продвинулся с базового уровня, [ОТ](/overview/features/shared/collaboration) преобразует эти мутации против более поздних правок багажника, прежде чем служба подтвердит новую редакцию.

Слияние, таким образом, применяется редактирование; оно не заменяет последний документ старым моментальным снимком. Параллельные изменения, которые могут быть преобразованы, примиряются. Изменения, которые не могут быть изменены или которые больше не применяются, возвращаются в качестве конфликтов для приложения для обработки. OT не улаживает каждое деловое несогласие.

Единица, созданная внутри Worktree, не имеет базового уровня багажника, чтобы слиться с ним. Слияние создает его в багажнике, не копируя всю историю изменений.

## Проверка изменений и результата объединения [#review]

- Чтобы увидеть, что изменилось, сравните полное базовое состояние с состоянием Ready draft с использованием [сравнивать](/overview/features/shared/compare).
- Чтобы увидеть, что произойдет в данный момент, позвоните в `evaluateUnitMerge()` после Ready. Когда багажник продвинулся, изолированное время выполнения применяет OT-преобразованного кандидата к текущему багажнику и производит предварительный просмотр только для чтения. Он не представляет никаких изменений и не изменяет ни багажник, ни черновик.

Предварительный просмотр описывает состояние в момент его запроса. Багажник может измениться впоследствии, и фактическое слияние работает из состояния, которое он находит при его запуске. Слияние нескольких единиц также не является одной атомной транзакцией, поэтому, если одна единица выходит из строя, единицы, которые уже слились, остаются слитыми. Отобразите результат для каждой единицы и обработайте сбои индивидуально.

## Подключение и охват [#integration]

Объедините адаптеры Worktree Client, Service, Endpoint и базы данных с ядром коллаборации. Держите проект хранилища отдельно, и делитесь одним магазином билетов сеанса с багажником. Приложение разрешает проект доступа и багажник пишет отдельно; изоляция не предоставляет доступ сама по себе.
