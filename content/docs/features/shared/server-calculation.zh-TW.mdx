Headless Univer 是 Univer 的無介面內容執行環境，與瀏覽器編輯器共用內容模型、命令、計算和 Facade API。它按需組合外掛，不掛載互動式編輯器 UI，可在 Node.js 中處理內容，也可用於瀏覽器中的無介面任務。可用能力由註冊的產品與功能外掛決定。

本頁的 JavaScript/TypeScript 內容執行環境與 `univer-rs` 是不同的實作。後者用於伺服器端計算與檔案轉換，可圍繞同一份快照與 Headless 工作流程組合使用。

## Headless 能做什麼 [#headless-capabilities]

- **讀寫內容與結構**：建立或載入 Univer 快照，透過 Facade API 讀寫儲存格、段落、頁面、圖形物件或記錄，再儲存更新的快照。適合批次處理、資料產生、內容檢查與 Agent 自動化。
- **執行已註冊的業務邏輯**：執行公式、排序、篩選、資料驗證和樞紐分析等外掛能力，修改圖片、圖表、形狀與留言等資源。可用操作取決於產品、功能外掛及其相依項目。
- **串接其他服務**：加入 Node.js 協同用戶端後，可載入協同 Unit、提交修改並等待同步確認；結合 Server SDK 轉換模組，可匯入與匯出 Office 檔案。

Headless 本身不提供選單、工具列、對話框、滑鼠鍵盤互動、截圖或列印，也不會自動提供持久化、身分驗證、協同伺服器或檔案轉換。`save()` 回傳 Univer 快照，不等於寫入資料庫或匯出 XLSX、DOCX、PDF。截圖與視覺版面檢查需要另接[渲染執行環境](/ai/visual-inspection)；無介面瀏覽器仍會執行渲染層。

### 哪些套件不屬於純內容執行環境

- `@univerjs/ui`、`@univerjs/design` 和產品或功能的 `*-ui` 套件，例如 `@univerjs/sheets-ui`、`@univerjs/docs-ui`、`@univerjs-pro/slides-ui`，提供介面、渲染整合或互動，不應加入純 Node.js 內容處理設定。
- `@univerjs/sheets-find-replace`、`@univerjs/sheets-crosshair-highlight` 雖沒有 `-ui` 後綴，仍依賴 `@univerjs/sheets-ui`，不能據名稱判定為 Headless 外掛。
- `@univerjs/preset-sheets-core`、`@univerjs/preset-docs-core` 的預設組合會註冊 UI 外掛，並非 Node.js Headless 預設組合。請使用外掛模式明確選擇內容層相依項目。

**`@univerjs/engine-render` 需個別看待。** 目前 Node.js 範例會註冊它，以提供共用的渲染管理等相依服務；註冊外掛不等於建立 Canvas 或掛載編輯器。它可出現在 Headless 組合中，但實際繪製、字型測量、截圖等 API 仍需相應渲染環境，並非整個套件的 API 都能在純 Node.js 中使用。

**Facade 是操作入口，不是環境適配器。** 按需匯入內容外掛的 `/facade` 擴充並註冊實作功能的外掛。`@univerjs/ui/facade`、`@univerjs/sheets-ui/facade` 等 UI 擴充的選單、捲動與選取範圍視覺互動 API 仍需 UI。應檢查外掛相依項目和實際呼叫路徑，而非僅看名稱或是否提供 Facade。

可執行的外掛組合見 [Sheets Headless 入門](/guides/sheets/getting-started/node)與 [Docs Headless 入門](/guides/docs/getting-started/node)。

## 前端即時計算，伺服器依版本計算 [#伺服器預先計算前端快速顯示]

前端與伺服器都具備公式引擎。前端回應使用者編輯，伺服器在產生快照或處理檔案時，針對確定的內容版本計算。

- **編輯時**：前端在本機增量計算並即時顯示結果，也可透過 Worker 執行；協作服務記錄並同步內容修改。
- **產生快照時**：依伺服器快照策略觸發儲存流程，取得本次內容版本，由 `univer-rs` 計算，再將該版本的內容與計算結果一起儲存。
- **再次開啟時**：前端重用快照中有效的計算結果，補齊之後的修改並持續計算，減少重複的完整計算。

<Mermaid chart={"flowchart LR\n    F[\"前端編輯<br/>即時計算\"]\n    C[\"內容同步<br/>已確認修改\"]\n    R[\"Rust 計算<br/>內容版本 N\"]\n    S[\"儲存快照<br/>saveSnapshot\"]\n    F <--> C\n    C -->|\"產生快照時\"| R\n    R --> S"} />

**修改持續同步；伺服器計算在產生快照時觸發，結果與對應的內容版本一起儲存。**

首次載入可依已儲存的結果選擇計算策略：

- `WHEN_EMPTY`：重用已儲存的公式值，只計算缺少的結果。
- `NO_CALCULATION`：初始化時不計算，由應用程式提供結果。
- `FORCED`：既有結果需要更新時，重新計算全部公式。

這些選項控制首次載入。後續編輯由前端持續計算；伺服器在產生對應版本快照或處理檔案時按需計算。請參閱[公式文件](/guides/sheets/features/core/formula)、[協作總覽](/server/collaboration/overview)與[檔案匯入匯出](/overview/features/shared/file-conversion)。

## 陣列公式的計算與展開

在已支援的函數與格式範圍內，Rust 依 Excel 的陣列公式與溢出規則計算及展開。結果包含錨點、展開範圍與各儲存格數值，支援動態陣列與舊式陣列公式的宣告區域。

例如，在空白 `A1` 輸入 `=SEQUENCE(3,2)`，結果為：

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

公式保留於 `A1`，結果展開至 `A1:B3`。陣列縮小時清除舊展開值；展開區域被占用時回傳 `#SPILL!`。前端顯示、Agent 讀取與檔案匯出可重用已計算的快照。

函數與範圍規則見[公式支援](/guides/sheets/features/core/formula)及 [Excel 陣列展開行為](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior)。

## 接入 Agent 的執行與驗證流程

模型、對話與工具調度沿用現有 Agent，AI SDK 提供 Office 內容操作入口：

1. 檢查結構，讀取任務涉及的內容。
2. 透過無頭執行環境進行 Facade 修改與計算。
3. 等待計算與提交確認，讀回更新後的狀態。
4. 驗證數值與結構；需要視覺驗證時產生截圖或檢查版面。

可結合[內容操作](/ai/content-operations)與[視覺檢查](/ai/visual-inspection)。需要人工審閱時，先在 [Worktree](/ai/worktree) 修改，再比較與合併。[Univer CLI](/overview/examples/cli) 展示如何組成 Agent 可用的應用程式。
