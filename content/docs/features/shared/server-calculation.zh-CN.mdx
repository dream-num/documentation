Headless Univer 是 Univer 的内容运行时，不包含可交互的编辑器界面。它与浏览器编辑器共用同一套内容模型、命令、计算和 Facade API。应用可以在 Node.js 中运行它来处理内容，也可以在浏览器中运行它来执行不需要界面的任务。它具备哪些能力，取决于注册了哪些产品和功能插件。

本页介绍的 JavaScript/TypeScript 内容运行时与 `univer-rs` 是两套彼此独立的实现。后者负责服务端计算和文件转换，可以基于同一份快照与 Headless 工作流配合使用。

## Headless 能做什么 [#headless-capabilities]

- 读写内容和结构。创建或加载 Univer 快照，使用 Facade API 读写单元格、段落、页面、图形对象或记录，然后保存更新后的快照。批量处理、数据生成、内容检查和 Agent 自动化均以这套能力为基础。
- 运行已注册的业务逻辑。运行时支持公式计算、排序、筛选、数据验证和透视表插件，也可以修改图片、图表、形状和评论等资源。可执行的操作取决于注册的产品和功能插件及其依赖。
- 连接其他服务。接入 Node.js 协同客户端后，可以加载协同 Unit、提交修改并等待同步。将 Server SDK 的转换模块与运行时结合，可以导入和导出 Office 文件。

Headless 不提供编辑器界面，包括菜单、工具栏、弹窗、鼠标键盘交互、截图和打印。它也不自带持久化、用户认证、协同服务器和文件转换能力。`save()` 返回的是 Univer 快照，不会写入数据库，也不会导出 XLSX、DOCX 或 PDF。截图和视觉布局检查需要单独接入[渲染运行时](/ai/visual-inspection)，因为无界面浏览器仍然运行渲染层。

### 哪些包不属于纯内容运行时

- `@univerjs/ui`、`@univerjs/design`，以及产品或功能的 `*-ui` 包（例如 `@univerjs/sheets-ui`、`@univerjs/docs-ui`、`@univerjs-pro/slides-ui`）提供界面、渲染接入或交互能力，不应加入仅处理内容的 Node.js 配置。
- `@univerjs/sheets-find-replace` 和 `@univerjs/sheets-crosshair-highlight` 没有 `-ui` 后缀，但依赖 `@univerjs/sheets-ui`，因此不能仅凭包名认定它们是 Headless 插件。
- `@univerjs/preset-sheets-core` 和 `@univerjs/preset-docs-core` 这两个默认预设会注册 UI 插件，不是 Node.js Headless 预设。这类场景应使用插件模式，明确选择内容层的依赖。

**`@univerjs/engine-render` 需要单独说明。** 当前的 Node.js 示例会注册它，用于提供渲染管理等共享依赖。注册插件并不创建 Canvas，也不挂载编辑器。它可以出现在 Headless 组合中，但绘制、字体测量和截图 API 仍然需要合适的渲染环境。因此，不能认为该包的所有 API 都能在纯 Node.js 中使用。

**Facade 是操作 API，不是运行环境的适配层。** 对于所用的内容插件，导入其 `/facade` 扩展，并注册提供相应能力的插件。`@univerjs/ui/facade`、`@univerjs/sheets-ui/facade` 这类 UI 扩展仍然需要 UI，它们提供的菜单、滚动和选择区交互同样如此。判断时应检查插件依赖和实际调用路径，不能只看包名，也不能只看是否存在 Facade API。

可运行的插件组合见 [Sheets Headless 入门](/guides/sheets/getting-started/node)和 [Docs Headless 入门](/guides/docs/getting-started/node)。

## 前端即时计算，服务端按版本计算 [#服务端预计算前端快速展示]

前端和服务端都运行公式引擎。前端随编辑响应，服务端在生成快照或处理文件时，对抓取到的内容版本执行计算。

- 编辑时，浏览器在本地计算受影响的公式，也可以放在 Worker 中执行，计算结果立即显示。协同服务记录这些内容修改并将其同步。
- 生成快照时，服务端的快照策略触发保存流程。服务端先抓取该操作对应的内容版本，使用 `univer-rs` 计算，再将该版本的内容和结果一起保存。
- 重新打开文档时，前端复用快照中仍然有效的结果，应用后续修改并继续计算，避免每次全量重算。

<Mermaid chart={"flowchart LR\n    F[\"前端编辑<br/>即时计算\"]\n    C[\"内容同步<br/>已确认修改\"]\n    R[\"Rust 计算<br/>内容版本 N\"]\n    S[\"保存快照<br/>saveSnapshot\"]\n    F <--> C\n    C -->|\"生成快照时\"| R\n    R --> S"} />

**内容修改持续同步；服务端在生成快照时执行计算，结果与对应的内容版本一起保存。**

首次加载时，应用根据已保存的结果决定初始计算的方式：

- `WHEN_EMPTY`：复用已保存的公式值，只计算缺失的结果。
- `NO_CALCULATION`：初始化时不计算，结果由应用提供。
- `FORCED`：已保存的结果需要刷新时，全部重算。

这些选项仅控制首次加载。此后的编辑仍在前端计算；服务端在生成带版本的快照或处理文件时按需计算。配置见[公式文档](/guides/sheets/features/core/formula)，同步机制见[协同总览](/server/collaboration/overview)，文件处理见[导入与导出](/overview/features/shared/file-conversion)。

## 数组公式的计算与展开

在支持的函数和格式范围内，Rust 遵循 Excel 的数组公式和溢出规则进行计算。计算结果连同锚点和展开范围一并返回，同时支持动态数组和旧式数组公式的声明区域。

例如，在空白的 `A1` 里写入 `=SEQUENCE(3,2)`，得到的结果是：

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

公式仍保留在 `A1`，结果占据 `A1:B3`。数组缩小时，旧的展开值会被清除；展开区域被占用时返回 `#SPILL!`。前端展示、Agent 读取和文件导出都可以复用这份计算好的快照。

具体函数和范围规则见[公式支持](/guides/sheets/features/core/formula)和 [Excel 数组展开行为](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior)。

## 接入 Agent 的执行与验证流程

模型、对话和工具编排沿用现有方案。AI SDK 提供一组操作 Office 内容的工具，供该 Agent 调用：

1. 检查结构，读取目标内容。
2. 在无头运行时中执行 Facade 修改和所需的计算。
3. 待计算和提交确认后，读取更新后的状态。
4. 核对值和结构；需要视觉验证时，补充截图或布局检查。

[内容操作](/ai/content-operations)和[视觉检查](/ai/visual-inspection)可以配合使用。需要人工审阅时，先将修改放入 [Worktree](/ai/worktree)，再进行比较和合并。[Univer CLI](/overview/examples/cli) 演示了如何将这些能力组合成 Agent 可驱动的应用。
