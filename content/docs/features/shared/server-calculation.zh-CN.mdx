headless Univer 是 Univer 的无界面内容运行时，与浏览器编辑器共享内容模型、命令、计算和 Facade API。它按需组合插件，不挂载交互式编辑器 UI，可以在 Node.js 中处理内容，也可以用于浏览器中的无界面任务。可用能力由所注册的产品与功能插件决定。

本页的 JavaScript/TypeScript 内容运行时与 `univer-rs` 是不同的执行实现。后者用于服务端计算和文件转换，可围绕同一份快照与 Headless 工作流组合使用。

## Headless 能做什么 [#headless-capabilities]

- **读写内容与结构**：创建或加载 Univer 快照，通过 Facade API 读写单元格、段落、页面、图形对象或记录，执行命令后保存更新的快照。适合批量处理、数据生成、内容检查和 Agent 自动化。
- **运行已注册的业务逻辑**：执行公式计算、排序、筛选、数据验证、透视表等插件能力；修改图片、图表、形状、评论等内容资源。能操作哪些内容，取决于产品与功能插件及其依赖。
- **接入其他服务**：注册 Node.js 协同客户端后，可加载协同 Unit、提交修改并等待同步确认；结合 Server SDK 的转换模块，可处理 Office 文件的导入与导出。

Headless 本身不提供菜单、工具栏、弹窗、鼠标键盘交互、截图或打印，也不会自动提供持久化、用户认证、协同服务器或文件转换服务。`save()` 得到的是 Univer 快照，并不等于写入数据库或导出 XLSX、DOCX、PDF。截图和视觉布局检查需要另行接入[渲染运行时](/ai/visual-inspection)；无界面浏览器仍然在运行渲染层。

按需增加基础设施：`@univerjs/network`、`@univerjs/rpc-node` 用于网络和 Node.js 计算进程；`@univerjs-pro/license` 用于许可证接入。`@univerjs-pro/collaboration`、`@univerjs-pro/collaboration-client` 与 `@univerjs-pro/collaboration-client-node` 可组成 Headless 协同客户端，它们不等于协同服务器。独立处理本地快照不需要接入协同服务。

### 哪些包不属于纯内容运行时

- `@univerjs/ui`、`@univerjs/design` 和产品或功能的 `*-ui` 包（如 `@univerjs/sheets-ui`、`@univerjs/docs-ui`、`@univerjs-pro/slides-ui`）提供界面、渲染接入或交互，不应加入纯 Node.js 内容处理配置。
- `@univerjs/sheets-find-replace`、`@univerjs/sheets-crosshair-highlight` 虽然没有 `-ui` 后缀，也依赖 `@univerjs/sheets-ui`，不能据包名把它们视作 Headless 插件。
- `@univerjs/preset-sheets-core`、`@univerjs/preset-docs-core` 的默认预设会注册 UI 插件，不是 Node.js Headless 预设。此场景使用插件模式明确选择内容层依赖。

**`@univerjs/engine-render` 需要单独看待。** 当前 Node.js 示例会注册它，以提供共享的渲染管理等依赖；注册插件并不等于创建 Canvas 或挂载编辑器。它可以出现在 Headless 插件组合中，但实际绘制、字体测量、截图等 API 仍需要相应的渲染环境，不能据此认为整个包的 API 都能在纯 Node.js 中使用。

**Facade 是操作入口，不是运行环境适配器。** 按需导入内容插件的 `/facade` 扩展，并注册实现该能力的插件。`@univerjs/ui/facade`、`@univerjs/sheets-ui/facade` 等 UI 扩展及其菜单、滚动、选择区可视交互 API 仍需要 UI。判断边界时要检查插件依赖和实际调用路径，而不只看包名或是否提供 Facade。

可运行的插件组合见 [Sheets Headless 入门](/guides/sheets/getting-started/node)和 [Docs Headless 入门](/guides/docs/getting-started/node)。

## 前端即时计算，服务端按版本计算 [#服务端预计算前端快速展示]

前端与服务端都具备公式引擎。前端响应用户编辑，服务端在生成快照或处理文件时，针对确定的内容版本计算。

- **编辑时**：前端在本地增量计算并即时展示结果，也可通过 Worker 执行；协同服务记录并同步内容修改。
- **生成快照时**：按服务端快照策略触发保存流程，取得本次内容版本，由 `univer-rs` 计算，再将该版本的内容与计算结果一起保存。
- **再次打开时**：前端复用快照中有效的计算结果，补齐之后的修改并继续计算，减少重复的全量计算。

<Mermaid chart={"flowchart LR\n    F[\"前端编辑<br/>即时计算\"]\n    C[\"内容同步<br/>已确认修改\"]\n    R[\"Rust 计算<br/>内容版本 N\"]\n    S[\"保存快照<br/>saveSnapshot\"]\n    F <--> C\n    C -->|\"生成快照时\"| R\n    R --> S"} />

**修改持续同步；服务端计算在生成快照时触发，结果与对应的内容版本一起保存。**

首次加载可根据已保存的结果选择计算策略：

- `WHEN_EMPTY`：复用已保存的公式值，只计算缺失结果。
- `NO_CALCULATION`：初始化时不计算，由应用提供计算结果。
- `FORCED`：当已有结果需要刷新时，重新计算全部公式。

这些选项控制首次加载。后续编辑由前端继续计算；服务端在生成相应版本快照或处理文件时按需计算。配置见[公式文档](/guides/sheets/features/core/formula)，同步机制见[协同总览](/server/collaboration/overview)，文件处理见[导入与导出](/overview/features/shared/file-conversion)。

## 数组公式的计算与展开

在已支持的函数与格式范围内，Rust 按 Excel 的数组公式与溢出规则完成计算和展开。返回数据包含锚点、展开范围及每个单元格的结果，支持动态数组，也支持旧式数组公式声明区域的计算。

例如，在空白的 `A1` 中写入 `=SEQUENCE(3,2)`，计算结果为：

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

公式保留在 `A1`，结果展开到 `A1:B3`。数组范围缩小时会清理旧的展开值；展开区域被占用时返回 `#SPILL!`。前端展示、Agent 读取和文件导出可以复用这份已计算的快照。

具体函数和范围规则见[公式支持](/guides/sheets/features/core/formula)与 [Excel 数组展开行为](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior)。

## 接入 Agent 的执行与验证流程

模型、对话与工具调度继续使用已有 Agent，AI SDK 为其提供 Office 内容操作入口：

1. 检查结构，读取任务涉及的内容。
2. 通过无头运行时执行 Facade 修改及所需计算。
3. 等待计算和提交确认，读回更新后的状态。
4. 验证值与结构；需要视觉验证时，再生成截图或检查布局。

[内容操作](/ai/content-operations)与[视觉检查](/ai/visual-inspection)可以组合使用。需要人类审阅时，可先在 [Worktree](/ai/worktree) 中修改，再比较和合并。[Univer CLI](/overview/examples/cli) 展示了如何将这些能力装配为 Agent 可用的应用。
