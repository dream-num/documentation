Headless Univer는 대화형 편집기 UI가 없는 Univer 콘텐츠 런타임입니다. 브라우저 편집기와 콘텐츠 모델, 명령, 계산, Facade API를 공유합니다. Node.js에서 콘텐츠를 처리하거나 브라우저에서 UI 없는 작업을 실행할 수 있으며, 사용 가능한 기능은 등록한 제품·기능 플러그인에 따라 결정됩니다.

여기서 설명하는 JavaScript/TypeScript 콘텐츠 런타임과 `univer-rs`는 별도 구현입니다. 후자는 서버 계산과 파일 변환을 담당하며, 같은 스냅샷을 사용하는 Headless 작업 흐름과 조합할 수 있습니다.

## Headless로 할 수 있는 작업 [#headless-capabilities]

- **콘텐츠와 구조 읽기·수정**: Univer 스냅샷을 생성하거나 불러와 Facade API로 셀, 문단, 페이지, 도형 객체, 레코드를 조작하고 갱신된 스냅샷을 저장합니다. 일괄 처리, 데이터 생성, 콘텐츠 검사, Agent 자동화에 활용합니다.
- **등록된 업무 로직 실행**: 수식, 정렬, 필터, 데이터 유효성 검사, 피벗 기능을 실행하고 이미지, 차트, 도형, 댓글 리소스를 수정합니다. 작업 범위는 제품·기능 플러그인과 의존성에 따라 달라집니다.
- **다른 서비스 연결**: Node.js 협업 클라이언트를 추가하면 협업 Unit 로드, 변경 제출, 동기화 확인이 가능합니다. Office 파일 입출력은 Server SDK 변환 모듈과 결합합니다.

Headless 자체는 메뉴, 도구 모음, 대화상자, 마우스·키보드 상호작용, 스크린샷, 인쇄를 제공하지 않습니다. 영구 저장, 인증, 협업 서버, 파일 변환도 자동으로 제공되지 않습니다. `save()`는 Univer 스냅샷을 반환하며 DB 저장이나 XLSX·DOCX·PDF 내보내기가 아닙니다. 스크린샷과 시각적 레이아웃 검사는 별도 [렌더링 런타임](/ai/visual-inspection)이 필요합니다. 헤드리스 브라우저도 렌더링 계층을 실행합니다.

## Headless에 속하는 패키지 [#headless-packages]

필요한 콘텐츠 패키지를 선택하고 해당 제품 플러그인과 의존성을 등록하세요. Pro 기능에는 필요한 라이선스도 설정해야 합니다.

### 콘텐츠 모델

인스턴스, 콘텐츠 모델, 명령, 기본 콘텐츠 작업.

- `@univerjs/core`
- `@univerjs/sheets`
- `@univerjs/docs`

### 수식과 숫자 형식

수식 실행, Sheet 수식 통합, 숫자 형식. 기능에 맞춰 오픈 소스 또는 Pro 엔진을 선택합니다.

- `@univerjs/engine-formula`
- `@univerjs/sheets-formula`
- `@univerjs/sheets-numfmt`
- `@univerjs-pro/engine-formula`

시트 데이터와 규칙 작업. 패널과 시각적 상호작용은 포함하지 않습니다. 데이터 유효성 검사에는 `@univerjs/data-validation`도 필요합니다.

- `@univerjs/sheets-filter`
- `@univerjs/sheets-sort`
- `@univerjs/sheets-conditional-formatting`
- `@univerjs/sheets-data-validation`
- `@univerjs/sheets-table`
- `@univerjs/sheets-hyper-link`
- `@univerjs/sheets-note`

### 이미지, 링크, 댓글

이미지, 링크, 댓글의 모델·리소스·명령. 표시, 업로드, 외부 데이터 소스는 별도로 연결합니다.

피벗, 차트, 도형, 스파크라인, 그룹, 슬라이서의 콘텐츠와 계산 로직. 그래픽 기능은 `@univerjs-pro/engine-chart`, `@univerjs-pro/engine-shape` 등을 의존성으로 사용합니다.

문서 블록, 표, 단, 수식, 도형의 콘텐츠 작업. 편집기 UI는 포함하지 않습니다.

### 다른 제품 모델

다른 제품의 모델과 명령. `pdfs-editor`는 PDF 편집기의 수명 주기와 협업 통합을 설정하므로 editor라는 이름만으로 UI 패키지라고 판단할 수 없습니다. API는 제품별로 다릅니다.

- `@univerjs-pro/slides`
- `@univerjs-pro/bases`
- `@univerjs-pro/boards`

### 네트워크, 계산 프로세스, 협업

필요에 따라 `@univerjs/network`, `@univerjs/rpc-node`로 네트워크와 Node.js 계산 프로세스를 연결하고 `@univerjs-pro/license`로 라이선스를 설정합니다. `@univerjs-pro/collaboration`, `@univerjs-pro/collaboration-client`, `@univerjs-pro/collaboration-client-node`는 Headless 협업 클라이언트를 구성하며 협업 서버 자체가 아닙니다. 로컬 스냅샷 처리에는 협업 서비스가 필요하지 않습니다.

### 콘텐츠 전용 런타임에 포함하지 않는 패키지

- `@univerjs/ui`, `@univerjs/design`, 제품·기능의 `*-ui` 패키지(예: `@univerjs/sheets-ui`, `@univerjs/docs-ui`, `@univerjs-pro/slides-ui`)는 UI, 렌더링 통합, 상호작용을 제공합니다. 순수 Node.js 콘텐츠 처리 구성에 추가하지 않습니다.
- `@univerjs/sheets-find-replace`, `@univerjs/sheets-crosshair-highlight`는 `-ui` 접미사가 없어도 `@univerjs/sheets-ui`에 의존합니다.
- 기본 `@univerjs/preset-sheets-core`, `@univerjs/preset-docs-core` 프리셋은 UI 플러그인을 등록합니다. Node.js Headless 프리셋이 아니므로 플러그인 모드로 콘텐츠 계층을 선택합니다.

**`@univerjs/engine-render`는 별도로 판단해야 합니다.** 현재 Node.js 예제도 공유 렌더 관리 등의 의존성을 위해 등록합니다. 등록 자체로 Canvas를 만들거나 편집기를 마운트하지는 않습니다. Headless 구성에 포함할 수 있지만 그리기, 글꼴 측정, 스크린샷 API는 해당 렌더링 환경이 필요합니다. 패키지의 모든 API가 순수 Node.js에서 동작한다는 뜻은 아닙니다.

**Facade는 작업 API이며 환경 어댑터가 아닙니다.** 콘텐츠 플러그인의 `/facade` 확장을 가져오고 실제 기능을 구현하는 플러그인도 등록합니다. `@univerjs/ui/facade`, `@univerjs/sheets-ui/facade`의 메뉴, 스크롤, 선택 영역 시각적 상호작용에는 여전히 UI가 필요합니다. 이름이나 Facade 제공 여부 대신 의존성과 실제 호출 경로를 확인하세요.

실행 가능한 구성은 [Sheets Headless 시작하기](/guides/sheets/getting-started/node)와 [Docs Headless 시작하기](/guides/docs/getting-started/node)를 참고하세요.

## 프런트엔드의 즉시 계산과 서버의 버전별 계산 [#서버에서-미리-계산하고-브라우저에서-빠르게-표시]

프런트엔드와 서버 모두 수식 엔진을 갖추고 있습니다. 프런트엔드는 편집에 즉시 응답하고 서버는 Snapshot 생성이나 파일 처리 시 확정된 콘텐츠 리비전을 계산합니다.

- **편집 시**: 브라우저가 영향을 받는 수식을 로컬에서 증분 계산하고 결과를 즉시 표시합니다. Worker에서 실행할 수도 있습니다. 협업 서비스는 콘텐츠 변경 사항을 기록하고 동기화합니다.
- **Snapshot 생성 시**: 서버의 스냅샷 정책에 따라 저장 과정을 시작하고 이번 작업의 콘텐츠 리비전을 확보합니다. `univer-rs`로 계산한 뒤 해당 리비전의 콘텐츠와 결과를 함께 저장합니다.
- **다시 열 때**: Snapshot에 있는 유효한 결과를 재사용하고 이후 변경 사항을 적용해 계산을 계속하므로 전체 계산의 반복을 줄입니다.

<Mermaid chart={"flowchart LR\n    F[\"프런트엔드 편집<br/>즉시 계산\"]\n    C[\"콘텐츠 동기화<br/>확인된 변경 사항\"]\n    R[\"Rust 계산<br/>콘텐츠 리비전 N\"]\n    S[\"Snapshot 저장<br/>saveSnapshot\"]\n    F <--> C\n    C -->|\"Snapshot 생성 시\"| R\n    R --> S"} />

**변경 사항은 계속 동기화합니다. 서버 계산은 Snapshot 생성 시 실행되며 결과는 해당 콘텐츠 리비전과 함께 저장됩니다.**

저장된 결과에 맞게 초기 계산 정책을 선택합니다.

- `WHEN_EMPTY`: 저장된 수식 값을 재사용하고 누락된 결과만 계산합니다.
- `NO_CALCULATION`: 초기 수식 계산을 건너뛰고 애플리케이션이 결과를 제공합니다.
- `FORCED`: 저장된 결과를 갱신해야 할 때 모든 수식을 다시 계산합니다.

이 옵션은 최초 로딩을 제어합니다. 이후 편집은 프런트엔드에서 계속 계산하고 서버는 버전별 Snapshot 생성이나 파일 처리 시 필요에 따라 계산합니다. [수식 설정](/guides/sheets/features/core/formula), [협업 개요](/server/collaboration/overview), [파일 변환](/overview/features/shared/file-conversion)을 참고하세요.

### 수식 엔진 성능

통합 문서 10개의 [Univer Rust 수식 엔진 성능 실측](/blog/rust-formula-performance)은 Rust 입력 로드, 구간별 시간, 입력 형식 범위와 샘플 다운로드를 포함합니다.

## 배열 수식 계산과 확장

지원되는 함수와 형식 범위에서 Rust는 Excel의 배열 수식 및 스필 규칙을 따릅니다. 기준 셀, 확장 범위, 각 셀 결과를 반환하며 동적 배열과 기존 배열 수식의 지정 영역을 처리합니다.

예를 들어 빈 `A1`에 `=SEQUENCE(3,2)`를 입력하면 다음 결과가 나옵니다.

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

수식은 `A1`에 남고 결과는 `A1:B3`에 확장됩니다. 배열이 줄면 이전 확장값을 지우고, 확장 영역이 막히면 `#SPILL!`을 반환합니다. 브라우저, Agent, 파일 내보내기가 계산된 Snapshot을 재사용할 수 있습니다.

[수식 지원](/guides/sheets/features/core/formula)과 [Excel 배열 동작](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior)을 참고하세요.

## Agent 실행 및 검증 연결

기존 Agent의 모델, 대화, 도구 조정을 유지하고 AI SDK로 Office 작업을 제공합니다.

1. 구조와 작업 대상 콘텐츠를 읽습니다.
2. 헤드리스 런타임에서 Facade 변경과 계산을 실행합니다.
3. 계산 및 커밋 확인을 기다린 후 갱신된 상태를 읽습니다.
4. 값과 구조를 검증하고 필요하면 스크린샷과 레이아웃을 검사합니다.

[콘텐츠 작업](/ai/content-operations)과 [시각 검사](/ai/visual-inspection)를 결합할 수 있습니다. 사람의 검토가 필요하면 [Worktree](/ai/worktree)에 변경을 격리하고 비교 후 병합합니다. [Univer CLI](/overview/examples/cli)는 Agent용 앱으로 구성하는 예시입니다.
