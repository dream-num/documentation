История объединяет подтверждённые изменения совместного редактирования в доступные для просмотра версии. Можно увидеть авторов, время, действия и прошлое содержимое, а при наличии прав — восстановить версию. История доступна между сеансами и после перезагрузки страницы.

## Как работает история версий

- **Mutation**: Воспроизводимое изменение содержимого, например установка значения ячейки или вставка абзаца.
- **Changeset**: Единица отправки в совместном редактировании с упорядоченной группой mutations.

### 1. Запись изменений

**При отправке правок.** Изменения пользователя или Agent представляются как mutations, объединяются в changeset и отправляются сервису совместного редактирования для подтверждения и сохранения.

<Mermaid chart={"flowchart LR\n    A[\"Редактирование\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"Подтвердить и сохранить<br/>Записать revision\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

**Revision** обозначает позицию подтверждённой отправки в истории документа. History индексирует подтверждённые changesets и группирует их по времени и операции в шкалу версий.

### 2. Воссоздание прошлого содержимого

**При выборе прошлой версии.** Snapshot содержит полное состояние на определённой revision. Система загружает базовый snapshot и последующие changesets до целевой revision, затем по порядку воспроизводит mutations и показывает прошлое содержимое только для чтения.

<Mermaid chart={"flowchart LR\n    A[\"Выбрать версию<br/>revision N\"]\n    B[\"Загрузить snapshot<br/>и последующие changesets\"]\n    C[\"Воспроизвести mutations<br/>по порядку\"]\n    D[\"Прошлое содержимое<br/>Только чтение\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

Пример: **snapshot на revision 10 + changesets для ревизий 11–15 = содержимое на revision 15.**

### 3. Восстановление текущего документа

**При выборе «Восстановить эту версию».**

> Выбрать версию → Отправить mutation восстановления → Подтверждение → Обновить текущий документ с новой revision

Восстановление создаёт новую запись истории; предыдущие версии сохраняются.

## Просмотр версий и изменений

1. Откройте историю в редакторе и выберите версию.
2. Разверните группу, чтобы увидеть отдельные revision и проверить содержимое и различия в режиме только для чтения.
3. Выберите Восстановить эту версию. Общий документ обновится через механизм совместного редактирования, и другие участники получат изменение.

Группа может объединять изменения за определённый период. Запись истории не обязательно соответствует одному нажатию клавиши или созданию Snapshot.

### Цвета изменений

| Метка | Значение |
| --- | --- |
| 🟦 **Синий: изменение** | Изменение существующего содержимого, формата или свойства объекта. |
| 🟩 **Зелёный: добавление** | Новая строка, абзац, запись или объект доски. |
| 🟥 **Красный: удаление** | Удалённое содержимое сохраняет отметку в представлении истории. |

Цвет обозначает тип изменения. Замена текста может показывать добавление и удаление одновременно. Область выделения определяется просмотрщиком продукта.

## Интеграция с приложением

- **Сервер**: добавьте History Service, Endpoint и постоянный Database Adapter к Core Collaboration. События создания Unit и подтверждения changeset формируют индекс истории и запросы версий и изменений.
- **Браузер**: зарегистрируйте общую функцию истории и плагины History / History UI продукта, подключите API. Просмотрщик загружает выбранную revision и различия. Для собственного содержимого нужны соответствующие плагины просмотрщика.
- **Права**: приложение предоставляет идентификацию и авторизацию, сервер проверяет доступ к истории и восстановлению. Старые версии могут содержать данные, уже удалённые из текущего документа.

См. [расширения совместной работы](/server/collaboration/extensions) и [пример History](/server/collaboration/examples#history), затем подключите интерфейс по руководству продукта.

Индекс истории — производные данные, которые можно восстановить. Подтверждённые changesets остаются основным источником. Приложение определяет хранение и сроки сохранения; панель не заменяет резервные копии.

## Связь с другими функциями

- **Отмена / повтор**: отменяет или повторяет операции редактирования без сервиса истории.
- **История версий**: отслеживает подтверждённые версии между сеансами и восстанавливает общее содержимое.
- [Сравнение содержимого](/overview/features/shared/compare): сравнивает два состояния только для чтения и не восстанавливает данные.
- [Worktree](/overview/features/shared/worktree): изолирует черновые изменения для проверки перед объединением.

Изменения Agent через Facade API могут попасть в ту же историю после подтверждения совместной работой. Сравнение содержимого помогает автоматизировать проверку.
