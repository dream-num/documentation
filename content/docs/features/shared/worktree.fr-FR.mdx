Worktree fournit des ébauches isolées de contenu Office que les personnes et les agents peuvent encore éditer ensemble. Un agent peut réviser un budget, réorganiser les données ou réécrire un bref pendant que les gens continuent à éditer le document principal, qui est appelé le tronc. Le projet est validé et examiné avant que ses modifications atteignent le tronc.

L'isolement s'applique au contenu du document et à ses modifications, pas à un répertoire de travail Git. Une seule tâche peut s'étendre sur plusieurs [Unités](/guides/sheets/getting-started/quickstart#unit), par exemple un cahier de travail, un document et une présentation.

## Isolation : évoluer depuis une référence commune [#isolation]

Lorsqu'un Worktree est créé pour une unité existante, le service enregistre la révision actuelle du tronc de l'unité comme **de référence**. Le brouillon commence par cette révision et a ses propres instantanés, modifications, révisions, Présence et salles de collaboration. Les modifications faites dans le brouillon n'affectent pas le tronc.

| Notion | Rôle |
| --- | --- |
| Baseline | La version du tronc à partir de laquelle le projet a commencé, utilisé pour la comparaison et la fusion. |
| Draft head | Le projet de révision le plus récent a été confirmé, et les projets de communications ont progressé. |
| Ready head | Le projet de révision gelé qui définit ce qui est examiné et fusionné. |

Les révisions de chaque côté forment une séquence de soumission séparée, de sorte qu'un nombre plus élevé n'indique pas quel contenu est plus récent. Tirer une ébauche synchronise les propres modifications du brouillon. Les nouvelles éditions de tronc ne saisissent pas la version en cours d'examen par elles-mêmes ; l'aperçu de fusion et la fusion elle-même réconcilient les deux.

## Comment AI SDK rejoint le même brouillon [#ai-sdk]

AI SDK Collaboration Runtime gère les instantanés, les modifications et les révisions d'une unité. Du côté Server SDK, le service Worktree possède la création, le cycle de vie et la fusion.

L'application résout `worktreeID + unitID` dans l'instantané de l'ébauche, soumet, WebSocket et les URL de ticket de session, puis les passe à l'exécution. Les mêmes outils d'inspection et d'édition peuvent alors cibler soit le tronc, soit un brouillon.

<Mermaid chart={"flowchart LR\n    A[\"Agent / CLI métier\"]\n    B[\"Relecture humaine Web\"]\n    C[\"Adaptateur de cible\"]\n    D[\"Worktree Endpoint\"]\n    E[\"Même Unit brouillon\"]\n    A --> C\n    B --> C\n    C --> D --> E"} />

Un ID d'unité peut exister dans le coffre et dans plusieurs Worktrees à la fois. La cible doit inclure le Worktree dans lequel elle vit, et l'inspection, l'exécution, les captures d'écran et l'aperçu Web devraient tous utiliser cette même cible. Sinon, un outil peut lire à partir d'un brouillon et écrire dans le coffre. Le client Web charge le même brouillon avec la configuration de collaboration qui le correspond.

| Élément | Responsabilité |
| --- | --- |
| Web SDK | Le moteur de contenu partagé, pour les opérations d'agents Headless et pour l'édition dans le navigateur. |
| Server SDK | Isolation, stockage des changements et révisions, états et OT. |
| AI SDK | Les contrôles d'exécution, d'inspection, de recherche API, d'exécution Facade et visuels. |
| Votre application | Sélection de modèles, cartographie des cibles, identité, autorisation, tâches et l'interface utilisateur d'examen. |

## De l’édition à la remise [#agent-workflow]

L'application peut exécuter des tâches en parallèle en donnant à chaque agent son propre Worktree. Chaque agent modifie son brouillon, vérifie le résultat et le marque Prêt. Une personne passe ensuite en revue les brouillons un à la fois, rouvre le brouillon qui nécessite plus de travail, et fusionne les brouillards acceptés dans le coffre actuel.

<Mermaid chart={"flowchart TB\n    TRUNK[\"Document principal · Trunk\"]\n    subgraph PARALLEL[\"Agents en parallèle\"]\n        direction LR\n        AGENT_A[\"Agent A<br/>Worktree A<br/>Modifier et vérifier\"]\n        AGENT_B[\"Agent B<br/>Worktree B<br/>Modifier et vérifier\"]\n        AGENT_C[\"Agent C<br/>Worktree C<br/>Modifier et vérifier\"]\n    end\n    REVIEW[\"Relecture humaine<br/>Brouillon et aperçu\"]\n    MERGE[\"Merge individuel<br/>Dans le trunk actuel\"]\n    RESULT[\"Nouvelle révision trunk\"]\n    TRUNK --> AGENT_A\n    AGENT_A -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_B\n    AGENT_B -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_C\n    AGENT_C -->|\"Ready\"| REVIEW\n    REVIEW -->|\"Approuver\"| MERGE\n    REVIEW -.->|\"Reopen du brouillon concerné\"| PARALLEL\n    MERGE --> RESULT"} />

1. Créez le Worktree et chargez-le. Sélectionnez les unités que couvre la tâche, connectez la cible Worktree, et tirez son dernier contenu.
2. Inspectez la structure avec Inspection, recherchez les API au besoin et apportez des changements à travers Facades.
3. Soumettre à l'ébauche, lire les données et les résultats de calcul, et capturer des captures d'écran lorsque nécessaire. Les diapositives peuvent également exécuter Layout Lint. Si la vérification signale un problème, modifiez l'ébauche à nouveau.
4. Mark Ready. Cela bloque la révision préliminaire de chaque unité, et l'édition cesse jusqu'à ce que l'examen soit terminé.
5. Révision. Fusionner les ébauches acceptées. Réouvrir une ébauche avant qu'une personne ou un agent ne réédite les ébauches qui ne sont pas nécessaires.

| Opération | Effet |
| --- | --- |
| `runtime.commit()` | Il ne soumet que le projet de révision et le fait avancer. |
| `markReady()` | Gele la version de l'examen sans fusionner quoi que ce soit dans le coffre. |
| `reopenWorktree()` | Prend un brouillon de Ready back to Draft, de sorte que l'édition peut continuer. |
| `mergeWorktree()` | Fusionne les modifications de l'ébauche gelée dans le coffre, Unité par Unité. |

Commit, Ready et Merge sont trois opérations distinctes. Une fois qu'un brouillon est prêt, ni une personne ni un agent ne peuvent le modifier jusqu'à ce qu'il ait été rouvert. Pour la relation entre l'exécution et la CLI, voir le [flux de travail de AI SDK](/ai/worktree).

## Appliquer les changements au trunk actuel [#merge]

Pour une Unité qui vient du tronc, le service lit les changements de projet du **de base à la tête prête**, recueille leurs mutations et les soumet par le biais du service de collaboration du tronc. Si le tronc a progressé depuis la base de référence, [OT](/overview/features/shared/collaboration) transforme ces mutations contre les modifications du tronc ultérieures avant que le service ne confirme une nouvelle révision.

La fusion applique donc des modifications; elle ne remplace pas le dernier document par un ancien snapshot. Les modifications simultanées qui peuvent être transformées sont rapprochées. Les modifications qui ne peuvent pas être transformées, ou qui ne s'appliquent plus, sont renvoyées en tant que conflits pour que l'application puisse les gérer. OT ne règle pas tous les désaccords commerciaux.

Une unité créée à l'intérieur d'un Worktree n'a pas de base de base du tronc contre lequel fusionner.

## Relire les changements et leur intégration [#review]

- Pour voir ce qui a changé, comparez l'état de base complet avec l'état d'ébauche Ready en utilisant [Comparer](/overview/features/shared/compare).
- Pour voir ce que la fusion ferait à un moment donné, appelez `evaluateUnitMerge()` après Ready. Lorsque le tronc a avancé, un Runtime isolé applique un candidat transformé en OT au tronc actuel et produit un aperçu en lecture seule. Il ne soumet aucun changementet et ne modifie ni le tronc ni le brouillon.

Un aperçu décrit l'état au moment où il est demandé. Le tronc peut changer après, et le Merge fonctionne à partir de l'état qu'il trouve lorsqu'il fonctionne. Fusionner plusieurs Unités n'est pas non plus une transaction atomique, donc si une Unité échoue, les Unités qui ont déjà fusionné restent fusionnées. Affichez le résultat pour chaque Unité et manipulez les défaillances individuellement.

## Intégration et périmètre [#integration]

Combinez les adaptateurs Worktree Client, Service, Endpoint et base de données avec le noyau de collaboration. Conservez le stockage de l'ébauche séparément et partagez une session Ticket Store avec le coffre. La demande autorise l'accès d'ébauche et l'écriture de l'ensemble séparément; l'isolement n'accorde pas l'accès par lui-même.

Feuille, Doc, Diapositive, Toiles et Table Relationnelle sont pris en charge. PDF n'est pas inclus. Les [exemple](/server/collaboration/examples#worktree), les [modules d'extension](/server/collaboration/packages#worktree) et les [guide d'intégration de l'agent](/ai/worktree) fournissent des points de départ.
