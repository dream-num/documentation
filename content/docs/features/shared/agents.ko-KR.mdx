AI SDK는 Univer의 콘텐츠 모델, Facades 및 작곡 가능한 TypeScript 기능으로 협업을 노출합니다. 기존 에이전트는 콘텐츠를 읽고 수정하여 결과를 확인하고 검토를 위해 손을 확인합니다. 이 응용 프로그램은 모델, 도구 프로토콜 및 관현의 방법을 선택합니다.

## 기존 Agent에 기능 연결 [#capabilities]

애플리케이션이 자체 도구, 서비스 또는 CLI로 전달할 수 있는 기능 패키지 반환 구조화 결과. 옵션 `-command` 패키지는 기본 Commander 명령과 동일한 기능을 노출합니다. 두 형태는 웹 편집기와 공유된 콘텐츠 모델 및 명령 시스템에 작동 합니다.

| 기능 | 역할 |
| --- | --- |
| Inspection | 구조, 범위, 단락 및 개체 세부 정보를 좁히십시오. |
| API Reference | 번들 된 Facade 선언, 과부하, 유형 및 예를 오프라인으로 쿼리하십시오. |
| Content Execution | Binds `workbook`, `doc`, `presentation`, `base`, 또는 특정한 단위에 `board`는 실행을 위한 부호를 준비합니다. |
| Collaboration Runtime | 콘텐츠로드, mutations, reconciles 원격 변경을 캡처하고, 변경 설정을 명시적으로. |

## Runtime의 편집 상태 복원 [#runtime]

Collaboration Runtime는 전체 수명을 위한 단일 단위에 경계를 둡니다. 적재 도중 그것은 신청에 의해 제공된 백엔드를 열고, UnitData 또는 스냅 샷 체크포인트를 읽고, 그 체크포인트의 상단에 변경 집합을 재생합니다. 그런 다음 원격 머리에 지속적인 개정 간격을 닫고, 공식 단위가 설치될 때, 최신 계산 결과를 기다리십시오.

`fetch()`는 변화하고 그(것)들을 검증합니다. `pull()` reconciles는 국부적으로 구부리고 OT를 통해 국가를 기다리고, 그 후에 결과를 적용합니다. 실행 시간은 `baseRevision`, `knownHeadRevision`, `pendingMutationCount` 및 `awaitingChangeset`를 노출합니다 그래서 신청이 진전을 평가할 수 있다는 것을.

## 대상 확인 후 Facade 실행 [#inspection]

개요와 함께 모델을 제공 먼저, 다음 완벽한 스냅 샷을 전송 대신 안정적인 ID 또는 정확한 선택기를 쿼리합니다. 검사는 시트 범위, Doc 단락, 슬라이드 페이지, 관계 테이블 스키마 개요 및 캔버스 개체를 포함합니다. 관계 테이블 개요에는 필드 구성이 포함되어 있지만 값이나보기 투사가 포함되지 않습니다. 필요한 경우 Facades를 통해 사람들을 읽으십시오.

`prepareContentExecutionProgram()`는 현재 브라우저 선택의 단위 ID, 독립적으로에서 루트 Facade를 해결하고 주사 된 바인딩의 redeclaration을 거부합니다. 읽기 모드에서는 실행하기 전에 지속될 수 있는 Runtime 블록 비즈니스 작업을 읽습니다. 쓰기 모드에서는 대상 단위의 mutations를 캡처합니다. 단위 생성 및 처리는 별도의 수명주기 운영이며이 단일 단위 실행 항목 밖에 거짓말됩니다.

API가 unfamiliar일 때, `find()`는 후보자와 `show()`가 관련 유형과 함께 정확한 선언을 인쇄합니다. 참고는 SDK로 배포되므로 콘텐츠 엔진이나 온라인 문서가 필요하지 않습니다. [콘텐츠 운영](/ai/content-operations)와 [패키지 개요](/ai/packages)를 참조하십시오.

## 실행과 제출 확인 구분 [#commit]

`execute({ mode: 'write' })`는 라이브 유닛을 조절하고 축산을 축적합니다. **서버가 변경 사항을 저장 한 것을 의미하지 않습니다.** `commit()`가 부착 된 정체성을 가진 변화를 만듭니다. ACK는 정체성, 페이로드 및 변경 수를 확인하기 전에 수정해야합니다.

| 제출 상태 | 앱의 처리 |
| --- | --- |
| `confirmed` / `nothing-to-commit` | 변경 사항이 확인되었거나 제출할 수 없습니다. |
| `pull-required` | 원격 개정은 고급. `pull()`를 호출하여 재구성, 다음 `commit()`로 전화하십시오. |
| `retry` / `unknown` | 같은 Runtime 및 retry `commit()`에서 대기 상태를 유지하십시오. 편집 프로그램을 다시 실행하지 마십시오. |
| `conflict` | 쓰기를 중단하고 복구 또는 재로드를 결정합니다. |

제출의 결과가 불확실한 경우, Runtime은 `sid + reqId`를 유지하므로, 백엔드는 편집을 duplicating 대신 동일한 변경 사항을 확인할 수 있습니다. 백엔드가이 idempotency 컨트랙트를 구현해야 합니다. 던지는 프로그램은 이미 배치에서 만들어졌고, 구출 상태를 검사하고 복구하는 방법을 결정합니다. `execute()`는 자동으로 다시 롤을 롤하는 거래가 아닙니다.

아래 예는 이미 로드된 시트 실행 시간을 허용하고 실행 결과와 커밋 결과 모두 반환합니다. 콜러는 위 상태를 처리하고 소유권 기간이 종료될 때 런타임을 닫습니다.

```ts
import { prepareContentExecutionProgram } from '@univer-cli/content-execution'
import type { UniverCollaborationRuntime } from '@univer-cli/univer-collaboration-runtime'

async function updateSales(runtime: UniverCollaborationRuntime) {
  const pulled = await runtime.pull()
  if (pulled.status === 'conflict') return pulled

  const code = prepareContentExecutionProgram({
    unitId: runtime.unitId,
    unitType: 'sheet',
    code: `
      const sheet = workbook.getSheetByName('Data');
      if (!sheet) throw new Error('Worksheet Data not found');
      sheet.getRange('A2:B2').setValues([
        [{ v: 'East', t: 1 }, { v: 128000, t: 2 }]
      ]);
      return sheet.getRange('A2:B2').getRawValues();
    `,
  })
  const execution = await runtime.execute({ mode: 'write', code })
  const commit = await runtime.commit()
  return { execution, commit }
}
```

## 빈번한 작업의 Runtime 재사용 [#reuse]

빠른 작업은 응용 프로그램에 의해 소유 한 키에서 독점적으로 노동자 런타임을 임대 할 수 있습니다. 콜드 생성은 키 당 단일 기쁨이며, 임대는 FIFO 주문에 할당되며, 다른 키는 다른 노동자를 사용할 수 있습니다. `release()`는 인스턴스를 반환합니다. TTL/LRU eviction는 유휴 자원, `invalidate()`가 더 이상 신뢰할 수없는 인스턴스를 은퇴합니다.

키는 백엔드, 단위 및 Worktree를 구분해야 합니다. 풀은 초기화 입력의 두 세트가 세균성 호환이 되는지 확인하지 않습니다. 데몬은 짧은 CLI 통화를 통해 풀을 보유할 수 있지만 재사용된 런타임은 동기화 및 커밋 확인을 요구합니다. 이 응용 프로그램은 주민 메모리 및 노동자 카운트에 대한 시작 비용을 균형 잡히기해야 합니다. [런타임 재사용 및 daemon](/ai/runtime-architecture) 를 참조하십시오.

## 자동화에서 사람의 검토로 [#handoff]

이 기능은 보고, 데이터 정리, 템플릿 작성, 또는 콘텐츠 생성을 위해 결합 될 수 있습니다. 흐름은 대상을 찾습니다. Facades를 통해 쓰기, 결과가 의존하고 다시 값, 텍스트 및 객체 속성을 읽는 모든 계산을 기다립니다. 작업이 필요할 때 [시각 검사](/overview/features/shared/visual-inspection)를 추가하십시오.

승인 워크플로를 위해, 에이전트는 [Worktree](/overview/features/shared/worktree)에서 작동합니다. 그것은 라운드에서 편집하고 검증하고, 한 사람이 준비 콘텐츠를 검토하고 병합 여부를 결정합니다. 트랙 실행 및 단위 당 결과를 커밋합니다. 여러 런타임이 함께 교차 문서 원자 트랜잭션을 형성하지 않기 때문에.

응용 프로그램은 정체성, 허가, 모델 통합 및 작업 수명주기를 소유하고 있습니다. 읽고 쓰기 제한은 비즈니스 운영의 경계를 시행하고, 프로세스 고립 및 파일 또는 네트워크 권한이 무신 JavaScript는 응용 프로그램의 책임에 남아 있습니다. [시작하기](/overview/get-started)와 [Univer CLI 예제](/overview/examples/cli)를 참조하십시오.

## Skills로 콘텐츠 생성 및 편집하기 [#skills]

Office 콘텐츠에 직접 기존 에이전트 작업을 하려면, 파일의 위치를 일치 응용 프로그램에서 시작:

- [CLI 스킬](/overview/examples/cli#skills): 생성, 편집, 그리고 로컬 오피스 파일을 검사, 다음 검토에 대한 Viewer를 엽니 다.
- [작업 공간 기술](/overview/examples/workspace#skills): 연결된 공간의 파일에 작업하고, 사무실 콘텐츠 및 웹 앱을 생성하고, 협업 및 검토를 위해 손 변경합니다.
