评论把讨论保留在内容旁边。审阅者可以就数值、段落或图形提出问题，作者在同一线程内回复，其他参与者补充上下文，讨论因此不必分散到外部聊天工具中。

## 从问题到结论 [#review-workflow]

1. **定位问题**：将评论挂载到单元格、选中文本、记录、元素或页面位置上，锚点会保留对相应内容的引用。
2. **在线程中讨论**：线程由一条根评论和若干回复组成，每条评论都包含作者、时间和正文。
3. **解决或重新打开**：修改完成后将线程标记为已解决；需要跟随时重新打开，此前的讨论仍完整保留。

评论面板支持按全部、未解决、已解决或与当前用户有关的讨论筛选。已解决并不表示删除，处理结论仍可供查阅。

### 电子表格（Sheet） [#sheets]

将讨论锚定到具体单元格，即可在预算数字旁确认预测、费用明细或审批结论。示例中包含多条讨论、连续的多条回复，以及一个已解决分组。单元格评论通过 `range.addCommentAsync()` 添加；图片、图表和形状上的评论需要对应的绘图评论集成。

### 文档（Doc） [#docs]

审阅合同条款、方案措辞或发布日期时，可以选中一段文本并添加评论。评论卡片会保留引用的文本，编辑周边文本时由评论装饰维持锚点。示例讨论的是发布日期、指标定义以及旧流程的替换。调用 `document.getTextRange(...).createCommentAsync()`。

### 演示文稿（Slide） [#slides]

评论可以针对单个元素，也可以放在幻灯片的任意位置。元素评论通过稳定 ID 关联文本框、图片、图表等对象；位置评论使用页面归一化坐标。示例讨论的是发布目标和版式。调用 `slide.createElementCommentAsync()` 和 `slide.createPositionCommentAsync()`。

### 关系型表格（Relational Table） [#bases]

评论引用记录 ID，因此讨论始终绑定到某条业务记录，而与它在视图中的行号无关。评论可用于任务交接、客户跟进和验收确认。示例的发布跟踪表展示了负责人相关的讨论、待审批事项，以及记录旁的评论标记。调用 `record.createCommentAsync()`。

![Relational Table 评论：发布跟踪记录、评论标记与交接讨论](/assets/features/comments/bases.png)

[查看产品接入与 API](/guides/bases/features/thread-comment)

### 画布（Canvases） [#boards]

评论可以附加到图形等元素上，也可以在画布的特定位置单独留一条。元素评论关联对象；位置评论保存画布坐标。示例中，客户研究、开发交接和发布风险等讨论都位于对应的内容旁。调用 `board.createElementCommentAsync()` 和 `board.createPositionCommentAsync()`。

### PDF：页面批注 [#pdfs]

PDF 目前提供页面批注：高亮、下划线、删除线、波浪线和墨迹。这些是可持久保存的 PDF 批注对象，不同于上文支持回复和解决的评论线程。示例高亮了发布日期，标出了验收指标，并划掉了一个旧的审批步骤。调用 `page.insertAnnotation()`。

## 接入方式 [#integration]

**前端**：注册对应产品的评论插件和 UI 插件，并导入通用评论与产品评论的 `/facade` 入口。产品方法负责建立锚点，`replyCommentAsync()`、`updateCommentAsync()`、`resolveCommentAsync()` 等通用 API 负责后续的讨论操作。重新打开线程时传入 `resolved: false`。PDF 使用独立的批注 API。

**共享讨论**：在核心协同之外接入 Comment Service、Comment Endpoint 和独立的数据库适配器，再配置前端的远程评论数据源。主文档保存随内容变化的锚点；Comment Service 保存评论正文、回复和解决状态，并将评论更新发布到文档房间。参见[评论扩展包](/server/collaboration/packages#thread-comment)和 [Comments 示例](/server/collaboration/examples#comments)。

评论权限可以与正文编辑权限分开配置。应用身份和服务端授权参见[权限与授权](/overview/features/shared/permissions)。
