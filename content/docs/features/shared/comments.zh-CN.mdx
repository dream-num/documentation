评论把讨论留在内容旁边。审阅者可以指出某个数值、段落或图形的问题，作者在同一线程中回复，其他参与者继续补充上下文；无需把讨论拆散到外部聊天中。

## 从问题到结论 [#review-workflow]

1. **定位内容**：对单元格、选中文本、记录、元素或页面位置发起评论，保留对应的内容引用。
2. **回复讨论**：一条根评论与后续回复组成线程，展示作者、时间与讨论正文。
3. **解决或重新打开**：完成修改后将线程标为已解决；仍需跟进时可以重新打开，保留原有讨论。

评论面板可按全部、未解决、已解决或与当前用户相关的讨论筛选。已解决不等于删除，仍可回看处理过程。

### 电子表格（Sheet） [#sheets]

将讨论定位到具体单元格，在预算数字旁确认预测口径、费用明细与审批结论。示例同时展示多条讨论、连续回复和已解决分组。单元格评论使用 `range.addCommentAsync()`；图片、图表和形状的对象评论需要相应的绘图评论插件。

### 文档（Doc） [#docs]

对选中的文本范围发起评论，适合合同条款、方案表述或发布日期的审阅。评论卡片保留引用片段，文本编辑通过评论装饰维护定位。示例讨论发布日期、指标定义和旧流程替换；入口为 `document.getTextRange(...).createCommentAsync()`。

### 演示文稿（Slide） [#slides]

可以评论单个页面元素，也可以在幻灯片的自由位置放置评论。元素评论通过稳定 ID 关联文本框、图片、图表等对象；自由位置使用页面内的归一化坐标。示例在发布目标与版式旁展开讨论；入口为 `slide.createElementCommentAsync()` 和 `slide.createPositionCommentAsync()`。

### 画布（Canvases） [#boards]

### PDF：页面批注 [#pdfs]

PDF 当前展示的是页面批注：高亮、下划线、删除线、波浪线和墨迹。它们是可保存的 PDF 批注对象，与前面可回复、可解决的评论线程不同。示例突出发布日期、标记验收指标，并划去旧审批流程；入口为 `page.insertAnnotation()`。

## 接入方式 [#integration]

**前端**：注册相应产品的评论功能与 UI 插件，调用 Facade 时导入通用评论和产品评论的 `/facade` 入口。各产品方法负责建立锚点，通用 `replyCommentAsync()`、`updateCommentAsync()`、`resolveCommentAsync()` 等方法负责后续讨论操作；`resolved: false` 用于重新打开线程。PDF 使用独立的批注 API。

**多人共享**：在核心协同之外接入 Comment Service、Comment Endpoint 与独立数据库适配器，并配置前端远程评论数据源。主文档保存随内容变化的锚点，Comment Service 保存正文、回复与解决状态，通过文档房间发布评论更新。参见[评论扩展包](/server/collaboration/packages#thread-comment)和 [Comments 示例](/server/collaboration/examples#comments)。

评论权限可独立于正文编辑权限配置。业务身份与服务端授权的接入方式见[权限与授权](/overview/features/shared/permissions)。
