Embed 블록은 다른 곳에서 하나의 Univer 제품을 배치합니다. 프로젝트 문서는 예산과 작업을 보유 할 수 있으며 슬라이드는 작업 스프레드 시트를 수행 할 수 있으며 캔버스는 노트와 함께 계획을 제시 할 수 있습니다. 임베디드 콘텐츠는 자체 데이터 모델과 기본 편집기를 유지하므로 블록이 집중하고 메뉴를 어린이 단위로 이동합니다.

## 원리: 호스트와 하위 Unit [#principle]

**호스트 단위**는 블록의 배치 및 크기를 저장하고, 어린이 단위에 대한 참조 및 기본보기. **아이 단위**은 실제 셀, 단락 또는 레코드를 저장합니다. 블록을로드하면 참조, 아이 단위를로드하고 호스트 내부 편집기를 마운트합니다. [제품정보](/guides/sheets/getting-started/quickstart#unit)가 워크북, 문서, 프리젠 테이션, 관계 테이블, 또는 캔버스가 될 수 있습니다.

관계와 내용은 별도로 지속됩니다. 내장 된 스프레드 시트의 세포를 편집하면 어린이 시트를 업데이트합니다. 블록 업데이트를 이동하거나 호스트에 저장 한 앵커를 다시 재구성합니다.

## 지원 위치 [#locations]

| 호스트 제품 | 삽입 위치 | 주요 용도 |
| --- | --- | --- |
| Sheet | 플로팅 객체 또는 작업 책 탭 | 계산 모델 외에 간단한, 또는 별도의 탭에 작업 데이터베이스. |
| Doc | 본문 블록 | 1개의 프로젝트 페이지에 Narrative, 예산 및 작업. |
| Slide | Floating object 또는 발표 페이지 | 결론에 따라 편집 가능한 소스 데이터. |
| Relational Table | 테이블 목록 항목 | Business Database 내부에 위치한 프로젝트 문서. |
| Canvases | 캔버스 부동 개체 | 단일 캔버스에 데이터, 제안 및 토론. |

## 다섯 가지 호스트 사례 [#examples]

아래 예제는 Facade API를 통해 생성되었으며 브라우저에서 캡처 된 것처럼 인터페이스는 영어로되어 있습니다. 각 케이스는 독립적 인 어린이 단위를 사용하고 모든 콘텐츠와 숫자는 샘플 데이터입니다.

### Sheet: 계산과 의사결정 문서 [#sheet-host]

제어 센터 총은 왼쪽에 지출하고 오른쪽에 완전한 Doc를 포함. 그것의 시작 추적기 탭은 관계 테이블을 엽니 다. 이 레이아웃 소송 가격, 운영, 금융 작업 책은 가정, 계산 및 한 곳에서 서면 결정을 유지해야합니다. 가장 가까운 동등은 [Excel의 문서 객체 삽입](https://support.microsoft.com/en-au/excel/insert-an-object-in-your-excel-spreadsheet)입니다.

![Doc과 연동 합계를 포함한 Sheet 호스트](/assets/features/embed/sheet.png)

### Doc: 예산과 작업이 있는 프로젝트 페이지 [#doc-host]

신체는 관계 테이블에 따라 예산 시트를 포함, 그래서 독자는 모델을 검사하고 상황에 작업 유지 할 수 있습니다. 배열은 [Notion의 인라인 데이터베이스](https://www.notion.com/help/guides/full-page-vs-inline-databases)와 유사, 예산은 여전히 시트 공식 엔진에 실행하고 작업은 관계 테이블 필드와 레이아웃을 유지.

![Doc 본문에 삽입된 예산 Sheet](/assets/features/embed/doc-sheet.png)

![같은 Doc에 삽입된 작업 Relational Table](/assets/features/embed/doc-base.png)

### Slide: 검토 화면의 원본 데이터 [#slide-host]

하나의 슬라이드는 예산 시트, 작업 관계 테이블 및 공식 중심 예산 미터를 운반합니다. 상호 작용은 [PowerPoint에 Excel 삽입](https://support.microsoft.com/en-gb/powerpoint/insert-and-update-excel-data-in-powerpoint)에 유사합니다. 검토자는 결론에서 시작하여 편집 가능한 데이터 모델로 돌아갈 수 있습니다. 그림 예산은 $ 62,100로 업데이트되었습니다.

![예산, 작업 및 수식 지표를 포함한 Slide](/assets/features/embed/slide.png)

### Relational Table: 데이터베이스 안의 설명 문서 [#base-host]

시작 간단한 Doc는 테이블 목록에 작업 테이블 옆에 앉아 있습니다. CRM, 프로젝트 추적기 또는 작업 데이터베이스에서 사람들이 구조 작업과 작성된 컨텍스트 사이에서 이동합니다. 이것은 테이블 목록 항목이며, 각 레코드에 대한 문서를 자동으로 생성하지 않습니다.

![Relational Table 테이블 목록에서 연 Doc](/assets/features/embed/base.png)

### Canvases: 함께 논의하는 데이터 캔버스 [#board-host]

캔버스는 예산 시트, 제안 된 Doc 및 공식 중심 지출 요약을 결합합니다. 이 소송 프로젝트 룸, 리뷰 및 연구 캔버스는 소스 데이터와 토론 중에 손으로 문맥을 필요로합니다.

![Sheet, Doc 및 수식 합계를 포함한 Canvases](/assets/features/embed/board.png)

## 수식 연동 방식 [#formulas]

이 웹 사이트는 애플 리케이션에 전념. 우리는 정품 앱과 게임을 제공 할 목적으로이 사이트를 만들었습니다. 4AppsApk 최고의 안드로이드 애플 리케이션을위한 무료 APK 파일 다운로드 서비스, 계략.

| 시나리오 및 수식 | 검증 결과 |
| --- | --- |
| Slide 예산 합계: `=SUM('[Leadership Budget]Budget'!C5:C8)` | `C7`을 17,100에서 18,000으로 변경하면 **61,200 → 62,100**으로 업데이트됩니다. |
| Sheet에서 Relational Table 비용 합계: `=SUM([Control Tasks]!Launch_tasks[Cost])` | Cost 하나를 4,000에서 4,500으로 변경하면 **18,000 → 18,500**으로 업데이트됩니다. |

공식 이름은 읽기 쉬운 정량제로 봉사하고, 통합은 또한 그(것)들의 뒤에 안정되어 있는 단위 ID를 persist해야 합니다. 호스트 소유한 외부 매핑과 함께 참조를 생성하는 `getFormula().buildReference()`를 사용하십시오. 관계 테이블에 있는 테이블을 위해, 전시 이름 또는 ID를 concatenating 대신 `table.getFormulaName()`를 사용하십시오. 공식 몬 모양 사용 `shape.setFormula({ formula, externalReferences })`; 계산 완료 후에 결과를 읽으십시오. [공식 Facade](/reference/facade/formula#buildreference), [모양 Facade](/reference/facade/shape#setformula) 및 [관계 표식](/guides/bases/features/core/formulas)를 보십시오.

## 생성 및 통합 [#integration]

호스트 제품, 아이 제품 및 같은 Univer 인스턴스에서 UI를 등록하면 Embed 및 Embed UI를 추가합니다. 아래 예제는 Doc body로 기존 시트를 삽입합니다. `hostDocument` 및 `budgetWorkbook`는 해당 Facades입니다.

```ts
import '@univerjs-pro/embed/facade'

const block = univerAPI.createEmbed({
  host: {
    unitId: hostDocument.getId(),
    surface: univerAPI.Enum.FEmbedHostSurface.DocBlock,
  },
  content: {
    unitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
    ref: `#unit=${encodeURIComponent(budgetWorkbook.getId())}&type=sheet`,
  },
})

const embeddedWorkbook = await block.loadAsync()
```

`createEmbed()`는 관계와 주인 닻을 창조합니다. `loadAsync()`는 아이 단위를 적재하고 그것의 정면을 돌려보냅니다. `displayTarget`는 처음 워크시트, 활주 페이지, 또는 관계되는 테이블 보기를 선정합니다. [관련기관](/guides/fundamentals/features/embed)는 플러그인, 작풍, 국부적으로 및 장전기를 포함합니다. [에덴 Facade](/reference/facade/embed)는 다른 표면 및 방법을 포함합니다.

## 저장, 공동 작업 및 지원 범위 [#scope]

- 호스트 Snapshot는 참조, 배치 및 표시 설정을 유지하지만 최신 어린이 콘텐츠를 자동으로 포장하지 않습니다. 블록 제거는 어린이 문서를 삭제하지 않습니다.
- Server SDK는 어린이 스냅 샷과 함께 협업 서비스를 제공합니다. `@univerjs-pro/collaboration-embed`로, 브라우저는 아이를로드하고 협업 세션에 가입합니다. 부모와 자녀는 별도의 변경 및 버전을 유지합니다.
- 이 응용 프로그램은 참조,로드 데이터를 해결하고 액세스 권한을 부여합니다. 호스트를 열 수 없기 때문에 자녀의 보조금 편집 권한이 없습니다.
- 시트, 도크, 슬라이드, 관계 테이블 및 캔버스 유형은 서로 내장 될 수 있습니다. PDF, 동일한 유형 embedding, 그리고 더 깊은 배열은 제외됩니다. 하나의 Univer 런타임 내에서 어린이 단위는 하나의 활성 embed에 속할 수 있습니다.

[2 방법 바인딩](/overview/features/shared/binding)를 사용하여 애플리케이션 자체 입력, 미터 및 스프레드 시트에서 차트를 구동하십시오. 아이 제품의 편집기가 필요할 때 Embed Block을 사용하십시오.
