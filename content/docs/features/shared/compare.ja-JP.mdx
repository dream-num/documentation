2つのバージョン間で変更されたレポートを比較します。 2つの完全に再構成されたユニットスナップショットを受け入れ、セル、段落、ページ、またはレコードのセマンティックの違いを返します。 Worktreeの履歴レビュー、エージェントの出力の確認、および検査をサポートしています。

## 製品別の比較対象

| 製品 | 対象例 |
| --- | --- |
| Sheet | ワークシート、セル値と数式、行列、スタイル、登録済みグラフなど。 |
| Doc | 段落、文字、スタイル、表、ブロック、描画。 |
| Slide | ページ、要素、位置、スタイル、レイアウト、テーマ。 |
| Relational Table | テーブル、フィールド、レコード、ビュー。 |
| Canvases | ページ、要素、関連リソース。 |

変更は追加、削除、または更新です。ズームレベルや選択などの一時的なUI状態はコンテンツ変更ではありません。比較カバーは製品アダプタに依存し、PDFは含まれていません。

## Snapshot と changeset による比較の仕組み

スナップショットは、特定のリビジョンで完全なコンテンツの状態を保存します。 突然変異は、単一のコンテンツの変更と、注文されたコミットに変化するグループの変更について説明します。 歴史はバージョンを保存し、要求に応じて再構築します。 比較では、既に再構築されている2つのバージョンの違いについて説明します。

履歴エントリまたは Worktree を比較するには、ベーススナップショットをロードし、コンテンツがターゲットリビジョンに到達するまで、その後のチェンジセットを適用します。この再構築を実行し、製品アダプタに完全な状態を渡す。対応する変更が利用可能な場合、インサートまたは削除された行や列などの構造的な変更を詳細に比較します。2つの完全な状態のみが提供されると、比較はスナップショット比較を生成します。

結果は、各製品のコンテンツモデルに従います。 シート、ドキュメント用の段落、スライドとキャンバスの要素、およびフィールドとリレーショナルテーブルのレコード。 一時的な選択またはズームレベルは、コンテンツ変更ではありません。 比較は読み取り専用です。 バージョンを復元し、Worktreeをマージすることは、別の操作です。

## Server SDK・AI SDK との連携

**Server SDK**は、スナップショット、チェンジセット、およびリビジョン番号を供給し、コンテンツを比較するために再構築します。アプリケーションは、比較するべき状態と歴史の両方を通過し、構造の差を受け取り、Web上でレビューインターフェイスを提示します。 [歴史・歴史](/overview/features/shared/history)と[コラボレーションサービス拡張](/server/collaboration/extensions)を参照してください。

**AI SDK**は、Worktreeでコンテンツを読み込み、編集し、Agentの結果をコミットします。アプリケーションは、エージェントのチェックと処理の構造化された違いを使用することができます。一方、人は同じ変更を視覚的に見直し、それらを結合するかどうかを決定します。 [エージェント Worktree ワークフロー](/ai/worktree)と[コンテンツの操作](/ai/content-operations)を参照してください。

## 五つの製品の比較例

5つの例では、同じNorthstarの起動計画を使用します。私たちは、完全なベースラインを作成して提出し、Worktreeでそれを編集し、その後、変更を調べるために開いた。

変更リストでは、**ブルーブルー**マーク変更、**グリーングリーン**追加、**レッド**削除。 読み取り専用パンは変更前後のコンテンツを表示します。 画像をクリックして拡大します。

### Sheet：予算と行構造

研究とエディタの予測を更新し、レガシーツーリングを削除し、アクセシビリティQAを追加し、合計を再計算します。 変更された値と式の結果は、彼らが属する行構造と一緒に表示されます。

![Sheet：予算と行構造](/assets/features/compare/sheets.jpg)

### Doc：公開計画と段落

起動日、パイロットチームカウント、完了目標を変更し、レガシー承認テキストを削除し、品質ゲートを追加しました。保存されたコンテキストは、段落レベルのレビューを容易にします。

![Doc：公開計画と段落](/assets/features/compare/docs.jpg)

### Slide：指標とページ要素

従来の承認ブロックを削除し、品質ゲートを追加した3つのメトリックカードを更新しました。比較は、ページを新しいイメージとして扱うのではなく、同じページ上のテキストと要素をカバーします。

![Slide：指標とページ要素](/assets/features/compare/slides.jpg)

### Relational Table：フィールドとタスク [#baseフィールドとタスク]

進捗状況、ステータス、日付を更新し、日付フィールドの名前を変更し、レガシー承認レコードを削除し、アクセシビリティタスクを追加しました。 違いは、テーブル、フィールド、レコードによって検査できます。

![Relational Table：フィールドとタスク](/assets/features/compare/bases.jpg)

### Canvases：フローとキャンバス要素 [#boardフローとキャンバス要素]

パイロットサイズと起動日を更新し、レビューノードを移動し、レガシー承認カードを品質ゲートに置き換えます。コンテンツとレイアウトの変更は、キャンバスのコンテキストに表示されます。

![Canvases：フローとキャンバス要素](/assets/features/compare/boards.jpg)

## 結果を取得する

製品の履歴比較プラグインとファサード拡張子を登録し、`compareUnitData()`を呼び出します。繰り返しフィルタリングとペジネーションのために、`prepareUnitComparison()`でセッションを作成し、`query()`を呼び出す。

要約を最初に表示し、ワークシート、ページ、またはテーブルにドリルします。 必要に応じて変更リストまたはフル前後の値をリクエストします。 デフォルト詳細結果がバインドされるので、最初のページは必ずしも完全な差分ではありません。 結果を示す前に診断とカバレッジの状態を確認してください。

[API](/reference/facade/unit-comparison)、[履歴](/overview/features/shared/history)、[Worktree](/overview/features/shared/worktree)を参照してください。
