AI SDK expose les modèles de contenu de Univer, Facades, et la collaboration comme des capacités composables TypeScript. Un Agent existant peut lire le contenu, le modifier, vérifier le résultat et le remettre pour examen. L'application choisit le modèle, le protocole d'outil et la méthode d'orchestration.

## Connecter les capacités à l’Agent [#capabilities]

Les paquets de capacités renvoient des résultats structurés que l'application peut transmettre à ses propres outils, services ou CLI. Les paquets optionnels `-command` exposent les mêmes capacités que les commandes natives Commander. Les deux formulaires fonctionnent sur le modèle de contenu et le système de commande partagés avec l'éditeur Web.

| Capacité | Responsabilité |
| --- | --- |
| Inspection | Lire la structure, les plages, les paragraphes et les détails de l'objet pour restreindre la tâche. |
| API Reference | Interroge les déclarations groupées Facade, les surcharges, les types et les exemples hors ligne. |
| Content Execution | Reliures `workbook`, `doc`, `presentation`, `base` ou `board` à une unité spécifique et prépare le code à exécuter. |
| Collaboration Runtime | Charge le contenu, capture les mutations, réconcilie les modifications à distance et commit des changements explicitement. |

## Restaurer un état modifiable [#runtime]

Un Collaboration Runtime reste lié à une unité unique pendant toute sa durée de vie. Pendant le chargement, il ouvre le moteur fourni par l'application, lit un point de contrôle UnitData ou Snapshot, et rejoue les changements au-dessus de ce point de contrôle. Il ferme ensuite l'écart de révision continue à la tête distante et, lorsque le module formule est installé, attend les derniers résultats de calcul.

`fetch()` récupère les modifications et les valide. `pull()` concilie les modifications à distance avec l'état local en attente et en attente par l'intermédiaire de l'OT, puis applique le résultat. Le Runtime expose `baseRevision`, `knownHeadRevision`, `pendingMutationCount` et `awaitingChangeset` afin que l'application puisse évaluer les progrès.

## Localiser avant d’exécuter une Facade [#inspection]

Fournir au modèle un aperçu d'abord, puis demander un ID stable ou un sélecteur précis au lieu d'envoyer un Snapshot complet. L'inspection couvre les plages de feuilles, les paragraphes de Doc, les pages de diapositives, les aperçus de schéma de table relationnelle et les objets Canvas.

`prepareContentExecutionProgram()` résout la racine Facade de l'United ID, indépendamment de la sélection courante du navigateur, et rejette une nouvelle déclaration d'une liaison injectée. En mode lecture, l'opération Runtime bloque les actions commerciales qui persisteraient avant qu'elles ne s'exécutent; en mode écriture, elle capture les mutations de l'Unité cible. La création et l'élimination de l'unité sont des opérations distinctes du cycle de vie et se situent en dehors de cette entrée d'exécution unique.

Lorsqu'une API n'est pas connue, `find()` liste les candidats et `show()` imprime la déclaration exacte avec les types connexes. La référence est distribuée avec le SDK, donc elle ne nécessite ni un moteur de contenu ni la documentation en ligne. Voir [Opérations de contenu](/ai/content-operations) et [vue d'ensemble du paquet](/ai/packages).

## Exécution et persistance confirmée [#commit]

`execute({ mode: 'write' })` modifie l'unité en direct et accumule les mutations en attente. **Cela ne signifie pas que le serveur a enregistré les modifications.** `commit()` crée un jeu de changements avec une identité attachée; l'ACK doit correspondre à cette identité, à la charge utile et à la révision avant que le changement ne compte comme confirmé.

| État | Action de l’application |
| --- | --- |
| `confirmed` / `nothing-to-commit` | Les changements sont confirmés, ou il n'y avait rien à soumettre. |
| `pull-required` | La révision distante a avancé. Appelez `pull()` pour se rapprocher, puis appelez `commit()` à nouveau. |
| `retry` / `unknown` | Gardez l'état d'attente dans le même temps d'exécution et réessayez `commit()`. Ne recourez pas le programme d'édition. |
| `conflict` | Arrêter les écritures et décider récupération ou rechargement. |

Lorsque le résultat d'une soumission est incertain, l'exécution conserve `sid + reqId`, de sorte que le moteur peut confirmer les mêmes changementset idempotently au lieu de dupliquer les modifications. Le moteur doit implémenter ce contrat d'idempotency. Un programme qui lance peut laisser les mutations qu'il a déjà faites en place, donc inspecter l'état en attente et décider comment récupérer. `execute()` n'est pas une transaction qui retourne automatiquement.

L'exemple ci-dessous accepte une feuille d'exécution déjà chargée et renvoie à la fois le résultat d'exécution et le résultat de commit. L'appelant gère les statuts ci-dessus et ferme l'exécution lorsque sa période de propriété prend fin.

```ts
import { prepareContentExecutionProgram } from '@univer-cli/content-execution'
import type { UniverCollaborationRuntime } from '@univer-cli/univer-collaboration-runtime'

async function updateSales(runtime: UniverCollaborationRuntime) {
  const pulled = await runtime.pull()
  if (pulled.status === 'conflict') return pulled

  const code = prepareContentExecutionProgram({
    unitId: runtime.unitId,
    unitType: 'sheet',
    code: `
      const sheet = workbook.getSheetByName('Data');
      if (!sheet) throw new Error('Worksheet Data not found');
      sheet.getRange('A2:B2').setValues([
        [{ v: 'East', t: 1 }, { v: 128000, t: 2 }]
      ]);
      return sheet.getRange('A2:B2').getRawValues();
    `,
  })
  const execution = await runtime.execute({ mode: 'write', code })
  const commit = await runtime.commit()
  return { execution, commit }
}
```

## Réutiliser les Runtimes [#reuse]

Les tâches fréquentes peuvent louer un Worker Runtime exclusivement sous une clé appartenant à l'application. La création froide est un vol par clé, les baux sont en file d'attente dans l'ordre FIFO, et différentes clés peuvent utiliser différents Workers. `release()` retourne l'instance, l'expulsion TTL/LRU récupère les ressources inoccupées, et `invalidate()` prend sa retraite d'une instance qui n'est plus digne de confiance.

Une clé doit distinguer le moteur, l'unité et le Worktree. Le pool ne vérifie pas si deux ensembles d'entrées d'initialisation sont compatibles sémantiquement. Un démon peut tenir le pool sur de courts appels CLI, mais un Runtime réutilisé nécessite toujours une synchronisation et une confirmation de commit. L'application doit équilibrer le coût de démarrage par rapport à la mémoire résidente et au nombre de travailleurs; voir [Réutilisation et démon des temps d'exécution](/ai/runtime-architecture) .

## De l’automatisation à la revue humaine [#handoff]

Les capacités peuvent être combinées pour le reporting, le nettoyage des données, le remplissage des modèles ou la génération de contenu. Le flux localise la cible, écrit par Facades, attend tout calcul dont dépend le résultat et lit les valeurs, le texte et les propriétés de l'objet. [Contrôle visuel](/overview/features/shared/visual-inspection) lorsque la tâche l'exige.

Pour les flux de travail d'approbation, l'Agent travaille dans un [Worktree](/overview/features/shared/worktree). Il édifie et vérifie en ronds, puis une personne passe en revue le contenu Ready et décide s'il faut fusionner.

L'application possède l'identité, l'autorisation, l'intégration du modèle et le cycle de vie des tâches. JavaScript demeure la responsabilité de la demande. Voir [commencer](/overview/get-started) et les [Exemple de CLI Univer](/overview/examples/cli).
