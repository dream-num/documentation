內容比較（Compare）用於說明兩個版本之間發生了哪些變化。它接收兩份已完整還原的 Unit 快照，按單元格、段落、頁面或記錄返回語義差異。Compare 可用於審閱歷史版本、核查 Agent 的輸出，以及檢查 Worktree 中的改動。

## 各產品的差異

| 產品 | 比較物件範例 |
| --- | --- |
| Sheet | 工作表、單元格值和公式、行、列、樣式，以及圖表等已註冊資源。 |
| Doc | 段落、文字、樣式、表格、內容塊和繪圖。 |
| Slide | 頁面、元素、位置和尺寸、樣式、版面配置和主題。 |
| Relational Table | 資料表、欄位、記錄及檢視。 |
| Canvases | 頁面、元素及相關資源。 |

每一項變化都歸為新增、刪除或修改。縮放、選區這類臨時介面狀態不算內容修改。可比較的範圍由產品的比較介面卡決定，不包含 PDF。

## Snapshot 與 changeset 如何共同參與比較

Snapshot 儲存指定修訂號上的完整內容狀態。mutation 描述一次內容變更，changeset 將這些 mutation 組成一次有序提交。歷史記錄負責儲存版本並按需還原，Compare 負責說明兩個已還原版本之間的差異。

比較歷史記錄中的某個版本或 Worktree 時，先載入基礎 Snapshot，再按順序應用其後的 changeset，直到內容到達目標修訂號。兩側都按此方式還原後，將兩份完整狀態交給產品比較介面卡。如果還能取得對應的 changeset，插入或刪除行列這類結構變化會對齊得更準確。只提供兩份完整狀態時，Compare 仍然可以完成快照比較。

比較結果遵循各產品的內容模型：Sheet 為單元格和行列，Doc 為段落，Slide 和 Canvases 為元素，Relational Table 為欄位和記錄。臨時選區或縮放不算內容修改。Compare 本身只讀，恢復版本與合入 Worktree 是兩項獨立操作。

## 串接 Server SDK 與 AI SDK

**Server SDK** 提供 Snapshot、changeset 和修訂號，並還原待比較的內容。應用將兩側狀態和已有的歷史交給 Compare，取得結構化差異，再在 Web 端展示審閱介面。參見[歷史記錄](/overview/features/shared/history)和[協同服務擴充套件](/server/collaboration/extensions)。

**AI SDK** 在 Worktree 中載入和修改內容，並提交 Agent 的結果。應用可以將結構化差異用於 Agent 檢查和後續處理，審閱者則在視覺化的比較結果中檢查同一批改動，再決定是否合入。參見 [Agent 的 Worktree 流程](/ai/worktree)與[內容操作](/ai/content-operations)。

## 五個產品的比較範例

五個範例使用同一份 Northstar 釋出計劃。我們先建立並提交完整的基準版，再在 Worktree 中完成一次編輯，最後開啟 Compare 檢視改動。

差異列表中，**藍色**表示修改，**綠色**表示新增，**紅色**表示刪除。只讀面板分別展示改動前後的內容。點選圖片可以放大。

### Sheet：預算與列結構

我們更新了研究和編輯器的預測預算，刪除了 Legacy tooling，新增 Accessibility QA，並重新計算了合計。變更的數值和公式結果與所屬的行結構相鄰顯示。

![Sheet：預算與列結構](/assets/features/compare/sheets.jpg)

### Doc：發布計畫與段落

我們修改了釋出日期、試點團隊數和目標完成率，刪除了舊審批說明，並新增一條質量檢查要求。保留的上下文使逐段審閱更容易。

![Doc：發布計畫與段落](/assets/features/compare/docs.jpg)

### Slide：指標與頁面元素

我們更新了三張指標卡片，移除了舊審批區塊，並新增質量檢查區塊。比較覆蓋的是同一頁中的文字和元素，而不是把整頁當作一張新圖片。

![Slide：指標與頁面元素](/assets/features/compare/slides.jpg)

### Relational Table：欄位與任務記錄 [#base欄位與任務記錄]

我們更新了進度、狀態和日期，重新命名了日期欄位，刪除了舊審批記錄，並新增一條無障礙檢查任務。差異可以按資料表、欄位和記錄檢視。

![Relational Table：欄位與任務記錄](/assets/features/compare/bases.jpg)

### Canvases：流程與畫布元素 [#board流程與畫板元素]

我們更新了試點規模和釋出日期，移動了評審節點，並用質量檢查卡替換了舊審批卡。內容和版面配置的變化都在畫布上下文中呈現。

![Canvases：流程與畫布元素](/assets/features/compare/boards.jpg)

## 查詢與展示

先註冊對應產品的歷史比較外掛和 Facade 擴充套件，再呼叫 `compareUnitData()`。需要反覆篩選和分頁時，用 `prepareUnitComparison()` 建立比較會話，再呼叫 `query()`。

展示時先給出摘要，再按工作表、頁面或資料表逐層檢視。需要時請求變更列表或完整的前後值。預設明細結果有數量限制，第一頁不一定是全部差異。展示結果前應檢查診斷資訊和覆蓋狀態。

介面參見 [Unit Comparison API](/reference/facade/unit-comparison)，相關流程參見[歷史記錄](/overview/features/shared/history)和 [Worktree](/overview/features/shared/worktree)。
