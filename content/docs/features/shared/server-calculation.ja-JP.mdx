Univer は内容モデル、計算、UI を分離しています。ヘッドレス実行は Node.js で内容ランタイムを動かし、サーバー側計算は `univer-rs` で重い計算とファイル変換を処理します。アプリと Agent は同じ Snapshot を中心に両者を組み合わせられます。

**製品名：** [Relational Table（リレーショナルテーブル）](/docs/features/relational-table) は SDK と API では `Base`、[Canvases（キャンバス）](/docs/features/canvas) は `Board` という名前を使用します。

## UI プラグインなしの Node.js 実行

コア、製品モデル、計算、Facade の必要なプラグインを登録し、メニューやツールバーなど DOM 依存の UI プラグインは登録しません。製品構成に応じて Sheet、Doc、Slide、Base、Board、PDF を処理できます。Sheets と Docs は Node プリセット、他の製品は対応するプラグイン構成から始めます。

| 機能 | できること |
| --- | --- |
| 読み込みと解析 | Snapshot を読み込み、セル、段落、ページ、オブジェクト、レコードと構造を調べます。 |
| 計算 | 数式と配列の計算、ピボット更新、数値書式の表示値生成。 |
| 変更 | Facade API で内容と構造を編集し、Snapshot を保存または変更を送信します。 |
| ファイル処理 | Server SDK の変換機能と組み合わせて一括インポート・処理・エクスポート。 |
| 視覚的検証 | Render Runtime でスクリーンショットとレイアウト検査を生成します。 |

内容操作は Node.js で直接実行します。スクリーンショットとレイアウト検査には別途レンダリング環境を設定します。CLI の Render Runtime はヘッドレスブラウザーを使い PNG と検査結果を返します。

## 編集時の即時計算と、サーバーのバージョン別計算 [#サーバーで事前計算しブラウザーに素早く表示]

フロントエンドとサーバーの両方に数式エンジンがあります。フロントエンドは編集に応答し、サーバーは Snapshot の生成やファイル処理時に、確定した内容のリビジョンを計算します。

- **編集中**：ブラウザーが影響を受ける数式を差分計算し、結果をすぐに表示します。Worker での実行も可能です。共同編集は内容の変更を記録・同期します。
- **Snapshot 生成時**：サーバーのスナップショット保存ポリシーに応じて保存処理を開始し、その処理の対象リビジョンを取得します。`univer-rs` で計算した後、同じリビジョンの内容と結果をまとめて保存します。
- **再度開くとき**：Snapshot 内の有効な計算結果を再利用し、その後の変更を適用して計算を続けることで、全体の重複計算を減らします。

**変更は継続的に同期します。サーバー計算は Snapshot の生成時に実行し、対応する内容のリビジョンとともに結果を保存します。**

保存済み結果に合わせて初期計算を設定します。

- `WHEN_EMPTY`：保存済みの値を再利用し、不足する結果だけ計算します。
- `NO_CALCULATION`：初期計算を省き、アプリが結果を提供します。
- `FORCED`：保存済み結果を更新するため全数式を再計算します。

これらは初回読み込みの設定です。その後の編集はフロントエンドで計算を続け、サーバーはリビジョン別の Snapshot 生成やファイル処理時に必要に応じて計算します。[数式設定](/guides/sheets/features/core/formula)、[共同編集の概要](/server/collaboration/overview)、[ファイル変換](/docs/features/shared/file-conversion)を参照してください。

## 配列数式の計算と展開

対応する関数と形式の範囲で、Rust は Excel の配列数式とスピル規則に従います。アンカー、展開範囲、各セルの結果を返し、動的配列と従来の配列数式の指定範囲を扱います。

例えば空の `A1` に `=SEQUENCE(3,2)` を入力すると、次の結果になります。

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

数式は `A1` に残り、結果は `A1:B3` に展開します。配列が縮むと古い展開値を消去し、展開先が塞がれている場合は `#SPILL!` を返します。ブラウザー、Agent、ファイル出力で計算済み Snapshot を再利用できます。

[関数の対応範囲](/guides/sheets/features/core/formula)と [Excel の配列動作](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior)を参照してください。

## Agent の実行と検証につなぐ

既存 Agent のモデル、会話、ツール制御を利用し、AI SDK から Office 操作を提供します。

1. 構造と対象の内容を読み取ります。
2. ヘッドレス環境で Facade による編集と必要な計算を実行します。
3. 計算とコミット完了を待ち、最新状態を読み戻します。
4. 値と構造を検証し、必要なら画像とレイアウトも確認します。

[内容操作](/ai/content-operations)と[視覚的検証](/ai/visual-inspection)を組み合わせられます。人によるレビューには [Worktree](/ai/worktree) で変更を隔離し、比較後にマージします。[Univer CLI](/docs/examples/cli)は Agent 向けアプリへの組み立て例です。
