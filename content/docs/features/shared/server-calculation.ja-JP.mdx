Headless Univerは、インタラクティブエディタUIなしでUniverコンテンツランタイムです。 これは、コンテンツモデル、コマンド、計算、およびブラウザエディタでファサードAPIを共有します。 アプリケーションは、Node.jsでコンテンツを処理するか、UIを必要としないタスクのためのブラウザで実行できます。 その機能は、登録された製品と機能プラグインに依存します。

JavaScript/TypeScript のランタイムは、このページに記載されています。`univer-rs`は別々の実装です。 `univer-rs`では、サーバー側の計算とファイル変換をサポートしており、同じスナップショットの上にヘッドレスワークフローに参加しています。

## Headless でできること [#headless-capabilities]

- コンテンツと構造を読み、変更します。 Univer スナップショットを作成またはロードし、ファサード API を使用して、セル、段落、ページ、グラフィックオブジェクト、またはレコードを読み取り、編集し、更新されたスナップショットを保存します。 これらの操作は、バッチ処理、データ生成、コンテンツの検査、およびエージェントの自動化をサポートしています。
- 登録されたビジネスロジックを実行します。式計算、ソート、フィルタリング、バリデーション、ピボットプラグインが利用可能で、アプリケーションは画像、チャート、図形、コメントなどのリソースを変更できます。利用可能な操作は、登録済み製品や機能プラグインとその依存関係に依存します。
- 他のサービスに接続します。 Node.jsコラボレーションクライアントを追加して、コラボレーションユニットをロードし、変更を提出し、同期を待ちます。 Server SDK変換モジュールとランタイムを組み合わせて、Officeファイルをインポートおよびエクスポートします。

Headless は、エディタ UI を提供していません。メニュー、ツールバー、ダイアログ、マウス、キーボードのやりとり、スクリーンショット、または印刷はありません。 永続、認証、コラボレーションサーバー、ファイル変換はどちらも含まれていません。 `save()` は Univer スキャナを返します。 それは、データベースやエクスポートXLSX、DOCX、または PDF に書きません。 スクリーンショットとビジュアル レイアウト チェックには、別の [レンダリングのランタイム](/ai/visual-inspection)、ヘッドレス ブラウザーがレンダリングされます。

## Headless に含まれるパッケージ [#headless-packages]

アプリケーションが必要とするコンテンツパッケージを選択し、必要な製品プラグインと依存関係を登録します。 Proの機能には、ライセンスの設定が必要です。

### 通信・計算プロセス・共同編集

必要なときだけインフラを追加します。 `@univerjs/network` と `@univerjs/rpc-node` は、ネットワークと Node.js の計算プロセスを提供し、`@univerjs-pro/license` はライセンス統合を処理します。 `@univerjs-pro/collaboration`、`@univerjs-pro/collaboration-client`、`@univerjs-pro/collaboration-client-node` は共同サーバーではなく、ヘッドレスコラボレーションクライアントを形成します。 ローカルスナップショットを扱うことは、コラボレーションサービスを必要としません。

### 内容処理のみのランタイムに含めないパッケージ

- `@univerjs/ui`、`@univerjs/design`および`*-ui`パッケージは、`@univerjs/sheets-ui`や`@univerjs/docs-ui`などの製品や機能、`@univerjs-pro/slides-ui`など、UI、レンダリングの統合、またはインタラクションを提供します。 コンテンツを処理するNode.js設定にそれらを追加しないでください。
- `@univerjs/sheets-find-replace`と`@univerjs/sheets-crosshair-highlight`は`-ui`サフィックスはありませんが、`@univerjs/sheets-ui`に依存しているため、パッケージ名だけではヘッドレスプラグインであることは意味がありません。
- デフォルトの`@univerjs/preset-sheets-core`と`@univerjs/preset-docs-core`プリセットはUIプラグインを登録し、Node.jsヘッドレスプリセットではありません。この場合、プラグインモードを使用してコンテンツ層の依存関係を明示的に選択します。

**`@univerjs/engine-render`は別途検討が必要です。** 現在のNode.jsの例は、レンダリング管理などの共有された依存関係を供給するためにそれを登録します。 プラグインを登録すると、キャンバスを作成したり、エディタをマウントしません。 それはヘッドレス構成に表示することができますが、描画、フォント測定、およびスクリーンショットAPIは、適切なレンダリング環境を必要とします。 したがって、パッケージ内のすべてのAPIが純粋なNode.jsで使用可能ではありません。

**ファサードは、環境アダプタではなく、運用APIです。** 各コンテンツプラグインが使用中のため、`/facade`拡張子をインポートし、必要な機能を実装するプラグインを登録します。 `@univerjs/ui/facade`や`@univerjs/sheets-ui/facade`などのUI拡張はUIを必要としています。そのため、メニュー、スクロール、およびビジュアル選択のインタラクションを実行します。プラグインの依存関係と実際のコールパスを調べるのではなく、パッケージ名やファサードAPIの存在に依存します。

[シートヘッドレスガイド](/guides/sheets/getting-started/node)と[Docs ヘッドレスガイド](/guides/docs/getting-started/node)に実行可能なプラグイン構成が表示されます。

## 編集時の即時計算と、サーバーのバージョン別計算 [#サーバーで事前計算しブラウザーに素早く表示]

フォーミュラエンジンは、フロントエンドとサーバーの両方で実行されます。 フロントエンドは、ユーザの編集として応答し、サーバーは、スナップショットを生成したり、ファイルを処理するときにキャプチャされたコンテンツリビジョンを計算します。

- 編集中に、ブラウザは、影響を受ける式をローカルで計算し、ワーカーでオプションで計算し結果をすぐに表示します。コラボレーションサービスは、これらのコンテンツの変更を記録し、それらを同期させます。
- スナップショットが生成されると、サーバーのスナップショットポリシーは保存ワークフローを開始します。サーバーは、その操作のコンテンツリビジョンをキャプチャし、`univer-rs`で計算し、そのリビジョンのコンテンツと結果を保存します。
- ドキュメントが再オープンされると、フロントエンドはスナップショットの有効な結果を再使用し、その後の変更を適用し、計算を続け、完全な再計算を回避します。

<Mermaid chart={"flowchart LR\n    F[\"フロントエンド編集<br/>即時計算\"]\n    C[\"内容の同期<br/>確定した変更\"]\n    R[\"Rust 計算<br/>リビジョン N\"]\n    S[\"Snapshot 保存<br/>saveSnapshot\"]\n    F <--> C\n    C -->|\"Snapshot 生成時\"| R\n    R --> S"} />

**コンテンツの変更は、継続的に同期します。サーバーの計算はスナップショット生成の一環として実行され、その結果はそのコンテンツリビジョンのために保存されます。**

最初のロードでは、アプリケーションは、初期の計算が保存された結果をどのように使用しているかを設定します。

- `WHEN_EMPTY`：保存済みの値を再利用し、不足する結果だけ計算します。
- `NO_CALCULATION`：初期計算を省き、アプリが結果を提供します。
- `FORCED`：保存済み結果を更新するため全数式を再計算します。

これらのオプションは初期のロードのみを管理します。 ロード後、編集はフロントエンドで計算し続け、バージョンのスナップショットまたはプロセスファイルを生成するときにサーバーはオンデマンドを計算します。 [方式の構成](/guides/sheets/features/core/formula)、[コラボレーション](/server/collaboration/overview)および[ファイル変換](/overview/features/shared/file-conversion)を参照してください。

### 数式エンジンの性能

[Univerの錆の方式エンジンのベンチマーク](/blog/rust-formula-performance)は10本のワークブックをカバーし、Rustの入力ローディング、段階のタイミング、入力フォーマットの境界、およびワークブックのダウンロードを含みます。

## 配列数式の計算と展開

サポートされている関数とフォーマット内で、Rust は Excel の配列形式とスピルセマティクスに従います。 計算された値をアンカーとスピル範囲とともに返し、動的配列とレガシー配列の宣言された範囲の両方を処理する。

例えば空の `A1` に `=SEQUENCE(3,2)` を入力すると、次の結果になります。

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

式は残っています `A1`, 結果が占める `A1:B3`. 配列が縮小すると、以前のスピル値がクリアされます。スピルがブロックされると、結果は `#SPILL!`. ブラウザ、エージェント、およびエクスポートパイプラインは、すべての計算されたスナップショットを再利用することができます。

[式サポート](/guides/sheets/features/core/formula)と[Excel 配列の動作](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior)の対応機能と範囲ルールです。

## Agent の実行と検証につなぐ

既存のモデル、会話、ツールのオーケストレーションをキープします。AI SDK ツールは、Office コンテンツの操作をエージェントに公開します。

1. 構造を点検し、ターゲット コンテンツを読んで下さい。
2. ファサードの変更を適用し、ヘッドレスランタイムで必要な計算を実行します。
3. 計算とコミットが確認されるのを待ってから、更新された状態を読んでください。
4. 値と構造を確認し、ビジュアル検証が必要なときにスクリーンショットやレイアウトチェックを追加します。

[コンテンツの操作](/ai/content-operations)と[ビジュアル検査](/ai/visual-inspection)を一緒に使用してください。 人が作業を検討する必要がある場合は、[Worktree](/ai/worktree)で編集を最初に配置し、それらを比較して結合します。 [Univer クリップ](/overview/examples/cli)は、エージェントが運転できるアプリケーションにこれらの機能を組み立てる方法を実証しています。
