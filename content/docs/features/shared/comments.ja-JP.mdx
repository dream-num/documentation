コメントは議論をコンテンツのそばに保ちます。レビュー担当者は数値、段落、図形の問題を指摘し、作成者や他の参加者は同じスレッドで返信できます。外部チャットに議論を分散させず、文脈を共有できます。

**製品名：** [Relational Table（リレーショナルテーブル）](/docs/features/relational-table) は SDK と API では `Base`、[Canvases（キャンバス）](/docs/features/canvas) は `Board` という名前を使用します。

## 質問から結論まで [#review-workflow]

1. **対象を指定**：セル、選択テキスト、レコード、要素、ページ位置にコメントし、コンテンツへの参照を保持します。
2. **スレッドで議論**：最初のコメントと返信をまとめ、作成者、時刻、本文を表示します。
3. **解決または再開**：修正後に解決済みにします。追加対応が必要なら、議論を残したまま再開できます。

コメントパネルでは、すべて、未解決、解決済み、自分に関連する議論を絞り込めます。解決は削除とは異なり、判断の経緯を後から確認できます。

## 製品別のコメントと注釈 [#product-comments]

スクリーンショットは英語の Northstar リリースプロジェクトです。Facade API で実際のエディターに作成し、フロントエンドのコメントと注釈を示しています。画像をクリックすると拡大できます。

### Sheets [#sheets]

セルに議論を紐付け、予算の数値のそばで予測の定義、費用、承認を確認します。複数スレッド、連続した返信、解決済みのグループを表示しています。セルには `range.addCommentAsync()` を使います。画像、グラフ、図形へのコメントには対応する描画コメント連携が必要です。

![Sheets のコメント：公開予算、セルの位置、レビュー返信、解決済みの議論](/assets/features/comments/sheets.png)

[製品の導入と API](/guides/sheets/features/comments)

### Docs [#docs]

選択したテキスト範囲にコメントして、契約条項、提案書、公開日などをレビューします。カードに引用を残し、テキスト編集中はコメント装飾が位置を維持します。例では公開日、指標の定義、旧手順の置き換えを議論しています。`document.getTextRange(...).createCommentAsync()` を使います。

![Docs のコメント：公開概要、引用テキスト、3つのレビュースレッド](/assets/features/comments/docs.png)

[製品の導入と API](/guides/docs/features/comments)

### Slides [#slides]

スライドの要素、または自由な位置にコメントできます。要素コメントはテキストボックス、画像、グラフなどの安定した ID を参照し、位置コメントはページ内の正規化座標を使います。例は公開目標とレイアウトのレビューです。`slide.createElementCommentAsync()` と `slide.createPositionCommentAsync()` を使います。

![Slides のコメント：公開レビュー、要素への紐付け、複数担当者の返信](/assets/features/comments/slides.png)

[製品の導入と API](/guides/slides/features/comments)

### Base [#bases]

コメントはレコード ID に紐付き、現在の表示行番号に依存しません。引き継ぎ、顧客対応、検収の確認に使えます。リリース管理表に担当者の議論、承認待ち事項、レコードのコメントマークを表示しています。`record.createCommentAsync()` を使います。

![Base のコメント：公開管理レコード、コメントマーク、引き継ぎの議論](/assets/features/comments/bases.png)

[製品の導入と API](/guides/bases/features/thread-comment)

### Board [#boards]

図形などの要素、またはボードの指定位置にコメントします。要素コメントはオブジェクトを参照し、位置コメントはボード座標を保持します。顧客調査、開発の引き継ぎ、公開リスクをフロー上で議論しています。`board.createElementCommentAsync()` と `board.createPositionCommentAsync()` を使います。

![Board のコメント：色付き公開フロー、要素と位置へのコメント、返信](/assets/features/comments/boards.png)

[製品の導入と API](/guides/boards/features/comments)

### PDF：ページ注釈 [#pdfs]

PDF は現在、ハイライト、下線、取り消し線、波線、インクによるページ注釈を提供します。保存可能な PDF 注釈オブジェクトであり、上記の返信・解決可能なスレッドとは異なります。例では公開日と検収条件をマークし、旧承認手順を取り消しています。`page.insertAnnotation()` を使います。

![PDF 注釈：公開レビュー文書のハイライト、下線、取り消し線、インク](/assets/features/comments/pdfs.png)

## 導入方法 [#integration]

**フロントエンド**：製品のコメントと UI プラグインを登録し、共通と製品固有の `/facade` エントリーをインポートします。製品のメソッドで対象を紐付け、`replyCommentAsync()`、`updateCommentAsync()`、`resolveCommentAsync()` などの共通 API で議論を操作します。`resolved: false` で再開します。PDF は専用の注釈 API を使います。

**共有の議論**：基本の共同編集に加えて Comment Service、Comment Endpoint、独立したデータベースアダプターを導入し、フロントエンドのリモートデータソースを設定します。本文書は内容に追従するアンカーを保持し、Comment Service は本文、返信、解決状態を保存して文書ルームに更新を配信します。[コメントパッケージ](/server/collaboration/packages#thread-comment)と [Comments サンプル](/server/collaboration/examples#comments)を参照してください。

コメント権限は本文編集とは独立して設定できます。アプリケーションの ID とサーバーの認可は[権限と認可](/docs/features/shared/permissions)を参照してください。
