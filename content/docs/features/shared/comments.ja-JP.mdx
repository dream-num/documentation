コメントは、コンテンツの横に議論を続けます。 査読者は、同じスレッドで価値、段落、またはグラフィック、著者の応答に関する質問を上げることができ、他の参加者はコンテキストを追加しているので、ディスカッションは外部チャットツールに普及していません。

## 質問から結論まで [#review-workflow]

1. **質問をアンカーする**は、セル、選択したテキスト、レコード、要素、またはページの位置に。アンカーは、ポイントするコンテンツへの参照を保持します。
2. **スレッドでそれを区別します。**は、rootコメントと返信から成り立っています。それぞれ、その作者、タイムスタンプ、コメントテキストです。
3. **解決するか、または再オープンして下さい** 変更後のスレッド。フォローアップが必要なときにスレッドを再オープン。以前の議論はそのまま残します。

コメントパネルフィルタは、すべての、未解決、またはスレッドを解決するか、現在のユーザーを関与する議論によってフィルタリングします。スレッドを解決することは削除しません。決定はレビューのために利用できます。

## 製品別のコメントと注釈 [#product-comments]

スクリーンショットは、英語で単一のNorthstarの起動プロジェクトを使用します。 それらは、正面のコメントと注釈を表示するために、実際のエディタでファサードAPIを介してキャプチャされました。 画像をクリックして拡大します。

### Sheets [#sheets]

単一セルに固定された議論では、レビュー担当者が予測、コストの詳細、または予算番号の横にある承認を直接確認することができます。例は、いくつかのスレッド、連続した返信の実行、および解決されたセクションを示しています。 セルコメントは、`range.addCommentAsync()`を介して追加されます。 画像、チャート、および形状に関するコメントは、対応するドローイングコンメンションが必要です。

### Docs [#docs]

テキスト範囲を選択し、契約条項の見直し、単語の提案、または日付の起動時にコメントを追加します。コメントカードは引用されたテキストを保持し、コメントの装飾は、周囲のテキストが変更される間アンカーを維持します。 例では、リリース日、メトリックの定義、および古いワークフローの置換について説明します。 `document.getTextRange(...).createCommentAsync()` を呼び出す。

![Docs のコメント：公開概要、引用テキスト、3つのレビュースレッド](/assets/features/comments/docs.png)

[製品の導入と API](/guides/docs/features/comments)

### Slides [#slides]

コメントは、単一の要素またはスライド上の自由な位置をターゲットにすることができます。 要素コメントは、テキストボックス、画像、チャート、およびその他のオブジェクトの安定したIDを参照します。 位置コメントは、正規化ページ座標を使用します。 たとえば、起動ターゲットとレイアウトについて説明します。 `slide.createElementCommentAsync()`と`slide.createPositionCommentAsync()`を呼び出します。

![Slides のコメント：公開レビュー、要素への紐付け、複数担当者の返信](/assets/features/comments/slides.png)

[製品の導入と API](/guides/slides/features/comments)

### Relational Table [#bases]

コメントの参照レコードID, ので、議論は、その目に見える行番号ではなく、ビジネスレコードに縛ら残っています. 彼らは、ハンドオフに使用されます, 顧客フォローアップ, そして、受諾レビュー. 打ち上げトラッカーは、所有者の議論を示しています, 終了承認, そして、レコードの横にあるコメントマーカー. コール`record.createCommentAsync()`.

![Relational Table のコメント：公開管理レコード、コメントマーク、引き継ぎの議論](/assets/features/comments/bases.png)

[製品の導入と API](/guides/bases/features/thread-comment)

### Canvases [#boards]

コメントは、形状などの要素に添付したり、特定のボードの位置でメモとして残したりすることができます。 要素コメントはオブジェクトを参照します。 位置コメントは、ボード座標を保持します。 たとえば、顧客調査、エンジニアリングの手渡、コンテキストでリスクを立ち上げます。 `board.createElementCommentAsync()`と`board.createPositionCommentAsync()`を呼び出します。

![Canvases のコメント：色付き公開フロー、要素と位置へのコメント、返信](/assets/features/comments/boards.png)

[製品の導入と API](/guides/boards/features/comments)

### PDF：ページ注釈 [#pdfs]

PDFは現在、ページアノテーションを提供しています:ハイライト、アンダーライン、ストライクアウト、スクイズライン、インク。 これらは、永続性のPDFアノテーションオブジェクトであり、応答と解像度をサポートする上記のスレッドとは別々です。 この例では、起動日、マークの受諾基準を強調し、古い承認ステップを渡します。 コール`page.insertAnnotation()`.

## 導入方法 [#integration]

**フロントエンド**:製品のコメントとUIプラグインを登録し、共有および製品固有のコメント`/facade`エントリをインポートします。 製品固有の方法は、アンカーを確立し、`replyCommentAsync()`、`updateCommentAsync()`などの共有APIが、`resolveCommentAsync()`は、フォローするディスカッション操作を処理します。 `resolved: false`を渡すと、スレッドを再開くことができます。 PDFは別のアノテーションAPIを使用します。

**共有ディスカッション**:コメントサービス、コメントエンドポイント、およびコアコラボレーションと独立したデータベースアダプタを追加し、リモートフロントエンドのデータソースを設定します。 主な文書は、アンカーを保持し、コンテンツと変更します。 コメントサービスはテキスト、返信、および解像度の状態を保存し、コメントの更新を文書室に公開します。 [コメントパッケージ](/server/collaboration/packages#thread-comment)と[コメント例](/server/collaboration/examples#comments)を参照してください。

コメントのパーミッションは、コンテンツの編集権限から個別に設定できます。アプリケーション ID とサーバー側の許可については、[許可と認可](/overview/features/shared/permissions) を参照してください。
