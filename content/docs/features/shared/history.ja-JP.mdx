バージョン履歴は、参照可能なバージョンに確認された共同変更を整理します。 各確認された変更、開発者、およびユーザーは、著者、タイムスタンプ、およびアクションを見ることができます。その時点で解決する文書を開き、その権限を持っているときに、違いを見直し、バージョンを復元します。 編集セッションが終了した後、履歴は利用でき、ページをリロードします。

## バージョン履歴の仕組み

**ミューテーション**は、セルの設定や段落の入力など、再生可能なコンテンツの変更です。 **変更点** は、注文されたグループをミューテーションする1つのコラボレーション投稿です。

### 1. 変更を記録する

ユーザやエージェントから編集されると、ミューテーションが生成されます。Univerは、これらのミューテーションをチェンジセットにパックし、コラボレーションのためにそれを提出して確認し、主張します。

<Mermaid chart={"flowchart LR\n    A[\"内容を編集\"]\n    B[\"Mutation\"]\n    C[\"Changeset\"]\n    D[\"確定して保存<br/>revision を記録\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

確認後、文書の履歴にその位置を識別する**更新履歴**が送信されます。履歴は確認された変更点をインデックス化し、時間と操作でグループ化し、バージョンのタイムラインを構築します。

### 2. 過去の内容を再構築する

**スナップショット**は1つのリビジョンで完全なコンテンツ状態です。 歴史バージョンが選択されると、Univer はベースラインスナップショットと、ターゲットリビジョンに従ったチェンジセットをロードし、順番にミューテーションを再生します。 この結果は、そのリビジョンで解決するコンテンツの読み取り専用ビューです。

<Mermaid chart={"flowchart LR\n    A[\"バージョンを選択<br/>revision N\"]\n    B[\"Snapshot と<br/>後続 Changeset を取得\"]\n    C[\"Mutation を<br/>順番に再生\"]\n    D[\"過去の内容を表示<br/>読み取り専用\"]\n    A --> B\n    B --> C\n    C --> D\n"} />

例：**revision 10 の Snapshot + revision 11〜15 の Changeset = revision 15 の内容。**

### 3. 現在のドキュメントを復元する

**このバージョンを復元** を選択すると、次のフローが始まります。

> 対象バージョンを選択 → 復元 Mutation を送信 → 共同編集で確定 → 現在の内容を更新し、新しい revision を作成

復元操作は、新しい履歴レコードを作成します。 以前のバージョンは利用可能です。

## バージョンと変更を確認する

1. エディターからバージョン履歴を開き、バージョンを選択します。
2. 個々のリビジョンを調べるためにバージョングループを拡大します。 読み取り専用のビューアでコンテンツと変更を1つのリビジョンを選択します。
3. ロールバックが必要な場合は、**このバージョンを復元**を選択します。 共有文書を共同で更新復元すると、他の参加者全員が変更を受け取ります。

バージョングループは、タイムウィンドウ内で行われた編集を組み合わせることができます。グループを拡大して、個々のリビジョンを調べます。 **1つの履歴エントリは、必ずしも1つのキーストロークまたは1つの生成されたスナップショットに対応するものではありません。**

### 変更の色

| 表示 | 意味 |
| --- | --- |
| 🟦 **ブルー:更新** | 既存のコンテンツが変更されました。 | 値、段落形式、またはオブジェクトプロパティが更新されました。 |
| 🟩 **緑：追加** | 新しい行、段落、レコード、ボードのオブジェクト。 |
| 🟥 **赤:削除** | このバージョンで削除されたコンテンツ。 | 削除されたテキストまたはオブジェクトは、履歴ビューでマーカーを保持します。 |

色は**変更の種類**を示します。テキストを置き換えると、インサートと削除の両方を生成できます。各製品のビューアは、コンテンツのどのくらいが強調表示されているかを決定します。

## アプリケーションへの導入

バージョン履歴は、Server SDKの履歴拡張機能をWeb SDKで製品履歴プラグインと組み合わせています。

- サーバ上で、History Service、Endpoint、Persistent Database AdapterをCore Collaborationに追加します。このサービスは、ユニットの作成とコミットされたチェンジセットを購読し、履歴インデックスを作成したり、バージョンやチェンジセットのクエリを調べたりします。
- ブラウザでは、一般的な履歴機能と製品の履歴/履歴UIプラグインを登録し、履歴エンドポイントを接続します。ビューアは選択したリビジョンをロードし、変更を表示します。カスタムコンテンツについては、マッチングビューアプラグインを登録します。
- アプリケーションは、ID と認可を発行し、サーバーは履歴読み取りと権限を復元します。 歴史バージョンには、現在の文書が既に削除されたデータが含まれています。

[コラボレーションエクステンション](/server/collaboration/extensions) を見て、[歴史例](/server/collaboration/examples#history)でサービスを組み立て、上記の製品ガイドでUIを接続します。

履歴インデックスは、再構築可能な派生したデータです。 **確認された変更は、権限のあるコンテンツソースのままです。** アプリケーションは、永続性と保持を制御します。 履歴パネルは、バックアップを交換しません。

## 関連機能との違い

| 機能機能 | 目的: |
| --- | --- |
| 宇都宮/赤尾 | 履歴サービスなしで編集操作を反転または再適用します。 |
| バージョン履歴 | セッション全体で確認されたバージョンをトレースし、変更を調べ、共有コンテンツを復元します。 |
| [コンテンツの比較](/overview/features/shared/compare) | UI または Agent の 2 つのコンテンツの状態を比較します。読み取りのみの比較では、コンテンツを復元しません。 |
| [Worktree](/overview/features/shared/worktree) | 共有コンテンツにそれらをマージする前に、レビューの草案の変更を隔離します。 |

ファサード API によるエージェントの変更は、コラボレーションが確認すると、同じ履歴パイプラインに入ります。アプリケーションは、自動レビューとチェックのコンテンツ比較と履歴を組み合わせることができます。
