La conversión conecta los formatos externos con los modelos de contenido de Univer. La importación analiza un archivo y genera el Snapshot del producto correspondiente; la exportación serializa ese snapshot en el formato elegido.

**Nombres de producto:** [Relational Table (tabla relacional)](/docs/features/relational-table) se denomina `Base` en el SDK y las API; [Canvases (lienzos)](/docs/features/canvas) se denomina `Board`.

## Del archivo al snapshot

`.xlsx`, `.docx` y `.pptx` son paquetes OOXML con XML y recursos como imágenes. `.xls`, `.doc` y `.ppt` usan estructuras binarias antiguas; CSV y TSV son formatos de texto. Envía el archivo original compatible: el módulo realiza la decodificación, el análisis del paquete y la correspondencia de recursos.

Un snapshot contiene el estado del contenido de un producto que se puede guardar y restaurar. [Ver las estructuras de los seis productos](#estructuras-de-datos-snapshot)

### Estructuras de datos Snapshot

Cada producto tiene una interfaz Snapshot para guardar su contenido y referencias a recursos, normalmente en JSON. Los enlaces muestran las definiciones de campos, tipos y ejemplos.

<div className="[&_table]:min-w-180 [&_code]:whitespace-nowrap">

| Producto | Interfaz Snapshot | Contenido principal |
| --- | --- | --- |
| Hojas de cálculo (Sheet) | [`IWorkbookData`](/guides/sheets/model/workbook-data#iworkbookdata) | Hojas, celdas, estilos compartidos y recursos de complementos. |
| Documentos (Doc) | [`IDocumentData`](/guides/docs/model/document-data#idocumentdata) | Cuerpo, párrafos, estilos, encabezados, pies de página y recursos. |
| Presentaciones (Slide) | [`ISlideData`](/guides/slides/model/slide-data#islidedata) | Diapositivas, elementos, patrones, temas y recursos. |
| Tabla relacional (Base) | [`IBaseSnapshot`](/guides/bases/model/base-snapshot#ibasesnapshot) | Tablas, campos, registros, vistas y su orden. |
| Lienzo (Board) | [`IBoardData`](/guides/boards/model/board-data#iboarddata) | Páginas, elementos, temas y recursos. |
| PDF | [`IPdfUnitData`](/guides/pdfs/model/pdf-data#ipdfunitdata) | Documento original, estado de edición persistente y vínculos de recursos. |

</div>

Usa `save()` en la Facade del producto para obtener el snapshot actual y su API de creación para restaurarlo. Modifica el contenido activo mediante Facade API. Para PDF, `pdf.save()` conserva tanto la base original como `editState`.

## Formatos por producto

Los formatos Office y tabulares siguientes corresponden a las rutas directas de Rust Exchange. PDF utiliza un módulo de conversión independiente.

<div className="[&_table]:min-w-180 [&_code]:whitespace-nowrap">

| Producto | Importar / compilar | Exportar | Alcance |
| --- | --- | --- | --- |
| [Hojas de cálculo (Sheet)](/guides/sheets/features/import-export) | `.xls`, `.xlsx`, `.csv`, `.tsv` | `.xlsx`, `.csv`, `.tsv` | CSV/TSV representa una sola hoja. |
| [Documentos (Doc)](/guides/docs/features/import-export) | `.doc`, `.docx` | `.docx` | DOC antiguo se importa al modelo Docs; la salida utiliza DOCX. |
| [Presentaciones (Slide)](/guides/slides/features/import-export) | `.ppt`, `.pptx` | `.pptx` | PPT antiguo se importa al modelo Slides; la salida utiliza PPTX. |
| [Tabla relacional (Base)](/guides/bases/features/import-export) | `.xls`, `.xlsx`, `.csv`, `.tsv` | `.xlsx`, `.csv`, `.tsv` | CSV/TSV representa una tabla; XLSX permite mapear tablas y campos. |
| [Lienzo (Board)](/guides/boards/features/import-export) | Mermaid (`.mmd` / texto fuente) | `.pptx` | Mermaid genera un borrador que se aplica mediante Board Facade antes de guardar el snapshot. PPTX exporta la página activa. |
| [PDF](/guides/pdfs/features/import-export) | `.pdf` | `.pdf` | Requiere el servicio de conversión PDF, separado del CLI Rust Exchange. |

</div>

- Los formatos antiguos `.xls`, `.doc` y `.ppt` se pueden importar; las salidas son `.xlsx`, `.docx` y `.pptx`, respectivamente.
- La exportación CSV/TSV selecciona una hoja o tabla Base. Guarda el snapshot para conservar el modelo completo y sus recursos.
- Las extensiones admitidas varían según el punto de entrada SDK. Comprueba el backend y la API del navegador para `.xlsm`, `.pptm`, `.ppsx`, `.ppsm` y `.potx`; no son nombres adicionales de formatos directos del CLI Rust.

## Cálculo durante la conversión

Los flujos compatibles de conversión de hojas de cálculo pueden incluir cálculo en el servidor:

- **Fórmulas:** completar resultados en caché ausentes al importar o recalcular antes de exportar según la política seleccionada.
- **Tablas dinámicas:** calcular agrupaciones y agregaciones a partir de los datos y la configuración, y materializar los resultados en el snapshot o libro exportado.
- **Formatos numéricos:** generar el texto mostrado para fechas, porcentajes, monedas y otros valores. CSV/TSV permite elegir valores mostrados o sin formato.

Consulta [Headless y cálculo en el servidor](/docs/features/shared/server-calculation) para el procesamiento de contenido relacionado.

## Integración

La conversión pertenece al Server SDK. La aplicación proporciona carga, tareas, almacenamiento y descarga. Los snapshots pueden convertirse sin colaboración; la exportación compartida lee una revisión confirmada tras sincronizar los cambios.

Empieza por [Integración de la conversión](/server/import-export) y [Conversión en Node.js](/server/import-export/node).

La compatibilidad de formato y la conservación de cada función son aspectos distintos. Comprueba fórmulas, imágenes, estilos y diseño con las listas de funciones y archivos reales.
