Los bloques insertados colocan un producto Univer dentro de otro. Un documento de proyecto puede contener presupuestos y tareas, una diapositiva puede llevar una hoja de cálculo de trabajo, y un lienzo puede presentar planes junto con notas. El contenido integrado mantiene su propio modelo de datos y su editor nativo, así que activar el bloque mueve enfoque y menús a la unidad infantil.

## Principio: Unit anfitriona y Unit hija [#principle]

El **Unidad de acogida** almacena la colocación y el tamaño del bloque, la referencia a la unidad infantil y la vista predeterminada. El **Dependencia de la Infancia** guarda las celdas, párrafos o registros reales. Carga un bloque resuelve esa referencia, carga la unidad infantil, y monta su editor dentro del host. Un [Dependencia](/guides/sheets/getting-started/quickstart#unit) puede ser un libro de trabajo, un documento, una presentación, una tabla relacional, o un lienzo.

<Mermaid chart={"flowchart LR\n    A[\"Unit anfitriona<br/>Documento, página o lienzo\"]\n    B[\"Descriptor Embed<br/>Posición + referencia hija\"]\n    C[\"Resolver referencia<br/>Cargar Unit hija\"]\n    D[\"Editor nativo hijo<br/>Visualización e interacción\"]\n    E[\"Editar / guardar<br/>Actualizar Unit hija\"]\n    A --> B --> C --> D --> E"} />

La relación y el contenido se persisten por separado. Editar una célula en una hoja de cálculo incrustada actualiza la hoja de niño. Moviendo o redimensionando el bloque actualiza el ancla almacenado en el host.

## Ubicaciones compatibles [#locations]

| Producto anfitrión | Ubicación | Uso habitual |
| --- | --- | --- |
| Sheet | Objeto flotante o una pestaña de libro de trabajo | Un breve junto a un modelo de cálculo, o una base de datos de tareas en una pestaña separada. |
| Doc | Bloque del cuerpo | Narrative, budgets, and tasks on one project page. |
| Slide | Objeto flotante o página de presentación | Datos de origen editables al lado de la conclusión. |
| Relational Table | Entrada de la lista de tablas | Documentación del proyecto que permanece dentro de una base de datos de negocios. |
| Canvases | Objeto flotante en el lienzo | Datos, propuestas y discusión sobre un único lienzo. |

## Cinco ejemplos de anfitrión [#examples]

Los ejemplos a continuación fueron producidos a través de Facade API y capturados en un navegador, por lo que la interfaz está en inglés. Cada caso utiliza unidades infantiles independientes, y todos los contenidos y figuras son datos de muestra.

### Sheet: cálculos y un informe de decisión [#sheet-host]

El centro de control total gasta a la izquierda e incorpora un Doc completo a la derecha. Su pestaña de rastreador de lanzamiento abre una Tabla de Relación. Esta disposición se adapta a los precios, operaciones y libros de trabajo financieros que deben mantener suposiciones, cálculos y una decisión escrita en un solo lugar. El equivalente más cercano es [insertar un objeto de documento en Excel](https://support.microsoft.com/en-au/excel/insert-an-object-in-your-excel-spreadsheet).

### Doc: una página de proyecto con presupuesto y tareas [#doc-host]

El cuerpo contiene una hoja presupuestaria seguida de una Tabla de Relación, por lo que los lectores pueden examinar el modelo y mantener tareas en contexto. El arreglo se asemeja a [Bases de datos en línea de Noción](https://www.notion.com/help/guides/full-page-vs-inline-databases), excepto que el presupuesto todavía funciona en el motor de fórmula de hoja y las tareas mantienen campos y puntos de vista de tabla relacional.

### Slide: datos fuente durante la revisión [#slide-host]

Una diapositiva lleva una hoja presupuestaria, una tabla de relaciones y una métrica de presupuesto impulsada por fórmulas. La interacción es comparable a [incrustaciones Excel en PowerPoint](https://support.microsoft.com/en-gb/powerpoint/insert-and-update-excel-data-in-powerpoint): los revisores pueden comenzar desde la conclusión y volver a un modelo de datos editable. El presupuesto ilustrado ha sido actualizado a $62,100.

![Slide con presupuesto, tareas y métrica calculada](/assets/features/embed/slide.png)

### Relational Table: documentación dentro de la base [#base-host]

Un breve Lanzamiento Doc se sienta al lado de la tabla de tareas en la lista de tablas. En una base de datos CRM, rastreador de proyectos o operaciones, esto permite a la gente moverse entre el trabajo estructurado y su contexto escrito. Esta es una entrada de lista de tabla, y no crea automáticamente un documento para cada registro.

![Doc abierto desde la lista de tablas de Relational Table](/assets/features/embed/base.png)

### Canvases: un espacio de planificación compartido [#board-host]

El lienzo combina una hoja presupuestaria, una propuesta Doc, y un resumen de gasto basado en fórmulas. Esto se adapta a las salas de proyectos, revisiones y lienzos de investigación que necesitan datos fuente y contexto a mano durante una discusión.

![Canvases con Sheet, Doc y resumen calculado](/assets/features/embed/board.png)

## Cómo se conectan las fórmulas [#formulas]

La inserción de un bloque no crea una fórmula sumaria, por lo que las referencias transversales deben configurarse primero. Una vez que estén en su lugar, las células de hoja y las formas impulsadas por fórmulas en Doc, Slide y Canvases pueden leer rangos de hoja o campos de tabla relacional, y los campos de fórmulas de tabla de relacional también pueden hacer referencia a una hoja.

<Mermaid chart={"flowchart LR\n    A[\"Editar Sheet / Relational Table incrustada\"]\n    B[\"Cambiar datos de Unit hija\"]\n    C[\"Actualizar referencias y dependencias\"]\n    D[\"Recalcular fórmula\"]\n    E[\"Actualizar celda / Shape\"]\n    A --> B --> C --> D --> E"} />

| Escenario y fórmula | Resultado verificado |
| --- | --- |
| Presupuesto en Slide: `=SUM('[Leadership Budget]Budget'!C5:C8)` | Cambiar `C7` de 17,100 a 18,000 actualiza el total de **61,200 → 62,100**. |
| Total de Relational Table en Sheet: `=SUM([Control Tasks]!Launch_tasks[Cost])` | Cambiar un Cost de 4,000 a 4,500 actualiza el total de **18,000 → 18,500**. |

Los nombres de las Fórmulas sirven como calificadores legibles, y una integración también debe persistir los IDs de Unidad estables detrás de ellos. `getFormula().buildReference()` para generar una referencia junto con la cartografía externa de propiedad de host que requiere. Para una tabla en Tabla de Relación, utilice `table.getFormulaName()` en lugar de concatenar un nombre de pantalla o ID. `shape.setFormula({ formula, externalReferences })`; leer el resultado después de completar el cálculo. [Fórmula Facade](/reference/facade/formula#buildreference), [Shape Facade](/reference/facade/shape#setformula) y [Fórmulas de tablas relacionales](/guides/bases/features/core/formulas).

## Creación e integración [#integration]

Registrar el producto anfitrión, el producto del niño y su interfaz de usuario en la misma instancia Univer, luego añadir Embed y Embed UI. El ejemplo a continuación inserta una hoja existente en un cuerpo Doc; `hostDocument` y `budgetWorkbook` son las Facades correspondientes.

```ts
import '@univerjs-pro/embed/facade'

const block = univerAPI.createEmbed({
  host: {
    unitId: hostDocument.getId(),
    surface: univerAPI.Enum.FEmbedHostSurface.DocBlock,
  },
  content: {
    unitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
    ref: `#unit=${encodeURIComponent(budgetWorkbook.getId())}&type=sheet`,
  },
})

const embeddedWorkbook = await block.loadAsync()
```

`createEmbed()` crea la relación y el ancla anfitriona. `loadAsync()` carga al niño Unidad y devuelve su Facade. `displayTarget` selecciona la hoja de trabajo inicial, página de diapositivas, o vista de tabla relacional. El [guía de la incrustación](/guides/fundamentals/features/embed) cubre plugins, estilos, locales y cargadores. [Embed Facade](/reference/facade/embed) cubre las otras superficies y métodos.

## Persistencia, colaboración y alcance [#scope]

- El host Snapshot mantiene las referencias, la colocación y la configuración de visualización, pero no empaqueta el último contenido del niño automáticamente. La eliminación de un bloque no elimina el documento del niño.
- Server SDK ofrece instantáneas infantiles y los servicios de colaboración que los acompañan. Con `@univerjs-pro/collaboration-embed`, el navegador carga al niño y se une a su sesión de colaboración.
- La aplicación resuelve referencias, carga datos y autoriza el acceso. Ser capaz de abrir el host no otorga por sí mismo derechos de edición sobre el niño.
- Los tipos de Hoja, Doc, Diapositiva, Tabla Relacional y Canvasas se pueden incrustar entre sí. PDF, incrustación del mismo tipo, y anidación más profunda están excluidos. Dentro de un tiempo de ejecución Univer, una unidad infantil puede pertenecer a sólo una incrustación activa.

Utilice [dos vías vinculantes](/overview/features/shared/binding) para conducir las propias entradas, métricas y gráficos de la aplicación desde una hoja de cálculo. Use Embed Block cuando necesite el editor del producto del niño.
