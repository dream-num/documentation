Los comentarios mantienen la discusión junto al contenido. Un revisor puede preguntar por un valor, párrafo o gráfico; el autor responde en el mismo hilo y otros participantes aportan contexto sin repartir la conversación entre chats externos.

## De la pregunta a la decisión [#review-workflow]

1. **Vincule la pregunta** a una celda, texto seleccionado, registro, elemento o posición de página, conservando la referencia al contenido.
2. **Converse en un hilo** formado por un comentario raíz y respuestas, con autores, fechas y texto.
3. **Resuelva o reabra** tras los cambios. Reabra el hilo si requiere seguimiento, conservando la conversación.

El panel permite filtrar todos los hilos, pendientes, resueltos o relacionados con el usuario actual. Resolver no elimina la discusión: la decisión puede consultarse después.

## Comentarios y anotaciones por producto [#product-comments]

Las capturas usan un proyecto de lanzamiento Northstar en inglés. Se crearon con las API de Facade en editores reales para mostrar comentarios y anotaciones del frontend. Pulse una imagen para ampliarla.

### Sheets [#sheets]

Vincule las discusiones a celdas para confirmar previsiones, costes y aprobaciones junto al presupuesto. El ejemplo muestra varios hilos, respuestas consecutivas y un grupo resuelto. Use `range.addCommentAsync()`; los comentarios sobre imágenes, gráficos y formas requieren su integración de comentarios de dibujos.

### Docs [#docs]

Comente rangos de texto al revisar contratos, propuestas o fechas de lanzamiento. Las tarjetas conservan el fragmento citado y las decoraciones mantienen la ubicación durante la edición. El ejemplo discute la fecha, las métricas y la sustitución de un proceso anterior. Use `document.getTextRange(...).createCommentAsync()`.

### Slides [#slides]

Comente elementos o una posición libre de la diapositiva. Los comentarios de elementos referencian ID estables de cuadros de texto, imágenes o gráficos; los de posición usan coordenadas normalizadas de página. El ejemplo revisa objetivos y distribución. Use `slide.createElementCommentAsync()` y `slide.createPositionCommentAsync()`.

### Relational Tables [#bases]

Los comentarios se vinculan al ID del registro, sin depender del número de fila visible. Úselos para traspasos, seguimiento de clientes y aceptación. El seguimiento del lanzamiento muestra responsables, aprobaciones pendientes y marcas de comentarios junto a los registros. Use `record.createCommentAsync()`.

![Comentarios de Relational Tables: registros, marcas de comentarios y discusiones de traspaso](/assets/features/comments/bases.png)

### Canvases [#boards]

Adjunte comentarios a elementos, como formas, o a una posición del tablero. Los primeros referencian el objeto; los segundos conservan coordenadas del tablero. El ejemplo trata investigación de clientes, traspaso de ingeniería y riesgos del lanzamiento. Use `board.createElementCommentAsync()` y `board.createPositionCommentAsync()`.

### PDF: anotaciones de página [#pdfs]

PDF ofrece actualmente anotaciones de página: resaltado, subrayado, tachado, líneas onduladas y tinta. Son objetos PDF persistibles, distintos de los hilos con respuestas y resolución anteriores. El ejemplo resalta la fecha, marca criterios de aceptación y tacha un paso de aprobación antiguo. Use `page.insertAnnotation()`.

## Integración [#integration]

**Frontend**: registre los plugins de comentarios y UI del producto e importe las entradas `/facade` comunes y específicas. Los métodos del producto establecen anclajes; `replyCommentAsync()`, `updateCommentAsync()` y `resolveCommentAsync()` gestionan las operaciones posteriores. Use `resolved: false` para reabrir. PDF tiene una API de anotaciones independiente.

**Discusiones compartidas**: añada Comment Service, Comment Endpoint y un adaptador de base de datos independiente junto a la colaboración básica y configure la fuente de datos remota del frontend. El documento principal conserva los anclajes que cambian con el contenido; Comment Service guarda texto, respuestas y estado, y publica actualizaciones en las salas del documento. Consulte los [paquetes de comentarios](/server/collaboration/packages#thread-comment) y el [ejemplo Comments](/server/collaboration/examples#comments).

El permiso de comentar puede configurarse independientemente de la edición. Consulte [permisos y autorización](/overview/features/shared/permissions) para la identidad de la aplicación y la autorización del servidor.
