Worktreeは、人やエージェントが一緒に編集できるOfficeコンテンツの隔離されたドラフトを提供します。エージェントは、予算を見直し、データを再構成したり、主要な文書を編集し続けながら、簡単な書き換えを行うことができます。これはトランクと呼ばれるものです。変更がトランクに達する前に、ドラフトは検証され、レビューされます。

分離は、Git の作業ディレクトリではなく、文書の内容とその変更に適用されます。単一のタスクは、ワークブック、ドキュメント、プレゼンテーションなど、いくつかの [ユニット](/guides/sheets/getting-started/quickstart#unit) にスパンすることができます。

## 分離の仕組み：共通の基準から進む [#isolation]

Worktreeが既存のユニット用に作成されると、ユニットの現在のトランクリビジョンが**ベースライン**として作成されるサービスレコード。そのリビジョンから始まり、独自のスナップショット、チェンジセット、リビジョン、プレゼンス、コラボレーションルームがあります。ドラフトで行われた編集はトランクに影響を与えません。

<Mermaid chart={"flowchart LR\n    A[\"作成時の trunk<br/>Baseline\"]\n    B[\"trunk の編集継続\"]\n    C[\"Worktree 下書き\"]\n    D[\"Ready · レビュー\"]\n    E[\"OT マージ\"]\n    F[\"trunk の新しい版\"]\n    A --> B\n    A --> C --> D\n    B --> E\n    D --> E --> F"} />

| 概念 | 役割 |
| --- | --- |
| Baseline | ドラフトが起動したトランクバージョンは、比較とマージに使用されます。 |
| Draft head | 最新確認の草案修正。 原稿の提出は、転送します。 |
| Ready head | 見直しとマージされるものを定義する凍結した草案の修正。 |

トランクとドラフトは独立して進めます。各サイドにリビジョンすると、別の投稿シーケンスが形成されますので、より高い番号はどのコンテンツが新しいかを示すものではありません。ドラフトを引っ張って、ドラフトの自身の変更を同期させます。新しいトランクの編集は、レビューの下にバージョンを入力しません。マージプレビューとマージ自体は2を再構成します。

## AI SDK が同じ下書きに接続する仕組み [#ai-sdk]

AI SDKのCollaboration Runtimeは1つのユニットのスナップショット、チェンジセット、リビジョンを管理します。 Server SDK側では、Worktreeサービスは作成、ライフサイクル、マージを所有しています。 ランタイムは、Worktreesで動作する2番目の編集エンジンを必要としません。

アプリケーションは、`worktreeID + unitID`をドラフトのスナップショット、送信、WebSocketおよびセッションチケットURLに解決し、ランタイムにそれらを渡します。 同じ検査と編集ツールは、トランクまたはドラフトのいずれかをターゲットにすることができます。

<Mermaid chart={"flowchart LR\n    A[\"Agent / 業務 CLI\"]\n    B[\"人による Web レビュー\"]\n    C[\"アプリの対象アダプター\"]\n    D[\"Worktree Endpoint\"]\n    E[\"同じ下書き Unit\"]\n    A --> C\n    B --> C\n    C --> D --> E"} />

1つのユニットIDは、トランクと複数のワークツリーに一度に存在することができます。 ターゲットには、それが住んでいるWorktreeを含める必要があります。 検査、実行、スクリーンショット、およびWebプレビューは、すべての同じターゲットを使用する必要があります。 それ以外のツールは、ドラフトから読み、トランクに書き込むことができます。 Webクライアントは、それが一致するコラボレーション構成と同じ草案をロードします。

| 担当 | 責務 |
| --- | --- |
| Web SDK | 共有コンテンツエンジン、ヘッドレスエージェントの操作とブラウザでの編集。 |
| Server SDK | 下書き分離、変更・版の保存、状態、OT マージ。 |
| AI SDK | 互換性のあるランタイム、検査、API のルックアップ、ファサード実行、およびビジュアルチェック。 |
| アプリケーション | モデル選択、ターゲットマッピング、アイデンティティ、権限、タスク、およびレビューUI。 |

## Agent の編集から引き渡しまで [#agent-workflow]

アプリケーションは、各エージェントに独自のWorktreeを与えることによって、並行してタスクを実行することができます。各エージェントは、そのドラフトを編集し、結果を確認し、それを準備します。その後、一回草案をレビューし、より多くの作業を必要とする草案を再オープンし、承認された草案を現在のトランクにマージします。

<Mermaid chart={"flowchart TB\n    TRUNK[\"メイン文書 · Trunk\"]\n    subgraph PARALLEL[\"複数 Agent が並行作業\"]\n        direction LR\n        AGENT_A[\"Agent A<br/>Worktree A<br/>編集と検証\"]\n        AGENT_B[\"Agent B<br/>Worktree B<br/>編集と検証\"]\n        AGENT_C[\"Agent C<br/>Worktree C<br/>編集と検証\"]\n    end\n    REVIEW[\"人によるレビュー<br/>下書きとマージ案\"]\n    MERGE[\"個別に Merge<br/>最新 trunk へ\"]\n    RESULT[\"trunk の新しい版\"]\n    TRUNK --> AGENT_A\n    AGENT_A -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_B\n    AGENT_B -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_C\n    AGENT_C -->|\"Ready\"| REVIEW\n    REVIEW -->|\"承認\"| MERGE\n    REVIEW -.->|\"対象の下書きを Reopen\"| PARALLEL\n    MERGE --> RESULT"} />

1. Worktreeを作成し、それをロードします。 タスクがカバーするユニットを選択し、Worktreeターゲットを接続し、最新のコンテンツをプルします。
2. 構造を点検し、必要に応じてAPIを調べ、ファサードによる変化をします。
3. ドラフトに提出し、データと計算結果を読み、必要に応じてスクリーンショットをキャプチャします。 スライドは、Layout Lintを実行することもできます。 チェックが問題を報告する場合、もう一度ドラフトを編集します。
4. Mark Ready. これは、各ユニットの草案の修正を凍結し、編集は、レビューが完了するまで停止します。
5. レビュー。 受け入れられた草案をマージします。 人やエージェントが再び編集する前に、ドラフトに戻ります。 必要のない草案を破棄します。

| 操作 | 結果 |
| --- | --- |
| `runtime.commit()` | ドラフトだけに提出し、ドラフトのリビジョンを前進させます。 |
| `markReady()` | 何もトランクにマージすることなく、レビューバージョンを凍結します。 |
| `reopenWorktree()` | Ready から Draft へ移行するので、編集は続行できます。 |
| `mergeWorktree()` | 冷凍ドラフトは、ユニット単位でトランクに変化します。 |

コミット、レディ、マージは3つの別々の操作です。 ドラフトが準備完了したら、その人が、エージェントが再オープンするまで編集できるわけではありません。 ランタイムとCLIの関係については、[AI SDKワークフロー](/ai/worktree)を参照してください。

## マージ：最新 trunk に変更を適用する [#merge]

トランクから来たユニットでは、サービスが**準備の頭部へのベースライン**から変更点を読み取り、そのミューテーションを収集し、トランクコラボレーションサービスを通じてそれらを提出します。 ベースラインが進んでいると、[オタク](/overview/features/shared/collaboration)は、サービスが新しいリビジョンを確認する前に、後でトランクの編集に対するこれらのミューテーションを変換します。

そのため、編集を適用します。最新の文書を古いスナップショットに置き換えません。変換できる同時変更は再調整されます。変換できない変更、または適用しない変更は、アプリケーションが処理する競合として返されます。 OTは、すべてのビジネスの不一致を解決しません。

Worktree内で作成されるユニットは、マージするトランクベースラインはありません。マージは、チェンジセット全体の履歴をコピーすることなくトランクで作成します。

## 変更内容とマージ結果を確認する [#review]

- [比較する](/overview/features/shared/compare)を使用して、変更されたものを見るには、完全なベースライン状態とReadyドラフト状態を比較します。
- 特定の瞬間に何が起きるかを見るには、Ready の後の `evaluateUnitMerge()` を呼び出します。トランクが進んでいると、分離されたランタイムは、現在のトランクに OT トランスフォームされた候補を適用し、読み取り専用のプレビューを生成します。それは変更を提出し、トランクやドラフトの両方を変更しません。

プレビューでは、要求される瞬間に状態を記述します。トランクは後方を変えることができ、実際のマージは実行時に見つけた状態から動作します。複数のユニットをマージすることは、原子トランザクションの1つではありません。もし1つのユニットが失敗した場合は、既にマージしているユニットはマージされ続ける。各ユニットの結果を表示し、個々の障害を処理します。

## 導入と対象 [#integration]

Worktreeクライアント、サービス、エンドポイント、データベースアダプタを連携コアと組み合わせます。ストレージを別々に保ち、セッションチケットストアをトランクで共有します。アプリケーションは、ドラフトアクセスとトランクが別々に書き込みます。分離は、それ自体でアクセスを許可しません。

シート、Doc、スライド、キャンバス、およびリレーショナルテーブルがサポートされています。 PDFは含まれていません。 [例)](/server/collaboration/examples#worktree)、[拡張モジュール](/server/collaboration/packages#worktree)および[エージェントの統合ガイド](/ai/worktree)は、開始点を提供します。
