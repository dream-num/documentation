Worktree는 사람들과 대리인이 아직도 함께 편집할 수 있는 사무실 내용의 고립된 초안을 제공합니다. 대리인은 예산을 개정할 수 있고, 자료를 재구성하거나, 간선이라고 칭하는 사람들 동안 간선을 편집하는 동안 간략한 간결을 재쓰기할 수 있습니다. 초안은 그것의 변화가 간선에 도달하기 전에 검증되고 검토됩니다.

isolation은 문서 내용과 그 변경에 적용되며 Git 작업 디렉토리에 아닙니다. 단일 작업은 여러 [단위 단위](/guides/sheets/getting-started/quickstart#unit)를 경작 할 수 있습니다. 예를 들어 워크북, 문서 및 프레젠테이션.

## 격리 원리: 같은 기준에서 독립적으로 진행 [#isolation]

Worktree는 기존 단위를 위해 생성될 때, 서비스 기록은 **기본 정보**로 단위의 현재 간선 개정을 기록합니다. 초안은 그 개정에서 시작하고 그것의 자신의 스냅샷, 변경, 개정, 존재 및 협력 방이 있습니다. 초안에서 한 편집은 간선에 영향을 미치지 않습니다.

<Mermaid chart={"flowchart LR\n    A[\"생성 시 원본<br/>Baseline\"]\n    B[\"원본 편집 지속\"]\n    C[\"Worktree 초안\"]\n    D[\"Ready · 검토\"]\n    E[\"OT 병합\"]\n    F[\"원본 새 버전\"]\n    A --> B\n    A --> C --> D\n    B --> E\n    D --> E --> F"} />

| 개념 | 역할 |
| --- | --- |
| Baseline | 초안 버전은 비교 및 수은에 사용되어 시작되었습니다. |
| Draft head | 새로운 확인 된 초안 개정. 초안 제출은 앞으로 이동. |
| Ready head | 검토하고 합병되는 것을 정의하는 냉동 초안 개정. |

트렁크와 초안은 독립적으로 발전합니다. 각 측면에 대한 개정은 별도의 제출 순서로, 그래서 더 높은 수는 내용이 더 새로운 것을 나타내지 않습니다. 초안을 동기화하는 것은 초안의 자신의 변경을. 새로운 트렁크 편집은 자신의 검토 아래 버전을 입력하지 않습니다; 병합 미리보기와 병합 자체는 두 가지를 재구성합니다.

## AI SDK가 같은 초안을 연결하는 방식 [#ai-sdk]

AI SDK의 Collaboration Runtime는 1개의 단위의 스냅샷, 변경 집합 및 개정을 처리합니다. Server SDK 측에, Worktree 서비스는 창조, 수명주기 및 merging를 소유합니다. 런타임은 Worktrees와 일하기 위하여 두번째 편집 엔진을 요구하지 않습니다.

이 응용 프로그램은 `worktreeID + unitID`를 초안의 스냅 샷, 제출, WebSocket 및 세션 티켓 URL로 수정하여 Runtime에 전달합니다. 동일한 검사 및 편집 도구는 트렁크 또는 초안을 대상으로 할 수 있습니다.

<Mermaid chart={"flowchart LR\n    A[\"Agent / 업무 CLI\"]\n    B[\"사용자 Web 검토\"]\n    C[\"앱 대상 어댑터\"]\n    D[\"Worktree Endpoint\"]\n    E[\"같은 초안 Unit\"]\n    A --> C\n    B --> C\n    C --> D --> E"} />

하나의 단위 ID는 트렁크에 존재하고 한 번에 여러 워크 트리에서. 대상은 Worktree를 포함해야, 이는 생명, 검사, 실행, 스크린 샷 및 웹 미리보기는 모두 같은 대상을 사용해야합니다. 그렇지 않으면 도구는 초안에서 읽고 트렁크로 쓸 수 있습니다. 웹 클라이언트는 그것을 일치시키는 협업 구성과 동일한 초안을로드합니다.

| 구성 요소 | 역할 |
| --- | --- |
| Web SDK | 공유 콘텐츠 엔진, 헤드리스 에이전트 작업 및 브라우저에서 편집을위한. |
| Server SDK | 초안 격리, 변경·버전 저장, 상태, OT 병합. |
| AI SDK | 구성 가능한 실행 시간, 검사, API 조회, Facade 실행 및 시각 검사. |
| 앱 | 모델 선택, 대상 매핑, 정체성, 권한 부여, 작업 및 검토 UI. |

## Agent 편집에서 전달까지 [#agent-workflow]

이 응용 프로그램은 각 에이전트 자신의 Worktree를 제공 하 여 병렬에서 작업을 실행할 수 있습니다. 각 에이전트는 그 초안을 편집 하 고 결과를 표시 하 고 준비를 표시 합니다. 한 사람이 한 번에 초안을 검토 하 고 더 많은 작업을 필요로 하는 초안을 다시 열고, 허용 된 초안을 현재의 트렁크에 병합.

<Mermaid chart={"flowchart TB\n    TRUNK[\"원본 · Trunk\"]\n    subgraph PARALLEL[\"여러 Agent의 병렬 작업\"]\n        direction LR\n        AGENT_A[\"Agent A<br/>Worktree A<br/>편집과 검증\"]\n        AGENT_B[\"Agent B<br/>Worktree B<br/>편집과 검증\"]\n        AGENT_C[\"Agent C<br/>Worktree C<br/>편집과 검증\"]\n    end\n    REVIEW[\"사용자 검토<br/>초안과 미리보기\"]\n    MERGE[\"개별 Merge<br/>최신 원본에 병합\"]\n    RESULT[\"원본 새 버전\"]\n    TRUNK --> AGENT_A\n    AGENT_A -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_B\n    AGENT_B -->|\"Ready\"| REVIEW\n    TRUNK --> AGENT_C\n    AGENT_C -->|\"Ready\"| REVIEW\n    REVIEW -->|\"승인\"| MERGE\n    REVIEW -.->|\"해당 초안 Reopen\"| PARALLEL\n    MERGE --> RESULT"} />

1. Worktree를 만들고로드하십시오. 작업 덮개가 있는 단위를 선택하고 Worktree 표적을 연결하고 최신 콘텐츠를 끌어냅니다.
2. 검사와 구조 검사를 검사하고, API를 필요에 따라 파악하고, Facades를 통해 변화를 만듭니다.
3. 초안에 제출하면 데이터와 계산 결과를 다시 읽고 필요한 경우 스크린 샷을 캡처 할 수 있습니다. 슬라이드는 Layout Lint를 실행할 수 있습니다. 체크가 문제를 보고하면 다시 초안을 편집합니다.
4. Mark Ready. 이 각 단위의 초안 개정을 동결하고, 검토가 완료 될 때까지 편집 중지합니다.
5. 검토. 받아 들여진 초안을 병합합니다. 한 사람 또는 에이전트가 다시 편집하기 전에 초안을 다시 엽니다. 필요한 초안을 버리십시오.

| 작업 | 효과 |
| --- | --- |
| `runtime.commit()` | 초안에 제출하고, 초안 개정을 진행합니다. |
| `markReady()` | 트렁크에 아무것도 merging없이 검토 버전을 동결합니다. |
| `reopenWorktree()` | 준비된 뒤에서 초안으로 가져가서 편집이 계속될 수 있습니다. |
| `mergeWorktree()` | 얼어붙은 변화는 트렁크로, 단위로 단위로 변화합니다. |

Commit, Ready 및 Merge는 세 가지 별도의 작업입니다. 초안이 준비되면 사람이거나 에이전트가 다시 열릴 때까지 편집 할 수 없습니다. Runtime과 CLI 사이의 관계를 위해 [AI SDK 워크플로우](/ai/worktree)를 참조하십시오.

## 최신 원본에 변경을 병합하는 원리 [#merge]

트렁크에서 온 단위를 위해, 서비스는 **준비된 머리에 baseline**에서 초안 변경을 읽고, 그들의 mutations를 수집하고, 간선 협업 서비스를 통해 제출합니다. 트렁크가 기본으로 발전 한 경우 [₢ 킹](/overview/features/shared/collaboration)는 서비스 전에 나중에 트렁크 편집에 대한 그 mutations을 새로운 개정을 확인합니다.

따라서 합병은 편집을 적용합니다; 이전 스냅 샷으로 최신 문서를 대체하지 않습니다. 변환 할 수있는 동시 변경은 재구성됩니다. 변환 할 수없는 변경, 또는 더 이상 적용되지 않는 변경은 처리 할 응용 프로그램에 대한 충돌로 반환됩니다. OT는 모든 사업 불분명에 침입하지 않습니다.

Worktree 내부에 생성 된 단위는 트렁크 기반이 없습니다. 합병은 전체 초안 변경 기록을 복사하지 않고 트렁크에서 만듭니다.

## 수정 내용과 병합 결과 검토 [#review]

- 변경된 내용을 보려면 [더 보기](/overview/features/shared/compare)를 사용하여 준비된 초안 상태와 비교하십시오.
- 메르세데스가 주어진 순간에 무슨 일이 할지 확인하려면, 준비 후 `evaluateUnitMerge()`로 전화하십시오. 트렁크가 고급 때, 격리 된 런타임은 현재 트렁크에 OT 전환 후보를 적용하고 읽기 전용 미리보기를 생성합니다. 그것은 변경 사항을 제출하고 트렁크와 초안을 수정하지 않습니다.

미리 보기가 요청된 순간에 국가를 설명합니다. 트렁크는 나중에 변경할 수 있고, 실제적인 Merge는 그것이 실행될 때 발견합니다. 몇몇 단위를 합병하는 것은 1개의 원자 거래가 아닙니다, 그래서 1개의 단위가 실패한 경우에, 이미 합병한 단위는 병합됩니다. 각 단위를 위한 결과를 표시하고 개별적으로 취급 실패를 취급하십시오.

## 통합과 범위 [#integration]

Worktree 클라이언트, 서비스, 엔드포인트 및 데이터베이스 어댑터를 공동 작업 코어와 결합합니다. 별도의 저장을 유지하고, 트렁크와 함께 한 세션 티켓 저장소를 공유하십시오. 응용 프로그램은 초안 액세스 및 트렁크를 별도로 작성합니다. 고립은 자체로 액세스 권한을 부여하지 않습니다.

시트, 도크, 슬라이드, 캔버스 및 관계 테이블이 지원됩니다. PDF는 포함되어 있지 않습니다. [이름 *](/server/collaboration/examples#worktree), [확장 모듈](/server/collaboration/packages#worktree) 및 [에이전트 통합 가이드](/ai/worktree)는 시작점을 제공합니다.
