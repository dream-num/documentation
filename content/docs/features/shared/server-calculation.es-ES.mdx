Headless Univer es el tiempo de ejecución de contenidos Univer sin el editor interactivo UI. Comparte modelos de contenido, comandos, cálculos y APIs Facade con el editor del navegador. Una aplicación puede ejecutarlo en Node.js para procesar contenido allí, o en un navegador para tareas que no necesitan una interfaz de usuario. Sus capacidades dependen del producto registrado y de los plugins de características.

El tiempo de ejecución JavaScript/TypeScript descrito en esta página y `univer-rs` son implementaciones separadas. `univer-rs` es compatible con el cálculo del lado del servidor y la conversión de archivos, y participa en flujos de trabajo sin cabeza sobre las mismas instantáneas.

## Qué permite Headless [#headless-capabilities]

- Leer y modificar contenido y estructura. Crear o cargar una instantánea Univer, utilice APIs Facade para leer y editar celdas, párrafos, páginas, objetos gráficos o registros, y luego guardar la instantánea actualizada. Estas operaciones soportan el procesamiento por lotes, la generación de datos, la inspección de contenidos y la automatización de agentes.
- Ejecute la lógica comercial registrada. Los plugins de cálculo, clasificación, filtración, validación y pivote están disponibles, y las aplicaciones pueden modificar recursos como imágenes, gráficos, formas y comentarios. Las operaciones disponibles dependen del producto registrado y de los plugins de características y sus dependencias.
- Conectarse a otros servicios. Agregue el cliente de colaboración Node.js para cargar Unidades colaborativas, enviar cambios y esperar a sincronización. Combine módulos de conversión Server SDK con el tiempo de ejecución para importar y exportar archivos de Office.

Headless no proporciona al editor UI: no se incluyen menus, barras de herramientas, diálogos, interacción con el ratón o el teclado, capturas de pantalla o impresión. Persistencia, autenticación, un servidor de colaboración y conversión de archivos tampoco están incluidos. `save()` devuelve una instantánea Univer; no escribe a una base de datos o exporta XLSX, DOCX, o PDF. Imágenes y controles de diseño visual requieren una capa de renderización separada [Tiempo de ejecución](/ai/visual-inspection),

## Qué paquetes pertenecen a Headless [#headless-packages]

Estos paquetes proporcionan casos, modelos de contenido, comandos y operaciones de contenido básicos.

- `@univerjs/docs`

### Red, procesos de cálculo y colaboración

Agrega la infraestructura sólo cuando sea necesario. `@univerjs/network` y `@univerjs/rpc-node` proporcionan redes y Node.js procesos de cálculo, y `@univerjs-pro/license` maneja la integración de licencias. `@univerjs-pro/collaboration`, `@univerjs-pro/collaboration-client`, y `@univerjs-pro/collaboration-client-node` juntos forman un cliente de colaboración sin cabeza, no un servidor de colaboración. Trabajar con instantáneas locales no requiere un servicio de colaboración.

### Paquetes fuera del runtime de contenido puro

- `@univerjs/ui`, `@univerjs/design`, y los `*-ui` paquetes para un producto o característica, como `@univerjs/sheets-ui`, `@univerjs/docs-ui`, y `@univerjs-pro/slides-ui`, proporcionan IU, renderizando la integración o la interacción. No añadirlos a una configuración de Node.js que sólo procesa el contenido.
- `@univerjs/sheets-find-replace` y `@univerjs/sheets-crosshair-highlight` no tienen sufijo `-ui` pero todavía dependen de `@univerjs/sheets-ui`, por lo que un nombre de paquete por sí solo no implica que son plugins sin cabeza.
- Los presets predeterminados `@univerjs/preset-sheets-core` y `@univerjs/preset-docs-core` registran plugins de interfaz de usuario y no son presets sin cabeza Node.js. En ese caso, utilice el modo plugin para seleccionar dependencias de capa de contenido explícitamente.

**`@univerjs/engine-render` requiere una consideración separada.** Los ejemplos actuales de Node.js lo registran para suministrar dependencias compartidas como la gestión de renderizado. Registrar el plugin no crea un Canvas o montar un editor. Puede aparecer en una composición sin cabeza, pero la medición de fuentes y API de captura de pantalla todavía necesitan un entorno de renderización adecuado. Por lo tanto, no cada API en el paquete es utilizable en Node.js puro.

**Facade es una API de operación, no un adaptador de entorno.** Para cada plugin de contenido en uso, importa su extensión `/facade`, y registra los plugins que implementan las capacidades requeridas. Extensiones UI como `@univerjs/ui/facade` y `@univerjs/sheets-ui/facade` todavía requieren UI, y así hacen los menús, desplazamiento, y las interacciones de selección visual que proporcionan. Examinar las dependencias del plugin y la ruta de llamada real en lugar de confiar en un nombre de paquete API.

Las composiciones de plugin ejecutables aparecen en el [Hojas Guía sin cabeza](/guides/sheets/getting-started/node) y el [Docs Guía sin cabeza](/guides/docs/getting-started/node).

## Cálculo inmediato en el navegador y por revisión en el servidor [#precalcular-en-el-servidor-y-mostrar-rápidamente]

Los motores de Fórmula funcionan tanto en el frontend como en el servidor. El frontend responde a medida que el usuario edita, y el servidor calcula una revisión de contenido capturada cuando genera una instantánea o procesa un archivo.

- Durante la edición, el navegador calcula las fórmulas afectadas localmente, opcionalmente en un Trabajador, y muestra los resultados inmediatamente. El servicio de colaboración registra estos cambios de contenido y los sincroniza.
- Cuando se genera una instantánea, la política de instantáneas del servidor inicia el flujo de trabajo de ahorro. El servidor captura la revisión de contenido para esa operación, la calcula con `univer-rs`, y guarda el contenido y los resultados de esa revisión juntos.
- Cuando se reabierte el documento, el frontend reutiliza los resultados válidos en la instantánea, aplica los cambios posteriores, y continúa calculando, lo que evita una recalculación completa.

<Mermaid chart={"flowchart LR\n    F[\"Edición en el navegador<br/>Cálculo inmediato\"]\n    C[\"Sincronización<br/>Cambios confirmados\"]\n    R[\"Cálculo Rust<br/>Revisión N\"]\n    S[\"Guardar snapshot<br/>saveSnapshot\"]\n    F <--> C\n    C -->|\"Al generar el snapshot\"| R\n    R --> S"} />

**Los cambios de contenido se sincronizan continuamente. El cálculo del servidor funciona como parte de la generación de instantáneas, y los resultados se guardan para esa revisión de contenido.**

En primera carga, la aplicación configura cómo el cálculo inicial utiliza los resultados guardados:

- `WHEN_EMPTY`: reutilizar los valores guardados y calcular solo los resultados que faltan.
- `NO_CALCULATION`: omitir el cálculo inicial; la aplicación proporciona los resultados.
- `FORCED`: recalcular todas las fórmulas para actualizar los resultados.

Estas opciones sólo rigen la carga inicial. Después de la carga, la edición continúa calculando en el frontend, y el servidor calcula a la demanda cuando genera una instantánea o archivos de procesos versionados. Ver [configuración de fórmula](/guides/sheets/features/core/formula), [colaboración](/server/collaboration/overview) y [conversión de archivo](/overview/features/shared/file-conversion).

## Fórmulas matriciales y resultados desbordados

Dentro de las funciones y formatos soportados, Rust sigue la forma de matriz y semántica de derrame de Excel. Devuelve los valores calculados junto con el rango de anclaje y derrame, y maneja tanto los arrays dinámicos como los rangos declarados de fórmulas de matriz heredadas.

Por ejemplo, `=SEQUENCE(3,2)` en una celda `A1` vacía produce:

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

La fórmula permanece en `A1`, y los resultados ocupan `A1:B3`. Cuando el array se contrae, los valores de derrame anteriores se despejan. Cuando se bloquea un derrame, el resultado es `#SPILL!` . El navegador, un agente, y el oleoducto de exportación pueden reutilizar la instantánea calculada.

Las reglas de función y rango correspondientes están en [apoyo a las fórmulas](/guides/sheets/features/core/formula) y [Excel comportamiento de la matriz](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior).

## Conectar ejecución y verificación con un agente

Mantenga el modelo existente, la conversación y la orquestación de herramientas. Herramientas AI SDK exponen operaciones de contenido de Office a ese agente:

1. Inspeccione la estructura y lea el contenido objetivo.
2. Aplicar los cambios Facade y ejecutar los cálculos necesarios en el tiempo de ejecución sin cabeza.
3. Esperar el cálculo y el compromiso para ser confirmado, luego leer el estado actualizado de nuevo.
4. Revise los valores y la estructura, y agregue capturas de pantalla o cheques de diseño cuando se requiere verificación visual.

Utilice [operaciones de](/ai/content-operations) y [inspección visual](/ai/visual-inspection) juntos. Cuando una persona necesita revisar el trabajo, coloque las ediciones en un [Worktree](/ai/worktree) primero, compare y fusione. [Univer CLI](/overview/examples/cli) demuestra cómo montar estas capacidades en una aplicación que un agente puede conducir.
