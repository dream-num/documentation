Headless Univer es el runtime de contenido de Univer sin interfaz de edición interactiva. Comparte modelos de contenido, comandos, cálculos y API Facade con el editor web. Puede procesar contenido en Node.js o ejecutar tareas sin interfaz en un navegador. Las capacidades disponibles dependen de los plugins de producto y función registrados.

El runtime de contenido JavaScript/TypeScript descrito aquí y `univer-rs` son implementaciones distintas. El segundo se ocupa del cálculo del servidor y la conversión de archivos; pueden combinarse alrededor de las mismas instantáneas.

## Qué permite Headless [#headless-capabilities]

- **Leer y modificar contenido y estructura**: crear o cargar instantáneas Univer, usar Facade para operar sobre celdas, párrafos, páginas, objetos gráficos o registros y guardar la instantánea actualizada. Sirve para procesos por lotes, generación de datos, inspección y automatización con agentes.
- **Ejecutar la lógica registrada**: calcular fórmulas, ordenar, filtrar, validar, trabajar con tablas dinámicas y modificar recursos de imágenes, gráficos, formas o comentarios. Las operaciones dependen de los plugins del producto y sus dependencias.
- **Conectar servicios**: añadir el cliente de colaboración Node.js para cargar Units compartidas, enviar cambios y esperar su confirmación. Los módulos de conversión de Server SDK permiten importar y exportar archivos Office.

Headless no proporciona por sí mismo menús, barras de herramientas, diálogos, interacción con ratón o teclado, capturas ni impresión. Tampoco añade automáticamente persistencia, autenticación, servidor de colaboración ni conversión. `save()` devuelve una instantánea Univer; no escribe en una base de datos ni exporta XLSX, DOCX o PDF. Las capturas y comprobaciones visuales requieren un [runtime de renderizado](/ai/visual-inspection) separado; un navegador headless sigue ejecutando la capa de renderizado.

### Paquetes fuera del runtime de contenido puro

- `@univerjs/ui`, `@univerjs/design` y los paquetes `*-ui` de productos o funciones, como `@univerjs/sheets-ui`, `@univerjs/docs-ui` y `@univerjs-pro/slides-ui`, proporcionan interfaz, integración de renderizado o interacción. No los añada a una configuración de contenido en Node.js puro.
- `@univerjs/sheets-find-replace` y `@univerjs/sheets-crosshair-highlight` dependen de `@univerjs/sheets-ui` aunque no tengan el sufijo `-ui`.
- Los presets predeterminados `@univerjs/preset-sheets-core` y `@univerjs/preset-docs-core` registran plugins UI. No son presets Headless para Node.js; use el modo plugin para seleccionar las dependencias de contenido.

**Considere `@univerjs/engine-render` por separado.** Los ejemplos actuales de Node.js lo registran para aportar dependencias compartidas, como la gestión del renderizado. Registrarlo no crea un Canvas ni monta un editor. Puede formar parte de Headless, pero dibujar, medir fuentes y capturar imágenes requiere un entorno de renderizado apropiado. No todas sus API funcionan en Node.js puro.

**Facade es una API de operaciones, no un adaptador de entorno.** Importe las extensiones `/facade` de contenido y registre los plugins que implementan las funciones. Las extensiones UI como `@univerjs/ui/facade` y `@univerjs/sheets-ui/facade`, incluidos menús, desplazamiento y selección visual, siguen necesitando UI. Compruebe dependencias y rutas de llamada, no solo nombres o disponibilidad de Facade.

Consulte las guías [Sheets Headless](/guides/sheets/getting-started/node) y [Docs Headless](/guides/docs/getting-started/node) para composiciones ejecutables.

## Cálculo inmediato en el navegador y por revisión en el servidor [#precalcular-en-el-servidor-y-mostrar-rápidamente]

El navegador y el servidor tienen motores de fórmulas. El navegador responde a la edición y el servidor calcula una revisión determinada del contenido al generar un snapshot o procesar un archivo.

- **Durante la edición**: el navegador calcula de forma incremental las fórmulas afectadas y muestra los resultados de inmediato, opcionalmente en un Worker. La colaboración registra y sincroniza los cambios de contenido.
- **Al generar el snapshot**: la política del servidor inicia el proceso de guardado y captura la revisión del contenido para esa operación. `univer-rs` calcula los resultados y después guarda juntos el contenido y los resultados de esa revisión.
- **Al volver a abrir**: el navegador reutiliza resultados válidos del snapshot, aplica los cambios posteriores y sigue calculando, reduciendo los cálculos completos repetidos.

<Mermaid chart={"flowchart LR\n    F[\"Edición en el navegador<br/>Cálculo inmediato\"]\n    C[\"Sincronización<br/>Cambios confirmados\"]\n    R[\"Cálculo Rust<br/>Revisión N\"]\n    S[\"Guardar snapshot<br/>saveSnapshot\"]\n    F <--> C\n    C -->|\"Al generar el snapshot\"| R\n    R --> S"} />

**Los cambios se sincronizan continuamente. El cálculo del servidor se ejecuta al generar un snapshot y los resultados se guardan para esa revisión del contenido.**

Ajusta el cálculo inicial a los resultados guardados:

- `WHEN_EMPTY`: reutilizar los valores guardados y calcular solo los resultados que faltan.
- `NO_CALCULATION`: omitir el cálculo inicial; la aplicación proporciona los resultados.
- `FORCED`: recalcular todas las fórmulas para actualizar los resultados.

Estas opciones controlan la carga inicial. La edición posterior sigue calculándose en el navegador; el servidor calcula bajo demanda al generar un snapshot por revisión o procesar archivos. Consulta la [configuración de fórmulas](/guides/sheets/features/core/formula), la [colaboración](/server/collaboration/overview) y la [conversión de archivos](/overview/features/shared/file-conversion).

## Fórmulas matriciales y resultados desbordados

Dentro de las funciones y formatos admitidos, Rust sigue las reglas de Excel para fórmulas matriciales y desbordamiento. Devuelve el ancla, el rango y los valores, con matrices dinámicas y rangos declarados de fórmulas matriciales heredadas.

Por ejemplo, `=SEQUENCE(3,2)` en una celda `A1` vacía produce:

| A | B |
| --- | --- |
| 1 | 2 |
| 3 | 4 |
| 5 | 6 |

La fórmula permanece en `A1` y los resultados ocupan `A1:B3`. Si la matriz se reduce, se borran los valores anteriores; si el rango está bloqueado, devuelve `#SPILL!`. El navegador, el agente y la exportación pueden reutilizar el snapshot calculado.

Consulta las [funciones admitidas](/guides/sheets/features/core/formula) y el [comportamiento matricial de Excel](https://support.microsoft.com/en-us/excel/dynamic-array-formulas-and-spilled-array-behavior).

## Conectar ejecución y verificación con un agente

Conserva el modelo, la conversación y la orquestación de tu agente. AI SDK le ofrece operaciones Office:

1. Inspeccionar la estructura y leer el contenido objetivo.
2. Aplicar cambios Facade y ejecutar los cálculos necesarios en el entorno headless.
3. Esperar el cálculo y la confirmación del envío y volver a leer el estado actualizado.
4. Verificar valores y estructura; añadir capturas o comprobaciones de diseño cuando haga falta.

Combina [operaciones de contenido](/ai/content-operations) e [inspección visual](/ai/visual-inspection). Para revisión humana, usa un [Worktree](/ai/worktree) antes de comparar y fusionar. [Univer CLI](/overview/examples/cli) muestra cómo ensamblar una aplicación para agentes.
