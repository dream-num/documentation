Comments keep discussions beside the content. Reviewers can question a value, paragraph, or graphic; authors reply in the same thread, and others add context without splitting the discussion across external chats.

## From question to decision [#review-workflow]

1. **Anchor the question** to a cell, selected text, record, element, or page position, preserving its content reference.
2. **Discuss in a thread** containing a root comment and replies, with authors, timestamps, and comment text.
3. **Resolve or reopen** after making changes. Reopen a thread when follow-up is needed while retaining the discussion.

The comment panel can filter all, unresolved, resolved, or discussions involving the current user. Resolving a thread does not delete it; the decision remains available for review.

### Sheets [#sheets]

Anchor discussions to individual cells to confirm forecasts, cost details, and approvals beside the budget. The example shows several threads, consecutive replies, and a resolved section. Use `range.addCommentAsync()` for cell comments; comments on images, charts, and shapes require their drawing-comment integration.

### Docs [#docs]

Comment on selected text ranges when reviewing contract clauses, proposals, or launch dates. Comment cards retain the quoted text, and comment decorations maintain the anchor during text editing. The example discusses the release date, metric definitions, and replacing an old workflow. Use `document.getTextRange(...).createCommentAsync()`.

### Slides [#slides]

Comment on individual elements or place a comment at a free position on a slide. Element comments reference stable IDs for text boxes, images, charts, and other objects; position comments use normalized page coordinates. The example discusses launch targets and layout. Use `slide.createElementCommentAsync()` and `slide.createPositionCommentAsync()`.

### Relational Tables [#bases]

Comments reference record IDs, keeping a discussion tied to a business record rather than its visible row number. Use them for handoffs, customer follow-up, and acceptance reviews. The launch tracker shows owner discussions, pending approvals, and comment markers beside records. Use `record.createCommentAsync()`.

### Canvases [#boards]

Attach comments to elements such as shapes or leave a note at a specific board position. Element comments reference an object; position comments retain board coordinates. The example discusses customer research, engineering handoff, and launch risks in context. Use `board.createElementCommentAsync()` and `board.createPositionCommentAsync()`.

### PDF: page annotations [#pdfs]

PDF currently provides page annotations: highlights, underlines, strikeouts, squiggly lines, and ink. These are persistable PDF annotation objects, distinct from the replyable, resolvable threads above. The example highlights a launch date, marks acceptance criteria, and crosses out an old approval step. Use `page.insertAnnotation()`.

## Integration [#integration]

**Frontend**: register the product’s comment and UI plugins, and import the shared and product-specific comment `/facade` entries. Product methods establish anchors; shared APIs such as `replyCommentAsync()`, `updateCommentAsync()`, and `resolveCommentAsync()` handle subsequent discussion operations. Pass `resolved: false` to reopen a thread. PDF uses a separate annotation API.

**Shared discussions**: add Comment Service, Comment Endpoint, and an independent database adapter alongside core collaboration, then configure the remote frontend data source. The main document retains anchors that change with content; Comment Service stores text, replies, and resolution state and publishes comment updates to document rooms. See [comment packages](/server/collaboration/packages#thread-comment) and the [Comments example](/server/collaboration/examples#comments).

Comment permission can be configured independently of content editing. See [permissions and authorization](/overview/features/shared/permissions) for application identity and server-side authorization.
