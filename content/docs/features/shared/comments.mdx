Comments keep discussions next to the content. Reviewers can raise questions about a value, a paragraph, or a graphic, authors reply in the same thread, and other participants add context, so the discussion does not spread to external chat tools.

## From question to decision [#review-workflow]

1. **Anchor the question** to a cell, selected text, a record, an element, or a page position. The anchor retains a reference to the content it points to.
2. **Discuss it in a thread** consisting of a root comment and replies, each with its author, timestamp, and comment text.
3. **Resolve or reopen** the thread after making changes. Reopen a thread when follow-up is required; the earlier discussion remains intact.

The comment panel filters by all, unresolved, or resolved threads, or by discussions involving the current user. Resolving a thread does not delete it; the decision remains available for review.

### Sheets [#sheets]

A discussion anchored to a single cell allows a reviewer to confirm a forecast, a cost detail, or an approval directly beside the budget number. The example shows several threads, a run of consecutive replies, and a resolved section. Cell comments are added through `range.addCommentAsync()`; comments on images, charts, and shapes require the corresponding drawing-comment integration.

### Docs [#docs]

Select a text range and add a comment when reviewing contract clauses, proposal wording, or launch dates. Comment cards retain the quoted text, and comment decorations maintain the anchor while the surrounding text changes. The example discusses the release date, metric definitions, and the replacement of an old workflow. Call `document.getTextRange(...).createCommentAsync()`.

### Slides [#slides]

Comments can target a single element or a free position on a slide. Element comments reference stable IDs for text boxes, images, charts, and other objects; position comments use normalized page coordinates. The example discusses launch targets and layout. Call `slide.createElementCommentAsync()` and `slide.createPositionCommentAsync()`.

### Relational Table [#bases]

Comments reference record IDs, so a discussion remains tied to a business record rather than to its visible row number. They are used for handoffs, customer follow-up, and acceptance reviews. The launch tracker shows owner discussions, pending approvals, and comment markers beside records. Call `record.createCommentAsync()`.

### Canvases [#boards]

A comment can be attached to an element such as a shape, or left as a note at a specific board position. Element comments reference an object; position comments retain board coordinates. The example discusses customer research, engineering handoff, and launch risks in context. Call `board.createElementCommentAsync()` and `board.createPositionCommentAsync()`.

### PDF: page annotations [#pdfs]

PDF currently provides page annotations: highlights, underlines, strikeouts, squiggly lines, and ink. These are persistable PDF annotation objects, separate from the threads above that support replies and resolution. The example highlights a launch date, marks acceptance criteria, and crosses out an old approval step. Call `page.insertAnnotation()`.

## Integration [#integration]

**Frontend**: register the comment and UI plugins of the product, and import the shared and product-specific comment `/facade` entries. Product-specific methods establish anchors, while shared APIs such as `replyCommentAsync()`, `updateCommentAsync()`, and `resolveCommentAsync()` handle the discussion operations that follow. Pass `resolved: false` to reopen a thread. PDF uses a separate annotation API.

**Shared discussions**: add Comment Service, Comment Endpoint, and an independent database adapter alongside core collaboration, then configure the remote frontend data source. The main document retains anchors, which change with the content; Comment Service stores text, replies, and resolution state, and publishes comment updates to document rooms. See [comment packages](/server/collaboration/packages#thread-comment) and the [Comments example](/server/collaboration/examples#comments).

Comment permission can be configured separately from permission to edit content. For application identity and server-side authorization, see [permissions and authorization](/overview/features/shared/permissions).
