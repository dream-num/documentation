埋め込まれたブロックは、Univer製品を別の場所に置きます。プロジェクト文書は予算とタスクを保持することができ、スライドは作業スプレッドシートを運ぶことができ、キャンバスはノートと一緒に計画を提示することができます。埋め込まれたコンテンツは、独自のデータモデルとそのネイティブエディタを保持しているため、ブロックはフォーカスとメニューを子供ユニットに移動します。

## 仕組み：ホストと子 Unit [#principle]

**ホストユニット**は、ブロックの配置とサイズ、子供ユニットへの参照、およびデフォルトビューを保存します。 **チャイルドユニット** は、実際のセル、段落、またはレコードを保存します。 ブロックをロードすると、参照を解決し、子ユニットをロードし、ホスト内のエディタをマウントします。 A [ユニット](/guides/sheets/getting-started/quickstart#unit)では、ワークブック、ドキュメント、プレゼンテーション、リレーショナルテーブル、またはキャンバスにすることができます。

関係とコンテンツは別々に主張されます。 埋め込まれたスプレッドシート内のセルを編集すると、子シートが更新されます。 ブロックを移動または再サイズすることで、ホストに格納されているアンカーが更新されます

## 埋め込み可能な場所 [#locations]

| ホスト製品 | 配置場所 | 代表的な用途 |
| --- | --- | --- |
| Sheet | フローティングオブジェクトまたはワークブックタブ | 計算モデルの横にある、または別のタブのタスクデータベース。 |
| Doc | 本文ブロック | 一つのプロジェクトページ上の物語、予算、タスク。 |
| Slide | フローティングオブジェクトまたはプレゼンテーションページ | 結論の横にある編集可能なソースデータ。 |
| Relational Table | テーブル一覧の項目 | ビジネスデータベースにとどまるプロジェクトドキュメント。 |
| Canvases | キャンバスの浮動オブジェクト | 単一のキャンバス上のデータ、提案、およびディスカッション。 |

## 5 種類のホストの実例 [#examples]

以下の例は、Facade API を介して生成され、ブラウザでキャプチャされたため、インターフェイスは英語です。各ケースは独立した子ユニットを使用し、すべてのコンテンツと図はサンプルデータです。

### Sheet：計算と意思決定メモ [#sheet-host]

コントロールセンターの合計は、左に費やし、右側に完全なドキュメントを埋め込む。 その起動トラッカータブは、リレーショナルテーブルを開きます。 このレイアウトは、価格設定、操作、および1つの場所で前提、計算、および書面による決定を維持しなければならないワークブックを財務する。 最も近い等しいのは、[Excelにドキュメントオブジェクトをインサートする](https://support.microsoft.com/en-au/excel/insert-an-object-in-your-excel-spreadsheet)です。

![Doc と連動集計を含む Sheet ホスト](/assets/features/embed/sheet.png)

### Doc：予算とタスクを含むプロジェクトページ [#doc-host]

ボディには、Real Table の後に予算シートが含まれているため、リーダーはモデルを調べて、コンテキスト内のタスクを維持することができます。この配置は、予算がまだ公式のシートエンジンで実行され、タスクはReal Tableフィールドとビューを維持することを除いて、[Notionのインラインデータベース](https://www.notion.com/help/guides/full-page-vs-inline-databases)に似ています。

![Doc 本文内の予算 Sheet](/assets/features/embed/doc-sheet.png)

![同じ Doc 内のタスク Relational Table](/assets/features/embed/doc-base.png)

### Slide：レビュー画面の元データ [#slide-host]

1つのスライドは予算シート、タスクのリレーショナルテーブル、および式主導の予算メトリックを運びます。 相互作用は、[PowerPointのExcelを埋め込むこと](https://support.microsoft.com/en-gb/powerpoint/insert-and-update-excel-data-in-powerpoint)に匹敵します。 査読者は結論から始まり、編集可能なデータモデルに戻ることができます。 映像予算は$ 62,100に更新されています。

![予算、タスク、数式指標を含む Slide](/assets/features/embed/slide.png)

### Relational Table：データベース内の説明文書 [#base-host]

起動の簡単なドキュメントは、テーブルリストのタスクテーブルの横にある。CRM、プロジェクトトラッカー、または操作データベースでは、これにより、人々が構造化された作業と書かれたコンテキスト間で移動することができます。これはテーブルリストのエントリであり、各レコードの文書を自動的に作成しません。

![Relational Table のテーブル一覧から開いた Doc](/assets/features/embed/base.png)

### Canvases：議論のためのデータキャンバス [#board-host]

キャンバスは予算シート、提案書Doc、および式主導の支出の要約を組み合わせています。これは、ディスカッション中にソースデータとコンテキストを必要とするプロジェクトルーム、レビュー、および調査キャンバスに適しています。

![Sheet、Doc、数式集計を含む Canvases](/assets/features/embed/board.png)

## 数式の連動 [#formulas]

Embedding は、表示と編集をカバーします。計算は参照から来ます。ブロックをインサートすると、まとめ式は作成されません。そのため、クロスユニットの参照は最初に構成する必要があります。配置されると、Doc、Slide、Canvas のシートセルと式駆動型形状は、シート範囲やリレーショナルテーブルフィールドを読み取り、また、Real Table の式フィールドはシートを参照できます。ソースデータと変更通知が利用可能になると、関連する編集は再計算をトリガーします。

<Mermaid chart={"flowchart LR\n    A[\"埋め込み Sheet / Relational Table を編集\"]\n    B[\"子 Unit のデータ変更\"]\n    C[\"参照と依存関係を更新\"]\n    D[\"数式を再計算\"]\n    E[\"セル / 数式 Shape を更新\"]\n    A --> B --> C --> D --> E"} />

| 用途と数式 | 検証結果 |
| --- | --- |
| Slide の予算集計：`=SUM('[Leadership Budget]Budget'!C5:C8)` | `C7` を 17,100 から 18,000 に変更すると、合計が **61,200 → 62,100** に更新。 |
| Sheet で Relational Table を集計：`=SUM([Control Tasks]!Launch_tasks[Cost])` | Cost を 4,000 から 4,500 に変更すると、合計が **18,000 → 18,500** に更新。 |

式の名前は読みやすい修飾子として機能し、統合はまたそれらを支える安定した単位 ID を主張しなければなりません。`getFormula().buildReference()` を使用して、要求するホスト所有の外的なマッピングと参照を一緒に作り出します。リレーショナルテーブルのテーブルのために、表示名か ID を連結するのではなく `table.getFormulaName()` を使用して下さい。方式主導型の形は `shape.setFormula({ formula, externalReferences })` を使用します;計算が完了した後結果を読みました。[フォーミュラファサード](/reference/facade/formula#buildreference)、[シェイプファサード](/reference/facade/shape#setformula) および [リレーショナルテーブル式](/guides/bases/features/core/formulas) 参照して下さい。

## 作成と組み込み [#integration]

ホスト製品、子製品、および同じ Univer インスタンス内の UI を登録し、Embed と Embed UI を追加します。以下の例では、既存のシートを Doc ボディに差し込みます。`hostDocument`、`budgetWorkbook`は対応するファサードです。

```ts
import '@univerjs-pro/embed/facade'

const block = univerAPI.createEmbed({
  host: {
    unitId: hostDocument.getId(),
    surface: univerAPI.Enum.FEmbedHostSurface.DocBlock,
  },
  content: {
    unitType: univerAPI.Enum.UniverInstanceType.UNIVER_SHEET,
    ref: `#unit=${encodeURIComponent(budgetWorkbook.getId())}&type=sheet`,
  },
})

const embeddedWorkbook = await block.loadAsync()
```

`createEmbed()`は関係およびホストのアンカーを作成します。`loadAsync()`は子供の単位を荷を積み、ファサードを戻します。`displayTarget`は最初のワークシート、スライドのページ、またはリレーショナルテーブルビューを選択します。[埋め込むガイド](/guides/fundamentals/features/embed)はプラグイン、スタイル、ロケール、およびローダーをカバーします。[埋め込まれたファサード](/reference/facade/embed)は他の表面と方法をカバーします。

## 保存、共同編集、対応範囲 [#scope]

- ホストスナップショットは参照、配置、および表示設定を保持しますが、最新の子コンテンツを自動的にパッケージ化しません。 ブロックを削除すると、子文書を削除しません。
- Server SDKは、子供スナップショットとそれに付随するコラボレーションサービスを提供します。 `@univerjs-pro/collaboration-embed`では、ブラウザは子供をロードし、コラボレーションセッションに参加します。 両親と子供は変更とバージョンを分離します。
- アプリケーションは参照を解決し、データをロードし、アクセスを承認します。 ホストを開くことができることは、子の編集権限を付与するものではありません。
- シート、ドキュメント、スライド、リレーショナルテーブル、キャンバスの種類は、それぞれに埋め込むことができます。 PDF、同じタイプの埋め込み、より深いネスティングは除外されます。 1つのUniverランタイム内で、子供ユニットは1つのアクティブエンベデッドにのみ属することができます。

[2方向の結合](/overview/features/shared/binding)を使用して、アプリケーション独自の入力、メトリック、およびスプレッドシートからチャートを駆動します。 子製品エディタが必要な場合は、Embed Blockを使用してください。
