Compare explains what changed between two versions. It reads two fully reconstructed Unit snapshots and returns semantic differences in cells, paragraphs, pages, or records. Use it to review history, agent output, or a Worktree.

## Differences by product

| Product | Example comparison objects |
| --- | --- |
| Sheet | Worksheets, cell values and formulas, rows, columns, styles, and registered resources such as charts. |
| Doc | Paragraphs, text, styles, tables, blocks, and drawings. |
| Slide | Pages, elements, geometry, styles, layouts, and themes. |
| Relational Table | Tables, fields, records, and views. |
| Canvases | Pages, elements, and associated resources. |

Changes are additions, deletions, or updates. Temporary UI state such as zoom and selection is excluded. Coverage depends on the product adapter; PDF is not included.

## How Snapshot and changesets contribute to Compare

A Snapshot stores the complete content state at a revision. A mutation describes a specific content change; a changeset groups mutations into an ordered commit. History stores and reconstructs versions; Compare explains the differences between two reconstructed versions.

For history or Worktree comparisons, load a base Snapshot and apply subsequent changesets in order to reconstruct each target revision. Pass the complete states to the product adapter. Available changesets can also improve alignment for structural changes such as inserted or deleted rows and columns. Snapshot comparison is available when only the two complete states are provided.

Results follow each product's content model: Sheet cells and rows or columns, Doc paragraphs, Slide and Canvases elements, and Relational Table fields and records. Temporary selections and zoom are not content changes. Compare is read-only; restoring a version and merging a Worktree are separate operations.

## Working with Server SDK and AI SDK

**Server SDK** supplies Snapshots, changesets and revision numbers and reconstructs the content to compare. The application passes both states and available history to Compare, obtains structured differences, and displays a review interface on the web. See [history](/overview/features/shared/history) and [collaboration service extensions](/server/collaboration/extensions).

**AI SDK** loads and edits content in a Worktree and commits the Agent's result. Applications can use structured differences for Agent checks and further processing, while humans review the same changes visually before deciding whether to merge. See the [Agent Worktree workflow](/ai/worktree) and [content operations](/ai/content-operations).

## Query and display results

Register the product’s history comparison plugins and Facade extensions, then call `compareUnitData()`. For repeated filtering and pagination, create a session with `prepareUnitComparison()` and call `query()`.

Show a summary first, then drill into worksheets, pages, or tables. Request change lists or full before/after values as needed. Default detail results are bounded: the first page is not necessarily the complete diff. Check diagnostics and coverage status before presenting results.

See the [Unit Comparison API](/reference/facade/unit-comparison), [version history](/overview/features/shared/history), and [Worktree](/overview/features/shared/worktree).
