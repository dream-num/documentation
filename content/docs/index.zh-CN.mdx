Univer Office SDK 包含三部分：Web SDK、Server SDK 和 AI SDK，覆盖电子表格、文档、演示文稿、关系型表格、画布和 PDF。

Web SDK 是共用的内容引擎，既运行浏览器编辑器，也以 Headless 方式在无界面环境中处理内容。另外两个 SDK 都建立在它的 Headless 运行时之上：Server SDK 增加协同和文件处理能力，AI SDK 增加面向 Agent 的内容操作和结果检查能力。

### Web SDK：统一内容引擎

要在应用中展示、编辑或处理 Office 内容，可使用 Web SDK。无论在浏览器编辑器中运行，还是在无界面的 Node.js 进程中运行，内容、数据和界面都通过 Facade API 操作。

Web SDK 的各个部分都由插件构成，包括产品能力、编辑器界面以及查找替换等具体功能。应用可以从预设（Preset）开始，也可以选择所需的产品插件和功能插件，连同依赖一起组装。

业务特有的功能可以通过自定义插件实现，无需修改 Univer 核心代码。同一套内容引擎通过更换插件适配不同环境：浏览器应用加载编辑器 UI，Headless 应用则不加载这些 UI 插件。详见 [Univer 架构：插件化设计](/blog/univer#plugins)。

**统一的 Canvas 渲染。** Office 内容都通过同一套 Canvas 渲染体系呈现，因此不同内容类型可以复用排版和绘制代码，也支持嵌套内容。例如，电子表格单元格中的文本沿用了文档的排版和渲染路径，从而保持一致的表现。详见[渲染引擎架构设计](/blog/rendering)。

**前后端混合计算。** 公式引擎既可以在前端计算，也可以在服务端的 Rust 引擎中计算。前端计算保证编辑时的响应速度，大规模公式计算由 Rust 引擎承担。相关能力见[公式功能](/guides/sheets/features/core/formula)与[服务端计算](/overview/features/shared/server-calculation)。

建议从[电子表格](/guides/sheets/getting-started/quickstart)开始。同一套 SDK 还支持[文档](/guides/docs)、[演示文稿](/guides/slides)、[关系型表格](/guides/bases)、[画布](/guides/boards)和 [PDF](/guides/pdfs)。

### Server SDK：连接协作与文件

Server SDK 提供多人协同、文件转换和后端扩展能力。它基于 Web SDK 的 Headless 内容能力：各模块在应用自己的后端中运行，并使用应用自身的身份、权限和存储。

**实时协同。** OT（操作转换）处理行列变更和内容修改等并发操作。一次修改先在本地生效，随后各副本趋于一致，并尽可能保留用户原本的意图。历史记录、评论和 Worktree 是独立模块，需要时再添加。详见[协同编辑设计](/blog/ot)与[协同接入](/server/collaboration/quick-start)。

**文件格式转换。** 转换负责在 Office 文件和 Univer 文档数据之间转移内容，并衔接导入、编辑和导出三个环节。无论是否启用协同服务，转换都可以使用。转换 API 见[Office 文件导入导出](/server/import-export/node)，上传、任务和下载接口见[文件交换集成](/server/import-export)。

**部署与扩展。** 各模块组装在自己的 Node.js 应用中，单台机器即可开始。随着负载增长，可以将文件转换拆分为独立服务，再扩展到多个协同节点。详见[应用架构](/server/architecture)与[部署指引](/server/deployment)。

[Server SDK 总览](/server)对各模块有更详细的说明。

### AI SDK：为 Agent 提供操作入口

AI SDK 为已有的 Agent、自动化流程和业务 CLI 增加 Office 能力。它基于 Web SDK 的 Headless 运行时和 Facade API，提供内容操作、计算和检查能力。

**接入已有 Agent 体系。** Office 工具既可以封装为 TypeScript API，也可以封装为从 SDK 组装的 CLI。模型选择、任务编排和 Skills 仍由应用负责。Agent 收到执行结果和检查反馈后，继续执行自身的工作流。

**创建可继续编辑的内容。** Agent 先读取文档结构，定位所需的区域或段落，再通过 Facade API 创建和修改电子表格、文档、演示文稿等内容，并可以执行公式计算。产出保留内容结构和编辑能力，用户可以继续完善。见[内容操作](/ai/content-operations)。

**检查结果，再继续修正。** Agent 回读数值和公式结果，并检查实际页面的截图。对于演示文稿，布局检查还能发现超出页面、溢出和重叠的文本。Agent 根据这些反馈修改内容并再次验证，从而形成“读取 → 编辑与计算 → 检查 → 修正”的循环。见[视觉检查](/ai/visual-inspection)。

配合 Server SDK，[Worktree](/ai/worktree) 可以将 Agent 的中间修改隔离起来，直到有人在 Web 应用中审阅并合并。从 [AI SDK 总览](/ai)开始。

## 应用中的协作流程

<Mermaid chart={"flowchart TB\n    Human[人类用户] --> Browser\n    Agent[AI Agent / 自动化] --> AI[AI SDK · 操作与验证]\n    subgraph WebSDK[Web SDK · 统一内容引擎]\n      Browser[浏览器编辑器]\n      Headless[Headless · 内容模型与 Facade API]\n    end\n    Server[Server SDK · 协同、文件转换与扩展] -->|依赖| Headless\n    AI -->|依赖| Headless\n    Browser <-->|共享内容| Server\n    AI -.->|协同与审阅| Server\n    Server --> Storage[应用身份、权限与存储]\n    classDef default rx:8,ry:8,stroke-width:1px"} />

- **嵌入式编辑器**：Web SDK 在应用中展示和编辑内容。
- **多人协同应用**：Web SDK 与 Server SDK 组合，让多个用户共同编辑共享文档。
- **人类与 Agent 协作**：Agent 通过 AI SDK 编辑和验证草稿，Server SDK 管理版本与合并，Web 应用提供查看、比较和人工审阅。完整的审阅流程需要三者共同参与。

<Callout title="共同基础与依赖关系">
  Web SDK 可以独立运行，既可以作为编辑器，也可以作为 Headless 内容引擎。Server SDK 和 AI SDK 都依赖 Web SDK 的 Headless 能力：即使没有浏览器界面，仍然需要内容运行时。应用按需启用所需的服务和模块，而完整的人类与 Agent 协作流程通常需要三个 SDK 组合使用。
</Callout>
