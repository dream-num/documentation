**Univer Office SDK 由 Web SDK、Server SDK 和 AI SDK 三個部分組成。** 三者基於統一的 Office 內容執行環境，支援試算表、文件、簡報、多維表格、畫板和 PDF，讓人類使用者與 AI Agent 圍繞同一份內容工作。

**產品名稱：** [Relational Table（關係型表格）](/docs/features/relational-table) 對應 SDK/API 中的 `Base`；[Canvases（畫布）](/docs/features/canvas) 對應 `Board`。

Web SDK 提供統一的內容引擎，既可以執行瀏覽器編輯器，也可以透過 Headless 在伺服器端處理內容。 Server SDK 與 AI SDK 都依賴這項 Headless 能力，分別提供協同、檔案處理等伺服器端能力，以及 Agent 的內容操作與驗證能力。

## SDK 架構與分工 [#sdk-architecture-and-responsibilities]

Web SDK 提供統一的 Office 內容引擎及瀏覽器與 Headless 運作能力。 Server SDK 提供協同與文件服務，AI SDK 提供面向 Agent 的操作與驗證能力，三者共同支援人與 Agent 圍繞同一份內容協作。

### Web SDK：統一內容引擎 [#web-sdk-the-shared-content-engine]

針對需要在產品中展示、編輯或處理 Office 內容的開發者。使用 Facade API 操作文件、資料和介面，既支援瀏覽器中的編輯器，也支援 Node.js 無頭執行。

Web SDK 採用插件架構，產品能力、編輯器介面，以及尋找替換等特定功能，都可以透過插件組合。你可以從預設（Preset）快速開始，也可以依照實際需求選擇產品與功能插件，依插件依賴關係組裝自己的 Office 應用。

你也可以開發自訂外掛程式來擴展業務功能，無需修改 Univer 核心程式碼。同一內容引擎透過不同的插件群組適當配執行環境：瀏覽器中載入編輯器 UI，Headless 場景則不載入瀏覽器 UI 插件。詳見 [Univer 架構：插件化設計](/blog/univer#plugins)。

**統一的 Canvas 渲染。** Office 內容統一採用以 Canvas 為基礎的渲染體系，讓不同內容類型重複使用排版與繪製能力，並支援內容巢狀。例如，試算表單元格中的文字與文件復用排版和渲染能力，保持一致的內容呈現。詳見[渲染引擎架構設計](/blog/rendering)。

**前後端混合計算。** 公式引擎支援前端計算與伺服器端 Rust 引擎配合的混合計算模式，兼顧編輯時的交互響應與大規模公式計算的處理性能。相關能力見[公式功能](/guides/sheets/features/core/formula)與[伺服器端計算](/docs/features/shared/server-calculation)。

[從試算表快速開始](/guides/sheets/getting-started/quickstart)，或選擇[文件](/guides/docs)、[簡報](/guides/slides)、[多維表格](/guides/bases)、[畫板](/guides/boards)和 [PDF](/guides/pdfs)。

### Server SDK：連線協作與文件 [#server-sdk-connect-collaboration-and-files]

面向需要多人協同、文件轉換和伺服器端擴充的開發者。基於 Web SDK 的 Headless 內容能力，將所需模組整合到自己的後端，沿用業務身分、權限與儲存。

**即時協同。** 基於 OT（操作轉換）處理行列變更、內容修改等並發操作，讓編輯先在本地生效，再使多端副本最終一致，並儘可能保留用戶意圖；可進一步組合歷史記錄、評論與 Worktree。詳見[協同編輯設計](/blog/ot)與[協同接入](/server/collaboration/quick-start)。

**文件格式轉換。** 在 Office 文件與 Univer 文件資料之間轉換，打通匯入、編輯、匯出流程，也可不啟用協同服務。轉換 API 見[Office 文件匯入匯出](/server/import-export/node)，上傳、任務與下載介面見[文件交換集成](/server/import-export)。

**部署與擴充。** 將模組組裝進自己的 Node.js 應用，從單機部署開始，依負載拆分檔案轉換服務，再擴展到多協同節點。詳見[應用架構](/server/architecture)與[部署指引](/server/deployment)。

[進入 Server SDK 總覽](/server)。

### AI SDK：為 Agent 提供操作入口 [#ai-sdk-give-agents-an-entry-point]

針對為現有 Agent、自動化流程和業務 CLI 接入 Office 能力的開發者。基於 Web SDK 的 Headless 執行環境與 Facade API，提供內容操作、運算與檢查能力。

**接取已有 Agent 體系。** 透過 TypeScript API 或組裝後的業務 CLI 提供 Office 工具。模型選擇、任務編排與 Skills 由接入方組織，Agent 取得執行結果與檢查回饋後，繼續自己的工作流程。

**建立可繼續編輯的內容。** Agent 讀取文件結構、定位區域或段落，再透過 Facade API 建立和修改表格、文件、投影片等內容，並執行公式計算。成果保留內容結構與編輯能力，使用者可以繼續完善。見[內容操作](/ai/content-operations)。

**檢查結果，再繼續修正。** 回讀數值與公式結果，透過截圖核對實際頁面；投影片也可使用版面檢查定位文字出界、溢出與重疊問題。 Agent 根據回饋修正，再次驗證，形成「讀取 → 編輯與計算 → 檢查 → 修正」的循環。見[視覺檢查](/ai/visual-inspection)。

連線 Server SDK 後，可透過 [Worktree](/ai/worktree)隔離 Agent 的中間修改，再交由人類在 Web 中審閱和合併。[進入 AI SDK 總覽](/ai)。

## 應用程式中的協作流程 [#application-workflow]

<Mermaid chart={"flowchart TB\n    Human[\"人類使用者\"] --> Browser\n    Agent[\"AI Agent / 自動化\"] --> AI[\"AI SDK · 操作與驗證\"]\n    subgraph WebSDK[\"Web SDK · 統一內容引擎\"]\n      Browser[\"瀏覽器編輯器\"]\n      Headless[\"Headless · 內容模型與 Facade API\"]\n    end\n    Server[\"Server SDK · 協同、檔案轉換與擴充\"] -->|依賴| Headless\n    AI -->|依賴| Headless\n    Browser <-->|分享內容| Server\n    AI -.->|協同與審閱| Server\n    Server --> Storage[\"應用程式身分、權限與存儲\"]\n    classDef default rx:8,ry:8,stroke-width:1px"} />

- **嵌入式編輯器**：使用 Web SDK，在應用程式中展示和編輯內容。
- **多人協同應用**：組合 Web SDK 與 Server SDK，讓使用者共同編輯共用文件。
- **人類與 Agent 協作**：透過 AI SDK 讓 Agent 編輯和驗證草稿，Server SDK 管理版本與合併，Web 應用承載人的檢視、比較和審查互動。完整的審閱流程由三者共同完成。

<Callout title="共同基礎與依賴關係">
  Web SDK 可以獨立用於編輯器或 Headless 內容處理。 Server SDK 與 AI SDK 皆依賴 Web SDK 的 Headless 能力；無需瀏覽器介面，也需要內容執行時間。按需啟用的是具體服務和模組，應用程式通常會組合三個 SDK 完成人類與 Agent 的協作流程。
</Callout>

## 下一步 [#next-steps]

從 Web SDK 的內容執行階段開始，結合 Server SDK 與 AI SDK 跑通應用程式的第一個完整流程，再逐步增加所需模組。保持相關 Univer 套件版本匹配，並根據所選模組準備執行環境、身分權限和授權。

查看[範例](/docs/examples)，了解開源應用程式、Agent 整合、演示與原始碼；也可以開啟[線上示範](https://office.univer.ai)，體驗不同 Office 產品的互動與功能。
