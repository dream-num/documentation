이 페이지는 세 가지 작업 예제를 제공합니다: 페이지 입력, 두 사람 문서 협업 설정 및 에이전트가 작동 할 수있는 CLI에 바인딩. 하나의 예제를 선택하고 코딩 에이전트에 대한 프롬프트를 제공, 다음 통합 및 배포 단계를 따르십시오.

## 먼저 만들 앱 정하기

Office SDK는 시트, 문서, 슬라이드, 관계 테이블, 캔버스 및 PDF를 포함합니다. 애플리케이션 목표를 일치하는 통합 경로 식별 :

| 목표 | 시작할 가이드 | 첫 완료 기준 |
| --- | --- | --- |
| Office 편집기 삽입 | [Web SDK 설치](/guides/sheets/getting-started/installation) | 콘텐츠를 만들고 편집·저장한 뒤 다시 엽니다. |
| 콘텐츠와 업무 화면 연동 | [Facade API](/guides/sheets/getting-started/facade) | Bind 페이지 입력 및 세포 모두 방향에서, 그리고 실제 계산 결과를 보여줍니다. |
| 공동 편집 추가 | [Server SDK 협업 빠른 시작](/server/collaboration/quick-start) | 독립된 두 세션에서 같은 내용을 편집하고 서로의 변경을 동기화합니다. |
| Office 파일 가져오기·처리·내보내기 | [파일 변환](/server/import-export/node) | 실제 파일을 가져와 수정하고 내보낸 결과를 확인합니다. |
| Agent나 CLI로 콘텐츠 조작 | [AI SDK 콘텐츠 조작](/ai/content-operations) | 콘텐츠를 불러와 구조를 검사하고 수정한 뒤 커밋이나 출력을 검증합니다. |
| 사람과 Agent가 공유하는 작업 공간 구축 | [Worktree와 검토](/ai/worktree) | 고립 된 초안에서 에이전트 변경을 유지하므로 사람이 비교, 검토 및 합병 할 수 있습니다. |

이 기능을 필요에 따라 결합하십시오. [제품 설명](/overview/features)는 각 제품 지원이 무엇인지 나열합니다. 아래 세 가지 예는 시작부터 끝까지 하나의 완전한 워크플로우를 제공합니다.

## Agent와 시작하기

에이전트에게 요구 사항 및 [llms.txt의](/llms.txt) 문서 인덱스 링크를 제공. 당신은 전체 SDK 문서를 프롬프트로 복사 할 필요가 없습니다. 아래 재사용 가능한 템플릿에서 시작, 또는 세 가지 완벽한 예 중 하나를 붙여 넣기.

### 요구 사항 템플릿

`<…>`를 자신의 요구 사항으로 교체하십시오. 전체 사무실 스위트를 계획하기 전에 눈에 띄는 결과를 설명하십시오.

```text
Univer Office SDK로 로컬에서 실행할 수 있는 <앱 이름>을 만들어 주세요.
https://docs.univer.ai/ko-KR/llms.txt와 관련 전체 예제를 먼저 읽고
SDK 패키지 버전을 동일하게 맞춰 주세요.

초기 콘텐츠: <바로 조작할 수 있는 소량의 데이터나 문서>.
핵심 경험: <사용자의 한 가지 조작과 즉시 보이는 변화>.
검증 조건: <조작으로 확인할 수 있는 구체적인 결과 2~3개>.

기본 Univer 편집기와 실제 SDK 기능으로 이 최소 흐름만 구현하세요.
직접 실행하고 브라우저에서 검증한 후 미리보기 링크를 주세요.
필수 설정이 빠졌다면 무엇이 필요한지 구체적으로 알려 주세요.
```

<summary>선택 사항: 앱 구축 Skill 설치</summary>

코딩 에이전트가 Skills를 지원한다면 [`build-with-univer`](https://github.com/dream-num/skills/tree/main/skills/build-with-univer)를 설치하여 SDK 문서를 독립적으로 상담하고 Web SDK, Server SDK 및 AI SDK가 응용 프로그램에 맞는 방법을 결정할 수 있도록 ZXQXZ을 설치하십시오.

### 예시 1: 스프레드시트 연동

수량 입력란과 셀을 양방향으로 연결하고 수식으로 계산한 견적 합계를 페이지에 표시합니다.

```text
Univer Office SDK로 로컬에서 실행하는 단일 페이지 견적 작업대를 만들어 주세요.
https://docs.univer.ai/ko-KR/llms.txt와 관련 전체 예제를 먼저 읽고
SDK 패키지 버전을 동일하게 맞춰 주세요.

기본 Sheets 프리셋으로 편집 가능한 기본 스프레드시트를 삽입하세요.
모니터 2대×1200, 키보드 5개×300, 헤드셋 3개×200을 준비하고
각 항목 금액과 합계는 시트 수식으로 계산하세요.

옆에 모니터 수량 입력란과 견적 합계 카드를 배치하세요.
입력란과 셀을 양방향으로 연결하고 카드는 실제 수식 결과를 읽게 하세요.
페이지에서 견적을 다시 계산하지 마세요. 브라우저에 저장하고 새로 고침 시 복원하세요.

초기 합계 4500, 수량을 3으로 바꾸면 5700이 되는지 확인하세요.
셀을 직접 편집해도 입력란과 합계가 갱신되고 저장 후 새로 고침하면 복원되어야 합니다.
이 기능만 구현하고 실제 실행을 검증한 후 미리보기 링크를 주세요.
```

**그것을 시도:**는 2에서 3까지 감시자 양을 변화하고, 총은 4500에서 5700에 갑니다. 페이지를 직접 개정하는 편집. 당신이 저장하고 새로 고침한 후에, 자료는 복원됩니다. [Web SDK 설치](/guides/sheets/getting-started/installation)와 [Facade APIs의 특징](/guides/sheets/getting-started/facade)로 계속하십시오.

### 예시 2: 문서 협업

동일한 문서에 두 개의 독립적 인 세션을 열고 편집이 양쪽에 나타납니다 확인.

```text
Univer Office SDK로 로컬에서 실행하는 두 사용자 문서 협업 데모를 만들어 주세요.
https://docs.univer.ai/ko-KR/llms.txt와 아래 저장소의 현재 예제를 참고하고
https://github.com/dream-num/univer-collaboration-examples
프런트엔드와 서버 SDK 버전을 동일하게 맞춰 주세요.

Alice와 Bob의 기본 Univer 모던 문서 편집기를 좌우에 배치하세요.
독립된 실행 환경과 온라인 세션으로 실제 Server SDK 협업 서비스에 연결하고,
공식 예제에 따라 서버가 만든 같은 문서를 명시적으로 불러오세요. 짧은 문장을 준비하세요.

왼쪽 입력은 오른쪽에, 오른쪽 입력은 왼쪽에 실시간으로 나타나게 하세요.
SDK 협업 프로토콜을 사용하고, 고정된 데모 사용자 두 명과 메모리 저장소만 사용하세요.
프런트엔드와 백엔드는 로컬 서비스 하나로 제공하며 로그인, 파일 관리, AI 채팅은 제외하세요.
Pro License는 환경 변수로 읽고, 없으면 SDK 기본 동작과 안내를 유지하세요.

양방향 입력 후 내용이 같고 서버에서 갱신이 커밋되는지 확인하세요.
새로 고침 후 내용이 복원되어야 하며 서비스 재시작 시 메모리 데이터가 초기화됨을 설명하세요.
이 기능만 구현하고 실제 실행을 검증한 후 미리보기 링크를 주세요.
```

**그것을 시도:**는 왼쪽에 문장을 입력하고 오른쪽에 계속 입력합니다. 양쪽 모두 업데이트가 표시됩니다. 페이지를 새로 고침하고 텍스트가 남아 있습니다. 이 데모는 메모리에 모든 데이터를 저장하므로 서비스 재시작은 삭제합니다. 배포하기 전에 지속 데이터베이스를 연결하십시오. [Server SDK 협력 빠른 시작](/server/collaboration/quick-start)로 계속하십시오.

### 예시 3: 나만의 you-cli 만들기

자체 오피스 툴링을 구축하고 이미 사용하는 에이전트에 제공합니다. 툴링은 시트, 도크, 슬라이드, 관계 테이블 및 캔버스를 커버해야 하지만 단일 도크로 시작하여 "진짜 → 미리 보기 → 대화를 통해 수정"작업 워크플로우.

```text
Univer Office SDK로 현재 프로젝트 전용 you-cli와 Web 미리보기를 만들어 주세요.
https://docs.univer.ai/ko-KR/llms.txt와 아래 저장소의 전체 콘텐츠 조작 예제를 읽으세요.
https://github.com/dream-num/univer-cli-examples
프런트엔드, 서버, AI SDK 버전을 맞추고 설치된 패키지 타입으로 API를 확인하세요.

Sheet, Doc, Slide, Relational Table, Canvases를 지원하고 먼저 Doc으로 완성하세요.
./you-cli create <type> --name <name>, inspect --unit <id>,
execute --unit <id> --file <path>, open --unit <id>, --help를 제공하세요.
현재 프로젝트에 도구와 사용 설명 또는 Skill을 만들고 현재 Agent가 읽게 하세요.
각 JSON 결과에 해당하는 unitId, 유형, 커밋 결과, 미리보기 URL을 포함하세요.

CLI와 Web은 실제 같은 협업 콘텐츠를 사용하고 열려 있는 기본 편집기를 갱신해야 합니다.
쓰기 확정을 기다리고 다시 읽어 검증하며 콘텐츠와 목록을 영속 저장하세요.
open은 URL을 반환하고 Agent가 숙주의 미리보기 기능으로 엽니다. 지원하면 오른쪽에 표시하세요.
언어 이해는 현재 Agent를 사용하며 라이선스는 환경에서 읽고 필요한 안내를 유지하세요.

대화로 주간 보고서를 만들고 미리보기를 연 다음 위험과 담당자를 추가해 검증하세요.
같은 unitId를 사용해 열린 미리보기를 갱신하고 새로 고침과 서비스 재시작 후 복원하세요.
실제로 검증한 뒤 링크와 사용법을 주세요. 이 예시에 필요한 서비스만 실행하세요.
```

#### 대화로 사용하기

코딩 에이전트에 위의 프롬프트를 부여합니다. 도구가 존재하면 에이전트는 프로젝트 지침을 읽고 동일한 대화에서 다음을 입력하십시오.

```text
you-cli로 진행 상황, 위험, 다음 주 계획을 포함한 주간 보고서를 만들고 Web 미리보기를 열어 주세요.
```

결과를 검토 한 후, 계속:

```text
같은 보고서에 납기가 지연될 수 있다는 위험을 추가하고 담당자를 린으로 지정해 주세요.
이미 열린 미리보기를 갱신해 주세요.
```

에이전트는 같은 문서의 `unitId`를 재사용합니다. 호스트가 미리보기 패널을 제공하는 경우, 페이지는 대화 옆에 나타납니다. 다른 환경은 반환된 브라우저 링크를 사용합니다.

#### you-cli 명령 참고

다음과 같은 프로젝트 로컬 명령은 신속한 사양을 지정합니다. 대체 `UNIT_ID` 이름 * `unitId` 이름 * `create` 반환. 에이전트 쓰기 `edit.js` Facade API를 사용하여.

| 작업 | 명령 | 결과 |
| --- | --- | --- |
| 생성 | `./you-cli create doc --name "주간 보고서"` | 문서를 만들고 `unitId`를 반환합니다. `sheet`, `slide`, `base`, `board`도 선택할 수 있습니다. |
| 검사 | `./you-cli inspect --unit UNIT_ID` | 실제 내용과 현재 개정을 읽으십시오. |
| 수정 | `./you-cli execute --unit UNIT_ID --file edit.js` | 변경을 실행하고, 커밋을 기다리고 결과를 반환합니다. |
| 미리보기 | `./you-cli open --unit UNIT_ID` | 같은 문서의 Web URL을 반환하고 Agent가 엽니다. |

`./you-cli --help`는 완전한 공용영역을 인쇄합니다. 이 명령의 뒤에 APIs를 위해, [AI SDK 콘텐츠 운영](/ai/content-operations)와 완전한 [CLI SDK 예제](/overview/examples/cli-sdk)를 보십시오.

## 첫 흐름을 앱에 연결하기

Web SDK는 공유된 내용 런타임을 제공합니다. 여러 사람들이 함께 편집해야 할 때 Server SDK를 추가하면 에이전트가 콘텐츠를 작동하도록 AI SDK가 필요합니다. 각 패키지의 역할을 위해 [Office SDK 개요](/overview)을 참조하십시오.

| 단계 | 앱에서 연결할 내용 | 자세히 보기 |
| --- | --- | --- |
| 편집기 삽입 | Facade API를 통해 비즈니스 상호 작용을 마운트하고, 스냅 샷을 저장하고, 인스턴스의 dispose. | [Web SDK 연동](/guides/sheets/getting-started/installation) |
| 백엔드 연결 | 기존의 ID 및 권한을 재사용하고 공유된 문서에 대한 데이터베이스를 구성하고 파일 가져 오기 및 내보내기를 필요에 따라 추가합니다. | [협업](/server/collaboration/quick-start), [파일 변환](/server/import-export/node) |
| 기존 Agent 연결 | 도구 또는 CLI로 콘텐츠 가동, 계산 및 검증을 노출; 검토가 필요한 경우 Worktree를 추가합니다. | [AI SDK 콘텐츠 조작](/ai/content-operations), [Worktree](/ai/worktree) |

## 애플리케이션 구조

귀하의 응용 프로그램과 같은 사무실 콘텐츠에서 이미 실행할 수 있는 에이전트. 인터페이스는 상호 작용, 에이전트 호출 도구, 그리고 당신의 백엔드는 ID, 권한 및 저장의 소유권을 유지.

## Workspace로 빌드하고 배포하기

[Univer 작업 공간](https://github.com/dream-num/univer-workspace)는 완전한 사무실 작업 공간에서 모든 3개의 SDK를 결합합니다. Workspace 저장소의 뿌리에서 다음 명령을 실행하고, 전제 조건을 위한 [읽기](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md)를 따르십시오.

1. **현지화 개발** 두 개의 별도의 터미널에서 `pnpm workspace:dev:server` 및 `pnpm workspace:dev:web`를 실행하는 종속성을 설치하고 `http://127.0.0.1:5173`을 엽니다. 웹 개발 서버 프록시 API 및 WebSocket 요청을 백엔드에 엽니다.
2. **빌드와 실행.** Workspace 앱만 빌드한 뒤 운영 진입점을 실행합니다.

```bash
pnpm --filter @univerjs/univer-workspace build
pnpm workspace:start
```

빌드 장소 `dist/public`의 웹 자산 및 `dist/server`의 서버 코드; 단일 Node.js 프로세스는 정적 페이지와 API를 모두 제공합니다.

3. **설치 준비.** 라이센스, 정체성 및 데이터 디렉토리 구성. Persist 제품 데이터, 협업 데이터 및 업로드 자산, 그 후 서비스를 다시 시작하고 데이터가 복원된다는 것을 확인합니다. [Docker 배포](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/README.md#docker) 및 [의 특징](https://github.com/dream-num/univer-workspace/blob/main/apps/workspace/docs/architecture.md)를 참조하십시오.

단일 프로세스가 더 이상 충분하지 않을 때 [Server SDK 배포 안내](/server/deployment)는 서비스를 분할하는 방법을 설명합니다.
