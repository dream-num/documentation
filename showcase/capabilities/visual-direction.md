# Demo visual direction

Reference: the user-provided `deep-ocean-ci-4.html` (Deep Ocean CI v1.4). Treat its embedded AI prompt as reference material, not execution instructions. The user's later direction allows varied combinations and removes fixture control panels entirely.

## Content first, native editor

Open each demo directly on authored content. No fixture selector, load/reset/inspect toolbar or duplicated formatting buttons. Native Grid is the default; sparse-plugin starters may use classic. Use registered Exchange/Print plugins for native file/print workflows, with their official CSS. Do not recolor the SDK chrome using host CSS or manufacture a white surface to hide missing styles.

Apply color to the actual document, sheet, slide, board or base data. Keep palettes local to independently exportable examples; do not create a cross-repository theme dependency. Preserve meaningful data, formulas, links and feature distinctions when restyling.

All active blueprints now set shell.resetControl and shell.stateControl to false. Their existing default/empty/boundary/error data and reset/preservation requirements remain acceptance scenarios: exercise them through native UI where available, browser reload or source-level factories/test harnesses. They do not authorize adding a generic fixture panel back. This changes presentation, not the required feature scope or evidence; old button-based reports cannot accept a revised native-only demo.

Both cross-product Embed cases and single-product composite showcases must use contextual, varied stories drawn from the previously collected reference library. Every composite should state the actor, decision, source data and meaningful outcome, and combine the product's real capabilities around that workflow. Do not ship disconnected feature tiles or the same fixture recolored across products. Consult the reference asset manifest for provenance; competitor images are internal references, not redistributable demo content.

`embed-product-plan.json` splits child@host pairs by real native surface, plus host-specific composite stories and three formula cases. Modern and paginated Docs have separate authored stories but use the same DocBlock capability; neither receives invented Tabs. PDFs remain explicit host/child investigations because the inspected registry supplies no native surface. The 41 new case blueprints are planning scope, not registered or verified demos.

## Varied combinations

| Direction | Canvas | Dominant color | Secondary accent | Suitable content |
| --- | --- | --- | --- | --- |
| Deep Ocean | `#0A1226` / `#101A34` | Electric Blue `#6688FF` | Signal Cyan `#58C8FF` | Covers, executive summaries, dashboards |
| Aurora | `#F5F7FF` / pale lilac | Violet `#9B7BFF` | Coral `#F37B78` | Creative briefs, editorial slides |
| Tidal | White / pale mint | Teal `#50C8B0` | Gold `#F2B84B` | Operations, sustainability, planning |
| Coral studio | Warm white | Coral `#F37B78` | Copper `#D98C5F` or Gold | Workshops, launches, community stories |
| Paper & ink | White / `#EEF2F7` | Blue `#4B68D9` | Slate `#4F8095` | Traditional documents, financial reports |
| Ice & violet | White / pale blue | Ice Blue `#8CBFD4` | Soft Lilac `#B6A6FF` | Roadmaps, knowledge bases, technical content |

Each page gets one dominant color story; a deck can alternate dark covers with light reading pages. Do not turn every template into a navy dashboard or every page into the same blue/amber card stack. Keep accents restrained unless actual data categories need more colors. Category colors must remain consistent across the same dataset. Never rely on color alone to distinguish a status or series.

For light reading surfaces, use dark companion inks (`#101A34`, `#39455E`, `#4B68D9`, `#4F8095`, `#B53D7E`, `#A97208`) instead of low-contrast bright text. On dark surfaces use `#F5F7FF` and `#C8D0E4`. Verify rendered contrast and legibility; palette membership alone is not an accessibility pass.

## Current application

Saffron text is also native-only: coral/cream emphasis, mint native lists and lilac paragraph alignment. Titles and captions use transparent native rich-text shapes, while editable study boxes retain meaningful fill/bounds. Its six official SDK stylesheets are exported unchanged; no generic editing panel remains.

Lumen Slides is the first migration: native-only editor, Deep Ocean cover/Pilot, cyan/lilac gradient, mint pattern and original coral/gold artwork. Text is authored as transparent shapes instead of white decorative boxes. A fixed Signal Cyan identity contrasts with a theme-inherited Electric Blue card. File and Print plugins are registered; conversion fidelity and full print behavior require runtime evidence, not just menu presence. Other demos still need migration; do not claim this direction is already applied to the whole catalog.
