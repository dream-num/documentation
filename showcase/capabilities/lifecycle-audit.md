# Owning-instance disposal audit

On 2026-09-04, the PDF browser test exposed a host integration bug: Facade-only disposal plus DOM clearing left the owner alive. A remounted viewer had a valid model but no visible editor, with React `removeChild` exceptions.

## Installed SDK contract

`FUniver.dispose()` releases Facade subscriptions; `Univer.dispose()` destroys the injector/plugins. The Facade registers an injector-disposal callback, so owner disposal releases the Facade too. Presets return both objects without overriding this contract. `scripts/test-showcase-disposal.mjs` verifies both directions against the installed SDK.

## Corrections

- Replaced the original 43 exported Facade-only cleanup calls with retained-owner disposal.
- Corrected `docs/lit` and `sheets/lit` to retain and capture the owner on disconnection, deferring disposal outside a possible React commit. Local SDK CSS assets and Shadow DOM styles remain intact.
- Migrated five legacy preset Previews (`sheets/slim-via-preset`, `sheets/basic-via-preset`, `docs/slim-via-preset`, `sheets/watermark`, `docs/watermark`) to shared `create-demo.ts` factories. Preview and exported entry use the same plugins, CSS and cloned fixture. Removed the Basic Sheets duplicate filter-preset registration. Both entry points retain owning-instance disposal; React defers initialization/cleanup outside commits. Their exported file maps include the shared source and exact Preview reference.
- React adapters use resolved theme, cancellable animation-frame initialization and captured old-controller cleanup. Deferred cleanup never reads a possibly replaced controller ref.
- Guarded selected Slides continuations after animation frames, three Bases continuations after view activation and Sheets import/export completion after disposal. This does not cover every asynchronous path.
