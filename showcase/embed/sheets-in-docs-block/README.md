## Native integration

createEmbed uses DocBlock at the empty paragraph before Decision gates. Docs
owns the UTF-16 marker and drawing; Embed loads a real local workbook through
a provider honoring createOptions. The child has Investment and Phasing sheets.
Native expansion reveals the sheet bar, which the SDK omits in the inline view.
There is no HTML table, iframe substitute, fixture panel or duplicate toolbar.

Preview and standalone use the same factory/data. Nineteen official CSS imports
include Docs Drawing and the Sheets feature presets, which publicly re-export
their plugins. The browser-only Next
adapter is exported as reference text. Owned content/menu roots are unmounted
before releasing the SDK, following the existing beta.2 lifecycle pattern.

The beta.2 Embed ribbon contributes all Sheets feature menus, even when their
plugins are absent. Menu factories run before hidden-state configuration, so
hiding a button cannot supply its dependencies. This example follows the SDK's
docs-embed-local feature registration: formatting, validation, filters, links,
notes, sorting, tables, local comments, outlines, pivots, charts, sparklines,
shapes and printing. It uses installed public presets, not placeholder services
or SDK/package patches. The Advanced preset's server-endpoint configuration is
not used. No collaboration or version-history plugin is registered.

Formula UI is registered and its native menu schema is added through the public
registerEmbedProductMenuContribution extension point. Start, Insert, Formulas,
Data and View use Grid. There is no parallel host toolbar.

Native Print prepares the selected embedded worksheet, then SheetPrintOpen
exits Embed fullscreen through EmbedFullscreenService so the host-mounted
preview is not obscured. Cancel returns to the document; expand the block again
to continue editing. FitWidth is initialized through FWorkbook.updatePrintConfig.
This demonstrates local print preview, not a verified printer or binary export.
