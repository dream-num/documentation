# Solstice / Supplier delivery readiness

The demo runtime, authored data and startup alerts are English-only, including on
Chinese-language guide pages. The legacy third locale argument remains accepted
but is ignored. Earlier EN/ZH reports below describe historical interaction runs,
not current bilingual SDK acceptance. English-only source/CSS/startup checks do
not certify every native interaction or resolve the recorded SDK failures.

An original fictional portable reading-light release uses three narrative slides,
seven distinct checks and three suppliers. The first slide hosts a real native
SlideFloating Base, not a replacement table, iframe or fixture panel. The Base
owns its records, supplier links and history; the presentation owns its narrative.

The internal `airtable-template-01.png` reference informed task/evidence structure
only. All names, slide layouts and records here are original; no competitor
artwork is exported. Aubergine, pale yellow and mist blue differentiate this
review from the Copper retail Tab case.

## Edit evidence without rewriting the review

Double-click the register to activate its native Base. Edit Enclosure finish, or
execute this equivalent Facade example after activation:

```ts
const record = window.univerAPI
  .getBase('solstice-supplier-readiness')
  .getTableById('checks')
  .getRecordById('checks-1')
record.setValue('title', 'Enclosure edge review')
```

The native floating Undo/Redo controls are currently failing their runtime gate,
as is Enter fullscreen; do not assume they restore an edit. Scroll within the
register to inspect sample counts, owners, review dates and evidence. This compact
Float exposes one table view, not the full table navigation of the Tab example.
To inspect the supplier directory as a source variant, set displayTarget to
`{ tableId: 'suppliers', viewId: 'suppliers-grid' }` in create-demo.ts and reload.
To demonstrate a linked-name change without replacing record IDs, run:

```ts
window.univerAPI.getBase('solstice-supplier-readiness')
  .getTableById('suppliers').getRecordById('suppliers-1')
  .setValue('title', 'Alder Works')
```

The two Alder checks retain the same supplier record ID. Native Slides thumbnails
lead to the quality and decision pages.
Changing theme uses the same API owner and must preserve edits; reload starts
again from the authored data. All operations remain local: no supplier messages,
purchase orders, approvals, product-safety certification or persistence.

## Runtime boundaries

The installed beta.2 Slides Float fullscreen/floating-menu behavior is an open
gate. This example must test it directly and retain failures; it does not replace
native controls with host buttons. Registration and static checks alone do not
prove runtime acceptance. Separate source, independent production, Next EN/ZH,
official CSS/source parity, lifecycle and native keyboard checks are required.
Full menu/dialog coverage, narrow/touch layouts, error/delayed providers and
resource preservation also remain open until evidenced. No Exchange/Print
conversion is claimed by this embedding example, and no SDK package is patched.
