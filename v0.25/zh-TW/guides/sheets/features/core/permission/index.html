核心功能

權限控制

在 GitHub 上編輯

Univer 提供權限控制能力，用於限制使用者對工作簿、工作表、選區的操作。當使用者執行無權限動作時，Univer 會中止執行並提示缺失權限。常見場景如：對一片選區設定保護，限制協作者的編輯/檢視/複製等能力。

使用前須知

Univer 提供的是可擴充的基礎能力，而不是完整的權限系統。 如果你需要權限持久化、組織架構、使用者資訊等客製化能力，需要自行實現權限規則儲存與組織架構接入，通常透過自訂外掛來完成。 因此出現“權限列表為空”或“使用者資訊為空”的情況是正常的：這些資訊需要由你的介面返回。可參考下方的“第三方權限服務接入”。

Preview

核心概念

  • 作用範圍：權限可以作用在工作簿、工作表、選區三個層級。
  • 權限點位：每個功能對應一個權限點位，修改點位即可控制功能是否可用。
  • 保護規則：工作表和選區在設定權限點位前，需要先建立保護規則。

權限點位說明

本機非持久化（非協同編輯環境）權限控制可直接透過修改權限點位實現，持久化權限請參考下方的“第三方權限服務接入”。 協同編輯場景下，更新權限點位會同步更新服務端狀態：

  • false：該權限點至少需要 owner 角色
  • true：該權限點至少需要 reader 角色

注意事項

已經開始接入自訂權限，可以直接操作更細粒度的權限點位，建議不要和 Permission Facade API 混用。

權限的判斷邏輯通常由外接服務處理，這部分一般會帶有一個通訊流程。在純前端 SDK 實現中，我們使用 AuthzIoLocalService 來承載這部分邏輯。

在生產環境中，我們需要將這部分實現轉由後端實現，前端需要基於 IAuthzIoService 型別實現對應的請求函式，以便在執行時替換。

下面是一個簡單示例：預設 2 個角色（所有者/閱讀者）情況下區域保護權限點位的增刪。所有者擁有保護區域的編輯/檢視權限，而閱讀者不能編輯也不能檢視保護區域內單元格的內容。

權限點位列表

不同的功能權限由不同的權限點位控制，修改點位的值即可控制對應功能。具體點位程式碼請參閱這裡。

如果 workbook 的權限控制和 worksheet / range 有交叉，那麼必須全部為 true 才能使用。例如一個單元格的編輯權限必須 workbook 和 worksheet 的編輯權限都為 true 才能編輯。
